# AGENTS.md — trellis

Skeleton-constrained knowledge base (Obsidian vault + Anki build) **plus** the interview
folder `vault/interviews/`. Vocabulary is in `CONTEXT.md`; the product is in `README.md`.
This file is only what an agent needs to work here without re-deriving it. It is the single source of
agent instructions: `CLAUDE.md` just imports it (`@AGENTS.md`). Contributor docs: `docs/README.md`.

| `codebases/<name>.yaml` | declared employer / personal codebases to study as cases (ADR 0003) |

| `obsidian/` | Obsidian config shipped to devices (Git plugin settings, CSS snippets); installed by `scripts/obsidian_setup.sh`; how-to in `docs/how-to/obsidian-sync.md` |
| `docs/` | contributor docs in four kinds (`how-to/`, `reference/`, `explanation/`, `adr/`), indexed by `docs/README.md` |
| `tests/` | the trellis package tests (`pytest`, scoped to this folder) |

The layout is ADR 0008: organise by purpose, at most two levels before the content. A new subject goes
under `domains/`, a new round skill under `interviews/rounds/`, a company under `interviews/companies/`.
Wikilinks resolve by note name, so a move never breaks them; plain-text paths do — re-audit after moving.

Rules that are not derivable from the code:

- **Everything Chi studies lives in this repo's vault and is merged to `main`.** Never write
  interview or study material into `~/Documents/Chi` or any other vault; never copy across vaults.
- `vault/` is an Obsidian vault: `.py` files inside company kits are invisible to Obsidian and
  harmless to `trellis` (it only reads `*.md`). Root `pytest` is scoped to `tests/` via
  `pyproject.toml`; run a kit's suite with `scripts/kit_suites.py --co <co>` or from inside its folder (`cd vault/interviews/companies/stripe && python3 -m pytest problems -q`).
- `core/resume/resume.tex` is the only resume source. Company folders link to `core/`, never copy it.
- **Chi reviews in Chinese.** Every learner-facing text (skeleton titles, readings, cards, drills,
  study articles) is Chinese, technical terms in English in parentheses. A skeleton without `lang`
  is `zh`; only an older English domain says `lang: en`.

## Interview kit methodology (the Stripe way — reuse for every company)

**Learning area vs research area (Chi, 2026-10-17; Amazon is the first kit done this way).** Obsidian (`vault/`) holds only
what Chi studies: no sources, report ids, confidence, 「（重建）」, evidence tables, commit hashes, agent/gate talk — not
even in a last section. `companies/<co>/` keeps only company-specific rounds and topics (entry README, LOOP_GUIDE, LP,
company-only rounds); general topics go to `core/<topic>/<co>/` or a domain branch (LLD deck 10 = `amazon` branch).
Steps 0–2 below (`catalog/raw`, `CATALOG.md`) live in `research/companies/<co>/`. Rules: `proposals/WRITING_RULES.md`,
checked by `scripts/plain_style.py` (LP pages `--outline`); dead links: `scripts/check_wikilinks.py`. Problems not asked in
the last month carry `（low priority）` in the title.


Full procedure, lessons and red flags: `.claude/skills/building-company-interview-kits/SKILL.md`.

0. **GitHub first, always.** Before any web research, search GitHub for what others already
   curated (`gh api -X GET search/repositories -f q="<co> interview"`, `search/code`, company-wise
   LeetCode repos), then distill into `catalog/raw/github_repos.md` with a confidence per source.
   Only then go to forums/aggregators. The coverage denominator must include what GitHub found.
   - LeetCode originals never get a full kit: run `python3 vault/interviews/core/leetcode/lc_company.py <Company>`
     (link + tags + frequency, tiered A/B/C); map to kit ids in `core/leetcode/companies/<co>.kitmap.json`.
1. `catalog/raw/`: one file per source, every fact with URL + date; nothing rewritten.
2. `catalog/CATALOG.md`: one row per problem — aliases, stage, parts, last asked, `#refs`
   (independent sources), confidence (high/medium/low), URLs. Rank by stage × refs × recency;
   the top ~20% of rows must cover ~80% of reported sightings (write the cut line down).
3. `LOOP_GUIDE.md`: per round — format · what is scored · pass line · failure modes · prep actions,
   every claim traceable to raw.
4. Problem sets follow `CONVENTIONS.md` (`problem.md` + `starter_template.py` + `solution.py` +
   `test_*.py` with part/edge/fmt/perf/io markers + `REPORT.md`); non-coding rounds are
   `bank.json` + `questions.md` + `rubric.md` + `stories.md`; system design is
   `prompt.md` + `rubric.md` + `model_answer.md` + `followups.md`.
5. `study/` is Chinese: essentials (transferable), per-round prep, one article per problem.
6. Runners: `drill.py` (OA) and `loop/mock.py` (all other rounds), started with `uv run --project <repo> python …`
   (they import `trellis.kit`); `trellis kit summary --co <co> --run` regenerates the test summary;
   `trellis kit refresh_check --co <co>` re-verifies sources. Authoring tools are shared in `trellis/kit/`, never copied into a kit.
7. Reconstructed parts are labelled **(reconstructed)** in `problem.md`; AI content farms
   (lodely, vervecopilot) are never cited; a single fetch failure never condemns a site —
   record which path failed (see `research/companies/stripe/HANDOFF.md` §2 for the reachability table).

## Deck rules set by Chi in 2026-11 (they outrank older per-deck habits)

- **Remove filler first.** A line stays only if it tells the learner something the rest of the card does not (a
  mechanism, a number, a failure, a decision, a concrete scene). No section is kept for its name — not 业务场景, not
  2026 亮点, not an example. Brief for trimming: `research/agents/trim-long-cards.md`.
- **Self-contained, in order.** A card uses a term only if an earlier leaf teaches it or the card defines it in one
  line; each new domain keeps `research/domains/<d>/terms.yaml`, and `scripts/term_order.py <d>` must report 0.
- **English technical terms, Chinese prose** in every domain created after 2026-11-20 (older decks are not converted).
- **Citations and interview tails are folded**, never a body line: `scripts/card_normalize.py fold-source|fold-tail`.
- **No new decks.** New topics become leaves of an existing deck (`research/domains/EXPANSION.md`); write cards only
  when Chi asks, and not while reviews are behind.
- **One new-card budget for the focus decks.** Plan config `caps` (180 a day over the focus decks: 120 as before, 30 of them 算法模式识别, plus 20 each for `3 低层设计测验` and `AI 测验` since 2026-11-22, and `5 系统设计高频题` 10 → 30 since 2026-11-23; these are ceilings, Chi studies at his own pace; reviews first; every
  other deck stays open at its normal pace — never zero a deck Chi may open) is applied by `scripts/daily_cap.py`, which
  `study_plan.py daily` runs last. Change the split there; a preset changed by hand is reset the next morning.
- **Algorithms are studied in `2 算法模式识别`** (it replaced 今日算法): a recognition question on the front, the
  problem's whole tree card on the back (`scripts/daily_quiz.py todo | import --set recog | full`, rules in
  `research/agents/daily-quiz.md`). The tree deck keeps the source cards and their reviews; it deals no new cards.
  Sub-decks `1 学习卡` (a leaf's learning card, dealt by `daily_quiz.py learn` with its first problem) and `2 识别题`.
  Bulk questions: card agents on `research/agents/recog-questions.md`, each chunk checked with `scripts/recog_review.py`.
- **The two test decks are the main path** (Chi, 2026-11-22): `4 碎片速刷` for system design and `2 算法模式识别` for
  algorithms. They share one design (`scripts/test_cards.py`): a tap-graded front, and a back that shows the answer,
  why, an optional 延伸 line, then the source cards under 原卡. Quick cards he used to grade himself (快问, 找错) are being
  rewritten as choice cards on their own notes (`quick_deck.py tap-export | tap-gate`, briefs
  `research/sysdesign/TAP_AGENT.md` and `TAP_VERIFY.md`). Every batch of test cards gets a writer and then a verifier.
- **LLD and AI are studied through test decks too** (Chi, 2026-11-22): `3 低层设计测验` (1,818 questions, one per card
  of 低层设计（LLD）; it replaced 3 今日低层设计, `lld_deck: false`) and `AI 测验` (868 questions in sub-decks that follow
  the AI reading order: the ai-literacy, llm-inference and ml-system-design cards borrowed by 6 Cerebras, and AI 应用工程).
  Same card design; `scripts/card_tests.py` (`status | todo | review | import-ready | full | chunks`), briefs
  `research/agents/card-test-questions.md` and `card-test-verify.md`. The source decks keep their cards for the backs and
  for reviews and deal no new ones (`caps.zero_under`). `study_plan.py daily` re-copies the source cards onto the backs.
  New source cards: `card_tests.py todo <set>` writes the next chunk; writer, verifier, `review`, `import-ready`.
  Slips the writers and verifiers found in source cards wait in `sources/local/quiz/source-card-issues.md` for Chi.
- **Overview cards (通览), Chi 2026-11-24**: the detail cards of an article lose its shape, so every Hello Interview
  article gets three cards one level above its leaves: 这一章的地图 (one sideways tree that names the blocks and methods, then
  only what the tree cannot show: 关键直觉, 2–4 ideas, and 容易漏的细节; nothing under the tree repeats it),
  做法一览 (each method: what it does; what it solves; its cost) and 什么时候用 (signals, scenarios, when not, common
  follow-ups). Complete, not deep, at most 350 汉字 each. They attach to the article's own node (ADR 0013), come before
  everything below it, and all file into the tour deck through the skeleton's `own_decks`, one sub-deck per chapter
  and under it one per article: `系统设计::00 通览::<NN chapter>::<NN article>` (261 cards: 76 articles, done
  2026-11-24, plus 11 topics that have no article — 估算, 幂等, 可靠性, 排行与检索, 分布式锁 and six payment domains in a
  chapter `07 支付系统` — written from those topics' detail cards on made-up pages `ov.<slug>`, `EXTRA_OV` in gen.py,
  numbered after the chapter's articles so no deck is renamed). A deep dive never borrows them (`deep_dive.TOUR_CARDS`), so the tour stays whole. Other article kinds
  (key technology, problem breakdown, framework page, case study) have their own three titles in the brief; gate

  `research/sysdesign/gen.py` brings a page that has such cards back as its topic's first leaf.

- **Nothing in Anki is deleted by a script.** Retire cards with `scripts/anki_archive.py` (suspend + move, restorable);

- **Samples before bulk.** Show 10–20 cards with `scripts/card_gallery.py` and wait for Chi's word. Tell card agents

## Orchestration rules for multi-agent work in this repo

- The main session orchestrates; **subagents are `sonnet`, at most 3 in parallel, and never spawn their own agents**.
  There is no settings key for this — it is a rule, apply it by passing `model: "sonnet"`.
  When sonnet hits its session limit, relaunch the remaining work on `model: "opus"` (Chi, 2026-09-14).
- Give every relaunchable agent a resume rule in its prompt (check what already exists, skip it),
  and put long shared instructions in one prompt file per group rather than in the Agent call.
- Tasks are atomic: one agent → one directory it owns → one deliverable that is verifiable by
  a command (`pytest`, `check_tree.py`, a row count). No shared files between parallel agents.
- Progress is durable: after every accepted task append a row to the company's `LEDGER.md`,
  update `CHECKPOINT.md` (state + next action), and **commit + push the worktree branch**.
  A new session must be able to resume from `CHECKPOINT.md` alone.
- Usage limits: user settings set `fallbackModel: ["claude-opus-5"]`; if the session dies,
  resume from the ledger, do not redo accepted tasks.
- Git in a worktree: the rtk hook rewrites `git` and the worktree guard then refuses it —
  call `/usr/bin/git ...` in plain, single commands. Merge PRs only when Chi says so.
  Chi set `worktree.bgIsolation: "none"` (2026-09-14); sessions started before that stay isolated
  and cannot run `git -C ~/Code/trellis` — Chi pulls the main checkout from a normal terminal.
  Agents may not edit permission or isolation settings themselves; hand Chi the exact snippet.
- **Review is the orchestrator's job, and the gate is not the review.** For written content: re-derive every number with
  `python3 -c`, check the conclusion is something a product could ship, check the agent's self-reported weakest claims,
  grep for process talk. Small fixes in place; substantive ones back to the same agent with `SendMessage` (it keeps its
  context and returns in ~5 min). Every defect found becomes a rule in the group's instruction file.
- Keep exactly three agents running: when one returns, review, commit, launch the next. Two sibling deliverables per
  agent is the sweet spot (~250k tokens, ~20 min); budget ~130k tokens and ~12 min per problem-sized deliverable.
- Never accept a subagent's "done": re-run `trellis kit verify_suites --co <co> "<glob>"` (reference green **and** empty
  starter red) and `trellis kit check_tree --co <co> --strict` yourself. A 429 usage-limit death leaves partial files —
  salvage and finish them, don't respawn from scratch.

## Gotchas

- The worktree guard rejects heredocs, `for` loops and `$var` in commands: write the script to
  `$CLAUDE_JOB_DIR/tmp/*.py` with Write, then run `python3 <script>`.
- Plain `python3` has no pytest: `uv run --project <worktree> --with pytest python -m pytest ...`; `git checkout uv.lock` if uv touches it.
- macOS `sed -i ''`; relative links from `loop/rounds/<round>/<id>/` to the kit root are `../../../`.
- Counts in prose (cut line, coverage, "N problems") come from a script (`trellis kit pareto|coverage|summary`),
  never from memory — hand counts were wrong twice.
- Paywalled aggregators (trueinterview) still expose intro + part outline via WebFetch: enough to
  rebuild the problem, labelled **(reconstructed)**.
- `uv run trellis --all anki-push` needs desktop Anki running (AnkiConnect on :8765). Company kits are
  not trellis domains: syncing adds no cards for them. A domain with 0 cards builds no deck, so it
  does not appear in Anki until step 4 of `building-study-domains` is done.
- `trellis --all build --lang zh` aborts on the first Chinese-native domain; build without `--lang`.
- `trellis ingest` of `chapters:` URLs needs `uv run --extra clip`; a page under ~2.5k chars of prose
  is skipped as an index.
- `trellis scaffold` prompts carry no language rules; write cards through `digest` or `grow`, which do.
- `python3 -c "…"` that builds a path at runtime is refused by the guard like a heredoc: use a script file.
- Desktop Anki is usually running while tests are: a CLI test that touches Anki must replace `cli._anki_call` with a fake
  (see `tests/test_loop_e2e.py`). `tests/conftest.py` makes the real client refuse, because a fixture deck once reached the live collection.
- The repo is public: a reading for a commercial prep site is tagged `no-archive` (linked, never clipped); `clip` skips it.
  A reading with no `url:` and a real body is an *authored* article and needs no clipping — card footers open it directly.
- Card agents miscompute, contradict their own assumptions and pass off secondhand numbers: the failure table and guards are in
  the `building-problem-banks` skill. Medium-hosted blogs, uber.com, dl.acm.org, w3.org and LeetCode Discuss refuse fetches (same skill).
- `anki-push` can fail with 'Collection lifecycle operation is active' (it imports while its own AnkiWeb sync is still
  running): sync, wait until AnkiConnect answers, `importPackage`, then `trellis --domain <d> anki-align`.
- AnkiConnect (2026-10) refuses `setSpecificValueOfCard` on `due` ('Use native scheduling commands for protected state'), so
  `anki-align` cannot reposition new cards, and `forgetCards` restores the *original* position. For still-new cards with no
  reviews: `deleteNotes` then re-import the apkg — positions follow the package's Sequence order.
- `anki-push` moves a domain's decks onto their own preset `Trellis · <title>` (cloned, deals new cards by position) and
  repositions only cards Anki still calls new. Never write to the shared `Default` preset or to a reviewed card's `due`.
- **Private material never reaches GitHub.** An employer's internals or interview notes a company must not see live only in `sources/local/private/<name>/` (or `vault/private/`, `skeleton/private-*.yaml`, all gitignored) and in Anki, which may sync them to Chi's phone. Never stage them, never quote them in a public file, never send them to another cloud service. `scripts/private_guard.py` runs as pre-commit and pre-push hooks (`scripts/install_private_guard.sh`) against the private term list in `~/.config/trellis/private_terms.txt`; a refusal is never bypassed with `--no-verify`.
- **Before any statistic or report from Anki, sync first:** `git pull`, then AnkiConnect `sync`, waiting until it answers again, and only then read or add anything up. Chi studies on his phone, so without a sync the desktop collection misses those reviews and every number is wrong.
- A new system-design card or LeetCode problem must be annotated, or the daily planner gives it no weight: exam points for cards, technique and pitfall tags for problems. A new exam point also needs its prerequisite edges. `scripts/plan_maintain.py` lists what is missing.
- The quick deck (碎片速刷, ten-second cards; `scripts/quick_deck.py`, card data only in `sources/local/quick/`) is planned by
  `scripts/quick_plan.py`, called from `study_plan.py daily`: one priority per unseen card from the answers so far, sorted and cut at
  the day's number. The cut is made with decks (the day's cards in the deck, the rest in `碎片速刷::后备`, whose preset deals 0 new),
  because new-card positions cannot be written. Options on those cards carry `class="tappable"` and `onclick`: without them
  AnkiMobile reads every tap as "show answer".
- Every note type ends with the fields `Note` and `NoteAnswer` (`trellis/build.py` `NOTE_FIELDS`). Chi writes questions
  into `Note` on the phone; `scripts/card_notes.py` lists them and starred cards (`marked`) and writes explanations into
  `NoteAnswer` (rules in `docs/card-notes.md`). A build or refresh never writes these two fields. A new note type gets them
  too, at the end, or its notes have nowhere for Chi's questions. Adding a field to a note type that exists forces a
  one-way full sync. AnkiConnect refuses a full sync, so the upload is done once in the desktop app. Importing a whole
  package over existing notes (`anki-push`) would blank both fields.
- Anki lists decks only alphabetically. The daily decks carry numbers so they sort first (1 每日测验, 2 算法模式识别,
  3 低层设计测验, 4 碎片速刷; 今日计划 and 今日算法 were retired on 2026-11-21 and 今日低层设计 on 2026-11-22: `plan_deck` / `lc_deck` / `lld_deck: false`); their presets kept the old names (`PLAN_PRESET`, `quick_deck.PRESET`). Rarely used
  domains live under `📦 其他` through their skeleton's `deck:`. Rename a deck with Anki closed (`col.decks.rename`):
  AnkiConnect cannot, and a running Anki keeps the old names.
- `5 系统设计高频题` (scripts/deep_dive.py, run inside `study_plan.py daily`): one design question a day, all its cards
  in teaching order, plus due cards of questions done before. The next question is the one adding the most exam-point
  coverage; its sub-deck names the coverage once learnt. Its cards leave every other part of the plan. State:
  `sources/local/plan/deepdive.json`.
- A new domain reaches Anki with `scripts/anki_refresh.py --add <id-prefix> <domain>`, then `trellis --domain <d>
  anki-align` for its preset: no other deck is touched and the `Note` fields stay. `scripts/knowledge_tree.py` draws only
  nodes that have cards; a domain that keeps uncarded leaves on purpose writes its own full map (`psych`).
- Card agents that research the web share 200 searches a turn and the account's usage window: five in parallel ran out
  in about 20 minutes. Budget searches in the brief and have agents write card by card (skill `building-study-domains`).
- A leaf is weak only on cards with a verdict (taken / slipped); young cards are not evidence, and a weak leaf whose grown
  cards are unreviewed is *settling* and is not a `grow` target (ADR 0009).
