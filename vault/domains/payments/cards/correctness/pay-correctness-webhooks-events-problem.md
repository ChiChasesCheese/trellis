## Q
PSP 的异步通知（webhook）在支付系统里扮演什么角色？它为什么既重要又不可靠？

## A
**webhook** 是 PSP 在事件发生后，主动向你的 HTTP 接口推送通知，如支付成功、退款完成、拒付发起、打款到账。

**为什么重要**：很多状态只能异步得知——3DS 之后的授权结果、银行转账到账、退款最终成功、拒付、打款退票。同步响应只回答"受理了没有"。

**为什么不可靠**
1. **重复**：你的服务超时或返回非 2xx，PSP 会重发，同一事件可能收到多次。
2. **乱序**：不同事件走不同的重试路径，后发生的可能先到。
3. **丢失**：你的服务宕机或发布期间，PSP 重试耗尽后放弃（通常几天内重试几十次）。
4. **伪造**：公开的 URL 可能被攻击者发送伪造的"支付成功"。
5. **延迟**：事件可能比同步响应晚几分钟甚至几小时到。

**设计目标**
- 验证真实性（签名）。
- 至少一次投递下做到效果恰好一次（去重 + 幂等）。
- 乱序下状态不倒退（状态机守卫）。
- 丢失时能补偿（主动查询、对账）。
- 事件可保存、可重放，便于排查和修复。

**核心定位**：webhook 是**提示**，不是唯一的真相来源；状态的最终依据是 PSP 的查询接口和结算文件。
