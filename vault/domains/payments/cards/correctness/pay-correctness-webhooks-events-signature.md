## Q
怎么验证一条 webhook 确实来自 PSP，并且没有被重放？为什么要用原始请求体？

## A
**签名校验**（以常见的 HMAC 方案为例）
1. PSP 和你共享一个密钥（secret），保存在你的密钥管理里。
2. PSP 发送时计算 `HMAC-SHA256(secret, timestamp + "." + raw_body)`，把签名和时间戳放在请求头。
3. 你收到后用同样的方式计算，与头里的签名**常量时间比较**（避免时序攻击）。
4. 不一致则返回 4xx 并丢弃，记录告警。

**防重放**：签名里包含时间戳，你检查时间戳与当前时间的差在容差（如 5 分钟）内；超出视为重放攻击。合法的重试会带新的时间戳和新的签名。

**为什么要用原始请求体**：签名是对原始字节算的。如果你先把 JSON 解析再重新序列化，空格、字段顺序、数字格式（1.0 与 1）都可能变化，计算出的签名对不上。所以框架里要拿到未解析的 raw body。

**其他防线（辅助，不是唯一）**
- IP 白名单：只是辅助，PSP 的 IP 会变，且不能替代签名。
- 密钥轮换：支持两个密钥同时有效，平滑切换。
- HTTPS：必须。

**签名通过也不能盲目信任内容**：处理金额时，以你自己数据库里的订单金额为准，核对 webhook 里的金额与币种是否一致，不一致告警。关键状态还可以收到 webhook 后调用 PSP 查询接口二次确认。
