## Q
面试官问"用户余额怎么扣，怎么防止并发超扣，热点账户怎么办"，怎么回答？

## A
**一句话**：余额存成字段，用条件更新在数据库里原子扣减，分录同事务；预留用冻结；热点账户靠分桶或异步汇总。

**要点**
1. **模型**：账面余额 = 分录汇总；可用 = 账面 − active 冻结；余额字段是缓存，与分录同事务更新，并定期重算校验。
2. **防超扣**：`UPDATE ... SET balance = balance - x WHERE id = ? AND balance >= x`，影响行数为 0 即拒绝；再加 CHECK 约束做兜底。对比悲观锁和乐观锁，说明为什么条件更新最合适。
3. **冻结的状态机**：active → captured / released，业务引用唯一，转移用条件更新保证幂等；未知结果的冻结不得自动释放。
4. **热点账户**：先算数（持锁 2 毫秒，单行约 500 次每秒），再区分是否需要实时余额：不需要的（手续费收入）分桶或异步汇总，需要的（用户钱包）靠分库分表分散。
5. **监控**：冻结超龄、重算差异。

**追问预判**
- 冻结和扣款在一个事务还是两个？创建冻结一个事务，转扣款一个事务，都幂等。
- 为什么不直接扣再回滚？失败路径要补偿，用户看到余额抖动，且无法表达未知状态。
