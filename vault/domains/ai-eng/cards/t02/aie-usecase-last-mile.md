## Q
**Use case evaluation · 演示容易，最后一段难**｜考点 · 必会

周末你做出了一个客服机器人 demo，效果惊艳，老板说"下个月上线"。你怎么给老板定预期？该先写下哪些指标？

## A
**现实：** 基础模型已经很强，做出一个好看的 demo 很快（可能一个周末）；做成产品可能要几个月甚至几年。"从 0 到 60 容易，从 60 到 100 极难"。

**LinkedIn（2024）的例子：** 一个月就做到想要体验的 80%；再花了四个月才超过 95%。很多时间花在细节和处理 hallucination（模型编造不实内容）上，每提高 1% 都很慢。

**上线前先写下成功标准：**

| 类别 | 例子 |
|---|---|
| 业务指标（最重要） | 自动化多少比例的客户消息？节省多少人力？响应快多少？客户满意度 |
| 质量指标 | 回答质量 |
| 延迟指标 | TTFT（首 token 延迟）、TPOT（每个输出 token 的时间）、总延迟 |
| 成本指标 | 每次请求成本 |

**usefulness threshold（可用门槛）：** 达到什么分数才算有用。以此为标准做 milestone：例如目标自动化 60% 的工单，现成模型已能自动化 30%，要补的就比从 0 开始少。

**评测后目标可能改变：** 也许发现要达到门槛的投入超过回报，那就不做。

**回到题目：** 告诉老板 demo 只说明"方向可行"，用评测定义可用门槛，按评测结果排时间，并预留最后 20% 的时间。

**出处：** Huyen《AI Engineering》ch1 §Setting Expectations、§Milestone Planning
