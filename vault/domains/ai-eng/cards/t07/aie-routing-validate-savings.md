## Q
**Model routing · 成本省了，质量降了吗**｜考点 · 必会

上线 cascade 后账单降了 40%，产品说"太好了"。你要在庆祝前验证什么？

## A
**省钱是确定的，质量下降是要验证的。**

| 要查 | 怎么查 |
|---|---|
| **路由准确率** | 一批标注样本上，router 把"该给强模型"的请求错给小模型的比例（漏升级）；把简单请求给了强模型的比例（浪费） |
| **分层质量** | 在评测集上**分别看小模型处理的那部分和大模型处理的部分**的质量；并与"全部给强模型"的基线比较 |
| **把握度是否可靠** | 小模型"有把握"时，真的对吗？（用 logprobs 或自评的把握度，在带标注的集合上看校准） |
| **延迟** | 升级的请求要等两次，总延迟变长 |
| **分切片** | 哪类问题被降级、效果掉得最多（语言、长度、主题） |

**决策：** 质量下降要换算成业务指标（解决率、满意度），再和节省的成本比；通过阈值调节"升级比例"来在两者间取舍。

**别忘了回归：** router 和阈值也是会漂移的组件，进入回归测试和监控；路由到不同模型后，注意不同模型对同一个 prompt 的表现不一样，要各自测。
