## Q
**Explicit 与 implicit user feedback**｜摘要 · 必会

产品上线后，除了点赞点踩，还能从用户的哪些行为里读出"这个回答好不好"？各有什么可靠性问题？

## A
| | Explicit（显式） | Implicit（隐式） |
|---|---|---|
| 是什么 | 用户**被明确询问**后给的：点赞/点踩、星级、"问题解决了吗" | 从用户**行为**读出来的 |
| 优点 | 容易解读 | 更多、更便宜 |
| 缺点 | **稀疏**，用户要多做一步；有回应偏差（不满的人更爱抱怨） | **更噪**，同一行为含义不明确 |

**对话式产品里的隐式信号：**

| 信号 | 含义 |
|---|---|
| 提前终止（中途停止、退出、不回应） | 对话可能进行得不好 |
| 纠错（"不，……"、"我的意思是……"、重新表述） | 回答偏了 |
| 要求确认（"你确定吗？""给出来源"） | 缺细节，或不信任 |
| 直接编辑模型的输出 | 很强的信号：被改的部分不对；还可作为偏好数据（原回答为输家，修改后为赢家） |
| 抱怨、负面情绪、拒答率 | 用户不满 |
| 重新生成 | 可能不满意，也可能只是想比较（创意类任务多） |
| 删除、重命名、分享对话 | 删除多为负面；重命名说明标题不好；分享可正可负 |
| 对话轮数 | 陪伴类产品越长越好，客服类越长越糟 |
| 对话多样性 | 长但一直重复，用户可能卡住了 |

**要点：** 同一信号在不同产品里含义不同，要研究用户为什么这么做；加上其他信号可以澄清意图（例如分享之后又重新表述，说明对话没满足预期）。

**用途：** 评测（做监控指标）、开发（训练或指导新模型）、个性化。
