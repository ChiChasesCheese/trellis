## Q
**挑战。** 让一个编程智能体把 300 个文件从旧的日志库迁到新的，预计跑 6 小时。试跑发现：到第 3 小时它开始重复改已经改过的文件，也忘了你们约定的命名规则，而且每一圈越来越慢、越来越贵。请设计这个任务的上下文方案，不换模型。

## A
**评分点（答出 3 条算过）：**

1. 把状态放到窗口外：一个进度文件或 JSON 清单，列出 300 个文件和状态（待办、完成、需要人看），每改完一个就更新，新窗口开头先读它。
2. 命名规则写进 CLAUDE.md 或任务模板，每次会话都会重新读入，不依赖对话历史。
3. 拆分并隔离：把文件分成批次，每批交给子智能体或新会话，主窗口只收到"完成了哪些、失败了哪些"的摘要。
4. 控制窗口里的垃圾：清理旧的工具输出，大文件分段读取，必要时手动压缩并指定要保留的内容。
5. 每批后做验证并提交（编译、测试、git 提交），出错可以回退，也让"完成"有客观依据。

<details class="pt"><summary>参考答案</summary>问题在于所有状态都靠窗口里的对话保存，窗口满了就被压缩丢失，而且每圈要重送全部历史。做法是把状态移到文件：进度清单记录每个文件的状态，命名规则写进 CLAUDE.md，每个新窗口先读它们。把 300 个文件分批，每批交给子智能体，它们在干净窗口里工作，只回传简短摘要。每批结束后跑编译和测试并提交，既能回退，又能证明真的完成。</details>
