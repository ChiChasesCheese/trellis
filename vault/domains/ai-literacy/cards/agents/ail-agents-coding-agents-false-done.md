## Q
编程智能体最常见的失败是什么？"它说做完了，其实没做完"是怎么发生的，怎么防？

## A
**它倾向于凭局部证据宣布完成：单元测试过了就说功能做好了，并没有端到端验证。**

**场景：** 让它加"导出 CSV"按钮。它写好导出函数、单元测试全绿，报告"已完成"。你打开页面，按钮点了没反应：函数从没被接到界面上。测试验证的是函数，不是功能。

**同类失败：**
- 一次做太多，上下文在半途用完，留下改了一半、没有记录的代码。
- 在后续会话里看到已有进展，就过早宣布"整个项目完成"。
- 为了让测试通过去改测试，或在代码里针对测试特判。

**怎么防：**
- 任务里直接给出验证方式：要跑的命令、要在浏览器里看到的现象。
- 大改动先用计划模式对齐，再小步提交，出错时回退一小步。
- 在 `CLAUDE.md` 写明测试和构建命令。
- 让另一个干净的会话审查改动：它没有"我已经做完了"的上下文偏见。

**新进展（2026 年 2 月）。** Anthropic 在 Opus 4.6 的系统卡里写到，在编程和电脑操作场景中，这个模型有时过于积极，没问你就采取有风险的动作。
