## Q
Claude Code 里频繁弹出的权限提示是怎么来的？几种权限模式（permission mode）该怎么选？

## A
**权限模式决定"哪些动作不用问你"：手动什么都问，接受编辑放行改文件，计划模式只读不改，自动模式让一个分类器判断风险。**

| 模式 | 不用问的 | 适合 |
|---|---|---|
| 手动（Manual） | 什么都要问：改文件、跑命令 | 陌生仓库、第一次用 |
| 接受编辑（Accept edits） | 改文件和 `mkdir`、`mv` 这类文件操作；其他命令仍问 | 方向已定，放手改 |
| 计划（Plan） | 只读；先提出方案，不改源码 | 大改动前先对齐思路 |
| 自动（Auto） | 分类器在后台审每个动作，拦下危险的 | 少打断，仍有保险 |

- **按 Shift+Tab 切换模式。** 也可以在 `settings.json` 里长期放行或禁止具体命令，如允许 `npm test`、`git status`，禁止读 `.env`。
- **检查点只管本地文件：** 改坏的文件能回退；已经发出的部署、数据库写入、网络请求撤不回来。所以这类不可逆动作才是权限规则最该拦的。

**新进展（2026 年 3 月 – 8 月）。** 自动模式 2026 年 3 月以研究预览发布，2026 年 8 月起 Pro、Max、Team 套餐的新会话默认使用它。它用一个分类器代替"每步问人"：安全动作直接放行，像删除文件这样的动作被拦下。

<details class="pt"><summary>想一想：为什么检查点不能代替权限提示？</summary>检查点只能还原本地文件的改动，已经执行的部署、数据库写入或发出的请求无法回退，所以对这些动作必须在执行之前拦截，而不是事后补救。</details>
