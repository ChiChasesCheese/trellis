## Q
固定流程（workflow）和智能体（agent）有什么区别？什么时候该用哪一种？

## A
**区别只有一个：下一步由谁决定。写死在代码里的是 workflow，由模型在运行时决定的才是 agent。**

workflow 里模型也被调用很多次，但调用顺序是程序员画好的。常见五种：

| 模式 | 做法 | 例子 |
|---|---|---|
| 提示链（prompt chaining） | 上一步输出喂下一步，中间可加程序检查 | 先写大纲，检查，再写正文 |
| 路由（routing） | 先分类，再走对应的提示或工具 | 客服问题分成退款、技术、其他 |
| 并行（parallelization） | 同时跑多次再合并：分段，或投票 | 三次独立审查代码，取共同意见 |
| 协调者-工人（orchestrator-workers） | 一个模型运行时拆任务，交给工人模型 | 改动涉及几个文件事先不知道 |
| 评估者-优化者（evaluator-optimizer） | 一个写，一个挑错，循环到满意 | 翻译初稿再润色 |

**怎么选：**
- 先试最简单的：一次调用加检索和几个例子，很多场景已经够用。
- 路径可预知（退款流程固定四步）：用 workflow，可预测、便宜、好测。
- 步数无法事先写死（排查一个陌生仓库的 bug）：才用 agent。
- 代价：更慢、更贵、错误会累积，所以要在沙箱里充分测试，信任度只给到你能验证的程度。

实际产品多是混合：外层是固定流程，只在"开放"的那一步放一个小智能体。
