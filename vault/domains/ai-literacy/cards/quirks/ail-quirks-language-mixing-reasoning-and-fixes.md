## Q
推理模型的"思考"里也会冒出中文或别的语言，这是怎么回事？写中文应用时怎么减少串语言？

## A
**强化学习只奖励"答对"，不管思考用什么语言，模型就滑向对自己最顺手的语言；DeepSeek-R1 的修法是加"语言一致性奖励"，代价是准确率略降。**

- **R1 的做法：** 没有这项奖励的 R1-Zero，训练越久混用越严重；一致性奖励按思考里目标语言词的占比计分，加上后稳定，论文承认性能略降。
- **没有定论：** 有研究让推理只用拉丁或汉字脚本，准确率明显上升；也有研究发现禁止混用会降准确率。模型内部可能有"枢纽语言"（英语，其次中文），属「推测」。

**用的时候：**

- 系统提示写明"只用简体中文回答，不出现日文假名和韩文"：能压低概率，但用户反馈里仍有指令被忽略的例子，不是保证。
- 上下文里混着大量英文、日文的工具输出和网页，会把语言拉偏：压缩或开新会话。
- 要硬保证，就在代码里检查，命中就重试一次（抽样有随机性，重试多半就好）：

```python
import re
BAD = re.compile(r"[぀-ヿ가-힯]")  # 假名、谚文

def mixed(text):
    return bool(BAD.search(text))
```

**新进展（2025 年 5 月）。** 一项覆盖 15 种语言的研究发现，推理轨迹里的文字混用和模型内部表示吻合；用约束解码（抽样时屏蔽某些字符）让推理只用拉丁或汉字脚本，准确率明显提高。

<details class="pt"><summary>想一想：约束解码屏蔽字符，和 R1 加一条奖励相比，各有什么好处和风险？</summary>屏蔽字符是在抽样时直接保证不出现，不靠训练；风险是误伤需要引用日文原文的场景，也改变了模型自然的输出分布。奖励是软约束，保证不了，但不会硬砍。</details>
