## Q
你想证明"模型真的变笨了"，而不只是感觉。要怎么测，才不被噪声骗？

## A
**建一组固定的金丝雀（canary）测试：固定提示、固定版本号，每天每题跑多次，只看通过率的变化；单次对比毫无意义，因为同一个模型本来就会抖。**

```python
def pass_rate(cases, run, n=20):
    ok = total = 0
    for case in cases:
        for _ in range(n):
            ok += run(case)   # 通过记 1，否则 0
            total += 1
    return ok / total
```

- **噪声有多大：** 通过率 80%、跑 100 次，标准误差约 4 个百分点；比较两个这样的结果，差值的标准误差约 5.7 个点。差 5 个点完全可能是运气，要差 11 个点以上才有把握。
- **固定版本：** 用带日期的版本号，不用会被悄悄指向新版本的别名。
- **同时记录：** 版本号、入口（API 或应用）、时间、输出长度、停止原因；输出突然变短，往往是提示变了。
- **分入口测：** 2026 年 4 月的故障只出在 Claude Code，直接调 API 并没有变；只测一个入口会得出相反的结论。

**新进展（2026 年 4 月）。** 复盘说，那条限制啰嗦的系统提示，是在更大的评测集上逐行消融（每次去掉一条再测）才测出：Sonnet 4.6、Opus 4.6 和 Opus 4.7 的编码质量下降约 3%。Anthropic 之后承诺，每次系统提示改动都要在每个模型上跑更广的评测，并分阶段发布。

<details class="pt"><summary>想一想：3% 的下降，为什么你自己跑几十个例子几乎看不出来，厂商却能测到？</summary>几十个例子的标准误差有好几个百分点，3% 的变化淹没在噪声里；厂商用大得多的评测集，并且逐条消融，只改一个变量，噪声小得多，才能看见这样细的差异。</details>
