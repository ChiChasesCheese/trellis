## Q
**挑战。** 一个编程助手聊了三个小时后，用户抱怨两件事：它忘了开头说好的"不许改数据库表结构"，随后接口又开始返回 400 错误 "prompt is too long"。你是开发者，怎么解释这两件事、怎么修？

## A
**评分点（答出 3 条算过）：**

1. 解释 400：每轮都重发全部历史，输入本身超过窗口上限，接口直接拒绝。
2. 解释"忘了"：即使没超限，长输入里旧约束被稀释（上下文腐烂、中间内容易被忽略），模型对它的利用变弱。
3. 修法之一：发送前用 token 计数接口估算，接近上限时把旧对话压缩成摘要，或清理体积大的旧工具输出。
4. 修法之二：把"不许改表结构"这类硬约束放进系统提示，或在每轮末尾重复一次，而不是只留在对话开头。
5. 压缩摘要有损：约束、目标、当前状态三类信息必须在摘要里保留；必要时开新会话并带上摘要。

<details class="pt"><summary>参考答案</summary>400 说明单次输入已超过窗口，因为每轮都把整段历史重新发送；"忘了约束"是另一回事，长输入里早期内容被稀释，模型不再可靠地使用它。解决办法是发送前计数，接近上限就压缩历史并清理旧的大块工具输出，同时把硬约束放进每次都会发送的系统提示或消息末尾。摘要要明确保留约束、目标和当前进度，否则压缩本身也会丢掉约束。</details>
