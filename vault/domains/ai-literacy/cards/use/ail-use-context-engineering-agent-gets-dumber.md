## Q
一个跑了两小时的编程智能体开始重复读同一个文件、忘了你的约束。这是模型变笨了吗？怎么查、怎么修？

## A
**多半不是模型变笨，而是窗口被旧工具输出、走过的弯路和一堆工具定义填满，真正重要的指令被稀释了。**

| 原因 | 现象 | 修法 |
|---|---|---|
| 旧工具输出堆积 | 早先 cat 过的大文件还留在窗口里 | 清理旧结果；只读需要的行 |
| 失败的尝试留在历史里 | 模型模仿自己之前的错误做法 | 压缩时丢掉死胡同；必要时开新会话 |
| 工具定义太多 | 约 5.5 万 token 的工具定义，占 20 万窗口的 27% | 按需加载工具；只留常用的 |
| 关键约束埋在中间 | 开头说好的规则不再被遵守 | 约束写进项目说明文件，每次重新载入 |

**怎么查：** 看每次请求的 token 用量，把窗口按"系统提示、工具、历史、检索结果"分块统计，先砍最大的那块；很多时候一个大块占了一半。

**怎么修的顺序：** 先清理（最便宜），再压缩，再换成子智能体做搜索，最后才是换更大的窗口或更强的模型。

**案例：** 搜索 20 个文件找一个函数，主窗口读进去 20 个文件的内容；改成交给子智能体搜索，主窗口只收到"在 utils.py 第 88 行"，省下 20 个文件的 token。
