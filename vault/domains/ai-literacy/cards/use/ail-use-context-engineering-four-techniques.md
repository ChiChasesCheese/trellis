## Q
窗口快满时有哪几招？压缩、清理工具结果、笔记、子智能体各适合什么，各丢掉什么？

## A
**四招：压缩（摘要后继续）、清理旧工具结果、结构化笔记（写到窗口外）、子智能体（用干净窗口干活，只回传摘要）。**

| 手段 | 做法 | 丢掉什么 |
|---|---|---|
| 压缩（compaction） | 把长历史总结成摘要，换掉原文继续 | 细节；摘要有损 |
| 清理工具结果 | 删掉旧的大块输出（整个文件、长日志），留下"调用过"的记录 | 原始输出，需要时重新调用 |
| 结构化笔记 | 智能体把进度、决定写进文件（如 NOTES.md），新会话读回来 | 要它主动写，没写就没了 |
| 子智能体（subagent） | 子任务在新窗口里做，只返回约 1,000–2,000 token 的摘要 | 中间过程 |

- **在 Claude Code 里：** 手动 /compact 或自动压缩就是第一招；子智能体做大范围搜索时，几十个文件的内容留在它自己的窗口，主窗口只收到结论。
- **取舍：** 压缩最通用但有损，笔记最可靠但要靠智能体自觉，子智能体最干净但要多花一次调用。

**新进展（2026 年 2 月）。** 压缩成了接口内置功能：Claude 4.6 及之后的模型支持服务器端压缩（beta），快到窗口上限时，由服务器把前面的对话总结掉，对话可以超过窗口继续进行。

<details class="pt"><summary>想一想：压缩后，早期说好的一条约束被摘要丢了，怎样设计才能避免？</summary>把硬约束放进每次都会重新发送的系统提示或项目说明文件，而不是只留在对话历史里；摘要的要求里也要明确"必须保留约束、目标和当前状态"。</details>
