## Q
语义检索什么时候会找错？给出几个典型情形和对策。

## A
**嵌入捕捉的是"主题相近"，不是"逻辑相同"：否定、精确标识、换了嵌入模型、过长的文本和近似索引，都会让它找错。**

| 情形 | 例子 | 对策 |
|---|---|---|
| 否定和反义 | "支持退款"与"不支持退款"向量几乎一样 | 重排，或让模型读原文判断 |
| 精确标识 | 查错误码 E-4021，近邻却是 E-4012 | 混合检索，加关键词（BM25） |
| 换了嵌入模型 | 新旧模型的向量不在同一空间，混用无意义 | 整库重新嵌入，记录模型版本 |
| 降维或量化过度 | 为省存储截到 256 维，召回明显下降 | 在自己的标注集上测 recall@k |
| 近似索引漏召回 | 为了速度，真正最近的没被找到 | 调大搜索宽度（如 HNSW 的 ef_search），测召回 |
| 块太长 | 一个向量里混着多个主题，谁都不像 | 切小块，每块一个主题 |

- **排行榜只是参考：** 公开榜单（如 MTEB）排名靠前的模型不一定适合你的语料；拿自己的 50–100 个真实问题做一次小评测最可靠。
- **新鲜度：** 文档更新后，旧向量要及时删除或重算，否则搜到的是过期内容。

**案例：** 搜索"如何关闭自动续费"，向量检索把"如何开启自动续费"排在第一，因为两句话主题几乎相同；加上重排后正确的页面才排到前面。
