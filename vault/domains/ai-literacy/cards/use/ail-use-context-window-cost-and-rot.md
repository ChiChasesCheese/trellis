## Q
窗口越塞越满，会出什么问题？一个 50 轮的客服对话，输入 token 总共要付多少？

## A
**塞得越满，越贵、越慢、也越不准：每轮都重发全部历史，累计输入按轮数的平方增长，而且模型对长输入的利用并不均匀。**

**算一笔账：** 每轮问答新增约 1,000 token，第 k 轮要发送 k × 1,000 token。
- 50 轮累计输入 = 1,000 × (1 + 2 + … + 50) = 1,000 × 1,275 ≈ **128 万 token**，而真正的新内容只有 5 万。
- 按每百万 2 美元（Sonnet 5.5）约 2.55 美元，且不含输出。

| 问题 | 原因 |
|---|---|
| 变贵 | 每轮重发，累计 ≈ 轮数² |
| 变慢 | 输入越长，首个 token 出来前的预填充（prefill）越久 |
| 变不准 | 上下文腐烂（context rot）：token 越多，召回和准确度越下降，窗口远没满时就开始 |

**新进展（2025 年 7 月）。** Chroma 的研究对多个前沿模型加入干扰内容、改变输入结构后发现：输入变长，表现不均匀地下降，而只测"大海捞针"的评测会高估长上下文能力。Anthropic 的文档现在直接用"context rot"这个词，提醒"放什么"和"能放多少"同样重要。

<details class="pt"><summary>想一想：既然窗口有 100 万，为什么不把整个公司知识库每次都塞进去？</summary>每次请求都要为全部 token 付费并等待预填充，准确度还会随长度下降；只放与问题相关的几段，通常又便宜又准。</details>
