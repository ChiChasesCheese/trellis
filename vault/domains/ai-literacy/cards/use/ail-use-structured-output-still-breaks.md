## Q
线上解析模型的 JSON 仍然偶尔报错或数据不对，可能是哪些原因？

## A
**"合法 JSON"不等于"业务正确"，而且有些失败发生在约束之外：被截断、没开约束、内容错但格式对、schema 改了。**

| 场景 | 现象 | 对策 |
|---|---|---|
| 被截断 | 输出很长，达到 max_tokens，JSON 缺了右括号 | 检查 stop_reason；留足 token；字段别太多 |
| 没开约束，只在提示里写 | 偶尔多出"好的，以下是结果："或 markdown 围栏 | 开 schema 模式，不要自己用正则去剥壳 |
| 内容错但格式对 | refund_amount 应为 120，模型填了 1200 | 业务校验：范围、与订单核对 |
| 枚举太宽 | 有"其他"一项，什么都往里放 | 细分类别；加"不确定"选项并监控占比 |
| schema 演进 | 加了必填字段，旧版客户端解析失败 | 版本号；先加可选字段再收紧 |

- **别逼模型填它不知道的字段：** 必填字段而资料里没有，模型会编一个合法的值；允许 null 或"未提供"，再统计缺失率。
- **验收：** 用带标签的样本，按字段统计准确率；格式合规率几乎 100% 之后，准确率才是真问题。

**案例：** 工单分类的枚举里有"其他"，上线一个月后 40% 的工单落进了"其他"，格式全部合法，但统计图表已经没有信息量；这类问题要靠监控分布发现。
