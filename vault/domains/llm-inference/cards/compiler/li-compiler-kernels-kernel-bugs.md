## Q
自定义 GPU 内核（kernel）常见哪些缺陷？哪些工具能帮助发现它们？

## A
**内核：** 在 GPU 上成千上万个线程并行执行的函数。并行和手工管理内存带来了普通代码里少见的缺陷类型。

**常见缺陷：**
- **越界读写：** 数据长度不是块大小的倍数时，最后一块没有屏蔽越界的下标。可能读到垃圾数据（结果偶尔错误），或写坏别的张量（错误出现在完全不相关的地方）。
- **竞争条件（race condition）：** 多个线程读写同一块共享内存，缺少同步屏障（如 CUDA 的 `__syncthreads()`），一个线程读到了另一个线程还没写完的数据。结果随机出错，难以复现。
- **累加精度：** 累加器用了低精度（BF16 而不是 FP32），短向量测试正常，长归约维度时误差很大。
- **对齐假设：** 内核假设地址是 16 字节对齐、或张量是连续存储的。传入切片、转置后的张量时出错。
- **特殊值处理：** 输入含有 inf 或 NaN、全为 0、或者 softmax 一整行都被掩码屏蔽（全是负无穷，计算 0/0 得到 NaN）。
- **形状特化的分支：** 内核对不同形状走不同的代码路径（比如小批量时拆分归约），某条路径很少被测试到。

**发现工具：**
- **`compute-sanitizer`（NVIDIA）：** 运行时检查内存错误。
  - `compute-sanitizer --tool memcheck python test.py`：越界和非法访问；
  - `--tool racecheck`：共享内存的竞争条件；
  - `--tool initcheck`：读取未初始化的显存。
  - 程序会慢几十倍，只在测试中使用。
- **`CUDA_LAUNCH_BLOCKING=1`：** 让每次内核启动同步执行，错误在出错的那一次调用处报出，而不是之后某个不相关的位置。
- **数值对比：** 和 FP32 或 FP64 的参考实现比较，配合大范围的形状和数据类型扫描。
- **重复运行比较：** 同一输入跑 100 次，结果应逐位相同；不同说明存在竞争或使用了原子操作。
- **哨兵填充：** 在输出张量前后多分配一段内存并填入固定值，运行后检查这段内存是否被改写，能抓到越界写。

**测试设计原则：** 形状集合必须包括 1、质数、块大小的倍数及其 ±1、超大尺寸；数据包括随机值、极端值、特殊值；内存布局包括连续、转置、切片。
