## Q
在推理的每一步里，运行时怎样安排主机和设备之间的数据搬运和计算，才能让设备不空等？有哪些常用技术？

## A
**一步推理里主机要做的事：** 准备输入（这一步每个请求的 token 编号、位置编号、KV 缓存块表），拷贝到设备，启动几百个计算内核（在设备上运行的函数），取回结果（每个请求新生成的 token），更新状态。

**问题：** 设备计算一步可能只要几毫秒，而主机上的准备、内核启动、取回如果串行执行，也要毫秒级。设备在这段时间里空等。

**常用技术：**
- **双缓冲（double buffering）与异步拷贝：** 设备在算第 N 步时，主机已经把第 N+1 步的输入准备好，用另一条命令队列（流）通过 DMA（由硬件引擎直接搬数据，不占 CPU）异步拷贝过去。需要锁页内存（操作系统保证不会换出的内存）。
- **CUDA Graph（或其他设备上的"预录制执行"）：** 把一整步的几百个内核启动录制成一张图，之后只需一次提交。省掉每个内核几微秒的启动开销，主机侧的工作大幅减少。代价是形状必须固定，所以按一组固定批大小分别录制。
- **异步调度：** 调度器提前一步做决策，下一步的调度和当前步的计算重叠。难点是下一步的输入依赖当前步生成的 token，需要在设备上直接把结果接到下一步的输入里，不经过主机。
- **减少同步点：** 避免每步把大量数据拷回主机；只取回必须的新 token 编号。
- **持久化数据：** 权重和 KV 缓存始终留在设备上；只有每步变化的小数据在主机和设备之间来回。

**在空间数据流芯片上的对应问题：** 模型常驻在芯片上，运行时持续把新请求的输入送进去、把生成的 token 取出来。设备生成极快时（每秒上千 token），主机侧的流式输入输出、分词、网络发送更容易成为瓶颈。

**怎么测：**
- **时间线：** Nsight Systems 看设备时间轴上的空隙，以及空隙期间主机在做什么。
- **主机开销指标：** 测量"每步主机耗时"和"每步设备耗时"，二者之比随批大小、模型大小变化。小模型、小批量时主机开销占比最高，是最容易暴露问题的配置。
- **开关对比：** 关闭 CUDA Graph（vLLM 的 `--enforce-eager`）对比每 token 间隔，直接看出启动开销的大小。
