## Q
面试里被问"推理栈里的 runtime 做什么？你会怎么测试它？"，怎么答？

## A
按这个顺序说：

- **定位：** 引擎管请求和批，编译器把模型变成设备程序，运行时管执行：加载编译产物并校验版本兼容，分配和管理设备内存，在主机和设备、设备和设备之间搬数据，按依赖提交计算并同步，把设备错误翻译给上层，提供计时和内存观测。
- **关键机制：** 执行是异步的，命令进入流（队列）后主机立即返回；用多条流和事件让拷贝与计算重叠，配合锁页内存和 DMA；用 CUDA Graph 一类的预录制执行减少启动开销；设备内存用缓存分配器和预分配池，KV 缓存按固定块管理以避免碎片。
- **功能测试：** 加载不兼容版本的产物要明确报错；内存分配与释放在长时间运行后不泄漏，用 `memory_allocated` 曲线和内存快照检查；极端输入下峰值内存在预算内；跨流依赖正确，用高负载和同步调试模式去抓竞争。
- **性能测试：** 用 Nsight Systems 看设备时间线上的空隙和主机同步点；分别测每步主机耗时和设备耗时，小模型小批量时最容易暴露主机开销；对比开关 CUDA Graph 的差异；测模型加载和冷启动时间。
- **故障测试：** 注入内存不足、挂起、非法访问、版本不匹配、设备掉线，验证单请求错误不扩散、设备级故障被健康检查发现并快速摘除、正在处理的请求得到明确错误而不是挂起。
- **兼容矩阵：** 运行时、驱动、固件、编译器各自升级，我会维护已验证的版本组合，每次升级都跑完整回归，并在每条测试结果里记录硬件和版本标识。
