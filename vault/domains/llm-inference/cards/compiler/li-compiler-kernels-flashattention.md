## Q
FlashAttention 解决了标准注意力实现的什么问题？分块（tiling）和在线 softmax（online softmax）是怎样工作的？

## A
**标准注意力的实现：** 对长度为 N 的序列，每个头先算出分数矩阵 `S = Q Kᵀ`（N × N），写回显存；再读出来做 softmax 得到 P，写回显存；再读出来乘以 V。

**问题——巨大的中间矩阵：** N = 32,768 时，一个头的分数矩阵有 32,768² ≈ 10.7 亿个数，BF16 下约 **2 GB**。每层几十个头，显存放不下，读写也极慢。注意力的计算量其实不大，时间主要花在读写这个中间矩阵上。

**FlashAttention 的思路：** 永远不在显存里生成完整的 N × N 矩阵。

**分块：**
- 把 Q 按行切成块（比如每块 128 行），K、V 也按行切成块。
- 一个线程块把一块 Q 读进片上 SRAM（共享内存，GPU 芯片内部的高速存储），然后依次把每一块 K、V 读进来，在片上算出这一小块的分数、做 softmax 的部分计算、乘以 V，累加到输出。
- 所有中间结果都留在片上，显存只需要读 Q、K、V 和写最终输出。

**在线 softmax：** softmax 需要知道整行的最大值和总和，但分块时一次只看到一部分。解决办法是边看边修正：
- 维护目前为止的最大值 m 和指数和 l，以及累积的输出 o。
- 新来一块分数，得到这块的最大值 m'。如果 m' 更大，把之前的 l 和 o 都乘以 `exp(m − m')` 进行缩放，再加上新块的贡献。
- 全部块处理完后，用 o ÷ l 得到最终结果。数学上和一次性计算整行 softmax 完全相同。

**效果：**
- 显存占用从 O(N²) 降到 O(N)，长上下文成为可能。
- 显存读写大幅减少，速度提升数倍。
- 结果在数学上精确（不是近似），但求和顺序和标准实现不同，数值上会有最后几位的差异。

**测试要点：** 和朴素的参考实现（FP32 下逐步计算）比较，覆盖序列长度为 1、不是块大小倍数、非常长、带因果掩码（只能看前面的位置）和不带掩码、不同头维度（64、128、256）、分组查询注意力等情况。
