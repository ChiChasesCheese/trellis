## Q
面试里被问"衡量 LLM 推理服务性能用哪些指标？它们之间什么关系？"，怎么答？

## A
按这个顺序说：

- **两个用户感知的延迟：** TTFT，发出请求到第一个 token，包含排队和对整段输入的预填充，输入越长越大；TPOT，之后平均每个 token 的间隔，由生成阶段决定，生成阶段每步要读一遍全部权重和 KV 缓存，所以主要受显存带宽限制。端到端延迟约等于 TTFT 加 TPOT 乘以输出 token 数减一。
- **再补 ITL：** TPOT 是请求内平均，会掩盖卡顿；看相邻 token 间隔的 P99 才能发现长输入预填充、抢占造成的停顿。
- **吞吐：** 系统每秒输出多少 token 或完成多少请求，决定成本。说数字时要分清是单用户速度还是整机吞吐，是只算输出还是包含输入。
- **两者的矛盾和 goodput：** 加大并发，批变大，吞吐上升，但每个人的 TPOT 和排队时间变差。所以用 goodput，只统计同时满足 TTFT 和 TPOT 目标的请求，作为容量规划依据；吞吐最高的点往往不是 goodput 最高的点。
- **怎么报告：** 每个指标给 P50、P90、P99，并写清负载：输入输出长度分布、并发或到达率、模型和精度、硬件。画延迟—吞吐曲线，找拐点，比较版本时看整条曲线，而不是单点。
- **测量严谨性：** 预热、开环发压避免协同遗漏、用同一分词器计数、关闭代理缓冲、样本量足够支撑 P99，并用利特尔定律核对实际并发。
