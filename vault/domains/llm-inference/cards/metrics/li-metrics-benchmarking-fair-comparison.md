## Q
有人说"系统 A 比系统 B 快 3 倍"。你要问哪些问题才能判断这个比较是否公平？

## A
**"快"至少有四种不同含义，先问是哪一种：**
- **单用户生成速度：** 每秒多少 token，即 1 / TPOT（TPOT 是第一个 token 之后平均每个 token 的间隔）。低并发下的体验。
- **首 token 延迟（TTFT）：** 用户多久看到第一个字。
- **整机吞吐：** 每秒总共输出多少 token。
- **单位成本吞吐：** 每块芯片、每千瓦、每美元每秒多少 token。

一个系统可能单用户速度快 10 倍、整机吞吐只高一点；另一个反之。宣传数字常常只挑最有利的一种。

**再逐项核对条件是否相同：**
- **模型和精度：** 同一个模型、同一套权重？一边是 BF16、另一边是 4 位量化，速度差异有很大一部分来自精度降低，必须同时报告精度评测结果。
- **负载：** 输入输出长度、并发数是否一样？短输入、低并发天然有利于单用户速度。
- **硬件规模：** 用了多少芯片、多少功耗？8 张卡对 64 张卡，要换算成"每芯片"或"每瓦"比较。
- **延迟约束：** 吞吐是在什么延迟目标下测的？没有延迟约束的最大吞吐，可以靠极大的批量刷高。比较 goodput（满足延迟目标的有效吞吐）更公平。
- **测量方式：** 谁测的、客户端在哪、包不包括网络、是否有预热、多少样本、是否开了投机解码（每步接受多个猜测的 token，速度依赖内容的可预测程度）。
- **是否端到端：** 只测模型计算，还是包括分词、调度、网络传输？

**一个合理的结论格式：** "在 Llama 3.1 70B、BF16、输入 2K 输出 512、TTFT ≤ 1 s 且 TPOT ≤ 50 ms 的约束下，A 每芯片的 goodput 是 B 的 1.8 倍；单用户 TPOT 在并发 1 时是 B 的 1/3。精度评测分数差异在 0.2 分以内。"
