## Q
OpenAI 兼容推理接口应该返回哪些错误码？错误体的格式是什么？上下文超长、限流、流式中途失败这几类错误各应怎样处理和测试？

## A
**错误体格式（OpenAI 风格）：**

```json
{"error": {"message": "This model's maximum context length is 8192 tokens...", "type": "invalid_request_error", "param": "messages", "code": "context_length_exceeded"}}
```

**常见状态码：**
- **400：** 参数非法：`temperature` 超出 0–2、`messages` 为空、`top_logprobs` 超过 20、JSON 格式错误。
- **401 / 403：** 认证失败或无权限。
- **404：** 模型不存在。
- **413 或 400：** 请求体过大。
- **429：** 限流或配额用尽，应带 `Retry-After` 头，告诉客户端多久后重试。
- **500：** 服务内部错误。
- **503：** 过载或正在启动、维护，客户端应退避重试。

**三类重点场景：**
- **上下文超长：** 输入 token 数加上 `max_completion_tokens` 超过模型上限（token 是文字切成的小片段）。行为必须是确定的：要么返回 400 并在消息里给出上限和实际值，要么按文档自动缩小输出上限。边界测试：输入恰好等于上限、超出 1 个 token、输入未超但加上输出上限后超出。
- **限流：** 按每分钟请求数（RPM）或每分钟 token 数（TPM）计。测试：在限额附近发送突发流量，确认超额请求收到 429 和合理的 `Retry-After`，未超额的请求不受影响；限额窗口重置后恢复。
- **流式中途失败：** 第一块数据发出时 HTTP 200 已经确定，后续出错（如内部进程崩溃、被抢占后超时）只能在流里发一个错误事件后关闭连接。测试：在生成中途杀掉工作进程，确认客户端收到明确的错误而不是无限挂起，也不是悄悄截断后假装正常结束（没有 `finish_reason` 就断开）。

**其他要求：**
- 错误消息不能泄露内部信息（堆栈、文件路径、其他用户的数据）。
- 不支持的参数应明确报 400，而不是静默忽略，否则用户以为参数生效了。
- 同一类错误在流式和非流式下返回一致的 `type` 和 `code`。
