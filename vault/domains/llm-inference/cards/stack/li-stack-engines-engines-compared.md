## Q
vLLM、TensorRT-LLM、SGLang 三个主流开源推理引擎各有什么特点？做测试或选型时要关注哪些差异？

## A
三者都提供连续批处理（每一步都可以有请求加入或离开）、分页式 KV 缓存管理（把每个请求历史 token 的键、值向量分成固定小块按需分配）、OpenAI 兼容接口、多卡并行和量化。差别主要在设计取向上。

**vLLM：**
- 起源于 PagedAttention 论文（分页式 KV 缓存）。以 Python 和 PyTorch 为主，模型和硬件支持面最广（NVIDIA、AMD、TPU 等多种后端）。
- 启动：`vllm serve <模型>`；基准：`vllm bench serve`。
- 优点是新模型支持快、社区大；代价是不同版本间默认参数和行为变化较频繁，升级要做回归。

**TensorRT-LLM（NVIDIA）：**
- 针对 NVIDIA GPU 深度优化，内核（GPU 上执行的计算函数）性能强，FP8、FP4 等新格式支持最早。
- 传统流程要先用 `trtllm-build` 把模型编译成针对特定 GPU、批大小、序列长度的"引擎"文件；较新版本也提供直接基于 PyTorch 的运行方式。服务可用 `trtllm-serve` 或 Triton 推理服务器。
- 代价：编译产物和 GPU 型号、配置绑定，配置一变就要重新构建；只支持 NVIDIA。

**SGLang：**
- 以 RadixAttention（用基数树管理和复用公共前缀的 KV 缓存）著称，多轮对话、智能体、共享长系统提示的场景前缀复用效率高；结构化输出（约束生成合法 JSON 等）快。
- 启动：`python -m sglang.launch_server --model-path <模型>`。配套的路由器支持按缓存命中情况分配请求。

**测试和选型时关注的差异：**
- **同一模型的数值输出不同：** 内核实现和求和顺序不同，贪心解码的输出可能在近似平局处分叉。迁移引擎时要做精度对比，而不是期望逐字相同。
- **默认值不同：** 最大上下文、最大并发、显存占用比例、采样参数的处理顺序、是否默认开启前缀缓存。基准测试必须把配置显式写全。
- **接口细节差异：** 错误码、`usage` 的计算口径、流式最后一块的格式、对不支持参数的处理（报错还是忽略）。
- **性能结论依赖负载：** 不同输入输出长度和并发下排名会变，比较必须在同一负载、同一硬件、同一精度下进行。
