## Q
面试里被问"你会怎么测试一个 OpenAI 兼容的推理 API？"，怎么答？

## A
按这个顺序说：

- **先分层：** 我把测试分成接口契约、模型正确性、并发与稳定性、性能四层，前两层每次提交都跑，后两层每个发布候选版本跑。
- **接口契约：** 每个参数的合法和非法取值；每种 `finish_reason`（stop、length、tool_calls）都有用例；`max_completion_tokens=N` 时恰好输出 N 个 token；停止串不返回、跨两个 token 也能识别；错误返回正确的状态码和 `error.code`，比如上下文超长的 400、限流的 429 带 `Retry-After`。
- **流式：** SSE 每块是增量，所有增量拼接后必须等于非流式结果；`usage` 两种方式一致；没有半个多字节字符；只有一个 `[DONE]`；中途出错时客户端能收到错误事件而不是挂起。
- **正确性和计数：** `temperature=0` 下和参考实现比较输出与 logprobs；`prompt_tokens` 用同一分词器和对话模板独立计算核对，因为计数错误就是计费错误。
- **并发与稳定性：** 高并发下每个请求放唯一标记检查不串话；单发和混跑在贪心解码下一致；客户端断开后请求在秒级内被取消并释放显存；慢客户端不拖累别人；长时间浸泡没有显存增长。
- **性能：** 用接近真实流量的输入输出长度分布扫并发，记录 TTFT、TPOT 的 P50 和 P99 以及吞吐，和上一版本的基线比较，超过阈值阻断发布。我会用官方 OpenAI 客户端做测试驱动，保证真实用户的调用方式被覆盖。
