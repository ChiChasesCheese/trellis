## Q
推理引擎"一步"（一次迭代）里依次做了哪些事？哪些环节会让 GPU 空闲，引擎用什么手段消除？

## A
**一步：** 为本步选中的每个请求处理若干 token（正在生成的请求各 1 个，正在预填充的请求一段输入），产出每个请求的下一个 token。

**顺序：**
1. **调度（CPU）：** 选请求、算 token 预算、分配 KV 缓存块（保存历史 token 每层键、值向量的显存块）。
2. **准备输入（CPU → GPU）：** 拼接 token 编号、位置编号、块表，拷贝到 GPU。
3. **前向计算（GPU）：** 几十层，每层几十个小操作。
4. **采样（GPU）：** 按每个请求的温度、top-p 等参数选出下一个 token。
5. **取回结果（GPU → CPU）：** 把新 token 拷回 CPU，更新每个请求的状态，检查停止条件。
6. **反分词与流式输出（CPU）：** 把 token 转成文字，推给客户端。

**GPU 为什么会空闲：**
- **第 1、2、5 步在 CPU 上，GPU 在等。** 小模型、小批量时，这部分可能占一步时间的 10%–30%。
- **内核启动开销：** 每个 GPU 小操作（称为 kernel，内核：在 GPU 上执行的一个函数）从 CPU 提交需要几微秒。一步几百上千个内核，光提交就是毫秒级，而 7B 模型一步的计算本身只有几毫秒。

**消除手段：**
- **CUDA Graph：** 把一整步的所有内核录制成一张图，之后一次提交，大幅减少启动开销。要为每种批大小分别录制，所以引擎会预先录制一组常用批大小，实际批大小向上取整到最近的一个。
- **`torch.compile` 与算子融合：** 把多个小操作合成一个内核，减少内核数量和对显存的读写。
- **异步调度：** GPU 在算第 N 步时，CPU 已经在准备第 N+1 步。
- **进程分离：** HTTP 和反分词放在另一个进程，不阻塞调度循环。

**测量：** 用 NVIDIA Nsight Systems（`nsys profile -o step python ...`）抓一段时间线，看 GPU 时间轴上的空隙；空隙多、且对应 CPU 上的 Python 代码，说明瓶颈在主机侧。对比开启和关闭 CUDA Graph（vLLM 的 `--enforce-eager` 会关闭它）的每 token 间隔，能直接看到启动开销的大小。
