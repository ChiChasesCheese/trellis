## Q
面试里被问"讲讲一个 LLM 推理引擎的架构，你会从哪里入手测试它？"，怎么答？

## A
按这个顺序说：

- **分层：** 最外层是 API 服务，提供 OpenAI 兼容接口，负责校验、套对话模板、分词，以及把生成的 token 反分词后用 SSE 流式返回。中间是引擎核心，跑一个逐步循环：调度器每一步决定哪些请求参与、各处理多少 token，分配 KV 缓存块，显存不够时抢占。底层是每张卡一个工作进程，模型执行器把本步所有请求拼成一批做前向计算，再逐请求采样。vLLM 把 API 和引擎核心放在不同进程，避免 CPU 工作拖慢 GPU。
- **关键机制：** 连续批处理让请求每一步都能加入或离开；分页式 KV 缓存按块分配；分块预填充控制每步工作量；CUDA Graph 降低内核启动开销；前缀缓存复用公共开头。
- **从哪测起，按层次：** 接口层做契约测试，覆盖每个参数、每种结束原因、流式格式和错误码；引擎层做隔离和一致性测试，比如单发与高并发混跑在贪心解码下输出一致、开关前缀缓存输出一致、抢占恢复后输出一致；模型层和参考实现比较 logprobs。
- **性能：** 用 `vllm bench serve` 扫并发和输入输出长度，记录 TTFT、TPOT 的 P50/P99 和吞吐，和基线比较；用 Nsight Systems 看 GPU 时间线上的空隙判断瓶颈在主机侧还是设备侧。
- **稳定性：** 长时间浸泡、客户端中途断开、超长输入、显存打满时的抢占，以及多卡时某个进程被杀掉后能否正确失败和恢复。
- **收尾：** 我会让每层都有自动化测试，并把引擎版本、模型版本和硬件驱动版本作为一个组合来回归，因为三者任何一个变化都可能改变数值或性能。
