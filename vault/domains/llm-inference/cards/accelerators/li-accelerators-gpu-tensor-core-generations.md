## Q
Tensor Core 是什么？不同代 GPU 支持的数据类型有什么区别？为什么矩阵的形状（比如是否是 16 的倍数）会影响性能？

## A
**Tensor Core：** GPU 里专门做"小矩阵乘加"的硬件单元。普通计算单元一次做一个乘加，Tensor Core 一条指令就能完成一个小矩阵块（比如 16×16 乘 16×16）的乘法并累加。大模型的矩阵乘法被切成很多这样的小块，交给 Tensor Core 完成，速度是普通单元的十几倍。

**各代支持的低精度格式（数据中心卡）：**
- **Volta（V100，2017）：** FP16。
- **Ampere（A100，2020）：** 增加 BF16、TF32（一种 19 位格式，用于加速 FP32 计算）、INT8。
- **Hopper（H100、H200，2022）：** 增加 FP8（E4M3、E5M2 两种）。
- **Blackwell（B200 等，2024）：** 增加 FP4 等更低精度格式。

**含义：** 在一块不支持某种格式的卡上运行该格式的模型（比如在 A100 上跑 FP8 权重），只能先转换回支持的格式再计算，省显存但不提速，甚至更慢。部署前要核对"模型精度 × GPU 代际"的组合。

**低精度为什么更快：** 同样的芯片面积和功耗，处理 8 位数比 16 位数能多做约一倍的运算；每个数占的字节也少一半，读得更快。H100 的 FP8 稠密峰值约是 BF16 的 2 倍。

**为什么形状会影响性能：** Tensor Core 按固定大小的块计算。
- 矩阵维度不是块大小（常见是 8 或 16）的倍数时，边缘部分要补零或改用较慢的路径，浪费算力。
- 内核为不同形状预先调好了分块方案；形状很"怪"（比如质数维度）时可能落到效率差的方案上。
- 这就是模型的宽度、头维度、词表大小常取 64、128 的倍数的原因；推理引擎也会把批大小向上取整到某些固定值。

**测试意义：** 性能和数值测试的形状矩阵里，要包含"非 16 的倍数"的维度，比如批大小 1、7、17，序列长度 1、15、16、17、4,095、4,097。很多内核缺陷和性能断崖只在这些形状上出现。
