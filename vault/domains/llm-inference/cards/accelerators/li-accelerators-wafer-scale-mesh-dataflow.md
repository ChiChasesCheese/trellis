## Q
晶圆级芯片上的 90 万个核心是怎样组织和通信的？它的编程模型和 GPU 有什么不同？

## A
**每个核心（处理单元，PE）包含三样东西：**
- **计算引擎：** 执行指令，擅长向量和矩阵运算。
- **本地 SRAM：** 每个核心 48 KB（44 GB ÷ 约 90 万个核心，正好是这个量级）。存放这个核心负责的数据和代码，其他核心不能直接读写它。
- **路由器：** 连接自己的计算引擎和上下左右四个相邻核心的路由器。

**网格互连（2D mesh）：** 所有核心排成一个巨大的二维网格。数据以 32 位为单位的小消息（称为 wavelet）在相邻核心之间逐跳传递，每个时钟周期可以收发一个。路由器上有 24 条虚拟通道（称为颜色，color），不同的数据流走不同的颜色，路由规则按颜色配置，互不干扰。

**数据流驱动（dataflow）：** 一个核心上的计算任务由"数据到达"触发：某种颜色的消息到了，就激活对应的任务去处理它。没有全局的"一起执行这个函数"的概念。

**和 GPU 编程模型的对比：**

| | GPU | 晶圆级芯片 |
|---|---|---|
| 数据在哪 | 大部分在片外 HBM，用时搬进片上 | 全部在各核心自己的本地 SRAM |
| 怎么协作 | 很多线程读写共享的显存 | 核心之间通过网格显式传消息 |
| 一个内核 | 启动大量线程处理一块数据 | 每个核心运行自己的小程序，数据流过 |
| 关键问题 | 怎样复用片上缓存、减少 HBM 读写 | 怎样把计算和数据放到网格的哪些位置、怎样路由 |

**对编译器的含义：** 编译器（或开发者）要决定神经网络的每一层放在网格的哪个区域、权重怎样切分到各核心的本地存储、激活值沿哪条路径流向下一层。这类似芯片设计里的"布局布线"，是这类硬件软件栈的核心难点。

**开发与测试工具：** 厂商提供了 SDK，设备端代码用一种类 C 的数据流语言（CSL）编写，主机端用 Python；SDK 自带网格的软件模拟器，可以在没有硬件的情况下开发和测试小规模程序。模拟器能验证逻辑正确性，但时序、带宽、规模相关的问题仍然要在真实硬件上验证。
