## Q
训练用"权重流式执行"，推理却把权重常驻在片上 SRAM 里。为什么推理不能也用流式执行？用带宽算一下。

## A
**两种放置方式：**
- **流式执行（weight streaming）：** 权重放在外部存储，每一步把每一层的权重送进晶圆，用完即丢。
- **常驻（resident）：** 权重一直放在晶圆的片上 SRAM 里，计算时就地读取。

**关键区别：每次送入的权重被多少计算复用。**
- **训练：** 一批数据有成千上万个样本、每个样本几千个 token。一层权重送进来一次，要对几百万个 token 做计算。送权重的时间被大量计算摊薄。
- **推理的生成阶段：** 每步每个请求只有 1 个 token。如果每步都要把全部权重从外部送进来，几乎没有计算可以摊薄。

**算一笔账（70B 模型，FP16，140 GB）：**
- 假设晶圆对外链路的总带宽是 1.2 Tb/s，即约 150 GB/s。
- 每生成一个 token 都要送一遍 140 GB：140 ÷ 150 ≈ **0.93 秒**。
- 也就是说，流式执行下单用户每秒只能生成约 1 个 token，比 GPU（每秒几十个）还慢得多。
- 对比常驻：参数在片上 SRAM 里，读一遍按约 21 PB/s 的片上带宽计算只要微秒级。

**所以：**
- 训练适合流式执行：模型大小不受片上容量限制，计算足够多来掩盖送权重的时间。
- 推理适合常驻：生成阶段要求每步极快地读完全部参数，只有片上存储能提供这种带宽。代价是模型必须放得进 SRAM，大模型要分到多片晶圆上。

**GPU 上的类比：**
- GPU 推理把权重放在 HBM（显存）里，相当于"常驻显存"。
- 显存不够时，有的框架会把部分权重放在 CPU 内存里，每步经 PCIe（约 64 GB/s）搬过来，这就是 GPU 上的"流式"，速度会掉一到两个数量级。只适合离线、不在乎延迟的场景。

**测试启示：** 如果一个推理配置因为放不下而退化成从外部或主机内存搬运权重，延迟会断崖式上升。部署检查必须确认权重全部常驻在快速存储里，并对每 token 时间设上限告警。
