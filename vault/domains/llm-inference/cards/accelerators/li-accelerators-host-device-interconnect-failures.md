## Q
多卡、多机推理系统中，和主机—设备通路、互连相关的故障有哪些典型表现？怎样排查？

## A
**互连：** 加速卡之间（机内 NVLink、PCIe）、机器之间（InfiniBand、以太网 RDMA）传数据的硬件链路。张量并行每层都要做全体求和（所有卡的部分结果相加，每张卡拿到总和），任何一条链路变慢或出错，整组卡都受影响。

**典型故障与表现：**
- **PCIe 链路降级：** 插槽接触不良或固件问题，链路从 x16 降到 x8，或从 5.0 降到 3.0。模型加载变慢、主机与设备交换数据的步骤变慢，计算本身正常。查：`nvidia-smi -q | grep -A3 "Link"` 比较当前与最大的代数和宽度；`lspci -vv` 的 `LnkSta` 字段。
- **NCCL 走错了网络：** 本应走 InfiniBand 或 RoCE，因为配置或驱动问题退化为普通 TCP 套接字，多机通信慢一个数量级。查：设置 `NCCL_DEBUG=INFO`，在初始化日志里看使用的是 `NET/IB` 还是 `NET/Socket`。
- **集合通信挂死：** 所有卡必须按相同顺序调用同一个集合操作。某个进程因异常提前退出，或者走了不同的分支，其余卡永远等待。表现为 GPU 显示忙碌但没有任何输出。查：用 `py-spy dump --pid <进程号>` 看每个进程停在哪一行；设置通信超时，让挂死变成报错。
- **硬件错误：** GPU 的 Xid 错误（驱动报告的错误代码）、显存 ECC 不可纠正错误、NVLink 链路错误。查：`dmesg | grep -i xid`、`nvidia-smi -q -d ECC`、DCGM 的诊断工具 `dcgmi diag -r 3`。
- **拓扑不对称：** 部分卡之间经过 CPU 之间的连接而不是直连，带宽低。查：`nvidia-smi topo -m` 显示每对卡之间的连接类型（NV# 表示 NVLink，SYS 表示跨 CPU）。

**系统级的应对：**
- **机器验收测试：** 新机器上线前跑主机—设备带宽测试、`all_reduce_perf` 和 DCGM 诊断，结果和同型号基线比较，不达标的机器不进入服务池。
- **服务健康检查：** 不仅检查进程是否存活，还要定期发一个小推理请求并检查延迟，挂死的服务进程才能被发现。
- **故障隔离：** 一组多卡服务中任何一张卡出错，整组摘除并重启，而不是让它以错误状态继续接收请求。
- **记录硬件标识：** 每次测试和线上错误都记录机器、卡的序列号，便于发现集中在少数硬件上的问题。
