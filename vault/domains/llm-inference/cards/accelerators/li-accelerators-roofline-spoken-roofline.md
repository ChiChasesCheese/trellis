## Q
面试里被问"什么是 roofline 模型？用它解释一下为什么 LLM 的 prefill 和 decode 性能特征不同。"，怎么答？

## A
按这个顺序说：

- **定义：** 一个计算的算术强度是运算次数除以读写字节数。可达性能等于峰值算力和"强度乘以带宽"两者中的较小值。强度低于拐点受带宽限制，高于拐点受算力限制。H100 BF16 的拐点约是 989 TFLOPS 除以 3.35 TB/s，约 295 FLOP/byte。
- **矩阵乘法的强度约等于同时处理的 token 数：** 权重矩阵被这一步的所有 token 共享，每读一次权重，每个 token 做一次乘加。
- **预填充：** 一次处理几千个输入 token，强度上千，远超拐点，受算力限制，决定首 token 延迟；优化方向是提高算力利用率、用 FP8。
- **解码：** 每个请求一步只有 1 个 token，批大小为 B 时强度约 B。B = 1 时约 1，只能用到峰值的 0.3%；要用满算力需要批大小接近 300，通常先被显存装不下的 KV 缓存挡住。注意力部分的强度始终约 1（GQA 时约为组大小），因为每个请求的 KV 缓存不能共享。所以解码受带宽限制，优化方向是减少要读的字节：量化权重和 KV、GQA、凑大批。
- **用作测试预期：** 一步生成的理论最短时间约等于每步读的字节数除以带宽，7B 在 H100 上约 4.2 ms。实测达到 70% 以上算合理；很低就用 Nsight 看是内核问题还是调度空隙。
- **延伸一句：** 如果把权重放进片上 SRAM，带宽高几个数量级，拐点降到 1 以下，解码就不再受带宽限制，瓶颈转向计算延迟和芯片间通信。
