## Q
权重常驻 SRAM 的晶圆级推理在哪些情况下优势会缩小甚至消失？列出这些边界，并说明各自该用什么负载去测。

## A
**它的核心优势：** 生成阶段每步要读全部参数，参数放在片上 SRAM，带宽极高，所以单用户每秒 token 数极高。以下情况会削弱这个优势：

- **模型越来越大：** 片上容量有限（每片 44 GB），参数越多需要的晶圆越多。一个 token 要串行经过所有晶圆，每多一片多一跳网络延迟和一段计算延迟；硬件数量和成本也线性增加。
  测法：同一系列不同大小的模型，测单用户每 token 时间和每片晶圆的吞吐，看随模型增大怎样下降。
- **长上下文和高并发：** KV 缓存也要放在 SRAM 里，和权重抢空间。上下文越长、并发越高，需要的缓存越多，要么限制并发、要么增加晶圆。
  测法：固定模型，扫上下文长度（8K、32K、128K）和并发数，记录最大可服务并发、吞吐和每 token 间隔，找出容量边界。
- **大批量吞吐场景：** GPU 在大批量下也能把算力用起来，整机吞吐不差。如果业务只关心"每美元多少 token"而不在乎单用户速度，优势变小。
  测法：在相同的延迟约束下比较每单位功耗或成本的 goodput（满足延迟目标的有效吞吐），而不是只比单用户速度。
- **小批量下的通信与同步：** 批很小时，每层计算量小，层内和片间的通信时间可能和计算时间一样长。
  测法：并发 1、4、16 下测每 token 时间，并拆分计算与通信时间。
- **长输入的预填充：** 预填充受算力限制，不受益于高带宽，还会占用流水线。
  测法：注入长输入，看首 token 延迟和对正在生成的请求的干扰；对比把预填充放到 GPU 的分离部署。
- **主机侧成为瓶颈：** 每秒几千个 token 时，分词、反分词、流式发送、网络都可能跟不上。
  测法：测主机 CPU 占用和客户端实际收到 token 的速率，与设备侧生成速率比较。
- **精度取舍：** 为了放进有限的 SRAM 而降低权重精度，会影响质量。
  测法：同一模型不同精度的评测集分数和逐位置概率对比，确认精度损失在可接受范围内。

**测试者的态度：** 宣称的速度数字通常是在最有利的条件下测得的（中等模型、短上下文、低并发）。验证时要画出完整的边界：模型大小、上下文长度、并发、输入长度四个维度上，性能如何变化。
