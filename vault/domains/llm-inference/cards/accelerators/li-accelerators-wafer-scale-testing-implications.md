## Q
如果你负责一个晶圆级加速器上的推理软件栈的集成测试，和测试 GPU 推理栈相比，有哪些额外的风险点要覆盖？

## A
**背景：** 晶圆级加速器把整个模型（或模型的一段）放在一片晶圆的片上 SRAM（直接做在芯片里的高速存储）里，编译器决定每一层放在核心网格的哪个区域、数据怎样在核心之间流动；模型大于一片晶圆时分到多片晶圆上，按层流水执行。

**额外风险点和对应的测试：**
- **编译结果的"放得下"问题：** 每个模型、每种精度、每种最大上下文配置，编译器都要把权重和 KV 缓存（每个请求历史 token 的键、值向量）安排进有限的片上存储。新模型、新配置可能编译失败，或者为了放得下而降低可用的并发数。测试：每个模型 × 配置的编译成功率、编译耗时，以及编译后报告的最大并发和最大上下文，和预期比较。
- **多晶圆流水线：** 层被切到多片晶圆上，片间只传激活值。要测：切分点不同时输出是否一致；某一片晶圆或片间链路故障时，整条流水线是否能被检测出来并摘除，而不是挂起；片间延迟变化对每 token 间隔的影响。
- **每台机器物理不同：** 每片晶圆屏蔽了不同的缺陷核心。同一个编译产物要在多台机器上轮换测试，测试结果要记录机器和晶圆标识，才能发现"只在某几台机器上出现"的问题。
- **软件版本组合：** 编译器、运行时、固件、主机驱动、集群管理软件各自升级。需要维护一张"已验证的版本组合"矩阵，任一组件升级都要重跑完整的回归。
- **主机侧瓶颈：** 加速器生成极快时（每秒上千 token），分词、反分词、HTTP 流式发送、调度这些主机上的工作更容易成为瓶颈。要专门测量主机 CPU 占用和每 token 的主机侧开销。
- **数值一致性：** 计算核心的数值格式、累加方式和 GPU 参考实现不同。要做逐层、逐位置的概率对比，用参考实现自身的差异范围设定容差。
- **异构部署：** 如果预填充放在别的硬件上、解码放在晶圆上，KV 缓存跨硬件传输的格式转换和数值一致性都要单独验证。
- **模拟器与实机：** 模拟器能覆盖逻辑正确性和小规模用例，规模、时序、热和功耗相关的问题只能在实机上暴露。测试计划要明确哪些在模拟器上跑、哪些必须上实机。
