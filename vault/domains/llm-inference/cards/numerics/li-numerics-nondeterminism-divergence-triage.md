## Q
回归测试发现新版本在 `temperature=0` 下有 7% 的用例输出和旧版本不同。怎样区分"可接受的数值差异"和"真正的缺陷"？

## A
**问题：** 推理计算在不同软件版本、批大小、硬件下数值上不会逐位相同。低精度运算的求和顺序一变，最后几位就变，当两个候选 token 的分数几乎相等时，名次可能翻转，之后的输出全部不同。所以"输出文字不同"本身不能直接判为缺陷。

**分诊步骤：**
1. **找首次分叉位置：** 对每个不一致的用例，找到新旧输出第一个不同的 token 位置 t。
2. **用"教师强制"（teacher forcing）对比分叉点：** 把旧版本输出的前 t 个 token 原样作为输入喂给新版本，取新版本在位置 t 的分数分布。比较旧版本选的 token 和新版本选的 token 在新版本里的对数概率之差。
   - 差值很小（比如 < 0.05）：近似平局，属于数值噪声导致的翻转，可接受。
   - 差值很大：新版本对这个位置的判断明显不同，需要调查。
3. **在分叉之前也做比较：** 公共前缀上每个位置的对数概率差，应该在历史噪声范围内。前缀上的差异已经明显变大，说明整体数值发生了漂移，即使最终文字相同也要警惕。
4. **按用例特征聚类：** 不一致是否集中在长输入、某种语言、多轮对话、带工具调用的请求、某个并发配置？集中分布往往指向具体的代码路径。
5. **用质量指标兜底：** 在评测集（有标准答案的题目）上比较新旧版本的分数，差异在统计误差内，说明分叉没有影响质量。

**可接受的典型画像：** 分叉点全部是近似平局，前缀漂移在历史范围内，评测分数无显著变化，分叉率和历史版本相当。

**缺陷的典型画像：** 分叉点分数差大；分叉集中在某个长度之后（位置编码或缓存的问题）；集中在某种并行配置下；评测分数显著下降。

**流程化：** 把"不一致率""近似平局占比""前缀最大漂移"作为三项指标纳入发布检查，比"输出必须完全相同"或"人工看看差不多"都更可靠。
