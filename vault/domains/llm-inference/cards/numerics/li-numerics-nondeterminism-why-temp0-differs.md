## Q
为什么把 `temperature` 设为 0（贪心解码，每步选概率最高的 token），同一个请求发两次，推理服务仍然可能返回不同的回答？

## A
**直觉上：** 温度为 0 时没有随机抽样，模型是确定的函数，同样的输入应该得到同样的输出。

**实际上：** 模型计算本身在不同"环境"下会产生最后几位不同的数，而环境随服务负载变化：

- **批大小在变：** 服务把同一时刻的多个用户请求拼成一批计算。你的请求第一次和 3 个人一起算，第二次和 60 个人一起算。矩阵形状不同，GPU 内核（GPU 上执行的计算函数）可能选择不同的分块方式，把一个长求和拆成不同的段数。浮点加法不满足结合律，求和顺序一变，最后几位就变。
- **"拆分求和"的优化：** 矩阵乘法在批小时常用 split-K（把求和维度切成几段，并行算再合并）；注意力在长上下文时把历史拆成几段并行处理（split-KV）。是否拆、拆几段取决于批大小和长度。
- **前缀缓存命中与否：** 第二次请求的开头命中了缓存，跳过了部分计算，走的是不同的计算路径。
- **分块预填充：** 长输入被切成多少块、块边界在哪，可能随当时的负载变化。

**小差异怎样变成不同的回答：** 每一步输出的是词表上每个 token 的分数。如果第 1 名和第 2 名的分数非常接近（比如差 0.0001），最后几位的扰动就可能让名次翻转。一旦某一步选了不同的 token，后面所有步骤的输入都不同，回答从此完全分叉。

**一个公开的实验：** 对 Qwen3-235B 用温度 0 生成同一段 1,000 token 的回答 1,000 次，得到 80 种不同的结果；前 102 个 token 全部相同，第 103 个 token 开始分叉（992 次是 "Queens, New York"，8 次是 "New York City"）。

**常见误解：** 很多人以为原因是"GPU 并行加上原子操作的随机顺序"。但大模型推理的前向计算基本不使用原子加法，同一批组成下重复运行通常是逐位相同的。主要原因是**批组成随负载变化**，也就是缺乏批不变性。
