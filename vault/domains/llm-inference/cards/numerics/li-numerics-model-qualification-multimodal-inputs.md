## Q
多模态模型（能看图的模型）在推理时，图片是怎样进入语言模型的？上线这类模型要额外测试什么？

## A
**图片进入语言模型的过程：**
1. **预处理：** 把图片缩放、裁剪或切块到模型要求的尺寸，按固定的均值和标准差归一化像素值。
2. **视觉编码器（vision encoder）：** 一个专门处理图片的神经网络（常见的是 ViT，把图片切成 14×14 或 16×16 像素的小块，每块变成一个向量），输出一串图像特征向量。
3. **投影层（projector）：** 把图像特征向量变换到语言模型的隐藏宽度，使它们和文字 token 的向量形状相同。
4. **拼接：** 文字提示里有一个图片占位标记，推理引擎把它展开成 N 个位置，填入这 N 个图像向量。之后语言模型像处理普通 token 一样处理它们。

**数量级：** 一张图片常常变成几百到上千个"图像 token"。例如 336×336 的图片按 14 像素切块是 24 × 24 = 576 块。高分辨率图片被切成多个子图后，token 数成倍增加。所以图片会大量占用上下文长度和 KV 缓存（保存每个位置每层键、值向量的显存），也会显著增加首 token 延迟。

**额外要测试的：**
- **预处理一致性：** 缩放的插值方式、归一化参数、颜色通道顺序（RGB 还是 BGR）、图片方向（EXIF 旋转信息）。和官方处理器（如 Hugging Face 的 `AutoProcessor`）对同一张图的输出张量逐元素比较。差一点点就会让模型"看错"，而且不会报错。
- **图像 token 数：** 不同分辨率、长宽比的图片，平台展开的占位数量必须和模型的计算方式一致；`usage.prompt_tokens` 要包含图像 token，计费才正确。
- **数值对比：** 视觉编码器的输出和最终分数分别与参考实现比较。
- **前缀缓存的隔离：** 两个请求文字相同、图片不同时，占位 token 完全一样，缓存必须把图片内容纳入判断，否则会复用别人图片的缓存。
- **输入边界：** 极小和极大的图片、多张图片、损坏的文件、不支持的格式、通过 URL 和 base64 两种方式传入；超出图片数或尺寸上限时返回清晰的 400 错误。
- **质量评测：** 视觉问答、图表理解、文字识别类的评测集，与官方分数对比。
- **性能：** 图片编码耗时、含图请求的首 token 延迟和对纯文本请求的干扰。
