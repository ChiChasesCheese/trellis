## Q
为什么说浮点加法不满足结合律？举一个具体的数值例子，并说明它对 GPU 上的推理结果意味着什么。

## A
**结合律：** 数学上 `(a + b) + c = a + (b + c)`。浮点数每次运算后都要舍入到最近的可表示数，所以计算顺序不同，舍入发生的位置不同，结果可能不同。

**FP32 的例子：** FP32 在 10⁸ 附近相邻两个可表示数的间隔是 8。

```python
import torch
a, b, c = torch.tensor(1e8), torch.tensor(1.0), torch.tensor(-1e8)
print((a + b) + c)   # tensor(0.)   因为 1e8 + 1 被舍入回 1e8
print(a + (b + c))   # tensor(0.)   -1e8 + 1 也被舍入回 -1e8，再加 1e8 得 0
print((a + c) + b)   # tensor(1.)   先抵消再加 1，结果精确
```

同样三个数，不同顺序得到 0 或 1。

**BF16 更明显：** 在 BF16 里 256 + 1 = 256。对 `[256, 1, 1, 1, 1]` 从左往右累加，结果是 256；先把四个 1 加起来得 4，再加 256，结果是 260。

**对推理的意义：**
- **矩阵乘法就是大量求和：** 一个输出元素是 4,096 个乘积之和。GPU 为了并行，会把这 4,096 项拆成若干段分别求和再合并。拆法（分块大小、分几段）由内核根据矩阵形状选择。
- **形状变，拆法就可能变：** 同一个请求，批里有 1 个请求和有 64 个请求时，矩阵形状不同，内核选择的拆分方式可能不同，求和顺序随之改变，结果的最后几位不同。
- **差异会被放大：** 最后几位的差异经过几十层传递，有时会让两个概率几乎相等的候选 token 名次翻转，之后生成的文字完全不同。
- **多卡也一样：** 张量并行时，不同卡的部分和合并的顺序取决于卡数和通信算法。

**结论：** "同样的输入在不同批大小、不同卡数、不同硬件上输出逐位相同"在默认情况下不成立。测试必须预期这种差异，用合理的容差比较，而不是要求完全相等。
