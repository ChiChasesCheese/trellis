## Q
"模型回答完不停，一直输出到长度上限"或"回答说了一半就结束"，最常见的原因是什么？怎样排查和防止？

## A
**生成什么时候停止：** 模型每步输出一个 token（文字切成的小片段）。服务在以下情况停止：生成了结束 token（EOS，表示"我说完了"的特殊 token）、遇到用户指定的停止字符串、达到最大输出长度。

**不停的常见原因：**
- **结束 token 不止一个，服务只认了一个：** 例如 Llama 3.1 的对话模型，`generation_config.json` 里 `eos_token_id` 是一个列表 `[128001, 128008, 128009]`，回答结束时实际输出的是 `<|eot_id|>`（128009）。如果服务只从分词器配置里读到 `<|end_of_text|>`（128001），模型说完话后会继续"自言自语"，常见表现是开始扮演用户角色继续提问。
- **对话模板错误：** 模板不对，模型没有处在"助手正在回答"的状态，不会自然收尾。
- **`ignore_eos` 被意外打开：** 基准测试常用它强制生成到固定长度，配置泄漏到线上就会不停。
- **`skip_special_tokens` 的副作用：** 停止判断如果在"去掉特殊 token 后的文本"上做，结束 token 就看不见了。

**提前结束的常见原因：**
- **停止字符串太宽泛：** 比如把 `"\n"` 设为停止串，回答在第一个换行处就结束。
- **最大长度计算错误：** 把上下文窗口减去输入长度作为输出上限时，输入长度用错误的分词器计数。
- **把某个普通 token 误配成结束 token。**

**排查：**
1. 看返回的 `finish_reason`：`length` 说明是被长度截断，`stop` 说明是结束 token 或停止串触发。
2. 打开 `logprobs` 或引擎的调试日志，看最后几个生成的 token 编号是什么。
3. 核对服务实际使用的结束 token 集合，与模型的 `generation_config.json` 比较。

**防止：** 资格验证时自动比较"服务识别的结束 token 集合"和"模型配置里的集合"；回归测试里放一组短回答的问题（如"1+1 等于几？只回答数字"），断言 `finish_reason == "stop"` 且输出 token 数很少。
