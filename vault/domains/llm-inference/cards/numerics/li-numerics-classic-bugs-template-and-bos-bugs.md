## Q
对话模板（chat template）和开始 token（BOS）相关的经典缺陷有哪些？为什么它们会让模型"能用但变笨"？

## A
**对话模板：** 把消息列表（系统提示、用户、助手、工具）按模型训练时的格式拼成一段文本的规则，包括角色标记、特殊 token 和换行。**开始 token（BOS）：** 放在整个输入最前面、表示"文本开始"的特殊 token。

**为什么是"变笨"而不是报错：** 模型对任何 token 序列都能算出结果。格式和训练时不一样，它照样回答，只是处在"没见过的情境"里：简单问题照样答对，复杂指令、多轮对话、工具调用的成功率下降。只看几个例子很难发现。

**经典缺陷：**
- **双重 BOS：** 模板文本里已经包含 `<|begin_of_text|>`，分词时分词器又自动加了一个。开头出现两个 BOS，对某些模型影响明显。检查方式：看最终 token 序列的前两个编号。
- **缺少"助手开始"的提示：** 渲染模板时没有加 `add_generation_prompt=True`，输入停在用户消息末尾，模型可能继续写用户的话，而不是开始回答。
- **系统提示被丢弃或位置错误：** 有的模型模板不支持系统角色，有的把它合并到第一条用户消息；平台自己实现模板时容易丢掉。
- **工具调用格式不一致：** 工具定义、工具调用结果的格式和模型训练时不同，模型不调用工具或参数格式错误。
- **多轮历史里的"思考"内容：** 有的模型要求把历史回答中的思考段落去掉再拼接，模板里有专门逻辑；平台手工实现时遗漏。
- **空白字符：** 多一个或少一个换行，改变了 token 序列。

**测试方法：**
- **逐 token 对比：** 对单轮、多轮、带系统提示、带工具、带图片等场景，把平台实际送进模型的 token 序列（引擎通常可打印或通过调试接口获取）和 `tok.apply_chat_template(messages, add_generation_prompt=True, tokenize=True)` 的结果逐 token 比较，必须完全相同。
- **模板版本跟踪：** 模型发布方会更新模板（修复工具调用等），平台要记录使用的模板哈希，更新时重跑对比。
- **行为抽测：** 在多轮和工具调用的评测集上和官方分数比较，模板问题在这里表现为显著下降。
