## Q
位置编号（position id）错位会导致什么样的输出问题？在推理引擎里，哪些功能最容易把位置编号算错？

## A
**位置编号：** 推理引擎给每个 token（文字切成的小片段）一个从 0 开始递增的编号，告诉模型它在第几个位置。现代模型用旋转位置编码（RoPE）：按位置编号把注意力里的查询向量和键向量旋转一个角度，模型据此判断词与词的先后和距离。

**错位的表现：** 不报错，输出"像人话但不对"：
- 开头几句正常，之后开始重复、跑题或胡言乱语；
- 多轮对话里忘记前文，或者把前后内容的顺序搞混；
- 只在特定长度、特定功能开启时出现，很难复现。

**最容易算错的场景：**
- **左侧填充（left padding）：** 把不同长度的输入补齐成一样长时，在左边补填充 token。位置编号应从第一个真实 token 开始算 0，而不是从填充开始，否则每个真实 token 的位置都被偏移。连续批处理的引擎通常不填充，但自写的参考脚本、离线批处理代码常踩这个坑。
- **前缀缓存命中：** 跳过已缓存部分的计算时，新部分的位置编号必须从"缓存长度"开始，而不是从 0 开始。
- **分块预填充：** 长输入切成几块分步处理，每块的起始位置必须是前面所有块的总长度。
- **抢占后重算：** 请求被暂停后重新计算，"原始输入 + 已生成部分"必须保持原来的位置编号。
- **投机解码：** 一次检查多个猜测的 token，它们的位置编号是连续的，被拒绝后要回退。
- **多模态：** 一张图片展开成几百个位置，后续文字的位置编号要算上它们；有的模型对图像 token 使用二维或特殊的位置编号方案。

**测试方法：**
- **功能开关等价：** 同一组请求，在开启和关闭前缀缓存、分块预填充、投机解码时比较贪心输出和每个位置的对数概率；位置错误会让差异从某个固定位置开始突然增大。
- **边界长度：** 让输入长度恰好跨过块大小、缓存块大小（如 16 的倍数正负 1）。
- **长度递增扫描：** 同一篇文档截取不同长度，看质量是否在某个长度后突然下降。
