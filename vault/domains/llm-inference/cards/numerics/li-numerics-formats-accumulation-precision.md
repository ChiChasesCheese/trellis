## Q
为什么矩阵乘法要"低精度输入、高精度累加"？用一个累加实验说明不这样做的后果，并说明对 FP8 计算有什么额外要求。

## A
**矩阵乘法的每个输出元素是很多乘积之和。** 一个 `[1, 4096] × [4096, 4096]` 的乘法，每个输出要把 4,096 个乘积加起来。

**累加器（accumulator）精度的影响：** 累加过程中，部分和越来越大，而每次加上的乘积可能很小。如果部分和本身用低精度保存，小的乘积会被舍入掉。

**实验：** 把 10,000 个 1 依次累加。

```python
import torch
acc = torch.tensor(0.0, dtype=torch.bfloat16)
for _ in range(10000):
    acc = acc + torch.tensor(1.0, dtype=torch.bfloat16)
print(acc)                                                   # tensor(256., dtype=torch.bfloat16)
print(torch.ones(10000, dtype=torch.bfloat16).float().sum())  # tensor(10000.)
```

BF16 只有 7 位尾数，在 256 附近相邻可表示数的间隔是 2，256 + 1 舍入回 256，之后再也加不动。用 FP32 累加则得到精确的 10,000。

**硬件的做法：** GPU 的 Tensor Core（专门做矩阵乘法的单元）读入 BF16 或 FP16 的输入，乘积在 FP32 的累加器里求和，最后再按需要转回 BF16 输出。所以"BF16 推理"实际上关键的求和都是 FP32 精度。

**FP8 的额外要求：**
- 输入只有 3 位（E4M3）或 2 位（E5M2）尾数，必须配缩放因子（scale）把数值放到格式擅长的范围内，否则大量数下溢为 0 或溢出。
- 累加器精度也很关键。有报告指出部分硬件的 FP8 矩阵运算内部累加精度不足完整 FP32，长求和（大 K 维度）时误差变大。DeepSeek-V3 的训练做法是每累加一段（如 128 项）就把部分和提升到 FP32 寄存器里继续累加。

**测试启示：**
- 自定义内核（GPU 上执行的计算函数）必须检查累加器的数据类型；把累加器错写成低精度，短向量测试能过，K = 8,192 这样的长维度才暴露。
- 测试形状要包括很大的归约维度，而不仅仅是 64、128 这类小尺寸。
- 归一化、softmax 这类归约操作也同样需要高精度累加。
