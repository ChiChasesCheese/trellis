## Q
面试里被问"线上用户反馈模型突然开始重复、乱码或答非所问，你怎么排查？"，怎么答？

## A
按这个顺序说：

- **先确定范围：** 是所有模型还是一个模型、所有请求还是某类请求（长输入、多轮、带图片、某种语言）、从什么时候开始。对照这个时间点的变更：引擎版本、模型权重、分词器或模板、驱动、配置，以及流量构成的变化。
- **拿到可复现的请求：** 用同样的输入、`temperature=0`，在当前版本和上一个已知正常的版本上分别运行；能稳定复现就二分变更，`git bisect run` 或逐个回退依赖版本。
- **从外往里查格式问题：** 看 `finish_reason` 和最后几个生成 token 的编号，判断是结束 token 识别问题还是被长度截断；把服务实际送进模型的 token 序列和 `apply_chat_template` 的结果逐 token 比较，找双重开始 token、缺少助手提示、系统提示丢失；乱码先查流式反分词是否切开了多字节字符。
- **再查数值问题：** 用教师强制把同一序列分别喂给服务和参考实现，比较逐位置的对数概率。差异从某个位置开始突然变大，指向位置编号、前缀缓存、分块预填充或长上下文缩放；所有位置都偏，指向权重、精度或量化；只在高并发时出现，检查请求之间是否串用了缓存。
- **逐个关闭功能缩小范围：** 前缀缓存、分块预填充、投机解码、CUDA Graph 逐个关掉，看问题是否消失。
- **收尾：** 修复后把这个请求做成回归用例，并补上缺失的那类检查，比如结束 token 集合的自动核对，或者功能开关的等价测试。
