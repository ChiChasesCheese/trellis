## Q
什么是批不变性（batch invariance）？哪些算子需要专门改造才能做到？代价多大？vLLM 怎么开启？

## A
**批不变性：** 一个请求的计算结果，与"同一批里还有哪些请求、一共有多少个"无关。做到这一点，温度为 0 时同一请求无论服务多忙都会得到逐位相同的输出。

**为什么默认做不到：** 为了在不同批大小下都跑得快，内核（GPU 上执行的计算函数）会根据形状选择不同的并行策略，其中一些策略改变了求和顺序。浮点加法不满足结合律，求和顺序不同，结果的最后几位就不同。

**需要改造的是三类"归约"（把很多数合成一个数）操作：**
- **RMSNorm（归一化）：** 要对一个向量的所有元素求平方和。批很小时，一些实现会把一个向量的求和拆给多个计算单元以提高并行度。改造：无论批大小，每个向量都用同一种方式归约。
- **矩阵乘法：** 批小时常用 split-K（把求和维度切成几段分别算再相加），段数随形状变化。改造：固定一种分块配置，不随批大小切换。
- **注意力：** 解码时把很长的历史拆成几段并行处理再合并（split-KV），拆法随批大小和长度变化。改造：按固定的段大小拆分，而不是按"固定段数"拆分，这样同一个位置的计算方式永远相同。

逐元素操作（激活函数、残差相加）本身就与批无关，不需要改。

**代价：** 放弃了针对形状的最优策略，速度下降。公开的测试里，Qwen3-8B 单卡生成 1,000 条约 100 token 的序列，默认 26 秒，批不变模式 42–55 秒。

**vLLM 中开启：**

```bash
VLLM_BATCH_INVARIANT=1 vllm serve meta-llama/Llama-3.1-8B-Instruct
```

文档标注为测试版功能，对硬件和模型有要求，多卡时部分通信路径还不能保证批不变。

**什么时候需要：** 强化学习训练中要求采样和打分数值一致；需要严格可复现的评测和调试；合规审计。对普通在线服务，通常接受非确定性，而在测试中按容差比较。
