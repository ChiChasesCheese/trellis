## Q
为什么比较两个推理实现时，用"教师强制"（teacher forcing）的方式比直接比较生成文本更可靠？怎样据此设计一套黄金测试（golden test）？

## A
**直接比较生成文本的问题：** 两个实现在某一步因为数值差异选了不同的 token，之后的输入就不同了，后面的所有位置都无法再比较。一个第 5 个 token 就分叉的用例，几乎什么信息都没提供；而且无法区分"近似平局翻转"和"真正算错"。

**教师强制：** 不让被测系统自己生成，而是把一段**固定的** token 序列（token 是文字切成的小片段）整体作为输入喂进去，取每个位置对"下一个 token"的分数。两边看到的输入完全相同，每个位置都可以逐一比较，无论多长都不会分叉。

**黄金测试的设计：**
1. **准备序列：** 选几百条覆盖不同领域、语言和长度的文本，最好包括参考模型自己生成的回答（这样最接近真实使用的分布），长度从几十到上万 token。
2. **生成黄金数据：** 用参考实现（固定版本、FP32 或 BF16、开启 PyTorch 确定性设置）对每条序列算出每个位置的前 k 名候选及其对数概率（比如 k = 20），存成文件，连同参考实现版本和模型哈希一起入库。
3. **被测系统计算：** 用同样的序列请求被测系统返回每个位置的对数概率。vLLM 等引擎支持返回输入部分的对数概率（如 `prompt_logprobs` 参数）。
4. **比较：** 每个位置计算近似 KL 散度（只用前 k 名）、top-1 一致率、真实 token 的对数概率差；按序列长度分段统计，比如 0–1K、1K–8K、8K 以上。
5. **门限：** 基于参考实现自身在不同精度和批大小下的差异来设定，并对每个长度段分别设。

**它能抓到的问题：**
- 从某个位置开始差异突然增大：位置编码、长上下文缩放、滑动窗口的边界错误。
- 某些序列整体差异大：特殊 token 或对话模板处理不同。
- 所有位置均匀偏移：精度或量化设置问题。

**局限：** 教师强制只测"每一步的判断"，不测采样、停止条件、流式拼接等生成过程。这些要靠单独的生成类测试覆盖。
