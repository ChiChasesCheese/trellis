## Q
面试里被问"为什么 LLM 推理在温度为 0 时也不确定？你在测试里怎么处理？"，怎么答？

## A
按这个顺序说：

- **根因不是"GPU 随机"：** 前向计算基本不用原子操作，同样的批重复运行通常是逐位相同的。真正的原因是服务会把不同用户的请求拼成一批，批大小随负载变化；内核根据形状选择不同的分块和拆分求和策略，比如矩阵乘法的 split-K、注意力的 split-KV、小批量下拆分的归一化；浮点加法不满足结合律，求和顺序变了，最后几位就变。
- **小差异怎么变成大差异：** 当前两名候选 token 的分数几乎相等时，微小扰动让名次翻转，之后整段输出分叉。公开实验里 Qwen3-235B 温度 0 跑 1,000 次得到 80 种结果，前 102 个 token 都相同。
- **怎么彻底消除：** 批不变的内核，让归一化、矩阵乘法和注意力的归约方式不随批大小变化。vLLM 用 `VLLM_BATCH_INVARIANT=1` 开启，代价是速度变慢，公开数据里慢了一半到一倍。
- **测试里怎么处理：** 不要求逐字相同。对不一致的用例找首次分叉位置，用教师强制比较分叉点的对数概率差，区分近似平局和真实差异；同时看公共前缀上的 logprob 漂移，以及评测集分数是否在统计误差内。
- **可复现的测试环境：** 参考实现用 PyTorch 的确定性设置固定，存成黄金结果；在测试里控制批组成，比如单发与混跑分开测，确认单发时完全确定。
- **收尾：** 把不一致率、近似平局占比、前缀漂移做成发布指标，既不漏掉真缺陷，也不被数值噪声误报淹没。
