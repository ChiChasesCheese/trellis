## Q
一次前向计算里，时间主要花在哪些操作上？短输入和长输入、处理输入和逐个生成时，各部分的占比怎样变化？

## A
把一层里的操作分成三类，以 7B 模型（宽度 d = 4,096，32 层）计：

- **矩阵乘法（Q/K/V/输出投影、前馈网络）：** 每个 token 约 2 × 参数量次浮点运算，7B 约 140 亿次。要读的数据是全部权重，14 GB（FP16，每数 2 字节）。
- **注意力里的打分和加权（Q·Kᵀ 和 权重·V）：** 每个 token 每层约 4 × 上下文长度 × d 次运算。要读的数据是这个请求已缓存的 K、V（KV 缓存：保存每个历史 token 每层的 K、V 向量，7B 模型每个 token 约 512 KB）。
- **逐元素操作（归一化、激活函数、残差相加、旋转位置编码）：** 运算很少，但每个都要把数据读写一遍。

**处理整段输入（预填充，prefill），比如 2,000 个 token：**
- 矩阵乘法：2,000 × 140 亿 = 28 万亿次运算，权重只读一遍被 2,000 个 token 分摊，**受算力限制**，占绝大部分时间。
- 注意力：每层 n² 级别。2,000 个 token 时只有矩阵乘法的约 5%；32,000 个 token 时变得和矩阵乘法相当甚至更多。

**逐个生成（解码，decode），批大小为 1：**
- 矩阵乘法：只有 140 亿次运算，却要读 14 GB 权重，**受内存带宽限制**。在 H100（约 3.35 TB/s）上约 4.2 毫秒。
- 注意力：读 KV 缓存。上下文 2,000 时约 1 GB，上下文 32,000 时（假设模型支持这么长）约 16 GB，比权重还大，此时注意力成为主要耗时。
- 逐元素操作和每个操作的启动开销（GPU 上每个小操作有几微秒启动时间，一层几十个操作）在小批量时占比可达百分之十几，所以推理引擎会把它们合并（算子融合）或用 CUDA Graph（把一整步的操作预先录制成一张图）一次性提交。

**测量工具：** `torch.profiler` 或 NVIDIA Nsight Systems（`nsys profile`）可以按操作列出耗时，先看矩阵乘法、注意力、其他三类各占多少，再决定优化方向。
