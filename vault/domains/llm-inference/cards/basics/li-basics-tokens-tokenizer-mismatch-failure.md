## Q
线上一个模型升级后，部分中文回答出现乱码，英文正常，模型权重没有变。怎么排查分词器相关的原因？

## A
**先建立判断：** 权重没变而输出变了，问题一定在模型"之外"，最可疑的就是分词器（把文字和编号互转的程序）和它的配置。中文受影响、英文不受影响，进一步指向**多字节字符**的处理。

**排查步骤：**
1. **比对分词器文件：** 对 `tokenizer.json`、`tokenizer_config.json` 算哈希，和上一个版本比较。依赖库升级（如 `transformers`、`tokenizers`）也可能改变行为，记录版本号。
2. **离线复现编码：** 用新旧两套环境对同一段中文 `encode`，比较编号序列。编号不同，说明输入侧就错了，模型看到的是"另一句话"。
3. **检查解码路径：** 编号相同但输出乱码，问题在把编号转回文字的环节。一个汉字在 UTF-8 里是 3 个字节，可能被拆成 3 个 token。流式输出时逐 token 解码，若服务把"不完整的字节"直接发给用户，就会出现 `�`。正确做法是缓冲到能解出完整字符再发送。
4. **看特殊 token：** 新版本是否改了开始标记或对话模板，导致模型看到的格式和训练时不一样，输出质量整体下降，中文更明显。
5. **回归测试补洞：** 加入一组固定的多语言样本，比较新旧版本的编码序列和流式拼接后的最终文本，全部一致才允许发布。

**根因常见分布：** 依赖库升级改了默认行为、分词器文件没随模型一起发布、流式解码没有处理字节边界。三者都不改权重，都能让输出变坏。
