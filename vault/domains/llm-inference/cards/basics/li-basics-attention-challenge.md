## Q
**挑战。** 产品要把 7B 模型的输入上限从 2,000 token 提到 32,000 token（把整份合同贴进去）。负责人说"模型没变，成本应该差不多"。按注意力的机制估算：处理输入的计算、KV 缓存、一张 80 GB 卡能同时服务的对话数、每个新 token 的生成，各怎么变？

## A
**评分点（答出 3 条算过）：**

1. 输入长 16 倍：注意力里的两两比较约为长度平方的一半，是 256 倍（200 万次到 5.12 亿次）；其余按 token 数线性增长的计算是 16 倍。首 token 延迟明显变长。
2. KV 缓存每个 token 512 KB：2,000 token 约 1 GB，32,000 token 约 16 GB。
3. 80 GB 的卡放下 14 GB 权重后剩约 60 GB：同时进行的对话从约 60 个降到 3 个。
4. 生成每个新 token 要读 14 GB 权重再加 16 GB 缓存，每步读的数据多了一倍多，出字速度约减半。
5. 应对：只放相关的段落（检索）、缓存多个请求共用的前缀、按 token 计费和限流。

<details class="pt"><summary>参考答案</summary>成本会大幅上升。输入长 16 倍，注意力的两两比较随长度的平方增长，是 256 倍，其余计算是 16 倍，所以首 token 延迟明显变长。KV 缓存每个 token 占 512 KB，一段对话从约 1 GB 涨到约 16 GB，一张 80 GB 的卡放下权重后只剩约 60 GB，同时能进行的对话从约 60 个降到 3 个。生成时每一步除了读 14 GB 权重还要读 16 GB 缓存，出字速度约减半。所以应该只把相关段落放进上下文，并对共用的前缀做缓存。</details>
