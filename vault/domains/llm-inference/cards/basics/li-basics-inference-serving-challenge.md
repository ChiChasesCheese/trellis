## Q
**挑战。** 监控显示：晚高峰时，首 token 延迟（TTFT）的 p99 从 0.3 秒涨到 4 秒，每 token 间隔（TPOT）稳定在 5 毫秒，GPU 利用率没有到顶。值班同事准备"换更快的 GPU"。问题出在哪一段？你会查什么，怎么治？

## A
**评分点（答出 3 条算过）：**

1. TTFT = 排队 + 预填充；TPOT 没变，说明生成阶段正常，问题在第一个 token 之前。
2. 预填充本身是几十毫秒的量级（除非输入突然变得极长），4 秒主要是排队：请求在等一个空位。
3. 查：队列长度和等待时间；同时进行的对话数上限（常被 KV 缓存占的显存卡住）；有没有超长输入堵在前面；p99 落在哪类请求上。
4. 治：加副本，显存允许时提高并发上限，限流，按输入长度分队列。更快的 GPU 主要改善 TPOT，对排队帮助有限。
5. 指标要分开报：TTFT、TPOT、排队等待各自的分位数；只看平均值或 GPU 利用率看不出这个问题。

<details class="pt"><summary>参考答案</summary>问题在第一个 token 之前。TTFT 由排队和预填充两部分组成，TPOT 没有变化说明 GPU 的生成阶段是正常的，而预填充通常只有几十毫秒，所以 4 秒主要是请求在队列里等空位。要查队列长度和等待时间、同时进行的对话数上限是不是被 KV 缓存的显存卡住、有没有超长输入堵在前面。治理办法是加副本、在显存允许时提高并发上限、限流和按输入长度分队列。换更快的 GPU 主要缩短每 token 间隔，解决不了排队。</details>
