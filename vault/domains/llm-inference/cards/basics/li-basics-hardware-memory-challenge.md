## Q
**挑战。** 供应商推销新芯片："算力（FLOPS）是 H100 的 2 倍，显存带宽相同，所以聊天机器人的出字速度翻倍。"你们的负载是 7B 模型、长回答、每张卡的并发不高。这句话对不对？哪个指标会改善，哪个不会？

## A
**评分点（答出 3 条算过）：**

1. 生成阶段每步只算一个 token，运算量很小（约 140 亿次，约 0.014 毫秒），时间花在把 14 GB 权重读一遍（约 4.2 毫秒）：瓶颈是带宽，不是算力。
2. 带宽不变，单用户出字速度上限仍是 3,350 ÷ 14 ≈ 240 token/s，不会翻倍。
3. 会改善的是受算力限制的部分：长输入的预填充（首 token 延迟里的计算部分），以及并发高到上百时的总吞吐。
4. 要让出字更快：换更高带宽的内存，或让每步读的字节更少（参数压到 4 位，上限约 4 倍）。
5. 验收：用自己的负载分别测首 token 延迟和每 token 间隔，不接受一个笼统的"快 2 倍"。

<details class="pt"><summary>参考答案</summary>不对。生成时每一步只为一个 token 做计算，运算只要约 0.014 毫秒，而把 14 GB 权重从显存读一遍要约 4.2 毫秒，所以出字速度由显存带宽决定。带宽相同，上限仍是约 240 token/s。算力翻倍能改善的是长输入的预填充，也就是首 token 延迟里的计算部分，以及并发很高时的总吞吐。想让出字更快，要么换带宽更高的内存，要么把参数压缩，让每一步读的数据更少。</details>
