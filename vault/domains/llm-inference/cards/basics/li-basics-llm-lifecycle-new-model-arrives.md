## Q
一个新的开源大模型发布后，推理服务团队要先看清它的哪些属性？每个属性影响服务的哪个方面？

## A
拿到一个新模型，先读它的配置文件和发布说明，回答以下问题。每一项都直接决定部署方式或测试重点。

- **参数规模和数据类型：** 比如 70B、BF16，权重 140 GB。决定需要几张卡、怎么切分、加载要多久。
- **是不是混合专家（MoE）模型：** 混合专家模型每层有很多组前馈网络，每个 token 只走其中几组。总参数决定显存，激活参数决定速度；还要关心各组之间负载是否均衡。
- **层数、宽度、注意力头的配置：** 尤其是 K、V 有几组（分组查询注意力让多个查询头共用一组 K、V）。它决定每个 token 的 KV 缓存多大，直接决定同时能服务多少用户。
- **上下文长度和位置编码参数：** 比如 128K、`rope_scaling` 的类型和系数。长上下文要专门测，配置抄错会导致长文本质量崩溃。
- **分词器和对话模板：** 词表多大、结束标记是哪个（甚至可能有好几个）、`chat_template` 的格式，是否支持工具调用和"思考"段落。
- **输入类型：** 是否接收图片、音频（多模态）。需要额外的预处理和图像编码部分。
- **许可证与版本：** 权重文件的版本号和哈希，以及是否允许商用。

**为什么要逐项确认：** 推理引擎常常靠模型结构名（如 `LlamaForCausalLM`）选择实现。新模型名字相同但细节不同（比如某个归一化参数、注意力的特殊变体），引擎会"成功加载、静默算错"。所以新模型上线必须和官方参考实现做数值对比，而不是"能跑就行"。
