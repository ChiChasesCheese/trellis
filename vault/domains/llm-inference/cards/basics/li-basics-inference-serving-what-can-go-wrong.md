## Q
从测试的角度看，一个大模型推理服务会以哪些方式"出错"？各举一个具体例子和发现它的办法。

## A
推理服务的错误分四类，前两类最危险，因为往往不报错。

- **算错（数值正确性）：** 输出质量悄悄下降。例子：新驱动或新的计算实现让某层结果有微小偏差，长回答后半段开始重复。发现办法：和参考实现逐层、逐 token 比较分数；固定评测集上的正确率和基线比较。
- **格式和协议错（功能正确性）：** 模型本身没问题，服务的"外壳"错了。例子：结束标记配错，回答不停；流式输出把一个汉字的字节拆开，出现乱码；`usage` 里的 token 计数和实际不符，计费出错；停止字符串没被去掉。发现办法：接口层的契约测试，覆盖每个参数和每种结束原因。
- **变慢（性能回归）：** 结果对但慢了。例子：某次升级后首 token 延迟 P99 从 400 毫秒涨到 900 毫秒，原因是调度策略变化导致长输入阻塞短请求。发现办法：固定负载下的基准测试，和上一版本的基线比较，超过阈值阻断发布。
- **崩溃和资源耗尽（稳定性）：** 例子：长上下文请求在高并发下耗尽显存，进程崩溃；客户端断开后请求未取消，资源泄漏；某个请求触发异常，拖垮同批的其他请求。发现办法：压力测试、长时间浸泡测试（soak test）、故障注入（中途断开、超长输入、非法参数）。

**一个快速上手的测试环境：**

```bash
vllm serve meta-llama/Llama-3.1-8B-Instruct --port 8000
curl localhost:8000/v1/chat/completions -H 'Content-Type: application/json' \
  -d '{"model":"meta-llama/Llama-3.1-8B-Instruct","messages":[{"role":"user","content":"1+1=?"}],"temperature":0,"max_tokens":20}'
```

`temperature: 0` 让输出尽量可复现，`max_tokens` 限制输出长度。四类问题都可以从这样一个本地服务开始复现。
