## Q
衡量一个推理服务"快不快"有哪几个基本指标？分别对应用户的什么感受？用一个 7B 模型的例子给出量级。

## A
- **首 token 延迟（TTFT，time to first token）：** 从发出请求到收到第一个字。用户感受是"它开始回答了没有"。由排队时间 + 处理整段输入（预填充）的时间组成。7B 模型、500 token 输入、单卡空闲时约几十毫秒；排队严重时可以到几秒。
- **每 token 间隔（TPOT，time per output token；逐个间隔也叫 ITL，inter-token latency）：** 生成阶段相邻两个字之间的时间。用户感受是"字蹦得快不快"。7B 模型在 H100 上单用户约 5 毫秒，即每秒约 200 个 token；人阅读速度每秒只有几个到十几个 token。
- **端到端延迟（end-to-end latency）：** 从请求到最后一个字。约等于 TTFT + TPOT × (输出 token 数 − 1)。300 token 的回答约 1.5 秒。
- **吞吐（throughput）：** 整台机器每秒总共生成多少 token，或每秒完成多少请求。决定成本。
- **有效吞吐（goodput）：** 只统计**满足延迟目标**的那部分吞吐。例如要求 TTFT < 1 秒且 TPOT < 50 毫秒，超标的请求不算数。

**单用户速度和总吞吐是一对矛盾：** 多个请求凑成一批，读一次参数服务多人，总吞吐上升；但每一步算得更久，每个人的 TPOT 变长。所以只报一个数字没有意义，必须说明"在多少并发下"。

**测量时的注意点：**
- 看分布而不是平均值：报告 P50、P90、P99。
- 输入和输出长度要贴近真实流量，长度不同，结论完全不同。
- 客户端计时包含网络，服务端计时不包含，对比时要用同一口径。
