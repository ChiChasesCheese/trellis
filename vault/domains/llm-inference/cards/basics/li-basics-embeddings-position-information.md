## Q
只把每个 token 查表变成向量，模型怎么知道词的顺序？位置编码（positional encoding）有哪些做法，出错会怎样？

## A
**问题：** 查表只看编号，"狗咬人"和"人咬狗"查出来的是同一组向量，只是顺序不同。而模型内部比较词与词关系的运算（注意力）本身不关心先后顺序，所以必须**额外告诉模型每个 token 在第几个位置**。

**三类做法：**
- **固定正弦编码：** 最早的 Transformer 论文用不同频率的正弦、余弦函数为每个位置生成一个向量，加到 token 向量上。
- **可学习的位置向量：** 再建一张表，第 0 个位置、第 1 个位置……各一行，训练出来，加到 token 向量上（GPT-2 这样做）。缺点是只能处理训练时见过的最大位置。
- **旋转位置编码（RoPE，rotary position embedding）：** 当今主流（Llama、Qwen 等）。不加在输入上，而是在每层比较词与词时，把向量按位置旋转一个角度。两个词的比较结果只取决于它们**相对相隔多远**，因此更容易外推到更长的文本。

**位置编号由谁提供：** 推理引擎为每个 token 传入一个位置编号（position id），从 0 开始递增。

**出错的后果：**
- **位置编号错位：** 例如多轮对话复用缓存时位置从 0 重新开始，模型"以为"新内容在最前面，回答开始答非所问，但不报错。
- **超出训练长度：** 模型只训练到 4,096，强行输入 8,000 个 token，后半段输出质量急剧下降。扩展长度要用专门的缩放方法，并且配置里的参数（如 `rope_theta`、`rope_scaling`）必须和模型发布时一致。

**测试要点：** 同一句话放在长对话的不同位置，回答质量应一致；长度接近上限时抽查输出。
