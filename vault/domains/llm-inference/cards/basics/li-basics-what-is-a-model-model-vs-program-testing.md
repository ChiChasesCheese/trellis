## Q
既然模型的"逻辑"藏在几十亿个数字里，测试一个模型和测试普通代码有什么根本不同？

## A
普通代码有明确的规格，测试是"输入 X 必须得到 Y"。模型没有逐条规则，只有统计意义上的好坏，所以测试方法要换。

- **没有唯一正确答案：** 问"写一首关于秋天的诗"，好答案有无数个。不能用 `assertEqual` 检查整段输出。
- **有些地方仍然能精确比：** 同一份权重、同一输入，用参考实现（比如 PyTorch 原始代码）算出每个候选词的分数，再用被测系统算一遍，两边的数字应在容差内一致。这是模型测试里最硬的一类检查。
- **用统计指标代替断言：** 拿几千道有标准答案的题（数学题、选择题）跑一遍，看正确率有没有比上个版本掉。掉 0.3 个百分点可能是噪声，掉 5 个点一定有问题。
- **输出带随机性：** 生成文字时模型常常"抽签"选词，同一个问题两次回答可以不同。测试要么固定随机种子、关掉随机，要么多跑几次看分布。
- **错误往往是静默的：** 程序不崩溃、不报错，只是答案变差了一点。比如数值精度降低导致长文本后半段胡言乱语。只有和基线对比才能发现。

所以模型测试的骨架是：**参考实现对比（精确到容差）+ 评测集分数（统计）+ 和上一版本的回归对比**。
