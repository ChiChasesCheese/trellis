## Q
面试里被问"一个 70B 模型怎么部署到多张卡上？张量并行和流水线并行怎么选？"，怎么答？

## A
按这个顺序说：

- **先算账：** 70B 模型 BF16 权重约 140 GB，一张 80 GB 卡放不下；还要给 KV 缓存（每个请求历史 token 的键、值向量）留空间，每 token 约 320 KB。所以至少 2 张，实际常用 4 或 8 张，把多出的显存留给缓存。
- **张量并行：** 把每一层的矩阵切到 N 张卡，每卡算一部分，每层两次全体求和合并结果。好处是每卡只读 1/N 的权重，单请求的每 token 延迟直接下降；代价是每步上百次通信，需要 NVLink 这类机内高速互联，一般不跨机器。
- **流水线并行：** 按层切成几段，段间只传每个 token 的激活向量，几十 KB，可以跨机器。它不降低单请求延迟，因为一个 token 仍要串行走完所有段；要靠多组请求同时在途填满流水线来提高吞吐，流量不足会有空闲气泡。
- **我的选择：** 单机 8 卡能放下就用 TP = 8，再用数据并行复制多份扩容；放不下才在机器之间加 PP。MoE 模型的专家部分用专家并行。
- **测试和验证：** 不同 TP、PP 配置下和单卡或参考实现比较 logprobs 与 top-1 一致率，因为求和顺序变化会带来微小数值差异；性能上扫并发，看每卡吞吐是否随卡数合理变化；稳定性上设置通信超时、做杀进程的故障注入，防止挂死。
- **一句总结：** TP 换延迟、PP 换容量、DP 换吞吐，选择取决于模型大小、互联带宽和延迟目标。
