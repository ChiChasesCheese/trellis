## Q
专家并行（expert parallelism，EP）推理一层混合专家时，数据是怎样在卡之间流动的？通信代价有多大？

## A
**专家并行：** 混合专家模型（每层有很多"专家"前馈网络，每个 token 只走其中 k 个）的专家太多，一张卡放不下，就把不同的专家放到不同的卡上。比如 256 个专家放 32 张卡，每卡 8 个。

**一层的流程：**
1. **路由：** 每张卡对自己手上的 token 运行路由器，决定每个 token 去哪 k 个专家。
2. **分发（dispatch）：** 把每个 token 的向量发到它要去的专家所在的卡。这是一次**全体对全体（all-to-all）**通信：每张卡都要给其他每张卡发送一份不同的数据。
3. **专家计算：** 每张卡把收到的 token 交给本地专家计算。
4. **汇合（combine）：** 再做一次全体对全体，把结果送回 token 原来所在的卡，按路由权重加权求和。

所以**每个混合专家层有两次全体对全体通信**。

**通信量估算：** 隐藏宽度 7,168、BF16 每数 2 字节、top-8：一个 token 在一层里要发出 8 份向量，约 8 × 14 KB ≈ 115 KB，去程和回程各一次。一批 4,096 个 token、61 层，每步跨卡传输量是几十 GB 量级，必须依赖高带宽互联（机内 NVLink、跨机 RDMA 网络）。分发阶段常用 FP8 传输以减半数据量。

**代价和优化：**
- **小批量解码时延迟主导：** 每层两次全体对全体，每次几十到上百微秒，乘以几十层就是毫秒级。
- **计算与通信重叠：** 把一批拆成两半，一半在通信时另一半在计算。
- **专用通信库：** 如 DeepEP 为这种分发和汇合专门优化，分别提供高吞吐（预填充用）和低延迟（解码用）两种模式。
- **注意力部分和专家部分并行方式不同：** 注意力常用数据并行（每卡处理不同请求），专家用专家并行，两者之间的切换本身就需要数据重排。

**测试要点：** 比较不同 EP 规模下的输出与单机参考是否在容差内；在网络带宽受限（比如降速或单链路故障）时测吞吐的退化曲线；注意某张卡负载过重时，全体对全体会被它拖慢。
