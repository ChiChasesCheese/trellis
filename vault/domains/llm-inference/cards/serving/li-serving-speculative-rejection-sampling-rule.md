## Q
投机解码为什么能保证输出分布和只用大模型完全一样？讲清"接受或拒绝"的规则，并手算一个例子。

## A
**符号：** 对某个位置，大模型（目标模型）给出下一个 token 的概率分布 p，起草者给出分布 q。起草者按 q 抽出了候选 token x。

**规则：**
1. 以概率 `min(1, p(x) / q(x))` **接受** x。
2. 如果拒绝，就从修正分布 `norm(max(0, p − q))` 里重新抽一个 token。norm 表示把非负部分重新归一化，使其总和为 1。
3. 一旦某个位置被拒绝，它之后的所有起草 token 一律丢弃（它们建立在一个错误的前提上）。

**手算：** 词表只有 A、B 两个 token。
- 大模型：p(A) = 0.6，p(B) = 0.4
- 起草者：q(A) = 0.9，q(B) = 0.1

起草者抽到 A 的概率 0.9。接受概率 = min(1, 0.6/0.9) = 2/3。
- 最终输出 A 的路径：起草 A 且被接受 = 0.9 × 2/3 = **0.6**。
- 起草 A 被拒绝的概率：0.9 × 1/3 = 0.3。拒绝后从 max(0, p − q) = (A: 0, B: 0.3) 归一化得到 (A: 0, B: 1) 中抽，必然是 B。
- 起草 B 的概率 0.1，接受概率 min(1, 0.4/0.1) = 1，必然接受。
- 最终输出 B：0.3 + 0.1 = **0.4**。

结果恰好是 (0.6, 0.4)，与大模型的分布 p 完全一致。

**贪心解码的特例：** `temperature=0` 时 p 是"最高分的 token 概率为 1"，规则退化为"起草 token 等于大模型的最高分 token 就接受，否则用大模型的最高分 token 替换"。所以输出应和不开投机解码时**逐字相同**。

**实践中的例外：** 理论上无损，但大模型一次检查多个位置与逐个生成时，矩阵形状不同、求和顺序不同，数值有微小差异。在两个候选概率极其接近处，贪心输出也可能分叉。vLLM 文档明确说明只保证到硬件数值精度为止，且不保证 logprobs（每个 token 的对数概率）稳定。
