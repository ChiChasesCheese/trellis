## Q
**Whiteboard layout · 版面**｜原则 · 必会

面试中你在共享白板上画系统设计图。画到一半发现左边挤满了，只好把数据库塞在角落，箭头交叉成一团。事先该怎么规划版面？

## A
**原则：** 白板是给对方**随时读得懂**的，不是你的草稿纸。留出位置、按固定方向画、给东西编号，图不用重画也能一路加下去。

**怎么做：**

| 做法 | 为什么 |
|---|---|
| 请求从左到右流 | 读图习惯和讲述顺序一致 |
| 先画主路径的几个框，周围留白 | 后面加缓存、队列时有位置 |
| 给步骤编号（1、2、3） | 讲述时可以说"回到第 3 步" |
| 表的关键字段写在数据库框旁边 | 讲数据时不用翻页 |
| 角落放一个小图例或约束清单 | 复述需求时可以指着它 |
| 白板工具提前练熟 | 面试时不用边讲边摸索软件 |

**常见错法：**
- **一开始就画满：** 没有位置加后面的东西，只能擦掉重画。
- **箭头不标内容：** 对方不知道线上流的是什么。
- **字段类型写满：** 对方看得出来，写了只会拖慢你。

**示例：** 左侧放 Client，中间放 API 和 Service，右侧放 DB 和 Cache，顶部留一条给 Queue；每条箭头旁写 `1 POST /orders`、`2 write`、`3 publish`。
