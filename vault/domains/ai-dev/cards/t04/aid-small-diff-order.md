## Q
**读 diff 的顺序**｜实践 · 追问

一个 400 行的 AI diff，你有 20 分钟。读的顺序和每一步看什么？

## A
| 顺序 | 看什么 | 原因 |
|---|---|---|
| 1 | 测试文件的改动 | 先排除"为过测试改了测试"；测试说明了它**打算**做什么 |
| 2 | 范围：改了哪些文件 | 超出 spec 的文件改动要问为什么 |
| 3 | 错误处理和边界 | 吞错误、默认值掩盖失败 |
| 4 | 新增依赖和 API 调用 | 包是否存在、方法是否真实 |
| 5 | 主逻辑 | 前面都过了才值得细读 |

**做：** 每读完一段，用自己的话说出它做了什么；说不出来的段落，标记并问 agent 或打回。
**别做：** 从第一行读到最后一行、读完才发现整个方向偏了。

**出处：** Claude Code docs《Best practices》（Review against your spec）
