## Q
**测试质量 · 变异测试**｜考点 · 追问

agent 写的测试覆盖率 95%，全部通过。变异测试报告说 40% 的 mutant 存活。这意味着什么？

## A
**变异测试的做法：** 工具把实现里的小处改坏（`>` 改成 `>=`，`+` 改成 `-`，删一行），每个改坏的版本叫一个 mutant；跑测试，**测试应该失败**，失败就是 mutant 被杀死。

| 结果 | 含义 |
|---|---|
| mutant 被杀死 | 测试能发现这类错误 |
| mutant 存活 | 实现被改坏了，测试仍全绿：**这一行实际没有被断言** |

**回到题目：** 覆盖率只说"这行被执行过"，不说"这行的结果被检查过"。40% 存活说明测试在运行很多代码但很少断言——典型的"只断言实现"的伪测试。

**怎么处理：** 对存活的 mutant，让 agent 补一个能杀死它的测试（先看它在原实现上通过，在 mutant 上失败）；不要为了数字好看加没有意义的断言。

**出处：** 概念出处：Claude Code docs《Best practices》（Give Claude a check to run：check 要能分辨通过与失败）
