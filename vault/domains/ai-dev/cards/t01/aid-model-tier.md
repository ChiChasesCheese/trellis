## Q
**Model tier · 强模型与快模型**｜实践 · 追问

团队要对 400 个文件做同一种机械改动，规划阶段又很复杂。每个阶段该用什么档位的模型和 effort？

## A
| 阶段 | 档位 | 理由 |
|---|---|---|
| 规划（拆解、找所有读者、做取舍） | 强模型，effort 高 | 漏看一个边界情况，后面全部返工 |
| 机械批量改动（模式固定） | 快、便宜的模型，effort 低 | 每个文件工作量小，吞吐与成本更重要 |
| 小型辅助任务（收集 import 某模块的文件） | 最小档位 | 不需要深度推理 |

**做：** 官方文档的建议：日常功能开发默认 effort 够用；调试自己没写过的代码、flaky 测试、要找全所有引用的改动时调高；快速来回、你本来就逐步检查时调低；最高档只留给你不在场也要它独立啃的难题，普通任务上它容易想过头，花得更多而答案不见得更好。

**别做：** 全程用最贵的档位，或全程用最便宜的档位。

**时效：** 具体型号名、默认 effort、价格都会变（2026-11 的文档默认值是 medium）；"规划用强、机械活用快、按任务调 effort"这个结构不变。

**出处：** Claude Code docs《Best practices》（Change the model and effort）
