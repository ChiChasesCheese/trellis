## Q
**验证：走一遍对局**｜低层设计 · 题目拆解

写完代码后，面试里怎样验证 makeMove 与 checkWin 是对的？拿什么样的局面走查最有效？

## A
**要点。** 构造一个已有若干子的局面再走几步，别从空盘开始。例：第 0 列底部已有红子两枚，红方在第 0 列再下，落在第 3 行；`checkWin(3, 0, RED)` 往下数到 2 个同色，总数 3，未赢，换黄方；黄方随便下一步后又轮到红方，红方再落第 0 列到第 2 行，往下数到 3 个，总数 4，状态变 WON。此后黄方再下，`state != IN_PROGRESS`，立即返回 false。

**为什么。** 这一条路径同时验证了落点、垂直连线、状态转换和结束后拒绝。

**取舍。** 不必把每一步状态都写满白板，口头走几个测试用例通常就够；目的是赶在面试官之前发现逻辑漏洞。
