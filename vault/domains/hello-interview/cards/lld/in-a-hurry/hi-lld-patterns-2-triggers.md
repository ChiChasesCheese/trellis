## Q
**从需求措辞想到哪个模式**｜低层设计 · 速览

低层设计面试里，需求中出现哪些措辞，应该联想到哪种设计模式？请给出八个常用模式的触发信号。

## A
| 信号 | 模式 |
|---|---|
| 调用方不该关心具体建哪个类 | 工厂 |
| 对象有很多可选字段、构造复杂 | 建造者 |
| 需要全局唯一实例（很少） | 单例 |
| 可选功能、可叠加的增强 | 装饰器 |
| 隐藏内部复杂度，一个简单入口 | 外观 |
| 一堆 if/else 按类型分支，可互换的做法 | 策略 |
| “通知”“更新多个组件” | 观察者 |
| “状态”反复出现，转换规则复杂 | 状态机 |

**易错。** 触发信号只是提示，不是命令：需求没描述复杂对象就不需要建造者；简单规则用不上状态机。

**要点。** 最常被问的是策略，其次是观察者；状态机一旦出现，通常是整个设计的核心。
