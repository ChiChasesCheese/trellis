## Q
**API 与数据建模的安全默认值**｜系统设计 · 速览

面试里 API 设计和数据建模各自该花多少精力？关系型与 NoSQL、规范化与反规范化的默认选择是什么？

## A
**要点。**

- API：默认 REST（资源对应 URL，HTTP 方法操作资源，如 `POST /events/{id}/bookings`）。几分钟内勾勒 4 到 5 个核心端点就走，10 分钟了还在抠接口细节说明陷得太深。大结果集用分页（实时数据多的用游标分页，其他偏移分页即可）；认证用户用 JWT，服务间用 API key；可能被滥用时提一句限流。
- 数据模型默认：关系型（如 Postgres）加规范化，结构清晰、有关系、要强一致与事务时合适；NoSQL（DynamoDB、MongoDB）适合灵活 schema 或要免联表水平扩展的场景。
- 反规范化是后来的优化：识别出读热点后再针对性冗余，代价是更新要改多处。读多写少、数据很少变的场景值得。

**易错。** 一上来就反规范化；NoSQL 必须先知道所有查询模式，例如按用户取帖很快，按话题标签取帖就得全表扫描。
