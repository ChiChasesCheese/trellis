## Q
**核心实体与 API 怎么定**｜系统设计 · 速览

系统设计面试里，核心实体和 API 这两步各自怎么做？协议怎么选，用户身份该怎么传？

## A
**核心实体（约 2 分钟）。** 列出实体的要点清单当作初稿，不要一上来写完整数据模型，因为设计中还会发现新的实体与关系。问自己：系统里的参与者是谁，是否重叠；满足功能需求需要哪些名词或资源。命名要认真，有人会借此看你取名的能力。推特例子：用户、推文、关注。

**API（约 5 分钟）。** 默认选 REST，用 HTTP 动词操作资源，资源名用复数名词（`/v1/tweets`）；GraphQL 适合客户端多样、数据需求各异；RPC（如 gRPC）适合对性能敏感的内部服务调用。实时功能再补 WebSocket 或 SSE，但先设计核心 API。

**易错。** 当前用户从认证令牌里取，不要用请求体或路径参数传用户 ID，否则可被冒充。
