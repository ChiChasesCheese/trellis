## Q
**生成唯一短码：前缀、哈希**｜系统设计 · 问题拆解

生成短码有哪几种思路？为什么取长链接前缀不行？哈希方案怎么做、碰撞怎么处理？

## A
**约束。** 唯一、尽量短、生成高效。

**差的方案：取前缀。** 以长链接前 8 个字符为码，任何前缀相同的链接都撞车，无法唯一。

**哈希方案。** 对规范化后的 URL 做哈希（如 SHA-256），转 base62 取前 N 位，N=8 时有 62^8 约 218 万亿种。base62 不用 base64 的 `+` 和 `/`，因为斜杠是路径分隔符，加号在查询串里可能被当作空格。纯哈希是确定性的：同一长链接总得同一码，要多码或防猜测时加秘密盐（HMAC）。

**碰撞。** 已用 n 个码、码空间 |S| 时，下一个冲突的概率为 n/|S|。对短码列加 UNIQUE 约束，冲突就加随机盐重试，限制重试 3 到 5 次。

**取舍。** 唯一、短、高效三者难兼得，码越长越不容易撞，但就不短了。
