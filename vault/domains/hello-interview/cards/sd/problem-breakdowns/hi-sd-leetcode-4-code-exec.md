## Q
**在哪里运行用户提交的代码**｜系统设计 · 问题拆解

判题要运行不可信的用户代码。直接在 API 服务器上跑、放进虚拟机（VM）、放进容器（container）、放进无服务器函数（serverless），各自的优缺点是什么？最终怎么选？

## A
**差：API 服务器直接跑。** 有安全风险（删数据、外传、挖矿、发起 DDoS），代码吃 CPU，死循环或内存泄漏会拖垮服务，进程崩溃会让整个服务器不可用。

**中：虚拟机。** 隔离强、崩溃可重置，但每个 VM 带完整操作系统，启动慢、资源重，生命周期管理不当会造成浪费。

**好：容器（Docker）。** 与宿主共享内核，只含应用和依赖，轻量、启动快；每种语言一个运行时容器，多次提交复用。代价是隔离弱于 VM，要自行配置加固并限制资源，防止逃逸。

**好：无服务器函数。** 自动伸缩，适合突发的 CPU 密集任务；问题是冷启动延迟和资源上限。

**取舍。** 选容器：提交量波动不大，也不想承担冷启动。流程是 API 服务器把代码和题目发给对应语言的容器，容器内不发起外部调用，管理容器的 worker 同步执行并读取输出，结果存库后返回。判题耗时数秒，属于长耗时任务模式。
