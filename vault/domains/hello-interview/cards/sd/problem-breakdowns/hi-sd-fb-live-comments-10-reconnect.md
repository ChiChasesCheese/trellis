## Q
**断线重连与补拉评论**｜系统设计 · 题目拆解

直播评论的观众常因网络切换、切后台而断线。请说明忽略断线的问题，以及利用 SSE 的 Last-Event-ID 加客户端记录位置怎样补拉遗漏的评论，需要注意哪些限制。

## A
**不处理（差）。** 重连后只能看到之后的新评论，比如精彩一刻前后网络断了 5 秒，就错过了全部反应；断得久的更是没有任何上下文。

**Last-Event-ID（好）。** 每条推送都带事件 ID（用评论 ID），浏览器重连时自动带上最后收到的 ID，服务器据此先重放遗漏的评论，再继续推流。客户端也可以自己记最后评论 ID（localStorage 或应用存储），用 HTTP `GET ...?since=...&limit=100` 显式补拉，再以 2 到 3 倍速动画展示，或提示“你错过了 47 条”。移动端在切后台前主动断开，回前台再补拉，更省电。

**限制与细节。** 重放要有上限，比如只补最近 5 分钟；重连可能落到另一台服务器，因此要用共享的 Redis 缓存存近期评论；SSE 推送和 HTTP 补拉同时到达时，客户端按评论 ID 去重合并。
