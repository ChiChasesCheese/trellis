## Q
**热点键：滥用流量与合法的大客户**｜系统设计 · 问题拆解

某个用户或 IP 每秒产生数万请求，让一个 Redis 分片过载，怎么处理？合法大客户和滥用流量分别怎么办？

## A
**成因。** 单一来源要产生足以压垮分片的流量，通常是滥用（DDoS、配置错误的机器人），也可能是合法的高流量客户端（分析系统、数据管道、刷新太频繁的移动端）。

**合法大客户。**
- 客户端限流：鼓励 SDK 内置限流并遵守响应头，是服务端保护的补充，不能替代
- 请求批处理：把多个操作合并成一次请求，减少检查次数
- 高级套餐：给需要的用户更高限额，甚至专用基础设施

**滥用流量。**
- 自动封禁：持续触发限流（如一分钟 10 次）就加入黑名单，名单可放在某个 Redis 分片，缓存未命中时才查
- DDoS 防护：Cloudflare 或 AWS Shield 在到达限流器前拦截

**易错。** 公司 NAT、公共 WiFi 下多个合法用户共用 IP，设计时就给 IP 限额放宽，更多依赖登录用户限额，而不是事后处理热点。
