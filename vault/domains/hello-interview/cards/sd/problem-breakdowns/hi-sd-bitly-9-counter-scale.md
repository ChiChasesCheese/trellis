## Q
**横向扩展写服务后的计数器**｜系统设计 · 问题拆解

写服务有多个实例时全局计数器怎么保证唯一且不成为瓶颈？计数器批量分配、高可用和多地域怎么做？

## A
**单一事实来源。** 用集中的 Redis 实例做计数器，各实例都向它原子 `INCR`。一次网络请求相对其他操作开销很小；单个 Redis 能处理十万以上操作 / 秒，远超短链创建速率。

**批量（counter batching）。** 每个写实例一次申请一批（如 1000 个），Redis 原子地加 1000 并返回起点，实例在本地用完再申请，减少对 Redis 的请求。

**高可用。** Redis Sentinel 或 Redis Cluster 自动故障转移。若在复制前宕机会丢几个值，但只需唯一而非连续，可接受；数据库短码上的 UNIQUE 约束是最终保险。

**多地域。** 给每个区域分配互不重叠的计数区间（A 区 0 到 10 亿，B 区 10 亿到 20 亿），写入走本地 Redis，避免跨区协调。
