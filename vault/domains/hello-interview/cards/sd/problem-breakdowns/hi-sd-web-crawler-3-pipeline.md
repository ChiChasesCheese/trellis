## Q
**拆成流水线并引入元数据库**｜系统设计 · 问题拆解

单个爬虫服务既解析 DNS、拉页面，又提取文本和链接，任何一步失败都会丢进度。怎样改造才容错？为什么队列里不放 HTML？

## A
**要点。** 把爬虫拆成流水线阶段：URL Fetcher 只负责拉取 HTML 并存入 blob 存储；文本与 URL 提取阶段（文本和链接提取很轻，合在一起）读取 HTML，输出文本并把新链接送回队列。哪一级失败，就只重试那一级。

**为什么。**
- 失败隔离：拉页面最容易失败（站点下线、慢、页面过大）。
- 各阶段可独立扩缩容和优化。
- 需求变化时（比如要把图片 alt 文本也提进来），只换提取函数，不用重爬。

**元数据库。** 用 DynamoDB（也可 PostgreSQL / MySQL）存每个 URL 的状态，以及 HTML 和文本在 blob 存储里的位置。队列消息只放 URL 在元数据库里的 ID。

**易错。** 把原始 HTML 塞进队列是反模式：队列不适合大载荷，而且很贵。
