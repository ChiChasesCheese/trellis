## Q
**搜索结果排序：请求时排序还是多个索引**｜系统设计 · 题目拆解

帖子搜索要支持按时间或按点赞数排序。请比较“请求时取出所有 ID 再排序”和“维护多个索引”，说明 Redis 里用什么结构，各自的代价。

## A
**请求时排序（差）。** 先取关键词的所有帖子 ID，逐个向帖子服务查时间戳或点赞数，再在搜索服务里排序。热门词有数千万结果，索引返回的载荷可达几百 MB，还要几千万次查询，排序也增加延迟。

**多个索引（好）。** 每个关键词维护两份：创建时间索引用 Redis 列表（只追加、只取末尾）；点赞索引用有序集合（sorted set），按点赞数当分数，插入和查询的复杂度与优先队列类似。发帖时两份都写；点赞事件更新有序集合的分数。

**代价。** 索引存储翻倍，换来大幅提升的查询性能；更严重的是点赞极其频繁，每个点赞都要更新该帖所含的很多个关键词下的分数，写入压力大，需要继续优化。
