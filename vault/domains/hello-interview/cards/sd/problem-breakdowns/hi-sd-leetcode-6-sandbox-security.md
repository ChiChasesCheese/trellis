## Q
**沙箱加固：怎样让容器里的用户代码安全**｜系统设计 · 问题拆解

用户代码跑在容器里之后，还要采取哪些措施防止滥用？如果面试官追问，回答到什么程度就够了？

## A
**要点。** 容器只是起点，再叠加这些限制：
- **只读文件系统。** 代码目录只读，输出写入临时目录，稍后清除
- **CPU 与内存上限。** 超限就杀掉容器，防止耗尽资源
- **显式超时。** 如 5 秒，到时杀进程，防死循环，也顺带满足 5 秒返回的要求
- **限制网络。** 禁用网络访问，在 AWS 上可用 VPC 安全组和 NACL 只放行必要连接
- **限制系统调用。** 用 seccomp 限制容器能发出的 syscall

**易错。** 面试里不需要讲每项的实现细节，用一句话说清概念即可：“用 Docker 容器，限制网络，设 CPU 和内存上限，给执行加超时。”面试官感兴趣的地方，他会再追问。
