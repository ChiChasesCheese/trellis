## Q
**需求：服务端请求级限流与数字**｜系统设计 · 问题拆解

设计分布式限流器（rate limiter）时，功能和非功能需求是什么？为什么选择服务端而不是只靠客户端限流？

## A
**范围。** 为社交平台的 API 做请求级（单个 HTTP 请求）限流，不是更高层的业务动作限流。

**功能需求。**
- 按用户 ID、IP 地址或 API key 识别客户端
- 按可配置规则限制请求，如每用户每分钟 100 次
- 超限时返回 HTTP 429，并带有剩余次数、重置时间等响应头

范围外：复杂的限流数据查询分析、限流数据的长期持久化。

**非功能需求。**
- 每次检查附加延迟小于 10ms
- 高可用，接受最终一致（各节点间执行有轻微延迟没关系）
- 规模：每秒 100 万请求、1 亿日活

**为什么服务端。** 客户端不可信，不会自我约束，服务端限流是安全与保护系统的必要手段；客户端限流只是补充。先问面试官规模，规模会彻底改变设计。
