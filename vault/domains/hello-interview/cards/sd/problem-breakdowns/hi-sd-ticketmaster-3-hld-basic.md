## Q
**高层设计：浏览、搜索与基础订票**｜系统设计 · 问题拆解

高层设计里三个功能分别怎么实现？基础订票用什么数据库、怎么防重复？为什么多个服务共用一个数据库也可以？

## A
**浏览。** 客户端经 API 网关到活动服务（Event Service），读 Events DB 里的活动、场馆、艺人。

**搜索。** 先做最朴素的：搜索服务按参数直接过滤数据库，后面再深挖优化。

**订票。** 要的是 ACID 事务，选 PostgreSQL（MySQL、DynamoDB 也行）。新增 Bookings 和 Tickets 表；订票服务在一个事务里检查票是否可用、把状态改成已订、写订单记录；若别人抢先了就返回失败。再配合隔离级别与行锁或乐观并发控制（OCC）防双订。支付由外部的 Stripe 处理。

**共享数据库。** 「每个服务一个库」不是铁律。这里订单、票、活动紧耦合，订票又需要 ACID 事务，拆库只增加复杂度。要做取舍，而不是背教条。

**缺陷。** 用户填完支付信息才发现票没了，下一张卡解决。
