## Q
**判题平台的基础高层设计**｜系统设计 · 问题拆解

判题平台的题目列表和题目详情怎么实现？为什么这里选单体加一个 API 服务器，数据库为什么选 NoSQL，题目文档长什么样？

## A
**要点。** 系统小，用客户端加一个 API 服务器的单体即可，微服务的管理开销不值得。API 服务器处理请求和分页，数据库存题目。

**取舍。** 选 DynamoDB 这类 NoSQL：不需要复杂查询，还可以把测试用例作为子文档内嵌进题目。关系库也能用。

**数据。** 题目文档：id、标题、题面、难度、标签、按语言区分的代码模板（codeStubs）、测试用例数组（类型、输入、输出）。模板可由管理员手写，也可以让大模型从一种语言生成其他语言。

**细节。** 详情页用 Monaco 编辑器让用户在浏览器里写代码。列表要对分页建好索引。
