## Q
**GraphQL 适合什么场景，代价是什么**｜系统设计 · 核心概念

GraphQL 解决了 REST 的什么问题？什么时候在面试里该提它？N+1 问题是什么，授权和 REST 有什么区别？

## A
**为什么出现。** Facebook 的移动端和网页端需要的数据不同，而 REST 端点返回固定结构，要么端点越来越多，要么每个接口返回一切、造成 over-fetching。GraphQL 只有一个端点，客户端用查询语言描述想要的字段形状，服务端返回刚好那些数据，关系（活动关联场馆和票）一次查询就能取到。

**何时用。** 客户端多样、数据需求各异；前端要快速迭代、不想每加一个字段就让后端发版；面试官提到“避免 over-fetching”。

**代价。** 需要实现查询解析、模式校验、复杂缓存。最大陷阱是 N+1：查 100 个活动再逐个查场馆，是 101 次数据库查询而不是 2 次，要用批处理（dataloader）合并。授权按字段在 resolver 里做，而不是按端点。

**取舍。** 遇到明显的取数过多或不足问题再提，不要默认选它，面试官更想先看到你用简单工具解决核心架构问题。
