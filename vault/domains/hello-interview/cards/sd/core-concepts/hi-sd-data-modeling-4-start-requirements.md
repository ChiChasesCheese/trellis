## Q
**从三个因素出发设计模式**｜系统设计 · 核心概念

设计模式（schema）时，哪三个来自需求的因素决定大部分选择？面试里怎样把选择和它们联系起来？

## A
**要点。**
- 数据量：决定数据能否放在同一处。用户和帖子若因性能或组织原因必须放在不同系统，就是不同的模式，要想清楚彼此怎样引用。
- 访问模式：最重要，驱动大部分决策。直接从 API 推出来，问每个接口要支持什么查询。「关注者的最新帖子」暗示要反范式数据或精心设计索引；按时间段聚合的看板则需要完全不同的表结构。
- 一致性要求：决定数据耦合多紧。金融交易要强一致，通常相关数据放在同一个有 ACID 的库里；用户活动流允许最终一致，可分散到针对不同访问模式优化的系统中。

**使用时机。** 说话时明确挂钩：「动态要加载得快，点赞可以最终一致，所以我把点赞数反范式化到帖子表。」这说明你在推理，不是背模式。后面的实体、键、范式化、索引、分片，都是为这三个因素服务的工具。
