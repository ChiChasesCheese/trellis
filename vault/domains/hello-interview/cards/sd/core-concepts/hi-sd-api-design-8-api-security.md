## Q
**API 的认证、授权、限流**｜系统设计 · 核心概念

面试里 API 安全要说到什么程度？认证与授权的区别是什么，API Key 和 JWT 各适合什么场景，RBAC 和限流怎么提？

## A
**区别。** 认证（authentication）确认“你是谁”；授权（authorization）确认“你能不能做这件事”，例如 John 能取消自己的订单，不能取消别人的。

**API Key 与 JWT。**
- API Key：长随机字符串，像应用的密码，放在 Authorization 头里，服务器查表识别调用方，可附带权限和限流配置。适合服务间调用和对第三方开发者开放接口；用户产品几乎不适合，因为不过期、不带用户上下文
- JWT：登录后服务器签发，令牌里直接编码用户 ID、角色、过期时间，并用密钥签名；验证只需检查签名，不用查库，任何持有验证密钥的服务都能独立验证。适合网页和手机端的用户会话，便于无状态扩展

**RBAC。** 给用户分配角色，给角色分配权限：customer 能订票和看自己的订单，venue_manager 能创建活动，admin 能做一切。检查时两步：令牌是否有效，是否拥有该资源或是管理员。

**限流。** 按用户（如每小时 1000 次）、按 IP（未认证请求）、按端点（订票每分钟 10 次防黄牛），在 API 网关或中间件实现，超限返回 429。

**易错。** 多数面试里不是重点：说出哪些端点需要登录，“用 JWT 或会话存库”，加一句“做限流防滥用”就够了。
