## Q
**现代数据库的分片与面试讲法**｜系统设计 · 核心概念

主流数据库各自怎么分片？在面试里什么时候提分片、怎么讲才算好？

## A
**现代数据库自动分片，机制各不相同。**
- Cassandra：分区器（如 Murmur3）加虚拟节点，是一致性哈希，把分区键映射到节点的令牌范围
- DynamoDB：对分区键哈希路由到内部分区，并在增长时拆分合并，不是暴露给用户的环形一致性哈希
- MongoDB：按分片键划成范围分块；用哈希分片键时，范围划在哈希空间上；后台平衡器自动拆分和迁移，也不是经典一致性哈希
- SQL 世界：Vitess、Citus 在 MySQL / PostgreSQL 前面做路由、跨分片操作和再分片；Aurora、Spanner 提供内置分片的分布式 SQL

**什么时候提。** 先算账，确认瓶颈再提：存储（如 5 亿用户 × 5KB = 2.5TB，单个 Postgres 还撑得住，再涨 10 倍才要分）、写吞吐（高峰每秒 5 万写）、读吞吐（加了读副本仍撑不住）。最常见的错误是还没证明必要就先分片。

**怎么讲。**
1. 按访问模式提分片键
2. 选分布策略（哈希加一致性哈希）
3. **说取舍：全局查询变贵：** 说明取舍（全局查询变贵，用缓存和后台预计算）
4. **说增长：先 64 个分片：** 说明增长（先 64 个分片，加分片只搬一小部分数据）

用 DynamoDB 或 Vitess 时，一句「以 user_id 做分区键」就够，不用讲内部实现。
