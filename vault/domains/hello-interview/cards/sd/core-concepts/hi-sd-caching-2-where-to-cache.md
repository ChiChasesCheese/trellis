## Q
**缓存可以放在哪些层**｜系统设计 · 核心概念

系统里缓存可以放在哪几层（外部缓存、CDN、客户端、进程内）？各自适合什么，面试里默认怎么选，什么顺序引入？

## A
**外部缓存。** Redis 或 Memcached 这类独立服务，所有应用服务器共享，支持 LRU 淘汰和 TTL。面试里讲缓存默认就是它，先从这里开始。

**CDN。** 全球分布的边缘服务器，缓存内容靠近用户。图片从弗吉尼亚的源站到印度用户约增加 250 到 300 ms，从就近边缘节点取只要 20 到 40 ms。现代 CDN 也能缓存公共 API 响应和 HTML，但在面试里引入它最稳妥的理由是大规模的静态媒体。

**客户端缓存。** 浏览器 HTTP 缓存、localStorage、手机本地存储（比如 Strava 离线保存跑步数据再同步）；Redis 客户端库缓存集群的槽位分布，直接路由到正确节点。后端对它控制有限，失效更难。

**进程内缓存。** 直接放在应用进程内存里，比 Redis 还快，没有网络往返。适合变化少的小数据：配置、功能开关、小型参考表、热点键、限流计数、预计算值。缺点：每个实例各存一份，彼此不同步，一个实例失效别人不知道。

**取舍。** 先 Redis；只有静态媒体才引 CDN；进程内缓存只作为已有外部缓存之上的优化层。
