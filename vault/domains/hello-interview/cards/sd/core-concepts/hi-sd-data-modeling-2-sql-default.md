## Q
**为什么默认选关系型数据库**｜系统设计 · 核心概念

面试里选数据库时，为什么默认答 PostgreSQL 这类关系型数据库？人们常说它不好扩展，这个说法对吗？有什么要小心的？

## A
**要点。** 关系型数据库用固定模式的表，通过外键强制关系，并提供 ACID 事务。社交应用的用户、帖子、评论、点赞，电商的用户、商品、订单、支付，都很自然地对应到表。需要强一致（支付不能重复扣款，库存不能超卖）时，ACID 正是合适的工具。

**为什么。** 说它扩展性差被夸大了：读副本、分片、连接池、缓存都能帮它扩展，Facebook、Airbnb 都建立在关系型基础上。扩展靠的是围绕它的架构，而不只是选了哪个库。

**取舍。** 别为了显得高级而选冷门数据库。除非你有丰富经验和明确的看法，就坚持 PostgreSQL。

**易错。** 多表 join 在大规模下可能成为性能陷阱，报表式的复杂查询在面试里会让人起疑，要想想能否用反范式的视图、缓存或预计算结果代替。
