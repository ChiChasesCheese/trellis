## Q
**Redis 的模型与速度**｜系统设计 · 深入技术

Redis 的执行模型是什么？为什么它既快又好推理？在 Redis 里「每个元素发一次查询」的 N+1 为什么没那么可怕？

## A
**要点。** Redis 是用 C 写的「数据结构存储」：数据全在内存，命令在单线程里一条条按序执行。值可以是字符串、哈希、列表、集合、有序集合、流（stream）、地理索引，键是字符串，例如 `leaderboard:game:123` 对应一个有序集合。命令走简单的 RESP 协议。

**为什么。** 单线程是有意为之：命令执行不需要锁，对这么简单的操作单核极少是瓶颈，所以每条命令天然原子。键怎么组织，就等于数据怎么分片、集群怎么扩展。

**数字。** 单节点约 10 万次写/秒；命令本身微秒级，网络上读取在亚毫秒。

**取舍。** 在 SQL 里每个元素一次查询是灾难，在 Redis 里每次只耗微秒，还可以用流水线（pipeline）或 `MGET` 合并成一次往返，所以不会拖垮设计，但仍应尽量避免。

**易错。** 新版本会把 I/O 和后台任务交给其他线程，但推理时仍按「一次一条命令」来想。
