## Q
**用作缓存与热键应对**｜系统设计 · 深入技术

把 Redis 当缓存时，TTL 和淘汰策略各管什么？热键（hot key）问题是什么，有哪三种应对办法？

## A
**要点。** 缓存键对应 Redis 键，缓存值对应 Redis 值（JSON 或 Hash）。TTL 解决的是数据过期，保证过期后不会读到；但它不管内存压力：默认内存满了 Redis 会拒绝写入。缓存场景要配淘汰策略，比如 `allkeys-lru`，Redis 用采样近似 LRU，足够用。

**为什么。** 热键指某个键吃掉不成比例的流量。比如 100 个节点上缓存商品，突然某个商品的流量等于其余所有商品的总和，那台服务器就会被压垮，Memcached、DynamoDB 也一样。

**取舍。**
- 客户端本地缓存：应用服务器内存里放最热的少数键，代价是多一层缓存，会有最多一个 TTL 的陈旧，适合短 TTL。
- 键副本：同一数据存成 `product:123:1` 到 `:10`，哈希到不同节点，读时随机选后缀；但每次写要扇出到所有副本，还要知道哪些键是热的。
- 读副本：成倍增加读容量，但客户端默认读主节点，要配置才读副本；对写热键无效，因为写仍落在同一个主节点。

**使用时机。** 先识别热键风险，再主动给出补救方案。
