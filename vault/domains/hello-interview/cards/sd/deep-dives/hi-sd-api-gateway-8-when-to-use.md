## Q
**什么时候提出网关**｜系统设计 · 深入技术

什么情况下应该在设计里加 API 网关，什么情况下是过度设计？

## A
**该用。** 微服务架构。没有网关，客户端要知道并直接调用多个服务，耦合重；网关把内部服务结构与对外 API 隔离。

**不该用。** 简单的单体应用，或只有一种客户端的系统，引入网关只增加复杂度。

**取舍。** 网关是为了解耦客户端与服务拓扑，同时集中放置横切逻辑；代价是多一跳延迟，以及一个必须保证高可用的入口。

**说法。** 说清它负责路由和基础中间件，然后迅速回到核心设计，在这上面纠缠过久比讲得太少更容易出错。
