## Q
**预留过期：Redis 与 MySQL 的做法**｜系统设计 · 真实案例

买家付款一直没完成，预留怎样自动释放？为什么在 Redis 计数器方案里用 TTL 行不通，而在 MySQL 方案里反而不需要定时触发？

## A
**要点。** 预留有三种结局：付款成功（扣账本）；付款失败或退出结账（有明确信号，直接释放）；超时（约 10 分钟，没有任何信号，必须自己消亡）。截止时间要存在数据里，由仍在运行的东西处理，不能指望浏览器或接收原请求的服务器。

**为什么。** Redis 的做法：一个商品一个计数器，TTL 会删掉整个计数器而不是某个买家的预留。改成每个预留一个键，锁的场景合适，但库存是「500 件相同的卫衣任选一件」，可用量是所有有效预留的计数，而 Redis 没有快速的办法数出这些键（键空间是扁平哈希表，扫描是 O(n)）。到期事件通知是发了就忘的发布订阅，消费者掉线就丢。更稳的办法是把预留放进有序集合，分数是截止时间，用后台任务或在每次预留时顺带回收到期项，用原子脚本一次完成「移除并归还计数」，每次回收的数量要设上限，因为 Redis 执行脚本时会阻塞其他命令。

**取舍。** MySQL 方案里预留是带 `expires_at` 的一行，补充进程按「账本数减去 `expires_at > NOW()` 的有效预留数」来计算池的目标，截止时间一过预留就不再计入，下次补充自动恢复容量。清理任务只是垃圾回收，晚一点也不影响正确性。预留期间没有任何数据库锁被持有，锁只出现在毫秒级的短事务里。
