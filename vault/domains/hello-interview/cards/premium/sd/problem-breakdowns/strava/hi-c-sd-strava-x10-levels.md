## Q
**Strava 运动记录 · 高级比中级多什么**｜考点 · 必会

候选人画出了"手机每 3 秒上传 GPS 点"的方案并配了分片和缓存。要把这个回答提升到高级，应当如何重新框定问题？

## A
- **看穿根源：** 指出"离线可用"和"本地统计准确"两条非功能需求，已经暗示数据应先留在客户端；上传频率从每点一次降到每活动一次，写入下降 2–3 个数量级，扩容问题几乎消失。
- **用数字说话：** 估算原始写入 333 万次/秒、年存储约 530TB，再解释为什么本地优先之后这些不再可怕。
- **补上失败模式：** 掉电（落盘间隔）、重复上传（幂等）、时钟被改（单调时钟）。
- **对扩展保持克制：** 好友实时观看先问"需要什么延迟"，选轮询加滞后缓冲，而不是反射式地上 WebSocket；排行榜给出三档方案并说出 Redis 与主库的一致性问题。
- **说清为什么不拆微服务：** 读写没有倾斜，不拆。
