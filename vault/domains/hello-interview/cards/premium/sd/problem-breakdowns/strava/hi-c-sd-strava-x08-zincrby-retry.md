## Q
**Strava 运动记录 · 预测失败：排行榜的重试与重复累加**｜考点 · 必会

活动完成后，后台任务对 Redis 做 `ZINCRBY`，Redis 响应超时，任务重试。排行榜会怎样？怎么保证每个活动只被计入一次？Redis 还和主库不一致怎么办？

## A
- **后果：** 如果第一次其实已经成功，重试会再累加一次，该用户距离被重复计算。ZINCRBY 不是幂等的（ZADD 设固定分数才是）。
- **去重做法：**
  - 每个活动一个"已计入"标记：用 `SET processed:{activityId} 1 NX EX …` 成功才执行 ZINCRBY；二者要放在同一个 Lua 脚本里原子执行，否则两步之间崩溃仍会出错；
  - 或把排行榜写成活动队列的消费者，用活动 ID 做幂等键。
- **与主库不一致：** Redis 是派生数据，主库才是准的。定期（如每夜）从主库重新聚合一份，与 Redis 对账并修正；任何差异就说明有丢更新或重复。
- **取舍：** 实时榜容许小误差，但"总里程"这种用户会对着看的数字，误差久了会被发现，所以需要对账。
- **模式。** 幂等键：以业务事件的 ID 去重，让重试变得安全。
