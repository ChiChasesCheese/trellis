## Q
**网约车 · 预测失败：接单迟到一点点**｜考点 · 必会

锁是 Redis 键 `driver:{id}`，TTL 10 秒。订单 A 在第 0 秒发给司机 D；D 在第 10.5 秒点了接受；此时锁已过期，匹配服务在第 10.2 秒又把订单 B 发给 D 并重新加了锁。接单请求到达后会发生什么？怎样改？

## A
- **后果：** 如果接单只检查"司机有没有锁"，会通过，订单 A 被标为 accepted，而 D 同时又被订单 B 占着，一人两单，违反强一致。
- **改一，锁带身份：** 锁的值写入 `rideId`。接单时检查锁的值等于该订单；不等就拒绝（A 已被收回）。比较和删除要用 Lua 脚本原子完成，否则检查和删除之间锁又被别人拿走。
- **改二，条件更新数据库：** `UPDATE rides SET driver_id=?, status='accepted' WHERE id=? AND status='requested'`，影响行数为 0 表示该订单已被改派，直接告诉司机"已失效"。
- **改三，给司机端也留余量：** 客户端倒计时略短于服务端 TTL，减少边界上的迟到点击。
- **要点：** 带过期时间的锁只能保证"大多数时候互斥"，真正的正确性靠写入时的条件检查。
