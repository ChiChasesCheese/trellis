## Q
**网约车 · 深入一：用 Redis 地理类型存司机位置**｜摘要 · 必会

Redis 怎样同时扛住每秒 200 万次位置更新并支持近邻搜索？掉线司机怎么清？丢数据怎么办？

## A
- **原理：** Redis 把经纬度编码成 geohash（用交错的位把二维坐标变成一个数），得到 52 位整数分数，存进有序集合（sorted set），司机 ID 为成员。
- **写：** `GEOADD` 覆盖该司机上一次位置，所以始终是最新位置，也就不需要批处理。
- **读：** `GEOSEARCH` 按半径或矩形查附近成员，是 Redis 6.2 起取代 `GEORADIUS` 的新命令。
- **清理掉线司机：** 再维护一个按"最后更新时间"排序的有序集合，定期删除超过阈值（如 30 秒）的条目，同时从地理集合中移除。
- **主要风险是持久性：** 内存数据遇到崩溃或断电会丢。缓解办法是开启 RDB 或 AOF 持久化，并用 Sentinel 做主从自动切换。
- **为什么损失很小：** 司机每 5 秒会重新上报，状态大约五秒就能重建，所以即使丢了也影响有限。
