## Q
**网约车 · 整体设计一：估价与叫车**｜摘要 · 必会

乘客打开 App 输入目的地、再确认叫车，请求经过哪些组件，数据怎么写？

## A
- **估价流程的组件：** 乘客客户端（iOS、Android）；API 网关（鉴权、限流，并把请求路由到对应微服务）；叫车服务（Ride Service，管理行程状态，先负责估价）；第三方地图 API（算距离与耗时）；数据库（先存 Fare）。
- **估价步骤：** 客户端 `POST /fare` → 网关鉴权限流 → 叫车服务调地图 API 得到距离和耗时，套定价模型得出估价 → 写入 Fare 记录 → 经网关返回给客户端，由乘客决定要不要叫。
- **叫车：** 不需要新服务，只在数据库里加 Ride 表。客户端带 `fareId` 提交，叫车服务建 Ride 并关联该 Fare，状态初始为 requested，然后触发匹配。
- **注意：** 先把简单版搭出来，匹配触发是否可靠（服务崩了会丢）留到后面的深入问题。
