## Q
**Facebook 直播评论 · 评论 ID 与写热点：游标和 DynamoDB 单分区**｜拓展 · 加分

游标分页要求评论 ID 有什么性质？爆红直播每秒 5000 条评论写进 DynamoDB，会不会有问题？

## A
- **ID 必须能按时间排序：** 查询是 `commentId < :cursor`，所以 ID 要有全序且与发布时间一致。随机 UUIDv4 做不到，会让分页乱序。常见选择：ULID（128 位，前 48 位是毫秒时间戳，后 80 位随机，按字典序可排序）、雪花 ID（64 位：时间戳加机器号加序号）、KSUID。同一毫秒内的 ID 靠随机位或序号区分，不保证严格的发布先后，但对评论流够用。
- **写热点：** 评论库以 liveVideoId 为分区键，一个爆红直播的所有写入都落在同一个分区键上。DynamoDB 官方文档给出的单个分区上限大约是每秒 1000 个写容量单位（1KB 以内的写入每次算一个）、3000 个读容量单位；每秒 5000 条评论远超这个量级。
- **解法：**
  - 写分片：分区键改成 `liveVideoId#k`（k 取 0 到 K−1），写入时随机选一个 k；读取历史时并行查 K 个分片，再按评论 ID 合并排序；
  - 缓冲批量写：爆红直播的评论先进内存环形缓冲或消息队列，批量异步写库（它们反正会被采样，丢极少几条可接受）；
  - 把热门直播的最近评论只放在 Redis，库里只保留归档。
- **取舍：** 分片让读变复杂（要合并），所以只对超过阈值的直播启用，普通直播仍用单分区键。
- **模式。** 写分片（write sharding）：给热点键加后缀，把写入分散到多个分区，读时再汇总。
