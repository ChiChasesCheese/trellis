## Q
**在线判题平台 · 判题队列的至少一次与幂等**｜拓展 · 加分

判题任务经队列分发给 worker，worker 崩溃或重试会带来什么问题？怎样保证结果不重复、不卡死？

## A
- **语义：** 常见托管队列（如 SQS 标准队列）提供至少一次投递：同一任务可能被执行两次，或者一个任务在 worker 处理过程中因可见性超时到期而被另一个 worker 取走。
- **幂等写结果：** 以提交 ID 为键写入结果，已有终态结果就忽略后来的写入；排行榜只在状态从"未通过"首次变为"通过"时更新，避免重复计分。
- **可见性超时：** 必须大于最坏判题时间（含超时上限）加余量，否则正在运行的任务会被别人重复拿走。
- **毒丸提交：** 某个提交总是把 worker 搞崩，会无限重试。设置最大接收次数，超过就进死信队列（dead-letter queue），返回"系统错误"并告警，同时不占用重试容量。
- **用户感知：** 状态机用 `QUEUED → RUNNING → DONE | ERROR`，`GET /check/:id` 把中间状态也返回。
- **模式。** 至少一次 + 幂等消费：不追求恰好一次，让重复执行无害。
