## Q
**在线判题平台 · 深入三：水平扩容与队列**｜摘要 · 必会

动态水平扩容和加队列分别解决什么？队列让接口发生了什么变化，值不值得加？

## A
- **动态水平扩容：** 每种语言的容器各自扩展，用自动伸缩组（如 ECS Auto Scaling）按 CPU、内存或流量增减实例。风险只是过度配置带来的成本，云上可以接受。
- **水平扩容加队列：** 在 API 服务器和容器之间放队列（如 SQS）。API 把提交入队，容器按自己的处理能力拉取，削平峰值；容器崩溃时把提交重新入队重试，不丢单。
- **接口变化：** 队列让流程变成异步，API 不能再直接返回结果。新增 `GET /check/:id`，客户端每秒轮询，处理完返回结果，否则返回 processing；worker 判完后通知应用服务器，同时更新数据库和排行榜缓存。用 WebSocket 能省掉轮询，但间隔只有 1 秒，不值得增加复杂度。
- **值不值得：** 就体量而言队列是过度设计，比赛需报名，可提前扩容。选它的理由是重试和缓冲，让你放心不会丢提交。没有标准答案，把利弊说清楚就是得分点。
