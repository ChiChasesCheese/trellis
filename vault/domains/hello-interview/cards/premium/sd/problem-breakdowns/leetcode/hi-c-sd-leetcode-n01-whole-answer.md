## Q
**在线判题平台 · 完整解答**｜摘要 · 必会

设计一个类似 LeetCode 的在线判题平台：用户浏览题目、在浏览器里写代码并提交、几秒内拿到结果，比赛时还能看实时排行榜。给出需求、实体与接口、整体设计、深入问题、各级别期望。

## A
**一句话。** 这是一个"小规模系统里安全地运行不可信代码"的题：难点不是流量，而是执行隔离、突发提交的算力，以及排行榜别把数据库压垮。

**60 分钟路线。**

| 时间 | 做什么 |
|---|---|
| 0–5 分 | 需求与规模：几十万用户、约 4000 题，比赛 10 万人、5 秒内出结果 |
| 5–10 分 | 实体 Problem / Submission / Leaderboard 与四个接口 |
| 10–20 分 | 高层设计：单体 API 服务器 + 数据库；提交先用最简单的方式跑通 |
| 20–50 分 | 必讲深入：执行隔离与加固；排行榜；突发扩容；测试用例怎样跑在任意语言上 |
| 50–60 分 | 追问：队列的取舍、沙箱更强的隔离、结果重试 |

- **需求**
  - 功能：看题目列表；看单题并用多种语言写代码；提交并立即得到反馈；比赛排行榜实时。认证、资料、支付、分析、社交都不做
  - 非功能：可用性优先于一致性；运行用户代码要隔离安全；5 秒内返回结果；支持 10 万人比赛。规模小，单体即可，不要过度设计
- **实体与接口**
  - Problem（题面、测试用例、期望输出）、Submission、Leaderboard
  - `GET /problems?page&limit` 只返回 id、标题、难度、标签；`GET /problems/:id?language` 返回题面和代码模板；`POST /problems/:id/submit`；`GET /leaderboard/:competitionId`
  - userId 取自会话，时间戳由服务端生成
- **整体设计**
  - 单体 API 服务器 + DynamoDB 一类库，测试用例作为子文档内嵌进题目；浏览器里用 Monaco 编辑器
  - 提交：API 把代码交给对应语言的容器，容器里跑完，结果存库后返回
  - 朴素排行榜：查通过的提交，按用户分组数不同题目数，按解题数降序、完成时间升序；客户端约 5 秒轮询
- **深入一，执行隔离（必讲）**
  - 直接在 API 服务器上跑最差；虚拟机隔离强但重且启动慢；容器轻、可复用；无服务器自动伸缩但有冷启动
  - 选容器，再叠加：只读文件系统、CPU 与内存上限、超时（约 5 秒）、禁用网络、seccomp 限制系统调用
- **深入二，排行榜（必讲）**
  - 库里聚合会被轮询压垮；Redis 有序集合（`ZADD`、`ZRANGE ... REV`）存分数，读不碰库；客户端 5 秒轮询就够，不必 WebSocket
- **深入三，突发扩容（必讲）**
  - 1 万个并发提交 × 100 个用例 × 每个 100ms = 10 万核秒，1 分钟内跑完要约 1667 核，纵向扩容不可行
  - 每种语言的容器水平自动伸缩；加队列削峰并支持失败重试，代价是接口变异步，需 `GET /check/:id` 每秒轮询
- **深入四，测试用例（必讲）**
  - 每题只写一份与语言无关的用例，约定统一序列化（二叉树用层序数组），每种语言带自己的测试框架（harness）还原、调用、比较
- **级别**：中级跑通流程并意识到隔离；高级讲清容器与 VM、无服务器的取舍并说出用例怎么跑；Staff 少见，应给出简单且有扩展路径的系统
