## Q
**Tinder · 深入一：用户对作分区键**｜摘要 · 必会

怎样在 Cassandra 里让互相的滑动落在同一个分区，从而单分区内原子判定匹配？运维上有什么代价？

## A
- **做法：** 分区键用 `user_pair`，由两个 ID 排序后拼成（较小 ID : 较大 ID）；聚簇键是 `from_user`、`to_user`。排序保证 A→B 与 B→A 得到同一个键，落在同一分区。
- **为什么有效：** Cassandra 的原子性只在单分区内成立。互相的滑动同在一个分区后，"写入我的滑动并读对方方向"就是单分区操作，不需要分布式事务。
- **代价一，分区无限增长：** 一对用户的记录随时间累积，需要归档或删除旧数据的清理策略，同时保留必要历史。
- **代价二，热点：** 极活跃的用户会让相关分区流量偏高。
- **代价三，按用户查不方便：** "A 滑过谁"不再是一个分区内的查询（后面去重要用），需要另建以 swiping_user_id 为键的副本表或索引。
- **口述重点：** 说清"为什么排序"和"为什么单分区才能原子"，这两句是得分点。
