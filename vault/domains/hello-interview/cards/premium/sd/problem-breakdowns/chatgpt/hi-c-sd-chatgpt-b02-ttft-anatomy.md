## Q
**ChatGPT · 拓展：首 token 时间由什么组成，为什么长提示更慢**｜拓展 · 加分

首 token 延迟（TTFT）不只是"模型启动"，它由哪几段组成？它们各受什么限制？

## A
- **组成：** 排队等待 + 预填充（prefill）+ 第一次解码。预填充一次性处理整个提示，把每个 token 的 KV 状态算出来，这一步是**计算受限（compute-bound）**，耗时随提示长度增加；之后的解码逐 token 进行，受**内存带宽限制（memory-bandwidth bound）**：每步只算一个新 token，计算量小，却要把全部权重和整个 KV 缓存从显存读一遍。
- **含义：** 长提示的 TTFT 更长；前缀缓存能跳过预填充中命中的部分，所以直接降 TTFT，而不只是省钱。分块预填充（chunked prefill）把长提示切块与别的序列的解码混合调度，避免一个长提示卡住别人。
- **2026 亮点：** 压 TTFT 的服务端手段是前缀缓存加缓存感知路由，而不只是加 GPU：同前缀、同会话的请求粘到同一副本，才能跳过预填充；代价是粘性会造成热点，要在负载和命中率之间权衡。
- **KV cache 的内存：** 每条序列要为每个已处理 token 保存 KV 状态，序列越长占显存越多，批的大小受显存而不仅是算力限制；这就是批量上限和上下文长度互相挤占的原因。vLLM 的 PagedAttention 把 KV 分块按需分配，减少碎片，提高可同时容纳的序列数。
- **监控：** 把 TTFT 拆成排队、预填充分别度量，才知道该扩容还是该限提示长度。
