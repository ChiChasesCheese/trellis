## Q
**ChatGPT · 高层设计一：朴素的同步发送**｜摘要 · 必会

最朴素的"发送提示词、得到回答"怎么设计？为什么把聊天服务和推理服务分开？它有哪两个缺口？

## A
- **组件：** 客户端；API 网关（认证、限流、路由）；聊天服务（无状态，负责存取对话与消息、编排对模型的调用）；Postgres（chats 和 messages 表，按 chatId 与 userId 的简单行，几乎任何库都行，选它只是合理默认）；推理服务（一组 GPU 机器，每台把模型权重常驻 GPU 显存，称为工作者）。
- **流程：** 客户端 `POST` 消息 → 网关认证转发 → 聊天服务写用户消息 → **同步**调用推理服务拿完整回答 → 写助手消息 → 返回客户端。
- **为什么拆开：** 聊天层便宜且无状态，推理层昂贵且受 GPU 限制，要能各自独立扩缩和调度。
- **缺口一：** 长回答可达 30 秒，用户盯着 30 秒空白屏，违反首 token 要求。
- **缺口二：** 聊天服务直接调工作者，没有准入控制，GPU 满了也没人决定接受或拒绝哪些请求。前者用流式修，后者用调度层修。
