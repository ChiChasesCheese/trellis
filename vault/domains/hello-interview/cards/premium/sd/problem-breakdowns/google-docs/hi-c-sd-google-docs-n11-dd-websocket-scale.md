## Q
**协同文档编辑 · 深入一：用一致性哈希摊开百万 WebSocket 连接**｜摘要 · 必会

单台文档服务撑不住百万连接，怎么横向扩展，同时保证同一篇文档的所有人连到同一台服务器？

## A
- **问题：** 一台服务器既有单点故障，又撑不住百万并发。连入文档服务时，要么和同文档的人在同一台，要么知道他们在哪。
- **方案：** 横向扩展文档服务，用一致性哈希环分配文档：每台服务器负责一段哈希范围，所以总能知道哪台服务器负责某篇文档，所有连接都去那里。用 ZooKeeper 维护环的配置并协调服务器。
- **连接流程：**
  - 客户端带着文档 ID，先用 HTTP 连任意一台服务器（可轮询）；
  - 该服务器查环配置，不是自己负责就返回重定向到正确服务器的地址，客户端最终直连；
  - 找到正确服务器后，HTTP 连接升级为 WebSocket，服务器维护文档 ID 到连接的映射；
  - 若操作尚未加载，从操作库加载全部历史操作。
- **好处：** 同文档的人在同一台，更新直接转发给所有连接；增删服务器时，只有一小部分连接需要重新分配。
- **边缘终结：** 套接字有状态，很麻烦，所以在系统边缘终结 WebSocket，对内暴露内部接口，其他系统保持无状态。
- **多数候选人忘记的方向：** 画图时想想右到左的箭头，即内部服务怎么把消息送到客户端。
- **模式。** 一致性哈希路由：用确定性映射把同一资源的所有请求送到同一节点。
