## Q
**协同文档编辑 · 拓展：在压缩之上做版本历史**｜拓展 · 加分

压缩会把操作折叠成一条，但产品想要"回到昨天的版本"。怎样在不放弃压缩的前提下支持版本历史？

## A
- **冲突：** 压缩的目的是丢掉旧操作省空间，版本历史恰好需要旧状态。
- **做法一，保留快照：** 压缩时不仅写出最新的折叠操作，还按策略（每天、每 N 次编辑、用户手动命名）保留若干快照，回溯就是加载那个快照，之后的增量操作也保留到下一个快照为止。
- **做法二，版本号链：** 利用已有的 `documentVersionId`：旧版本不删除，只是不再是当前版本；到期（如 30 天）后按保留策略清理。
- **存储代价：** 历史快照可以只存与前一快照的差异（delta）；冷数据放对象存储，热数据留在操作库。
- **恢复：** 回到旧版本时，不是覆盖，而是把旧快照作为一次新的编辑写进当前日志，这样其他在线用户也能通过正常同步看到变化，历史也不被破坏。
- **模式。** 快照加增量日志：定期物化状态，既能快速加载，又保留可回放的历史。
