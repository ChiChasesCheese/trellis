## Q
**协同文档编辑 · 并发编辑：操作转换 OT**｜摘要 · 必会

操作转换（Operational Transformation，OT）怎么解决位置错位？它有什么优缺点？

## A
- **做法：** 所有编辑汇集到一台服务器，由它排定最终顺序；对每个后到的编辑，根据已经落地的编辑来调整，再应用，并在发回客户端前同样转换。
- **例子：** 文档 `cat`，A 在开头插入 `the `（4 个字符），B 同时删除下标 2 的 `t`。若 A 的编辑先落地，B 的 `DELETE(2)` 被转换为 `DELETE(6)`（2 + 4），在 `the cat` 中仍然删到那个 `t`，不会误删别的字符。反过来，若 B 先落地，A 的插入位置在前面，不受影响。
- **优点：** 内存占用小，处理快，适合文本，Google Docs 采用。
- **缺点：**
  - 需要一个中心服务器给出最终顺序，只适合少量协作者，所以靠"每篇文档不超过 100 个编辑者"这条非功能需求兜住；
  - 正确实现很难，容易出错。
- **关键：** 转换的本质是让"到达顺序不同"的操作经过调整后得到同一个文档。
