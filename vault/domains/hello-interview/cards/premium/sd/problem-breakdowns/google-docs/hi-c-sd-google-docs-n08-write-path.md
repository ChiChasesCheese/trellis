## Q
**协同文档编辑 · 写路径：操作日志与持久化**｜摘要 · 必会

编辑操作到达文档服务后怎么存？用什么数据库，什么时候才向用户确认？

## A
- **流程：** 客户端把编辑作为操作发到文档服务；服务按 OT 转换后，把操作记录进"文档操作库"；记录成功才向用户确认。
- **存储选型：** 先用一个写入很快的追加型存储，如 Cassandra：按 `documentId` 分区，按时间戳排序（时间戳由文档服务设置）。同一篇文档的操作聚在一个分区、按顺序读出。
- **为什么先落盘再确认：** 这样持久性需求（服务重启后不丢）就被满足：用户收到确认时，操作已经安全。
- **注意：** 追加日志是为了写入快速。之后文档会越来越大，需要快照与压缩，见存储深入问题。Cassandra 只有行级事务，这个限制会影响后面压缩时的原子性。
