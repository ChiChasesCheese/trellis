## Q
**协同文档编辑 · 拓展：百万读者围观一篇文档**｜拓展 · 加分

一篇文档有一百万人在只读围观（如直播稿），这对"一篇文档一台服务器"的设计是什么压力？怎么拆？

## A
- **压力：** 编辑者最多 100 人，但读者没有上限。若都连到持有文档的那一台服务器，广播要对一百万个连接各写一次，连接数和出站带宽都会压垮它，反过来影响编辑者的延迟。
- **拆开读写：** 编辑者仍连主服务器；读者连另一层只读服务器。主服务器把落盘后的操作流只发一份给读服务层，读服务层再扇出给各自的读者，这是典型的"分层扇出"。
- **读者的一致性要求更低：** 读者可以接受几百毫秒到几秒的延迟，所以可以合并多个操作成批发送，甚至对非常热的文档降为定期推送快照。
- **更激进：** 对极大规模的读者，直接发布静态快照到 CDN，读者轮询或通过长连接订阅增量。
- **取舍：** 读者端不参与 OT 转换时，只需要按序应用服务器给出的最终操作，实现简单。
- **模式。** 读写分离的扇出：写者数量有限的路径与读者规模无限的路径分层处理。
