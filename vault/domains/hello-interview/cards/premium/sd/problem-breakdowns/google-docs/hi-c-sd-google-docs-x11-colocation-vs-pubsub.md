## Q
**协同文档编辑 · 权衡：同文档用户为什么必须连同一台服务器**｜考点 · 必会

如果允许同一篇文档的用户连到不同服务器，用 Redis 发布订阅在服务器间转发编辑，行不行？OT 在这种设计里会遇到什么问题？

## A
- **可行但更复杂：** 每篇文档一个频道，服务器之间转发。这是"知道其他用户在哪"的另一条路。
- **OT 的真正障碍：** OT 需要对一篇文档的所有编辑有唯一的全序，必须有一个排序者。多台服务器各自接收编辑时：
  - 要么有一台服务器被指定为该文档的排序者，其他服务器把编辑转发给它，等于又回到"一篇文档一台主服务器"，还多了一跳；
  - 要么没有排序者，则退回到 CRDT 的思路。
- **额外的代价：** 多一跳网络，延迟预算（100ms）更紧；广播多了一层中转；服务器间的消息丢失或乱序要处理。
- **所以选择：** 每篇文档固定到一台服务器，一致性哈希路由，排序、持久化、广播都在本机完成，逻辑最简单。
- **何时才拆开：** 同一篇文档的并发人数极大（如上万读者）。读者可以与编辑者分离，由其他服务器通过订阅获取只读流，编辑者仍留在主服务器。
