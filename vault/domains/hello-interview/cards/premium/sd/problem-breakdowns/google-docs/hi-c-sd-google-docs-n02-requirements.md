## Q
**协同文档编辑 · 需求与规模**｜摘要 · 必会

协同文档编辑器的功能需求、非功能需求是什么？"单文档最多 100 个并发编辑者"这条约束对设计有什么帮助？

## A
- **功能（四条）：** 创建新文档；多人并发编辑同一文档；实时看到彼此的修改；看到他人的光标位置和在线状态。
- **范围外：** 复杂文档结构（先当作纯文本编辑器）；权限与协作级别；文档历史与版本。
- **非功能：**
  - 最终一致：所有用户最终看到相同的文档状态；
  - 更新延迟小于 100ms；
  - 百万级并发用户、数十亿篇文档；
  - 单文档并发编辑者不超过 100；
  - 持久可用：服务器重启后文档不丢。
- **100 人上限的价值：** 它让你不必担心单篇文档上的海量吞吐，可以专注核心功能；也意味着一篇文档可以放在一台服务器上处理，不需要把一篇文档的写入拆到多台。Google Docs 自己也这样做：并发用户超过一定数量后，新进入的人只能当读者。
- **面试做法：** 先做出一个不管规模的最简版，满足功能；再在深入问题里逐个把规模和非功能需求补回来。
