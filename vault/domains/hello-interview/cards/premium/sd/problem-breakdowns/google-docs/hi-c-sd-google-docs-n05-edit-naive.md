## Q
**协同文档编辑 · 并发编辑：为什么发快照和发位置编辑都不对**｜摘要 · 必会

两个人同时编辑，为什么每次发送整篇文档快照、或只发"在位置 N 插入或删除"的编辑，都会出错？

## A
- **发快照（错）：** 每次编辑把整篇文档发给服务，存到对象存储。
  - 低效：快速打字时每次按键可能传几百 KB；
  - 更严重：丢修改。A 在末尾加了内容，B 同时删了某个字符，各自提交的是整篇文档，最终保存的是后到达的那份，另一个人的修改整个消失。
- **发编辑（接近）：** 只发修改本身，比如 `INSERT(5, "xx")`、`DELETE(6)`，不再传整篇，流量问题解决。
- **新问题：** 每个编辑都是"基于某个特定文档状态"的，位置是相对产生它时的文档而言。如果 A 先在前面插入了字符，B 的 `DELETE(6)` 到达时位置已经移动，会删错字符。
- **关键洞察：** 并发编辑的本质是上下文：一条编辑的含义依赖于它被发出时看到的文档。解决办法有两条路线：在应用前重新解释每条编辑（OT），或让所有编辑天然可交换（CRDT）。
