## Q
**协同文档编辑 · 读路径：加载文档与实时推送**｜摘要 · 必会

新编辑者打开文档时怎么拿到当前内容？别人的修改怎么到达，为什么客户端自己也要做 OT？

## A
- **加载：** WebSocket 建立时，服务端把已有的全部操作推给这个连接。因为所有人都连在同一台服务器上，可以假定每个连接都从同一状态出发。
- **更新：** 一个编辑落库成功后，立即发给同一台服务器上连着该文档的所有客户端；因为同文档的人都在同一台服务器，这一步很直接。
- **为什么客户端也要转换：** 用户期待自己的修改立刻显示，所以本地先应用、再发给服务器。如果其他人的编辑在这之间先到了服务器，各方看到的顺序就不同。比如 A 提交 Ea，B 提交 Eb（后到）：
  - 服务器顺序：Ea、Eb；
  - A 看到：Ea、Eb；
  - B 看到：Eb、Ea（自己的先应用）。
- **解决：** 对收到的操作做 OT，让不同顺序的操作序列仍给出同一份文档。
- **结论：** 服务器决定最终顺序，客户端把"自己尚未被确认的本地编辑"和"服务器推来的编辑"互相转换。
