## Q
**协同文档编辑 · 预测：压缩过程中有人连进来**｜考点 · 必会

文档服务在最后一个客户端离开后，开始用低优先级进程压缩。200ms 后又有人打开这篇文档。会出什么问题？怎么处理？

## A
- **风险一：** 新客户端读到旧版本日志，同时压缩写出新版本并翻转版本号。如果这时新客户端已经开始写入旧版本，翻转之后这些写入就落在被抛弃的旧版本里，修改丢失。
- **风险二：** 版本号翻转发生在客户端加载之后，客户端基于旧版本，服务器却认新版本，状态不一致。
- **做法：** 文档服务是该文档的唯一写入者，应把"压缩中"当作文档的一个状态：
  - 方案一：新连接等压缩完成并翻转后再加载，延迟只有压缩时间；
  - 方案二：压缩被打断，放弃这次结果（丢弃新版本，不翻转），有人要用就继续用旧版本，下次空闲时再压缩；
  - 无论哪种，翻转要在文档服务内串行执行，且只在文档未被加载时进行。
- **选择：** 压缩可以随时重来，编辑不可以延迟，通常选方案二，优先保证用户操作。
- **原则：** 后台维护任务要让路给前台流量，且能安全中断。
