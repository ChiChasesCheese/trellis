## Q
**协同文档编辑 · 拓展：客户端-服务器 OT 为什么只需处理两方**｜拓展 · 加分

OT 在多人场景里听起来要处理 N 个人互相之间的转换，实际的客户端-服务器架构怎样把它简化？

## A
- **朴素担忧：** N 个人各自产生并发操作，两两转换的组合会爆炸。
- **简化：** 让服务器作为唯一排序者，每个客户端只和服务器这一方同步。经典做法（如 Jupiter 系统、Google Wave 的 OT）：客户端同一时刻只有一个"在途"（已发出、未确认）的操作，其余新的本地编辑缓冲起来合并成一个；收到服务器推来的操作时，只需要同这个在途操作和缓冲区做转换。
- **效果：** 每个客户端只需处理自己和服务器之间的两方转换，而不是和其他每个人；服务器上的转换也只针对"该客户端基于的版本之后"的操作。
- **版本号：** 每个客户端的操作带它基于的服务器修订号，服务器据此知道要对哪些已落地的操作做转换。
- **价值：** 这也是为什么中心化 OT 在实现上比去中心化 OT 简单得多，去中心化 OT 的转换函数难以做对。
- **模式。** 单一排序者：把并发问题变成一条有序日志，只需要处理客户端和日志的两方关系。
