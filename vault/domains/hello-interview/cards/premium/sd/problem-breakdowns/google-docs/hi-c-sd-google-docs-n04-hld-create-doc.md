## Q
**协同文档编辑 · 高层设计一：创建文档与元数据**｜摘要 · 必会

创建文档这个功能的最小设计是什么？为什么把文档内容和元数据分开考虑？

## A
- **接口：** 输入标题，返回文档 ID。
- **做法：** 水平扩展的无状态 CRUD 服务，前面挂 API 网关，后面一个 Postgres 存元数据。
- **为什么先分开：** 文档上可以挂很多元数据（权限、历史、标签等），而文档内容有完全不同的访问模式（高频追加写入）。把元数据独立出来，各自选存储、各自扩展；这一步只处理元数据。
- **为什么是 Postgres：** 查询灵活，需要扩展时可以再分区和复制。
- **面试节奏：** "无状态 CRUD 服务加网关"是极其常见的模式，要能很快画出，不要在这里花太多时间，面试官多半会问用什么数据库，给出理由即可。
