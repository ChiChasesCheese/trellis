## Q
**帖子搜索 · 拓展：有序列表求交集，怎样比哈希更快**｜拓展 · 加分

两个词各有几百万条帖子 ID 要求交集。把一个放进哈希表再逐个查，有更好的办法吗？

## A
- **哈希交集：** 把一个列表放进哈希表，扫另一个列表逐个查。时间 O(m + n)，需要额外内存，且必须整张列表传到一处。
- **有序列表的双指针：** 如果两个列表都按帖子 ID 排序，用两个指针同步前进：相等就输出，较小的一方前进。同样 O(m + n)，但不需要额外内存，顺序读对缓存友好。
- **跳表或指数跳跃（galloping）：** 当一个列表远短于另一个（m ≪ n）时，对短列表的每个元素，在长列表里用跳表指针或指数加二分查找去定位，时间约 O(m log n)，只读到长列表的一小部分。Lucene 等搜索引擎用跳表指针加速交集。
- **先从最短的列表开始：** 多个词时，按列表长度从短到长依次求交集，中间结果越来越小。
- **与分片的关系：** 这也是按帖子分片更合适的原因之一：交集在本地用顺序读完成。
- **模式。** 以最小集合驱动：让最稀有的条件先缩小候选集，再用其它条件验证。
