## Q
**帖子搜索 · 拓展：新帖 1 分钟可搜，大索引怎么做到**｜拓展 · 加分

大倒排索引通常批量构建、定期合并。要让新帖在一分钟内可搜，常见的做法是什么？

## A
- **难点：** 大索引的合并和重建很重，不会每个新帖都改动它；但新帖又要很快可见。
- **两层索引：** 一个小的、放在内存里的"近期索引"接收实时写入，一个大的"主索引"按批次构建、周期性合并。查询同时查两层，再把结果合并。近期索引到达一定大小或时间后，并入主索引。Twitter 的实时搜索系统 Earlybird 就是这种思路的典型例子，Lucene 的小段（segment）加定期合并也同理。
- **好处：** 新帖的可见延迟只取决于近期索引的写入，与主索引的构建无关；主索引可以做更重的压缩和优化。
- **对本设计的映射：** Redis 里的列表本身就是实时写入的"近期层"；若主索引放在磁盘或对象存储，近期层补足最新部分。
- **代价：** 每次查询多查一层，要合并去重；两层要处理好相同帖子的点赞数更新。
- **模式。** 近期层加主索引：用小而新的结构吸收写入，大而旧的结构负责体量。
