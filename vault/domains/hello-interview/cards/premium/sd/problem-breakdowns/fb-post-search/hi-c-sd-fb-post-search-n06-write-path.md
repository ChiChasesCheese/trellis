## Q
**帖子搜索 · 整体设计：发帖与点赞的写入路径**｜摘要 · 必会

先搭最简单的写入路径时，怎样处理发帖和点赞？为什么要主动承认它过于简化？

## A
- **假设已有服务：** 搜索只是社交产品的一部分，已有发帖服务和点赞服务接收客户端请求；我们设计的是它们之后的摄入服务（Ingestion Service）。
- **简版：** 请求进来，摄入服务写入数据库。发帖和点赞的规模差别很大，但此时操作很简单，先合成一个服务，并向面试官指出这个隐患。
- **要点：** 面试官会挑毛病，你把问题留着不说，他们就会以为你没看见。主动承认"这很简化，后面会解决"。
- **策略：** 对照需求逐条搭系统，先满足功能，再用非功能需求做深入。
