## Q
**帖子搜索 · 预测失败：多层缓存让新帖超过一分钟才出现**｜考点 · 必会

要求新帖 1 分钟内可搜。团队在 Redis 搜索缓存设 TTL 50 秒，又在 CDN 上对 `/search` 响应设 `max-age=50`。最坏情况下新帖多久才可能出现在结果里？怎么设置才不违反要求？

## A
- **最坏情况：** 某个 CDN 节点刚好在 Redis 缓存条目即将过期前的最后一刻回源，拿到一份快要过期的 Redis 结果（已存在近 50 秒），又把它缓存 50 秒。叠加最长约 100 秒，超过 1 分钟。
- **规律：** 串联的缓存，最大陈旧度是各层 TTL 之和（再加上索引自身的写入延迟）。
- **改法：** 给整条链路分配预算：比如总预算 60 秒，索引写入延迟留 10 秒，CDN 与 Redis 各 20 秒；或者只缓存一层；或让 CDN 只缓存很短时间（几秒）用来合并同一时刻的重复请求。
- **其它：** 浏览器也会遵循 `Cache-Control`，同样要计入；热门查询加上随机抖动，避免大量条目同时过期。
- **要点：** 新鲜度 SLA 是整条链路的预算，分配给每一层。
