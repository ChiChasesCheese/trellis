## Q
**在线拍卖 · 发布拍卖与出价服务**｜摘要 · 必会

发布拍卖和出价怎么实现？为什么出价要单独成一个服务？为什么不能只存一个 maxBid 字段？

## A
- **发布拍卖：** 客户端 → API 网关（认证、限流、路由）→ 拍卖服务（校验后存拍卖与物品）→ 数据库。基本就是一个 CRUD。
- **出价服务单独拆的理由：**
  - 独立扩缩：出价量大约是拍卖创建的 100 倍；
  - 隔离复杂性：校验、竞态、实时更新的逻辑都在这里；
  - 性能取向不同：出价服务为写吞吐优化，拍卖服务为读优化。
- **简单流程：** 出价请求 → 出价服务查当前最高价 → 在 bids 表存一条，状态是接受（高于最高价）或拒绝 → 返回状态。
- **不要只存 maxBid：** 很多人想只在拍卖对象上存一个最高价字段。这违反"不要销毁历史数据"的原则：每次覆盖就永久丢了信息，无法审计、无法查争议。总会有用户说"我的出价没记录、我本该赢"，没有完整记录就无法反驳。
