## Q
**在线拍卖 · 优解：最高价存在拍卖行里**｜摘要 · 必会

怎样既只锁很少的行，又不引入缓存与数据库的不一致？悲观锁和乐观并发各怎么写？

## A
- **核心想法：** 把最高价直接存进数据库的 Auction 表，让拍卖这一行扮演缓存。最高价与出价记录在同一个数据库的同一个事务里。
- **悲观锁版本：** 锁定这一场拍卖的一行 → 读最高价 → 写出价（接受或拒绝）→ 若更高就更新拍卖行的最高价 → 提交。只锁一行，时间很短。
- **乐观并发（OCC）版本：** 读拍卖行，拿到当前最高价（相当于版本号）→ 验证新价更高 → `UPDATE auctions SET max_bid = :new WHERE id = :id AND max_bid = :original`，只在最高价没变时才成功 → 成功就写出价记录，失败就从读取重来。
- **为什么 OCC 合适：** 同一拍卖上同时出价的冲突相对少见，不用加锁，偶尔重试一次即可。
- **取舍：** 悲观锁简单可靠，冲突多时（拍卖最后几秒）排队；OCC 无锁，冲突多时重试多。
