## Q
**短链服务 · 扩展：多个写实例的计数器**｜摘要 · 必会

写服务有多个实例时，计数器怎么保持全局唯一又不成为瓶颈？批量、高可用、多地域怎么做？

## A
- **集中计数器：** 所有写实例向同一个 Redis 原子 `INCR`，再算短码，写库。多一次网络往返相对其他操作可以忽略。
- **批量（counter batching）：** 每个实例一次领一批（如 1000 个）：Redis 原子地加 1000，返回区间起点；实例在本地用完再领。减少对 Redis 的请求，仍保证唯一。
- **高可用：** Redis Sentinel 或 Cluster 自动故障转移；单个 Redis 可处理十万以上操作/秒，远超创建速率。
- **多地域：** 给每个区域互不重叠的区间（A 区 0 到 10 亿，B 区 10 亿到 20 亿），写入用本地 Redis，避免跨区协调。
- **兜底：** 只需唯一，不需连续；数据库短码上的 UNIQUE 约束是最终保险。
- **最终架构：** 客户端到读服务、写服务；读服务经缓存查库；写服务取计数器写库。
