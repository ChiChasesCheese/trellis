## Q
**短链服务 · 短码生成：前缀与哈希**｜摘要 · 必会

生成短码要满足什么约束？为什么取长链接前缀不行？哈希加 base62 怎么做，碰撞怎么处理？

## A
- **三个约束：** 唯一；尽量短；生成高效。
- **前缀（差的方案）：** 取长链接前 8 个字符，前缀相同的链接就撞车，无法唯一，不知道用户想去哪个。
- **随机数：** 熵不够，不能保证唯一。
- **哈希（好的方案）：** 对规范化后的 URL 做 SHA-256，转 base62 取前 8 位，空间 62^8 约 218 万亿。base62（a–z、A–Z、0–9）不用 base64 的 `+` 和 `/`，因为斜杠是路径分隔符，加号在查询串里可能被当空格。
- **纯哈希是确定的：** 同一长链接永远得到同一码，可能要的（去重），也可能不要；不要就加秘钥盐（HMAC）。
- **碰撞：** 已用 n 个码、空间 |S| 时，下一个冲突的概率是 n/|S|。短码列加 UNIQUE 约束，冲突就加随机盐重试，限制 3–5 次，再不行换策略或报错。
- **三角取舍：** 码越长越不容易撞，但就不短了；查重又增加延迟，唯一、短、高效很难同时最优。
