## Q
**短链服务 · 拓展：除了哈希和 Redis 计数器还有什么发号法**｜拓展 · 加分

不想依赖一个中心 Redis，还能怎样生成全局唯一的短码？

## A
- **预生成密钥服务：** 一个独立的服务离线批量生成唯一的随机码，存进数据库，标记已用未用；写服务一次领一批。码不可预测，没有碰撞，但要维护这个服务和已用标记。
- **区间租约：** 协调服务（ZooKeeper、etcd 或数据库一行）给每个实例分配一段 ID 区间，实例本地自增，用完再领，和前面的批量计数器同一类思路，只是协调者换了。
- **雪花式 ID（Snowflake）：** 64 位里放时间戳、机器号、序号，各机器独立生成，不需要协调；缺点是 ID 很长，转成 base62 要 11 位左右，不适合短链。
- **随机加唯一约束：** 直接随机生成 7 位码，插入时靠 UNIQUE 约束，冲突重试；码不可预测，简单，空间用得越满重试越多。
- **选择：** 要最短码就用计数器；要不可预测就用随机或预生成。
