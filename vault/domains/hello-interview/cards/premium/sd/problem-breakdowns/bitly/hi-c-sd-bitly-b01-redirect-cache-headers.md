## Q
**短链服务 · 拓展：302 能被缓存吗，缓存放在哪一层**｜拓展 · 加分

「302 不缓存」是绝对的吗？想让 CDN 缓存热门短链的跳转，同时又保留撤销能力，该怎么做？

## A
- **默认行为：** 302 默认不被缓存，但响应里带 `Cache-Control: max-age=…` 时，浏览器和 CDN 都可以缓存它；301 则默认可长期缓存，浏览器会记很久。
- **做法：** 对热门短链给 302 加短的 `max-age`（如几十秒到几分钟），换取 CDN 命中；链接被撤销或修改时，最多过一个 TTL 就失效，也可以主动让 CDN 清除（purge）。
- **取舍：** TTL 是「撤销生效延迟」和「命中率」之间的旋钮；做不到秒级撤销的场景（恶意链接下架）要有主动清除或把 TTL 压到很低。
- **统计的含义：** 一旦 CDN 或浏览器缓存了跳转，点击不会到源站，源站的点击计数会偏少；想要精确统计，就要在边缘记录日志，或不缓存。
- **模式。** 用 TTL 换一致性：延迟容忍度越高，缓存越久。
