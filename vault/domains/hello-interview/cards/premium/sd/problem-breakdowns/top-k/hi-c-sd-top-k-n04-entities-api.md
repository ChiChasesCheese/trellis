## Q
**Top K · 实体、接口与播放事件从哪来**｜摘要 · 必会

Top K 的实体和 API 怎么定？为什么不给"记一次播放"设计接口，也不在这一步多花时间？

## A
- **实体：** 视频（Video）、播放（View，一次播放事件）、时间窗口（Time Window，即全部、近一小时、近一天、近一月）。
- **接口只有一个：** `GET /views/top-k?window={窗口}&k={K}`，返回 `{videoId, views}` 的数组。通常结果可能很长就要分页，这里 K 最多 1000 且由客户端自己指定条数，所以不用分页。
- **写入不设接口：** 假设播放服务已经把事件写进一个按视频 ID 分区的 Kafka 主题（ViewEvent），本系统只消费。这个假设合理，省掉不有趣的组件，把时间留给难点。
- **别在这里耗时间：** 对高级候选人，在显而易见的部分花太久，会让面试官怀疑你分不清简单与复杂，这本身是一项被考察的能力。
