## Q
**分布式限流器 · Redis Cluster 里的多规则检查与复制丢失**｜拓展 · 加分

一个请求要同时检查"每用户""每 IP"两条规则时，Redis Cluster 能用同一个脚本吗？主从切换会不会让限额出错？

## A
- **跨槽限制：** Redis Cluster 里一个脚本或事务涉及的所有键必须在同一个哈希槽，否则报 CROSSSLOT 错误。`user:alice:bucket` 和 `ip:1.2.3.4:bucket` 通常落在不同槽，不能放进同一个脚本。
- **解法：**
  - 分别检查两条规则，各调一次脚本，在网关里合并结果，取最严格的；代价是两次往返，且"第一条放行、第二条拒绝"时第一条已经扣了令牌，需要补偿或接受轻微多扣；
  - 或者用哈希标签（hash tag）：键名里花括号 `{...}` 内的部分决定槽，如 `{alice}:user`、`{alice}:endpoint:search` 就落在同一槽，可在一个脚本内检查同一用户的多条规则；但 IP 规则通常不属于同一个用户，仍需单独调用。
- **复制是异步的：** 主节点接受写入后先返回，再异步同步到副本。故障转移时，副本可能缺少最后几次扣减，客户端的桶回到稍早的状态，得到少量"白送"的令牌。
- **怎么看：** 对限流这种近似场景可以接受：丢的只是几次计数，且客户端的桶会很快重新收敛。如果是计费或配额扣减则不能这样，要用 WAIT 等待副本确认，或换成持久化存储。
- **模式。** 把相关数据放到同一分片：用哈希标签让需要一起原子更新的键共享同一个槽。
