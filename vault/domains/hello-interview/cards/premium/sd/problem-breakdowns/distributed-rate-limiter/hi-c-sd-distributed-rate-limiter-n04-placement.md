## Q
**分布式限流器 · 限流器放在哪里**｜摘要 · 必会

限流器放进应用进程、做成独立服务、放在 API 网关，各有什么优缺点？为什么选网关？

## A
- **差：进程内（in-process）。** 每台应用服务器用内存计数，最快，没有网络调用。但每台只看到自己的流量：限额 100 次/分钟、5 台服务器均匀分流，每台只见 20 次，都认为没超。负载均衡的路由一变，限额就完全不可预测，最坏会放过服务器数倍的流量。只适合单机或能接受按服务器数放大的近似限额。
- **中：独立服务。** 应用服务器每次先调限流服务问"放不放行"。全局状态，限额精确；应用能传入订阅等级、端点、业务规则等丰富上下文。缺点：每个请求多一次网络往返（如 10ms）；多一个故障点，要决定它挂了是放行还是拒绝；又多一个要部署、监控、扩容的服务；还要处理慢响应和网络分区。
- **好：API 网关或负载均衡。** 在系统最边缘，请求先限流再转发，被拒的请求应用服务器看不到，就像门口的保安。这是生产中最常见的做法，概念简单、保护强。
- **网关的局限：** 只能看到 HTTP 请求本身（头、URL、IP、令牌），看不到深层业务；"高级用户限额是 10 倍"这类规则要把等级编码进 JWT。状态也需要放进 Redis 这样的内存存储，要处理它变慢或不可用。
- **选择：** 网关。集中控制，又不给每个请求额外加调用。
