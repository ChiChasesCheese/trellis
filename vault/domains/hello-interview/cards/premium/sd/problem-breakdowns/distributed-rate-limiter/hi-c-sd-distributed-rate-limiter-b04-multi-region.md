## Q
**分布式限流器 · 多区域限流：全局限额怎么分**｜拓展 · 加分

用户的请求会打到多个区域，"每用户每分钟 100 次"的全局限额怎么执行，才不被跨区域延迟拖垮？

## A
- **问题：** 跨区域往返动辄上百毫秒，远超 10ms 的检查预算，不可能每次检查都去同一个中心 Redis。
- **做法一，按区域切分配额：** 把全局限额拆成各区域的子配额（如按历史流量占比，60 / 40），各区域只在本区域 Redis 里计数。检查是本地的，延迟低；代价是用户可以在两个区域各用满自己的份额，总量不超过全局限额，但某区域额度闲置时会浪费。
- **做法二，周期性再平衡：** 各区域每隔几秒上报用量，由协调者把闲置区域的额度挪给繁忙区域。额度在一个周期内是固定的，所以不会超发，但响应流量变化有延迟。
- **做法三，异步同步计数：** 各区域本地计数，后台合并（类似 CRDT 计数器），接受短时间内略微超限。限流本来就允许最终一致，这是合理的。
- **要说出的权衡：** 精度越高，延迟和耦合越大；多数 API 限流选"本地检查加周期性对账"。
- **粘性路由：** 若能让同一用户总是路由到同一区域（按用户哈希或就近），问题大大简化，但要处理区域故障时的切换。
