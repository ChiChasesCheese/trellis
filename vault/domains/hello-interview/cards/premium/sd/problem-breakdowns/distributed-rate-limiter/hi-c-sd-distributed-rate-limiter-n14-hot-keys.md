## Q
**分布式限流器 · 深入四：热点键**｜摘要 · 追问

某个客户端每秒产生数万个请求，把一个 Redis 分片压垮，合法的大客户和滥用流量分别怎么处理？

## A
- **成因：** 单一来源要压垮分片，通常是滥用（DDoS、配置错误的机器人），也可能是合法的高流量客户端：分析系统、数据管道、刷新过于频繁的移动端。
- **合法大客户：**
  - 客户端限流：鼓励 SDK 内置限流并遵守响应头，让流量变平稳，减少服务端负载；
  - 请求批处理：允许把多个操作合并成一个请求，减少检查次数；
  - 高级套餐：给需要的用户更高限额，甚至专属基础设施。
- **滥用流量：**
  - 自动封禁：持续触发限流（如一分钟内 10 次）就把该 IP 或 API key 暂时加入黑名单，名单可放在某个 Redis 分片，只在缓存未命中时查；
  - DDoS 防护：用 Cloudflare、AWS Shield 之类，在流量到达限流器前识别并拦截。
- **不要忘了：** 公司 NAT、公共 WiFi 下多个合法用户共享一个 IP。设计规则时就给 IP 限额放宽，更多依赖登录用户的限额，而不是事后再处理热点。
