## Q
**WhatsApp 即时通讯 · 发送者重试怎样不产生重复消息**｜拓展 · 加分

发送者发出 sendMessage 后没收到成功回复（网络抖动），重试会不会出现两条一样的消息？服务器和客户端各自怎么处理重复？

## A
- **两个方向的重复：**
  - 上行：发送者重发，服务器写了两次；
  - 下行：服务器重发推送（ack 丢了或超时），接收方收到两次。
- **上行：** 由客户端生成消息 ID（如 UUID 或 ULID），随 `sendMessage` 一起发。服务器以（chatId，客户端消息 ID）为条件写入，已存在就直接返回之前的结果，这就是幂等键（idempotency key）。不能靠服务器重新生成 ID，那样每次重试都是新消息。
- **下行：** 投递语义是至少一次，客户端按消息 ID 去重，同一个 ID 只显示一次；ack 要带上 ID，而且对重复到达也要回 ack，否则服务器会一直重发。
- **ID 的另一个好处：** 用 ULID 或时间有序 ID 做排序键，既能去重又能给出稳定的取回顺序。
- **模式。** 至少一次 + 幂等消费：传输层不追求恰好一次，让重复无害。
