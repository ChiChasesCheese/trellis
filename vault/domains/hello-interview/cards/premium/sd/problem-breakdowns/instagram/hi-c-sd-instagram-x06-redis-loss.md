## Q
**Instagram 图片分享 · 预测失败：Redis 动态流节点丢失后**｜考点 · 必会

一个存了 2000 万用户动态流的 Redis 分片没有持久化，宕机后重启为空。用户刷新时会看到什么？怎么恢复才不会把数据库压垮？

## A
- **现象：** 这些用户的流是空的或只有刚进来的新帖，体验是"关注的人好像都不发帖了"。
- **恢复路径：** 流缺失时回退到读时扇出（查关注列表、取每人最近帖子、合并），结果回写到 Redis 重建这个用户的流。
- **风险：** 2000 万用户同时回退，每人查上千个账号，等于把读时扇出的洪峰重新放回数据库，压垮它。
- **防护：**
  - 对重建限流，按活跃度排队，先重建最近活跃的用户；
  - 每次重建只拉最近一页，不拉全部历史，其余懒加载；
  - 用 Sentinel 副本 + AOF 避免大面积丢失，这是前置手段；
  - 同一用户并发重建要合并（只让一个请求去建，其余等待）。
- **取舍：** 流是派生数据，丢了能重建，所以持久化的要求比"主数据"低，但重建的成本决定你是否值得配 AOF。
