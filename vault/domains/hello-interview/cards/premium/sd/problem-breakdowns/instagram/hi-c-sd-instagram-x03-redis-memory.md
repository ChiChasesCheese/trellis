## Q
**Instagram 图片分享 · 估算：Redis 动态流要多少内存**｜考点 · 必会

假设 5 亿日活用户每人在 Redis 里保存最近 500 条动态的 postId，每条 postId 8 字节、时间戳分数 8 字节。原始数据多大？实际要按多少余量规划？这个量说明了什么设计要求？

## A
- **原始大小：** 5×10⁸ × 500 × 16B = 4×10¹² B = 4TB。
- **余量：** Redis 有序集合每个元素还有内部结构开销（跳表节点、哈希表条目），实际占用远大于裸数据，保守按 2–4 倍留余量，即 8–16TB；若每个节点可用 100GB，则需要 80–160 个节点。这是按假设做的规划，应在生产中实测。
- **设计要求：**
  - 必须用 Cluster 分片，并且按 userId 分片，使一个用户的动态流在同一节点；
  - 限制每个流的长度（只保留最近 N 条，老的丢弃，需要时用读时路径补）；
  - 只为活跃用户预计算，长期不登录的人不推，回来时再冷启动重建。
- **取舍：** 条数 N 越大，翻页越深越不用回库，但内存线性增长。
