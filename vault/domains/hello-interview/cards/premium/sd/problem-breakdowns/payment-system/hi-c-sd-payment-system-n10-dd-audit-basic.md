## Q
**支付系统 · 深入二：为什么不能只存当前状态**｜摘要 · 必会

支付数据"永不丢、可审计"，只在数据库里原地更新状态为什么不行？加审计表能解决吗？

## A
- **要求的由来：** 丢交易数据是财务与法律灾难；PCI DSS、SOX 和审计标准要求完整、不可变的记录。顾客半年后争议扣款，我们要能证明发生了什么：何时发起、授权多少、何时扣款、是否退款。Webhook、对账、欺诈检测都依赖可查询的审计轨迹。
- **只存当前状态（差）：** `UPDATE ... SET status='captured'` 后历史没了：不知道曾处于什么状态、何时变化、谁发起。有 bug 的发布会悄悄污染数据，发现时原值已不在，备份也难判断哪些行受影响；合规审计要看完整历史与防篡改证明，这些都没有；排查要靠服务器日志考古。
- **独立审计表（好）：** 同一事务里既更新主表，又向只追加的审计表插入一行（旧状态、新状态、操作者、时间、元数据）；甚至在数据库权限上让审计表只能插入。能回答合规问题，也可以重放审计记录重建状态。
- **局限：**
  - 依赖应用代码记得写两次，漏写或有 bug 就静默丢审计，无法恢复；
  - 高吞吐的运营库还要存多年审计数据（数十亿行），审计查询会拖慢运营查询，运营表结构也被审计要求牵制，没法分别优化。
