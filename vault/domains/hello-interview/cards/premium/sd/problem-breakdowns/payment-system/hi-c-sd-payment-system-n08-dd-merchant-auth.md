## Q
**支付系统 · 深入一：商户身份认证（API 密钥与请求签名）**｜摘要 · 必会

怎么确认发请求的商户真的是商户本人？普通 API 密钥有什么问题，请求签名怎么做？

## A
- **两个安全问题：** 发请求的商户是不是它声称的人；顾客的个人信息有没有被保护好。这张卡讲第一个。
- **基础 API 密钥（好）：** 商户入驻时生成唯一密钥，放在请求头（`Authorization: Bearer ...`），网关查库得到商户。缺点：静态凭据，每次请求都带，可以被网络嗅探截获，截获后可无限重放；还常被硬编码进客户端或配置文件，泄露到代码仓库或备份。对金融系统风险不可接受。
- **请求签名（最好）：** 入驻时发两把钥匙：公开的 API 密钥（标识商户）和只存在商户服务器上的私密密钥（绝不进客户端）。每个请求，商户用私密密钥对（方法、路径、参数、请求体）加时间戳加唯一随机数（nonce）做 HMAC 签名，放在请求头。
- **网关验证：** 按 API 密钥取出私密密钥 → 用同一算法（SHA-256）重算签名并比对 → 检查时间戳在可接受窗口内（通常 5–15 分钟）→ 检查该 nonce 在窗口内没有用过（查缓存或库）。
- **效果：** 既认证了身份（只有持私密密钥的人能签出），又保证了完整性（请求体被改签名就错），还防重放（过期的时间戳或用过的 nonce 会被拒）。
