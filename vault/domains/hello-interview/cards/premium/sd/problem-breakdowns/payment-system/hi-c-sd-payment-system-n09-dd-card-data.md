## Q
**支付系统 · 深入一：保护顾客卡数据**｜摘要 · 必会

顾客的卡号怎么送进系统才安全？商户服务器收集、iframe、iframe 加加密各有什么利弊？

## A
- **服务器端收集（差）：** 顾客在商户网站填卡，商户服务器转发给我们。卡数据绝不应经过商户服务器（也是 PCI DSS 要求）；每台商户服务器都成为攻击目标，一个漏洞就会泄露卡数据，商户还承担巨额责任。
- **iframe 隔离（好）：** 学到的教训是卡号不能碰商户服务器。我们提供 JavaScript SDK，在商户网页里加载一个来自我们域名的 iframe，顾客输入的卡信息直接经 HTTPS 发到我们，绕开商户系统；浏览器的同源策略阻止商户代码读取 iframe 内部。
  - 局限：安全依赖浏览器策略，复杂攻击可能攻破；数据只靠 HTTPS 保护；定制性差，移动浏览器上体验也有问题。
- **iframe 加加密（最好）：** SDK 在卡信息离开设备前，就用我们的公钥加密。卡数据在顾客浏览器之外从不以明文存在，即使商户网站被攻陷也只拿到密文。密文经 HTTPS 送到我们，用保存在硬件安全模块（HSM）里的私钥解密。
- **纵深防御（defense in depth）：** 任何一层失败（如 iframe 被攻破），其他层仍保护卡数据：设备上加密、传输加密、服务端 HSM。
