## Q
**支付系统 · 追问：CDC 能记录"谁、为什么"吗**｜考点 · 必会

CDC 只看到行的变化。审计要求知道是谁、因为什么请求把状态从 authorized 改成了 captured。设计上要补什么？

## A
- **CDC 的盲区：** 它捕获的是"这一行从什么变成什么"，看不到应用层的上下文：哪个服务、哪个商户请求、哪条幂等键、什么原因。
- **补法：** 把上下文写进业务行本身：给表加 `updated_by`、`request_id`、`reason` 之类的列，随同一事务写入，这样变更事件的 `after` 里就带上这些信息。
- **更干净的做法：** 一张只追加的"状态转换"表，每次转换插入一行（旧状态、新状态、请求 ID、操作者），它也是被 CDC 捕获的表，既有业务含义又有保证。
- **关联追踪：** 请求 ID 贯穿网关、服务、数据库、事件，排查时能把一笔支付的所有痕迹串起来。
- **权衡：** 完全依赖应用写上下文，回到"应用可能漏写"的问题，但此时漏写的只是附加信息，核心的变更事实仍由 CDC 保证不丢。
- **加分：** 在数据库层设约束，如 `request_id` 不可为空，让漏写在测试阶段暴露。
