## Q
**支付系统 · 预测：交易服务在四个位置崩溃**｜考点 · 必会

交易服务流程：1 写尝试记录；2 调用支付网络；3 更新尝试结果；4 返回商户。分别在 1 与 2 之间、2 与 3 之间崩溃，会留下什么状态，怎么恢复？

## A
| 崩溃位置 | 留下的状态 | 恢复 |
|---|---|---|
| 1 之前 | 什么都没有 | 商户超时后用同一幂等键重试，正常创建 |
| 1 与 2 之间 | 尝试记录是 `initiated`，网络没收到请求 | 恢复任务发现 `initiated` 太久，用引用号向网络查询：查无此笔，则可以安全重发（同一引用号），网络靠引用号去重 |
| 2 与 3 之间 | 尝试仍是 `initiated`，但网络可能已处理 | 同样按引用号查询：网络有记录就把结果补进来；没有再重发 |
| 3 与 4 之间 | 库里已是最终状态，商户没收到响应 | 商户重试同一幂等键，直接返回已存的结果 |

- **共同点：** 先记尝试再动作，使每个崩溃点都留下可寻的痕迹；引用号既是查询凭据，也是向网络的幂等标识。
- **不能做的事：** 在不查询的情况下对 `initiated` 的记录重新发起新的、引用号不同的请求，会造成重复扣款。
- **与两阶段事件的关系：** 生产里的"创建事件"和"完成事件"正好对应这里的 1 和 3，比较两者能判断崩溃发生在哪一段。
