## Q
**支付系统 · 拓展：复式记账账本**｜拓展 · 加分

Transaction 表能记录"收了多少钱"，为什么真正的支付系统还要一个复式记账（double-entry）的账本？

## A
- **问题：** 用一个可更新的"余额"字段，任何 bug 或并发错误都会让钱凭空增减，无法发现，也无从追溯。
- **复式记账：** 每笔资金动作写成一组账本分录（LedgerEntry），每组借方与贷方金额相等。例如顾客付款 100：借"待结算资产"100，贷"商户应付"100。所有分录之和恒为零，这是一个可随时校验的不变量。
- **只追加：** 分录不修改不删除，更正通过追加反向分录完成；余额等于相关分录之和（可以缓存，但可从分录重算）。
- **好处：** 钱的去向可审计；对账时能和网络、银行的数据逐项核对；退款、拒付、手续费都只是新的分录，模型不变。
- **与幂等的结合：** 每组分录带来源的交易 ID 作为唯一键，重试不会重复记账。
- **与本设计的关系：** 事件流提供不可变的状态历史，账本提供不可变的资金历史，两者互补；面试中提到账本的存在和不变量即可。
- **模式。** 只追加加不变量：用永不修改的记录加可校验的总和来防止静默错误。
