## Q
**支付系统 · 深入三：事件驱动的安全与自动对账**｜摘要 · 必会

事件驱动加自动对账的完整流程是什么？为什么说要先记录意图再动作，生产里的两阶段事件模型是什么？

## A
- **核心：** 先记录意图，再行动。
  - 记录尝试：调用任何网络之前，先向库写一条尝试记录（网络名、引用号、要做什么），触发一个 CDC 事件；
  - 调用网络：发真正的扣款请求，设超时；
  - 处理结果：成功则更新尝试为 `succeeded`；超时则更新为 `timeout`，触发 CDC 事件交给对账服务；明确失败则更新为 `failed` 并写原因；
  - 自动对账：对账服务消费超时事件，用记录的引用号主动向网络查询真实结果。
- **两种核实方式：** 直接的 API 查询（实时）；批量对账文件（reconciliation file）：网络按固定周期（每天或每小时）送来的、格式严格的全部已处理交易的权威记录。对账服务把这些外部事件与内部尝试关联，按网络的权威数据更新支付状态，而不是靠超时猜。
- **好处：** 每一步都是不可变事件，成功、失败、超时都有完整审计轨迹；把支付网络当作一等的异步伙伴，而不是同步服务。
- **生产里的两阶段事件：** "交易创建"事件在交易服务开始处理时发出（数据库写完成之前），发不出则交易进入锁定或失败态可重试；"交易完成"事件在数据库写成功后发出，发不出则交易同样锁定，在完成事件发出前禁止更新。重试时拿"创建"事件的数据与实际数据库状态比较：库已写入就只补发完成事件，不重试整个交易。生产中缺失的完成事件，多数是外部系统超时发生在库写入之前。
