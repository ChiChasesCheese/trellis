## Q
**支付系统 · 最终架构：各部件一览**｜摘要 · 必会

合并所有深入问题后，支付系统的最终架构是什么，数据怎么流动？

## A
- **请求路径：** 商户经 API 网关（请求签名验证、限流）进入意图服务或交易服务；卡信息由 SDK 在浏览器里加密后经 iframe 直达我们，HSM 解密。
- **运营库：** 保存意图、交易、尝试记录与商户信息，按商户分片，带读副本和缓存。
- **事件流：** CDC 把每次提交的变更发布到 Kafka（按意图 ID 分区、三副本），归档到对象存储。
- **消费者：** 审计、分析、对账、Webhook 各自消费同一个事件流。
- **对外：** 交易服务通过专线或 VPN 连接支付网络；先记录尝试再调用；超时由对账服务按引用号查询并处理结算文件。
- **每个部件对应的需求：** 签名与 iframe 加密对应安全；CDC 加事件流对应持久审计；尝试记录加对账对应异步网络下的安全；分区、分片、冷存储对应规模。
