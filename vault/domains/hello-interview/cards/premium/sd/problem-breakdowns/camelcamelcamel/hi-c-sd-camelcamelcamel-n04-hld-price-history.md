## Q
**价格追踪服务 · 高层设计一：查价格历史**｜摘要 · 必会

价格历史的读路径怎么搭？为什么价格库要和主库分开，历史服务要和爬虫分开？

## A
- **组件：** 客户端（网站或扩展）→ API 网关（认证、限流、路由）→ 价格历史服务 → 价格库；爬虫服务定期爬取并写价格库；另有主库存用户、商品、订阅。
- **读流程：** 客户端发 `GET /products/{id}/price?period=30d` → 网关认证后转发 → 服务按 `product_id` 加时间范围查价格表 → 返回 JSON，前端画折线图。
- **价格库与主库分开：** 价格数据只追加、会涨到数十亿行、要时序优化、容忍最终一致；主库的用户、商品、订阅体量小、是常规增删改查。访问模式不同，分开后可以各选存储、各自扩容。
- **历史服务与爬虫分开：** 历史服务要扛大量并发读（用户看图表），爬虫是定时、写入节奏稳定的批量任务。扩缩容特征不同，分开后互不拖累。
- **先把爬虫当黑盒：** 假设它会定期更新价格表，细节留到深入采集那一节，避免一开始就陷进去。
