## Q
**股票交易平台 · 最终架构：各部件一览**｜摘要 · 必会

合并所有改动后，股票交易平台的最终架构由哪些部件组成，数据如何流动？

## A
- **行情路径：** 价格处理器监听交易所成交流 → 写缓存、发布到 Redis 频道 → 符号服务服务器订阅 → 通过 SSE 推给连接的客户端；新连接先从缓存拿初始价格。
- **下单路径：** 客户端 → 网关 → 订单服务 → 写订单库（按 userId 分片，`pending`）→ 经 NAT 网关同步调用交易所 → 写键值库并把订单更新为 `submitted`。
- **回写路径：** 成交处理器（webhook 加负载均衡）→ 查键值库 → 定位分片和订单 → 更新状态。
- **兜底：** 清理任务扫描卡在中间态的订单，用 `clientOrderId` 向交易所对账。
- **每个部件对应的需求：** 缓存加 SSE 加 pub/sub 对应低延迟行情；NAT 网关对应最少连接；订单库加清理任务对应强一致。
