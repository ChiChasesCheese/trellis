## Q
**股票交易平台 · 深入一：用 Redis 发布订阅路由行情**｜摘要 · 必会

很多用户订阅很多只股票时，怎么把某只股票的价格送到正确的符号服务服务器，再扇出给用户？

## A
- **要解决的问题：** 价格更新要路由到"连着关心这只股票的用户"的那些符号服务服务器。
- **方案：** Redis 发布订阅（pub/sub），每个符号一个频道。
- **完整流程：**
  - 用户订阅时，符号服务服务器在本地维护 `Symbol -> Set<userId>`，为用户订阅的每个符号加一项；
  - 服务器确保自己已订阅这些符号对应的 Redis 频道，没有就订阅；
  - 符号变价时，价格处理器发布到 Redis，所有订阅了该频道的服务器都收到，再各自扇出给自己连着的、关心该符号的用户；
  - 用户取消订阅或断线（用心跳检测），服务器从各符号的集合里删掉他；如果某符号再没有用户，就退订那个 Redis 频道。
- **为什么能扩展：** 用户可以均匀分到各服务器，负载分散；系统自我调节，只传输真正有人订阅的价格，服务器不会收到不相关的符号。
- **关键设计：** 订阅关系由服务器进程持有，而不是由 Redis 持有，所以一个符号只要有人看，每台服务器只订阅一次，而不是每个用户一次。
