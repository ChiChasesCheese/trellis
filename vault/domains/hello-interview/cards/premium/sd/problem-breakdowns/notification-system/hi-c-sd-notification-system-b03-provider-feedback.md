## Q
**通知系统 · 拓展：服务商的反馈回路和发送信誉**｜拓展 · 加分

状态 SENT 是否意味着用户收到了？平台还需要处理服务商的哪些回传信息，为什么这对长期运行很重要？

## A
- **SENT 的含义：** 只表示服务商接受了请求，不等于送达。真正的送达、退信、投诉通过服务商的回调（webhook）或状态回执异步返回，需要另外的状态（如 DELIVERED、BOUNCED）。
- **无效令牌：** APNs 和 FCM 在设备令牌失效（卸载应用、令牌轮换）时返回错误，应据此删除令牌，否则每次活动都在白白发送并占用额度。
- **邮件退信和投诉：** 硬退信（地址不存在）的地址应进入抑制名单，不再发送；用户标记垃圾邮件的投诉率过高会损害发信域名的信誉，导致连正常邮件（包括验证码）也进垃圾箱。
- **短信：** 用户回复停止（STOP）要及时记入退订，否则有合规风险。
- **回调本身也是至少一次：** 状态更新要幂等，且可能乱序到达（DELIVERED 先于 SENT 记录），状态机只允许向前推进。
- **为何重要：** 平台的价值是让所有团队的通知都稳定送达，发信信誉是共享资源，一个团队的垃圾发送会拖累所有人，所以要集中管理抑制名单和反馈。
