## Q
**通知系统 · 找错：免打扰时间的判断与检查时机**｜考点 · 必会

用户设免打扰 22:00–08:00（时区 America/Los_Angeles）。有人写判断逻辑 `start <= now < end`；还有人把检查放在接受通知时。各有什么错？

## A
- **判断错误：** 22:00 > 08:00，窗口跨过午夜。`22:00 <= now < 08:00` 永远为假，免打扰完全不生效。正确写法：若 `start <= end`，条件是 `start <= t < end`；若 `start > end`（跨午夜），条件是 `t >= start 或 t < end`。
- **时区：** 要先把当前时间转换成用户时区的本地时间再比较；夏令时切换日，本地 02:30 可能不存在或出现两次，要用带时区的库，而不是自己加偏移。
- **检查时机错误：** 在接受时检查，定时通知在 20:00 接受、23:00 发送，用户在 22:00 才改了偏好，检查结果已经过期。应在调用服务商之前检查。
- **例外：** 高优先级不受免打扰影响。
- **处理方式：** 被免打扰拦截的标准通知，可以标 `SUPPRESSED` 丢弃，也可以延后到 08:00；这是产品决策，要在设计里明确，别默认丢弃促销以外的内容。
