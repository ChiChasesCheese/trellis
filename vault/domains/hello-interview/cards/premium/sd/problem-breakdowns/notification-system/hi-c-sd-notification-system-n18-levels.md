## Q
**通知系统 · 各级别的期望**｜摘要 · 必会

通知系统这道设计，中级、高级、Staff 及以上分别要做到什么？

## A
- **中级：** 明确定义 API 与数据模型：发送和活动端点都带优先级，活动扇出成通知。给出覆盖直发与定时活动的高层设计；意识到同步调用服务商会丢通知，提示后能达到持久投递的"好"方案。优先级隔离和去重顺序不要求独立想到。
- **高级：** 很快过完高层设计，把时间花在深入问题，不靠引导地推进持久投递和高优先级层的隔离；能自信讨论隔离、队列、优先级的细节，越提前想到问题越好。可能自己想不到按层服务商额度和去重顺序，也没关系。
- **Staff 及以上：** 三个深入问题都要有深度。主动用数字找问题所在；知道天花板是服务商而不是自己的工作进程。有失败模式判断力：去重存储挂了怎么办，备用服务商何时值得切换（只对高优先级），为什么先占幂等键再调服务商会把至少一次变成最多一次。最好的候选人会讲出图上看不到的运维约束。
