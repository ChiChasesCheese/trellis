## Q
**通知系统 · 设计：活动发出去一半，法务要求取消**｜考点 · 必会

一个 100 万人的活动已经有 40 万条消息在队列里，法务要求立即取消。怎么做才快、又不拖慢每条消息的处理？

## A
- **不要去清空队列：** 队列通常不支持按条件删除，而且清空会误伤其他活动。
- **标记加检查：** 取消只是给活动写一个"已取消"状态，并把已取消的活动 ID 放进一个小集合；工作进程处理每条消息时检查它的 `campaignId` 是否在集合里，在就丢弃并记 `SUPPRESSED`（原因：活动取消）。
- **让检查便宜：** 已取消的活动很少，集合很小，缓存在进程内存里并每隔几秒从 Redis 或库刷新；每条消息只是一次内存哈希查找，不增加网络往返。
- **扇出阶段也检查：** cron 扇出尚未完成时要停止继续扇出，避免队列继续被灌入。
- **取消延迟：** 约等于缓存刷新间隔，加上已经被取走、正在发送的那几条无法追回；要和法务说清楚"尽力阻止、已送出的无法撤回"。
- **取舍：** 刷新间隔短则更快取消，但对 Redis 的压力大；几秒就够。
