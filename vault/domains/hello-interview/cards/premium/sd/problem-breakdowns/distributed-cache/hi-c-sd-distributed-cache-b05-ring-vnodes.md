## Q
**分布式缓存 · 拓展：虚拟节点为什么让一致性哈希均匀**｜拓展 · 加分

只给每台机器在环上放一个点，负载会多不均匀？虚拟节点怎么解决，Python 里怎么写？

## A
- **问题：** 50 个随机点把环切成长短不一的 50 段，最大的段可以比平均大好几倍。实测 5 万个键、每节点 1 个点，最忙节点的负载是平均的 4.14 倍。
- **虚拟节点（vnode）：** 每台物理机放几十到几百个点，各段的长度趋于平均。100 个点时最忙节点只有平均的 1.22 倍。
- **额外好处：** 节点加入时从很多节点各接管一小段，故障时它的负载分摊给很多邻居而不是压垮某一个；也可以给大机器多放几个点，实现加权。
- **代价：** 环上的点多了，路由表占内存，加入节点要插入很多点（用有序数组 + `bisect` 是 O(n) 插入，节点变更不频繁时可接受）。
- **实现：** 用有序列表存 (位置, 节点)，查找键用 `bisect` 找到第一个大于键位置的点，到末尾绕回开头。实测增加一个节点（50 → 51）只搬了 2.0% 的键，取模则搬 98.2%。
- **模式。** 环形哈希：用二分在有序点集上做顺时针后继查询，查找 O(log n)。

```python
def owner(self, key):
    i = bisect.bisect(self.points, (h(key), "")) % len(self.points)  # 顺时针第一个点，到头绕回
    return self.points[i][1]
```
