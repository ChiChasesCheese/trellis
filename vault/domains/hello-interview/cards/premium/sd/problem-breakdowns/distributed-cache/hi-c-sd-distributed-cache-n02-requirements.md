## Q
**分布式缓存 · 需求与规模**｜摘要 · 必会

设计分布式缓存时，功能和非功能需求怎么定？为什么要追问规模和范围？

## A
- **功能：**
  - 设置、读取、删除键值对；
  - 可给键配置过期时间；
  - 内存满时按 LRU（最近最少使用）淘汰。
  - 可配置缓存大小先不做。LRU 是自己选的，要问面试官想要什么，别的策略有 LFU（最少使用频率）、FIFO（先进先出）或自定义。
- **规模要主动问：** 假设 1TB 数据、峰值 10 万请求/秒，它决定后面要不要分片、要多少节点。
- **非功能：**
  - 高可用，最终一致可接受（缓存本来就是副本，可以稍旧）；
  - get / set 延迟 < 10ms；
  - 扩展到 1TB 与 10 万 QPS。
- **范围外：** 持久化（重启后保留数据）、强一致、复杂查询、事务。这些是大胆的假设，一定要向面试官确认，有人会在意持久化。
- **要点：** 缓存的核心取舍是用一致性和持久性换速度与可用性，需求阶段就把这个立场讲出来。
