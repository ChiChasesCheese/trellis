## Q
**分布式缓存 · 计算：节点从 50 增到 51 要搬多少键**｜考点 · 必会

用 `hash(key) % N` 分片，N 从 50 变成 51，约多少比例的键换了归属？用一致性哈希呢？缓存被这么多键重映射会发生什么？

## A
- **取模：** 一个键不换节点，需要 `h mod 50 == h mod 51`。在一个 50 × 51 的周期里，只有 50 个余数满足，所以不变的比例是 1/51，换节点的比例是 50/51 ≈ 98%。实测（5 万个键）约 98.2%。
- **一致性哈希：** 新节点只接管环上相邻的一段，理想是 1/51 ≈ 2%；100 个虚拟节点的实测约 2.0%。
- **后果（取模）：** 98% 的键在新位置没有数据，等于缓存几乎全冷；这些请求同时回源到数据库，容易在扩容时造成缓存雪崩，数据库被压垮。
- **缓解（一致性哈希下）：** 被重映射的 2% 也会出现未命中，但量小，数据库承受得住；还可以让新节点先预热再上线。
- **要点：** 一致性哈希的价值是把"扩缩容"从全局事件变成局部事件。
