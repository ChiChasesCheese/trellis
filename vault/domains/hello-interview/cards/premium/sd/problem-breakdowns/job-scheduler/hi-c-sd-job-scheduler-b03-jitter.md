## Q
**分布式任务调度器 · 拓展：退避为什么要加抖动，上限和重试预算**｜拓展 · 加分

指数退避 5、25、125 秒还有什么隐患？抖动怎么写，该不该无限重试？

## A
- **隐患：** 同时失败的一批作业用同一个公式，会在同一秒一起重试，下游刚恢复就又被同步的重试冲垮（雷同重试，也叫共振）。实测 1000 个第一次重试，无抖动全是 5 秒；全抖动后分布在 0 到 5 秒之间。
- **全抖动（full jitter）：** 延迟 = 在 `[0, min(上限, 基数 × 倍数^次数)]` 里均匀取随机数，同时设上限防止延迟无限增长。它比只加一点点随机更能打散负载；代价是个别作业的重试会很快发生，平均等待比无抖动更短。
- **重试预算：** 全局限制重试占总请求的比例（例如不超过 10%），超出就不再重试，防止下游故障时重试放大成事故。
- **分类：** 参数错误、权限错误等永久性失败不应该重试，直接进死信队列；网络超时、5xx 才重试。
- **与 SQS 的配合：** 重新入队时的 DelaySeconds 设为抖动后的值（上限 900 秒），尝试次数用 ApproximateReceiveCount 记录。
- **模式。** 加噪声破坏同步：确定性的公式会让大量实例步调一致，加随机让它们错开。

```python
def backoff(attempt: int, base: float = 5, cap: float = 300) -> float:
    ceiling = min(cap, base * 5 ** attempt)   # 5, 25, 125, ... 封顶
    return random.uniform(0, ceiling)         # 全抖动
```
