## Q
**分布式任务调度器 · 找错：用 Redis 有序集合实现延迟队列的领取**｜考点 · 必会

方案是把作业放进 ZSET（分数是到期时间）。worker 用 `ZRANGEBYSCORE jobs -inf now LIMIT 0 1` 取最早到期的一个，然后 `ZREM` 删除再执行。多个 worker 并发会怎样？取出后崩溃呢？怎么改？

## A
- **并发问题：** 取和删是两条命令，两个 worker 可能同时取到同一个作业，各自执行，重复执行。
- **改进一：** 只让 `ZREM` 的返回值（删除成功为 1）决定是否领取：返回 0 就说明被别人抢先了，重新取。这样领取变成原子操作，用 Lua 脚本把“取 + 删”合成一步更好。
- **崩溃问题：** 取走并删除后，worker 在执行前崩溃，作业就丢了（至多一次）。
- **改进二：** 不要直接删除，而是把作业移进“处理中”有序集合，分数是可见性截止时间（如现在 + 30 秒）；执行成功才从中删除；另有一个回收器定期把截止时间已过的作业放回主集合。这就是自己实现的 SQS 可见性超时。
- **持久性：** Redis 异步复制，主节点宕机可能丢掉最近的写；要么接受并用数据库扫描兜底（数据库才是事实来源，Redis 里的内容可以重建），要么开 AOF 持久化。
- **结论：** 自建延迟队列要实现三件事：原子领取、可见性超时回收、可重建；这就是 SQS 帮你省下的东西。
