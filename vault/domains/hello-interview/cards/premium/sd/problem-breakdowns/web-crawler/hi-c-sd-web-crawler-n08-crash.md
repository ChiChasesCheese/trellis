## Q
**网络爬虫 · 深入一：爬虫宕机后进度不丢**｜摘要 · 必会

爬虫处理到一半宕机，怎样保证那个 URL 不丢？Kafka 和 SQS 各自的机制是什么？

## A
- **原则：** 在 HTML 成功存进 blob 之前，URL 一直留在队列里；换一个爬虫接着处理即可，宕机就再起一个新的。
- **Kafka：** 消息留在日志里，读了也不删除。爬虫靠偏移量（offset）记录进度，成功拉取并处理之后才更新偏移量；爬虫失败后，下一个从旧偏移量接着读。
- **SQS：** 消息一直在队列里，直到被显式删除。收到消息后，可见性超时让其他爬虫暂时看不到；若爬虫没来得及确认就挂了，超时后消息重新可见，别的爬虫再试。HTML 存好之后才删除消息。
- **解析 worker 同理：** 文本存进 blob 之前，URL 一直留在队列里。
- **这里选 SQS：** 可见性超时让退避很容易、自带死信队列、托管伸缩。
