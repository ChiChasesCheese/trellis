## Q
**网络爬虫 · 深入三：去重，URL 与内容**｜摘要 · 必会

怎样避免重复爬取？为什么只做 URL 去重不够？内容去重用"哈希加索引"和"布隆过滤器"各有什么利弊？

## A
- **URL 去重（第一道防线）：** 入队前先查元数据库的 URL 表，已有则跳过。
- **为什么不够：** 不同 URL 可能返回相同内容，如 `example.com` 与 `www.example.com`，甚至不同域名完全一样。所以拉取之后还要做内容去重：对网页内容算哈希，已见过就跳过昂贵的解析。
- **哈希加索引：** 把哈希存在 URL 表里并对哈希列建索引，新网页哈希一查即知。担心索引变大拖慢写入偏悲观，现代数据库对索引处理得很好，这是更实用的做法。
- **布隆过滤器（Bloom filter）：** 概率性集合：说"没见过"一定对，说"见过"可能是假阳性。可用 Redis 的 RedisBloom（`BF.ADD`、`BF.EXISTS`），调大过滤器和哈希函数个数能降低误判率。缺点是误判会漏爬一小部分网页。
- **取舍：** 布隆过滤器在这里有点过度设计，简单的索引更实用；它的价值是候选人总会提到，要能讲清楚。
