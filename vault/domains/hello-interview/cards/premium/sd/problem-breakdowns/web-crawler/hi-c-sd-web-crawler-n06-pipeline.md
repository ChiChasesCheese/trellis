## Q
**网络爬虫 · 深入一：拆成流水线以容错**｜摘要 · 必会

单个爬虫服务既查 DNS、拉网页，又提文本和链接，一步失败就丢全部进度。怎样改造？为什么队列里不放 HTML？

## A
- **问题：** 拉网页最容易失败（站点下线、迁移、慢、网页太大），而爬虫把所有步骤放在一起，一处失败整体重来。
- **做法：** 拆成流水线阶段。第一级 URL Fetcher 只拉 HTML，存进 blob；第二级读 HTML，提取文本和链接（两者都轻，合并成一级即可）。哪一级失败，只重试那一级。
- **好处：** 失败隔离；各级可独立伸缩和优化；需求变化时（比如要把图片 alt 文本也提进来）只换提取函数，不必重新拉网页，因为重爬是最昂贵的一步。
- **元数据库：** 用 DynamoDB（PostgreSQL、MySQL 也可）存已拉取 URL 的状态，以及 HTML 和文本在 blob 里的位置。
- **队列消息只放 URL 在元数据库里的 ID。** 把 HTML 塞进队列是反模式：队列不为大载荷设计，又贵。
- **习惯：** 数据处理题第一反应就是拆成小的流水线阶段。
