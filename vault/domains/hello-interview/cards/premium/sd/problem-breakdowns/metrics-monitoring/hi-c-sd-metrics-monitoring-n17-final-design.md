## Q
**指标监控平台 · 最终架构：各部件一览**｜摘要 · 必会

合并所有深入问题后，指标监控平台的最终架构由哪些部件组成，数据怎么流动？

## A
- **摄入路径：** 每台服务器上的采集器本地聚合、缓冲、批量发送 → 摄入服务（校验、基数强制）→ Kafka（跨区复制）→ 写入消费者批量写时序库（幂等）。
- **存储：** 时序库按时间和序列哈希分片，带多分辨率降采样；Postgres 存告警规则和基数策略。
- **查询路径：** 仪表盘 → 查询服务（类 PromQL）→ Redis 缓存（历史块）加时序库（近期块）。
- **告警路径：** 告警评估器定时查询时序库，关键规则由 Flink 消费 Kafka 做窗口评估 → 告警事件写 Kafka → 通知服务（去重、分组、静默、升级、重试、备用渠道）→ Slack、PagerDuty、邮件。
- **兜底：** 元监控由独立系统承担，加看门狗心跳。
- **每个部件对应的需求：** 采集器与 Kafka 对应吞吐；时序库与降采样对应查询；缓存对应秒级仪表盘；通知服务对应可靠告警；基数强制对应系统存活。
