## Q
**广告点击聚合 · 深入三：点击幂等与展示 ID**｜摘要 · 必会

怎样避免同一次点击被重复计数？按用户加广告去重为什么不对？展示 ID（impression ID）方案怎么做、怎样防伪造？

## A
- **差：把 userId 放进点击数据。** 要求用户登录，按 userId 加 adId 去重。问题一，不是所有用户都登录；问题二，再营销（retargeting）会故意在很长时间里向同一用户多次展示同一广告，应该"每次展示最多算一次点击"，而不是"每个用户每个广告只算一次"。
- **好：展示 ID。** 投放服务为每次展示给每个用户生成唯一 ID（展示指广告在网页上被渲染一次），随广告发给浏览器，点击时带回，这就是幂等键。
- **去重位置：** 必须在入流之前做。窗口边界两侧的重复点击在 Flink 里会被算成两次。点击来了先查缓存：已存在就忽略；不存在就写入流，再把 ID 写缓存。先写流，是因为缓存更新失败最多多一次重复，对账能修正，而丢点击无法恢复。
- **防伪造：** 攻击者可以伪造大量唯一 ID。用密钥对展示 ID 和 adId 一起做 HMAC 签名，点击时验证，防止拿一个有效 ID 重放到别的广告上；HMAC 只是哈希计算，微秒级。
- **缓存规模：** 每天 1 亿个 ID × 16 字节 ≈ 1.6 GB，用 Redis Cluster 加副本和持久化（RDB 或 AOF）即可。
