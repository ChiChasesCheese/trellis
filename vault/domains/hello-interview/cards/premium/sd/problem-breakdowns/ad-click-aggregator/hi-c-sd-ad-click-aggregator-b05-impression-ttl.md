## Q
**广告点击聚合 · 拓展：展示 ID 的过期时间与去重缓存 TTL**｜拓展 · 加分

攻击者拿到一个合法的已签名展示 ID，等去重缓存过期后再重放，能多算一次点击吗？怎么设计过期？

## A
- **漏洞：** HMAC 签名只证明"这个 ID 是我们发的、并且匹配这个广告"，不证明"这是第一次使用"。唯一性靠去重缓存；缓存条目过期后，同一个有效 ID 再次出现就会被当成新点击。
- **做法一，签名里带过期时间：** 在被签名的内容里加入展示时间或有效期（例如广告展示后 24 小时内有效），验证时检查未过期。过期的点击直接拒绝，缓存 TTL 只要不短于有效期即可。
- **做法二，缓存 TTL 对齐有效期：** 缓存 TTL = 有效期 + 一点余量，保证有效期内的 ID 一定在缓存里；过期后签名验证本身就会拒绝。
- **密钥轮换：** 密钥定期轮换，签名里带版本号，验证时同时接受当前和上一个版本。
- **规模：** 有效期越长，缓存越大；按每天 8640 万个 ID、16 字节算，一天的有效期约 1.4 GB，七天约 9.7 GB，仍可接受，但要权衡。
- **模式。** 带时效的令牌：用签名内的有效期限制可重放的时间窗口，让去重状态可以过期回收。
