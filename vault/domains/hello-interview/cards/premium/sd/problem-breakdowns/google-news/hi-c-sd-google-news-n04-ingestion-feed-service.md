## Q
**新闻聚合 · 采集与读取是两个服务**｜摘要 · 必会

文章怎么从出版商进入系统，又怎么到达用户？为什么要把缩略图复制一份？

## A
- **数据收集服务（后台）：** 每 3–6 小时（按各出版商的更新频率）轮询它们的 RSS 或接口；从数据库取出版商列表和 RSS 地址，逐个请求，提取文章内容与元数据，下载图片作为缩略图。缩略图存对象存储，文章数据（含媒体链接）存数据库。
- **RSS 是什么：** 一种简单标准的 XML 格式，出版商用它对外分发内容。靠 HTTP GET 获取，响应里有标题、链接等元数据，解析轻量，很多出版商已支持。
- **为什么不直接链接出版商的图片：** 出版商的服务器可能慢、过载甚至宕机，图片链接也会变；复制一份才能保证快速稳定，还能统一画质和尺寸。
- **动态流服务（读取）：** 客户端 → API 网关（路由、认证、限流）→ 动态流服务按用户地区查最近的文章，按发布时间排序，返回带媒体链接的结果。
- **为什么分成两个服务：** 扩缩需求不同（读多 vs 写多）、更新频率不同（实时 vs 批处理）、运维需求不同（面向用户 vs 后台）。
