## Q
**新闻聚合 · 找错：Webhook 端点的安全与重复**｜考点 · 必会

端点直接接受 JSON 就入库。哪几类问题会出现？同一篇文章可能既被 Webhook 推送又被 RSS 轮询到，怎么办？

## A
- **伪造：** 任何人都可以向端点发假文章，污染动态流。要用共享密钥签名：出版商用 HMAC 对请求体加时间戳签名，我们验证签名；或使用 API Key。
- **重放：** 攻击者截获一个合法请求反复重发。验证时间戳在几分钟之内，并记录近期见过的签名或事件 ID。
- **重复投递：** 出版商没收到我们的 200 响应会重试，同一篇文章会来多次。入库用文章的规范化 URL（或出版商 GUID）作唯一键，重复插入变成无操作（幂等）。
- **与 RSS 重叠：** 同一篇文章经两条渠道到达，也由这个唯一键去重；规范化 URL 时要去掉追踪参数（utm_*）和末尾斜杠，否则同一篇会被当成两篇。
- **端点自身：** 先快速返回 202 并把载荷入队，再异步处理；不要在请求里做下载图片之类的慢操作，否则出版商超时重试。大新闻时多家同时来，要有限流和队列缓冲。
- **信任边界：** 载荷里的内容当作不可信输入，渲染前要清洗，防止注入。
