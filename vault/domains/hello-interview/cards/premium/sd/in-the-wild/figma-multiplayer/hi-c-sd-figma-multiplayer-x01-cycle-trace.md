## Q
**Figma 多人编辑 · 三个并发移动会发生什么**｜考点 · 必会

文档树为 A、B、C 三个对象并列在根下。三个客户端同时发出：客户端 1 把 A 的父设为 B；客户端 2 把 B 的父设为 C；客户端 3 把 C 的父设为 A。服务器按 1→2→3 的顺序收到。每个客户端本地看到什么，最终文档是什么？

## A
- **服务器：** 收到 1，A 在 B 下，合法；收到 2，B 在 C 下，合法（现在 A→B→C）；收到 3，把 C 放到 A 下会形成环 C→A→B→C，服务器拒绝，C 仍在根下。
- **最终文档：** 根 → C → B → A 的一条链。
- **客户端 3：** 本地先乐观地把 C 放到 A 下，此时没有环；等它收到别人已生效的 1、2，与自己尚未确认的修改叠在一起就形成环，它先隐藏环里的对象，等服务器拒绝了第三步，再把它们放回服务器确定的位置。客户端 1、2 不会见到环。
- **要点：** 每个写入单独都合法，环只在合起来时才出现，所以必须由能看到全局状态的服务器检查；换一个到达顺序，被拒绝的会是另一个客户端。
