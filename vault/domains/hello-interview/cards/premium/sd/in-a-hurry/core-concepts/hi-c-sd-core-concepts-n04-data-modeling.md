## Q
**核心概念速览 · 数据建模：先规范化再反规范化**｜摘要 · 必会
关系型与 NoSQL 怎么选？规范化与反规范化的默认顺序是什么？NoSQL 的陷阱是什么？

## A
- **关系型（如 Postgres）：** 数据有结构和清晰关系（用户 → 订单 → 商品），需要强一致、复杂查询（SQL）、事务和外键约束时用。
- **NoSQL（DynamoDB、MongoDB）：** 模式灵活（结构经常变），或需要免联表的水平扩展时用。
- **规范化：** 拆表避免重复，订单只存用户 ID 和商品 ID；改商品名只改一处，一致性好，但读取要联接，表巨大或多表联接时代价高。
- **反规范化：** 复制数据避免联接，读更快；代价是用户改名要更新用户表加每条订单。读多写少、数据很少变的系统值得。
- **安全默认：** 从规范化的关系模型开始，发现读性能问题再反规范化热点路径；别一开始就反规范化。
- **NoSQL 的约束：** 必须按访问模式设计分区键和排序键。例：以 `user_id` 为分区键，"取某用户的所有帖子"是快速的单分区查询，而"取提到某话题标签的所有帖子"就要扫全表。查询要事先知道。
