## Q
**核心概念速览 · 扩展读的梯度与触发数字**｜拓展 · 加分
如何把"索引 → 缓存 → 副本 → 分片"变成一个可以在面试里直接讲的判断流程？

## A
- **每一级配一个触发信号：** 查询慢且全表扫描 → 加索引；数据库 CPU 高且读重复、数据变化少 → 缓存（命中率目标 80% 以上，低于它先看缓存键与 TTL 设计）；缓存命中后读仍多或要读到较新的数据 → 读副本（接受复制延迟）；数据量到几十 TB、写吞吐持续超过约 1 万 TPS 或备份窗口失控 → 才分片。
- **每一级的代价也要说：** 索引拖慢写、占空间；缓存带来失效与惊群；副本带来读到旧数据（复制延迟）；分片带来跨分片查询、一致性与重分片。
- **读己之写：** 加了副本和缓存后，用户刚写完的数据可能读不到，对关键路径可读主库或在写后短暂路由到主。
- **说法：** "先查是否有索引，其次缓存，副本再说；根据 X 的数字，目前不需要分片。"这样显示出对成本的感觉。
