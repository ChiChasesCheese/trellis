## Q
**核心概念速览 · 缓存：旁路缓存、失效与故障**｜摘要 · 必会
缓存的默认做法是什么？最难的问题是什么？缓存击穿和整个缓存宕机各怎么防？

## A
- **价值：** Redis 命中约 1 毫秒，对比数据库查询约 20-50 毫秒，快 20-50 倍，还减轻数据库负载，让它能处理更多写入、延缓过早扩展。
- **默认模式：** 约 90% 用旁路缓存（cache-aside）加 Redis：先查缓存，命中返回；未命中查库，带 TTL 写回缓存再返回。
- **最难的是失效：** 用户更新资料后要删除或更新缓存，否则读到旧数据。策略：写后立即失效；短 TTL 容忍陈旧；或两者结合，取决于数据需要多新。
- **击穿（stampede）：** 热点条目过期的瞬间，大量请求同时未命中并涌向数据库，可能压垮整个系统。对策：加锁，只让一个请求重建；过期前提前重算；TTL 加随机抖动，避免集中过期。
- **整个缓存宕机：** Redis 挂了所有请求落库。对策：进程内小缓存兜底；熔断器削减流量；优雅降级到恢复。
- **别缓存一切：** 只缓存读得频繁且不常变的数据，每次请求都变的数据缓存只增加延迟和复杂度。
- **其他层：** CDN 缓存静态资源（图片、视频、脚本）；进程内缓存放变化少的小值（功能开关、配置）；核心应用数据仍默认外部 Redis。
