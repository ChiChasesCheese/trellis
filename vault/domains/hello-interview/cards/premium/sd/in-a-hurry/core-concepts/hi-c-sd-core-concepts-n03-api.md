## Q
**核心概念速览 · API 设计：4-5 个端点就走**｜摘要 · 必会
API 设计在面试里的默认做法和时间纪律是什么？分页、认证、限流各提到什么程度？

## A
- **默认 REST：** 资源对应 URL，HTTP 方法操作资源，如 `/users/{id}`、`POST /events/{id}/bookings`。90% 的面试这样，面试官也默认。
- **时间：** 几分钟内勾勒 4-5 个核心端点就走；10 分钟了还在抠细节，说明陷得太深。
- **顺带提的几点：** 大结果集要分页，实时数据多用游标分页，其他偏移分页就够；认证用户用 JWT，服务间用 API key；可能被机器人或滥用时提一句限流。除非被问，别深入。
- **为什么仍要懂：** 马虎的 API 会暴露经验不足。
