## Q
**关键技术 · 队列的投递语义与重复消息**｜拓展 · 加分

队列里的消息会不会被处理两次？消费者该怎么写才安全？

## A
- **队列多为至少一次投递：** 多数队列是至少一次（at-least-once）投递：消费者处理完但确认（ack）丢失、或处理超过可见性超时（visibility timeout，SQS 里消息被取走后对别人隐藏的时长），消息会重新出现，被再次处理。
- **所以消费者必须幂等：** 同一条消息处理两次结果和一次相同。常见手段：用业务唯一键做去重（数据库唯一约束），或用条件更新。
- **"恰好一次"要小心：** SQS FIFO 队列有去重窗口（5 分钟）内的去重，Kafka 有事务和幂等生产者，但边界只在系统内部；碰到外部副作用（发邮件、扣款）仍要靠幂等设计。
- **重试策略：** 指数退避加上限，超过次数进死信队列，避免毒消息（一条永远处理失败的消息）卡住整个队列。
