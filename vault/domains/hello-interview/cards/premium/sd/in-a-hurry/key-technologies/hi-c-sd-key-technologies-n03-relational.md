## Q
**关键技术 · 关系型数据库要懂的三样**｜摘要 · 必会

关系型数据库在面试里要重点讲哪三个能力？它们各自的代价是什么？

## A
- **连接（join）：** 把多张表按键拼起来，例如查某用户的全部帖子。能表达任意关系，但 join 往往是性能瓶颈，所以尽量减少，必要时靠反规范化（把数据冗余存一份）避开。
- **索引（index）：** 为了让查询不必扫全表而额外维护的数据结构，常见实现是 B 树或哈希表。关系库可以建任意多个索引，也支持多列索引和专用索引（地理空间、全文）；代价是每个索引都会拖慢写入并占空间。
- **事务（transaction）：** 把多步操作打包成原子单元，要么全成功要么全失败，避免出现"属于不存在用户的帖子"这类脏数据。这是选关系库最站得住的理由。
- **常见产品：** Postgres 与 MySQL，没偏好就选 Postgres。内部原理（存储引擎、日志）不要求深讲，但理解数据如何在库内流动，有助于想出性能和扩展的招数。
