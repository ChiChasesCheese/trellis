## Q
**关键技术 · 消息队列：缓冲、解耦与反压**｜摘要 · 必会

消息队列解决什么问题？什么时候不该加？为什么说反压（backpressure）是它最大的坑？

## A
- **两个用途：** 给突发流量做缓冲，例如打车高峰涌入大量叫车请求；或把昂贵任务分给一池 worker，例如图片处理。生产者发完即忘，消费者按自己的节奏取。
- **削峰：** 每秒只能处理 200 个，瞬间来了 1000 个，剩下 800 个排队而不是丢弃。还能解耦：两端独立伸缩，下线 worker 对上游几乎无影响。
- **不该加：** 同步、延迟要求严格的路径（如 500 ms 内）。队列让请求多等一段，几乎必然破坏延迟目标。
- **要知道的特性：** 多数是 FIFO；可配置重试次数与间隔；死信队列（dead letter queue）存放反复失败的消息，便于排查；按分区键分区扩展，同键消息落同一分区。
- **反压：** 队列只是把容量不足藏起来——进 300 / 秒、处理 200 / 秒，积压永远清不完。解法是队列满时拒绝新消息或降低接收速度，并向生产者或用户返回错误。
- **产品：** Kafka、SQS（AWS 托管）。
