## Q
**关键技术 · 要不要为搜索单独引入 Elasticsearch**｜摘要 · 追问

搜索需求出现时，直接用现有数据库的全文索引，和引入独立搜索引擎，如何取舍？

## A
- **用现有数据库（如 Postgres GIN）：** 设计里少一个组件，不用同步数据，运维简单。适合数据量不大、搜索需求朴素（关键词匹配）的场景。
- **用独立搜索引擎：** 需要模糊搜索、相关性排序、大规模分片时才值得。代价是多一套系统，要考虑数据怎么从主库同步过去。
- **面试里的说法：** 先声明知道库自带全文能力，说明在什么规模、什么需求下需要升级。资深候选人要能讲出倒排索引和搜索集群的扩展方式。
