## Q
**关键技术 · 核心数据库：怎么选、怎么讲**｜摘要 · 必会

面试里核心数据库该选关系型还是 NoSQL？为什么不建议主动做一段"SQL vs NoSQL"对比？

## A
- **默认选择：** 偏产品设计（用户、订单、帖子）选关系型，如 Postgres；偏基础设施设计（高吞吐存储、日志、指标）选 NoSQL，如 DynamoDB。两类各挑一个自己熟的就行。
- **别主动对比：** 两类技术高度重叠——NoSQL 也能表达关系，关系库用对了（索引、分片、读副本）也能撑大规模，关系库还能用 JSON 列存灵活结构。所以"有关系所以必须 SQL""要扩展所以必须 NoSQL"这类断言是黄牌，暴露的是经验不足。
- **更好的开场：** 讲你选的那个库的具体特性如何解决眼前问题，例如"选 Postgres，因为 ACID 事务能保证订单和库存一起成功或一起失败"。被问到对比时，只比你真用过的几个库，并落到它们对设计的影响上。
