## Q
**实时更新 · 按场景选第一跳协议**｜考点 · 必会

下面六个场景各选什么协议并说明理由：(1) 拍卖界面实时显示当前最高价；(2) 即时聊天；(3) 对话式 AI 逐字输出；(4) 支付后等待扣款结果再跳转；(5) 视频会议；(6) 每 5 秒刷新一次的排行榜。

## A
- **(1) SSE：** 价格只需服务器推给客户端，出价走普通 HTTP POST；单向、简单、自带重连。
- **(2) WebSocket：** 高频双向。若消息量不高，"SSE 收 + POST 发"也是可辩护的，说明为什么不用更重的方案会加分。
- **(3) SSE：** 逐个 token 流式输出，单向，用 HTTP 流即可；警惕代理缓冲导致流被卡住。
- **(4) 长轮询：** 一次性等待一个异步结果，结果出来就结束，最简单；挂起时间要和各跳超时对齐。
- **(5) WebRTC：** 音视频点对点，需要信令服务器和 STUN/TURN；信令本身再用 WebSocket。
- **(6) 简单轮询：** 5 秒的延迟可以接受，不需要持久连接，最容易讲、最稳。
- **共同方法：** 先看是否能容忍延迟，再看是否需要双向，最后看是否是音视频。每个选择说出被排除的更重方案。
