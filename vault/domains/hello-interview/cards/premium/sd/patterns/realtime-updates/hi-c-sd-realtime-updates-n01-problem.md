## Q
**实时更新 · 为什么实时推送是个问题**｜摘要 · 必会

聊天、协作文档、实时看板需要几乎立刻把变化送到用户屏幕上。普通的 HTTP 请求响应模式为什么不够，难点到底在哪？

## A
- **模型的限制：** 标准 HTTP 是"客户端问、服务器答、连接结束"，服务器不能主动先说话。而协作文档里一个人敲一个字，其他人要在几百毫秒内看到。
- **硬凑的代价：** 让每个客户端每隔几毫秒轮询一次，大量请求会压垮基础设施，绝大多数请求还拿回"没有新内容"。
- **真正的难点：** 要在客户端和服务端之间建立高效的持久通道，并保证服务端知道把消息交给哪条通道。
- **为什么候选人常答不好：** 这类问题在真实公司里往往由专门团队解决一次，很多有十年经验的工程师没亲手搭过。所以需要掌握"有哪些选项、各自代价、什么场景选哪个"，而不是背实现细节。
- **典型题目：** 票务、网约车、聊天、股票交易、协作文档、运动追踪、在线拍卖、直播弹幕、在线对弈、对话式 AI、秒杀。
