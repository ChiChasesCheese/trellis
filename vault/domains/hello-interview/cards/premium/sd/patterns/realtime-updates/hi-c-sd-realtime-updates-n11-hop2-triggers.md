## Q
**实时更新 · 第二跳：更新需要一个触发**｜摘要 · 必会

更新从来源送到服务器有哪三种触发模式？推送类模式要先解决什么问题？

## A
- **三种模式：** ①通过轮询拉取；②通过一致性哈希推送；③通过发布订阅（pub/sub）推送。
- **为什么需要触发：** 系统总在产生更新（别人编辑文档、司机报告位置、朋友发消息），要把它们送到最终目的地，就需要某个东西把"产生"和"送达"连接起来。
- **推送模式的共同难题：** 长轮询、SSE、WebSocket 里，客户端都与某一台服务器保持持久连接，也只有那台服务器能往这条连接写数据。给用户 C 发消息时必须：①找出 C 连在哪台服务器；②把消息发给那台服务器；③它查出 C 对应哪条连接；④写入连接。
- **两种常用解法：** 靠哈希让每个用户固定在一台服务器上（路由），或靠发布订阅让所有服务器订阅它关心的主题（广播）。轮询拉取则回避了这个问题。
