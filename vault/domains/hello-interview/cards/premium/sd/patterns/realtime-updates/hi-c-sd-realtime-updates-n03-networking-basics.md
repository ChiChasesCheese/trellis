## Q
**实时更新 · 网络基础：三层与一次请求的代价**｜摘要 · 追问

做实时更新要懂哪些网络基础？一次普通 HTTP 请求里哪两点对选择协议最重要？

## A
- **三层够用：**
  - 网络层（第 3 层，IP）：路由和寻址，尽力而为的投递，包可能丢失、重复、乱序
  - 传输层（第 4 层）：TCP 面向连接，保证有序可靠，但建立连接要时间、维持要资源；UDP 无连接，不保证送达与顺序
  - 应用层（第 7 层）：HTTP、DNS、WebSocket、WebRTC 等，建立在 TCP（或 UDP）之上
- **一次 HTTP 请求：** DNS 解析 → TCP 三次握手 → 发请求 → 服务器处理 → 返回响应 → 四次挥手关闭。
- **关键点一：** 每一次往返都增加延迟，包括正式发数据之前建立连接的往返。
- **关键点二：** TCP 连接本身是双方都要维护的状态。不用 keep-alive 就每个请求重建一次连接。
- **推论：** 实时更新的各种方案，本质上是在回答"要不要复用连接、连接由谁保持、保持多久"。
- **面试里：** "输入网址回车发生了什么"在大厂较少单独问了，但这些基础帮助你判断每种方案的开销。
