## Q
**实时更新 · 通过哈希把用户路由到固定服务器**｜摘要 · 必会

简单取模哈希怎么做到"每个用户固定在一台服务器"？扩缩容时它为什么不行，一致性哈希怎么改进？

## A
- **简单哈希：** 一个协调服务（ZooKeeper 或 etcd）记录服务器总数 N，给服务器编号 0 到 N−1；用户 u 由编号 `u % N` 的服务器负责。
- **连接时：** 客户端随机连任意服务器 → 该服务器用协调服务里的列表算出该用户应归哪台 → 重定向 → 客户端连到正确的服务器 → 对方把连接登记到自己的连接表。也可以让客户端自己知道哈希、N 和各服务器地址，直连。
- **发消息时：** 更新服务保持与协调服务的连接，知道所有服务器地址和 N；给用户 C 发送时哈希出负责的服务器（如 2 号），把消息发过去，它查出 C 的连接并写入。
- **原理：** 一个用户永远只有一台服务器负责，所有入站连接和出站转发都找它。
- **问题：** N 变了（扩缩容），几乎所有用户的归属都变，几乎所有连接要断开重连，代价极高。
- **一致性哈希：** 服务器和用户都映射到一个哈希环上，用户连顺时针遇到的第一台服务器。增删服务器时，只有受影响区段的用户要迁移，大幅减少连接抖动。
- **要点：** 这是"状态在服务器里"的做法，所以需要协调服务和路由信息。
