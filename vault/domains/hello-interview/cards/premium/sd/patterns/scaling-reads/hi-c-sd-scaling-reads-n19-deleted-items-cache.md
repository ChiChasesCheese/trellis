## Q
**读扩展 · 追问：已删除项缓存与 CDN 失效**｜摘要 · 追问

信息流、搜索结果这类缓存没法版本化时怎么处理删除？全球 CDN 的失效怎么办？

## A
- **已删除项缓存（deleted items cache）先过滤：** 维护一份小而快的缓存，存最近被删除、隐藏或修改的条目。服务信息流时先查它，过滤掉命中的条目，同时在后台慢慢把更大的缓存结构正确失效。适合内容审核和隐私变更。
- **思路：** 立即提供"基本正确"的缓存数据，把复杂的失效放到后台。
- **CDN 更复杂：** 要清几百个边缘节点，CDN 的 API 能帮忙但传播需要时间。关键更新可用缓存头完全禁止 CDN 缓存，牺牲性能换一致；不太关键的数据在边缘用较短 TTL，应用缓存用较长 TTL。
- **按数据分级：** 用户资料容忍 5 分钟过时，场馆信息要立刻更新。按各自的一致性需求设计，不要全局套用一种策略。
