## Q
**多步流程 · 单机顺序执行及其补丁**｜摘要 · 必会

一台服务器按顺序依次调用各步骤，有哪两个根本问题？打补丁后还剩什么？

## A
- **做法：** API 服务器收到订单后按顺序扣款、预留库存、出运单、发邮件，然后响应。没有可靠性要求时这就是起点。
- **问题一，崩溃：** 扣款之后、预留库存之前宕机，重启后没有任何记忆，不知道做到哪一步。
- **问题二，回调路由：** 支付网关几分钟后通过 webhook（网关主动发起的 HTTP 回调）通知结果，多台服务器时回调可能落到另一台，它不知道对应哪个订单。
- **补丁：** 每步后把订单状态写入数据库，让任何机器都能接手；回调经发布订阅层分发给空闲服务器。
- **补丁之后仍缺：** 手写状态机；数据库只记录进度，不会主动行动，服务器挂了订单就停在那，需要自己写轮询、加锁（避免两台同时认领）、重试逻辑；还没有补偿（已提交步骤的撤销）。逻辑散落在各服务器里，成了一团乱麻。
