## Q
**大文件 · 问题所在**｜摘要 · 必会

大文件为什么要放对象存储，而让文件字节经过应用服务器又有什么问题？

## A
- **为什么用对象存储（blob storage）：** 数据库擅长带复杂查询的结构化数据，存 100MB 的二进制大对象会拖垮查询、备份和复制。S3 这类对象存储容量几乎无限、11 个 9 的耐久性、按对象计费。经验法则：超过约 10MB 又不需要用 SQL 查询的内容，放对象存储。
- **代理模式的瓶颈：** 客户端上传 2GB 视频，API 服务器接收后转发给存储；下载时存储先发给 API 服务器，再转发给客户端。小文件可以，大文件就崩。应用服务器是只增加延迟和成本的"哑管道"，云厂商已有全球基础设施、断点续传能力和巨大带宽，我们却插了个有限的中间人。
- **直传后又出现的新问题：** 25GB 上传在 99% 失败就要从头来；绕过服务器后看不到上传进度；数据库显示"待处理"，S3 可能已有完整文件，也可能没有，不查就不知道。这就变成了带最终一致性、进度追踪和状态同步的分布式系统问题。
