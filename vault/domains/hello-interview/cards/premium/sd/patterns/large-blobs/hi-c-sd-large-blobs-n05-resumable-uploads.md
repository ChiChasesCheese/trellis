## Q
**大文件 · 分块与断点续传**｜摘要 · 必会

5GB 视频上传到 99% 断线怎么办？分块上传怎么工作，要注意什么清理？

## A
- **问题：** 100Mbps 下上传 5GB 约要 7 分钟，在 99% 断开就要从头来。
- **分块 API：** S3 用分段上传（multipart upload），每个 5MB 以上的分块有自己的预签名 URL；Google Cloud Storage 和 Azure 用单一会话 URL，向同一端点按范围头上传分块。都支持从失败的块恢复，只需重传失败的部分。
- **续传过程：** 客户端上传各块并记录存储服务返回的校验和（只是已传数据的哈希，计算和验证都便宜）。传了 100 块中的 60 块后断线，客户端查询存储 API 看哪些块已成功，从第 61 块继续。存储服务用会话标识保存状态（S3 的 upload ID，GCS 的可续传 URL）。
- **进度条：** 每块完成就知道百分比，客户端做简单计算即可。
- **收尾：** 所有块传完，客户端必须调用完成接口并给出块号与校验和列表，存储服务才把它们组装成最终对象。完成前只有分块，没有可访问的文件。完成后，分块不再存在，如同一次性上传。
- **清理：** 未完成的分段上传会产生费用，用生命周期规则在 24 到 48 小时后清理。
- **2026 亮点：** 整体完整性用 S3 的 CRC 校验和（优先全对象的 CRC64NVME），不要拿 ETag 当整体 MD5：分块上传对象的 ETag 不是整个对象的 MD5，而全对象 CRC 能由各分块线性组合，分块仍可并行上传，完成后对照存入元数据的校验和核对。新版 SDK 默认随上传发送 CRC，代价是客户端多一次计算。
