## Q
**长任务 · 重复提交**｜考点 · 必会

用户连点三次生成报告。你的幂等键怎么设计，有什么坑？

## A
- **键的构成：** 用户发起的操作用用户 ID + 动作 + 取整的时间窗口（决定多长时间内视作同一个请求）；系统生成的任务用输入数据的确定性哈希。
- **流程：** 提交时先按键查，已有就返回旧任务 ID。
- **坑一：** 先查再建不是原子的，两个并发请求可能都没查到而各建一个；要用数据库唯一约束让第二个失败，再读出已有任务。
- **坑二：** 时间窗口取整太宽会把真正想要的新请求当作重复。
- **还要：** 工作本身幂等，因为任务仍可能因重试被重复执行。
