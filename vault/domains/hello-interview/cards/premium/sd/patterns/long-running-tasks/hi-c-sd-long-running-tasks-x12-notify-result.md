## Q
**长任务 · 用户怎么知道任务完成**｜考点 · 必会

任务异步完成后，客户端怎么拿到结果？轮询、WebSocket、邮件怎么选？

## A
- **轮询状态接口：** 最简单，无状态服务器就能支撑；缺点是延迟和空查询的负载，可用退避间隔。
- **WebSocket 或 SSE 推送：** 用户还停在界面时实时更新，需要保持长连接，扩展更复杂。
- **邮件或推送通知：** 用户可以关掉浏览器离开，适合耗时很长的任务。
- **选择：** 几秒到几十秒的用轮询或推送，数小时的用邮件和推送；结果文件放对象存储，状态里带链接。
