## Q
**长任务 · 代价与新的失败模式**｜摘要 · 必会

异步工作者池带来哪些成本，又会引入哪些新问题？

## A
- **系统复杂度：** 多了队列、工作者、任务状态跟踪，活动部件更多，更多东西会坏。
- **最终一致：** API 返回时工作还没完成，用户在后台处理完成前可能看到旧数据。
- **任务状态追踪：** 需要存任务状态、处理重试、暴露状态查询接口，增加数据库负载和 API 复杂度。
- **监控负担：** 队列深度、工作者健康、任务失败率、处理延迟，从简单的请求响应变成监控一个分布式系统。
- **新的失败模式：** 队列满了怎么办？反复让工作者崩溃的毒消息（poison message）怎么处理？何时放弃重试？这些都能解决，但需要同步系统不需要的规划。
