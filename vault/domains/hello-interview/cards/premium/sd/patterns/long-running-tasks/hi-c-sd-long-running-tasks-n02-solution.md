## Q
**长任务 · 解法：接受与处理解耦**｜摘要 · 必会

长任务模式的核心思路是什么？为什么让各部分能独立扩展？

## A
- **做法：** 把操作拆成两段。点击"生成报告"时，立刻把请求存入队列并返回"正在生成，好了通知你"，只花毫秒。Web 服务器只负责校验请求、入队、返回任务 ID，真正的工作在别处完成。
- **核心：** 解耦请求接受与请求处理。Web 服务器变成轻量路由，另一池工作者（worker pool）从共享队列拉任务、按自己的节奏处理、完成后更新状态。"异步"指原始 HTTP 请求立即结束。
- **队列的作用：** 缓冲区，持久地存任务，工作者崩溃也不丢；也能看到排队数量、耗时、失败情况。常见选择：Redis（Bull / BullMQ）、AWS SQS、RabbitMQ，规模更高用 Kafka。
- **独立扩展：** Web 服务器不必因为部分请求要处理视频而配 GPU，可跑在便宜小实例上，视频工作者用 GPU 机器；月底报告积压时只加工作者。
- **体验：** 用户可以看排队位置或进度，完成后通过邮件、推送或 WebSocket 通知，可以关掉浏览器离开。
