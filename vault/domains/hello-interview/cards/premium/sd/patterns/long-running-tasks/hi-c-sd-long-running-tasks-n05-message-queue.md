## Q
**长任务 · 消息队列怎么选**｜摘要 · 必会

实现需要哪两样基础设施？Redis、SQS、RabbitMQ、Kafka 各自适合什么情况？

## A
- **两样东西：** 消息队列（解耦发送方和接收方，让它们独立运行）和工作者池（专门处理队列消息、更新任务状态的进程）。
- **队列的要求：** 必须持久，崩溃不能丢全部待处理任务；必须能被多个工作者并发访问而不重复分发。
- **Redis + Bull / BullMQ：** 多数创业公司的首选。Redis 提供存储，Bull 补上自动重试、延迟任务、优先级。简单，多数场景够用。但以内存为主，硬崩溃可能丢任务，要真正耐久用 SQS 或 RabbitMQ。
- **AWS SQS：** 零运维，亚马逊管理基础设施和扩容，按消息计费，低量时划算，规模大时会贵。消息上限 1MB，所以通常只在队列里传 ID，数据存别处。
- **RabbitMQ：** 路由模式复杂时更可控，久经企业环境考验，但要自己托管，运维负担真实存在（集群、升级、磁盘监控）。
- **Kafka：** 技术栈已有事件流时首选。追加式日志可重放、可扇出给多个消费者、能长期保留，量大且分区内严格有序。
