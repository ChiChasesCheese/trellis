## Q
**处理竞争 · 不必要的 Redis 锁**｜考点 · 必会

面试官让你设计会议室预订。你准备直接用 Redis 分布式锁防止重复预订，这样答有什么不足？

## A
- **不足：** 引入新组件和新故障模式，TTL 锁在持有者停顿时还可能同时授予两人。数据本来就在数据库里，一次 DB 事务就能解决。
- **更好的做法：** 房间和时间段各占一行，对时间段行做条件写（`status='free'` 才改成已订），或悲观锁 / 乐观并发，一个数据库搞定。
- **什么时候才用分布式锁：** 独占要跨过多步或外部调用，比如先临时保留再等用户确认。
- **要点：** 先留在一个数据库里，用最简单够用的工具，以后可以再收紧。
