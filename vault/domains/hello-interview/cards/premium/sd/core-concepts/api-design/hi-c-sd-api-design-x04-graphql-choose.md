## Q
**API 设计 · 该不该用 GraphQL**｜考点 · 必会
面试官说："我们的 App 有手机端、电视端和合作伙伴的数据看板，每个要的字段都不一样，前端团队总在等后端加字段。"你怎么回应？并说出你为此付出的代价。

## A
- **回应：** 这是多取/少取与前端迭代速度的典型信号，提出 GraphQL：单入口，客户端按需声明字段，加字段只要模式里已有就不需后端发版。
- **要主动讲的代价：** 解析层复杂，N+1 需 DataLoader 批处理；字段级授权；缓存难（请求都是 POST 到同一 URL，不能直接用 HTTP 缓存）；还要防"超大查询"拖垮后端。
- **折中说法：** 对外或客户端多样的聚合层用 GraphQL，下面的服务仍可 REST 或 gRPC。
- **别做的事：** 不是因为"流行"就默认选它；没有明确的多取/少取问题时 REST 更简单。
