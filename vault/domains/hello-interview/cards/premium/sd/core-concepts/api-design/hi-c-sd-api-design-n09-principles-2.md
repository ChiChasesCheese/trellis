## Q
**API 设计 · 设计原则（下）**｜摘要 · 必会
另外四条原则（分页、默认安全、可演进、可操作的错误）具体要求什么？

## A
- **6 一切会增长的集合都要分页：** 开发时 50 行没事，线上 500 万行会拖垮服务；从第一天就分页，并给页大小设上限，防止 `?limit=100000`。
- **7 默认安全：** 认证默认开启、公开才需显式标注；授权要落到具体资源（用户只能取消自己的订单）；限流兜底。
- **8 演进不破坏旧客户端：** 旧版手机 App 能存活好几年。新增字段安全，重命名、删除、改变字段含义都是破坏性变更，需要版本策略。
- **9 错误要可操作：** 用对状态码类别（4xx 是你错、5xx 是我们错），加上机器可读的错误码和给人看的消息，让客户端知道出了什么事、下一步做什么。
