## Q
**API 设计 · 幂等键的边界**｜考点 · 追问
你给订座接口加了幂等键。两个问题：同一个 key 却带着不同的请求体到达怎么办？两个带同一 key 的请求几乎同时到达怎么办？

## A
- **同 key 不同体：** 是客户端 bug（复用了 key），不能返回旧结果假装成功。通常存请求体的指纹，不匹配就返回 4xx 错误（常见做法是 422）。
- **并发的同 key：** 如果只是"先查后存"，两个请求都查不到而都执行，重复扣款。必须原子地"占位"：用数据库唯一约束（key 作主键）或 Redis `SET NX`；先占位成功的执行，后来者要么等待、要么得到"处理中"的冲突响应。
- **结果要和副作用同事务记录：** 若扣款成功但存结果前崩溃，重试会再扣一次。
- **key 的保留期：** 过期后重放就会当作新操作，所以保留时间要大于客户端的最长重试窗口。
- **2026 亮点：** 返回码有行业草案可对照（Idempotency-Key 请求头草案，尚未成为 RFC，别说成标准）：缺少 key 返回 400，同 key 不同参数返回 422，处理中的并发重试返回 409。另外要想清楚失败的处理：回放首次的 500 会让重试在保留期内一直失败，更好的做法是成功的跳过、失败的接着做完。
