## Q
**API 设计 · 角色权限与限流**｜摘要 · 追问
角色访问控制（RBAC）怎么表达？限流在 API 层有哪几种维度，状态码是什么？

## A
- **RBAC：** 给用户分配角色，再给角色分配权限。例：顾客能订票、看自己的订单；场馆经理能建活动、看自己场馆的销量；管理员全部可以。检查顺序：先认证（令牌有效？），再授权（订单是他的，或他是管理员？）。面试里至多说一下哪些端点归哪些角色。
- **限流维度：** 按用户（每小时 1000 次）、按 IP（未登录请求每小时 100 次）、按端点（订票接口每分钟 10 次，防黄牛）。
- **位置与响应：** 通常在 API 网关或中间件实现，超限返回 429 Too Many Requests。
- **面试策略：** 说"会做限流防滥用"即可，除非被问，不展开算法。
