## Q
**API 设计 · GraphQL 的防护：深度、成本与持久化查询**｜拓展 · 加分
GraphQL 对外开放时，一个恶意或写错的查询会怎样拖垮后端？有哪些常用防护？

## A
- **问题：** 客户端控制查询形状，可以写深层嵌套的循环关系（活动 → 场馆 → 活动 → …）或一次请求大量列表，一条查询就放大成海量数据库访问。REST 的每个端点成本是服务端预先固定的。
- **深度和复杂度限制：** 在执行前静态计算查询深度或"成本分"，超过上限就拒绝。
- **分页必须有上限：** 列表字段强制 `first`/`limit` 并设最大值。
- **持久化查询（persisted queries）：** 客户端只发查询的哈希，服务端只执行预先登记的查询。既防任意查询，也省带宽，并让 GET + CDN 缓存成为可能。
- **限流要按成本而不是按请求数：** 一个请求的开销差别可达几个数量级。
