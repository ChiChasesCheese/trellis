## Q
**API 设计 · 幂等键**｜摘要 · 必会
用户下单后请求超时，客户端重试，怎么避免重复扣款？幂等键怎么工作？

## A
- **问题：** POST 不幂等，而"别重试"不是答案，网络本来就会失败。若第一次其实成功了，重试就会再订一次、再扣一次钱。
- **做法：** 客户端为每个"逻辑操作"生成唯一 ID，放在请求头 `Idempotency-Key` 里。服务器把这个 key 和第一次的处理结果一起存起来；带着同一个 key 的重试到达时，直接返回已存的响应，不再执行。同 key，同结果，不重复扣款。
- **2026 亮点：** 失败怎么处理要想清楚：把首次结果（包括 500）在保留期内一直回放（Stripe API v1 即如此），客户用同一个 key 重试一直拿到旧错误；更好的做法是记录处理进度，成功的直接跳过，失败或部分失败的接着做完（Stripe API v2 即如此，POST 和 DELETE 都可以带键）。key 的保留期写进接口文档（常见 24 小时到 30 天）。取舍：续做式要求每一步本身可续做，实现更复杂。
- **现实参照：** 支付接口的重试就是这样处理的。
- **面试信号：** 只要设计里有支付、预订、下单，主动提这一点，说明你想的是失败路径而不只是顺利路径。
