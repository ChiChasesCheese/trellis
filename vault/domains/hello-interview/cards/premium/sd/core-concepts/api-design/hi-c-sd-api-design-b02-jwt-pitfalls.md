## Q
**API 设计 · JWT 的实际坑**｜拓展 · 加分
说 JWT "无状态、不用查库"是真的吗？上线时有哪些常见安全坑？

## A
- **无状态的代价是撤销困难：** 令牌在过期前一直有效。常见做法是短寿命访问令牌（如几分钟）加长寿命刷新令牌，刷新那一步需要查库，所以可以在这里封号或吊销。
- **签名不是加密：** 载荷只是 base64 编码，任何人都能读，不要放敏感数据。
- **验证要钉死算法：** 服务端必须固定接受的签名算法并检查过期时间、签发者、受众；历史上有库因为信任令牌头里的 `alg` 而被伪造（例如 `alg: none`）。
- **存放位置：** 放在可被 JavaScript 读取的存储里有被 XSS 窃取的风险，放在 Cookie 里则要考虑 CSRF，要用 `HttpOnly`、`SameSite` 等属性。
- **密钥轮换：** 用 `kid` 标识密钥，网关从公钥集（JWKS）取验证密钥，便于轮换。
