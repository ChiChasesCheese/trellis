## Q
**数据库索引 · 哈希索引**｜摘要 · 必会
哈希索引是什么？为什么在磁盘数据库里很少用？什么时候才合适？

## A
- **是什么：** 一个持久化的哈希表：一组桶，把被索引的值哈希后决定放进哪个桶，桶里存指向行位置的指针。精确匹配的查找平均 O(1)。碰撞靠一个桶放多个条目、必要时链接溢出页处理（PostgreSQL 的哈希索引用溢出页链）。
- **限制：** 相近的值被故意打散到不同桶，所以**不能范围查询，也不能排序**。
- **很少用的原因：** B 树做精确匹配几乎一样快，还支持范围和排序；PostgreSQL 支持哈希索引但不默认使用。数据库专家有句话："哈希索引解决的是我们很少遇到的问题。"
- **适合：** 全在内存的场景，如 Redis 用哈希表做键值查找；MySQL 的 MEMORY 引擎默认用哈希索引。
- **面试里：** 只有当你需要最快的精确匹配、永远不需要范围或排序、内存充足时才考虑。别强调过度，会显得脱离实际。
