## Q
**缓存 · 缓存回填的竞态与租约**｜拓展 · 加分
cache-aside 读路径本身有什么竞态？大规模缓存怎么用租约（lease）解决？

## A
- **竞态：** 读者 B 未命中，从库里取到值 v1；此时写者 A 更新库为 v2 并删除缓存；B 随后把 v1 写入缓存。缓存里留下旧值，而且没有更晚的写来修正它，直到 TTL 过期。
- **租约：** 缓存在未命中时给读者发一个令牌（租约）；写者删除键时令牌作废。读者回填时带上令牌，缓存发现令牌失效就拒绝写入，旧值就进不来。同样的机制也能限制同一个键的回填速率，防止惊群。大规模 memcache 部署用的就是这种做法。
- **用 TTL 做兜底：** 没有租约机制时（如 Redis 用 cache-aside），靠较短的 TTL 限制陈旧时长；强一致场景改为读主库。
- **面试说法：** "写后删缓存 + TTL 兜底"，并知道这个竞态存在。
