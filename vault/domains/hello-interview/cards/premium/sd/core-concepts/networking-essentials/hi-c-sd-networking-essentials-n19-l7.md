## Q
**网络基础 · L7 负载均衡与健康检查**｜摘要 · 必会

L7 负载均衡器和 L4 的本质区别是什么？健康检查怎么做？

## A
- **L7 工作方式：** 在应用层理解 HTTP 等协议，查看每个请求的内容，做更智能的路由。它接收应用层请求（如 HTTP GET）并转发给合适的后端；终止进来的连接，再向后端建立新的连接。
- **特征：** 可按 URL、头部、Cookie 路由；更耗 CPU（要检查内容）；功能更灵活；更适合 HTTP 流量。
- **例子：** 把所有 API 请求发给一组服务器，网页请求发给另一组（类似 API 网关的功能），或基于 Cookie 保证同一用户的请求落在同一台服务器。
- **注意：** L7 让你不必关心 TCP 连接等底层细节，但如果需要持久连接落到固定服务器，就不能忽略连接层面的现实。
- **适用：** 基于 HTTP 的流量，覆盖前述除 WebSocket 外的所有协议；个别 L7 均衡器明确支持 WebSocket，但一般 L4 更适合 WebSocket，L7 对长轮询之类的 HTTP 方案更灵活。
- **健康检查（health check）：** 均衡器要监控后端是否健康，服务器断电或崩溃就停止向它转发流量，直到恢复，这是高可用的基础。检查间隔和协议可配置。TCP 检查简单高效，只看服务器能否接受新连接；L7 检查发一个 HTTP 请求并确认响应成功（如 200，而不是表示内部故障的 500，或崩溃时无响应）。
