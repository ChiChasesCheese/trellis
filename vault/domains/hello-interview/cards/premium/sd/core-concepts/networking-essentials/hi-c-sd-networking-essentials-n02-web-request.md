## Q
**网络基础 · 一次网页请求的全过程**｜摘要 · 必会

在浏览器里打开一个网址，底下发生了什么？从中能得出哪三点对系统设计有用的观察？

## A
- **步骤：** 先用 DNS 把域名解析成 IP；TCP 三次握手（客户端发 SYN，服务器回 SYN-ACK，客户端发 ACK）建立连接；发 HTTP GET；服务器处理（多数工程师唯一关心和能控制的延迟）；返回 HTTP 响应；四次挥手（FIN、ACK、FIN、ACK）关闭连接。
- **面试里的地位：** "输入网址回车后发生了什么"曾是热门面试题，现在大厂少见；握手细节通常不会考，但基础概念有助于工作。
- **观察一，简化心智模型：** 应用可以默认数据被可靠有序地传输，TCP 保证送达且有序，没送到会通知应用；DNS 找到 IP，网络硬件负责路由，不用关心物理细节。
- **观察二，延迟藏在底层：** 一个概念上的请求和响应背后有很多来回的包，每次都有延迟，平时可忽略，到了某个规模就不能忽略；协议栈越往上，延迟和处理越多，这直接关系到后面 L4 和 L7 负载均衡的取舍。
- **观察三，连接是双方都要维护的状态：** 除非用 HTTP keep-alive 或 HTTP/2 多路复用，否则每个请求都要重复建立连接，开销可观；设计需要长连接的系统（实时更新）时尤其重要。
