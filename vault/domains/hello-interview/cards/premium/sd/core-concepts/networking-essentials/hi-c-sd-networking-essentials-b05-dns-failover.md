## Q
**网络基础 · DNS 轮转作为高可用的局限**｜拓展 · 加分

用 DNS 在两台负载均衡器之间轮转，故障切换真的"自动"吗？

## A
- **TTL 下限：** 解析结果被各级缓存（客户端、系统、运营商的递归解析器），条目的 TTL 到期前不会重新查询；把 TTL 设成 30 秒也无法保证所有客户端在 30 秒内切换，个别解析器和应用会忽略 TTL 或缓存更久。
- **DNS 本身不探测健康：** 普通轮转会继续把客户端指向已经挂掉的地址；一部分客户端会自动尝试列表里的下一个地址，但超时可能很长。要自动摘除故障地址，需要带健康检查的 DNS 服务（如云厂商的健康检查路由）。
- **2026 亮点：** DNS 自动化本身也是单点：区域端点的记录被自动化写成空记录时，整个区域的依赖会同时解析失败，客户端缓存还会拉长故障；关键依赖要有跨区域的备用端点，或本地保留上一次良好解析。
- **更快的切换：** 用任播（anycast）或浮动 IP：同一个 IP 由多个地点宣告，一处故障后路由收敛到其他地点，不依赖 DNS 缓存过期。
- **取舍：** DNS 轮转简单、跨区域，但切换慢；任播和浮动 IP 切换快，但需要网络层支持。
- **面试说法：** 说"DNS 轮转加健康检查，TTL 设短，并知道它切换不是瞬时的"，比说"DNS 自动故障转移"准确。
