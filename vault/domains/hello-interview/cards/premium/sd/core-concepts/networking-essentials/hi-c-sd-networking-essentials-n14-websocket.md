## Q
**网络基础 · WebSocket**｜摘要 · 必会

WebSocket 解决什么问题？怎么建立连接？为什么不能随便上？

## A
- **是什么：** 在客户端和服务器之间提供持久的、类似 TCP 的连接，支持实时双向通信且被广泛支持（包括浏览器）。服务器不用等请求就能推数据，客户端也能随时往回推。
- **怎么建立：** 通过 HTTP 的升级机制（upgrade）发起握手（背后是 TCP 连接），然后升级为 WebSocket 协议，接管这条 TCP 连接，双方可以互发二进制消息，连接一直开着直到被显式关闭。升级让现有 HTTP 会话信息（cookie、头部）可以复用，很方便。
- **不规定应用协议：** 你得自己定义交换什么，常用序列化的 JSON 消息，这也是定义服务 API 的机会。
- **基础设施要全程支持：** 客户端能升级不等于中间设施支持，防火墙、代理、负载均衡器常不支持 WebSocket。
- **适用：** 高频、持久、双向的通信，如实时应用和游戏。只需请求响应，或 SSE 的推送就够用的时候，WebSocket 是过度设计。
- **面试陷阱：** 没有理由就上 WebSocket 会被面试官扣分。基础设施昂贵，有状态连接（尤其是大规模时）需要在设计里大幅迁就，没有必要就先别用。
