## Q
**网络基础 · SSE（服务器推送事件）**｜摘要 · 必会

SSE 怎么实现服务器推送？它有哪些局限？

## A
- **背景：** 请求响应模型不适合推送。gRPC 虽支持流式，但对外部 API 支持有限（浏览器不能直接发起 gRPC 调用，需要 gRPC-Web 代理转换）。
- **机制：** SSE 是 HTTP 之上的规范，允许服务器在单个 HTTP 连接的同一个响应里推送许多条消息，是 HTTP 上的一个"好用的 hack"。普通 HTTP 要整块 JSON 收完才处理；SSE 把消息分块（每行 `data: {...}`）陆续推送，客户端把每一行当作一条独立消息即时处理。仍是同一个 TCP 连接上的一个大响应。
- **局限一，连接不能长久：** 服务器、负载均衡器或中间代理会关闭连接。所以标准定义了 `EventSource`：连接关闭后自动重连，并带上最后收到的消息 ID；服务器要记住客户端断线期间可能错过的消息并重发。
- **局限二，行为异常的网络：** 有些网络会把所有 SSE 响应攒成一个响应，行为就和想避免的普通响应一样。
- **面试分寸：** 多数面试官不熟悉这些局限，会让你假设它们不存在，但真做过 SSE 的人会有深刻印象，会试探你是否真的用过。
- **适用：** 客户端要在事件发生时立刻收到通知，如拍卖中让竞拍者实时看到当前价格。
