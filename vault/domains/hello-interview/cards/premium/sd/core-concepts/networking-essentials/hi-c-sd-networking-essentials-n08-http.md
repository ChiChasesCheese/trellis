## Q
**网络基础 · HTTP 与 HTTPS**｜摘要 · 必会

HTTP 的基本模型是什么？为什么说无状态是好事？HTTPS 保护什么、不保护什么？

## A
- **应用层的位置：** 应用层多在用户空间（user space）处理，下层在内核空间（kernel space）。应用层更灵活、易修改，下层难改但高效。
- **HTTP：** 事实标准的 Web 数据通信协议，请求-响应：客户端发请求，服务器回数据。**无状态**：每个请求独立，服务器无需记住之前的请求。设计里要尽量缩小需要有状态的部分，多数简单 HTTP 服务器可以描述为请求参数的函数。
- **四个概念：** 请求方法、状态码、头部（关于请求或响应的元数据，灵活的键值对）、正文。方法和状态码是标准化的，像枚举；除非用 RESTful API，面试官很少深究。
- **内容协商**（content negotiation）：客户端用 `Accept-Encoding` 声明能处理哪些编码，服务器用 `Content-Encoding` 返回最合适的（如 gzip、brotli），兼顾向后兼容和优雅降级。这是设计灵活接口的好例子。
- **HTTPS：** 在 HTTP 上加 TLS/SSL 加密，防窃听和中间人攻击；公网网站无一例外使用。
- **2026 亮点：** 主流浏览器和库（Chrome、Safari、OpenSSL 3.5+、Go 等）的 TLS 1.3 现在默认带后量子混合密钥交换（X25519+ML-KEM-768），防的是「先录下密文、以后用量子计算机解」；代价是握手的 key share 从 32 字节涨到约 1.2KB，对接老旧中间设备或外部专线前要验证兼容性。
- **但加密不等于可信：** 内容加密不保证请求由你的客户端生成。永远不要不加验证地信任请求正文。常见错误：把用户 ID 放在请求体里直接查数据库，攻击者改了 ID 就能读任意用户数据。可以带 ID，但服务器必须能验证它；API 不该索要无法信任的东西。
