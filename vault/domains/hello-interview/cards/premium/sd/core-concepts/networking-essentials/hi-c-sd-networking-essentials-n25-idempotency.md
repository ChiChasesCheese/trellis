## Q
**网络基础 · 幂等与幂等键**｜摘要 · 必会

重试为什么需要幂等？写操作怎么做到幂等？

## A
- **问题：** 重试遇到副作用就麻烦。支付系统里重试同一个扣 10 美元的请求，可能扣到 20 美元甚至 2000 美元。
- **幂等（idempotent）接口：** 调用多次，结果与调用一次相同。HTTP GET 是典型：返回内容可能变，但获取这个动作不改变系统状态。
- **写操作：** 引入幂等键（idempotency key），一个请求的唯一标识。比如一个用户一天只会买一次，可以把用户 ID 加当前日期作为键。服务器检查是否已经处理（或正在处理）带这个键的请求，只处理一次。
- **两种风格：** 友好的 API 等请求完成后把结果发给所有请求者；不友好的直接返回"请求已存在"的错误。两者都能避免重复扣款。
