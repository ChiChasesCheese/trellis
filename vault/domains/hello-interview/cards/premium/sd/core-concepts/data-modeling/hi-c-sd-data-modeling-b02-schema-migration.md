## Q
**数据建模 · 模式演进与在线迁移**｜拓展 · 加分
线上表有几亿行，要加一列或改类型，为什么不能直接 `ALTER TABLE`？常见的安全做法是什么？

## A
- **风险：** 一些变更会重写整张表或长时间持有锁，阻塞读写。具体因数据库和版本而异（例如 PostgreSQL 里添加带常量默认值的列在较新版本是元数据操作，而更改列类型多数会重写表）。
- **扩展-收缩六步：** 扩展-收缩模式（expand and contract）：先加新列（可空）→ 应用双写新旧列 → 后台分批回填历史数据 → 切换读取到新列 → 停止写旧列 → 最后删除旧列。每一步都能回滚，新旧版本代码可共存。
- **工具：** 在线模式变更工具（如 MySQL 生态的 gh-ost、pt-online-schema-change）以影子表加触发或日志复制完成。
- **反范式的代价会再现：** 重复存的数据在迁移时要全部改，这是"默认范式化"的又一个理由。
