## Q
**数据建模 · 文档数据库**｜摘要 · 必会
文档数据库解决什么问题？建模上有什么变化？为什么面试里很少是正解？

## A
- **是什么：** 数据存成类似 JSON 的文档，模式灵活。建模重点从"拆表范式化"变成"把相关数据嵌套进同一个文档"，例如把帖子直接放进用户文档，省掉联接；代价是改一条帖子就得定位并改写整个用户文档。
- **何时优于 SQL：** 模式经常变、数据深度嵌套（SQL 要很多联接）、不同记录结构差别很大。例如用户档案里有人有长长的工作经历，有人几乎没有。
- **面试里为什么少用：** 面试会把功能需求限定得很简洁，几乎没有"模式不断演化"，这就拿掉了选它的主要理由。除非面试官明说数据结构变化很快，否则别选。
- **对建模的影响：** 更激进地反范式，用存储空间和更新复杂度换读性能。例：MongoDB、Firestore、CouchDB。
