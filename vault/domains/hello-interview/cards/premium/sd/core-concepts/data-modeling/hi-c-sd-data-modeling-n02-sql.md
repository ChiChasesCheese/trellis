## Q
**数据建模 · 关系型数据库（默认选择）**｜摘要 · 必会
面试里数据库默认选什么？关系型数据库适合什么，常被质疑的"不能扩展"对不对？

## A
- **默认关系型，推荐 PostgreSQL：** 表有固定模式，行是实体、列是属性，用外键表达关系，并提供 ACID 事务。除非需求明确指向特殊模型，否则别为了显得高级去选冷门数据库。
- **天然匹配：** 社交（用户、帖子、评论、点赞）、电商（用户、商品、订单、支付）这类实体关系清晰的业务。
- **强项：** 复杂查询（如"我关注的人的帖子，按时间倒序"用联接就能表达）；需要强一致时，如支付不能重复扣款、库存不能超卖，ACID 正好对口。
- **陷阱：** 多表联接在大规模下容易成为性能陷阱，报表式的复杂查询会让面试官警觉。要想清楚是否够快，否则用反范式视图、缓存或预计算。
- **关于扩展：** "关系型库不能扩展"被夸大了。读副本、分片、连接池、缓存都能撑大规模，大公司的核心数据也建在关系型之上，扩展靠整体架构而不只是选哪个库。例：PostgreSQL、MySQL、SQLite。
