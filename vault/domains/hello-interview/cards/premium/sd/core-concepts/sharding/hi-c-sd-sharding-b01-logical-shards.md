## Q
**分片 · 逻辑分片与物理节点**｜拓展 · 加分
为什么生产系统常常"一开始就切成很多小分片，再让多个小分片住在一台机器上"？

## A
- **问题：** 若分片数 = 机器数，扩容就要改变取模的除数，几乎全量搬迁。
- **做法：** 先把键哈希到固定数量的**逻辑分片**（如 1024 个，这个数基本不变），再用一张小映射表把逻辑分片分配给物理节点。扩容时只是把若干整分片搬到新机器，搬的是现成的单元，不需要重新哈希每条记录。
- **好处：** 搬迁以分片为单位，可以逐个迁移、可回滚；热分片可单独迁出；与一致性哈希的虚拟节点是同一思路。
- **代价：** 分片总数上限就是并行度上限，数据超出预估时只能再拆分逻辑分片，所以初始就要留足余量；映射表又变成一个需要高可用的小目录。
- **例子：** Redis Cluster 把键空间固定为 16384 个槽（slot），再把槽分给节点。
