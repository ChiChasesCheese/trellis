## Q
**邻近搜索 · 密度不均与热点格子**｜拓展 · 加分

按格子 ID 对司机数据分片时，会遇到什么问题？

## A
- **密度差异：** 格子是固定大小，曼哈顿一个格子里有几千司机，沙漠里是零。按格子 ID 分片，市中心的分片成为热点：写入和查询都集中在少数分片。
- **规模感：** 100 万司机每 4 秒更新一次是每秒 25 万次写入，如果 30% 来自几个核心城区格子，这几个分片扛着约 7.5 万次每秒。
- **缓解一：** 用更高的分辨率（更小的格子）存储，同时使用格子 ID 的哈希来分片，把相邻格子打散到不同节点；代价是查一圈邻格时要访问更多分片。
- **缓解二：** 自适应分辨率：密集区用小格子、稀疏区用大格子，思路类似四叉树的自适应，S2 的多层级格子天然支持。
- **缓解三：** 对热点城区单独做副本或独立部署。
- **取舍：** 按区域分片查询局部性好但热点明显；哈希分片均衡但邻域查询要扇出。
