## Q
**DynamoDB · 查询与扫描、投影不省容量**｜摘要 · 必会

读取 DynamoDB 数据有哪两种基本操作？为什么只取几个属性并不能省钱？

## A
- **Query：** 按主键或索引键读取匹配的项，只读符合键条件的部分，可在排序键上做范围查询，高效。
- **Scan：** 读表或索引里的每一个项，分页返回；大表上低效又贵，能避免就避免，靠合理的分区键和排序键设计来消灭扫描。
- **接口：** 主要通过 SDK 或控制台；也支持类 SQL 的 PartiQL，但最终翻译为同样的底层操作，只是方便写法。
- **投影的真相：** `ProjectionExpression` 只减少网络传输；整个项仍从存储读出，容量费用仍按整项大小收，与 SQL 只读几列不同。
- **建模启示：** 项里有大字段时拆表，例如点评系统把评论放进单独的表，按商家 ID 查询，不让读商家基本信息时拖上全部评论。
