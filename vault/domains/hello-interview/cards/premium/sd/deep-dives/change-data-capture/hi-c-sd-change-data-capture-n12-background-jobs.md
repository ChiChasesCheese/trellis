## Q
**变更数据捕获 · 用 CDC 触发清理或延时任务**｜摘要 · 必会

删除账号后要清理对象存储、吊销 API key。监听 users 表的 DELETE 来触发，有什么问题？延时任务呢？

## A
- **同样的问题：** DELETE 只说明一行消失了，不说明该跑哪个清理任务。
- **更大的问题：** Kafka 能可靠投递 CDC 记录，消费者也可以重试，但一旦消费者还要管任务状态、退避、失败处理和延迟执行，你其实在隐式行变更之上造了一套作业系统。
- **延时更明显：** 预约创建 30 分钟后过期要释放库存。CDC 只告诉你插入了一条预约，消费者还得把定时器持久化、崩溃后恢复、保证最终会执行。Kafka 不改变这一点，定时器及其恢复还是得自己放在某处。
- **正确做法：** 应用已知要做什么，就直接表示出这项工作：立即的后台任务入持久队列；长时间、延迟或多步骤的用持久工作流引擎，如 Temporal。
