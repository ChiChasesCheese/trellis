## Q
**大数据结构 · 近似分位数适用场景与坑**｜摘要 · 必会

监控、SLO、自动扩缩容怎么用直方图？设计桶时最容易犯什么错？

## A
- **适用：** 要看分位数、内存有界、能容忍近似、需要实时流式分析。
- **监控：** APM 看响应时间分位数，基础设施看 CPU/内存分布，数据库看查询耗时分位数。Prometheus 的直方图指标本质就是桶，可跨机器聚合出分位数，不用集中存原始数据。
- **SLO：** 如「99% 请求在 100ms 内」：从直方图算出 p99，与 100ms 比较，通过或不通过。
- **其他：** A/B 测试看会话时长分布；自动扩缩容基于 p95 CPU，按响应时间分布路由，分位数突然移动时报警。
- **三个坑：** 桶边界选得不合理；没处理超出预期范围的数据；极端分位数（极高或极低）精度更差。例如 `[0–1s, 1–10s, 10s+]` 这样的桶，大多数请求在 100ms 内，就完全看不出差别，应改用对数或指数间距。
