## Q
**大数据结构 · Count-Min Sketch 的直觉**｜摘要 · 必会

布隆过滤器只能判断有没有，要估计「出现了多少次」该怎么扩展？为什么孔数太少或太多都没用？

## A
- **思路：** 把布隆过滤器的「置 1」换成「计数加 1」：每个元素对应几个孔，每出现一次，往它的每个孔里丢一颗弹珠。
- **读法：** 查某元素时，看它所有孔里的弹珠数，取最小值。别的元素也会往同一个孔里丢，所以每个孔的数都可能偏大，最小的那个偏得最少，因此它是真实次数的上界。
- **例子：** 阿尔伯特的孔里分别有 3 和 2，则他最多来过 2 次；某人有一个孔是 0，则他一定没来过。
- **孔太少：** 只有 1 个孔，所有人混在一起，只能说「都不超过 3 次」，毫无信息。
- **孔太多：** 每人一个孔等于精确计数，但省不了空间。要的是孔数远小于要统计的元素数。
