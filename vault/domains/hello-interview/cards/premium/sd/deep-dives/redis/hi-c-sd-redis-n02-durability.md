## Q
**Redis · 持久化：为什么它不能当唯一的数据源**｜摘要 · 必会

Redis 的两种持久化模式各会丢什么？这对选型意味着什么？

## A
- **RDB：** 定期做快照，崩溃会丢上一次快照之后的所有写入。
- **AOF：** 记录每一次写入，但默认每秒才 fsync 一次，崩溃最多丢约 1 秒已确认的写入。可配成每次写入都 fsync，但代价是它赖以成名的速度，很少有部署这么做。
- **这是有意的取舍：** 没有关系库默认那种"提交即落盘"的保证。
- **需要真正持久时：** AWS MemoryDB 这类实现牺牲一点速度换取基于磁盘的持久性。
- **选型含义：** 需要强持久性是不用 Redis 的一个重要理由。
