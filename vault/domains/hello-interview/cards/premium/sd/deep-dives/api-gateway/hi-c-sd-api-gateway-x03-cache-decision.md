## Q
**API 网关 · 哪些接口能在网关缓存**｜考点 · 必会

网关后面有三个接口：A `GET /products/{id}`（商品详情，几分钟才变一次）；B `GET /me/orders`（当前登录用户的订单）；C `POST /orders`（下单）。哪些可以在网关缓存？缓存键和失效怎么设计？

## A
- **A 可以：** 公共、读多、变化慢，缓存键用路径加查询参数；失效用较短 TTL（如几分钟），商品被编辑时可再发事件主动清除。
- **B 不能放共享缓存：** 响应因用户而异，除非缓存键里带上用户标识，那样命中率极低，不如不缓存。
- **C 不能缓存：** 写操作有副作用，缓存会让下单"看起来成功"而实际没发生。
- **缓存位置：** A 的热度高时，用 Redis 跨实例共享；仅用进程内存时，每个实例各存一份，命中率随实例数下降。
