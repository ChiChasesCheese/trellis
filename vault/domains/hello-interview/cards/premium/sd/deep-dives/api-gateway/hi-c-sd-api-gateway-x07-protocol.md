## Q
**API 网关 · 内部用 gRPC，要不要在网关转换**｜考点 · 追问

内部服务全用 gRPC，外部移动端希望用 JSON over HTTP。你会让网关做协议转换，还是让每个服务各自提供 REST 接口？

## A
- **网关转换：** 内部保持纯 gRPC，转换逻辑集中在一处；缺点是网关要为每个接口维护映射，接口一变就要同步更新，网关容易变厚。
- **每个服务自带 REST：** 服务多了会重复实现，各自行为不一致。
- **折中：** 用接口描述文件自动生成转换规则（例如由 protobuf 定义生成 HTTP 映射），网关只加载配置，不手写逻辑。
- **判断：** 对外接口少而稳定时，网关转换更干净；服务和接口数量大时必须自动生成。
