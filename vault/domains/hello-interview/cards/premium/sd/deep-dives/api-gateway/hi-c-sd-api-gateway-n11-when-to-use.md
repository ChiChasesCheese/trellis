## Q
**API 网关 · 什么时候该提网关**｜摘要 · 必会

设计里什么时候该画 API 网关，什么时候是过度设计？画了之后该花多少时间？

## A
- **该用：** 微服务架构。没有网关时客户端要认识并直接调用多个服务，耦合重、客户端代码复杂；网关把内部结构和对外 API 隔开。
- **不该用：** 简单的单体应用，或只有一种客户端的系统，多一层只增加复杂度和一跳延迟。
- **代价：** 多一跳延迟，网关本身成为必须高可用的入口。
- **时间分配：** 网关不是最有意思的部分，说错的概率主要来自讲得太久，而不是讲得太少。
- **标准话术：** 说它负责路由和基础中间件，然后立刻回到系统的核心难点。
