## Q
**ZooKeeper · 用途四：分布式锁，以及与 Redis 锁的取舍**｜摘要 · 必会

ZooKeeper 怎么实现分布式锁？什么时候该选它而不是 Redis 锁？

## A
- **做法：** 每个想拿锁的客户端在锁路径下创建"顺序加临时"节点；所有客户端按序号排序，最小的持有锁；每个客户端监视比自己小一号的节点；释放锁（或崩溃）时节点被删除，下一个客户端收到通知。
- **用途：** 资源分配、并发控制、集群调度。
- **不适合高频：** 每秒几百次的加锁不是它的设计目标，高频场景用 Redis 锁或数据库事务。
- **选 ZooKeeper 锁：** 正确性比性能重要（如金融交易）；锁持有很久（数小时），临时节点自动检测崩溃，比 Redis 锁要小心管理超时与心跳更稳健。
- **选 Redis 锁：** 更快更简单，订票之类场景够用。
