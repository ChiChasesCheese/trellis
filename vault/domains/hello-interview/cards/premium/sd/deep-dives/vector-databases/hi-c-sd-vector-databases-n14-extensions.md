## Q
**向量数据库 · 先从现有数据库的扩展开始**｜摘要 · 必会

要加向量搜索时，是不是该上专用向量数据库？有哪些扩展可选？

## A
- **建议：反直觉地，先别上专用库。** 现有数据库的扩展能轻松处理数百万向量，还避免多运维一套系统；规模或功能真的需要时才换。这个领域变化很快，几年前流行的方案已显老旧。
- **pgvector：** 已经用 PostgreSQL 时首选。支持 HNSW 和 IVF，数百万向量轻松应对；顺带得到事务、熟悉的工具，以及把向量结果与关系数据联接的能力，"相似、有库存、在用户所在区域"一条查询搞定。
- **Elasticsearch kNN：** 已经有 Elasticsearch 做搜索时很自然，混合搜索（关键词加向量）开箱即用；缺点是本身运维复杂，但已经在跑的话增加向量是增量工作。
- **Redis 向量搜索：** 要实时低延迟时合适，索引选项比专用库简单，但多数场景够用。
- **S3 Vector：** AWS 较新的服务，向量存在 S3 里用 S3 API 查询；已经用 S3 且不想增加专用库时可选。
