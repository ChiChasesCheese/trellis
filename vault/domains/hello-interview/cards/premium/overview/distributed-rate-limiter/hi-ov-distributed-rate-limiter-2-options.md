## Q
**分布式限流器 · 高层设计**｜通览

分布式限流器的高层设计怎么搭？每个功能需求走哪条路径？

## A
**组件。** API 网关（限流在这里）、共享的 Redis、规则配置、后端应用服务器。

**每条路径。**
- **识别客户端：** 请求先到网关，网关从请求本身取标识，登录用户看 JWT，匿名看 IP，开发者看 API key；多条规则叠加时取最严格的一条。
- **按规则限流：** 网关用令牌桶，把读、算、写放进一个 Lua 脚本，在 Redis 里完成；每个客户端只存令牌数和上次补充时间。
- **超限拒绝：** 令牌不够就立刻返回 429，不排队；响应头给出上限、剩余次数、重置时间。

**存储。** 令牌桶状态放 Redis，所有网关共用一份，每个网关各自计数会把限额放大；读改写要在一个脚本里原子完成，闲置的桶靠过期自动清理。规则放数据库或配置服务。
