## Q
**API 网关 · 能力一览**｜通览

API 网关有哪些核心能力和机制？各用来做什么，要注意什么？

## A
**11 项能力。**
- **请求校验：** 查 URL、头、请求体格式；坏请求早早拒绝；只做格式，不做业务。
- **中间件：** JWT 鉴权、限流、IP 黑白名单、SSL 终止、日志；统一横切逻辑；点到为止，别列清单。
- **路由：** 路由表按路径、方法、参数、头选服务；让客户端不认识后端；这是第一职责。
- **后端通信与协议转换：** HTTP 转 gRPC 等；内部协议自由；少见，映射要维护。
- **响应转换：** 把内部响应变成客户端要的格式；对外接口一致；网关会变厚。
- **缓存：** 整体、局部、TTL 或事件失效，放内存或 Redis；挡住重复读；只缓存与用户无关的响应。
- **水平扩展：** 无状态，多实例放在负载均衡后；扛流量；限流计数要共享。
- **两层负载均衡：** 客户端到网关靠独立均衡器，网关到服务由网关做；图上可画一个框；别陷进细节。
- **全球部署：** 多区域加 GeoDNS；离用户近；各区域配置要同步。
- **托管网关：** AWS、Azure、Google 的服务；最省事；最贵。
- **开源网关：** Kong、Tyk、Express Gateway；更可控，可自建机房；要自己运维。

**一句话定位。** 擅长做微服务前的路由入口；单体或单一客户端不需要，用负载均衡器即可。
