## Q
**API 设计 · 什么时候用**｜通览

面试里什么信号说明该用 API 设计？常见场景有哪些，什么时候不该用？

## A
**信号。**
- 面试进入 API 步骤，要定义对外接口。
- 题目有支付、预订、下单，重试会造成重复。
- 面试官提灵活取数、内部微服务，或列表会越来越大。

**常见场景。**
- **公开的 CRUD 服务：** REST，资源建模。
- **多端需求不同的前端：** GraphQL。
- **服务之间高频调用：** gRPC。
- **订票、付款：** 幂等键。
- **活动列表：** 分页，过滤排序用查询参数。
- **用户登录：** JWT，服务间用 API Key。
- **防黄牛：** 按端点限流。

**不该用。**
- **GraphQL：** 没有明确的多取少取问题就别当默认。
- **RPC：** 不要拿它设计对外接口。
- **安全与限流：** 除非被问，不展开算法。

**常见追问。**
- **客户端重试怎么办：** 幂等键，同键同结果。
- **数据量很大：** 分页，页大小设上限，高频数据用游标。
- **接口改动：** 新增字段安全，破坏性改动走 URL 版本。
- **N+1：** 批处理合并成一次查询。
