## Q
**API 设计 · 做法一览**｜通览

API 设计常见的做法有哪几种？各解决什么，代价是什么？

## A
**13 类做法。**
- **REST：** 资源加 HTTP 方法，参数分路径、查询、请求体；默认选它；只有固定端点。
- **GraphQL：** 单入口，客户端指定字段；解决过取欠取；有 N+1 和缓存难题。
- **RPC（gRPC）：** 像调本地函数，Protobuf 加 HTTP/2；内部调用快，类型安全；对外不如 REST。
- **偏移分页：** 跳过若干条再取；简单，可跳页；数据变动会错位。
- **游标分页：** 指针指向上次最后一条；稳定；不能跳页。
- **过滤与排序：** 都用查询参数；按需切片；难点是全站命名一致。
- **幂等键：** 请求头带唯一键，服务端回放结果；重试不重复下单；要存键和结果。
- **统一错误信封：** 状态码管类别，body 带错误码和消息；客户端只写一次处理；要全站统一。
- **URL 版本：** 路径带 v1、v2；显式，最常用；URL 变多。
- **请求头版本：** Accept-Version；URL 干净；不直观，难测试。
- **API Key 与 JWT：** Key 标识应用，JWT 携带用户；服务间用 Key，用户用 JWT；JWT 难撤销。
- **RBAC：** 角色绑权限，先认证再授权；权限清晰；面试点到即可。
- **限流：** 按用户、IP、端点限次，超限返回 429；防滥用；别展开算法。

**先后顺序。** 先 REST 再按需求换 GraphQL 或 gRPC；列表先加分页，写操作加幂等键，之后才谈版本与限流。
