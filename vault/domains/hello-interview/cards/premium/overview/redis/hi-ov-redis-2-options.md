## Q
**Redis · 能力一览**｜通览

Redis 有哪些核心能力和机制？各用来做什么，要注意什么？

## A
**13 项能力。**
- **单线程执行：** 命令逐条跑；无需加锁；慢命令会堵住全部。
- **持久化：** RDB 快照或 AOF 日志；崩溃后恢复；会丢一段写入。
- **哈希槽分片：** 16384 槽分给节点；按键扩容；无跨节点查询。
- **哈希标签：** 只哈希花括号内；相关键同槽；才能跨键事务。
- **异步复制：** 副本分担读；做高可用；故障转移可丢写，读有延迟。
- **缓存：** TTL 加淘汰策略；缓存热数据；热键难题仍在。
- **分布式锁：** SET NX EX 加令牌，Lua 校验后删；串行化操作；偶尔失效。
- **排行榜：** 有序集合按分数排序；对数时间取榜；要定期裁剪。
- **限流：** 固定窗口用 INCR，滑动窗口用有序集合加 Lua；挡住超额请求；窗口边界有突刺。
- **Geo：** GEOADD 与 GEOSEARCH；查附近的点；先粗筛后精筛。
- **Streams：** 追加日志加消费者组；做工作队列；偶尔重复处理，持久性有限。
- **Pub/Sub：** 向在线订阅者广播；实时通知；不持久，离线即丢。
- **热键补救：** 客户端缓存、键副本、读副本；分散单键压力；有陈旧，写热点无解。

**一句话定位。** 最擅长低延迟的简单操作；要持久、查询灵活或长期回放时，换数据库或 Kafka。
