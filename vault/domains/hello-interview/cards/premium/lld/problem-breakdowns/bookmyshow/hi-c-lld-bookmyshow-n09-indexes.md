## Q
**电影票预订 · 为什么给协调者建四个字典**｜摘要 · 必会

搜索、订座、取消各需要什么索引？为什么不每次遍历？

## A
- **朴素的搜索：** 每次遍历影院→场次→电影，检查标题；复杂度是影院数乘每家场次数，每次搜索都重复。搜索频繁、电影表很少变化的系统里是浪费。
- **构造时建索引：** 按电影 id 存电影；按电影 id 存它的所有场次；按场次 id 存场次；按确认号存订单（一开始是空的，订座时逐渐增加）。
- **搜索变成：** 扫描电影索引（最多几百部）找到标题匹配的，再取它们的场次，只保留未开场的。
- **订座变成：** 按场次 id 一次字典查找，而不是遍历全部场次。
- **取消变成：** 按确认号一次查找，再沿反向引用路由。
- **代价：** 构造时一次性建好，假设影院和场次此时已齐全；之后新增场次，索引不会自动更新，必须在新增入口里同步每一个索引。非冗余的数据是最简单的，建索引是用写入复杂度换读取速度。
- **旧场次堆积：** 场次永远留在内存里，列表越来越长；生产里用数据库，内存版要说一句需要清理过期场次。
