## Q
**限流器 · 澄清问题**｜摘要 · 必会

拿到"为 API 网关做内存限流器"，该问哪些问题？每个答案如何收窄设计？

## A
- **配置形态：** 每个端点的配置里有一个"算法名"和一个"算法参数"对象，参数随算法而变（令牌桶要容量和补充速率，窗口日志要最大次数和窗口长度）。所以配置是异构数据，需要有人把它翻译成对象。
- **请求输入：** 客户端 ID 加端点，都只是字符串，不需要请求对象。
- **返回值：** 不止布尔，要返回是否放行、剩余额度、被拒时多久后可重试。所以返回类型必须是结构，不能是裸 bool。
- **没有配置的端点：** 退回默认配置，而不是拒绝；一个缺配置的端点不能让服务整个不可用。
- **并发：** 面试官说"先不管"。这是常见套路：他们想先看你把干净的核心做出来，做完再问；这不代表不重要，要预留时间。
- **单进程还是分布式：** 单进程内存，省掉所有网络协调和跨机器共享状态。
- **配置是否动态：** 启动时加载一次，不处理热更新。
- **要领：** 每个问题都对应一个具体的设计决定或一块被划出范围的工作。
