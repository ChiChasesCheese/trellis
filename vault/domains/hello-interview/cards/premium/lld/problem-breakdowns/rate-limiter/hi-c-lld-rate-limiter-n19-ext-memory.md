## Q
**限流器 · 扩展：客户端数量带来的内存增长**｜摘要 · 追问

桶和日志的映射永远只增不减，百万用户怎么办？

## A
- **问题：** 每个出现过的客户端 ID 一份状态，没有删除，最终耗尽内存。
- **做法一，按空闲时间淘汰：** 每个键记最后访问时间，后台线程周期性扫描，删除超过某个时间（如 1 小时）没访问的。
- **做法二，LRU 缓存：** 用固定容量的 LRU，满了就淘汰最近最少使用的客户端。
- **做法三，Redis 的 TTL：** 分布式场景下给键设过期时间，由 Redis 自动淘汰，逻辑内置，更省事。
- **淘汰后果：** 被淘汰的客户端下次请求看起来像第一次，拿到满额度。对不活跃的客户端可以接受；活跃客户端的访问时间不断刷新，不会被淘汰。
- **更精细的说法：** 只淘汰空闲时间足够长的键就是无损的（见考点：淘汰什么时候无损）。
