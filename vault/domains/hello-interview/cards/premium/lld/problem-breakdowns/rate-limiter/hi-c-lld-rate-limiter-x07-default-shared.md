## Q
**限流器 · 默认限流器是否按端点分桶**｜考点 · 追问

两个都没配置的端点 `/a`、`/b` 共用同一个默认限流器，键只有客户端 ID。同一个客户端先调 `/a` 再调 `/b`，额度怎么算？想让每个端点各算各的怎么改？

## A
- **现状：** 默认限流器只有一个，里面的状态按客户端 ID 存。客户端在 `/a` 和 `/b` 的请求消耗同一个桶，额度合计。这是需求未说清的地方，需要和面试官确认。
- **按端点分桶：** 让 key 变成 `(endpoint, client_id)`，或者为每个未配置端点惰性复制一个默认限流器实例（用同一默认配置各造一个）。
- **两者区别：** 复合键只改 `RateLimiter.allow` 一行，但所有端点共享同一个实例的锁与映射；惰性复制则每个端点一份独立状态，需要处理"端点集合无限增长"（攻击者请求随机路径会撑爆内存），这时要限制个数或回落到共享默认实例。
- **要点：** 默认值设计里最常被忽略的是它的作用域，要主动问。
