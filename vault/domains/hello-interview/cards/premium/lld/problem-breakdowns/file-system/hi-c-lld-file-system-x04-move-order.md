## Q
**内存文件系统 · 找 bug：`move` 先摘下再检查**｜考点 · 必会

一个实现的 `move` 先把源从原父文件夹摘下，再检查目标是否重名，重名就抛异常。出了什么问题？

## A
- **后果：** 条目已经被摘下，异常抛出时没有任何地方持有它——文件（连同内容）或整棵子树凭空消失。
- **修法一：** 所有检查（源存在、目标父存在、不成环、不重名）放在第一次修改之前，通过后再摘与挂；摘与挂之间不会失败。
- **修法二：** 先挂后摘不行，因为同一个对象不能同时有两个父；做不到原子就要在 `except` 里放回去。
- **并发提醒：** 单线程下检查在前就够；多线程时检查和修改之间会被插入，需要锁。
- **规律：** 多步修改要么保证后续步骤不会失败，要么有回滚。
