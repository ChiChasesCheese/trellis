## Q
**内存文件系统 · 真实文件系统为什么没有"条目的路径"**｜拓展 · 追问

面试里每个条目有名字和父指针。真实的 Unix 文件系统是这样存的吗？硬链接意味着什么？

## A
- **真实结构：** 文件的数据和元信息放在一个编号节点里（inode）；名字不属于文件，而存在目录的条目里——目录本质上是一张"名字→inode 编号"的表。
- **硬链接：** 同一个 inode 可以被多个目录条目指向，所以一个文件可以有多个名字、多条路径。这时"这个文件的路径"是个没有唯一答案的问题，这就是为什么系统调用里没有"给文件求路径"。
- **对设计的启示：** 面试模型把名字和父指针放在条目上，等于规定每个条目只有一条路径（树，不是图）；一旦要支持硬链接，要把"名字"从条目移到父文件夹的映射里（实际上我们的字典键已经是名字），并让条目可以有多个父。
- **改名的原子性：** 同一个文件系统内的 `rename` 在 POSIX 下是原子的，即便目标已存在也能原子替换；内存版就是"摘下改名再挂上"，要靠锁才有同样的保证。
- **符号链接：** 是另一种条目，内容是一条路径，解析时再跳转，需要防止环。
