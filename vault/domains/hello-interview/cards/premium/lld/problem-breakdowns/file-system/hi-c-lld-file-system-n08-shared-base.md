## Q
**内存文件系统 · 文件与文件夹的共同抽象**｜摘要 · 必会

文件和文件夹有大量重复，应该抽接口还是抽抽象基类？

## A
- **重复在哪里：** 两者都有名字和父指针，都有取名字、取父、取路径的方法，还有各自返回不同值的"是不是目录"。文件夹的子节点容器也需要一个能装两种条目的类型。
- **信号：** 重复往往说明漏了一个抽象——它们在树里是同一类东西：节点。
- **只抽接口（够用但不彻底）：** 解决了类型问题，子节点可以按统一类型处理；但名字字段、`get_name`、父指针和 `get_path` 仍然各写一遍，接口不共享实现。
- **抽象基类（选这个）：** 基类拿走名字、父指针、`get_path` 和 `is_directory` 的声明；文件加内容，文件夹加子节点容器。
- **继承何时合理：** 子类共享行为而不只是数据；这些行为稳定；两者确实是"一种"关系。这里三点都满足——树里永远是有名字、有父节点的节点。
- **这是组合模式（Composite）：** 叶子（文件）和容器（文件夹）共用一个接口，代码可以一视同仁；面试里不用点名，结构自然出现即可。
