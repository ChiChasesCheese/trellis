## Q
**内存文件系统 · 扩展一：细粒度锁、死锁与读写锁**｜摘要 · 追问

每个文件夹一把锁会引入什么新风险？`move` 怎么避免死锁？读写锁有什么用？

## A
- **细粒度：** 每个文件夹一把锁，只锁正在改的那个；不同文件夹里的操作可以并行。
- **新风险：** `move` 要同时碰两个文件夹。线程 A 把 `/alice/f` 移到 `/bob`，线程 B 把 `/bob/g` 移到 `/alice`：A 锁住 alice 再要 bob，B 锁住 bob 再要 alice，互相等待，死锁。
- **加锁顺序：** 不管谁是源谁是目标，总按统一顺序加锁（例如按创建时分配、终身不变的编号；不要用会随改名变化的路径）。A、B 都先要编号小的那个，一个拿到，另一个等，不会形成环。
- **读写锁：** `get`、`list` 只读，普通锁让读者互相阻塞；读写锁允许多个读者同时进入，写者独占。读多写少时吞吐明显提高，但更复杂。
- **面试建议：** 粗粒度够用；说出细粒度的好处、`move` 死锁风险和加锁顺序即可，被要求再实现。
