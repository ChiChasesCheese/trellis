## Q
**内存文件系统 · 删除之后，手里的旧引用会怎样**｜考点 · 追问

调用者先保存了 `/home/user/q.txt` 的引用，随后删除了 `/home/user`。再调 `q.path()` 得到什么？这是 bug 吗？

## A
- **实际结果：** `user` 被摘下后父指针置空，`q` 的路径沿父指针走到 `user` 就停了，得到 `user/q.txt`——不是以 `/` 开头的路径。
- **这是个有意的信号还是缺陷：** 取决于约定。好处是调用者能看出"它已不在树里"；坏处是返回了一个像路径的字符串。
- **更严格的做法：** 给条目一个"是否仍在树里"的判断（沿父指针能走到真正的根），脱离时 `path()` 抛错或返回空。
- **为什么不能靠"父指针为空"判断根：** 根和被删下来的子树的顶端都是父指针为空，要区分就要让根有身份（比如持有指向文件系统的引用，或用专门的根类）。
- **类似问题：** 删除后 `get` 同一路径→找不到，旧引用却仍可调用方法——悬空引用在内存模型里不可避免，要靠约定与文档。
