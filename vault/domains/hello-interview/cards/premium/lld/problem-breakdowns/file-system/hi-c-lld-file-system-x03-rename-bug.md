## Q
**内存文件系统 · 找 bug：改名只调 `set_name`**｜考点 · 必会

某实现的改名是 `entry.name = new_name`，没碰父文件夹的字典。之后会发生什么？

## A
- **字典的键仍是旧名字：** 用新路径去解析，沿父文件夹按新名字查，查不到，报"找不到"。
- **旧路径反而找得到：** 按旧名字查到该对象，对象却自称新名字，`path()` 返回新路径；同一个条目对应两种说法。
- **继续出错：** 以后在该文件夹里用旧名字再建新条目，也会被误判为重名。
- **根因：** 同一信息（名字）存了两处——对象上和父的字典键。
- **正确做法：** 摘下、改名、再挂回去，让 `add` 用新键并设置父指针；所有校验（重名、非法字符）放在改动之前。
- **一般规律：** 冗余存储就要有唯一的写入口。
