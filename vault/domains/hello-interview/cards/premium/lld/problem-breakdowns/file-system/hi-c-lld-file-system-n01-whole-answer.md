## Q
**内存文件系统 · 完整解答（一张卡）**｜摘要 · 必会

设计一个内存文件系统：单根、Unix 风格的绝对路径（如 `/home/user/a.txt`）；支持创建、删除、列出、按路径取条目、改名、移动；文件存字符串内容；要能从任何条目得到它的完整路径；规模是几万个条目。给出需求、实体与接口、整体设计、关键实现、深入问题和各级别的期望。

## A
**一句话。** 文件和文件夹是同一棵树的两种节点：共同的名字和父指针放进抽象基类，文件夹用「名字→子节点」字典存孩子；路径不存，沿父指针现算；所有路径解析收进一个 `FileSystem` 门面。

**60 分钟路线。**

| 时间 | 做什么 |
|---|---|
| 0–5 分 | 澄清：单根、操作清单、报错方式、规模（几万条目） |
| 5–25 分 | 实体与类设计：路径不是类；门面、父指针、字典、共同基类 |
| 25–45 分 | 实现：创建、删除、移动、改名、路径解析 |
| 45–60 分 | 走创建与移动；追问线程安全、搜索 |

**必讲。**
- **路径存储：** 存字符串则改名一个文件夹要改所有后代，O(后代数)；存父指针则只改一个节点，`path()` 是 O(深度)，`move` 后同一对象的 `path()` 自动更新。
- **共同基类：** 文件与文件夹共享名字、父指针、`path()`，是组合模式（Composite）。`Folder.add / remove` 同时维护子节点字典和孩子的父指针，两边永远一致。
- **`move` 先检查后动手：** 源存在、目标父存在、不重名、不会成环；把 `/home` 移进 `/home/user/stuff` 要拒绝，检查方法是从目标父级向上走，看是否撞到被移的文件夹。

**追问再讲。** 门面：不让调用者拿根自己走，否则路径解析在每个调用者里重复。子节点容器：列表查找 O(n)，字典 O(1) 且天然禁止重名；改名要摘下、改名、再挂上，否则字典键与名字不一致。线程安全：创建的「先检查后操作」竞态、粗粒度锁、细粒度锁时 `move` 要同时锁两处并定加锁顺序。搜索：遍历 O(n)，名字索引，前缀用 trie。

**级别期望。** 中级主动抽出基类，解释父指针优于存路径，`move` 经提示做好成环检查；高级不提示就处理边界和成环，主动谈线程安全，并能说怎么加符号链接和权限。
