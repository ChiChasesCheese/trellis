## Q
**设计原则 · 一页速查**｜摘要 · 必会

能不能用一行话回忆每条原则的目的？面试里怎么提它们？

## A
| 原则 | 什么时候想到它，为什么 |
|---|---|
| KISS | 想加模式或拆类时：先简单，简单行不通再复杂 |
| DRY | 同一逻辑出现多处时：抽出来，改规则只改一处 |
| YAGNI | 想为未来留扩展时：为今天建，猜的需求多半会错 |
| 关注点分离 | 一个方法同时干多件事时：这样才能独立修改和测试 |
| 迪米特 | 出现长长的 getter 链时：降低耦合，隐藏内部结构 |
| SRP | 一个类有多个改动理由时：每个类只管一件事 |
| OCP | 每加一种变体就要改旧代码时：用抽象让新需求不碰旧代码 |
| LSP | 子类要抛"不支持"时：避免层级在运行时出问题 |
| ISP | 实现者被迫写用不到的方法时：接口应干净专注 |
| DIP | 业务类里直接创建具体实现时：业务与实现解耦，便于测试和替换 |

- **提法：** 不必点名，边解释取舍边带一句；关键是推理。
