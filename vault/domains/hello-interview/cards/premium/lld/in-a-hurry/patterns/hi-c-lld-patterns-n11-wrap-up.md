## Q
**设计模式 · 一页速查与选用判断**｜摘要 · 必会

设计模式的速查表是什么？一个设计里用几个算合适？

## A
| 模式 | 什么时候用，为什么 |
|---|---|
| Factory | 调用方不该关心具体创建哪个类：创建逻辑集中在一处，新增类型只改工厂 |
| Builder | 可选字段多、构造繁琐：避免十个参数一半为空的构造函数 |
| Singleton | 确实需要全局唯一实例（面试少见）：多数情况下传参更好 |
| Decorator | 要在运行时叠加可选行为：避免为每种组合都写一个子类 |
| Facade | 想用简单入口隐藏内部复杂度：调用方只和一个类打交道 |
| Strategy | 用 if/else 区分做法：换成可替换的行为对象 |
| Observer | 多个组件要响应同一个事件：被观察者不必知道谁在听 |
| State Machine | 行为取决于当前状态且转换复杂：每个状态管自己的合法动作 |

- **数量：** 多数面试级的设计用 0 到 2 个模式；用到三个以上，多半是在硬套、过度设计。
- 先把问题解干净，再在合适时顺势给模式起名。
