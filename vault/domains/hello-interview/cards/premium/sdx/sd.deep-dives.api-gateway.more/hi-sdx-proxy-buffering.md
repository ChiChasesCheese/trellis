## Q
**代理缓冲为何保护后端**｜补充 · API 网关 · 追问

为什么应用服务器（如 gunicorn、Tomcat）前面要放一层 Nginx 这样的反向代理，而不是直接面向用户？什么情况下又必须关掉它的缓冲？

## A
**结论。** 代理的缓冲把慢客户端挡在应用之外：它先完整收下慢速上传，再用内网速度转给应用，应用的 worker 不会被慢连接占住。流式输出和大文件要关掉缓冲。

**要点。**
- **请求缓冲：** 客户端以 50 KB/s 上传 1 MB 要 20 秒。没有代理，应用的一个 worker 被占 20 秒；有代理，代理收完再用内网转发，应用只忙约 8 ms（按 1 Gbps 算）。
- **响应缓冲：** 应用几毫秒把响应交给代理，代理再慢慢发给慢用户，worker 立刻释放。
- **防慢速攻击：** 慢速攻击（slowloris）靠大量慢连接占满 worker；代理用事件循环扛海量慢连接，应用不受影响。
- **必须关缓冲的场景：** SSE 和流式响应：缓冲会把事件攒到响应结束才发（Nginx 用 `proxy_buffering off`，或应用返回头 `X-Accel-Buffering: no`）。
- **大文件上传：** 缓冲会把整个文件落在代理的内存或磁盘，可以关掉请求缓冲直接转发。

**为什么。** 应用 worker 数有限，一个 worker 的占用时间等于处理时间加上与客户端交换数据的时间。缓冲把后一项从「用户的网速」变成「内网的速度」。

**面试里这样说。** 「应用前面放 Nginx，是用它的请求和响应缓冲把慢客户端隔开：1 MB 的慢速上传占 worker 20 秒，有缓冲只占约 8 毫秒。SSE 这类流式接口我会对该路径关掉缓冲。」

**易错。**
- **SSE 经过代理没关缓冲：** 事件不实时，客户端看到的是成批出现。
- **以为缓冲只有好处：** 大文件缓冲会占代理的磁盘和内存，还增加首字节延迟。
