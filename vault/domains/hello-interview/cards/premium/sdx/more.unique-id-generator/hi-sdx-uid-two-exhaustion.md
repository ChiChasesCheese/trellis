## Q
**序列号用完与机器号用完，处理完全不同**｜补充 · 发号器（Unique ID Generator） · 追问

面试官：「雪花式发号器里，『序列号用完』和『机器号用完』都叫位数耗尽，处理方式一样吗？」

## A
**结论。** 完全不同。序列号耗尽发生在单个节点的一毫秒内，自旋等下一毫秒即可；机器号耗尽发生在部署规模上，等待解决不了，要回收租约，并规划迁移到更宽的布局。

**要点。**
- **序列号耗尽：** 同一毫秒发满 1024 个，自旋等到下一毫秒再继续，是亚毫秒级的停顿。绝不能回绕到 0，否则会和同一毫秒里已发出的 ID 重复。
- **机器号耗尽：** 活跃实例数逼近 8192 时，新实例租不到机器号，直接启动失败，不是等一会儿能好的。
- **短期处理：** 回收已下线实例的租约（租约到期自动回收），并在活跃数到七八成时告警。
- **长期处理：** 迁移到更宽的机器号字段。新布局从某个时间点起生效，旧 ID 仍按旧布局解读，两种布局并存一段时间；不能原地改位宽，否则旧 ID 会被错误解读。

**为什么。** 两者耗尽的维度不同：一个是单点单毫秒的瞬时速率，一个是部署拓扑的规模。瞬时问题用等待解决，规模问题只能改设计。

**面试里这样说。** 「序列号满了我自旋等下一毫秒，绝不回绕；机器号满了等没用，我先回收闲置租约并设占用率告警，长期要迁到更宽的布局，新旧按切换时间点并存。」

**易错。**
- **序列号回绕：** 同一毫秒内出现重复 ID。
- **不监控机器号占用率：** 到耗尽那天才发现新实例都起不来。
