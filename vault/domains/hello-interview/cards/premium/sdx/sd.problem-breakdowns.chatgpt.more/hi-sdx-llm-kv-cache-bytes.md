## Q
**KV 缓存：一个 token 占多少显存**｜补充 · ChatGPT · 追问

面试官：「70B 参数的对话模型，结构类似 Llama 3 70B：80 层，8 个键值头（分组查询注意力），头维度 128，FP16。算一下一个 token 的 KV 缓存占多少显存。为什么是它而不是算力，决定了一个 GPU 副本能同时服务多少会话？」

## A
**结论。** 每个 token 约 320 KiB，一个 2000 token 的会话要占约 0.65 GB，而且在会话存活期间别人用不了。副本的显存扣掉权重之后是固定的，并发会话数 = 剩余显存 ÷ 单会话缓存，与算力无关。

**要点。**
- **每层每 token：** 2（K 和 V）× 8 个头 × 128 维 × 2 字节 = 4096 字节。
- **每 token：** 4096 × 80 层 = 327,680 字节，约 320 KiB。
- **每会话：** 2000 token × 327,680 字节 ≈ 0.65 GB。
- **一个副本能放多少：** 8 张 80 GB 的卡共 640 GB；权重 70B × 2 字节 = 140 GB；留约 100 GB 给激活和碎片，剩下约 400 GB，除以 0.65 GB，约 600 条 2000 token 的会话。
- **分组查询的作用：** 如果 64 个头都有各自的 KV，缓存是 8 倍，每 token 约 2.5 MiB，并发直接掉到原来的八分之一。

**为什么。** 解码时每一步要读出整个缓存来算注意力，缓存常驻显存直到会话结束；GPU 的算力再强，也放不下更多的会话。所以容量规划先算显存，再算算力。

**面试里这样说。** 「每个 token 的 KV 是 2 乘 8 个头乘 128 乘 2 字节再乘 80 层，约 320 KiB，两千 token 的会话就占 0.65 GB。8 卡 640 GB 去掉 140 GB 权重和余量，大约能放六百条会话，所以并发上限是显存决定的，不是算力。」

**易错。**
- **只算权重不算缓存：** 权重放得下，会话一多就爆显存。
- **忽略序列长度：** 8000 token 的会话占四倍，并发要按平均上下文长度估。
- **把键值头数当成注意力头数：** 差八倍。
