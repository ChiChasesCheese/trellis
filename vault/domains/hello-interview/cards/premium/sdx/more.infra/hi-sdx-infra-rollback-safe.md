## Q
**什么叫回滚安全**｜补充 · 平台基础设施：容器、服务网格、发布 · 必会

面试官：「什么情况下一次发布是「回滚安全」的？为什么要在新版本 N 上线之前，就用自动化测试证明旧版本 N-1 能读 N 写的数据？」

## A
**结论。** 回滚安全指：回到上一个版本一定能工作，具体说，版本 N-1 能正确读取版本 N 可能写下的所有数据、消息和线上格式。回滚是出事后的第一反应，必须是不会让情况更糟的条件反射。

**要点。**
- **坏法：** N 引入新的序列化格式（新字段、新枚举值、新编码）并写进存储或队列，回滚后 N-1 读不懂，要么崩溃，要么悄悄丢掉新字段，一次回滚变成第二次更深的故障。
- **没有回滚也一样：** 滚动发布和灰度期间，N-1 和 N 同时读写共享的存储和队列，相邻版本本来就必须互相兼容。
- **强制手段：** 流水线里做升级和降级测试：部署 N，写数据，回滚到 N-1，验证能读，作为一道卡点，而不是代码评审时的约定。

**为什么。** 在压力下往前修比回滚慢得多，也危险得多；回滚能当反射，前提就是它事先被证明过。

**面试里这样说。** 「我把回滚安全做成流水线卡点：部署新版本写一批数据，再回滚到旧版本，验证旧版本读得了。新格式分两次发布，先发能读的，再发开始写的。」

**易错。**
- **只测向前升级：** 没人测降级，回滚才发现旧版本读不了新数据。
- **有不可逆的迁移就放进同一次发布：** 一旦删了旧列，回滚就是空话。
