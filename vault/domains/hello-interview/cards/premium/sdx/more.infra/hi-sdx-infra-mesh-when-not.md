## Q
**什么时候不值得上服务网格**｜补充 · 平台基础设施：容器、服务网格、发布 · 追问

面试官：「什么情况下不值得采用服务网格？」

## A
**结论。** 服务少、语言单一、主要是南北向流量、没有平台团队，这几种情况都不值得。网格是一个要自己运营的产品：控制面升级、代理版本、CRD 堆积。

**要点。**
- **服务少或只有一种语言：** 共享库加 API 网关就能覆盖 TLS、重试和指标，机制少得多。
- **主要是南北向流量：** 网格管的是服务到服务的东西向调用；网关挡着一个单体或两三个后端，东西向没多少可管。
- **没有平台团队：** 谁来运营控制面和代理的版本？
- **值得的场景：** 很多种语言的大量服务、合规要求统一 mTLS 与授权、跨团队的流量策略（分流、镜像）；也就是替代方案是 N 个团队各自重复实现同样的保证。

**面试里这样说。** 「十个服务以内、语言统一，我用共享库加网关就够了。服务多到好几种语言、又有统一 mTLS 的合规要求，才上网格。」

**易错。**
- **为了「现代化」上网格：** 引入的运维负担比解决的问题更大。
- **把东西向与南北向混为一谈：** 网关管外部进来的流量，网格管内部服务之间的调用。
