## Q
**限流存储挂了：公平层放行，保护层保守**｜补充 · 分布式限流器 · 追问

面试官：「你的限流有两层：每个 API key 的公平限额，和保护后端总量的全局上限。存放计数的中心存储不可达了，两层都放行吗？」

## A
**结论。** 不一样。公平层偏可用性，放行；保护层偏安全，降级为每个网关自己的保守限额，不全放开。

**要点。**
- **公平层的目的：** 调用方之间的公平。短暂失准、多放一些流量，代价远小于把一次限流故障变成 API 可用性事故，所以放行。
- **保护层的目的：** 不让后端被压垮。这一层放开，恰好在高峰时最危险（故障常与高峰同时出现），所以不放开。
- **降级做法：** 每个网关节点按自己最近观察到的放行量，加一个本地限额，如全局上限 30 万/秒、20 台网关，每台先按 1.5 万/秒封顶。
- **有意的误差：** 流量不均时会多拒一些，这是可接受的代价。
- **运维信号：** 进入降级要告警、要记录时长，恢复后切回中心计数。

**为什么。** 离用户近、为公平服务的层，失败时倾向可用；贴近后端、为自保服务的层，失败时倾向保守。两层的失败代价不同，策略就不该一样。

**面试里这样说。** 「中心存储挂了，每个 key 的公平层我放行，因为拒绝会让 API 整体不可用；全局保护层我让每个网关按本地限额继续限，比如总量 30 万、20 台网关，每台 1.5 万，宁可多拒一点也不放开后端，并且告警。」

**易错。**
- **两层统一 fail-open：** 高峰期故障时后端直接被打穿。
- **保护层直接全拒：** 等于整站下线，后端明明健康。
