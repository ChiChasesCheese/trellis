## Q
**限流与负载丢弃的分工**｜补充 · 分布式限流器 · 追问

限流器已经给每个 API key 限了 100 QPS，服务为什么仍然会被打垮？限流（rate limiting）和负载丢弃（load shedding）有什么区别，为什么两个都要？

## A
**结论。** 限流是对每个客户端的配额约定，每个人都守规矩，总和也可能超过系统能力；负载丢弃是系统在真正过载时的自保，不管谁的配额。

**要点。**
- **总和问题：** 1000 个客户端各在 100 QPS 配额内，总量最多 10 万 QPS；系统只能服务 6 万，没人违规，系统仍然过载。
- **触发方式不同：** 限流按客户端用量触发，利用率 10% 时也生效；丢弃由队列深度、CPU、延迟这类健康信号触发。
- **保护对象不同：** 限流让租户互不影响、成本可预测；丢弃保护的是服务本身。
- **丢弃要分优先级：** 先丢未认证、后台、重试的流量，再丢付费的交互请求。
- **不能丢健康检查：** 丢掉探活请求会让负载均衡器把实例判死，反而放大故障。

**面试里这样说。** 「限流我按 API key 做，是配额约定；另外加负载丢弃，看队列深度和延迟，过载时先丢后台和重试流量，健康检查永不丢，因为每个客户端都在配额内，总和仍可能超过容量。」

**易错。**
- **以为限流就能防过载：** 配额总和可能超过容量，限流管不到这一层。
- **丢弃时一视同仁：** 付费的交互请求和后台批处理一起被丢，核心业务受伤。
