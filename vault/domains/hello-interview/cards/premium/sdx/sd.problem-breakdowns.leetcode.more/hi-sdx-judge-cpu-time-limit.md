## Q
**判题的超时：按 CPU 时间还是墙钟时间**｜补充 · 在线判题平台 · 追问

面试官：「判题时『超过时限』要按墙钟时间还是 CPU 时间算？同一份代码在机器空闲和繁忙时，结果可以不同吗？如果只按 CPU 时间，会有什么漏洞？」

## A
**结论。** 超时按 CPU 时间判，从沙箱所在 cgroup 的统计里读取，这样同样的代码不管何时运行结论都一样。再单独设一个宽松得多的墙钟上限兜底，防止代码睡眠或一直等一个永远不会就绪的连接，占着沙箱却几乎不耗 CPU。

**要点。**
- **墙钟的问题：** 宿主机繁忙时，调度争抢会拉长墙钟时间，同一份提交空闲时能过、繁忙时超时，对选手不公平。
- **CPU 时间的好处：** 只统计代码实际做的计算，结论与负载无关；cgroup v2 的 cpu.stat 里有累计的 CPU 用量。
- **只用 CPU 时间的漏洞：** 睡眠或阻塞等待不耗 CPU，沙箱槽位被无限占用，而 CPU 上限永远不触发。
- **墙钟兜底：** 比 CPU 上限宽松几倍，例如 3 到 5 倍，只负责回收卡住的沙箱，到点判超时并杀掉。
- **多线程：** CPU 时间是各线程之和，所以要同时限制进程和线程数，否则用多线程可以把一秒的墙钟变成几秒的 CPU。

**为什么。** 两个时间回答两个问题：CPU 时间回答「代码算得够不够快」，要公平；墙钟回答「这个沙箱占了多久」，要保护容量。

**面试里这样说。** 「判题时限我按 cgroup 里的 CPU 时间算，同样的代码在忙闲机器上结论一致；另外设一个宽松的墙钟上限，一般是 CPU 上限的三到五倍，用来回收睡眠或卡在网络等待上的沙箱。」

**易错。**
- **只按墙钟：** 抖一下就超时，选手会质疑判题。
- **只按 CPU 时间：** 睡眠的提交占满沙箱槽位，等于拒绝服务。
- **不限制线程数：** 多线程把 CPU 时间放大。
