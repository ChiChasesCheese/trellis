## Q
**「用 Google 登录」是 OAuth 还是 OIDC**｜补充 · 安全 · 必会

面试官：「『用 Google 登录』是 OAuth2 还是 OIDC？为什么把普通 OAuth2 访问令牌当成用户身份证明是个漏洞？」

## A
**结论。** 是 OIDC，在 OAuth2 之上加了身份层。OAuth2 回答「这个应用能否访问这个资源」（授权委托），不说用户是谁。访问令牌没有绑定到你的应用，别的应用拿到后可以重放到你的后端冒充用户。OIDC 的 ID 令牌才是用来验证身份的。

**要点。**
- **OAuth2：** 委托访问，令牌是「能访问什么」的凭证。
- **访问令牌的问题：** 受众不是你的应用，任何拿到它的应用都能拿来冒充登录。
- **ID 令牌：** 由身份提供方签名的 JWT，含用户标识（sub）。
- **要验证的字段：** aud 必须是你的客户端 ID，iss 是预期的提供方，exp 未过期，nonce 与发起请求一致。
- **用途区分：** ID 令牌是给你的应用验证的，不应转发给别的服务当访问凭证。

**为什么。** 身份与授权是两个问题。OIDC 补上的是「令牌明确说这是发给你的、是关于谁的」，所以可以安全地用来登录。

**面试里这样说。** 「登录要用 OIDC 的 ID 令牌，不是 OAuth 访问令牌。我验证签名、iss、aud 等于我的客户端 ID、exp 和 nonce，再取 sub 作为用户标识；访问令牌只用来调资源 API。」

**易错。**
- **用访问令牌当登录凭证：** 令牌可被其他应用重放。
- **不验证 aud：** 别的客户端的 ID 令牌也被接受。
- **用邮箱当唯一标识：** 邮箱会变，应使用 iss 加 sub。
