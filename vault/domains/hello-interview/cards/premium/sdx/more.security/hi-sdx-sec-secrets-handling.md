## Q
**服务凭据放哪里，什么比静态密钥更好**｜补充 · 安全 · 追问

面试官：「数据库密码、第三方 API 密钥这类服务凭据，放在哪里才合理？有什么办法能彻底不用静态密钥？」

## A
**结论。** 不能放在代码、镜像或明文环境文件里。放进密钥管理服务（Vault、云厂商的 Secrets Manager），集中保管、可审计、可自动轮换。更好的做法是消灭静态密钥：用工作负载身份换取短期凭据。

**要点。**
- **不要放哪：** 代码仓库、镜像、明文环境文件，它们会通过仓库、日志、崩溃转储泄露。
- **密钥管理服务：** 集中存储，访问有审计，支持自动轮换，应用启动时拉取或动态租约。
- **工作负载身份：** IAM 角色、SPIFFE、平台间的 OIDC 联合，按「这个工作负载是什么」签发短期凭据。
- **效果：** 没有长期凭据可偷，也不用轮换。
- **网格内通信：** 用 mTLS 双向认证并加密，而不是只在边缘加密。

**为什么。** 秘密越久、越多地方存放，泄露概率越大。短期且按身份签发的凭据，把泄露窗口压缩到几分钟。

**面试里这样说。** 「凭据不进代码和镜像。能用工作负载身份的地方，让平台签发短期凭据，不存任何静态密钥；不得不用静态密钥时放密钥管理服务，自动轮换并审计访问。」

**易错。**
- **密钥写进环境变量文件提交仓库：** 一次推送就泄露。
- **所有服务共用一个密钥：** 无法定位泄露源，也无法单独撤销。
- **密钥管理服务没有访问审计：** 泄露后不知道谁取过。
