## Q
**密码和 API 密钥：存储方式为什么不同**｜补充 · 安全 · 必会

面试官：「要存用户密码，也要校验高熵的 API 密钥。各用什么算法和参数？为什么两者不同？」

## A
**结论。** 密码用慢速、占内存的 KDF：首选 Argon2id（OWASP 基线内存 19 MiB、迭代 2、并行 1），校验耗时按服务能承受的登录量调到几百毫秒以内（不超过 1 秒）。API 密钥是 128 位以上随机数，直接 SHA-256 存哈希就对，慢哈希只会拖慢每个请求。

**要点。**
- **为什么要慢：** 人选的密码只有二三十位熵，数据库泄露后唯一的防线是让每次猜测很贵。
- **为什么要占内存：** 内存硬度（memory-hardness）限制 GPU 和专用芯片的并行度，否则它们每秒能算几十亿次 SHA-256。
- **算法顺序：** Argon2id 为首选；bcrypt 作为旧系统，工作因子至少 10，注意只处理前 72 字节；Argon2 不可用时用 scrypt。
- **盐与胡椒：** 每用户随机盐防彩虹表和相同密码被看出；可选胡椒放在密钥管理服务或硬件模块里，不放数据库。
- **API 密钥：** 随机 128 位无法暴力破解，用 SHA-256 存哈希，只展示一次；慢 KDF 对每个请求加 100 毫秒毫无收益。
- **容量检查：** 每次登录校验是故意的 CPU 开销，要对照峰值登录量，防止登录风暴打满机群。

**为什么。** 防御思路由输入熵决定：低熵输入靠增加每次猜测成本，高熵输入本身已经猜不出来，不需要额外成本。

**面试里这样说。** 「密码用 Argon2id，内存 19 MiB、迭代 2、并行 1 起步，调到每次校验几百毫秒以内，并按峰值登录量核对 CPU。API 密钥是长随机数，直接 SHA-256 存哈希，显示一次。」

**易错。**
- **用 SHA-256 或 MD5 存密码：** GPU 每秒几十亿次，泄露后秒破。
- **给 API 密钥也用 bcrypt：** 每个请求多 100 毫秒，没有安全收益。
- **忽略登录风暴：** 慢哈希叠加高峰登录把服务打满。
