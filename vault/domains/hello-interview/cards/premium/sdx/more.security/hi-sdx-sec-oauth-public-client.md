## Q
**公共客户端：藏不住密钥**｜补充 · 安全：认证、OAuth、密码、授权 · 必会

手机 App 和纯前端单页应用（SPA）也用授权码流程。它们能在兑换 code 时用 client_secret 证明自己吗？为什么？这留下了什么漏洞？

## A
**结论。** 不能。它们的代码装在用户设备上，任何人都能反编译出密钥，所以叫公共客户端（public client）；有自己的后端保管密钥的才是机密客户端（confidential client）。没有可信的密钥，谁截获了 code 谁就能换到令牌，这个洞由 PKCE 来补。

**要点。**
- **机密客户端：** 密钥只在自己的服务器上，比如传统 Web 应用的后端。
- **公共客户端：** 手机 App、SPA、桌面程序，打包进去的密钥等于公开。
- **真实的截获方式：** 手机上的恶意 App 注册同一个自定义回调地址（URL scheme），抢走带 code 的回调。
- **PKCE 的思路：** 把固定的密钥换成每次登录现场生成的随机数，只有发起这次登录的客户端知道它。

**面试里这样说。** 「移动端和 SPA 是公共客户端，存不住 client_secret，所以兑换 code 时靠 PKCE 证明自己：每次登录生成一个随机 verifier，先只发它的哈希，兑换时再出示 verifier 本身。」

**易错。**
- **把密钥打包进 App：** 一反编译就拿到了。
- **以为 HTTPS 能防截获：** 截获发生在设备内部的跳转环节，不在网络上。
