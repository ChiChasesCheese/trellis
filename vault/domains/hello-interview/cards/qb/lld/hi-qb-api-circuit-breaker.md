## Q
**熔断器（Circuit Breaker）**｜低层设计｜被报告 1 次 · Reddit · 最近 2026-07 · 先修见：可配置淘汰策略的内存键值存储 · 模式：实体状态机与合法迁移、下游保护：熔断、隔离与扇出预算、类设计中的并发：锁粒度与线程模型、时间注入与可测试性

设计一个用于保护外部依赖调用的熔断器：有三种状态（关闭 CLOSED、打开 OPEN、半开 HALF_OPEN），失败阈值、打开持续时间可配置，状态按规则自动转换；线程安全；熔断时可以返回降级（fallback）结果；并暴露指标（成功数、失败数、被拒绝数）以便监控服务可靠性。

讲出：难点一句话、必讲的决策、取舍、级别期望。

## A
**一句话。** 熔断器是小状态机：下游持续失败时快速失败，冷却后用少量探测请求判断恢复；难点是并发下状态转换的正确性。

**60 分钟路线。**

| 时间 | 做什么 |
|---|---|
| 0–8 分 | 问清需求，定接口 `call(fn, fallback)`，口述三状态四条转换 |
| 8–15 分 | 写 `State`、配置和字段 |
| 15–40 分 | 写 `call`、`_try_acquire`、`_on_result`，边写边讲锁和半开名额 |
| 40–45 分 | 注入假时钟，跑四条转换 |
| 45–60 分 | 追问迟到结果、失败判定；口述降级、指标、粒度、与重试关系 |

**状态与设计。** 关闭连续失败达阈值 → 打开；打开冷却到 → 半开；半开探测成功 → 关闭，失败 → 打开。`call` 三步：锁内取许可（半开在途探测达 `half_open_max_calls` 就拒绝）；锁外调下游；锁内回报结果。每次转换让代号 `_gen` 加一。

**必讲。**
- **半开惊群：** 冷却一结束所有线程冲向刚恢复的下游，所以半开只放 `half_open_max_calls` 个探测（通常 1），其余拒绝或降级；1 个最保守但恢复慢。
- **迟到的旧结果：** 许可携带领取时的代号，回报时不一致就只计指标、不改状态；否则在途数会减成负数，或旧失败被当成探测失败。
- **不持锁调下游：** 慢调用不会让线程排队；代价是回报时重新加锁并核对代号。

**取舍。**
- 失败判定：连续失败数简单，但低流量、失败穿插成功时不灵，生产用滑动窗口失败率（Resilience4j）；慢调用也算失败，前提是有超时。
- 降级要快且不依赖同一下游；顺序一般是限流 → 熔断 → 超时 → 重试，重试不能绕过熔断。
- 一个下游一个熔断器，配舱壁；多实例各自维护，不共享状态。

**级别。** 中级：三状态机加阈值冷却。高级：线程安全、不持锁调下游、半开限探测、降级与指标。资深：代号防污染、滑动窗口与慢调用、退避冷却、与限流重试超时舱壁组合。
