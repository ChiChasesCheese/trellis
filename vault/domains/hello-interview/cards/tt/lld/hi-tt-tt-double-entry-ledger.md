## Q
**复式账本（类设计）**｜低层设计｜支付类设计练习 · 先修见：可配置淘汰策略的内存键值存储、聊天与即时通讯系统 · 模式：只追加账本与派生余额、金额、取整与不可变值对象

实现一个复式账本（double-entry ledger）：`post(entry)` 写入一条分录，分录由若干条腿（posting）组成，每条腿是（账户、币种、带符号金额）；`balance(account, currency)` 返回余额；`reverse(entry_id)` 冲正一条已有的分录；同一条分录被重复提交时只记一次。面试官会继续追问：冻结与可用余额、不允许透支、并发、每秒几万次写入的热点账户、历史某一时刻的余额、怎么证明账没有被改过、跨币种转账。

讲出：难点一句话、必讲的决策、取舍、级别期望。

## A
**一句话。** 账本由两样东西构成：只追加、永不修改的分录日志（唯一事实来源）和随每次写入同步更新的派生索引（余额、历史余额）；正确性落在三条不变量：每条分录借贷平衡、余额等于腿之和、纠错只靠新分录。

**必讲。**
- **日志加派生索引：** 只存余额字段，改错无法追溯，两次更新间崩溃钱会凭空出现或消失，也证明不了总账是平的；只存日志则读余额要求和 O(腿数) → 日志加余额索引，读快可审计，代价是索引必须和日志同临界区更新（生产中同一数据库事务）；独立的 `verify` 从日志重算每账户余额并要求各币种全账户之和为 0，定期发现索引与日志分叉。例：充值 100.00 美元后送礼 30.00，钱包余额 −7000 展示为可用 70.00；冲正送礼得第 3 条，余额回到 −10000，日志没有一条被改动。
- **冻结与不透支：** 转账处理期间金额要先占住，防花两次 → 冻结表 `(账户, 冻结 ID) → 金额`，可用余额 = 账面展示值 − 冻结合计，冻结与释放以冻结 ID 为键幂等；“写入后可用余额不小于 0”必须与写入同锁或同事务，否则两个并发转账各自检查通过一起透支；数据库里 `UPDATE … SET balance = balance - x WHERE balance >= x`，影响行数 0 就是不足。只对用户类账户不允许透支，内部账户（应收渠道款）代表在途资金可以为负。
- **并发与热点：** 全局锁让写入全串行 → 按账户加锁，一条分录涉及多账户时按账户 ID 排序加锁，避免相反顺序死锁（`SELECT … FOR UPDATE` 按固定顺序）；平台手续费这类每秒几万笔的热点账户，单行余额成锁热点 → 分片追加分录，后台周期性折叠增量进快照，读余额取最近快照加增量，读略慢换写水平扩展。

**取舍。**
- 错误分录永远不改：写冲正分录再写正确分录，都带原因和操作人。
- 带符号金额而非借贷两列：和为 0 是最易检查的不变量，代价是要记各账户正常余额方向，展示时翻转。
- 幂等：分录 ID 由业务意图派生，账本层 `(分录 ID)` 唯一约束兜底，同 ID 同内容返回原序号，同 ID 不同内容抛 `ValueError`。
- 历史余额：每次更新追加“序号，更新后余额”，二分查找。
- 防篡改：存储层只开放追加；分录按块做哈希链；“应收渠道款”与渠道结算文件对账，结算后应回到 0。
- 跨币种经 FX 中间账户用两组各自平衡的腿，记汇率和报价编号，汇兑差额进汇兑损益账户。

**级别。** 高级：日志与派生索引、冲正代替修改、历史余额、冻结与可用余额、按账户排序加锁避免死锁。资深：热点账户分片追加与快照、哈希链与核对、多币种与 FX 账户、事务与条件更新写法、冷热分区与对账闭环。
