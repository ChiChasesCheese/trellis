## Q
**金额、取整与不可变值对象 (Money / Rounding / Immutable Value Objects)**｜跨题模式 · 对比

六道题都涉及金额或不可变值，但"守恒"的对象不同。请逐题说明取整和不变量放在哪里。

## A
| 题 | 在这里怎么用 | 为什么和别的题不同 |
|---|---|---|
| [[tt-installment-plan\|分期计划生成器]] | 各期本金之和恰好等于本金，取整误差由最后一期吸收；免息时余数分给前几期；全程整数加 `Decimal` | 是纯函数问题（同样输入同样输出，不读当前时间）；各币种小数位不同，到期日每期从起始日出发而不是逐期累加 |
| [[tt-billing-tax-engine\|计费 / 计税引擎]] | 规则内部全精度，每一行金额只在边界取整一次，每行记录所用的规则版本 | 取整位置影响多条规则链：税算在费用之上，后面的规则看到的是前面已取整的行；500 分的费用精确值 44.5，银行家舍入得 44，四舍五入得 45 |
| [[tt-double-entry-ledger\|复式账本]] | 带符号金额（借方为正、贷方为负），使"分录各币种的腿之和为 0"成为最简单的检查；跨币种经 FX 中间账户 | 守恒是对一组分录的约束，而不是对一次计算；纠错靠冲正分录，日志只追加 |
| [[date-time-management\|日期时间库]] | 全部做成不可变值对象，字段存规范化整数，可作键、线程安全，月份运算有明确语义（月末截断） | 不可变的是时间概念，不是金额；代价是每次运算产生新对象 |
| [[tt-live-gift-coin-settlement\|直播虚拟礼物：金币记账与主播结算]] | 整数 micro 单位（万分之一金币）累加，只在周期汇总值取整一次，余数记入下一周期 | 要在流式的实时展示和周结算的批处理之间保持一致：每份向下取整会损失 18.4% 并累成系统性误差 |
| [[tt-wallet-ledger-service\|钱包与复式账本服务]] | 多币种账本按币种各自平衡，分录金额是整数最小单位加币种 | 币种决定小数位，余额按币种分别维护，不同币种的分录不放进同一个守恒集合 |

**共同点：** 整数、只取整一次、不可变、可复现。**差异来自守恒的对象：** 一次拆分（分期）、一条规则链（计费）、一组分录（账本）、两条计算路径（流式与批处理）。
