## Q
**金额、取整与不可变值对象 (Money / Rounding / Immutable Value Objects)**｜跨题模式 · 怎么选

面对一道涉及金额的新题，怎么决定表示、取整位置和守恒检查？请按判断信号分支，各举一题。

## A
1. **一个总额要拆成多份？**（分期、分成）用守恒分摊：先整除，余数由固定位置吸收（最后一期，或分给前几期），测试"各份之和等于总额"。例：[[tt-installment-plan|分期计划生成器]]。
2. **多条规则依次计算？**（费用、税、封顶）规则返回全精度，引擎在边界对每行取整一次；取整方式写进规范，不留给调用方；每行记录规则版本以便复现。例：[[tt-billing-tax-engine|计费 / 计税引擎]]。
3. **钱在账户之间移动？** 带符号金额，每条分录各币种的腿之和为 0；纠错写冲正分录；跨币种经 FX 中间账户，汇兑差额进入汇兑损益。例：[[tt-double-entry-ledger|复式账本]]。
4. **同一笔钱有两条计算路径？**（实时展示加周结算）统一用整数最小单位，批处理才是真相；只在周期汇总值取整一次，余数记入下一周期，并比较两者的差异。例：[[tt-live-gift-coin-settlement|直播虚拟礼物：金币记账与主播结算]]。
5. **有多个币种？** 余额按币种分别维护，小数位由币种决定，换汇用带编号和有效期的报价。例：[[tt-wallet-ledger-service|钱包与复式账本服务]]。
6. **对象要被共享、作键或跨线程使用？** 做成不可变值对象，运算返回新对象；接受每次运算产生新对象的代价。例：[[date-time-management|日期时间库]]。

**取整方式的选择：** 银行家舍入在大量数据上无偏，四舍五入会让总额系统性偏高；具体由合同和监管决定。
