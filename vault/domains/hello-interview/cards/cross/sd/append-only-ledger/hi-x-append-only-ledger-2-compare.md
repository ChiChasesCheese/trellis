## Q
**只追加账本与派生余额**｜跨题模式 · 对比

同样是“只追加的账本”，复式账本类设计、钱包服务、直播金币结算、支付批量结算、菜品打赏、分期计划、股票交易这几道设计题各把账本用在哪里，重点和别的题有什么不同？

## A
| 题 | 在这里怎么用 | 为什么和别的题不同 |
|---|---|---|
| [[tt-double-entry-ledger\|复式账本（类设计）]] | 日志加派生余额索引，带符号金额，冻结与可用余额，用 (账户, 币种, 序号) 做索引 | 内存里的类设计，重点是三条不变量和历史余额，不涉及分片 |
| [[tt-wallet-ledger-service\|钱包与复式账本服务（余额、冻结、转账、多币种）]] | 钱包余额是投影；同步路径条件更新扣款并同事务写分录，其余汇总异步 | 服务级：分片、热点账户改为只追加加快照，跨分片转账走“在途”账户加幂等，不用分布式事务 |
| [[tt-live-gift-coin-settlement\|直播虚拟礼物：金币记账与主播结算]] | 观众钱包强一致扣币写流水；主播收益从事件重算；退款写负的冲销流水 | 把同步的钱和异步的账拆成两条路径，实时数字是估计，周结算重算对上每一分钱 |
| [[payment-batch-processing\|设计支付处理系统（授权冻结 + 每日批量结算）]] | 冻结、请款、结算每步写账本分录，结算后账本、网络结算报告、银行到账三方比对 | 面对外部卡组织，重点是批量不漏不重，而不是余额读写热点 |
| [[food-item-reviews\|设计带打赏的菜品评价系统（点评 + 投票 + 达标付款）]] | 只给达标的付款里程碑建账，(评论, 里程碑) 为主键保证只付一次 | 账本只记低频的钱；高频票数可丢可重算，不进账本 |
| [[tt-installment-plan\|分期计划生成器]] | 变更生成新计划并保留旧计划 | 追加的是计划版本而不是分录；各期本金之和守恒，取整误差由最后一期吸收 |
| [[stock-trading-platform\|设计简化版股票交易平台（券商端，限价单）]] | 下单冻结资金，成交按执行报告记流水，订单、成交、资金流水只追加 | 真相的一半在外部交易所，要靠有状态订单机和对账与它对齐 |
