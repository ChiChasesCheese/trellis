## Q
**实体状态机与合法迁移**｜跨题模式 · 共性

预订、订单、对局、熔断器这类业务实体，为什么要建成有限状态机（Finite State Machine）？状态机怎样让重试、过期和并发都只能走合法路径？

## A
**机制。** 把实体的生命周期写成显式的状态集合加一张迁移表：只有表里列出的 (当前状态, 事件) 才允许跳转，终态没有出边。每次迁移是一次“带前置状态条件”的原子动作：

- 数据库里是 `UPDATE ... SET status=新 WHERE id=? AND status=旧`，看影响行数，为 0 说明状态已被别人改过；
- 内存里是在锁内核对当前状态，或者让一个单线程独占该实体。

**共同的不变量。** 同一个实体同一时刻只有一个迁移能成功；重复事件（重试、重复回调）发现已在目标状态时变成无操作；非法迁移被拒绝或丢弃。

**不用它会怎样。** 过期任务和付款请求同时到达，各自先读后写，同一份库存被释放两次，或者已成交的订单又被标成已取消。状态散落在多个布尔字段里，崩溃重启后无法判断做到哪一步。
