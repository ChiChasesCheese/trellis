## Q
**实体状态机与合法迁移**｜跨题模式 · 怎么选

新题里出现“有生命周期的实体”，怎么决定保护状态迁移的手段？请按推进状态的来源和数据所在的位置分情况说明，并各举一例。

## A
| 信号 | 手段 | 例子 |
|---|---|---|
| 状态在数据库里，用户操作与定时任务会同时到 | 每次迁移一条 `WHERE status=旧` 的条件更新，按影响行数判胜负；释放动作幂等 | [[event-ticket-booking\|活动票务预订后端（防超卖的 REST 服务）]] |
| 全部事件发生在同一个实体上，且规模小、要强一致 | 唯一写者：按实体哈希到一个所有者，单线程队列串行处理，宕机后从日志重放 | [[online-chess-platform\|在线国际象棋平台]]、[[elevator-design\|设计电梯系统（面向对象，可运行的代码）]] |
| 状态被外部系统推进（交易所、供应商） | 状态里显式有“已发送、等待外部”，按唯一报告号去重，等最终回执再做不可逆动作 | [[stock-trading-platform\|设计简化版股票交易平台（券商端，限价单）]]、[[hotel-booking-system\|酒店预订系统（Expedia 型聚合与自营）]] |
| 不同角色可以做不同迁移 | 迁移表带“谁可以做”，权限在服务方法内检查 | [[job-board-platform\|招聘信息平台（Job Board）]] |
| 内存里的类设计，并发调用 | 迁移集中在一个类里，锁内核对状态；怕迟到的旧结果时给状态加代号 | [[api-circuit-breaker\|熔断器（Circuit Breaker）]] |
| 一个实体的状态依赖另一个实体 | 各自一张迁移表，跨在中间的资源用预留、提交、释放三步衔接 | [[beverage-vending-system\|多地点饮品自助售卖系统]] |
