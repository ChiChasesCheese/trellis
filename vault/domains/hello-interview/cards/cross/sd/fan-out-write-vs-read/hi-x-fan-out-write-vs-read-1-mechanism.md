## Q
**写扩散与读聚合**｜跨题模式 · 共性

一份内容要送到很多接收者手里时，有「写扩散」和「读聚合」两条路。它们各自把代价放在哪里，选择时有哪些共同的不变量？

## A
**两条路。**
- **写扩散（fan-out on write）：** 写入时把内容的 ID 推进每个接收者的收件箱。读取只是读一个列表，很快；写放大等于接收者数量。
- **读聚合（fan-out on read）：** 只写一份，读取时再去各个来源取最近内容并归并。写便宜；读的代价等于关注的来源个数。

**代价的决定因素。** 读写比、接收者数量是否极不均匀（有没有一个来源对应千万读者）、读者之间是否共享同一份内容。

**共同的不变量。**
1. 收件箱只存 ID，不存完整内容：编辑、删除只改内容库一处，读取时过滤已删除的 ID。
2. 热点对象单独处理：粉丝极多的来源走另一条路（读时再拉），其余走写扩散，这就是混合方案。
3. 收件箱是缓存，丢了必须能用读聚合重建，这是正确性的兜底。
4. 扇出的投递要幂等：同一个 ID 在有序集合里只有一份，失败的分块可以重试。
