## Q
**熔断器 · 不持锁调用下游**｜必会 · 出自：熔断器 › 整体设计

熔断器的 `call` 在判断放行和调用下游时，锁应该怎么用？如果在锁内直接调用下游会出什么问题，代价又是什么？

## A
**要点。** `call` 分三步：锁内取许可（`_try_acquire`）、锁外调用下游、锁内回报结果（`_on_result`）。
**为什么。** 锁内调用下游时，一个慢调用会让所有线程排队，熔断器自己变成瓶颈。
**代价。** 计数更新与调用不在同一个临界区，所以回报结果时必须重新加锁，并核对领取许可时的状态代号。
