## Q
把同一个限流（rate limit）装饰器应用到两个不同的函数上，如果装饰器内部用一个模块级全局变量记录「上次调用时间」，会出什么问题？应该怎么修？

## A
两个被装饰的函数会共享同一份计数状态，相当于把它们的调用频率合并限流，而不是各自独立限流——一个函数触发了限流，另一个完全无关的函数也会被卡住。正确做法是把限流状态（比如令牌桶剩余数量、上次调用时间）保存在装饰器返回的 `wrapper` 闭包里，或者放进类装饰器实例的属性里，让每次 `@rate_limit(...)` 应用产生一份独立状态；多线程环境下还要给这份状态加锁，否则并发调用可能读到脏的计数。
