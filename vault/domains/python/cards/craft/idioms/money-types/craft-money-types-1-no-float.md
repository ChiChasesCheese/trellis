## Q
**金额类型 · 为什么金额不能用 float，`Decimal(0.1)` 为什么也不对**｜写法

折扣引擎把 "19.99" 元转成分，最直接的写法是 `int(float("19.99") * 100)`。哪里会出错？既然有 `Decimal`，写 `Decimal(19.99)` 是不是就安全了？

## A
**要点。** `float` 是二进制浮点数（binary floating point）：像 0.1 这样的十进制小数在二进制里是无限循环的，只能存一个最接近的值，运算后误差会显形：`19.99 * 100` 是 `1998.9999999999998`，`int()` 截断就少了 1 分。`Decimal` 是十进制浮点，可以精确存十进制小数，但**必须从字符串构造**：`Decimal(0.1)` 是把 float 已有的误差原样展开，`Decimal('0.1')` 才是你写下的数。

```python
def to_cents(text: str) -> int:
    """把 "19.99" 这样的十进制字符串精确转成分，绝不经过 float。"""
    return int((Decimal(text) * 100).quantize(Decimal(1), rounding=ROUND_HALF_UP))

print("0.1 + 0.2 =", 0.1 + 0.2)
print("19.99 * 100 =", 19.99 * 100, "-> int() =", int(19.99 * 100))
print("Decimal(0.1)   =", Decimal(0.1))        # 把 float 的真实二进制值原样展开
print("Decimal('0.1') =", Decimal("0.1"))      # 从字符串构造才是你写下的数
print("to_cents('19.99') =", to_cents("19.99"))
```

实际输出：

```
0.1 + 0.2 = 0.30000000000000004
19.99 * 100 = 1998.9999999999998 -> int() = 1998
Decimal(0.1)   = 0.1000000000000000055511151231257827021181583404541015625
Decimal('0.1') = 0.1
to_cents('19.99') = 1999
```

**为什么。** 钱的要求是「你写下的数就是账上的数」。所以输入入口（文本、JSON、表单）一律以字符串或整数进入，一次转成整数分，之后整个系统里只流转整数。

**易错。** `Decimal(str(19.99))` 看上去能用，其实只是 `str()` 帮你四舍五入了；上游若已是 `float` 运算的结果，误差已经产生。金额从 float 进来就是 bug，要在边界处拒绝，而不是在这里修补。
