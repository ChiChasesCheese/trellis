## Q
**先校验后提交 · 从一个函数到两阶段提交（2PC）**｜架构

账本的 `post` 在一个进程里「先校验后提交」。同一件事发生在两个数据库之间（转账的借方在库 A，贷方在库 B）时，「不会再失败的提交段」还能保证吗？形状有什么变化？

## A
**要点。** 形状没变，成本变了。单进程里校验段只读、提交段是内存赋值，所以「提交不会失败」几乎免费。跨机器时，校验变成准备（prepare）：每个参与者要真的锁住资源并把承诺写盘，之后才能保证 commit 不会失败。

```
post : validate ─▶ | ─▶ commit
2PC  : prepare  ─▶ | ─▶ commit
```
左边是只读检查，右边必须不再失败；`|` 就是那条分界线。两阶段提交里，prepare 之后参与者已经承诺，commit 只能重试到成功。

**为什么。** prepare 的含义是「我已经锁住并持久化，你让我 commit 我一定能 commit」；它对应校验段加上「保留结果」这一步。

**代价。** 参与者在 prepare 到 commit 之间一直持锁，协调者宕机会阻塞它们（阻塞协议）；所以实践里常改用单库事务加发件箱（outbox），或补偿式的长事务。

**信号。** 看到「两个以上的系统都要成功」时，先问：能不能把校验放到同一个地方？不能的话，才引入 prepare/commit 或补偿。
