## Q
**代号令牌 · 令牌只比相等就够，还是需要有大小**｜模式

熔断器的代号、叫车的要约 ID 只做相等比较；分布式锁的 fencing token 却要求单调递增、拒绝「更小的」。什么时候只需要相等，什么时候需要有序？

## A
**要点。** 看谁是「当前」的仲裁者。如果当前这一轮只存在一个地方、且是同一把锁保护的（一个进程里的熔断器、一个字典里的司机），相等就够：不等就是旧的。如果有多个节点都可能自称当前（多个客户端各自以为自己持有锁），接收方要自己判断新旧，就需要单调递增，并记住见过的最大值。

```python
# 相等：当前这一轮只有一个仲裁者（同一把锁里）
if gen != self._gen: return

# 有序：接收方自己判断新旧
if token < self.max_token: return False   # 来自旧租约的写入
self.max_token = max(self.max_token, token)
```

**代价。** 有序令牌要求发令牌的一方保证单调（并要持久化，否则重启后回到 1），接收方要记住最大值；相等令牌不需要这些，但前提是只有一个人说了算。

**易错。** 用时间戳当有序令牌：多台机器的时钟不同步，旧租约的时间戳可能反而更大。令牌应来自发放租约的那个单点，而不是客户端的时钟。

**信号。** 看到「谁是当前的」这个问题，先问：判断新旧的人，和发出令牌的人，是不是同一个。
