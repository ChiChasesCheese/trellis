## Q
**惰性删除堆 · 「弹出过期的」为什么依赖时间单调向前**｜模式

额度账户有若干额度包，每次扣费用最早到期的包；到期的包浮到堆顶就弹掉，之后不会再用。事件如果乱序到达（先处理时刻 12 的扣费，再处理时刻 3 的），这个弹出还成立吗？

## A
**要点。** 不成立。弹出是不可逆的，它隐含「时间只往前走，已过期的包以后不会再有效」。乱序时处理 12 点的扣费会把 10 点到期的包永久弹掉，之后补处理的 3 点扣费就找不到它了。解法是不在乱序流上弹：先按（时间，类型，id）排序，再顺序重放。

```python
for at, need in charges:                     # 按列表顺序处理
    while heap and heap[0][0] <= at:
        heapq.heappop(heap)                  # 惰性删除：假设时间只往前走
    out.append(... if heap and heap[0][2] >= need else "额度不足")
```

一个额度包（到期 10，额度 5），两笔扣费：

```
按时间顺序: ['t=3 扣5: 成功', 't=12 扣1: 额度不足']
乱序到达   : ['t=12 扣1: 额度不足', 't=3 扣5: 额度不足']
先排序再重放: ['t=3 扣5: 成功', 't=12 扣1: 额度不足']
```

**为什么。** 额度账户把余额和每笔扣费的分配做成「对事件排序后重放」的纯函数，乱序到达的事件只需重新算一遍就自然生效，每个包最多进出堆各一次。

**易错。** 任何「弹出就丢」的惰性删除，都在悄悄依赖某种单调性。要问清楚：谁保证它单调。
