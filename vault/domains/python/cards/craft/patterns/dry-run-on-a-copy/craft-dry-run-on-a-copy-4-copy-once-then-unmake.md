## Q
**在副本上试运行 · 搜索时是每个节点复制，还是复制一次再撤销**｜架构

四子棋机器人向前看 4 步，每步 7 个落点，要探索几千个局面。每探索一个局面都复制一份棋盘，和只复制一次、在副本上落子再撤销，各自的代价是什么？

## A
**要点。** 试运行有两个层次。保护调用方：`best_move` 开头 `work = game.copy()` 复制一次，调用方的棋局永远不变，这是「副本」。搜索内部：在 `work` 上 `drop` → 递归 → `undo`，每个节点只改几格再改回来，不再复制。

```python
work = game.copy()                    # 一次完整复制：保护调用方
for column in order:
    work.drop(column)                 # 落子
    score = -_negamax(work, depth - 1, -_INF, -alpha)
    work.undo()                       # 撤销：棋盘回到进入循环时的样子
```

**为什么。** 每节点复制的成本是「节点数 × 棋盘大小」，还会产生大量垃圾对象；落子/撤销是「节点数 × 一步的大小」。前提是 `undo` 必须精确回滚（见 make-unmake 那张卡），否则搜索一路积累的误差无法发现。

**代价。** 这个 `copy` 是通过回放落子历史造出来的，成本随已下步数线性增长，但只发生一次。落子/撤销要求 `drop` 和 `undo` 严格对称，多一个字段就要两边同时改。

**什么时候不用撤销。** 状态是不可变值、每一步都返回新状态（树搜索的函数式写法）：直接传新对象，不需要撤销，代价是分配。状态太复杂、撤销很难写对时，复制反而是更安全的选择。
