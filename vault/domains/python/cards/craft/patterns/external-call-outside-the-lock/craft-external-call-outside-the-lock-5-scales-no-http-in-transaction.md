## Q
**外部调用不持锁 · 数据库事务里为什么不能发 HTTP**｜模式

进程里「不在锁里调外部」，放到服务里对应什么？在一个数据库事务中间调支付网关，成功后再提交事务，有什么隐患？有什么替代方案？

## A
**要点。** 事务就是跨请求的锁：行锁、连接都被占着。事务里调 HTTP，慢依赖会把行锁和连接池一并占住；网关成功而事务提交失败，钱扣了单没有。替代：用状态机把「占位—调用—提交」拆成几个短事务，重试加对账。

```
txn 1: 订单 NEW  -> CHARGING   （占位，持久化，提交）
call : 调支付网关，带订单号做幂等键（不在任何事务里）
txn 2: CHARGING  -> PAID / FAILED   （提交结果）
对账:  定期扫描卡在 CHARGING 的订单，向网关查询真实结果
```

**对应关系。** 内存里的「占位」是 `CHARGING` 状态；窗口里的「凭证」是订单号和幂等键；占位的「过期」是对账任务；锁外调用失败后的补救不再是 `finally`，而是重试和补偿。

**代价。** 状态变多、要写对账；换来慢网关不能拖垮数据库。网关返回超时时结果是未知的，不能直接标记失败，只能查询确认（见幂等键与 saga）。

**信号。** 流程里既有「要么全做要么不做」的本地写，又有一次不可撤销或慢的外部调用。
