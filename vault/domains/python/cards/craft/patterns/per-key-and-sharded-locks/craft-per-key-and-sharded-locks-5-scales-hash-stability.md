## Q
**每对象一把锁与分片锁 · 从分片锁到跨机器分片**｜模式

分片锁用 `hash(key) % N` 选锁。把这个想法放大到多台机器——按 key 分到不同的节点——还能直接用 Python 的 `hash` 吗？热点 key 怎么办？

## A
**要点。** 不能。字符串的 `hash()` 在每个 Python 进程里用随机种子，同一个字符串在不同进程算出的值不同，只在进程内部一致。进程内分片锁没问题，跨进程或跨机器的分片必须用稳定的哈希（如 CRC32 或 MD5）或一致性哈希（consistent hashing）。

```
$ python3 -c 'print(hash("alice") % 16)'
5
$ python3 -c 'print(hash("alice") % 16)'
0
```

同一个字符串，两次进程启动，得到不同的分片号（实际输出，随机种子每次不同）。

**尺度对照。** 一个对象一把锁 → 一个限流器内部的 N 把分片锁 → 多个实例按用户哈希分片的限流服务 → 数据库按主键分区。越往外，分片函数越要稳定、可迁移（加节点时尽量少搬数据）。

**变化。** 进程内跨分片的操作用「按分片号排序加锁」；跨机器的跨分片操作变成分布式事务或放弃原子性，所以设计时尽量让一次操作只落在一个分片。

**易错。** 热点 key（一个用户占了绝大多数请求）无法靠分片分散，所有请求仍落同一个分片；要换成对该 key 单独处理，或在 key 内再拆子 key。
