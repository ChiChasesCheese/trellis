## Q
**半开区间 · 按小时（或按结算周期）分桶统计，边界上的事件为什么会被算两次**｜写法

配送员薪酬按结算周期汇总，周期首尾相接：`[0,60)`、`[60,120)`……恰好在整点发生的事件（时间戳 60）该归哪个周期？如果每个周期都写成 `a <= t <= b`，各周期的合计会等于事件总数吗？

## A
**要点。** 相邻周期要**分割**时间轴：每个时刻恰好属于一个周期。半开区间做到这一点；闭区间不行，边界上的事件同时落进前一个周期的终点和后一个周期的起点，被算两次，各周期合计大于总数，对账永远对不平。结算周期因此是 `[start, end)`：送达时间落在周期内的订单才统计，整单的钱记在送达那一天所在的周期。

```python
events = [0, 30, 60, 60, 90, 120, 150, 180]            # 时间戳（分钟），60、120、180 恰好落在边界上
buckets = [(0, 60), (60, 120), (120, 180), (180, 240)]  # 相邻的计费周期

closed = [sum(1 for t in events if a <= t <= b) for a, b in buckets]      # [a, b]
half   = [sum(1 for t in events if a <= t < b) for a, b in buckets]       # [a, b)
print("闭区间每段:", closed, "合计", sum(closed), "（事件总数", len(events), "）")
print("半开区间每段:", half, "合计", sum(half))

xs = list("abcdefgh")                                  # Python 自己就是半开的
print("xs[2:5]       =", xs[2:5], " 长度 =", 5 - 2)
print("xs[0:3]+xs[3:8]==xs:", xs[0:3] + xs[3:8] == xs, "（相邻切片首尾相接，没有重叠也没有缝）")
print("range(3, 6)   =", list(range(3, 6)))
```

事件时间戳 `[0, 30, 60, 60, 90, 120, 150, 180]`（共 8 个），周期 `[0,60) [60,120) [120,180) [180,240)`：

```
闭区间每段: [4, 4, 3, 1] 合计 12 （事件总数 8 ）
半开区间每段: [2, 3, 2, 1] 合计 8
xs[2:5]       = ['c', 'd', 'e']  长度 = 3
xs[0:3]+xs[3:8]==xs: True （相邻切片首尾相接，没有重叠也没有缝）
range(3, 6)   = [3, 4, 5]
```

**为什么。** 守恒：周期合计应等于全期总数（见守恒不变式那一叶）。半开区间保证这一点而不需要额外去重。SQL 里同一个约定写成 `ts >= :start AND ts < :end`，不要用 `BETWEEN`（`BETWEEN` 是闭区间，两端都含）。

**Python 本身就是半开的。** 切片 `xs[2:5]` 长度是 `5 - 2`，`xs[0:3] + xs[3:8] == xs`，`range(3, 6)` 是 3、4、5。首尾相接的切片没有重叠也没有缝，这正是半开约定被语言选中的理由。

**易错。** 时间戳精度：用 `datetime` 时，终点写成"当天 23:59:59"的闭区间会漏掉 23:59:59.5 的事件；写成下一天的 00:00:00 且不含，就没有这个问题。
