## Q
In a metrics monitoring system, why does a pure push-based collection model (targets actively send metrics to a collector) make it harder to tell whether a target is unhealthy, compared to a pull-based model (a collector scrapes each target on a schedule)?

## A
In a pure push model, the collector has no independent signal about a silent target: not receiving data could mean the application crashed, a network path dropped the push, or the collector itself throttled and discarded it — three very different causes that look identical from missing data alone. In a pull model, the collector actively initiates each scrape on a known schedule, so a failed or timed-out scrape is itself a first-class signal (typically recorded as its own `up=0` time series) generated by the collector's own observation, without needing a separate heartbeat mechanism layered on top.

## Q zh
在一个指标监控系统中，为什么纯推送（push）式采集模型（目标主动把指标发给收集端）比拉取（pull）式模型（收集端按计划周期性抓取每个目标）更难判断一个目标是否健康？

## A zh
在纯推送模型中，收集端对一个沉默的目标没有独立信号：收不到数据可能是应用崩溃了、也可能是网络丢了这次推送、也可能是收集端自己限流丢弃了——三种完全不同的原因，仅从数据缺失这一点上看完全一样。在拉取模型中，收集端按已知计划主动发起每次抓取，所以一次失败或超时的抓取本身就是收集端自己观测到的一等公民信号（通常记录为一条独立的 `up=0` 时间序列），不需要在上面额外叠加一套心跳机制。
