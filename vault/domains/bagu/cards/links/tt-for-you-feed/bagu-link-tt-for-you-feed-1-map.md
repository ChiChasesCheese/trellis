## Q
**短视频推荐信息流（For You） · 会被追问哪些八股**｜必会

设计短视频推荐信息流（For You）时，面试官最可能从哪几步下钻到基础知识？每一步问什么，怎么答？

## A
**基本回答。** 这是一个漏斗：十亿视频逐层缩到几个。基础是：向量近似检索做召回、粗排精排的逐层缩小、布隆过滤器做已看过滤、多级缓存读特征、超时与降级保证首页不白屏、Kafka 回流行为。

**下钻路线。**
- 十亿视频怎么召回 → 向量近似最近邻，分片的图索引或倒排加量化，[[b.agent.rag-vector-index|向量索引与向量数据库]]
- 召回几千条、精排几十条 → 粗召回加重排的漏斗，与 RAG 同构，[[a.agent.rag-pipeline|RAG 流水线]]
- 刷多久都不重复 → 最近观看集合加布隆过滤器，宁漏勿重，[[b.cache.bloom-filter|布隆过滤器原理与误判]]
- 用户和视频特征低延迟读 → 本地缓存加 Redis 两级，批量获取，[[b.cache.multilevel|多级缓存设计与冷启动]]
- 爆款视频的统计被反复读 → 本地缓存吸收热 key，[[a.cache.hot-key|热 key 的发现与处理]]
- 召回通道有慢的 → 每个通道设超时，到点用已返回的部分，[[b.protect.timeout|超时时间怎么设置]]
- 精排超时 → 逐层降级：粗排分数，缓存热门，地区兜底列表，[[b.protect.degrade|降级怎么做]]
- 行为实时回流 → 事件进 Kafka，流处理更新用户实时特征，[[b.mq.kafka-throughput|Kafka 为什么吞吐这么高]]

**业务场景。** 新视频没有任何行为数据，先进试探池推给少量用户；排序服务整体故障时，抖音式首页也要返回兜底列表，不能白屏。
**系统设计。** [[links.instagram|图片分享（Instagram）]]：Instagram 是关注关系的扇出，这里是全局召回；[[links.youtube|视频平台（YouTube）]]：同样的元数据热读，但没有冷启动试探和多目标排序。
