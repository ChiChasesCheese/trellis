## Q
训练流水线和普通 CI 流水线有什么不同？Airflow、Kubeflow Pipelines 和 TFX 这类工具各适合做什么？

## A
**和普通 CI 的区别：**
- **触发条件更多**：CI 由代码提交触发；训练流水线还会被**新数据到达**、定时计划、线上效果下滑触发。
- **运行时间与资源**：CI 几分钟到几十分钟，用 CPU；训练可能几小时到几周，要 GPU，失败重来很贵，所以需要检查点和步骤级缓存。
- **输出不是二值**：CI 的结果是通过或失败；训练的结果是一个指标数字，要和线上版本比较后才知道"算不算成功"。
- **产物更大**：一个模型文件几百 MB 到几百 GB，不能像构建产物那样随手存。
- **可复现更难**：数据会变、GPU 计算有随机性，同一配置重跑不一定得到完全相同的模型。

**编排工具**（orchestrator，按依赖关系调度一串任务的系统）：
- **Airflow**：通用的定时任务调度器，用 Python 定义有向无环图（DAG）。适合"每天凌晨跑一次"的数据和训练任务，生态最成熟，但对 GPU 和容器调度要借助其他组件。
- **Kubeflow Pipelines**：在 Kubernetes 上运行，每一步是一个容器，天然支持 GPU 节点、步骤缓存和产物追踪。适合已经用 Kubernetes 的团队。
- **TFX**：带一组 ML 专用的现成组件：数据取入、统计、模式推出、数据校验、转换、训练、评估、推送。它的评估组件把新模型和基线比较，只有达到阈值才把模型标记为"可上线"（blessed），推送组件只推送被标记的模型。
- 其他常见选择：Metaflow、Flyte、Dagster、云厂商的托管流水线。

**怎么选**：团队已有 Airflow 就从 Airflow 起步，把训练步骤提交到 GPU 集群；需要大量 GPU 作业和步骤缓存时用 Kubernetes 原生的方案。工具不是重点，**校验、评估对比、注册这三道检查必须在流水线里**才是重点。
