## Q
特征是不是越多越好？加一个特征会带来哪些隐藏成本？怎样决定删掉哪些特征？

## A
**不是。** 加特征通常能让离线指标涨一点，但每个特征都是一份长期负债：

- **线上延迟**：每个特征都要在请求时取到。一个需要实时查询外部服务的特征可能多花 5–20 ms，而排序的总预算只有 50 ms。
- **维护与故障面**：每个特征背后都有一条数据管道。上游表改了字段、延迟了一天、出现大量空值，模型都会悄悄变差。200 个特征就是 200 个可能的故障点。
- **训练与服务不一致**：特征越多，离线算法和线上算法对不上的机会越多。
- **泄漏风险**：新特征是否只用了预测时刻之前的信息，每个都要检查。
- **牵一发动全身**：特征之间相互影响，删一个特征可能让另一个特征的作用变化，难以单独评估。
- **合规**：有些特征（位置、年龄）涉及隐私或公平问题，需要审批和删除机制。

**怎样决定保留哪些：**
- **特征重要性**：看每个特征对预测的贡献（例如树模型的分裂增益，或 SHAP 值，一种把单次预测拆成各特征贡献的方法）。贡献接近 0 的列入候选。
- **消融实验**（ablation）：去掉一个或一组特征重训，看离线指标下降多少。下降小于随机种子带来的波动（例如 AUC 波动 ±0.001），就可以删。
- **算成本账**：特征带来 AUC +0.002，但要多一个实时服务、多 10 ms 延迟，常常不值得。
- **定期清理**：给每个特征记录负责人和上线时间，长期没人维护、贡献很小的特征定期下线。

**面试里的说法**："我会先用二三十个强特征上线，后续每加一个特征都要过消融实验和延迟预算。"
