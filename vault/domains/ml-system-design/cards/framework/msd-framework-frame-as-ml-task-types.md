## Q
同一个业务目标可以定义成分类、回归、排序或生成任务。以"预测用户会不会喜欢一个视频"为例，比较这几种定义的取舍。

## A
- **二分类**（classification，输出属于两个类别之一的概率）：标签"看过一半记 1，否则 0"。
  - 优点：标签干净、模型简单、概率可以直接加权。
  - 缺点：看了 49% 和看了 0% 被当成一样；阈值 50% 是拍脑袋定的。
- **回归**（regression，输出一个连续数值）：直接预测观看秒数。
  - 优点：保留了"看多久"的信息。
  - 缺点：长视频天然秒数大，模型会偏爱长视频；观看时长分布极偏，少数几小时的样本会主导误差。常见改法是预测观看比例，或对秒数取对数。
- **排序**（ranking，只关心候选之间的先后）：
  - 逐点（pointwise）：每个视频单独打分再排序，就是上面两种；
  - 成对（pairwise）：训练时比较"用户看了 A 没看 B"，学 A 应排在 B 前；
  - 列表（listwise）：直接优化整张列表的排序指标。
  - 优点：和"给用户一个列表"的实际用途最一致。缺点：样本构造更复杂，分数不再是概率，不能直接拿来做预算或报警。
- **生成**（generation，输出一段新内容）：用大语言模型直接写出推荐理由或视频标题列表。适合需要解释的场景，但成本高、结果难评测，一般不用来做主排序。

**怎么选**：推荐系统最常见的是"多个逐点二分类 + 一个回归"，再加权成一个排序分：概率可解释、可校准（预测 0.3 就真有约 30% 的人会看），又能按业务调权重。说出"选这个定义，后面的标签和评估指标就跟着变"，就是面试官要的信号。
