## Q
ML 系统设计题和普通系统设计题（设计短链、设计聊天）最根本的区别是什么？

## A
**普通系统**：行为由代码决定。同样的输入、同样的代码，结果确定；写对了就一直对。

**ML 系统**：行为由**代码 + 数据 + 模型**三者共同决定。模型（从数据学出来的函数）的"逻辑"藏在几百万到几十亿个数字里，没人能逐行读懂。于是多出几个一等公民：

- **数据是输入也是"源码"**：训练数据变了，模型就变了，代码一行没改。必须像代码一样做版本管理。
- **标签**：训练需要"正确答案"，它从哪来、多久之后才知道、有没有偏差，普通题根本不涉及。
- **正确性是统计意义的**：没有"这个请求的正确返回值"，只有"在 1 万个样本上准确率 92%"。测试从断言变成阈值。
- **会静默变差**（silent failure）：普通服务出错会报 500；模型变差时照样返回 200 和一个看似合理的预测。线上用户行为变了（数据漂移），模型就悄悄变差，没有任何异常日志。
- **会影响自己的未来数据**：推荐什么，用户就看什么，下一轮训练数据就由上一轮模型塑造（反馈闭环）。

**落到答题上**，普通题的五件事（需求、估算、API、存储、扩展）都还要讲，但要多讲四件：
1. 标签与训练数据从哪来；
2. 离线怎么评、线上怎么做实验；
3. 训练和线上的特征怎么保持一致；
4. 上线后怎么发现模型变差、怎么回滚到上一版模型。

**一句话**：普通题问"系统能不能扛住"，ML 题还要问"系统给出的答案好不好、会不会悄悄变坏"。
