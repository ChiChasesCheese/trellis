## Q
线上模型突然变差，团队想回滚，却发现说不清"上一个好版本"是什么、也无法重新训练出一样的模型。缺了哪些东西？怎样让模型可追溯、可复现？

## A
**一个真实感很强的场景：** 欺诈模型的召回率（真欺诈里被抓到的比例）从 0.80 掉到 0.65。排查时发现：
- 线上加载的是 `s3://bucket/fraud/model.pkl`，这个路径被覆盖过 5 次，不知道现在是哪次的。
- 训练数据的查询是"最近 90 天"，今天再跑，数据已经不一样了。
- 训练脚本在某人的笔记本上改过，没有提交。

**缺的四样东西：**
1. **不可变的模型版本：** 每次训练产出写新路径（按版本号或内容哈希），从不覆盖；线上通过注册表的别名找到具体版本。
2. **数据快照：** 训练用的数据要能按 ID 找回，比如 Delta Lake 或 Iceberg 表的时间旅行（按版本号或时间点读历史数据）、DVC 记录的数据哈希，或者把训练集导出成带日期的 Parquet 文件。
3. **代码版本：** 训练只能从 CI 里、基于某个 Git 提交运行，提交哈希写进注册表；不允许从个人环境注册上线模型。
4. **环境与随机性：** 容器镜像摘要（digest）、依赖锁文件、随机种子。

**做到之后，回滚和排查变成：**
- **回滚：** 把 `champion` 别名指回上一个版本，几分钟内完成。
- **定位：** 对比两个版本的血缘：代码差了哪几个提交、数据多了哪几天、特征定义有没有变。
- **复现：** 用记录的（代码提交，数据快照，镜像，种子）重新训练，指标应在很小的误差内一致（GPU 训练有非确定性，不要求逐位相同）。

**流程上的护栏：**
- **注册必须带血缘：** 缺少数据版本或代码提交的注册请求直接拒绝。
- **上线只认注册表：** 服务只能加载注册表里批准过的版本，禁止直接指向任意文件路径。
