## Q
面试里被问"你的大模型服务怎么用缓存省钱，模型挂了怎么办？"，怎么答？

## A
按这个顺序说：

1. **分层缓存，从安全到激进：** 先开引擎的前缀缓存，复用系统提示和多轮历史的计算，只省算力、不改输出；再考虑精确结果缓存，只对温度为 0 的重复请求有效；最后才是语义缓存，只对 FAQ 类意图、在同一租户内开。
2. **讲缓存键：** 模型版本 + 系统提示版本 + 采样参数 + 租户 + 输入。任何一项变了都不能命中，否则会返回旧答案或泄露别人的数据。
3. **语义缓存的阈值用数据定：** 人工标注一批相似问题对，选错误率低于 1% 的阈值，并持续抽样复查命中结果。
4. **超时分两段：** 首字超时（还没输出就可以无感切换）和生成中途（一般不切，报错让用户重试）；截止时间从网关逐层往下传。
5. **降级阶梯：** 同模型别的集群或区域 → 小模型 → 外部服务商 → 503 加 `Retry-After`。备用路径要么按全量备容量，要么配合优先级和限流，防止连锁故障。熔断器防止所有请求都卡在超时上。
6. **可观测与测试：** 响应里标明 `served_by`，监控命中率、降级率和缓存命中样本的质量；定期演练"主模型超时"，确认降级生效、报警触发、备用不被压垮。
