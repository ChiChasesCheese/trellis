## Q
从推理和发布工程的角度看，大模型评测分数"变了"时，最常见的非模型原因有哪些？各举一个现象和检查办法。

## A
**前提**：模型权重没变，只是推理引擎、服务配置或评测脚本变了，分数也会变。先排除这些，才轮得到"模型变差了"。

- **对话模板不一致**：推理服务把消息拼成文字的模板（插入角色标记和特殊 token 的规则）和模型训练时的不同。
  - 现象：所有任务普遍下降几个点，回答里偶尔出现奇怪的角色标记。
  - 检查：把服务实际发给模型的完整提示打印出来，和模型自带的模板逐字符比对。
- **分词器版本变化**：分词器（把文字切成 token 编号的程序）升级后，同一段文字切出的 token 不同。
  - 检查：对固定文本比对新旧分词结果。
- **生成参数默认值变化**：引擎升级后默认的温度、`max_tokens`、停止词变了。
  - 现象：数学题大量"没写完"，被截断在推理过程中。
  - 检查：统计"因长度截断结束"的比例，和上一版比较。
- **答案提取失败**：模型输出格式略有变化（"答案是 42。"变成"**42**"），提取正则取不到。
  - 检查：抽看判错的题，区分"答错了"和"答对了但没取到"。
- **采样不固定**：评测时温度大于 0，或者凑批（多个请求合在一起算）导致数值末位不同，贪心解码也会在几乎并列的词上走向不同分支。
  - 检查：同一版本跑 3 次，看分数本身的波动有多大。
- **数值精度变化**：换了量化（用更少的比特存权重）或新的计算内核（kernel，GPU 上执行的底层函数）。
  - 检查：在固定输入上比较新旧版本每个位置的 logprob（模型给实际输出词的对数概率），找出差异最大的样本。
- **评测集或评委变了**：题目被增删、评委模型被升级。
  - 检查：评测集和评委都带版本号，分数只在同版本之间比较。

**原则**：分数变化先归因到"环境、配置、脚本、模型"中的哪一个，一次只改一样。
