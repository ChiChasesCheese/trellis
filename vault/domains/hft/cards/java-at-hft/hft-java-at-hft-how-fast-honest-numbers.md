## Q
报告一个 Java 系统的延迟数字时，怎样说才不夸大？

## A
一个延迟数字至少要说清五件事：
1. **测的是哪一段**：线程间传递一个事件，还是从收到包到发出单；
2. **哪个分位数**：p50 还是 p99.9，还是最大值；
3. **什么负载**：每秒多少条消息；
4. **多长的时间窗口**，其中是否包含 GC、预热和开盘高峰；
5. **怎么测的**：是否避免了协同遗漏（coordinated omission，测量线程在系统卡顿时也停发请求，漏记了本该很慢的请求）。

例：线程间传递一个事件的 p50 可能只有约 100 ns，但同一个系统的 p99.99 可能是几十微秒甚至毫秒。只报 p50，会严重夸大。

面试里这样表述最可信：“p50 是多少，p99.9 是多少，在什么负载下测的。”
