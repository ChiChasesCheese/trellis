## Q
风控与订单管理系统（OMS）适合用 Java 写吗？哪一部分对延迟更敏感？

## A
要分两层看：
- **交易前风控**（pre-trade risk）在下单热路径上，每个订单发出前必须检查，如“单笔不超过 X 手”“价格偏离不超过 Y”，这是几次比较的事，预算是微秒甚至更低，通常用 C++ 或硬件实现。
- **盘中、盘后的聚合风控与订单管理**：汇总全公司几千个策略的合计持仓、盈亏（PnL）和敞口，对账，维护订单状态，规则复杂且常变，只需毫秒到秒级的响应，吞吐大，这就是 Java 擅长的。

另一方面，LMAX 交易所的撮合引擎是用 Java 写的，说明在严格的零垃圾、预热、绑核之下，Java 也能做微秒级的热路径。选 Java 还是 C++，看延迟预算，不是看行业。
