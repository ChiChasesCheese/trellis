## Q
为什么说“一个公司里同时用 Java 和 C++”是有成本的？公司怎样控制这个成本？

## A
多语言的成本：
- 两套构建、部署、监控和调试体系；
- 跨语言要共享数据格式，一边改了 schema，另一边必须同步，否则读错字段；
- 跨语言的 bug 难定位，要同时懂两边；
- 招聘和培养要走两条线。

收益是各取所长：热路径用 C++ 拿到极致延迟，其余部分用 Java 拿到开发速度。

所以公司通常有意识地**把边界做窄**：只固定少数几个接口，例如用 SBE 的 schema 同时生成两种语言的编解码器、用共享内存队列交换消息，而不是到处用 JNI 互相调用。边界越粗、越少、越规范，混合系统越好维护。
