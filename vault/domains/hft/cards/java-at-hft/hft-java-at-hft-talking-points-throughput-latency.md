## Q
被问“为什么 Java 工程师在高频交易公司有价值”时，怎样用“吞吐与延迟的取舍”来回答？

## A
论点：延迟和吞吐常常此消彼长（批量处理提高吞吐，却让每个请求多等一会儿）；交易公司的系统分两类：热路径追求延迟，其余追求吞吐和迭代速度，而大多数工程量属于后者。

论据：研究员的迭代速度就是公司的研究产出。试 1000 组参数，每组回测 1 小时，串行 1000 小时，100 台机器并行 10 小时。能把回测或数据读取再快 2 倍、让计算集群利用率提高的工程师，直接让同样的研究员一年验证更多想法。

结论的说法：“我清楚热路径需要极致延迟，但整个公司大多数代码追求的是吞吐、可靠和开发速度，Java 在这里有生态和生产力优势，我的价值在于把这些系统做得又快又稳。”
