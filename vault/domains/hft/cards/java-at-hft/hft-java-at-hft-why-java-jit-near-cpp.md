## Q
“Java 经过 JIT 之后，长期运行可以接近 C++ 的速度”，这句话成立的前提是什么？

## A
JIT 能看到程序运行时的统计，做静态编译器做不到的激进优化：按实际类型去虚化并内联、按真实分支频率排布代码、用逃逸分析消除对象分配。一个玩具方法的实测里，解释执行约 565 ns/次，JIT 到 C2 后约 123 ns/次，快了约 4.6 倍。所以对长时间运行的吞吐型代码，Java 常和 C++ 在同一个量级。

前提条件：
- **充分预热**，代码已经被 C2 编译；
- **热路径行为稳定**，不频繁发生去优化；
- **数据布局友好**，用原始类型数组，而不是满地的对象指针；
- **GC 不来打扰**。

不成立的地方：启动阶段、尾延迟（GC、safepoint）、内存占用与布局不可控，这些恰好是 C++ 的优势。
