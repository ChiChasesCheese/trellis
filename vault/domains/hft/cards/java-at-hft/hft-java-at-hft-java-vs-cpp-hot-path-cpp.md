## Q
为什么纳秒级的热路径更偏向 C++？从 Java 的哪几处“不可控”来解释？

## A
热路径的预算可能只有几百纳秒，而一次主存访问就约 100 ns，所以任何不可控的环节都会吃掉预算：
- **GC**：C++ 没有垃圾回收，不会有停顿；Java 要靠零分配才能避开；
- **内存布局**：C++ 的 struct 可以连续存放、对齐到缓存行、没有对象头；Java 的对象数组是指针数组；
- **预热与去优化**：C++ 是提前编译，第一次就是最终的机器码；Java 要等 JIT，且可能被去优化；
- **编译期计算**：C++ 的模板和 `constexpr` 能把运行时的分支、虚调用消掉；
- **底层接口**：内核旁路网卡库、SIMD 内建函数直接可用。

Java 可以把前几项压到很小，但代价是写得像 C。
