## Q
FPGA 的开发迭代为什么比软件慢得多？出了 bug 怎么调试？

## A
**编译慢**：把设计变成能下载进芯片的文件，要经过综合（synthesis，把描述变成逻辑门）、布局布线（place and route，决定每个单元放在芯片哪里、怎么连线）和时序分析。大设计常需要**数小时**。软件改一行代码重编译只要几秒。所以 FPGA 一天只能试几次，每次改动都必须想清楚。

**调试难**：芯片里没有断点，也没有 `printf`。常用办法：
- **仿真**（simulation）：在电脑上用软件模拟电路，输入测试数据，查看每个信号在每个时钟周期的波形。大部分 bug 在这里发现；
- **片上逻辑分析仪**（如 ILA）：在设计里额外加入采样电路，把选定的内部信号录下来，事后读出来看。它占用芯片资源，也可能影响时序；
- **硬件时间戳和计数器**：在关键点计数，对比预期。

例：一个因为交易所协议新版本多出一个字段而错位的 bug，在软件里改一行几秒钟；在 FPGA 里需要改电路、仿真、重新综合（几个小时）、再验证。这也是 FPGA 通常只放稳定、变化少的功能的原因。
