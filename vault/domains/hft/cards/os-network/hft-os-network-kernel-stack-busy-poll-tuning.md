## Q
不换成内核旁路，只在标准 Linux 网络栈上，还有哪些办法能降低收包延迟？它们的上限在哪里？

## A
可以在内核栈内部减少"手续"：

- **忙轮询**：`SO_BUSY_POLL` 选项和系统参数 `net.core.busy_read`、`net.core.busy_poll` 让 socket 的读调用先在用户线程里直接轮询网卡队列一小段时间，而不是睡眠等中断。这样去掉了中断和唤醒，能省几微秒。
- **关闭中断合并**：网卡默认会攒几个包或等几十微秒再发一次中断，用 `ethtool -C <网卡> rx-usecs 0` 关掉，包一到就立刻通知。
- **绑定中断和线程到同一个核**，避免跨核搬运缓存行；关掉 `irqbalance`。
- **精简内核处理**：关闭防火墙规则（netfilter）、连接跟踪等不需要的功能。

上限：即便这样，包仍然要经过协议栈、拷贝一次、进出一次系统调用，调到极致一般是 **3–5 µs** 的水平，还剩下抖动问题（内核代码可能被其他事情打断）。

要进一步下探到约 1 µs 或更低，只能绕开内核，让应用直接读网卡队列。这就是内核旁路。
