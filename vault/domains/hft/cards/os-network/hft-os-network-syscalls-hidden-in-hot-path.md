## Q
交易热路径里有哪些看起来无害、实际会触发系统调用或阻塞的操作？应该怎么找出它们？

## A
容易忽略的几个：
- **日志**：`write` 到文件或终端，每次系统调用，磁盘慢时还可能阻塞几毫秒。
- **内存分配**：C 里的 `malloc` 在内存不够时会向内核要内存（`brk`、`mmap`），Java 里新对象触发堆扩容或 GC 线程相关操作。
- **锁**：竞争的互斥锁在 Linux 上最终调用 `futex` 系统调用来睡眠和唤醒。
- **文件和 socket 的读写**：直接就是系统调用。
- **读取时间**：并不都是。Linux 上 `clock_gettime`（Java 的 `System.nanoTime()`）通常经 vDSO（内核映射进用户空间的一小段代码）直接读时钟，不进内核，约 20 ns；但换成别的时钟源或在某些虚拟机里会退化成真正的系统调用。

找出它们：
- `strace -c -f -p <pid>` 统计一个进程各类系统调用的次数和耗时；
- `perf trace` 开销更小，适合生产环境；
- 目标是热线程在稳定运行时**一个系统调用都没有**。

做法：日志写进内存里的环形缓冲，由另一个线程在非热核上异步落盘；内存在启动时一次性预分配；用无锁结构代替锁。
