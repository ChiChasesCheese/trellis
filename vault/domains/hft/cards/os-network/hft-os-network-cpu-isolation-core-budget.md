## Q
给交易线程做 CPU 隔离需要付出什么代价？如果把两个忙轮询线程绑到同一个核上会怎样？

## A
**代价是核的浪费**。忙轮询（busy spin，不停循环检查有没有新数据，不让出 CPU）的线程让它所在的核一直 100% 占用，整个核留给它一个线程，别的任务用不了。所以要为核做预算。

例子：一台 16 核的机器，可能这样分配：
- 0–1 号核：操作系统、日志、监控、中断；
- 2 号核：行情接收线程；
- 3 号核：策略线程；
- 4 号核：订单发送线程；
- 其余留给研究或备用。

N 个热线程就要 N 个独占核，核数和线程数要提前规划。

**把两个忙轮询线程绑到同一个核的后果**：忙轮询线程从不主动睡眠，调度器只能按时间片（常见几毫秒）强制切换。于是其中一个线程运行时，另一个就被冻住几毫秒，延迟从微秒变成毫秒，而且这种停顿是周期性的。

规则：一个隔离核只放一个忙轮询线程，并在上线前用命令 `ps -eLo psr,comm` 之类核对实际的线程分布。
