## Q
即使已经预触了堆内存，交易进程在运行中还是可能遇到缺页延迟。哪些情况会漏掉？

## A
常见的漏网之鱼：

1. **没被预触的区域**：堆之外还有很多内存——Java 的直接内存（direct memory）、元空间（metaspace）、线程栈、JIT 编译后的代码、内存映射文件。这些区域第一次用到时仍会缺页。
2. **第一次执行的代码路径**：程序的可执行文件和库是按页映射的，某段代码第一次运行时要把它所在的页载入，也是缺页。所以预热要把完整的下单路径空跑几遍。
3. **内存映射文件**：用 `mmap` 打开的日志或数据文件，第一次写入某页会缺页，页缓存里没有时还要读盘。启动时应该顺序访问一遍。
4. **写时复制（copy-on-write）**：进程 `fork` 之后，父子进程共享的页只要被写就会复制一份，触发缺页。

发现方法：运行时用 `perf stat -e page-faults,minor-faults,major-faults -p <pid>` 观察缺页计数，稳定交易期间它们应当几乎不增长；一旦增长，就能对照时间点找出是哪一块内存。
