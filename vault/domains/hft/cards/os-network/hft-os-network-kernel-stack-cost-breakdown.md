## Q
内核网络栈收一个小包大约要花多久？时间主要花在哪几件事上？

## A
典型的收包路径，从包到网卡到应用读到数据，在调优过的 Linux 服务器上约 **5–10 µs**，没调优时常见十几微秒甚至更多（量级，随机器和负载变化）。

时间主要花在：
- **中断与软中断处理**：打断当前线程，保存恢复现场，驱动取包，几微秒；
- **协议栈处理**：每个包都要走 IP、UDP/TCP 的逻辑，申请和释放内核的包结构，查表，有些路径要加锁，约几百纳秒到 1–2 µs；
- **唤醒与调度**：在 `recv` 里睡眠的线程被唤醒后，还要等调度器把它放到某个核上，如果线程在别的核睡着，唤醒还会涉及核间中断；
- **系统调用和内存拷贝**：`recv` 进出内核约几百 ns，复制数据取决于包大小，一般几百 ns；
- 此外还有缓存和 TLB 被内核代码冲刷的间接成本。

对比：用内核旁路（绕过内核、应用直接读网卡）后可降到约 1 µs 或更低。可见内核栈里"真正搬运数据"的占比不大，**大头是围绕数据的各种手续**。想降延迟，就要想办法砍掉这些手续。
