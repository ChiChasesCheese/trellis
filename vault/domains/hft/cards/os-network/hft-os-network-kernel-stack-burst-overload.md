## Q
行情突发（burst）时，内核网络栈为什么会丢包或延迟暴涨？请用一个数字例子说明。

## A
突发时包的到达速率远高于平时。如果每个包在内核里要花一定的 CPU 时间，处理能力就是个有限的数。

例子：行情高峰时，一个组播流每秒到达 **100 万个包**（量级）。
- 内核每个包的处理约 5 µs（含中断、协议栈、唤醒、拷贝）。
- 100 万 × 5 µs = **5 秒的 CPU 时间需要在 1 秒内完成**，一个核根本处理不过来。
- 网卡的环形缓冲区和 socket 的接收缓冲区（大小由 `net.core.rmem_max` 等限制）先被填满，再来的包被直接丢弃；对 UDP 行情来说，这就是**丢包**，程序后来收到的序号会出现缺口。
- 即使没丢，包在缓冲区里排队，每个包的排队等待也让延迟变成毫秒。

对策：
- 加大 socket 接收缓冲区，缓冲突发（治标）；
- 把中断和软中断分散到多个核（接收端扩展，RSS / RPS）；
- 换成轮询加内核旁路，每个包只花几百纳秒，同一个核能轻松吞下百万包每秒。

所以数据量越大，内核栈的"每包手续费"越致命。
