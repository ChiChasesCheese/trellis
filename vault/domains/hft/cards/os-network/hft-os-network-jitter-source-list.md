## Q
操作系统和硬件层面，哪些常见因素会让一个已经绑核的交易线程偶尔停顿？请列出几个并说明量级。

## A
即使线程独占一个核，下面这些仍可能打断它：

| 来源 | 说明 | 量级 |
|---|---|---|
| 调度器 tick | 内核周期性的定时器中断，默认每秒 250–1000 次 | 每次几微秒 |
| SMI（系统管理中断） | 固件（BIOS）接管 CPU 做电源、温度、纠错等，操作系统看不见也无法屏蔽 | 几十微秒到几毫秒 |
| 透明大页整理 | 内核后台线程合并内存页，或缺页时整理连续内存 | 可达毫秒 |
| 内核后台线程 | kworker、ksoftirqd 等线程在该核上运行 | 几微秒到几百微秒 |
| 频率变化 | 升降频、睿频调整 | 几十微秒 |

此外还有 TLB 击落（别的核修改映射，要求本核清 TLB）、定时器、设备中断。

排查原则：先用测量工具确认停顿多久、多频繁，再对症处理——tick 用 `nohz_full`，THP 关闭或改用显式大页，SMI 要在 BIOS 里关相关功能或找厂商，频率变化通过固定频率解决。
