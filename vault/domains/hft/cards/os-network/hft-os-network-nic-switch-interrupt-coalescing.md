## Q
网卡的中断合并（interrupt coalescing）是什么？它用延迟换来了什么，交易系统为什么要把它关掉？

## A
网卡每收到一个包就向 CPU 发一次中断，在包很多时 CPU 会被中断淹没（每次处理几微秒）。中断合并让网卡**攒一会儿**再发：等到攒够 N 个包，或等满 X 微秒，才发一次中断，一次中断处理多个包。

- **好处**：中断次数大幅减少，CPU 占用下降，吞吐提高。适合下载、文件服务器这类追求吞吐的场景。
- **代价**：先到的包要等后面的包，或等满定时器，才会被通知，延迟增加最多 X 微秒。很多网卡默认的等待时间是几十微秒量级（具体因驱动和型号而异）。

例子：定时器设为 50 µs，一个孤零零到达的行情包，可能要等满 50 µs 才触发中断，而整条 tick-to-trade 预算才几微秒。

交易系统的做法：用 `ethtool -C <网卡> rx-usecs 0 rx-frames 1` 之类的命令关掉合并（包到就通知），或直接用内核旁路 + 轮询，根本不依赖中断。

代价：中断次数增多，CPU 占用上升；但对延迟敏感的系统，这是值得的。
