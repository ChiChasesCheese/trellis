## Q
一个服务每秒处理 100 万条消息，每条消息要做一次系统调用，每次约 600 ns。这些系统调用占多少 CPU？说明什么？

## A
计算：1,000,000 次/秒 × 600 ns = 600,000,000 ns = **0.6 秒**。

也就是说，每过 1 秒，光系统调用就要占 0.6 秒的 CPU 时间，一个核有 **60%** 的时间花在进出内核上，还没算消息本身的处理。

延伸到延迟：每条消息固定多出 600 ns。如果整条 tick-to-trade 链路预算是几微秒，这一个调用就吃掉了几分之一；若每条消息有 3 次系统调用，就是 1.8 µs。

所以热路径上要"少进内核"：
- **批量**：一次 `read` 读 64 KB，而不是 64 次读 1 KB；
- **聚集 I/O**：用 `writev` 一次写出多块不连续的数据；
- **共享内存**：线程或进程间通过共享内存传数据，不经过内核；
- **内核旁路**：网卡数据直接给应用，不走系统调用。

结论：看起来很小的单次开销，乘以每秒百万次，就成了瓶颈。
