## Q
程序申请了一大块内存，为什么操作系统在第一次访问其中某一页时才会真正给它物理内存？这会带来什么延迟？

## A
操作系统采用**按需分配**：`malloc` 或 JVM 申请堆时，内核只在进程的虚拟地址空间里划出一段地址，并不立刻分配物理内存。这样可以先承诺很多、实际用多少才给多少。

等到程序第一次读写某个页（page，通常 4 KB）时，CPU 发现这个虚拟页还没有对应的物理页，触发**缺页异常**（page fault）。内核接管，找一个空闲物理页，清零，填好页表，再回到原指令重试。

代价：
- 次要缺页（minor fault，数据不用从磁盘取）：约 **0.5–几微秒**，页越多越累计；
- 主要缺页（major fault，要从磁盘或交换区读）：约**毫秒**级。

交易场景：如果第一笔订单用到的缓冲区从未被碰过，处理它的第一次写入就会触发缺页，多出几微秒，而整条链路的预算只有几微秒。所以要在开盘前把用到的内存全部访问一遍，这叫预触（pre-touch）。
