## Q
feed handler 为什么说"宁可停止报价，也不能给出错误的订单簿"？它发现自己状态不对时该怎么做？

## A
**错价比没价更危险。** 策略完全相信 feed handler 给的订单簿。如果簿子是错的，比如少了一笔 300 股的买单，或者价位被偏移了，策略会基于不存在的流动性做决定：对着一个已经被撤掉的"买一"卖出，或是以为买卖价差很宽而挂出过激的报价。一次错误的成交就可能亏掉很多天的利润。没有行情只是暂时没机会，错误的行情却会真的亏钱。

**自检手段（都很便宜）：**
- 序号连续性：发现缺口就标记该股票"过期"（stale）。
- 引用了不认识的订单编号（Executed 或 Delete 找不到对应订单）。
- 连续竞价时出现买一 ≥ 卖一（交叉簿，crossed book）。
- 数量变成负数。

**发现问题后：**
1. 把该股票标记为不可用，通知策略撤单、停止报价。
2. 用快照或重传恢复订单簿。
3. 恢复后重新校验，才恢复发布。
4. 记录事件，用于事后排查。

这需要策略和 feed handler 之间约定好"状态"字段，而不只是传价格。
