## Q
在 Java 里解码 SBE 消息时，生成的解码器为什么能做到几乎不产生垃圾（零分配）？写代码时应该怎么用它才不会破坏这个性质？

## A
**原理：** SBE 生成的 Java 解码器是**轻量视图**（flyweight）：它自己只保存两个值，一个缓冲区引用和一个偏移量。调用 `decoder.wrap(buffer, offset, ...)` 就只是改这个偏移量，之后 `decoder.price()` 等方法直接从缓冲区的固定位置读取原始类型。整个过程**没有创建对象**，也没有字符串拷贝。

**怎么用才不破坏零分配：**
- 解码器对象在启动时创建一次，每条消息都重复使用（反复 `wrap`），不要为每条消息 `new` 一个。
- 字段读出来直接用原始类型（`long`、`int`），不要转成 `String` 或装箱的 `Long`。
- 缓冲区用直接内存（direct buffer）或预分配的数组，不在收包路径上分配。
- 不要把解码器放进集合或传给别的线程：它指向的缓冲区下一条消息就会被覆盖，保存下来的值会悄悄变掉。

**收益：** 垃圾回收（GC）暂停是毫秒级，而低延迟路径每条消息只有约 1 µs，零分配的解码避免了 GC 暂停打断行情处理。
