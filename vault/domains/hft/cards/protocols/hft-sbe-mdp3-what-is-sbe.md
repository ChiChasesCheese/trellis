## Q
SBE（Simple Binary Encoding）是什么？它和 JSON 或 Protobuf 这类序列化格式相比，为什么更适合低延迟场景？

## A
SBE 是一种面向低延迟的二进制编码规范，核心思路是 **schema 驱动**：

1. 先用一份 XML 的 schema 描述每种消息有哪些字段、什么类型、顺序是什么。
2. 工具根据 schema 生成 Java 或 C++ 的编码、解码代码。
3. 消息的字节布局和程序里使用它的方式是同一套：字段都在固定偏移，定长。

**读一个字段就是：** 缓冲区基址 + 固定偏移 + 按类型读取，**不需要先解析成一个对象**。生成的 Java 解码器就是一个贴在缓冲区上的"视图"（flyweight），换一条消息只需要改它指向的偏移，不分配新对象。

**对比：**

| | JSON | Protobuf | SBE |
|---|---|---|---|
| 读字段前要先 | 解析整段文本 | 解码变长整数，建对象 | 无，直接按偏移读 |
| 内存分配 | 很多 | 有 | 基本没有 |

代价：schema 变动要重新生成代码；字段是定长的，没有 Protobuf 那样的灵活性。
