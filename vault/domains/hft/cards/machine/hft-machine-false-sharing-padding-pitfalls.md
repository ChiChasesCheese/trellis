## Q
给 Java 类的热字段手工加了填充字段，伪共享却仍然没消失，可能有哪些原因？

## A
常见的坑有三个：

1. **JVM 会重排字段**。虚拟机为了对齐，可能把你写的填充字段挪到别处，热字段又靠到了一起。补救是用继承（父类放填充、子类放热字段，父类字段总是排在前面），或用 `@Contended`，并用 `jol`（Java Object Layout 工具）打印对象布局来验证。
2. **缓存行大小不是 64**。Apple M 系列是 128 字节，只填 56 字节（7 个 `long`）在那里不够。`@Contended` 默认留 128 字节正是为了两种情况都覆盖。
3. **只填了一侧**。对象在内存里相邻，前一个对象的尾部字段可能和你的热字段同行，所以要在热字段**前后**都留空。

还有一种：看起来无关的两个对象恰好被分配在相邻位置（如两个线程各自的小对象），同样会同行。

结论：填充后要用 `perf c2c` 或对比计时实测，确认问题确实消失，而不是相信"我已经加了 padding"。
