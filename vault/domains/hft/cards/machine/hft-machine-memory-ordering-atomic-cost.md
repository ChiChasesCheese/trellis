## Q
在 x86 上，带 `lock` 前缀的原子指令（如原子加、CAS）和栅栏（fence）大约有多贵？没有竞争和有竞争时差别在哪？

## A
`lock` 前缀指令（`lock add`、`lock cmpxchg` 等）会让该指令成为一个完整的屏障：它要等存储缓冲区里之前的写入全部生效，并独占所访问的缓存行。

- **没有竞争**（缓存行已在本核，独占状态）：约 **20 个周期**，在 3 GHz 下约 5–10 ns，比普通的加法贵一个数量级。
- **有竞争**（缓存行在别的核手里）：还要加上把缓存行搬过来的时间，约几十 ns，多个线程抢同一行时更糟。

对比：普通的 `mov` 写读一般 1 个周期量级，一把无竞争的互斥锁（mutex）加解锁约 25 ns。

结论：
- 原子操作不是"免费的"，热路径上每次都要有成本意识。
- 最好的优化是**避免共享**：单写者、每线程独立数据，需要原子的地方越少越好。
- 能用更弱的顺序时（比如只需要 release 语义）就不要用最强的（volatile/seq_cst），因为 x86 上后者要多一次昂贵的栅栏。
