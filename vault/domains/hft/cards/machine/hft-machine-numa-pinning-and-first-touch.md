## Q
怎样保证一个交易线程用的内存在它自己所在的 NUMA 节点上？Linux 的"首次接触"（first-touch）策略是什么？

## A
做法有两步：把线程固定在某个节点的核上，再让它的内存分配在同一节点。

- 绑定线程：用 `taskset` 或线程亲和性（affinity，指定线程只能在哪些核上运行）。
- 绑定内存：用 `numactl --cpunodebind=0 --membind=0 java ...`，让进程只用节点 0 的核和节点 0 的内存。
- **首次接触策略**：Linux 默认在**第一次写入某页的那个线程所在的节点**上分配物理页。也就是说，申请内存时并不决定位置，谁先碰谁说了算。

陷阱：如果由启动线程在节点 1 上初始化了一个大缓冲区（把所有页都碰了一遍），而后来的交易线程跑在节点 0，那么这块内存全在远端，每次未命中都多付几十 ns。

所以要么让交易线程自己来初始化它要用的内存，要么用 `--membind` 强制节点。另外网卡也挂在某个插槽的 PCIe 上，处理它的线程最好放在同一节点。
