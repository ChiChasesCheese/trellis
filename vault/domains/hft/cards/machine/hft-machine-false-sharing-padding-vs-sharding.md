## Q
解决伪共享有哪两类办法？填充（padding）和分片（sharding）各自适合什么场景，代价是什么？

## A
**填充**：在热变量前后塞入无用字节，让不同线程的热变量落到不同缓存行。
- Java 做法：在类里手写几个 `long` 占位字段，或用 `@Contended` 注解（需要 JVM 参数 `-XX:-RestrictContended` 才对应用类生效），它默认在字段前后各留 128 字节。
- 适合：变量个数固定，确实要各线程独立写各自的位置，比如 Disruptor 里生产者序号和消费者序号。
- 代价：浪费内存（一个 8 字节计数器占 128 字节）；JVM 可能重排字段，要实测确认。

**分片**：每个线程更新自己的一份数据，要总数时再汇总，例如 `LongAdder`。
- 适合：写很多、读总数很少的统计量。
- 代价：读总数时要遍历所有分片，结果是近似快照。

两者可以组合：分片之间再用填充隔开。

选择依据：能不共享就不共享（分片），必须相邻存放的独立变量才用填充。
