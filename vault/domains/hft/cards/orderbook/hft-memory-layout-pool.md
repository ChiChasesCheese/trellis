## Q
订单簿为什么要在启动时就预分配好一批订单对象（对象池，object pool），而不是每来一笔订单就新建一个？

## A
**问题：每次新建都有不可预测的代价。**
- C++ 的 `malloc` 平时约几十纳秒，但偶尔要加锁、向操作系统申请内存、触发缺页（page fault），耗时可到微秒甚至更长。
- Java 的 `new` 平时只是移动指针，很快，但会产生垃圾，积累到一定量就触发垃圾回收（GC）暂停，可能是毫秒级，而一条行情消息只有约 1 µs 的预算。

HFT 关心的不是平均值，而是尾延迟（偶尔的慢）：一次几毫秒的停顿，足以让所有挂单被吃掉。

**对象池的做法：**
1. 启动时按峰值需求分配好，比如 200 万个订单槽。
2. 用一个空闲链表记录哪些槽可用。
3. 新增订单：从空闲链表取一个槽，填上数据。
4. 订单结束：把槽还回空闲链表。

运行时不再向系统申请内存，行为是确定的，延迟稳定。

**代价：** 峰值要提前估计好，池子空间提前占用。
