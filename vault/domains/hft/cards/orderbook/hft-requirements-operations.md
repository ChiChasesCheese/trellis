## Q
一个订单簿（order book）数据结构要支持哪几种基本操作？每种操作的目标复杂度是多少？

## A
订单簿记录了所有还在排队的买单和卖单。要支持的操作：

| 操作 | 含义 | 目标复杂度 |
|---|---|---|
| 新增（add） | 在某价位队尾加一笔订单 | O(1) 或 O(log 价位数) |
| 撤单（cancel） | 按订单编号删除一笔订单 | **O(1)** |
| 改单（replace） | 通常等于撤单加新增 | 同上两者之和 |
| 成交（execute） | 减少队首订单的数量，吃完则移除 | O(1) |
| 查最优价 | 买一价、卖一价 | **O(1)** |
| 查深度 | 前 N 档每档的总量 | O(N) |

其中撤单和查最优价必须是 O(1)。撤单是按订单编号来的，没有价格信息，如果要去簿里扫描才能找到那笔订单，复杂度就会变成 O(订单数)，在每秒百万条消息的行情下撑不住。

**核心问题：** 每一种操作都要找到某一笔订单或某一个价位，选哪种数据结构，决定了这些操作是 O(1) 还是 O(n)。
