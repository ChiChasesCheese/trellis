## Q
在 Java 里要让订单簿完全不产生垃圾，常见做法是用原始类型数组加整数下标代替订单对象和指针。这是怎么做的？

## A
**普通写法：** `class Order { long id; int price; int qty; Order prev, next; }`，每笔订单是一个堆上对象，对象之间用引用连接。对象数量多，分散在内存里，也都要被垃圾回收器扫描。

**数组写法（按字段拆开存放）：**
```java
long[] id;  int[] price;  int[] qty;
int[] prev; int[] next;      // 前后订单的槽位下标
```
第 i 号订单的所有数据，就是各数组的第 i 项。"指针"变成了 `int` 下标，用 `-1` 表示空。空闲槽用同样的 `next` 数组串成空闲链表。

**好处：**
- **零对象：** 启动时分配 5 个大数组就够了，运行时没有 `new`，GC 无事可做。
- **紧凑：** 一个下标 4 字节，比对象引用加对象头小得多。
- **遍历友好：** 比如需要汇总所有订单数量时，`qty[]` 是连续内存，顺序访问，硬件预取（prefetch）很高效。

**代价：** 代码可读性变差，没有类型安全，容易写出下标越界或用错槽位的 bug，需要靠不变量检查和测试兜底。
