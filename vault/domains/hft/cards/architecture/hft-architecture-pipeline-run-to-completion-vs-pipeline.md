## Q
把"解码 → 订单簿 → 策略 → 风控 → 编码"每个环节各放一个线程、用队列串起来（线程流水线），与让同一个线程从头做到尾（run-to-completion），哪个延迟更低？为什么？

## A
**同一个线程从头做到尾延迟更低。**

每次线程交接都要：生产者把数据写进队列，消费者读出来。数据所在的缓存行（cache line，CPU 缓存里 64 字节的搬运单位）要从一个核搬到另一个核，约 **50–100 ns**，还会带来排队抖动。四次交接就是约 0.2–0.4 µs，加上队列一积压，尾部更糟。

线程流水线的好处是吞吐：各环节并行，总吞吐由最慢的那一环决定。

所以热路径通常 run-to-completion，靠**按品种分片**（每个分片一个线程，各管一部分品种）来扩展吞吐；只有本来就必须换线程的地方（网卡收发、写日志）才做交接。
