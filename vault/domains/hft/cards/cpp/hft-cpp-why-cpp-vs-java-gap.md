## Q
说“C++ 一定比 Java 快”为什么不准确？C++ 和 Java 在交易场景下真正的差距体现在哪里？

## A
**稳态吞吐**上差距没有想象的大：Java 的 JIT（即时编译器，运行中把热点代码编译成机器码）能看到真实的类型分布和分支概率，可以把虚调用改成直接调用并内联，还能用逃逸分析（escape analysis）省掉不逃出方法的对象分配。长时间运行后，热点循环可以和 C++ 在同一数量级。

真正的差距在**尾延迟和可预测性**：
- **预热**：Java 刚启动时慢，第一笔真实订单可能还在解释执行。
- **GC 停顿**：偶发的暂停可达毫秒级，而交易热路径的预算往往只有几微秒。
- **布局**：对象头、指针追逐、没有可内联嵌套的值类型。
- **硬件控制**：对齐、预取、SIMD 内建函数在 C++ 里直接可用。

所以更准确的说法：Java 不是慢，而是它的**最差情况**和**不可控成分**更多；C++ 用复杂度换来了确定性。
