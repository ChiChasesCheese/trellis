## Q
把 400 万个订单放进 C++ 的 `vector<Order>`（连续存放）遍历求和，和放进“指针数组”（像 Java 的 `List<Order>`，每个订单是堆上另一个对象）遍历，速度大约差多少？为什么？

## A
一次实测里：连续的 `vector<Order>` 每个订单约 **0.3 ns**，指针数组（内存顺序被打乱）约 **2.7 ns**，差约 **8–9 倍**（具体倍数随机器而变，量级才重要）。

原因是 CPU 取数据以缓存行（cache line，通常 64 字节）为单位，并会预取顺序访问的数据：
- 连续存放：一个 32 字节的订单，一条缓存行装 2 个，预取器提前把后面的拉进来，几乎没有等待。
- 指针数组：每个订单都要先读指针、再跳到别处读对象，是“指针追逐”（pointer chasing），每次都可能是缓存未命中；一次主存访问约 80–100 ns，相当于几百条指令。

这就是 C++ 能手动控制内存布局带来的收益；Java 的对象数组是引用数组，还带约 12–16 字节的对象头。
