## Q
启动时跑一遍预热（warm-up，比如 Java 的 JIT 预热或预先触碰内存）和运行中持续的缓存预热（cache warming）有什么区别？为什么前者不能替代后者？

## A
两者解决的是**不同层面**的“冷”：

- **启动预热**：让一次性的慢事先发生，且之后不再重复。例：程序加载、JIT 把热点代码编译成机器码、预先访问所有内存页让缺页（page fault）提前发生。做完就永久有效。
- **持续缓存预热**：对付 CPU 缓存里的“冷”。缓存是**会被不断挤出**的，今天预热的结果几百微秒后就可能被别的数据覆盖，所以必须反复做。

例：启动时把订单对象池整个预触碰过，缺页消失了；但池里的一个对象在 L1 里只能存活到被后面的行情数据挤走，几十微秒到毫秒就没了。

另一类办法是减少被挤出的概率：把交易线程绑到独占的核，不让别的任务污染它的 L1/L2；也可以在预计信号快到来时用 `prefetch` 指令提前取数据。这些与周期性预热互补，而不是替代。
