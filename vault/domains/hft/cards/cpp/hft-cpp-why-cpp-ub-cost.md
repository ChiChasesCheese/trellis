## Q
C++ 用“不做检查”换来了速度。这个代价具体是什么？请用未定义行为（undefined behavior，UB）举一个交易系统里可能出事的例子。

## A
C++ 默认不替你做安全检查：`vector` 的 `operator[]` 不查越界，指针不查是否已释放，整数溢出也不报错。一旦出错，标准说程序行为**完全不确定**，称为未定义行为（UB）：可能立刻崩溃，可能读到垃圾，也可能“看起来正常”，换个编译器或优化级别才暴露。

交易例子：订单簿用数组存价格档位，价格下标算错多 1，写越界就改掉了相邻的**持仓**变量；系统不报错，但风控拿着被改坏的数字继续判断，可能放行一笔本该拦截的大单。

代价是复杂度和工程纪律：
- 开发和测试阶段开 AddressSanitizer、UBSan 等检查工具。
- 严格的代码规范和代码评审。
- 招聘门槛更高，同样功能的开发速度比 Java 慢。

这也是 Java 在非热路径上更受欢迎的原因：内存安全，错误会变成异常而不是静默的数据损坏。
