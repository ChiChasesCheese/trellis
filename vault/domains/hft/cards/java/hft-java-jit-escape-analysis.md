## Q
逃逸分析（escape analysis）和标量替换是什么？它为什么和低延迟的 GC 压力直接相关？

## A
JIT 分析一个 `new` 出来的对象是否“逃出”当前方法：被存进堆里的字段或集合、传给没被内联的方法、传给别的线程、从方法返回，都算逃逸。如果**不逃逸**，JIT 就做**标量替换**（scalar replacement）：把对象的字段拆成局部变量放进寄存器，连对象头都不分配。

实验：循环 2000 万次，每次 `new Point(i, i + 1)` 且只在方法内使用。开启逃逸分析时一共只分配约 5.5 MB（几乎为 0）；用 `-XX:-DoEscapeAnalysis` 关掉后分配 640 MB（每个 32 字节）。分配得少，年轻代填满得慢，GC 触发得少，尾延迟更平。

但它不保证生效，而且依赖内联：对象一旦传进没内联的方法就被视为逃逸。所以要用分配统计去验证，不能靠假设。
