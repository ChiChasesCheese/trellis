## Q
Chronicle Map 是什么？与 `HashMap` 相比，什么场景适合用它？

## A
Chronicle Map 是**堆外的键值存储**：数据放在堆外内存（也可以映射到文件做持久化），键和值以序列化后的字节存放，支持多个进程共享同一张表。

适合的场景：
- 表很大（几十 GB），放在堆里会让 GC 的工作量暴涨，放堆外则 GC 完全不受影响；
- 多个 JVM 进程要共享同一份参考数据（合约表、风控限额），不想每个进程各存一份；
- 重启后希望数据还在。

代价：键值要序列化，每次 `get` 都要做序列化或反序列化（可以用复用对象的 `getUsing` 方式避免分配）；预先要估计条目数和平均键值大小，估错了需要扩容；单次访问通常比堆内的 `HashMap` 慢。
