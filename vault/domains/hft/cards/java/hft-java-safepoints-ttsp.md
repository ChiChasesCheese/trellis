## Q
“到达安全点的时间”（TTSP）为什么会成为延迟尖刺的来源？

## A
安全点请求发出后，每个线程要跑到自己下一个轮询点才会停。如果某个线程正在跑一个没有轮询点的长循环（历史上 `int` 计数的有界循环不放轮询）、或者很长的数组拷贝、或一次耗时很长的本地调用，其他线程早就停好了，却要干等这一个线程。

例：10 个线程在 1 微秒内都停了，第 11 个线程正在一个跑 80 ms 的循环里，那么整个 JVM 一共停顿约 80 ms，而这次 GC 本身只用了 2 ms，GC 日志里看到的“暂停时间”只有 2 ms，其余 78 ms 是在等那个线程到达安全点。

新版 JDK 对长循环做了缓解（循环分段，loop strip mining），但长时间的本地调用和某些超长操作仍可能拖长 TTSP。可用 `-Xlog:safepoint` 查看每次的到达时间和停顿时间。
