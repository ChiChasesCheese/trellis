## Q
Chronicle Queue 用 mmap 文件，哪些情况下会出现延迟尖刺或数据风险？

## A
因为数据在操作系统的页缓存里，风险都来自操作系统一侧：
- **缺页**（page fault）：写入新页，或读取不在页缓存中的旧数据，内核要分配页或读磁盘，耗时从微秒到毫秒；缓解办法是预分配文件、提前触碰各页，把队列放在快速的 SSD 或内存文件系统上。
- **写回争用**：脏页累积后，内核集中写回，同盘的其他进程也会受影响，造成 I/O 抖动。
- **文件滚动**：新周期（如每天）创建新文件的一刻有额外开销，最好提前创建。
- **断电**：页缓存里没写盘的数据会丢，进程崩溃则不会；要保证不丢需要刷盘或复制到别的机器。
- **磁盘满**：写入失败，严重时进程收到总线错误信号。
