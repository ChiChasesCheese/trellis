## Q
虚拟线程（virtual thread）适合做什么、不适合做什么？为什么不用于交易热路径？

## A
虚拟线程（JDK 21 正式）由 JVM 调度，栈放在堆上按需增长，遇到阻塞 I/O 就挂起，让出底层的平台线程（carrier thread）。它适合**大量并发的阻塞 I/O**：每秒 1 万个请求、每个阻塞 100 ms，同时在途约 1000 个，用平台线程池很吃力，虚拟线程轻松写成“一请求一线程”。

不适合热路径的原因：
- 它让等待变便宜，但不会让 CPU 计算变快，热路径是 CPU 绑定或忙轮询；
- 调度由 JVM 的线程池决定，不能绑核，挂起和恢复的时机难预测，有抖动；
- 栈在堆上，大量活跃虚拟线程增加 GC 压力；
- `synchronized` 内阻塞会固定住载体线程（JDK 24 起已改善）。

所以研究平台、RPC 服务、监控用虚拟线程；撮合、行情线程用固定的平台线程加绑核。
