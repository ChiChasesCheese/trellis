## Q
对低延迟系统来说，升级到更新的 LTS JDK（如 JDK 21、25）有哪些实际收益？为什么交易公司升级时很谨慎？

## A
与低延迟相关的收益：分代 ZGC（JDK 21 可用，23 起默认）；虚拟线程（21）；FFM API 正式（22）；偏向锁被移除（18）；JIT 和向量化的持续改进；启动方面的 AOT 缓存（JDK 24 起）。

谨慎的原因：
- 同一份代码在新版 JIT 上，内联和逃逸分析的决策可能不同，性能和**尾延迟**可能回退；
- 要用重放的真实流量重新做延迟基准并重新预热；
- 内部 API（如 `Unsafe`）会变化，第三方库（Agrona、Chronicle）要升级到兼容版本，有时还要加 `--add-opens`。

所以升级是一个有测量闸门的项目：先在影子环境对比 p99、p99.9，再上线，而不是“新版本应该更快”。
