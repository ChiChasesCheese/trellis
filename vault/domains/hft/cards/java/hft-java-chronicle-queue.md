## Q
Chronicle Queue 是什么？为什么说它“写入即落盘、跨进程共享”？

## A
Chronicle Queue 是基于**内存映射文件**的持久化消息队列。生产者（appender）把消息顺序写进映射的内存，实际写进了操作系统的页缓存；消费者（tailer）可以从任意位置读取。

因为文件的页在页缓存里，同一台机器上多个进程映射同一个文件，就共享同一份数据，不需要网络、不需要 broker、不需要额外拷贝。进程崩溃时，已写入页缓存的数据仍由内核保留并最终写盘，所以说“写入即落盘”（机器断电时未刷盘的部分除外）。写入成本接近一次内存写，通常是微秒量级，而且读写接口是无垃圾的。常见用途：事件日志（journal）、审计、进程间通信。
