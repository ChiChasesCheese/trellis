## Q
为什么遍历 `Fill[]`（100 万个对象的数组）比遍历 `long[]` 慢得多？

## A
`Fill[]` 里存的只是 100 万个**引用**（指针），对象本身散落在堆的各处。对象经过交错分配和 GC 搬动后，通常不再保证连续。遍历时每个元素要先读数组里的引用，再**跟着指针**跳到对象去读字段，等于每个元素多一次内存访问。

这些访问地址不规则，CPU 的硬件预取器很难预测，每次未命中缓存的访问约 100 ns（L1 命中约 1 ns）。`long[]` 则是一段连续内存，一条 64 字节缓存行装 8 个 `long`，顺序读取时预取器提前把后面的数据拉进来，几乎全部命中缓存。

结果是两者可相差数倍到一个数量级，而且 GC 还要多追踪 100 万个对象。
