## Q
垃圾回收器为什么要让所有应用线程停下来（stop-the-world，STW）？停顿的长短取决于什么？

## A
GC 要先标记哪些对象还活着，通常还会把活对象搬到一块连续区域（复制或整理），避免内存碎片。搬家时如果应用线程同时在读写这些对象，就可能读到搬到一半的数据，或者用着已经失效的旧地址。最简单的办法就是让所有应用线程暂停，GC 干完再放行。

停顿时长取决于**要搬多少活对象**，而不是垃圾有多少。量级：年轻代回收通常几毫秒（G1 的一个实验里 3～7 ms）；整堆 Full GC 可达数百毫秒到秒级。对交易系统，几毫秒已经是几十个行情包的间隔了。
