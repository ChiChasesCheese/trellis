## Q
与 `ArrayBlockingQueue` 相比，Disruptor 快在哪里？有哪些限制？

## A
`ArrayBlockingQueue` 用一把锁保护队首和队尾，每次 `put`/`take` 都加锁，竞争时线程要挂起再唤醒（进内核，微秒级）；队首和队尾的计数器落在同一缓存行，有伪共享；每个元素都是新建的对象，产生垃圾。Disruptor 则是无锁、预分配、带填充、可批处理。官方技术论文的对比中，单次传递延迟相差两三个数量级（几十微秒对几十纳秒）。

限制：
- 容量固定且为 2 的幂；满了生产者要等待或失败（背压）；
- 事件对象可变，消费者必须在生产者绕一圈覆盖前处理完，慢消费者会拖住生产者；
- 多个生产者要用 CAS 抢槽位，比单生产者慢；
- 编程模型是事件处理器图，比普通队列复杂。
