## Q
Chronicle Queue 的队列可以回放，这对交易系统有什么价值？

## A
做法：把所有输入（行情、订单指令）按到达顺序写入队列，业务引擎是确定性的，那么从头（或某个快照之后）回放同一条队列，状态必然重现。

价值：
- **崩溃恢复**：进程重启后重放日志，重建订单簿和持仓；
- **事后排查**：拿线上某一天的输入，在测试机上重放来复现 bug；
- **审计与合规**：每条指令有序留存；
- **回归与基准**：用真实流量压测新版本，对比输出是否一致。

与传统队列不同，读取**不消耗数据**：多个 tailer 可以各自从任意位置读，互不影响；数据保留多久由文件滚动和清理策略决定，而不是读一次就没了。
