## Q
“零垃圾（garbage-free）编码”的目标是什么？为什么稳态下不分配就能彻底避开 GC 停顿？

## A
目标是：程序启动并预热完成后，热路径上**不再 `new` 任何对象**，堆里没有新增垃圾。做法是启动时把要用的对象、数组、缓冲区一次性预分配好，运行时只复用、只覆盖字段。

原因很直接：GC 的触发频率约等于分配速率除以年轻代大小；分配速率为 0，年轻代就永远填不满，也就没有 GC 停顿。

例：处理一条行情消息会产生约 400 字节垃圾（典型的对象图订单簿大约每条命令 400 字节），每秒 100 万条就是 400 MB/s，1 GB 的年轻代约 2.5 秒就要回收一次；改成零分配后，一次都不会发生。
