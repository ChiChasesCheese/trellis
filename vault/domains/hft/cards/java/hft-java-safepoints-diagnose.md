## Q
GC 日志显示最长暂停只有 2 ms，但应用的延迟监测却记录到约 80 ms 的停顿，应该怎样排查？

## A
这种“GC 说没问题、应用却卡了”的矛盾，是 JVM 停顿的典型线索。排查思路：
1. 先用**卡顿探测线程**（hiccup meter）确认：一个线程每 1 ms 睡一次，记录实际醒来比预期晚多少；如果整个 JVM 暂停，它必然晚醒，说明是全局停顿而不是业务代码慢；
2. 对齐时间戳，看 `-Xlog:safepoint` 里同一时刻是否有一次长的 safepoint，对比“到达安全点的时间”和“停顿时间”：前者大，说明有线程迟迟不到安全点；
3. 在 JFR 或线程转储里找出那时正在跑长循环或本地调用的线程；
4. 如果 JVM 一侧都对不上，再查操作系统：CPU 频率、调度、透明大页。

先测基线：测量工具自己也有噪声。
