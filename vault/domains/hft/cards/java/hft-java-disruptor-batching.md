## Q
Disruptor 的批处理（batching）为什么能让消费者在落后时反而更快地追上？

## A
消费者向等待策略请求时，拿到的是“当前最大可用序号”。如果生产者已经发布到 105，而消费者刚处理完 100，它一次拿到 101～105 共 5 个事件，在一个循环里连续处理，最后才更新一次自己的序号。

所以积压越多，每批越大，而每个事件分摊到的同步成本（写序号、内存栅栏、缓存行在核间传递）越小。消费者“越落后越高效”，队列不会因为积压而越来越慢。处理器还能通过 `endOfBatch` 标志，在一批结束时统一做一次昂贵操作，比如一批事件只写一次磁盘。

对比传统有界阻塞队列：每个元素都要加锁、解锁、通知，积压时竞争反而更激烈。
