## Q
在单生产者单消费者队列里，生产者先写数据槽，再用普通（非 volatile）变量更新“已发布序号”，会出什么问题？

## A
编译器或 CPU 可能把“更新序号”重排到“写数据槽”之前，消费者也可能一直读到缓存的旧序号。结果是：消费者看到序号变了，却读到槽里的旧数据，或者只写了一半的数据。

例：槽里原来是价格 100、数量 5，生产者写成价格 101、数量 7。消费者可能读到“价格 101、数量 5”，据此下出一个根本不存在的订单。这类 bug 在测试里几乎不出现，因为 x86 比较守规矩，而且一旦 JIT 优化方式变化才会暴露；到了 ARM 或线上高负载就突然出现。

修法：序号用 `setRelease` / `getAcquire`（或 `volatile`），保证“序号可见时，序号之前写的数据也可见”。
