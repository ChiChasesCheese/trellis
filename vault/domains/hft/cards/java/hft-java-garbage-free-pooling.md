## Q
对象池（object pool）和复用可变对象是怎样减少垃圾的？使用时要小心什么？

## A
做法：启动时预先建好 N 个 `Order` 对象放进数组；用的时候取出来、填字段，用完**清空并归还**，而不是丢给 GC。这样热路径上没有 `new`，也就没有垃圾。池里的对象长寿，会被晋升到老年代，不再被反复回收。

风险都在“可变”和“复用”上：
- 归还时忘记清字段，残留数据污染下一个订单（正确性 bug）；
- 归还后还有别处持有引用，继续读写，等于用了别人的对象；
- 池太小，要么阻塞等待，要么退回 `new`，零分配的承诺就破了；
- 多线程共享池要加同步，或每线程一个池。

代价是代码更难读、更容易出错，所以只用在真正的热路径。
