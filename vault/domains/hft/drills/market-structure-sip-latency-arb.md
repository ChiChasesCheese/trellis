# 练习：同一时刻，两个人看到的是两个 NBBO

交易所 A 上某只股票的报价在 t = 0 从 10.00 / 10.01 涨到 10.02 / 10.03。交易所 B 上有人挂着 10.01 卖 1000 股，他靠汇总行情（SIP，Securities Information Processor，把各交易所报价合成全国最优买卖价 NBBO 再广播的系统）看价格，约 100 µs 后才知道 A 涨了。你的同事靠交易所直连行情（direct feed），t = 0 就知道。美股的三个主要交易所各在新泽西的一个数据中心，两两相距约 50 公里。

**要你给出的**
- 画出 t = 0 到 100 µs 的时间线：直连用户和 SIP 用户各在什么时刻看到什么；谁能赚钱，1000 股赚多少；这种赚钱方式在业内为什么受批评。
- 解释公司为什么要订所有交易所的直连行情并自己算一份 NBBO，要付哪些成本，自己算错会怎样。
- 一笔买单要 1200 股、最高愿付 10.03；A 有 500 股 @10.01，B 有 300 股 @10.02，C 有 1000 股 @10.03。写出怎样用跨市场扫单（ISO，Intermarket Sweep Order）一次扫完，各成交多少，并说明为什么这样发单不违反订单保护规则。
- 给三个数据中心的部署提一条建议，并写出光速给出的延迟下界。

**评分要点**
- SIP 是在直连路径上多加了几步：交易所 → SIP 机房 → 排序并计算 NBBO → 再广播；比直连慢几十到几百微秒，行情繁忙时更长 ([[hft-sip-direct-what-is-sip]], [[hft-sip-direct-delay]])
- 延迟套利：直连用户在 B 以 10.01 抢先买入 1000 股，价格已涨到 10.02，转手卖出，每股赚 0.01，共 10 美元；B 上靠 SIP 的人被吃掉。重复几千次就是一门生意 ([[hft-sip-direct-latency-arbitrage]])
- NBBO 是各场所最高买价和最低卖价的合成，不属于任何一家交易所；官方版本由 SIP 发布，HFT 自己用直连合成一份更早的 ([[hft-reg-nms-nbbo]])
- 自己算 NBBO 的成本：每个交易所单独收的数据费和端口费，每家协议不同要自己写解码和重建订单簿，任何一路直连丢数据合出的 NBBO 就是错的，必须有检测 ([[hft-sip-direct-who-uses-what]])
- 订单保护规则禁止穿价成交，价格优先在全市场成立、时间优先不跨场所；ISO 由发单方同时给每个有更好报价的场所各发一单并打标记，成交 500 + 300 + 400 = 1200 股，责任在发送方 ([[hft-reg-nms-order-protection]], [[hft-reg-nms-iso]])
- 光在光纤里约 200 km/ms，50 公里单程 50 ÷ 200 = 0.25 ms，即 250 µs；微波约 300 km/ms 也要约 170 µs。所以套利公司在每个数据中心都放机器，本地看、本地下单，只在内部同步信号 ([[hft-colocation-geography]], [[hft-colocation-why]])
- 机房内部用等长线缆：光纤每米约 5 ns，最近和最远的机柜差 90 米就是 450 ns，不做的话机柜位置会变成可以买的优势；做了以后竞争回到软件、网卡和 FPGA ([[hft-colocation-equalized-cabling]])
- 延迟再低也不能绕过下单前风控：市场准入规则要求订单发出之前就由自己控制信用上限、错误订单和合规检查，所以风控只能做得更快（整数比较，甚至放进 FPGA），不能省 ([[hft-rules-market-access]])
