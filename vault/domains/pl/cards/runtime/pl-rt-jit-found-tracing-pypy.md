## Q
追踪 JIT（tracing JIT，PyPy 的做法）和 CPython 的 copy-and-patch JIT 分别是什么？与 HotSpot 的方法 JIT 有什么不同？

## A
**方法 JIT**（HotSpot、V8）：以**函数/方法**为单位编译，把整个热方法翻译成机器码。

**追踪 JIT**（PyPy、LuaJIT）：以**热循环的一次实际执行路径**为单位。流程：
1. 解释执行时给循环计数，计数超过阈值就开始**记录**（trace）：把循环体这一次迭代里实际走过的每一步操作录下来，不管函数边界，分支只记录走过的那一边；
2. 把这条线性的轨迹优化（消除类型检查、拆开对象、常量折叠）并编译成机器码；
3. 轨迹里的每个分支处加一个**守卫**（guard）：检查“这次还是走录制时的路径吗、类型还是一样吗”；守卫失败就退回解释器，并可能录制新的轨迹。

好处：对**动态语言**的热循环极有效，因为轨迹记录下了具体类型，整条路径可以按类型特化。PyPy 用 RPython 工具链从一个解释器**自动生成**这套 JIT。

实测（一次测量，纯 Python 的素数计数循环，40 万以内）：CPython 3.14 默认 0.33 秒；PyPy 3.11 约 0.02 秒，约快 16 倍。代价：与依赖 C API 的扩展（NumPy 等）兼容性差，启动与内存开销更大。

**copy-and-patch JIT**（CPython 3.13 起的实验性 JIT，PEP 744）：构建 CPython 时，为每一种“微操作”（字节码拆成的更小单元）用 C 预先编译好一段机器码**模板**，里面留着需要运行时填入的“洞”（常量、跳转目标）。运行时的 JIT 只做：把需要的模板**拷贝**到一段内存里，把洞**修补**成具体值，串成一段机器码。
- 优点：编译极快、实现简单、不需要在 CPython 里引入一个完整的编译器后端，维护成本低；
- 局限：没有跨指令的深度优化（没有内联、没有基于类型的特化），所以收益有限。需要用 `PYTHON_JIT=1` 开启，本机同一个素数循环开启后 0.51 秒，比默认的 0.33 秒还慢。

一句话区别：方法 JIT 编译“函数”，追踪 JIT 编译“热路径”，copy-and-patch 拼接“预制的零件”。
