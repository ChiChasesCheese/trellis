## Q
内存分配在各语言里要花多少？堆分配、栈分配、逃逸分析和 GC 在“分配成本”里各扮演什么角色？

## A
**栈 vs 堆**：栈上的局部变量随函数调用自动分配和释放，只是移动栈指针，几乎免费。堆上的对象由分配器管理，需要找空闲块，之后还需要回收。
**逃逸分析**（escape analysis）：编译器判断一个对象是否会“逃出”当前函数（被存入全局变量、返回给调用者、传给别的线程）。没有逃逸的对象，可以放在栈上，甚至拆成几个局部变量，根本不分配。

实测（Apple Silicon，创建 1 亿个含两个 `long` 的小对象，一次测量）：

| 语言 | 逃逸到堆（存入全局变量） | 不逃逸（栈 / 标量替换） |
|---|---|---|
| Go | 约 4.5 ns / 个，期间 GC 运行 439 次 | 约 0.23 ns |
| Java | 约 3.4 ns / 个 | 约 0.23 ns（JIT 的逃逸分析消除了分配） |
| Rust | 约 5.6 ns / 次 `Box` 分配加释放 | 值类型直接在栈上，本质无分配 |
| Python | 约 50 ns / 个（带 `__slots__` 的类实例） | 无逃逸分析，每个对象都分配 |

**GC 的角色**：分配本身便宜（“指针碰撞”），贵的是之后的回收。追踪式 GC（Go、Java）要定期遍历活跃对象；分配得越快，GC 越忙，CPU 和暂停时间都会受影响。Rust 在值离开作用域时立刻释放（`Drop`）；Python 在引用计数归零时立刻释放。

**规律**：
1. 堆分配约几纳秒到几十纳秒；逃逸分析成功后接近零，差两个数量级。
2. 热路径上的分配会通过 GC 压力放大成额外的 CPU 与延迟抖动。
3. 所以“**减少分配**”常常是最有效的性能手段：复用缓冲区、避免临时对象、选择不逃逸的写法。
