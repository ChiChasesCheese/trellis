## Q
面对“这段代码慢”，资深工程师的排查与优化流程是什么？各语言里最常见的优化点是什么？

## A
**流程**：
1. **定义目标与度量**：延迟（p50、p99）还是吞吐？目标数值是多少？在接近生产的数据与并发下测量。
2. **剖析，不要猜**：CPU 剖析找热点函数，分配剖析找谁在制造垃圾，火焰图看全貌。Java 用 JFR / async-profiler，Go 用 `pprof` 与 `trace`，Rust 用 `perf` / flamegraph / criterion，Python 用 `cProfile` / `py-spy`。
3. **从大到小下手**：算法和数据结构 → 减少 I/O 与往返 → 并发度 → 内存布局 → 分配 → 常数因子。
4. **每次只改一处，重新测量**，保留基准以防回退。

**各语言常见高回报点**：
- **Java**：去掉热路径的装箱（用原始类型数组、原始类型流，本机实测 `int[]` 对洗牌后的 `ArrayList<Integer>` 快约 15 倍）；减少短命对象与分配；用 JMH 验证，注意预热；检查 GC 日志与堆大小。
- **Go**：减少堆分配（预分配切片容量、复用缓冲区 `sync.Pool`、避免热路径上的接口装箱）；看逃逸分析输出；热路径避免锁争用；`GOGC`/`GOMEMLIMIT` 调整内存与 GC 的取舍。
- **Rust**：保证 `--release`；避免不必要的 `clone`；热路径避免 `Box<dyn Trait>`；利用迭代器让编译器向量化；必要时再看 SIMD、`unsafe`。
- **Python**：换算法与数据结构；用内置函数与推导式；向量化库（NumPy、Polars）；函数内局部变量；`multiprocessing` 或 C/Rust 扩展处理 CPU 密集。

**通用准则**：
1. **让数据连续**：数组优于链表，结构体数组优于对象图；
2. **减少每个元素上的固定开销**：批量处理，边界调用一次传一整块；
3. **能不分配就不分配**，能复用就复用；
4. **不要为可读性不好的优化付费，除非它出现在剖析的前几名**；
5. **写下优化的原因和数据**，让后来的人知道什么时候可以安全撤销。
