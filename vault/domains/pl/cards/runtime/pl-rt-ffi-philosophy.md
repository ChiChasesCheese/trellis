## Q
Python 为什么是“胶水语言”，Rust 和 C++ 为什么适合与别的语言“共存”，而 Go 却倾向于“重写而非绑定”？这些分别反映了什么价值观？

## A
**Python：我只做编排，重活交给别人。** 解释器的对象模型就是 C 结构体，所以绑定 C 库几乎是零阻力的事；几十年里积累了 NumPy、SciPy、PyTorch 这些“Python 外壳、C/Fortran/C++/CUDA 内核”的库。价值观是：**让人用最高的效率表达想法，性能靠生态下沉。** 副作用是性能关键代码都不在 Python 里，调试跨语言困难，打包（wheel 的平台矩阵）复杂。

**Rust：可以和 C 平等对话。** 没有运行时和 GC，数据布局可控（`#[repr(C)]`），所以导出的函数就是普通 C 函数。价值观是：**能逐步替换 C/C++，而不是推倒重来。** Linux 内核、Android、浏览器引擎、Python 的 Polars/Ruff，都是“在已有系统里一块一块换成 Rust”。

**C++：与 C 同源，是互操作的另一端。** 从第一天起承诺兼容 C（Stroustrup 的 “C with Classes”），所以 C 的库、系统接口和 ABI 全部直接可用，这既是它能在存量代码里落地的原因，也让它背上了 C 的全部包袱。价值观是：**不要求世界迁就我，我去适应世界**。大多数“Python 外壳、原生内核”的库内核是 C++，别的语言通过 `extern "C"` 或 pybind11 之类的绑定调用它。

**Go：自成一体。** 自己的调度器、自己的栈、自己的工具链，进入 C 要付出切栈和构建复杂度。价值观是：**简单、统一、可部署**。所以 Go 生态的惯例是：把 C 库用纯 Go 重写（`net` 的 DNS 解析、纯 Go 的 SQLite、加密库），宁可多写代码也不引入 cgo。

**Java：长期的“纯 Java”主义。** 平台强调可移植与安全，JNI 难用且危险，生态的主流是把一切移植成 Java（所谓“100% Pure Java”）。但性能库、操作系统接口的需求迫使平台推出 Panama 项目的 FFM API，在保持安全检查的前提下开放原生互操作。

共同规律：**一门语言对 FFI 的态度，取决于它想成为“世界的中心”还是“世界的一员”。** 想做中心（Go、Java）的语言倾向把原生代码当外来者，设门槛；想做成员（Python、Rust、C++）的语言把互操作当作核心设计。互操作能力也决定了语言能多快接入已有的生态：C++ 靠兼容 C 起家，Python 靠 C 扩展起家，Rust 靠和 C++ 共存立足。
