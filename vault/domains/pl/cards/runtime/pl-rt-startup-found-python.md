## Q
Python 启动时发生了什么？为什么 `import` 会成为启动时间的主要来源？怎么找出哪个导入最慢？

## A
**Python 启动流程**：运行 `python3 script.py` 时：
1. 启动解释器：初始化内置类型、内存分配器、`sys`、编码、`site` 模块（把第三方包目录加入 `sys.path`）。
2. 编译脚本：解析成字节码；被导入的模块若有 `__pycache__` 里的 `.pyc` 缓存且源码未变，则跳过编译直接加载。
3. 执行脚本顶层代码：`import x` 语句是**运行时**行为：在 `sys.path` 里找到模块、读取 `.pyc`、**执行模块顶层代码**（定义函数、类、可能再导入别的模块），结果缓存到 `sys.modules`。

关键认识：**导入不是声明，而是执行代码**。导入一个大包，等于运行它所有的顶层代码并传递地导入它依赖的全部模块。

实测（一次测量，20 次或 7 次取中位数）：
| 命令 | 耗时 |
|---|---|
| `python3 -c pass` | 约 7.5 毫秒 |
| `python3 -S -E hello.py`（不加载 `site`、忽略环境变量） | 约 6.5 毫秒 |
| 导入 `asyncio`、`json` | 约 25 毫秒 |
| 导入 `numpy` | 约 32 毫秒 |
| 导入 `pandas` | 约 121 毫秒 |

解释器自身启动约 7 毫秒，而一个典型的数据处理脚本光导入就要上百毫秒。

**定位慢导入**：`python3 -X importtime -c "import json"` 会逐个模块打印“自身耗时 / 累计耗时”（微秒），输出形如：
```
import time: 90 | 3063 | json
```
最后一列是模块名，缩进表示被谁导入。累计耗时大的就是该优化的。

常见手段：把重模块的导入推迟到真正用到的函数内（惰性导入）；避免在模块顶层做 I/O 或建立连接；确保 `.pyc` 可写或预先生成。
