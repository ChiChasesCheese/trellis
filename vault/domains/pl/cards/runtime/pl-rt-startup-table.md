## Q
Go、Rust、C++、Java、Python 在启动与内存占用上各站在设计空间的哪一点？分别换来什么、付出什么？

## A
| 语言 | 选择 | 换来 | 代价 |
|---|---|---|---|
| Go | 静态原生二进制 + 自带运行时（GC、调度器） | 启动约 3 毫秒，部署即一个文件 | 运行时随二进制，文件较大（约 2 MB 起）；GC 带来内存余量 |
| Rust | 静态原生二进制，几乎无运行时 | 启动约 2 毫秒，基线内存最小，余量近零 | 构建慢；放弃运行时灵活性 |
| C++ | 原生二进制，动态链接系统的 C++ 运行库（也可静态链接），无运行时初始化 | 启动约 2 毫秒，基线内存约 1.7 MB，几乎无余量 | 动态链接要求目标机有匹配的库版本；静态链接体积变大；`main` 之前的全局对象构造顺序跨文件不确定，是出名的坑 |
| Java | 平台模式：JVM 解释 + JIT，类动态加载 | 稳态高性能，动态性强（反射、热加载） | 启动约 24 毫秒起，基线内存约 40 MB，框架会放大到秒级；有预热 |
| Python | 解释器 + 源码 + 运行时导入 | 零编译、最快的修改-运行循环 | 启动约 7 毫秒，导入重包可达上百毫秒；每个对象开销大 |

背后的逻辑：
- 这是“**构建时决定多少**”的光谱。Go、Rust 在构建时决定一切，启动只剩运行时初始化；Java 把类加载、链接、编译推迟到运行时；Python 把几乎一切推迟到运行时。
- 越晚决定，越灵活，也越慢启动、越占内存。Java 的反射、动态代理、热部署，Python 的猴子补丁，都建立在“运行时才定”上。
- C++ 与 Rust 站在同一端：没有强制运行时，`main` 之前只有动态链接和全局对象的构造。启动成本几乎等于操作系统加载一个进程；这是零开销原则（不用的不付费）的直接体现。
- 内存余量的差别源于回收方式：所有权/引用计数几乎无余量，追踪式 GC 用余量换吞吐。
- 因此对短命和高密度场景（CLI、Serverless、sidecar、大量小服务），Go 和 Rust 有结构性优势；对长期运行的大服务，Java 的稳态性能和生态仍有竞争力，Python 则靠开发效率。
