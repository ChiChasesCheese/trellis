## Q
Go、Java、Rust、Python、C++ 各自在性能模型的五类成本上付了哪些，躲掉了哪些？
这对它们擅长的场景意味着什么？

## A
| 语言 | 躲掉的 | 付出的 | 擅长 |
|---|---|---|---|
| C++ | 解释、装箱、GC；分配与间接都由你显式控制 | 编译时间；未定义行为（UB）与内存错误的风险；虚函数、`std::function`、`shared_ptr` 的间接与原子计数 | 延迟敏感、资源受限、游戏、高频交易、数据库与运行时本身 |
| Rust | 解释、装箱、GC、分配隐藏成本（可控） | 编译时间、所有权的学习成本；`dyn`/FFI 边界的间接 | 延迟敏感、资源受限、系统组件 |
| Go | 解释、大部分装箱（结构体内联） | GC（并发、低暂停但有成本）；接口调用与逃逸到堆；较保守的优化 | 网络服务、云原生工具，吞吐与简单性平衡 |
| Java | 解释（JIT 后）、部分分配（逃逸分析） | 对象头和装箱、GC、预热、虚调用（靠 JIT 内联摊销） | 长期运行的大型后端，稳态吞吐高 |
| Python | 无（五类全付） | 解释、装箱、动态分派、引用计数 | 编排、胶水；性能靠 C/Rust 内核 |

背后的逻辑：
- **每门语言都在用某种价值买性能的折扣**：Rust 买它用的是程序员的学习成本；Go 用的是表达力（泛型来得晚、抽象少）；Java 用的是内存和预热；Python 用的是几乎全部性能，换来了开发速度。
- 性能最敏感的是“**每个元素的成本**”：Python 的 12 ns 对一次函数调用不重要，对 10 亿次循环致命。因此 Python 的生态都围绕“批量化”：NumPy、Polars、PyTorch。
- Java 与 Go 在中间：Java 的稳态吞吐与 Go 相当甚至更高（JIT 优化更激进、GC 更成熟），Go 的启动、内存、尾延迟更好控制。
- Rust 与 C++ 的性能上限最高，但达到它的前提不同：Rust 要你为所有权和编译时间买单，C++ 要你自己保证没有 UB 与内存错误。C++ 用安全换取最大的控制权（零开销原则、手动内存管理），这也是游戏引擎、数据库、交易系统以及 JVM 的 HotSpot、V8 这类运行时本身仍然用 C++ 写的原因。
- 真实系统的性能通常由**数据结构、I/O、并发度**决定，语言本身的常数因子只是其中一项。
