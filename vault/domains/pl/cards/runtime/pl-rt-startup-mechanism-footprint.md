## Q
一个进程的内存占用由哪几部分组成？为什么同样持有 200 MB 的活跃数据，Rust、Python、Go、Java 的常驻内存（RSS）差别这么大？

## A
进程的常驻内存 ≈ **运行时基线** + **活跃数据（live set）** + **回收余量（headroom）**。
- 运行时基线：解释器、JIT、类元数据、线程栈、代码缓存。Hello World 的 RSS：Rust 约 1.8 MB，Go 约 4.2 MB，Python 约 16 MB，Java 约 40 MB。
- 活跃数据：程序真正还在用的对象，各语言基本相同。
- 回收余量：已经不用、但内存还没还给操作系统的部分。它由**内存回收方式**决定。

实验：持有 200 MB 活跃数据，再反复分配并丢弃 2 GB 的 1 MB 缓冲区（所有页面都被写入，一次测量）：

| 语言 | 最大 RSS | 原因 |
|---|---|---|
| Rust | 约 203 MB | 所有权：值离开作用域立刻释放，没有余量 |
| Python | 约 222 MB | 引用计数：计数归零立刻释放 |
| Go | 约 510 MB（`GOGC=50` 约 346 MB，`GOMEMLIMIT=250MiB` 约 243 MB） | 追踪式 GC 默认让堆长到活跃数据的约 2 倍才回收 |
| Java（G1 默认） | 约 2176 MB（`-Xmx300m` 约 201 MB） | 默认最大堆是物理内存的 1/4（本机 4 GB），G1 在堆里“有空间就不急着回收” |

规律：
- **追踪式 GC 用内存换 CPU**：余量越大，回收越少、吞吐越高；限制得越紧，回收越频繁。
- Go 提供两个旋钮：`GOGC`（回收触发的增长比例）和 `GOMEMLIMIT`（软内存上限）。
- Java 的堆上限由 `-Xmx` 或 `-XX:MaxRAMPercentage` 决定；容器里必须设置，否则按宿主机或容器限额的默认比例来。
- 引用计数与所有权下，余量接近零，但每个对象有计数或元数据成本，且可能有内存碎片。

数字不是“哪门语言更省内存”的排名，而是说明：**RSS 取决于回收策略和你给的上限，不只是数据本身。**
