## Q
CPython 3.11 引入的自适应特化解释器（specializing adaptive interpreter）是什么？它怎样在不改变语义的前提下让字节码变快？

## A
**思路**：把 JIT 的“根据观察到的类型押注”搬进解释器。每条字节码对应一个**通用**版本（能处理任何类型）和若干**特化**版本（只处理特定类型，更快）：
1. 一条 `BINARY_OP` 最初是通用的，每次执行都要走完整的类型分派。
2. 执行若干次之后（热点预热），解释器观察到操作数一直是 `int`，就把这条指令**就地改写**为 `BINARY_OP_ADD_INT`（称为 quickening）。特化版本先检查“两个都是 int 吗”（守卫），是就直接做整数加法，否则退回通用版本，必要时重新特化。
3. 属性访问、全局变量查找、函数调用也有特化版本，并用**内联缓存**（inline cache，存放在字节码后面的缓存槽）记住类型版本号、属性偏移、全局字典版本，省掉字典查找。

真实演示（`dis.dis(add, adaptive=True)`，函数 `add(a, b): return a + b`）：
- 用整数调用 2000 次后：`BINARY_OP_ADD_INT`
- 改成字符串调用多次后：`BINARY_OP_ADD_UNICODE`

指令在运行中自己变了，它仍然是同一份源代码的同一个语义，只是针对当前类型走了快车道。

**效果与局限**：
- 官方称 3.11 平均比 3.10 快约 25%（pyperformance 基准，因程序而异）。
- 它仍然是解释器：每条字节码仍要分派，整数仍是堆对象（只是减少了分配），没有跨语句的优化。收益是“把动态的开销削掉一层”，而不是质变。
- 特化依赖**类型稳定**：同一个位置一会儿 int 一会儿 str，会反复去特化和重新特化，退回慢路径。
