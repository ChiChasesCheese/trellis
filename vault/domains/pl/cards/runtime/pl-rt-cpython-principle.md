## Q
CPython 解释器的基本设计是什么？它是怎样执行一段 Python 代码的，为什么这种设计天然比 AOT 编译的语言慢？

## A
**设计**：CPython 是 Python 的参考实现，用 C 写成，是一个**字节码虚拟机**：
1. **编译**：源码被解析成 AST，再编译成字节码（`.pyc` 缓存），一种基于栈的指令序列，如 `LOAD_FAST a`、`BINARY_OP +`、`RETURN_VALUE`。这一步在导入模块时发生，很快。
2. **解释**：一个大循环（求值循环，eval loop）逐条取出字节码，用一个巨大的分派表跳到对应的 C 代码执行。
3. **数据模型**：一切都是对象。每个值（包括整数）都是堆上的 `PyObject`，对象头有引用计数和类型指针，操作通过类型的函数表分派（`a + b` 要问 `type(a)` 怎么加）。

**设计空间**（执行动态语言的几条路）：解释字节码（CPython）；JIT 编译（PyPy）；编译成 C 再编译（Cython、Nuitka）；静态类型子集 AOT（Mojo 等）。CPython 选了最简单、最易移植、最容易和 C 库对接的一条。

**为什么慢**，每一层都有成本：
- **分派开销**：每条字节码一次间接跳转，CPU 的分支预测难受；
- **装箱**：整数 `1` 占 28 字节（对象头 + 数值），`a + b` 要分配新对象（小整数有缓存）；
- **动态类型检查**：每次加法都要查类型、找 `__add__`；
- **引用计数**：每次赋值、传参都要增减计数；
- **没有跨语句优化**：解释器看不到两条指令之外的东西，不能内联、不能消除重复。

实测（一次测量）：函数内循环 `s += i`，CPython 3.14 约 12.4 纳秒 / 次；等价的 Go 循环约 0.22 纳秒 / 次，差约 55 倍。这是“解释 + 装箱 + 动态”叠加后的数量级。
