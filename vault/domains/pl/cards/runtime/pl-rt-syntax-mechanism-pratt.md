## Q
Pratt 解析（binding power，绑定力）怎样用不到 15 行代码处理任意多级优先级和结合性？为什么手写解析器的表达式部分几乎都用它？

## A
朴素的递归下降要为每个优先级写一个函数（加法级调用乘法级，乘法级调用幂级……），十几级就是十几个函数，加一个运算符要改一串。**Pratt 解析**把“优先级”变成一张表：每个二元运算符有一对**绑定力**（左、右），解析函数只有一个，带一个参数 `min_bp`，意思是“你要吞掉的运算符，左绑定力至少要这么大”。

```python
BP = {'+': (10, 11), '-': (10, 11), '*': (20, 21), '^': (31, 30)}  # (left, right)
def parse(toks, min_bp=0):
    t = toks.pop(0)
    lhs = int(t) if t.isdigit() else parse_group(toks)
    while toks and toks[0] in BP and BP[toks[0]][0] >= min_bp:
        op = toks.pop(0)
        lhs = (op, lhs, parse(toks, BP[op][1]))
    return lhs
```
（`parse_group` 解析括号，略。）输出：`8-3-2` 得 `('-', ('-', 8, 3), 2)`（左结合），`2^3^2` 得 `('^', 2, ('^', 3, 2))`（右结合），`1+2*3` 得 `('+', 1, ('*', 2, 3))`。

**结合性怎么来的**：加号的右绑定力 11 比左绑定力 10 大，递归调用时 `min_bp=11`，遇到下一个 `-`（左绑定力 10）就不够格，于是回到外层循环，结果是左结合；`^` 反过来，右绑定力 30 比左绑定力 31 小，递归调用能继续吞下一个 `^`，结果是右结合。

**为什么常用**：加运算符只是往表里加一行；一元、后缀、三元运算符也只是表项的变种；不用生成器，也没有文法冲突要消解。代价：它只管表达式，语句和声明仍靠普通递归下降。
