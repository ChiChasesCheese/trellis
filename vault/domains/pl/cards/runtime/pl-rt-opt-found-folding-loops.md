## Q
常量折叠（constant folding）、死代码消除（dead code elimination）和循环优化分别是什么？为什么 Rust 能把 `(1..=n).sum()` 的循环直接换成一个公式？

## A
这些优化都靠一个前提：编译器把代码改写成 SSA（每个变量只赋值一次的中间表示）后，每个值从哪来、被谁用，一目了然。

- **常量折叠/传播**：编译期就能算出来的表达式提前算好，并把结果代入后面的使用。CPython 在编译字节码时也做：`def f(): return 3*4 + 1` 的字节码只有 `LOAD_SMALL_INT 13`，运行时没有乘法。
- **死代码消除**：结果没人用、或者永远不会执行的分支，直接删掉。常量传播之后，`if 12 > 100 { ... }` 整个分支就成了死代码。
- **强度削弱**（strength reduction）：用便宜的操作代替贵的，如乘 2 换成左移。
- **循环优化**：外提不变量、展开循环、向量化，以及最强的一种：LLVM 的“标量演化”分析能识别出循环里的累加量是等差/多项式变化，把整个循环**替换成闭式公式**。

一个有说服力的真实例子，Rust：
```rust
pub fn sum_to(n: u64) -> u64 { (1..=n).sum() }
```
`rustc -O` 生成的 ARM64 汇编里没有循环、没有跳回，只有乘法和移位：`sub x8, x0, #2; sub x9, x0, #3; mul ...; umulh ...; extr ...`，即算 n(n+1)/2 的等价公式。1 亿次迭代变成大约十条指令，耗时不随 n 增长。

结论：优化器的上限不是“把每条指令变快一点”，而是**识别出你想要的数学对象然后换一个算法**。这依赖 AOT 编译器能看到完整循环和确定的整数语义；对应地，你在 debug 构建里看到的是真的一亿次迭代，性能测试必须用优化后的构建。
