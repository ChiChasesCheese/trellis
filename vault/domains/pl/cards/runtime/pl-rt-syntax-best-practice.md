## Q
资深工程师在日常代码、自己设计配置/DSL、写代码分析工具时，对语法和解析应该遵守哪些原则？

## A
**读写代码时**：
1. 把格式交给工具，不在评审里争论：Go 的 `gofmt`、Rust 的 `rustfmt`、Java 的 google-java-format、Python 的 `black`/`ruff format`，并在 CI 里检查。
2. 混用位运算、比较、逻辑运算时一律加括号。优先级表是最容易让人记错的东西，括号的成本为零。
3. 不炫耀语法技巧（链式比较的嵌套、一行嵌套三层推导式）；语法糖的价值是消除噪声，不是压缩行数。

**设计自己的配置语言或 DSL 时**：
1. 先问能不能用现成的：JSON/YAML/TOML、或者就是宿主语言本身（Python/Starlark/Lua 作配置）。自己发明语法，就要永久承担文档、工具和错误信息的成本。
2. 一定要做就刻意保持文法简单：单记号前瞻能决定的，不要依赖回溯；表达式部分用 Pratt；其余用手写递归下降。不要用正则表达式解析嵌套结构（括号、引号嵌套），它在数学上做不到。
3. 错误信息是语法设计的一部分：报出行列号、期望什么、看到什么，并尽量继续解析以一次报出多个错误。

**写代码分析/重写工具时**：
1. 永远用语言自带的解析库，不要自己 grep：Python `ast`、Go `go/ast`、Rust `syn`、Java 的 `javac` Tree API / JavaParser。
2. 需要保留注释和空白的重写（codemod）要用“具体语法树”（CST）工具，如 `libcst`、tree-sitter，而不是丢弃注释的 AST。
3. 编辑器里的高亮、折叠这类要容错的场景，用 tree-sitter 这样的增量解析器，它在语法不完整时也能产出树。

**何时打破**：一次性脚本里用正则提取几个字段完全可以，前提是你能说清楚它不会遇到嵌套。
