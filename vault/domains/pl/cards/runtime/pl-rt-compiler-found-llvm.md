## Q
LLVM 是什么？Rust 借 LLVM、Go 自研后端，这两种做法在实际编译产物和编译速度上各有什么表现？

## A
**LLVM** 是一个可复用的编译器基础设施：它定义了一种与语言和 CPU 都无关的 **LLVM IR**（SSA 形式），提供大量成熟的优化 pass（内联、循环展开、向量化、常量传播……）和面向 x86、ARM、RISC-V 等十几种 CPU 的代码生成后端。语言的前端只需把自己的程序翻译成 LLVM IR，剩下的优化与机器码生成就都有了。使用 LLVM 的有 Clang（C/C++）、Swift、Rust、Julia 等。

分工：
- **前端**（各语言自己写）：解析、类型检查、借用检查、把高层结构降成 LLVM IR；
- **LLVM 中端**：在 IR 上优化；
- **LLVM 后端**：为目标 CPU 选指令、分配寄存器、输出机器码。

**Go 的选择**：自己写编译器和后端（不用 LLVM），也基于 SSA，但优化较少、更注重编译速度。

同一个函数 `a * 2 + b` 在两条路径下的结果（ARM64）：
- Rust（LLVM）：`add w0, w1, w0, lsl #1`
- Go（自研）：`ADD R0<<1, R1, R0`
一条指令，完全一样。简单代码上没有差别。

编译速度差别（生成 3000 个小函数，一次测量）：Go 约 0.25 秒；rustc `-C opt-level=0`（几乎不优化）约 0.54 秒；rustc `-O`（LLVM 全套优化）约 3.0 秒。差距主要来自 LLVM 的优化 pass 和 Rust 前端的类型/借用检查、单态化工作。

权衡：
| | 借 LLVM | 自研后端 |
|---|---|---|
| 代码质量 | 业界顶级，免费享受新 CPU 支持与新优化 | 取决于自己投入 |
| 编译速度 | 慢（LLVM 很重） | 可以很快 |
| 工作量 | 前端即可 | 要自己维护每个 CPU 的后端 |
| 可控性 | 依赖外部大项目，LLVM 的 bug 会影响你 | 完全可控，交叉编译简单 |

这是“**复用生态**”与“**掌控速度与简单**”的选择：Rust 要拿最好的优化，选前者；Go 要快速的构建和简单的工具链，选后者。
