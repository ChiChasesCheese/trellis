## Q
CPython 里“一切皆对象”具体是什么意思？`PyObject` 的结构、整数对象的大小和 `a + b` 的分派过程是怎样的？

## A
在 CPython 里，每个值——整数、字符串、列表、函数、类——都是堆上的一个 C 结构体，开头都是同一个**对象头** `PyObject`，至少包含两样东西：
1. **引用计数**（`ob_refcnt`）：有多少引用指向这个对象；
2. **类型指针**（`ob_type`）：指向描述它是什么类型的类型对象。

变量只是**指向对象的引用**（指针）。赋值 `y = x` 只是复制了一个指针并把计数加 1，不拷贝对象。

大小可以用 `sys.getsizeof` 查看（64 位，Python 3.14，一次测量）：
- 整数 `1`：**28 字节**（对象头 16 字节 + 8 字节长度/符号标记 + 4 字节数值位）；`2**30`：32 字节；
- 3 个元素的列表：88 字节（只含列表本身的结构和指针数组，不含元素对象）；3 元素的元组：72 字节。
所以 `[1, 2, 3]` 实际占用：列表 88 + 三个整数对象（小整数 -5 到 256 是共享的缓存对象，不另算）。

**类型决定行为**：类型对象里有一张**函数表**（`tp_as_number->nb_add`、`tp_hash`、`tp_call` 等）。`a + b` 的执行：
1. 取 `a` 的类型 `type(a)`，在它的函数表里找“加法”槽；
2. 调用，传入 `a` 和 `b`；如果它返回“不支持”（`NotImplemented`），再试 `b` 的类型的反向加法；
3. 都不行就抛 `TypeError`。
这套机制让 `+` 对整数、字符串、列表、自定义类都有效，也是**动态类型和运算符重载**的基础；代价是每次加法都要经历类型查找和函数调用，不能像 C 的 `int + int` 那样编译成一条指令。

**对性能的含义**：
1. 小整数运算也要创建对象（缓存的小整数除外）；
2. 容器里存的是指针，数据分散在堆里，访问时多一次指针跳转；
3. 每个对象有 16 字节头，海量小对象的内存开销是数据本身的数倍。
