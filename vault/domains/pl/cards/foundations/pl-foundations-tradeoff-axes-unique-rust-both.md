## Q
Rust 怎样同时拿到「内存安全」和「接近 C 的控制」？它把「放弃检查」的权利放在哪里？

## A
其他三门语言基本是二选一：Go、Java、Python 用垃圾回收和强制边界检查换安全，放弃了对内存布局和释放时机的控制。C 和 C++ 相反，控制全给你，安全也交给你。

Rust 的做法是把语言分成两层：

- 安全 Rust（safe Rust）：默认层。借用检查器在编译期证明没有悬空指针和数据竞争，没有垃圾回收，没有运行时开销。
- `unsafe` 块：显式写出来的小范围逃生口，里面可以解引用裸指针、调用不做检查的函数。责任回到程序员，但范围用关键字标出来，审查者只需盯住这几处。

```rust
let v = vec![1, 2, 3];
let s: i32 = v.iter().sum();                 // 迭代器：没有下标，没有边界检查
let x = unsafe { *v.get_unchecked(2) };      // 显式放弃检查
println!("{} {}", s, x);                     // 6 3
```

代码实际输出 `6 3`。第一行不是靠检查而是靠结构避免越界：迭代器不产生下标。第二行要求你写 `unsafe`，并自己保证下标在范围内。

独有之处在于「安全是默认，不安全是显式例外」。Go 的 `unsafe` 包、Java 的 `Unsafe` 类也能绕过检查，但那是整个库的接口，Rust 把它变成了语法，可以被工具统计和审查。代价是前面讲过的：证明安全需要程序员配合，学习曲线陡。
