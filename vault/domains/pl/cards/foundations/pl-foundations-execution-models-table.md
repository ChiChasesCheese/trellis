## Q
C++、Go、Java、Rust、Python 各选了哪种执行模型？它们换来什么，又付出什么？

## A
下面的数字是「hello world」在一台 Apple Silicon 机器上的一次测量（进程启动，20 次中位数）。

| 语言 | 选择 | 换来 | 代价 |
|---|---|---|---|
| Go | 提前编译成原生可执行文件，自带运行时 | 启动约 2 ms，单文件部署，二进制约 1.8 MB | 优化深度不如 LLVM，无法利用运行时信息 |
| Rust | 提前编译，借 LLVM 优化，无运行时 | 启动约 2 ms，二进制约 0.47 MB，峰值性能高 | 编译慢，交叉编译需要目标平台工具链 |
| C++ | 提前编译（GCC、Clang、MSVC 等），无运行时，分别编译再链接 | 启动约 2 ms，动态链接标准库时二进制仅约 36 KB，优化深度与 Rust 同级 | 头文件反复解析使编译慢，产物绑定平台与 ABI（二进制接口约定），没有统一的包与构建工具 |
| Java | 字节码加 JVM，解释后 JIT | 一次编译处处运行，长时间运行后按真实数据优化 | 启动约 24 ms，要预热，JVM 本身占内存 |
| Python | 编译成字节码，由解释器逐条执行 | 启动约 8 ms，修改即运行，无构建步骤 | 稳态最慢，热点循环比 JIT 语言慢一到两个数量级 |

背后的逻辑：执行模型是在「把成本放在哪个时刻」之间选择。提前编译把成本放在构建期，所以运行时轻；字节码加 JIT 把成本放在运行期，换来可移植和基于真实数据的优化；解释器几乎没有成本放在任何地方，所以启动和开发循环最短，但每次执行都付全价。Go 的作者要的是快速构建和易部署，Rust 和 C++ 要的是最大性能（C++ 还要直接复用 C 的生态和既有二进制），Java 要的是一次编译到处运行加长期服务的峰值，Python 要的是开发速度，各自的执行模型正好对应。体积和启动数字是个例，量级关系稳定：原生约毫秒，JVM 约几十毫秒。
