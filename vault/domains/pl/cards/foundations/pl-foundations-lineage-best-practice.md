## Q
一个会 Java 或 Python 的工程师学 Go 和 Rust 时，怎样利用谱系知识快速迁移？哪些经验可以带过去，哪些必须丢掉？

## A
谱系知识的用法是：先问「这个特性的祖先是什么」，把已知的概念映射过去，再单独标记「语法像、语义不同」的假朋友（false friend）。

可以直接迁移的：

- 概念层面：Java 的接口对应 Go 的接口和 Rust 的 trait，Java 的 `Optional`（可能没有值的容器）对应 Rust 的 `Option`，Python 的生成器对应 Go 1.23 的 `iter.Seq` 和 Rust 的迭代器。
- 设计原则：依赖抽象、组合优于继承、不可变优先，这些在五门语言里都成立，只是实现手段不同。

必须丢掉的（假朋友）：

- Go 长得像 C 和 Java，但没有异常和继承；把错误当返回值，把「类」换成「结构体加方法加接口」。
- Rust 的赋值是移动（move），不是 Java 引用赋值，`let t = s;` 之后 `s` 就不能用了。C++ 也不是引用赋值：`a = b` 默认把整个对象拷贝一份（值语义），要转移所有权得显式写 `std::move`，而且被移走的对象依然存在、编译器不拦你再用。
- 整数除法和取模：Python 向下取整，Java、Go、Rust 向零取整，`-7 // 2` 是 -4 而 `-7 / 2` 是 -3。
- Python 的 `is`/`==`、Java 的 `==` 与 `equals`：引用相等和值相等的默认值不同。

迁移的方法：

1. 先读该语言的设计哲学（Go 的惯用法指南、Rust 官方教程里关于所有权的部分、Python 之禅），再学语法。
2. 写第一个项目时刻意用这门语言的惯用法，不要翻译已有项目。
3. 每遇到一个「怪」设计，回到它的祖先和痛点去找原因，而不是死记。

何时可以破例：赶时间的原型可以先翻译，但要尽早用 linter（`clippy`、`go vet`、`ruff`）把不地道的写法暴露出来。
