## Q
Go 和 Rust 都是针对 C++ 的不满而诞生的，为什么它们的做法恰好相反？

## A
两者的出发点相同：C++ 太复杂，编译太慢，写出内存错误太容易。但它们对「问题出在哪」的判断不同，于是给出了相反的药方。

Go（2009）认为问题出在特性太多。Google 的工程师在大型 C++ 代码库上要等很久才编完，团队里每个人用的 C++ 子集还不一样。药方是做减法：25 个关键字，没有继承，没有异常，没有运算符重载，编译器快，格式统一。语言故意留出空白，把并发用 CSP 的通道解决，而这部分思想并不来自 C 家族，而来自 Rob Pike 之前做的 Newsqueak 和 Limbo。

Rust（2010 公开）认为问题出在编译器没有替程序员检查内存。药方是做加法：加一个借用检查器，在编译期证明内存和线程安全，没有垃圾回收，保留 C++ 的零成本抽象。类型系统借自 ML 和 Haskell，使得 `enum` 加 `match` 能让「必须处理每种情况」由编译器强制。

结果：Go 的特点是简单到几乎没有设计空间，代价是表达力有限；Rust 的特点是几乎能表达一切并保证安全，代价是复杂度并没有比 C++ 低多少，只是把它从运行期事故转成编译期的错误信息。同一个起点、相反的哲学：一个相信「去掉就不会出错」，一个相信「检查就不会出错」。
