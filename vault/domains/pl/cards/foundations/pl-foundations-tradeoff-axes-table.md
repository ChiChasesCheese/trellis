## Q
Go、Java、Rust、Python 在五条根本权衡轴（安全与控制、表达力与简单、检查时机、性能与开发速度、兼容与演进）上各站在哪里？换来什么，付出什么？

## A
| 语言 | 站位 | 换来 | 代价 |
|---|---|---|---|
| Go | 安全优先于控制，简单优先于表达力，编译期检查，兼容承诺强 | 可读、构建快、升级几乎无痛 | 抽象手段少，样板代码多 |
| Java | 安全优先，居中表达力，编译期检查，极度向后兼容 | 大型系统可长期维护，生态巨大 | 旧设计难修（类型擦除），语言演进慢 |
| Rust | 安全和控制都要，表达力优先，编译期检查为主，用 edition 演进 | 无 GC 的内存安全，接近 C 的性能 | 学习曲线陡，编译慢，复杂度外露给程序员 |
| Python | 安全但无控制，表达力优先，运行期检查，允许断裂 | 开发最快，生态覆盖面最广 | 运行慢，大代码库靠工具补类型；2 到 3 的迁移痛了十年 |

背后的逻辑：没有一门语言在每条轴上都站最好的一端，因为这些轴背后是同一份预算。Rust 看似「安全和控制都要」，是用学习复杂度和编译时间付的账；Go 和 Python 站在相反位置：一个克制特性、一个放开特性，各自换来可读性或开发速度。评价语言特性时，先问它挪动了哪条轴、由哪一端来付账，比争论「哪个更好」有意义。
