## Q
C++、Go、Java、Rust、Python 各自的首要设计目标、为此做的关键决定、付出的代价分别是什么？

## A
| 语言 | 首要目标 | 关键决定 | 代价 |
|---|---|---|---|
| Go | 简单、工程规模、编译快 | 25 个关键字，无继承，显式返回错误，统一格式 | 样板代码多，抽象手段偏少 |
| Java | 可移植、向后兼容、长期可维护 | 字节码加 JVM，很少删除旧 API，类型擦除泛型 | 历史包袱重，写法偏冗长 |
| C++ | 性能与对硬件的控制，兼容 C | 零开销原则（不用的功能不付钱），安全交给程序员，保留 C 的全部能力 | 未定义行为（UB，标准不规定后果的操作）多，语言庞杂，编译慢 |
| Rust | 无 GC 的内存安全，零成本抽象 | 所有权与借用检查，没有隐式开销 | 学习曲线陡，编译慢 |
| Python | 可读、开发效率 | 动态类型，缩进即语法，标准库齐全 | 运行慢，大型代码库难以维护 |

规律：每一行的「代价」列，几乎都是「关键决定」列换来的。Go 的简单换来了样板代码，Java 的兼容换来了包袱，Rust 的安全换来了陡峭的曲线，Python 的灵活换来了运行期错误和速度。不存在没有代价的特性，只存在「代价被谁、在什么时候承担」：Rust 让程序员在编译期承担，Python 让用户在运行期承担。C++ 站在与 Rust 同样的「零开销」一端，但不要求编译器证明安全，而是相信程序员；这部分来自 1980 年代必须兼容海量 C 代码的历史，所以它的代价是错误在运行期静默出现。
