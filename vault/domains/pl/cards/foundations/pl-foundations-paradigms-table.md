## Q
C++、Go、Java、Rust、Python 在编程范式上各自默认站在哪里？这个选择换来什么，又让你付出什么？

## A
| 语言 | 默认选择 | 换来 | 代价 |
|---|---|---|---|
| Go | 过程式加方法，不提供继承，也不提供 map/filter 工具箱 | 风格高度统一，新人很快读懂任何人的代码 | 数据变换要手写循环，抽象手段少 |
| C++ | 刻意多范式：过程式、面向对象、泛型（模板）、函数式（lambda、算法）并存，哪个都不强制 | 每种抽象编译后几乎不留运行时成本，可以只取需要的子集 | 写法太多，团队必须约定子集（如 Core Guidelines）；同一件事有多种写法，风格不统一 |
| Java | 面向对象为主，Java 8 起补上函数式 | 类与接口为大团队划清边界，工具链成熟 | 小任务仪式感重；函数式是后加的，`Stream` 有调试和性能成本 |
| Rust | 命令式内核加表达式导向，变量默认不可变 | 函数式的可组合加对内存的控制，迭代器链通常不比手写循环慢 | 函数式写法要服从所有权规则（值移走之后原变量不能再用） |
| Python | 什么都能写的多范式 | 表达最快，探索和原型最顺手 | 风格不统一，一致性全靠团队约定；`lambda` 只能是单个表达式 |

背后的逻辑：Go 的哲学是「同一件事只有一种写法」，所以主动拒绝范式的多样性；Java 面向大型组织，把「类」当作切分责任的单位；Rust 要在不要运行时的前提下提供高层抽象，所以必须选择能被编译器完全展开的范式（迭代器、泛型）；Python 面向个人生产力，宁可放任风格分裂。C++ 与 Python 都是「什么都能写」，区别在谁来付账：Python 付运行时速度，C++ 付学习与约定成本，因为它的原则是「不为没用到的功能付钱」，于是每种范式都做成可选的库或语法，不选择就不付费。评价一门语言的范式，不是看它支持几种，而是看它为哪种团队规模和哪种问题优化。
