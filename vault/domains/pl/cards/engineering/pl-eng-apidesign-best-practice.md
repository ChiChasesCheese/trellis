## Q
给其他团队使用的库设计公开 API 时，资深工程师在五门语言里各遵守哪些规则？为什么？

## A
**通用原则**：最小化公开面；默认安全；错误可编程处理；不破坏已发布的合同。一旦发布，一个公开的名字就是永久的承诺。

**Go**：
- **“接受接口，返回结构体”**：函数参数用小接口（只写你需要的方法，最好由消费者定义），返回具体类型，避免替调用者决定抽象。
- `ctx` 作为第一个参数；错误作为最后一个返回值，用 `fmt.Errorf("...: %w", err)` 保留原因，导出哨兵错误或类型供 `errors.Is/As` 判断。
- 让零值可用；选项多时用函数式选项；不要导出不必要的字段；包名不重复（`http.Client` 而不是 `http.HTTPClient`）。

**Java**：
- 对象尽量不可变（`record`、`final`）；对外返回副本或不可变视图（`List.copyOf`、`Collections.unmodifiableList`）；
- 可选项多用构建器；不要返回 `null`，返回 `Optional` 或空集合；
- 用 `sealed` 接口与 `record` 表达封闭的结果类型；
- 公共类的修改遵守二进制兼容，新增用默认方法。

**Rust**：
- 参数：只读用 `&str`/`&[T]`，需要拥有用 `impl Into<String>`；返回具体类型而不是 `Box<dyn Trait>`，除非需要擦除；
- 公共枚举与结构体加 `#[non_exhaustive]`，保证以后加变体不是破坏性变更；
- 错误用自己的枚举（`thiserror`），库里不要返回 `anyhow::Error`（它是给应用用的）；
- 用 `must_use` 标记不该被忽略的结果。

**C++**：
- 参数用类型表达所有权：只读用 `const T&` 或 `std::string_view`/`std::span<const T>`，要拥有用按值加 `std::move` 或 `std::unique_ptr<T>`；不要用裸指针表示所有权；
- 选项多时用选项结构体加指定初始化，不要写一长串位置参数（尤其多个同类型的 `bool`、`int`）；
- 错误处理风格在项目里统一：异常、返回码或 `std::expected` 选一种，并在公共头文件里写明；
- 公共头文件保持精简，隐藏实现细节（pimpl，即把实现放进指针指向的私有类）以便不破坏二进制兼容；用 `[[nodiscard]]` 标记不该被忽略的返回值。

**Python**：
- 布尔和可选参数设为仅限关键字；可变默认值用 `None` 加函数内创建；
- 用类型提示和 `Protocol` 表达契约；用 `__all__` 声明公开面，下划线前缀表示内部；
- 错误继承一个库根异常，调用者一个 `except` 就能处理本库全部错误。

**何时打破**：内部包、一次性脚本不需要这些仪式；这些规则是为了“很多人长期依赖”这个场景准备的。
