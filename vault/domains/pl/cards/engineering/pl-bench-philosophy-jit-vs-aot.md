## Q
为什么 Java 需要 JMH 这样的整套框架，而 Go 靠标准库里的一个循环就够了？这反映了两种语言怎样的取舍？

## A
关键区别是**「性能」这个量是在什么时候确定的**。

**Java**：机器码是运行时 JIT 根据观察到的行为生成的。同一个方法在刚启动时是解释执行，稍后被 C1 编译，再后来被 C2 按「这个调用点只见过一种类型」之类的画像激进优化；画像变了还会反优化。所以一个 Java 基准的数字只是在说：「在某个预热状态、某种运行时画像下，稳态大约是多快」。JMH 的整套机制（预热轮、fork、状态对象、`Blackhole`）都是在**定义并控制这个状态**，让数字可复现。

**Go 与 Rust**：机器码在编译时就固定了，同一个二进制每次运行都是同样的指令。变化只来自硬件和操作系统（缓存、频率、调度），基准的任务只是「重复运行 + 防止被删除 + 做统计」，一个循环加一个统计工具就够。

这是两种语言价值观的体现：Java 用启动期的不可预测，换取长期运行时按真实负载自适应的峰值性能，所以测量必须建模这种适应；Go 选择可预测、构建简单，把基准做成 `go test -bench` 这样的普通测试代码，没有额外的概念。Rust 追求「编译时就把成本定死」，因此只需要对付优化器。

推论：Java 基准的结论是关于「一个预热后的 JVM 进程」的，换了 JVM 版本或参数要重测；Go 与 Rust 基准的结论是关于「这个二进制在这台机器上」的，换了编译器版本或 CPU 要重测。
