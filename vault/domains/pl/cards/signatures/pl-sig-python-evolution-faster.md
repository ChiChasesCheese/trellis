## Q
Python 近年的演进方向是什么？“更快的 CPython”、自由线程、类型系统和打包工具链各在补什么缺口？

## A
Python 在 2020 年结束 2 到 3 的迁移之后，把精力放在**性能、并行、类型和工具**这四条线上，目的是补上“大型、高性能场景”的短板，同时不再做破坏式改动。

1. **更快的 CPython**（Faster CPython 计划）：3.11 的自适应解释器（PEP 659）让常见代码快一成到六成；3.12、3.13 继续优化帧、调用和启动；3.13 起有实验性 JIT（PEP 744）。方向是在**不改变语言语义**的前提下榨取解释器的潜力。
2. **自由线程**（PEP 703）：3.13 引入可选的无 GIL 构建，3.14 继续推进。本机用同一份四线程 CPU 密集代码，有 GIL 约 0.47 秒，自由线程构建约 0.14 秒。挑战是生态：大量 C 扩展需要适配；单线程性能略受影响。
3. **类型系统**：类型注解（3.5 起）、`X | Y` 联合类型和内建泛型（3.9、3.10）、`match`、`TypedDict`、`Protocol`、`Self`、`override` 等持续加入，配合 `mypy`、`pyright` 做渐进类型。方向是让大型代码库可维护，而不改变运行时。
4. **打包与工具链**：`pyproject.toml` 成为统一配置；`uv` 与 `ruff`（Rust 写成）把环境管理、依赖解析、检查、格式化变得极快且一体化；wheel 与跨平台二进制分发越来越成熟。
5. **标准库清理**：按弃用政策删除“死电池”（`distutils`、`imp` 等），保持标准库精简。
6. **模板字符串**（3.14，t-string）等新语法，给库提供安全处理字符串插值的钩子（SQL、HTML 的转义）。

**规律**：
- 每一项都**对应一个公认的弱点**：慢、不能并行、缺类型、打包混乱。
- 采用**可选、渐进**的方式推出（实验构建、可选注解），保护存量。
- 许多关键改进来自**用 Rust 重写的工具**（ruff、uv、Polars、pydantic-core），说明 Python 的生态策略与它的语言策略一致：Python 做界面，核心用更快的语言。

**对使用者的建议**：升级到较新的 Python 版本本身就是免费的性能提升；对新项目启用类型检查和 `uv`；对 CPU 密集代码，评估自由线程构建但先在测试环境验证依赖。
