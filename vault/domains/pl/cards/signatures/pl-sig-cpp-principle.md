## Q
C++ 是为解决什么问题而设计的？零开销抽象、确定性析构、模板、对硬件的直接控制，共同指向怎样一个目标？

## A
**诞生背景**：1979 年 Bjarne Stroustrup 在贝尔实验室写网络模拟程序，用过 Simula（有类和对象，抽象好，但运行慢）和 BCPL/C（速度和硬件控制好，缺乏抽象），他想要二者兼得，于是在 C 上加类，1983 年命名为 C++。1998 年第一版 ISO 标准发布，2011 年起每三年一版。

**C++ 的问题陈述**：能不能用**高层抽象**组织大型程序，同时**不付任何运行时代价**，并且**随时能下到硬件层**？

**答案由几部分组成**：
1. **零开销抽象**：不用的功能不付费，用到的抽象不比手写慢。类、模板、迭代器、lambda 在编译期展开；
2. **确定性析构与 RAII**：对象离开作用域时立即释放资源，覆盖内存、文件、锁、套接字，没有 GC；
3. **模板与编译期计算**：泛型代码为每种类型生成专用机器码，`constexpr` 把计算前移到编译期；
4. **对硬件的直接控制**：自己决定内存布局、对齐、分配器、SIMD 指令、原子操作与内存序；
5. **与 C 兼容及最大的系统软件生态**：所有操作系统接口、驱动、图形与硬件 SDK 都能直接调用。

**设计目标**：**让程序员既能写出最快的代码，又能用抽象管理复杂度**。代价由程序员承担：复杂的语言、未定义行为、漫长的编译。

**适合的场景**：游戏引擎、高频交易与低延迟系统、浏览器内核、数据库与存储引擎、操作系统与嵌入式、科学计算与机器学习的底层库、图形与音视频、编译器本身（LLVM）。

**不适合的场景**：快速迭代的业务应用与脚本（用 Python/Go/Java）、团队缺少 C++ 经验又没有性能硬约束的项目、面向不可信输入的新网络服务（内存安全语言更省心）、需要开发速度胜过运行速度的原型。

**取舍轴**：运行时性能与控制，对比安全、开发效率与编译速度。C++ 站在前一端，由程序员付后一端。

**要记住的一点**：选 C++，是选择"最大的控制权"，同时接受"保证由你自己建立"。
