## Q
写地道的现代 C++ 有哪些核心实践？资深工程师怎样处理所有权、错误、接口、构建与安全？

## A
**规则与理由**：
1. **选定标准与子集**：构建系统里明确 `-std=c++20`（或 23）；采用 C++ Core Guidelines 为基线，用 `clang-tidy` 强制。理由：C++ 的“现代”靠约定，不靠语言；
2. **资源靠 RAII，所有权靠类型**：不写裸 `new`/`delete`；`unique_ptr` 默认，`shared_ptr` 要有理由；类遵循零法则；
3. **接口用借用类型**：`const T&`、`std::span`、`std::string_view` 做参数；返回拥有的值；谨慎保存视图；
4. **错误处理分类**：预期失败用 `std::expected`，罕见失败和构造失败用异常，程序员错误用断言；项目内统一约定；
5. **默认 `const`、`noexcept` 的移动、`override`/`final`、`explicit`、`[[nodiscard]]`**：把意图交给编译器检查；
6. **模板接口加 concepts**；类型分支用 `if constexpr`；避免深层元编程；
7. **并发**：`std::jthread`、`std::scoped_lock`、减少共享；原子操作先用默认内存序；
8. **容器默认 `vector`**，数据布局以缓存为准；先测量再优化；
9. **安全措施叠加**：警告全开、生产构建开标准库加固、CI 跑 ASan/UBSan/TSan、解析不可信输入的代码做模糊测试；
10. **构建**：CMake + Ninja，目标化写法，包管理器锁版本，`ccache`，至少两个编译器在 CI 里编译；
11. **头文件自包含，包含最少**；ODR 风险点（同名内联函数、宏）要有约定；
12. **性能优化流程**：基准测试（Google Benchmark）→ profiler → 汇编 → 修改 → 再测。

**何时破例**：
- 热路径上自定义分配器、手写布局、无锁结构，要隔离在小模块里，写明不变量，加测试；
- 与 C 库、旧代码交互的边界，局部使用裸指针；
- 嵌入式/游戏里禁用异常与 RTTI，用项目约定的错误机制。

**一个判断标准**：每一处 C++ 的“危险写法”都问两个问题：它换来的是测得出来的性能，还是只是习惯？它被隔离在多大的范围里？

**为什么这样**：这些实践把 C++“默认放任”的特性，转换成“默认受约束，必要时才放开”，让自由发生在小而可审查的地方。
