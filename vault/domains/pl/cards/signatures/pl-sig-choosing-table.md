## Q
按典型项目类型，Go、Java、Rust、Python 各自的适配度怎样？一张决策表能怎样使用？

## A
| 项目类型 | 首选 | 备选 | 理由 |
|---|---|---|---|
| 云原生微服务、网络工具、基础设施 | Go | Java、Rust | 并发简单，部署轻，团队易规模化 |
| 大型企业业务系统、长期维护 | Java | Go | 生态、人才、工具、兼容性 |
| 数据科学、机器学习、研究原型、脚本自动化 | Python | 无直接替代 | 库与社区决定，速度由原生库承担 |
| 性能关键组件、内存与安全敏感、嵌入式、WebAssembly | Rust | Go（延迟要求不极端时） | 无 GC、编译期安全、可预测延迟 |
| 低延迟交易、游戏引擎核心 | Rust（或 C++） | Java（精心调优） | 需要完全控制内存与延迟 |

**怎样使用这张表**：
1. 先确定项目属于哪一行，看**首选**。
2. 如果团队没有首选语言的经验，评估学习成本是否在项目周期内可接受；否则从**备选**中选择，或为关键部分引入首选语言的顾问或试点。
3. 对混合型项目（有数据科学部分，又有高并发服务），不要强求一门语言，参考下一步的多语言分工。

**多语言系统的常见分工**：
- **Python 加 Rust/C++**：Python 作为接口与组织者，核心计算用 Rust 或 C++ 扩展（NumPy、Polars、PyTorch）。
- **Go 加 Python**：Go 写服务和平台，Python 写数据管道和模型训练。
- **Java 加 Python**：Java 是业务主体，Python 服务数据与 ML 团队，通过 API 或消息队列衔接。
- **前端 TypeScript 加后端任意语言**：用 OpenAPI 或 gRPC 定义契约。
- **Rust 作为 WebAssembly 或边缘组件**嵌入其他语言的系统。

**重要警告**：表格是起点，不是规则。团队技能、现有代码、公司的运维能力可以推翻任何一行。**多语言本身有成本**：构建、部署、监控、招聘、代码共享都变复杂，通常两到三门语言是合理上限。
