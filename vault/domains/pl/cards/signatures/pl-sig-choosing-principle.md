## Q
为一个项目选语言，本质上是在做什么决定？有哪些决策维度，为什么“哪门语言最好”是个错误的问题？

## A
**本质**：选语言是在**约束**下做取舍，而不是评比。同一门语言在一个项目里是最优，在另一个项目里是灾难。正确的问题是：“在这个项目的约束下，哪一门语言的代价最小？”

**六个决策维度**：
1. **性能与资源**：延迟要求（毫秒、微秒）、吞吐、内存预算、能否容忍 GC 暂停、启动时间。
2. **团队**：现有技能、招聘市场、新人上手时间、规模（几个人还是几百人）。
3. **生态**：所需的库、框架、云服务 SDK、领域工具（机器学习、金融、嵌入式）是否成熟。
4. **部署与运维**：运行环境（容器、边缘、函数计算、嵌入式）、二进制大小、可观测性与调试工具。
5. **正确性要求**：出错的代价（安全漏洞、资金损失、生命安全）、静态保证的需求、可测试性。
6. **项目寿命与演进**：是原型还是十年系统；需求稳定还是快速变化；向后兼容与升级成本。

**为什么“最好的语言”是错误的问题**：不同维度互相冲突。Rust 在性能与安全上最强，在上手与迭代速度上最弱；Python 相反；Go 居中；Java 在生态与长期稳定上最强。没有语言在所有维度领先，因为这些维度本身是语言设计的取舍轴。

**决策的两条老规则**：
- **选无聊的技术**（boring technology）：新颖的技术消耗“创新预算”，一个项目承担不了太多；把创新留给真正的核心差异化。
- **团队技能常常胜过理论最优**：一个熟练的 Java 团队用 Java 做出的东西，多半好于一个初学团队用 Rust。

**一个常被忽略的事实**：语言选择中，**可逆性**很重要。系统通过服务边界、协议（HTTP、gRPC、消息队列）拆分后，每个部分可以独立换语言，选错的代价就被限制住了。
