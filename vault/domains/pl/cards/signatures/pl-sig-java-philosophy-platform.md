## Q
为什么说 Java 的价值在“平台”而不是“语言”？“保守演进加兼容为先”怎样塑造了它的设计取舍？

## A
**平台思维**：Java 把“语言规范、字节码格式、JVM、标准库、工具协议（JVMTI、JFR）”作为一个整体来承诺。语言只是进入平台的一个入口，Kotlin、Scala、Clojure、Groovy 也进入同一个平台，共享库与运行时。所以 Java 的演进常常发生在平台层：GC、JIT、虚拟线程、外部内存 API（Panama）、值类型（Valhalla）、启动优化（Leyden），而不是语言语法上。

**保守演进的原则**：
1. **兼容优先**：不破坏现有代码，几十年的 `.class` 文件继续运行。
2. **特性要经过预览**：新特性先作为预览特性（preview）发布若干版本，收集反馈，再定稿；`record` 与 `sealed` 都走过这个流程。
3. **固定节奏**：每六个月一个版本，每两年一个长期支持（LTS）版本，企业可以按 LTS 节奏升级。
4. **实现细节也算承诺**：如类型擦除，为了兼容旧字节码，泛型实现选择了擦除，结果是今天泛型仍有 `List<int>` 做不到的限制。

**这些选择的代价**：
- 历史包袱：装箱、受检异常、数组协变等设计，无法删除，只能绕开。
- 创新较慢：模式匹配、值类型、轻量线程等特性，从提案到稳定要若干年。
- 冗长：很多样板需要框架或 Lombok 消除。

**这些选择的回报**：企业可以在 Java 上押注十年二十年，升级不会导致大规模重写；工具链和人才市场稳定。

**对照**：Go 的承诺是“语言稳定”，Rust 的承诺是“稳定版不破坏、用 edition 演进”，Python 经历了 2 到 3 的断裂。Java 最彻底地把“**不要让用户为我们的改进买单**”当作第一原则。

**揭示的价值观**：Java 相信大型软件的主要风险是**变化的成本**，而不是**表达力的不足**。这在企业环境里是合理的判断，在个人或实验环境里就显得保守。
