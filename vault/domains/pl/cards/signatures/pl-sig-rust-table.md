## Q
把 Rust 放在 Go、Java、Python 旁边比较：它在哪些维度最强，哪些最弱？

## A
| 维度 | Rust 相对位置 | 说明 |
|---|---|---|
| 运行时性能与可预测性 | 最强（与 C/C++ 同级） | 无 GC，无运行时，延迟可预测 |
| 内存与并发安全 | 最强 | 编译期保证，不靠运行时检查 |
| 启动与足迹 | 最强之一 | hello world 约 470 KB、常驻约 2 MB、启动约 9 ms |
| 学习曲线与开发速度 | 最弱 | 所有权、生命周期、trait 约束需要时间，迭代周期更长 |
| 生态成熟度 | 中等（快速增长） | 系统与命令行很强，企业应用框架少于 Java |

**与另三门语言**：
- **对 Go**：Rust 更快、更省、更安全，类型表达力强；Go 学得快、写得快、编译快、团队更容易规模化。
- **对 Java**：Rust 没有 GC 暂停、足迹小、性能可预测；Java 生态、人才、工具成熟度远超。
- **对 Python**：Rust 快两个数量级、有静态类型；Python 开发速度与生态（数据科学）无可替代。二者常配合：Python 的核心扩展用 Rust 写（PyO3、Polars、Pydantic-core）。

**逻辑**：Rust 的位置由它的赌注决定——“**用编译期的复杂性换运行期的简单与安全**”。在需要极致性能与高度可靠的地方（浏览器、内核、数据库、基础设施），这笔交易划算，因为一个内存安全漏洞或一次 GC 暂停的代价很高。在多数业务代码里，这笔交易不划算，因为开发效率比最后的 30% 性能重要。

**最适合的组合**：系统组件、性能关键库、安全敏感的解析器、嵌入式与 WebAssembly、命令行工具。不适合的组合：快速变化的业务系统、团队多数人是初学者的短期项目。
