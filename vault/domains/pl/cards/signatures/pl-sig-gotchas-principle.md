## Q
为什么每门语言都有“经典陷阱”？它们是设计缺陷，还是设计取舍留下的影子，怎样系统地学习它们？

## A
**观察**：Go 的 nil 接口、Java 的 `Integer` 缓存、Rust 与借用检查器的拉锯、Python 的可变默认参数，都是几乎每个使用者踩过的坑。它们不是偶然的疏漏。

**每个陷阱是一个设计取舍的影子**：语言为了某个收益，选择了某条规则；这条规则在某些场合下与直觉相反，就成了陷阱。
- Go 追求简单、零值可用，于是 `nil` 的语义在接口、指针、切片、map 上各不相同。
- Java 为了兼容和性能保留基本类型与装箱类型两套，于是 `==` 在两者上语义不同。
- Rust 为了在编译期证明安全，借用规则保守，于是会拒绝一些你认为安全的写法。
- Python 为了灵活，函数默认参数在定义时求值一次、闭包按名字晚绑定，于是共享状态与延迟求值出现意外。

**学习陷阱的正确方式**：不要背清单，而是对每个陷阱回答三个问题：
1. **它背后是哪个设计选择**？理解根源，才能举一反三。
2. **失败时是什么样子**？编译错误（最好）、运行时崩溃（较好）、静默的错误结果（最坏）。
3. **用什么工具或约定避免**？编译器选项、linter、测试、代码评审规则。

**按失败方式给四门语言的陷阱分级**：
- **静默错误结果（最危险）**：Go 的切片别名与 nil 接口、Java 的 `Integer ==`、Python 的可变默认参数与晚绑定。
- **运行时崩溃**：Go 写 nil map 的 panic、Rust 调试模式的整数溢出 panic。
- **编译期拦截（最友好）**：Rust 的所有权错误。

**取舍轴**：陷阱的位置反映了语言把“安全检查”放在哪个阶段。越靠近编译期，陷阱越是“摩擦”（你被拦住）；越靠近运行时，陷阱越是“惊吓”（你被坑到）。
