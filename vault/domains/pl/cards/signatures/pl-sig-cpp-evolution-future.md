## Q
C++ 从 1983 年到今天是怎样演进的？面对 Rust 与内存安全的压力，它的前景和位置是什么？

## A
**关键节点**：
- **1979 / 1983**：C with Classes，更名为 C++。
- **1998 / 2003**：第一个 ISO 标准（C++98）和修订。
- **2011**：C++11，现代 C++ 的起点：移动语义、`auto`、lambda、智能指针、线程与内存模型。
- **2014、2017**：C++14、C++17 逐步补全：结构化绑定、`optional`/`variant`、`string_view`、强制拷贝省略。
- **2020**：C++20：concepts、ranges、协程、模块、`<=>`。
- **2023**：C++23：`std::expected`、`std::print`、`deducing this`。
- **C++26**：静态反射、契约、`std::execution`、标准库加固、未初始化读取不再是 UB 而是“错误行为”；特性集已冻结，编译器仍在逐步实现。

**节奏**：1998 到 2011 之间隔了 13 年，之后改为每三年一版的“列车”。

**压力与回应**：
1. **内存安全**：政府机构与大厂公开建议转向内存安全语言；C++ 的回应是标准库加固、契约、错误行为、Core Guidelines 与静态分析；profiles 仍在讨论；
2. **Rust 的竞争**：新的、攻击面大的系统组件越来越多地选择 Rust；Linux 内核、Android、Windows 组件都在引入；
3. **构建与生态**：模块和包管理的标准化缓慢；
4. **后继语言实验**：Google 的 Carbon（定位为与 C++ 互操作的后继）、Herb Sutter 的 cppfront（用新语法编译到 C++）；它们尚未形成主流采用。

**C++ 的位置**：
- **不会消失**：存量代码以数十亿行计，游戏、交易、浏览器、数据库、AI 框架内核、操作系统和编译器的底层都在 C++；
- **不再是新代码的默认选择**：在新服务和高风险组件里，Go、Rust、Java 抢走了一部分；
- **渐进现代化**：新项目用 C++20/23，旧项目用 clang-tidy 逐步迁移；
- **与其他语言共存**：Python 调用 C++ 内核，Rust 与 C++ 通过 FFI 互操作，混合语言系统越来越常见。

**判断**：C++ 的未来取决于两件事——**标准库加固与契约等能否把默认值从“放任”改成“检查”**，以及**工具链（模块、包管理、构建）能否追上其他语言**。语言的底层能力不是问题，问题是安全与体验。

**对学习者**：学 C++ 的收益有两层——直接写 C++ 的能力（在存量和性能领域非常值钱），以及理解其他语言背后的机制（RAII、移动语义、模板、内存布局、UB），这些知识会让你读懂 Rust、Go、Java 的设计取舍。

**要记住的一点**：C++ 是一门“在原地持续改造自己”的语言；它的未来不在于取代谁，而在于在最需要控制力的地方继续保持不可替代，同时把安全的默认值一点点补上。
