## Q
Rust 的 trait、泛型与单态化（monomorphization）是什么？“零成本抽象”的实测怎样体现，代价在哪里？

## A
**trait**：描述“一类类型能做什么”的接口，如 `Display`（能格式化输出）、`Iterator`（能逐个产出元素）。类型用 `impl Trait for Type` 声明实现，不需要继承。泛型函数用 trait 约束参数：`fn print_all<T: Display>(xs: &[T])`。

**单态化**：编译器为泛型函数用到的每一种具体类型各生成一份专门的机器码。`print_all::<i32>` 与 `print_all::<String>` 是两份独立的代码，调用是静态分派，可以内联，没有虚函数表。需要运行时多态时，才显式使用 `dyn Trait`（动态分派）。

**零成本抽象的含义**：使用高层抽象（迭代器链、闭包）不比手写底层循环更慢；而你没有使用的功能不会拖累程序。

**实测（本机，一亿个 `u64`）**：

```rust
let a: u64 = v.iter().map(|&x| x * 2).sum();          // iterator chain
let mut b = 0u64; for i in 0..v.len() { b += v[i]*2 } // indexed loop
```

热身后两者都约 8 ms，几乎相同（第一次运行因页面缓存等原因略高）。编译器把迭代器链内联成同样的循环，甚至自动向量化。

**代价**：
1. **编译时间**：每个泛型实例化都要生成并优化代码，大项目编译慢（一个依赖了 serde 的小项目干净构建约 2.8 秒，大型项目可达分钟级）。
2. **二进制体积**：重复实例化会膨胀代码。
3. **错误信息**：泛型与 trait 约束出错时报错较长。
4. **学习曲线**：需要理解 trait 约束、生命周期与泛型的交互。

**要记住的一点**：Rust 的抽象“免费”，是因为成本在编译期付清；你用编译时间和二进制体积换取运行时的速度。
