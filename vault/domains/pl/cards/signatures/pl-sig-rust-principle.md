## Q
Rust 是为解决什么问题而设计的？所有权、无 GC 的内存安全、零成本抽象、无畏并发这些特点共同指向怎样一个目标？

## A
**诞生背景**：Rust 起于 Mozilla 的 Graydon Hoare 的个人项目（约 2006），后来 Mozilla 为重写浏览器引擎 Servo 而投入。目标场景是**系统编程**：浏览器、操作系统、数据库、嵌入式。过去这些只能用 C/C++，它们的代价是内存安全漏洞和数据竞争；用 Java/Go 这类有 GC 的语言，又承担不起 GC 的暂停和内存开销。

**Rust 的问题陈述**：能不能**同时**得到 C 的性能与控制，和 Java 的内存安全？

**答案由几部分组成**：
1. **所有权与借用**：每个值有唯一的所有者，引用有生命周期，编译器证明不会悬空、不会同时存在可变别名。
2. **无 GC 的内存安全**：值离开作用域时确定地释放，运行时没有收集器。
3. **零成本抽象**：泛型、迭代器、闭包、trait 在编译期展开，生成的代码和手写的一样快。
4. **无畏并发**：同一套类型规则也能在编译期阻止数据竞争。
5. **cargo**：统一的构建、依赖、测试、文档工具，生态健康。

**设计目标**：**把本来在运行时（或根本不会）发现的一整类错误，提前到编译期**。代价由开发者在写代码时承担。

**适合的场景**：系统软件（操作系统组件、驱动、浏览器引擎）、性能关键库、嵌入式、WebAssembly、命令行工具、需要低延迟且不能有 GC 暂停的服务、对安全要求极高的解析器与密码库。

**不适合的场景**：快速原型和脚本（学习曲线与编译周期偏重）、需要大量动态性的业务系统、团队缺乏时间学习的短期项目、GUI 的生态仍在成熟。

**取舍轴**：运行时成本与安全，对比开发者的学习与编码成本。Rust 选择了前者，由程序员付出后者。
