## Q
C++ 怎样把代码分成多个文件、再组合成一个程序？这套"头文件加翻译单元"的模型要解决什么问题，设计空间里有哪些别的做法？

## A
**问题**：大程序不能放在一个文件里。需要：
1. 一个文件能使用另一个文件定义的函数和类型（共享**声明**）；
2. 每个文件可以独立编译，改一个文件不用重编全部；
3. 最终把所有部分合成一个可执行文件，而且同一个东西不能被定义两次。

**设计空间**：
1. **文本包含**（C、C++）：用预处理器把头文件的**文本**直接粘贴进每个用到它的源文件，每个源文件单独编译成目标文件，最后由链接器合并；
2. **编译器理解的模块**（Java 的 package/class 文件、Rust 的 crate、Go 的 package）：编译器读取已编译好的模块接口，不是重新解析源码文本；
3. **运行时导入**（Python）：`import` 在运行时加载文件，执行其顶层代码。

**C++ 的答案**：第 1 种，沿用 C 的做法。一个 `.cpp` 文件加上它 `#include` 进来的所有内容，称为一个**翻译单元**（translation unit），是编译的基本单位。头文件里写**声明**（"有这么个函数"），`.cpp` 里写**定义**（实际代码）；每个翻译单元独立编译，**互相看不到对方的内部**；链接器按名字把对同一函数的引用连到它的定义上。

**为什么这样**：这是 1970 年代 C 为了在内存很小的机器上编译大程序而设计的：每个文件独立编译，不需要同时把所有源码装进内存。C++ 为了与 C 兼容，也为了让模板、内联函数这些需要完整定义的东西能被使用，保留了这个模型。

**代价**：
1. **重复解析**：同一个头文件被每个翻译单元重新读一遍；
2. **隐式耦合**：宏和 `#include` 的顺序会影响含义；
3. **单一定义规则**（ODR）：一个函数的多份定义必须相同，违反不一定报错；
4. **没有包的概念**：语言只管源码文件，依赖管理、构建、分发全在语言之外。

**要记住的一点**：C++ 的"模块化"是靠文本粘贴 + 链接器按名字匹配实现的，不是语言的类型系统理解的；它的所有痛点都从这里来，C++20 模块是对它的修正。
