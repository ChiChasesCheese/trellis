## Q
函数参数怎样选 `T`、`const T&`、`T&&`？资深 C++ 工程师在移动语义上遵循哪些规则？

## A
**参数选择**（看函数对参数做什么）：
1. **只读**：`const T&`。小而便宜的类型（`int`、`double`、`string_view`、`span`）按值传。
2. **要存下它**（“sink”参数，构造函数把参数存进成员）：**按值接收再 `std::move` 进成员**。调用者传左值，付一次拷贝；传右值，付一次移动。写法简单，只有一个函数。
3. **要原地修改**：`T&`。
4. **模板里要原样转发**：`T&&` 加 `std::forward`。
5. **几乎不用的**：普通函数里的 `T&&` 参数，除非你想强制调用者传右值。

**规则**：
1. **移动构造函数写 `noexcept`**。`std::vector` 扩容时，只有移动构造函数 `noexcept` 才会移动旧元素，否则为了异常安全退回拷贝，性能悄悄下降。
2. **不要对返回值写 `std::move`**；不要对 `const` 对象 `std::move`（实际会拷贝）。
3. **`std::move(x)` 之后，除赋值或析构外不再使用 `x`**。把这当作团队约定，工具（`bugprone-use-after-move`）帮你查。
4. **遵循零法则**：类的成员都是 `string`、`vector`、`unique_ptr` 这类自管理类型，就不要手写拷贝和移动函数，编译器自动生成的版本正确且最快。
5. **需要手写时，五个特殊函数一起写**：析构、拷贝构造、拷贝赋值、移动构造、移动赋值。

**什么时候打破**：热路径上，确实测得 sink 参数多一次移动有影响时，可以提供 `const T&` 和 `T&&` 两个重载；这种情况不多见。

**为什么这样**：C++ 的移动没有编译器保证，所以规则的作用是**把“程序员能犯错的地方”缩小到固定的几个位置**。
