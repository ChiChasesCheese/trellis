## Q
整数溢出和数组越界，C++、Rust、Go、Java、Python 各自规定了什么？换来什么，代价是什么？

## A
| 语言 | 整数溢出 | 越界访问 | 换来 | 代价 |
|---|---|---|---|---|
| C++ | 有符号：UB；无符号：回绕 | `[]`：UB | 零检查，优化空间最大 | 错误静默，编译器可据此变换 |
| Rust | 调试版 panic；发布版回绕（均有定义） | 一律 panic | 无 UB（`unsafe` 之外） | 每次访问一次边界检查 |
| Go | 回绕（有定义） | panic | 行为确定 | 边界检查开销 |
| Java | 回绕（有定义） | 抛异常 | 行为确定，可移植 | 边界检查 + 无法对溢出做激进优化 |
| Python | 无溢出（任意精度整数） | `IndexError` | 不会算错 | 整数运算慢 |

**本机实测**：同样让 `i32` 最大值加一，Rust 调试版 `panicked ... attempt to add with overflow`，Rust 发布版和 Go 都输出 `-2147483648`；C++ 在 `-O0` 和 `-O2` 下也都得到这个负数，但那只是编译器恰好选择了回绕；有符号溢出在标准里是未定义行为，同一个文件里换一种写法（如 `x + 1 > x`），两档优化的结果就不同。

**逻辑**：这张表是一条"**谁承担检查**"的轴。Java、Python、Go、Rust 都选择**让语言或运行时承担**：要么检查，要么规定一个确定值。C++ 选择**让程序员承担**：你保证不越界，编译器相信你并省掉检查。

两个重要观察：
1. **Rust 并没有放弃性能**：它的 `unsafe` 之外无 UB，靠边界检查（可被优化器去掉）和所有权规则换来。Rust 发布版溢出选"回绕"也是为了避免 UB，只是不做 panic 检查。
2. **有符号溢出 UB 是 C/C++ 的独特选择**：无符号溢出却有定义。这是历史上为了兼容不同整数表示（补码以外的机器）和给优化器留空间。如今所有现代硬件都是补码，但标准保留了这个 UB。

**怎么选**：如果你需要"溢出就报错"，C++ 里要用库（`__builtin_add_overflow`、Boost.SafeNumerics）或编译选项（`-ftrapv`、`-fsanitize=signed-integer-overflow`）；不能指望语言默认。
