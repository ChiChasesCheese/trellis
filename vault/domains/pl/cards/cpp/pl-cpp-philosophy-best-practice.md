## Q
资深 C++ 工程师怎样在“语言给了你所有自由”的前提下保证代码质量？一个项目起步时应当先固定哪几件事？

## A
因为语言本身的护栏少，**护栏要由项目自己搭**。起步时固定五件事：

1. **语言标准**：在构建系统里明确写 `-std=c++20`（或 23），不要依赖编译器默认值。默认标准随编译器升级而变，会让同一份代码在不同机器上行为不同。
2. **警告级别**：开 `-Wall -Wextra`，CI 里加 `-Werror`（或至少对新代码如此）；再加 `-Wconversion`、`-Wshadow` 抓隐式转换。
3. **Sanitizer（运行时检查工具）**：CI 里至少跑一轮 `-fsanitize=address,undefined`（越界、释放后使用、整数溢出等），多线程代码加 `-fsanitize=thread`。UB 在普通构建下可能“碰巧正常”，只有这些工具才能稳定暴露。
4. **编码规范**：以 C++ Core Guidelines（由 Stroustrup 与 Herb Sutter 主持的开源指南）为基线，选一个子集：禁裸 `new`/`delete`，禁 C 风格强转，所有权用智能指针表达。
5. **静态分析**：`clang-tidy` 的 `cppcoreguidelines-*`、`modernize-*`、`bugprone-*` 检查组，加入 CI。

**原则**：把“靠自觉的规则”变成“机器检查的规则”。一个规则如果只写在文档里，三个月后就没人遵守；写进 CI，才是真正的约束。

**什么时候可以打破**：热路径上为了性能手写内存布局或自定义分配器是合理的，但要把这类代码**隔离在小模块里**，写清楚不变量，并用基准测试证明收益。

**对比其他语言**：Go 靠语言本身（`gofmt`、`go vet`）、Rust 靠编译器提供这些护栏；C++ 的对应物是上面五件事。它们不是“可选的最佳实践”，而是这个语言正常使用的**前置条件**。
