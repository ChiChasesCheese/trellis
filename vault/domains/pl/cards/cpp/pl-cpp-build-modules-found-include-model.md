## Q
`#include` 实际上做了什么？一个简单的标准头文件包含进来有多大，为什么 C++ 编译慢？

## A
**预处理器**（preprocessor）在编译之前处理以 `#` 开头的指令。`#include <vector>` 的作用是：**找到那个头文件，把它的全部文本原样替换到这一行**。头文件里再有 `#include`，递归展开。展开后的结果才交给编译器。所以一个源文件最终的编译输入，是它自己加上所有被包含文件的拼接。

**防止重复包含**：同一个头文件可能被间接包含多次，如果里面有类定义，会造成重复定义。办法是**包含守卫**：

```cpp
#ifndef MYLIB_FOO_H
#define MYLIB_FOO_H
// 声明...
#endif
```

或者在文件首行写 `#pragma once`（非标准但所有主流编译器都支持）。

**一个头文件有多大**：用 `clang++ -E`（只做预处理）统计展开后的行数（本机，libc++，`-std=c++23`）：

| 头文件 | 展开后行数 |
|---|---|
| `<cstdio>` | 约 700 |
| `<ranges>` | 约 34,000 |
| `<vector>` | 约 40,000 |
| `<print>` | 约 45,000 |
| `<iostream>` | 约 57,000 |

即使一个只写了 `#include <iostream>` 加一行输出的程序，编译器也要先解析近六万行。每个翻译单元都要重来一遍。

**本机实测**：20 个各自包含 `<ranges>`、`<algorithm>`、`<map>`、`<string>` 并定义一个小函数的源文件，总共编译约 2.9 秒（`-O0`，平均每个文件约 0.14 秒）。大型项目里数千个翻译单元，头文件解析经常占总编译时间的大头。

**头文件里能放什么**：
- 声明：函数原型、`extern` 变量、类定义；
- **模板的完整定义**：实例化需要看到定义；
- `inline` 函数、`constexpr` 函数：可以出现在多个翻译单元，要求定义相同；
- **不要放**非 `inline` 的函数定义和全局变量定义：会被多个翻译单元各自包含，链接时重复定义。

**为什么慢是结构性的**：修改一个被广泛包含的头文件，所有依赖它的翻译单元都要重新编译。

**缓解**：预编译头（PCH）、unity build（多个 `.cpp` 合并成一个翻译单元）、`ccache`（缓存编译结果）、少包含（前置声明）、C++20 模块。

**对比**：Java 的 `import` 只是名字的缩写，编译器从已编译的 `.class` 里读接口；Rust 的 `use` 同理；Go 的编译器直接读包的导出数据，不重新解析源码。这些语言没有"粘贴文本"这一步，所以没有这个成本。

**要记住的一点**：`#include` 是文本复制，不是引用；头文件越重、被包含得越广，编译越慢。
