## Q
为什么说"现代 C++ 是一种纪律，而不是一门语言"？这反映了 C++ 演进的什么特点，对团队意味着什么？

## A
**事实**：C++ 标准委员会遵循"**不破坏现有代码**"的强原则。所有新特性都是**加**的，旧的几乎不删（`auto_ptr` 是少数被移除的）。因此今天一个 C++23 编译器仍然接受 1990 年代的 C 风格代码：裸指针、`malloc`、宏、`goto`、`(int)x` 强转。

**后果**：一门语言里同时有"**写 C 的方式**""**写 C++98 的方式**""**写现代 C++ 的方式**"，它们在同一个文件里可以并存，编译器一视同仁。所谓"现代 C++"其实是你自己**选择只用的那个子集**。

**这个子集由谁定义**：
- C++ Core Guidelines（Stroustrup、Sutter）；
- 公司的风格指南（Google、LLVM、Chromium、Bloomberg 各有）；
- 项目的 clang-tidy 配置；
- 编译器警告开关。

**与其他语言对比**：
- **Go**：几乎只有一种写法，`gofmt` 统一格式；
- **Rust**：edition 机制（2015、2018、2021、2024）允许语言做**不兼容的修改**，旧代码继续用旧 edition 编译，新旧可以互相链接；
- **Python 3**：一次大的不兼容升级（2008 到 2020 年），代价惨重；
- **Java**：强向后兼容，但也有"现代 Java"（records、sealed、var）与旧写法并存，规模比 C++ 小；
- **C++**：没有 edition 机制，靠"`-std=` 选版本 + 团队规范选子集"。

**对团队的含义**：
1. **每个项目要明确自己的子集**，并写进文档和 CI；不同项目的 C++ 看起来像不同的语言；
2. **招聘和培训**要考虑"会 C++"并不等于"会这个团队的 C++"；
3. **阅读开源代码**要预期遇到各个时代的风格；
4. **升级标准版本是低风险的**（兼容），**升级写法是高成本的**（需要改代码），后者要靠自动化（`clang-tidy --fix`）。

**哲学上**：这是"**不替用户做决定**"的延续。C++ 提供越来越好的工具，而不强迫你用；代价是安全和一致性依赖团队的纪律。Stroustrup 曾说过 C++ 内部有一门更小更干净的语言，Core Guidelines 就是想把它划出来。

**要记住的一点**：问"这个项目用的是哪个 C++"，要问的是标准版本、编码规范和静态检查配置，而不是编译器的名字。
