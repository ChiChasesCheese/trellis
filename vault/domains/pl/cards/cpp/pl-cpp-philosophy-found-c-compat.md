## Q
C++ 为什么要和 C 保持兼容？这份兼容给 C++ 带来了什么资产，又留下哪些至今存在的包袱？

## A
**为什么兼容**：C++ 起步时 C 已经是系统编程的事实标准，几乎所有操作系统接口、驱动和库都是 C。保持兼容意味着：一个 C++ 项目可以直接 `#include` C 头文件、调用 C 库，现有代码逐文件迁移，不用推倒重来。这是 C++ 能快速普及的主要原因。

**资产**：操作系统 API、数据库客户端、图形与音视频库、硬件驱动，开箱即用；与其他语言互操作的事实标准也是 C ABI（二进制接口，函数在二进制层面怎样传参、命名）。

**包袱**：兼容的是 C 的**默认行为**，而 C 的默认行为偏危险。三个例子：
1. **数组退化为指针**：把数组传给函数，长度信息丢失。
2. **隐式转换**：窄化转换悄悄发生。
3. **预处理器宏**：文本替换，无视作用域与类型。

```cpp
void f(int a[3]) { std::println("{}", sizeof a); }   // 参数其实是 int*
int a[3]; f(a);          // sizeof a 在 main 里是 12，进 f 之后是 8
double d = 3.9; int i = d;   // 编译通过，i == 3
```

编译器对第一段给出真实警告：`sizeof on array function parameter will return size of 'int *' instead of 'int[3]'`。

**后果**：C++ 无法修改这些默认值（会破坏大量旧代码），只能**加新写法**并劝大家用：`std::array` 和 `std::span` 代替裸数组，花括号初始化禁止窄化，`constexpr` 与模板代替宏。结果是语言里同时存在“旧的危险写法”和“新的安全写法”，学习者必须知道该用哪一个。

**要记住的一点**：C++ 的兼容策略是“永不删除，只增加”，所以现代 C++ 的主要技能之一，是知道哪些老特性不该碰。
