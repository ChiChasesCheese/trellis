## Q
"C++ 模板是编译期的鸭子类型"是什么意思？这个设计反映了 C++ 的什么价值观，带来什么灵活，又带来什么风险？

## A
**含义**：Python 的鸭子类型说"看起来像鸭子、叫起来像鸭子，就当鸭子用"，运行时才看对象有没有 `quack()`。C++ 模板在**编译期**做同样的事：模板体里写 `a < b`，实参类型只要有 `<` 就能通过，不必提前声明"我实现了 `Comparable`"。

```cpp
template <std::integral T> void bad(T x) { x.nonexistent(); }  // 没有实例化时编译通过
bad(1);   // 实例化时才报：member reference base type 'int' is not a structure or union
```

**价值观**：
1. **不强迫声明**：任何类型都能适配任何模板，包括你无法修改的第三方类型和内置类型（`int` 也可以是 `maxof` 的实参，它不需要"继承"什么）。这与 Java 的"必须实现接口"相对。
2. **信任程序员**：模板体写什么就是什么，语言不替你限制。
3. **库设计者的自由**：STL 的泛型编程允许算法和容器彼此独立组合，不用先定义一棵继承树。

**灵活**：同一个 `std::sort` 既能排 `int` 数组，也能排 `std::string` 的 `vector`，只要它们的迭代器是随机访问、元素可比较；用户自定义类型加一个 `operator<` 就能进入整个标准库生态。

**风险**：
1. **契约隐式**：模板需要类型有什么，不看实现读不出来（concepts 缓解）。
2. **约束漂移**：库作者改了模板体，多用了一个类型操作，没改约束，下游的类型就编译失败，且是库升级引起的"二进制兼容"之外的"源码兼容"破坏。
3. **鸭子的偶然匹配**：两个类型都有 `.size()` 但含义不同，模板仍然接受。

**与其他语言**：Rust 的 trait 是**名义式**的（必须 `impl Trait for Type`），Go 的接口是**结构式**的但检查在定义处；Python 的鸭子类型是运行时的。C++ 在结构式的一端，并且检查延迟到实例化。

**要记住的一点**：这个设计是 C++ 泛型编程的力量之源，也是它报错难读、接口难看清的原因；concepts 是对后者的补救，不是对前者的否定。
