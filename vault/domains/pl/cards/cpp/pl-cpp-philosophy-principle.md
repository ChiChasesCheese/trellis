## Q
C++ 是为解决什么问题而设计的？在“抽象”与“对硬件的控制”这条取舍轴上，它为什么选了一个不同于 Java、Go、Python 的位置？

## A
**诞生背景**：1979 年 Bjarne Stroustrup 在贝尔实验室写模拟器，发现 Simula 的类和抽象写起来舒服但太慢，C 够快却没有抽象手段。他想要的是**两者兼得**：用类、模板这类高层机制组织大型程序，同时生成的机器码和手写 C 一样快、一样可控。这个项目先叫 C with Classes，后来改名 C++。

**设计空间有三种答案**：
1. **低层语言，不提供抽象**（汇编、C）：性能与控制最大，大程序难维护。
2. **高层语言加运行时**（Java、Python、Go）：GC（垃圾回收器，自动回收内存的运行时组件）、虚拟机、动态类型换来开发速度与安全，代价是运行时开销和不可预测的延迟。
3. **抽象在编译期被展开**（C++，之后的 Rust）：抽象只存在于源码里，编译后消失，运行时不留痕迹。

**C++ 的选择**是第三种，并把它写成两条底线：不用的功能不付费；用到的功能，手写也不可能更快。取舍轴因此是：**运行时成本对比程序员的负担**。C++ 把成本压到最低，把管理资源、保证安全的责任留给程序员。

**一个小例子**：`std::vector<int>` 求和与手写 C 数组循环，在优化编译后都变成向量化的循环，耗时相同；而同样的“自动内存管理”若交给 GC，就要付出运行时收集器的成本。C++ 用 RAII（对象析构时释放资源）代替 GC，靠的正是这种“抽象编译后消失”的路线。

**要记住的一点**：理解 C++ 的所有怪癖——为什么默认不检查越界、为什么模板要在头文件里、为什么没有统一的运行时——都从这个选择推出：它优先保证“你能做到最快”，其次才是“你不会出错”。
