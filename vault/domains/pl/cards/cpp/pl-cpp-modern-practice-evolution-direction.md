## Q
C++ 的演进方向是什么？C++26 及之后，哪些特性会改变"现代 C++ 的写法"？

## A
**演进的主线**（三年一版，每版几项大特性）：

1. **更少样板，更强编译期**：C++20 的 concepts、`<=>`、指定初始化；C++23 的 `deducing this`、`std::print`；`constexpr` 年年扩张。
2. **更好的库**：C++20 的 ranges 和 `std::span`；C++23 的 `std::expected`、`std::flat_map`、更多 ranges 适配器；C++26 的 `std::execution`（异步/并行的统一框架）、`std::inplace_vector` 等。
3. **更安全**：标准库加固、未初始化读取变成"错误行为"、契约（`pre`/`post`/`contract_assert`），profiles 仍在讨论。
4. **元编程升级**：C++26 的**静态反射**让编译期代码能读取类型的成员、枚举值名字，用来做序列化、枚举转字符串、绑定生成，取代大量宏和代码生成器。
5. **工具链改善**：模块、`import std;` 逐步可用；构建系统和包管理仍靠生态。

**这些的取向**：
- **增加表达力而不增加运行时成本**（"零开销"仍是底线）；
- **把过去靠约定和工具做的事纳入语言**（边界检查、契约、反射）；
- **对内存安全问题给出回应**，但不引入借用检查那样大的新语言子集；
- **继续不破坏兼容**。

**对写法的影响**（预期方向）：
1. 序列化、日志、绑定代码用反射生成，不再手写或用宏；
2. 异步和并行用 `std::execution` 的 sender/receiver 组合，代替自己拼线程池和回调；
3. 前置条件用契约写在函数签名上，加固构建里自动检查；
4. 模块逐步取代头文件，`import std;` 取代一屏 `#include`；
5. 模式匹配仍是候选，若进入标准，将补上 `variant` 的使用体验。

**不确定性**：标准的发布与编译器落地之间有数年的差距。一个特性在标准里并不等于你的编译器可用；本机的 libc++ 就还缺 `<generator>`、`views::enumerate`，Apple clang 也不接受模块写法。**判断是否采用，要看你所有目标编译器和标准库的实现状况**。

**如何跟进**：看 cppreference 的"编译器支持"表，看项目自己的最低编译器版本；对关键特性在 CI 里用多个编译器验证；用 `__cpp_lib_*` / `__cpp_*` 特性测试宏做条件编译。

**要记住的一点**：C++ 在向"更安全的表达力、同样的零开销"这条线上缓慢但持续地前进；用的时候以工具链支持为准，不以标准文本为准。
