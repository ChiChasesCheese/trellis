## Q
标准把"结果不唯一"的情况分成哪几类？实现定义行为（implementation-defined）、未指定行为（unspecified）和未定义行为有什么区别？

## A
按"标准要求编译器做什么"，从严到松：

1. **明确定义**：结果唯一，如 `unsigned` 整数溢出一律回绕（模 2^n）。
2. **实现定义**（implementation-defined）：允许多种结果，但**编译器必须选定一种并写进文档**。例：`sizeof(long)`（本机 8，Windows 上是 4）、`char` 是否有符号、位域在内存中的排布。可移植性问题，但行为稳定、可预期。
3. **未指定**（unspecified）：允许多种结果，**不要求文档**，也不要求每次相同。例：函数参数的求值顺序。结果总是几种合法可能之一，程序不会崩，但代码不应依赖某一种。
4. **未定义**（undefined）：**没有任何要求**。

**用本机输出看前三类**：

```cpp
int order(int v) { print("{} ", v); return v; }
int add(int a, int b) { return a * 10 + b; }
add(order(1), order(2));   // 本机 clang 打印 "1 2"，换编译器可能是 "2 1"
```

`sizeof(long)` 为 8，`(char)-1 < 0` 为 `true`（本机 `char` 有符号）。这些都是实现定义，写在平台文档里。

**关键区别**：
- 实现定义与未指定是"**选项有限**"：结果必是几种之一，程序的其他部分仍然有意义。
- 未定义是"**没有选项**"：编译器可以假设它不发生，并据此变换整个程序。

**常见的 UB**：有符号整数溢出、解引用空指针或悬垂指针、越界访问、数据竞争、读取未初始化变量（C++26 前）、违反严格别名（用不兼容的类型读同一块内存）、移位位数超过类型宽度、非 `void` 函数没有 `return`。

**要记住的一点**：遇到"这段代码在我这儿正常"时，先问它属于哪一类——实现定义只是不可移植，未定义才是真正的炸弹。
