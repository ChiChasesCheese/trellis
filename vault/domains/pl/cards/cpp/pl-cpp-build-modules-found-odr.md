## Q
单一定义规则（ODR，One Definition Rule）是什么？违反它时，编译器和链接器分别会怎样？

## A
**规则**：整个程序里，每个非内联的函数和变量只能有**一个定义**；允许出现在多个翻译单元里的东西（类定义、`inline` 函数、模板）必须在每个翻译单元里是**逐词相同**的。声明可以有多个，定义只能有一个。

**为什么存在**：链接器按**名字**把引用连到定义。每个翻译单元独立编译，编译器看不到别的翻译单元里有没有同名定义。如果有两个不同的 `answer()`，链接器无法决定用哪个。

**违反的两种后果**：

1. **非内联函数两处定义：链接器报错**（最好的结果）。本机真实输出：

```
duplicate symbol 'answer()' in:
    e-d55c98.o
    f-f214ad.o
ld: 1 duplicate symbols
```

2. **`inline` 函数在两个文件里定义得不同：不报错，行为未定义**。标准规定 `inline` 函数可以在多个翻译单元出现，**前提是定义相同**。链接器看到同名的 `inline` 函数，会认为它们是同一个，只留下一份。本机实测：

```cpp
// a.cpp:  inline int answer() { return 1; }  int from_a() { return answer(); }
// b.cpp:  inline int answer() { return 2; }  int from_b() { return answer(); }
```

`-O0` 编译得到 `from_a=1 from_b=1`（链接器丢掉了第二份，`from_b` 却返回了 `a.cpp` 的值）；`-O2` 编译得到 `from_a=1 from_b=2`（优化器把 `answer()` 内联了，各自用了自己的版本）。**同一份源码，换个优化级别结果就变**，没有任何错误或警告。

**为什么编译器和链接器都不报错**：编译器一次只看一个翻译单元，看不到冲突；链接器只比较名字，不比较内容。检查需要跨翻译单元比较定义，C++ 的构建模型不提供。

**检测手段**：
- ASan 的 `detect_odr_violation`（对全局变量的大小/位置不一致有效，不能保证抓住函数体差异）；
- LTO（链接时优化）加警告，如 GCC 的 `-Wodr`；
- 避免在多个文件里定义同名的非 `static` 小函数，用匿名命名空间或 `static` 限定内部链接。

**其他语言**：Rust 的 crate 是编译单位，编译器看得到整个 crate，重复定义是编译错误；Java 一个类一个文件，类加载器按名字加载；Go 包内重复定义也是编译错误。C++ 的这类错误只能在链接阶段被发现，或者完全发现不了。

**要记住的一点**：ODR 违反是"可以通过构建的 bug"，最危险的是完全无声的那种；在多个源文件里定义同名的东西要用匿名命名空间隔开。
