## Q
C++ 的并发模型是什么？在"怎样让多段代码同时工作又不出错"的设计空间里，它给了什么、没给什么？

## A
**问题**：要让程序利用多核，就要让多段代码同时运行；一旦它们共享数据，就可能互相干扰（数据竞争）。语言需要回答：怎么启动并行单元，怎么共享数据，怎么保证共享是安全的。

**设计空间**：
1. **共享内存加锁**（C++、Java）：线程直接读写同一块内存，用互斥锁和原子操作同步。灵活、接近硬件，正确性靠程序员。
2. **消息传递**（Go 的 channel，Erlang 的 actor）：线程之间不共享可变状态，只传消息。更容易推理。
3. **类型系统保证**（Rust）：编译器用所有权和 `Send`/`Sync` 在编译期阻止数据竞争。
4. **全局锁**（CPython 的 GIL）：同一时刻只有一个线程跑 Python 字节码，回避大部分竞争，牺牲并行。

**C++ 的位置**：选第 1 种，并且是**最低层**的版本。C++11 起标准定义了：
- 线程：`std::thread`，后来的 `std::jthread`；
- 同步：`std::mutex`、`std::scoped_lock`、`std::condition_variable`；
- 原子操作与**内存模型**：`std::atomic` 加六种 `memory_order`，规定多线程下读写的可见性与顺序；
- 异步结果：`std::future`、`std::async`；
- C++20 协程：语言层面的可暂停函数，但**库支持很薄**。

**关键规则**：对同一内存位置，如果一个线程写、另一个线程读或写，且没有同步，就是**数据竞争**，是**未定义行为**。语言既不检查，也不保证出错时的行为。

**没给什么**：没有内置的任务调度器和绿色线程（C++26 的 `std::execution` 正在补）；没有类似 Go 的 channel；没有 Rust 那样在编译期阻止竞争的类型规则。

**取舍轴**：对硬件的控制与可移植性，对比易用与安全。C++ 给出能写出最快并发代码的原语，把用对它们的责任留给你。

**要记住的一点**：在 C++ 里，并发的安全不是语言给的，而是你的设计纪律：共享越少越好，需要共享就用锁或原子操作，并用 TSan 验证。
