## Q
零开销原则在实现上靠哪几个机制？“用才付费”的几个典型功能（虚函数、异常、RTTI）各自在什么时候才产生成本？

## A
**四个支撑机制**：
1. **值语义**：对象直接放在栈上或成员里，不默认带对象头、不默认在堆上。`struct P { int x; }` 的大小就是 4 字节。
2. **静态分派加内联**：普通函数和模板调用在编译期绑定，编译器可以把调用展开，进一步优化。
3. **没有强制运行时**：没有 GC、没有虚拟机、没有反射元数据；程序启动前后不跑额外的系统。
4. **成本推到编译期**：模板实例化、`constexpr` 计算都在编译时完成，代价是编译慢、二进制变大。

**“用才付费”的例子**：
- **虚函数**：只有声明了 `virtual`，对象才多一个指向虚表（vtable，函数地址表）的指针。本机实测：`struct P { int x; }` 为 4 字节，加上 `virtual void f()` 后变成 16 字节（8 字节虚表指针，加上 4 字节数据和对齐填充）。调用也变成间接调用，通常不能内联。
- **异常**：不抛异常时几乎无运行时指令；代价是编译器生成的展开表占二进制体积，以及抛出时的慢路径。
- **RTTI**（运行时类型信息，支撑 `dynamic_cast`、`typeid`）：只有多态类型才生成类型信息，可以用 `-fno-rtti` 整个关掉。

**反面**：这套模型意味着 C++ 里几乎没有“免费的东西”被隐式地给你。`std::string` 默认 24 字节，拷贝会分配堆内存；`std::shared_ptr` 的引用计数是原子操作。你必须知道每个类型背后做了什么，才能判断“这行代码有多贵”。

**要记住的一点**：C++ 的抽象成本是**可预测**的，但不是**可见**的；编译器不告诉你一行代码是否分配了内存，需要靠类型知识、性能分析和汇编去核对。
