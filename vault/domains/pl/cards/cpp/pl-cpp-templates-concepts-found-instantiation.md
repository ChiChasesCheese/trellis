## Q
函数模板和类模板是怎么"实例化"（instantiation）的？为什么模板的完整定义必须放在头文件里？

## A
**模板**是用类型（或常量）参数化的代码配方，写法 `template <class T>`。使用时，编译器**推导**类型实参，把模板体里的 `T` 全部替换为实参，生成一份具体函数或类，称为**实例**。

```cpp
template <class T> T maxof(T a, T b) { return a < b ? b : a; }
maxof(3, 4);        // 推导 T = int，生成 maxof<int>
maxof(2.5, 1.5);    // 另生成 maxof<double>
```

每种不同的实参类型对应一份**独立编译**的代码。对 4 个不同结构体各调用一次 `std::sort`，本机 `nm` 实测目标文件里有 4 份独立的 `__introsort` 实例（每个类型一份）。同一个类型在多个文件里被实例化，链接器会合并重复的实例。

**两个阶段的检查**：
1. **定义时**：只检查与模板参数无关的部分（语法、非依赖名字）。
2. **实例化时**：把 `T` 换成真实类型再检查，依赖 `T` 的表达式（比如 `a < b`）此时才被验证。

**为什么模板定义要放头文件**：实例化时编译器必须看到模板的**完整定义**才能生成代码。如果只有声明，别的源文件在调用时没有配方可用，链接阶段就找不到实例。所以模板通常整个写在头文件里，每个用到它的源文件都包含一遍；这也是 C++ 编译慢的原因之一。

**按需实例化**：只有被用到的成员函数才会被实例化。`std::vector<T>` 对一个没有默认构造函数的 `T` 仍可使用，只要你不调用需要默认构造的函数（比如 `resize(n)` 不带初值）。

**类模板还有特化**（specialization）：对特定类型提供不同实现，例如 `std::vector<bool>` 是按位压缩的特化。这是 C++ 模板强大也容易出意外的一面。

**要记住的一点**：模板本身不产生代码，被使用时才产生；"模板的错误"常常在你第一次用某个类型调用它时才暴露。
