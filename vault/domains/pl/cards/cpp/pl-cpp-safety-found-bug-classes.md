## Q
C++ 里典型的内存安全 bug 有哪几类？每一类怎样产生，哪些手段能对付它？

## A
| 类别 | 怎样产生 | 防御 |
|---|---|---|
| 越界访问（spatial） | `v[i]` 超出 `size()`；指针算术越过缓冲区 | 加固标准库、`std::span`、`.at()`、ASan |
| 生命周期错误（释放后使用、返回后使用、重复释放） | 迭代器/指针/引用在容器扩容或对象析构后继续使用；返回指向局部变量的引用，lambda 按引用捕获局部变量后逃逸；两个所有者各自释放同一资源 | 智能指针与五法则、按值捕获、编译器警告、ASan（含 `detect_stack_use_after_return`） |
| 未初始化读取 | 局部变量未赋值就使用 | 就地初始化、`-ftrivial-auto-var-init`、C++26 的错误行为 |
| 数据竞争 | 无同步的并发读写 | TSan、锁与原子 |
| 类型混淆 | 错误的强制转换、`union` 误用、`reinterpret_cast` | 避免 C 风格强转，用 `std::variant`、`std::bit_cast` |

**第 1 类（越界）的最小例子**，本机真实行为：

```cpp
std::vector<int> v{1, 2, 3};
println("v[10] = {}", v[argc + 9]);
```

普通构建输出 `v[10] = 0`：读到了堆上相邻的内存，没有崩溃，没有警告，这是未定义行为"碰巧安静"的形态。

**为什么这些 bug 这么常见**：C++ 的核心类型 `T*` 和 `T&` **不携带任何边界或生命周期信息**。一个 `int*` 不知道自己指向 1 个还是 100 个元素，也不知道所指向的对象何时消失。所有的检查都要靠额外的包装类型（`span`、智能指针）或外部工具。

**严重性的差别**：
- 越界读：泄漏信息（Heartbleed 即此类）；
- 越界写、释放后写：可被利用来控制程序执行；
- 释放后使用在大型代码库里最难查，因为问题出现的位置和原因相隔很远。

**一个有用的区分**：空间错误多数可以靠**运行时检查**低成本解决（加固库）；时间错误需要**对象生命周期信息**，运行时检查代价高（需要追踪每个指针），静态证明需要语言支持（Rust 的借用检查器）。这是 C++ 的两条不同的路。

**要记住的一点**：越界和生命周期是两类问题，C++ 近期的措施对越界很有效，对生命周期仍然不足。
