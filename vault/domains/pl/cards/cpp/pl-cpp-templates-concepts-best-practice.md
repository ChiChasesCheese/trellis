## Q
资深 C++ 工程师怎样写和用模板？什么时候该用模板，什么时候该用虚函数或类型擦除？

## A
**写模板的规则**：
1. **公共接口的模板一律加 concepts**：写 `template <std::ranges::input_range R>`，不写裸 `template <class R>`。约束是接口文档，也是良好错误信息的来源。
2. **优先用标准 concepts**，自定义 concept 要有清楚的语义，并用 `static_assert` 做正例和反例测试，防止约束漂移。
3. **用缩写函数模板**：`void f(std::integral auto x)`，比 `template <std::integral T>` 简洁。
4. **模板要薄**：与类型无关的大段逻辑抽到非模板的内部函数，让模板只做类型相关的那几行，减少重复实例化。
5. **接口用 `constexpr`、`noexcept` 按需标注**，让优化器和调用者有信息。
6. **避免深层模板元编程**：能用 `constexpr` 函数、`if constexpr` 或 concepts 的地方，不要写递归模板特化；后者编译慢、难调试。

**什么时候用什么**：

| 需要 | 选择 |
|---|---|
| 类型编译期已知，追求速度，容器、算法、数值 | 模板 |
| 运行时才知道具体类型，插件、异构集合 | 虚函数 |
| 想要值语义的多态、又不想暴露继承 | 类型擦除（`std::function`、自写 `any_drawable`） |
| 减少二进制体积和编译时间 | 在模块边界用虚函数，内部用模板 |

**常见搭配**：模板用在库的"内核"，运行时多态用在系统的"边界"（插件接口、服务层），两者组合，边界处付一次间接调用，内部保持零开销。

**工具**：
- `-ftime-trace`（Clang）生成火焰图，看哪个头文件、哪个模板实例最耗时；
- `clang-tidy` 的 `cppcoreguidelines-*`、`modernize-*` 检查组；
- `nm -C` 或 `bloaty` 看目标文件里重复的实例。

**何时打破**：当类型数量很多、每个实例只在极少数地方使用，且性能不重要时，用类型擦除或虚函数更省编译时间；不要为了"现代"而把所有东西写成模板。

**为什么**：模板的成本是编译期、体积和可读性，收益是运行时。只有收益大于成本的地方才值得付出。
