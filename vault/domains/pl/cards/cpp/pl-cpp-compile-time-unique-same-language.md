## Q
"编译期和运行期用同一份语言"这个设计，对 C++ 意味着什么？它与 Rust 的宏、Zig 的 `comptime` 比，哲学上的差别在哪？

## A
**C++ 的做法**：`constexpr` 函数是普通函数，用同样的语法、同样的类型、同样的标准库，只是调用时机不同。写一个排序函数，既能在运行时排用户输入，也能在编译期排一个常量数组。这背后的价值观是：**不引入第二种语言**。

**对比三种路线**：
1. **C++：同一语言，函数粒度**。编译期计算的是**值**；对**类型**的计算要借助模板（另一套机制）。所以 C++ 有两套编译期设施：`constexpr`（算值）和模板（算类型）。C++26 的反射把"读取类型的结构"也纳入同一风格，补上缺口。
2. **Rust：两种语言**。`const fn` 算值；**宏**是另一种东西，在语法树上做代码生成，写起来像模式匹配或另一个 Rust 程序（过程宏本身是一个编译到动态库的 Rust 程序）。分工清楚：宏生成代码，`const fn` 算常量。
3. **Zig：统一成一种**。`comptime` 让类型是普通值，一个函数可以接收类型、返回类型，泛型就是 `comptime` 参数。没有模板这一套，也没有宏。

**对 C++ 的影响**：
- **优点**：不用学新语言就能写编译期代码；已有的函数不改就能复用；测试容易（`static_assert`）。
- **缺点**：两套机制（`constexpr` 与模板）并存，历史包袱重；写类型相关的元编程仍然要用晦涩的模板；一个函数能否在编译期用，要靠语言规则一版版放宽，学习者必须知道自己的编译器支持到哪一版。

**哲学**：C++ 的做法是"**渐进补齐**"——不停止旧机制，只在旁边加更好的。结果是能力很强、历史很重。Zig 是"重新设计"，一致但不兼容；Rust 是"分层"，各管一块。

**要记住的一点**：C++ 里想问"这件事能不能编译期做"，答案常常是"能，但要看标准版本和编译器"；写可移植的库时，要查清目标编译器支持到 `constexpr` 的哪一级。
