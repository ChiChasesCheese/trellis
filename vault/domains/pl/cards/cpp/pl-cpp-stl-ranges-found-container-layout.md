## Q
`vector`、`list`、`map`、`unordered_map`、`flat_map` 在内存里各是怎样排布的？为什么布局决定了真实性能？

## A
容器的复杂度（O(1)、O(log n)）只是理论；在现代 CPU 上，**内存布局**决定缓存命中率，常常比复杂度更重要。

| 容器 | 内存布局 |
|---|---|
| `std::vector` | 一整块**连续**内存，扩容时搬到更大的新块 |
| `std::list` | 每个元素一个**独立节点**（数据 + 前后指针），各自堆分配 |
| `std::map` | 红黑树，每个键值对一个独立节点 |
| `std::unordered_map` | 桶数组 + 每个元素一个节点（链式），节点各自堆分配 |
| `std::flat_map`（C++23） | 键和值各存在**有序的连续数组**里，用二分查找 |

**为什么布局重要**：CPU 一次从内存取一整条缓存行（常见 64 字节），连续访问时后续元素已经在缓存里；遍历链表每个节点是一次指针跳转，很可能是一次缓存未命中（代价约上百个周期）。

**本机实测**（一次测量，`-O2`）：
- 对 200 万个 `int` 求和：`vector` 约 0.08 ms，`list` 约 1.5 ms，慢约 20 倍（节点是顺序分配的，已是接近最好的情况；真实程序里节点散落时更糟）。
- 100 万个随机键的查找：`std::map` 约 275 ms，`std::unordered_map` 约 12 ms，`std::flat_map` 约 31 ms。红黑树每次查找要沿指针走约 20 层，每层一次缓存未命中；哈希表一次计算 + 一两次跳转；`flat_map` 是连续数组上的二分，缓存友好。

**经验规则**：
1. **默认用 `vector`**。即使要在中间插入删除，元素较小时 `vector` 也常常比 `list` 快，因为移动连续内存很便宜；
2. 需要按键查找，先想 `unordered_map`；需要有序遍历，用 `map`，或读多写少时用 `flat_map`；
3. `list` 的适用场景很窄：需要保持迭代器稳定且频繁在中间插入删除的大元素。

**代价**：连续容器的代价是**扩容时的拷贝或移动**，以及**元素地址会变**（见迭代器失效）。

**对比**：Java 的 `ArrayList` 里存的是对象引用，遍历仍要逐个解引用；C++ 的 `vector<int>` 存的是值本身，没有间接，这是同样"O(n) 遍历"下 C++ 更快的重要原因。Rust 的 `Vec<T>` 与 C++ 的 `vector` 同构。

**要记住的一点**：选容器时先问"数据是否连续、会不会常搬动"，再看复杂度。
