## Q
模板为什么运行得快，又为什么让编译变慢、二进制变大？用 `std::sort` 与 `qsort` 的对比说明。

## A
**为什么快：比较函数可以内联。**

C 的 `qsort` 通过**函数指针**调用比较函数：每次比较一个间接调用，编译器看不到被调函数，无法内联，也无法做针对 `int` 的优化。`std::sort` 是模板，比较器是模板参数（一个具体类型），调用在编译期绑定，编译器直接把比较内联进排序循环。

**本机实测**（500 万个随机 `int`，`-O2`，三次稳定）：

```cpp
std::qsort(a.data(), a.size(), sizeof(int), cmp);   // 约 321 ms
std::sort(b.begin(), b.end());                      // 约 77 ms
```

`std::sort` 约快 4 倍。这是"零开销抽象"最典型的收益：抽象（可替换的比较器）没有运行时成本。

**为什么编译慢、体积大**：
1. **每种类型实参一份实例**。对 4 个不同结构体各调用一次 `std::sort`，目标文件里 `nm` 看到 4 份独立的 `__introsort`。同时有 100 种类型就有 100 份。
2. **头文件里的模板定义要被每个源文件重新解析**。本机用 `-fsyntax-only` 测，仅 `#include <vector>` 约 0.10 秒；再加上 `<ranges>`、`<algorithm>`、`<map>`、`<string>`、`<print>` 约 0.24 秒（一次测量，仅一个很小的文件）。大型项目里这样的开销乘以数千个源文件。
3. **错误信息长**：实例化链条越深，报错越长。

**怎么缓解**：
- **显式实例化**：`extern template class std::vector<Foo>;` 告诉编译器"别处已有这个实例，别再生成"，在一个源文件里 `template class std::vector<Foo>;` 生成一次。
- **把与类型无关的部分抽成非模板**：模板函数的"薄外壳"调用一个非模板的内部实现，减少重复代码。
- **预编译头、unity build、C++20 模块**：减少重复解析。
- **链接器的相同代码折叠**（ICF）：把字节相同的函数合并。

**对比**：Java 泛型擦除只有一份代码，体积小但装箱有运行时成本；Rust 同样单态化，编译慢、体积大，与 C++ 一样，所以 Rust 编译慢不是偶然，是同一笔交易的同一个代价。

**要记住的一点**：模板的"快"和"慢"来自同一个机制——每个类型一份专用代码；运行时的收益换编译期的开销。
