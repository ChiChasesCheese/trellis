## Q
Go 1 兼容承诺是什么？`go.mod` 里的 `go` 行和 `GODEBUG` 怎样让语义变化也能按项目选择加入，一个循环变量的例子说明了什么？

## A
**Go 1 兼容承诺**（2012）：为 Go 1 写的合法程序，在所有后续 Go 1.x 版本里应当继续编译并按原样运行。语言规范与标准库 API 因此只增不删。例外很少：安全问题、规范模糊或编译器 bug。

**问题**：有些错误是**语义**而非 API，修改就会改变旧代码行为。最经典的是循环变量：

```go
for i := 0; i < 3; i++ { fs = append(fs, func() { fmt.Print(i, " ") }) }
```

在 Go 1.21 及以前，整个循环共享同一个 `i`，闭包稍后调用时 `i` 已经是 3，打印 `3 3 3`，几乎所有人都被这个坑过。要修，但直接改会破坏兼容承诺。

**解法：用 `go.mod` 的 `go` 行按模块选择语义**。Go 1.22 把每次迭代变成新变量，但**只对 `go.mod` 里声明了 `go 1.22` 及以上的模块生效**。真实结果：同一段代码，`go 1.21` 的模块输出 `3 3 3`，`go 1.22` 的模块输出 `0 1 2`。旧代码保持旧行为，升级是显式的一行改动。

**`GODEBUG`**：对运行时和标准库的行为变化，Go 用 `GODEBUG` 设置（如某个开关取旧值）保留旧行为；默认值随 `go.mod` 的 `go` 行变化，并且可以在 `go.mod` 里用 `godebug` 指令固定。Go 团队承诺这些兼容开关至少保留若干年。

**工具链配合**：Go 1.21 起，`go` 行是**最低要求**，工具链可自动下载所需版本（`toolchain` 指令），使得“旧编译器遇到新语义”会明确报错，而不是悄悄按旧语义编译。

**要记住的一点**：Go 的兼容策略是“承诺不破坏，同时让需要改变语义的地方按模块选择加入”。
