## Q
Go 把兼容性写成对用户的公开承诺，Python 的 2→3 则选择了断裂。这两种态度怎样体现语言设计者对“用户信任”的看法？

## A
**Go：兼容性是承诺，不是努力**。Go 1 的兼容文档是一份契约：只要你的程序符合规范，未来的 Go 1.x 就不应让它失效。设计者把这当成一种资本：开发者信任工具链不会在升级时背叛自己，才愿意在语言上长期投入。代价同样明确：团队放弃修正许多已知的设计缺陷（如标准库里一些命名和行为），只能新增替代品（例如新的 `slices`、`maps`、`log/slog` 与旧包并存）。当语义缺陷（循环变量）严重到必须修改时，Go 团队没有违反承诺，而是花了多年设计“按模块选择加入”的机制，修复的成本由语言团队承担。

**Python 2→3：为了对的设计，让用户付出代价**。核心设计者判断文本模型的错误是根本性的，每多等一年，受害的代码就多一年的量。选择了不兼容，换来 Unicode 的正确性。结果是迁移用了十几年，2020 年才结束维护；同时它也是迄今最有名的“教训案例”，之后 Python 社区的口头禅变成“不会再有 Python 4 式的断裂”。

**Java 在中间并更接近 Go**：几乎不删除，宁可让旧 API 无用也不让旧程序失败（`Thread.stop()` 仍在，只是抛 `UnsupportedOperationException`）。

**Rust 的做法是第三种哲学**：承诺 1.0 之后稳定版不破坏，但允许语言本身有“方言”。设计者认为：兼容性与演进不矛盾，只是需要一个机制，让“破坏”变成“局部的、可选择的、机械可迁移的”。

**揭示的价值观**：
- **Go、Java**：用户的时间比语言的优雅更宝贵。
- **Python（早期）**：长期正确性比短期痛苦更重要。
- **Rust**：把“破坏”工程化，使其成本可控。

**对选语言的意义**：寿命长、团队更替多的系统，倾向选择兼容承诺强的语言；快速迭代、可以定期重写的产品，对兼容性的要求较低。
