## Q
Go 的 `go generate` 是什么？它的工作流程和产物是什么，用 `stringer` 的场景说明。

## A
**是什么**：`go generate` 是 Go 工具链里的一个独立命令。它扫描源文件中形如 `//go:generate 命令行` 的特殊注释，逐条执行这些命令。命令通常是一个读你的 Go 代码、写出新的 `.go` 文件的程序。重点：`go build` 和 `go test` 不会自动调用它，你必须手动运行。

**心智模型**：把「生成代码」当作一个显式的、人来触发的构建前步骤，输出的是普通源文件，之后和手写代码一视同仁。

**场景**：有一个枚举（Go 里用 `iota` 常量模拟），想让打印时显示名字而不是数字。官方的 `stringer` 工具能生成 `String()` 方法：

```go
//go:generate go run golang.org/x/tools/cmd/stringer@latest -type=Color
type Color int
const ( Red Color = iota; Green; Blue )
```

运行 `go generate ./...` 后，旁边多出 `color_string.go`，文件第一行是 `// Code generated by "stringer -type=Color"; DO NOT EDIT.`，里面是一张从数字到名字的查表。`fmt.Println(Red, Blue)` 的真实输出是 `Red Blue`。

**要记住的两点**：
- 第一行的 `Code generated ... DO NOT EDIT.` 是 Go 的约定，linter 和代码评审工具看到它就跳过该文件。
- 生成的文件按惯例提交进版本库，这样别人 clone 下来直接 `go build`，不需要安装生成器。典型的生成对象还有 Protocol Buffers 的 `.pb.go`、mock、SQL 查询代码（sqlc）。
