## Q
Python 的运行时动态特性（猴子补丁、`__getattr__`、描述符、元类、`eval`/`exec`）想解决什么问题？它们共同的设计原则和代价是什么？

## A
**问题**：库作者想让用户几乎不写样板就能用上复杂行为：属性像普通字段，实际上却带校验；对象的方法由外部数据决定；测试时临时替换一个依赖；插件自动注册。在编译型语言里这些要靠反射、代理、代码生成，在 Python 里由语言的**数据模型**直接支持。

**共同原则**：Python 的对象模型把「属性查找」「类的创建」「函数的调用」都暴露成可以被覆盖的协议（以双下划线开头的特殊方法），任何类都可以接入。你不是在使用框架提供的扩展点，而是在改写语言规则本身。

**设计空间**：同一个目标（让一个名字背后的行为可定制）有不同层级的钩子，从轻到重：
1. 直接替换：猴子补丁（monkey patching），运行时给模块、类、函数换新实现。
2. 属性协议：`property`、描述符（descriptor）、`__getattr__`，定制「读写一个属性时发生什么」。
3. 类创建协议：`__init_subclass__`、元类（metaclass），定制「创建一个类时发生什么」。
4. 执行字符串：`eval`/`exec`，把文本当代码运行。

**取舍轴**：灵活性对比可分析性与性能。每往下一级，库作者能力更强，同时静态工具（类型检查器、IDE）更难知道对象有哪些属性，解释器也更难优化。Python 的整个生态（Django ORM、SQLAlchemy、pytest、Pydantic）建立在前三级上，代价就是这一张表。
