## Q
Go、Java、Rust、Python 的代码生成分别插在编译与运行流程的哪个位置？这个位置怎样决定它的成本和失败方式？

## A
把一个项目从源码到运行看成：生成 → 编译 → 运行三步，各语言插入点不同：

| 语言 | 插入点 | 触发方式 | 生成物位置 |
|---|---|---|---|
| Go | 编译之前 | 人手动运行 `go generate` | 源码目录，提交入库 |
| Java | 编译之中（多轮） | `javac` 自动调用处理器 | 生成源码目录，通常不入库 |
| Rust | 编译之前或之中 | Cargo 自动运行 `build.rs`；编译器调用过程宏 | `target/` 下，不入库 |
| Python | 运行时（导入或类创建时） | 解释器执行装饰器、元类 | 内存中，无文件 |

**成本差异**：构建期生成的成本付在构建上（Rust 过程宏让编译变慢），运行时零开销。运行期生成的成本付在启动上：一次本机测量，创建 1000 个 `dataclass` 约 65 ms，每个约 66 微秒，而简单的 `type()` 创建约 2 微秒。每个类看起来无所谓，几千个类的大型应用，导入阶段就是几百毫秒。

**失败方式差异**：Go 的生成需要人记得运行，失败表现为「生成物过期」；Java 与 Rust 随构建自动运行，失败表现为编译错误，但错误信息常指向生成的代码；Python 的失败表现为导入时或首次调用时抛异常，错误栈里出现 `<string>`。

**规律**：生成得越早、越显式，故障越可见、越容易在 CI 里拦住；生成得越晚，越灵活，也越把问题留给运行时。
