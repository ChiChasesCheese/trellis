## Q
Rust 的宏在编译流程的哪一步展开？什么是卫生（hygiene），它为什么让 `macro_rules!` 比 C 宏安全？

## A
**展开位置**：宏在解析（parsing）之后、类型检查之前展开。输入是 token 树，输出是语法树片段，然后才进入类型检查。所以宏可以引入新语法，但展开出的代码必须仍然是合法的 Rust。过程宏则是一个单独编译的 crate，编译器把它加载进自己的进程里执行，等于在编译机上运行你写的程序。

**卫生**：宏内部引入的局部变量带有「语法上下文」标记，和调用者的同名变量属于不同的名字，永不冲突。参数写成 `$x:expr` 时，展开结果是一个已解析好的表达式整体，不会被周围运算符拆开。

```rust
macro_rules! using_a { ($e:expr) => { { let a = 42; $e + a } } }
fn main() { let a = 1; println!("{}", using_a!(a)); }
```

输出 `43`：`$e` 里的 `a` 是调用者的 1，宏里的 `a` 是 42，二者互不遮蔽。同样的写法如果在 C 里用文本替换，两个 `a` 会撞在一起，结果取决于宏怎么写。

要点：卫生解决的是名字冲突和运算符优先级这两类「文本拼接」问题，但没有解决「参数被求值几次」，那是语义层面的事：宏参数写了几次，就会被求值几次。
