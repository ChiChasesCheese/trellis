## Q
Python 的动态特性在近年的演进方向是什么？为什么语言在给动态性「加约束」，同时让解释器利用「大多数时候其实是静态的」？

## A
**观察**：真实的 Python 程序里，绝大多数对象的形状在整个运行期都不变，类很少被改写。动态性是**能力**，而不是**常态**。现代 CPython 的演进就围绕这个观察展开：

1. **让常见情形变快，保留罕见情形的能力。** 3.11 的自适应解释器（PEP 659）把字节码根据实际见到的类型「特化」，属性访问、方法调用、全局查找在稳定类型下走快速路径；一旦类被改写，退回慢路径。3.13 起还有实验性的 JIT（PEP 744）和可选的无 GIL 构建（PEP 703），同样建立在「运行期行为大多可预测」的前提上。
2. **用显式声明给工具提供信息。** 类型注解（3.0 起可写，3.5 起有 `typing`）、`dataclass`、`__slots__`、`typing.Protocol`、`TypedDict`，让原本只能运行时发现的结构变成静态可检查。
3. **把常见的动态技巧升级为标准件。** `__init_subclass__` 替代多数元类，`dataclass` 替代手工的 `__init__` 元编程，`functools.cache` 替代手写缓存装饰器。

**方向总结**：语言没有放弃动态，而是让「需要动态的人明确声明」，其余代码被工具和解释器当作静态处理。这与 TypeScript 给 JavaScript 加类型、Java 给反射收紧、PHP 加严格类型的趋势一致：**渐进类型**（gradual typing）加上**对动态性的约束**，是动态语言走进大型代码库的共同路径。

**对读者的含义**：学 Python 元编程时，要学的不只是怎样用，还要学怎样让它**可被静态分析**。
