## Q
C 的预处理器宏（preprocessor macro）是什么？它在编译流程里处在哪一步，为什么说它「不懂语法」？

## A
**是什么**：C/C++ 在真正编译之前，先跑一个独立的文本处理阶段，叫预处理器（preprocessor）。`#define NAME 替换内容` 声明一条规则，之后源码里每出现 `NAME`，预处理器就把它换成替换内容。带参数的写法 `#define SQUARE(x) x*x` 看起来像函数，实际上也只是文本替换。

**心智模型**：把宏想成编辑器里的「查找并替换」，在编译器看到代码之前执行。预处理器只认识词（token）和括号配对，不知道什么是表达式、什么是类型、什么是作用域。

**场景**：

```c
#define SQUARE(x) x*x
int a = SQUARE(1+2);   // preprocessor outputs: int a = 1+2*1+2;
```

替换完变成 `1+2*1+2`，等于 5 而不是 9。预处理器没有错，它只是完全按文本做了替换。

**它能做什么**：条件编译（`#ifdef LINUX` 选择不同平台的代码）、定义常量、包含头文件（`#include` 就是把另一个文件的文本贴进来）、消除样板。这套机制简单、强大，也因此成为后来所有语言设计宏的反面教材：新语言要么不要宏，要么要求宏理解语法并保持名字不冲突。

**要记住的一点**：C 宏在编译器之外，编译器报错时指向的是替换之后的代码，调试器看不到宏名。
