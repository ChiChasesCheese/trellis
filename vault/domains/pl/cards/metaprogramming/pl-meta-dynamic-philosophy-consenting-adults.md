## Q
Python 社区常说「我们都是成年人」（we are all consenting adults here）。这句话怎样体现在动态特性的设计中，与 Rust 的态度形成怎样的对比？

## A
**Python 的立场：信任而不强制**。语言几乎不阻止你做任何事：下划线开头的 `_private` 只是约定，没有任何访问控制；你可以替换标准库函数，给内置类型之外的所有类添加方法，运行时改一个类的父类。Python 的假设是：程序员知道自己在做什么，语言的责任是提供能力，而不是替你设防。好处是库作者能写出 Django ORM、pytest 这种在其他语言里要靠编译器插件才能实现的体验；也因此测试可以不改源码就替换任何依赖。

**Rust 的立场：编译器是不可信任的代理人**。私有性由编译器强制，类型在编译期封闭，没有运行时改写的机制。Rust 假设：人会犯错，在大型代码库、多人协作、多年维护中尤其如此，所以把规则做成不可违反的，而不是靠约定。代价是灵活度低，需要在设计阶段想清楚。

**Java 在中间并向 Rust 靠拢**：早期反射可以越过 `private`，但 JDK 9 的模块系统和 JDK 16/17 的强封装把这扇门关上了，理由和 Rust 一样：当太多人依赖实现细节时，系统无法演进。

**揭示的价值观**：Python 为「一个人快速做对的事」优化，把安全留给纪律；Rust 与（后来的）Java 为「一千个人长期共同维护」优化，把安全编码进规则。同一份动态能力，在 50 行脚本里是生产力，在 50 万行代码库里就成了需要治理的风险，这也是 Python 大型项目都会加上类型注解和 lint 的原因。
