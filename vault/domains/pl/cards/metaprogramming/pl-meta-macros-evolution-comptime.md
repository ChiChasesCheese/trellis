## Q
宏这条技术路线是怎样演进的？为什么现代语言越来越倾向「用同一种语言在编译期运行代码」，而不是文本宏？

## A
**演进线索**：
1. Lisp 把代码当数据，宏就是操作列表的普通函数，强大但需要括号语法的支持。
2. C 预处理器把这个想法简化成文本替换，简单粗暴，带来优先级、重复求值、无法调试等问题。
3. C++ 用模板和 `constexpr` 逐步把预处理器要做的事移回语言内部。
4. Rust 保留了语法树级别的宏（`macro_rules!`、过程宏），但加上卫生规则和类型检查前展开。
5. Zig 的 `comptime` 更进一步：编译期运行的就是普通 Zig 代码，没有第二套宏语言。Rust 的 `const fn` 与 const 泛型也在往同一个方向走。

**为什么趋同**：宏的根本代价是「第二门语言」。读宏要学宏的语法，写宏要处理 token 与语法树，工具也要支持两套。让编译期执行用同一门语言，类型、调试器、测试都能复用。

**对 Go/Java/Python 的影响**：它们不走宏路线，但在补同一块需求。Go 1.18 加了泛型，消除了很大一部分「复制粘贴样板」；Java 的 `record` 和 `sealed` 消除了 Lombok 的主要用例；Python 的 `dataclass` 把装饰器模式做成标准库。共同的趋势：把常见样板吸收进语言本身，使得需要宏的场景越来越少。
