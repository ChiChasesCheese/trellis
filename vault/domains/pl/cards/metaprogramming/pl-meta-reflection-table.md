## Q
比较 Go、Java、Rust、Python 在反射上的取舍：各选了设计空间的哪一点，买到什么，付出什么？

## A
| 语言 | 选择 | 买到 | 付出 |
|---|---|---|---|
| Go | 运行时 `reflect`，类型描述链接进二进制 | `encoding/json`、`database/sql` 这类通用库 | 违规操作在运行时 panic，代码啰嗦，慢 |
| Java | 最完整的运行时元数据加注解 | Spring、Hibernate、JUnit 整个框架生态 | 启动慢，难做 AOT，强封装带来的兼容问题 |
| Rust | 没有运行时反射，靠 `derive` 宏编译期展开 | 零运行时开销，二进制不带元数据 | 做不了「运行时发现类型」，宏让编译变慢 |
| Python | 对象即字典，反射是日常 | 反射几乎免费，monkey patch、插件很容易 | 静态工具看不出类型，运行时才暴露错误 |

**为什么各走各路**：这条线是每门语言「类型信息归谁管」的直接结果。Java 诞生在企业框架时代，目标是让容器替你装配对象，所以元数据越丰富越好。Go 要的是读得懂、编译快、二进制自带，所以只给一个够标准库用的最小反射，并且故意不好用。Rust 要「抽象不产生运行时代价」，既然类型信息可以在编译期用掉，就不带到运行期。Python 是动态语言，反射不是一个特性，而是语言本来的样子。
