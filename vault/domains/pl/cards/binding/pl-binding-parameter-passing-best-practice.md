## Q
资深工程师在 C++、Go、Java、Rust、Python 里怎样设计函数参数，才能让调用者不被意外修改数据？

## A
共同原则：**默认不修改入参；确实要修改，就让名字和类型说明它。**修改入参是函数最隐蔽的副作用，调用者无法从调用点发现。

**C++**
- 小类型（整数、指针、两个字以内的结构）按值传；只读的大对象传 `const T&`；只想看一段连续数据或字符串、不拥有它，用 `std::span`、`std::string_view`（只含指针和长度的视图）；要修改用 `T&`，函数名或文档里写清楚。理由：C++ 默认按值是深拷贝，签名要同时说明「拷不拷、改不改」。
- 要接管所有权才按值接收并 `std::move`；不要把引用参数存进长寿命对象。
**Go**
- 小结构体按值传，大结构体或需要修改时传指针；同一类型的方法接收者保持一致（要么全是值，要么全是指针）。理由：混用会让方法集和接口实现变得难懂。
- 函数接收切片时，文档写清楚是否修改元素、是否保留引用；要保存别人的切片，先 `slices.Clone`。理由：切片共享底层数组，保存即别名。
- 要让函数增长切片，返回新切片：`s = add(s, x)`。

**Java**
- 参数加 `final` 不是必需，但**不要重新赋值参数**，不要修改传入的集合；需要保存时防御性复制（`List.copyOf`）。理由：调用者的集合在你不知道的时候被别人改，会让你的对象内部状态被破坏。
- 公共 API 优先返回不可变视图或新集合，使用 `record` 和不可变集合。

**Rust**
- 参数默认用 `&T`（只读）；需要消费才用 `T`；需要修改才用 `&mut T`。接受字符串时用 `&str` 而不是 `&String`，接受序列时用 `&[T]` 而不是 `&Vec<T>`。理由：让调用者可以传任何兼容的来源。
- 不要为了绕过借用检查而到处 `clone()`；先想所有权设计能否改变。

**Python**
- 不修改入参；要修改就在名字里表达，或者返回新对象。默认参数不要用可变对象（`def f(x=None)`，函数内再创建）。
- 公共函数接受 `Sequence`、`Mapping` 等只读抽象类型的注解，向调用者承诺不会修改。

什么时候违反：性能关键路径上原地修改是合理的（排序、缓冲区复用），此时在函数名和文档里写明「原地」，并保证调用者不会在别处并发使用同一个对象。
