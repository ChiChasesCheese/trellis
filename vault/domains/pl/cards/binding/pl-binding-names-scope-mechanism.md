## Q
词法作用域在编译后留下了什么？一个名字在 Python、Java、Go、Rust 里分别被解析成什么，闭包捕获的变量放在哪里？

## A
词法作用域的好处是名字解析**在编译期完成**，运行时不再需要「名字」这个概念：

- **Java**：局部变量变成当前栈帧里的槽位编号（字节码 `iload_1` 就是「读第 1 号槽」），名字只留在调试信息里。
- **Go、Rust**：局部变量变成寄存器或栈上的偏移量，同样没有名字。
- **Python**：编译器按词法规则给每个名字分类，生成不同的字节码，名字本身仍保留在代码对象里。

用 `dis` 看内层函数 `k`，它引用了自己的参数 `a`、外层函数的 `b` 和模块级的 `x`：

```python
def h(a):
    b = 1
    def k(): return a + b + x
    return k
# dis(h(1)):  LOAD_DEREF a   LOAD_DEREF b   LOAD_GLOBAL x
```

三条指令对应三种成本：局部变量是数组下标（`LOAD_FAST`，最快）；被内层函数捕获的变量放进堆上的**单元**（cell），内外函数共享这一个单元，所以 `nonlocal` 能修改它（`LOAD_DEREF`）；全局和内置名字要在字典里按名字查（`LOAD_GLOBAL`，解释器会缓存结果来加速）。

**闭包捕获的变量放哪里**，决定了它能不能被修改、生命周期多长：

1. Python：捕获变量本身，放进共享的 cell。
2. Java：捕获变量的**值**，复制进 lambda 对象，所以要求不可变。
3. Go：捕获变量本身；被闭包引用的变量可能比函数活得久，编译器的逃逸分析把它搬到堆上。
4. Rust：闭包是一个编译器生成的结构体，按需持有引用（借用）或值（`move`），由借用检查器保证不悬空。

要记住的事实：词法作用域让局部名字成为纯粹的编译期概念；四门语言里只有 Python 在运行时仍按名字查全局变量和属性，所以它必须靠编译期的分类，才能把局部变量做成数组下标。
