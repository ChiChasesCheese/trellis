## Q
资深工程师怎样写表达式，才不会受求值顺序影响？Go、Java、Rust、Python 里有哪些具体做法？

## A
核心规则：**一个表达式里至多有一个带副作用的子表达式，而且它修改的变量不被表达式的其他部分读取。**违反了这条，行为是否正确取决于语言规范里的某一小段，而读者不会去查。

**通用做法**
- 把副作用拆成独立语句，先把结果放进具名局部变量，再使用：

```go
n := next()        // statement 1
m := next()        // statement 2
use(n, m)          // order now explicit
```

- 不在同一个语句里既修改变量又读取它（`i++` 与 `i` 同行出现）。
- 方法链里每一步应是纯函数或明确的副作用。

**各语言要点**
- **Go**：函数参数里不要依赖局部变量被闭包修改；`defer` 要用到的值，在 `defer` 之前显式赋给局部变量或作为参数传入；遍历 `map` 前如需稳定顺序，先收集键并排序。
- **Java**：不要使用 `i = i++`、`a[i] = i = 2` 这类依赖规范细节的写法；`++`/`--` 单独成句；构造函数里不调用可被子类重写的方法（子类字段尚未初始化时就被调用，这是另一种「顺序陷阱」）。
- **Rust**：多数时候由借用检查器替你守住这条线（同一语句里既可变借用又读取通常编译失败）；用 `let` 分步绑定中间结果，顺序一目了然。
- **Python**：多目标赋值和链式赋值（`a = b = f()`）尽量不要让后面的目标依赖前面的新值；交换用元组 `a, b = b, a`，它先整体算完右边，再赋值。

**什么时候可以违反**：纯函数之间（没有副作用）的顺序无关紧要，不必拆。判断标准是：把子表达式的顺序调换，输出会变吗？不会，就不用管。

**验证手段**：C/C++ 打开 `-Wall`（clang 会警告 `unsequenced modification`）；Go 用 `go vet` 与 `-race`；对依赖顺序的代码，换编译器或优化级别各跑一次测试。
