## Q
Go、Java、Rust、Python 对子表达式求值顺序的保证有什么不同？在实践中各留下了什么陷阱？

## A
| 语言 | 子表达式顺序 | 赋值 `t = v` | 留下的陷阱 |
|---|---|---|---|
| Go | 调用、通信按词法顺序；调用与变量读取之间未规定 | 右边整体先算，再统一赋值 | `[]int{a, f()}` 可能是 `[2 2]` |
| Java | 严格从左到右，先操作数后运算 | 先算目标的数组和下标，再算右边 | `i = i++` 之类的怪异写法 |
| Rust | 从左到右 | 先算右边，再算目标位置 | 与 Java 的赋值顺序相反，来回切换会混淆 |
| Python | 从左到右 | 先算右边，再依次处理目标 | 多目标赋值中后面的目标依赖前面刚赋的值 |

C 和 C++ 作为对照：函数实参的顺序未规定，无序修改同一变量是未定义行为。

规律：**越晚设计的语言，越把顺序写进规范。**C 的规则诞生于编译器技术和机器资源都很吃紧的年代，把自由留给了实现者；Java 为了跨平台可预测，把顺序规定死；Rust 设计时已有足够经验，选择与 Java 相同的从左到右，只在赋值上选了先右后左；Python 的目标是脚本行为可预测，所有规则对读者可见。

Go 的位置有点特殊：它是为服务器并发而设计的，所以对「调用」与「通信」这类有副作用的操作排序，保证 goroutine 间同步语义可预测；而普通变量读取这类无副作用的操作，保留了优化余地。

由此得到的统一实践：**无论语言怎么规定，不要写依赖求值顺序的表达式。**规范的差异只对写编译器和读面试题的人有意义。
