## Q
编译器为什么想要重排子表达式的求值顺序？C 的「未规定」和「未定义行为」在这里有什么区别？

## A
**重排的收益来自寄存器。**CPU 只有十几到几十个寄存器，计算 `(a+b) * ((c+d) * (e+f))` 时，先算较复杂的右半边能让需要同时保存的中间结果更少，不必把值倒腾到内存。这是 Sethi–Ullman 算法的核心思想：为了用最少的寄存器，应当先求值「更费寄存器」的子树。指令调度（让 CPU 流水线不空转）也要重排。

重排只有在**子表达式没有副作用**时才无损。所以语言面临的选择是：要么限制编译器，要么限制程序员。

- **规定顺序**（Java、Rust、Python）：编译器要保证可观察结果等同于从左到右。它仍可在能证明无依赖时重排（as-if 规则：只要可观察行为不变，怎样实现都行），所以对纯计算几乎没有损失。
- **未规定**（unspecified，C 的函数实参）：几种顺序都合法，编译器可以任选，但程序仍有定义：

```c
int n = 0; int next(void) { return ++n; }
printf("%d %d\n", next(), next());   // clang: 1 2   (2 1 is equally legal)
```

- **未定义行为**（undefined behavior，C 的「无序修改」）：对同一变量在两个没有先后关系的位置修改，标准不对程序的任何行为作保证：

```c
int i = 1;
int r = i++ + i++;   // clang -Wall: warning: multiple unsequenced
                     // modifications to 'i'    (here it printed r=3, i=3)
```

区别：「未规定」是几种结果里选一种，每种都是正确程序；「未定义」是整个程序失去意义，优化器可以假设它不会发生，并据此删掉代码。

C++17 补了一批规则（赋值先算右边，`<<` 链从左到右等），但函数实参的相对顺序仍然未规定。

结论：求值顺序的取舍本质上是**谁来承担 as-if 规则的前提**：规定顺序的语言让编译器去证明无依赖；未规定的语言让程序员保证不依赖顺序。
