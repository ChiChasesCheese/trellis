## Q
C++、Go、Java、Rust、Python 的参数传递各属于哪个模型？函数能不能改调用者的变量和对象？

## A
| 语言 | 模型 | 函数能改调用者的对象吗 | 函数能改调用者的变量吗 |
|---|---|---|---|
| C++ | 三种都有：传值（默认拷贝整个对象）、传引用（`T&`、`const T&`，调用点看不出）、移动（`T&&`，转移内容） | 能（`T&`、指针；`const T&` 不能） | 能（`T&` 是调用者变量的别名） |
| Go | 全部传值；切片、map、指针复制的是头或地址 | 能（经指针、切片、map） | 只能经显式的 `*T` |
| Java | 全部传值；对象变量里的值是引用 | 能（引用类型） | 不能 |
| Rust | 移动或借用 | 取决于 `&mut T`；`&T` 不能 | 经 `&mut`（显式） |
| Python | 传共享：绑定同一个对象 | 能（可变对象） | 不能（`nonlocal` 只作用于词法外层，碰不到调用者） |

规律：除了 Rust 和 C++，其余三门语言的「对象」默认可被别处修改，调用点看不出来；Rust 是唯一把可变性和所有权都放进签名、并由编译器证明的。C++ 的 `const T&` 也把「只读」写进了签名，但是只读承诺可被 `const_cast` 绕开，也不保证调用期间别处不改这个对象。

这与各语言的哲学一致。Java 和 Python 追求一种简单的心智模型：所有对象都放在堆上、用引用访问，传参只是复制引用，不必关心谁拥有谁。代价是别名无处不在，一个函数拿到列表就可能改它，调用者要靠文档和惯例。

Go 选择更接近 C 的显式：值就是值，要共享就写指针；但切片和 map 在语法上像值、实质是引用，成了例外，需要单独记住。

C++ 的取向是给你全部三种，并让每种都零开销：值语义是默认，引用避免拷贝，移动避免重复分配；代价是调用者看不出 `f(x)` 里的 `x` 会不会被 `T&` 改掉，也没有东西阻止你把引用存下来比对象活得更久。
Rust 的取向是把别名与可变性当作一个需要证明的性质：同一时刻要么多个只读，要么一个可写。`&T`、`&mut T`、`T` 三种参数写法，就是证明所需要的信息，代价是学习曲线和签名上的负担。

由此得到的经验：**读到函数签名，要能回答「这个函数会不会改我的数据」**。Rust 签名直接回答，Go 要看类型，Java 和 Python 要看实现或文档。
