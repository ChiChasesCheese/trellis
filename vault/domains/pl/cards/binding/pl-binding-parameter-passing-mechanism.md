## Q
在机器层面，「传值」「传引用」「移动」各自复制了什么？大对象按值传参有多贵？

## A
机器层面只有一件事：把若干个字（word，64 位机器上是 8 字节）放进寄存器或栈。不同语义的区别只是**放进去的是数据本身还是它的地址**。

- **传值**：把数据的全部字节复制进去。小类型（整数、指针）只占一个寄存器，几乎免费；大结构体或数组要复制整块内存。
- **传引用 / 指针**：只传一个地址（8 字节），无论目标多大。C++ 的 `int&` 在底层就是一个被自动解引用的指针。
- **Java、Python 的对象参数**：传的是对象的引用（地址），和上一条同样便宜，这就是「传共享」低成本的原因。
- **Rust 的移动**：把值的字节复制到新位置（`memcpy`），然后让旧位置失效。小值与传值相同；`Vec<T>` 的字节只有指针、长度、容量三个字（24 字节），堆上的元素不动，所以移动一个有百万元素的 `Vec` 也只复制 24 字节。

对 Go 做一次基准测试：同一个 800 KB 的数组，按值传参与传指针。

```go
type Big [100000]int
func byVal(b Big) int  { return b[0] }
func byPtr(b *Big) int { return b[0] }
// BenchmarkVal  9266 ns/op     BenchmarkPtr  0.44 ns/op   (one measurement)
```

按值传约 9 微秒，每次调用复制整个数组；传指针不到 1 纳秒。差了约 4 个数量级，而且按值传时被调用者看到的是独立副本，这是用时间换隔离。

这给出两个实用判断：

1. 小类型（不超过两三个字）按值传更好：数据在寄存器里，不用解引用，也不引入别名。
2. 大结构体按引用传以避免复制；但引用意味着别名，需要考虑修改与并发（Rust 靠借用检查，Go 靠约定）。

Go 编译器会通过逃逸分析和内联消除部分复制，但数组按值传参的语义要求「副本独立」，不能随意省掉。
