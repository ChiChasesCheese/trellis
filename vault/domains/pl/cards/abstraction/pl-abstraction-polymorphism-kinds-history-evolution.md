## Q
主流语言的多态机制是怎样演变的？为什么新语言的重心从子类型多态移向了参数多态加 trait？

## A
早期面向对象语言（Simula 1967、Smalltalk、C++、Java 1995）把子类型多态当成唯一的抽象手段：一切复用都靠继承层级。问题在于继承把「复用实现」和「声明可替换性」绑在一起，层级一深就脆弱（见继承一节）。

另一条线来自函数式语言：ML 的参数多态，以及 1989 年 Haskell 的类型类，把「类型能做什么」做成可以事后补充的实现。这条线的收益是：编译期就能确定调用目标，可以内联，可以零成本。

C++ 是个特例，它早在 1998 年就用模板（编译期按类型参数生成代码）把参数多态做进了语言，并在 2020 年用 concepts（显式的类型约束）补上了约束，所以它是「子类型多态为主」的早期语言里最早引入参数多态的一个。后来的语言都在补这一块：

- Java 5（2004）加泛型，用擦除保持向后兼容。
- Rust（1.0 在 2015）以 trait 为核心，没有实现继承。
- Go 在 1.18（2022）补上泛型。
- Python 的类型注解从 3.5 起逐步成熟，3.12 引入 `class Stack[T]` 这种泛型语法。

趋势的原因：大型代码库需要「在不改动旧类型的前提下给它们增加能力」，继承做不到，trait / 接口 / 协议能做到；同时，现代编译器和 CPU 让可内联的静态分派越来越划算。结论不是子类型多态消失了，而是它退到「需要运行期异构」的场景里，不再是默认选项。
