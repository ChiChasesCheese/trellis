## Q
Go、Java、Rust、Python 在「用组合复用行为」上各自怎么做？各有什么得失？

## A
| 语言 | 复用手段 | 买到 | 付出 |
|---|---|---|---|
| Go | 结构体嵌入，编译器生成转发 | 样板少，无脆弱基类，内联布局 | 外层不是子类型；暴露出内层全部公开方法 |
| Java | 手写委托（或继承） | 依赖完全显式 | 转发样板多；无语言支持 |
| Rust | 字段 + 手写转发 + trait 默认方法 | 静态分派，零成本，所有权清晰 | 无自动转发，靠宏生成 |
| Python | 持有对象，`__getattr__` 动态转发，或混入 | 一行代码转发所有属性 | 动态转发对静态检查不透明，容易吞掉拼写错误 |

规律：越是强调「简单」的语言（Go、Rust）越没有继承，但它们对「怎样省掉样板」的回答不同：Go 把它做进语法，Rust 把它留给宏和生态。

Go 的选择反映它的哲学：为最常见的需求（组合加转发）提供最小的语法糖，同时不让它变成继承。Rust 的选择反映它的哲学：语言核心保持小，显式性高于便利，有需要的人用宏。Java 是历史包袱：类库建立在继承上，委托只是好的实践而非语言特性。Python 则按自己的方式：运行期动态，用 `__getattr__` 就能写出透明代理，代价是工具链看不懂。
