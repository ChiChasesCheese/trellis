## Q
Java 和 Python 的继承在运行时各是怎么实现的？方法调用的代价从哪里来？

## A
**Java**：子类对象的内存布局是「父类字段在前，子类字段在后」，所以把子类当父类用时，父类字段的偏移不变，不需要转换。每个类有一张**虚方法表**（virtual method table，`vtable`），是一个函数指针数组；子类的表先复制父类的表，再把被覆写的槽位换成自己的方法。单继承让每个方法在表里的下标固定，调用 `x.sound()` 就是「读对象头里的类指针，取表的第 k 项，跳转」，比直接调用多一次内存读取。

**Python**：对象有一个指向类的引用和自己的属性字典。`obj.hi()` 要沿类的 MRO 逐个查类的字典，找到第一个有 `hi` 的类；每个类的字典是一次哈希查找。CPython 为此做了缓存：解释器对热点调用点记录「这个类、这个版本号」，下次直接命中（3.11 起的自适应特化），所以实际开销远低于「逐层查字典」的字面描述。

**C++** 的布局与 Java 相同（父类部分在前），但虚表是选择加入的：只有声明了 `virtual` 函数的类，对象开头才有一个隐藏的虚表指针；非虚函数是普通的直接调用。多继承时对象里有多个父类子对象，把派生类指针转成第二个基类的指针，编译器要调整地址。
两者的共同点是：继承让**方法的最终目标要到运行期才知道**，编译器无法直接内联。Java 的 JIT 能靠运行期统计（如发现某调用点永远只有一个实现）把这次虚调用重新优化成直接调用，所以通常不是瓶颈；但这也意味着，被覆写的方法越多，调用点越难被优化。多继承再叠加 MRO 顺序，就是 Python 里「读代码时无法一眼看出调用哪个方法」的根源。
