## Q
接口 / trait 机制是怎样演变的？为什么各语言都在向「可以事后补、可以带默认实现」靠拢？

## A
最初的接口（Java 1.0，1995）只是纯签名：类显式声明实现，接口一旦发布就不能改，否则所有实现者都会编译失败。这在大型生态里是严重的演进瓶颈。

之后的演进都在缓解同一个矛盾——**契约要稳定，但又要能扩展**：

- Java 8（2014）：`default` 方法，允许在不破坏旧实现的前提下给接口加方法，`Collection.stream()` 就是这样加入的。
- Go（2009 起）：从一开始就隐式满足，使用方可以自己定义需要的接口。Go 1.18（2022）后接口还可以描述「类型集合」，成为泛型约束。
- Rust（2015）：trait 带默认方法与关联类型，可以事后给已有类型补实现；`async fn` 在 trait 中的用法也在 1.75（2023）稳定。
- Python 3.8（2019）：`Protocol` 把鸭子类型变成静态检查器能理解的形状。

收敛的方向有三点：契约越来越小；越来越少需要类型作者的参与（Go 隐式、Rust 事后补、Python 协议）；越来越多由编译器 / 检查器保证。留下的差异是「满足关系是显式还是隐式」，这个差异不太可能收敛，因为它反映的是工程文化：显式换可查找性，隐式换低耦合。
