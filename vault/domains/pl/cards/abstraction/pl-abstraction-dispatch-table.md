## Q
Go、Java、Rust、Python 的默认方法分派方式各是什么？分别怎样处理「动态分派挡住内联」的问题？

## A
| 语言 | 默认分派 | 怎样变回快路径 | 代价 |
|---|---|---|---|
| Go | 接口调用动态，具体类型调用静态 | 编译器内联和去虚化，可用 PGO（按性能剖析数据优化） | 优化器保守，接口调用通常不内联 |
| Java | 虚调用 / 接口调用 | JIT 内联缓存 + 类层次分析，运行期推测 | 需要预热，类型太杂就退化 |
| Rust | 泛型静态，`dyn` 才动态 | 由程序员选泛型，编译期单态化 | 代码膨胀，编译变慢 |
| Python | 全部按名字动态查找 | 3.11 起自适应特化缓存查找 | 无法内联函数体，上限低 |

规律：**谁来承担「把动态变回静态」的责任**不同。Rust 让程序员在语法层面选，所以运行期没有意外；Java 让运行时去猜，所以写代码轻松但性能依赖运行期的类型分布；Go 取中间，编译期做有限优化，保持简单可预测；Python 的灵活性是它的卖点，因此只能在查找环节做缓存。

背后的哲学：Rust 信奉「抽象不该有隐藏代价」，所以代价必须显式；Java 信奉「平台应该聪明，程序员写自然的代码」，所以把复杂性放进 JVM；Go 信奉「简单可预测」，宁可放弃部分极致优化；Python 信奉「灵活」，把性能留给 C 扩展。
