## Q
资深工程师在各语言里怎样设计公开面？什么该暴露，什么该藏起来？

## A
通用原则：**默认私有，只暴露使用者确实需要的**。一旦公开就成了承诺，撤回的代价远高于新增。公开面越小，库的演进越自由。

- **Java**：字段一律 `private`，通过方法暴露；包内共享的实现细节用包私有；用 `module-info` 只 `exports` 真正的 API 包，实现包不导出。不要为了测试把方法改成 `public`，用包私有加同包测试。
- **Go**：把不想承诺的包放在 `internal/` 下；导出的类型尽量返回具体结构，不暴露内部字段，需要校验时提供构造函数 `NewX`；结构体里不应导出的字段保持小写（并注意序列化会忽略它们，见陷阱）。
- **C++**：数据成员一律 `private`，通过成员函数暴露；`.cpp` 里的辅助函数放进匿名命名空间（只在本文件可见）；对外稳定的库接口用 pimpl 或只暴露抽象基类，避免类的布局进入 ABI（二进制接口约定，布局一变，已编译的调用方就失效）；少用 `friend`，它是点名放行，不是随手开的门。
- **Rust**：默认私有；跨模块共享但不对外的用 `pub(crate)`；结构体字段通常私有，通过构造函数保证不变量；用 `#[non_exhaustive]` 标记以后可能增加字段 / 变体的公开类型，让下游代码不会因新增而编译失败。
- **Python**：下划线前缀标内部；需要校验时用 `property`；`__all__` 列出模块的公开名字；不要滥用双下划线，它只是为了防子类重名。

何时打破：做调试工具、测试辅助、序列化框架时可以用反射或 `_` 属性访问内部，但要限定在少数基础设施代码里，并且注明依赖了哪些内部细节。
