## Q
一个泛型函数 `max<T>` 在编译后要变成真正的机器码或字节码，有哪几种实现策略？它们沿着什么轴取舍？

## A
泛型代码有个根本困难：不同的 `T` 大小和操作都可能不同（`int` 占 4 字节、`String` 是指针、结构体可能占几十字节），一份代码怎么同时处理它们？已知策略有四种：

1. **擦除**（erasure，Java）：运行期只保留一份代码，`T` 被替换成它的上界（通常 `Object`），所有值都按引用处理，需要时插入强转。
2. **单态化**（monomorphization，Rust、C++）：为每种实际用到的 `T` 各生成一份专用代码，就像手写了多个版本。
3. **字典传递 / 部分单态化**（Go）：按内存形状（GC shape）分组生成代码，同形状的类型共用一份，类型相关的操作通过一个隐含参数「字典」查表。
4. **具化**（reification，C#）：运行期保留完整类型信息，由 JIT 在运行时为值类型特化、对引用类型共享。

轴有三条：**运行速度**（单态化最快，因为可内联和按具体类型优化）、**代码体积与编译时间**（单态化最差，实例越多越大）、**运行期类型信息**（擦除最少：`List<String>` 与 `List<Integer>` 运行期是同一个类）。还有一条经常被忽略：**对已有生态的兼容**，Java 选择擦除的主要原因就是让泛型代码与 Java 5 之前的旧库互通。
