## Q
Go 把可见性编码在标识符的首字母大小写里，没有 `public`/`private` 关键字。这个设计反映了什么价值观？

## A
Go 的设计者认为可见性是**使用者最频繁需要知道的信息**，应该在每一个使用处都能看见，而不是藏在定义里。`fmt.Println` 一看就是包外 API，`c.n` 一看就是包内细节。这带来三点好处：

- **读代码时零成本判断**：不需要跳转到定义，也不需要 IDE 悬停。
- **重构时一目了然**：把 `foo` 改成 `Foo` 就是公开它，改名会影响所有使用处，这个代价自然提醒你它是个 API 承诺。
- **没有关键字噪音**：每个字段、方法不用多写一个修饰符。

代价也很明确：只有两级可见性（导出或不导出），没有「只给同包」「只给子类」这样的细分；没有类型私有；大小写与命名风格绑定，不能给导出的名字用小写开头（比如与 C 库对接时有时很别扭）。

Go 接受这些，是因为它的价值观是**用最少的语言机制，让大团队写出风格一致、容易读的代码**。同样的哲学还体现在 `gofmt`（只有一种格式）和没有继承。Java 提供了丰富的修饰符，让作者精确表达意图；Go 提供一个极简的约定，让所有人使用同一种表达。两者针对不同的问题：Java 优先「表达力」，Go 优先「一致性」。
