## Q
`Result` 和 `Option` 这类类型要解决什么问题？它们背后的设计思想是什么？

## A
问题有两个：
1. **缺失值**：很多语言用 `null` 表示「没有」，结果是任何引用都可能是空，编译器不知道，空指针异常成了最常见的运行时错误（发明者 Tony Hoare 称之为「十亿美元的错误」）。
2. **失败结果**：函数返回 -1 或 `null` 表示失败，成功和失败共用一个返回类型，调用者容易把失败当成功用。

思想：**把「可能没有」和「可能失败」放进类型里**，用代数数据类型（algebraic data type，ADT，由「或」组成的类型，也叫和类型 sum type）表示：
- `Option<T>` = `Some(T)` 或 `None`：值可能缺失。
- `Result<T, E>` = `Ok(T)` 或 `Err(E)`：操作可能失败，失败时携带原因 `E`。

这些类型有一个特点：**要拿到里面的 `T`，就必须先处理另一种可能**。编译器强制 `match` 要覆盖所有变体，也就不存在「忘了检查」。也就是常说的「让非法状态无法表示」（make illegal states unrepresentable）。

难点是冗长：如果每次调用后都要 `match`，代码会被淹没。所以这类语言配套了两样东西：
1. **组合器**：`map`、`and_then`、`unwrap_or` 等，把变换链起来。
2. **早返回运算符**：Rust 的 `?`，一个字符展开成「成功就取值，失败就把错误转换后立刻返回」。

设计空间的对照：
- 异常：失败不在类型里，隐式传播。
- Go 的 `(T, error)`：失败在返回值里，但不强制，且两个值同时存在，可以组合出非法状态（既有值又有错误）。
- `Result`：失败在类型里，强制处理，成功与失败互斥。
- C++23 的 `std::expected<T, E>`：同样成功与失败互斥、失败在类型里，用 `transform`、`and_then` 组合；但没有 `?`，也不强制处理（取值 `*r` 不检查状态），强制性靠 `[[nodiscard]]`（丢弃返回值时编译器警告）。
