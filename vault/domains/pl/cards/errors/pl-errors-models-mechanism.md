## Q
异常、错误值和 `Result` 在运行时分别是怎么传播失败的？一次从 `h` 到 `f` 的传播会发生什么？

## A
设想调用链 `f → g → h`，`h` 失败，只有 `f` 知道怎么处理。

**异常**：`h` 执行 `throw`。运行时创建异常对象，通常同时记录当前调用栈（栈追踪，stack trace），然后展开（unwind）：弹出 `h` 的栈帧，在 `g` 的异常表里查找是否有匹配的处理器，没有就继续弹出，直到 `f` 找到匹配的 `catch`。`g` 里没有任何错误处理代码。途中遇到的 `finally` 或析构会被执行。

**错误值（Go）**：`h` 返回 `(0, err)`。`g` 必须写 `if err != nil { return 0, err }` 自己向上传。传播是 `g` 的每一个调用点上的显式代码，控制流永远是普通的函数返回。

**`Result`（Rust）**：`h` 返回枚举 `Err(e)`。`g` 里的 `?` 运算符展开成：「如果是 `Ok(v)` 就取出 `v`，如果是 `Err(e)` 就立刻把 `Err(From::from(e))` 返回」。和 Go 一样是逐层返回，只是样板代码由 `?` 生成，并且类型系统保证你没有漏掉。

**内存与代价**：`Result<T, E>` 是一个带标签的联合体，大小是标签加上较大的那个变体，成功路径不分配。异常的正常路径不执行任何额外指令（表驱动，table-driven），失败路径要建对象、记录栈、逐帧展开，贵得多。错误值的两条路径都是一次普通返回加一个条件分支。

所以，异常是「正常路径便宜，失败路径贵」，值是「两条路径都不贵，但每个调用点都有一个分支和一段样板」。
