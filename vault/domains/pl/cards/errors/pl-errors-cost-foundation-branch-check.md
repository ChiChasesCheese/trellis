## Q
为什么返回值式的错误检查（Go、Rust）在正常路径上几乎没有成本？分支预测是什么？

## A
`if err != nil { return err }` 编译成一次比较加一个条件跳转。现代 CPU 把指令分成很多流水线阶段，提前取下一批指令；遇到条件跳转时，它不等结果，而是**分支预测**（branch prediction）：根据历史猜“跳”还是“不跳”，先沿着猜的方向执行。猜对了几乎不花时间，猜错才要丢弃已执行的指令、重新取指，损失约十几个时钟周期。

错误检查的特点是**几乎总是同一个方向**（99.99% 的调用成功），预测器几乎总猜对，所以正常路径的成本约 0.5 ns 量级。本机测量：Rust 的 `Result` 每次调用约 0.5 ns（含一半调用失败的混合）；Go 返回哨兵错误几乎测不出差别。失败路径也只是一次普通返回，没有额外的分配或栈遍历。

对比异常：`try` 块在正常路径上不执行任何指令（编译器生成静态的异常表）；CPython 3.11 起也是如此，实测有无 `try` 都约 11 ns 每次迭代。

要记住的一个事实：两种机制的正常路径都很便宜，真正的差别在失败路径：异常要建对象、遍历栈，返回值只是返回。
