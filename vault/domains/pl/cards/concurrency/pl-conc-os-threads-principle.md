## Q
什么是操作系统线程（OS thread）的 1:1 模型？语言把用户线程映射到内核线程有哪几种设计，为什么 1:1 最常见？

## A
**线程**是操作系统（OS）能独立调度的最小执行单元：一份寄存器状态加一个栈，同一进程内的线程共享堆和全局数据。语言里的「线程」对象与内核线程之间有三种映射：

1. **1:1**：语言的每个线程对应一个内核线程，调度完全交给内核。
2. **N:1**：许多用户线程挤在一个内核线程上，由运行时自己切换。切换便宜，但只能用一个核，任何阻塞的系统调用都会卡住所有线程。
3. **M:N**：M 个用户线程由运行时复用到 N 个内核线程上，兼得便宜与多核，但运行时要自己做调度器，并处理阻塞调用。

1:1 最常见，是因为实现最简单：创建线程就是调用一次 `pthread_create`，调度、多核、阻塞系统调用、抢占（preemption，内核按时间片强行换下占 CPU 的线程）全都免费得到，还能让线程使用原生库和调试器。代价是每个线程成本较高：内核结构、固定大小的栈、微秒级的切换，所以数量上限是几千到几万。

Java 平台线程、Rust `std::thread`、C++ `std::thread`、Python `threading` 都是 1:1 的 OS 线程；Go 的 goroutine 与 Java 21 的虚拟线程属于 M:N。
