## Q
资深工程师在 Rust、Java、Python、Go 里怎样使用表达式化的结构？通用规则是什么，何时破例？

## A
**通用规则**：
1. **用表达式绑定值，用语句做副作用**：“根据条件算一个值”用表达式；“做一件事”用语句。
2. **让变量不可变**：能用 `let x = if ...`（或 `final var x = switch ...`）就不要“先声明再赋值”。
3. **避免嵌套超过两层**：嵌套的条件表达式或 `match` 抽成命名函数。
4. **让编译器检查穷尽性**，不要用 `default`/`_` 吞掉新增的变体。
5. **一行读得懂**：表达式再短，读不懂也要拆开。

按语言：
- **Rust**：函数最后一个表达式作为返回值，提前返回才写 `return`；`match` 不写 `_ =>` 通配（自己定义的枚举）；链式调用（`map`、`and_then`、`?`）保持在三四环以内；留意函数体最后误加的分号。
- **Java**：新代码用箭头 `switch` 表达式，不再写 `case` 穿透；对密封类型和枚举不写 `default`；三元运算符只用于简单选值，不嵌套。
- **Python**：条件表达式只写简单的一行；复杂逻辑写成函数；推导式嵌套超过两层改写成循环；海象运算符用于“匹配并使用”的场景，不要拿来炫技；`lambda` 超过一个简单表达式就改成 `def`。
- **Go**：接受“先声明变量，再 `if/else` 赋值”的写法；把条件取值逻辑抽成小函数，用早返回；利用 `if v, err := ...; err != nil` 缩小作用域。

**何时破例**：性能热点或需要明确控制求值顺序时，语句更直白；跨语言代码库中，遵守该语言的惯用写法，而不是把一门语言的风格强行搬到另一门。
