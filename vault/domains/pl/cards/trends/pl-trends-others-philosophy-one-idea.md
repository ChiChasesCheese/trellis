## Q
“一门语言的价值来自一个核心想法”这个说法，怎样用 Zig 和 TypeScript 这样两个对立的例子说明？

## A
**Zig：把一切显式化**。核心想法是“**没有任何隐藏**”：函数是否分配内存、控制流是否会跳转、编译期做了什么，都必须在代码里看得见。为此它付出了便利：没有运算符重载，没有 RAII，没有宏，一切要手写。回报是可预测性：读一个函数就知道它会做什么、花多少，不需要查看类型的析构函数或某个宏展开。价值观：**程序员应该完全理解自己的程序**。

**TypeScript：接受现实，渐进改善**。核心想法是“**不要求世界先改变**”。JavaScript 已经有数十亿行代码，不可能重写。所以它的类型系统被设计成可以逐步加入，甚至故意不完全可靠（`any`、类型断言、擦除），因为目标不是证明程序正确，而是让绝大多数 bug 在编辑器里被提前发现。价值观：**实用的改进胜过完美的保证**。

**对比揭示的轴**：
- Zig 在“**控制与可预测**”端：宁可麻烦，也要看得见。
- TypeScript 在“**采纳与兼容**”端：宁可不严格，也要能落地。

**对五门主流语言的映射**：
- Go 接近 Zig 的精神（显式、少魔法），但目标域是服务端应用。
- Python 的类型注解接近 TypeScript 的精神（渐进、可选、工具驱动）。
- Rust 想要“又显式又有强保证”，所以复杂。
- Java 想要“兼容十年前的代码又现代化”，所以特性并存而不整齐。
- C++ 的核心想法是“零开销加控制权”，与 Zig 的“没有隐藏”有重叠，却在隐藏上走了相反的路：RAII（析构函数自动运行）、运算符重载、隐式转换都是为了让抽象好用而允许的“看不见的行为”，所以它是最强大也最难读的一个。

**一个有用的练习**：给任意一门语言写下一句话的核心想法，并用它预测这门语言会拒绝什么特性：Go 拒绝复杂性，Rust 拒绝运行时开销，Python 拒绝仪式，Java 拒绝破坏兼容，Zig 拒绝隐藏。预测与事实往往一致，这就是理解这门语言的证据。
