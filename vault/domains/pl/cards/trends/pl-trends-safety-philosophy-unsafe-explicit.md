## Q
Rust 的 `unsafe` 块被称为“安全的边界声明”。这个设计与 GC 语言的“调用 C”逃生舱相比，反映了什么哲学？

## A
**Rust 的设计：把不安全局限在可审计的、显式的区域**。语言分成两部分：
- **安全 Rust**：编译器保证没有未定义行为。
- **`unsafe` 块**：解除少数几条限制（解引用裸指针、调用不安全函数、访问可变静态变量等），**由写代码的人保证**不变量成立。

关键的惯例是：用 `unsafe` 实现，对外暴露**安全的 API**。标准库里的 `Vec`、`Mutex`、`Rc` 内部都有 `unsafe`，但调用者无法用它们触发未定义行为。于是 `unsafe` 的范围缩小到“少量被仔细审查的基础设施”，大量应用代码完全不写。`grep unsafe` 就能列出所有需要人工审计的位置，工具（如 `cargo geiger`、Miri 解释器）能进一步检查。

**GC 语言的设计：边界在语言之外**。Java、Python、Go 的运行时是用 C/C++ 写的，JVM 与 CPython 自身就有内存漏洞的历史；用户代码的逃生舱是调用 C 库。边界很清楚：进了 JNI 或 `ctypes`，你就在 C 的世界里了，语言不再提供任何帮助。

**哲学上的区别**：
- Rust 说：“危险是有的，但让它**可见、局部、可审计**。”
- GC 语言说：“危险被**关在运行时里**，用户代码一般接触不到；需要时请用另一门语言。”

**揭示的价值观**：Rust 相信**把信任的范围显式化**比假装没有风险更诚实。这也是它的取舍：你必须学会决定“这里需不需要 unsafe”以及“它的不变量是什么”，而 GC 语言的用户把这个决定交给了运行时作者。

**经验法则**：Rust 项目里 `unsafe` 的数量是质量信号之一；每一处都应有注释说明它依赖的不变量，并有测试或 Miri 覆盖。
