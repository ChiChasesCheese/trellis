## Q
Go 的 goroutine 和 Java 21 的虚拟线程（virtual thread）这类轻量线程是什么？它们怎样做到“写同步代码，跑出异步的规模”？

## A
**是什么**：轻量线程（又称用户态线程、绿色线程）由语言运行时而不是操作系统调度。运行时维护少量真正的系统线程（通常等于 CPU 核数），在上面复用海量轻量线程。

**关键机制**：
1. **小而可增长的栈**：goroutine 初始栈约 2 KB，按需增长；虚拟线程的栈保存在堆上，只在运行时才放到系统线程上。创建一个只需几百字节到几 KB，而不是 MB。
2. **阻塞变成挂起**：当轻量线程调用会阻塞的操作（睡眠、网络读、通道接收），运行时把它的栈保存起来，让出系统线程去运行别的轻量线程；操作就绪后再恢复。对用户代码来说，看起来就是一次普通的阻塞调用。

**场景**：同时开十万个各自睡眠一秒的任务。本机真实结果：

| 机制 | 十万个任务 | 说明 |
|---|---|---|
| Java 虚拟线程 | 约 1.5 秒完成 | `newVirtualThreadPerTaskExecutor` |
| Go goroutine | 约 1.1 秒完成 | 栈占用约 205 MB（即每个约 2 KB） |
| Python asyncio 任务 | 约 1.3 秒完成 | 单线程，任务是状态机对象 |
| 系统线程 | 约 4000 个即失败 | 达到本机进程线程上限 |

总时间主要是那 1 秒睡眠加调度开销，说明规模不再受任务数限制。

**与 async/await 的区别**：轻量线程**没有函数染色**。任何普通函数都可以阻塞，运行时负责挂起；你不需要把整个调用链改成 `async`。代价是运行时更复杂（需要抢占或安全点、栈拷贝），以及对本地代码调用或持锁操作可能“钉住”（pin）系统线程。

**要记住的一点**：轻量线程把“线程”这个编程模型保留下来，把成本降下去，是 Java 选择虚拟线程的原因：不让数百万行现有的同步代码重写。
