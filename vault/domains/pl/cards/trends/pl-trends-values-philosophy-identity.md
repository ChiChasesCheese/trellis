## Q
Java 的“对象身份”与 Go/Rust 的“值语义”代表了怎样的设计哲学差异？Valhalla 为什么说是“让代码像类，运行像 int”？

## A
**Java 的出发点：一切是对象，对象有身份**。1995 年的设计目标是让 C++ 程序员摆脱指针和手动内存管理。对象总在堆上、通过引用访问，GC 管理一切。身份带来了方便：同步锁、对象图、共享状态都建立在“这是同一个对象”上。代价是任何数据都至少付出对象头和一次间接寻址。

**Go/Rust/C++ 的出发点：数据就是字节，指针由你决定**。它们继承（C++ 是直接兼容）C 的内存模型，Go 和 Rust 加了安全措施，C++ 没有。结构体是值，复制就是复制字节；共享需要明确地写指针。所以代码里的 `*` 或 `&` 是**可见的成本标记**：看到它，你就知道这里有间接访问、可能的逃逸与共享。

**Valhalla 的目标**是调和两者：Brian Goetz 常把它概括为“让代码像类（codes like a class），运行像 `int`（works like an int）”。值类仍然是类，有字段、方法、接口、泛型，但放弃身份，使 JVM 可以把它扁平存放、按值传递、放进寄存器。同时让泛型可以直接对值类型特化（`List<int>`），不再装箱。

**深层的区别在“身份”这个概念**：
- Java 默认“有身份”，值类是后来的例外，需要显式声明放弃。
- Go/Rust 默认“没有身份”（值），要共享才引入指针（身份的近似物）。

**哲学**：Java 先给抽象，再逐步让出对布局的控制；Go/Rust 先给控制，再通过类型系统和约定提供抽象。这就是为什么 Java 做布局优化需要改 JVM 和语言规范，数年才能落地；而 Go/Rust 的使用者今天就能写。

**对设计的启发**：如果某类对象数量巨大、小、没有可变的共享身份（坐标、金额、时间点），就适合作为值类型；如果它们代表有生命周期的实体（连接、会话、账户），身份是语义的一部分，应当是引用。
