## Q
内存布局的基本概念是什么：缓存行、对齐与填充（padding）、值与引用？一个结构体的字段顺序怎样改变它的大小？

## A
**缓存行**（cache line）：CPU 与内存交换数据的最小单位，常见 64 字节。读一个字节，整条缓存行都会被读进缓存。因此“相邻存放且一起使用”的数据快，“分散存放”的数据慢。

**值与引用**：
- **值**：数据直接放在变量所在的位置（栈上、结构体里、数组里）。一个元素是 `Point{x,y}`，数组里就直接是 x、y 的字节。
- **引用/指针**：变量里放的是地址，数据在别处。数组里是一排地址，每个元素的真实内容分散在堆上。

**对齐与填充**：CPU 访问数据按其自然大小对齐最高效（8 字节整数放在 8 的倍数地址）。编译器在字段之间插入空白（填充）满足对齐。于是**字段顺序会改变结构体大小**：

```go
type Bad  struct { A bool; B int64; C bool }   // 24 bytes
type Good struct { B int64; A bool; C bool }   // 16 bytes
```

真实输出：Go 里 `Bad` 是 24 字节，`Good` 是 16 字节（`Bad` 在 `A` 后补 7 字节、在 `C` 后再补 7 字节）。Rust 的默认布局允许编译器**自动重排字段**，同样内容的结构体只有 16 字节；需要与 C 兼容时写 `#[repr(C)]`，则保持声明顺序，得到 24 字节。

**空位优化**（niche optimization）：Rust 的 `Option<Box<i32>>` 只有 8 字节，因为 `Box` 永远非空，用空指针表示 `None`，不需要额外标志位。

**要记住的一点**：布局不是实现细节，它决定缓存命中率、内存占用与是否能零拷贝地与 C 或网络格式互通。能控制布局的语言（Rust、Go、C）把这种能力交给程序员；不能的语言（Python、Java 对象）把它交给运行时。
