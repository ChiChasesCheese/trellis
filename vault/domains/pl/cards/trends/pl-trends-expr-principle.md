## Q
“表达式化”（expression orientation）是什么意思？语句与表达式的区别为什么重要，语言在这条轴上有哪些位置？

## A
**定义**：**表达式**（expression）求值后产生一个值，可以嵌进别的表达式里；**语句**（statement）只做事（赋值、循环、条件跳转），不产生值，不能嵌进表达式。`1 + 2` 是表达式；`x = 3;` 在 C 家族是语句。

**为什么重要**：值能流动的地方，代码就能**组合**。如果 `if`、`switch`、`try` 是语句，想“根据条件选一个值”就必须先声明一个变量，再在各个分支里赋值：

```
let label;               // declare, uninitialized
if (n > 3) label = "big"; else label = "small";
```

这有三个问题：变量声明与初始化被分开（中间状态可以被误用），可能漏掉某个分支，变量必须是可变的。表达式化的写法 `let label = if n > 3 { "big" } else { "small" }` 一步完成，且不可变。

**设计空间**：
1. **语句为主**（C、C++、Go、早期 Java）：控制流是语句，值通过变量传递。简单、命令式，好懂执行顺序。
2. **一切皆表达式**（Rust、ML、Lisp、Scala、Kotlin 的大部分）：`if`、`match`、块都有值。更易组合，能把意图直接写出来。
3. **混合**：保留语句，但给出表达式版本的关键结构（Java 14 的 `switch` 表达式、Python 的条件表达式、赋值表达式）。

**取舍轴**：组合性与不可变性（表达式）对比执行顺序的直观与学习成本（语句）。

**趋势**：新语言几乎都是表达式导向，老语言在往这一边补。原因是“让编译器知道每个分支都给出了值”能抓住一类 bug，同时让数据流更清晰。
