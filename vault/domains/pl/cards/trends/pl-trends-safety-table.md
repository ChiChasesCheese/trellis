## Q
比较 Go、Java、Rust、Python、C++ 在内存安全上的位置：保证方式、逃生舱和适用场景，各自买到什么，付出什么？

## A
| 语言 | 保证方式 | 逃生舱 | 买到 | 付出 |
|---|---|---|---|---|
| Go | GC 加边界检查；数据竞争不在保证内 | `unsafe`、`cgo` | 简单，服务端够用 | 并发数据竞争可以破坏内存安全；GC 开销 |
| Java | GC 加边界检查；类型安全的字节码验证 | JNI、`Unsafe`、FFM API | 成熟、长期稳定 | 运行时开销；内存余量 |
| Rust | 所有权与借用，编译期证明；无数据竞争 | `unsafe` 块 | 无 GC 的安全，系统级性能 | 学习曲线，编译时间，`unsafe` 需要审计 |
| Python | 解释器管理一切 | `ctypes`、C 扩展 | 极易使用 | 慢；C 扩展里的 bug 仍然致命 |
| C++ | 没有语言级保证；加固标准库（`[]` 边界检查）、sanitizer、静态分析是外挂 | 整门语言：任何一行都可能引入未定义行为（UB） | 零开销与最大的控制权，C 兼容，存量代码和生态最大 | 越界、释放后使用等内存安全漏洞的主要来源；保证全靠纪律和工具 |

**一个重要细节：Go 并不完全“内存安全”**。Go 的 `map`、切片头、接口值在多个 goroutine 竞争读写时，可能产生撕裂的值（例如接口的类型指针与数据指针不匹配），这会让安全保证失效。Go 的内存模型明确说明：存在数据竞争的程序行为未定义（实践中表现为可能崩溃或读到错误数据）。Java 的内存模型则保证即便有数据竞争，也只会读到“某个写入过的值”，不会破坏 JVM 本身。Rust 通过 `Send`/`Sync` 在编译期阻止数据竞争。

**逻辑**：五门语言的分布是安全与性能、简单的三角：C++ 占着“性能与控制”的顶点，把安全放在最后，这是它的出身（C 兼容、零开销原则、信任程序员）决定的，也是整场内存安全运动针对的对象。
- Python 与 Java 选择“一切交给运行时”，用性能和内存换简单。
- Go 选择“够用”的安全，把并发正确性交给程序员与竞争检测器（`go test -race`）。
- Rust 选择把安全做到编译期，用学习成本换无运行时开销。
- C++ 选择不在语言里做，用外挂（加固、sanitizer、模糊测试）逐步收紧，因为存量太大、兼容太重，无法重新设计。

**选择指南**：写新的网络服务、业务系统：任何一个都比 C/C++ 安全得多；写需要 C 级性能、又不能容忍内存漏洞的组件（解析器、驱动、密码库、浏览器引擎）：Rust 是当前最主流的选择。
