## Q
Go 拒绝三元运算符，Rust 却把 `if` 本身变成表达式。这对比怎样揭示两门语言对“可读性”的不同理解？

## A
**两者在回答同一个需求**：“根据条件选一个值”。

**Go 的答案：不提供捷径**。三元运算符的问题是容易嵌套成 `a ? b : c ? d : e` 这种难以阅读的形式。Go 的设计者宁可让这个需求用四行 `if/else` 加一个中间变量来表达，也不引入一个会被滥用的语法。这反映了 Go 的可读性观：**可读性等于一眼能看出每一步在做什么**。多写几行没关系，只要每行都平白。同时，语言里“同一件事只有一种写法”，代码评审时没有风格分歧。

**Rust 的答案：让整个 `if` 都是表达式**。不需要新语法，`if` 本来就产生值，可以写 `let s = if c { a } else { b };`。嵌套的 `if` 与 `match` 也一样合法，可读性的保证来自**类型系统**（所有分支同类型）和**格式化器**（`rustfmt` 统一排版），而不是语法限制。Rust 的可读性观：**可读性等于意图直接可见**。把“选一个值”写成一个值的形式，比“先声明，再分支赋值”更接近意图。

**更深层的差别**：
- Go 把安全放在**简单**上：规则少，所以没有陷阱。
- Rust 把安全放在**检查**上：规则多，但编译器验证你用对了。

**Java 与 Python 是折中**：都保留了三元（`?:`、`x if c else y`），并向表达式一侧扩展。

**对工程的影响**：在 Go 团队里，“没有三元”从来不是争论点，因为答案只有一个；在 Rust 团队里，“这个 `match` 是否太复杂应该拆函数”才是评审话题。选择语言，也是在选择“团队把精力花在哪种争论上”。
