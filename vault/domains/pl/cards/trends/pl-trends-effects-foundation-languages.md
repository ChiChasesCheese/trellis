## Q
Haskell 的 `IO`、OCaml 5 的效应处理器、Koka 的效应类型各自怎样对待效应？它们对 Java 的虚拟线程有什么启发？

## A
三种语言代表了三种不同的立场，都能和主流语言形成对比：

**Haskell：纯与不纯在类型上泾渭分明。**函数类型 `Int -> Int` 保证没有副作用；有副作用的值带 `IO` 标记，如 `readFile :: FilePath -> IO String`。`IO` 值是「描述动作的数据」，要由运行时执行；纯函数不能偷偷调用它。这让编译器可以大胆地重排、缓存、并行化纯代码，代价是所有副作用都要经过 `IO` 的组合，写日志也不例外，需要一套 `Monad` 语法糖（`do` 记法）。惰性求值和纯性是互相依赖的。

**OCaml 5（2022 年底）：效应处理器，但不进类型。**OCaml 5 加入了效应处理器（`Effect` 模块），可以用 `perform` 发出效应，用处理器（`Effect.Deep` 里的函数）处理。OCaml 5 并**不在类型里追踪效应**：函数类型看不出它会执行哪些效应；未被处理的效应在运行时才报错。它的动机是在**不改变现有代码的情况下**支持并发：Eio 等库用效应实现直接风格的 I/O，调度器是一个处理器，每个纤程（fiber）遇到阻塞操作就发出效应让出。

**Koka：效应进类型，且是多态的。**函数类型写成 `(a) -> e b`，`e` 是效应行（如 `<exn, console>`）。纯函数的效应行为空，编译器知道它没有副作用；高阶函数的效应随传入函数变化，不会遇到 Java 受检异常的问题。代价是类型更复杂、生态很小。

对主流语言的启发：

1. **Java 的虚拟线程本身是效应处理器思想的工程版**：JDK 内部有一个一次性的限定续延（`Continuation`）实现，虚拟线程在阻塞调用处挂起（相当于发出「等待」效应），调度器是处理器，等 I/O 完成后恢复。使用者看到的仍然是同步代码，类型里没有颜色。
2. **Python 的生成器和 `async`、JavaScript 的 `async`、Rust 的 `Future`** 都是效应处理的一种受限版本，分别在语法层面支持。
3. 这些做法的取舍与 OCaml 5 相似：效应的**能力**很强，**类型层面的可见性**被牺牲，换来对既有代码的兼容。
