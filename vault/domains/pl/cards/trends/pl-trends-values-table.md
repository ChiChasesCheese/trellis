## Q
比较 Go、Java、Rust、Python 的值类型与布局控制：各自站在哪一点，买到什么，付出什么？

## A
| 语言 | 位置 | 买到 | 付出 |
|---|---|---|---|
| Go | 结构体是值，数组内联；是否指针由你写；字段顺序影响大小，不自动重排 | 可预测的布局，易与 C、二进制格式互通 | 要自己留意填充和逃逸；接口会装箱 |
| Java | 基本类型是值，其余是引用对象；Valhalla 值类仍在孵化 | 简单、GC 管理；对象身份和多态方便 | 对象数组不连续，每个对象有头；紧凑布局要手写原始数组 |
| Rust | 结构体是值；编译器可重排字段，`#[repr(C)]` 固定布局；空位优化 | 布局可控、零成本抽象，与 C 互通精确 | 要理解所有权与布局的关系；泛型实例化增加二进制体积 |
| Python | 一切皆对象；`__slots__`、`array`、NumPy 局部补救 | 极度灵活，使用简单 | 内存大，缓存差；性能依赖 C 扩展 |

**逻辑**：布局控制与语言的“抽象层次”成反比。Python 与 Java 把内存管理和布局交给运行时，换取开发效率和安全；Go 与 Rust 把布局暴露给程序员，换取可预测的性能与互操作。这并非优劣之别，而是选择“谁为布局负责”：运行时，还是你。

**趋势的方向**：
- Java 通过 Valhalla 补上值类，让对象能摊平；
- Python 通过 NumPy、Arrow、Polars 等库，把核心数据放进连续的列式内存；
- Go 与 Rust 本来就在这一侧，更多的工作是工具化（`fieldalignment` 分析器、`cargo` 的布局检查）。

**选语言时的启示**：如果你的系统瓶颈是内存带宽或缓存（数据密集型处理、游戏、高频交易、嵌入式），值类型与布局控制是首要标准；如果瓶颈是 I/O 与业务复杂度，这一项的权重小得多。
