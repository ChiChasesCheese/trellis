## Q
Go 和 Rust 的结构体为什么“天然是值”？`[]P` 与 `[]*P`（`Vec<P>` 与 `Vec<Box<P>>`）有什么区别，什么时候该用哪个？

## A
**结构体是值**：在 Go 和 Rust 里，一个结构体变量就是它字段的字节本身。把结构体放进切片或 `Vec`，元素就**内联**在那块连续内存里；赋值和传参默认是复制（Rust 是移动或复制）。要共享或要引用，需要显式使用指针（`*P`、`&P`、`Box<P>`）。

**两种布局**：
- `[]P` / `Vec<P>`：一块连续内存，每个元素 12 字节（三个 `int32`）。一千万个元素约 120 MB，没有额外的对象头。
- `[]*P` / `Vec<Box<P>>`：连续的是指针（8 字节），每个元素另在堆上分配。内存多出指针数组，每个堆分配还有分配器的开销，遍历要追逐指针。

**一次本机测量**：对一千万个元素顺序求和，Go 的 `[]P` 约 2 ms，`[]*P` 约 2 到 3 ms；Rust 的 `Vec<P>` 约 1.2 ms，`Vec<Box<P>>` 约 2.1 ms，约慢 1.8 倍。这里分配是按顺序做的，堆对象恰好相邻，所以差距被低估；真实程序里对象创建与访问顺序不一致，指针版本更慢。

**什么时候用指针**：
- 需要多处共享同一个数据并看到彼此的修改。
- 结构体很大，复制成本高于间接访问（一般超过几十到上百字节才考虑）。
- 需要表示“可能没有”（Go 的 `nil`）或递归类型（链表、树）。
- 接口里放结构体时要注意装箱。

**Go 的补充**：`[]P` 的元素地址随扩容变化，不要长期保存 `&s[i]`；`for _, p := range s` 里的 `p` 是副本，修改它不会影响切片。

**要记住的一点**：在 Go 与 Rust 里，“值还是引用”由你在类型里写出来，不是运行时替你决定。
