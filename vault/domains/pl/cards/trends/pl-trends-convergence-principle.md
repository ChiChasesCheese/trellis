## Q
为什么 Java、Go、Python 这些出身迥异的语言，近十年在往相似的特性集合上收敛？推动收敛的力量是什么？

## A
**现象**：Java 加入了 `record`、`sealed`、模式匹配和 `var`；Go 加入了泛型和迭代器；Python 加入了类型注解和 `match`。这些特性很多最早来自函数式语言（ML、Haskell）和 Rust。几门语言并没有商量过，却在往同一个方向走。

**四种推动力**：
1. **问题压力相同**：所有人都在写“有多种形态的数据”（订单状态、消息类型、AST）、“对集合做变换”、“大型代码库的可维护性”。老办法（继承加访问者模式、`interface{}`、鸭子类型）在这些问题上有已知的成本，新办法（代数数据类型、泛型、类型注解）在实践中被证明更省力。
2. **跨语言迁移的开发者**：同一批工程师写 Rust、TypeScript、Kotlin，再回到 Java 或 Python 时，会要求同样的表达能力。语言社区是互相可见的。
3. **工具与编译器能力提高**：编译器能做穷尽性检查、类型推断、泛型实例化，让这些特性的实现成本降低。
4. **硬件与负载变化**：多核让不可变数据和值类型更重要，云服务让启动速度、内存占用成为一等指标。

**设计空间（对收敛的态度）**：
- **快速吸收**：看到好用就加（Python、Java 近年）。
- **审慎吸收**：等社区痛到共识，且找到与语言哲学相容的形式（Go 用了十年才加泛型）。
- **先发者**：原本就有（Rust 的枚举与模式匹配从 1.0 就在）。

**取舍轴**：采纳新特性的速度对比语言的内聚性。吸收太快，语言变成特性堆砌（C++ 的批评）；太慢，用户流失到别的语言。
