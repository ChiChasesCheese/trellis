## Q
效应处理器在运行时怎样实现「暂停再恢复」？限定续延（delimited continuation）是什么，为什么说一次性续延就是仿射值？

## A
**续延**（continuation）是「程序接下来要做的事」，把它当作一个值拿在手里。当业务代码执行一个效应操作时，运行时把**从这个操作一直到最近的处理器之间**的那段栈抓住，打包成续延交给处理器，这叫**限定续延**（delimited continuation，只抓到处理器为止，而不是抓整个程序）。处理器拿到后可以：

- 调用它并传入一个值：业务代码从暂停处继续，操作表达式的值就是传入的值；
- 不调用：业务代码被丢弃，相当于异常；
- 保存起来以后再调用：相当于挂起，异步的本质；
- 调用多次：每次从同一点重新继续，可以表达回溯和非确定性。

**实现方式**（以 OCaml 5、Java 虚拟线程为例）：每个纤程（fiber）有一小块**独立分配在堆上的栈**，处理器各自对应一个纤程。执行操作时，当前纤程暂停，控制权切换到处理器所在的纤程（只改栈指针和几个寄存器，不涉及操作系统）；恢复时切回来。创建和切换纤程都只是在用户态分配和换出栈块，比创建和切换系统线程便宜得多，量级上差一到两个数量级。

**为什么限制为一次性。**允许多次恢复，意味着要**复制**暂停点上的整段栈，每个副本继续运行，栈里如果有可变的资源（打开的文件、锁），多个副本会共享并重复释放。OCaml 5、Java 的续延都是**一次性**的：每个续延至多恢复一次。

从子结构类型的角度看，这就是**仿射值**：续延至多被使用一次，用过就作废，不可复制。这个限制与 Rust 的所有权规则同源：禁止复制，才能安全地持有资源。OCaml 在运行时检查「续延已被使用」（再次恢复抛 `Continuation_already_resumed`），Rust 的类型系统会在编译期检查同类问题。允许多次恢复的语言（Koka 的多次恢复、Scheme 的 `call/cc`）更强，但有资源安全的代价。

与其他异步机制对比：

| 机制 | 暂停保存的是 | 谁驱动 |
|---|---|---|
| 协程 / `async`（编译器改写） | 编译成状态机的局部变量 | 执行器 |
| 虚拟线程 / 纤程 | 一块可移动的栈 | 调度器（处理器） |
| 回调 | 手写的闭包 | 事件循环 |
| 系统线程 | 内核管理的栈 | 操作系统 |

这解释了为什么 Java 虚拟线程、Go 协程、OCaml 5 纤程是同一类东西：都是**不染色的、栈式的限定续延**，只是暴露给程序员的接口不同。
