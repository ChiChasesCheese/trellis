## Q
Python 里一切皆对象意味着什么内存成本？`__slots__`、`array` 和 NumPy 各自怎样绕开它？

## A
**一切皆对象**：Python 的整数、浮点数、元组、实例都是堆上的对象，每个至少带引用计数和类型指针。本机一次测量（64 位 CPython 3.14）：

| 对象 | 大小 |
|---|---|
| `int`（小整数） | 28 字节 |
| `float` | 24 字节 |
| 三元素元组 | 72 字节（含三个指针和头，不含元素本身） |
| 普通类实例（三个属性） | 实例 48 字节，加上 `__dict__` 288 字节 |

对比：C 里一个 `int` 是 4 字节。一个 `list` 存的是指针，装着三百万个整数就是三百万个指针加三百万个整数对象，内存和缓存局部性都很差。

**三个绕开办法**：
1. **`__slots__`**：类里声明 `__slots__ = ('x','y','z')`，实例不再有 `__dict__`，同样三个属性的实例只有 56 字节，约省 85%，属性访问也略快。限制是不能随意添加新属性。
2. **`array` 模块**：`array.array('i', range(1000))` 把整数当作 C 的 4 字节 `int` 连续存放，1000 个元素 4000 字节，没有对象头。
3. **NumPy 等数值库**：数组是连续的原始数据块，运算在 C 中完成。这是 Python 在数据科学中能用的根本原因：**用另一门语言的值类型布局，通过 Python 对象来操纵它**。

**要记住的一点**：Python 不是不能控制布局，而是控制布局的事由 C 扩展完成，Python 层只持有它的句柄。这与 Valhalla 对 Java 的意义相同，只是解决方式是“逃到另一门语言”。
