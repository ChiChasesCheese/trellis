## Q
`pickle` 和 serde 代表了序列化的两个哲学极端。「数据就是数据」与「数据可以是程序」的分歧，各反映了语言怎样的价值观？

## A
**`pickle`：数据可以是程序**。Python 的哲学是「方便，一切皆对象」：pickle 能保存几乎任意对象，是因为它让对象通过 `__reduce__` 自己描述怎样重建。这对机器学习尤其方便：一个训练好的模型对象一行保存，一行加载，不用写任何转换代码。代价是 pickle 文件就是一段交给 `loads` 执行的指令序列，信任问题被转嫁给使用者。Python 的立场是：我们都是成年人，你应当只加载自己信任的数据。

**serde：数据只是数据**。Rust 的哲学是「把能力显式化、把权限收窄」：`Deserialize` 的实现由编译期生成，每个类型**只能**从它声明的字段构造，数据无法决定创建什么类型，也没有任何回调会被数据触发。想要多态要显式写枚举（外部标签）。你付出的是：每个要序列化的类型都要 `derive`，不能存函数和任意引用；换来的是：解析不可信输入是安全的操作（不考虑内存和 CPU 的资源耗尽）。

**中间位置**：
- **Java** 的内建序列化接近 pickle（数据指定类，触发回调），所以一再出漏洞；Jackson 的默认行为接近 serde（只绑定声明的类型），但其「多态类型」功能（`enableDefaultTyping`）重新开启了由数据指定类的能力，曾导致大量远程执行漏洞。
- **Go** 的 JSON 只能填入你给的目标结构，数据无法选择类型，天然接近 serde 的安全模型；`gob` 等格式也是如此。

**揭示的价值观**：**可信边界**该画在哪里。Python 画在「使用者的判断」，Rust 画在「类型系统」。当数据来自网络或用户，后者才是工程上可以审计的安全。

**经验法则**：任何会越过信任边界的数据，只用「数据就是数据」的格式。
