## Q
语言设计一个字符串类型时，要回答哪些根本问题？有哪几种设计，沿什么轴取舍？

## A
**要回答的问题**：「一个字符串的长度和下标，到底按什么单位计数？」文本在内存里最终是字节，而人理解的是字符，两者之间隔着编码（encoding）。再加上两个问题：字符串可不可变？拼接的代价由谁承担？

**设计空间（按计数单位分）**：
1. **字节序列**：字符串就是一段字节，长度和下标按字节。Go 的 `string`。简单、快、不丢信息，但「第 3 个字符」要自己解码。
2. **UTF-16 编码单元序列**：每个单元 2 字节，大部分常见字符占一个单元，少数占两个。Java 的 `String`（也是 JavaScript、C# 的选择）。历史原因：Java 诞生时 Unicode 以为 16 位够用。
3. **码点序列**：长度和下标按 Unicode 码点（code point，给每个字符分配的编号）。Python 的 `str`。语义直观，代价是内存布局要灵活。
4. **保证合法 UTF-8，但禁止按下标取字符**：Rust 的 `String`/`&str`。编码正确性由类型保证，把「取第 n 个字符」这个看似简单实则含糊的操作变成显式选择。

**取舍轴**：下标访问的速度与简单对比语义正确性与内存。能 O(1) 取第 n 个单位的设计，那个单位往往不是用户理解的「字符」；以「字符」为单位的设计要么占更多内存，要么下标不再是 O(1)。

另一条轴是可变性：主流语言的字符串都**不可变**，换取线程安全、可作哈希键、可共享，代价是循环里反复拼接会产生大量临时对象。
