## Q
Unicode 的码点（code point）、UTF-8、UTF-16 和字形簇（grapheme cluster）分别是什么？为什么「字符数」没有唯一答案？

## A
**码点**：Unicode 给世界上每个字符分配一个编号，写作 `U+0061`（字母 a）、`U+00E9`（é）、`U+1F600`（😀）。这是抽象的编号，不规定怎样存进内存。

**编码**：把码点序列变成字节的规则。
- **UTF-8**：变长，1 到 4 字节。ASCII 字符占 1 字节，é 占 2，大部分汉字占 3，emoji 占 4。互联网和文件的主流。
- **UTF-16**：每个单元 2 字节；U+FFFF 以上的码点（emoji 等）要用两个单元，叫代理对（surrogate pair）。
- **UTF-32**：每个码点固定 4 字节，下标 O(1)，但最占内存。

**字形簇**：用户眼中的「一个字符」，可能由多个码点组成。例如 é 既可以是一个码点 `U+00E9`，也可以是 `e` 加上组合重音 `U+0301` 两个码点；国旗 🇯🇵 是两个码点；👨‍👩‍👧 是五个码点（三个人加两个零宽连接符）。

**数字**：字符串 `"a😀é"` 的 UTF-8 是 7 字节（1+4+2），码点 3 个，UTF-16 单元 4 个。同一个字符串，字节长度 7，码点数 3，UTF-16 长度 4。在 Python 中，`len("🇯🇵")` 是 2，`len("👨‍👩‍👧")` 是 5，而用户看到的都是 1 个符号。

**规范化**：同一个视觉字符可以有多种码点写法，所以 `"é" == "é"` 在 Python 里是 `False`。比较或去重前要统一成 NFC 或 NFD 形式（Unicode normalization）。

**结论**：「字符」在不同层次有不同答案，语言选择的是**哪一层作为默认的计数单位**。
