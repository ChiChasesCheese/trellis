## Q
同一个小 JSON 对象，Go（反射）、Rust（编译期生成）和 Python（C 加速）解析和输出的速度差多少？差距来自哪里？

## A
**本机一次测量**（同一个 `{"id":12345,"name":"alice","tags":["a","b","c"]}`，每次操作的平均耗时，量级参考）：

| 语言与方式 | 解码 | 编码 |
|---|---|---|
| Rust serde_json（编译期生成） | 约 100 ns | 约 30 ns |
| Go `encoding/json`（反射） | 约 350 ns | 约 140 ns |
| Python `json`（C 加速） | 约 415 ns | 约 570 ns |

**差距来自哪里**：
1. **反射 vs 生成**。Go 每次编码都要通过类型描述找字段、读 tag 的缓存、经接口取值；这些查表和间接调用 Rust 在编译期就展开成直线代码。Go 标准库为此缓存了每个类型的字段信息，所以才比朴素反射快很多，但仍比生成的代码慢约 3 到 5 倍。
2. **分配**。Rust 把字符串借用或一次分配；Go 和 Python 要为每个字符串、切片、字典分配堆对象。Python 的每个值都是一个对象。
3. **对象模型**。Python 的 C 加速模块省去了解释器开销，但生成 `dict`、`list`、`str` 对象本身的成本无法避免。

**什么时候这些差别重要**：服务每秒处理几万个请求、每个请求几 KB 的 JSON 时，序列化常常是 CPU 前几名。Go 社区因此有 `easyjson`、`sonic` 等代码生成或 JIT 方案；Java 的 Jackson 用 `afterburner` 之类的模块把反射换成字节码生成，和 serde 的路线殊途同归。

**反过来的提醒**：在多数业务服务里，序列化比数据库调用和网络小几个数量级，不值得为它换语言。数字是用来判断「这是不是瓶颈」，而不是用来选语言的。
