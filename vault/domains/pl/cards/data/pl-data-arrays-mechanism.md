## Q
Go、Rust、C++、Java、Python 的动态数组各按什么倍率扩容？元素的内存布局不同带来什么性能差别？

## A
**扩容倍率**（本机观察到的容量序列）：

| 语言 | 序列（节选） | 倍率 |
|---|---|---|
| Rust `Vec` | 4、8、16、32、…、1024、2048 | 2 倍 |
| Go 切片 | 4、8、…、512、848、1280、1792、2560 | 先 2 倍，超过约 256 个元素后逐渐降到约 1.25 倍加固定量，并取整到内存分配器的规格 |
| C++ `std::vector`（libc++） | 1、2、4、8、…、1024、2048、4096 | 2 倍；标准只要求均摊常数，倍率由实现定（各实现不同） |
| Java `ArrayList` | 10、15、22、33、49、73 | 1.5 倍，首次添加分配 10 |
| Python `list` | 4、8、16、24、32、40、52、64、76 | 约 1.125 倍 |

倍率越小，浪费的内存越少，复制越频繁。Go 的策略是折中：小的时候激进，大的时候保守，避免一个几百兆的切片翻倍就多占几百兆。

**布局差别（更重要）**：
- Go、Rust、C++ 的 `[]int`、`Vec<i32>`、`std::vector<int>` 是连续的**值**。遍历时 CPU 预取器顺序读，非常快。
- Java 的 `int[]` 同样连续；但 `ArrayList<Integer>` 存引用，每个元素是堆上另一个对象（约 16 字节对象头加值），遍历要指针追逐。
- Python 的 `list` 存 8 字节指针，数字对象各自在堆上。

一个粗略的量级：对一百万个整数求和，连续存放的数组（Go/Rust/Java 原始类型数组）通常是毫秒级，`ArrayList<Integer>` 慢数倍，Python 纯循环慢两个数量级。差距的主要来源不是循环解释的开销，而是内存布局：每个元素多一次间接寻址，缓存利用率差很多。

**结论**：选序列类型时，先问元素是否连续存放，再问增长策略。
