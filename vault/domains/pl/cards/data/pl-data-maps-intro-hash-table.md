## Q
哈希表（hash table）是怎样工作的？哈希函数、冲突、链表法与开放寻址、负载因子分别是什么？

## A
**核心思路**：用一个哈希函数把键映射成一个整数，对数组长度取模得到下标，直接把值放到那个格子里。查找时再算一遍，O(1) 到位，不需要比较整个集合。

**冲突**：两个不同的键可能算出同一个下标，这叫冲突（collision）。两种主流处理：
- **链表法**（chaining）：每个格子挂一条链表，冲突的元素串在一起。查找时先定位格子，再沿链表逐个比较键。Java 的 `HashMap` 属此类。
- **开放寻址**（open addressing）：冲突时按规则在数组里找下一个空位（线性探测、二次探测等）。元素都在同一块连续内存里，对 CPU 缓存友好。Go、Rust 和 Python 的实现都属此类。

**负载因子**（load factor）：元素数除以格子数。太满则冲突增多、查找变慢，所以超过阈值（Java 默认 0.75）就扩容：新建一个更大的数组，把每个元素重新算位置放入（rehash）。扩容的代价是一次 O(n)，摊销到每次插入仍是 O(1)，原理与动态数组相同。

**契约**：哈希表的正确性依赖两个函数一致：**相等的键必须有相同的哈希**。违反的话，同一个键在存与取时会落到不同位置，找不到。这就是 Java 要同时重写 `hashCode` 和 `equals`、Python 要求键可哈希、Rust 要求 `Hash + Eq` 的原因。

**场景**：一百万个整数键插入哈希表，平均每次插入、查找都只做常数次比较；同样用有序树则每次要约 20 次比较（log₂ 一百万）。

**要记住的一点**：哈希表的遍历顺序取决于哈希值和数组布局，不是插入顺序，也不是键的大小顺序，除非实现特意额外记录。
