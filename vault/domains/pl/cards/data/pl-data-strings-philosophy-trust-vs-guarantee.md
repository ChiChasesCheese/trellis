## Q
Go 与 Rust 的字符串都以 UTF-8 为中心，却一个「信任」一个「保证」。这个差别揭示了两门语言怎样的价值观？

## A
**Go：信任约定，不做强制**。`string` 就是字节，源码是 UTF-8 所以字符串通常是 UTF-8，但类型不检查。非法字节原样通过，`range` 遇到它给出替换字符 `U+FFFD`，而不是失败。这符合 Go 的务实风格：服务器要处理的常常是来自网络、文件、数据库的脏数据，让程序能继续运行比拒绝更重要；而且字符串到字节的转换是零成本，没有验证开销。代价是由程序员记得在边界处检查，忘了就让脏数据一路流到下游。

**Rust：用类型保证不变量**。`&str` 的合法性在构造时验证一次（`from_utf8` 返回 `Result`），之后整条调用链都可以放心。字符串切片落在字符中间会 panic，因为那会破坏不变量。这符合 Rust 的信条：把检查移到边界，让内部代码不必防御。代价是你必须在边界处处理 `Result`；处理操作系统路径、文件名这类不保证 UTF-8 的数据时，还要引入另外的类型（`OsString`、`Path`），而不是用 `String` 将就。

**最尖锐的对比**：同一份来自网络的脏字节，Go 让它进入程序并继续跑，Rust 要求你在入口处决定怎么办（拒绝、替换、保留为字节）。

**Python 3 的立场介于两者之间但更激进**：`bytes` 与 `str` 是两个互不兼容的类型，边界处必须显式编解码，等价于 Rust 的边界思路，只是错误在运行时抛出。

**选择指南**：处理管道、代理、日志转发这类「只搬运不解释」的程序，Go 的模型省事；处理需要正确性（解析、校验、国际化）的程序，Rust 的模型能早发现问题。
