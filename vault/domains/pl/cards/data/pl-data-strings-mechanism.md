## Q
字符串不可变时，在循环里反复 `+=` 拼接为什么慢？Java、Go、Python 各慢多少，Rust 为什么没有这个问题？

## A
**原因**：不可变意味着每次 `r += "x"` 都要分配一个新字符串，把旧内容整个复制过去再追加。拼接 n 次的总复制量是 1+2+…+n，也就是 O(n²)。长度 5 万的字符串，就是约 12.5 亿字节的复制。

**解法**：用可变的缓冲区累积，最后一次性转成字符串。Java 的 `StringBuilder`，Go 的 `strings.Builder`，Python 的 `"".join(parts)`，Rust 的 `String` 本身就是可变的，`push_str` 摊销 O(1)。

本机一次测量，拼接 5 万个 `"x"`：

| 语言 | 循环 `+=` | 缓冲区 |
|---|---|---|
| Java | 约 43 ms | 约 0 ms（低于 1 ms） |
| Go | 约 71 ms | 约 74 微秒 |
| Python | 约 12.6 ms | `join` 更快 |

**Python 的例外**：CPython 对 `r += "x"` 有一个实现层面的优化：当 `r` 的引用计数为 1 时，原地扩容而不复制，所以实测并不是平方级。这个行为是 CPython 的实现细节，不是语言保证；在 PyPy 或字符串被别处引用时就不成立，所以不应依赖。

**Java 的补充**：JDK 9 起编译器把 `a + b + c` 这种单个表达式编译成 `invokedynamic`，运行时选最优的拼接策略，所以单个表达式里的 `+` 没问题；问题只出在**循环里累积**。

**结论**：不可变字符串让共享和线程安全变得简单；累积场景必须显式使用构建器，这是语言用 API 形状提醒你成本。
