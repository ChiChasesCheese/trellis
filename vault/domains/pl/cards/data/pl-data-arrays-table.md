## Q
比较 Go、Java、Rust、Python、C++ 的序列类型设计：各把数组、动态数组、切片怎样组合，买到什么，付出什么？

## A
| 语言 | 设计 | 买到 | 付出 |
|---|---|---|---|
| Go | 数组是值；`[]T` 同时是视图和可增长序列 | 类型少，传子区间零复制，写起来轻 | 别名由容量决定，`append` 会静默共享或不共享 |
| Java | 定长数组 + 库类 `ArrayList`，无视图类型 | 容易理解，`List` 接口统一多种实现 | 对象列表要装箱，切片要复制，数组协变有运行时检查 |
| Rust | `[T;N]`、`Vec<T>`、`&[T]` 三类分开 | 所有权清晰，别名错误在编译期消失 | 概念多，要在类型之间转换，要和借用检查器协作 |
| Python | 只有存指针的 `list`，切片是复制 | 异构、灵活，语义简单（赋值就是绑定） | 内存和速度成本高，浅拷贝陷阱 |
| C++ | `T[N]`/`std::array`（定长）、`std::vector`（动态，拥有数据）、`std::span`（C++20，非拥有视图），三类分开 | 值语义、连续存放、视图零复制；和 Rust 同构 | 没有借用检查：`push_back` 扩容让旧引用悬空；`[]` 越界是未定义行为（UB），要边界检查须用 `.at()` |

**逻辑**：这张表的本质是「谁承担别名的复杂度」。Go 追求最少的类型，把复杂度推给运行期的程序员（需要记得容量）。Rust 追求在编译期证明安全，把复杂度推给类型系统和学习曲线。Java 与 Python 通过**不提供视图**（或视图返回复制）来回避别名：要么每次都复制，要么用不可变包装；代价是性能。三种答案是同一个难题的三种成本分配：运行期风险、编译期复杂度、复制开销。

Go 的设计者为切片选了第一种，是因为他们认为系统编程需要零复制的子区间，而新手也不应被类型数量吓到。

C++ 的拆分与 Rust 一样（拥有的 `vector`、借用的 `span`），区别只在没有编译期检查。零开销原则决定了 `vector` 就是一块裸内存，没有任何追踪；手动控制决定了责任在你。同一个错误，Rust 是编译错误 `E0502`，C++ 是：

```cpp
std::vector<int> v = {1, 2, 3};
int& first = v[0];
v.push_back(4);              // may reallocate
std::printf("%d\n", first);  // dangling reference
```

`-Wall -Wextra` 零警告，加 `-fsanitize=address` 运行报 `heap-use-after-free`。这类错误在 C++ 里叫迭代器（或引用）失效。
