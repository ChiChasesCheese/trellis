## Q
序列化格式的几个基本概念是什么：文本与二进制、自描述与 schema、往返（round-trip）与兼容性？它们怎样影响选择？

## A
**文本格式 vs 二进制格式**：
- 文本（JSON、YAML、TOML）：人能读，工具多，体积大，数字要解析。
- 二进制（Protocol Buffers、MessagePack、Java 序列化）：紧凑，解析快，人不能直接读。

**自描述 vs 依赖 schema**：JSON 的每个值旁边都带字段名，读者不需要提前知道结构。Protocol Buffers 只存字段编号和值，读者必须有 `.proto` 才能解释。前者灵活，后者小、快、易于校验。

**往返**：把对象序列化再反序列化，应当得到等价的对象。往返会在这些地方出问题：
- 类型丢失：JSON 没有整数与浮点之分，所有数字都是「数」；很多解析器把它读成 64 位浮点，超过 2⁵³ 的整数会丢精度。
- 键类型：JSON 的键必须是字符串，Python 的整数键往返后变成字符串键。
- 没有的概念：集合、日期、二进制数据，JSON 都没有原生类型。

**兼容性与演进**：数据格式一旦存在于别人的磁盘或网络上，就不能随便改。新增字段、删除字段、改类型，旧读者和新读者都要能处理。好的格式让「忽略未知字段」成为默认或可选行为，并支持字段默认值。

**安全边界**：反序列化把外部输入变成程序内的对象。如果格式允许输入指定要创建的类型（类名），攻击者就能让你的进程创建任意类的对象；如果这些类的构造或回调里有副作用，就等于远程执行代码。这是 Java 序列化和 Python `pickle` 反复出安全事故的根源。

**一个选择规则**：对外的接口用与语言无关、显式 schema 的格式；进程内缓存或测试夹具才考虑语言绑定格式。
