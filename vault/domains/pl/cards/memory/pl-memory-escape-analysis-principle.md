## Q
逃逸分析（escape analysis）是什么？它要解决 GC 语言的什么问题，设计空间里还有哪些做法？

## A
在 GC 语言里，程序员写 `new Point(1, 2)` 或 `&P{1, 2}`，按字面意思对象要放在堆上，之后由 GC 回收。但绝大多数这类对象只在一个函数内部用一下就没人要了，如果每个都走堆分配，分配器和 GC 的压力会很大。

逃逸分析让编译器（或 JIT）自己判断：这个对象的引用会不会「逃出」创建它的函数？
- **不逃逸**：引用只在函数内使用，函数返回后没人再能访问它。这种对象可以直接放在栈帧里，函数返回时随栈帧自动消失，不需要分配器，也不需要 GC。
- **逃逸**：引用被返回、存进堆上的对象或全局变量、传给无法分析的代码、被另一个线程捕获。这种对象必须在堆上。

判断依据是保守的：只要无法证明不逃逸，就当作逃逸。

设计空间：
1. **程序员显式决定**（C、C++、Rust）：想放栈就写局部变量，想放堆就写 `Box`。可控但要负责。
2. **语言规定对象全在堆上**（早期 Java、Python）：简单，靠 GC 或引用计数兜底，性能靠 GC 的效率。
3. **编译器或 JIT 优化**（Go、现代 Java）：语义上都是堆对象，实现上能放栈就放栈。程序员不需要改代码，但也看不到、保证不了结果。

逃逸分析的价值是把「语义简单」与「性能接近手动管理」连起来：它不改变程序行为，只改变对象放在哪里。
