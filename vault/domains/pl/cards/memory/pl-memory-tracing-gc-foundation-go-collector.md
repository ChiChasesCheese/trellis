## Q
Go 的垃圾回收器是什么样的？`GOGC` 怎么决定回收频率，`gctrace` 日志怎么读？

## A
Go 只有一个回收器：**并发的三色标记-清除**，既**不分代**也**不移动对象**。标记阶段与程序并发运行，只在开始与结束时各有一次极短的停止世界（通常几十微秒到亚毫秒）。因为对象不移动，一个对象的地址一经分配就不变，指针可以放心传给 C 代码；碎片靠分配器按大小分级（同一类大小的对象放在一起）来控制。

回收频率由环境变量 `GOGC`（默认 100）控制：下一次回收的目标是上次**存活数据量**的 (1 + GOGC/100) 倍，即存活 10 MB，堆长到约 20 MB 时再回收；下限约 4 MB。要限制总内存，设 `GOMEMLIMIT`（软上限）。

运行 `GODEBUG=gctrace=1` 会为每次回收打印一行（本机实测之一）：

```console
gc 3 @0.007s 3%: 0.020+0.14+0.007 ms clock, ... 3->3->1 MB, 4 MB goal, ... 12 P
```

读法：第 3 次回收，程序启动后 7 ms，GC 占用约 3% 的 CPU；三个时间依次是开头暂停、并发标记、结尾暂停（0.020 与 0.007 ms 就是两次暂停）；`3->3->1 MB` 是回收开始、标记结束、存活的堆大小；`4 MB goal` 是目标堆大小。

要记住的一个事实：Go 把简单和低暂停放在首位，用很少的旋钮（`GOGC`、`GOMEMLIMIT`）换取可预期的行为，不提供分代和多种回收器可选。
