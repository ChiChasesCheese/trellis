## Q
Java 的 G1 和 ZGC 是什么？它们各自怎样回收，该怎么选？

## A
Java 虚拟机（JVM）内置多个可替换的回收器，用启动参数选择（如 `-XX:+UseG1GC`、`-XX:+UseZGC`）。常见的三种：

- **Parallel**：停止世界，但回收时用多个线程并行，吞吐最高，暂停和堆大小相关。适合离线批处理。
- **G1**（Garbage-First，现在的默认）：把堆切成许多等大的小块（region，如 1 到 32 MB）。每块可以是年轻代或老年代。回收时选“垃圾最多、最划算”的若干块，把存活对象复制到空块（所以顺带整理了内存），并发标记，每次暂停只处理一部分块，目标暂停时间可设定（默认约 200 ms 量级的目标，实际通常更短）。适合通用服务。
- **ZGC**：目标是暂停亚毫秒级，且不随堆大小变化。关键技巧：并发完成标记**和对象移动**；做法是指针里带几位元数据（着色指针，colored pointer），程序线程读引用时检查一下（读屏障 load barrier），发现对象已被搬走就自动转发到新位置。JDK 21 起支持分代，之后分代成为唯一模式。代价：吞吐略低、CPU 开销更高、需要堆里留出余量。

怎么选：先用默认的 G1；对尾延迟敏感的在线服务试 ZGC；离线批处理可用 Parallel。用 `-Xlog:gc` 看日志决定，不要凭感觉。

要记住的一个事实：Java 不是“一个 GC”，而是一族回收器，在吞吐、暂停、内存开销之间让用户选点。
