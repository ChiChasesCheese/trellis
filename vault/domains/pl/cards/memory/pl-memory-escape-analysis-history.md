## Q
逃逸分析是什么时候出现的，Java 和 Go 各自怎样采用，下一步往哪里发展？

## A
1. **1999 年前后**：逃逸分析作为静态分析技术在学术界被系统提出，其中就有针对 Java 的 OOPSLA 论文（Choi 等人），目标是对象栈分配和消除同步。
2. **Java**：HotSpot 的 C2 编译器在 JDK 6 时期加入，之后成为默认开启的优化，主要产出是标量替换和锁消除（不逃逸的对象上的 `synchronized` 可以去掉）。
3. **Go**：从一开始就依赖编译期逃逸分析，因为语言里没有栈和堆的区别；后来分析器被重写过，精度和可读的诊断输出逐步改善。
4. **Java 的局限与改进**：HotSpot 的分析是「全有或全无」：对象在任何一条路径上逃逸，就整体当作逃逸。GraalVM 的编译器实现了部分逃逸分析（partial escape analysis），只在逃逸的分支才真正创建对象。

趋势：
- 与其让编译器猜，不如让语言本身表达「这不是一个有身份的对象」。Java 的 Valhalla 项目引入值类（value class），没有对象身份，可以直接内联存放，不必依赖逃逸分析。
- 编译器与运行时的分析越来越多地用在跨语言边界之外：减少分配、消除装箱、锁消除，这些工作最终都是为了把「语义上的堆对象」变成「实现上的寄存器值」。
