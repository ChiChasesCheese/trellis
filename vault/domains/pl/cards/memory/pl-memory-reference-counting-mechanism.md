## Q
CPython 的引用计数在底层怎么工作？循环垃圾检测器又是怎么找出孤立的环的？

## A
CPython 里每个对象的头部都有一个计数字段 `ob_refcnt`。绑定一个名字、放进列表、作为参数传入，都会 `Py_INCREF`（加 1）；名字重新绑定、`del`、容器销毁、函数返回，都会 `Py_DECREF`（减 1）；减到 0 就立即调用对象的销毁函数，销毁时再对它引用的对象 `DECREF`，形成级联释放。

小轨迹：`a = Node()` 计数 1；`b = a` 变 2；`del b` 变 1；`del a` 变 0，立刻释放。

循环检测只针对**容器对象**（列表、字典、实例等，因为只有它们才可能成环）。它们被 GC 链表串起来，周期性运行，每次大致这样：
1. 对每个容器对象，先复制出一份计数 `gc_refs = ob_refcnt`。
2. 遍历容器内部的每个引用，对被引用的容器 `gc_refs -= 1`，扣除「来自容器内部」的引用。
3. 扣完后 `gc_refs` 仍大于 0 的对象，说明有来自外部（栈、全局）的引用，是根；从它们出发标记所有可达对象。
4. 其余没被标记到的就是孤立的环，统一销毁。

触发条件：按「分配减去释放」的次数超过阈值，分三代，越老的代越少扫描。可以用 `gc.collect()` 手动触发，`gc.disable()` 关闭。

Rust 的 `Rc<T>` 把两个计数放在堆上的控制块里：强计数（strong）决定值何时 `drop`，弱计数（weak）决定控制块何时释放。强计数归零时值就被销毁，哪怕仍有 `Weak`。
