## Q
引用计数（reference counting）是怎样的回收思路？它相对追踪式 GC 的优缺点是什么，设计空间里有哪些变体？

## A
思路：每个对象自带一个整数，记录「现在有多少个引用指向我」。新增一个引用就加 1，删除一个引用就减 1，减到 0 的瞬间，对象立即被释放，并对它引用的其他对象继续减计数。

优点：
1. **即时**：垃圾一产生就回收，内存占用平稳，没有 GC 暂停。
2. **确定**：知道对象会在哪一行代码销毁，所以文件、锁等资源也可以放在对象里。
3. **局部**：不需要扫描整个堆，成本和程序实际的引用操作成正比。

缺点：
1. **循环引用**：A 引用 B，B 引用 A，两者计数都是 1，即使没人从外部引用，也永远不归零，泄漏。
2. **更新开销**：每次赋值、传参、离开作用域都要改计数，是对内存的写；多线程共享时还要用原子指令。
3. **级联释放**：释放一个大结构时可能连续释放成千上万个对象，产生不可预期的停顿。

变体：
- 计数是否原子：单线程用普通加减（便宜），多线程共享用原子操作（贵）。
- 强/弱引用（strong/weak）：弱引用不加计数，用来表示「父指针」「观察者」这类不应延长生命周期的关系，打破循环。
- 辅以循环检测：对可能成环的容器对象周期性做一次追踪，找出孤立的环。
- 由编译器自动插入加减（Swift、Objective-C 的 ARC），或由库手动封装（Rust 的 `Rc`、C++ 的 `shared_ptr`）。
