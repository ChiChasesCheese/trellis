## Q
程序里的值要放在内存的哪里？栈（stack）和堆（heap）各解决什么问题，语言设计者有哪几种做法？

## A
每个值都要占一块内存，难点在于它能活多久。函数的局部变量只活到函数返回；而一个链表节点、一个缓存条目可能比创建它的函数活得久得多。一套机制无法同时便宜又灵活，所以运行时把内存分成两类区域。

**栈**：按函数调用先进后出地划出一块块栈帧（stack frame），函数返回时整块一起丢掉。分配和释放只是移动一个指针，几乎免费，但值的生命周期必须和调用嵌套一致，大小也要在编译期已知。

**堆**：由分配器（allocator）按需切出任意大小的内存块，值可以活到任何时候，代价是要找空闲块、要有人决定何时释放，访问还多一次指针跳转。

设计空间有三个维度：
1. 谁决定放哪：程序员显式选（C、C++ 的 `new`、Rust 的 `Box`）、编译器自动判断（Go 的逃逸分析）、语言规定死（Python 所有对象在堆上）。
2. 谁回收堆：人手动、作用域结束自动（RAII）、垃圾回收（GC）、引用计数。
3. 栈是否可增长：固定大小的栈会溢出，可增长的栈则把成本转给运行时。

后面每种内存管理方式，本质上都是对「堆上的东西谁来释放」这个问题的一种回答。
