## Q
真正的线性类型存在于哪些语言里？它们和 Rust 的所有权相比，换来了什么、付出了什么？

## A
严格的线性类型（每个值恰好用一次）主要出现在研究型和小众语言里，近年开始渗入主流：

- **Linear Haskell**（GHC 9.0 起的 `LinearTypes` 扩展）：函数类型可以写成线性箭头 `a %1 -> b`，表示「恰好消耗一次参数」。它和普通 Haskell 共存，只在需要的函数上声明线性。
- **Idris 2**：基于「数量类型论」（quantitative type theory），每个变量带一个数量：0（只在类型层面出现）、1（恰好一次）、无限。
- **Clean**：用**唯一性类型**（uniqueness types）保证一个值只有一个引用，因此可以安全地原地更新，用来在纯函数式语言里做 I/O。
- **Swift 5.9 的 `~Copyable`**：不可复制类型，默认只能移动，类似 Rust 的非 `Copy` 类型；编译器检查使用后不可再用。
- **ATS、Austral** 等语言：为系统编程设计的线性类型。

对比 Rust 的仿射：

| | 线性（恰好一次） | 仿射（至多一次） |
|---|---|---|
| 值可以被忽略吗 | 不行，必须显式消耗 | 可以，离开作用域自动清理 |
| 能保证资源一定被处理吗 | 能（连 `forget` 都不允许） | 不能（可泄漏） |
| 代价 | 每条路径（错误、提前返回）都要显式消耗，样板多 | 简单，但保证较弱 |

线性类型换来的是**强保证**：文件一定会被关闭、事务一定会被提交或回滚、令牌一定会被归还。在安全关键或需要证明资源协议的场合很有价值。

付出的代价：

1. **人体工学**：与异常、提前返回、循环等控制流交互复杂；语言需要大量辅助设施（比如 Linear Haskell 里连库函数都要提供线性版本）。
2. **和现有生态兼容**：现有代码都是无限制的，线性函数调用普通函数很不方便，混用时规则繁琐。
3. **泛型与线性**：容器、迭代器、闭包要区分线性与否，类型签名翻倍。

这也解释了主流语言的路线：Rust 取仿射加 `Drop`（够用且简单），Swift 逐步增加不可复制类型，Java、Go、Python 干脆不碰，靠 `try-with-resources`、`defer`、`with` 这类约定式的清理。

要记住：线性类型是子结构类型光谱中保证最强的一端，代价是语言实现与使用的复杂度，目前的主流选择是「仿射加自动清理」。
