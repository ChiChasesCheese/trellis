## Q
从 C 到 Java、Go、Rust，「值放栈还是放堆」这个问题的答案是怎么演变的？

## A
这是一条由放权到收回的曲线。

1. **C**：程序员完全负责。局部变量在栈，`malloc` 的在堆，忘记 `free` 就泄漏，多 `free` 一次就崩溃。
2. **C++（1980 年代起）**：沿用 C 的模型，局部变量在栈、`new` 在堆，并用析构函数（RAII）让堆内存在作用域结束时自动释放；这是 Rust「默认栈、显式堆、作用域结束释放」的直接前身。
3. **Java、Python 一代（1990 年代）**：为了消灭手动释放，语言规定对象一律在堆上，由 GC 或引用计数回收。程序员省心，代价是每个小对象都要走分配器、多一层指针，缓存局部性变差。
4. **逃逸分析一代（2000 年代起）**：既然语言不让程序员选，就让编译器替他选。Java 的 JIT 在运行时分析对象是否逃出方法，没逃出就拆成标量放寄存器或栈；Go 从一开始就在编译期做逃逸分析，所以 Go 的语法里没有栈/堆之分。
5. **Rust（2015 年 1.0）**：回到「默认栈、显式堆」，同时用所有权规则保证堆内存在作用域结束时被释放，不需要 GC。

当前趋势是：托管语言在补「小而短命的值不要进堆」（Java 的 Valhalla 值类型就是为此），系统语言在补「堆的释放别让人操心」。两边在向中间靠拢。
