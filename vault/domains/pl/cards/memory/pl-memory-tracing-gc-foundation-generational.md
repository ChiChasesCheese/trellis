## Q
复制式回收（copying）、整理（compact）和分代假说（generational hypothesis）分别是什么？为什么按年龄分区能让 GC 变便宜？

## A
**复制式回收**：把堆分成两块区域。分配只往其中一块里连续地放；回收时，把从根可达的对象复制到另一块的开头，然后整块丢弃旧区域。好处：没有碎片，分配只需把指针往后移（几条指令）；成本只和**存活对象**成正比，垃圾不用碰。代价：对象的地址会变，运行时必须能改写所有指向它的引用，而且要预留空间。**整理**（compact）是类似的思路：标记之后把存活对象滑到堆的一端。

**弱分代假说**：经验观察——绝大多数对象朝生夕死（循环里的临时字符串、请求对象），活下来的少数则往往活很久。

于是堆被分成**年轻代**（young）和**老年代**（old）：新对象都在年轻代；年轻代很小，经常回收，且其中绝大部分已经是垃圾，复制存活的一点点对象很便宜；熬过几次回收的对象“晋升”到老年代，老年代很少回收。

一个数字例子（Java G1 一次实测）：程序分配约 200 MB 的短命数组，每次年轻代回收只需复制约 1 MB 存活对象，暂停约 0.1 ms：

```console
GC(5) Pause Young (Normal) (G1 Evacuation Pause) 22M->1M(37M) 0.121ms
```

`22M->1M(37M)` 表示回收前占用 22 MB、回收后 1 MB、当前堆容量 37 MB。

要记住的一个事实：分代把“经常回收的小区域”和“很少回收的大区域”分开，代价是需要跟踪老年代指向年轻代的引用（见写屏障）。
