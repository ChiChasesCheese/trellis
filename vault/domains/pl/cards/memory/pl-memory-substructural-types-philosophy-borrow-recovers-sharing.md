## Q
如果非 `Copy` 的值只能用一次，Rust 为什么还能写出自然的代码？借用（`&T`、`&mut T`）在子结构类型的角度是什么？

## A
纯粹的仿射类型很难用：每次把值传给函数，值就没了，你得让函数把它再还回来。如果 Rust 只有「移动」，读一个 `Vec` 的长度都要写 `let (n, v) = len(v);`。

**借用**就是为此设计的逃生通道：它在**不转移所有权**的前提下，临时恢复了被拿掉的两条规则。

- **`&T`（共享借用）恢复了复制**：`&T` 是 `Copy` 的，可以随意复制出许多份，同时存在，所有人只读。复制是安全的，因为没人能写。这就是收缩律在读场景下被安全地放回来了。
- **`&mut T`（独占借用）仍是仿射的**：它不能复制，只能移动或「重借」（reborrow，在较短的时间内再借出去，借完原来的独占借用恢复可用）。同一时刻最多一个写者。
- **同一个值的借用不能同时有读者和写者**：读者与写者互相排斥，这是借用检查器的规则。

这个设计的深层含义是：**别名（多个引用）与可变性（修改）不能同时存在**。该约束与子结构类型同源：复制一个可写的引用，就违反了「至多一次」。

它直接造就了 Rust 的两个招牌能力：

1. **没有数据竞争**：数据竞争需要「两个线程同时访问、至少一个写」，恰好是借用检查器禁止的组合（`Send`/`Sync` 把这一点扩展到跨线程）。
2. **迭代器失效在编译期消失**：遍历集合时同时修改集合，Java 在运行时抛 `ConcurrentModificationException`，Rust 里 `for x in &v { v.push(…) }` 根本编译不过，因为 `&v` 的共享借用还活着。

代价是借用检查器会拒绝一些其实安全的程序（比如同时借用结构体的两个不同字段通过方法，编译器看不出它们不相交），迫使你调整数据结构或使用内部可变性（`RefCell`）。

要记住的关键：**所有权规则很严，是为了让借用可以很宽。**移动给出唯一的责任人，借用在其之上允许安全的临时共享。
