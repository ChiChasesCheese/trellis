## Q
Rust 的移动语义（move semantics）和 Java、Python 的引用赋值相比，独特在哪里？它换来了什么？

## A
`let b = a;` 在三门语言里机器层面的动作相似，都只复制几个字节（指针或 `Vec` 的三字段头），不复制堆上的数据。差别在这之后：

- Java、Python：`a` 和 `b` 都继续有效，指向同一个对象，成了两个可写别名。
- Rust：`a` 在编译期就被标记为「已移动」，之后任何使用都是编译错误。堆上的数据只有一个所有者（owner）。

这样换来三样东西：
1. **没有隐式的深拷贝**：不会出现悄悄复制 1 GB 的情况，想复制必须写 `.clone()`，成本在代码里可见。
2. **没有释放歧义**：只有当前所有者负责释放，不可能重复释放（double free），也不需要 GC 或引用计数去判断「最后一个使用者是谁」。
3. **别名受控**：要共享就显式借用 `&T`，要修改就 `&mut T`，两者不能同时存在。

代价是：你需要习惯「把值交出去就不能再用」。传一个 `Vec` 给函数，想继续用它，就要么传 `&v`，要么让函数把它还回来。

对比：C++ 的赋值默认是深拷贝，移动是 `std::move` 手动开启的优化；Rust 把默认和显式反过来，默认移动，拷贝要写出来。
