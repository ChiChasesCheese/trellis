## Q
一个值在内存里到底长什么样？为什么「字段内联」还是「通过指针间接」会影响内存占用和速度？

## A
一个值在内存中的布局，由三件事决定：
1. **内联还是间接**：容器里直接存数据本身（字段内联，inline），还是存一个指向别处的指针。
2. **元数据**：值本身之外，运行时是否在每个对象前面加了额外信息（对象头：类型指针、锁状态、GC 标记、引用计数）。
3. **对齐与填充**（alignment and padding）：CPU 要求一个 8 字节的整数放在 8 的倍数地址上，编译器因此在字段之间插入空白。

这些决定了三个看得见的成本：
- **空间**：一个只含一个整数的对象，可能比整数本身大好几倍。
- **缓存局部性**（cache locality）：CPU 一次从内存读一整条 64 字节的缓存行。数据紧挨着放，一次读入就能处理多个元素；每个元素都要跟着指针跳到别处，几乎每个都是一次缓存未命中（数十到上百 ns）。
- **GC 与分配压力**：对象越多、指针越多，回收器要扫描和管理的越多。

设计空间：
1. **全部是对象，通过引用访问**（Python、早期 Java）：统一简单，布局固定，代价最高。
2. **值类型与引用类型并存**（Java 的基本类型加对象、Go 的结构体与指针、C# 的 struct）：程序员选择。
3. **默认内联，显式用指针间接**（Rust、C++）：数据布局由程序员完全控制。

理解布局，是理解为什么「同样的算法，一个语言比另一个慢几倍」的最直接的钥匙。
