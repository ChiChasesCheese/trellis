## Q
C++、Go、Java、Rust、Python 的内存布局选择有什么不同？换来什么，代价是什么？

## A
| 语言 | 选择 | 换来 | 代价 |
|---|---|---|---|
| Go | 结构体与数组内联，切片是连续块，无对象头 | 缓存友好；`[]P` 约 16 字节每元素 | 接口值是 16 字节胖指针，装箱要堆分配 |
| Java | 对象带约 12 字节头，经引用访问；基本类型数组紧凑 | 统一的对象模型，GC 友好 | `Integer[]` 约比 `int[]` 大 5 倍；对象散落在堆中 |
| C++ | 默认内联，布局按声明顺序（同一访问级别内，标准要求地址递增），与 C 兼容；只有带虚函数的类才多一个虚表指针；`alignas`（指定对齐）、`[[no_unique_address]]`（让空成员不占空间）精确控制 | 与 Rust 同等的零开销，`std::vector<T>` 连续存放，与 C 的结构体二进制兼容 | 要自己排字段避免填充（`{bool, int64, bool}` 为 24 字节，调整后 16 字节）；`vector<T*>` 和 `list` 这类指针结构容易写出缓存不友好的代码 |
| Rust | 默认内联，布局可重排，`repr(C)` 精确控制 | 零开销抽象，`Option<Box<T>>` 与指针等大 | 要自己想布局与缓存；`Box<dyn Trait>` 有间接调用 |
| Python | 一切皆对象，`int` 约 28 字节，`list` 存指针 | 统一动态语义 | 空间膨胀约 9 倍，数值计算要靠 NumPy 下沉到 C |

（Java、Python 数字为一次本机测量；Go、Rust、C++ 来自 `unsafe.Sizeof`、`size_of`、`sizeof`。）

逻辑：布局体现了语言对「抽象成本」的态度。C++ 是这条路线的原型：零开销原则（用不到的不付费，用到的手写也不会更快）最早就是 C++ 提出的，Rust 继承并加上了安全检查。Rust 的哲学是零开销抽象（zero-cost abstraction）：用不到的不付费，用到的手写也不会更快，所以布局默认紧凑；Go 追求简单可预测，值类型内联；Java 和 Python 为统一的对象模型付出了内存与间接访问的代价，再靠 JIT、原生扩展或未来的值类来缓解。

对工程师的含义：同样的算法，布局差异可以造成一个数量级的速度差距，因此在选语言、选数据结构时，布局是和算法复杂度同等重要的维度。
