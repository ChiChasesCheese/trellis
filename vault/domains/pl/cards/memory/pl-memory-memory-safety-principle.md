## Q
内存安全（memory safety）具体指避免哪几类错误？语言有哪几种做法来保证它？

## A
内存安全指程序不会以违背类型和内存模型的方式访问内存。违反它的典型错误有：
1. **越界访问**（out-of-bounds）：数组长 3，却读写第 5 个元素。
2. **释放后使用**（use-after-free）：对象已释放，旧指针还在用。
3. **重复释放**（double free）。
4. **空指针或悬空指针解引用**。
5. **读未初始化的内存**。
6. **数据竞争**（data race）：多个线程同时读写同一内存，且没有同步，至少一个在写。

这些错误一旦发生，C 和 C++ 称之为**未定义行为**（undefined behavior）：标准不规定结果，编译器甚至可以假设它不会发生而做优化，结果可能崩溃，也可能被攻击者利用来执行任意代码。所以内存安全不只是稳定性问题，更是安全问题：公开的统计里，大型 C/C++ 项目中严重安全漏洞的大约七成属于内存安全类。

语言保证它的方式有四种：
1. **运行时检查**：每次数组访问都检查下标（边界检查，bounds check），空引用访问抛出异常。
2. **运行时托管内存**：GC 或引用计数保证只要有引用，对象就不会被释放。
3. **编译期证明**：所有权、借用和生命周期检查，在编译期保证引用有效、没有数据竞争。
4. **沙箱隔离**：不修复错误，而是限制它能造成的影响（WebAssembly、进程隔离）。

大多数「安全」语言把 1 与 2 合用；Rust 用 3 加 1，没有运行时托管。
