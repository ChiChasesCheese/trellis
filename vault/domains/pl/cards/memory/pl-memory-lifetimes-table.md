## Q
「引用不能比被引用的值活得更久」这件事，Go、Java、Rust、Python 各自在哪个阶段、用什么保证？换来什么，代价是什么？

## A
| 语言 | 选择 | 换来 | 代价 |
|---|---|---|---|
| Go | 逃逸分析发现地址外泄，就把变量放到堆，由 GC 保活 | 无需标注，随便返回地址 | 堆分配与 GC 压力，由编译器隐式决定 |
| Java | 对象都在堆，GC 保证有引用就不回收 | 无需任何标注 | 所有对象都是托管堆对象 |
| Rust | 借用检查器比较引用与被引用值的生命周期 | 零运行时成本，无 GC 也不悬空 | 多引用的函数签名要写 `'a`，部分正确程序被拒 |
| Python | 引用计数，有名字指向就不销毁 | 无需标注 | 计数更新与循环检测 |

逻辑：生命周期是 Rust 为「没有 GC 又要安全」付的那笔账。GC 语言在运行时统一解决，所以语言里根本没有这个概念；Rust 把账从运行时挪到签名里，换来零成本，也换来了一类新的复杂度：API 设计者必须想清楚「返回值借用了谁」。

一个实用的判断：如果你的代码不能容忍 GC 的暂停或内存开销，生命周期是值得付的代价；否则 GC 语言把这个问题彻底隐藏了，是更划算的选择。
