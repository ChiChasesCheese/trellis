## Q
Go、Rust、C++ 与 Java 在「谁掌控内存布局」上有什么根本区别？Rust 的哪些设计让它能做到零开销抽象？

## A
**Rust 和 Go：程序员掌控布局。** 结构体里的字段直接内联，结构体放进数组就是一块连续内存，没有对象头。Rust 更进一步：
- 泛型采用单态化（monomorphization），`Vec<i32>` 与 `Vec<f64>` 各生成一份专用代码，元素按本身大小紧密排列，没有装箱。
- 枚举（`enum`）带数据，大小等于最大的变体加一个标签，并通过空位优化（niche）尽量省掉标签。
- `#[repr(C)]`、`#[repr(packed)]`、`#[repr(align(64))]` 精确控制布局，可对接 C，也可手动避免伪共享（false sharing，两个线程写同一条缓存行里的不同变量而相互拖慢）。

**C++ 与 Rust 站在同一边**：布局由程序员掌控，模板（编译期按类型参数生成代码的机制）与 Rust 的单态化一样让 `vector<int>` 里存裸 `int`，没有装箱。区别是 C++ 的字段严格按声明顺序，不重排；也没有 Rust 那样的枚举空位优化，`std::optional<unique_ptr<int>>` 本机是 16 字节，裸指针是 8 字节。
**Java：JVM 掌控布局。** 程序员无法指定字段顺序和对象头，HotSpot 自己重排字段以减少填充。泛型靠类型擦除（type erasure），`List<Integer>` 里存的是引用，元素必须装箱。这是 Java 内存开销的根源，也是 Valhalla 项目（值类，value class，没有对象身份，可内联存放）要解决的问题。

**Go：中间位置。** 值类型内联、数组连续，类似 Rust；但泛型的实现（按 GC 形状模板化）和接口（16 字节的胖指针，并通过指针间接调用）处在两者之间。

对性能敏感的代码，选语言往往等于选布局：
- 高频交易、游戏引擎、数据库内核倾向 Rust、C++，因为能手工排布数据结构，让热点数据挤进一条缓存行。
- 业务后端对延迟不敏感，Java、Go 的布局足够，并获得更高的开发效率。
