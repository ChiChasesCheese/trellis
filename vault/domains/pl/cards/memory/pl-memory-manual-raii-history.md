## Q
RAII 从 C 的手动管理发展到现代语言，经历了怎样的路线？为什么后来的语言多数没有走 RAII 这条路？

## A
1. **C（1970 年代）**：`malloc`/`free` 全靠人。大型代码库里内存错误长期占安全漏洞的相当比例（微软、Google 的公开统计都在六七成量级）。
2. **C++（1980 年代起）**：Stroustrup 提出 RAII，用构造函数和析构函数把资源绑到对象生命周期上；智能指针 `unique_ptr`、`shared_ptr`（C++11）把它推广到堆内存。但裸指针和拷贝仍然存在，安全靠纪律。
3. **Java、Python、Go 一代**：选择了 GC 或引用计数，目标是让所有程序员「不用想」。代价是回收时机不确定，于是为文件、锁另外发明了 try-with-resources、`with`、`defer`。
4. **Rust（2015 年 1.0）**：重新回到 RAII，但加上所有权和借用检查，让编译器证明「每个值只有一个所有者、引用不会比值活得久」。这是在没有 GC 的前提下获得内存安全的唯一主流方案。
5. **趋势**：Swift 用自动引用计数、Zig 用显式分配器加 `defer`、C++ 社区推动 lifetime profile，都在尝试在不引入完整 GC 的前提下减少手动管理。

没有走 RAII 的原因：RAII 要求每个值有明确的所有者，对图、缓存、共享状态很别扭；GC 让这些场景写起来最自然，对大多数业务系统，开发效率比确定性析构更值钱。
