## Q
C++、Go、Java、Rust、Python 分别在子结构类型光谱的哪个位置？各自怎样保证（或不保证）资源被正确地使用一次并释放？

## A
| 语言 | 类型系统的位置 | 资源协议靠什么 | 能静态保证什么 |
|---|---|---|---|
| Rust | 仿射（非 `Copy` 类型至多用一次） | 所有权加 `Drop`，类型状态，`must_use` | 不会重复释放、不会移动后使用；不保证一定释放 |
| C++ | 基本无限制；`unique_ptr` 等类型禁用复制、只能移动，近似仿射；但被移走的对象依然存在、编译器不拦再用 | RAII（对象析构时自动释放资源）、`unique_ptr`（只能移动的独占指针）、`[[nodiscard]]`（忽略返回值时警告） | 禁止复制由编译器保证；「移动后不再使用」「一定释放」都不保证 |
| Java | 无限制 | `try-with-resources`、`Cleaner` | 几乎没有；忘记 `try` 编译器不会提醒 |
| Go | 无限制 | `defer`、约定 | 几乎没有；`go vet` 能抓少数忘记关闭的情形 |
| Python | 无限制 | `with`、上下文管理器、引用计数的回收 | 没有；忘记时靠解释器收尾，可能出现资源警告 |

规律：**类型系统对「值的使用方式」约束越多，能在编译期防止的资源错误越多，语言越不灵活。**

逻辑：

- C++ 站在 Rust 旁边但缺最后一步：它有 `unique_ptr` 这类只能移动的类型，也有 RAII，却不跟踪「已被移走」这个状态，被移走的对象继续留在作用域里等着被析构，使用它不会被编译器拦下。所以 C++ 的所有权是由库类型加约定实现的，Rust 的是由类型系统实现的。
- Java、Go、Python 的赋值与传参总是复制引用，值可以有任意多个别名、任意次使用，这是它们简单易用的基础。代价是没有任何类型层面的手段表达「这个值只能用一次」，资源管理只能是语法糖加约定：`try-with-resources` 保证作用域结束时调用 `close`，前提是你记得写。
- Rust 把「唯一所有者」放进类型系统，代价是赋值默认是移动，传参要考虑所有权，借用需要生命周期，学习曲线陡。回报是整类错误（重复释放、释放后使用、迭代中修改集合、数据竞争）在编译期消失。

三条判断：

1. 值有别名吗？Java、Go、Python 里是的，所以并发修改、资源双重释放要靠运行时手段防范。
2. 非法状态能被表达吗？Rust 的类型状态能把「已关闭的连接」变成不能调用 `send` 的类型，其他语言只能抛运行时异常。
3. 泄漏会被发现吗？没有一门语言能靠类型系统阻止泄漏（Rust 的仿射允许 `forget`），这要靠泄漏检测工具（`-race`、`valgrind`、`tracemalloc`、堆转储）。

结论：仿射类型不是为了更严格，而是为了把「谁负责释放」这件事从口头约定变成可检查的事实。
