## Q
缓存行（cache line）和缓存局部性（locality）是什么？为什么布局会决定遍历速度？

## A
CPU 比内存快得多，中间放了几层高速缓存（cache）。CPU 从内存读数据时，不是一个字节一个字节地读，而是一次读入一整条**缓存行**，常见 64 字节（Apple 部分芯片 128 字节）。读到缓存里的数据，下次访问几乎免费；访问不在缓存里的数据叫**缓存未命中**（cache miss），要等主存，量级是几十到上百纳秒，相当于几百条指令。

两个后果：
- **空间局部性**：数据紧挨着放，读一个元素就把它的邻居也带进了缓存，顺序遍历时后面的访问全部命中；硬件还会检测顺序模式，提前预取下一行。
- **指针间接**：每个元素都是一个指向别处对象的指针时，遍历就是在内存里到处跳，每次几乎都是未命中。

本机一次 Go 基准（400 万个 16 字节的结构体求和）：连续的 `[]P` 约 0.9 ms；`[]*P`（每个元素单独分配，且打乱了顺序）约 8.6 ms，约 10 倍。后者每个元素约 2 ns 而不是上百 ns，是因为各次读取互不依赖，CPU 能同时发出多个未命中请求；如果是链表那样“下一个地址要读完上一个才知道”的依赖链，就无法重叠，更慢。

要记住的一个事实：算法复杂度相同的两段代码，数据是否连续可以造成一个数量级的速度差，布局是和算法同等重要的性能维度。
