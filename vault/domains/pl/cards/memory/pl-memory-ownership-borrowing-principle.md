## Q
Rust 的所有权（ownership）和借用（borrowing）要解决什么问题？它的三条规则是什么，设计空间里其他做法是什么？

## A
问题：没有 GC 的语言要安全地释放堆内存，必须保证「释放后没有人再用」和「同一块内存只释放一次」。C 靠程序员的纪律，GC 语言靠运行时追踪。能不能在编译期就证明它们？

Rust 的回答是用类型系统追踪每个值的「谁拥有它」，规则只有三条：
1. 每个值有且只有一个所有者（owner）。
2. 所有者离开作用域时，值被释放（`Drop`）。
3. 所有权可以移动（move）给别人，原来的变量作废。

只有所有权太苛刻，每次传参都要交出值。于是有借用：不转移所有权，只临时拿一个引用：
- 共享引用 `&T`：可以同时有多个，只读。
- 可变引用 `&mut T`：同一时刻只能有一个，且此时不能有任何 `&T`。

这条借用规则也叫「别名 XOR 可变」（aliasing XOR mutability）：数据要么被多处看到，要么被一处修改，不能两者兼有。迭代器失效、悬空引用、数据竞争都是「有人读的同时有人写」，被这一条规则一并消灭。

设计空间里的其他做法：
- 全靠程序员（C、C++）：快但不安全。C++ 用 RAII 和智能指针表达所有权，但不检查引用是否悬空，也不检查别名。
- 运行时追踪（GC、引用计数）：安全但有运行时成本。
- 全部值语义不共享（早期纯函数式、Go 的传值风格）：安全但频繁复制。
- 所有权加借用检查：编译期证明，零运行时成本，代价是学习曲线。
