## Q
标记-清除（mark-sweep）是怎么工作的？“根”和“可达”指什么，它为什么能回收循环引用？

## A
追踪式 GC 的出发点：不记账“谁在用我”，而是从程序一定能访问到的地方出发，沿引用往下找，找得到的就是活的。出发点叫**根**（roots）：所有线程栈上的局部变量、全局变量/静态变量、寄存器。从根出发沿引用能走到的对象叫**可达**（reachable），其余是垃圾。

一个小例子：根指向 A；A 指向 B；B 指向 C；D 指向 E；F 与 G 互相指向。

1. **标记**（mark）：从根出发依次访问 A、B、C，给它们打上标记。
2. **清除**（sweep）：扫描整个堆，没有标记的 D、E、F、G 全部回收，回收的内存还给分配器。F 和 G 虽然互相引用，但从根走不到，也一并回收。

最朴素的实现要在回收期间暂停所有程序线程（**停止世界**，stop-the-world，STW），否则程序一边改引用、回收器一边标记，可能漏标仍然活着的对象。堆越大、存活对象越多，标记越久，暂停越长。

标记-清除不移动对象，只是把空闲块还给分配器，所以回收后堆里会有大小不一的空洞，称为内存碎片。

要记住的一个事实：追踪式 GC 的成本和**存活对象的数量**成正比，而不是和垃圾的数量成正比；这和后面的分代回收为什么有效直接相关。
