## Q
结构体在内存里怎么排？对齐（alignment）和填充（padding）是什么，Go、Rust 与 C++ 对字段顺序的处理有何不同？

## A
结构体（struct）是把几个字段并排放在一块连续内存里的类型。CPU 读写一个 8 字节整数时，要求它的地址是 8 的倍数，否则很慢甚至出错。这条要求叫**对齐**。为满足它，编译器在字段之间插入空白字节，叫**填充**；整个结构体的大小也会补到最大对齐值的倍数。

字段顺序 `bool`（1 字节）、`int64`（8 字节）、`bool`（1 字节）：
1. 第一个 `bool` 在偏移 0；
2. `int64` 要对齐到 8，偏移 1 到 7 被填充，它从偏移 8 开始；
3. 第二个 `bool` 在偏移 16；
4. 总大小 17，补到 8 的倍数得 24 字节，其中有效数据只有 10 字节。

把顺序改成 `int64`、`bool`、`bool`，则偏移 0、8、9，总大小补齐到 16 字节。

- **Go**：严格按声明顺序布局，上面两种写法的 `unsafe.Sizeof` 实测分别是 24 与 16；程序员自己把大字段放前面。
- **Rust**：默认布局**允许编译器重排字段**，同一个结构体实测只有 16 字节；加 `#[repr(C)]` 才强制按声明顺序（与 C 兼容，做 FFI 时需要），得到 24 字节。
- **C++**：与 Go 一样，同一访问级别内的非静态成员按声明顺序排列，编译器不能重排（这是对 C 兼容的要求）。本机 `sizeof` 实测同样是 24 与 16：大字段放前面是你的责任。
- **Java、Python**：程序员无法控制，JVM 自己重排字段，Python 对象则是字典或槽位。

要记住的一个事实：结构体的大小不是字段大小之和，对齐会带来填充；Go 和 C++ 要你自己排好，Rust 默认替你排。
