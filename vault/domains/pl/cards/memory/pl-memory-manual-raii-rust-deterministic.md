## Q
Rust 的 RAII 相比 Java、Go 的 GC，独特的好处是什么？它有什么限制？

## A
Rust 把「确定性析构」和「没有运行时回收器」同时做到了，这是 GC 语言做不到的（C++ 的 RAII 也有这两点，下面的好处在 C++ 里同样成立，Rust 多出的是编译器对所有权的检查）。

好处：
1. **时机可预测**：值在所属作用域结束的那一行被释放，不会有「不知道哪个时刻 GC 突然暂停」的问题。内存、文件句柄、互斥锁、数据库连接都能用同一个 `Drop` 表达，锁的 `MutexGuard` 离开作用域就解锁。
2. **没有额外运行时**：没有 GC 线程、没有写屏障、没有对象头里的标记位，适合内核、嵌入式、低延迟交易系统。
3. **内存占用紧**：不需要为 GC 预留堆空间余量，回收是即时的。

限制：
1. 生命周期必须能用嵌套作用域描述。图结构、需要多个所有者共享的数据，要显式用 `Rc`（引用计数的共享指针）/`Arc`（引用计数）。
2. 安全 Rust 只保证「不会重复释放、不会释放后使用」，不保证「一定释放」。循环引用的 `Rc` 和 `std::mem::forget` 都会让 `drop` 永远不执行，这是允许的，不被视为内存安全问题。
3. 递归释放很深的数据结构（如超长链表）会在 `drop` 时递归，可能栈溢出，需要手写迭代的 `Drop`。

对比 C++：同样是 RAII，但 C++ 可以拷贝出第二个所有者，需要纪律；Rust 靠移动语义由编译器强制。
