## Q
标记-清除怎样一步步工作？为什么需要三色标记、写屏障（write barrier）和分代假设？

## A
一个小例子：根指向 A；A 指向 B；B 指向 C；D 指向 E；F 和 G 互相指向。

1. **标记**：从根出发访问 A、B、C，打上标记。
2. **清除**：扫描整个堆，没标记的 D、E、F、G 被回收，F 和 G 虽然互相引用，也一并回收。

最朴素的做法要**停止世界**（stop-the-world，STW）：回收期间所有程序线程暂停，否则程序一边改引用，一边在标记，可能把还活着的对象漏标。堆越大，暂停越长。

**三色标记**（tri-color marking）让回收可以和程序并发：
- 白：还没被访问，最后仍为白的是垃圾。
- 灰：已发现，但它引用的对象还没检查。
- 黑：自己和直接引用的对象都检查完。

不变量：黑对象不能直接指向白对象。若程序线程在并发期间让一个黑对象去引用白对象，那个白对象会被漏标。所以编译器在每次引用字段写入时插入一小段**写屏障**，把这种情况通知回收器重新标记。这是并发回收的核心代价：程序线程每次写引用都稍慢一点。

**弱分代假说**（weak generational hypothesis）：绝大多数对象朝生夕死。据此把堆分成年轻代和老年代，年轻代小且常回收，且多数是垃圾，复制存活者的成本很低；老年代很少回收。Java 的 G1、ZGC 利用了它；Go 的回收器没有分代。
