## Q
为什么这些年内存安全被提升为工业界的头等大事？语言和行业都做了什么回应？

## A
背景：C 与 C++ 诞生时，机器资源珍贵，安全检查被视为浪费。但几十年下来，微软、Google Chrome、Android 等项目公开的统计相近：严重漏洞里大约六到七成是内存安全问题。缓冲区溢出、释放后使用成了最常见的攻击入口。

行业的回应：
1. **加缓解措施**：栈保护（stack canary）、地址随机化（ASLR）、数据执行保护（DEP）、控制流完整性等，让漏洞更难利用，但不能消除。
2. **加检测工具**：AddressSanitizer、Valgrind、模糊测试（fuzzing），在测试阶段发现，仍依赖覆盖。
3. **换语言**：新代码改用内存安全语言。Android 在新增代码中大量使用 Rust 与 Kotlin；Linux 内核接纳 Rust 驱动；2024 年美国政府的报告与指南公开建议软件厂商转向内存安全语言。
4. **改造老语言**：C++ 社区提出安全配置（profiles）与更严格的标准库加固；Clang 提供缓冲区边界注解（`-fbounds-safety`）。

语言一侧的演进：
- 1990 年代，Java 把「GC 加边界检查」带入主流；
- 2010 年代，Rust 证明「不要 GC 也能内存安全」；
- Go 选择了 GC 与检查，对并发安全则留给开发者。

趋势：内存安全正从「可选的特性」变成「默认要求」，新项目的问题已经不是要不要，而是在哪一层、用什么代价获得：运行时（GC）、编译期（借用检查）还是隔离（沙箱）。
