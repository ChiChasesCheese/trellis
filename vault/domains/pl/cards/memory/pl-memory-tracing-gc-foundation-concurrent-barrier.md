## Q
并发 GC 是怎么在程序运行的同时回收的？三色标记（tri-color）和写屏障（write barrier）是什么？

## A
停止世界的暂停和堆大小成正比，对在线服务不可接受。**并发回收**让 GC 线程和程序线程同时运行，只在开头和结尾各停一小会儿。难点：程序一边在改引用，回收器一边在标记，可能出错。

**三色标记**用三种颜色记录标记进度：
- 白：还没访问到，标记结束时仍为白的就是垃圾。
- 灰：已发现，但它引用的对象还没检查完。
- 黑：自己和它直接引用的对象都检查完了。

回收器不断取出灰对象，把它引用的白对象染灰，自己染黑，灰对象耗尽时标记结束。

**危险场景**：回收器已把对象 X 染黑（认为它的引用都检查完了）；这时程序线程让 X 指向一个还是白色的对象 Y，并且删除了其他指向 Y 的引用。回收器不会再回头看 X，Y 被误当垃圾回收，而程序还在用它。

**写屏障**就是修复办法：编译器在每次“给对象字段写入引用”的地方，插入一小段额外代码，把这类写入通知给回收器（例如把 Y 重新染灰）。代价：程序每次写引用都稍微慢一点。分代回收也用写屏障，记录“老年代对象指向了年轻代对象”，这样只回收年轻代时不用扫描整个老年代。

要记住的一个事实：并发 GC 用“程序线程每次写引用时多付一点”来换取“回收时几乎不暂停”。
