## Q
C++ 也有「移动」（`std::move`），它和 Rust 的移动有什么本质区别？为什么说 C++ 的移动不是仿射类型？

## A
C++ 的移动语义是一种**性能优化**：`std::string b = std::move(a);` 让 `b` 偷走 `a` 内部的缓冲区，避免复制。但语言**不阻止你继续使用 `a`**：

```cpp
std::string a = "hello";
std::string b = std::move(a);
std::cout << "[" << a << "] [" << b << "]\n";   // [] [hello]
```

输出 `[] [hello]`。`a` 仍是一个合法的对象，处于「有效但未指定」的状态（标准库的惯例是变成空），编译器不报错，也没有警告。

和 Rust 对比：

| | C++ | Rust |
|---|---|---|
| 移动后原变量 | 仍可使用（通常是空） | 编译期禁止使用 |
| 谁来保证 | 程序员记住不要用 | 编译器检查 |
| 默认行为 | 赋值是复制，要写 `std::move` 才移动 | 赋值是移动（非 `Copy` 类型），要写 `.clone()` 才复制 |
| 析构 | 被移走的对象仍会运行析构 | 被移走的变量不会再被析构 |

这个差别在类型理论上就是：C++ 的值仍满足「可以使用多次」的规则，移动只是一种带副作用的复制；Rust 把「移动后不可用」放进了类型系统，所以是仿射。

后果在于**正确性的责任归属**。C++ 里使用已移动的对象是一类真实的 bug，静态分析器（clang-tidy 的 `bugprone-use-after-move`）才能查出来；Rust 里同样的写法根本编译不过。反过来，C++ 允许你在移动后把对象重新赋值再用，写法更灵活；Rust 要求通过重新绑定。

Rust 的默认选择也不同：C++ 的默认是复制（需要复制就不用写什么，复杂对象一不小心就是深拷贝）；Rust 的默认是移动，复制必须显式 `clone()`，在代码里看得见、搜得到。

要记住的一点：移动语义的差别不在于运行时做了什么（都是搬几个指针），而在于**类型系统是否记住了「它已经被搬走了」**。
