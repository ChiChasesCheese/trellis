## Q
追踪式垃圾回收（tracing garbage collection）要解决什么问题？「可达性」是什么意思，回收算法有哪几大类？

## A
手动释放容易出错，引用计数处理不了循环引用。追踪式 GC 换了一个思路：不记账「谁还在用我」，而是定期从一组**根**（roots）出发，沿着引用一路追踪，凡是能走到的对象就是**可达**（reachable）的，走不到的就是垃圾，可以安全回收。

根包括：所有线程栈上的局部变量、全局变量/静态变量、CPU 寄存器。「可达」是对「程序将来还可能用到」的保守近似：走不到的对象，程序一定再也用不到。

这个定义的好处是天然处理循环引用：两个对象互相指着对方，只要从根走不到，就一起被回收。

设计空间里有三类基本算法：
1. **标记-清除**（mark-sweep）：先标记所有可达对象，再扫描整个堆把没标记的回收。简单，但会留下内存碎片。
2. **复制**（copying）：把存活对象复制到另一块空区域，原区域整块清空。没有碎片，分配只需移动指针，但要预留一半空间，并且对象会被移动。
3. **标记-整理**（mark-compact）：标记后把存活对象滑动到一端，消除碎片。

在此之上还有两个正交的维度：是否**分代**（generational，按对象年龄分区回收），以及是否**并发**（concurrent，回收线程与程序线程同时运行以缩短暂停）。
