## Q
Rust 里设计带引用的 API 时，有经验的工程师怎样对待生命周期？什么时候该用借用，什么时候该用拥有的类型？

## A
生命周期标注是一种 API 契约，每多一个，调用者就多一层约束。所以原则是：**默认让数据被拥有，只有当零拷贝带来可测量的收益时才引入借用。**

具体做法：
1. **结构体默认存拥有的类型**（`String`、`Vec<T>`、`Arc<T>`：引用计数的共享所有权指针），不要一上来就存 `&'a str`。带生命周期参数的结构体会「传染」：包含它的类型、返回它的函数、放它的集合都要带上生命周期。
2. **函数边界上输入借用、输出拥有**：参数写 `&str`、`&[T]`，这样调用者传 `String`、`Vec`、切片都行；返回值若需要独立使用就返回拥有的值。
3. **让省略规则工作**：能不写 `'a` 就不写。需要写时，名字有语义（`'input`、`'arena`）比 `'a`、`'b` 更好读。
4. **零拷贝是有场景的**：解析器与分词器（词元指向原文）、网络协议的帧视图、大文件的内存映射。这些地方，不复制的收益大，并且数据流天然是「先有原文，后有视图」。
5. **不要为了通过编译而 `'static`**：泄漏（`Box::leak`，故意不再释放堆内存以换取 `'static`）与过宽的 `'static` 约束把问题藏起来。需要跨线程或长期保存，就交出所有权（`Arc`、`clone`）。
6. 遇到复杂的生命周期标注，先考虑能否改用索引或 ID 引用。

为什么：生命周期把「数据流向」写进类型，价值在于让读者不用读函数体就明白谁借了谁；滥用则让签名比逻辑还复杂。

什么时候违反：性能分析证明复制是瓶颈，或者要写不可避免需要借用的库（迭代器、解析器）。
