## Q
所有权与借用这套思想从哪里来，Rust 之后其他语言怎样吸收它？

## A
理论根源是线性类型（linear types）和仿射类型（affine types）：「一个值最多被使用一次」。Rust 的移动语义对应仿射类型；借用是在这之上为了实用而加的放宽。研究语言 Cyclone（C 的安全方言，2000 年代初）的区域（region）和唯一指针也是重要前身。

Rust 自己的演进：
- 早期版本曾有语言内置的 GC 指针（`@T`）和多种指针种类，在 1.0 之前被删除，换成库里的 `Rc`/`Arc` 加所有权。
- **2015 年 1.0**：借用检查基于词法作用域，借用到作用域结束才失效，很多正确程序被拒绝。
- **2018 年起的 NLL**：借用到最后一次使用为止，被拒绝的正确程序大幅减少。
- **Polonius**：下一代借用检查算法，仍在推进，目标是接受更多正确程序（例如某些「条件返回借用」）。

对其他语言的影响：
- **Swift**：引入 `~Copyable` 不可复制类型，以及 `borrowing`、`consuming` 参数修饰符。
- **C++**：社区讨论的生命周期 profile 与安全 C++ 提案，试图在编译期检查借用。
- **Mojo** 等新语言：把所有者与借用作为核心。
- **Java**：没有借用，但 Valhalla 值类型与 FFM API 都在缩小「无必要的堆对象」。

趋势：编译期证明内存安全已成为系统语言的标配思路，区别只在于把多少复杂度暴露给程序员。
