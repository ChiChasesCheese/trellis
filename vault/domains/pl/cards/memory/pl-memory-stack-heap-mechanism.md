## Q
函数调用时栈帧（stack frame）是怎么分配和释放的？为什么栈分配比堆分配便宜得多？

## A
CPU 里有一个栈指针寄存器（stack pointer，SP），栈从高地址向低地址增长。调用函数 `f` 时，编译器已经知道 `f` 的所有局部变量一共要多少字节，比如 48 字节，于是函数入口只做一件事：`SP = SP - 48`。每个局部变量的地址就是「SP + 固定偏移」，编译期就算好了。

一个小轨迹：
1. `main` 的栈帧占 SP 在 1000 到 1100 之间；
2. `main` 调用 `f`，`SP` 从 1000 变成 952，局部变量 `x` 在 952+8 处；
3. `f` 再调用 `g`，SP 变成 900；
4. `g` 返回：`SP = 952`；`f` 返回：`SP = 1000`。没有任何释放动作，旧内容只是被之后的调用覆盖。

所以栈的分配和释放各是一条加减指令，量级在 1 ns 以内，而且栈上刚用过的内存几乎总在 CPU 缓存里。

堆分配则要走分配器：在空闲块链表或大小分级的池里找一块合适的，记录元数据，多线程时还要同步；释放时要合并空闲块。一次通常是几十 ns 量级，回收还要由 GC 或程序员负责。这就是「能放栈就放栈」成为通用优化原则的原因，栈的上限也是代价：主线程栈常见只有 1 到 8 MB。
