## Q
为什么近年各语言都在想办法压缩对象开销？Java 做了哪些具体改动？

## A
CPU 的运算速度增长远快于内存延迟的下降，访问一次未命中缓存的内存，相当于执行几百条指令。所以对象越小、数据越连续，就越快。这使「内存布局」从实现细节变成语言设计的重点。

Java 一侧的演进：
1. **压缩指针**（compressed oops，JDK 6 时代起）：堆小于 32 GB 时引用只占 4 字节。
2. **紧凑对象头**（compact object headers，JEP 450 在 JDK 24 实验性引入，JDK 25 作为正式特性可用）：把 12 字节对象头压缩到 8 字节，实测只含两个 `int` 的对象平均每个由 28 字节（含 4 字节引用）降到 20 字节。
3. **Valhalla 项目**：引入值类（value class）：没有对象身份，字段可以内联进数组和其他对象，目标是让 `Point[]` 像 C 的结构体数组一样连续。它仍是进行中的工作，在 JDK 25 里还不可用（带 `--enable-preview` 也无法编译 `value class`）。
4. 同时，Java 22 的 FFM API（外部函数与内存 API）允许在堆外按布局描述结构化内存。

其他语言：
- **Python**：3.11 起降低了实例的内存占用，对象的 `__dict__` 采用延迟创建和共享键；`__slots__` 去掉每实例字典；NumPy 等库把布局下沉到 C。
- **Go**：布局本来就紧凑，近年更多的是优化 GC 扫描的局部性。
- **Rust**：提供最细的控制，社区通过 SoA 库（如 ECS 游戏引擎）进一步改善缓存使用。

趋势：托管语言正在追赶「值类型内联」，系统语言则追求在保持控制的同时降低使用门槛。
