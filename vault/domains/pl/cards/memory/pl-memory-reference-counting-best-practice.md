## Q
使用引用计数时的最佳实践是什么？在 Rust 和 Python 里各自怎么避免循环与多余开销？

## A
核心原则：**给所有权画出方向**。拥有关系应当形成一棵树或有向无环图，不拥有的反向引用必须是弱引用。

**Rust**
1. 默认单一所有权，只有在确实有多个所有者时才用 `Rc` 或 `Arc`。不要因为借用检查器麻烦就把一切包进 `Rc<RefCell<T>>`，那等于放弃了 Rust 的主要好处。
2. 父拥有子用强引用，子指向父用 `Weak`，观察者列表用 `Weak`。
3. 只在跨线程时才用 `Arc`；`Rc` 更快，且类型系统会替你挡住误用。
4. 克隆写成 `Arc::clone(&x)` 而不是 `x.clone()`，让读代码的人一眼看出这只是增加计数，不是深拷贝。
5. 对热路径上的 `Arc` 要知道每次克隆是一条原子指令；在紧循环里传 `&Arc<T>` 或 `&T`，不要反复克隆。

**Python**
1. 缓存、注册表、观察者用 `weakref`（`WeakValueDictionary`、`WeakSet`），让它们不延长对象寿命。
2. 避免在 `__del__` 里做重要的事；资源清理用 `with` 或 `weakref.finalize`。
3. 不要靠引用计数的即时销毁来关闭文件、释放锁，那是 CPython 的实现细节。

为什么：引用计数的失败模式是静默的：循环不会报错，只会让内存缓慢上涨。把方向画清楚，等于在设计阶段就消掉了这个风险。

什么时候违反：真正的图结构（图、网络、双向链表）。这时要么用索引加 `Vec`（arena，竞技场分配），要么接受 GC 语言更自然。
