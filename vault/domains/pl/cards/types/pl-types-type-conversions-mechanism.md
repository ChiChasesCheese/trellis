## Q
有损数值转换和向下转型在底层各是怎么做的？为什么 300 转成 `uint8` 是 44，而 `(byte) 200` 是 -56？

## A
整数缩窄就是丢掉高位、保留低位。300 的二进制是 `1 0010 1100`（9 位），转成 8 位只保留低 8 位 `0010 1100`，即 44。`200` 是 `1100 1000`，同样 8 位，无符号解释为 200，有符号（补码）解释为 -56，所以 Java 的 `(byte) 200` 是 -56：位模式相同，解释不同。

浮点转整数则是另一套规则：Java 的 `(int) 3.99` 向零截断得 3，`(int) Double.NaN` 得 0，`(int) 1e20` 饱和成 `Integer.MAX_VALUE`（2147483647）。Rust 的 `as` 在 1.45 起也是饱和，`f64::NAN as i32` 得 0。早期 C 语言对越界浮点转整数是未定义行为，现代语言把它定义成了确定的饱和；C++ 至今保留了未定义行为，`static_cast<int>(1e20)`（C++ 的数值转换）在本机 ARM 上碰巧也得到 `2147483647`（硬件饱和），但标准不保证，换平台或优化级别可能不同。

向下转型是运行时检查：对象头里有它的真实类型。`(Integer) o` 时，JVM 比较对象的真实类与目标类，不是子类就抛异常；Go 的接口值内部是（类型指针，数据指针）一对，`v.(int)` 比较类型指针是否等于 `int` 的类型描述符，等就取数据，不等：带 `ok` 的形式返回 `0, false`，不带 `ok` 的形式 panic：

```console
panic: interface conversion: interface {} is string, not int
```

实现上两者都很快（一次指针比较），代价在于失败后的控制流：异常展开、panic 展开，或者调用者自己处理 `ok`。
