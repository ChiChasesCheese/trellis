## Q
语言对整数溢出和浮点数的处理是怎样演变的？今天的趋势是更安全还是更快？

## A
浮点方面，1985 年 IEEE 754 标准统一了二进制浮点的格式和舍入规则，今天几乎所有硬件和语言都遵循，这是少见的「真正跨语言一致」的行为。

整数方面，历史是从「不管」走向「明确」：

- C 把有符号整数溢出定为未定义行为，编译器可以假设它不会发生并据此优化，导致不少安全漏洞。C++ 继承了这一点；C++20 规定有符号整数必须是补码表示，但溢出仍然是未定义行为，没有改成回绕。
- Java（1995）把行为定义为回绕，去掉了未定义，换来可预测；没有无符号类型的设计取舍到 Java 8 才加入 `Integer.divideUnsigned` 等辅助方法，同时加入了 `Math.addExact` 这一族检查型运算。
- Python 早期有 `int` 和 `long` 两种类型，Python 3 统一成无限精度的 `int`。
- Rust（2015）的选择是：溢出是 bug，debug 下 panic，release 下按配置回绕，并提供显式 API。Swift 则默认在溢出时陷阱，要回绕必须用 `&+` 等运算符。

趋势是把溢出默认当成错误，把「我就是想回绕」变成显式声明。原因是安全漏洞（整数溢出导致缓冲区分配错误）的代价远高于检查的性能开销，而现代 CPU 上检查的开销已经很小。另一个趋势是 128 位整数和十进制类型进入标准库（Rust 的 `i128`、Python 的 `Decimal`、Java 的 `BigDecimal`），让金额和大数不再需要手写。
