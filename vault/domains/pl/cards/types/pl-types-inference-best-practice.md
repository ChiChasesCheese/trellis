## Q
什么时候该依赖类型推断省略类型，什么时候必须写出来？Java、Go、Rust、Python 各有什么经验规则？

## A
总原则：推导用来省掉读者已经知道的信息，而不是省掉读者需要的信息。

- 公共 API 的签名永远明写类型：函数参数、返回值、结构体字段。签名是契约，也是文档，同时把编译器的错误限制在局部。
- 局部变量：右边的类型一目了然时省略（字面量、构造函数、`new Foo()`）；右边是方法调用而类型对理解很重要时，写出来。Java 的 `var x = repo.load()` 在读者看来类型不明，就不宜用。
- 数值字面量要带上意图：Go 的 `x := 1 / 2` 是整数 0，想要浮点就写 `1.0 / 2`；Rust 用 `1u8` 或 `1_i64` 固定宽度。
- Rust：中间变量过多、报错看不懂时，临时加标注或用 `collect::<Vec<_>>()` 缩小问题范围，这是读编译器报错的技巧。
- Python：公共函数要把参数和返回值都标注。只标参数、漏掉返回值的函数，检查器把返回值当作 `Any`，之后所有调用都失去检查：

```python
def f(n: int):            # 返回值没有标注
    return n * 2.5
reveal_type(f(1))         # mypy: Revealed type is "Any"
```

实际输出就是 `Any`，而且没有任何错误提示。`Any` 会沿调用链传染，一个漏标就能让整条链失去保护。启用 `mypy --strict`（或 `disallow_untyped_defs`）可以把漏标变成错误。

何时可以破例：私有的短小 lambda、一次性脚本，推导带来的简洁优先；越是长期维护、多人协作的代码，越应该在边界上明写类型。
