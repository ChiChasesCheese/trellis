## Q
Go、Java、Rust、Python 对隐式类型转换各是什么态度？换来什么，付出什么？

## A
| 语言 | 选择 | 换来 | 代价 |
|---|---|---|---|
| Go | 没有隐式数值转换，`int` 和 `int64` 相加是编译错误 | 每次类型变化都写在代码里，审查不会漏 | 到处是 `int64(x)`、`float64(y)` 的噪音 |
| Java | 数值自动加宽，字符串 `+` 隐式转换，复合赋值 `+=` 隐式缩窄 | 日常数值代码简洁 | 精度悄悄丢失（`int` 到 `float`），`'a' + 1` 是 98，`s += 1` 绕过缩窄检查 |
| Rust | 完全没有隐式转换；`From` 表示无损，`TryFrom` 表示可能失败，`as` 表示有损 | 无损与有损在类型和语法上有区分 | 啰嗦；`as` 仍然会悄悄截断 |
| Python | 只做数值之间的安全提升（`int` 到 `float`），其余一律 `TypeError` | 动态语言里行为依然可预测 | `bool` 是 `int` 的子类等历史遗留，`True + 1` 得 2 |

背后的逻辑：隐式转换是便利和可见性之间的交换。Go 和 Rust 的哲学是「代码里没写的事情不该发生」，Go 把它用在可读性上，Rust 用在正确性上，甚至把转换按风险分成三档。Java 继承了 C 的便利取向，早期为了让数值代码好写而放宽规则，代价是留下了几个著名的陷阱。Python 的动态类型需要在运行期补偿，所以选择了「严格但不繁琐」的折中。
