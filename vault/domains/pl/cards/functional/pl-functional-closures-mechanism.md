## Q
被捕获的变量在内存里到底放在哪里？Java、Go、Rust、Python、C++ 各自怎样让它活得比原函数更久？

## A
闭包对象 = 代码指针 + 被捕获变量的存放方式。区别全在存放方式上：

- **Java**：复制值。lambda 被编译成一个对象，捕获的值是它的**字段**。原局部变量与它无关，所以栈帧销毁也没关系。代价：必须不可变。
- **Go**：被捕获并逃逸的变量搬到**堆**上（`moved to heap`），闭包持有指针；GC 负责回收。所有共享该变量的闭包看到同一份。代价：堆分配加 GC 压力。
- **Rust**：闭包是匿名结构体。按引用捕获时字段是指向原变量的引用，生命周期由借用检查器证明：闭包不能活得比被借的变量更久（否则 `E0373`）；用 `move` 时字段直接存值，闭包自给自足。代价：编译期的约束；收益：没有堆分配，没有 GC。
- **Python**：每个被内层函数引用的变量是一个堆上的 cell 对象，外层和内层函数都指向它，引用计数管理生命周期。代价：每次访问多一次间接。
- **C++**：lambda 是编译器生成的匿名类，捕获的变量是它的成员；`[x]` 存拷贝，`[&x]` 存引用（本质是指针）。闭包本身就在栈上，没有堆分配，也没有 GC 或借用检查；只有存进 `std::function`（类型擦除的通用函数包装器）且闭包较大时才会上堆。代价：引用捕获的生命周期完全由程序员负责。

规律：**GC 语言（Go、Python）用堆来解决生命周期问题，Java 用复制绕开，Rust 用类型系统证明，C++ 交给程序员**。四条路线的代价依次是：运行期的堆分配、对可变性的限制、编译期的复杂度、悬空引用的风险。

一个直接后果：同一个看似无害的闭包，在 Go 里可能引入一次堆分配（性能敏感的热点要注意），在 Rust 里可能引入一次借用检查失败，在 Java 里直接是编译错误。理解这些，才能判断某个闭包写法在特定语言的代价。
