## Q
Go、Java、Rust、Python、C++ 对不可变性的支持有什么区别？

## A
| 语言 | 默认 | 语言提供的手段 | 不可变的深度 |
|---|---|---|---|
| Go | 可变，按值复制 | `const`（仅编译期标量），其余靠约定 | 无类型层保证 |
| Java | 可变 | `final`、`record`、`List.of` | 浅（`final` 只管绑定，`record` 管字段） |
| Rust | 不可变，`mut` 才可改 | `let`/`mut`，`&`/`&mut` | 深（对拥有的数据），且排他 |
| Python | 可变 | `tuple`、`frozenset`、`frozen` dataclass | 浅 |
| C++ | 可变 | `const` 修饰符、`constexpr`（编译期常量）、`const` 成员函数 | 对按值持有的成员逐层生效（深）；遇到指针或引用就停（浅）；`mutable`、`const_cast` 可绕过 |

规律：默认值决定了行为。默认可变的语言里，不可变是需要主动选择的优良实践，忘了写就是可变；Rust 把默认翻转，可变需要显式标记。

Rust 的哲学是「状态变化是需要被看见的事」，所以 `mut` 要写出来，`&mut` 要写出来，读代码时一眼就看到哪里会变。Java 作为企业语言，倾向于通过规范和类库（`record`、不可变集合）提供不可变，而不改变默认。Go 的设计者认为共享内存加锁与通道已足以管理状态，没有必要增加类型层的复杂性。Python 作为动态语言，信任程序员，提供几个不可变类型作为工具。C++ 的 `const` 是类型的一部分，沿着按值持有的成员逐层传播，编译器据此拒绝修改，是默认可变的语言里最成体系的一套。但它是「只读视图」而不是「不可变保证」：同一个对象可以同时被非 `const` 的别名修改，`const` 引用看到的值就会变；这正是 Rust 要把可变性与别名绑在一起的原因。

一个共同事实：没有一门主流语言默认深不可变（只有 Haskell 等纯函数式语言如此），因为性能与表达上的代价通常被认为不值得。
