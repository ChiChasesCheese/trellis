## Q
最大递归深度由什么决定？五门语言各自的上限数量级是多少，怎样估算？

## A
最大深度 ≈ **栈大小 ÷ 每层栈帧大小**，栈帧大小取决于参数、局部变量和编译器优化。

| 语言 | 栈 | 实测 / 默认的深度量级 |
|---|---|---|
| Python | 解释器设限，默认 1000 | 调高后纯 Python 递归可达 10 万以上 |
| Java | 固定约 1 MB | 简单函数约 4.5 万层，真实代码数千到万级 |
| Rust | 固定，主线程 8 MB | debug 下约 10 万层量级，release 可能被优化为循环 |
| Go | 可增长，上限 1 GB | 一千万层正常，约数千万层触顶 |
| C++ | 固定，主线程 8 MB（`ulimit -s`） | 简单函数约 17 万层（每层约 48 字节），溢出即段错误 |

（数字均为本机一次测量或默认值的量级，仅供估算。）

复用栈帧的 TCO 在机器层面就是：把参数写进原来的参数位置，然后 `jmp` 到函数开头，而不是 `call`。它要求当前函数在调用之后没有任何收尾工作。编译器做起来不难（LLVM、GCC 在优化时会做），难的是**语言层面承诺**：一旦写进规范，所有实现、所有构建模式都必须做到，而这会与栈回溯、调试器、析构语义冲突。

Go 的可增长栈在机制上是"复制并重定位"：新栈是更大的连续内存，旧栈内容整块复制，栈上所有指向栈内的指针都要修正，所以需要编译器为每个函数生成精确的栈布局信息。

选择归结为两种风格：Python / Java / Rust / C++ 把"深度是有限资源"暴露给程序员，Go 把它藏在运行时里换取便利，Scheme 通过 TCO 保证把一类递归变成无限深度。
