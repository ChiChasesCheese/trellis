## Q
调用栈和栈帧是什么？一个「尾调用」为什么在原理上可以复用栈帧，而语言为什么仍不愿意做？

## A
每个线程有一块连续的内存叫**调用栈**。每次函数调用，在栈顶压入一个**栈帧**：存放参数、局部变量、返回地址（调用完成后回到哪里）。函数返回时弹出。递归 `f(n)` 调 `f(n-1)` 调 `f(n-2)` ……就是一层层压栈，到了底再一层层弹出。栈的大小是固定上限（线程创建时定下），所以最大深度 = 栈大小 ÷ 每层栈帧大小。

```java
static long loop(long n, long acc) {
    return n == 0 ? acc : loop(n - 1, acc + 1);   // 尾调用
}
// loop(1_000_000, 0) -> StackOverflowError（HotSpot 不做 TCO）
```

这是一个标准的尾递归：递归调用是最后一个动作，返回值原样返回。第 k 层栈帧在发起调用之后再没有任何用处，理论上可以直接用新参数覆盖当前栈帧并跳回函数开头，就等于一个 `while` 循环。

语言仍不愿做 TCO 的理由：

- **栈回溯会丢失**：被复用的栈帧不留痕迹，异常堆栈里看不到调用链，调试困难（Python 的 Guido 明确以此为由拒绝 TCO）。
- **运行时依赖栈帧**：JVM 的安全检查和栈遍历（`StackWalker`、安全管理器）假设调用链完整。
- **清理动作破坏尾位置**：Rust 里局部变量有析构函数，函数最后的调用之后还要运行 `drop`，严格说就不再是尾调用。
- **多数代码没有这种需求**：现实中深递归通常是树 / 图遍历，不是尾递归。

所以实际工程里的做法是：已知会很深的循环，直接写成 `while`。
