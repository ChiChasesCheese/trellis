## Q
推送式迭代（Go）与拉取式迭代（Rust、Python）各自擅长什么？为什么 Go 还要提供 `iter.Pull`？

## A
两种模型是**对偶**的：

**拉取**（调用者控制节奏）：每次 `next()` 返回一个元素。擅长需要**同时推进多个序列**的场景：`zip` 两个迭代器、归并两个有序序列、手写的状态机式解析器。因为每个迭代器是一个有状态的对象，可以单独暂停与恢复。缺点：实现迭代器本身要保存状态，遍历递归结构（树）时必须手写栈或状态机。

**推送**（数据源控制节奏）：数据源调用你的回调。擅长**遍历复杂结构**：树的中序遍历直接用递归写，`defer` 清理资源也很自然；调用者只需要给一个循环体。缺点：很难同时推进两个序列，因为两个序列函数都想占住控制权。

Go 的选择是把推送作为主要形式（`range` 支持函数），因为 Go 的数据结构遍历多数是「写一个递归 / 嵌套循环」的类型，推送写起来最自然；当确实需要拉取时，`iter.Pull` 通过把序列函数放进一个**协程**里转换：每次 `next()` 切换到协程运行到下一个 `yield`，再切回来。切换比 goroutine 通信便宜，但仍有成本，所以应该只在必要时使用。

Python 的生成器是两者的结合：写起来像推送（函数里 `yield`），用起来是拉取（`next()`）。它之所以能这样，是因为 Python 的函数帧可以被挂起 / 恢复，也就是生成器本质上是协程；Go 和 Rust（`async` 状态机）也在用类似的机制。

选择规则：写数据结构的遍历 API，Go 提供推送形式；提供标准库式的通用工具，Rust 和 Python 的拉取更灵活。
