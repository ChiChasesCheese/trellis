# 付款记录接口（Payments API）

**这个项目要做什么。** SQLite 上建账户、查余额（正负金额求和）、记一笔付款；账户不存在时不改任何数据也不消耗 ID；重开数据库后数据与 ID 序列仍在。

## 设计要点

付款记录接口（Payments API）：SQLite 里的两张表，三个函数。
设计：账户只有 id，余额不存，每次从付款流水现算（余额 = 该账户全部付款金额之和，正负都算）；
存在性由 `accounts` 表回答，不由付款表回答，所以"没有付款的账户"（余额 0）和"不存在的账户"（None）分得开；
记付款是单条 `INSERT … SELECT … WHERE EXISTS`，账户不在时一行都不写，也就不会消耗付款 id；
两个 id 序列都靠 AUTOINCREMENT 落在 `sqlite_sequence` 表里，关库重开后接着走。
三个函数都不关调用方的连接，也不自己管事务：每个函数只发一条会改数据的语句，语句本身是原子的。

## 考点与卡片

- **不存在的账户是正常结果：查询与记付款都返回 None，不抛异常**：[[lcp-payments-api-contract-rules]]
- **有账户但没有付款，余额是 0；不存在才是 None**：[[lcp-payments-api-reflection-existing-vs-missing]]
- **余额等于该账户全部付款金额之和，正负都算**：[[lcp-payments-api-contract-rules]]、[[lcp-payments-api-state-and-invariant]]
- **不检查透支：余额可以是负数**：[[lcp-payments-api-contract-rules]]
- **金额为 0 的付款也是一条记录，也推进付款 id**：[[lcp-payments-api-contract-rules]]
- **两次相同的提交是两条不同的记录，没有幂等去重**
- **账户 id 与付款 id 是两条独立的序列**：[[lcp-payments-api-contract-rules]]、[[lcp-payments-api-state-and-invariant]]
- **缺失账户的付款不写行、不消耗付款 id**：[[lcp-payments-api-contract-rules]]
- **只对付款表求和：空账户与缺失账户都得到 NULL，分不开**：[[lcp-payments-api-reflection-existing-vs-missing]]
- **内连接付款表会把没有付款的账户丢掉**：[[lcp-payments-api-reflection-existing-vs-missing]]
- **存在性问账户表：从账户表出发，用标量子查询求和并 COALESCE 成 0**：[[lcp-payments-api-reflection-existing-vs-missing]]、[[lcp-payments-api-state-and-invariant]]
- **余额不存列、每次现算：少一份要同步的副本**：[[lcp-payments-api-state-and-invariant]]
- **SUM 返回整数，TOTAL 返回浮点数；余额必须是 int**：[[lcp-payments-api-reflection-existing-vs-missing]]
- **记付款是单条 INSERT … SELECT … WHERE EXISTS：检查与写入之间没有缝隙**：[[lcp-payments-api-contract-rules]]
- **先查后写会留下检查与写入之间的空隙，也多一次往返**
- **捕获外键错误：能工作，但会把别的完整性错误一并当成缺失，且在别的数据库里会烧掉序列值**
- **rowcount 为 0 就返回 None；此时 lastrowid 还是上一次的旧值，不能用**：[[lcp-payments-api-contract-rules]]
- **AUTOINCREMENT 把最大 id 记进 sqlite_sequence，删除最后一行后也不复用**：[[lcp-payments-api-state-and-invariant]]
- **不要用 max(id)+1 自己分配 id**
- **重开数据库后账户、付款、余额与两条序列都在**：[[lcp-payments-api-contract-rules]]、[[lcp-payments-api-reflection-verify-balances]]
- **不同的库文件互不共享任何状态：不要用模块级的全局变量存数据**：[[lcp-payments-api-contract-rules]]
- **连接归调用方：函数不关连接，也不自己开关事务**：[[lcp-payments-api-contract-rules]]
- **自动提交模式下每条语句是一个事务，所以单语句操作原子**：[[lcp-payments-api-state-and-invariant]]
- **外键是连接级开关，每次连接都要 PRAGMA foreign_keys=ON**：[[lcp-payments-api-state-and-invariant]]
- **SQL 用参数绑定，不拼字符串**
- **金额是整数分，边界 ±10 亿；余额与 id 到 ±(2^53−1) 仍是精确整数**：[[lcp-payments-api-reflection-verify-balances]]
- **余额的索引：付款表在账户 id 上建索引，否则每次查余额扫全表**：[[lcp-payments-api-state-and-invariant]]
- **测试只经公开函数和重开连接观察，不断言 SQL 文本、语句条数或 sqlite_sequence**：[[lcp-payments-api-reflection-verify-balances]]
- **和纯 Python 字典模型对拍：固定种子的随机操作，夹着重开**：[[lcp-payments-api-reflection-verify-balances]]
- **把合同写成数字例子交给智能体，一次一个失败的测试，不让它改测试迁就代码**：[[lcp-payments-api-contract-rules]]
- **智能体常犯：加存余额的列、先查后写、用 ORM、在 Python 里求和**

## 参考解

```python
from __future__ import annotations

import sqlite3
from dataclasses import dataclass

# ---- 值类型与建库（真实工作区里由 models.py 提供，函数部分单独放进 service.py）----


@dataclass(frozen=True)
class Account:
    id: int
    balance: int


@dataclass(frozen=True)
class Payment:
    id: int
    account: int
    amount: int


SCHEMA = """
CREATE TABLE IF NOT EXISTS accounts (id INTEGER PRIMARY KEY AUTOINCREMENT);
CREATE TABLE IF NOT EXISTS payments (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    account_id INTEGER NOT NULL REFERENCES accounts(id),
    amount     INTEGER NOT NULL
);
"""


def open_database(path: str) -> sqlite3.Connection:
    """打开（或新建）一个数据库文件。自动提交模式：每条语句各自成为一个事务；外键约束打开。"""
    connection = sqlite3.connect(path, isolation_level=None)
    connection.executescript("PRAGMA foreign_keys = ON;" + SCHEMA)  # 外键是连接级开关，每次打开都要设
    return connection


# ---- 三个操作 ----

BALANCE_OF = """
SELECT a.id,
       (SELECT COALESCE(SUM(p.amount), 0) FROM payments AS p WHERE p.account_id = a.id)
FROM accounts AS a
WHERE a.id = ?
"""

# 账户在才会产生一行可插入的数据：存在性检查与写入是同一条语句里的两个部分，中间没有缝隙
PAY_IF_ACCOUNT_EXISTS = """
INSERT INTO payments (account_id, amount)
SELECT a.id, ? FROM accounts AS a WHERE a.id = ?
"""


def create_account(database: sqlite3.Connection) -> Account:
    """新账户：id 由 AUTOINCREMENT 分配，余额必然是 0（还没有任何付款）。"""
    cursor = database.execute("INSERT INTO accounts DEFAULT VALUES")
    return Account(cursor.lastrowid, 0)


def get_account(database: sqlite3.Connection, account_id: int) -> Account | None:
    """账户不存在返回 None；存在但没有付款，余额是 0（COALESCE 把空集的 NULL 换成 0）。"""
    row = database.execute(BALANCE_OF, (account_id,)).fetchone()
    return None if row is None else Account(row[0], row[1])


def create_payment(database: sqlite3.Connection, account_id: int, amount: int) -> Payment | None:
    """给已有账户记一笔付款；账户不存在返回 None，什么都不写（rowcount 为 0），付款 id 原地不动。
    金额可正可负可为零，不检查透支；两笔相同的付款就是两条记录。"""
    cursor = database.execute(PAY_IF_ACCOUNT_EXISTS, (amount, account_id))
    if cursor.rowcount == 0:
        return None
    return Payment(cursor.lastrowid, account_id, amount)


if __name__ == "__main__":
    db = open_database(":memory:")
    first = create_account(db)
    print(first, create_payment(db, first.id, 700), create_payment(db, first.id, -250))
    print(get_account(db, first.id), get_account(db, 99), create_payment(db, 99, 5))
```
