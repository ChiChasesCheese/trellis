# 交易列表视图模型（Transactions List）

**这个项目要做什么。** 把交易转成展示项并保持输入顺序、全部/收入/支出三种筛选只能有一个生效、换新列表时保留当前筛选、快照与输入和后续操作互相独立。

## 设计要点

交易列表视图模型（Transactions List）：参考解。

1. 视图只记两样东西：当前筛选（`all`/`credit`/`debit` 之一）和一份“冻结的行”元组。
2. 来源列表在进入视图的那一刻就被读成冻结的行（`_Row`），之后调用方怎么改自己的对象都碰不到视图。
3. 每次 `snapshot()` 都从冻结的行现造一批新的展示项和筛选项，所以快照之间、快照与视图之间不共享任何可变对象。
4. 换列表时先把新元组完整建好再赋值，旧列表整体丢弃；筛选另存一处，换列表不碰它。
5. 展示用的字符串（金额、日期、地址）一律原样搬运，不解析、不去空白、不重排。

## 考点与卡片

- **快照的 filters 恰好三项，顺序固定 all、credit、debit**：[[lcp-transactions-list-contract-rules]]
- **每项 active 是真布尔，且恰好一项为真，activeFilter 与它一致**：[[lcp-transactions-list-contract-rules]]、[[lcp-transactions-list-state-and-invariant]]
- **默认选中 all；构造之后第一次快照就是完整的**：[[lcp-transactions-list-contract-rules]]
- **all 显示全部；credit、debit 只显示 txnType 与之相等的交易**：[[lcp-transactions-list-contract-rules]]
- **重复选择同一个筛选没有副作用（赋值，不是切换）**：[[lcp-transactions-list-contract-rules]]、[[lcp-transactions-list-reflection-keep-filter]]
- **没有匹配的交易时，所选筛选仍然生效，items 为空，不退回 all**：[[lcp-transactions-list-contract-rules]]、[[lcp-transactions-list-reflection-keep-filter]]
- **一条可见交易恰好一个展示项，顺序就是输入顺序，不排序不去重**：[[lcp-transactions-list-contract-rules]]
- **展示项的 id 取交易的 id，不是 location.id；zipCode 与地点 id 不外泄**：[[lcp-transactions-list-contract-rules]]
- **替换是整体替换：不追加、不合并、不排序；空列表合法**：[[lcp-transactions-list-contract-rules]]、[[lcp-transactions-list-reflection-keep-filter]]
- **换列表保留当前筛选，并立刻作用在新列表上**：[[lcp-transactions-list-contract-rules]]、[[lcp-transactions-list-reflection-keep-filter]]
- **金额与日期是展示文本：不解析、不去空白、不改格式，Unicode 原样**：[[lcp-transactions-list-contract-rules]]
- **输入范围：至多 1000 条、id 在 ±9007199254740991 内可以为负；整数原样通过**：[[lcp-transactions-list-contract-rules]]
- **不修改传入的列表、交易与地点**：[[lcp-transactions-list-contract-rules]]、[[lcp-transactions-list-state-and-invariant]]
- **构造或替换之后调用方再改输入，视图不变：进口读一次，不保存引用**：[[lcp-transactions-list-state-and-invariant]]、[[lcp-transactions-list-reflection-ownership-and-history]]
- **保存引用的缺陷：调用方清空列表，视图就空了**：[[lcp-transactions-list-state-and-invariant]]、[[lcp-transactions-list-reflection-ownership-and-history]]
- **浅拷贝的缺陷：容器独立了，嵌套的交易与地点仍共享，改地址会穿透**：[[lcp-transactions-list-state-and-invariant]]、[[lcp-transactions-list-reflection-ownership-and-history]]
- **进口就投影成冻结的行（frozen dataclass），字符串与整数本身不可变**：[[lcp-transactions-list-state-and-invariant]]
- **内部状态只有两个字段：当前筛选名和冻结行的元组**：[[lcp-transactions-list-state-and-invariant]]、[[lcp-transactions-list-reflection-keep-filter]]
- **筛选与列表是两个独立的状态变量，选择只写前者，替换只写后者**：[[lcp-transactions-list-reflection-keep-filter]]
- **替换先建完整元组再赋值：中途出错时旧列表还在**：[[lcp-transactions-list-reflection-keep-filter]]、[[lcp-transactions-list-state-and-invariant]]
- **快照每次现造：新的 FilterState、TransactionItem 和列表，不缓存**：[[lcp-transactions-list-state-and-invariant]]、[[lcp-transactions-list-reflection-ownership-and-history]]
- **快照被改（改字段、增删项、改筛选项）不影响视图和别的快照**：[[lcp-transactions-list-reflection-ownership-and-history]]
- **旧快照在之后的选择与替换后保持原样；两次快照没有共享的可变对象**：[[lcp-transactions-list-reflection-ownership-and-history]]
- **不同实例互不影响：没有类级或模块级的可变状态**：[[lcp-transactions-list-reflection-ownership-and-history]]
- **可变快照与不可变快照合同都接受；选可变数据类，因为界面与适配层已按它写好**：[[lcp-transactions-list-reflection-ownership-and-history]]
- **筛选用元组常量加一行判断，拒绝为三个字符串建策略类**
- **未知筛选名合同不要求处理；要拒绝就在 selectFilter 开头加一行**
- **并发不在合同内；若要加，把 (筛选, 列表) 合成一个冻结状态整体替换**
- **规模：1000 行一次快照 O(n) 约 70 微秒；十万行再按类型预分组或分页**
- **测试隔离的方式：先拍下整份期望快照，破坏后断言整份相等（asdict 比较）**：[[lcp-transactions-list-reflection-ownership-and-history]]
- **隔离测试必须在保存引用与浅拷贝的实现上失败，否则它什么也没断言**：[[lcp-transactions-list-reflection-ownership-and-history]]
- **示例里的三步（选支出、换成一条、换成空）逐字写成测试，用乱序 id 防排序**：[[lcp-transactions-list-contract-rules]]
- **指挥编程智能体：先交规则与示例，一次只给一个失败的测试，自己读 __init__**
- **智能体常犯的错：保存调用方列表、只做浅拷贝、返回内部列表、换列表时重置筛选**
- **模板的 __init__ 直接保存传入的列表：开工第一步就要改掉它**：[[lcp-transactions-list-state-and-invariant]]

## 参考解

```python
from __future__ import annotations

from dataclasses import dataclass

FILTERS = ("all", "credit", "debit")  # 对外固定的筛选顺序


@dataclass
class Location:
    id: int
    address: str
    city: str
    zipCode: int


@dataclass
class Transaction:
    id: int
    date: str
    txnType: str
    amount: str
    location: Location


@dataclass
class FilterState:
    filter: str
    active: bool


@dataclass
class TransactionItem:
    id: int
    address: str
    city: str
    amount: str
    date: str


@dataclass
class ListSnapshot:
    activeFilter: str
    filters: list[FilterState]
    items: list[TransactionItem]


@dataclass(frozen=True, slots=True)
class _Row:
    """一条交易里视图真正需要的全部内容：冻结，所以放进元组后没有任何代码能再改它。"""

    kind: str
    id: int
    address: str
    city: str
    amount: str
    date: str

    @classmethod
    def read(cls, txn: Transaction) -> _Row:
        # 只在这里碰调用方的对象；字符串和整数本身不可变，读出来就是独立的值
        return cls(txn.txnType, txn.id, txn.location.address, txn.location.city, txn.amount, txn.date)

    def visible_under(self, active: str) -> bool:
        return active == "all" or self.kind == active

    def to_item(self) -> TransactionItem:
        return TransactionItem(self.id, self.address, self.city, self.amount, self.date)


def _freeze(transactions: list[Transaction]) -> tuple[_Row, ...]:
    return tuple(_Row.read(t) for t in transactions)


class TransactionsList:
    def __init__(self, transactions: list[Transaction]) -> None:
        self._rows = _freeze(transactions)
        self._active = "all"

    def selectFilter(self, filter: str) -> None:
        self._active = filter

    def replaceTransactions(self, transactions: list[Transaction]) -> None:
        self._rows = _freeze(transactions)  # 建完再赋值：中途出错时旧列表还在

    def snapshot(self) -> ListSnapshot:
        active = self._active
        return ListSnapshot(
            active,
            [FilterState(name, name == active) for name in FILTERS],
            [row.to_item() for row in self._rows if row.visible_under(active)],
        )
```
