# 关注演员与上新通知修复（Actor Follows & Notifications）

**这个项目要做什么。** 关注与取关、新片上线时每位关注者只收一条通知、重复导入幂等与冲突拒绝、收件箱按插入序返回独立快照、并发安全。

## 设计要点

关注演员与新片通知（修复版），设计五行：

1. 关注关系只存一份反向索引"演员 -> 关注者集合"：新片上线时对卡司求并集，天然每人一份，也不必遍历全部用户。
2. 电影 id 对应一条冻结记录（片名、卡司集合）；重复导入拿新记录和旧记录比较：相同返回 False，不同抛冲突。
3. 一把锁罩住"判重、算受众、登记电影、写收件箱"；校验和冲突检查都在第一次写入之前，失败不留痕。
4. 收件箱按插入顺序追加冻结的 `Notice`，读取返回新列表；取关只动索引，不动历史。
5. 集合清空时立刻删除，关注索引的大小只和现存的关注关系成正比。

## 考点与卡片

- **受众是关注了卡司任一演员的用户，不是关注全部演员的用户**：[[lcp-actor-follow-notifications-contract-rules]]
- **同时关注两位主演的用户只收一条通知**：[[lcp-actor-follow-notifications-contract-rules]]
- **卡司里重复的演员 id 不会让用户多收通知**
- **空卡司不通知任何人；子集判断会让空卡司通知所有人**：[[lcp-actor-follow-notifications-contract-rules]]
- **按演员建反向索引，受众是关注者集合的并集**：[[lcp-actor-follow-notifications-state-and-invariant]]
- **关注不回填登记之前的电影**：[[lcp-actor-follow-notifications-contract-rules]]
- **取关只删这一条关系，不删已收到的历史通知**：[[lcp-actor-follow-notifications-contract-rules]]
- **重复关注和取关不存在的关系都是无操作**：[[lcp-actor-follow-notifications-contract-rules]]
- **取关到没人关注时索引里不留空集合**：[[lcp-actor-follow-notifications-state-and-invariant]]
- **相同的重复导入返回 False 且不通知，哪怕关注者变了**：[[lcp-actor-follow-notifications-contract-rules]]
- **卡司按集合比较，顺序和重复不影响相等**
- **同 id 不同片名或不同卡司集合抛 movie_conflict 且状态不变**：[[lcp-actor-follow-notifications-contract-rules]]
- **冲突检查在所有写入之前，所以不需要回滚**：[[lcp-actor-follow-notifications-reflection-atomic-boundary]]
- **片名逐字比较，区分大小写和首尾空白**
- **校验先于冲突检查，非法输入得到 ValueError**：[[lcp-actor-follow-notifications-contract-rules]]
- **非法输入在拿锁之前、改状态之前抛 invalid_input**：[[lcp-actor-follow-notifications-contract-rules]]
- **空白判定用合同列出的字符表，不用 strip 或 isspace**
- **U+00A0、U+0085、U+2007、U+202F 是合法字符**
- **空串是空白；None、数字、bool、字节串都不是合法的 id**
- **actors 只收 list，元组、集合、生成器都是非法输入**
- **先复制 actors 再校验同一份副本，避免校验后被调用方改动**：[[lcp-actor-follow-notifications-state-and-invariant]]
- **收件箱按登记顺序返回，不是按 id 排序**：[[lcp-actor-follow-notifications-contract-rules]]
- **inbox 返回新列表，调用方改它不影响内部**：[[lcp-actor-follow-notifications-contract-rules]]、[[lcp-actor-follow-notifications-state-and-invariant]]
- **之后的导入不会改变已经拿到的快照**：[[lcp-actor-follow-notifications-state-and-invariant]]
- **Notice 是冻结数据类，浅拷贝列表就足够独立**：[[lcp-actor-follow-notifications-state-and-invariant]]
- **check-then-act：两个线程都看到电影不存在会产生两个 True**：[[lcp-actor-follow-notifications-reflection-atomic-boundary]]
- **判重、算受众、写电影、写收件箱必须在同一个临界区**：[[lcp-actor-follow-notifications-reflection-atomic-boundary]]、[[lcp-actor-follow-notifications-state-and-invariant]]
- **电影表与关注索引分两把锁，结果不对应任何串行顺序**
- **取关与登记并发：收件箱 0 条或 1 条都合法，不能是 2 条**
- **先算后写：把可能失败的只读工作放在写入之前**：[[lcp-actor-follow-notifications-reflection-atomic-boundary]]、[[lcp-actor-follow-notifications-state-and-invariant]]
- **用屏障让线程同时起跑，不用 sleep，断言不变量**
- **第一条指令带合同规则和具体数据，先让测试变红再修**
- **每次只让智能体修一个缺陷、重跑全部测试、读 diff**
- **锁的范围、校验与冲突的先后、受众算法由自己决定**
- **已读与分页只动收件箱：下标是稳定游标，水位只增不减**
- **按渠道发送时观察者才有位置，现有三块状态不动**
- **事务发件箱：电影与待发通知在同一个事务里提交**：[[lcp-actor-follow-notifications-reflection-outbox]]
- **发件箱投递至少一次，接收端用 (用户, 电影 id) 去重**：[[lcp-actor-follow-notifications-reflection-outbox]]
- **超大演员推拉结合：大 V 读扩散，需要记录关注区间**：[[lcp-actor-follow-notifications-reflection-ten-million-followers]]
- **一把锁罩住全部受众时，持锁时间随关注者数增长**：[[lcp-actor-follow-notifications-reflection-ten-million-followers]]

## 参考解

```python
from __future__ import annotations

import threading
from collections.abc import Iterable
from dataclasses import dataclass

INVALID_INPUT = "invalid_input"
MOVIE_CONFLICT = "movie_conflict"

# 合同逐个列出的"空白字符"：不能用 str.strip() / str.isspace()，它们还会把 U+0085、U+00A0、U+2007、U+202F 当成空白。
_BLANK_CHARS = frozenset(
    "\t\n\v\f\r\x1c\x1d\x1e\x1f  "
    "          "
    "   　"
)


def _valid(value: object) -> str:
    """合法的标识符：是 str，且至少有一个非空白字符。空串也是空白。"""
    if not isinstance(value, str) or all(ch in _BLANK_CHARS for ch in value):
        raise ValueError(INVALID_INPUT)
    return value


@dataclass(frozen=True)
class Notice:
    movie_id: str
    title: str


@dataclass(frozen=True)
class _Movie:
    """一部已登记的电影。卡司是集合：顺序和重复都不影响相等。"""

    title: str
    cast: frozenset[str]


class MovieCatalog:
    """电影登记表，"新电影／重复导入／冲突"只在这里判定。不带锁，由服务的锁保护。"""

    def __init__(self) -> None:
        self._movies: dict[str, _Movie] = {}

    def is_new(self, movie_id: str, movie: _Movie) -> bool:
        """只读判定：没见过返回 True；记录完全相同返回 False；同 id 不同内容抛冲突。不修改任何东西。"""
        known = self._movies.get(movie_id)
        if known is None:
            return True
        if known != movie:
            raise RuntimeError(MOVIE_CONFLICT)
        return False

    def add(self, movie_id: str, movie: _Movie) -> None:
        self._movies[movie_id] = movie

    def __len__(self) -> int:
        return len(self._movies)


class Subscriptions:
    """关注索引：演员 -> 关注者集合。不带锁，由服务的锁保护。"""

    def __init__(self) -> None:
        self._followers: dict[str, set[str]] = {}

    def follow(self, user: str, actor: str) -> None:
        self._followers.setdefault(actor, set()).add(user)

    def unfollow(self, user: str, actor: str) -> None:
        users = self._followers.get(actor)
        if users is None:
            return
        users.discard(user)
        if not users:
            del self._followers[actor]

    def audience(self, cast: Iterable[str]) -> set[str]:
        """关注了卡司中至少一人的用户，每人一次。"""
        users: set[str] = set()
        for actor in cast:
            users.update(self._followers.get(actor, ()))
        return users

    @property
    def edge_count(self) -> int:
        return sum(len(users) for users in self._followers.values())

    @property
    def actor_count(self) -> int:
        return len(self._followers)


class Inboxes:
    """每个用户一份按插入顺序追加的通知历史。不带锁，由服务的锁保护。"""

    def __init__(self) -> None:
        self._notices: dict[str, list[Notice]] = {}

    def deliver(self, users: Iterable[str], notice: Notice) -> None:
        for user in users:
            self._notices.setdefault(user, []).append(notice)

    def snapshot(self, user: str) -> list[Notice]:
        """新列表；`Notice` 本身是冻结的，所以调用方拿到的和内部状态互不影响。读不创建条目。"""
        return list(self._notices.get(user, ()))


class NotificationService:
    """所有公开方法都在同一把锁下执行：任意并发调用等价于某一个串行顺序（可线性化）。"""

    def __init__(self) -> None:
        self._lock = threading.Lock()
        self._catalog = MovieCatalog()
        self._subscriptions = Subscriptions()
        self._inboxes = Inboxes()

    def follow(self, user: str, actor: str) -> None:
        _valid(user)
        _valid(actor)
        with self._lock:
            self._subscriptions.follow(user, actor)

    def unfollow(self, user: str, actor: str) -> None:
        _valid(user)
        _valid(actor)
        with self._lock:
            self._subscriptions.unfollow(user, actor)

    def add_movie(self, movie_id: str, title: str, actors: list[str]) -> bool:
        _valid(movie_id)
        _valid(title)
        if not isinstance(actors, list):
            raise ValueError(INVALID_INPUT)
        # 先把调用方的列表复制成不可变集合再校验：之后调用方怎么改它，校验过的内容都不变。
        cast = frozenset(_valid(actor) for actor in list(actors))
        movie = _Movie(title, cast)
        with self._lock:
            if not self._catalog.is_new(movie_id, movie):
                return False
            # 到这里不会再失败：先算出受众，再一并提交，电影和通知要么都在要么都不在。
            audience = self._subscriptions.audience(cast)
            self._catalog.add(movie_id, movie)
            self._inboxes.deliver(audience, Notice(movie_id, title))
            return True

    def inbox(self, user: str) -> list[Notice]:
        _valid(user)
        with self._lock:
            return self._inboxes.snapshot(user)

    @property
    def subscription_count(self) -> int:
        """现存的（用户，演员）关注关系个数。"""
        with self._lock:
            return self._subscriptions.edge_count

    @property
    def tracked_actor_count(self) -> int:
        """至少有一个关注者的演员个数：最后一个关注者取关后应当归零。"""
        with self._lock:
            return self._subscriptions.actor_count

    @property
    def movie_count(self) -> int:
        with self._lock:
            return len(self._catalog)


if __name__ == "__main__":
    service = NotificationService()
    service.follow("alice", "actor-1")
    service.follow("alice", "actor-2")
    service.follow("bob", "actor-2")
    print(service.add_movie("m1", "Opening Night", ["actor-1", "actor-2", "actor-1"]))
    print(service.add_movie("m1", "Opening Night", ["actor-2", "actor-1"]))
    print(service.inbox("alice"), service.inbox("bob"))
    try:
        service.add_movie("m1", "Another Title", ["actor-1"])
    except RuntimeError as exc:
        print("conflict:", exc)
```
