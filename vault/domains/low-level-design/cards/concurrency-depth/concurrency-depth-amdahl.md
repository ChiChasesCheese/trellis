## Q
一个任务 90% 的时间可以并行，加到 64 个 worker 能快多少倍？8 个进程跑纯 Python 计算，为什么实测只快了 5.5 倍而不是 8 倍？

## A
**上限由串行部分决定：加速比 ≤ 1 / (1 − p)**

- **阿姆达尔定律（Amdahl's law）**：并行占比 p、worker 数 n，加速比 = 1 / ((1 − p) + p / n)。p = 0.9 时，n = 8 是 4.7 倍，n = 64 是 8.8 倍，n 无穷大也只有 10 倍；
- **串行部分是什么**：持锁的区间、最后的合并、进程的启动和参数的序列化（pickle）、收集结果、读同一个磁盘；
- **实测（3.11，12 核机器，把 8 个 800 万次循环的纯 Python 任务交给 `ProcessPoolExecutor`）**：2、4、8 个进程分别是 1.99、3.52、5.54 倍。由公式反推的串行占比约 0.5%、4.5%、6.3%，随 worker 数上升（进程启动、通信、核的快慢不一都摊在里面）；
- **同样的任务用 3.11 的线程池**：0.98–1.01 倍，因为 GIL 让整个函数都是串行的，p ≈ 0；3.14t（free-threaded）上同样的线程池 8 线程 4.3 倍；
- **用它做判断**：先量出串行占比再决定要不要并行；占比 20% 的任务，买再多核也不会超过 5 倍。

```python
def speedup(p, n):                 # p：可并行占比，n：worker 数
    return 1 / ((1 - p) + p / n)

for p in (0.5, 0.9, 0.99):
    print(p, [round(speedup(p, n), 1) for n in (2, 8, 64)], round(1 / (1 - p), 1))
# 0.5  [1.3, 1.8, 2.0]   2.0
# 0.9  [1.8, 4.7, 8.8]   10.0
# 0.99 [2.0, 7.5, 39.3]  100.0
```

**知识点：**并行加速与锁竞争（Parallel Speedup & Contention）
