## Q
一份机器编码答案里给关键方法都加上类型注解，在设计评审时具体帮面试官验证了什么？

## A
面试官不需要读完实现细节，只看签名就能确认关键契约：这个参数是否可能是 `None`（要不要处理空）、返回的是共享的可变集合还是快照、这个 ID 是不是被强类型区分开（不会和另一种 ID 混用）。注解等于把“这个接口打算怎么被正确使用”提前写在纸面上，让评审可以在读实现之前先判断设计对不对，也让面试官更快定位“这里没加注解、说明作者自己也没想清楚这个边界情况”的地方。
