## Q
在 LeetCode Project 的浏览器 IDE 里，你已经把 README 的规则列成清单，现在要把一个从接口实现的项目分给右侧的编程智能体。用时 45 分钟，已过去 8 分钟。你怎么把工作拆给它？每条指令写什么？

## A
**评分点**
- 说出按能独立验证的小块拆：每块有明确的输入输出和一个失败的测试，而不是一次写完整个项目
- 说出每条指令带着相关规则和数字例子，并限定只改哪个文件、哪个函数，不许改测试和公开签名
- 说出先让它起草边界清楚、容易验证的部分，把难点和共享状态的部分留到你定好设计之后
- 说出必要时先让它说出计划再动手，计划与你的清单对不上就先纠正
- 说出一次只推进一块，通过之后再给下一块，不要同时开几条互相依赖的改动
- 说出把已确定的规则写在指令里重复给它，因为它不会记得你脑子里的假设

<details class="pt"><summary>参考答案</summary>

把工作切成"一块一个失败用例"：先给它规则清单中和这一块有关的几条、一个数字例子、"只改这个函数，不动测试和签名"。先让它做边界清楚的部分，共享状态与并发这类难点等你定了方案再给。每次只推进一块，通过再给下一块；它的计划与你的清单对不上，先纠正再让它写。

</details>

**知识点：** 拆成可验证的小步（Decomposition）、写清任务（Specifying the Task）、AI 辅助编码轮（AI-Assisted Round）
