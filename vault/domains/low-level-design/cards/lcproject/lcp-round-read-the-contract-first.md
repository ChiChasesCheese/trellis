## Q
你打开一个 LeetCode Project：浏览器里是 Eclipse Theia 写成的 IDE，工作区有 README、要填写的模板文件、只读的公开测试（点 Run 运行）、写着书面问题的 REFLECTION.essay，右侧是 AI 智能体面板（模型可选，有 Manual 模式），倒计时已经开始。项目可能是按接口从零实现、修复出问题的服务、或处理带数据修复的线上事故。你在对智能体说第一句话之前先做什么？

## A
**评分点**
- 说出先把 README 读完，把产品规则逐条列成清单：输入输出、返回形状、错误优先级、边界取整、失败后留下什么
- 说出读模板文件的公开 API，签名和返回形状不能改，因为提交时由隐藏测试和现成代码调用
- 说出把公开测试当作格式示例来读，并清楚它只是规则的一部分：隐藏测试会提交时才跑
- 说出扫一遍 REFLECTION 的问题：它们暗示评分关心什么，编码时就边写边记要回答的素材
- 说出按任务类型选第一步：实现类先读接口和测试；修复类先跑测试看失败；事故类先读数据和日志，不先改代码
- 说出合同里没写清的地方当场列成假设并确定下来，而不是让智能体去猜

<details class="pt"><summary>参考答案</summary>

先不碰智能体。读完 README，把规则写成十来行清单：返回形状、边界值怎么取整、哪个错误先于哪个、失败后是否留下痕迹。再读模板的公开 API 和公开测试，记下哪些例子是格式、哪些规则测试没覆盖。瞄一眼 REFLECTION 的问题，边写边攒答案。实现类先读接口，修复类先跑出失败，事故类先看数据。含糊的地方写成明确假设。

</details>

**知识点：** AI 辅助编码轮（AI-Assisted Round）、写清任务（Specifying the Task）、扩展现有代码轮（Extend Existing Code）
