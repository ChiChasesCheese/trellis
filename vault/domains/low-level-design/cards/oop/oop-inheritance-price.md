## Q
继承用一个关键字就买到了多态加代码复用。它收取了哪些组合不收的代价？

## A
- **可选方案里最强的耦合**：子类依赖基类内部——改基类就会打断子类（fragile base class，脆弱基类）。
- **公开的 is-a 承诺**：基类的每一条契约从此都约束你（Liskov 替换原则），并且永久成为你 API 的一部分。
- Python 允许**多继承**，代价搬到了 **MRO（方法解析顺序）**上：菱形继承时到底调用哪个祖先的方法，取决于 C3 线性化的结果——改一下某个基类的继承链，就可能悄悄改变一个原本无关的子类的行为。

所以：为可替换的 is-a 而继承，为复用而组合。
