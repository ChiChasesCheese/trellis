## Q
如果要把一个单线程设计的内存文件系统改成支持多线程并发调用，为什么给每个目录单独加一把细粒度的锁，会比给整个文件系统加一把全局锁更难正确实现？

## A
`move` 这类操作天然要同时触及两个不同的目录——源路径所在的目录和目标路径所在的目录——如果每个目录一把锁，`move` 就必须同时持有两把锁，这正是经典的死锁场景：两个线程分别把两个目录反过来移动，各自先锁住了对方想要的那把锁，就会永久互相等待。避免的办法是按某种稳定的顺序（比如路径的字典序）决定先锁哪一个，但这个规则必须在每一处需要同时锁两个目录的地方都被遵守，一旦有一处遗漏就会重新引入死锁。给整个文件系统加一把锁没有这个问题——任意时刻只有一个调用方在操作树，`move` 天然不需要考虑加锁顺序，代价是牺牲了并发度，但正确性容易验证得多。
