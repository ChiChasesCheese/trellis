## Q
实现内存文件系统的 `move(src, dst)` 时，如果先把 `src` 从原目录的字典里摘下来、再去解析 `dst` 是否合法，这个实现顺序有什么真实的风险？应该怎么改？

## A
如果先摘下节点、再验证目标，一旦目标路径本身不合法（比如父目录不存在、或者目标名字已经被占用），节点已经被摘下但还没有放到任何地方——异常抛出之后这个节点直接从树里丢失了，是一次真实的数据丢失。更隐蔽的一种情况是：如果 `dst` 恰好是 `src` 自己的子孙路径，先摘再验证甚至会把这个目录重新接到它自己的子树下面，造出一个真实的环，之后任何递归遍历它的操作（比如求体积、复制、查找）都会无限循环下去。正确的做法是在真正摘下节点之前，先完整验证目标路径合法（父目录存在、名字未被占用、目标不是源路径自己或自己的子孙路径），全部通过之后才做“摘下、放入”这两步，保证 `move` 要么完全成功、要么完全不改变树。
