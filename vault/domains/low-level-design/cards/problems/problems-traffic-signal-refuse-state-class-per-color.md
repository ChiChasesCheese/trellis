## Q
交通信号灯（Traffic Signal）设计里，为什么不给每个颜色写一个状态类、也不把控制器做成单例？

## A
**状态模式（State）值得上，是当每个状态都有成套的、彼此不同的进入与退出副作用时**，而不是「状态多」时。这道题里三个阶段（绿 / 清空 / 全红）的行为差异只有两点：给哪些流向设哪个显示、倒计时多少格。用一个枚举加三个分支写完只要十几行；换成六个类（三个颜色 + 每个相位一个），加一个相位就要再加两个类，而且「相位怎么轮转」这条主线被拆到六个文件里，再没有一个地方能一眼看完。

**单例同理是错的**：「一个路口只有一台信号机」是业务事实，不是拦截构造函数的理由。做成单例之后，一个进程里跑两个路口的仿真就不可能了——而那恰恰是这道题最有用的测试场景（验证「加行人相位不动引擎」时，你需要现场造第二个路口）。

同样该删的还有只转发调用的 `Road` 和只存一个枚举值的 `TrafficLight`：在 Python 里它们就是一个字典加一个枚举。
