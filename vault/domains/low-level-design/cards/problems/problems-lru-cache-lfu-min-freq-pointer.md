## Q
LFU（最不经常使用）缓存怎么把淘汰操作做到 O(1)？`min_freq` 这个指针是干什么用的，什么时候需要往前推进？

## A
把 key 按访问频率分组，每个频率对应一条独立的双向链表（同一频率内部按最近使用排序，频率相同时淘汰该频率桶里最久未用的那个）；只保留非空的桶，一个桶被搬空就立刻从桶表里删掉，否则一个被反复读取的热 key 会在自己身后留下无数个空桶，白白占内存。`min_freq` 始终等于“当前存在的桶里最小的那个频率”，淘汰时直接弹出这个桶的头部，不需要遍历所有 key 去找最小频率，这就是 O(1) 的关键。`min_freq` 在两类时机下需要更新：任意 key 被新插入时，直接重置为 1（新 key 的初始频率一定是 1，且一定是当前最小）；无论是访问导致某个 key 的频率升级、淘汰弹出受害者、还是主动删除某个 key，只要这一步操作恰好把 `min_freq` 当前指向的桶搬空了，就要重新算成“现存桶里最小的那个频率”（而不是简单地加一，因为搬空之后下一个非空的频率不一定紧挨着）。最常见的手滑有两处：一是每次访问后都无条件把 `min_freq` 加一，而不检查“旧桶是否真的变空了”；二是只在插入时维护 `min_freq`，误以为淘汰之后一定紧跟着插入，结果连续淘汰多次而中间不插入时，在一个早已不存在的频率上找桶。
