## Q
**Bean 注册表：按名查、按序遍历、按依赖反序销毁**｜Spring Framework · 7.0

Spring 容器要记住成百上千个 Bean 的定义（怎样创建这个 Bean 的说明书）：按名字取要快，启动时要按注册先后遍历，关闭时还要先销毁依赖别人的那些。这几件事各靠什么结构？

## A
**背景。** 启动时容器一个个注册 Bean 定义，之后按注册顺序预先创建所有非懒加载的单例；关闭时必须“被依赖的最后走”，否则 A 还在用 B，B 已经被销毁了。

| 操作 | 要求 |
|---|---|
| 按名字取定义 | O(1) |
| 注册时判断重名 | O(1) |
| 按注册顺序遍历 | 顺序固定 |
| 谁依赖我、我依赖谁 | 两个方向都 O(1) |
| 关闭容器 | 依赖我的先销毁 |

**难点。** 哈希表按名字找是 O(1)，但没有顺序；列表有顺序，按名字找却要 O(n)；单向的依赖表答不了“谁依赖我”。每个要求交给一个结构：一张 Map、一个名字列表、两张方向相反的依赖表。Python 3.7 起 `dict` 自带插入顺序，一张就能兼任前两个；Java 的 `ConcurrentHashMap` 不保序，Spring 里就拆成了两份。
