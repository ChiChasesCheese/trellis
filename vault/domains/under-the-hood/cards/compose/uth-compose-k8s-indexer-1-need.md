## Q
**本地缓存要支持哪些查法**｜Kubernetes · client-go v0.37

client-go 的本地缓存除了按 key 取对象，还要按命名空间、按节点列出对象。为什么一张 map 不够？

## A
**背景。** 控制器不想每次都问 API server（集群的中心服务，一次请求要走网络），所以 client-go 把关心的对象同步一份放在本地内存里。控制器的查法有好几种：按 key（`命名空间/名字`）取一个 Pod；列出某个命名空间的全部 Pod；列出某个节点上的全部 Pod；列出引用了某个 PVC（持久卷声明）的全部 Pod。

| 操作 | 要求 |
|---|---|
| `Get(key)` | O(1) |
| 增、改、删一个对象 | 主表和所有索引一起更新，读者看不到半新半旧 |
| 按某个索引值列出对象 | 只和结果个数有关，不扫全表 |
| 对象的索引值变了 | 旧分组里摘掉，新分组里挂上 |
| 运行中新增一种查法 | 对已有对象补建索引 |

**为什么。** 一张 `key → 对象` 的 map，按 key 查是 O(1)，按命名空间列出却要扫整张表。集群里有上万个 Pod，控制器每轮都扫一遍，受不了。办法是为每一种查法另建一张索引表：先按"命名空间"分好组，查的时候直接取那一组。
