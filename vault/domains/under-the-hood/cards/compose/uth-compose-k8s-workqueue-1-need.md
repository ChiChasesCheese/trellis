## Q
**工作队列要满足什么**｜Kubernetes · client-go v0.37

控制器的工作队列要同时满足哪几条要求？为什么单用一个队列或一个集合都不行？

## A
**背景。** 控制器（controller）是一个不停循环的程序：发现 Pod、Deployment 这类对象变了，就把实际状态改成期望状态。变化事件由 informer（把集群数据同步到本地缓存的组件）发来，控制器不在回调里直接干活，而是把对象的 key（`命名空间/名字`）放进工作队列，几个 worker（工作线程）再取出来处理。同一个对象可能在上一次处理完之前，又连续变了好几次。

| 操作 | 要求 |
|---|---|
| `Add(key)` | 任意线程随时调用，O(1) |
| 排队中的 key 再被 `Add` | 不重复排队，只留一份 |
| `Get()` | 先来先取；队列空就睡眠等待 |
| key 正被某个 worker 处理 | 其他 worker 不能同时取到它 |
| 处理中又被 `Add` | 不能丢，处理完要再来一轮 |
| `Done(key)` | worker 处理完后调用 |

**为什么。** 只用队列：`Add` 十次就排十份，白白处理十遍，还可能两个 worker 同时改同一个对象。只用集合：没有先后顺序，也看不出"正在处理"。把多个事件合成一次处理不会丢信息，因为 worker 拿到 key 后，会去本地缓存读该对象的最新状态，不看是哪次事件。
