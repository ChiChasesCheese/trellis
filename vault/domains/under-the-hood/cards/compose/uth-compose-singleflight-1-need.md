## Q
**同时到来的重复请求**｜Go · golang.org/x/sync v0.24

缓存里的热点 key 刚好过期，1000 个请求同时去查数据库，怎样让数据库只被查一次？

## A
**背景。** 首页数据缓存在 Redis 里，过期的那一瞬间，比如 1000 个请求同时发现"缓存没有"，于是 1000 个请求同时去查数据库，数据库被压垮，这叫缓存击穿。这 1000 次查的是同一份数据，只要一个请求去查，其余的等它的结果就够了。

| 操作 | 要求 |
|---|---|
| `Do(k, fn)` 先到 | 真的执行 `fn` |
| `Do(k, fn)` 同 key 正在执行时到达 | 不执行 `fn`，等结果，拿到同样的返回值 |
| 不同 key | 互不影响，并行执行 |
| `fn` 结束后 | 这个 key 的记录清掉，下一次重新执行 |
| 判断先到还是后到 | 两个线程同时到，只能有一个先到 |

**为什么。** 一把全局锁：不同 key 也被迫排队。每个 key 一把锁：锁表自己要有人保护，用完还要清理。把结果存起来：那是缓存的事，这里只合并"同时在飞"的调用。要的是一张"正在进行的调用"表，加一个让后到者睡眠、等先到者喊醒的办法。
