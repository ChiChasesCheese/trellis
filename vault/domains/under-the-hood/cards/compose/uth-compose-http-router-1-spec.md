## Q
**路由表要同时做到什么**｜httprouter · v1.3.0

Web 框架收到 `GET /user/42`，要立刻找到处理函数，还要取出 `42`。路由表要支持哪些操作？为什么一张哈希表不够？

## A
**背景。** 注册路由时写 `GET /user/:id`，其中 `:id` 是占位符（placeholder），能匹配任意一段路径。请求来了，按真实路径查出处理函数（handler）。路由表要支持：

| 操作 | 要求 |
|---|---|
| 注册 `add(方法, 模式, 处理函数)` | 启动时做一次，要能发现互相冲突的路由 |
| 查找 `find(方法, 路径)` | 每个请求都做，要快，最好不分配内存 |
| 取参数 | 查到处理函数的同时带出 `:id` 对应的 `42` |
| 路由条数增加 | 查找不能跟着变慢 |

只用一张 `dict[路径, 处理函数]`：静态路径是 O(1)，但 `/user/42` 和 `/user/43` 是两个键，占位符没法匹配。逐条拿模式去匹配，能支持占位符，却要扫遍所有路由，O(路由条数)。路径本来就是一层一层的，所以改用树：沿路径往下走，每走一段就排除掉一大片路由。
