## Q
**Decimal 和 Fraction 什么时候用**｜Python · CPython 3.14

记账不想要 `0.30000000000000004`，标准库里有哪两个精确的数值类型？各自付出了什么代价？

## A
**背景。** 问题出在「二进制写不出 0.1」，所以有两条出路：改用十进制存，或者干脆存成分数。

**结构。**

| | `float` | `Decimal` | `Fraction` |
|---|---|---|---|
| 存什么 | 二进制近似 | 十进制数字 + 小数点位置 | 分子 / 分母 |
| `0.1 + 0.2` | `0.30000000000000004` | `0.3` | `3/10` |
| 怎么算 | 硬件直接算 | 软件逐位算 | 每次求最大公约数约分 |

**细节。**

- `Decimal` 默认保留 28 位有效数字，舍入默认是四舍六入五取偶（`ROUND_HALF_EVEN`）；CPython 的 C 实现基于 libmpdec 库。
- `Fraction` 创建时用 `math.gcd` 约分，`Fraction(1, 3) * 3 == 1` 精确成立。

**坑。** 必须用字符串构造：`Decimal(0.1)` 会把 `float` 里已有的误差原样搬进来，得到 `Decimal('0.1000000000000000055511151231257827021181583404541015625')`。

**为什么。** 金额要和人工账目逐位对得上，用 `Decimal`；要精确的有理数，用 `Fraction`；科学计算容得下误差，用硬件直接算的 `float`。
