## Q
结果看板和分诊界面应该提供哪些视图，才能让分诊从"翻日志"变成"看趋势"？

## A
- **测试 × 运行网格**：行是测试，列是按时间排的运行（或提交），格子是红绿色。Kubernetes 社区用的 TestGrid 就是这种视图。一眼能分辨三种形状：
  - 某列整列变红 → 那次运行的环境或构建坏了；
  - 某行从某列开始一直红 → 那个提交引入了回归；
  - 某行红绿交错 → flaky。
- **"新失败"列表**：只列出"上次通过、这次失败"的测试，并按失败指纹分组。分诊从这里开始，而不是从全部失败开始。已知问题自动标注对应的缺陷单。
- **失败聚类视图**：同一个失败指纹影响了哪些测试、哪些机器、从哪天开始，点进去是代表性日志。50 条测试因同一个原因失败，只需要分诊一次。
- **单测试历史页**：这条测试最近 N 次结果、耗时曲线、按机器和配置拆分的失败率、负责人、相关缺陷单。
- **分支和发布视图**：主干、各发布分支、当前发布候选各自的必过套件状态，用于发布决策。
- **基础设施视图**：错误（`error`）与失败（`failure`）分开统计，按机器、按资源类型的失败率，用于发现坏机器。

**交互上要做到**：
- 从任何一个红格子两次点击之内到达日志和版本信息；
- 能把一个失败标注为"已知问题 / flaky / 环境"，标注写回结果库，统计时可以过滤；
- 支持按组件、负责人、档位筛选，让每个团队只看自己的。

衡量看板好不好：值班的人每天早上多少分钟能把夜间失败全部归类完。
