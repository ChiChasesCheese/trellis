## Q
面试里被问"同一个测试在你的机器上通过，在 CI 上失败，你怎么处理？怎么从根本上避免"，怎么答？

## A
- **先找差异，不先改测试**：两边结果不同，一定有输入不同。列出候选：依赖版本、操作系统和镜像、环境变量（时区、语言、`PYTHONHASHSEED`）、并行和执行顺序、网络、机器硬件、文件路径和权限。
- **在 CI 的环境里复现**：拉同一个镜像，用同样的命令和参数本地跑；对比两边的 `pip freeze` 或 `uv pip list`、环境变量和执行顺序。顺序问题用 `pytest-randomly` 打乱顺序，再用 `--randomly-seed=<种子>` 原样复现。
- **修根因**：没锁的依赖进锁文件，`latest` 镜像换成摘要，读当前时间的地方注入时钟，写共享路径的改成 `tmp_path`，访问网络的改用替身或固定数据。
- **从根本上避免**：本地和 CI 用同一个容器镜像和同一条命令（例如 `make test` 或 `uv run pytest`）；CI 每次从锁文件干净安装；测试默认断网。
- **加检查防退化**：每晚一个可复现性作业，用不同顺序、不同机器、断网跑同一提交；结果库里存每次运行的环境清单，方便下次直接 diff。

收尾一句：可复现不是为了好看，而是为了让"红灯"只有一个解释：代码有问题。
