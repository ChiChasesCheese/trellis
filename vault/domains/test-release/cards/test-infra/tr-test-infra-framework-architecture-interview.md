## Q
面试里被问"从零设计一个测试框架，用来测一个跨多个组件（编译器、运行时、硬件）的推理系统"，怎么答？

## A
先一句话说明被测系统：推理系统把训练好的模型（一大组数字参数加一串计算步骤）跑起来回答请求；编译器把计算翻译成芯片程序，运行时（runtime）负责把程序加载到芯片上执行。

按下面顺序讲：

- **先问清楚**：谁写测试（测试组还是各特性团队）、跑在哪（模拟器、真机、多机集群）、每天多少次、结果给谁看。这些决定了框架要多重。
- **讲分层**：资源层（租用设备、部署指定版本、清理）、驱动层（把编译、加载、请求包装成函数）、测试逻辑、判定层（容差、参考实现对比）、报告层（JUnit XML + 结果库）。强调测试逻辑里不出现机器名和端口。
- **讲扩展**：新配置靠配置矩阵展开；新硬件实现驱动接口；新判定方式注册插件。目标是加一个特性只写一层。
- **讲执行**：基于 pytest，外层一个编排器负责申请稀缺硬件、分片并行、超时与重跑策略，每个测试声明自己需要的资源。
- **讲可观测与分诊**：失败时自动收集日志、版本清单、设备状态；基础设施错误和产品失败分开计数；结果进历史库，能看每条测试的趋势。
- **讲框架自身质量**：框架有单元测试和负责人；用两三个指标证明它在起作用，例如加一个新配置要改的文件数、基础设施错误占失败的比例、每次运行的总时长。

结尾可以补一句取舍：先用 pytest 扩展，只有分布式作业这类 pytest 装不下的部分才自研。
