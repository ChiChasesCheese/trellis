## Q
测试结果为什么要存进一个历史数据库，而不是看完每次 CI 的报告就算了？这个库的一条记录应该有哪些字段？

## A
**单次报告只能回答"这次挂了什么"，历史库能回答"它从什么时候开始挂、挂得多频繁、只在哪种机器上挂"**。分诊、flaky 治理、分片、发布决策都要靠这些问题。

**一条记录 = 一条测试的一次执行**，常见字段：

| 字段 | 用途 |
|---|---|
| `test_id`（稳定的名字，含参数） | 跨运行追踪同一条测试 |
| `run_id`、`job`、`tier`（提交前 / 夜间 / 发布验证） | 区分来源 |
| `commit`、`branch`、`build_id` 或制品摘要 | 结果对应哪个版本 |
| 组件版本清单（编译器、运行时、固件、驱动） | 跨栈失败归因 |
| `env`：机器编号、硬件型号、模拟器还是真机 | 发现坏机器和环境相关失败 |
| `outcome`：通过 / 失败 / 错误 / 跳过 / 重试后通过 | 计算通过率和不稳定率 |
| `attempt`：第几次尝试 | 区分重试 |
| `duration` | 分片装箱、慢测试告警 |
| `failure_signature`：失败指纹 | 自动归到已知问题 |
| `log_url`、附件链接 | 一键跳到证据 |
| `owner`、`component` | 自动指派 |

**由历史库直接得到的东西**：
- **不稳定率**：同一提交上既有通过又有失败的比例；
- **第一次失败的提交**：失败从哪次运行开始，候选范围立刻缩小；
- **耗时分布**：给分片用，也能发现"测试越来越慢"；
- **按机器聚合**：哪台机器失败率异常；
- **发布报告**：某个发布候选上所有必过测试的状态。

**规模估算**：1 万条测试 × 每天 50 次运行 = 每天 50 万行，一年约 1.8 亿行。适合列式存储或按日期分区的表，日志本体放对象存储，库里只存链接。
