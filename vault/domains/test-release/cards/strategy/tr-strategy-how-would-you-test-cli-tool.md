## Q
怎么测一个命令行工具（例如一个把计算描述文件 `model.onnx` 编译成加速芯片可执行文件的 `compile` CLI）？除了功能之外，命令行工具特有的测试点是什么？

## A
**功能**：合法输入编译成功，产物能被加载执行并算出正确结果；每个命令行参数单独和组合生效（两两组合覆盖）。

**命令行工具特有的测试点**：
- **退出码**：成功返回 0，失败返回非 0，而且不同错误类别的退出码稳定、有文档；CI 脚本依赖它判断成败。
- **标准输出与标准错误分离**：结果写 stdout，日志和错误写 stderr；`compile model.onnx > out.json` 时日志不能混进 JSON。
- **参数解析**：未知参数、缺少必需参数、互斥参数同时给出时报出清楚的错误；`--help` 输出正确。
- **文件系统行为**：输入文件不存在、无读权限；输出目录不存在、磁盘满；路径含空格和非 ASCII 字符；中途失败时不留下半个产物（先写临时文件再原子重命名）。
- **信号与中断**：Ctrl-C（SIGINT）后清理临时文件、子进程被一起终止。
- **可复现**：同样的输入和参数两次编译，产物逐字节相同（或差异只在明确的元数据字段），否则缓存和二分定位都无法工作。
- **环境依赖**：不同的 `PATH`、语言环境（`LANG=C`）、当前工作目录下行为一致。

**怎么写**：用 `subprocess.run([...], capture_output=True, text=True)` 调用，断言 `returncode`、`stdout`、`stderr`；pytest 的 `tmp_path` 夹具给每个测试一个独立目录。
