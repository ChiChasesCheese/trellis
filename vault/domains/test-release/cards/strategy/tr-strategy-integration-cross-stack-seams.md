## Q
一个 AI 加速芯片的软件栈从上到下是框架 → 编译器 → 运行时 → 设备固件。跨层集成测试最常见的缝隙（seam）有哪些，各自怎么测？

## A
**先认识四层**（不需要懂 AI）：
- **框架（framework）**：用户写计算的 Python 库，例如 PyTorch；一个"模型"在这里就是一长串数学运算，输入输出都是多维数组（张量，tensor）。
- **编译器**：把这串运算翻译成芯片能执行的程序。每个基本运算（加法、矩阵乘）叫一个算子（operator）。
- **运行时（runtime）**：在机器上加载编译产物、分配内存、启动执行、取回结果。
- **固件（firmware）**：芯片自带的底层程序。

每一层对下一层都有**没写进接口签名的假设**，缺陷集中在这里：
- **数字格式**：上层以为用 32 位浮点（FP32）累加，下层用 16 位（BF16，只有约 2–3 位有效十进制数字）累加，误差大了几个数量级。测法：每种格式组合跑一个小计算，与 64 位浮点参考结果比误差。
- **数组排列与形状**：内存里按行连续还是分块存放、长度是否要求对齐。测法：形状扫描（shape sweep），长度取 1、质数、非对齐值、最大值。
- **算子语义**：舍入方式、`NaN`/`inf` 怎么传播、整数溢出、不支持的算子是否回退到慢路径。测法：逐算子与参考实现对比，加入边界值。
- **资源与时序**：芯片内存预算、异步执行的完成信号、超时。测法：在内存接近上限时运行，注入延迟。
- **错误传播**：下层报错是被上层正确报告，还是被吞掉变成一个错的结果。测法：让下层返回错误码，断言上层报清楚的错。
- **版本错配**：新编译器的产物交给旧运行时加载。测法：相邻版本的兼容矩阵。

**组织方式**：每个缝隙保留一组"薄切片"测试：一个很小但覆盖关键算子的计算从框架一直跑到设备，失败时逐层导出中间结果，看哪一层先偏离参考。
