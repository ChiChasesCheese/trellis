## Q
缺陷的严重度（severity）和优先级（priority）有什么区别？举出"高严重度低优先级"和"低严重度高优先级"的例子。

## A
- **严重度**：缺陷发生时**后果有多坏**。是缺陷本身的属性，由测试或分诊的人按客观标准评定。常见四级：
  - S1：数据损坏或丢失、安全漏洞、服务整体不可用、结果静默出错；
  - S2：主要功能不可用，且没有绕开的办法；
  - S3：功能受损，但有绕开办法；
  - S4：外观、文字、轻微不便。
- **优先级**：**多快要修**。是排期决定，由负责人综合严重度、影响的用户数、发生频率、发布时间、修复成本来定。常见 P0（立刻修，放下手头工作）到 P3（有空再修）。

**两者不一致的例子**：
- **高严重度、低优先级**：在一种已经停止支持、没有用户在用的旧硬件型号上，长时间运行后服务崩溃。后果严重（S1），但没人会遇到，可以 P3。
- **低严重度、高优先级**：发布说明和 API 文档里把一个参数名写错了，第二天要给大客户演示，按文档写的调用会报错。严重度 S3–S4，但必须在发布前修好，P0。
- **另一个常见例子**：推理服务（把训练好的模型部署成在线服务，回答用户的问题）的回答偶尔多出一个空格，严重度低；但如果它让一个大客户的自动化解析全部失败，优先级就高。

**为什么要分开**：
- 只有一个字段时，大家倾向于把所有东西都标"高"，字段失去意义；
- 严重度用于统计质量（每个版本有多少 S1 逃逸），优先级用于排工作，两者用途不同；
- 发布阻断的判断主要看严重度和"是否为本版本引入的回归"，而不是看谁喊得最响。

**评定严重度要写依据**：触发条件、影响范围、有无绕开办法。依据清楚，不同的人会评出同一个等级。
