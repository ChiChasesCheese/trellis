## Q
一个已确认的问题不满足准出标准，但团队决定带着它发布，这就是豁免（waiver）。豁免需要满足什么条件、记录什么？

## A
**豁免的含义**：明确承认"这个版本不满足某条标准"，由有权限的人接受这个风险，并承诺后续处理。它不是"假装没看见"。

**可以考虑豁免的条件**（通常要同时满足）：
- 问题已经被理解：根因或至少触发条件清楚，不是"偶尔会出、不知道为什么"；
- 影响有限：只在少见配置下触发，或有可行的绕开办法；
- 不发布的代价更大：例如这个版本包含一个重要的安全修复或客户承诺的功能；
- 有缓解措施：功能开关可以关掉、监控能发现、可以快速回滚；
- 不属于不可豁免的类别：数据泄露、静默算错这类通常不允许豁免。

**豁免记录的字段**：

```text
标准:     性能，首字延迟 p99 退化 ≤ 5%
实际:     某硬件型号上 +8%，其他型号 +2%
影响:     该型号约占流量 10%，p99 从 410 ms 到 443 ms
根因:     新调度策略在该型号上排队更久，已定位
缓解:     该型号可通过配置回退旧策略；已加告警
批准人:   发布负责人、性能负责人
修复计划: 下一版本修复，缺陷单编号
到期:     下一个正式版本，届时自动转为阻断
```

**流程要点**：
- **批准人要有权限也有信息**：通常是发布负责人加对应领域负责人，不是提出豁免的人自己；
- **写进发布说明的已知问题**，让下游和支持团队知道；
- **有到期日**：到期未修复自动转为阻断，或重新审批；
- **可统计**：看板展示每个版本的豁免数量和最老豁免的年龄。豁免越来越多，说明标准不现实或者质量在下滑，两者都需要讨论。
