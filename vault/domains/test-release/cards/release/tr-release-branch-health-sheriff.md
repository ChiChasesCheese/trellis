## Q
构建值班（build cop / build sheriff，Chromium 现在叫 gardener）是什么角色？一个值班周期里具体做什么？

## A
**角色**：轮值的工程师，负责在值班期间让主干（以及发布分支）保持绿色。名字各家不同：build cop、sheriff；Chromium 在 2023 年把 sheriff 轮值改名为 gardener（园丁），意思是"让树保持绿色和健康"。

**为什么需要专人**：主干红了，每个人都以为别人在处理；没有明确的负责人，红灯会持续一整天。

**值班期间做的事**：
- **盯信号**：提交后和夜间的结果看板，新出现的失败第一时间处理。
- **分诊**：对每个新失败判断类别：产品回归、flaky、基础设施问题、测试缺陷。
- **处理回归**：找嫌疑提交：看失败开始的那次运行之前合入了什么，必要时二分（在提交区间里反复取中点测试，找出引入问题的那个提交）；然后回滚并通知作者。
- **处理 flaky**：隔离测试，给负责团队开单并设修复期限。
- **处理基础设施**：机器、网络、制品服务器出问题时找对应团队，必要时暂停相关作业，避免产生大量误报。
- **沟通**：在团队频道里更新主干状态（"主干红，原因 X，已回滚，预计 30 分钟恢复"）；必要时宣布暂停合入。
- **交接**：值班结束写交接记录：未解决的失败、已隔离的测试、进行中的调查。

**周期和工作量**：常见一周一轮，在值班期间这是主要工作，不再安排功能开发。值班人员应来自各个组件团队，这样大家都理解失败处理的痛苦，也会更愿意写稳定的测试。

**怎么让值班不变成苦差**：
- 工具化：失败自动分组、自动找嫌疑提交、一键回滚；
- 规则明确：revert first 的授权写进团队规范，值班者不需要征求作者同意；
- 度量：值班期间处理了多少失败、平均恢复时间、重复出现的问题，交给对应团队改进。
