## Q
在加速芯片的测试机上，一个测试偶发地得到错误结果或挂起。怎样区分是硬件故障还是软件缺陷？

## A
加速芯片（accelerator）是专门做大规模数值计算的芯片，例如 GPU；芯片上的内存出错、芯片之间的连接出错，都会让软件看起来"算错了"。

**核心判据：问题跟着机器走，还是跟着代码走**。

**倾向硬件的证据**：
- **只在某一台（或某几台）机器上出现**，换机器后同一构建稳定通过；
- **多个无关测试在这台机器上都偶发失败**，失败没有共同的代码路径；
- **系统和设备日志里有硬件错误**：`dmesg -T` 里的设备错误或总线错误；内存纠错计数（ECC，内存自带的检错纠错机制，计数上升说明内存在出错）在增加；设备链路错误计数；温度过高或降频记录。NVIDIA GPU 上可以用 `nvidia-smi -q -d ECC` 查看纠错计数；
- **同一输入在同一机器上重复运行，结果偶尔不同**，而在其他机器上始终一致。

**倾向软件的证据**：
- **在所有机器上都出现**，只是频率较低；
- **从某个提交之后开始出现**，之前同一批机器上从不出现；
- **与负载或时序有关**：并发更高、输入更长时更容易出现，换到另一台同型号机器也一样；
- **挂起时的调用栈总是停在同一个位置**（例如等待一个永远不会到来的完成信号）。

**确认方法**：
1. 把失败的测试固定在嫌疑机器上重复运行 N 次，再在 2–3 台健康机器上各运行 N 次，比较失败率；
2. 在嫌疑机器上跑设备厂商的诊断工具和内存测试；
3. 结果库按机器聚合失败率，看这台机器是否明显高于平均。

**处理**：确认是硬件就隔离机器、开维修单，失败的测试在健康机器上重跑；确认是软件，就按回归或竞态缺陷处理。不确定时两边同时推进，不要因为"可能是硬件"而搁置一个软件缺陷。
