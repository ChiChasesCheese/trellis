## Q
面试里被问"你会怎么度量和提升 CI 与主干的健康度"，怎么答？

## A
- **先定义要度量的东西**：主干和各发布分支的绿色时间占比、红灯恢复时间（中位数和 p90）、每周变红次数和原因分布；提交前流水线时长 p50 / p90 与排队时间；不稳定率和 flaky 导致的误失败率；基础设施错误率；隔离区规模和年龄。
- **口径写清楚**：没有结果的运行计入不可用；"重试后通过"单独计数；只看工作时间或按受影响的 PR 数加权，避免数字好看但体验差。
- **定 SLO 和错误预算**：从现状出发定目标，例如工作时间绿色占比 ≥ 95%、红灯 90% 在 2 小时内恢复、flaky 误失败 ≤ 2%；预算用完时按约定暂停大改动、集中治理。
- **看板与告警**：首页是当前状态、SLO 达成和趋势；排行榜指向具体测试、组件和机器的负责人；能一路下钻到单次运行；主干红超过一小时无人处理就告警。
- **按原因改进**：回归多 → 加强提交前检查和合并队列；flaky 多 → 隔离、限期修复、不加盲目重试；基础设施多 → 交给平台团队，坏机器自动下线；流水线慢 → 缓存、分片、处理排队。
- **验证指标贴近体验**：对比开发者调查和"重跑"次数，数字和体验背离时修正定义。

收尾：健康度指标的目的不是排名，而是让每个问题都有负责人和可见的进展。
