## Q
性能测试的噪声从哪里来？在 CPU 和 GPU 测试机上分别可以用哪些手段降低噪声？

## A
**常见噪声来源**：
- **频率变化**：CPU 睿频（turbo）和节能降频，GPU 按温度和功耗动态调整频率；同一测试在机器"凉"和"热"时结果不同。
- **其他进程**：同一台机器上的其他任务、定时任务、日志上传。
- **调度和内存位置**：线程在核心之间迁移，在多路服务器上访问另一个 CPU 插槽的内存更慢。
- **硬件个体差异**：同型号的两块卡也可能有几个百分点的差别。
- **预热**：缓存、即时编译、内存池在第一次运行时还没准备好。

**CPU 机器上的手段**：
- 关闭睿频、把调频策略固定为 `performance`；Python 的 pyperf 提供 `python -m pyperf system tune` 一键完成这类设置；
- 用 `taskset -c 2-5 <命令>` 把进程绑到固定核心，必要时把这些核心从系统调度中隔离；
- 专机专用，测试期间不跑其他任务。

**GPU 机器上的手段**：
- `nvidia-smi -pm 1` 打开持久模式，避免驱动反复初始化；
- `nvidia-smi -lgc <最低>,<最高>` 锁定 GPU 核心频率（`-rgc` 恢复），让每次运行在同一频率下；
- 监控温度和降频原因（`nvidia-smi -q -d PERFORMANCE`），出现降频的运行作废。

**测试方法上的手段**：
- **预热**：丢弃前几次运行；
- **交替运行**：基线和新版本按 A、B、A、B 交替跑，而不是先 10 次 A 再 10 次 B，抵消随时间漂移的环境变化；
- **固定硬件**：基线和新版本在同一台机器上比较；
- **先测噪声**：同一构建跑 30 次，量出变异系数，再据此设阈值。噪声 1% 的环境里能可靠发现 3% 的回归，噪声 8% 的环境里不可能。
