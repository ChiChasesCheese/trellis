# q28 · 任务分派（最闲的人 · 技能要求 · 优先专才 · 容量）

> `problems/q28_worker_task_assignment/` · 4 个 part
> **主题：每个 part 往排序键上加一项 —— 排序键就是这道题的全部。**

## 一句话题意

把任务逐个分派给工人。P1 只看负载，P2 加技能要求，P3 同负载时**优先技能少的（专才）**，
P4 加容量上限。

## 核心考点

`S02` 分节 + `;` 列表 · `S03` 工人建成记录 · `S04` 按技能分组 · **`S05` `<=` 容量** ·
**`S08` 确定性多键 tie-break** · `S09` 格式 · `S19` 每个 part 加一项 · **`S21` 堆 + 惰性失效**

## 解题思路

**排序键逐 part 增长（这是整道题的骨架）**：

| Part | 键 |
|---|---|
| 1 | `(load, worker_id)` |
| 2 | 先过滤 `required_skill in worker.skills`，键同 P1 |
| 3 | `(load, len(set(worker.skills)), worker_id)` |
| 4 | 先过滤 `load + cost <= capacity`，键同 P3 |

**负载在任务之间立刻更新**，下一个任务看到的是新值。
没有候选（没人有该技能 / 没人装得下）→ `UNASSIGNED`，**负载不变**。

**性能**：10^5 个任务 × 10^3 个工人，每个任务线性扫是 10^8 次比较。
用**按技能分组的堆**（每个技能一个堆，键就是上面的元组），
负载变化后堆里的旧条目用**惰性失效**（弹出时校验 `load` 是否还是当前值）。

## 坑

1. **平手按 id 的字符串序**（`w10` < `w2`）；负载在连续任务之间更新。
2. 技能未知的任务 → `UNASSIGNED`；**零负载的工人也要打印**。
3. **零成本任务照样分派**，而且**装得进满员的工人**。
4. P3：**负载优先** —— 负载更低的通才仍然打败负载更高的专才。
5. P4：`load + cost == capacity` **接受**，多一点拒绝；`capacity 0` 只接零成本任务；
   **最闲的那个可能装不下，而更忙的那个装得下**。
6. 工人技能列表里的**重复技能（`python;python`）在专才规则里只算一次** → 用 `len(set(skills))`。
7. 空任务列表 → 只有工人行；空工人列表 → 全部 `UNASSIGNED`。

## 变体

- 1point3acres 的摘要只写到 "prefer the …"，第三条规则可能是
  "分到的**任务数**最少的" 或 "等待最久的（轮转）" 而不是"技能最少的"。
  仓库的解法留了一个 `specialist_key` 钩子，可以换掉这一项。
- Onsite 版本要求写成内存类（`add_worker`、`assign(task)`），并讨论堆 + 惰性失效的扩展。
