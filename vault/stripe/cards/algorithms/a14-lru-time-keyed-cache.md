## Q
当题目要求实现一个有容量上限、需要按访问顺序淘汰的缓存（LRU），或者需要按时间戳查询"某个时刻生效的值"时，怎么识别该用**LRU / 时间键缓存**套路？

## A
LRU 标准实现是 `OrderedDict` 的 `move_to_end`（Python）或者手写 dict + 双向链表：`get`/`put` 时把该 key 移动到链表尾部表示"最近使用"，
容量超限时从链表头部淘汰最久未使用的 key，保证 O(1) 的 get/put。如果是"按时间戳查询某个时刻生效值"（比如时间旅行版本控制），
则对每个 key 维护一个按时间排序的列表，查询时用 `bisect` 二分查找小于等于目标时间的最后一次写入。

**最易错处**：
1. `get` 操作本身也算一次"使用"，必须把该 key 移动到最近使用的位置，只在 `put` 时更新顺序是常见漏洞；
2. 如果题目同时有 **TTL 过期**和**容量淘汰**两套机制，要明确两者的**优先级**（比如先清理过期 key 还是先按容量淘汰），顺序不同会导致淘汰的 key 不一样。
