# 10 · 动态规划 1D / 2D（Dynamic programming）

动态规划（DP）就是把一个大问题拆成重叠的小问题，每个小问题只算一次并记下来。你要做的是五件事：定义状态、写转移、定初值、定计算顺序、读出答案。先写出暴力递归，再加缓存（记忆化），再改成自底向上的表格，最后压缩到只保留下一步会读的几格。题目说「最多 / 最少 / 方案数」且选择会影响后面的选择时，先想 DP。

> 本讲覆盖：LC 70 Climbing Stairs · 121 Best Time to Buy and Sell Stock · 53 Maximum Subarray · 322 Coin Change · 5 Longest Palindromic Substring · 10 Regular Expression Matching（Hard）· 312 Burst Balloons（Hard）
> 前置：递归、`list` 的二维索引。上一讲的「递归 = 相信子问题」是基础。
> 读完你应该能：(1) 用「状态 → 转移 → 初值 → 顺序 → 答案」五步写出任何 DP；(2) 把记忆化递归改写成自底向上的表格，再压缩状态；(3) 判断什么时候贪心就够、什么时候必须 DP。

## 1. 这个模式是什么，为什么存在

### 1.1 从最笨的解法开始

斐波那契 `fib(n) = fib(n-1) + fib(n-2)`（LC 70 爬楼梯的本质：到第 n 阶的方法数 = 到第 n−1 阶的 + 到第 n−2 阶的）。直接递归：

```text
fib(5)
├── fib(4)
│   ├── fib(3) ...
│   └── fib(2) ...
└── fib(3)          <- fib(3) 被重复算了
    ├── fib(2) ...
    └── fib(1)
```

调用次数 T(n) = T(n−1) + T(n−2) + 1，指数增长；`fib(20)` 就要调用 21891 次，`fib(50)` 需要约 4×10¹⁰ 次。

### 1.2 慢在哪里

`fib(3)` 的值只依赖 3，**不管是谁来问**答案都一样，却被算了很多遍。问题里**不同的子问题其实很少**（n 个），是它们被**重复求解**（overlapping subproblems）。

> 因果链：子问题重叠 → 把每个子问题的答案存起来（memoization，记忆化）→ 每个子问题只算一次 → O(子问题个数 × 每个子问题的转移代价)。
> 前提还有一条：**最优子结构（optimal substructure）**——大问题的最优解由小问题的最优解拼出来。（Coin Change：凑 11 的最少硬币数 = 1 + 凑 `11 - c` 的最少硬币数的最小值。）

### 1.3 五步法（每道 DP 题都按这个顺序写）

1. **状态**（state）：`dp[i]`（或 `dp[i][j]`）表示什么？一句话说清楚，含单位。
2. **转移**（transition）：`dp[i]` 由哪些更小的状态怎么得到？
3. **初值**（base case）：最小的状态答案是多少？
4. **顺序**（order）：填表时保证依赖的格子已经算好（从小到大）。
5. **答案**（answer）：最终答案在哪个格子？是 `dp[n]` 还是整张表的最大值？

### 1.4 自顶向下 vs 自底向上 vs 状态压缩

| 写法 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 自顶向下（top-down） | 递归 + `@lru_cache` | 贴近定义，只算用到的状态，容易写对 | 递归深度（Python 1000）、函数调用开销 |
| 自底向上（bottom-up） | 循环填表 | 没有递归限制，快 | 要想清楚填表顺序 |
| 状态压缩（rolling） | 只保留下一步要读的格子 | 空间 O(n) → O(1) | 不能再回溯重建方案 |

### 1.5 贪心 vs DP

贪心每步做一个不可撤销的选择，需要「局部最优 ⟹ 全局最优」的证明；DP 把所有选择都考虑（通过子问题）。**不确定能不能贪心时，写出反例再决定**——见 4.4 的 Coin Change。

## 2. 模板与逐行讲解

```python
from functools import lru_cache

# Step 0: the brute force -- plain recursion recomputes the same sub-problems exponentially often
calls = 0
def fib_slow(n):
    global calls
    calls += 1
    return n if n < 2 else fib_slow(n - 1) + fib_slow(n - 2)

# Step 1: memoization = same recursion + a cache keyed by the state  (top-down)
@lru_cache(maxsize=None)
def fib_memo(n):
    return n if n < 2 else fib_memo(n - 1) + fib_memo(n - 2)

# Step 2: tabulation = fill the table from small to large  (bottom-up)
def fib_table(n):
    dp = [0, 1] + [0] * max(0, n - 1)
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]          # transition
    return dp[n]

# Step 3: state compression = keep only the cells the next step reads
def fib_rolling(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a

assert fib_slow(20) == 6765
assert calls == 21891                           # 21,891 calls to compute a 20-element table
assert fib_memo(20) == fib_table(20) == fib_rolling(20) == 6765
assert fib_rolling(90) == 2880067194370816120

# 2D template: dp[i][j] over two prefixes (e.g. longest common subsequence)
def lcs(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]   # dp[i][j]: LCS of a[:i], b[:j]; row/col 0 = empty prefix
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[-1][-1]

assert lcs("abcde", "ace") == 3 and lcs("abc", "def") == 0
```

逐行讲解：

1. `fib_slow` + `calls`：用计数器**亲眼看到** 21891 次调用，这是「为什么需要 DP」最有说服力的证据。
2. `fib_memo`：`@lru_cache(maxsize=None)` 把函数变成「状态 → 值」的字典查询。状态必须是**可哈希**的参数（整数、元组）。
3. `fib_table`：`dp[i]` = 第 i 个斐波那契数；初值 `dp[0], dp[1]`；顺序 `i` 从小到大；答案 `dp[n]`。
4. `fib_rolling`：转移只读 `dp[i-1]` 和 `dp[i-2]`，所以只留两个变量；`a, b = b, a + b` 是同时赋值。
5. `lcs`（二维模板）：`dp[i][j]` 表示 `a[:i]` 和 `b[:j]` 的最长公共子序列长度；第 0 行 / 第 0 列代表空串，值为 0（这就是「初值」），所以表比字符串多一行一列。字符相等就「各退一步 +1」，不等就「各退一步取较大」。**二维 DP 的两个下标几乎总是『两个序列的前缀长度』或『区间的左右端点』。**

## 3. 完整手算（Worked trace）

**1D：Coin Change**，`coins = [1, 2, 5]`，`amount = 11`。`dp[a]` = 凑出金额 a 的最少硬币数；对每个 a 尝试最后一枚硬币 c：`dp[a] = min(dp[a - c] + 1)`。

```python
def coin_trace(coins, amount):
    INF = float("inf")
    dp = [0] + [INF] * amount
    print("coins", coins, " dp[0]=0, others = inf")
    for a in range(1, amount + 1):
        options = [(c, dp[a - c] + 1) for c in coins if c <= a]
        dp[a] = min([v for _, v in options], default=INF)
        print(f"dp[{a:>2}] = min over {options} = {dp[a]}")
    return dp[amount]

assert coin_trace([1, 2, 5], 11) == 3
print()
```

读 `dp[5]`：可选最后一枚是 1（`dp[4]+1 = 3`）、2（`dp[3]+1 = 3`）、5（`dp[0]+1 = 1`），最小是 1；读 `dp[11]`：最后一枚是 5 → `dp[6] + 1 = 3`，是 1 → `dp[10] + 1 = 3`，是 2 → `dp[9] + 1 = 4`；最小 3（5 + 5 + 1）。

**2D：回文子串表**（LC 5，字符串 `cbbd`）。`dp[i][j]` = `s[i..j]` 是不是回文；`T` 表示是。转移：`s[i] == s[j]` 且（长度 ≤ 2 或 `dp[i+1][j-1]`）。表的第二部分就是上面输出的下半段：`dp[1][2]`（`bb`）为真，所以最长回文是 `bb`。填表顺序为什么是「右端点外层、左端点内层」？因为 `dp[i][j]` 依赖 `dp[i+1][j-1]`（左下方），这样到 `(i, j)` 时它已经算好了。

### 4.1 LC 70 · Climbing Stairs（Easy）

```python
# solutions/70_climbing_stairs.py
def climb_stairs(n):
    a, b = 1, 1                    # ways(0), ways(1)
    for _ in range(n - 1):
        a, b = b, a + b            # ways(i) = ways(i-1) + ways(i-2)
    return b


def climb_stairs_memo(n):          # top-down version of the same recurrence
    @lru_cache(maxsize=None)
    def ways(i):
        return 1 if i <= 1 else ways(i - 1) + ways(i - 2)
    return ways(n)
```

- **一句话洞见**：最后一步要么走 1 阶要么走 2 阶，所以 `ways(n) = ways(n-1) + ways(n-2)`；只依赖前两项 → 两个变量。
- **复杂度**：时间 O(n)，空间 O(1)（记忆化版本空间 O(n)）。

**资深追问**

- **规模 ×1000**：n = 10⁹：线性循环太慢 → 矩阵快速幂或 fast doubling，O(log n)，通常要对某个模数取余（因为结果是天文数字；Python 大整数也能算但很慢）。
- **推广**：一次最多走 k 阶 → 滑动窗口和 `dp[i] = sum(dp[i-k..i-1])`，O(n)；有些台阶不能踩 → 把 `dp[bad] = 0`。
- **流式 / 内存**：O(1)；递归版本在 n = 10⁵ 时爆栈。
- **并发**：纯函数，无共享状态；多个 n 的查询可以缓存 / 并行。
- **接口 / 边界**：n = 0 的约定（1 种：什么都不走）；n < 0 非法；是否要对 10⁹+7 取模？
- **测试**：n = 1..8 的已知值、n = 45（32 位整数上限附近）、递归版与迭代版互相对拍。

### 4.2 LC 121 · Best Time to Buy and Sell Stock（Easy）

```python
# solutions/121_best_time_to_buy_and_sell_stock.py
def max_profit(prices):
    cheapest = float("inf")
    best = 0
    for p in prices:
        cheapest = min(cheapest, p)          # best day to have bought, among days up to today
        best = max(best, p - cheapest)       # sell today
    return best
```

- **一句话洞见**：卖在第 i 天的最大利润 = `prices[i]` − 此前最低价；只需一个变量记录「到目前为止的最低价」。这是状态压缩后的 DP：`dp[i] = max(dp[i-1], prices[i] - min_so_far)`。
- **复杂度**：时间 O(n)，空间 O(1)。
- **家族**：LC 122（可多次交易 → 把所有上涨段相加）、123 / 188（最多 k 次 → `dp[k][day][持有?]` 状态机）、309（冷冻期）、714（手续费）。

**资深追问**

- **规模 ×1000**：线性；并行时每块返回 `(最低价, 最高价, 块内最大利润)`，合并 `best = max(左.best, 右.best, 右.max − 左.min)`，满足结合律，可以树形归约。
- **流式**：天然在线：每个新价格 O(1) 更新 `cheapest` 和 `best`。
- **内存**：O(1)。
- **并发**：多个股票并行；单只股票按上面的归约并行。
- **接口 / 边界**：不能亏钱时返回 0（不交易）；要不要返回买入和卖出的日期（记录最低价所在的下标）？**金额用整数（分）或 `Decimal`，不要用浮点**——这是金融场景的资深关注点。
- **测试**：严格下跌（0）、单个元素、空、最低价在最后、与 O(n²) 暴力对拍。

### 4.3 LC 53 · Maximum Subarray（Medium）

```python
# solutions/53_maximum_subarray.py
def max_sub_array(nums):
    ending_here = best = nums[0]
    for x in nums[1:]:
        ending_here = max(x, ending_here + x)      # extend the previous run, or restart at x
        best = max(best, ending_here)
    return best
```

- **一句话洞见**：`ending_here` = 以当前元素**结尾**的最大和；要么接上前面的（`ending_here + x`），要么从自己重新开始（`x`）。答案是所有 `ending_here` 里的最大值（Kadane 算法）。
- **复杂度**：时间 O(n)，空间 O(1)。

**资深追问**

- **规模 ×1000**：线性。分治 / 并行：每块返回四元组 `(总和, 最大前缀和, 最大后缀和, 最大子数组和)`，合并：`best = max(左.best, 右.best, 左.suffix + 右.prefix)`；结合律 → 线段树 / 并行归约，也是支持「区间查询 + 单点更新」的基础。
- **流式**：在线 O(1)。
- **内存**：O(1)。
- **并发**：同上，块归约。
- **接口**：全为负数时返回最大的负数（不是 0），所以初值用 `nums[0]` 而不是 0；空数组非法；是否要返回子数组下标（多记一个起点）？
- **测试**：全负、全正、单个、含 0；与 O(n²) 暴力对拍。

### 4.4 LC 322 · Coin Change（Medium）

```python
# solutions/322_coin_change.py
def coin_change(coins, amount):
    INF = amount + 1                       # larger than any real answer
    dp = [0] + [INF] * amount              # dp[a] = fewest coins to make a
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a:
                dp[a] = min(dp[a], dp[a - c] + 1)
    return dp[amount] if dp[amount] != INF else -1
```

- **一句话洞见**：`dp[a]` = 凑出 a 的最少硬币数；枚举最后一枚硬币 c，`dp[a] = min(dp[a-c] + 1)`；不可达用一个大于任何真实答案的 `amount + 1` 表示。
- **为什么不能贪心**：下面这段代码演示——`[1,3,4]` 凑 6，贪心取 4+1+1 = 3 枚，最优是 3+3 = 2 枚（美元硬币体系恰好贪心可行，但那是特例，需要证明）。

```python
def greedy_coins(coins, amount):                 # "always take the biggest coin": plausible, but wrong in general
    count = 0
    for c in sorted(coins, reverse=True):
        count += amount // c
        amount %= c
    return count if amount == 0 else -1

assert greedy_coins([1, 3, 4], 6) == 3           # 4 + 1 + 1
assert coin_change([1, 3, 4], 6) == 2            # 3 + 3  -> the DP from 4.4 beats greedy
assert greedy_coins([1, 5, 10, 25], 63) == coin_change([1, 5, 10, 25], 63) == 6   # US coins: greedy happens to work
```

- **复杂度**：时间 O(amount × len(coins))，空间 O(amount)。

**资深追问**

- **规模 ×1000**：`amount` 是 10⁹ 时表格放不下——DP 是**伪多项式**的（pseudo-polynomial）。硬币种类少而面额大时，换成「模最小面额」的最短路（Dijkstra on residues），状态数只有最小面额的大小。
- **流式 / 内存**：只需 O(amount) 的一维数组；如果还要还原具体用了哪些硬币，多存一个 `choice[a]`（上一步用的硬币）。
- **并发**：同一个金额的所有硬币转移互不依赖，但不同金额按序依赖，一般不并行；多个 `amount` 查询共享同一张表（预计算到最大金额）。
- **接口 / 边界**：`amount = 0` → 0；不可达 → −1；硬币含 0 或负数、重复面额（非法 / 去重）；是求最少个数还是方案数（LC 518，外层循环顺序必须是「硬币在外」避免排列重复计数）？
- **测试**：不可达（`[2]`、3）、金额 0、贪心反例 `[1,3,4]`、大金额（`[186,419,83,408]`、6249）；与回溯暴力对拍（文件里已有）。

### 4.5 LC 5 · Longest Palindromic Substring（Medium）

```python
# solutions/5_longest_palindromic_substring.py
def longest_palindrome(s):
    n = len(s)
    dp = [[False] * n for _ in range(n)]       # dp[i][j]: s[i..j] is a palindrome
    start, length = 0, 1
    for j in range(n):                         # right end outer, so dp[i+1][j-1] is already known
        for i in range(j + 1):
            if s[i] == s[j] and (j - i < 2 or dp[i + 1][j - 1]):
                dp[i][j] = True
                if j - i + 1 > length:
                    start, length = i, j - i + 1
    return s[start:start + length]


def longest_palindrome_expand(s):
    def grow(l, r):
        while l >= 0 and r < len(s) and s[l] == s[r]:
            l -= 1
            r += 1
        return l + 1, r                        # bounds of the last valid palindrome
    best = (0, 1)
    for c in range(len(s)):
        for l, r in (grow(c, c), grow(c, c + 1)):     # odd and even centers
            if r - l > best[1] - best[0]:
                best = (l, r)
    return s[best[0]:best[1]]
```

- **一句话洞见**：二维表 `dp[i][j]`（`s[i..j]` 是否回文）；或者更省空间的「中心扩展」——每个位置（和每对相邻位置）向两侧扩展，O(n²) 时间 O(1) 空间。Manacher 算法 O(n)，面试里知道有即可。
- **复杂度**：表格 O(n²) 时间 O(n²) 空间；中心扩展 O(n²) 时间 O(1) 空间。

**资深追问**

- **规模 ×1000**：n = 10⁵ 时 O(n²) 表格（10¹⁰ 格）不可行；中心扩展时间也太长；换 Manacher O(n)。
- **流式**：回文的中心可以在线维护，但完整最长回文需要看到后文；通常离线处理。
- **内存**：表格 → 中心扩展：O(n²) → O(1)；这是资深面试官喜欢听的「从 DP 降到 O(1) 空间」。
- **并发**：不同中心的扩展互相独立，可并行（fork-join 后取最大）。
- **接口 / 边界**：多个最长回文返回哪个（最左）；空串；Unicode 组合字符（按码点还是字形簇）；大小写 / 标点是否忽略（那是 LC 125 的变体）。
- **测试**：`aaaa`、`cbbd`（偶数长度）、`babad`（奇数长度）、单字符、与暴力对拍（只比较长度并验证返回的确是回文且是原串子串）。

### 4.6 LC 10 · Regular Expression Matching（Hard）

```python
# solutions/10_regular_expression_matching.py
def is_match(s, p):
    m, n = len(s), len(p)
    dp = [[False] * (n + 1) for _ in range(m + 1)]     # dp[i][j]: s[:i] matches p[:j]
    dp[0][0] = True
    for j in range(2, n + 1):                          # empty s can match "a*b*" style prefixes
        if p[j - 1] == "*":
            dp[0][j] = dp[0][j - 2]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if p[j - 1] == "*":
                dp[i][j] = dp[i][j - 2]                # zero copies of the char before '*'
                if p[j - 2] in (s[i - 1], "."):
                    dp[i][j] = dp[i][j] or dp[i - 1][j]     # one more copy absorbs s[i-1]
            elif p[j - 1] in (s[i - 1], "."):
                dp[i][j] = dp[i - 1][j - 1]
    return dp[m][n]
```

- **一句话洞见**：`dp[i][j]` = `s[:i]` 能否被 `p[:j]` 完全匹配。若 `p[j-1]` 是 `*`：要么让 `*` 前面的字符出现 0 次（看 `dp[i][j-2]`），要么让它再吸收一个字符（当 `p[j-2]` 能匹配 `s[i-1]` 时看 `dp[i-1][j]`）。
- **初值**：`dp[0][0] = True`；`s` 为空时，`p` 形如 `a*b*` 才能匹配。
- **复杂度**：时间 O(m·n)，空间 O(m·n)（可压成两行 O(n)）。

**资深追问**

- **规模 ×1000**：文本很长而模式很短时，改用 NFA 模拟（Thompson 构造），维护「当前状态集合」，O(|text| × |pattern|) 时间、O(|pattern|) 空间，并且天然流式；回溯式引擎在 `(a*)*b` 这类模式上会指数爆炸（ReDoS），RE2 之类的引擎保证线性时间。
- **流式**：NFA 状态集合在线推进，不需要缓冲文本。
- **内存**：两行滚动数组 O(n)。
- **并发**：不同的（文本，模式）对并行；单次匹配串行。
- **接口 / 契约**：支持的语法（只有 `.` 和 `*`）；是**完整匹配**（fullmatch）还是**搜索**；非法模式（以 `*` 开头、连续 `**`）要拒绝而不是产生未定义行为。
- **测试**：与 Python `re.fullmatch` 在小字母表上随机对拍（文件里已有 500 组）；空串与 `a*b*`、`mississippi` 经典用例。

### 4.7 LC 312 · Burst Balloons（Hard）

```python
# solutions/312_burst_balloons.py
def max_coins(nums):
    a = [1] + nums + [1]                      # virtual balloons at both ends
    n = len(a)
    dp = [[0] * n for _ in range(n)]          # dp[l][r]: best coins bursting everything strictly between l and r
    for length in range(2, n):                # widen the open interval (l, r)
        for l in range(n - length):
            r = l + length
            for k in range(l + 1, r):         # k is the LAST one burst: its neighbours are l and r
                dp[l][r] = max(dp[l][r], dp[l][k] + a[l] * a[k] * a[r] + dp[k][r])
    return dp[0][n - 1]
```

- **一句话洞见**：正着想「先戳哪个」，戳完邻居会变，子问题不独立；**倒着想「最后戳哪个」**：区间 `(l, r)` 里最后戳 `k`，此时 `k` 的邻居恰好是 `l` 和 `r`，左右两段互不影响。这是区间 DP（interval DP）。
- **复杂度**：时间 O(n³)，空间 O(n²)。

**资深追问**

- **规模 ×1000**：O(n³) 在 n = 500 以内可用，更大不可行；没有简单的降阶方法，面试里诚实说明并给出剪枝（去掉 0 值气球不影响答案之外的结构）。
- **并发**：同一长度的区间互不依赖，可按「对角线」并行（wavefront）。
- **内存**：O(n²) 表；还原最优戳气球顺序需要多存 `k`。
- **接口**：值为 0 的气球；空数组返回 0；是否要返回具体顺序。
- **测试**：与枚举所有戳法顺序的记忆化暴力对拍（文件里已有）；单个 / 两个气球；全 1；含 0。

## 5. 常见 bug

1. **状态定义含糊**：写 `dp[i]` 前先用一句话说清楚它是「以 i 结尾」还是「前 i 个」——Kadane 的 `ending_here` 是前者，而答案要取所有 i 的最大值。
2. **初值错**：Coin Change 的不可达用 `inf` 或 `amount + 1`，初值 `dp[0] = 0`；二维 DP 的第 0 行 / 列代表空串。
3. **遍历顺序错**：依赖的格子还没算（LC 5 要「右端点在外层」）；LC 518 里「硬币在外还是金额在外」决定算排列还是组合。
4. **全负数的最大子数组**：初值写成 0。
5. **直接用贪心**：Coin Change 的 `[1,3,4]` 反例。
6. **记忆化函数的参数不可哈希**：传了 `list`。转成 `tuple`。
7. **`@lru_cache` 没清理**：在多测试用例的场景里跨用例共用缓存（如果函数依赖外部变量会出错）。
8. **递归 DP 深度**：n = 10⁵ 的链式依赖会 `RecursionError`；改自底向上。

## 6. 自测题

1. 如何判断一个问题适合 DP？
   <details><summary>答案</summary>(1) 可以拆成子问题；(2) 子问题有重叠（同一个子问题会被多次求解）；(3) 最优子结构：大问题的最优解由子问题的最优解组合而成。</details>
2. LC 53 里为什么答案不是 `ending_here` 的最后一个值？
   <details><summary>答案</summary>`ending_here` 表示「以当前位置结尾」的最大和，最优子数组可以结束在任何位置，所以要对所有位置取最大值 `best`。</details>
3. 为什么 Coin Change 的初值 `dp[0] = 0` 而不是 `inf`？
   <details><summary>答案</summary>凑出金额 0 不需要任何硬币；`dp[c] = dp[0] + 1 = 1` 才能得到「恰好一枚面额为 c 的硬币」。</details>
4. 小编程：打家劫舍（LC 198）——相邻房子不能同时抢，求最大金额。
   <details><summary>答案</summary>`dp[i] = max(dp[i-1], dp[i-2] + nums[i])`；两个变量滚动：`a, b = 0, 0; for x in nums: a, b = b, max(b, a + x)`；返回 `b`。O(n) 时间 O(1) 空间。</details>
5. LC 5 的表格 DP 和中心扩展在时间 / 空间上有什么区别？什么时候选哪个？
   <details><summary>答案</summary>时间都是 O(n²)，空间分别是 O(n²) 和 O(1)；中心扩展更省内存、更易写，除非面试官想考二维 DP 的表达；n 很大时用 Manacher O(n)。</details>
6. 资深追问：Coin Change 的 `amount` 是 10¹²，硬币面额是 `[1000003, 1000033]`，怎么办？
   <details><summary>答案</summary>DP 表放不下。以最小面额 `m = 1000003` 为模，状态是「余数」，边是「加一枚另一种硬币」，用 Dijkstra 求到每个余数的最少花费（最短路），状态数只有 m；然后对每个余数用 `(amount - cost) // m` 补足最小面额的硬币。核心思想是把伪多项式的金额维度换成「余数」维度。</details>
