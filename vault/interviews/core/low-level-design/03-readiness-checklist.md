# 验收清单

每一条都要不看资料做到。做不到的，回到括号里的阶段。

## 建模（阶段 1）

- [ ] 拿到需求，5 分钟内列出核心对象、各自职责和它们之间的关系。
- [ ] 能说清一个类为什么存在；说不清的就合并或删掉。
- [ ] 知道什么时候用 dataclass、Enum、Protocol、ABC，以及什么时候一个函数就够了。
- [ ] 不用继承也能表达变化，并能说出继承在什么情况下才合适。

## 模式（阶段 2）

- [ ] 策略、观察者、状态、命令：各说出一个用了它的场景和一个不该用它的场景。
- [ ] 能把一个状态机写成转换表，并说出非法转换怎么处理。
- [ ] 面试官加一个新需求时，能指出改动落在哪、哪些类不用动。

## 组件（阶段 3）

- [ ] 不查资料写出 O(1) 的 LRU；说清 LFU 比它多维护什么。
- [ ] 过期有惰性和定期两种清理，能说出各自的代价。
- [ ] 时间由外部注入，测试不靠 sleep。
- [ ] 错误用明确的异常表达，调用方不需要猜。

## 并发（阶段 4）

- [ ] 说清 GIL 保证什么、不保证什么，为什么 `count += 1` 还是会出错。
- [ ] 每把锁能说出它保护的不变量，以及锁的范围为什么到这里为止。
- [ ] 不查资料写出有界阻塞队列，说清条件变量为什么要放在 while 循环里等待。
- [ ] 预订类题能讲清楚怎么防超卖、怎么释放超时的预留。
- [ ] 能说出死锁的常见成因和避免方法。

## 业务与支付（阶段 5）

- [ ] 金额全程用整数或 Decimal，能说出舍入发生在哪一步。
- [ ] 能讲清幂等键存什么、重复请求返回什么、并发的重复请求怎么处理。
- [ ] 复式记账：说出为什么余额是算出来的，以及借贷必须相等怎么保证。
- [ ] 乱序事件和重复事件来了，结果不变或者能解释为什么变。

## 现场（阶段 6）

- [ ] 前 8 分钟问清需求并定好接口，不是直接开写。
- [ ] 第 1 关在 25 分钟内跑通。
- [ ] 写的时候一直在说话，面试官不需要猜你在干什么。
- [ ] 留出时间跑一遍例子，自己发现问题。
- [ ] 追问时能先说改动范围，再动手。
