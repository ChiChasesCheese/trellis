# 海战棋：题解

**一句话。** 每个玩家一份 `_Side`（待摆舰队、格子到船的反查表、已被打过的格子），三态 `Phase` 驱动流程，所有校验都在改状态之前做完。

**关键决策。**
- 用 `Phase` 枚举驱动流程，放弃"`started`、`finished` 两个布尔"：两个布尔有四种组合，其中两种没有意义，而枚举只有三个合法状态。
- 船只有长度，不做 `Carrier`、`Destroyer` 之类的子类。放弃继承，因为各种船的行为完全相同，差别只有长度，用数据表达（`fleet` 元组）就够了，规则变体也只需改配置。
- `_Side.at` 把格子映射到船，开火是一次字典查询。放弃"每炮扫描所有船的所有格子"，那是 O(舰队总格数)，而且代码更长。
- 船自己记录命中的格子（`hits`），`sunk` 是 `len(hits) == len(cells)`。放弃另存一个 `sunk` 布尔，因为它必须和 `hits` 同步更新，漏一处就出错。
- 开火先校验（阶段、轮次、越界、重复），最后才调用 `_apply`。放弃"边打边检查"，因为齐射要求要么全打要么一发不打，把"校验"和"施加"分成两个函数，齐射直接复用。
- 胜负判定放在换人之前（`_after_turn`）：打沉最后一艘船时游戏结束，`current_player` 变 `None`，不会出现"赢了但还在轮到对手"的状态。
- 规则变体放进不可变的 `Rules`，默认值等于前几关的规则。放弃把变体写成子类 `Game`，因为变体会组合（不许紧贴加连击加齐射），子类数量会爆炸。
- `board_view` 按"谁在看"决定显示什么，只读、返回新列表。放弃让调用方自己拿内部字典，那会泄露对手的船位。

**写法。**
- 状态机用 `Enum`（`Phase`）加入口处的守卫：`place_ship` 和 `fire` 开头先看阶段，再看参数，再改状态。两个布尔标志有四种组合，其中两种没有意义，非法组合在代码里无处可防。属于"枚举状态加守卫"。
- 校验和施加拆成两步：`_check_shot` 只检查，`_apply` 只修改。齐射因此可以先把所有炮弹检查一遍再统一施加，单发开火复用同一对函数。写成"边查边改"的版本，齐射中途失败就要回滚。属于"两阶段提交（先验证后施加）"。
- `_Side.at` 是格子到船的反查字典，开火是一次查询。扫描全部船的全部格子是 O(舰队格数)，每炮都要付。属于"反向索引"。
- 数据类用 `slots=True`，`Rules` 再加 `frozen=True`：规则是不可变配置，传进 `Game` 后不会被外面改；`slots` 去掉每个实例的 `__dict__`。属于"不可变配置对象"。
- 沉没由 `len(hits) == len(cells)` 现算（`@property`），不另存布尔。另存就要在每次命中时同步，漏一处就出现"打满了却没沉"。属于"派生状态不存储"。

**每关怎么走。**
- 第 1 关：先写 `Phase`、异常、`_Ship`、`_Side`，再写 `place_ship`（长度额度、越界、重叠）和 `fire`（反查、命中、沉没）。摆放完成的判定放在 `place_ship` 的末尾。
- 第 2 关：加 `current_player`、`_check_can_shoot`、`_after_turn`，把 `fire` 的收尾改成调用后者。
- 第 3 关：`Rules` 的两个开关各只动一两行：相邻检查在 `place_ship` 里，连击是 `_after_turn` 的 `extra` 参数。视图是一个独立的只读方法。
- 第 4 关：`fire_salvo` 先整体校验（用 `seen` 集合检出齐射内部重复），再统一施加。

**易错。**
- 摆放失败时额度已经被扣掉，或船已经登记了一半。
- 重复开火也换了人；越界开火也换了人。
- 沉没后忘了先判胜负就换人，导致 `current_player` 指向一个游戏已结束的对手。
- 相邻检查只查上下左右，漏了斜角；或者把对手的船也算进去。
- 视图直接返回内部列表，调用方一改就破坏游戏。
- 齐射中途遇到非法坐标，前几发已经生效。

**追问。**
- 想加"AI 对手"？答：对战循环放在 `Game` 外面，AI 只通过 `board_view` 和 `fire` 说话，引擎不用改。
- 想支持任意形状的船？答：`_Ship` 本来就存格子集合，只要 `place_ship` 接受格子列表即可。
- 想支持多于两名玩家？答：`_sides` 变成列表，`current_player` 按顺序轮转，目标选择变成参数。
- 想做回放或撤销？答：把每次成功的操作记成事件，状态由事件重放得到。

**级别期望。** 初级：第 1 关正确，规则散在 `if` 里也行。中级：第 2、3 关通过，阶段和反查表设计清晰。高级：主动提出校验与施加分离、规则用配置而不是子类、视图不泄露内部状态，并能讲清变体组合时为什么不用继承。
