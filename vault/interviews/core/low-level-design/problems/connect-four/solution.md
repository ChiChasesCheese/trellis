# 四子棋：题解

**一句话。** 三层，各管一件事：`Game` 是只懂规则的棋盘，`GameService` 在它外面管身份、轮次和并发，`best_move` 只用 `drop / undo` 做搜索；每一层只依赖下一层公开的接口。参考实现见 `solution.py`。

**关键决策。**

- 棋盘按列存成栈。落子就是往某一列的栈顶压一个，重力不需要计算；放弃的做法是二维数组加"从底往上找第一个空格"，每次落子多一个循环，列满的判断也要另写。栈的长度同时就是这一列的高度。
- 判赢只看刚落的那个子。输赢只可能由新子触发，所以沿四个方向各向两边延伸，数同色连续的格子；放弃的做法是每步扫整个棋盘（`O(行 x 列 x 方向)`）。
- 规则层不认识"玩家"，只认标记。把"谁的回合""谁认输""超时"放进规则层，规则层就要知道时间和身份，没法单独测试，也没法被机器人当模拟器用。
- 失败的落子不改任何状态，检查顺序固定：`GameOver`、`InvalidColumn`、`ColumnFull`。先结束再看列号，是为了让"对局已结束"这个回答不依赖调用方传的什么参数。
- 撤销是规则层的能力，不是机器人私有的。有了 `undo`，搜索可以"落子、递归、撤销"，不用每个节点复制整个棋盘；它同时也是悔棋和回放需要的东西。
- 服务层每局一把锁，全局锁只保护字典。放弃的做法是整个服务一把锁：不同对局互相排队。同一玩家并发落子靠锁加回合检查，后到的看见已经轮到对手，拿到 `NotYourTurn`。
- 超时惰性判断。放弃的做法是为每局起定时器或后台线程：多一类竞态，而超时只有在有人访问对局时才需要被观察到。

**写法。**

- 数据结构即规则：`list[list[str]]` 按列的栈。`len(stack)` 就是高度，`stack.append` 就是重力，`pop` 就是撤销；二维数组要自己维护"每列的高度"，两份数据迟早对不上。模式：选对数据结构，让规则成为它的自然操作。
- 方向表 `_DIRECTIONS = ((0, 1), (1, 0), (1, 1), (1, -1))` 加"两个符号向两边延伸"的双重循环。四个方向共用一段代码，改成别的连子规则只需要改表；四段复制的代码改一处漏三处。模式：数据驱动（方向表）。
- `@contextmanager` 写 `_locked(game_id)`：先在全局锁下查出对局，立刻放掉，再持有这一局自己的锁并 `yield`。每个公开方法都是 `with self._locked(gid) as m:`，不会忘记解锁，也不会把"查字典"和"持有局锁"的顺序写错。模式：上下文管理器（作用域内持有资源）。
- 惰性过期加注入时钟 `clock`：`_settle` 在每次访问时比较 `clock() - turn_started`。测试里换成假时钟，没有 `sleep`，也没有后台线程。模式：惰性过期与注入时钟。
- 落子、递归、撤销：`best_move` 里 `drop` 之后递归，返回后 `undo`，同一个 `Game` 对象被整棵搜索树复用；配合 `copy()` 保证调用方的棋局不被碰。每个节点复制棋盘要多出 `O(行 x 列)` 的分配。模式：回溯（make / unmake）。

**每关怎么走。**

1. 第 1 关：先写构造函数里的参数校验和 `cell`，再写 `drop`（先检查、后修改），然后 `_line_through`，最后 `status`、`winner`、`current_player`。最后一个子同时放满棋盘又连线，先看有没有线。核心代码约 75 行。
2. 第 2 关：`undo` 是 `drop` 的逆操作：弹出栈顶和历史里最后一项，清掉结果。`winning_line` 来自 `_line_through` 的结果，所以第 1 关就要把线存下来，不要只存"有没有赢"。`from_moves`、`copy` 都建立在 `drop` 上。
3. 第 3 关：先写 `_Match` 和 `_locked`，再写 `move` 的校验顺序，然后 `resign` 和 `_settle`。并发测试靠"锁内先看回合再落子"就能过。
4. 第 4 关：先让 `best_move` 能在深度 1 找到立即获胜，再加深度和 alpha-beta。走法排序（中间列优先）会让剪枝更有效。

**易错。**

- 失败的 `drop` 已经改了棋盘或换了回合。
- 判赢只数一侧，漏掉新子落在中间把两段连起来的情况。
- 斜线用错符号，或者越界时下标变负数、绕到另一端（Python 的负下标不会报错）。
- 放满棋盘的最后一子赢了，却报平局。
- `undo` 之后没有清掉赢家，或者只弹了栈没弹历史。
- 服务层把棋盘或内部的 `Game` 交出去，调用方可以绕过轮次检查。
- 超时的玩家再落子时，错误是 `NotYourTurn` 而不是 `GameOver`。
- 机器人在传入的对局上直接搜索，出错时留下半截棋局。

**追问。**

- 位棋盘（bitboard）：每个玩家一个整数，判四连只要几次移位与按位与，搜索快几十倍；代价是代码更难读，机考里先写清楚版本。
- 搜索加速：置换表缓存已经算过的局面；迭代加深；开局库。
- 局面估值：数每个玩家"还能连成"的窗口（四格里只有自己的子和空格），比中心加权更准。
- 观战与断线重连：`view` 已经是快照；事件推送用订阅挂钩，规则层不用改。
- 持久化：只存落子序列 `moves`，用 `from_moves` 就能恢复，棋盘是它的派生物。
- 多于两个玩家、更大的棋盘：规则层已经支持；机器人要换成多人搜索。

**级别期望。**

- 中级：棋盘、重力、轮流、判赢、平局、错误处理，测试能跑通。
- 高级：只检查新子的四个方向、失败不改状态、撤销与回放、服务层身份与轮次、每局一把锁。
- 资深：规则与身份分层、惰性超时与注入时钟、不可变快照、搜索与剪枝，并能说清位棋盘和估值函数这类扩展为什么在 60 分钟里先不写。
