# 图像变换流水线：题解

**一句话。** 图像和步骤都是不可变值对象，流水线是步骤元组；形状推演和像素计算分开，缓存以 `(图像, 步骤前缀)` 为键，化简只做保证等价的改写。

**关键决策。**
- 图像存成元组的元组，构造时拷贝并校验。放弃"直接持有调用方传入的列表"：调用方之后一改，缓存里的键就失效了，同一个对象会变成另一个值。
- 步骤是各自独立的小类，共享 `apply` / `output_size` 两个方法（`Protocol`）。放弃"一个 `Step` 基类加 `if kind ==` 分发"：新增步骤只需新增一个类，流水线、缓存、校验全都不用改。
- `output_size` 单独存在，只算形状。放弃"先跑一遍看会不会出错"：大图上跑一遍很贵，而且缓存已经被半截结果污染了。第 3 关的 `run` 一开始就调用它。
- 缓存键是 `(输入图像, 步骤前缀)`，每个前缀单独存一项。放弃只缓存最终结果：两条共享前三步的流水线本来可以只算最后一步。放弃用 `id(image)` 做键：内容相同的另一个对象会错过缓存，对象被回收后 id 还可能被复用，造成错误命中。
- 查找从最长前缀往短找，命中的项移到最近使用端。放弃"只看完整流水线是否命中"，那样共享前缀就没有意义。
- 化简只做能证明等价的改写。亮度调整带截断：同号时 `min(255, min(255, x+a)+b)` 等于 `min(255, x+a+b)`，可以合并；一正一负时截断发生在中途，合并就错了。放弃"按数学直觉合并所有亮度"，用随机流水线对照原结果的测试能抓到它。

**写法。**
- 步骤和图像用 `@dataclass(frozen=True, slots=True)`：自动得到按值比较、哈希和不可变，`slots` 省掉每个实例的字典。普通类要手写 `__eq__` 和 `__hash__`，漏掉哈希就不能做缓存键。属于"不可变值对象"。
- 步骤接口用 `typing.Protocol`：结构化类型，步骤不必继承任何基类，类型检查器也能检查 `Pipeline` 里放的东西。继承基类的写法会把所有步骤绑在一个层级上。属于"鸭子类型加静态检查"。
- 化简里的 `_merge` 用 `match` 加类模式（`case Rotate(n), Rotate(m)`）：同时按两个步骤的类型和字段分派，守卫 `if d1 * d2 >= 0` 直接写在规则旁边。`isinstance` 链读起来要先拆字段、再比较。属于"代数数据类型上的模式匹配"。
- 缓存用 `collections.OrderedDict`，`move_to_end` 刷新、`popitem(last=False)` 淘汰：两个调用就是 LRU。自己维护列表要线性扫描。属于"LRU 缓存"。
- `Image.__post_init__` 里用 `object.__setattr__` 在冻结对象上做一次规范化。普通赋值会被冻结拦下；不规范化就要把"拷贝并校验"放在每个调用点。属于"构造时规范化的不可变对象"。

**每关怎么走。**
- 第 1 关：`Image` 与五个步骤，再写 `Pipeline.apply` 和 `StepError` 的包装（捕获步骤的 `ValueError`）。
- 第 2 关：`Resize`、`output_size`（每个步骤各一个，不碰像素）、`then` 与 `+`。
- 第 3 关：`CachedRunner.run`：先校验，再找最长前缀，再逐步执行并存入缓存。
- 第 4 关：`simplified` 用栈：新步骤与栈顶尝试合并，合并成功就弹出栈顶继续往下试。

**易错。**
- 图像里保留了调用方的列表。
- 流水线执行到一半才发现裁剪越界，缓存里已经留了半截结果。
- 缓存只存最终结果，或者键里漏了输入图像（不同图像共用同一项）。
- 命中缓存后没有刷新最近使用，淘汰了刚用过的项。
- `Rotate` 对负数或大于 4 的转数处理错；`Rotate` 之后宽高没有互换。
- 化简合并了一正一负的亮度，或合并后没有继续与更前面的步骤尝试。

**追问。**
- 想支持彩色图？答：像素从整数变成元组，`Image` 校验与 `Brighten`、`Invert` 的逐像素函数变化，流水线和缓存不变。
- 缓存的内存怎么控制？答：按字节而不是按项数计量，或者只缓存每隔 k 步的前缀。
- 步骤能不能并行？答：流水线的每步依赖上一步，但同一步内部可按行分块并行；不同输入图像之间天然并行。
- 想让相邻的逐像素步骤融合成一次遍历？答：给逐像素步骤加一个 `pixel_fn`，化简时把相邻的逐像素步骤合成一个函数组合，再一次遍历。
- 步骤的顺序什么时候可以交换？答：逐像素步骤与几何步骤互相可交换，把裁剪提前能减少后面的工作量。

**级别期望。** 初级：第 1 关的步骤和流水线正确。中级：第 2、3 关通过，缓存键与失效处理清楚。高级：主动提出不可变值对象、校验与计算分离、化简的等价性依据，并能谈缓存的内存与并行策略。
