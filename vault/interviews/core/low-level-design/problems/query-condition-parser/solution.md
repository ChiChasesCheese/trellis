# 条件解析与内存表查询：题解

**一句话。** 把任务拆成三层：词法（字符串变 token）、语法（token 变语法树）、求值（语法树在每一行上算真假）；难点只有一个，优先级，靠"每个优先级一个递归函数"解决，参考实现见 `solution.py`。

**关键决策。**

- 递归下降，而不是 `split` 或调度场算法（Shunting-yard）。文法的每一行对应 `_Parser` 的一个函数，优先级低的先调用、后结合，所以 `AND` 先把操作数收走；括号回到最低优先级的函数。`split("AND")` 处理不了引号里的 `AND` 和括号；调度场不用递归，但 `IN (a, b)`、`IS NOT NULL` 这类多段语法很别扭。
- 解析和存储分开。语法树只认 `matches(row)`，`Table` 只负责存行和调用。换成别的存储不用改解析，加运算符不用改表。
- `matches` 返回 `True / False / None`。放弃的做法是"缺值当假"：那样 `NOT age >= 18` 会多返回 age 为空的行，而且和真实数据库的结果不一致。`select` 只保留 `is True` 的行。
- 索引只产生"候选行号的超集"，最后一律复查完整条件。放弃的做法是"索引命中就是结果"：`AND` 的另一边、`OR`、`NOT` 都会让它出错。`AND` 取交集或任一边，`OR` 必须两边都能用索引才取并集，其余返回 `None` 表示全表扫描。
- 校验列在解析阶段做，不在求值阶段做。放弃的做法是"求值时 `row[field]` 抛 `KeyError`"：空表就永远发现不了拼错的列名，错误取决于数据。
- 文档表复用同一套解析和求值，只把 `row[field]` 换成按点号取路径的 `_get`，缺失得 `None`，所以第 4 关几乎不用改动前面的代码，前提是第 2 关的 NULL 语义已经正确。

**写法。**

- `@dataclass(frozen=True, slots=True)` 写语法树节点。节点只有字段、没有可变状态，冻结后可以被多线程共享，也能当缓存值；`slots` 省掉每个节点的 `__dict__`。手写 `__init__ / __eq__ / __repr__` 每个节点多出五六行，还可能被谁悄悄改掉字段。模式：不可变值对象。
- `functools.lru_cache` 缓存"条件字符串 -> 语法树"。正因为节点不可变，同一棵树才能被所有表、所有线程复用。自己写字典缓存要处理淘汰和线程安全，而且缓存的树万一被改了就是隐蔽的错。模式：记忆化（Memoization）。
- `match` 语句按节点类型选索引策略（`_candidates`）。`case _And(left=l, right=r)` 一行完成"判断类型加取字段"，每个分支对应一条规则，漏掉的类型落到 `case _`。`isinstance` 链加属性访问写出来更长，也看不出分支是否穷尽。模式：模式匹配（访问者的轻量替代）。
- `Protocol` 声明 `_Node`：只要有 `matches(row)` 就是节点。用抽象基类要求所有节点继承它，节点是数据类时多一层没有收益的继承。模式：结构化类型。
- `MappingProxyType` 包住运算符表。表是模块级常量，只读视图让任何地方都改不动它；普通 `dict` 只能靠约定。模式：只读视图。

**每关怎么走。**

1. 第 1 关：先写 `_tokenize`（引号整段一个 token，长运算符写在前面），再写 `_Cmp / _And / _Or`，最后写解析。顺序是"只有比较" -> 加 `AND` -> 加 `OR` -> 加括号，每加一步就跑例子。完成后核心代码约 105 行。
2. 第 2 关：新增 `_Not / _In / _IsNull`，解析多一层 `_not`（夹在 `_and` 和 `_primary` 之间）。然后只改三个节点的 `matches`，让它们返回三值。
3. 第 3 关：`_index` 是 `列 -> 值 -> 行号列表`，`insert` 里同步维护。`select` 先问 `_candidates`，再在候选上复查。候选行号要排序，保证结果仍是插入顺序。
4. 第 4 关：`columns=None` 时不校验，`_get` 按点号取路径。

**易错。**

- 长运算符写在后面，`<=` 被切成 `<` 和 `=`。
- `NOT` 写成 `and_expr` 之下、`primary` 之上的一层；写成最外层，`NOT a AND b` 会变成 `NOT (a AND b)`。
- 二元节点用 Python 的 `and` / `or` 直接组合三值：`None and False` 得 `None`，而正确答案是 `False`。
- `OR` 只用一边的索引，漏掉另一边满足条件的行。
- 候选集直接当结果，不复查，`AND` 的非索引一边被忽略。
- 返回内部的行字典，调用方改了返回值，表里的数据跟着变。
- 索引建在数据之后却没把已有行放进去。

**追问。**

- `LIKE`：`%` 转 `.*`，`_` 转 `.`，其余字符 `re.escape`，用 `re.fullmatch`。
- 范围查询走索引：有序列表加 `bisect`，查询 `O(log n + k)`，插入 `O(n)`；真实数据库用 B+ 树。
- 排序遇到 NULL：`None < 3` 会报错，排序键用 `(v is not None, v)`。
- 频繁查询：缓存"条件字符串 -> 语法树"，语法树不可变，可以共享。
- 并发：读多写少用读写锁，行和索引在同一把锁里更新。
- 完整 `SELECT`：在 `_Parser` 前后加列名、表名、`ORDER BY`、`LIMIT`；`JOIN`、`GROUP BY` 要把执行层改成算子链。

**级别期望。**

- 中级：词法、语法分开，优先级和括号正确，例子跑通，坏输入有明确错误。
- 高级：`NOT`、`IN`、NULL 三值逻辑正确，索引只做候选再复查，说得清 `OR` 为什么用不了单边索引。
- 资深：主动控制范围；说清解析与存储的边界、校验时机、缓存和并发的演进；能口述范围索引和 `LIKE`。
