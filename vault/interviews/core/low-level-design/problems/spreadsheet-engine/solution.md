# 电子表格引擎：题解

**一句话。** 公式在 `set` 时解析成语法树并登记依赖边，改一个格子就沿"谁读我"的边按拓扑序把下游各算一次，`get` 只读缓存，环在改动之前就被拒绝。

**关键决策。**
- 公式存成语法树（`parse_raw`），不存字符串。选它是因为语法错误必须在 `set` 时当场报出并保持原样；每次 `get` 重新解析字符串是被放弃的做法，既慢又把错误推迟到读的时候。
- 求值函数 `evaluate(node, read)` 不知道格子存在哪里，只通过 `read` 取值。第 1、2 关让 `read` 递归求值（惰性），第 3 关换成读缓存；解析和求值不用改。
- 两张边表：`_deps` 是我读谁，`_users` 是谁读我。放弃"每次改动全表重算"，因为 `eval_count` 要求不相关的格子不被碰；放弃"只存 `_deps`"，因为反向找下游要扫全表。空格子也允许有 `_users`，所以先写公式后填引用能工作。
- 重算顺序用 `_users` 上的后序遍历再反转。放弃"递归地把每个下游各算一遍"，因为菱形的 `D1` 会被两条路径各算一次，而且第一次算时用到了还没更新的 `C1`。
- 出错状态存进缓存（`EvalError` 本身当作值），`_read` 读到就重新抛。放弃"算到一半抛出去"：那样重算停在中途，其余下游留着旧值，表格不一致。
- 环检测放在 `set` 里、动手改状态之前：从新公式的依赖出发，沿 `_deps` 能走回这个格子就拒绝。放弃"先改后检测再回滚"，因为回滚要恢复两张边表和缓存，漏一处就留下脏状态。
- 区间展开成它覆盖的每一个格子登记依赖（包括空格子），这样第 2、3 关的机制不用为区间改一行。

**写法。**
- 语法树节点用 `@dataclass(frozen=True, slots=True)`（`Num`、`Ref`、`Neg`、`Bin`、`Func`），求值和找依赖都用 `match` 加类模式（`case Bin(op, left, right)`）：每种节点一个分支，字段直接拆出来，漏掉一种节点一眼可见。用元组加字符串标签（`("bin", "+", l, r)`）要靠下标取值，改字段顺序就悄悄出错。属于"代数数据类型加模式匹配"。
- `evaluate(node, read)` 把"怎么读格子"作为函数参数传入，求值函数本身不知道格子存在哪里。直接在求值里访问 `self._val` 会把解析求值和缓存策略焊死，第 1 关的惰性递归与第 3 关的缓存就得写两套。属于"依赖注入（传函数）"。
- `cells_in` 是生成器，区间按需产出格子名，`refs_of` 和 `evaluate` 共用。先建完整列表要多占内存，也容易在两处各展开一遍。属于"生成器流水线"。
- `set` 里先 `parse_raw`、再 `_reaches`、最后才改状态：所有可能失败的步骤排在任何写入之前，失败时表格原样。边写边检查的版本要手工回滚两张边表。属于"校验在先、提交在后"。
- 出错状态把 `EvalError` 实例本身存进缓存，读取时重新抛出。用"算到一半抛出去"的写法，重算会停在中途，其余下游留着旧值。属于"错误即值"。

**每关怎么走。**
- 第 1 关（约 85 行代码）：`check_cell`，几个语法树小类（`Num`、`Ref`、二元运算 `Bin`，第 1 关只有 `+`），`parse_raw` 里用 `split("+")` 逐项判断是数字还是格子，递归的 `get`，`set` 先解析、再用 `_reaches` 查环、最后才写入。只存 `_node` 和 `_deps` 两张表，求值是惰性的。
- 第 2 关：把 `split` 换成分词加递归下降（`expr` 管加减，`term` 管乘除，`unary` 管负号，`atom` 管数字、引用、括号），求值多几个运算符和 `EvalError`。语法树、`set`、环检测一行不动。
- 第 3 关：加 `_users`、`_val` 缓存、`_recalc`、`eval_count`；`get` 改为读缓存，出错状态存进缓存。
- 第 4 关：`atom` 里多一个函数分支，`refs_of` 展开区间，`evaluate` 多一个分支；其余不动。

**易错。**
- 改线时忘了从旧依赖的 `_users` 里删掉自己，之后误报环，或白白多算。
- 清空格子忘了重算它的下游。
- 菱形被算两次；或者按"发现顺序"而不是拓扑序算，用到旧值。
- 先改了边表再发现有环，抛异常时表格已经被改坏。
- `MIN` 把空格子当 0；区间 `B1:A1` 没被拒绝。
- `a1`、`A0`、`A01` 这类名字放行。

**追问。**
- 一次改动波及十万个格子怎么办？答：重算本身是 O(波及面)；深链用迭代的后序遍历避免栈溢出，必要时把重算放到后台并标记"脏"。
- 想支持跨表引用、命名区域？答：格子名变成 (sheet, cell) 二元组，`refs_of` 与两张边表的键随之变化。
- 想做撤销？答：`set` 返回或记录前一个 `raw`，撤销就是再 `set` 一次，边表自动同步。
- 想加线程安全？答：`set` 是读-改-重算的整体，整张表一把写锁；`get` 只读缓存，可用读写锁。
- 想显示 `#CYCLE!` 而不是拒绝赋值？答：环里每格存一个 `EvalError`，不再抛 `CycleError`，但重算的拓扑序要对环单独处理。

**级别期望。** 初级：第 1 关通过，惰性递归即可。中级：第 2、3 关通过，写得出递归下降，说清拓扑序和为什么不重算全表。高级：主动提出解析与求值解耦、出错状态传播、改动前检测环，并能谈规模化时的栈深和波及面。
