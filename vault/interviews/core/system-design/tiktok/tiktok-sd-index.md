# TikTok 系统设计题单（System Design Questions）

这里每一篇都是一道完整的系统设计题：先用大白话讲清这个系统是什么、难在哪里，再按面试的顺序走一遍：澄清问题、需求、容量估算、API、数据模型、高层设计、深挖、故障与边界、追问、评分要点。标准按 senior 写：每个选择都说清楚「是什么逼出了它」和「它换来了什么、代价是什么」，每个数字都能当场重新算出来。

TikTok 的设计轮和别家有一个明显的不同：题目常常是团队真实业务里的一个模块（支付、直播礼物、榜单），面试官不在乎你画了多少个方框，而在乎你在「任意一步崩溃、消息重复、数据迟到、一个键过热」这些场景下，系统怎么收敛到正确。所以每篇的深挖都围绕一条流程的失败行为展开。

和具体题目无关的通用知识（复制、分区、缓存、一致性……）在 [[System Design MOC|系统设计域]]。方法与词汇可以先读 [[00_how_to_run_the_round]] 和 [[00_ddia_refresh]]。

## 贯穿所有题的五个问题

面试官往往只盯一条流程连问四五个问题。下面五个问题几乎可以套在每一道题上，练的时候对每道题都自己问一遍。

| 问题 | 标准回答的骨架 | 在哪几篇里最完整 |
|---|---|---|
| 重试、重复、双击会不会产生两次效果？ | 每个入口一个去重键；至少一次投递加幂等处理；唯一约束兜底 | SD01、SD02、SD04 |
| 这一步崩溃了，系统停在什么状态？ | 先记意图再动手；状态单调前进；恢复任务用同一个键重放 | SD01、SD04、SD06 |
| 你怎么知道结果是对的？ | 独立数据源对账；守恒不变量；夜间批处理校正流式结果 | SD01、SD02、SD03 |
| 一个键突然过热怎么办？ | 先算数字确认是否真的成问题；预聚合、加盐、分桶；把热点移出同步路径 | SD02、SD03、SD04 |
| 精确还是近似、强一致还是最终一致？ | 先问；算出精确的代价；说明误差只影响边界 | SD03、SD05、SD08 |

## 怎么跑这一轮

**这一轮长什么样。** 通常 45 到 60 分钟；在混合的一小时里可能只有 15 到 30 分钟（经理面里先聊项目、写一道代码，剩下一点时间做设计）；偶尔会连续一两个小时深挖。题目可能只有两句话，也可能是一份很长的内部需求，面试官不一定回答你的澄清问题，这时直接说出你的假设并写在白板角落。有的轮次没有画图工具，只能在代码编辑器里打字：把图改写成带编号的步骤列表，每一步写清「谁调用谁、写了什么、失败了怎么办」，这和有白板时的口述一样有效。

**面试官怎么追一条流程。** 你列完需求、实体，写出主流程，画完图之后，面试官会挑其中一条流程，连续问四五个问题，这才是这一轮的重点。常见的追问方向：这一步崩溃了怎么办；这条消息重复、迟到、丢了怎么办；这个键过热怎么办；你怎么知道结果是对的；这个数字你是怎么算出来的。你可以主动把他引到你最强的一条流程上：画完图就说「我想深入讲这一步，因为这里最容易出错」，把选择权拿在自己手里。

**评分最看重的几件事。**

- **先估算**：QPS、每条事件的字节数、存储、带宽，并把数字接回设计决策（「所以单机放得下，难点不在容量」）。
- **精确还是近似**：开场就问，并说出代价。没问就开画，是明确的失分点。
- **分离摄入、聚合、服务**：三段各自能降级，各自有积压指标。
- **失败行为多于画图**：崩溃、重复、迟到、背压、死信，以及通知路径本身在部分系统宕机时是否可用。
- **工具的机制**：窗口类型、Count-Min Sketch 的误差界、Kafka 的分区与顺序、Redis 脚本的原子性。说得出机制，而不是只报工具名。
- **运维形状**：延迟与积压指标、审计、规则不重新发布就能更新、灰度与回滚。

**时间预算（60 分钟）。**

| 分钟 | 做什么 | 时间不够时 |
|---|---|---|
| 0–5 | 澄清：规模、精度、一致性底线、范围；把硬性约束写成一句话（如「不重复扣款」） | 只问规模和底线，其余自己声明假设 |
| 5–10 | 估算：QPS、峰值、存储，并说出「驱动设计的那个数字」 | 只讲两个数字 |
| 10–15 | 实体与 API：幂等键、分页、状态码 | 口述，不写字段 |
| 15–25 | 高层图：读写分路，走一遍主流程，每一步标出失败时发生什么 | 不能省 |
| 25–45 | 深挖：先讲面试官问的一条，再讲你选的一条；每条都是「决定、替代方案、理由、代价」 | 只做两条 |
| 45–55 | 故障与边界：崩溃、重复、迟到、热点、对账；爆炸半径 | 只讲三个最危险的 |
| 55–60 | 总结与最弱一环 | 一句话收束 |

**30 分钟版。** 5 分钟澄清加估算，5 分钟画图，15 分钟只深挖一条（面试官挑的那条），5 分钟故障与总结。不要试图覆盖全部功能：支付题里退款、打款、双 PSP 各用一两句口述规则；榜单题里趋势榜、全球合并用一两句话带过。主线先讲完，宁可浅，也不要把时间耗在一个细节上而没有讲到失败处理。

**怎么练。**

1. 先读表里「先读的通用题解」，再读这里的题解。这里假设你已经知道通用版本，重点是每道题自己的难点和 senior 深挖。
2. 合上页面，计时 8 分钟，口述一条流程：先说硬约束，再列步骤，然后对每一步问四个问题：这里进程崩溃会怎样？这条消息重复来两次会怎样？这条消息迟到或丢失会怎样？这个键过热会怎样？每个问题用一种机制回答（幂等键、状态机、对账、预聚合）。
3. 对着「评分要点」打勾：估算有没有接回设计，精确还是近似有没有说，失败行为有没有覆盖，有没有主动说出最弱的一环。
4. 每篇的追问部分，遮住答案，自己答一遍再对照。
