# S11 · 实习期：Kafka 事件流 · Spring/JPA · Spark 校验（Java / Kafka / K8s 三条 JD 线的证据）

> [!abstract] 一句话
> 2024 夏在同一团队实习：给 fee-validation 扩展 **Kafka → Snowflake 的 CDC 摄取管线**（sink connector + Snowpipe Streaming + 自定义 protobuf converter，坏消息返回 `SchemaAndValue.NULL` 不毒死 task，JSONPath 白名单 SMT 只要 upsert 不要 delete），写 **Kotlin/Spring Boot + JPA** 的合规审计日志模块（`JpaSpecificationExecutor` 动态查询、servlet filter 抓请求体），写 **Spark + Airflow** 的 EOD 合规校验器（pricing schedule 创建来源、settlement 数据合规，结果推 Slack）。消费者和 connector 跑在 Kubernetes 上：一 topic 一 Deployment，replicas × tasks.max 两级并行度，上限是 partition 数。

## 1. 整条事件流（30–60 s 总览的底稿）

```
Gateway 结算 ──protobuf TransactionEvent──▶ Kafka
   ├─▶ Pricing 服务（Kotlin + Spring Kafka，@KafkaListener 批量消费）
   │      查商户账户 → 幂等落库（批量去重 + 唯一约束 + DataIntegrityViolationException）→ 算 BT fee
   │      → 发 fee event 到另一个 topic 给 Funding
   └─▶ Kafka Connect sink（Snowpipe Streaming，schematization=TRUE）
          自定义 Converter：parseFrom(bytes) → JsonFormat → JsonConverter → 列
          CDC：Funding 变更 {table, kind, before, after} → Filter$Value SMT（JSONPath 白名单，@.kind != 'delete'）
          → Snowflake（Snowglobe 做对账 / 费用 / 质检）
批处理层：Spark（读大表做 DataFrame 规则校验）+ Airflow DAG（cron/weekly）事后验数
```

## 2. 追问一句话

| 追问 | 答 |
|---|---|
| 费用怎么不重复 / 不漏？ | Kafka at-least-once 会重投 → 消费侧幂等：落库前批量去重、DB 唯一约束兜并发、catch `DataIntegrityViolationException` 跳过、`BatchListenerFailedException` 精确重投失败那条。at-least-once + 幂等 ≈ effectively-once |
| Connect 怎么扩？ | K8s replicas × connector `tasks.max`，上限被 partition 数卡住；加吞吐先看 partition 够不够 |
| Kafka proxy？ | 放在 broker 前做 SASL SCRAM + 双向 TLS 的代理，凭据走 vault；不是出网代理 |
| proto 怎么落成表？ | 自定义 converter → JSON（保留字段名）→ Snowflake schematization 自动展开；坏消息返回 NULL |
| 实时和批怎么分工？ | 实时（Kafka + Connect，秒级）搬数据、算费用；批（Spark + Airflow，天级）事后校验 |
| 消费者挂了会丢吗？ | 自动提交 + 短间隔更偏 at-most-once；真正防丢靠上游重试 + 对账 / 健康检查（[[S2]]） |

> [!warning] 证据边界
> 简历原句 "Kafka in Kubernetes" 证据薄——**要讲 Kafka 就讲生产的**：Gateway 事件 → Kafka → Snowpipe Streaming 落地表 → Stream/Task；Funding → Snowflake 的 Kafka CDC 管道（terraform 里有对应 funding commit 的注释）。broker / proxy 是平台团队的；我的地盘是**消费 / 落库 / 校验侧**。K8s 只有部署形态经验，没运维过集群（[[05-kubernetes|TS05]] §5）。

## 3. English · 60 s

> As an intern on the same team I worked on the event-streaming side of the fee platform. A settled transaction publishes a protobuf event to Kafka; the pricing service consumes it with Spring Kafka in batches, books it idempotently — dedup before insert, unique constraint as the backstop — computes the Braintree fee and publishes a fee event for payouts. My pieces: I extended the Kafka Connect sink path into Snowflake — Snowpipe Streaming, a custom protobuf converter that returns a null record on a poison message instead of killing the task, and the CDC filter that whitelists tables and drops deletes; I wrote a Spring Boot / JPA audit-log module with dynamic criteria queries; and I wrote Spark validators scheduled by Airflow that check pricing-schedule provenance end of day. Everything ran on Kubernetes as one Deployment per topic, parallelism being replicas times connector tasks, capped by partition count.
