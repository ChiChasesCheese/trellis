## Q
**LC 3665 统计镜子反射路径数目**｜Medium

给你一个 `m x n` 的二进制网格 `grid`：`grid[i][j] == 0` 表示空格子，`grid[i][j] == 1` 表示一面镜子。机器人从左上角 `(0, 0)` 出发，想要到达右下角 `(m - 1, n - 1)`，只能向**右**或向**下**移动。如果机器人试图移入一个有镜子的格子，它会在进入该格子前被反射：试图向右进入镜子，会被转向下方，移动到镜子正下方的格子里；试图向下进入镜子，会被转向右方，移动到镜子正右方的格子里。如果反射会使机器人移动到网格边界之外，该路径无效，不计数。

注意：如果一次反射把机器人移动到另一个有镜子的格子，机器人会立即再次被反射，方向取决于它进入该镜子的方向（向右进入则转向下方，向下进入则转向右方）。

返回从 `(0, 0)` 到 `(m - 1, n - 1)` 不同的有效路径数量，对 `10^9 + 7` 取模。`m == grid.length`，`n == grid[i].length`，`2 <= m, n <= 500`，`grid[i][j]` 为 `0` 或 `1`，`grid[0][0] == grid[m - 1][n - 1] == 0`。

例：`grid = [[0,1,0],[0,0,1],[1,0,0]]` → `5`；`grid = [[0,0],[0,0]]` → `2`；`grid = [[0,1,1],[1,1,0]]` → `1`（`(0,0) → (1,0)` 的镜子把机器人转向右，进入 `(1,1)` 的镜子又转向下，出界，无效；有效路径只有 `(0,0) → (0,1)` 反射到 `(1,1)`，再反射到 `(1,2)`）。

给出完整的最优解答：考点、识别、推导、代码、复杂度、易错点。

## A
**考点。** 网格路径计数 DP，状态带上「进入格子的方向」（二维 DP + 方向维度）。

**核心题。**

- LC 62 不同路径（Blind 75、NeetCode 150、Hot 100）：同一个网格路径计数 DP：这里状态多了进入格子的方向

**一句话。** 因为反射的结果取决于进入镜子的方向，所以把状态拆成两张表：`right[i][j]` 是「向右试图进入 `(i, j)`」的方案数，`down[i][j]` 是「向下试图进入 `(i, j)`」的方案数；空格接住两种进入方式，镜子则把向右进入转成对下方格子的向下进入、把向下进入转成对右方格子的向右进入，答案是终点处 `right + down`。

**识别。** 只能向右/向下 + 数路径数 + 模 `10^9 + 7`，是 LC 62/63 的路径计数 DP；新增的「镜子」让一个格子的转移依赖进入方向，所以不能只开一张 `dp[i][j]`，需要把方向写进状态。镜子连续反射（镜子的下方还是镜子）在这种状态定义下自然处理，不需要循环模拟。

**推导。** 直接做：DFS 模拟每一步，路径数指数级。DP：看格子 `(i, j)` 能被怎样「试图进入」。向右进入它，来源是左边格子 `(i, j-1)`：若左边是空格，机器人本来就停在那里，可以向右走，贡献 `right + down`（两种进入方式都停在这里）；若左边是镜子，它只能是被「向下进入」后转向右而来，贡献 `down[i][j-1]`（向右进入镜子的会转向下，去了正下方，不会走向右）。向下进入同理，来源是上方格子，上方是空格贡献 `right + down`，上方是镜子贡献 `right[i-1][j]`。这个递推里镜子的连锁反射不需要特殊处理：被反射到下一个镜子，只是在那个格子里又记一次进入。

```python
def mirror_paths(grid: list[list[int]]) -> int:
    MOD = 10**9 + 7
    m, n = len(grid), len(grid[0])
    right = [[0] * n for _ in range(m)]     # right[i][j]：向右试图进入 (i, j) 的方案数
    down = [[0] * n for _ in range(m)]      # down[i][j]：向下试图进入 (i, j) 的方案数
    right[0][0] = 1                         # 起点是空格，记作一种方案
    for i in range(m):
        for j in range(n):
            if i == 0 and j == 0:
                continue
            if j > 0:
                if grid[i][j - 1] == 0:     # 左边是空格：停在那里的方案都能向右走
                    right[i][j] = (right[i][j - 1] + down[i][j - 1]) % MOD
                else:                       # 左边是镜子：只有「向下进入」的才被转向右，来到这里
                    right[i][j] = down[i][j - 1]
            if i > 0:
                if grid[i - 1][j] == 0:     # 上边是空格：停在那里的方案都能向下走
                    down[i][j] = (right[i - 1][j] + down[i - 1][j]) % MOD
                else:                       # 上边是镜子：只有「向右进入」的才被转向下，来到这里
                    down[i][j] = right[i - 1][j]
    # 终点是空格，两种进入方式都停在这里；出界的反射本来就没有对应的格子，自然不被计入
    return (right[m - 1][n - 1] + down[m - 1][n - 1]) % MOD
```

运行：示例 1 → `5`；示例 2 → `2`；示例 3 → `1`；`grid = [[0,1],[1,0]]` → `2`；`grid = [[0,0,0],[0,1,0],[0,0,0]]` → `4`。

**复杂度。** 时间 `O(m * n)`，空间 `O(m * n)`（两张 `m x n` 表）。

**易错点。**
- 只开一张 `dp[i][j]` 且把镜子格子的值直接转给下方或右方：同一个镜子既被向右也被向下进入时，两种进入方向的去向不同，合在一起就混了。示例 3 里 `(1,1)` 同时被两个方向进入，都要分开记。
- 镜子格子也当作路径停靠点，从它继续向右/向下走：机器人不会停在镜子上，示例 1 的路径 `(0,1) [M] → (1,1)` 里镜子只是中转。
- 反射后出界忘了排除：在 DP 里这自然成立（没有对应的格子，不会被累加），但如果用「`dp[i+1][j]` 直接加」的写法，要先判断 `i + 1 < m`。

**同模式。** LC 62 不同路径、LC 63 不同路径 II、LC 1301 最大得分的路径数目、LC 576 出界的路径数。
