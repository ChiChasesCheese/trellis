## Q
**LC 4097 合并整数后的最小值**｜Easy · 2026-10-31 解出

给你一个长度为偶数 `n` 的整数数组 `nums`。需要将 `nums` 中的元素两两合并：`nums[0]` 与 `nums[1]` 合并，`nums[2]` 与 `nums[3]` 合并，依此类推，直到 `nums[n - 2]` 与 `nums[n - 1]` 合并。返回所有合并后得到的整数中的最小值。合并两个整数，是指将第二个整数的所有十进制数位拼接在第一个整数的所有十进制数位之后。`2 <= n == nums.length <= 100`，`n` 为偶数，`1 <= nums[i] <= 1000`。

例：`nums = [23,55,42,21]` → `2355`（`2355` 与 `4221` 取小）；`nums = [34,7,11,11]` → `347`（`347` 与 `1111` 取小）；`nums = [9,20]` → `920`。

给出完整的最优解答：考点、识别、推导、代码、复杂度、易错点。

## A
**考点。** 模拟 + 数字拼接，比较的是**整数值**而不是字符串字典序。

**一句话。** 每两个相邻元素拼成一个整数（前一个在高位），在所有拼出的整数里取最小值。

**识别。** 配对方式已经固定（`0` 与 `1`、`2` 与 `3`……），不存在选择，只有一遍扫描加一次取最小；`n <= 100`，`nums[i] <= 1000`，拼接结果最多 8 位，不会溢出。

**推导。** 直接拼接：`int(str(a) + str(b))`，按步长 2 配对。也可以用算术拼接 `a * 10 ** len(str(b)) + b`；两者同为 `O(1)` 级别（数字最多 4 位）。关键只有一点：先转成整数再比较，因为不同位数的拼接结果，字典序和数值大小不一致。

```python
def min_merged(nums: list[int]) -> int:
    # 步长 2 配对：nums[0::2] 是每对的前一个，nums[1::2] 是后一个
    # f"{a}{b}" 把 b 的数位接在 a 之后；转成 int 再取最小，比较的是数值
    return min(int(f"{a}{b}") for a, b in zip(nums[0::2], nums[1::2]))
```

运行：`[23,55,42,21]` → `2355`；`[34,7,11,11]` → `347`；`[9,20]` → `920`。

**复杂度。** 时间 `O(n)`（数字位数是常数），空间 `O(1)`（生成器逐个比较）。

**易错点。**
- 用字符串直接比较大小：`[34,7,11,11]` 的两个拼接结果是 `"347"` 与 `"1111"`，字典序 `"1111"` 更小，得到 `1111`，正确是 `347`。
- 拼接顺序反了（后一个在前）：`[9,20]` 得到 `209`，正确是 `920`。
- 配对错位（`nums[1]` 与 `nums[2]`）：题目要求 `0-1`、`2-3` 这样固定配对，不是相邻的滑动窗口。

**同模式。** LC 179 最大数、LC 2160 拆分数位后四位数字的最小和、LC 2578 最小和分割。
