## Q
**LC 4093 至多 K 次数字重排后的最大和**｜Medium · 2026-10-26 解出

给你一个长度为 `n` 的整数数组 `nums` 和一个整数 `k`。在一次操作中，你可以选择 `nums` 中的任意一个元素，并以任意顺序重新排列其十进制数字，组成一个新的整数。返回在执行至多 `k` 次操作后，数组元素之和的最大值。`1 <= n == nums.length <= 10^5`，`1 <= nums[i] <= 10^9`，`1 <= k <= n`。

例：`nums = [123,45]`，`k = 1` → `366`（把 `123` 重排成 `321`，`321 + 45`）；`nums = [102,90,14]`，`k = 2` → `341`（`102 → 210`，`14 → 41`，`210 + 90 + 41`）。

给出完整的最优解答：考点、识别、推导、代码、复杂度、易错点。

## A
**考点。** 贪心：各元素的收益互相独立，取收益最大的 `k` 个（Top-K）。

**一句话。** 每个元素重排的最优结果是把数字从大到小排列，收益 `gain = 降序重排后的值 - 原值 >= 0`；操作之间互不影响，所以答案是原数组之和加上最大的 `k` 个收益之和。

**识别。** 「至多 `k` 次」「每次选任意一个元素」且一个元素的重排结果与其他元素无关：这是在 `n` 个独立收益里挑 `k` 个；`n` 到 `10^5` 排除对元素组合的枚举。

**推导。** 对单个数字，把数字降序排列得到的整数最大（高位放大数字），且不会有前导零问题，因为 `nums[i] >= 1`，最大的那位至少是 1。对同一个元素操作两次没有额外好处（一次就到最大），所以每个元素至多操作一次，是 0/1 选择。每个元素贡献的收益固定，不依赖别的元素是否被操作，于是选收益最大的 `k` 个，收益全部 `>= 0`，凑满 `k` 个也不会变差。

```python
def max_sum(nums: list[int], k: int) -> int:
    # 每个元素的最优重排是数字降序；收益 = 降序后的值 - 原值（>= 0）
    gains = [int("".join(sorted(str(x), reverse=True))) - x for x in nums]
    # 收益互相独立，取最大的 k 个（k 次操作用满不会变差，因为收益都 >= 0）
    return sum(nums) + sum(nlargest(k, gains))
```

运行：`[123,45]`，`k = 1` → `366`；`[102,90,14]`，`k = 2` → `341`；`[91,19]`，`k = 1` → `182`。

**复杂度。** 时间 `O(n log n)`（每个数最多 10 位，排序数字 `O(1)`；`nlargest` 是 `O(n log k)`），空间 `O(n)`。

**易错点。**
- 按数值大小而不是按收益挑元素：`[91, 19]`，`k = 1` 选了更大的 `91`，它的收益是 `0`，得到 `110`，正确是 `182`（选 `19 → 91`，收益 `72`）。
- 重排成最小或随便一种顺序：要的是最大，降序排列才对。
- 以为 `k` 次操作可以反复作用在同一个元素上来叠加收益：一个元素一次就已经是最大，再操作没有增益，所以只能在 `k` 个**不同**元素里取收益。

**同模式。** LC 670 最大交换、LC 2231 按奇偶性交换后的最大数字、LC 2279 装满石头的背包的最大数量、LC 179 最大数。
