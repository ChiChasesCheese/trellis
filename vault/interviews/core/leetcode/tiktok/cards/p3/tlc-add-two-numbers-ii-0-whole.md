## Q
**LC 445 两数相加 II**｜Medium · LC TikTok 全时段热度 25/100 · 近一年被问：美国 1 次、国内 1 次 · CodeTop 国内累计 15 次 · 最近 2026-09-23（国内面试记录）

给两个**非空**链表，各表示一个非负整数，数字**高位在前**（最高位在链表头），每个结点存一位数字（`0 <= node.val <= 9`，链表长度 `1` 到 `100`）。把两数相加，以同样形式返回和的链表。除了数字 `0` 本身，两个数都没有前导零。进阶：不能翻转输入链表。例：`l1 = [7,2,4,3]`、`l2 = [5,6,4]` → `[7,8,0,7]`（`7243 + 564 = 7807`）；`[2,4,3] + [5,6,4]` → `[8,0,7]`；`[0] + [0]` → `[0]`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 加法必须从个位开始，但链表只能从高位走：把两条链表各压进一个栈，栈顶就是个位；同时弹栈相加并带进位，每算出一位就用**头插法**接到结果链表的最前面，结果天然是高位在前。`O(n + m)`。

**识别。** 「链表表示的数相加」是链表 + 模拟竖式加法；高位在前意味着需要**倒序访问**。倒序访问有三条路：反转链表、栈、递归；进阶明确禁止改动输入，所以用栈（后进先出恰好把顺序倒过来）。长度只有 `100`，复杂度不是瓶颈，考的是进位和链表操作是否写得干净。

**推导。** 暴力：把两条链表读成整数，相加，再拆成链表。Python 的整数不会溢出所以可行，但这绕开了题目考的链表操作，换成定宽整数的语言就会溢出。竖式加法的浪费在于：对齐要从低位开始，而链表给的是高位 → 先把顺序倒过来。反转输入是破坏性的；用栈复制一份顺序，弹出顺序就是个位到高位。结果也是从低位往高位生成，用头插法每次接在已有结果前面，不需要最后再反转。

```python
def add_two_numbers(l1: ListNode | None, l2: ListNode | None) -> ListNode | None:
    s1: list[int] = []
    s2: list[int] = []
    while l1:                              # 压栈：栈顶就是个位
        s1.append(l1.val)
        l1 = l1.next
    while l2:
        s2.append(l2.val)
        l2 = l2.next
    head: ListNode | None = None
    carry = 0
    while s1 or s2 or carry:               # 最后一个进位也要处理
        carry += (s1.pop() if s1 else 0) + (s2.pop() if s2 else 0)
        carry, digit = divmod(carry, 10)
        head = ListNode(digit, head)       # 头插法：新结点接在已有结果前面
    return head
```

运行：`[7,2,4,3] + [5,6,4]` → `[7,8,0,7]`，`[2,4,3] + [5,6,4]` → `[8,0,7]`，`[0] + [0]` → `[0]`，`[5] + [5]` → `[1,0]`，`[9,9,9] + [1]` → `[1,0,0,0]`。

**复杂度。** 时间 `O(n + m)`；空间 `O(n + m)`（两个栈）加结果链表。

**易错点。**
- 循环条件必须包含 `carry`：`[5] + [5]` 只写 `while s1 or s2` 会得到 `[0]`（正确 `[1,0]`），丢掉最高位的进位。
- 不能从链表头逐位相加：`[7,2,4,3]` 与 `[5,6,4]` 位数不同，头对头相加得到 `[12,8,8,3]`，完全错位（正确 `[7,8,0,7]`）。
- 头插法返回的是最后插入的结点（最高位）；不要返回第一个创建的结点。

**追问。**
- 不用栈、`O(1)` 额外空间：先反转两条输入链表、相加、再还原（会临时改动输入，进阶不允许时不能用）。
- 递归写法：先算两条链表长度，较长的先走差值步对齐，再递归到底，回溯时加进位；空间是递归深度 `O(n)`。
- 链表长到 `10^5`：递归会触到默认递归深度上限 `1000`，栈 + 迭代版没有这个问题。
