## Q
**LC 4 寻找两个正序数组的中位数**｜Hard · LC TikTok 全时段热度 26/100 · 近一年被问：美国 2 次、国内 1 次 · CodeTop 国内累计 69 次 · 最近 2026-08-23（国内面试记录）

给两个大小分别为 `m` 和 `n` 的正序（从小到大）数组 `nums1` 和 `nums2`，找出并返回这两个正序数组合并后的**中位数**。算法的时间复杂度应该为 `O(log(m + n))`。`0 <= m, n <= 1000`，`1 <= m + n <= 2000`，`-10^6 <= nums1[i], nums2[i] <= 10^6`。例：`nums1 = [1,3]`，`nums2 = [2]` → `2.0`（合并为 `[1,2,3]`）；`nums1 = [1,2]`，`nums2 = [3,4]` → `2.5`（合并为 `[1,2,3,4]`，`(2 + 3) / 2`）。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 在较短的数组上二分「切割位置」：从两个数组各切一刀，让左边一共有 `(m + n + 1) // 2` 个元素，并且左边每个元素都不大于右边每个元素，也就是 `a_left <= b_right` 且 `b_left <= a_right`。找到这样的切法后，中位数由四个边界值直接算出。`O(log min(m, n))`。

**识别。** 「两个有序数组」+「`O(log)`」→ 二分。难点在于二分的对象不是某个值，而是**切割点**。把中位数理解成「把全部元素分成相等的左右两半」：左半由 `a[:i]` 和 `b[:j]` 组成，且 `i + j = half` 固定，所以只有一个自由度 `i`，可以对 `i` 二分。

**推导。** 暴力：合并两个数组再取中间，`O(m + n)`（`m + n <= 2000` 时其实能过，但题目要求对数级）。双指针走到中间可以做到 `O(1)` 空间，仍是线性。洞察：设 `a` 取前 `i` 个、`b` 取前 `j = half - i` 个进左半。每个数组内部本来有序，所以合法只需要交叉条件 `a[i-1] <= b[j]` 和 `b[j-1] <= a[i]`。`i` 增大时，`a_left` 变大，同时 `j` 减小让 `b_right` 变小，所以「`a_left > b_right`」这个违规单调：出现了就说明 `i` 取大了，往左找；「`b_left > a_right`」说明 `i` 取小了，往右找。在**较短**的数组上二分，既保证 `j` 一定落在 `[0, n]` 内，二分范围也最小。

```python
from math import inf


def find_median_sorted_arrays(nums1: list[int], nums2: list[int]) -> float:
    a, b = (nums1, nums2) if len(nums1) <= len(nums2) else (nums2, nums1)   # 在较短的数组上二分
    m, n = len(a), len(b)
    half = (m + n + 1) // 2             # 左半边的元素个数（总数为奇数时，左边多一个）
    lo, hi = 0, m
    while lo <= hi:
        i = (lo + hi) // 2              # a 的前 i 个进左半边
        j = half - i                    # b 的前 j 个进左半边
        a_left = a[i - 1] if i > 0 else -inf
        a_right = a[i] if i < m else inf
        b_left = b[j - 1] if j > 0 else -inf
        b_right = b[j] if j < n else inf
        if a_left > b_right:            # a 取多了：左边界往左挪
            hi = i - 1
        elif b_left > a_right:          # a 取少了：往右挪
            lo = i + 1
        else:                           # 左半边每个数都 <= 右半边每个数
            left_max = max(a_left, b_left)
            if (m + n) % 2:
                return float(left_max)
            return (left_max + min(a_right, b_right)) / 2
    raise ValueError("输入不是有序数组")
```

运行：`([1,3], [2])` → `2.0`，`([1,2], [3,4])` → `2.5`，`([], [1])` → `1.0`，`([2], [])` → `2.0`，`([0,0], [0,0])` → `0.0`，`([1,2,3,4,5], [6])` → `3.5`。

**复杂度。** 时间 `O(log min(m, n))`；空间 `O(1)`。

**易错点。**
- 在较长的数组上二分（没有先交换）：`j = half - i` 可能超出 `[0, n]`，结果也会错。`([1,2,3,4,5,6], [7,8])` 得到 `5.5`，正确是 `4.5`。
- `half` 写成 `(m + n) // 2`：总数为奇数时左半少了一个，`([1,3], [2])` 得到 `1.0`，正确是 `2.0`。
- 不加哨兵：切在数组两端时 `a[i - 1]`（`i = 0`）会取到最后一个元素，`a[i]`（`i = m`）会越界。用 `-inf` 和 `inf` 代表「那一侧没有元素」。
- 偶数个元素时用整数除法 `//`：`([1,2], [3,4])` 要返回 `2.5`，必须用 `/`。

**追问。**
- 二分「值」而不是「切点」：对候选值 `x` 用 `bisect_right` 统计两个数组中 `<= x` 的个数，二分出第 `k` 小；值域 `[-10^6, 10^6]` 约 `21` 轮，每轮两次 `bisect`。
- 数据流中位数（LC 295）：大顶堆加小顶堆，每次加入 `O(log n)`。
- 求第 `k` 小（见「另一种解法」）：每次排除 `k // 2` 个不可能的元素。

**同模式。** LC 295 数据流的中位数、LC 378 有序矩阵中第 K 小的元素、LC 33 搜索旋转排序数组、LC 162 寻找峰值、LC 410 分割数组的最大值。
