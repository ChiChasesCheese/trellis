## Q
**LC 141 环形链表**｜Easy · 近一年被问：美国 0 次、国内 2 次 · CodeTop 国内累计 84 次 · 最近 2026-10（国内面试记录）

给链表的头节点 `head`，判断链表中是否有环：如果有某个节点可以通过连续跟踪 `next` 指针再次到达，则存在环。有环返回 `true`，否则返回 `false`。链表中节点的数目范围是 `[0, 10^4]`，`-10^5 <= Node.val <= 10^5`（节点值可以重复）。例：`head = [3,2,0,-4]`，尾节点连回下标 `1` 的节点 → `true`；`head = [1,2]`，尾节点连回下标 `0` → `true`；`head = [1]`，无环 → `false`。进阶：用 `O(1)` 内存解决。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 快慢指针（Floyd 判圈）：`slow` 每次走一步，`fast` 每次走两步。有环时 `fast` 进环后会追上 `slow`，在环内相遇；无环时 `fast` 先走到 `None`。`O(n)` 时间，`O(1)` 空间。

**识别。** 「链表是否有环」+ 进阶「`O(1)` 内存」→ 不能用哈希集合记录访问过的节点，要用两个指针。环里像操场跑步：`fast` 每步比 `slow` 多走一格，两者的距离每步减 `1`，减到 `0` 之前不会跳过 `0`，所以一定相遇。

**推导。** 暴力：用集合记录已访问的节点（按对象身份），走到已记录的节点就是有环，走到 `None` 就无环，`O(n)` 时间但 `O(n)` 空间。浪费：空间。洞察：不需要记住走过哪些节点，只需要两个速度不同的指针。无环时 `fast` 先到末尾；有环时两个指针都困在环里，`fast` 相对 `slow` 每步靠近一格，最多再走一圈就追上。

```python
def has_cycle(head: ListNode | None) -> bool:
    slow = fast = head
    while fast and fast.next:           # fast 走到头（None）说明无环
        slow = slow.next                # 慢指针一步
        fast = fast.next.next           # 快指针两步
        if slow is fast:                # 先走再比较：起点本来就相等
            return True
    return False
```

运行：`[3,2,0,-4]`（尾连下标 1）→ `True`，`[1,2]`（尾连下标 0）→ `True`，`[1]` → `False`，`[]` → `False`，`[1]` 自己连自己 → `True`，`10^4` 个节点、尾连下标 `5000` → `True`，`10^4` 个节点无环 → `False`。

**复杂度。** 时间 `O(n)`：无环时 `fast` 走 `n/2` 步；有环时先走入环前的路程，再最多绕环一圈；空间 `O(1)`。

**易错点。**
- 在移动之前比较 `slow is fast`：两者起点相同，第一轮就相等，无环的 `[1,2,3]` 也会返回 `True`，正确是 `False`。要先走再比较。
- 循环条件只写 `while fast`：`fast.next` 为 `None` 时 `fast.next.next` 抛 `AttributeError`，`[1]` 就会崩。要写 `fast and fast.next`。
- 用节点值判重：节点值可以重复，无环的 `[0, 0]` 会被判成有环。必须用节点对象本身（身份）。

**追问。**
- 找环的入口（LC 142）：相遇后让一个指针回到 `head`，两个指针每次各走一步，再次相遇的节点就是入口。设入环前长 `a`，环长 `L`，相遇时慢指针在环内走了 `c`，则 `a + c` 是 `L` 的倍数，所以从相遇点再走 `a` 步正好回到入口。
- 求环的长度：相遇后让一个指针继续走，数到再次回到相遇点的步数。
- 哈希集合版本：`seen = set()`，节点存进去，`O(n)` 空间，写法最直观，先说这个再优化到快慢指针。

**同模式。** LC 142 环形链表 II、LC 202 快乐数、LC 287 寻找重复数、LC 160 相交链表、LC 876 链表的中间结点。
