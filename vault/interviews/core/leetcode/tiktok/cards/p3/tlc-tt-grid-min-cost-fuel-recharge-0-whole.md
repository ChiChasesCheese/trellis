## Q
**带油量限制和补给点的网格最小代价路径**｜Hard · 近一年被问：美国 4 次、国内 0 次 · 最近 2026-06-30（面试记录）

`m x n` 的网格 `grid`：`grid[r][c] >= 0` 是进入该格的代价，`-1` 是障碍不能走；另有一组补给点 `recharge`，到达补给点后油量立刻恢复到满（`K`）。起点 `(0, 0)`（不计入场代价），终点 `(m-1, n-1)`，初始油量为 `K`，每向上下左右走一步消耗 `1` 单位油，油量为 `0` 时不能再走。求从起点到终点的最小总代价，不可达返回 `-1`。`1 <= m, n <= 50`，`0 <= grid[r][c] <= 100`（障碍除外），`0 <= K <= 10^9`。例：`grid = [[0,1,1,1],[9,-1,9,1],[1,1,1,1]]`，无补给点：`K = 5` → `5`，`K = 4` → `-1`（至少要走 `5` 步）；补给点 `{(0, 3)}`、`K = 4` → `5`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 状态是（位置，剩余油量），在这个扩展的图上跑 Dijkstra（优先队列，按总代价）；同一个格子里，若之前已经以不更大的代价弹出过剩余油量不少于现在的状态，现在的状态被支配，直接丢弃；油量上限取 `min(K, m * n)`。

**识别。** 「最小总代价」是带权最短路，Dijkstra；「油量限制」让只靠位置不足以描述状态——同一个格子，剩余油量不同，后续能走多远不同，所以油量要进入状态。补给点把油量重置，意味着状态不会无限增长。`K` 可以是 `10^9`，不能按 `K` 展开成 `m·n·K` 个状态，要靠支配剪枝和对 `K` 封顶。

**推导。** 暴力：DFS 枚举所有路径，指数级。第一步：Dijkstra 加油量维度，状态 `m·n·(K+1)` 个，`K` 大时爆炸。浪费：同一个格子里，代价更小且油更多的状态，使所有代价更大、油更少的状态都没有存在价值。洞察一：Dijkstra 按代价递增弹出，所以先弹出的状态代价都不大于后弹出的；每个格子只需记录「已弹出的最大剩余油量」，之后弹出的剩余油量不超过它就丢弃，每个格子里保留的状态，油量严格递增。洞察二：最优路径不会重复经过同一个格子（环路不会降低代价，也不会增加油量），步数小于 `m·n`，所以 `K` 超过 `m·n` 等价于 `m·n`。

```python
import heapq


def min_cost(grid: list[list[int]], recharge: set[tuple[int, int]], fuel: int) -> int:
    """grid[r][c] 是进入该格的代价，-1 表示障碍；到达 recharge 里的格子油量恢复到 fuel；每走一步耗 1 单位油。
    从 (0, 0) 到 (m-1, n-1) 的最小总代价，不可达返回 -1。"""
    m, n = len(grid), len(grid[0])
    if grid[0][0] == -1 or grid[m - 1][n - 1] == -1:
        return -1
    fuel = min(fuel, m * n)                          # 最优路径不会重复经过同一格，步数 < m*n，更大的油量没有意义
    best_fuel = [[-1] * n for _ in range(m)]         # 每格已经弹出过的最大剩余油量（支配剪枝）
    heap = [(0, 0, 0, fuel)]                         # (总代价, 行, 列, 剩余油量)
    while heap:
        cost, r, c, left = heapq.heappop(heap)
        if (r, c) == (m - 1, n - 1):
            return cost
        if left <= best_fuel[r][c]:                  # 早先以不更大的代价弹出过、油量不少于现在：现在这个被支配
            continue
        best_fuel[r][c] = left
        if left == 0:
            continue                                 # 没油了，走不动
        for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
            if 0 <= nr < m and 0 <= nc < n and grid[nr][nc] != -1:
                nxt_fuel = fuel if (nr, nc) in recharge else left - 1
                heapq.heappush(heap, (cost + grid[nr][nc], nr, nc, nxt_fuel))
    return -1
```

运行：`grid = [[0,1,1,1],[9,-1,9,1],[1,1,1,1]]`：`K = 5` → `5`，`K = 4` → `-1`，补给点 `{(0, 3)}`、`K = 4` → `5`，`K = 10**9` → `5`；`[[0,5,1],[1,5,1],[1,1,1]]`：`K = 4` → `4`，`K = 3` → `-1`；`[[0]]`、`K = 0` → `0`；`[[0,1]]`、`K = 0` → `-1`；`[[0,-1]]` → `-1`；`60 x 60` 全 `1` 的网格，`K = 118` → `118`，`K = 117` → `-1`。

**复杂度。** 状态数每格至多 `min(K, m·n) + 1` 个（剪枝后油量严格递增），所以最坏 `O(m·n·min(K, m·n) · log)`；实际远小于这个上界。

**易错点。**
- 忽略油量：只按代价跑 Dijkstra。上面的第一个例子 `K = 4` 会得到 `5`，正确是 `-1`（走到终点至少要 `5` 步）。
- 补给点的语义：到达补给点后油量重置为满，不是“加一点”。`K = 4` 加补给点 `(0, 3)`：走到 `(0, 3)` 用了 `3` 步，油量回到 `4`，再走 `2` 步到终点，总代价 `5`；不处理补给点则得到 `-1`。
- 弹出终点要在检查油量之前：到达终点时油量恰好为 `0` 是合法的（`K = 5` 的例子）。
- 剪枝条件用 `<=` 而不是 `<`：等油量的重复状态也是被支配的，用 `<` 会重复展开，结果不变但变慢。

**追问。**
- `K` 很大：对 `K` 封顶 `m·n`，并用支配剪枝；不要开 `m·n·K` 的三维数组。
- 补给点只补固定油量，或补满但有上限：只改 `nxt_fuel` 的计算，如 `min(fuel, left - 1 + gain)`。
- 只问能不能到达（BFS）：同样的状态，用 BFS 并同样剪枝（每格只保留最大剩余油量）；代价按步计就是最短步数。
