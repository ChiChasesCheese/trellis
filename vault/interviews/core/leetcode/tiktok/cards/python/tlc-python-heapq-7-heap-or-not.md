## Q
**Python 工具箱｜什么时候堆不是最好的选择**

遇到「第 k 大」「前 k 个」「持续取最小」时，怎样在堆、排序、快速选择（quickselect）、桶排序（bucket sort）之间选？

## A
先看四件事：**要不要顺序**、**数据是否一次给全**、**`k` 相对 `n` 多大**、**值域有没有上界**。

| 条件 | 选择 | 复杂度 |
|---|---|---|
| 一次给全，只要第 `k` 个，不要顺序 | quickselect | 平均 `O(n)` |
| 一次给全，`k` 很小，要前 `k` 个 | 大小为 `k` 的堆 | `O(n log k)` |
| 数据是流，要随时回答 | 堆（常配懒删除） | 每次 `O(log k)` |
| `k` 接近 `n`，或要完整排序 | `sorted` | `O(n log n)` |
| 值是频次，上界为 `n` | 桶排序 | `O(n)` |

- LC 347 前 K 个高频元素：频次最大为 `n`，开 `n+1` 个桶，从高到低收集，`O(n)`，比堆更快；堆版 `O(n log k)` 也被接受。
- LC 215 第 K 大：面试官若要求「平均 `O(n)`」就写 quickselect（随机选枢轴，三路划分）；否则 `heapq.nlargest(k, nums)[-1]` 足够。
- 只需要最大、最小各一个且随时增删：用有序容器（`bisect` 维护的列表，或 `SortedList`），堆做不了中间删除。
- Python 里排序是 C 实现，`n` 在 `10^5` 量级时，`sorted(nums)[-k]` 往往比自己写的 Python 堆循环还快；渐近更优不等于实际更快。

**坑**：quickselect 最坏 `O(n^2)`，遇到大量重复元素用普通二路划分会退化，必须用三路划分或随机化。
