## Q
**拓扑排序（Topological Sort）｜正确性：为什么取出的点数不足就说明有环，边的方向写反会怎样**

Kahn 算法凭什么用「输出点数是否等于 `V`」判环？课程表里边方向写错的后果是什么？

## A
**无环 ⇒ 全部取出。** 任何有限的有向无环图（DAG）都至少有一个入度为 0 的点（沿着入边一直往回走，不可能重复，必然停在入度为 0 的点）。取出它并删掉它的出边后，剩下的仍是 DAG，重复即可，所以全部点都会被取出。

**有环 ⇒ 环上的点永远取不出。** 环上每个点至少有一条来自环上前驱的入边，只要环上有任何点没被取出，它的后继的入度就不会降到 0。所以取出的点数严格小于 `V`。

**不变量**：某个点被取出的那一刻，它的所有前驱都已经被取出——这正是合法拓扑序的定义。

**反例：边方向写反。** 课程表 `[[1,0]]`（学 1 之前先学 0），正确顺序 `[0, 1]`。
- 把边写成 `course -> pre`，同一输入得到 `[1, 0]`。
- `(4, [[1,0],[2,0],[3,1],[3,2]])` 的正确顺序是 `[0, 1, 2, 3]`；反向建边得到 `[3, 1, 2, 0]`，课程 3 排在它的先修课 1 之前。

- 写反时 **LC 207 的判环结果仍然正确**（反转所有边不改变是否有环），只有 LC 210 返回的顺序会错——这个 bug 在判环题里测不出来。
- 重复的边 `[[1,0],[1,0]]` 会让入度加 2、邻接表里有两项，仍然正确（出队时也减两次）；不要对邻接表去重而不去重入度。
