## Q
**前缀和与差分（Prefix Sum）｜正确性：为什么要先放 `{0: 1}`，为什么不能用滑动窗口**

LC 560 的哈希表为什么一开始就要放 `0: 1`？数组含负数时滑动窗口哪里错？

## A
**不变量**：处理到下标 `i` 时，`cnt` 里装着前缀和 `pre[0..i]`（含空前缀 `pre[0] = 0`）出现的次数；子数组 `nums[j..i]` 的和 = `pre[i+1] - pre[j]`，要等于 `k` 就是 `pre[j] = pre[i+1] - k`。

**空前缀**：子数组从下标 0 开始时，对应的 `j` 是 0，即 `pre = 0`。如果没放 `0: 1`，这些子数组全都漏掉。
- `nums = [1, 2, 3]`，`k = 3`：正确答案 `2`（`[1,2]` 和 `[3]`）。
- 不放 `0: 1`：处理 `[1,2]` 时 `pre = 3`，查 `cnt[0]` = 0，漏掉；最后只得到 `1`。

**不能用滑动窗口**：窗口法依赖「右端增大和单调不减，所以和超了就左端收缩」，只在元素全为正数时成立。
- `nums = [1, -1, 1]`，`k = 1`：正确答案 `3`（`[1]`、`[1,-1,1]`、`[1]`）。
- 滑动窗口（和大于 `k` 就收缩）得到 `2`：它漏掉了整段 `[1,-1,1]`，因为在 `[1,-1]` 之后和为 `0`，窗口不会回头。

- 顺序同样重要：必须先 `ans += cnt[pre - k]` 再 `cnt[pre] += 1`；反过来，`k = 0` 时会把当前位置自己算成一个空子数组。
- `k` 可以为负，`pre - k` 可能大于 `pre`，哈希表不在乎。
