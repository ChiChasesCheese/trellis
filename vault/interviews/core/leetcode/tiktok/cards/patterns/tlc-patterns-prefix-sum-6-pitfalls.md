## Q
**前缀和与差分（Prefix Sum）｜常见陷阱**

前缀和与差分题最常见的错误有哪些？

## A
1. **漏掉空前缀**：不放 `{0: 1}`，从下标 0 开始的子数组全漏（LC 560 的 `[1,2,3], k=3` 少算一个）。
2. **先登记后查询**：`cnt[pre] += 1` 放在查询前，`k = 0` 时会把「空子数组」算进答案。顺序：先查，再登记。
3. **下标偏移一位**：`pre` 长度是 `n+1`，区间 `[l, r]`（闭）的和是 `pre[r+1] - pre[l]`；半开 `[l, r)` 才是 `pre[r] - pre[l]`。统一用一种区间约定。
4. **差分数组的末端**：`diff[r + 1] -= v` 要求 `diff` 长度至少 `n + 1`，否则 `r = n - 1` 时越界。
5. **含负数用了滑动窗口**：右端增大和不单调，窗口法会漏解（`[1,-1,1]` 里 `k=1` 得 2，正确是 3）。
6. **取模与负数**：Python 的 `%` 结果非负，直接可用；移植 C++ 题解时不要再 `+ k` 处理一遍（多处理也无害，但要明白原因）。
7. **键太大**：前缀和可能到 `10^9` 量级，字典没问题；但不能开一个长度等于前缀和范围的数组。
8. **整数溢出**：Python 无此问题；若题目要求取 `10^9 + 7` 的模，每次累加后取模。
9. **静态 vs 动态**：数组会被修改（LC 307）时前缀和 `O(n)` 更新，要换树状数组。
10. **二维前缀和的容斥符号**：`p[r][c] = a + 上 + 左 - 左上`；查询是 `右下 - 上 - 左 + 左上`，一个符号错了，整张表都错。

自检：用 `[1, 2, 3]` 这类 3 个元素的输入，手算 `pre = [0, 1, 3, 6]`，对照代码的输出。
