## Q
**字符串处理与表达式解析｜正确性：为什么这样处理优先级，除法的截断方向错在哪里**

不用栈、直接从左到右算会错在哪里？用 `//` 代替向零截断的除法会错在哪里？

## A
**不变量**：扫描到某个位置时，栈里是"已经完全确定的项"（`+`/`-` 开头、`*`/`/` 已经乘除完的值），栈顶的项还**可能**被后面的 `*` 或 `/` 继续修改，其余的项不会再变。最后只剩加法。

**反例一：从左到右、忽略优先级。** `"3+2*2"`：
- 从左到右：`3 + 2 = 5`，`5 * 2 = 10`，得 `10`。
- 正确：`2 * 2 = 4`，`3 + 4 = 7`。
- 栈的写法把 `2` 压栈，遇到 `*` 才与栈顶的 `2` 结合，`3` 不受影响。

**反例二：减号后面的除法。** `"1-7/2"`：
- 正确：`7 / 2 = 3`，`1 - 3 = -2`。
- 实现把 `-7` 压栈（减法转加负数），之后 `/ 2` 作用在 `-7` 上：向零截断 `int(-7/2) = -3`，`1 + (-3) = -2`，正确。
- 如果除法用 Python 的 `//`：`-7 // 2 = -4`，得 `1 + (-4) = -3`，错误。
- 所以除法要向零截断：`q = abs(a) // abs(b)`，符号相同取 `q`，否则取 `-q`（或 `int(a / b)`，但大数下浮点不精确，不推荐）。

**符号转移是否安全**：`a - b / c` = `a + (-(b / c))`，而 `(-b) / c` 向零截断恰好等于 `-(b / c)`（向零截断对符号对称）；如果用向下取整除法，这个对称性就不成立，这是 `//` 出错的根源。

- 关于 LC 772：题面写"向下截断"，参考实现按向零截断处理；有疑问时先问面试官负数除法的规则。
- 检查办法：手写 `"3+2*2"`、`"1-7/2"`、`"42"`（只有一个数）三个例子过一遍。
