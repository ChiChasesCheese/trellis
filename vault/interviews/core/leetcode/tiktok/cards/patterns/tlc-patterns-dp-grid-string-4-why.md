## Q
**动态规划：网格、双串与区间｜正确性：编辑距离为什么需要"替换"，LCS 为什么相等时直接取左上**

编辑距离转移里去掉"替换"会错多少？两个末尾字符相等时，为什么可以只看 `dp[i-1][j-1]`？

## A
**不变量**：`dp[i][j]` 是 `a[:i]` 变成 `b[:j]` 的最少操作数（编辑距离），或 `a[:i]` 与 `b[:j]` 的最长公共子序列长度。每个状态都覆盖了"最后一步做了什么"的全部可能。

**编辑距离去掉替换**：`dp[i][j] = 1 + min(dp[i-1][j], dp[i][j-1])`（只有删、插）。
- `"horse"` → `"ros"`：只用删和插得到 `4`，正确答案是 `3`（替换 `h→r`、删 `r`、删 `e`）。
- `"intention"` → `"execution"`：只用删和插得到 `8`，正确是 `5`。
- 替换相当于"删一个再插一个"合并成 1 步；没有它，每个不同字符都要多花一步。

**末尾字符相等时直接取左上（不用 `min`）**：设 `a[i-1] == b[j-1]`，把这两个字符对齐（不做操作）不会比其他方案差——任何别的方案要么也把它们对齐，要么至少多花 1 步，而多花的代价不会换来更少的后续代价（交换论证）。所以 `dp[i][j] = dp[i-1][j-1]`。LCS 同理：相等的末尾字符一定可以放进某个最长公共子序列。

**LCS 末尾字符不相等**：两个字符至少有一个不在公共子序列的末尾，取 `max(dp[i-1][j], dp[i][j-1])`；`dp[i-1][j-1]` 已经被这两个包含，不用再比较。

- 写法检查：两个串长度分别为 `0` 和 `1`（`("", "a")` → `1`），以及完全相同的串（编辑距离 `0`，LCS 等于长度）。
- 状态的定义用"前 `i` 个"（长度 `i + 1` 的表）比"以第 `i` 个结尾"更自然地处理空串。
