## Q
**并查集（Union-Find）｜信号**

什么样的题面该想到并查集？它和 BFS / DFS 求连通块相比有什么取舍？

## A
并查集（Union-Find，也叫 Disjoint Set Union）维护一组**互不相交的集合**，支持两个操作：`find(x)` 找 `x` 所在集合的代表；`union(a, b)` 合并两个集合。几乎 `O(1)`（摊还 `O(α(n))`）。

**触发信号：**
- 「**是否同一组 / 是否连通**」，且关系是**逐步添加**的（动态连边）：LC 721 账户合并（共享邮箱即同一人）、LC 128 最长连续序列。
- 「**连通块个数**」「合并之后还剩几个集合」：LC 200 的 UF 写法、LC 924。
- 「**加入这条边会不会成环**」：最小生成树的 Kruskal 算法（LC 1584）。
- 「**等价关系**」：传递性的"相等 / 同类"，如除法求值 LC 399、二分图的"敌人的敌人"LC 886。
- 要把"相关"的元素归成组再输出（分组聚合）。

**和 DFS / BFS 的取舍：**
- 一次性给全图、只要连通块 → DFS / BFS 同样 `O(V + E)`，写起来更直接。
- **边是在线逐条到来**，每加一条就要回答连通性 → 并查集（DFS 要重新跑）。
- 要求最短路径、路径本身、层数 → 并查集做不了（只知道连通，不知道怎么走）。
- 要**删除**边 → 并查集不支持，需要离线反向处理或其他结构。

**近似信号：**
- 有向图的可达性 / 先后顺序 → 拓扑排序，并查集处理的是无向关系。
- 只问相邻格子的连通 → BFS 即可。
