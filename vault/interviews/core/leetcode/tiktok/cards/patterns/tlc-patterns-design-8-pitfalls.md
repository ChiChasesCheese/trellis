## Q
**数据结构设计题｜常见陷阱**

设计题最容易在哪里出错？

## A
1. **多个结构不同步**：数组、字典、链表里存着同一份数据，修改一处要同步其他处（交换删除后漏更新 `pos[last]` 会越界 / 数据损坏）。
2. **没写不变量**：动手前先说出每次操作后必须成立的条件，写完逐个方法核对。
3. **忽略重复 / 不存在**：`insert` 已存在返回 `False`、`remove` 不存在返回 `False`、`dec` 的 key 保证存在；先读清楚每个方法的约定。
4. **链表空桶不摘除**：AllOne 里桶空了要摘链，否则最小 / 最大会取到空桶。
5. **哑头 / 哑尾缺失**：对 `None` 到处判空，容易漏；用哨兵节点。
6. **复杂度没达标**：用 `list.pop(0)`、`list.remove`、`sorted` 在每次操作里，把 `O(1)` 变成 `O(n)`。
7. **随机性**：`random.choice` 对列表等概率；对 `set` 不能直接用（需要先转列表，`O(n)`）。
8. **哈希函数**：负键 `key % SIZE` 在 Python 里非负，不用补；用其他语言要注意。
9. **二分的比较键**：快照数组里用 `(snap_id, float("inf"))` 找上界；漏掉会找不到同一快照号的记录。
10. **小规模过度设计**：调用次数 `<= 1000` 的题，朴素扫描更不容易出错（内存分配器）。
11. **共享可变默认值**：`[[]] * n` 让所有下标共享一个历史列表；用推导式创建。
12. **只测样例**：设计题用一个朴素参考实现和随机操作序列对照，最容易发现同步 bug。
