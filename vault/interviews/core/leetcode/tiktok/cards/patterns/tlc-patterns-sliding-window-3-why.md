## Q
**滑动窗口（Sliding Window）｜正确性：为什么左端不用回头，什么时候会错**

窗口法凭什么只让左端向右走就不漏解？元素含负数时它为什么失效？写 `Counter` 窗口时漏掉哪一步会出错？

## A
**不变量**：对每个右端点 `right`，`left` 是「以 `right` 结尾的合法窗口里**最靠左**的起点」。

**单调性**：约束是「窗口越大越难满足」（至多 `k` 种字符、元素为正的和不超过上限）。窗口 `[l, right+1]` 合法一定推出 `[l, right]` 合法，所以 `right+1` 的最靠左合法起点不会比 `right` 的更靠左。`left` 因此不会回退，每个元素进出一次，`O(n)`。

**反例一：元素含负数。** 用最短子数组和 `>= target` 的窗口写法，输入 `target = 2`，`nums = [-2, 3, -3]`：
- 窗口法：和依次为 `-2`、`1`、`-2`，从没 `>= 2`，返回 `0`。
- 正确答案是 `1`（子数组 `[3]`）。
- 原因：负数让「和变小」，窗口里带着一个拖后腿的 `-2`，窗口法却不会把它丢掉，因为它只在「和够大」时才缩左端。

**反例二：不删计数为 0 的键。** LC 340 里省掉 `del cnt[c]`，`len(cnt)` 就包含已经出窗的字符：`s = "abcdd"`，`k = 2`：
- 漏删的写法得到 `2`；
- 正确答案是 `3`（`"cdd"`）。

- 判断一个题能不能用窗口，问自己：「窗口扩大后，合法性是单向变化的吗？」是 → 窗口；不是 → 前缀和 + 哈希 / DP。
- 窗口不是总要 `while`：LC 424 可以用 `if` 配合「只增不减的历史最大频次」，窗口长度只增不减。
