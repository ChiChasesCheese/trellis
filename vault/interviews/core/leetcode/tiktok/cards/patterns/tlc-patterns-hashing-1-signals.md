## Q
**哈希（Hashing）｜信号**

什么样的题面该想到哈希表？有哪些长得像、实际上要用排序、双指针或前缀和的近似信号？

## A
**该想到哈希的信号：**
- 内层循环是「找有没有一个值」：找 `target - x`、找「之前出现过的」、找重复 → 把内层 `O(n)` 查找换成 `O(1)`。
- 要**统计次数**、判断「出现次数是否相同」、比较两个多重集 → `Counter`。
- 要把元素按某个**签名（signature）**分组：排序后的字符串、计数向量、归一化的形状 → `defaultdict(list)`。
- 要**去重**或判断是否见过 → `set`。
- 数据范围到 `10^5`，暴力是 `O(n^2)`，且顺序不重要。

**近似信号（要换别的）：**
- 要保持**有序**、找前驱 / 后继 → 有序结构或排序 + 二分，哈希不记顺序。
- 数组**已有序**，找两数之和 → 双指针，`O(1)` 空间，不用哈希。
- 问的是**连续子数组**的和 / 个数 → 前缀和 + 哈希（哈希只是其中一半）。
- 键是**范围**（`x` 落在 `[l, r]`）→ 排序 / 二分 / 区间结构。
- 键是浮点数 → 哈希不可靠（精度），改用整数化或排序。

**代价**：平均 `O(1)`，空间 `O(n)`；最坏情况（大量哈希冲突）退化，但 Python 的 `int` 与 `str` 哈希足够好，面试里不必担心。
