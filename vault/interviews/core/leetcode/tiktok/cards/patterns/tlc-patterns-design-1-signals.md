## Q
**数据结构设计题（Design）｜信号**

"设计一个支持若干操作的类"这类题怎么入手？怎样从复杂度要求反推数据结构？

## A
设计题考的不是新算法，而是把**几种基础结构组合起来**，让每个操作达到题目要求的复杂度。入手顺序：

1. **列出接口**：有哪些方法、参数、返回值，边界（空、重复、不存在）怎么处理。
2. **写下复杂度目标**：题面常写"每个操作平均 `O(1)`"。
3. **逐个操作问"需要什么能力"**，再选结构：

| 需要的能力 | 结构 |
|---|---|
| 按键 `O(1)` 查找 / 更新 / 删除 | 哈希表 `dict` |
| 按位置 `O(1)` 随机取 | 数组 `list` |
| `O(1)` 删除中间节点 + 保持顺序 | 双向链表（`dict` 指向节点） |
| 取最大 / 最小 | 堆，或维护一个有序的计数桶链 |
| 按版本 / 时间回查 | 每个键存 `(时间, 值)` 升序列表 + `bisect` |
| 滑动窗口内求和 / 平均 | `deque` + 维护的和 |

**常见组合：**
- LRU（LC 146）：哈希 + 双向链表。
- 随机集合（LC 380）：哈希 + 数组（交换删除）。
- 全 O(1)（LC 432）：哈希 + 按计数分桶的双向链表。
- 快照数组（LC 1146）：每个下标一个变更历史 + 二分。
- 数据流中位数（LC 295）：双堆。
- 内存分配器（LC 2502）：数组 / 区间表模拟。

**近似信号：**
- 数据范围很小（`<= 1000` 次调用）⇒ 朴素 `O(n)` 的扫描就能过，别过度设计。
- 需要持久化 / 并发 ⇒ 先问面试官是否要考虑。
- 只是一次性计算 ⇒ 普通算法题，不是设计题。
