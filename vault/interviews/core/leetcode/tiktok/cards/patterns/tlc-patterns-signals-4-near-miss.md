## Q
**模式识别｜长得像、其实要换算法的近似信号**

哪些题面信号看上去指向 A 模式，实际上必须用 B？举出最容易选错的几组。

## A
| 看起来像 | 实际要 | 为什么 |
|---|---|---|
| 子数组和 = `k`，用滑动窗口 | 前缀和 + 哈希 | 数组含**负数**时，窗口右扩和不单调（LC 560）；全正数才能滑动窗口（LC 209） |
| 求最少硬币，贪心取最大面额 | DP | 局部最优不推出全局：硬币 `[1, 3, 4]` 凑 `6`，贪心是 `4+1+1` 三枚，最优 `3+3` 两枚（LC 322） |
| 子串，用 DP | 滑动窗口 | 子串**连续**、约束单调时，窗口 `O(n)`，DP 不必要 |
| 子序列，用滑动窗口 | DP | 子序列不要求连续，窗口的「收缩」没有意义 |
| 最短路径，用 DFS | BFS（无权）/ Dijkstra（有权） | DFS 先找到的路径不一定最短 |
| 无权图最短，用 Dijkstra | BFS | 都能对，BFS `O(V+E)` 更简单 |
| 有负权边，用 Dijkstra | Bellman-Ford | Dijkstra 假设弹出即最终最短，负权破坏它（LC 787 限制边数，用 Bellman-Ford 或带状态） |
| 有序数组，用哈希 | 双指针 | 有序是信号，哈希浪费空间（LC 15 先排序再双指针） |
| 第 `k` 大，排序 | 堆 / 快速选择 | 只要 `k` 个，不必全排 |
| 求「恰好 `k`」，直接做窗口 | 「至多 `k`」减「至多 `k-1`」 | 恰好不单调，至多单调（LC 1248、992） |

- 判断是否换算法的标准：**这个性质是否单调**（窗口收缩 / 扩张、二分、双指针都依赖单调性），以及**局部选择是否影响后面**（贪心依赖无后效）。
- 用小反例检验：找一个 3 到 5 个元素的输入让自己的做法出错，找不出才继续写。
