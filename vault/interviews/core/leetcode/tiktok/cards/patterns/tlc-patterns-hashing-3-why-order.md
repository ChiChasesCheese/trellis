## Q
**哈希（Hashing）｜正确性：为什么「先查后存」**

两数之和一遍扫描的版本里，把 `seen[x] = i` 放在查询之前会错在哪里？这个写法的不变量是什么？

## A
**不变量**：处理到下标 `i` 时，`seen` 恰好包含下标 `0..i-1` 的元素。所以查到的搭档一定来自**更早的、不同的位置**，不会把同一个元素用两次；任何一对 `(j, i)`（`j < i`）会在处理 `i` 时被发现，因此不漏解。

**反例**：`nums = [3, 2, 4]`，`target = 6`。
- 先存后查：处理 `i=0` 时先存 `seen[3] = 0`，再查 `6 - 3 = 3`，立刻命中自己，返回 `[0, 0]`。
- 先查后存：`i=0` 时 `seen` 为空，查不到，再存；`i=1` 查 `4` 没有；`i=2` 查 `6 - 4 = 2`，命中 `seen[2] = 1`，返回 `[1, 2]`，正确。

**重复值**：`nums = [3, 3]`，`target = 6`：先查后存时，`i=1` 查到 `seen[3] = 0`，返回 `[0, 1]`；字典同键只保留最后写入的下标，没问题，因为命中发生在覆盖之前。

- 若题目允许同一元素用两次，才可以先存后查。
- 同样的「先查后存」顺序出现在：判断重复（LC 217）、LC 3 里更新 `last[ch]` 之前先读旧位置、LC 560 里前缀和计数（先累加 `ans += cnt[pre - k]`，再 `cnt[pre] += 1`）。
- 要返回所有解对而非一个时，字典值改存下标列表。
