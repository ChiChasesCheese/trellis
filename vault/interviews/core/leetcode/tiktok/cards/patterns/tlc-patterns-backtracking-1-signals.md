## Q
**回溯（Backtracking）｜信号**

什么样的题面该想到回溯？数据范围怎样帮你确认？哪些近似信号其实要 DP 或贪心？

## A
回溯（Backtracking）= 深度优先地**枚举所有候选**，每一步做一个选择，递归下去，回来后**撤销选择**再试下一个。它的搜索树是指数级的，靠**剪枝**砍掉不可能的分支。

**触发信号：**
- 要求**列出所有**方案：子集 LC 78、组合 LC 39 / 77、排列 LC 46、括号生成 LC 22、复原 IP LC 93。
- 在棋盘 / 网格里**找一条路径或一种摆放**：N 皇后 LC 51、单词搜索 LC 79。
- 数据范围很小：`n <= 8` 到 `n <= 20`（LC 51 的 `n <= 9`，LC 473 的 `matchsticks.length <= 15`，LC 78 的 `nums.length <= 10`，LC 22 的 `n <= 8`）。指数级复杂度只有在这种范围才可行。
- 约束要**边选边检查**：括号必须匹配、皇后不能互攻、和不能超过目标。

**近似信号：**
- 只问**方案个数**或**最优值**，且有重叠子问题 ⇒ DP（LC 322、139、62），回溯会超时。
- 每步局部最优就能得到全局最优 ⇒ 贪心。
- 数据范围到 `10^5` ⇒ 绝不是回溯。
- 只要判断"存在"一种可行方案，且分支多 ⇒ 回溯加剪枝，或 DP / 位掩码。
- 排列 / 组合的个数本身就是指数级：输出规模决定了复杂度下限，不用试图优化到多项式。
