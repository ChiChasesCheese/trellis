## Q
**LC 13 罗马数字转整数**｜Easy · LC TikTok 全时段热度 38/100 · CodeTop 国内累计 10 次 · 最近 2025-09-25（国内 CodeTop）

罗马数字由 `I=1, V=5, X=10, L=50, C=100, D=500, M=1000` 组成，通常大数在左、小数在右；特例是小数放在大数左边表示减法，只有六种：`IV=4, IX=9, XL=40, XC=90, CD=400, CM=900`。给定一个罗马数字字符串 `s`，转换成整数。`1 <= s.length <= 15`，`s` 只含 `I V X L C D M`，保证是有效罗马数字且在 `[1, 3999]` 内。例：`"III"` → `3`；`"LVIII"` → `58`；`"MCMXCIV"` → `1994`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 从右往左扫，当前字符比右边那个小就减，否则就加。

**识别。** 「符号值固定、只有局部相邻关系影响正负」：查表加一遍扫描。减法规则的本质是「小数在大数左边」，所以只需要和右邻居比较大小。

**推导。** 把六个减法特例当 13 个符号去贪心匹配也行，但要记 13 项。洞察：`IV` 等于 `-1 + 5`，一个字符若小于它右边的字符就贡献负值，不需要认识特例。从右往左扫时「右边的值」就是上一个字符，只需一个变量。

```python
def roman_to_int(s: str) -> int:
    VALUE = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000}
    total = 0
    prev = 0                                 # 右边相邻字符的值；最右边的字符没有右邻，当 0
    for ch in reversed(s):
        v = VALUE[ch]
        total += v if v >= prev else -v      # 比右邻小：是减法特例里的小数，扣掉
        prev = v
    return total
```

运行：`"III"` → `3`，`"IV"` → `4`，`"IX"` → `9`，`"LVIII"` → `58`，`"MCMXCIV"` → `1994`；`"MMMCMXCIX"` → `3999`。

**复杂度。** 时间 `O(n)`，空间 `O(1)`（符号表大小固定）。

**拓展优化。**
- 反方向（LC 12 整数转罗马数字）：把 13 个符号（含 `CM`、`CD` 等特例）从大到小排好，贪心减。

```python
def int_to_roman(num: int) -> str:
    SYMBOLS = ((1000, "M"), (900, "CM"), (500, "D"), (400, "CD"), (100, "C"), (90, "XC"),
               (50, "L"), (40, "XL"), (10, "X"), (9, "IX"), (5, "V"), (4, "IV"), (1, "I"))
    parts: list[str] = []
    for value, symbol in SYMBOLS:            # 从大到小，每个符号能放几次就放几次
        count, num = divmod(num, value)
        parts.append(symbol * count)
    return "".join(parts)
```

**易错点。**
- 从左往右扫时漏掉最后一个字符的处理：要么越界，要么忘了加最后一个值；从右往左没有这个问题。
- 把比较写成 `v > prev` 而漏掉相等：`"II"` 会变成 `1 - 1 = 0`，正确是 `2`。
- 误以为 `"IL"`、`"IM"` 合法而写复杂规则：题目保证输入有效，不用校验。

**追问。**
- 校验是否为合法罗马数字：用正则 `^M{0,3}(CM|CD|D?C{0,3})(XC|XL|L?X{0,3})(IX|IV|V?I{0,3})$`，只覆盖 `[1, 3999]`。
- 输入很长（超过 3999 的扩展写法）：加横线表示千倍，需要自定义符号，思路不变。
