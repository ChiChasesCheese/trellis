## Q
**LC 2422 使用合并操作将数组转换为回文序列**｜Medium · LC TikTok 全时段热度 38/100

给定由正整数组成的数组 `nums`。可以对数组执行任意次操作：选择任意两个**相邻**元素，用它们的和替换它们（例如 `[1,2,3,1]` 可以变成 `[1,5,1]`）。返回将数组转换为回文序列所需的最小操作数。`1 <= nums.length <= 10^5`，`1 <= nums[i] <= 10^6`。例：`nums = [4,3,2,1,2,3,1]` → `2`（先合并第 4、5 个元素得 `[4,3,2,3,3,1]`，再合并第 5、6 个元素得 `[4,3,2,3,4]`）；`nums = [1,2,3,4]` → `3`（合成 `[10]`）。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 双指针从两端向中间走：两端的值相等就都向内收一格；否则合并**较小的一端**（把它和相邻的元素相加），操作数加一，`O(n)`。

**识别。** 「相邻合并成回文」的两端必须对得上，而元素都是正数：合并只会让数变大，所以谁小就必须和邻居合并，别无选择。这种「每步只有一个正确选择」的结构就是贪心 + 双指针。

**推导。** 暴力：每一步尝试所有相邻对合并，搜索所有结果数组，指数级。洞察：设两端当前的值是 `left` 和 `right`。若 `left < right`，右端已经不能再变小，左端要想等于右端，只能继续并入右边的邻居，别的操作都不会让两端更近；`left > right` 对称；相等则这两个值配成一对，两端各向内走一格重新开始。每次操作只消耗一个元素，指针总共走 `n` 步。

```python
def minimum_operations(nums: list[int]) -> int:
    l, r = 0, len(nums) - 1
    left, right = nums[l], nums[r]               # 两端当前（可能已合并过的）值
    ops = 0
    while l < r:
        if left == right:                        # 配成一对，两端各向内走一格
            l += 1
            r -= 1
            left, right = nums[l], nums[r]
        elif left < right:                       # 左端更小，它只能继续并入右邻居
            l += 1
            left += nums[l]
            ops += 1
        else:                                    # 右端更小，对称
            r -= 1
            right += nums[r]
            ops += 1
    return ops
```

运行：`[4,3,2,1,2,3,1]` → `2`，`[1,2,3,4]` → `3`；`[1]` → `0`，`[1,1]` → `0`，`[1,2]` → `1`，`[2,1,3,3,1,2]` → `0`。

**复杂度。** 时间 `O(n)`，空间 `O(1)`。

**拓展优化。**
- 前缀和视角：最终回文的每个「元素」是原数组的一段连续和，位置由前缀和切点决定，且切点必须关于总和对称。数一数对称切点的个数，答案是 `n` 减去最终长度，用集合 `O(n)` 实现。

```python
from itertools import accumulate


def minimum_operations_prefix(nums: list[int]) -> int:
    prefix = list(accumulate(nums))              # 严格递增（元素都为正）
    total = prefix[-1]
    cuts = set(prefix[:-1])                      # 所有可能的切点（不含数组末尾）
    kept = sum(1 for p in cuts if total - p in cuts)   # 关于中心对称的切点才能保留
    return len(nums) - (kept + 1)                # 保留 kept 个切点，最终元素数 kept + 1
```

**易错点。**
- 相等时只移指针、不重新取 `left`、`right`：`[4,3,2,1,2,3,1]` 得到 `1`，正确是 `2`。
- 合并较大的一端：较大的一端并入邻居只会更大，永远追不上，`[4,3,2,1,2,3,1]` 得到 `6`。

**追问。**
- 返回具体的最终数组：合并时把值写进一个结果列表的两端。
- 元素可以为 0 或负数：贪心的前提（合并只会变大）不成立，需要重新推导。
