## Q
**LC 2931 购买物品的最大开销**｜Hard · LC TikTok 全时段热度 26/100

给定 `m x n` 的整数矩阵 `values`，表示 `m` 个商店里的 `m * n` 件不同物品，第 `i` 个商店的第 `j` 件物品价值为 `values[i][j]`；每个商店的物品已按价值非递增排好序（`values[i][j] >= values[i][j + 1]`）。每天（第 `d` 天）可以选一个商店，购买**最右边**还没买过的物品 `j`，花费 `values[i][j] * d`。返回购买全部 `m * n` 件物品的**最大**总开销。`1 <= m <= 10`，`1 <= n <= 10^4`，`1 <= values[i][j] <= 10^6`。例：`values = [[8,5,2],[6,4,1],[9,7,3]]` → `285`；`values = [[10,8,6,4,2],[9,7,5,3,2]]` → `386`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 把所有物品按价值从小到大排序，第 `d` 天买第 `d` 小的物品：越贵的物品越晚买，开销最大；每个商店的最右边物品本来就最便宜，这个顺序永远可行。

**识别。** 「每件物品乘以一个互不相同的天数，使总和最大」：排序不等式，大值配大乘数。限制条件「每次只能买最右边」恰好和价值排序一致（右边更小），所以不会限制全局最优顺序。

**推导。** 暴力：每天选哪个商店，`m^(mn)` 种。洞察：任何买入顺序对应一个把天数 `1..mn` 分配给物品的方案，总开销是 `Σ 价值 × 天数`，由排序不等式，最大值是把最大的天数配给最大的价值，即按价值升序买。这个顺序合法：每个商店内部价值从右到左不降，升序序列在同一商店里天然先买右边的（价值相同的随便先后）。

```python
def max_spending(values: list[list[int]]) -> int:
    items = sorted(v for row in values for v in row)     # 所有物品升序：越晚买越贵
    return sum(day * v for day, v in enumerate(items, 1))   # 第 d 天买第 d 小的
```

运行：`[[8,5,2],[6,4,1],[9,7,3]]` → `285`，`[[10,8,6,4,2],[9,7,5,3,2]]` → `386`；`[[5]]` → `5`；`[[3,3],[3,3]]` → `30`。

**复杂度。** 时间 `O(mn log(mn))`，空间 `O(mn)`。

**拓展优化。**
- 每个商店本来就有序，`m` 很小时可以用 `heapq.merge` 做 `m` 路归并，免去全体排序：`O(mn log m)`，且不需要把全部元素先放进一个列表。

```python
from heapq import merge


def max_spending_merge(values: list[list[int]]) -> int:
    ascending = merge(*(reversed(row) for row in values))   # 每行倒过来就是升序，m 路归并
    return sum(day * v for day, v in enumerate(ascending, 1))
```

**易错点。**
- 排序方向写反：降序（贵的先买）得到的是较小的开销，示例 1 得到 `165`，不是 `285`。
- 天数从 `0` 开始：第一天的乘数是 `1`，`enumerate(items, 1)` 不能漏掉起始值 `1`。
- 总和超出 32 位：`mn = 10^5`，价值 `10^6`，总和最大约 `10^6 × 5 × 10^9 = 5 × 10^15`，需要 64 位；Python 没有问题。

**追问。**
- 求最小开销：理想顺序是降序，但每个商店只能先买最右边（最便宜）的，降序不合法，要在合法顺序里取最小，是另一道题。
- 每天可以买多件：天数相同的物品放同一组，仍然按排序后依次分配。

**同模式。** LC 455 分发饼干、LC 1029 两地调度、LC 1402 做菜顺序、LC 1465 切割后面积最大的蛋糕、LC 2558 从数量最多的堆取走礼物。
