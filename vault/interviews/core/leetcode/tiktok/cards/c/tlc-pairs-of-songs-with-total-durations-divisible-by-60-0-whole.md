## Q
**LC 1010 总持续时间可被 60 整除的歌曲**｜Medium · LC TikTok 全时段热度 38/100 · CodeTop 国内累计 1 次 · 最近 2023-05-07（国内 CodeTop）

歌曲列表中第 `i` 首的时长为 `time[i]` 秒，返回满足 `i < j` 且 `(time[i] + time[j]) % 60 == 0` 的歌曲对数量。`1 <= time.length <= 6 * 10^4`，`1 <= time[i] <= 500`。例：`time = [30,20,150,100,40]` → `3`；`time = [60,60,60]` → `3`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 只看每首歌时长对 60 的余数，一边扫描一边用长度 60 的计数数组查「余数互补」的歌曲已经出现几次。

**识别。** 「两数之和被 k 整除」是余数配对：`(a + b) % k == 0` 等价于 `a % k + b % k` 为 `0` 或 `k`。计对数用哈希计数，不必枚举。

**推导。** 暴力：双重循环 `O(n^2)`，`n = 6 * 10^4` 约 18 亿次比较。浪费：只有余数重要。洞察：对每首歌，需要的搭档余数是 `(60 - r) % 60`，前面已出现的这类歌曲每首都能配成一对，累加即可。

```python
def num_pairs_divisible_by_60(time: list[int]) -> int:
    seen = [0] * 60                              # seen[r]：前面已出现、余数为 r 的歌曲数
    pairs = 0
    for t in time:
        r = t % 60
        pairs += seen[(60 - r) % 60]             # 需要的搭档余数；r = 0 时搭档余数也是 0，所以再取一次模
        seen[r] += 1                             # 先统计后登记，保证 i < j 且不与自己配对
    return pairs
```

运行：`[30,20,150,100,40]` → `3`；`[60,60,60]` → `3`；`[30,30,30]` → `3`；`[30]` → `0`；`[1,2,3]` → `0`。

**复杂度。** 时间 `O(n)`，空间 `O(60)` 即 `O(1)`。

**拓展优化。**
- 一次性统计：先 `Counter(t % 60 for t in time)`，再用组合数算：余数 `0` 和 `30` 各自 `c * (c - 1) // 2`，余数 `r` 与 `60 - r` 之间 `c[r] * c[60 - r]`。
- 模数不是 60 而是任意 `k`：把 `60` 换成 `k`，其他一样（LC 1497）。

**易错点。**
- 余数 `0` 的搭档写成 `60 - 0 = 60`，`seen[60]` 越界；必须再取模 `(60 - r) % 60`。
- 先登记再查询：`[30]` 会和自己配成一对，得到 `1`，应为 `0`。
- 用 `time[i] % 60 + time[j] % 60 == 60` 判断：漏掉两个余数都是 `0` 的情况，`[60,60,60]` 得到 `0`，应为 `3`。

**追问。**
- 三首歌总时长被 60 整除：固定一首用 `Counter` 套两数之和，`O(n^2)`。
- 数据流式到来：本解法本来就是在线的，每次 `O(1)`。

**同模式。** LC 1 两数之和、LC 1497 检查数组对是否可以被 k 整除、LC 974 和可被 K 整除的子数组、LC 523 连续的子数组和、LC 560 和为 K 的子数组。
