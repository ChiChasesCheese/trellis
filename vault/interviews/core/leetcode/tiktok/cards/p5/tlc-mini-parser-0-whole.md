## Q
**LC 385 迷你语法分析器**｜Medium · 近一年被问：美国 1 次、国内 0 次 · CodeTop 国内累计 1 次 · 最近 2026-02-27（美国面试记录）

给一个字符串 `s`，表示整数的嵌套列表，实现解析器返回对应的 `NestedInteger`。列表里的每个元素只可能是整数，或整数的嵌套列表。`NestedInteger` 接口：`NestedInteger()` 创建空列表，`NestedInteger(v)` 创建单个整数，`add(x)` 把 `x` 追加进列表。`1 <= s.length <= 5 * 10^4`，`s` 只含数字、方括号、负号 `-`、逗号，保证可解析，所有数值在 `[-10^6, 10^6]`。例：`"324"` → 一个整数 `324`；`"[123,[456,[789]]]"` → 含两个元素的列表：整数 `123` 和列表 `[456,[789]]`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 用正则把字符串切成 `[`、`]`、整数三种记号，共享一个记号迭代器做递归下降：`parse(tok)` 遇到整数直接返回，遇到 `[` 就新建列表，不断读下一个记号交给 `parse` 递归，直到读到 `]` 为止；`O(n)`。

**识别。** 「括号嵌套的字符串 → 层次结构」，结构本身就是递归定义的：一个元素要么是整数，要么是 `[` 加若干元素加 `]`。这是递归下降解析（recursive descent）的典型信号，与 LC 394、LC 224 同类。多位数和负号容易在逐字符扫描时出错，先分词。

**推导。** 递归下降：`parse()` 读到 `[` 就循环解析元素直到 `]`，每个子元素又是同样的问题，天然递归 → 手写逐字符扫描时数字与负号的处理容易出错（多位数、`-`），改用 `re.findall(r"\[|\]|-?\d+", s)` 先分词 → 把记号列表包成一个迭代器，所有递归层共享它，每层读到的位置自然接着上一层，不用传下标 → 整个字符串若只是一个整数，`parse` 的第一个分支直接返回，不需要单独处理。

```python
import re


def deserialize(s: str) -> NestedInteger:
    tokens = iter(re.findall(r"\[|\]|-?\d+", s))       # 切成 [  ]  整数 三种记号；共享一个迭代器当“读指针”

    def parse(tok: str) -> NestedInteger:              # 读完以 tok 开头的一个元素
        if tok != "[":
            return NestedInteger(int(tok))             # 整数：直接返回
        lst = NestedInteger()                          # 列表：继续读，直到对应的 ]
        for nxt in tokens:
            if nxt == "]":
                break
            lst.add(parse(nxt))                        # 子元素交给递归，它会用掉自己那一段记号
        return lst

    return parse(next(tokens))
```

运行（结果用嵌套 Python 列表表示）：`"324"` → `324`；`"[123,[456,[789]]]"` → `[123, [456, [789]]]`；`"[]"` → `[]`；`"[-1,[]]"` → `[-1, []]`；`"-5"` → `-5`；`"[[]]"` → `[[]]`。

**复杂度。** 时间 `O(n)`：正则切分一遍，每个记号被读一次；空间 `O(n)`：记号列表，加上等于嵌套深度的递归栈。

**易错点。**
- 逐字符处理数字：`"[123,-4]"` 会解析成 `[1, 2, 3, 4]`，多位数被拆开、负号丢失。必须把整个整数（含 `-`）作为一个记号。
- 每一层递归各自新建迭代器（比如在 `parse` 里再写一次 `iter(re.findall(...))`）：子列表每次都从头读，`"[[1]]"` 永远读不完，抛 `RecursionError`；记号迭代器必须共享，读到哪里所有层都看得到。
- 深度：递归深度等于括号嵌套层数，`s` 最长 `5 * 10^4`，嵌套可深达约 `25000` 层，CPython 默认递归上限约 `1000`，`25000` 层的 `"[[[...]]]"` 会抛 `RecursionError`；要么 `sys.setrecursionlimit` 调高，要么改用显式栈（见追问）。

**追问。**
- 显式栈写法（深嵌套安全）：栈里放「正在填写的列表」；遇到 `[` 压入新列表，整数加进栈顶，遇到 `]` 弹出栈顶并加进新的栈顶，栈空时弹出的就是结果；整串只是一个整数要单独先处理。`O(n)`。
- 反过来序列化（`NestedInteger` → 字符串）：递归拼接，遇到整数输出数字，遇到列表输出 `"[" + ",".join(...) + "]"`。
- 输入可能含空格或非法字符：正则里加 `\s*` 吃掉空白；`]` 比 `[` 多或结尾还有多余记号，说明不合法，抛异常。

**同模式。** LC 394 字符串解码、LC 224 基本计算器、LC 339 嵌套列表加权和、LC 341 扁平化嵌套列表迭代器、LC 726 原子的数量。
