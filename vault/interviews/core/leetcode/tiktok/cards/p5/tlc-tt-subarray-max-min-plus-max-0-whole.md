## Q
**长度至少为 2 的子数组，最大化 min + max**｜Easy · 近一年被问：美国 1 次、国内 0 次 · 最近 2025-11-26（美国面试记录）

给 `n` 个正整数的数组 `nums`，找一个长度至少为 `2` 的连续子数组，使该子数组的最小值与最大值之和最大，返回这个和。`2 <= n <= 10^5`，`1 <= nums[i] <= 10^9`。先给出能用的暴力解，再给出线性时间的解。例：`[5, 12, 9, 6, 4]` → `21`（子数组 `[12, 9]`，`12 + 9`）；`[3, 1, 3]` → `4`；`[1, 100, 1]` → `101`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 答案就是所有相邻两数之和的最大值：任何长度至少为 `2` 的子数组，其「最小值 + 最大值」都不会超过它里面某一对相邻元素之和，所以只看长度为 `2` 的窗口就够了。`O(n)` 时间，`O(1)` 空间。

**识别。** 「子数组 + 最小值 + 最大值」第一反应是滑动窗口或单调队列，但目标是 `min + max` 的和，不是「窗口里满足条件的最长」；这类题先看结构性质：扩大窗口时最大值只会变大、最小值只会变小，两者互相抵消。`n = 10^5` 排除 `O(n^2)`；面试流程是先写暴力、再找线性，提示答案有简单的结构。

**推导。** 暴力：枚举每个子数组，求 `min` 和 `max`，`O(n^3)`；固定左端点向右扩展并滚动维护最小、最大，`O(n^2)` → 浪费：长度大于 `2` 的子数组都在重复计算，但它们的价值被某个长度为 `2` 的窗口盖住了 → 洞察：设子数组的最大值在位置 `p`，因为长度至少为 `2`，`p` 在子数组里至少有一个邻居 `q`；邻居的值不小于子数组的最小值，所以 `min + max <= nums[q] + nums[p]`；而 `(p, q)` 本身就是一个合法的长度为 `2` 的子数组，它的 `min + max` 恰好等于 `nums[p] + nums[q]`。于是最优解一定能取在相邻两个数上。

```python
from itertools import pairwise


def max_min_plus_max(nums: list[int]) -> int:
    return max(a + b for a, b in pairwise(nums))     # 最优子数组可以缩成相邻两个数
```

运行：`[5, 12, 9, 6, 4]` → `21`；`[1, 1]` → `2`；`[3, 1, 3]` → `4`；`[1, 100, 1]` → `101`。

**复杂度。** 时间 `O(n)`；空间 `O(1)`（`pairwise` 是惰性迭代器，生成器表达式不建列表）。

**易错点。**
- 取最大的两个数相加：`[100, 1, 99]` 会得到 `199`，但这两个数之间隔着 `1`，包含它们的子数组最小值是 `1`，真正的最优是 `100 + 1 = 101`。
- 允许长度为 `1`：单个元素的 `min + max = 2 * x`，会偏大。`[10, 1]` 若包含 `[10]` 会得到 `20`，正确是 `11`。
- 把结论推广到「长度至少为 `3`」：`[5, 12, 9, 6, 4]` 在长度至少 `3` 时最优是 `18`（`[12, 9, 6]`），不是 `21`；邻居的论证只对长度为 `2` 的下界成立。

**追问。**
- 长度至少为 `k`（`k >= 3`）：结论不再成立，可以枚举左端点向右滚动维护最小、最大，`O(n^2)`。
- 同样的论证需要正数吗：不需要，对任意整数都成立，只用了「邻居不小于最小值」。
- 要返回具体的子数组：用一个循环记录取得最大和的下标 `i`，答案是 `nums[i:i + 2]`。

**同模式。** LC 53 最大子数组和、LC 907 子数组的最小值之和、LC 2104 子数组范围和、LC 239 滑动窗口最大值。
