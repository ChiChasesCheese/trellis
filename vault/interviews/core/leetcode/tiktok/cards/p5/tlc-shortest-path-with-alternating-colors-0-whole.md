## Q
**LC 1129 颜色交替的最短路径**｜Medium · CodeTop 国内累计 3 次 · 最近 2026-09-21（CodeTop）

有向图有 `n` 个结点，编号 `0` 到 `n - 1`。每条边是红色或蓝色，可能有自环和平行边。给定 `red_edges` 和 `blue_edges`：`red_edges[i] = [a, b]` 表示从 `a` 到 `b` 有一条红边，`blue_edges[j] = [u, v]` 表示从 `u` 到 `v` 有一条蓝边。返回长度为 `n` 的数组 `answer`，`answer[x]` 是从结点 `0` 到结点 `x` 的**红蓝边交替出现**的最短路径长度，不存在则为 `-1`。`1 <= n <= 100`，`0 <= red_edges.length, blue_edges.length <= 400`，所有端点在 `[0, n - 1]`。例：`n = 3, red_edges = [[0,1],[1,2]], blue_edges = []` → `[0,1,-1]`；`n = 3, red_edges = [[0,1]], blue_edges = [[2,1]]` → `[0,1,-1]`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 在「状态 = (结点, 下一条边必须是什么颜色)」上做广度优先搜索（BFS）：起点同时以红、蓝两种状态入队（第一条边可以任选颜色），每走一条颜色 `c` 的边就进入 `(终点, 另一种颜色)`；每个状态只入队一次；结点第一次被取出时的步数就是它的答案。`O(n + e)`。

**识别。** 「无权图最短路」是 BFS 的信号；「颜色必须交替」让一条边能不能走取决于**上一条边的颜色**，所以结点本身不是完整状态，必须带上颜色（拆点：每个结点变成两个状态）。同族：LC 847 访问所有结点的最短路径（状态带已访问集合）、LC 1293 网格中带消除障碍的最短路径（状态带剩余次数）。`n <= 100`、边 `<= 800`，规模很小，考的是状态设计。

**推导。** 暴力：DFS 枚举所有交替路径，图里有环（甚至自环）时路径无限长，要额外加长度上限。只按结点标记「是否访问过」的普通 BFS 也不对：同一个结点可能以红边到达，也可能以蓝边到达，后续能走的边不同，先到的那次会把另一种到达方式挡掉。洞察：完整状态是 `(结点, 下一条边的颜色)`，共 `2n` 个；一个状态下一步只能走对应颜色的出边，到达后翻转颜色。BFS 按步数层层推进，每个状态只处理一次，边数总共被扫一遍。

```python
from collections import deque


def shortest_alternating_paths(n: int, red_edges: list[list[int]], blue_edges: list[list[int]]) -> list[int]:
    graph: list[list[list[int]]] = [[[] for _ in range(n)] for _ in range(2)]   # graph[颜色][u]：u 的出边
    for u, v in red_edges:
        graph[0][u].append(v)
    for u, v in blue_edges:
        graph[1][u].append(v)
    ans = [-1] * n
    # 状态 (u, c)：当前在 u，下一条边必须是颜色 c；起点可以先走红也可以先走蓝
    seen = {(0, 0), (0, 1)}
    queue = deque([(0, 0, 0), (0, 1, 0)])  # (结点, 下一条边颜色, 已走步数)
    while queue:
        u, c, d = queue.popleft()
        if ans[u] == -1:                   # BFS 按步数递增，第一次到 u 就是最短
            ans[u] = d
        for v in graph[c][u]:
            if (v, 1 - c) not in seen:     # 走完颜色 c 的边，下一条必须换色
                seen.add((v, 1 - c))
                queue.append((v, 1 - c, d + 1))
    return ans
```

运行：示例 1 → `[0, 1, -1]`，示例 2 → `[0, 1, -1]`，`n = 1` 无边 → `[0]`，`n = 3, red_edges = [[0,1],[1,2]], blue_edges = [[0,1]]` → `[0, 1, 2]`，`n = 3, red_edges = [[0,0]], blue_edges = [[0,1],[1,2]]` → `[0, 1, -1]`。

**复杂度。** 时间 `O(n + e)`：`2n` 个状态各入队一次，每个状态扫它的同色出边，每条边只会被一种状态扫到；空间 `O(n + e)`。

**易错点。**
- 只用结点标记已访问：`red_edges = [[0,1],[1,2]]`、`blue_edges = [[0,1]]`，若先走红边 `0→1` 就把 `1` 标记掉，蓝边 `0→1` 被丢弃，而 `1→2` 是红边，需要以蓝边到达 `1` 才能走，结果 `[0, 1, -1]`（正确 `[0, 1, 2]`）。
- 起点只放一种颜色：`red_edges = []`、`blue_edges = [[0,1],[1,2]]` 只放红色状态得到 `[0, -1, -1]`（正确 `[0, 1, -1]`，因为第一条边可以任选颜色）。
- `answer[0]` 是 `0`（空路径），不是 `-1`；结点 `x` 取首次出队时的步数，不要在入队时反复覆盖。

**追问。**
- 要返回路径本身：每个状态记父状态 `(u, c)`，到达后沿父指针回溯。
- 推广到 `k` 种颜色循环（红 → 蓝 → 绿 → 红）：状态 `(u, 下一色)`，颜色用 `(c + 1) % k` 轮转。
- 边带权：改成 Dijkstra，状态仍是 `(u, c)`；要求必须以某色边结束：只统计该色到达的状态。
