## Q
**一个骰子掷出更大点数的概率**｜Medium · 近一年被问：美国 1 次、国内 0 次 · 最近 2026-04-04（美国面试记录）

两个公平的骰子 `A`、`B`，各有若干个面，每面写一个整数（两个骰子面数可以不同，数字可以重复）。各掷一次，每个面朝上的概率相等。求 `A` 的点数**严格大于** `B` 的概率，返回精确的分数。`1 <= 面数 <= 10^5`，面上的数在 `[-10^9, 10^9]`。例：`A = [2,2,6]`，`B = [1,5,5]` → `5/9`（9 种等可能的组合里，`2>1` 两次，`6` 赢 3 次）。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 概率 = 「`A` 赢的组合数 / `p·q`」。把 `B` 排序，对 `A` 的每一面用 `bisect_left` 数出 `B` 中严格小于它的面数，求和就是赢的组合数；用 `Fraction` 返回精确分数。`O((p + q) log q)`。

**识别。** 两个骰子公平、各掷一次 → `p·q` 种组合等可能，概率问题变成**数对计数**：数 `a > b` 的对数。`10^5 × 10^5 = 10^10` 对，双重循环不行；「对每个 `a` 数有多少 `b < a`」是排序 + 二分（或排序 + 双指针）的标准信号。

**推导。** 暴力双重循环 `O(pq)`，最坏 `10^10`。浪费在于对每个 `a` 都把 `B` 整个扫一遍，而「`B` 中小于 `a` 的个数」只依赖 `a` 在有序的 `B` 里的位置。`B` 排序一次后，每个 `a` 二分 `O(log q)`；也可以把 `A` 也排序，`a` 递增时分界点只右移，双指针 `O(p + q)` 扫完（排序仍是 `O(n log n)`）。

```python
from bisect import bisect_left
from fractions import Fraction


def beat_probability(a: list[int], b: list[int]) -> Fraction:
    sorted_b = sorted(b)
    # 对 A 的每一面，数 B 中严格小于它的面：bisect_left 返回 < x 的个数
    wins = sum(bisect_left(sorted_b, x) for x in a)
    return Fraction(wins, len(a) * len(b))
```

运行：`A = [2,2,6]`，`B = [1,5,5]` → `Fraction(5, 9)`；反过来 `A = [1,5,5]`，`B = [2,2,6]` → `4/9`；`[3]` 对 `[3]` → `0`；`[-10^9]` 对 `[10^9]` → `0`；`A = [2,2,4,4,9,9]`，`B = [1,1,6,6,8,8]` → `5/9`。

**复杂度。** 时间 `O(q log q + p log q)`：排序加 `p` 次二分；空间 `O(q)`。`p = q = 10^5` 时约 `3.3·10^6` 次比较。

**易错点。**
- 用 `bisect_right`：数到的是「`<=`」，把平局算成赢。`A = [2,5]`，`B = [2,5]` 会得到 `3/4`（正确 `1/4`）。
- 用浮点除法 `wins / (p * q)`：结果不精确，`1/3` 这类值比较相等会出问题；题目要精确值就用 `Fraction`，或返回 `(wins, p*q)` 再约分。
- `wins` 最大 `10^10`，Python 整数不会溢出；换成 32 位整型的语言要用 64 位。

**追问。**
- 平局算一半：每面多数一个平局数 `bisect_right - bisect_left`，概率 = `(赢 + 平/2) / (p·q)`，写成 `Fraction(2·赢 + 平, 2·p·q)` 保持整数运算。
- 非传递骰子：存在。`A = [2,2,4,4,9,9]`、`B = [1,1,6,6,8,8]`、`C = [3,3,5,5,7,7]`，`A` 胜 `B`、`B` 胜 `C`、`C` 胜 `A` 的概率都是 `5/9`。「胜过」这个关系不满足传递性，不能排序选出「最强」的骰子。
- 面上的数重复很多：先用 `Counter` 压缩成（值，次数），对不同值二分后乘次数。

**同模式。** LC 2300 咒语和药水的成功对数、LC 1855 下标对中的最大距离、LC 2563 统计公平数对的数目、LC 315 计算右侧小于当前元素的个数。
