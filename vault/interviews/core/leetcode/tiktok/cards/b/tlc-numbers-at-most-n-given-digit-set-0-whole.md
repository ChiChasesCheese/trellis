## Q
**LC 902 最大为 N 的数字组合**｜Hard · TikTok·字节 高频

给一个按非递减顺序排列的数字字符数组 `digits`，每个数字可以使用任意多次来拼出数。返回能拼出的、小于或等于整数 `n` 的**正整数**个数。`1 <= digits.length <= 9`，`digits[i]` 是 `'1'` 到 `'9'` 之间的单个字符且互不相同，`digits` 按非递减顺序排列，`1 <= n <= 10^9`。例：`digits = ["1","3","5","7"]`，`n = 100` → `20`；`digits = ["1","4","9"]`，`n = 10^9` → `29523`；`digits = ["7"]`，`n = 8` → `1`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 数位计数：设 `n` 有 `L` 位，`d = len(digits)`。位数少于 `L` 的数随便拼，共 `Σ d^len`；位数等于 `L` 的数，从高位到低位贴着 `n` 走：第 `i` 位选比 `n[i]` 小的数字（`bisect_left` 个），后面随便拼，贡献 `小的个数 × d^(L-1-i)`；选等于 `n[i]` 才能继续贴着走，`n[i]` 不在 `digits` 就停；每一位都贴住，说明 `n` 本身可写，再加 `1`。

**识别。** 「不超过 `N`、由给定数字拼成的数有多少个」是数位 DP（digit DP）或数位计数。`n <= 10^9`，逐个枚举不行；约束只在“紧贴上界”的那一条路径上，一旦某一位小于 `n` 的对应位，后面就完全自由。

**推导。** 暴力：枚举 `1..n`，检查每位是否在 `digits` 里，`O(n · L)`，约 `10^10`。浪费：绝大多数数从某一位起已经小于 `n`，后面每一位都是 `d` 种选法，个数是 `d` 的幂，不需要逐个数。洞察：按“和 `n` 第一个不同的位置”给所有数分类，各类互不重叠：位数更少的一类，加上位数相同时第 `i` 位更小的各类，再加完全等于 `n` 的一个数。每类的个数是一个乘积。

```python
from bisect import bisect_left


def at_most_n_given_digit_set(digits: list[str], n: int) -> int:
    s, size = str(n), len(digits)
    total = sum(size ** length for length in range(1, len(s)))   # 位数比 n 少的：随便填
    for i, ch in enumerate(s):                                   # 位数和 n 相同：逐位贴着 n 走
        total += bisect_left(digits, ch) * size ** (len(s) - 1 - i)   # 这一位选比 ch 小的，后面随便填
        if ch not in digits:
            return total                                         # 贴不住了，后面没有“等于 n”的数
    return total + 1                                             # 每一位都贴住：n 自己也能写
```

运行：`(["1","3","5","7"], 100)` → `20`，`(["1","4","9"], 10**9)` → `29523`，`(["7"], 8)` → `1`，`(["7"], 77)` → `2`，`(list("123456789"), 10**9)` → `435848049`，`(["3"], 1)` → `0`。

**复杂度。** 时间 `O(L · d)`（`ch not in digits` 在长度至多 `9` 的列表上扫描，`bisect_left` 为 `O(log d)`），`L <= 10`；空间 `O(L)`。

**易错点。**
- 忘记 `n` 自己：`digits = ["7"]`、`n = 77`，贴住全部两位后要 `+1`，漏掉得到 `1`，正确是 `2`（`7` 和 `77`）。
- 贴不住时没有提前返回，而是继续往后累加并最后 `+1`：`digits = ["1","3","5","7"]`、`n = 100`，第二位 `'0'` 不在 `digits` 中，继续就得到 `21`，正确是 `20`。
- 漏掉位数更少的数：`n = 100` 时一位数和两位数共 `4 + 16 = 20` 个，正是全部答案；只数三位数会得到 `0`。

**追问。**
- `n` 以超长字符串给出（如 `10^5` 位）：算法本来就按字符走，只需把 `size ** k` 换成预先计算的幂表，复杂度 `O(L · d)`。
- `digits` 可以含 `'0'`：前导零不能算数位，要引入“是否已经开始”的状态，用 `(位置, 是否贴着上界, 是否已开始)` 的记忆化搜索（见另一种解法）。
- 只要严格小于 `n`：去掉最后的 `+1`，并且全部贴住时不计 `n`。

**同模式。** LC 233 数字 1 的个数、LC 600 不含连续 1 的非负整数、LC 1012 至少有 1 位重复的数字、LC 2376 统计特殊整数、LC 357 统计各位数字都不同的数字个数。
