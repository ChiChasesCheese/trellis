## Q
**LC 322 零钱兑换**｜Medium · LC TikTok 热度 75/100 · CodeTop 国内累计 59 次 · 最近 2026-04-15（CodeTop）

给整数数组 `coins`（不同面额的硬币）和整数 `amount`（总金额），返回凑成总金额所需的**最少**硬币个数；凑不出来返回 `-1`。每种硬币的数量无限。`1 <= coins.length <= 12`，`1 <= coins[i] <= 2^31 - 1`，`0 <= amount <= 10^4`。例：`coins = [1,2,5], amount = 11` → `3`（`5+5+1`）；`coins = [2], amount = 3` → `-1`；`coins = [1], amount = 0` → `0`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 完全背包（unbounded knapsack）的最小化版本：`dp[a]` 是凑成金额 `a` 的最少硬币数，`dp[a] = min(dp[a - c] + 1)` 对所有 `c <= a` 的面额 `c`；用 `amount + 1` 当「不可达」哨兵。`O(amount × 硬币种数)`。

**识别。** 「最少个数」「每种无限」「凑出目标」是动态规划信号：决策是「最后一枚用哪种面额」，剩下的子问题是更小金额的同一个问题（最优子结构）。金额上界 `10^4`、硬币至多 `12` 种 → 约 `1.2×10^5` 个状态转移，DP 很轻。**贪心不行**：最大面额优先不保证最少。

**推导。** 暴力：递归枚举每一步选哪种硬币，指数级 → 浪费：同一个剩余金额会被重复展开很多次（重叠子问题） → 把「凑成 `a` 的最少个数」记成 `dp[a]`，从小到大填表 → 每个金额只算一次，每次试 `len(coins)` 种面额。

```python
def coin_change(coins: list[int], amount: int) -> int:
    inf = amount + 1                      # 哨兵：比任何真实答案都大
    dp = [0] + [inf] * amount             # dp[a] = 凑成金额 a 的最少硬币数
    for c in coins:                       # 完全背包：外层硬币，内层金额正序（同一枚硬币可重复用）
        for a in range(c, amount + 1):
            dp[a] = min(dp[a], dp[a - c] + 1)
    return dp[amount] if dp[amount] < inf else -1
```

运行：`([1,2,5], 11)` → `3`，`([2], 3)` → `-1`，`([1], 0)` → `0`，`([1,3,4], 6)` → `2`，`([186,419,83,408], 6249)` → `20`，`([2147483647], 10000)` → `-1`。

**复杂度。** 时间 `O(amount × len(coins))`；空间 `O(amount)`。

**易错点。**
- 贪心错：`[1,3,4]`、`amount = 6`，贪心取 `4+1+1` 是 `3` 枚，正确是 `3+3` 的 `2` 枚。
- 内层金额必须**正序**：正序时 `dp[a - c]` 已经用过当前硬币，因此同一枚硬币可重复；倒序就成了 0/1 背包。`[2]`、`amount = 4` 倒序得到 `-1`，正确是 `2`。
- 哨兵不能用 `0` 或 `-1`；`amount + 1` 加一后仍不会被误当成答案。硬币面额可能大到 `2^31 - 1`，`range(c, amount + 1)` 此时为空，自然跳过。

**追问。**
- 要输出具体用了哪些硬币：另存 `pick[a]` 记录最后一枚，从 `amount` 回溯；`[1,2,5]`、`11` 得到 `[1, 5, 5]`。
- 统计组合数（LC 518）：`dp[a] += dp[a - c]`，外层硬币、内层金额正序；顺序对调会变成排列数（LC 377）。
- BFS 解法：把金额当节点、加一枚硬币当一条边，最短路径长度就是答案；金额极大而硬币很少时 BFS 有时更省。

**同模式。** LC 518 零钱兑换 II、LC 377 组合总和 IV、LC 279 完全平方数、LC 139 单词拆分。
