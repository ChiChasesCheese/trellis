## Q
**LC 403 青蛙过河**｜Hard · LC TikTok 全时段热度 50/100 · CodeTop 国内累计 1 次 · 最近 2021-03-14（国内 CodeTop）

河被等分成单元格，有些格子上有石子。青蛙只能跳到石子上，不能落水。给升序的石子位置 `stones`，判断青蛙能否跳到最后一块石子。青蛙开始在第一块石子（位置 `0`），**第一步只能跳 `1` 个单位**；如果上一步跳了 `k` 个单位，下一步只能跳 `k - 1`、`k` 或 `k + 1` 个单位；只能向前跳。`2 <= stones.length <= 2000`，`0 <= stones[i] <= 2^31 - 1`，`stones[0] == 0`，严格升序。例：`[0,1,3,5,6,8,12,17]` → `true`；`[0,1,2,3,4,8,9,11]` → `false`（第 5、6 块石子间距太大）。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 状态是「站在哪块石子、上一步跳了多远」`(pos, k)`。用字典 `jumps[pos]` 记录能以哪些「最后一跳长度」站上石子 `pos`，按石子从左到右推进：从 `pos` 出发尝试 `k − 1, k, k + 1`，落在石子上就把这一跳的长度加入目标石子的集合。终点集合非空即可。`O(n^2)`。

**识别。** 「能不能到达」+「下一步的选择取决于上一步」= 状态里必须带上一跳长度，单靠位置不够。位置高达 `2^31` 不能当数组下标，但石子只有 `2000` 块，用位置当字典的键。每块石子上的最后一跳长度不超过它是第几块石子（第 `i` 块最多跳了 `i` 步，每步至多比前一步大 `1`），所以每块石子的集合大小 `O(n)`，状态总数 `O(n^2) = 4 · 10^6`。

**推导。** 暴力 DFS：从 `(0, 0)` 出发递归尝试三种跳法，指数级且重复访问同一 `(pos, k)` → 加记忆化，状态 `O(n^2)`，每个状态 3 次转移，可行 → 改成自底向上：石子位置升序，所以按位置从左到右处理，一块石子的所有来源跳法在处理它之前就已经全部确定，刷表即可：对每个 `(pos, k)` 向前推三种目标。起点当作「上一跳长度 `0`」，下一步 `k − 1, k, k + 1` 中只有 `1 > 0` 合法，自然满足「第一步只能跳 1」。

```python
def can_cross(stones: list[int]) -> bool:
    jumps: dict[int, set[int]] = {pos: set() for pos in stones}   # 石子位置 -> 能以哪些「最后一跳长度」站上来
    jumps[0].add(0)                            # 起点：当作上一跳长度 0，于是下一跳只能是 1
    for pos in stones:
        for k in jumps[pos]:
            for step in (k - 1, k, k + 1):
                if step > 0 and pos + step in jumps:
                    jumps[pos + step].add(step)
    return bool(jumps[stones[-1]])
```

运行：`[0,1,3,5,6,8,12,17]` → `True`，`[0,1,2,3,4,8,9,11]` → `False`，`[0,1]` → `True`，`[0,2]` → `False`，`[0,1,2]` → `True`；`2000` 块连续石子约 `0.01` 秒，`2000` 块三角数位置的石子也同样很快。

**复杂度。** 时间 `O(n^2)`（`n^2` 个状态，每个 3 次转移）；空间 `O(n^2)`（所有集合的总大小）。

**易错点。**
- 漏掉 `step > 0`：`k = 1` 时 `step = 0`，`pos + 0` 就是自己，会往正在遍历的集合里加元素，`[0,1,2]` 抛 `RuntimeError: Set changed size during iteration`；即使不抛错，原地跳也没有意义。
- 只记「石子可达」不记上一跳：丢失了决定下一步范围的信息。
- 每次只贪心地跳最大步：`[0,1,3,5,8,11,13,15,16]` 贪心走进死路返回 `False`，正确是 `True`。

**追问。**
- 用递归 + `functools.cache`：状态 `(pos, k)`，只探索从起点可达的状态，找到终点即提前返回；写法是 `@cache` 修饰的 `dfs(pos, k)`，逐个尝试 `k + 1, k, k - 1`。
- 要输出一条跳法：字典里存 `(上一块石子, 步长)`，终点回溯。
- 石子数很大：这里 `n = 2000`；`n` 更大时用「第 `i` 块石子上的步长 `<= i`」剪枝，并跳过与下一块距离大于 `k + 1` 的状态。
