## Q
**面试题 16.01 交换数字**｜Medium · CodeTop 国内累计 1 次 · 最近 2025-12-19（CodeTop）

编写一个函数，不使用临时变量，直接交换 `numbers = [a, b]` 中 `a` 与 `b` 的值并返回。`numbers.length == 2`，`-2147483647 <= numbers[i] <= 2147483647`。 例：`numbers = [1,2]` → `[2,1]`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 异或交换（XOR swap）：`a ^= b; b ^= a; a ^= b`，靠的是 `x ^ x = 0`、`x ^ 0 = x` 和异或的交换律、结合律；加减法 `a = a + b; b = a - b; a = a - b` 是同一个思路。`O(1)`。

**识别。** 「不用临时变量交换」→ 用一种**可逆运算**把两个值的信息合在一个变量里，再从中剥出另一个：异或是自己的逆运算，加和减互为逆运算。值域到 `±(2^31 - 1)` → 在 32 位整数的语言里 `a + b` 会溢出；Python 整数没有上限，异或对负数按无限位补码计算，也没有问题。

**推导。** 常规写法 `t = a; a = b; b = t` 需要临时变量。想法是让 `a` 先存「`a` 和 `b` 的组合」`a ^ b`；再用 `b` 与组合异或，抵消掉 `b`，得到原来的 `a`，存进 `b`；最后组合再与新的 `b`（即原 `a`）异或，得到原来的 `b`。Python 惯用的 `a, b = b, a` 先在右边打包出一个元组，本质上借助了临时对象，面试官要求「不用临时变量」时要给出位运算版本。

```python
def swap_numbers(numbers: list[int]) -> list[int]:
    numbers[0] ^= numbers[1]        # numbers[0] = a ^ b
    numbers[1] ^= numbers[0]        # numbers[1] = b ^ (a ^ b) = a
    numbers[0] ^= numbers[1]        # numbers[0] = (a ^ b) ^ a = b
    return numbers
```

运行：`[1,2]` → `[2,1]`，`[-3,5]` → `[5,-3]`，`[7,7]` → `[7,7]`，`[0,-1]` → `[-1,0]`，`[2147483647,-2147483647]` → `[-2147483647,2147483647]`。

**复杂度。** 时间 `O(1)`；空间 `O(1)`。

**易错点。**
- 两个「位置」是同一个变量时，异或交换会清零：`nums[i] ^= nums[j]` 在 `i == j` 时第一步就把它变成 0，对 `[5,9]` 交换下标 0 与 0 得到 `[0,9]`（正确 `[5,9]`）。值相等但位置不同没问题，`[7,7]` → `[7,7]`。
- 加减法在 Java 的 `int` 上会溢出：`2147483647 + 1` 回绕成 `-2147483648`，但补码回绕下后两步也回绕，最终结果仍然正确，`[2147483647, 1]` → `[1, 2147483647]`；C/C++ 的有符号溢出是未定义行为，那里应该用异或。
- 乘除法 `a = a * b; b = a // b; a = a // b` 遇到 0 就失效（除零），不要用。

**追问。**
- 工程里为什么不用异或交换：临时变量通常就在寄存器里，更快；三步异或前后相互依赖，无法并行；可读性差，还有同址清零的坑。
- Python 的 `a, b = b, a`：右边先求值成元组，再从左到右赋给目标。目标里带下标时会踩坑，见下条。
- `nums[i], nums[nums[i] - 1] = nums[nums[i] - 1], nums[i]`：对 `nums = [3,1,2], i = 0` 得到 `[2,3,2]`（正确 `[2,1,3]`），因为赋第二个目标时 `nums[i]` 已经被改了；先存 `j = nums[i] - 1` 再交换。

**同模式。** LC 136 只出现一次的数字、LC 268 丢失的数字、LC 371 两整数之和、面试题 16.07 最大数值。
