## Q
**LC 1584 连接所有点的最小费用**｜Medium · LC TikTok 热度 50/100

给二维平面上的点数组 `points`，`points[i] = [xi, yi]`。连接点 `[xi, yi]` 和 `[xj, yj]` 的费用是它们的曼哈顿距离 `|xi - xj| + |yi - yj|`。返回把所有点连接起来的最小总费用；只有任意两点之间有且仅有一条简单路径时，才认为所有点都已连接。`1 <= points.length <= 1000`，`-10^6 <= xi, yi <= 10^6`，所有点两两不同。例：`[[0,0],[2,2],[3,10],[5,2],[7,0]]` → `20`；`[[3,12],[-2,5],[-4,1]]` → `18`；`[[0,0],[1,1],[1,0],[-1,1]]` → `4`；`[[-1000000,-1000000],[1000000,1000000]]` → `4000000`；`[[0,0]]` → `0`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 求完全图的最小生成树（minimum spanning tree，MST）。点多边稠密（`n = 1000` 时约 `5 × 10^5` 条边），用 Prim 算法的数组版：维护每个未选点到已选集合的最短距离 `dist`，每轮取最小的那个点加入，并用它更新其他点的 `dist`。`O(n^2)`，不需要堆，也不需要显式建边。

**识别。** 「连接所有点」「总费用最小」「任意两点之间有且仅有一条路径」是在描述一棵生成树，最小化总权重就是 MST。完全图是稠密图，`O(n^2)` 的 Prim 比先建出 `O(n^2)` 条边再排序的 Kruskal 更省。

**推导。** 暴力：枚举所有生成树，数量是 `n^(n-2)`（凯莱公式），不可能。贪心依据是割性质（cut property）：把点分成已选和未选两部分，连接两部分的最小边一定属于某棵 MST，所以每一步加入连接两部分的最小边是安全的。Prim 就是这样从点 `0` 开始一点点长出整棵树。每一轮需要“未选点里离已选集合最近的是谁”，稠密图里直接线性扫描 `dist` 数组，总共 `n` 轮，每轮扫描加更新 `O(n)`。

```python
def min_cost_connect_points(points: list[list[int]]) -> int:
    n = len(points)
    INF = 1 << 60
    dist = [INF] * n                       # dist[i]：i 到已选集合的最短曼哈顿距离
    dist[0] = 0
    used = [False] * n
    total = 0
    for _ in range(n):
        u = min((i for i in range(n) if not used[i]), key=dist.__getitem__)   # 离集合最近的未选点
        used[u] = True
        total += dist[u]
        ux, uy = points[u]
        for v in range(n):
            if not used[v]:
                d = abs(ux - points[v][0]) + abs(uy - points[v][1])
                if d < dist[v]:
                    dist[v] = d
    return total
```

运行：五个示例依次得到 `20`、`18`、`4`、`4000000`、`0`；`1000` 个随机点约 `40 ms`。

**复杂度。** 时间 `O(n^2)`；空间 `O(n)`。

**易错点。**
- 取 `n - 1` 条最短的边相加，不检查是否成环：示例 1 得到 `18`（边 `3, 4, 4, 7` 里 `7` 把前三个点连成了环，点 `[3,10]` 还没连上），正确是 `20`（`3 + 4 + 4 + 9`）。
- 把 Prim 写成 Dijkstra，更新成 `dist[v] = dist[u] + d`（到起点的路径长）：示例 1 得到 `31`，正确是 `20`。MST 里 `dist[v]` 只是“连到集合的一条边”的权重，不累加。
- 忘了 `dist[0] = 0`：所有 `dist` 都是 `INF`，第一轮选出的点不确定，`total` 会加上 `INF`。

**追问。**
- 点数很大（`10^5`）：`O(n^2)` 不行。曼哈顿距离的 MST 只需要每个点向八个方向扇区里最近的点连候选边，总共 `O(n)` 条，再用 Kruskal，`O(n log n)`。
- 边是显式给出的稀疏图：Kruskal 加并查集（Union-Find），`O(E log E)`。
- 返回 MST 的具体边：更新 `dist[v]` 时同时记 `parent[v] = u`。
