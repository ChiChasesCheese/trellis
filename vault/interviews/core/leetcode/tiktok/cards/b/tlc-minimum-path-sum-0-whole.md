## Q
**LC 64 最小路径和**｜Medium · TikTok·字节 高频

给一个 `m x n` 的非负整数网格 `grid`，找一条从左上角到右下角的路径，使路径上数字之和最小；每次只能向下或向右移动一步。`1 <= m, n <= 200`，`0 <= grid[i][j] <= 200`。例：`[[1,3,1],[1,5,1],[4,2,1]]` → `7`（路径 `1→3→1→1→1`）；`[[1,2,3],[4,5,6]]` → `12`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 网格 DP：到达格子 `(i, j)` 的最小路径和等于 `grid[i][j]` 加上「上方格」与「左方格」两者的较小值；每格只依赖上一行和同一行左边，所以用一维数组滚动。`O(mn)` 时间，`O(n)` 空间。

**识别。** 「网格 + 只能向右 / 向下 + 路径和最优」是网格 DP 的标准信号：每个格子只能从上或左到达，没有环，计算顺序天然是从左上到右下。数值非负、移动方向受限，所以不需要最短路算法；若允许四个方向走，才需要 Dijkstra。

**推导。** 暴力：DFS 枚举所有路径，路径数是 `C(m+n-2, m-1)`，指数级。浪费：到达同一格的多条路径，后面的走法完全一样，只有「到这格的最小和」有用。洞察：`dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])`，第一行只能从左来，第一列只能从上来。滚动：在同一行里从左到右更新，`dp[j]` 此刻还是上一行的值（从上来），`dp[j-1]` 已经更新为本行的值（从左来）。

```python
from itertools import accumulate


def min_path_sum(grid: list[list[int]]) -> int:
    dp = list(accumulate(grid[0]))               # 第一行只能一路向右：就是前缀和
    for row in grid[1:]:
        dp[0] += row[0]                          # 第一列只能从上面来
        for j in range(1, len(row)):
            dp[j] = min(dp[j], dp[j - 1]) + row[j]   # dp[j] 还是上一行的值（从上来），dp[j-1] 已更新（从左来）
    return dp[-1]
```

**运行。** `[[1,3,1],[1,5,1],[4,2,1]]` → `7`；`[[1,2,3],[4,5,6]]` → `12`；`[[7]]` → `7`；单行 `[[1,2,3]]` → `6`；单列 `[[1],[2],[3]]` → `6`；`200 x 200` 全是 `200` → `79800`。

**复杂度。** 时间 `O(mn)`，每格计算一次；空间 `O(n)`，只保留一行。

**易错点。**
- 漏掉第一列的初始化 `dp[0] += row[0]`：单列 `[[1],[2],[3]]` 会返回 `1`，正确是 `6`。
- 内层循环从右往左：`dp[j-1]` 还是上一行的值，等于用错了「左边」。`[[1,1,1],[9,1,1]]` 会返回 `3`，正确是 `4`。
- 贪心地每步走较小的邻格：`[[1,3,1],[1,5,1],[4,2,1]]` 会先走下（`1 < 3`）、再走下（`4 < 5`），总和 `9`，正确是 `7`。

**追问。**
- 输出路径本身：保留二维表（或前驱数组），从右下角按「来自上还是来自左」回溯，空间 `O(mn)`。
- 允许上下左右四个方向：不再有拓扑顺序，改用 Dijkstra（`heapq`），时间 `O(mn log mn)`。
- 有障碍物（LC 63）：障碍格的 `dp` 设为无穷大，或不可达的计数为 `0`。

**同模式。** LC 62 不同路径、LC 63 不同路径 II、LC 120 三角形最小路径和、LC 931 下降路径最小和、LC 174 地下城游戏。
