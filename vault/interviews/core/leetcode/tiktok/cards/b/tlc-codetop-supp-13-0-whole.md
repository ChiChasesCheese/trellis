## Q
**补充题 13 中文数字转阿拉伯数字**｜Medium · CodeTop 国内累计 4 次 · 最近 2026-02-27（国内 CodeTop）

给一个表示非负整数的中文数字字符串 `s`，把它转成对应的整数。`s` 只含 `零一二两三四五六七八九十百千万亿` 这些字符，规范书写、保证合法（`十二` 表示 `12`，开头的 `一十` 可省成 `十`；`两` 在百、千、万、亿前等同于 `二`；各单位按规范顺序出现）。`1 <= len(s) <= 30`，结果满足 `0 <= 结果 <= 10^12`。例：`"一亿两千三百万零五"` → `123000005`；`"十二"` → `12`；`"两千零二"` → `2002`；`"零"` → `0`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 从左到右扫一遍，维护三个量：`num`（刚读到、还没乘单位的个位数字）、`section`（当前万级块内，千位以下已算好的值）、`total`（已结算的万、亿级部分）。数字就记到 `num`；`十百千` 把 `num` 乘上单位加进 `section`；`万` 把 `section + num` 乘 `10^4` 结算进 `total`；`亿` 把**到目前为止的全部**乘 `10^8`。`O(n)`。

**识别。** 中文数字是「**数字 × 单位**」的累加，单位分两层：`十百千` 是块内单位，`万亿` 是块间单位，并且 `亿` 的作用范围比 `万` 大。这类「带层级单位的字符串解析」都用一次扫描加几个累加器，不需要递归或栈。字符串最长 `30`，任何线性解都够。

**推导。** 暴力：按 `亿`、`万` 把字符串递归切成三段，每段再按 `千百十` 解析，再相加，可行但切字符串多。浪费：切分和解析是两件事，其实一遍扫描就能同时完成。洞察：`万` 的系数只是「上一个 `万` 或 `亿` 之后」这一块，所以只结算 `section`；`亿` 的系数是它前面攒下的全部（比如 `一万二千三百亿` 里 `万` 块也在内），所以乘整个 `total`。`十` 前面的数字可以省略，用 `num or 1` 补上；`零` 只是把 `num` 设为 `0`，不影响累加。

```python
DIGITS = {"零": 0, "一": 1, "二": 2, "两": 2, "三": 3, "四": 4,
          "五": 5, "六": 6, "七": 7, "八": 8, "九": 9}
UNITS = {"十": 10, "百": 100, "千": 1000}


def chinese_to_int(s: str) -> int:
    total = 0       # 已结算的部分（万、亿级别的块）
    section = 0     # 当前块内（千位以内）已经算完的数
    num = 0         # 刚读到、还没乘单位的个位数字
    for ch in s:
        if ch in DIGITS:
            num = DIGITS[ch]
        elif ch in UNITS:                       # 十百千：乘到当前数字上；「十二」省略了前面的一
            section += (num or 1) * UNITS[ch]
            num = 0
        elif ch == "万":                         # 万：只结算上次万/亿以来的这一块
            total += (section + num) * 10_000
            section = num = 0
        else:                                    # 亿：前面攒下的全部都乘 1 亿
            total = (total + section + num) * 100_000_000
            section = num = 0
    return total + section + num
```

运行：`"一亿两千三百万零五"` → `123000005`，`"零"` → `0`，`"十"` → `10`，`"十二"` → `12`，`"二十"` → `20`，`"一百零五"` → `105`，`"两千零二"` → `2002`，`"三十亿零七"` → `3000000007`，`"一万亿"` → `1000000000000`，`"九千九百九十九亿九千九百九十九万九千九百九十九"` → `999999999999`。

**复杂度。** 时间 `O(n)`：每个字符一次判断；空间 `O(1)`。

**易错点。**
- 把 `万` 和 `亿` 一样处理，都乘全部累计：`"一亿两千三百万零五"` 得 `1000023000005`，正确 `123000005`。`万` 只能结算自己这一块。
- 十前面省略了 `一`：直接 `section += num * 单位`，`"十二"` 得 `2`（正确 `12`），`"十"` 得 `0`（正确 `10`）。用 `(num or 1)` 补一。
- 结尾忘了加上剩下的 `section + num`：`"一百零五"` 返回 `0`。

**追问。**
- 反过来，阿拉伯数字转中文：按 `亿`、`万` 切成四位一组，组内处理 `千百十`，组间根据中间是否出现 `0` 决定补 `零`。
- 兼容大写（`壹贰叁`、`拾佰仟`）和口语（`一百一` 表示 `110`）：扩大映射表；口语省略要多一条规则，末尾单独的数字补上比它高一级的单位。
- 小数和负数：先按 `负` 去符号，再按 `点` 切开，整数部分用上面的函数，小数部分逐位映射成数字。

**同模式。** LC 8 字符串转换整数 (atoi)、LC 273 整数转换英文表示、LC 12 整数转罗马数字、LC 13 罗马数字转整数。
