## Q
**LC 179 最大数**｜Medium · 近一年被问：美国 0 次、国内 1 次 · CodeTop 国内累计 32 次 · 最近 2026-10-18（国内面试记录）

给一组非负整数 `nums`，重新排列每个数的顺序（每个数不可拆分）使之拼成一个最大的整数。结果可能很大，返回字符串。`1 <= nums.length <= 100`，`0 <= nums[i] <= 10^9`。例：`[10,2]` → `"210"`，`[3,30,34,5,9]` → `"9534330"`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 自定义排序：把数转成字符串，两个串 `a`、`b` 比较时看 `a + b` 与 `b + a` 谁更大，大的排前面；排完直接拼接。全是 `0` 时特判返回 `"0"`。`O(n log n · L)`。

**识别。** 「重新排列使拼出来的结果最大 / 最小」= 排序题，但不能按数值或字典序排，要按「谁放前面拼起来更大」排，这就是**自定义比较器**（comparator）。`n <= 100` 说明比较器的常数无所谓；`10^9` 提示数字不能直接拼成 int，也不要转成 int 比（会大），用字符串。

**推导。** 暴力：`n!` 种排列取最大，`n = 100` 不可能 → 按值降序？`[3,30]` 得 `"303"`，不对 → 按字典序降序？`"30"` 排在 `"3"` 前，得到的也是 `"303"`，不对 → 问题在于前缀关系：`3` 和 `30` 谁在前取决于后面接什么，只能直接比两种拼法 → 交换论证（exchange argument）：最优排列里任何相邻的两个数，若 `b + a > a + b` 就交换一定更大，所以最优排列里每个相邻对都满足 `a + b >= b + a`；而这个比较是可传递的（它等价于比较无限循环小数 `0.aaa…` 与 `0.bbb…`），所以排序就能得到全局最优。

```python
from functools import cmp_to_key

def largest_number(nums: list[int]) -> str:
    def compare(a: str, b: str) -> int:
        return (b + a > a + b) - (b + a < a + b)     # a+b 更大时 a 排前面，返回负数

    strs = sorted(map(str, nums), key=cmp_to_key(compare))
    return "0" if strs[0] == "0" else "".join(strs)  # 最大的是 0，说明全是 0
```

运行：`[10,2]` → `"210"`，`[3,30,34,5,9]` → `"9534330"`，`[1]` → `"1"`，`[0,0]` → `"0"`，`[3,30]` → `"330"`，`[121,12]` → `"12121"`。

**复杂度。** 时间 `O(n log n · L)`，`L` 是数字的位数（至多 `10`），每次比较拼接并比较 `O(L)`；空间 `O(n · L)`。

**易错点。**
- 按字符串字典序降序排：`[3,30]` 得 `"303"`，正确 `"330"`；`[3,30,34,5,9]` 得 `"9534303"`，正确 `"9534330"`。
- 全零不特判：`[0,0]` 拼出 `"00"`，应为 `"0"`。
- 把 `cmp` 写成返回布尔值：`cmp_to_key` 要的是负 / 零 / 正的整数。

**追问。**
- 最小的拼接数：比较方向反过来（`a + b` 更小的排前面），注意前导零的题意。
- 不用比较器的写法：因为每个数至多 `10` 位，`sorted(strs, key=lambda s: s * 10, reverse=True)` 同样正确（把每个串重复到足够长再按字典序比），更快。
- 数字很多很长：比较器每次 `O(L)`，总成本 `O(n log n · L)`，可以按首字符分桶后各桶内排序，但通常不需要。

**同模式。** LC 56 合并区间（按起点排序）、LC 406 根据身高重建队列（两个键排序）、LC 252 / 253 会议室（排序后扫描）、LC 937 重新排列日志文件（自定义键）。
