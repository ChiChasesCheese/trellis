## Q
**LC 561 数组拆分 I**｜Easy · CodeTop 国内累计 1 次 · 最近 2026-04-15（CodeTop）

给长度为 `2n` 的整数数组 `nums`，把它分成 `n` 对 `(a_1, b_1), …, (a_n, b_n)`，使 `min(a_1, b_1) + … + min(a_n, b_n)` 最大，返回这个最大和。`1 <= n <= 10^4`，`nums.length == 2n`，`-10^4 <= nums[i] <= 10^4`。例：`[1,4,3,2]` → `4`（`(1,2), (3,4)`），`[6,2,6,5,1,2]` → `9`（`(1,2), (2,5), (6,6)`）。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 贪心（greedy）：排序后相邻两两配对，答案是排序后所有偶数下标元素之和。每对的较大者被「浪费」，让被浪费的数尽量小，就要让它紧挨着自己的较小者。`O(n log n)`。

**识别。** 「把元素两两配对 + 最大化（或最小化）某个按对计算的和」→ 先排序，再用交换论证（exchange argument）找配对规则。`2n` 到 `2·10^4`，枚举所有配对方式是 `(2n - 1)!!`，不可能。

**推导。** 暴力：枚举所有配对，`(2n - 1)!!` 种 → 观察：每对贡献较小者，较大者被浪费；全局最小的元素 `x_1` 无论和谁配都只贡献它自己，配给谁就浪费谁 → 配给第二小的 `x_2` 浪费最少（交换论证可证明不会更差）→ 去掉这两个后对剩下的数重复同样的论证 → 排序后 `(x_1, x_2), (x_3, x_4), …`，答案是 `x_1 + x_3 + …`。

```python
def array_pair_sum(nums: list[int]) -> int:
    nums = sorted(nums)                 # 不改调用方的列表
    return sum(nums[::2])               # 相邻两两配对，每对的较小者落在偶数下标
```

运行：`[1,4,3,2]` → `4`，`[6,2,6,5,1,2]` → `9`，`[-1,-2]` → `-2`，`[-10000,10000,3,3]` → `-9997`。

**复杂度。** 时间 `O(n log n)`，来自排序；空间 `O(n)`，`sorted` 返回新列表（改用 `nums.sort()` 原地排序则只需 Timsort 的辅助空间）。

**易错点。**
- 「最大配最小」的直觉配对：`[1,4,3,2]` 配成 `(1,4), (2,3)` 只得 `3`，正确是 `4`；`[6,2,6,5,1,2]` 得 `5`，正确是 `9`。
- 切片写成 `nums[1::2]`：取到的是每对的较大者，`[1,4,3,2]` 得 `6`，超过了真实最大值 `4`，是不合法的答案。

**追问。**
- `O(n)`：值域只有 `2·10^4 + 1` 种，计数排序（counting sort）后按顺序扫，交替取值。
- 改成每组 `k` 个、最大化各组最小值之和：同样排序，答案 `sum(nums[::k])`。
- 改成最小化各对**较大者**之和：排序后相邻配对仍最优，答案 `sum(nums[1::2])`。

**同模式。** LC 881 救生艇、LC 1877 数组中最大数对和的最小值、LC 455 分发饼干、LC 2144 打折购买糖果的最小开销。
