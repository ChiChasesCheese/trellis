## Q
**LC 321 拼接最大数**｜Hard · CodeTop 国内累计 6 次 · 最近 2026-05-21（国内 CodeTop）

两个整数数组 `nums1`、`nums2`，长度分别为 `m`、`n`，每个元素是一个数字。从两个数组中一共取 `k` 个数字，拼成一个长度为 `k` 的**最大的数**，**同一数组中取出的数字必须保持原来的相对顺序**，返回这个数的各位组成的数组。`1 <= m, n <= 500`，`0 <= nums1[i], nums2[i] <= 9`，`1 <= k <= m + n`，两个数组都没有前导 0。例：`nums1 = [3,4,6,5]`, `nums2 = [9,1,2,5,8,3]`, `k = 5` → `[9,8,6,5,3]`；`nums1 = [6,7]`, `nums2 = [6,0,4]`, `k = 5` → `[6,7,6,0,4]`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 枚举从 `nums1` 取 `i` 个、从 `nums2` 取 `k - i` 个；每边用单调栈挑出长度固定的最大子序列，再像归并一样合并（每步比较两边**剩余后缀**的字典序），所有 `i` 的结果取最大。

**识别。** 「保持相对顺序 + 挑出若干位使数最大」是单调栈挑子序列（LC 402 移掉 K 位数字的反向）的信号；「两个数组」提示把问题拆成「每边各取多少」加「两段怎么合并」；合并时首位相同要往后看，这是「比较后缀」的信号（LC 1754）。`k <= 1000`，枚举 `i` 再做线性的挑选和合并完全可行。

**推导。** 暴力枚举两边各取哪些位置再交错合并，组合数是指数级。拆解：固定 `i` 后，`nums1` 的贡献最好是「长度 `i` 的最大子序列」，因为合并结果对每一边的子序列是单调的，一边换成字典序更大的同长子序列，合并结果不会变小。挑最大子序列用单调栈：遇到更大的数字就弹掉栈顶较小的数字，前提是还能丢（总共只能丢 `len - t` 个）。合并时两边首位不同取大的；相同时要比较整个剩余后缀，取后缀更大的一边。最后对所有 `i` 取最大。

```python
def max_number(nums1: list[int], nums2: list[int], k: int) -> list[int]:
    def pick(nums: list[int], t: int) -> list[int]:
        """按原顺序从 nums 里挑 t 个数字，组成最大的子序列（单调栈）。"""
        drop = len(nums) - t                 # 最多还能丢掉几个
        stack: list[int] = []
        for x in nums:
            while drop and stack and stack[-1] < x:   # 栈顶比 x 小又还能丢：丢掉它
                stack.pop()
                drop -= 1
            stack.append(x)
        return stack[:t]                     # 没丢够的部分从尾部截掉

    def merge(a: list[int], b: list[int]) -> list[int]:
        """把两个子序列合并成最大的序列：每步取「剩余后缀」字典序更大的那一边的首位。"""
        out: list[int] = []
        i = j = 0
        while i < len(a) or j < len(b):
            if a[i:] >= b[j:]:               # 比较整个后缀，首位相同时才选得对
                out.append(a[i])
                i += 1
            else:
                out.append(b[j])
                j += 1
        return out

    m, n = len(nums1), len(nums2)
    return max(                              # 等长列表按字典序比较，就是按数值比较
        merge(pick(nums1, i), pick(nums2, k - i))
        for i in range(max(0, k - n), min(k, m) + 1)
    )
```

运行：`[3,4,6,5]`, `[9,1,2,5,8,3]`, `k = 5` → `[9,8,6,5,3]`；`[6,7]`, `[6,0,4]`, `5` → `[6,7,6,0,4]`；`[3,9]`, `[8,9]`, `3` → `[9,8,9]`；`[2,5]`, `[2,6]`, `4` → `[2,6,2,5]`；`[6]`, `[6,7]`, `3` → `[6,7,6]`。

**复杂度。** 外层枚举 `i` 至多 `k + 1` 种；`pick` 是 `O(m + n)`；`merge` 走 `k` 步，每步后缀比较最坏 `O(k)`。总时间最坏 `O(k · (m + n + k^2))`，后缀比较通常在第一个不同的位置就结束，`m = n = 500` 时远低于这个上界。空间 `O(m + n)`。

**易错点。**
- 合并时只比首位、相等时随便取一边：`[2,5]` 和 `[2,6]` 合并会得到 `[2,5,2,6]`（正确 `[2,6,2,5]`）。
- 单调栈不限制丢弃次数：`pick([1,2,3], 2)` 会把 1、2 都弹掉只剩 `[3]`，长度不够（正确 `[2,3]`）。
- `i` 的范围是 `max(0, k - n)` 到 `min(k, m)`：任何一边都不能取得比自己长度多。

**追问。**
- 单个数组、求最小的数：LC 402 移掉 K 位数字，单调栈改成弹掉更大的，再去前导 0。
- 后缀比较太慢：先给两个数组建后缀数组（suffix array）或比较时缓存，可降到每步 `O(1)`；实际面试讲清思路即可。
- 合并两个**字符串**使字典序最大：LC 1754，规则完全一样，`a[i:] >= b[j:]` 直接比较字符串切片。

**同模式。** LC 402 移掉 K 位数字、LC 316 去除重复字母、LC 1673 找出最具竞争力的子序列、LC 1754 构造字典序最大的合并串。
