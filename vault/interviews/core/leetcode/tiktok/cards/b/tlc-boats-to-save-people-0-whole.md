## Q
**LC 881 救生艇**｜Medium · CodeTop 国内累计 2 次 · 最近 2026-03-27（国内 CodeTop）

数组 `people` 中 `people[i]` 是第 `i` 个人的体重；船的数量不限，每艘船最大载重 `limit`，每艘船**最多同时载两人**，且这两人的体重之和不超过 `limit`。返回载所有人所需的最少船数。`1 <= people.length <= 5 * 10^4`，`1 <= people[i] <= limit <= 3 * 10^4`。例：`people = [3,2,2,1], limit = 3` → `3`（`(1,2)`、`(2)`、`(3)`）；`people = [3,5,3,4], limit = 5` → `4`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 排序后用对撞双指针：最重的人必须占一艘船；若最轻的人能和他同船就一起走，否则最重的人独自一船。每轮船数加一、最重的人下船。`O(n log n)`。

**识别。** 「每艘船最多两人」+「最少船数」是**排序 + 配对贪心**的信号：「至多两人」让问题从装箱（NP 难）退化成可以贪心的配对。`n = 5 * 10^4` 排序足够；体重值域只有 `3 * 10^4`，也可用计数排序到 `O(n + limit)`。

**推导。** 暴力：枚举所有配对方案（状态压缩 DP 也只能处理很小的 `n`）。关键洞见是交换论证（exchange argument）：最重的人 `H` 无论如何都要占一艘船。若最轻的人 `L` 与 `H` 同船都超重（`L + H > limit`），那么任何人都比 `L` 重，更放不进，`H` 只能独占；若 `L + H <= limit`，让 `L` 和 `H` 同船不会更差——`L` 最容易和别人搭，换成别人搭档 `H` 只会让剩下的人更难配。因此每轮看两端：能配就配，不能配最重的单走，指针向内收缩，`O(n)`；排序是瓶颈 `O(n log n)`。

```python
def num_rescue_boats(people: list[int], limit: int) -> int:
    people = sorted(people)              # 排序后最轻的在左端，最重的在右端
    lo, hi = 0, len(people) - 1
    boats = 0
    while lo <= hi:                      # lo == hi 时只剩一个人，也要一艘船
        if people[lo] + people[hi] <= limit:
            lo += 1                      # 最轻的人和最重的人同船
        hi -= 1                          # 最重的人一定上船
        boats += 1
    return boats
```

运行：`[1,2], 3` → `1`，`[3,2,2,1], 3` → `3`，`[3,5,3,4], 5` → `4`，`[5], 5` → `1`，`[1,1,3,3], 4` → `2`。

**复杂度。** 时间 `O(n log n)`：排序是瓶颈，双指针一趟 `O(n)`；空间 `O(n)`（`sorted` 的副本；用 `list.sort()` 原地排序可降到 `O(1)`，但会改动输入）。

**易错点。**
- 没排序就双指针：`[3,2,2,1]`、`limit = 3` 得到 `4`（正确 `3`）。
- 循环条件写成 `lo < hi`：只剩一个人（`lo == hi`）时漏掉这艘船，`[5]`、`limit = 5` 得到 `0`（正确 `1`）。
- 把最轻的两个人配对（从左端取两个）：`[1,1,3,3]`、`limit = 4` 得到 `3`（正确 `2`，应是 `(1,3)` 和 `(1,3)`）。

**追问。**
- 体重值域很小（`<= 3 * 10^4`）：用计数数组代替比较排序，`O(n + limit)`。
- 每艘船可载 `k > 2` 人：变成装箱问题（bin packing），NP 难，贪心不再保证最优。
- 要输出具体方案：每轮记下 `(lo, hi)` 或 `(hi,)`。
