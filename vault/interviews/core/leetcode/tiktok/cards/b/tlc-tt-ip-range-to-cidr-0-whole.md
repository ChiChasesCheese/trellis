## Q
**IP 区间转最少 CIDR 列表**｜Medium · TikTok 高频

给定一个 IPv4 区间的起止地址（闭区间，点分十进制字符串），输出恰好覆盖这个区间的 CIDR 块列表，列表要最短，按地址升序。CIDR 块 `a.b.c.d/k` 表示以该地址开头、共 `2^(32-k)` 个连续地址的块，起点必须是块大小的整数倍。格式不对（不是四段、某段超出 `0..255`）或起点大于终点时抛 `ValueError`。例：`"127.0.0.7"` 到 `"127.0.0.16"` → `['127.0.0.7/32', '127.0.0.8/29', '127.0.0.16/32']`；`"0.0.0.0"` 到 `"255.255.255.255"` → `['0.0.0.0/0']`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 把 IP 当 32 位整数。从起点 `lo` 出发，每一步取两个上限的较小者作为块大小：起点能对齐的最大块（`lo & -lo`，即 `lo` 最低位的 `1`）和不超过剩余地址数的最大 `2` 的幂；输出 `lo/前缀长度`，`lo` 前进一个块，直到越过终点。块数最多约 `2 * 32` 个。

**识别。** 「IP、CIDR、区间覆盖」是位运算题：一个 CIDR 块就是「起点对齐到 `2^k` 的倍数、长度为 `2^k`」的区间；「最少块数」像把一个数拆成二进制，每步用尽量大的块。

**推导。** 暴力：每个地址一个 `/32`，块数等于区间长度，最多 `2^32` → 浪费：大量相邻地址本可以合并成一个更短的前缀 → 洞察：块 `[lo, lo + 2^k)` 合法需要两个条件：`lo` 的低 `k` 位全是 `0`（对齐），并且 `lo + 2^k - 1 <= hi`（不越过终点）。第一个条件等价于 `2^k <= lo & -lo`，第二个等价于 `2^k <= hi - lo + 1`。贪心取同时满足的最大 `k`：块越大剩下的区间越短，且更大的块总能被切成更小的合法块，所以不会更差。

```python
def ip_range_to_cidr(start: str, end: str) -> list[str]:
    def to_int(ip: str) -> int:
        parts = ip.split(".")
        if len(parts) != 4:
            raise ValueError(f"bad ip {ip!r}")
        return int.from_bytes(bytes(map(int, parts)))        # 四个字节拼成 32 位整数；超出 0..255 时 bytes() 抛 ValueError

    def to_str(x: int) -> str:
        return ".".join(map(str, x.to_bytes(4)))

    lo, hi = to_int(start), to_int(end)
    if lo > hi:
        raise ValueError("start must not exceed end")
    blocks: list[str] = []
    while lo <= hi:
        align = lo & -lo or 1 << 32                          # 起点最低位 1 的值 = 起点处能对齐的最大块；0.0.0.0 不受限
        fit = 1 << (hi - lo + 1).bit_length() - 1            # 不超过剩余地址数的最大 2 的幂
        size = min(align, fit)
        blocks.append(f"{to_str(lo)}/{33 - size.bit_length()}")   # 块大小 2^k 对应前缀长度 32 - k
        lo += size
    return blocks
```

运行：`127.0.0.7` 到 `127.0.0.16` → `['127.0.0.7/32', '127.0.0.8/29', '127.0.0.16/32']`；`0.0.0.0` 到 `255.255.255.255` → `['0.0.0.0/0']`；`10.0.0.0` 到 `10.0.0.0` → `['10.0.0.0/32']`；`192.168.1.0` 到 `192.168.1.255` → `['192.168.1.0/24']`；`0.0.0.1` 到 `0.0.0.2` → `['0.0.0.1/32', '0.0.0.2/32']`；`"1.2.3"` 到 `"1.2.3.4"` → `ValueError: bad ip '1.2.3'`；`"1.2.3.256"` → `ValueError`；起点大于终点 → `ValueError`。

**复杂度。** 时间 `O(32)` 次循环（每次至少把剩余长度的最高位去掉一个或对齐一位），`O(1)` 空间（不含输出）。

**易错点。**
- 前缀长度写成 `32 - size.bit_length()`：`size = 8` 时 `bit_length() = 4`，得 `28`，正确是 `29`；`2^k` 的 `bit_length` 是 `k + 1`，所以是 `33 - size.bit_length()`。
- `lo = 0` 时 `lo & -lo` 是 `0`，块大小为 `0`，`lo` 不前进，死循环；要用 `or 1 << 32` 表示「对齐不受限制」。
- 只考虑对齐、不考虑剩余长度：`127.0.0.8` 到 `127.0.0.10` 只有 `3` 个地址，却输出一个 `/29`（`8` 个地址），多覆盖了 `.11` 到 `.15`；正确是 `['127.0.0.8/31', '127.0.0.10/32']`。只考虑剩余长度、不考虑对齐则会输出起点没有对齐的非法块，如起点 `7` 的 `/29`。

**追问。**
- 标准库已经有这件事：`ipaddress.summarize_address_range(first, last)` 给出同样的最少块列表；面试里要能手写。
- 只要一个能覆盖区间的最小 CIDR 块（允许多覆盖）：起止地址不同的最高位决定块大小，前缀长度是 `32 - (lo ^ hi).bit_length()`。
- 反方向（把一堆 CIDR 合并成最少）：`ipaddress.collapse_addresses`；IPv6 同理，位数换成 `128`。

**同模式。** LC 751 IP 到 CIDR、LC 468 验证IP地址、LC 93 复原 IP 地址、LC 191 位1的个数、LC 231 2 的幂。
