## Q
**LC 97 交错字符串**｜Medium · CodeTop 国内累计 12 次 · 最近 2026-10-28（国内 CodeTop）

给三个字符串 `s1`、`s2`、`s3`，判断 `s3` 能否由 `s1` 和 `s2` **交错**组成：把 `s1`、`s2` 各自切成若干非空子串（段数相差不超过 `1`），然后交替拼接，各自内部字符的相对顺序不变。等价地说，`s3` 的每个字符依次取自 `s1` 或 `s2` 的下一个未用字符，且两者恰好用完。`0 <= s1.length, s2.length <= 100`，`0 <= s3.length <= 200`，三个字符串都由小写英文字母组成。进阶：只用 `O(s2.length)` 额外空间。例：`s1 = "aabcc", s2 = "dbbca", s3 = "aadbbcbcac"` → `true`；`s3 = "aadbbbaccc"` → `false`；三个都是 `""` → `true`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 二维动态规划（DP）：`dp[i][j]` 表示 `s1` 的前 `i` 个字符与 `s2` 的前 `j` 个字符能否交错成 `s3` 的前 `i + j` 个字符；`s3` 的最后一个字符要么来自 `s1[i-1]`（需要 `dp[i-1][j]` 为真），要么来自 `s2[j-1]`（需要 `dp[i][j-1]` 为真）；`dp[0][0] = True`，答案是 `dp[m][n]`。`O(mn)` 时间和空间。

**识别。** 「两个序列保持各自顺序合并出第三个序列，问是否可能」是双序列 DP 的信号（和 LCS、编辑距离同族）。关键观察是 `s3` 已经给定，所以走到 `s1` 的第 `i` 个、`s2` 的第 `j` 个字符时，`s3` 的位置必是 `i + j`，状态只需要 `(i, j)` 两维。先比长度：`len(s1) + len(s2) != len(s3)` 直接 `false`。数据规模 `100 * 100`，`O(mn)` 毫无压力。

**推导。** 暴力：每一步从 `s1` 或 `s2` 取下一个字符，两条分支，最坏 `2^(m+n)`。浪费：同样的 `(i, j)` 会被不同取法反复到达。贪心也不行：能从 `s1` 取就取，会在 `s1 = "aa"`、`s2 = "ab"`、`s3 = "aaba"` 上误判（见易错点）。所以用 DP 记录每个 `(i, j)`，`O(mn)`。转移：交错出 `s3[:i + j]` 的最后一个字符 `s3[i + j - 1]`，只可能来自 `s1[i - 1]` 或 `s2[j - 1]`，两种情况互斥又完备，取「或」。边界：`dp[0][0] = True`；第 0 行只能全取自 `s2`，第 0 列只能全取自 `s1`，这两条在上面的转移里自动成立（`i = 0` 时没有「来自 `s1`」这一支，`j = 0` 时没有「来自 `s2`」这一支）。

```python
def is_interleave(s1: str, s2: str, s3: str) -> bool:
    m, n = len(s1), len(s2)
    if m + n != len(s3):                    # 长度不等一票否决
        return False
    # dp[i][j]：s1[:i] 与 s2[:j] 能否交错成 s3[:i + j]
    dp = [[False] * (n + 1) for _ in range(m + 1)]
    dp[0][0] = True                         # 都不取，交错出空串
    for i in range(m + 1):
        for j in range(n + 1):
            if i > 0 and dp[i - 1][j] and s1[i - 1] == s3[i + j - 1]:
                dp[i][j] = True             # s3 的最后一个字符取自 s1
            if j > 0 and dp[i][j - 1] and s2[j - 1] == s3[i + j - 1]:
                dp[i][j] = True             # 或取自 s2
    return dp[m][n]
```

运行：示例 1 → `True`，示例 2 → `False`，`("", "", "")` → `True`，`("", "", "a")` → `False`，`("a", "", "a")` → `True`，`("aa", "ab", "aaba")` → `True`。

**复杂度。** 时间 `O(mn)`；空间 `O(mn)`：`(m + 1) × (n + 1)` 的布尔表。

**易错点。**
- 贪心错：`s1 = "aa"`、`s2 = "ab"`、`s3 = "aaba"`，「能取 `s1` 就取」会在第三个字符 `b` 处卡住，输出 `False`；正确答案 `True`（`a` 取自 `s1`，`a` 取自 `s2`，`b` 取自 `s2`，`a` 取自 `s1`）。
- 不先比长度：`("a", "b", "abc")` 会被误判为 `True`，因为 DP 只检查了前两个字符；长度不等时更可能直接越界。
- 忘了 `dp[0][0] = True`：所有格子都推不出来，`("a", "", "a")` 得到 `False`，正确是 `True`；`("", "", "")` 也得到 `False`，正确是 `True`。
- `s3` 的下标写成 `i + j`：第 `i + j` 个字符是 `s3[i + j - 1]`，写成 `s3[i + j]` 会错位一格，`("a", "", "a")` 直接抛 `IndexError`。

**追问。**
- 返回一种交错方案：完整的二维表就是回溯的依据，从 `(m, n)` 往回看是 `s1` 还是 `s2` 贡献了 `s3[i+j-1]`。
- 进阶：只用 `O(len(s2))` 额外空间：空间可以压到 O(n)，见 Python 工具箱「DP 降维」。
- 自顶向下：`go(i, j)` 加 `@cache`，递归深度 `m + n <= 200`，不会超限。

**同模式。** LC 72 编辑距离、LC 1143 最长公共子序列、LC 115 不同的子序列、LC 44 通配符匹配、LC 10 正则表达式匹配。
