## Q
**LC 698 划分为k个相等的子集**｜Medium · LC TikTok 全时段热度 26/100 · CodeTop 国内累计 6 次 · 最近 2026-10-07（国内 CodeTop）

给整数数组 `nums` 和正整数 `k`，判断能否把数组分成 `k` 个**非空**子集，使它们的元素和都相等（每个元素恰属于一个子集）。

约束：`1 <= k <= len(nums) <= 16`，`0 < nums[i] < 10000`，每个元素的出现次数在 `[1, 4]` 范围内。

例：`nums = [4,3,2,3,5,2,1], k = 4` → `true`（`(5)`、`(1,4)`、`(2,3)`、`(2,3)`，和都是 `5`）；`nums = [1,2,3,4], k = 3` → `false`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 先算出每桶的目标和 `target = sum / k`（不能整除直接 `false`），再用**状态压缩 DP**：`dp[mask]` 表示已经用掉 `mask` 里的数、当前桶装了多少（装满就清零开新桶），按升序尝试放入下一个数；最终全选状态可达则为真。`O(n·2^n)`。

**识别。** 「把一组数分成若干份，每份满足某个和」+「`n ≤ 16`」是**状态压缩**的强信号：`2^16 = 65536` 个子集状态可以全枚举；要先做可行性剪枝（总和能否整除 `k`、最大值是否超过 `target`）。它和 LC 416 分割等和子集一脉相承，只是份数从 2 变成 `k`。`n ≤ 16` 同样允许带剪枝的回溯，但复杂度分析更玄。

**推导。** 暴力：把每个数分配给 `k` 个桶之一，`k^n`（`16` 个数 `16` 个桶不可行）。浪费 1：桶是无标号的，换桶顺序属于重复。浪费 2：同样的「已用数集合 + 当前桶装了多少」会被不同的放法重复到达。洞察：状态只需要「用掉了哪些数」`mask`——因为已用数之和固定，当前桶装了多少就是 `sum(mask) % target`，一次只填一个桶，前面的桶都已装满。所以 `dp[mask]` 只存「当前桶已装多少」，不可达为 `-1`。转移：从可达的 `mask` 出发，再放入一个不在 `mask` 里的数 `x`，只要当前桶装得下（`dp[mask] + x ≤ target`）。数组升序排序后，装不下就可以 `break`。

```python
def can_partition_k_subsets(nums: list[int], k: int) -> bool:
    total = sum(nums)
    if total % k:
        return False
    target = total // k
    nums = sorted(nums)                   # 升序：放不下当前数，更大的也放不下
    if nums[-1] > target:
        return False
    n = len(nums)
    # dp[mask]：用掉 mask 里的数、凑满若干桶后，当前桶已装的和；-1 表示 mask 不可达
    dp = [-1] * (1 << n)
    dp[0] = 0
    for mask in range(1 << n):
        if dp[mask] < 0:
            continue
        for i, x in enumerate(nums):
            if dp[mask] + x > target:
                break                     # 当前桶装不下 x，也装不下之后更大的数
            if mask >> i & 1:
                continue
            nxt = mask | 1 << i
            if dp[nxt] < 0:
                dp[nxt] = (dp[mask] + x) % target   # 装满一桶就清零，开新桶
    return dp[-1] == 0
```

运行：`nums=[4,3,2,3,5,2,1], k=4` → `True`，`nums=[1,2,3,4], k=3` → `False`，`nums=[2,2,2,2,3,3], k=2` → `True`，`nums=[5], k=1` → `True`，`16 个 1, k=16` → `True`，`nums=[10,10,10,7,7,7,7,7,7,6,6,6]（总和 90 不能被 4 整除）, k=4` → `False`。

**复杂度。** 时间 `O(n·2^n)`：`2^n` 个状态，每个状态枚举 `n` 个数（升序遍历，装不下就 `break`，实际更少）；`n = 16` 时约 `10^6` 次。空间 `O(2^n)`。

**易错点。**
- 不检查 `sum % k`：`nums=[1,1,1,1,1,1]`, `k=4`，总和 `6` 不能被 `4` 整除，答案是 `false`；去掉整除检查后 `target = 6 // 4 = 1`，DP 把 6 个 `1` 当成 6 个满桶，全集余数为 `0`，错返回 `true`。
- 用 `0` 表示不可达：`0` 是合法状态（「刚装满一桶 / 空桶」），必须用 `-1` 区分「不可达」。把 `dp[mask] == 0` 当作不可达，会把所有刚好装满桶的状态当作死路，对 `nums=[4,3,2,3,5,2,1]`, `k=4` 这类需要多次开新桶的输入给出 `false`。
- 大数优先的贪心「一桶一桶装」：`nums=[2,2,2,2,3,3]`, `k=2`，`target = 7`，大数优先先装 `3+3=6`，剩下的 `2` 放不进，判 `false`；实际 `{3,2,2}`、`{3,2,2}` 可行，答案是 `true`。
- 忘了 `max(nums) > target` 的早退出：不影响正确性（DP 里永远放不下它），但会白白枚举 `2^n` 个状态。

**追问。**
- 回溯写法：把数降序排序，递归给每个桶装数，装满一桶再开下一桶；剪枝：同一层里相同的「桶当前和」只试一次，装不下就跳过；最坏仍指数，但常数小，面试中常见。
- `n` 大到 `30+` 怎么办？子集和类问题是 NP 难，`k` 个桶均分需要近似算法 / 搜索加剪枝；说清楚 `n ≤ 16` 是在给状态压缩让路。
- 要输出具体的划分：多存一个 `parent[mask]`（最后加入的数），可达后从全集往回走，每遇到桶清零处断开成一组。

**同模式。** LC 416 分割等和子集、LC 473 火柴拼正方形（`k = 4`）、LC 1723 完成所有工作的最短时间、LC 2305 公平分发饼干、LC 1986 完成任务的最少工作时间段。
