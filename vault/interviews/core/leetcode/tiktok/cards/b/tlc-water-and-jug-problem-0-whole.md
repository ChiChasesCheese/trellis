## Q
**LC 365 水壶问题**｜Medium · TikTok 高频

有两个容量分别为 `x` 升和 `y` 升的水壶，水源无限。判断能否用这两个壶**恰好**得到 `target` 升水（两个壶里的水加起来是 `target` 即可）。允许的操作：装满任一水壶；清空任一水壶；把一个壶的水倒进另一个，直到接水的壶满或倒水的壶空。`1 <= x, y, target <= 10^3`。例：`x = 3, y = 5, target = 4` → `true`；`x = 2, y = 6, target = 5` → `false`；`x = 1, y = 2, target = 3` → `true`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 能量出的水量恰好是 `gcd(x, y)` 的所有倍数，且不超过 `x + y`：`target <= x + y and target % gcd(x, y) == 0`。`O(log min(x, y))`。

**识别。** 「用固定容量的容器倒来倒去，能不能凑出某个数」是裴蜀定理（Bézout's identity）的经典场景：每次操作让总水量变化 `±x`、`±y` 或不变，所以总水量永远是 `a·x + b·y`（`a, b` 为整数）。状态数很少（可达状态约 `2(x + y)` 个），也可以直接搜索，但数学结论一行搞定。

**推导。** 暴力：把状态 `(a, b)`（两个壶当前的水量）当节点，6 种操作当边，BFS / DFS 搜到总量或某个壶等于 `target`，可达状态约 `2(x + y)` 个，足够快但要写 6 种操作，容易出错 → 观察哪些总量可达：每次操作总量只会加减 `x` 或 `y`（倒水不改变总量，倒空 / 装满改变 `x` 或 `y` 的整数倍）→ 总量是 `a·x + b·y`，由裴蜀定理，所有可能的 `a·x + b·y` 恰好是 `gcd(x, y)` 的倍数 → 反过来，`gcd` 倍数且 `<= x + y` 的量都能凑出来（反复「装满 `x` 壶 → 倒进 `y` 壶 → `y` 壶满就清空」，总量会遍历所有这样的倍数）→ 得到结论。

```python
from math import gcd

def can_measure_water(x: int, y: int, target: int) -> bool:
    return target <= x + y and target % gcd(x, y) == 0
```

运行：`(3, 5, 4)` → `True`，`(2, 6, 5)` → `False`，`(1, 2, 3)` → `True`，`(1, 2, 4)` → `False`，`(6, 9, 3)` → `True`，`(4, 6, 8)` → `True`，`(1000, 999, 1000)` → `True`，`(1000, 1000, 1)` → `False`。

**复杂度。** 时间 `O(log min(x, y))`（欧几里得算法）；空间 `O(1)`。

**易错点。**
- 漏掉 `target <= x + y`：两个壶装不下。`x = 1, y = 2, target = 4` 会错答 `True`（正确 `False`）。
- 只判断 `target` 能否被 `x` 或 `y` 整除，或等于 `x`、`y`、`x + y`、`|x − y|` 之一：`(7, 11, 3)` 的 `3` 不属于其中任何一种，却是 `True`。
- 在 `x`、`y` 可能为 `0` 的变体里直接 `% gcd(x, y)` 会除零；这里 `x, y >= 1`，不需要特判。

**追问。**
- 不记得数学结论：BFS 状态搜索（`(a, b)` 为节点），可达状态约 `2(x + y)` 个，用集合去重。
- 要求输出具体倒水步骤：BFS 时记录父状态与操作。
- 三个水壶：总量仍是 `gcd(x, y, z)` 的倍数，但「恰好某个壶里」的要求变复杂，要搜索。

**同模式。** LC 1250 检查「好数组」（裴蜀定理）、LC 1071 字符串的最大公因子、LC 780 到达终点、LC 2413 最小偶倍数。
