## Q
**LC 772 基本计算器 III**｜Hard · TikTok 高频

实现一个基本的计算器来计算简单的表达式字符串。表达式只包含非负整数，算符 `+`、`-`、`*`、`/`，左括号 `(` 和右括号 `)`。整数除法需要**向下截断**（截去小数部分，如 `-3 / 2` 得 `-1`）。你可以假定给定的表达式总是有效的，所有中间结果的范围均在 `[-2^31, 2^31 - 1]`。不能使用任何把字符串当表达式求值的内置函数，比如 `eval()`。

约束：`1 <= s <= 10^4`（表达式字符串长度），`s` 由整数、`'+'`、`'-'`、`'*'`、`'/'`、`'('`、`')'` 组成，`s` 是有效的表达式。

例：`s = "1+1"` → `2`；`s = "6-4/2"` → `4`；`s = "2*(5+5*2)/3+(6/2+8)"` → `21`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 把整条表达式拆成「加法项」之和：用一个列表存当前层的项，`+` / `-` 只决定下一项的符号，`*` / `/` 立刻与上一项结合；遇到 `(` 就把外层的「项列表和待用运算符」压栈、开一层新的，遇到 `)` 就把这一层求和，得到的值当作一个数交还给外层。一遍扫描，`O(n)`。

**识别。** 「加减乘除 + 括号」的表达式求值，是计算器系列的终点（LC 224 只有 `+ - ()`，LC 227 只有 `+ - * /`，此处合并）：**运算符优先级 + 嵌套**。优先级用「项列表」解决（乘除当场结合、加减延后求和），嵌套用**栈**解决（括号 = 保存现场的函数调用）。长度到 `10^4`，括号可嵌套几千层 → 递归会撞上 Python 的递归上限，要用显式栈。

**推导。** 先化简：只有 `+ - * /` 时，LC 227 的做法是把表达式看成若干「项」之和，`*` `/` 让当前项继续变化，`+` `-` 才开启新项（`-` 记成负项）。含括号时，括号内的子表达式是一个独立的、可以递归定义的值，求完之后在外层就像一个普通整数。递归写法最直观：遇到 `(` 递归解析到匹配的 `)`，但嵌套深度可达 `5000`，会 `RecursionError`。所以用显式栈模拟：遇到 `(` 把「外层已有的项列表、括号前的运算符」存进栈，开一个新项列表；遇到 `)` 求和，弹出外层，把值当作 `num` 交给原来的运算符。除法在 Python 中要自己写成向零截断（`//` 向下取整，负数结果不同）。

```python
def trunc_div(a: int, b: int) -> int:
    q = abs(a) // abs(b)               # 先按绝对值整除，再补符号：向零截断
    return q if (a < 0) == (b < 0) else -q


def calculate(s: str) -> int:
    saved: list[tuple[list[int], str]] = []   # 进入括号前的 (外层各项, 括号前的运算符)
    terms: list[int] = []              # 当前层的加法项：加减号只负责决定项的符号
    op, num = "+", 0                   # num 前面等待结合的运算符；正在读的数

    def apply() -> None:               # 把 num 按 op 并入当前层
        if op == "+":
            terms.append(num)
        elif op == "-":
            terms.append(-num)
        elif op == "*":
            terms[-1] *= num           # 乘除立刻与上一项结合
        else:
            terms[-1] = trunc_div(terms[-1], num)

    for ch in s + "+":                 # 末尾补一个 "+"，把最后一个数冲刷进去
        if "0" <= ch <= "9":
            num = num * 10 + int(ch)
        elif ch == "(":
            saved.append((terms, op))  # 暂存外层，开一层新的
            terms, op, num = [], "+", 0
        else:                          # + - * / )
            apply()
            if ch == ")":
                value = sum(terms)     # 括号内算完，它就是外层的一个“数”
                terms, op = saved.pop()
                num = value
            else:
                op, num = ch, 0
    return sum(terms)
```

运行：`s="1+1"` → `2`，`s="6-4/2"` → `4`，`s="2*(5+5*2)/3+(6/2+8)"` → `21`，`s="(0-3)/2"（负数商向零截断）` → `-1`，`s="((2+3))*4"` → `20`，`s="7"` → `7`，`嵌套 4999 层括号 + 数字 1` → `1`。

**复杂度。** 时间 `O(n)`：每个字符处理常数次，每项最多被并入一次、`sum` 每层只算一次；空间 `O(n)`：括号嵌套深度和各层的项列表，最坏 `n/2` 层。

**易错点。**
- 除法直接用 `//`：`(0-3)/2` 应得 `-1`（截去小数部分），`//` 得 `-2`。先对绝对值整除再补符号，才是向零截断。
- 忘了冲刷最后一个数：循环结束没有后续字符触发 `apply`。`1+1` 得 `1`，`6-4/2` 得 `2`（应为 `4`）。简单的办法是在 `s` 末尾补一个 `"+"`。
- 括号结果丢了括号前的运算符：`6-(1+2)` 应得 `3`，把括号结果当成「加」项会得 `9`。必须把括号前的运算符一并存进栈，弹出后恢复。
- 从左到右不分优先级算：`6-4/2` 从左到右是 `(6-4)/2 = 1`，正确是 `6-(4/2) = 4`。乘除要立刻与上一项结合，加减才延后。
- 递归解析括号：深度 `4999` 的 `((…1…))` 会 `RecursionError`（见「另一种解法」）。

**追问。**
- 加一元负号 / 空格（LC 224）：遇到前面是 `(` 或表达式开头的 `-` 时当作 `0-`，或把 `num` 的符号提前；空格直接跳过。
- 加幂运算 `^`（右结合）或函数调用：升级成递归下降或调度场算法（shunting-yard），为每个运算符定义优先级和结合性。
- 表达式含变量 / 小数 / 多位数的词法：先 `re.findall` 切成 token 再解析，把词法和语法分开；用 `Fraction` 避免浮点误差。

**同模式。** LC 224 基本计算器、LC 227 基本计算器 II、LC 150 逆波兰表达式求值、LC 394 字符串解码（同样的括号栈结构）、LC 726 原子的数量。
