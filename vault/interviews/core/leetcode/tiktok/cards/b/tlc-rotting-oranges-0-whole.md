## Q
**LC 994 腐烂的橘子**｜Medium · LC TikTok 全时段热度 50/100 · CodeTop 国内累计 2 次 · 最近 2022-05-03（国内 CodeTop）

在 `m x n` 的网格 `grid` 中，每个格子是 `0`（空）、`1`（新鲜橘子）或 `2`（腐烂橘子）。每分钟，腐烂橘子上下左右四个方向相邻的新鲜橘子都会腐烂。返回直到没有新鲜橘子为止所必须经过的最小分钟数；如果不可能，返回 `-1`。`m == grid.length`，`n == grid[i].length`，`1 <= m, n <= 10`，`grid[i][j]` 仅为 `0`、`1` 或 `2`。例：`[[2,1,1],[1,1,0],[0,1,1]]` → `4`；`[[2,1,1],[0,1,1],[1,0,1]]` → `-1`（左下角的橘子永远不会腐烂）；`[[0,2]]` → `0`（本来就没有新鲜橘子）。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 多源广度优先搜索（multi-source BFS）：把所有初始腐烂橘子一起放进队列作为第 `0` 层，每处理完一层就是过了一分钟，被感染的新鲜橘子进入下一层；最后如果还有新鲜橘子就返回 `-1`，否则返回层数。`O(mn)`。

**识别。** 「同时从多个源头向外扩散，问扩散完成要多久」是多源 BFS 的标志；“每分钟”对应 BFS 的“每一层”。不是 DFS：DFS 不能保证先到达的是最短时间。网格只有 `10 x 10`，`O(mn)` 毫无压力，重点在写对层数和边界。

**推导。** 暴力：每分钟扫一遍整个网格，把与腐烂橘子相邻的新鲜橘子标记为“下一分钟腐烂”，直到没有变化，每分钟 `O(mn)`，最多 `O(mn)` 分钟，合计 `O((mn)^2)`。浪费：每分钟都重新扫描所有格子，其实只有“刚腐烂的”橘子才会感染别人。洞察：把刚腐烂的橘子放进队列，只从它们出发感染邻居；按层处理就得到分钟数。再维护一个“新鲜橘子计数”，感染一个减一个，最后用它判断是否有橘子永远不会腐烂，同时提前终止，避免多算一分钟。

```python
from collections import deque


def oranges_rotting(grid: list[list[int]]) -> int:
    m, n = len(grid), len(grid[0])
    queue = deque((i, j) for i, row in enumerate(grid) for j, v in enumerate(row) if v == 2)
    fresh = sum(row.count(1) for row in grid)
    minutes = 0
    while queue and fresh:                     # 没有新鲜橘子就立刻停，不多算一分钟
        minutes += 1
        for _ in range(len(queue)):            # 恰好处理完当前这一层 = 过去一分钟
            i, j = queue.popleft()
            for ni, nj in ((i + 1, j), (i - 1, j), (i, j + 1), (i, j - 1)):
                if 0 <= ni < m and 0 <= nj < n and grid[ni][nj] == 1:
                    grid[ni][nj] = 2           # 入队时就标记，避免重复入队
                    fresh -= 1
                    queue.append((ni, nj))
    return -1 if fresh else minutes
```

运行：`[[2,1,1],[1,1,0],[0,1,1]]` → `4`，`[[2,1,1],[0,1,1],[1,0,1]]` → `-1`，`[[0,2]]` → `0`，`[[0]]` → `0`，`[[1]]` → `-1`，`[[2]]` → `0`，`[[1,2]]` → `1`。

**复杂度。** 时间 `O(mn)`：每个格子最多入队一次；空间 `O(mn)`：队列。

**易错点。**
- 循环条件只写 `while queue`：最后一层处理完之后队列里还有刚腐烂的橘子，会再多数一分钟。`[[0,2]]` 返回 `1`，正确是 `0`；示例 1 返回 `5`，正确是 `4`。条件要加上 `and fresh`。
- 不按层处理，直接每弹一个计一分钟：分钟数变成被感染的橘子个数，不是层数。
- 忘了检查不可达的新鲜橘子：BFS 结束后 `fresh > 0` 必须返回 `-1`，示例 2 就是这种情况。

**追问。**
- 不改输入网格：用一个字典或二维数组 `time[i][j]` 记录每个格子腐烂的时刻，兼作 `visited`；答案是所有时刻的最大值。
- 每分钟只有部分橘子会腐烂（有概率），或有的格子是墙：BFS 框架不变，换成优先队列 / 加权最短路。
- 为什么不用 DFS：DFS 先沿一个方向深入，会先给橘子打上一个较晚的时刻，需要反复更新，复杂度变差；BFS 的层序天然保证先到的就是最早的。
