## Q
**LC 977 有序数组的平方**｜Easy · CodeTop 国内累计 11 次 · 最近 2026-01-18（国内 CodeTop）

给一个按**非递减**顺序排序的整数数组 `nums`，返回每个数字平方后组成的新数组，也要按非递减顺序排序。`1 <= nums.length <= 10^4`，`-10^4 <= nums[i] <= 10^4`。进阶：设计 `O(n)` 的算法。例：`[-4,-1,0,3,10]` → `[0,1,9,16,100]`；`[-7,-3,2,3,11]` → `[4,9,9,49,121]`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 平方最大的数一定在数组**两端**之一（绝对值最大），所以用对撞双指针，每次比较两端的平方，把较大的填到结果数组的**末尾**，然后向内收缩，从后往前填满。`O(n)`。

**识别。** 「数组已有序」+「做一个保序性被破坏的变换（平方）」→ 想到有序性仍有结构：负数一侧平方后是**递减**，非负一侧是**递增**，整体是「先降后升」的山谷，最大值一定在两端，用对撞双指针（two pointers）从两端向中间收；进阶要求 `O(n)`，直接 `sorted` 是 `O(n log n)`。

**推导。** 暴力：先平方再排序，`O(n log n)`。浪费：输入本来有序，平方后只是「先降后升」，完全没利用已有的有序性。洞察：平方只取决于绝对值，绝对值最大的元素一定在两端，所以结果数组的最后一格只能是 `nums[0]²` 或 `nums[-1]²`。取走较大的一个，剩下的子问题同样的形状。最优：两个指针从两端收缩，结果从后往前填，每个元素恰好处理一次，`O(n)` 时间。

```python
def sorted_squares(nums: list[int]) -> list[int]:
    n = len(nums)
    result = [0] * n
    left, right = 0, n - 1
    for pos in range(n - 1, -1, -1):          # 从结果的最后一格往前填
        l2, r2 = nums[left] ** 2, nums[right] ** 2
        if l2 > r2:                            # 平方最大的一定在两端之一
            result[pos] = l2
            left += 1
        else:
            result[pos] = r2
            right -= 1
    return result
```

运行：`[-4,-1,0,3,10]` → `[0, 1, 9, 16, 100]`，`[-7,-3,2,3,11]` → `[4, 9, 9, 49, 121]`，`[-5]` → `[25]`，`[-3,-2,-1]` → `[1, 4, 9]`，`[1,2,3]` → `[1, 4, 9]`。

**复杂度。** 时间 `O(n)`：每次循环确定结果的一个位置，指针各自只前进不后退；空间 `O(n)`（输出数组，不算额外空间则是 `O(1)`）。

**易错点。**
- 从前往后填：把较大的平方 `append` 到结果开头，结果是降序。示例 1 得 `[100,16,9,1,0]`，要么倒序输出，要么一开始就从后往前填。
- 比较的是**原值**而不是**平方**：`if nums[left] > nums[right]` 会在 `-4 < 3` 时选右边，示例 1 得 `[16,1,0,9,100]`（没排好）。必须比较 `abs` 或平方。
- 两个指针相遇时漏掉最后一个元素：循环按「填满 `n` 个位置」写，不要按 `while left < right`，否则 `n = 1` 时循环一次都不执行，结果停在初始值 `[0]`。

**追问。**
- 输入没有排序：只能先平方再 `sorted`，`O(n log n)`。
- 对有序数组做二次函数 `a*x*x + b*x + c` 再排序（LC 360）：`a >= 0` 时同样从两端取最大填后面，`a < 0` 时取最小填前面。
- 要求惰性输出（生成器）或省内存：从负数与非负数的分界处**向两侧**用 `heapq.merge` 两路归并。

**同模式。** LC 360 有序转化数组、LC 88 合并两个有序数组（也是从后往前填）、LC 167 两数之和 II、LC 15 三数之和、LC 11 盛最多水的容器。
