## Q
**LC 163 缺失的区间**｜Easy · TikTok 高频

给闭区间 `[lower, upper]` 和一个**升序**整数数组 `nums`（元素互不相同，且都落在 `[lower, upper]` 内）。区间内不在 `nums` 里的整数叫「缺失数」。返回**恰好覆盖所有缺失数**的最小有序区间列表（`nums` 的任何元素都不能出现在区间里）。`-10^9 <= lower <= upper <= 10^9`，`0 <= nums.length <= 100`。例：`nums = [0,1,3,50,75]`，`lower = 0`，`upper = 99` → `[[2,2],[4,49],[51,74],[76,99]]`；`nums = [-1]`，`lower = upper = -1` → `[]`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 在 `nums` 前面补哨兵 `lower - 1`、后面补哨兵 `upper + 1`，相邻两个「已知数」`prev`、`x` 的差 `>= 2` 时，中间 `[prev + 1, x - 1]` 就是一段缺失区间；一趟扫描 `O(n)`。

**识别。** 「有序数组 + 找空隙」：缺失数只会出现在相邻已知数之间；`lower`、`upper` 高达 `10^9` 而 `n <= 100`，说明不能去遍历值域，要按元素个数处理。头、尾、空数组三种边界最容易漏，哨兵把它们并进同一条规则。

**推导。** 暴力：用集合标记 `nums`，从 `lower` 扫到 `upper` 找连续的未标记段，代价随值域增长，`10^9` 不可行 → 缺失数只可能夹在两个相邻已知数之间，间隙的两端由差值直接算出，不必逐个数 → 头尾的特殊情形（第一个数大于 `lower`、最后一个数小于 `upper`、`nums` 为空）统一成「`nums` 前补 `lower - 1`，后补 `upper + 1`」，每个间隙都是两个已知数之间 → 每个元素只看一次，`O(n)`。

```python
from itertools import chain


def find_missing_ranges(nums: list[int], lower: int, upper: int) -> list[list[int]]:
    ans: list[list[int]] = []
    prev = lower - 1                           # 哨兵：把 lower 之前的一格当作"已出现"
    for x in chain(nums, (upper + 1,)):        # 末尾追加 upper + 1，统一处理最后一段
        if x - prev >= 2:                      # 相邻已知数之间隔着至少一个数
            ans.append([prev + 1, x - 1])
        prev = x
    return ans
```

运行：`[0,1,3,50,75]`, `0`, `99` → `[[2, 2], [4, 49], [51, 74], [76, 99]]`；`[-1]`, `-1`, `-1` → `[]`；`[]`, `1`, `1` → `[[1, 1]]`；`[]`, `-5`, `5` → `[[-5, 5]]`。

**复杂度。** 时间 `O(n)`，`n = len(nums)`；额外空间 `O(1)`（输出不计）。

**易错点。**
- 漏掉尾哨兵：`[0,1,3,50,75]`, `0`, `99` 会输出 `[[2, 2], [4, 49], [51, 74]]`，少了 `[76, 99]`。
- 判断写成 `x - prev > 2`：`[2,2]` 这种只缺一个数的间隙（`x - prev == 2`）被漏掉。
- 想去遍历 `[lower, upper]`：值域 `10^9`，必超时。

**追问。**
- 输出成字符串 `"2"`、`"4->49"`：`a == b` 写 `str(a)`，否则 `f"{a}->{b}"`。
- `nums` 很大、读不进内存：只用到一个 `prev`，边读边处理，空间仍是 `O(1)`。
- `nums` 可能有重复：差为 `0` 不满足 `>= 2`，自然不产生区间，`prev` 照常更新，代码不用改。

**同模式。** LC 228 汇总区间（取存在的段）、LC 56 合并区间、LC 57 插入区间、LC 352 将数据流变为不相交区间。
