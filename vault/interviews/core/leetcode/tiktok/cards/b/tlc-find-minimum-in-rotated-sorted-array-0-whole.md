## Q
**LC 153 寻找旋转排序数组中的最小值**｜Medium · TikTok 高频

一个元素**互不相同**的升序数组，经过 `1` 到 `n` 次旋转得到 `nums`（旋转一次是把最后一个元素移到最前面，例如 `[0,1,2,4,5,6,7]` 旋转 `4` 次得到 `[4,5,6,7,0,1,2]`，旋转 `n` 次回到原数组）。找出并返回最小元素，必须是 `O(log n)`。`1 <= n <= 5000`，`-5000 <= nums[i] <= 5000`，元素互不相同。例：`[3,4,5,1,2]` → `1`，`[4,5,6,7,0,1,2]` → `0`，`[11,13,15,17]` → `11`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 二分查找「断崖」：拿 `nums[mid]` 和**右端点** `nums[hi]` 比较——`nums[mid] > nums[hi]` 说明断崖（最小值）在 `mid` 右边，否则最小值在 `[lo, mid]` 内；区间缩到一个元素就是答案。`O(log n)`。

**识别。** 「有序数组被旋转」+「要求 `O(log n)`」= 二分，但数组整体不单调，不能直接比目标值。要找的是**单调性的分界点**：旋转后数组分成两段各自递增，左段所有元素都大于右段所有元素；每个下标只要回答「我在左段还是右段」就能二分。

**推导。** 暴力 `min(nums)` `O(n)`，不满足要求 → 想用二分，就需要一个能判断「最小值在 `mid` 左边还是右边」的条件 → 与 `nums[lo]` 比较在数组没旋转（本身有序）时会失效，与 `nums[hi]` 比较则始终有效：`nums[mid] > nums[hi]` 时 `mid` 在左段、断崖在右边；`nums[mid] < nums[hi]` 时 `mid` 在右段（或整段有序），最小值不会在 `mid` 右侧，但 `mid` 本身可能就是最小值 → `hi = mid`（不是 `mid - 1`）。元素互不相同，所以不会出现相等。

```python
def find_min(nums: list[int]) -> int:
    lo, hi = 0, len(nums) - 1
    while lo < hi:                      # 区间收缩到一个元素时，它就是最小值
        mid = (lo + hi) // 2
        if nums[mid] > nums[hi]:        # 断崖在 mid 右边，最小值在 (mid, hi]
            lo = mid + 1
        else:                           # mid 已在右半段，最小值在 [lo, mid]
            hi = mid
    return nums[lo]
```

运行：`[3,4,5,1,2]` → `1`，`[4,5,6,7,0,1,2]` → `0`，`[11,13,15,17]` → `11`，`[1]` → `1`，`[2,1]` → `1`。

**复杂度。** 时间 `O(log n)`；空间 `O(1)`。

**易错点。**
- 和 `nums[lo]` 比较、`nums[mid] >= nums[lo]` 就右移：数组没旋转时一路右移，`[11,13,15,17]` 返回 `17`（正确 `11`）。
- 把 `hi = mid` 写成 `hi = mid - 1`（配合 `lo <= hi`）：会跳过恰好是最小值的 `mid`。`[4,5,1,2,3]` 返回 `4`（正确 `1`）。
- 用 `min(nums)`：对但违反 `O(log n)`。

**追问。**
- 有重复元素（LC 154）：`nums[mid] == nums[hi]` 时无法判断，只能 `hi -= 1`，最坏退化到 `O(n)`。
- 在旋转数组里查目标值（LC 33）：先判断 `mid` 在哪一段，再判断目标是否落在有序的那段里。
- 只问旋转了几次：答案就是最小值的下标 `lo`。

**同模式。** LC 154 寻找旋转排序数组中的最小值 II、LC 33 搜索旋转排序数组、LC 162 寻找峰值、LC 852 山脉数组的峰顶索引。
