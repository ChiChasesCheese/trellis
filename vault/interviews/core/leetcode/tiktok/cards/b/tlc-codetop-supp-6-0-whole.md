## Q
**补充题 6 手撕堆排序**｜Medium · CodeTop 国内累计 19 次 · 最近 2026-03-24（国内 CodeTop）

给整数数组 `nums`，把它按升序排列。要求手写**堆排序**：原地排序，不调用 `sorted`、`list.sort`，也不使用 `heapq`。`1 <= nums.length <= 50000`，`-50000 <= nums[i] <= 50000`。例：`nums = [5,2,3,1]` → `[1,2,3,5]`；`nums = [5,1,1,2,0,0]` → `[0,0,1,1,2,5]`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 先把数组原地建成**大根堆**（从最后一个非叶子节点向前，逐个「下沉」），然后反复把堆顶（当前最大）换到未排序区的末尾、堆大小减一、对新堆顶下沉。建堆 `O(n)`，排序阶段 `O(n log n)`，额外空间 `O(1)`。

**识别。** 题目点名「堆排序」；堆就是数组表示的完全二叉树：下标 `i` 的左右孩子是 `2i + 1`、`2i + 2`，父节点是 `(i - 1) // 2`。「升序 + 原地」要用**大根堆**：最大的放到数组末尾，用小根堆就得借额外数组。`n = 5 * 10^4` 时 `O(n log n)` 足够；值域只有 `10^5` 种，计数排序 `O(n + 值域)` 是面试官常见的追问。

**推导。** 朴素：选择排序，每轮扫一遍找最大值放到末尾，`O(n^2)`，`n = 5 * 10^4` 时约 `1.25 * 10^9` 次比较，太慢。浪费：每轮都从头扫描，没有利用上一轮的比较结果。洞见：用堆维护「当前最大值」，取最大 `O(1)`，修复堆 `O(log n)`；堆就存在原数组里，不需要额外空间。步骤：① 建堆：从 `n // 2 - 1` 到 `0` 逐个下沉，`O(n)`；② 排序：重复 `n - 1` 次，把 `nums[0]` 与堆的最后一个元素交换，堆缩小一格，对 `nums[0]` 下沉。

```python
def sort_array(nums: list[int]) -> list[int]:
    n = len(nums)

    def sift_down(root: int, size: int) -> None:
        """把 nums[root] 下沉到合适位置，堆的范围是 nums[0:size]。"""
        while (child := 2 * root + 1) < size:              # 左孩子存在
            if child + 1 < size and nums[child + 1] > nums[child]:
                child += 1                                  # 取较大的孩子
            if nums[root] >= nums[child]:
                break                                       # 已满足大根堆性质
            nums[root], nums[child] = nums[child], nums[root]
            root = child

    for i in range(n // 2 - 1, -1, -1):                     # 建堆：最后一个非叶子节点向前
        sift_down(i, n)
    for end in range(n - 1, 0, -1):                         # 每轮把当前最大值放到 end
        nums[0], nums[end] = nums[end], nums[0]
        sift_down(0, end)                                   # 堆缩小为 nums[0:end]
    return nums
```

运行：`[5,2,3,1]` → `[1,2,3,5]`，`[5,1,1,2,0,0]` → `[0,0,1,1,2,5]`，`[1]` → `[1]`，`[2,1]` → `[1,2]`，`[3,3,3]` → `[3,3,3]`，`50000 到 1 倒序的前 3 个` → `[1,2,3]`。

**复杂度。** 时间 `O(n log n)`：建堆 `O(n)`，排序阶段 `n - 1` 次下沉各 `O(log n)`；空间 `O(1)`（下沉用循环而不是递归，原地交换）。不稳定排序。

**易错点。**
- 排序阶段下沉的 `size` 必须是当前堆大小 `end`，不是 `n`：用 `n` 会把已经排好的尾部又拉回堆里，`[5,2,3,1]` 得到 `[3,5,1,2]`（正确 `[1,2,3,5]`）。
- 建堆必须从最后一个非叶子节点**向前**到根：从根往后下沉，下面的子树还没满足堆性质，`[1,2,3,4,5]` 得到 `[1,2,4,5,3]`。
- 选较大孩子前要判断右孩子是否存在（`child + 1 < size`），否则会越界。

**追问。**
- 为什么建堆是 `O(n)` 而不是 `O(n log n)`：高度为 `h` 的节点至多 `n / 2^(h+1)` 个，各下沉 `O(h)`，求和是 `O(n)`。
- 稳定性：堆排序不稳定（交换堆顶和末尾会打乱相等元素的相对次序）；要稳定用归并排序或 `sorted`。
- 用标准库：`heapq.heapify` 加 `heappop` 循环，同样 `O(n log n)`，但要 `O(n)` 额外空间；求前 k 大用 `heapq.nlargest`。
