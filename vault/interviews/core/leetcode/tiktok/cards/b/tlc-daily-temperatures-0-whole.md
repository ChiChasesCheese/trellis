## Q
**LC 739 每日温度**｜Medium · LC TikTok 热度 63/100 · CodeTop 国内累计 26 次 · 最近 2025-09-19（国内 CodeTop）

给整数数组 `temperatures`，表示每天的温度。返回数组 `answer`，`answer[i]` 是第 `i` 天之后要等多少天才会出现**更高**的温度；之后再也不会升温则为 `0`。`1 <= temperatures.length <= 10^5`，`30 <= temperatures[i] <= 100`。例：`[73,74,75,71,69,72,76,73]` → `[1,1,4,2,1,1,0,0]`；`[30,40,50,60]` → `[1,1,1,0]`；`[30,60,90]` → `[1,1,0]`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 单调栈（monotonic stack）：栈里存「还没等到更高温度」的下标，对应温度从栈底到栈顶不增；遇到更高的温度就不断弹栈，被弹出的下标 `j` 的答案就是 `i - j`。每个下标进出栈各一次，`O(n)`。

**识别。** 「每个元素右边第一个比它大的元素」是单调栈的标志题（next greater element）；`n = 10^5` 排除 `O(n^2)`；要的是**距离**，所以栈里存下标而不是温度。

**推导。** 暴力：对每个 `i` 向右扫到第一个更高的，最坏（递减序列）`O(n^2)`。浪费：多个位置在等同一个「更高的数」，各自扫了同一段。洞察：从左往右扫，当前温度 `t` 一旦出现，所有栈里比它低的下标都被它「解决」了；未解决的下标按温度自然递减（否则早就被解决）。所以栈里始终是一个不增序列，新来的 `t` 只需要从栈顶开始弹，弹到不比它低为止，再把自己压入。每个下标压一次、弹一次，总共 `O(n)`。

```python
def daily_temperatures(temperatures: list[int]) -> list[int]:
    answer = [0] * len(temperatures)
    stack: list[int] = []              # 还在等更高温度的下标；对应温度自底向顶非严格递减
    for i, t in enumerate(temperatures):
        while stack and temperatures[stack[-1]] < t:   # t 是它们等到的第一个更高温度
            j = stack.pop()
            answer[j] = i - j
        stack.append(i)
    return answer                      # 栈里剩下的永远没等到，保持 0
```

运行：`[73,74,75,71,69,72,76,73]` → `[1, 1, 4, 2, 1, 1, 0, 0]`，`[30,40,50,60]` → `[1, 1, 1, 0]`，`[30,60,90]` → `[1, 1, 0]`，`[50]` → `[0]`，`[70,70,70]` → `[0, 0, 0]`；`10^5` 个随机温度约 `5 ms`。

**复杂度。** 时间 `O(n)`：每个下标入栈、出栈各一次；空间 `O(n)`：递减序列时栈会装下全部下标。

**易错点。**
- 弹栈条件写成 `<=`：相等的温度也被弹出，答案算成「下一个不低于它的」。`[70,70,80]` 得到 `[1, 1, 0]`，正确是 `[2, 1, 0]`，因为第一个 `70` 要等到 `80`（第 2 天），不是等到另一个 `70`。
- 栈里存温度而不存下标：弹出时算不出距离。
- 结尾忘了剩余栈元素：它们的答案就是初始化的 `0`，所以 `answer` 要先全部填 `0`。

**追问。**
- `O(1)` 额外空间：从右往左，用 `answer` 当跳转表，`j += answer[j]` 直接跳到 `j` 的下一个更高温度；仍是 `O(n)`。
- 温度范围只有 `30..100`：从右往左，用长度 `101` 的数组记录每个温度最近出现的下标，每个位置查比它高的至多 `70` 个温度，`O(70n)`。
- 环形数组的下一个更大元素（LC 503）：把数组遍历两圈，下标取模。

**同模式。** LC 496 / 503 下一个更大元素 I / II、LC 84 柱状图中最大的矩形、LC 42 接雨水、LC 901 股票价格跨度、LC 402 移掉 K 位数字。
