## Q
**LC 680 验证回文字符串 Ⅱ**｜Easy · CodeTop 国内累计 11 次 · 最近 2026-04-15（国内 CodeTop）

给字符串 `s`，**最多删除一个字符**，判断能否让它成为回文串（正着读和倒着读一样）。`1 <= s.length <= 10^5`，`s` 只含小写英文字母。例：`"aba"` → `true`；`"abca"` → `true`（删 `'c'` 得 `"aba"`）；`"abc"` → `false`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 对撞双指针从两端向中间比较；**第一次**遇到 `s[l] != s[r]` 时，要删的只可能是这两个字符之一，各试一次「剩下的闭区间是不是回文」，其余部分不再分叉。`O(n)`。

**识别。** 「回文」天然是两端对称，用对撞双指针（two pointers）；「最多删一个」意味着失配只能容忍一次，而且**第一次失配处只有两个分支**（删左 / 删右），分支数是常数，不是 `n`；`n = 10^5` 排除「枚举删哪个再整串判回文」的 `O(n^2)`。

**推导。** 暴力：枚举删哪个字符（共 `n + 1` 种，含不删），每种 `O(n)` 判回文，合计 `O(n^2)`。浪费：回文判断本来就从两端向中间比，外层已经配对成功的部分在每种删法里被重复检查，真正出问题的只有第一个失配的位置。洞察：第一次失配在 `(l, r)` 时，删外层已匹配的字符不会比删 `s[l]` 或 `s[r]` 更好（删除位置可以一路挪到 `l`，得到同一个串），所以只需试「删 `l`」「删 `r`」两种。最优：双指针走到失配，各用一次 `O(n)` 的判断，总共 `O(n)`。

```python
def valid_palindrome(s: str) -> bool:
    def is_pal(i: int, j: int) -> bool:        # s[i..j]（闭区间）是不是回文
        while i < j:
            if s[i] != s[j]:
                return False
            i += 1
            j -= 1
        return True

    left, right = 0, len(s) - 1
    while left < right:
        if s[left] != s[right]:                # 第一次失配：删左边或删右边，各试一次
            return is_pal(left + 1, right) or is_pal(left, right - 1)
        left += 1
        right -= 1
    return True
```

运行：`"aba"` → `True`，`"abca"` → `True`，`"abc"` → `False`，`"aab"` → `True`，`"a"` → `True`，`"ab"` → `True`。

**复杂度。** 时间 `O(n)`：主循环最多走 `n/2` 步，失配后的两次 `is_pal` 各最多扫 `n/2` 个位置，且只会触发一次；空间 `O(1)`（用下标，不切片）。

**易错点。**
- 只试删左边：`"aab"` 在 `l=0, r=2` 失配，删左得 `"ab"`（不是回文），误判 `False`；删右得 `"aa"`，正确是 `True`。两边都要试，用 `or` 连接。
- 失配后「两边都删」：写成 `is_pal(left + 1, right - 1)` 会把 `"abc"` 判成 `True`（只剩 `"b"`），正确是 `False`。删的是**一个**字符，区间只收缩一侧。
- 区间约定不统一：`is_pal(i, j)` 是闭区间，调用时 `left + 1, right` 和 `left, right - 1` 都不能再 `+1 / -1` 多一次。

**追问。**
- 返回该删的下标：失配后先试删左，成立返回 `left`；再试删右，成立返回 `right`；本来就是回文返回 `-1`；无解返回 `None`。
- 最多删 `k` 个（LC 1216）：分支不再是常数，改求最长回文子序列 `lps`，判断 `len(s) - lps <= k`，是 `O(n^2)` 的二维 DP。
- 忽略大小写与非字母数字（LC 125 的预处理）：先 `t = [c.lower() for c in s if c.isalnum()]`，再对 `t` 套同一个函数。
