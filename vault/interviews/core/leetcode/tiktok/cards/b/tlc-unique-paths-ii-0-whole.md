## Q
**LC 63 不同路径 II**｜Medium · CodeTop 国内累计 9 次 · 最近 2026-03-31（CodeTop）

`m x n` 的网格 `obstacleGrid` 里，`1` 是障碍、`0` 是空格。机器人从左上角 `obstacleGrid[0][0]` 出发，每步只能**向下或向右**走一格，要到右下角 `obstacleGrid[m-1][n-1]`，路径上不能有任何障碍格。返回不同路径的数量；保证答案不超过 `2 * 10^9`。`1 <= m, n <= 100`，`obstacleGrid[i][j]` 为 `0` 或 `1`。例：`[[0,0,0],[0,1,0],[0,0,0]]` → `2`（右右下下、下下右右）；`[[0,1],[0,0]]` → `1`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 二维 DP：到达一个空格的路径数 = 从上面来的路径数 + 从左边来的路径数，障碍格记 `0`；多开一行一列做哨兵，起点和边界就不用特判。`O(mn)`。

**识别。** 「只能向下或向右」意味着网格是一个**有向无环图**（DAG），按行优先的顺序遍历就是拓扑序；「求路径**数量**」而不是列出路径 → 计数 DP，不用回溯。`m, n <= 100`，`O(mn) = 10^4` 很轻松。

**推导。** 暴力 DFS 从起点每步分两叉，路径条数是指数级（无障碍时是 `C(m+n-2, m-1)`）。浪费在于：到达格子 `(i, j)` 之后的走法与怎么到的无关，同一个格子被不同前缀重复展开无数次。所以只记「到达 `(i, j)` 的路径数」：最后一步要么从上来、要么从左来，两类互不重叠，`dp[i][j] = dp[i-1][j] + dp[i][j-1]`；障碍格不可到达，保持 `0`，它自然不会贡献给下游。每格算一次，`O(mn)`。

```python
def unique_paths_with_obstacles(obstacle_grid: list[list[int]]) -> int:
    m, n = len(obstacle_grid), len(obstacle_grid[0])
    dp = [[0] * (n + 1) for _ in range(m + 1)]   # dp[i][j]：走到第 i 行第 j 列（行列都从 1 数起）的路径数
    dp[0][1] = 1                                  # 哨兵：让起点 dp[1][1] = dp[0][1] + dp[1][0] = 1
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if obstacle_grid[i - 1][j - 1] == 0:  # 障碍格保持 0
                dp[i][j] = dp[i - 1][j] + dp[i][j - 1]
    return dp[m][n]
```

运行：`[[0,0,0],[0,1,0],[0,0,0]]` → `2`，`[[0,1],[0,0]]` → `1`，`[[1]]` → `0`（起点是障碍），`[[0]]` → `1`，`[[0,0],[0,1]]` → `0`（终点是障碍），`[[1,0]]` → `0`。

**复杂度。** 时间 `O(mn)`：每格常数次加法；空间 `O(mn)`：`(m+1) x (n+1)` 的表。

**易错点。**
- 照搬 LC 62 把第一行、第一列全设成 `1`：障碍后面的边界格其实不可达。`[[0,1,0]]` 会错成 `1`（正确 `0`），`[[0,0],[1,0]]` 会错成 `2`（正确 `1`）。哨兵写法让边界格也走同一个公式，障碍自动截断。
- 起点或终点本身是障碍时答案是 `0`；哨兵写法里起点格被 `if` 跳过，`dp[1][1]` 保持 `0`，不必特判。

**追问。**
- 返回一条可行路径：从 `dp[m][n]` 倒推，哪个来源格的 `dp` 非零就从哪来；样例 1 得到 `"RRDD"`（`R` 右、`D` 下）。
- 没有障碍时可以直接用组合数 `math.comb(m + n - 2, m - 1)`：路径就是在 `m+n-2` 步里选哪几步向下。
- 空间可以压到 O(n)：见 Python 工具箱「DP 降维」。

**同模式。** LC 62 不同路径、LC 64 最小路径和、LC 120 三角形最小路径和、LC 174 地下城游戏。
