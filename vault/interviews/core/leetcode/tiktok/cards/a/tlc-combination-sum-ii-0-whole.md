## Q
**LC 40 组合总和 II**｜Medium · TikTok·字节 高频

给一个数组 `candidates`（元素可能重复）和目标数 `target`，找出所有和为 `target` 的组合。`candidates` 中每个元素在一个组合里只能用**一次**；结果不能包含重复的组合（元素相同、顺序不同算同一个）。`1 <= candidates.length <= 100`，`1 <= candidates[i] <= 50`，`1 <= target <= 30`。例：`candidates = [10,1,2,7,6,1,5], target = 8` → `[[1,1,6],[1,2,5],[1,7],[2,6]]`；`candidates = [2,5,2,1,2], target = 5` → `[[1,2,2],[5]]`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 先排序，再回溯：`dfs(start, remain)` 从 `start` 开始往后选，选了 `nums[i]` 就从 `i + 1` 继续（每个元素最多一次）；同一层里遇到和前一个相同的数就跳过（去重），遇到比剩余目标大的数就整层结束（剪枝）。

**识别。** 「找出所有组合」是回溯（backtracking）；「每个元素只用一次」让下一层从 `i + 1` 开始；「元素有重复、结果不许重复」是去重信号：先排序让相同的数相邻，再在**同一层**跳过重复的选择。`target <= 30`、元素都是正数，所以递归深度不超过 `30`，还能用「超额就停」剪枝。

**推导。** 暴力：枚举所有 `2^n` 个子集，求和，用集合去重，`n = 100` 完全不可行。浪费：大量子集的和已经超过 `target`，还在继续往里加。洞察一：元素全为正，排序后一旦 `nums[i] > remain`，后面的更大，直接结束这一层。洞察二：重复组合来自「同一层选了值相同的两个不同元素」，比如两个 `1` 都作为组合的第一个元素；排序后相同值相邻，规定同一层里相同的值只选第一个（`i > start and nums[i] == nums[i-1]` 就跳过）。注意是 `i > start` 而不是 `i > 0`：下一层里选第二个 `1` 是合法的，因为那是组合里的第二个元素。

```python
def combination_sum2(candidates: list[int], target: int) -> list[list[int]]:
    nums = sorted(candidates)              # 排序：相同数字相邻，才能剪重复、剪超额
    result: list[list[int]] = []
    path: list[int] = []

    def dfs(start: int, remain: int) -> None:
        if remain == 0:
            result.append(path[:])         # 拷贝当前路径
            return
        for i in range(start, len(nums)):
            if nums[i] > remain:           # 已排序：后面更大，直接结束这一层
                break
            if i > start and nums[i] == nums[i - 1]:   # 同一层不重复选相同的数
                continue
            path.append(nums[i])
            dfs(i + 1, remain - nums[i])   # 每个数只能用一次：下一层从 i + 1 开始
            path.pop()

    dfs(0, target)
    return result
```

运行：`[10,1,2,7,6,1,5], 8` → `[[1, 1, 6], [1, 2, 5], [1, 7], [2, 6]]`，`[2,5,2,1,2], 5` → `[[1, 2, 2], [5]]`，`[1], 2` → `[]`，`[1,1], 2` → `[[1, 1]]`；`100` 个 `1`、目标 `30` → 只有 `[1]*30` 一个组合，立刻返回；`1..50` 各出现两次、目标 `30` → `1225` 个组合，约 `1 ms`。

**复杂度。** 时间最坏 `O(2^n)`（组合数由输出规模决定），剪枝后实际远小于；空间 `O(target)`：递归深度和 `path` 长度不超过 `target`（元素全 `>= 1`），不算输出。

**易错点。**
- 去重条件写成 `i > 0`：下一层也会跳过合法的第二个 `1`。`candidates = [1,1,6], target = 8`，正确是 `[[1,1,6]]`，写成 `i > 0` 得到 `[]`。
- 忘了去重：示例 1 会得到 `[[1,1,6],[1,2,5],[1,7],[1,2,5],[1,7],[2,6]]`，`[1,2,5]` 和 `[1,7]` 各出现两次（用了不同位置的 `1`）。
- 忘了排序：相同的数不相邻，`nums[i] == nums[i-1]` 抓不到重复，`break` 剪枝也不成立。

**追问。**
- 不去重改成「每个不同的值选几个」：用 `Counter` 把数组变成 `(值, 个数)` 列表，每层决定这个值选 `0..count` 个，天然没有重复组合，也不用比较相邻元素。
- 元素可重复使用（LC 39）：下一层从 `i` 开始而不是 `i + 1`，不需要同层去重。
- 只问有多少种组合：转成 `0/1` 背包的计数 DP，`dp[s]` 表示和为 `s` 的方案数，`O(n · target)`；但有重复元素时要按值分组处理。
