## Q
**LC 1049 最后一块石头的重量 II**｜Medium · 字节 高频

有一堆石头，`stones[i]` 是第 `i` 块石头的重量。每一回合从中**任选**两块石头一起粉碎：设重量分别为 `x` 和 `y`（`x <= y`），若 `x == y` 两块都被粉碎；若 `x != y`，重量 `x` 的石头被粉碎，重量 `y` 的石头变成 `y - x`。最后最多剩下一块石头，返回它**最小的可能重量**；没有石头剩下则返回 `0`。`1 <= stones.length <= 30`，`1 <= stones[i] <= 100`。例：`stones = [2,7,4,1,8,1]` → `1`；`stones = [31,26,33,21,40]` → `5`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 最后剩下的重量等于「每块石头前面带一个 `+` 或 `-` 的代数和」的绝对值；于是问题变成把石头分成两堆使重量差最小，即 0/1 背包：用二维表 `dp[i][s]`（前 `i` 块石头能否凑出总重 `s`）求不超过 `总重 // 2` 的最大可达子集和 `best`，答案是 `总重 - 2 * best`。

**识别。** 「任选两块相撞，结果是差」。同族的 LC 1046 每次取最重的两块（用堆），但这里**任意选**，贪心不再最优。看到「相撞取差」要想到：每块石头最终要么被算进「加」的一边，要么算进「减」的一边，所以只关心分组，与碰撞顺序无关。`n <= 30`、重量 `<= 100`，总重不超过 `3000`，背包 `O(n · 总重)` 很小；`2^30` 的符号枚举太大。

**推导。** 暴力：枚举碰撞顺序是阶乘级，枚举每块石头的符号是 `2^n`，`n = 30` 约 `10^9`，太慢。洞察一：不管怎么碰，每块石头对最终结果的贡献是 `+w` 或 `-w`，最后一块石头的重量是 `|Σ ±w|`（反过来，使它最小的符号分配总能通过合适的碰撞顺序实现，这是该题的标准结论）。洞察二：设一堆的和为 `s`，另一堆为 `总重 - s`，差是 `|总重 - 2s|`，要最小，就要让 `s` 尽量接近 `总重 / 2`，也就是在不超过 `总重 // 2` 的子集和里取最大。这是 0/1 背包的可达性问题：状态 `dp[i][s]` 表示只用前 `i` 块石头能否凑出总重 `s`，基础行是 `dp[0][0] = True`（一块都不选只能凑出 `0`），每块石头要么不选 `dp[i-1][s]`，要么选 `dp[i-1][s-w]`，答案在最后一行 `dp[n]`。

```python
def last_stone_weight_ii(stones: list[int]) -> int:
    n = len(stones)
    total = sum(stones)
    half = total // 2                      # 较小的一堆最多是 total // 2
    # dp[i][s]：只用前 i 块石头，能否挑出总重恰为 s 的一堆
    dp = [[False] * (half + 1) for _ in range(n + 1)]
    dp[0][0] = True                        # 基础行：一块都不选，只能凑出 0
    for i in range(1, n + 1):
        w = stones[i - 1]
        for s in range(half + 1):
            dp[i][s] = dp[i - 1][s] or (s >= w and dp[i - 1][s - w])   # 不选第 i 块 / 选第 i 块
    best = max(s for s in range(half + 1) if dp[n][s])   # 最后一行里不超过 half 的最大可达重量
    return total - 2 * best
```

运行：`[2,7,4,1,8,1]` → `1`，`[31,26,33,21,40]` → `5`，`[1]` → `1`，`[1,1]` → `0`，`[100] * 30` → `0`。

**复杂度。** 时间 `O(n · total / 2)`，最坏约 `30 * 1500`；空间 `O(n · total / 2)`，整张表约 `4.6 * 10^4` 个布尔值。

**易错点。**
- 贪心「每次砸最重的两块」（LC 1046 的做法）：`[31,26,33,21,40]` 得到 `9`，正确是 `5`。
- 转移读错了行：写成 `dp[i][s - w]`（本行）而不是 `dp[i - 1][s - w]`（上一行），同一块石头会被用多次。`[1,3]` 会得到 `0`（把 `1` 用了两次凑出 `2`，`4 - 2 * 2`），正确是 `2`。
- 容量上界是 `total // 2`，不是 `total`；基础行 `dp[0][0]` 要设为 `True`，因为空集的和为 `0`，漏掉则整张表全是 `False`，`max()` 对空序列抛 `ValueError`。

**追问。**
- 空间可以压到 O(n)：见 Python 工具箱「DP 降维」。
- 用整数当位集（bitset）加速：把一整行布尔值存成一个整数的二进制位，每块石头相当于整体左移再并入，一次大整数运算替代内层循环。
- 要输出具体分组：已经有整张表，从 `dp[n][best]` 往回走，若 `dp[i-1][s]` 为真，第 `i` 块不选；否则选，`s -= w`。
- 相关变体：LC 416 分割等和子集（`total` 是偶数且 `total / 2` 可达）、LC 494 目标和（符号分配计数）。

**同模式。** LC 416 分割等和子集、LC 494 目标和、LC 474 一和零、LC 1046 最后一块石头的重量、LC 322 零钱兑换。
