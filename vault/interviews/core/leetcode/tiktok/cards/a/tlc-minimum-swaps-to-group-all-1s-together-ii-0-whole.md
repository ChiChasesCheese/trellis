## Q
**LC 2134 最少交换次数来组合所有的 1 II**｜Medium · LC TikTok 热度 25/100

「交换」指选中数组中两个互不相同的位置，交换它们的值。「环形数组」把第一个元素和最后一个元素视为相邻。给二进制环形数组 `nums`，返回在任意位置将所有的 `1` 聚集在一起所需的最少交换次数。`1 <= nums.length <= 10^5`，`nums[i]` 是 `0` 或 `1`。例：`[0,1,0,1,1,0,0]` → `1`；`[0,1,1,1,0,0,1,1,0]` → `2`；`[1,1,0,0,1]` → `0`（环形下最后一个 `1` 与开头的两个 `1` 相邻）。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 设 `1` 的总数为 `k`，最终所有 `1` 占据一段长为 `k` 的环形窗口。窗口里本来有多少个 `1`，就少换多少次，所需交换数等于窗口里的 `0` 的个数；所以在所有环形窗口里找 `1` 最多的一个，答案是 `k - 最大 1 的个数`。`O(n)`。

**识别。** 「把某种元素聚集在一起」且「最少交换」，是固定窗口长度 `k` 的滑动窗口；「环形」用下标取模处理。`n = 10^5` 要求线性。

**推导。** 暴力：枚举最终聚集的起点（`n` 个），每个起点统计窗口里的 `0`，`O(n · k)`。更暴力：对小数组做状态空间的 BFS，只能验证。洞察：窗口确定后，窗口外的每个 `1` 必须和窗口里的某个 `0` 交换，一次交换恰好完成一对，所以所需次数 = 窗口里的 `0` 数 = 窗口外的 `1` 数。因此要窗口里 `1` 最多。窗口右移一格，只多一个新元素、少一个旧元素，`O(1)` 更新；环形就是起点遍历 `0..n-1`，下标对 `n` 取模。

```python
def min_swaps(nums: list[int]) -> int:
    n, ones = len(nums), sum(nums)         # 最终 1 要聚成长度 ones 的一段
    window = sum(nums[:ones])              # 起点 0 的窗口里已有的 1 的个数
    best = window
    for i in range(ones, ones + n - 1):    # 窗口右端继续推进，下标对 n 取模当作环
        window += nums[i % n] - nums[(i - ones) % n]
        best = max(best, window)
    return ones - best                     # 窗口里的 0 的个数 = 需要换进来的 1 的个数
```

运行：`[0,1,0,1,1,0,0]` → `1`，`[0,1,1,1,0,0,1,1,0]` → `2`，`[1,1,0,0,1]` → `0`，`[0]` → `0`，`[1]` → `0`，`[0,0,0]` → `0`，`[1,1,1]` → `0`，`[1,0,0,0,1]` → `0`；长度 `10^5` 的随机数组约 `4 ms`。

**复杂度。** 时间 `O(n)`；空间 `O(1)`。

**易错点。**
- 不考虑环，只枚举线性窗口：`[1,1,0,0,1]` 得到 `1`，`[1,0,0,0,1]` 得到 `1`，正确都是 `0`。循环只到 `n` 而漏掉起点 `1..n-1` 里跨越末尾的窗口，也是同样的错。
- 返回窗口里最多的 `1` 的个数，而不是 `ones - best`：示例 1 得到 `2`，正确是 `1`。
- 窗口右端忘了取模：`nums[i]` 在 `i >= n` 时越界；环形窗口的新元素必须写 `nums[i % n]`。

**追问。**
- 非环形（LC 1151）：去掉取模，窗口起点只取 `0..n-k`。
- 前缀和写法：`pref = list(accumulate(nums + nums, initial=0))`，答案 `ones - max(pref[i + ones] - pref[i] for i in range(n))`，用 `O(n)` 空间，更好读。
- 想把所有 `0` 聚集：同样的窗口，答案不变，因为聚集 `1` 与聚集 `0` 互为补集。

**同模式。** LC 1151 最少交换次数来组合所有的 1、LC 1004 最大连续 1 的个数 III、LC 918 环形子数组的最大和、LC 1658 将 x 减到 0 的最小操作数。
