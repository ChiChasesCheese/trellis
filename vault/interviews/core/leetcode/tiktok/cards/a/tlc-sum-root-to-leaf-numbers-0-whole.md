## Q
**LC 129 求根到叶子节点数字之和**｜Medium · 字节 高频

给二叉树的根节点 `root`，每个节点存一个 `0` 到 `9` 的数字。每条从根到叶子的路径代表一个数，例如路径 `1 -> 2 -> 3` 表示 `123`。返回所有根到叶子路径所表示的数之和。叶子是没有子节点的节点。树中节点数在 `[1, 1000]`，`0 <= Node.val <= 9`，树的深度不超过 `10`。例：`root = [1,2,3]` → `25`（`12 + 13`）；`root = [4,9,0,5,1]` → `1026`（`495 + 491 + 40`）。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 深度优先搜索（DFS）时把「从根走到当前节点形成的数」当参数向下传，每下一层 `acc = acc * 10 + node.val`；走到叶子就返回这个数，非叶子返回左右子树结果之和。`O(n)`。

**识别。** 「根到叶子的路径」加「对每条路径算一个量再汇总」是自顶向下 DFS 的信号：路径上的信息（前缀数）只依赖祖先，可以随递归一路带下去，不需要先收集全部路径。深度不超过 `10`，递归栈不是问题；`n <= 1000` 任何线性解都够。

**推导。** 暴力：先收集所有根到叶子的路径（列表或字符串），再逐条转成整数相加，时间 `O(n * h)`，还要存路径。浪费在于路径前缀被每条经过它的路径重复保存和重复转换。其实「前缀数」每下一层只需要乘 10 加当前值，所以把它作为参数传递，不存路径，到叶子直接用。关键判断是叶子：必须左右子节点**都**为空才算路径终点。

```python
def sum_numbers(root: TreeNode | None) -> int:
    def dfs(node: TreeNode | None, acc: int) -> int:
        if node is None:
            return 0
        acc = acc * 10 + node.val                 # 沿路径把数字“接长”一位
        if node.left is None and node.right is None:
            return acc                            # 叶子：这条路径生成的数
        return dfs(node.left, acc) + dfs(node.right, acc)
    return dfs(root, 0)
```

运行：`[1,2,3]` → `25`，`[4,9,0,5,1]` → `1026`，单节点 `[0]` → `0`，`[1,null,2]`（根只有右孩子）→ `12`。

**复杂度。** 时间 `O(n)`：每个节点访问一次；空间 `O(h)`：递归栈深度等于树高，这里 `h <= 10`。

**易错点。**
- 叶子判断写错。不判断叶子、遇到空节点才返回 `acc`：`[1,2]`（根 `1` 只有左孩子 `2`）得到 `25`，正确是 `12`——根的空右孩子也被当成一条路径，把 `1` 多算了一次。
- 用 `or` 判断叶子（任一孩子为空就返回）：`[1,2]` 得到 `1`，正确是 `12`。只有一个孩子的节点不是叶子，必须继续往下。
- 值是 `0` 的节点照常参与：`acc * 10 + 0`，不要因为 `0` 就跳过。

**追问。**
- 不想递归：显式栈存 `(node, acc)`，弹出时更新 `acc`，叶子累加到 `total`，同样 `O(n)`。
- 返回所有路径本身（LC 257）：多维护一个 `path` 列表，进入时 `append`、离开时 `pop`，收集时复制一份。
- 数字位数多、可能很大：Python 整数不会溢出；若要取模，每步 `acc = (acc * 10 + val) % MOD`，不要最后才取模。

**同模式。** LC 112 / 113 路径总和、LC 257 二叉树的所有路径、LC 1022 从根到叶的二进制数之和、LC 988 从叶结点开始的最小字符串。
