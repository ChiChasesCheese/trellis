## Q
**LC 875 爱吃香蕉的珂珂**｜Medium · TikTok 高频

有 `n` 堆香蕉，第 `i` 堆有 `piles[i]` 根。警卫离开，`h` 小时后回来。珂珂决定吃香蕉的速度 `k`（根/小时）：每小时选一堆，吃掉 `k` 根；这堆不足 `k` 根就全吃完，这一小时不再吃别的。求能在 `h` 小时内吃完所有香蕉的**最小**整数速度 `k`。`1 <= piles.length <= 10^4`，`piles.length <= h <= 10^9`，`1 <= piles[i] <= 10^9`。例：`piles = [3,6,7,11]`，`h = 8` → `4`；`piles = [30,11,23,4,20]`，`h = 5` → `30`，`h = 6` → `23`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 二分答案（binary search on the answer）：速度越快，需要的小时数越少，这种单调性让可行与不可行的速度排成 `FFF…TTT`；在 `[1, max(piles)]` 上二分，找第一个满足 `sum(ceil(p / k)) <= h` 的 `k`。`O(n log max)`。

**识别。** 「求满足条件的最小值」，条件对答案单调（`k` 越大越容易），并且能用 `O(n)` 写出判定函数，就是二分答案。答案范围到 `10^9`，不可能逐个试。`h >= piles.length` 保证速度取到 `max(piles)` 时一定可行，上界因此确定。

**推导。** 暴力：`k` 从 `1` 递增，每个 `k` 判定 `O(n)`，最坏试 `10^9` 个 `k`，约 `10^13` 次运算。浪费：判定结果有单调性，`k` 可行则 `k + 1` 也可行，没必要逐个试。洞察：在 `FFF…TTT` 上二分找第一个 `T`。判定：一小时只能吃一堆，所以第 `p` 堆需要 `ceil(p / k)` 小时，求和与 `h` 比较。上界取 `max(piles)`：`k` 超过它之后每堆都恰好 `1` 小时，再快也没有收益。

```python
def min_eating_speed(piles: list[int], h: int) -> int:
    lo, hi = 1, max(piles)                  # 答案在 [1, max(piles)]
    while lo < hi:
        mid = (lo + hi) // 2
        hours = sum((p + mid - 1) // mid for p in piles)   # 向上取整
        if hours <= h:
            hi = mid                        # mid 够快，答案在 [lo, mid]
        else:
            lo = mid + 1                    # mid 太慢，答案在 (mid, hi]
    return lo
```

运行：`([3,6,7,11], 8)` → `4`，`([30,11,23,4,20], 5)` → `30`，`([30,11,23,4,20], 6)` → `23`，`([1], 1)` → `1`，`([10**9], 1)` → `1000000000`；`10^4` 堆、每堆随机到 `10^9` 的输入约 `10 ms`。

**复杂度。** 时间 `O(n log M)`，`M = max(piles)`，二分约 `30` 轮、每轮 `O(n)`；空间 `O(1)`。

**易错点。**
- 小时数向下取整：`sum(p // mid …)` 忽略了“不足 `k` 根也要占一小时”。`[3,6,7,11]`、`h = 8` 得到 `3`（正确 `4`）；`[30,11,23,4,20]`、`h = 5` 得到 `12`（正确 `30`）。向上取整写 `(p + k - 1) // k`。
- 找“第一个可行”的二分要成套写：`lo < hi`、可行时 `hi = mid`、不可行时 `lo = mid + 1`。换成 `lo <= hi` 配 `hi = mid` 会死循环，配 `hi = mid - 1` 会丢掉可行解。
- 判定只能比较 `hours <= h`；写成 `<` 会把恰好用满 `h` 小时的速度排除，答案偏大。

**追问。**
- 每小时可以吃多堆（只受总量 `k` 限制）：问题退化成 `ceil(sum(piles) / h)`，不需要二分。
- 速度允许是小数：二分改成浮点，用迭代次数或精度作终止条件。
- 标准库写法：`1 + bisect_left(range(1, max(piles) + 1), True, key=lambda k: 判定(k))`，Python 3.10 起 `bisect` 支持 `key`。
