## Q
**LC 154 寻找旋转排序数组中的最小值 II**｜Hard · CodeTop 国内累计 11 次 · 最近 2024-09-20（CodeTop）

长度为 `n` 的升序数组经过 `1` 到 `n` 次旋转得到 `nums`；旋转一次是把最后一个元素移到最前面，例如 `[0,1,4,4,5,6,7]` 旋转 `4` 次得到 `[4,5,6,7,0,1,4]`，旋转 `7` 次回到原数组。数组中可能存在重复元素。找出并返回数组中的最小元素，操作步骤要尽可能少。`n == nums.length`，`1 <= n <= 5000`，`-5000 <= nums[i] <= 5000`。进阶：和无重复版本相比，允许重复会影响时间复杂度吗？如何影响，为什么？例：`[1,3,5]` → `1`；`[2,2,2,0,1]` → `0`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 二分，拿 `nums[mid]` 和右端点 `nums[hi]` 比较：大于说明最小值在 `mid` 右边，`lo = mid + 1`；小于说明最小值在 `mid` 或它左边，`hi = mid`；相等时无法判断在哪一侧，但可以安全地丢掉右端点，`hi -= 1`。平均 `O(log n)`，最坏 `O(n)`。

**识别。** 「旋转有序数组找最小值」是二分；比较的对象选右端点，因为右端点能区分「`mid` 在右半有序段」与「`mid` 在被旋转到前面的大数段」；「允许重复」意味着 `nums[mid] == nums[hi]` 这一种情形不再能分辨方向，需要单独处理，这是整题的考点。

**推导。** 暴力：`min(nums)` 线性扫描，`O(n)`；无重复版本：`nums[mid] > nums[hi]` 就 `lo = mid + 1`，否则 `hi = mid`，`O(log n)` → 浪费/障碍：有重复时 `nums[mid] == nums[hi]` 的两侧都可能含最小值（`[3,3,1,3]` 最小值在 `mid` 右边，`[1,3,3]` 在 `mid` 左边），二分失去依据 → 洞察：此时 `nums[hi]` 被 `nums[mid]` 复制了一份，丢掉 `hi` 不会丢失最小值：若 `nums[hi]` 就是最小值，则相等的 `nums[mid]` 也是最小值且仍在区间内；于是 `hi -= 1`，区间缩小一格，其余情形仍然折半。

```python
def find_min(nums: list[int]) -> int:
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] > nums[hi]:        # 最小值一定在 mid 右边（mid 本身不是）
            lo = mid + 1
        elif nums[mid] < nums[hi]:      # 最小值在 mid 或它左边
            hi = mid
        else:                           # 相等：看不出在哪一侧，但 nums[hi] 有 nums[mid] 这个“替身”，可以安全丢掉
            hi -= 1
    return nums[lo]
```

运行：`[1,3,5]` → `1`；`[2,2,2,0,1]` → `0`；`[3,3,1,3]` → `1`；`[1]` → `1`；`[2,1]` → `1`；`[1,1]` → `1`；`[10,1,10,10,10]` → `1`；`[4,5,6,7,0,1,4]` → `0`；`[0] + [1] * 4999` 需要 `4999` 次迭代，`[1] * 5000` 也是 `4999` 次，而 `[2500..4999, 0..2499]`（无重复）只要 `13` 次。

**复杂度。** 平均 `O(log n)`；最坏 `O(n)`（大量重复，如全部相同）；空间 `O(1)`。

**易错点。**
- 相等时写成 `hi = mid`：`[3,3,1,3]` 会得到 `3`，正确是 `1`，因为 `mid` 与 `hi` 相等时最小值可能在 `mid` 右边。
- 相等时 `lo += 1`：`[1,3,3]` 会得到 `3`，正确是 `1`，丢掉的左端点可能正是最小值；只有右端点有「替身」可丢。
- 拿 `nums[mid]` 和左端点 `nums[lo]` 比较：数组已经有序（旋转 `n` 次）时失效，`[1,3,5]` 会得到 `5`；有重复时更多情形失效，`[2,2,2,0,1]` 会得到 `1`。

**追问。**
- 重复为什么让最坏变成 `O(n)`：`[1,1,1,0,1,1]` 这样的数组里，那个 `0` 可以在任意位置，任何算法在检查完所有其他位置之前都无法确定它在哪里，下界是 `Ω(n)`。
- 无重复版本（LC 153）：去掉相等分支，`else: hi = mid`，严格 `O(log n)`。
- 要返回最小值的下标：循环结束的 `lo` 是一个最小值的位置，不一定是它第一次出现的位置，`[0,1,1,0]` 返回的是 `3`。
