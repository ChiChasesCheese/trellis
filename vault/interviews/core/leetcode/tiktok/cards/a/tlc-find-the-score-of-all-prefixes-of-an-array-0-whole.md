## Q
**LC 2640 一个数组所有前缀的分数**｜Medium · LC TikTok 热度 62/100

对数组 `arr`，定义转换数组 `conver[i] = arr[i] + max(arr[0..i])`（`max(arr[0..i])` 是前 `i + 1` 个元素的最大值），`arr` 的**分数**是 `conver` 所有元素之和。给长度为 `n` 的数组 `nums`，返回长度为 `n` 的数组 `ans`，其中 `ans[i]` 是前缀 `nums[0..i]` 的分数。`1 <= nums.length <= 10^5`，`1 <= nums[i] <= 10^9`。例：`nums = [2,3,7,5,10]` → `[4,10,24,36,56]`；`nums = [1,1,2,4,8,16]` → `[2,4,8,16,32,64]`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 两层前缀：先做前缀最大值（prefix max），加上本位得到转换数组，再对转换数组做前缀和（prefix sum）；前缀 `nums[0..i]` 的分数就是整体转换数组前 `i + 1` 项之和。`O(n)`。

**识别。** 「所有前缀的某个量」+ 量本身是「前缀最大值」，是前缀聚合再叠一层前缀和的信号。关键观察：`conver[j]` 只依赖 `nums[0..j]`，所以前缀 `nums[0..i]` 的转换数组恰好等于整体转换数组的前 `i + 1` 项，不必对每个前缀重算。`n = 10^5` 排除 `O(n^2)`。

**推导。** 暴力：对每个 `i` 重新扫一遍前缀、边扫边维护最大值再求和，`O(n^2)`。浪费：相邻两个前缀的转换数组只差最后一项。洞察：转换数组只算一次；`ans[i] = ans[i-1] + conver[i]`。最优：一次扫描维护「当前最大值」，同时累加。

```python
from itertools import accumulate


def find_prefix_score(nums: list[int]) -> list[int]:
    prefix_max = accumulate(nums, max)                    # 前缀最大值：max(nums[0..i])
    conver = (x + m for x, m in zip(nums, prefix_max))    # 转换数组 conver[i] = nums[i] + max(nums[0..i])
    return list(accumulate(conver))                       # 前缀分数 = conver 的前缀和
```

**运行。** `[2,3,7,5,10]` → `[4, 10, 24, 36, 56]`；`[1,1,2,4,8,16]` → `[2, 4, 8, 16, 32, 64]`；`[5]` → `[10]`；`[3,3,3]` → `[6, 12, 18]`；十万个 `10^9` 时最后一项是 `200000000000000`（约 `2 * 10^14`，超出 32 位整数）。

**复杂度。** 时间 `O(n)`；除输出外额外空间 `O(1)`（`accumulate` 和生成器都是惰性的）。

**易错点。**
- 把「前缀最大值」写成「全局最大值」：`[2,3,7,5,10]` 里 `ans[0]` 会变成 `2 + 10 = 12`，正确是 `4`。
- 只加一次最大值，写成 `前缀和 + 前缀最大值`：`ans[2]` 得 `12 + 7 = 19`，正确是 `4 + 6 + 14 = 24`；每个位置都要加**各自**的前缀最大值。
- 数值会超过 32 位：Java / C++ 里用 `long`；Python 没有这个问题，但面试时要说出来。

**追问。**
- 数据逐个到来（流式）：只保留 `run_max` 和 `total` 两个变量，每个元素 `O(1)`。
- 要求原地、不开新数组：用 `run_max`、`total` 两个变量边扫边把 `nums[i]` 覆盖成答案。
- 问任意子数组 `[l, r]` 的分数：最大值从 `l` 起算，不再是普通前缀和，需要单调栈之类的工具，是另一类题。

**同模式。** LC 1480 一维数组的动态和、LC 724 寻找数组的中心下标、LC 238 除自身以外数组的乘积、LC 121 买卖股票的最佳时机（前缀最小值）。
