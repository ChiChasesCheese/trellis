## Q
**LC 41 缺失的第一个正数**｜Hard · CodeTop 国内累计 74 次 · 最近 2026-06-16（CodeTop）

给一个未排序的整数数组 `nums`，找出其中没有出现的最小的正整数。要求时间复杂度 `O(n)`，并且只使用常数级别的额外空间。`1 <= nums.length <= 10^5`，`-2^31 <= nums[i] <= 2^31 - 1`。例：`nums = [1,2,0]` → `3`；`nums = [3,4,-1,1]` → `2`；`nums = [7,8,9,11,12]` → `1`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 答案一定落在 `[1, n+1]`。把每个落在 `[1, n]` 内的数 `x` 交换到下标 `x - 1` 的位置（把数组本身当哈希表，也叫循环排序），然后第一个 `nums[i] != i + 1` 的 `i + 1` 就是答案；如果每个位置都对，答案是 `n + 1`。`O(n)` 时间，`O(1)` 额外空间。

**识别。** 「最小的缺失正整数」+「`O(n)` 时间、`O(1)` 空间」：排序是 `O(n log n)`，哈希集合要 `O(n)` 空间，都不行。突破口是一个范围观察：长度为 `n` 的数组最多装下 `1..n` 这 `n` 个正整数，所以答案至多是 `n + 1`；非正数、大于 `n` 的数、重复的数，对答案都没用。于是可以用数组自己的下标当作键：数 `x` 的「家」是下标 `x - 1`。

**推导。** 暴力：对 `k = 1, 2, 3, …` 逐个在数组里线性查找，`O(n^2)`；用集合是 `O(n)` 时间但 `O(n)` 空间；排序后扫描是 `O(n log n)`。洞察：只关心 `[1, n]` 内的数，并且数组恰好有 `n` 个格子 → 让每个数回到自己的家。回完之后，第一个「住了别人」的格子，它对应的数 `i + 1` 就没有出现。每次交换都至少让一个数回到家，一个数一旦回家就不会再被换走，所以总交换次数至多 `n`，整体 `O(n)`，尽管外面套了 `while`。

```python
def first_missing_positive(nums: list[int]) -> int:
    n = len(nums)
    for i in range(n):
        # 把每个落在 [1, n] 的数 x 送到下标 x - 1；目标位置已是 x 就停（重复值）
        while 1 <= nums[i] <= n and nums[nums[i] - 1] != nums[i]:
            j = nums[i] - 1             # 先把目标下标存下来，下面交换会改 nums[i]
            nums[i], nums[j] = nums[j], nums[i]
    for i, x in enumerate(nums):        # 第一个"站错位"的下标就是答案
        if x != i + 1:
            return i + 1
    return n + 1                        # 1..n 全在，答案只能是 n + 1
```

运行：`[1,2,0]` → `3`，`[3,4,-1,1]` → `2`，`[7,8,9,11,12]` → `1`，`[1]` → `2`，`[2]` → `1`，`[1,1]` → `2`，`10^5` 个打乱的 `1..n` → `100001`。

**复杂度。** 时间 `O(n)`：每次交换让一个数归位，至多 `n` 次；空间 `O(1)`，会修改输入数组。

**易错点。**
- 用元组一行交换 `nums[i], nums[nums[i] - 1] = nums[nums[i] - 1], nums[i]`：Python 先给左边第一个目标 `nums[i]` 赋值，第二个目标的下标 `nums[i] - 1` 再用**新值**计算，写到了错误位置。`[3,4,-1,1]` 会陷入死循环。先 `j = nums[i] - 1` 存下目标下标。
- 不检查目标位置是否已经是 `x`（`nums[nums[i] - 1] != nums[i]`）：遇到重复值 `[1,1]` 会和自己无限交换，死循环。
- 条件里先写 `nums[nums[i] - 1]` 再判范围：`-1`、`0` 或超大的值会取到错误位置或 `IndexError`。`1 <= nums[i] <= n` 必须在前，靠短路保护。
- 最后返回 `n` 而不是 `n + 1`：`[1,2,0]` 的 `1..n` 都在，答案是 `3`。

**追问。**
- 不允许改输入：先拷贝一份（`O(n)` 空间），或用集合 `set(nums)` 从 `1` 数起，`O(n)` 空间，这是不满足 `O(1)` 要求时最简洁的写法。
- 为什么是 `while` 不是 `if`：换过来的数还没归位，可能仍在 `[1, n]` 里，要继续送。
- 相关变体：数组里 `1..n` 恰好缺一个数（LC 268）、找出所有消失的数（LC 448）、找出所有重复的数（LC 442），都是同一个「下标当哈希」的技巧。

**同模式。** LC 268 丢失的数字、LC 287 寻找重复数、LC 442 数组中重复的数据、LC 448 找到所有数组中消失的数字、LC 645 错误的集合。
