## Q
**鱼塘捕鱼（产量递减）**｜Hard · TikTok 高频

有 `n` 个鱼塘，第 `i` 个鱼塘第一次捕鱼能捞到 `fish[i]` 条，之后每捕一次，这个鱼塘下一次的收获减少 `decay[i]` 条（不会低于 `0`）。你一共有 `t` 个时间单位，每个时间单位选一个鱼塘捕一次。求最多能捞到多少条鱼。`1 <= n <= 10^5`，`0 <= fish[i], decay[i] <= 10^9`，`1 <= t <= 10^9`。

例：`fish = [10, 6]`，`decay = [4, 1]`，`t = 3`：先捞鱼塘 0 得 `10`，再捞鱼塘 0 得 `6` 或鱼塘 1 得 `6`，再捞剩下那个最大的，共 `22`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 每个鱼塘的收获序列 `fish, fish - decay, fish - 2·decay, ...` 不增，所以答案就是把所有鱼塘的所有收获放进一个大集合后**最大的 `t` 个之和**。`t` 太大不能逐个取，改为二分**阈值** `x`：找最大的 `x`，使“收获 `>= x` 的机会不少于 `t` 个”；严格大于 `x` 的机会全拿（每塘一个等差数列，直接求和），剩下的名额每次恰好拿到 `x`。`O(n log n + n log max(fish))`。

**识别。** 「每次选一个、收益递减」是贪心：每一步取当前最大的边际收益。「`t` 到 `10^9`」排除逐步模拟，转为“第 `t` 大的值是多少”，对**答案（阈值）二分**：`count(>= x)` 随 `x` 增大单调不增，这是二分的前提。同一类：LC 1648 销售价值减少的颜色球（`decay = 1`）、LC 378 有序矩阵中第 K 小的元素、LC 875 爱吃香蕉的珂珂。

**推导。** 暴力：模拟 `t` 步，每步扫 `n` 个鱼塘找最大，`O(t · n)`。堆：每步弹出当前最大产量的鱼塘，减去 `decay` 再放回，`O(t log n)`，`t = 10^9` 不行。浪费：堆其实是在按从大到小的顺序把所有收获一个个列出来，而我们只要前 `t` 个的和。洞察：设第 `t` 大的值是 `x`，那么严格大于 `x` 的收获有 `< t` 个，每个鱼塘里它们是序列的一个前缀，等差数列 `f, f - d, ...` 的前 `k` 项和是 `k·f - d·k·(k-1)/2`，`O(1)` 求出；剩下的名额全是 `x`。`x` 用二分找：每塘 `>= x` 的个数是 `(f - x) // d + 1`，对 `n` 个塘求和，`O(n)`。

```python
def count_at_least(ponds: list[tuple[int, int]], x: int, cap: int) -> int:
    """单次产量 >= x 的捕鱼机会共有多少个（数到 cap 就停）。ponds 按首捞量降序。"""
    total = 0
    for f, d in ponds:
        if f < x:
            break                                    # 降序排列：后面的塘首捞量更小，都不够
        if d == 0:
            return cap                               # 这个塘永远产 f >= x：机会无限，直接记满
        total += (f - x) // d + 1                    # f, f-d, f-2d, ... 里 >= x 的项数
        if total >= cap:
            return cap
    return total


def find_threshold(ponds: list[tuple[int, int]], t: int) -> int:
    """最大的 x >= 1，使得 count_at_least(x) >= t；所有正产量加起来都不足 t 次时返回 0。"""
    if count_at_least(ponds, 1, t) < t:
        return 0
    lo, hi = 1, ponds[0][0]
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if count_at_least(ponds, mid, t) >= t:
            lo = mid
        else:
            hi = mid - 1
    return lo


def max_fish(fish: list[int], decay: list[int], t: int) -> int:
    ponds = sorted(((f, d) for f, d in zip(fish, decay) if f > 0), reverse=True)   # 产量为 0 的塘没用
    if not ponds:
        return 0
    x = find_threshold(ponds, t)
    taken = total = 0
    for f, d in ponds:
        if f <= x:
            break                                    # 严格大于 x 的机会才全拿
        k = (f - x - 1) // d + 1                     # f, f-d, ... 里 >= x+1 的项数（f > x 时 d > 0）
        taken += k
        total += k * f - d * k * (k - 1) // 2        # 等差数列求和
    return total + (t - taken) * x                   # 剩下的名额，每次恰好拿到 x
```

运行：`fish = [10, 6]`、`decay = [4, 1]`、`t = 3` → `22`；`[5]`、`[5]`、`t = 4` → `5`（第 2 次起收获是 `0`）；`[0, 0]`、`[1, 1]`、`t = 5` → `0`；`[7]`、`[0]`、`t = 10^9` → `7000000000`；`[3, 3]`、`[1, 1]`、`t = 3` → `8`（收获 `3, 3, 2, 2, 1, 1` 的前 3 大）；`[10^9]`、`[1]`、`t = 10^9` → `500000000500000000`。

**复杂度。** 排序 `O(n log n)`；二分约 `log2(max fish) ≈ 30` 轮，每轮 `O(n)`（有早停）；总计 `O(n log n + n log max(fish))`，空间 `O(n)`。

**易错点。**
- 阈值处并列：`[3, 3]`、`[1, 1]`、`t = 3`。把所有 `>= x = 2` 的机会都拿，得 `3 + 3 + 2 + 2 = 10`，多拿了一次；只拿严格大于 `x` 的又忘了补 `(t - taken) * x`，得 `6`；正确是 `8`。
- 一个塘榨干再换下一个：`[10, 6]`、`[4, 1]`、`t = 3` 得 `10 + 6 + 2 = 18`，正确是 `22`。
- 不在 `0` 处截断：`[5]`、`[5]`、`t = 4` 的序列 `5, 0, -5, -10` 加起来是 `-10`，正确是 `5`。
- `decay = 0` 当普通塘算：`(f - x) // d` 除零；`[7]`、`[0]`、`t = 10^9` 的正确答案是 `7000000000`，这种塘的机会是无限的，要单独记满。

**追问。**
- 输出方案（每塘捕几次）：二分得到 `x` 后，每塘取 `(f - x - 1) // d + 1` 次，剩下的名额分给“序列里恰好有一个 `x`”的塘。
- 每个塘最多捕 `c[i]` 次：`count(>= x)` 里每塘取 `min(c[i], (f - x) // d + 1)`，其余不变。
- `t` 很小（如 `<= 10^6`）：堆模拟更直观，`O(t log n)`。

**同模式。** LC 1648 销售价值减少的颜色球、LC 378 有序矩阵中第 K 小的元素、LC 719 找出第 K 小的数对距离、LC 875 爱吃香蕉的珂珂、LC 1011 在 D 天内送达包裹的能力。
