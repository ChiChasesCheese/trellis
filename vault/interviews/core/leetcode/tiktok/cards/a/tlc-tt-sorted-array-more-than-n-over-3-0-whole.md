## Q
**有序数组中出现次数超过 n/3 的数**｜Medium · TikTok 高频

给一个长度 `n >= 3` 的非递减有序整数数组 `nums`，找出所有出现次数大于 `n / 3` 的数字，按升序返回。要求时间复杂度低于 `O(n)`，要利用有序性。`3 <= n <= 10^6`。例：`[1,2,3]` → `[]`；`[1,1,2,3,4]` → `[1]`；`[1,1,2,4,4]` → `[1,4]`；`[1,2,3,4,5,6,7]` → `[]`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 令 `step = n // 3`。出现次数大于 `n / 3` 就是至少 `step + 1` 次，而相同的值在有序数组里占一段连续下标，任何 `step + 1` 个连续下标里一定含有 `step` 的倍数，所以这个值一定出现在下标 `0, step, 2*step, ...` 中的某一个；只检查这至多 5 个候选，每个用两次二分算出现次数。`O(log n)`。

**识别。** 「有序数组 + 统计某个值出现几次」是 `bisect_left` / `bisect_right` 两次二分；「超过 `n/3`」意味着答案最多两个，且一定是一大段连续块；「复杂度低于 `O(n)`」说明不能读完整个数组，只能抽样一些位置再验证。

**推导。** 暴力：`Counter` 数一遍，`O(n)` 时间 `O(n)` 空间；利用有序性，一遍扫描统计每段长度，`O(n)` 时间 `O(1)` 空间，但仍要读完整个数组 → 浪费：为了找几个很长的块，把每个元素都读了一遍 → 洞察：长块不会藏起来——长度至少 `step + 1` 的块必定覆盖某个 `step` 的倍数下标，于是候选值只有 `nums[0]`、`nums[step]`、`nums[2*step]`…… 常数个，每个用二分在 `O(log n)` 内数出它的出现次数，用整数比较 `3 * 次数 > n` 判断是否超过三分之一。

```python
from bisect import bisect_left, bisect_right


def more_than_third(nums: list[int]) -> list[int]:
    n = len(nums)
    step = n // 3                                        # 出现次数 > n/3，即至少 step + 1 次
    ans: list[int] = []
    for v in sorted({nums[i] for i in range(0, n, step)}):   # 候选：每隔 step 取一个下标上的值，至多 5 个
        if 3 * (bisect_right(nums, v) - bisect_left(nums, v)) > n:   # 整数比较避免 n / 3 的浮点
            ans.append(v)
    return ans
```

运行：`[1,2,3]` → `[]`；`[1,1,2,3,4]` → `[1]`；`[1,1,2,4,4]` → `[1, 4]`；`[1,2,3,4,5,6,7]` → `[]`；`[5,5,5]` → `[5]`；`[1,1,1,2,2,2]` → `[1, 2]`；`[1,1,2,2,3,3]` → `[]`；`10^6` 个元素（三个值各约三分之一，`1` 多一个）→ `[1]`。

**复杂度。** 时间 `O(log n)`：至多 5 个候选，每个两次二分；空间 `O(1)`。

**易错点。**
- 把「大于」写成「大于等于」：`[1,1,2,2,3,3]` 每个值恰好 `n / 3` 次，不应入选，写成 `>=` 会得到 `[1, 2, 3]`，正确是 `[]`。
- 只检查一个位置（比如多数元素的 `nums[n // 2]` 套路）：`[1,1,2,4,4]` 只看 `nums[n // 3]` 得到 `[1]`，漏掉 `4`，正确是 `[1, 4]`。超过 `n/3` 的值最多两个，候选要覆盖整个数组。
- 用浮点比较 `count > n / 3`：`n` 很大时不会出错，但整数比较 `3 * count > n` 更稳，也更容易说明。

**追问。**
- 超过 `n/k` 的值：`step = n // k`，候选仍是每隔 `step` 取一个，数量 `O(k)`，总成本 `O(k log n)`。
- 数组无序、要求 `O(n)` 时间 `O(1)` 空间：Boyer–Moore 多数投票的推广，维护 `k - 1` 个候选和计数器，再验证一遍（LC 229）。
- 数组放在磁盘 / 远程：二分只做 `O(log n)` 次随机读，而扫描要读全部。

**同模式。** LC 229 多数元素 II、LC 169 多数元素、LC 34 在排序数组中查找元素的第一个和最后一个位置、LC 1150 检查数字是否为排序数组中的多数元素。
