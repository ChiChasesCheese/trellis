## Q
**手写数字转字符串**｜Medium · 近一年被问：美国 0 次、国内 1 次 · 最近 2026-10-22（面试记录）

不使用 `str`、`repr`、`format`、f-string，把数转成十进制字符串（`chr`、`ord`、`divmod`、`"".join` 可以用）。

第一步：64 位有符号整数 `n`（`-2^63 <= n < 2^63`），注意 `0` 和负数。第二步：整数部分与小数部分分开表示的十进制数 `(sign, int_part, frac_value, frac_len)`：`sign` 是 `-1` 或 `1`，`int_part >= 0` 是整数部分，`frac_value` 是小数部分当作整数读出的值（`0 <= frac_value < 10^frac_len`），`frac_len` 是小数位数（`0 <= frac_len <= 1000`）。输出规范写法：去掉小数末尾的 `0`，小数全为 `0` 时不输出小数点，数值为 `0` 时不带负号。

例：`-12.050` 表示为 `(-1, 12, 50, 3)`，输出 `"-12.05"`；`(1, 0, 5, 3)` 输出 `"0.005"`；`n = -2^63` 输出 `"-9223372036854775808"`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 整数：反复 `divmod(n, 10)`，余数是最低位，低位先出，最后整体反转；`0` 和负号单独处理。小数：整数部分照旧；小数部分去掉末尾的 `0`（`frac_value` 除以 `10`、`frac_len` 减一），再把 `frac_value` 转成数字串，**在左边补回前导 `0`** 凑够 `frac_len` 位。

**识别。** 「禁用内置转换」就是考基数分解（radix conversion）：任何进制转换都是“取余得最低位、整除去掉最低位”。第二步的小数用整数加位数表示，是为了避开浮点误差，考点转成两个整数细节：前导 `0` 会在“当整数读”时丢失，所以要靠 `frac_len` 补；末尾 `0` 要去掉；符号要看整个数值。

**推导。** 想法一：从高位往低位取，需要先知道位数，要先算 `10^k`，绕远。想法二：`n % 10` 取最低位，`n // 10` 去掉最低位，循环到 `0` 为止；低位先出，所以最后反转。三个边界：`n = 0` 循环一次都不进，要特判；负数：先记下符号再取绝对值，因为 Python 的 `//`、`%` 向下取整，对负数会给出负方向的商和非负余数（`divmod(-12, 10)` 是 `(-2, 8)`），数字全错；`-2^63` 在 64 位语言里取绝对值会溢出，Python 的整数没有这个问题，但要知道原因。小数部分：把 `frac_value` 当整数转字符串会丢掉前导 `0`（`5` 变成 `"5"`，应是 `"005"`），所以用 `frac_len` 减去数字个数补零。

```python
def int_to_str(n: int) -> str:
    if n == 0:
        return "0"
    neg = n < 0
    n = -n if neg else n                       # 先取绝对值：Python 的 divmod 对负数向下取整，会得到负的余数位
    digits: list[str] = []
    while n:
        n, d = divmod(n, 10)                   # 一次同时拿商和余数
        digits.append(chr(48 + d))             # 48 是 '0' 的编码；d 是 0..9
    if neg:
        digits.append("-")
    return "".join(reversed(digits))           # 低位先出，最后整体反转


def decimal_to_str(sign: int, int_part: int, frac_value: int, frac_len: int) -> str:
    while frac_len and frac_value % 10 == 0:   # 去掉小数末尾的 0：frac_value 缩小十倍，位数减一
        frac_value //= 10
        frac_len -= 1
    out = int_to_str(int_part)
    if frac_len:                               # frac_len == 0 说明小数部分全为 0：不输出小数点
        frac = int_to_str(frac_value)
        out += "." + "0" * (frac_len - len(frac)) + frac   # 左边补回被整数表示吞掉的前导 0
    if sign < 0 and (int_part or frac_len):    # 数值为 0 时不输出负号，避免 "-0"
        out = "-" + out
    return out
```

运行：`int_to_str` 对 `0`、`5`、`-5`、`120`、`-2^63`、`2^63 - 1` 得 `"0"`、`"5"`、`"-5"`、`"120"`、`"-9223372036854775808"`、`"9223372036854775807"`；`decimal_to_str`：`(-1, 12, 50, 3)` → `"-12.05"`，`(1, 0, 5, 3)` → `"0.005"`，`(-1, 0, 5, 2)` → `"-0.05"`，`(-1, 0, 0, 2)` → `"0"`，`(1, 7, 0, 4)` → `"7"`，`(1, 3, 100, 3)` → `"3.1"`，`(1, 100, 0, 0)` → `"100"`。

**复杂度。** 时间 `O(d)`，`d` 是数字位数（整数至多 `19` 位，小数 `O(frac_len)`）；空间 `O(d)`。

**易错点。**
- `n = 0` 不特判：循环不进，返回空串 `""`，应是 `"0"`。
- 直接对负数做 `divmod(n, 10)`：`divmod(-1, 10)` 是 `(-1, 9)`，`n` 永远到不了 `0`，循环**不会结束**。
- 小数前导 `0` 丢失：`(1, 0, 5, 3)` 把 `5` 直接转成 `"5"` 拼接得到 `"0.5"`，正确是 `"0.005"`。
- 小数全为 `0` 或符号：`(1, 7, 0, 4)` 错成 `"7.0"` 或 `"7."`，正确是 `"7"`；`(-1, 0, 0, 2)` 错成 `"-0"`，正确是 `"0"`；只看 `int_part` 判断符号，`(-1, 0, 5, 2)` 会丢掉负号得到 `"0.05"`，正确是 `"-0.05"`。

**追问。**
- 直接给浮点数 `x`、保留 `k` 位四舍五入：不能 `x * 10**k` 再取整，乘法本身会舍入，`2.675 * 100` 得到 `267.5`，取整得 `2.68`，而 `2.675` 实际存的是 `2.67499999...`，正确是 `2.67`；正解是 `x.as_integer_ratio()` 拿到精确分数，用整数运算舍入。
- 64 位语言怎么办：不取绝对值，在负数一侧累积，`-2^63` 才不会溢出。
- 其他进制：把 `chr(48 + d)` 换成查字符表 `DIGITS[d]`（`DIGITS` 是按顺序排好 0 到 9、a 到 f 的字符串）。

**同模式。** LC 8 字符串转换整数、LC 7 整数反转、LC 12 整数转罗马数字、LC 168 Excel 表列名称、LC 415 字符串相加、LC 66 加一。
