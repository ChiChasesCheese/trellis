## Q
**LC 1330 翻转子数组得到最大的数组值**｜Hard · CodeTop 国内累计 1 次 · 最近 2026-07-02（CodeTop）

给整数数组 `nums`，「数组值」定义为所有 `0 <= i < nums.length - 1` 的 `|nums[i] - nums[i+1]|` 之和。你可以选择任意一个子数组并把它翻转，但**只能操作一次**。返回可能得到的最大数组值。`2 <= nums.length <= 3 * 10^4`，`-10^5 <= nums[i] <= 10^5`，答案保证在 32 位整数范围内。例：`nums = [2,3,1,5,4]` → `10`（翻转 `[3,1,5]` 得 `[2,5,1,3,4]`，数组值 `3 + 4 + 2 + 1 = 10`）；`nums = [2,4,9,24,2,1,10]` → `68`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 翻转一个子数组，只会改变它**两端**的两条相邻差，内部的相邻差不变（`|a - b|` 对称）。把每对相邻数看成数轴上的线段 `[min, max]`：翻转贴着数组端点的子数组时，直接算一条边的变化；翻转在中间时，两条不相交的线段间隔为 `g`，最多多赚 `2g`，所以增益是 `2 * (最大的左端点 - 最小的右端点)`。取各种情形的最大增益，加到原数组值上。`O(n)`。

**识别。** 「只翻转一次」+「相邻差的绝对值之和」：翻转只影响边界，问题从「改动整个数组」缩小成「选两个边界，让它们的变化最大」。`n = 3 * 10^4` 使 `O(n^2)` 的枚举（约 `4.5 * 10^8` 对 `(l, r)`）在 Python 里太慢，需要把 `max` 里的配对拆开。

**推导。** 暴力：枚举 `(l, r)` 翻转后重算，`O(n^3)`。优化：增益只和 `nums[l-1]`、`nums[l]`、`nums[r]`、`nums[r+1]` 有关，`O(1)` 算一对，总共 `O(n^2)`。洞察：翻转中间一段（两个边界是相邻对 `(a[i], a[i+1])` 和 `(a[j], a[j+1])`，`i < j`）的增益是 `|a[i] - a[j]| + |a[i+1] - a[j+1]| - |a[i] - a[i+1]| - |a[j] - a[j+1]|`。当第二条线段整个在第一条的右边，前两项去掉绝对值后，等于「右边线段两端点之和」减「左边线段两端点之和」；再减去两条线段的长度，剩下 `2 * (右边线段的左端点 - 左边线段的右端点)`；线段相交时增益不会为正。所以中间情形的最大增益就是 `2 * (max lo - min hi)`，一次扫描求出。

```python
from itertools import pairwise


def max_value_after_reverse(nums: list[int]) -> int:
    n = len(nums)
    total = sum(abs(a - b) for a, b in pairwise(nums))
    # 情况一：翻转的区间不含两端。相邻两数 (a, b) 看成数轴上的线段 [min, max]，
    # 两条不相交的线段间隔 g，翻转它们之间的部分能多赚 2g
    lo = max(min(a, b) for a, b in pairwise(nums))       # 所有线段左端点里最大的
    hi = min(max(a, b) for a, b in pairwise(nums))       # 所有线段右端点里最小的
    gain = max(0, 2 * (lo - hi))
    # 情况二：翻转的区间顶着数组的左端或右端，只改动一条相邻差
    for i in range(1, n):
        gain = max(gain,
                   abs(nums[0] - nums[i]) - abs(nums[i - 1] - nums[i]),            # 翻转 [0, i-1]
                   abs(nums[-1] - nums[i - 1]) - abs(nums[i - 1] - nums[i]))       # 翻转 [i, n-1]
    return total + gain
```

运行：`[2,3,1,5,4]` → `10`，`[2,4,9,24,2,1,10]` → `68`，`[1,2]` → `1`，`[5,5]` → `0`，`[1,5,4]` → `7`，`[-100000,100000]` → `200000`。

**复杂度。** 时间 `O(n)`：求和、求最大最小、边界扫描各一趟；空间 `O(1)`（`pairwise` 是迭代器，不建中间列表）。

**易错点。**
- 漏掉贴着端点的情形：`[1,5,4]` 只算中间情形得 `5`，翻转前缀 `[1,5]` 得 `[5,1,4]`，数组值 `7`，才是正确答案。
- 增益误写成 `2 * (整个数组的最大值 - 最小值)`：`[2,3,1,5,4]` 得 `8 + 8 = 16`，正确 `10`。必须是「最大的线段左端点」减「最小的线段右端点」。
- 以为翻转会改变内部的相邻差：不会，`|a - b| = |b - a|`，翻转后内部相邻对只是反向。

**追问。**
- 返回具体的 `(l, r)`：记录取到最大左端点的线段下标 `q` 和最小右端点的线段下标 `p`，翻转 `[min(p, q) + 1, max(p, q)]`。
- 不用几何怎么推：增益里两个带正号的绝对值各拆成两种符号，共 4 种组合；两种异号组合最多为 `0`，两种同号组合恰好是 `2 * (lo_i - hi_j)` 和 `2 * (lo_j - hi_i)`。
- `n` 到 `10^6`：本解法已经是 `O(n)`，只需要保证是一趟扫描。
