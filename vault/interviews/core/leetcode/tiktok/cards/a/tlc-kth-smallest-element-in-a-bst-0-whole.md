## Q
**LC 230 二叉搜索树中第 K 小的元素**｜Medium · CodeTop 国内累计 23 次 · 最近 2024-04-10（CodeTop）

给二叉搜索树的根节点 `root` 和整数 `k`，返回树中第 `k` 小的元素（`k` 从 `1` 开始）。节点数 `n`，`1 <= k <= n <= 10^4`，`0 <= Node.val <= 10^4`。例：`root = [3,1,4,null,2]`、`k = 1` → `1`；`root = [5,3,6,2,4,null,null,1]`、`k = 3` → `3`。进阶：树经常被修改（插入 / 删除）且要频繁查第 `k` 小，怎么优化？

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 二叉搜索树（BST）的中序遍历是升序，所以做迭代中序遍历，数到第 `k` 个节点立刻返回；不用遍历整棵树。`O(h + k)`。

**识别。** 「BST + 第 k 小 / 有序」直接对应中序遍历：左子树的所有值 < 根 < 右子树的所有值，中序「左、根、右」正好按升序吐出节点。`n` 到 `10^4`，退化成链时深度 `10^4`，超过 Python 递归上限 `1000`，所以用显式栈。

**推导。** 暴力：遍历整棵树收集全部值，排序后取第 `k - 1` 位，`O(n log n)` → 浪费：BST 已经按结构排好序，排序是白做；而且 `k` 小的时候没必要读完整棵树 → 先中序收集到列表再取下标，`O(n)` → 再改成边走边数，第 `k` 个出栈就返回，`O(h + k)` → 进阶：频繁修改又频繁查询时，每个节点多存一个「子树大小」，查询时按大小逐层向下，`O(h)`。

```python
def kth_smallest(root: TreeNode | None, k: int) -> int:
    stack: list[TreeNode] = []
    node = root
    while stack or node:
        while node:                    # 一路向左，沿途入栈
            stack.append(node)
            node = node.left
        node = stack.pop()             # 弹出的顺序就是升序
        k -= 1
        if k == 0:
            return node.val
        node = node.right
    raise ValueError("k 超过节点数")
```

运行：`[3,1,4,null,2]`、`k=1` → `1`；`[5,3,6,2,4,null,null,1]`、`k=3` → `3`；`10^4` 个节点的右链，`k=10000` → `9999`（链上的最大值），`k=1` → `0`。

**复杂度。** 时间 `O(h + k)`：先下到最左要 `h` 步，之后每弹出一个节点摊销 `O(1)`；空间 `O(h)`，栈里最多一条路径。

**易错点。**
- 在入栈时计数而不是出栈时计数，会数成「先序」位置：`[5,3,6,2,4,null,null,1]`、`k=3` 得到 `2`，正确是 `3`。
- 用先序或后序遍历后取第 `k` 个：同样顺序不对，先序取第 `3` 个也得到 `2`。
- 递归 / 生成器版本在 `10^4` 的链上会 `RecursionError`；不要靠调大递归上限。

**追问。**
- 频繁修改 + 频繁查询：每个节点维护子树大小 `size`，查询时左子树大小 `>= k` 去左边，`== k - 1` 就是当前，否则 `k -= 左 + 1` 去右边，`O(h)`；插入 / 删除沿路径更新 `size`。
- 第 `k` 大：镜像遍历（右、根、左），或者用 `n - k + 1`。
- 多次查询、树不变：中序一次存数组，之后每次 `O(1)`；或者用 BST 迭代器（LC 173）按需产出。
