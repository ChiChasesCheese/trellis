## Q
**LC 455 分发饼干**｜Easy · CodeTop 国内累计 2 次 · 最近 2026-03-16（CodeTop）

每个孩子最多分到一块饼干。孩子 `i` 的胃口值是 `g[i]`，饼干 `j` 的尺寸是 `s[j]`，`s[j] >= g[i]` 时饼干 `j` 能满足孩子 `i`。求最多能满足多少个孩子。`1 <= g.length <= 3 * 10^4`，`0 <= s.length <= 3 * 10^4`，`1 <= g[i], s[j] <= 2^31 - 1`。 例：`g = [1,2,3], s = [1,1]` → `1`（两块饼干尺寸都是 1，只能满足胃口为 1 的孩子）；`g = [1,2], s = [1,2,3]` → `2`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 排序 + 双指针贪心：饼干从小到大看，每块尽量给「胃口最小的、还没满足的孩子」，满足不了就扔掉；`O(n log n + m log m)`。

**识别。** 「两组对象一对一配对 + 配对要满足阈值 + 最大化配对数」→ 排序后贪心，用交换论证（exchange argument）证明。数量到 `3 * 10^4`，通用的二分图匹配算法不必要。

**推导。** 暴力：枚举所有分配方式，指数级；当成二分图最大匹配也远比需要的重。观察两点：一块小饼干如果连胃口最小的孩子都满足不了，它对谁都没用，扔掉不亏；能满足时，给胃口最小的孩子最划算，把更大的饼干留给更挑剔的孩子。两组都排序后，一个指针扫饼干、一个指针指向下一个待满足的孩子，一趟完成。

```python
def find_content_children(g: list[int], s: list[int]) -> int:
    greed = sorted(g)                      # 胃口从小到大
    child = 0                              # 下一个待满足的孩子；也等于已满足的人数
    for size in sorted(s):                 # 饼干从小到大
        if child < len(greed) and size >= greed[child]:
            child += 1                     # 这块饼干给当前胃口最小的孩子
        # 否则这块饼干连最小的胃口都满足不了，丢掉
    return child
```

运行：`g = [1,2,3], s = [1,1]` → `1`，`g = [1,2], s = [1,2,3]` → `2`，`g = [5], s = []` → `0`，`g = [1,2], s = [2,1]` → `2`。

**复杂度。** 时间 `O(n log n + m log m)`：两次排序，扫描 `O(m)`；空间 `O(n + m)`：`sorted` 返回的新列表。

**易错点。**
- 不排序，按输入顺序给每个孩子第一块够大的饼干：`g = [1,2], s = [2,1]` 时胃口 1 的孩子拿走了尺寸 2，胃口 2 的孩子只剩尺寸 1，得到 `1`（正确 `2`）。
- 孩子从小到大，但每次给最大的饼干：`g = [1,2], s = [1,2]` 得到 `1`（正确 `2`），大饼干浪费在小胃口上。
- `s` 可以为空：循环一次也不执行，返回 `0`，不需要特判。

**追问。**
- 反过来贪心：孩子从胃口大到小，用当前最大的饼干试，够就配对、不够就跳过这个孩子，同样正确。
- 输出具体的配对：对下标排序 `sorted(range(len(g)), key=g.__getitem__)`，配对时记录 `(孩子下标, 饼干下标)`。
- 每条船最多两人、载重上限 `limit`，求最少船数（LC 881）：排序后左右双指针，最重的人一定上船，能带上最轻的就一起走。

**同模式。** LC 2410 运动员和训练师的最大匹配数、LC 881 救生艇、LC 870 优势洗牌、LC 826 安排工作以达到最大收益。
