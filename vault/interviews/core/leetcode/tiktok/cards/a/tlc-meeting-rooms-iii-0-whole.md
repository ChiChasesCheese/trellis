## Q
**LC 2402 会议室 III**｜Hard · LC TikTok 热度 62/100 · 近一年被问：美国 2 次、国内 1 次 · 最近 2026-10（面试记录）

给整数 `n`，有编号 `0` 到 `n - 1` 的 `n` 个会议室。给二维数组 `meetings`，`meetings[i] = [start_i, end_i]` 表示一场在半闭区间 `[start_i, end_i)` 举办的会议，所有 `start_i` **互不相同**。会议按下面规则分配：每场会议在**未占用且编号最小**的会议室举办；若没有空房间，会议延期，直到有房间空出，延期后会议的**持续时间不变**；房间空出来时，**原开始时间更早**的会议优先使用。返回举办会议次数最多的房间编号，如果有多个，返回编号最小的。`1 <= n <= 100`，`1 <= meetings.length <= 10^5`，`meetings[i].length == 2`，`0 <= start_i < end_i <= 5 * 10^5`，`start_i` 互不相同。例：`n = 2`，`meetings = [[0,10],[1,5],[2,7],[3,4]]` → `0`（房间 0 和 1 各举办 2 场）；`n = 3`，`meetings = [[1,20],[2,10],[3,5],[4,9],[6,8]]` → `1`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 按开始时间排序后依次安排，用两个堆维护房间：空闲房间的最小堆（按编号），占用房间的最小堆（按 `(结束时间, 编号)`）。来一场会议，先把已结束的房间放回空闲堆；有空房间就取编号最小的；没有就取最早结束的房间，会议顺延到那个时刻开始，结束时间 = 空出时刻 + 原时长。`O(M log M + M log n)`。

**识别。** 「按规则逐个分配资源」是事件模拟；“编号最小的空房间”“最早空出的房间”这两个选择规则恰好对应**两个最小堆**。`start_i` 互不相同，所以排序后优先级（原开始时间更早的先用）自然成立，不需要额外的队列。`M = 10^5`，`n <= 100`，`O(M · n)` 也能过（见另一种解法），堆是更稳的 `O(M log n)`。

**推导。** 暴力：按时间一秒一秒推进，每秒检查所有房间和待办会议，时间到 `5 * 10^5`，每秒 `O(n + M)`，太慢。浪费：绝大多数时刻什么也没发生。洞察：只有“会议开始”这个事件需要决策，且会议已按开始时间排好序，所以按会议逐个处理即可。每次处理前，把所有已经结束（`结束时间 <= 当前会议开始时间`，半闭区间）的房间从占用堆搬回空闲堆。有空房间就用编号最小的；没有就弹出占用堆里最早空出的房间（并列时编号小的先出，元组比较正好满足），新会议的结束时间是 `空出时刻 + (end - start)`。

```python
from heapq import heappop, heappush


def most_booked(n: int, meetings: list[list[int]]) -> int:
    free = list(range(n))                      # 空闲房间号的最小堆（升序列表本身就是堆）
    busy: list[tuple[int, int]] = []           # (结束时间, 房间号) 的最小堆
    count = [0] * n
    for start, end in sorted(meetings):        # 按开始时间依次安排
        while busy and busy[0][0] <= start:    # 区间半开：结束时间 == start 的房间已空
            heappush(free, heappop(busy)[1])
        if free:
            room = heappop(free)               # 编号最小的空房间
            finish = end
        else:
            ready, room = heappop(busy)        # 最早空出来的房间（同时空出取编号小）
            finish = ready + (end - start)     # 延期：时长不变，从 ready 开始
        count[room] += 1
        heappush(busy, (finish, room))
    return max(range(n), key=count.__getitem__)   # max 取并列里第一个，即编号最小
```

运行：`(2, [[0,10],[1,5],[2,7],[3,4]])` → `0`，`(3, [[1,20],[2,10],[3,5],[4,9],[6,8]])` → `1`，`(1, [[1,2]])` → `0`，`(3, [[0,1]])` → `0`；`n = 100`、`10^5` 场随机会议 → 约 `40 ms`。

**复杂度。** 时间 `O(M log M)` 排序，加每场会议常数次堆操作 `O(M log n)`；空间 `O(n)`（两个堆合计至多 `n` 个房间）加排序的 `O(M)`。

**易错点。**
- 延期会议的结束时间写成原来的 `end`：忘了“持续时间不变”。示例 1 得到 `1`（正确 `0`），示例 2 得到 `2`（正确 `1`）。
- 回收房间的条件写成 `busy[0][0] < start`：半开区间 `[a, b)` 在 `b` 时刻房间已经空了，`结束时间 == start` 也要回收。
- 并列时取最大次数的编号：`max(range(n), key=count.__getitem__)` 对并列值返回第一个遇到的，即编号最小；用 `count.index(max(count))` 同样可以，但写成 `max(count)` 之后取最后一个就错了。

**追问。**
- 房间很多（`n` 到 `10^5`）：堆版本仍然是 `O(M log n)`；扫描版的 `O(M · n)` 会超时。
- 在线（会议不按开始时间到达）：需要用优先队列保存等待中的会议，在房间空出的事件上再弹出开始时间最早的会议，复杂度同阶。
- 统计每个房间的总占用时长：在分配时累加 `finish - 实际开始时刻`。

**同模式。** LC 253 会议室 II、LC 1834 单线程 CPU、LC 1882 使用服务器处理任务、LC 2406 将区间分为最少组数、LC 1851 包含每个查询的最小区间。
