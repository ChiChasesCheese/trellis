## Q
**LC 74 搜索二维矩阵**｜Medium · 字节高频

给 `m x n` 整数矩阵 `matrix`，满足：每行从左到右非严格递增；每行第一个整数大于前一行最后一个整数。判断 `target` 是否在矩阵中，要求时间 `O(log(m * n))`。`1 <= m, n <= 100`，`-10^4 <= matrix[i][j], target <= 10^4`。例：`matrix = [[1,3,5,7],[10,11,16,20],[23,30,34,60]]`，`target = 3` → `true`；`target = 13` → `false`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 两个条件合起来说明：按行优先把矩阵拼成一维数组，它就是一个完整的升序数组；于是在虚拟的一维下标 `[0, m·n)` 上做一次二分，每次用 `divmod(mid, n)` 把一维下标换成（行，列）。`O(log(m·n))`。

**识别。** 「要求 `O(log(m·n))`」+「有序」→ 二分；关键是看出矩阵可以当作一维有序数组（行首大于上一行行尾，保证了行与行之间也有序）。这与 LC 240（每行、每列各自有序，但行间不连续）不同，LC 240 不能压成一维，只能做 `O(m + n)` 的阶梯搜索。

**推导。** 暴力：逐个扫描，`O(m·n)`；或先二分行、再二分列，两次二分合起来也是 `O(log m + log n)` → 浪费：其实不需要两步，两个条件已经让整个矩阵展开后单调 → 虚拟一维数组上二分，不创建新数组，只在访问时换算下标：行 = `mid // n`，列 = `mid % n`，一次 `divmod` 搞定 → 二分模板用左闭右开的"第一个 `>= target`"，最后检查等于。

```python
def search_matrix(matrix: list[list[int]], target: int) -> bool:
    m, n = len(matrix), len(matrix[0])
    lo, hi = 0, m * n                      # 把矩阵按行拼成一维有序数组，二分的区间是 [lo, hi)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        row, col = divmod(mid, n)          # 一维下标 -> 行、列
        if matrix[row][col] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo < m * n and matrix[lo // n][lo % n] == target
```

运行：`([[1,3,5,7],[10,11,16,20],[23,30,34,60]], 3)` → `True`，`(同一矩阵, 13)` → `False`，`([[1]], 1)` → `True`，`([[1]], 0)` → `False`，`([[1,3]], 3)` → `True`；`100 x 100` 的矩阵中查最后一个元素 `9999` → `True`，查 `10000` → `False`。

**复杂度。** 时间 `O(log(m·n))`；空间 `O(1)`。

**易错点。**
- 换算下标时用错了除数：`row = mid // m`、`col = mid % m`（用行数而不是列数）。`2 x 4` 的矩阵里第一个 `mid = 4`，`4 // 2 = 2` 就超过行数，抛 `IndexError`。列数 `n` 才是每行的长度。
- 循环结束后不检查 `lo < m * n`：`target` 比所有元素都大时 `lo == m * n`，换算出的行号越界。
- 把它当成 LC 240（只保证行列各自有序）去写阶梯搜索：结果正确，但是 `O(m + n)`，不满足 `O(log(m·n))`；这里的条件更强，应该用一维二分。

**追问。**
- 标准库：`bisect_left(range(m * n), target, key=lambda k: matrix[k // n][k % n])`，把 `range` 当作虚拟数组（Python 3.10 起支持 `key=`）。
- 每行每列各自升序（LC 240）：从右上角出发，大了左移、小了下移，`O(m + n)`。
- 先二分行、再二分列：先找最后一个"行首 `<= target`"的行，再在该行里二分，`O(log m + log n)`，与一次二分同阶，但分两步更容易写错边界。

**同模式。** LC 240 搜索二维矩阵 II、LC 704 二分查找、LC 35 搜索插入位置、LC 378 有序矩阵中第 K 小的元素。
