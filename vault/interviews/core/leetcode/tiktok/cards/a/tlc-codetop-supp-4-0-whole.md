## Q
**补充题4 手撕快速排序**｜Medium · 字节 高频

给一个整数数组 `nums`，自己实现排序算法把它升序排列并返回（不能调用内置的 `sort` / `sorted`）。要求原地、平均 `O(n log n)`。`1 <= nums.length <= 50000`，`-50000 <= nums[i] <= 50000`，数组中可能有大量重复元素。例：`nums = [5,2,3,1]` → `[1,2,3,5]`；`nums = [5,1,1,2,0,0]` → `[0,0,1,1,2,5]`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 快速排序（quicksort）：随机选一个基准，用**三路划分**把区间分成「小于基准 / 等于基准 / 大于基准」三段，等于基准的那段已经就位；只对两侧继续排序，而且递归较短的一侧、用循环处理较长的一侧，栈深度保持 `O(log n)`。期望 `O(n log n)`，原地。

**识别。** 「手撕排序」考的是分治加原地划分，以及面试官一定会追问的三件事：基准怎么选、重复元素怎么办、递归会不会太深。`n` 到 `5 * 10^4` 并且可能全是相同的数，直接把最后一个元素当基准的朴素写法会退化。

**推导。** 暴力：冒泡或插入排序，`O(n^2)`，`n = 5 * 10^4` 约 `2.5 * 10^9`，超时。归并排序 `O(n log n)`，但需要 `O(n)` 辅助空间。朴素快排（取最后一个元素为基准，两路划分）：平均 `O(n log n)`，但输入已经有序或全部相同时，每次只能切掉一个元素，`O(n^2)`，递归深度也是 `n`，`5 * 10^4` 层会触发 `RecursionError`。三个修正：随机基准让期望时间与输入的排列无关；三路划分让所有等于基准的元素一次就位，全相同数组一轮就结束；先递归较短的一侧，较长的一侧回到循环里，递归深度不超过 `log n`。

```python
import random


def sort_array(nums: list[int]) -> list[int]:
    def quicksort(lo: int, hi: int) -> None:        # 原地排序 nums[lo:hi]
        while hi - lo > 1:
            pivot = nums[random.randrange(lo, hi)]  # 随机基准：不怕有序输入
            lt, i, gt = lo, lo, hi      # 三路划分：[lo,lt) < pivot，[lt,i) == pivot，[gt,hi) > pivot
            while i < gt:
                if nums[i] < pivot:
                    nums[lt], nums[i] = nums[i], nums[lt]
                    lt += 1
                    i += 1
                elif nums[i] > pivot:
                    gt -= 1
                    nums[i], nums[gt] = nums[gt], nums[i]   # 换来的数还没看过，i 不动
                else:
                    i += 1
            if lt - lo < hi - gt:       # 递归较短的一侧，循环处理较长的一侧：栈深 O(log n)
                quicksort(lo, lt)
                lo = gt
            else:
                quicksort(gt, hi)
                hi = lt

    quicksort(0, len(nums))
    return nums
```

运行：`[5,2,3,1]` → `[1, 2, 3, 5]`，`[5,1,1,2,0,0]` → `[0, 0, 1, 1, 2, 5]`，`[1]` → `[1]`，`[2,2,2]` → `[2, 2, 2]`；`5 * 10^4` 个元素的随机、全相同、升序、降序、先升后降、只有 4 种取值的数组都能正确排序，每个都在零点几秒内完成。

**复杂度。** 期望时间 `O(n log n)`，最坏 `O(n^2)`（随机基准下概率极小）；空间 `O(log n)`（递归栈）；原地，不稳定。

**易错点。**
- 取最后一个元素当基准、两路划分、纯递归：升序的 `5 * 10^4` 个数会 `RecursionError`；`5000` 个相同的数要做约 `1.25 * 10^7` 次比较（`n^2 / 2`）。
- 三路划分里，遇到大于基准的元素与 `gt` 交换后，把 `i` 也加了一：换过来的元素还没检查过。`[2,3,1]` 以 `2` 为基准，划分得到 `[2, 1, 3]`，`1` 没被划进左段；正确是 `[1, 2, 3]`。
- 区间开闭混用：本写法的区间是半开区间 `[lo, hi)`，递归 `(lo, lt)` 和 `(gt, hi)`；如果写成 `(lo, lt - 1)` 会漏掉元素。
- 用内置的 `sort` 交差：这类题要求自己实现。

**追问。**
- 快速选择（LC 215 第 `K` 大）：同样的三路划分，只进入包含目标下标的那一侧，期望 `O(n)`。
- 稳定性：快排不稳定；要稳定用归并排序。内置 `list.sort()` 是稳定的 Timsort，对部分有序的输入接近 `O(n)`。
- 最坏情况保证：递归过深时切换到堆排序（introsort），C++ 的 `std::sort` 就是这样。
