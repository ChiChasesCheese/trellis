## Q
**出现次数最多的元素（并列取较小的）**｜Easy · 近一年被问：美国 1 次、国内 0 次 · 最近 2026-07-15（美国面试记录）

给整数数组 `nums`，返回出现次数最多的元素；有多个元素并列最多时，返回**数值最小**的那个。`1 <= nums.length <= 10^5`，`-10^9 <= nums[i] <= 10^9`。例：`[3,1,3,1,2]` → `1`（`3` 和 `1` 各出现 2 次，取较小的 `1`）。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** `Counter` 一遍计数，再用复合键 `(-次数, 数值)` 取 `min`：次数大的排前，次数相同时数值小的排前，一次比较表达两条规则。`O(n)`。

**识别。** 「出现次数」→ 哈希计数；值域 `±10^9` 不能开数组计数，用字典。「并列时取最小」→ 排序规则有两级，用元组键（tuple key）一次比较完。

**推导。** 暴力：对每个不同的值 `x` 用 `nums.count(x)` 数一遍，`O(n·k)`，`k` 为不同值个数，最坏 `O(n^2)`。浪费在每个值都重新扫整个数组；一遍扫描建好计数表就够了，`O(n)`。也可以排序后数连续段（`O(n log n)`），并列时先遇到的天然就是较小的值，但计数法更快，也更容易扩展到流式。

```python
from collections import Counter


def most_frequent(nums: list[int]) -> int:
    count = Counter(nums)
    # 复合键：次数大的优先（取负），次数相同取数值小的
    return min(count, key=lambda x: (-count[x], x))
```

运行：`[3,1,3,1,2]` → `1`；`[7]` → `7`；`[-5,-5,2,2]` → `-5`；`[4,4,1]` → `4`。

**复杂度。** 时间 `O(n)`：计数 `O(n)`，`min` 遍历 `k <= n` 个不同值；空间 `O(k)`。

**易错点。**
- `Counter(nums).most_common(1)`：并列时按**首次出现的顺序**返回，不是按数值。`[3,1,3,1,2]` 得到 `[(3, 2)]`，答案错成 `3`（正确 `1`）。`max(count, key=count.get)` 同理也得到 `3`。
- 键写成 `(count[x], -x)` 再取 `max` 也对，但别写成 `(count[x], x)` 取 `max`：并列时会取**较大**的值。
- 只维护「当前最大次数」和「当前答案」一遍扫过去时，次数相等的分支要比较数值，否则退化成「先出现者优先」。

**追问。**
- 数据是流，随时回答：维护 `count` 和当前答案；新来 `x` 后若 `(count[x], -x) > (best_cnt, -best)` 就更新答案，每次 `O(1)`。
- 还要支持删除：次数会下降，答案可能要「退位」，单个变量不够；用懒删除堆（lazy deletion heap）存 `(-次数, 数值)`，每次变化推入新条目，查询时弹掉和当前计数对不上的过期条目，均摊 `O(log n)`。
- 要前 `k` 个：`heapq.nsmallest(k, count, key=lambda x: (-count[x], x))`，`O(k' log k)`（`k'` 为不同值个数）。

**同模式。** LC 347 前 K 个高频元素、LC 692 前 K 个高频单词（并列按字典序）、LC 895 最大频率栈、LC 169 多数元素。
