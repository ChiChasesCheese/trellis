## Q
**LC 21 合并两个有序链表**｜Easy · CodeTop 国内累计 84 次 · 最近 2026-10-09（国内 CodeTop）

把两个升序链表合并为一个新的升序链表并返回；新链表是通过拼接给定的两个链表的所有节点组成的。两个链表的节点数目范围是 `[0, 50]`，`-100 <= Node.val <= 100`，`list1` 和 `list2` 均按非递减顺序排列。例：`list1 = [1,2,4]`，`list2 = [1,3,4]` → `[1,1,2,3,4,4]`；`list1 = []`，`list2 = []` → `[]`；`list1 = []`，`list2 = [0]` → `[0]`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 用哑节点（dummy）加尾指针：每次比较两条链表的队头，把较小的节点接到结果尾部并前进；一条用完后，把另一条剩下的整段直接挂上。`O(m + n)` 时间，`O(1)` 空间。

**识别。** 「两个有序链表合成一个有序链表」就是归并排序里的**合并步**。链表可以 `O(1)` 地改指针拼接节点，不用额外数组；结果的头节点不确定（可能来自任一条链表，也可能为空），所以用哑节点统一处理，省掉特判。

**推导。** 暴力：把两条链表的值取出来排序，再新建链表 → `O((m + n) log(m + n))` 时间、`O(m + n)` 空间，还不是「拼接原节点」。递归版：取较小的队头，它的 `next` 指向对剩余部分的递归合并结果，代码很短，但递归深度是 `m + n`，链表一长就会超出 Python 默认递归上限。洞察：两条链表各自有序，所以下一个结果节点一定是两个队头里较小的那个；一条用完时，另一条剩下的节点已经有序且都不小于已合并的部分，整段挂上即可。

```python
def merge_two_lists(list1: ListNode | None, list2: ListNode | None) -> ListNode | None:
    dummy = tail = ListNode()           # 哑节点：省掉"第一个节点怎么接"的特判
    while list1 and list2:
        if list1.val <= list2.val:      # 相等时取 list1，保持稳定
            tail.next, list1 = list1, list1.next
        else:
            tail.next, list2 = list2, list2.next
        tail = tail.next
    tail.next = list1 or list2          # 至多一条还有剩，整段直接挂上
    return dummy.next
```

运行：`[1,2,4]` 与 `[1,3,4]` → `[1, 1, 2, 3, 4, 4]`，`[]` 与 `[]` → `[]`，`[]` 与 `[0]` → `[0]`；结果中的节点都是原来的节点对象，没有新建。

**复杂度。** 时间 `O(m + n)`；空间 `O(1)`。

**易错点。**
- 忘记挂上剩余部分：循环结束就返回，`[1,2,4]` 与 `[1,3,4,5,6]` 得到 `[1, 1, 2, 3, 4]`，丢了 `4, 5, 6`，正确是 `[1, 1, 2, 3, 4, 4, 5, 6]`。
- 不用哑节点：要单独判断结果的头来自哪条链表，两条都为空时还要再特判，分支多，容易漏。
- 新建节点而不是复用原节点：结果的值对，但题目要求「拼接给定链表的所有节点」，面试官会指出多用了 `O(m + n)` 空间。
- 写成递归后直接用在很长的链表上：深度等于总长度，会触发 `RecursionError`。

**追问。**
- 递归写法：`if not l1 or not l2: return l1 or l2`；`l1.val <= l2.val` 时 `l1.next = merge(l1.next, l2)` 并返回 `l1`，否则对称。短，但有递归深度的代价。
- `k` 个有序链表（LC 23）：最小堆或分治两两合并，反复调用这个函数。
- 合并并去重：每次接节点前，比较它的值与 `tail.val`，相等就跳过。

**同模式。** LC 23 合并 K 个升序链表、LC 88 合并两个有序数组、LC 148 排序链表、LC 143 重排链表、LC 2 两数相加。
