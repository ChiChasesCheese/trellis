## Q
**LC 440 字典序的第 K 小数字**｜Hard · CodeTop 国内累计 40 次 · 最近 2026-10-28（国内 CodeTop）

给定整数 `n` 和 `k`，返回 `[1, n]` 中字典序（按字符串比较的顺序）第 `k` 小的数字。`1 <= k <= n <= 10^9`。例：`n = 13, k = 2` → `10`（字典序是 `[1, 10, 11, 12, 13, 2, 3, 4, 5, 6, 7, 8, 9]`）；`n = 1, k = 1` → `1`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 把 `1..n` 看成一棵十叉前缀树（根的孩子是 `1..9`，结点 `x` 的孩子是 `10x..10x+9`），字典序就是这棵树的先序遍历。从 `cur = 1` 出发，算出以 `cur` 为根的子树里有多少个数 `size`：`size` 不超过剩余步数，就整棵跳过，走到右邻兄弟 `cur + 1`；否则钻进第一个孩子 `cur * 10`。每次计数 `O(log n)`，整体 `O(log^2 n)`。

**识别。** 「字典序第 `k` 小」且 `n` 到 `10^9`：排序 `10^9` 个字符串做不到。字典序等价于前缀树先序，「第 `k` 个」就是按子树大小在树上跳转（类似在平衡树里找第 `k` 小）。子树大小可以逐层用公式算，不需要真的遍历。

**推导。** 暴力：`sorted(range(1, n+1), key=str)`，`O(n log n)` 时间 `O(n)` 空间；一个一个走字典序的"下一个数"也要 `O(k)`，`k = 10^9` 同样太慢。洞察：先序遍历里整棵子树占据连续的一段。以 `prefix` 为根的子树，第一层是 `[prefix, prefix+1)`，下一层是 `[10·prefix, 10·(prefix+1))`，每层个数是区间与 `[1, n]` 的交，累加到区间起点超过 `n` 为止，最多十层。用它判断第 `k` 个数在不在当前子树里，不在就整段跳过，在就往下钻一层。

```python
def find_kth_number(n: int, k: int) -> int:
    def count(prefix: int) -> int:               # 以 prefix 为根的十叉树子树里，落在 [1, n] 的数有几个
        lo, hi, total = prefix, prefix + 1, 0    # 每一层的区间是 [lo, hi)，下一层是 [lo*10, hi*10)
        while lo <= n:
            total += min(n + 1, hi) - lo         # 最后一层可能被 n 截断
            lo, hi = lo * 10, hi * 10
        return total

    cur = 1                                      # 当前停在第 1 小的数：1
    k -= 1                                       # 还要再往后走 k-1 步
    while k:
        size = count(cur)
        if size <= k:                            # 第 k 小不在 cur 的子树里：整棵跳过，去右邻兄弟
            k -= size
            cur += 1
        else:                                    # 在子树里：走进第一个孩子 cur*10，消耗 cur 自己这 1 步
            k -= 1
            cur *= 10
    return cur
```

**运行。** `(13, 2)` → `10`；`(1, 1)` → `1`；`(13, 13)` → `9`；`(100, 100)` → `99`；`(10**9, 10**9)` → `999999999`；`(10**9, 1)` → `1`；`(10**9, 500000000)` → `549999998`；`n = 10**9` 的一次查询不到一毫秒。

**复杂度。** 时间 `O(log^2 n)`：每一层最多向右跳 `9` 次、向下钻一次，约 `9 log n` 次循环，每次 `count` 是 `O(log n)`；空间 `O(1)`。

**易错点。**
- `count` 里用 `min(n, hi)` 而不是 `min(n + 1, hi)`：区间是半开的，`n` 本身会漏数。`(13, 13)` 返回 `10`，正确是 `9`。
- 忘了 `k -= 1`：起点 `1` 已经占掉第一名。`(13, 2)` 返回 `11`，正确是 `10`。
- 在 C++ / Java 里 `lo * 10`、`hi * 10` 会超出 32 位（`n = 10^9` 时到 `10^10`），要用 `long`；Python 不会溢出，但要能说出来。

**追问。**
- 反过来求数字 `x` 的字典序排名：从根到 `x` 的路径上，每一步累加被跳过的左邻兄弟子树大小，再加上路径上的祖先个数。
- 输出字典序前 `k` 个数（LC 386）：不需要子树大小，直接按"下一个数"规则迭代，`O(k)`。
- `n` 极大（如 `10^18`）：整数不溢出的语言里复杂度仍是 `O(log^2 n)`，Python 直接可用。

**同模式。** LC 386 字典序排数、LC 60 排列序列、LC 668 乘法表中第 k 小的数、LC 378 有序矩阵中第 K 小的元素。
