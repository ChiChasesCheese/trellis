## Q
**LC 323 无向图中连通分量的数目**｜Medium · LC TikTok 全时段热度 38/100 · 近一年被问：美国 1 次、国内 0 次 · 最近 2026-03-10（美国面试记录）

无向图有 `n` 个节点，下标 `0` 到 `n - 1`；`edges[i] = [a, b]` 表示 `a` 与 `b` 之间有一条边。返回图中**连通分量**（互相可达的一组节点）的个数。`1 <= n <= 2000`，`1 <= edges.length <= 5000`，`0 <= a <= b < n`，`a != b`，没有重复的边。例：`n = 5`，`edges = [[0,1],[1,2],[3,4]]` → `2`；`n = 5`，`edges = [[0,1],[1,2],[2,3],[3,4]]` → `1`。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 并查集（Union-Find）：开始有 `n` 个分量，逐条边合并两端；只有两端的根不同时才真的合并，并让计数减一；扫完所有边，计数就是答案。

**识别。** 「无向图 + 连通分量个数 + 边以列表给出」：只问个数、不问路径，是并查集最顺手的场景（DFS / BFS 也行，但要先建邻接表）。如果边是一条条动态加入、每次都要回答当前分量数，并查集几乎是唯一合适的做法。

**推导。** 暴力：建邻接表，对每个没访问过的点做一次 DFS / BFS，启动 DFS 的次数就是分量数，`O(n + m)`，已经够快，但要建图 → 换个角度数：开始 `n` 个孤立点是 `n` 个分量，每条边若连接两个**不同**的分量，就让总数恰好减一；若两端早已连通（成环），总数不变 → 用并查集判断「两端是否同一个根」，边合并只花接近 `O(1)` 的时间 → 答案 = `n` − 成功合并次数。

```python
def count_components(n: int, edges: list[list[int]]) -> int:
    parent = list(range(n))

    def find(x: int) -> int:
        while parent[x] != x:
            parent[x] = parent[parent[x]]      # 路径减半：顺手把 x 挂到祖父下面
            x = parent[x]
        return x

    comps = n
    for a, b in edges:
        ra, rb = find(a), find(b)
        if ra != rb:                           # 两端本来不连通：合并一次，分量少一个
            parent[ra] = rb
            comps -= 1
    return comps
```

运行：`5, [[0,1],[1,2],[3,4]]` → `2`；`5, [[0,1],[1,2],[2,3],[3,4]]` → `1`；`1, []` → `1`；`4, []` → `4`。

**复杂度。** 时间 `O((n + m) α(n))`，`α` 是反阿克曼函数，实际可当作常数；空间 `O(n)`。

**易错点。**
- 用 `n - len(edges)`：只有森林（无环）才成立。`n = 5`，`edges = [[0,1],[1,2],[0,2],[3,4]]` 会得到 `1`，正确答案是 `2`（`{0,1,2}` 和 `{3,4}`）。
- 直接比较端点 `a != b` 而不比较根：每条边都会被当成一次成功合并。
- 递归写 `find` 且不压缩路径：链状数据下递归深度可超过 Python 默认的 `1000`，抛 `RecursionError`；这里用迭代的路径减半。

**追问。**
- 边动态加入，每加一条就返回当前分量数：并查集本来就是在线的，每次 `O(α(n))`；DFS 方案要整图重算。
- 返回最大分量的大小：并查集里再维护 `size[root]`，合并时累加；或最后 `Counter(find(i) for i in range(n))`。
- 判断这张图是不是一棵树（LC 261）：合并时遇到同根说明有环，并且最终分量数必须是 `1`。

**同模式。** LC 547 省份数量、LC 261 以图判树、LC 684 冗余连接、LC 721 账户合并、LC 200 岛屿数量。
