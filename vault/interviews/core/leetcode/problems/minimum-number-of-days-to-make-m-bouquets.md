## Q
**LC 1482 制作 m 束花所需的最少天数**｜Medium

给你一个整数数组 `bloomDay`，以及两个整数 `m` 和 `k`。现需要制作 `m` 束花，制作花束时需要使用花园中相邻的 `k` 朵花。花园中有 `n` 朵花，第 `i` 朵花会在 `bloomDay[i]` 时盛开，恰好可以用于一束花中。返回从花园中摘 `m` 束花需要等待的最少的天数；如果不能摘到 `m` 束花则返回 `-1`。`bloomDay.length == n`，`1 <= n <= 10^5`，`1 <= bloomDay[i] <= 10^9`，`1 <= m <= 10^6`，`1 <= k <= n`。例：`bloomDay = [1,10,3,10,2], m = 3, k = 1` → `3`；`bloomDay = [1,10,3,10,2], m = 3, k = 2` → `-1`；`bloomDay = [7,7,7,7,12,7,7], m = 2, k = 3` → `12`。

给出完整的最优解答：考点、识别、推导、代码、复杂度、易错点。

## A
**考点。** 二分答案（binary search on the answer）+ 贪心判定函数。

**一句话。** 天数越多开的花越多，「`d` 天内能否做出 `m` 束」对 `d` 单调，在 `[min, max]` 天里二分，判定时扫一遍数组，连续开花数凑够 `k` 就算一束并清零。

**识别。** 「最少的天数 / 最小的容量使得某条件成立」+ 条件随答案单调（多等一天不会变差）= 二分答案。`bloomDay` 高达 `10^9`，不能逐天模拟，但二分只需约 30 次判定，每次 `O(n)`。

**推导。** 暴力：枚举每一天，每天扫一遍判断，天数最多 `10^9`，不可行；只枚举 `bloomDay` 中出现的取值也是 `O(n^2)`。判定函数 `can(d)`：把开花的位置（`bloomDay[i] <= d`）视为 1，找出连续的 1，每 `k` 朵组成一束，贪心地从左到右分组不会比其他分法少。因为 `can` 单调，找最小的 `d` 就是二分。无解当且仅当总花数 `n < m * k`。

```python
def min_days(bloom_day: list[int], m: int, k: int) -> int:
    if m * k > len(bloom_day):             # 花的总数不够，等多久都没用
        return -1

    def can(day: int) -> bool:             # 第 day 天能否做出 m 束
        bouquets = run = 0                 # run：当前连续已开花的朵数
        for b in bloom_day:
            if b <= day:
                run += 1
                if run == k:               # 凑够一束，重新开始数
                    bouquets += 1
                    run = 0
            else:
                run = 0                    # 遇到没开的花，连续性断开
        return bouquets >= m

    lo, hi = min(bloom_day), max(bloom_day)    # 答案一定是某朵花的开花日，且 hi 天时所有花都开了
    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid):
            hi = mid                       # mid 可行：答案 <= mid
        else:
            lo = mid + 1                   # 不可行：答案 > mid
    return lo
```

运行：`([1,10,3,10,2], 3, 1)` → `3`，`([1,10,3,10,2], 3, 2)` → `-1`，`([7,7,7,7,12,7,7], 2, 3)` → `12`，`([10**9, 10**9], 1, 1)` → `1000000000`，`([1,10,2,9,3,8,4,7,5,6], 4, 2)` → `9`。

**复杂度。** 时间 `O(n log(max - min))`，空间 `O(1)`。

**拓展优化。**
- 标准库写法（Python 3.10+）：对单调布尔函数 `can` 二分，省掉手写循环：`return lo + bisect_left(range(hi - lo + 1), True, key=lambda i: can(lo + i))`。
- 同一类「二分答案 + 贪心判定」换个判定函数就是另一道题：运送包裹（LC 1011）判定能否在 `D` 天内送完，爱吃香蕉的珂珂（LC 875）判定能否在 `h` 小时吃完。

**易错点。**
- 遇到没开的花忘了把 `run` 清零：`[7,7,7,7,12,7,7]`、`m = 2`、`k = 3` 在第 `7` 天会把两段不相邻的花拼在一起数出 `2` 束，返回 `7`（正确 `12`）。
- 凑够一束后忘了把 `run` 置零，`run == k` 之后不会再成立：`[1,1,1,1,9]`、`m = 2`、`k = 2` 每一天都只数出 `1` 束，返回 `9`（正确 `1`）。
- 不先判断 `m * k > n`：`lo, hi` 范围内永远不可行，二分会返回 `max(bloom_day)` 而不是 `-1`（`[1,10,3,10,2]`、`m = 3`、`k = 2` 返回 `10`）。

**同模式。** LC 1011 在 D 天内送达包裹的能力、LC 875 爱吃香蕉的珂珂、LC 410 分割数组的最大值、LC 1283 使结果不超过阈值的最小除数。
