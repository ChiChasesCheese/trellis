## Q
**LC 724 寻找数组的中心下标**｜Easy

给你一个整数数组 `nums`，请计算数组的**中心下标**：该下标左侧所有元素之和等于右侧所有元素之和。如果中心下标位于数组最左端，左侧之和视为 `0`；位于最右端时右侧之和同理视为 `0`。如果有多个中心下标，返回**最靠近左边**的那个；不存在则返回 `-1`。`1 <= nums.length <= 10^4`，`-1000 <= nums[i] <= 1000`。例：`nums = [1,7,3,6,5,6]` → `3`（左 `1+7+3 = 11`，右 `5+6 = 11`）；`nums = [1,2,3]` → `-1`；`nums = [2,1,-1]` → `0`。

给出完整的最优解答：考点、识别、推导、代码、复杂度、易错点。

## A
**考点。** 前缀和（prefix sum）：左侧和用累加维护，右侧和由总和推出。

**一句话。** 总和 `total` 已知，扫描到 `i` 时左侧和 `left`，右侧和就是 `total - left - nums[i]`；二者相等的第一个 `i` 就是答案。

**识别。** 「某位置两侧的和比较」是前缀和的典型用法：一次预处理总和，之后每个位置 `O(1)` 得到两侧的和。`n <= 10^4`，朴素重算每个位置两侧和 `O(n^2)` 也能过，但 `O(n)` 同样简单。

**推导。** 对每个 `i` 重新对两边求和是 `O(n)`，总 `O(n^2)`。左侧和随 `i` 增大只多加一个元素，不必重算；右侧和不必另外求：`左 + nums[i] + 右 = total`，所以右 = `total - left - nums[i]`。从左往右扫，遇到的第一个满足条件的下标天然是最靠左的。

```python
def pivot_index(nums: list[int]) -> int:
    total = sum(nums)
    left = 0                                       # nums[:i] 的和，初始为空，等于 0
    for i, x in enumerate(nums):
        if left == total - left - x:               # 右侧和 = 总和 - 左侧和 - 自己
            return i                               # 从左往右扫，第一个命中的就是最靠左的
        left += x                                  # 先判断再累加：left 不能包含 nums[i]
    return -1
```

运行：`[1,7,3,6,5,6]` → `3`；`[1,2,3]` → `-1`；`[2,1,-1]` → `0`；`[1]` → `0`；`[-1,-1,-1,-1,-1,0]` → `2`。

**复杂度。** 时间 `O(n)`；空间 `O(1)`。

**易错点。**
- 先累加再判断，或判断时没有排除 `nums[i]`：`left == total - left` 把中心元素算进右侧。`[1,7,3,6,5,6]` 得 `-1`，正确是 `3`。
- 用「左侧和超过总和的一半就停」剪枝：含负数时前缀和不单调，会提前退出而漏掉答案。
- 对 `[2,1,-1]` 这类中心在最左端的情形，左侧是空数组，初始 `left` 必须是 `0` 而不是 `nums[0]`。
