## Q
**LC 605 种花问题**｜Easy

有一个很长的花坛，一部分地块种了花，另一部分没有。花不能种植在相邻的地块上。给你一个整数数组 `flowerbed`（`0` 表示没种花，`1` 表示种了花）和一个数 `n`，在不打破种植规则的情况下能否再种入 `n` 朵花？能返回 `true`，不能返回 `false`。`1 <= flowerbed.length <= 2 * 10^4`，`flowerbed[i]` 为 `0` 或 `1`，`flowerbed` 中不存在相邻的两朵花，`0 <= n <= flowerbed.length`。例：`flowerbed = [1,0,0,0,1], n = 1` → `true`；`flowerbed = [1,0,0,0,1], n = 2` → `false`。

给出完整的最优解答：考点、识别、推导、代码、复杂度、易错点。

## A
**考点。** 贪心（greedy）：能种就种；两端补 0 消除边界判断。

**一句话。** 从左到右扫，只要一个位置和它左右邻居都是空的就立刻种上，并且把它标成 `1`；种得越靠左，留给后面的空间越多，所以这样种出的数量就是最大值。

**识别。** 「相邻不能同时选」+「求最多能选几个」是区间 / 间隔选择的贪心：每次选最靠左的合法位置不会比其它选法更差。`n` 和长度都到 `2 * 10^4`，一遍扫描足够。

**推导。** 暴力：枚举所有种法，指数级。贪心的正确性：设最优方案里第一朵新花种在位置 `p`，而最左的合法位置是 `q <= p`；把这朵花从 `p` 挪到 `q`，只会让 `q + 1` 之后的空位更多，不会少种。所以每次在最左合法位置种花。两端没有邻居，在数组前后各补一个 `0`，每个位置都有左右邻居，不需要写边界条件。

```python
def can_place_flowers(flowerbed: list[int], n: int) -> bool:
    bed = [0, *flowerbed, 0]                       # 两端补 0：端点当作「邻居为空」，不用特判边界
    for i in range(1, len(bed) - 1):
        if bed[i - 1] == bed[i] == bed[i + 1] == 0:    # 自己和左右邻居都空：可以种
            bed[i] = 1                             # 立刻种上，影响下一个位置的判断
            n -= 1
    return n <= 0                                  # 种够了（n = 0 时一朵都不用种）
```

运行：`([1,0,0,0,1], 1)` → `True`，`([1,0,0,0,1], 2)` → `False`，`([0], 1)` → `True`，`([0,0], 2)` → `False`，`([1], 0)` → `True`。

**复杂度。** 时间 `O(n)`，空间 `O(n)`（补零后的副本，不修改传入的数组）。

**拓展优化。**
- 不用副本、不改数组：数每一段连续的 `0`。长度为 `z` 的段，两端都是花时能种 `(z - 1) // 2` 朵；段在数组两端时，补一个虚拟的 `0` 后用同一个公式。
- 提前返回：`n` 变成 `0` 时直接返回 `True`，大数组可以省下后半段扫描。

**易错点。**
- 种了花之后没有把 `bed[i]` 改成 `1`：`([0,0], 2)` 里补零后位置 `1` 和 `2` 都会被判为可种，返回 `True`（正确 `False`）。
- 不补零而直接写 `flowerbed[i - 1]`：`i = 0` 时下标 `-1` 会悄悄读到最后一个元素，`[0,1,0,0]` 之类的数组边界判断出错。
- 原地修改传入的 `flowerbed`：调用者的数据被改动，应当用副本。
