## Q
**LC 172 阶乘后的零**｜Medium

给定一个整数 `n`，返回 `n!` 结果中尾随零的数量。`0 <= n <= 10^4`。进阶：你可以设计并实现对数时间复杂度的算法来解决此问题吗？例：`n = 3` → `0`（`3! = 6`）；`n = 5` → `1`（`5! = 120`）；`n = 0` → `0`。

给出完整的最优解答：考点、识别、推导、代码、复杂度、易错点。

## A
**考点。** 数论：统计质因子 5 的个数（Legendre 公式）。

**一句话。** 尾随零的个数等于 `n!` 中因子 `10 = 2 * 5` 的对数，因子 2 总是比 5 多，所以只数 5 的个数，也就是 `n // 5 + n // 25 + n // 125 + ...`。

**识别。** 「阶乘末尾有几个 0」不要真的算阶乘；末尾的 0 来自因子 10，转化成质因子计数。`n <= 10^4` 时可以直接算大整数，但进阶要求对数时间。

**推导。** 直接算 `n!` 再数末尾零，数字有上万位，数起来也慢。`n!` 的质因数分解里，2 的个数不小于 5 的个数，所以零的个数 = 5 的个数。1 到 `n` 里有 `n // 5` 个数是 5 的倍数各贡献一个 5；其中 25 的倍数多贡献一个（再数 `n // 25`）；125 的倍数再多一个，依此类推。反复做 `n //= 5` 并累加，恰好把各层都加上。

```python
def trailing_zeroes(n: int) -> int:
    count = 0
    while n:
        n //= 5          # 第 k 轮之后 n 等于原 n // 5^k，正好是 1..原 n 中 5^k 的倍数的个数
        count += n
    return count
```

运行：`3` → `0`，`5` → `1`，`0` → `0`，`25` → `6`，`100` → `24`，`10000` → `2499`。

**复杂度。** 时间 `O(log_5 n)`，空间 `O(1)`。

**拓展优化。**
- 反向问题：给定零的个数 `k`，求最小的 `n`（LC 793 阶乘函数后 K 个零的数组）。尾零数关于 `n` 单调不减，可以对 `trailing_zeroes` 二分。
- 把 5 换成别的质数 `p` 就是 `n!` 中 `p` 的指数（Legendre 公式），同一个循环。

**易错点。**
- 只数 `n // 5`：`n = 25` 得到 `5`，漏掉 25 贡献的第二个 5，正确是 `6`。
- 真的计算 `n!`：`n = 10000` 时结果有 35660 位，`str(math.factorial(n))` 在 CPython 3.11+ 会抛 `ValueError`（整数转字符串默认上限 4300 位），也达不到进阶要求的对数时间。
- 用 `n / 5`（浮点）：会得到小数，累计出错；整除 `//`。

**同模式。** LC 793 阶乘函数后 K 个零、LC 1175 质数排列、LC 204 计数质数、LC 50 Pow(x, n)。
