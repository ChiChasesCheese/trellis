## Q
**LC 526 优美的排列**｜Medium

假设有从 `1` 到 `n` 的 `n` 个整数。用这些整数构造一个数组 `perm`（下标从 1 开始），只要满足下述条件之一，该数组就是一个优美的排列：`perm[i]` 能够被 `i` 整除，或者 `i` 能够被 `perm[i]` 整除。给你一个整数 `n`，返回可以构造的优美排列的数量。`1 <= n <= 15`。例：`n = 2` → `2`（`[1,2]` 和 `[2,1]`）；`n = 1` → `1`。

给出完整的最优解答：考点、识别、推导、代码、复杂度、易错点。

## A
**考点。** 回溯（backtracking）：按位置填数，边填边剪枝；`n <= 15` 提示可用状态压缩。

**一句话。** 从位置 1 到 `n` 依次填数，只选还没用过且满足整除条件的数字，填满就计一个方案。

**识别。** 「排列计数 + 每个位置有约束 + `n <= 15`」：全排列 `15!` 太大，但约束很强，每步剪枝后搜索树小得多；`n <= 15` 也是位掩码（bitmask）的典型范围。

**推导。** 暴力生成 `n!` 个排列再检查，`n = 15` 约 `1.3 * 10^12`，不可行。改成按位置逐个填并立刻检查整除条件，不合法的前缀不再展开，`n = 15` 时整棵搜索树只有约 75 万个节点。

```python
def count_arrangement(n: int) -> int:
    # used[x]：数字 x 是否已被放在前面的位置
    used = [False] * (n + 1)

    # 在位置 pos 填数，返回从这里开始的方案数
    def dfs(pos: int) -> int:
        if pos > n:                          # 1..n 全部填完且都合法
            return 1
        total = 0
        for num in range(1, n + 1):
            if not used[num] and (num % pos == 0 or pos % num == 0):
                used[num] = True             # 选择
                total += dfs(pos + 1)
                used[num] = False            # 撤销
        return total

    return dfs(1)
```

运行：`n = 1` → `1`，`n = 2` → `2`，`n = 3` → `3`，`n = 4` → `8`，`n = 15` → `24679`。

**复杂度。** 时间远小于 `O(n!)`，上界是各层合法选择数的乘积，`n = 15` 约 75 万个节点；空间 `O(n)`。

**拓展优化。**
- 已用集合压成位掩码，并用 `@cache` 记忆化：已填位置数等于掩码里 1 的个数，所以状态只有掩码一个，最多 `2^n` 个状态，每个 `O(n)`，总共 `O(n * 2^n)`：

```python
from functools import cache


def count_arrangement_mask(n: int) -> int:
    @cache
    # mask 的第 num-1 位为 1 表示数字 num 已用
    def dfs(mask: int) -> int:
        pos = mask.bit_count() + 1           # 下一个要填的位置
        if pos > n:
            return 1
        return sum(
            dfs(mask | 1 << (num - 1))
            for num in range(1, n + 1)
            if not mask >> (num - 1) & 1
            and (num % pos == 0 or pos % num == 0)
        )

    return dfs(0)
```

- 剪枝顺序：先填约束最强的位置（例如从 `n` 往 `1` 填），能让无解的分支更早被砍掉。

**易错点。**
- 只检查一个方向的整除：`n = 2` 时 `[2,1]` 需要 `pos % num == 0`（`2 % 1`）才合法，只检查 `num % pos` 会返回 `1`（正确 `2`）。
- 回溯时漏了撤销 `used[num] = False`：之后的分支看不到这个数字，计数偏少，`n = 3` 会得到 `1`（正确 `3`）。
- 位置和数字都从 `1` 开始：从 `0` 开始会出现 `x % 0` 的除零错误。
- 最坏递归深度是 `n = 15`，远小于 CPython 默认的约 1000 层上限。

**追问。**
- 为什么不直接 `n!` 个排列过滤？`15! ≈ 1.3 * 10^12`；按位置边填边检查，节点数降到约 `7.5 * 10^5`（我们数过 `747961`）。
- 记忆化和纯回溯各自什么时候占优？状态压缩把节点数封顶在 `2^n * n = 5 * 10^5` 量级，且 `n` 再大一点仍可用；纯回溯代码短，`n <= 15` 同样够快，但没有上界保证。
- 要输出所有方案而不是个数？只能回溯并保存路径，输出规模本身就是 `n = 15` 时 `24679` 个排列，无法比搜索更快。
- 为什么「从大到小填位置」有帮助？位置 `1` 对所有数都合法，位置 `n` 的候选极少（`n` 的因数），先填后者能让死路更早暴露。
