## Q
**LC 9 回文数**｜Easy

给你一个整数 `x`，如果 `x` 是回文整数（正序和倒序读都一样）返回 `true`，否则返回 `false`。`-2^31 <= x <= 2^31 - 1`。进阶：能不能不把整数转成字符串？例：`x = 121` → `true`；`x = -121` → `false`（倒着读是 `121-`）；`x = 10` → `false`（倒着读是 `01`）。

给出完整的最优解答：考点、识别、推导、代码、复杂度、易错点。

## A
**考点。** 回文判断；整数的数位操作（`%10`、`//10`），进阶是只反转一半数字。

**一句话。** 转成字符串，和它的反转比较；负数带着负号，反过来负号跑到末尾，自然不相等。

**识别。** 「回文」= 正着读等于反着读；`x` 最多 `10` 位，`O(log x)` 随便做。进阶「不用字符串」= 数位反转。

**推导。** 字符串版本不需要任何特殊处理：负数的 `str(-121)` 是 `"-121"`，反转是 `"121-"`，不相等；`10` 反转成 `"01"`，不相等。进阶要求不转字符串时，把整个数反转再比较会溢出（32 位整数反转后可能超过范围），所以只反转后半部分，与前半部分比较，见拓展。

```python
def is_palindrome(x: int) -> bool:
    # 负数带 '-'，反过来 '-' 在末尾，天然不相等；10 反转成 "01"，也不相
    # 等
    s = str(x)
    return s == s[::-1]
```

运行：`121` → `True`；`-121` → `False`；`10` → `False`；`0` → `True`；`1221` → `True`；`2147483647` → `False`。

**复杂度。** 时间 `O(log x)`（位数），空间 `O(log x)`（字符串）。

**拓展优化。**
- 进阶：不转字符串，只反转后一半数位，空间 `O(1)`，也不会溢出。`x` 的后半部分被一位位挪进 `rev`，当 `rev` 不再小于剩下的前半部分时停止：偶数位时两边相等，奇数位时 `rev` 多一位（中间那位），去掉它再比：

```python
def is_palindrome_digits(x: int) -> bool:
    # 负数不是；以 0 结尾的非 0 数，反转后会有前导 0，不可能相等
    if x < 0 or (x % 10 == 0 and x != 0):
        return False
    rev = 0
    while x > rev:  # 后半部分反转后追上（或超过）前半部分时停
        rev = rev * 10 + x % 10
        x //= 10
    # 偶数位：x == rev；奇数位：rev 多出的中间位用 // 10 去掉
    return x == rev or x == rev // 10
```

**易错点。**
- 忘记排除负数：用绝对值 `str(abs(x))` 比较会把 `-121` 判成 `True`，正确是 `False`。
- 数位版本漏掉以 `0` 结尾的情形：`x = 10` 时循环结束 `x = 0`、`rev = 1`，`0 == 1 // 10` 成立，返回 `True`，正确是 `False`；所以要先排除 `x % 10 == 0 and x != 0`。
- 数位版本奇数位只比较 `x == rev`：`121` 停在 `x = 1`、`rev = 12`，返回 `False`，正确是 `True`，需要 `rev // 10`。

**追问。**
- 为什么进阶不直接反转整个数：32 位有符号整数反转后可能超过 `2^31 - 1`（如 `1534236469`），在 C++ / Java 里溢出；只反转一半，`rev` 永远不超过原数。Python 不溢出，但面试要讲清楚。
- 判断其他进制下的回文：把 `10` 换成进制 `b`，`x % b`、`x //= b` 即可，其余不变。
- 判断回文链表（LC 234）：快慢指针找中点，反转后半段，再逐个比较；思路与「只反转一半」相同，空间 `O(1)`。

**同模式。** LC 125 验证回文串、LC 234 回文链表、LC 7 整数反转、LC 5 最长回文子串。
