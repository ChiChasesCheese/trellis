## Q
**LC 349 两个数组的交集**｜Easy · 全公司热度第 129 名

给定两个数组 `nums1` 和 `nums2`，返回它们的交集。输出结果中的每个元素一定是唯一的，不考虑输出顺序。`1 <= nums1.length, nums2.length <= 1000`，`0 <= nums1[i], nums2[i] <= 1000`。例：`nums1 = [1,2,2,1], nums2 = [2,2]` → `[2]`；`nums1 = [4,9,5], nums2 = [9,4,9,8,4]` → `[9,4]`（`[4,9]` 也可以）。

给出完整的最优解答：考点、识别、推导、代码、复杂度、易错点。

## A
**考点。** 哈希集合（hash set）的交集运算。

**一句话。** 把一个数组放进集合，扫另一个数组做 `O(1)` 的成员查询，集合本身顺便去重。

**识别。** 「交集 + 结果去重 + 不要求顺序」就是集合运算的直接对应；元素值很小（`<= 1000`）时布尔数组也行。

**推导。** 对 `nums1` 的每个元素在 `nums2` 里线性查找是 `O(nm)`。浪费在于成员查询没有索引；先把一边放进哈希集合，查询降到 `O(1)`，去重也由集合自动完成。

```python
def intersection(nums1: list[int], nums2: list[int]) -> list[int]:
    # set(nums1) 去重并建好哈希表；intersection 接受任意可迭代对象，
    # 直接遍历 nums2 逐个查询，不用再建第二个集合
    return list(set(nums1).intersection(nums2))
```

运行（结果顺序任意，这里排序后展示）：`([1,2,2,1], [2,2])` → `[2]`，`([4,9,5], [9,4,9,8,4])` → `[4, 9]`，`([1], [2])` → `[]`。

**复杂度。** 时间 `O(n + m)`，空间 `O(min(n, m))` 到 `O(n)`（一个集合加结果）。

**拓展优化。**
- 两个数组都已排好序：双指针归并，空间 `O(1)`，相等时记录并同时跳过重复值。
- 一个数组远小于另一个：把小数组放进集合，扫大数组；大数组在磁盘上、放不进内存时也只需流式读它。
- 要保留重复次数（LC 350）：用 `Counter(nums1) & Counter(nums2)`，交集取每个元素次数的较小者。

**易错点。**
- 忘了去重：用列表推导 `[x for x in nums1 if x in nums2]` 会得到 `[2, 2]`（正确 `[2]`），而且 `in` 查列表是 `O(m)`，整体 `O(nm)`。
- 题目只要唯一元素；若误用 `Counter` 的交集，`[1,2,2,1]` 与 `[2,2]` 会返回 `[2, 2]`，这是 LC 350 的答案。

**同模式。** LC 350 两个数组的交集 II、LC 217 存在重复元素、LC 1 两数之和、LC 202 快乐数。
