## Q
**LC 1838 最高频元素的频数**｜Medium · 全公司热度第 230 名

元素的频数是它在数组中出现的次数。给你整数数组 `nums` 和整数 `k`，一步操作可以选一个下标并把对应元素加 `1`。执行最多 `k` 次操作后，返回数组中最高频元素的**最大可能频数**。`1 <= nums.length <= 10^5`，`1 <= nums[i] <= 10^5`，`1 <= k <= 10^5`。例：`nums = [1,2,4]`, `k = 5` → `3`（变成 `[4,4,4]`）；`nums = [1,4,8,13]`, `k = 5` → `2`；`nums = [3,9,6]`, `k = 2` → `1`。

给出完整的最优解答：考点、识别、推导、代码、复杂度、易错点。

## A
**考点。** 排序 + 滑动窗口（sliding window）：窗口内所有数抬到窗口最大值的代价单调。

**一句话。** 排序后用窗口 `[left, right]`，把窗口里所有数抬到 `nums[right]` 的代价是 `nums[right] * 窗口长度 - 窗口和`，超过 `k` 就缩左端，答案是最大窗口长度。

**识别。** 「只能加、不能减」「让尽量多的数相等」= 目标值一定是某个已有元素，且应当抬最接近它的那些数（排序后连续的一段）；窗口代价随 `right` 右移而增、随 `left` 右移而减，所以双指针；`n = 10^5` 要求 `O(n log n)`。

**推导。** 暴力：枚举目标值 `v`，把所有不大于 `v` 的数从大到小依次抬到 `v`，能抬几个算几个，`O(n^2)`。排序后，目标 `nums[right]` 要抬的一定是它左边紧挨着的一段，所以只剩下「每个 `right` 最远能往左扩到哪」；`right` 增大时这个最左位置只会右移或不动，因此左指针不回退，整体 `O(n)`。

```python
def max_frequency(nums: list[int], k: int) -> int:
    nums.sort()  # 排序后，要抬的数是目标左边紧挨着的一段
    left = 0
    window = 0  # 窗口 [left, right] 的元素和
    best = 1
    for right, x in enumerate(nums):
        window += x
        # 把窗口里所有数抬到 x 所需操作数 = x * 窗口长度 - 窗口和；超过 k 就缩左端
        while x * (right - left + 1) - window > k:
            window -= nums[left]
            left += 1
        best = max(best, right - left + 1)
    return best
```

运行：`([1,2,4], 5)` → `3`；`([1,4,8,13], 5)` → `2`；`([3,9,6], 2)` → `1`；`([7], 1)` → `1`。

**复杂度。** 时间 `O(n log n)`（排序主导，扫描 `O(n)`），空间 `O(1)`（不计排序）。

**拓展优化。**
- 窗口永不缩小的写法：`while` 换成 `if`，缩一格后窗口长度不会减少，最后答案是 `len(nums) - left`；窗口"只增不减"，省去 `best` 的维护。

**易错点。**
- 不排序：`[3,9,6]`, `k = 2` 返回 `2`，正确是 `1`（`3` 抬到 `6` 需要 `3` 次，超过 `2`）。
- 缩左端时忘了 `window -= nums[left]`：窗口和越来越偏大，代价被低估，`[1,3,5]`, `k = 1` 返回 `2`，正确是 `1`。
- Java / C++ 里 `x * 窗口长度` 最大约 `10^5 * 10^5 = 10^10`，要用 `long`；Python 整数不溢出。

**同模式。** LC 1004 最大连续 1 的个数 III、LC 424 替换后的最长重复字符、LC 209 长度最小的子数组、LC 2090 半径为 k 的子数组平均值。
