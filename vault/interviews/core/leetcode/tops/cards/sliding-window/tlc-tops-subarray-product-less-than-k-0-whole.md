## Q
**LC 713 乘积小于 K 的子数组（Subarray Product Less Than K）**｜Medium · 全公司热度第 63 名

给定一个整数数组 `nums` 和一个整数 `k`，返回子数组内所有元素的乘积严格小于 `k` 的连续子数组的数目。`1 <= nums.length <= 3 * 10^4`，`1 <= nums[i] <= 1000`，`0 <= k <= 10^6`。例：`nums = [10,5,2,6]`，`k = 100` → `8`（`[10]`、`[5]`、`[2]`、`[6]`、`[10,5]`、`[5,2]`、`[2,6]`、`[5,2,6]`；`[10,5,2]` 乘积 100，不算）；`nums = [1,2,3]`，`k = 0` → `0`。

给出完整的最优解答：考点、识别、推导、代码、复杂度、易错点。

## A
**考点。** 滑动窗口（sliding window），按右端点计数子数组。

**一句话。** 右端点逐个右移，维护乘积 `< k` 的最长窗口 `[left, right]`；以 `right` 结尾的合法子数组恰有 `right - left + 1` 个，累加即可。

**识别。** 「连续子数组 + 乘积（和）小于阈值」且元素全是正数 `>= 1`：加元素乘积只增不减、去元素只减不增，具有单调性，可用双指针。`n = 3 * 10^4`，枚举所有子数组 `O(n^2)` 太慢。

**推导。** 枚举每个起点向右乘，乘积 `>= k` 就停：`O(n^2)`。单调性带来的浪费：如果 `[left, right]` 合法，它的所有后缀（左端更靠右）也合法，所以固定 `right` 时合法的左端是一个区间 `[left, right]`；`right` 右移时最小合法的 `left` 只会右移，不会回头。

```python
def num_subarray_product_less_than_k(nums: list[int], k: int) -> int:
    if k <= 1:                         # nums[i] >= 1，任何非空子数组乘积 >= 1 >= k
        return 0
    ans = left = 0
    prod = 1
    for right, x in enumerate(nums):
        prod *= x
        while prod >= k:               # 乘积太大：左端收缩（元素都 >= 1，收缩只会让乘积变小）
            prod //= nums[left]
            left += 1
        ans += right - left + 1        # 以 right 结尾、左端落在 [left, right] 的子数组乘积都 < k
    return ans
```

运行：`([10,5,2,6], 100)` → `8`，`([1,2,3], 0)` → `0`，`([1,1,1], 2)` → `6`，`([1,1,1], 1)` → `0`。

**复杂度。** 时间 `O(n)`：`left` 和 `right` 各至多走 `n` 步；空间 `O(1)`。窗口乘积在乘入新元素前小于 `k <= 10^6`，乘入后不超过 `10^9`，32 位整数刚好够用。

**易错点。**
- 漏掉 `k <= 1` 的特判：`([1,1,1], 1)` 时乘积 `1 >= 1` 永远成立，`left` 越过数组末尾，抛 `IndexError`；`k = 0` 同理。
- 只统计窗口个数（每步 `ans += 1`）：`([10,5,2,6], 100)` 得到 `4`，正确 `8`；要数的是以 `right` 结尾的所有子数组。
- 用 `/` 代替 `//` 更新乘积：浮点数累积误差，`prod >= k` 的判断可能出错；乘积本身整除 `nums[left]`，用整除保持精确。
