## Q
**LC 135 分发糖果**｜Hard · 近一年被问：美国 1 次、国内 0 次 · CodeTop 国内累计 28 次 · 最近 2026-08-08（美国面试记录） · 也在：Amazon、Top Interview 150

`n` 个孩子站成一排，`ratings[i]` 是第 `i` 个孩子的评分。给每个孩子分糖果：每人至少 `1` 颗；相邻两个孩子中评分**更高**的那个必须获得更多糖果。求最少需要准备多少颗。`1 <= n <= 5 * 10^4`，`0 <= ratings[i] <= 5 * 10^4`。例：`[1,0,2]` → `5`（分别 `2,1,2`）；`[1,2,2]` → `4`（分别 `1,2,1`，评分相等的相邻孩子没有约束）。

给出完整的最优解答：识别、推导、代码、复杂度、易错点、追问。

## A
**一句话。** 约束有左右两个方向，各扫一遍：左到右保证「比左邻居评分高 → 比左邻居糖多」，右到左保证「比右邻居评分高 → 比右邻居糖多」，第二遍取 `max` 不破坏第一遍的结果；总和即答案。`O(n)`。

**识别。** 「相邻比较 + 每个元素的值取决于两侧」是双向约束：一次只处理一侧就能把约束拆成两个独立的、单方向的传递（贪心）。每个孩子取满足两个方向要求的**最小值**，也就是两遍结果的最大值，这个最小值同时是所有可行方案里每个位置的下界，所以总和最小。`n` 到 `5 * 10^4`，线性即可。

**推导。** 暴力：反复扫描直到没有违反约束的相邻对，每次违反就给评分高者加 `1`，最坏 `O(n^2)` 轮 → 浪费：同一个孩子的糖数被反复微调，其实最终值可以一次算出 → 先只看左约束：`give[i] = give[i - 1] + 1`（若评分升），否则 `1` → 再只看右约束，从右往左扫，需要时把 `give[i]` 抬到 `give[i + 1] + 1`，抬高时用 `max`，因为左约束已经要求的值不能被降低 → 两遍都只往上抬，且只抬到必要的程度，所以每个值都是最小的。

```python
def candy(ratings: list[int]) -> int:
    n = len(ratings)
    give = [1] * n                                 # 每人至少 1 颗
    for i in range(1, n):                          # 左到右：只管「比左邻居评分高 -> 比左邻居多」
        if ratings[i] > ratings[i - 1]:
            give[i] = give[i - 1] + 1
    for i in range(n - 2, -1, -1):                 # 右到左：只管「比右邻居评分高 -> 比右邻居多」
        if ratings[i] > ratings[i + 1]:
            give[i] = max(give[i], give[i + 1] + 1)    # 取最大，不能破坏第一遍已满足的约束
    return sum(give)
```

运行：`[1,0,2]` → `5`，`[1,2,2]` → `4`，`[1]` → `1`，`[2,2,2]` → `3`，`[1,2,3,4,5]` → `15`，`[5,4,3,2,1]` → `15`，`[1,3,4,5,2]` → `11`（分配 `1,2,3,4,1`）。

**复杂度。** 时间 `O(n)`，两遍扫描；空间 `O(n)`，`give` 数组。`O(1)` 空间的单遍写法见另一种解法。

**易错点。**
- 只扫一遍：只做左到右时 `[1,0,2]` 得到 `4`（分配 `1,1,2`），第一个孩子评分比第二个高却没有更多糖，正确是 `5`。
- 第二遍直接赋值而不取 `max`：`[1,2,3,1]` 第二遍会把 `3` 的糖从 `3` 压成 `2`，总数 `6`，且评分 `2` 和 `3` 的孩子糖数相等；正确是 `7`。
- 评分相等不需要相同的糖：条件用严格大于。写成 `>=` 在第一遍里 `[2,2,2]` 会得到 `6`，正确是 `3`。

**追问。**
- 返回具体分配方案：`give` 本身就是一组最优分配。
- `O(1)` 额外空间：沿「上坡 / 下坡」一遍扫描，维护上坡长度、下坡长度和坡顶糖数，下坡比坡顶还长时给坡顶补 `1`。
- 孩子站成环（首尾相邻）：先找到评分最小的孩子，从他开始把环切开，转化为线性问题再处理首尾的约束。
