## Q
**LC 3161 物块放置查询**｜正确性

线段树里存的是「每个障碍物左边的空隙」，查询时为什么还要再单独算 `x - p`？插入障碍物时为什么必须同时改后继的值？给出忘掉其中任何一个会出错的输入。

## A
**不变量。** 线段树的位置 `p` 上存的是 `p - pred(p)`，对当前每个障碍物 `p` 成立（`pred` 是前一个障碍物，原点算障碍物）；其余位置为 `0`。插入 `x` 时，受影响的只有 `x`（新增）和它的后继 `s`（`pred(s)` 从原来的前驱变成 `x`，空隙从 `s - pred` 缩成 `s - x`），其余障碍物的前驱不变。

**为什么要单独算 `x - p`。** `[0, x]` 被 `p` 以及 `p` 之前的障碍物切开：`p` 之前的每个空隙两端都是障碍物，值已在线段树里；最后一段 `[p, x]` 的右端是 `x` 而不是障碍物，线段树里没有，必须单独算 `x - p`。`p` 之后的障碍物在 `x` 的右边，物块不能越过 `x`，所以它们的空隙不能参与。

**反例一：漏掉尾段。** `[[1,2],[2,5,3]]`：障碍物只有 `2`，完整空隙是 `[0,2]` 长 `2`，尾段 `[2,5]` 长 `3`。只看完整空隙得到 `2 < 3`，返回 `False`；加上尾段 `5 - 2 = 3 >= 3`，正确答案 `True`。

**反例二：不更新后继。** `[[1,7],[2,7,6],[1,2],[2,7,5],[2,7,6]]`：先建 `7`，它的空隙是 `7`；再建 `2`，`7` 的空隙应缩成 `7 - 2 = 5`。不更新的话，位置 `7` 仍存着 `7`，最后一次查询 `sz = 6` 得到 `7 >= 6`，输出 `[True, True, True]`；正确答案 `[True, True, False]`。

**越界提醒。** 前驱 `obstacles[k - 1]` 依赖原点哨兵：`x >= 1` 保证 `k >= 1`，所以 `k - 1 >= 0`，不会取到负下标。
