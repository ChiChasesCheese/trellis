## Q
**LC 72 编辑距离**｜追问

面试官接着问：（1）不仅要距离，还要**输出具体的操作序列**？（2）三种操作的**代价不同**，或者再加一个「交换相邻两个字符」？（3）两个字符串都有 `10^5` 长，但已知编辑距离很小呢？（4）表太大怎么办？

## A
1. **操作序列**：完整的 `(m+1) × (n+1)` 表保留了所有格子的值。从 `(m, n)` 往回走：两个字符相同就斜着走（无操作）；否则看当前值等于哪个邻格加 `1`：来自左上是替换，来自上方是删除 `word1[i]`，来自左边是插入 `word2[j]`。把走过的操作反过来就是从头到尾的序列。`("horse", "ros")` 得到：替换 `h → r`，删除 `r`，删除 `e`。
2. **加权与交换**：加权时把转移里的 `1 +` 换成各自代价，删除和插入的代价也要体现在边界行列上。允许相邻交换（Damerau-Levenshtein）时，如果 `word1[i-1] == word2[j-2]` 且 `word1[i-2] == word2[j-1]`，多一个候选 `dp[i-2][j-2] + 1`。
3. **长串、小距离**：如果距离不会超过 `k`，只有离主对角线不超过 `k` 的格子有意义，只算宽度 `2k + 1` 的带状区域，`O(k · n)`；距离超过 `k` 可以提前判负。位并行（Myers）算法可以进一步把常数压到 `n/64`。
4. 空间可以压到 O(n)：见 Python 工具箱「DP 降维」。

**Python 提醒**：建二维表要写 `[[0] * (n + 1) for _ in range(m + 1)]`。写成 `[[0] * (n + 1)] * (m + 1)` 会得到 `m + 1` 个指向**同一行**的引用，改一格全表跟着变。自顶向下用 `@cache` 的写法递归深度可达 `m + n`，两个 500 字符的串就会触发 `RecursionError`；面试里写自底向上。
