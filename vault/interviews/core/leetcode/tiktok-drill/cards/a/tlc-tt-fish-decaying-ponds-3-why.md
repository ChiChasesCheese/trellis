## Q
**鱼塘捕鱼（产量递减）**｜正确性

为什么“所有收获里最大的 `t` 个之和”就是答案？阈值 `x` 处出现并列时，为什么是“严格大于 `x` 的全拿，再用 `(t - taken) * x` 补满”？给出几个错误写法的反例。

## A
**不变量。** 每个塘的收获序列不增。所以取最大的 `t` 个收获时，同一个塘里被取的一定是序列的**前缀**（同值时可以选靠前的），这正好对应一种合法的捕鱼顺序；任何合法方案的收获集合大小为 `t`，其和不会超过最大的 `t` 个之和。

**阈值。** 设 `x` 是最大的值，使 `count(收获 >= x) >= t`。那么 `count(收获 >= x + 1) < t`，严格大于 `x` 的收获全部要拿；总数 `taken < t`，剩下 `t - taken` 个名额只能取 `x`（`count(>= x) >= t` 保证 `x` 的机会足够）。

**反例一：并列处理错。** `[3, 3]`、`[1, 1]`、`t = 3`，收获 `3, 3, 2, 2, 1, 1`。`x = 2`：严格大于 `2` 的有 2 个（`3, 3`），再补 `1` 个 `2`，共 `8`。把所有 `>= 2` 的都拿是 `3 + 3 + 2 + 2 = 10`（多拿一次）；忘了补 `(t - taken) * x` 是 `6`。

**反例二：一个塘一个塘榨干。** `[10, 6]`、`[4, 1]`、`t = 3`：最大首捞量的塘 0 连捕三次是 `10 + 6 + 2 = 18`；全局最大的三个收获是 `10, 6, 6`，共 `22`。

**反例三：不截断。** `[5]`、`[5]`、`t = 4` 的序列 `5, 0, -5, -10` 若直接加，得 `-10`；收获不低于 `0`，正确是 `5`。

**`decay = 0` 为什么安全。** 有这种塘（`f > 0`）时，`count(>= x)` 对 `x <= f` 恒为 `cap`，所以最大的 `x` 至少是它的 `f`，严格大于 `x` 的循环里不会遇到它，不会除零；它在补满阶段每次贡献 `x`。
