## Q
**LC 41 缺失的第一个正数**｜正确性

原地交换法的不变量是什么？为什么 `while` 里要同时判断 `1 <= nums[i] <= n` 和 `nums[nums[i] - 1] != nums[i]`？写成一行元组交换 `nums[i], nums[nums[i]-1] = nums[nums[i]-1], nums[i]` 为什么错？

## A
**不变量。** 外层处理完下标 `i` 时，`nums[i]` 要么是 `i + 1`（回到了家），要么是一个无用的值（非正、大于 `n`，或者家里已经有同样的数）。每个落在 `[1, n]` 的值，最终要么在自己的家里，要么是重复值。所以第二遍扫描中，第一个 `nums[i] != i + 1` 的下标说明 `i + 1` 没有出现：若它出现过，一定有一份在 `nums[i]`。

**两个条件各管一件事。** `1 <= nums[i] <= n` 过滤掉无用的值，也保证下标 `nums[i] - 1` 合法。`nums[nums[i] - 1] != nums[i]` 说明目标位置还没有放好这个值：已放好或遇到重复就停，否则交换后的值会反复和自己交换，永远退出不了。这个条件还保证每次交换都让一个值进入自己的家，所以交换总次数至多 `n`。

**反例一：缺少重复检查。** `nums = [1,1]`：`nums[0] = 1` 的家是下标 `0`，就是自己，交换不改变任何东西，`while` 永远为真，程序死循环；正确答案是 `2`。

**反例二：元组交换。** `[3,4,-1,1]`：写成 `nums[i], nums[nums[i]-1] = nums[nums[i]-1], nums[i]`，Python 先把右边求值成元组，再从左到右赋值：先写 `nums[i]`，随后第二个目标 `nums[nums[i]-1]` 的下标是用**刚改过**的 `nums[i]` 算的，值被写到了错误的格子。数组在几个状态之间来回打转，程序死循环；正确答案是 `2`。先 `j = nums[i] - 1`，再 `nums[i], nums[j] = nums[j], nums[i]`，两个目标的下标都是固定的。
