## Q
**LC 322 零钱兑换**｜正确性

零钱兑换为什么不能用「每次取不超过剩余金额的最大面额」的贪心？以及内层金额循环为什么必须正序、倒序会错在哪？各给一个具体输入。

## A
**不变量。** 处理完前 `t` 种硬币后，`dp[a]` 是只用这前 `t` 种硬币凑成 `a` 的最少个数（凑不出为哨兵）。加入第 `t+1` 种硬币 `c` 时，`dp[a] = min(不用 c, dp[a - c] + 1)`，其中 `dp[a - c]` 已经可以包含 `c`。

**反例一：贪心。** `coins = [1,3,4]`，`amount = 6`。
- 贪心先取最大的 `4`，剩 `2`，再取 `1+1`，共 `3` 枚。
- 最优是 `3+3`，共 `2` 枚。贪心只在面额有特殊结构（如每个面额是前一个的倍数）时才对，这里不满足。

**反例二：金额倒序。** 内层从大到小遍历时，更新 `dp[a]` 用到的 `dp[a - c]` 还没被当前这种硬币更新过，等于每种硬币只能用一次（0/1 背包）。
- `coins = [2]`，`amount = 4`：倒序时 `dp[4]` 看到的是 `dp[2] = 哨兵`，结果 `-1`。
- 正序时先得到 `dp[2] = 1`，再得到 `dp[4] = dp[2] + 1 = 2`，答案 `2`。

**哨兵的作用。** 不可达的 `dp[a - c]` 是 `amount + 1`，加一后是 `amount + 2`，不可能小于 `dp[a]` 的初值，所以不会把不可达的状态当成可达的。
