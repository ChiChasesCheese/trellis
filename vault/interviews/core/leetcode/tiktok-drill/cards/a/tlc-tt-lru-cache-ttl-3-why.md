## Q
**带 TTL 的 LRU 缓存**｜正确性

固定容量的 LRU 缓存，每条数据带自己的 `ttl`；用 `OrderedDict` 管使用顺序，用「按到期时刻排序的最小堆」加写入版本号清理过期条目。堆里为什么必须带版本号？「满了先清过期、再淘汰最久未用」的顺序换过来会错成什么样？

## A
**不变量。** 每个在缓存里的 key 在堆里**恰有一个**项的版本号等于 `version[key]`，其余同 key 的项都是旧项。弹出堆项时只处理版本号对得上的项，所以被删除的永远是「当前写入且已到期」的条目；旧项（被覆盖或已被淘汰的）直接丢弃，不影响缓存。

**反例一：不带版本号。** 容量 `2`：`put(1, 1, ttl=1)`，再 `put(1, 2, ttl=100)`（覆盖，到期时刻变成 `100`），`put(9, 9, ttl=100)`，`get(1)`（key 1 变成最近使用）。堆里还留着 key 1 的旧项（到期时刻 `1`，版本 `1`）。`t = 2` 时 `put(3, 3, ttl=100)`，缓存已满，清理会弹出这个旧项：只看 key 就把活着的 key 1 删掉，`get(1)` 得到 `-1`、`get(9)` 得到 `9`；带版本号时旧项版本 `1` 与当前版本 `2` 对不上，丢弃，最久未用的 key 9 被淘汰，`get(1)` 得到 `2`、`get(9)` 得到 `-1`。

**反例二：先淘汰、不清过期。** 容量 `2`，`t = 0` 时 `put(1, 1, 1)`、`put(2, 2, 100)`，`get(1)`（key 1 变成最近使用，key 2 成了最久未用），`t = 2` 时 `put(3, 3, 100)`。错误做法直接淘汰 key 2，之后 `get(1)`、`get(2)`、`get(3)` 得到 `-1`、`-1`、`3`；正确做法先清掉已过期的 key 1，容量已够，三次读取得到 `-1`、`2`、`3`。

**反例三：覆盖写也检查容量。** 容量 `2` 存着 key 1、key 2（key 1 更久未用），`put(2, 9, 5)` 只是改值，不该动别人。错误做法先淘汰 key 1，`get(1)` 得到 `-1`；正确做法跳过容量检查，`get(1)` 返回原值。
