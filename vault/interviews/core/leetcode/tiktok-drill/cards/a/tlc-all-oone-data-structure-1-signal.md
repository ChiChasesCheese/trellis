## Q
**LC 432 全 O(1) 的数据结构**｜Hard · TikTok 高频

设计类 `AllOne`，存储字符串计数：`inc(key)` 计数加 `1`（不存在则以 `1` 插入），`dec(key)` 计数减 `1`（减到 `0` 就删除，调用时 `key` 一定存在），`getMaxKey()` / `getMinKey()` 返回任意一个计数最大 / 最小的字符串，没有元素返回 `""`。每个操作要求平均 `O(1)`。`1 <= key.length <= 10`，`key` 由小写字母组成，最多调用 `5 * 10^4` 次。例：`inc("hello")` 两次、`inc("leet")` 一次后，`getMaxKey()` 得 `"hello"`，`getMinKey()` 得 `"leet"`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「所有操作 `O(1)`」+「计数的最大 / 最小」→ 堆和平衡树是 `O(log n)`，不满足；必须有一个**按计数有序、且更新只发生在相邻位置**的结构。
- 计数每次只变 `±1` → key 的新计数只可能落在**紧邻**的桶，这个性质让“有序”可以靠链表在 `O(1)` 内维护。
- 「返回**任意**一个最大 / 最小」→ 同计数的 key 可以放进一个集合（桶），不需要在桶内排序。
- 「按 key 找位置」→ 哈希表 `key → 桶`。这是**哈希表加双向链表**的组合设计题，同一思路是 LFU 缓存。

**推导链。**
1. 暴力：字典存计数，取最值时扫描，`O(n)`，调用 `5 * 10^4` 次、key 多时超时。
2. 想按计数有序：堆每次 `±1` 要 `O(log n)`；按计数下标开数组，计数范围太大且稀疏。
3. 洞察：把计数相同的 key 放进同一个桶，桶按计数排成**双向链表**；`inc` 把 key 搬到下一个桶，`dec` 搬到上一个桶。
4. 搬运的目标桶要么是相邻桶（计数恰为 `c ± 1`），要么不存在而在旁边新建；搬走后若原桶空了立刻摘除，保证链表头尾永远是非空桶。
5. 头尾哨兵省掉空表特判；`getMinKey` 取头后第一个桶任意 key，`getMaxKey` 取尾前第一个桶任意 key。五个操作都是 `O(1)`。

**同模式的题**：LC 460 LFU 缓存、LC 146 LRU 缓存、LC 380 `O(1)` 时间插入删除和获取随机元素、LC 895 最大频率栈。
