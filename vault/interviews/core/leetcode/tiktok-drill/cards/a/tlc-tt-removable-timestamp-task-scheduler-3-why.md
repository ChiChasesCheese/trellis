## Q
**可删除任务的时间戳调度器（popTask）**｜正确性

懒删除时，为什么用「`alive[id]` 等于条目的时间戳」判断条目是否有效，而不是只记一个「已删除 id 的集合」？`popTask` 为什么必须真的移除？给出写错时的具体输入。

## A
**不变量。** 任何时刻，调度器里的有效任务集合就是字典 `alive` 的键集合；堆里的每个有效任务都有一个且仅有一个时间戳与 `alive` 一致的条目（其余是失效的旧条目）。弹出堆顶时，如果它有效，那么它就是所有有效任务里 `(timestamp, taskId)` 最小的，因为堆顶是整个堆的最小条目，而有效条目是堆的子集。

**为什么用时间戳匹配。** 同一个 `taskId` 可能先后以不同时间戳存在于堆中（先加入、删除、再加入，或直接更新）。只用 id 判断，旧条目和新条目无法区分；与 `alive[id]` 比较时间戳，则只有当前那一个条目被认为有效。

**反例一：已删除集合。** 加入 `x@1`，删除 `x`，再加入 `x@7`，`popTask(1)`：
- 堆里有 `(1,x)` 和 `(7,x)`；已删除集合含 `x`。
- 两个条目都因为 `x` 在集合里被跳过，结果是 `[]`。
- 正确是 `['x']`：被取走的应该是重新加入后的那个任务。

**反例二：`popTask` 只查看。** 加入 `(a,5)`、`(b,3)`、`(c,3)`，连续调用两次 `popTask(2)`：
- 只查看不移除，两次都是 `['b','c']`。
- 正确：第一次 `['b','c']`，第二次 `['a']`。

**并列的确定性。** `(3,b)` 与 `(3,c)` 相比较时，元组按第二个字段继续比较，`b < c`，所以 `b` 先出，且每次运行结果相同。
