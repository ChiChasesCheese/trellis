## Q
**LC 926 将字符串翻转到单调递增**｜正确性

遇到 `'0'` 时为什么 `flips = min(flips + 1, ones)` 就够了？这两项分别对应什么选择？给出「只把第一个 `1` 之后的 `0` 全翻成 `1`」的做法出错的具体输入。

## A
**不变量。** 扫描完 `s[:i]` 后，`flips` 是把 `s[:i]` 变成单调递增所需的最少翻转，`ones` 是 `s[:i]` 中 `1` 的个数。

**遇到 `'1'`。** 在任何单调串后面接一个 `1` 仍然单调，且不需要翻转它，所以 `flips` 不变。

**遇到 `'0'`。** 这个新的 `0` 要么保持为 `0`，要么被翻成 `1`：
- 翻成 `1`：前缀 `s[:i]` 已经是最优单调串，再接一个 `1` 合法，总代价 `flips + 1`。
- 保持为 `0`：单调串里 `0` 后面不能再有 `1`，所以前面必须全是 `0`，也就是把前缀里所有 `ones` 个 `1` 翻成 `0`，总代价 `ones`（此时前缀已经全为 `0`，不需要别的翻转）。

两者已经覆盖了这个字符的全部合法处理方式，取最小值即最优。

**反例：贪心。** 「第一个 `1` 之后的每个 `0` 都翻成 `1`」：`s = "100000"`：
- 贪心：第一个 `1` 之后有 `5` 个 `0`，翻 `5` 次得到 `111111`。
- 最优：把开头的 `1` 翻成 `0`，得到 `000000`，只要 `1` 次。

贪心输出 `5`，正确答案 `1`。DP 在这里：`ones = 1`，每遇到一个 `0`，`flips = min(flips + 1, 1)`，始终不超过 `1`。
