## Q
**LC 81 搜索旋转排序数组 II**｜Medium · CodeTop 国内累计 3 次 · 最近 2026-04-16（CodeTop）

有一个按**非降序**排列的整数数组 `nums`，值**可能重复**。它在某个未知的下标 `k`（`0 <= k < nums.length`）上被旋转，变成 `[nums[k], ..., nums[n-1], nums[0], ..., nums[k-1]]`，例如 `[0,1,2,4,4,4,5,6,6,7]` 在下标 `5` 旋转后可能是 `[4,5,6,6,7,0,1,2,4,4]`。给旋转后的 `nums` 和整数 `target`，判断 `target` 是否在数组中，返回 `true` 或 `false`，操作步骤尽量少。`1 <= nums.length <= 5000`，`-10^4 <= nums[i] <= 10^4`，`-10^4 <= target <= 10^4`。例：`nums = [2,5,6,0,0,1,2], target = 0` → `true`；`target = 3` → `false`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「非降序排列」+「旋转」+「查找」→ **二分查找**：旋转让整体有序变成局部有序，但每次切开仍有一半有序。
- 「**可能重复**」→ 有些输入无法判断哪半有序（`nums[lo] == nums[mid] == nums[hi]`），要加一个收缩分支，最坏 `O(n)`；这是和 LC 33 的唯一区别。
- 「操作步骤尽量少」→ 面试官想看到 `O(log n)` 的主体加对最坏情况的诚实分析。
- `n <= 5000` → `O(n)` 也能过，但目标是给出二分解并讲清楚退化。

**推导链。**
1. 暴力：线性扫描 `target in nums`，`O(n)`。
2. 浪费：数组局部有序没被用上。
3. 洞察：断点只有一个，所以 `[lo, mid]` 与 `[mid, hi]` 至少一半有序；有序半边用端点判断 `target` 是否在内，决定丢哪一半。
4. 重复：三个端点相等时无法判断，`lo += 1, hi -= 1`；其余分支同 LC 33。

**同模式的题**：LC 33 搜索旋转排序数组、LC 153 / 154 寻找旋转排序数组中的最小值、LC 34 在排序数组中查找首尾位置。
