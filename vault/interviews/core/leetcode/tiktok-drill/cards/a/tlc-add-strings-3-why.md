## Q
**LC 415 字符串相加**｜正确性

竖式加法的循环里保持什么不变量？为什么循环结束后还要检查一次进位？如果把 `zip_longest` 换成 `zip`，会在什么输入上出错？

## A
**不变量。** 处理完第 `k` 位（从个位数起）后，`digits` 里已经是和的最低 `k` 位，`carry` 是传给第 `k + 1` 位的进位。每位的和最大是 `9 + 9 + 1 = 19`，所以 `carry` 只可能是 `0` 或 `1`，`divmod(19, 10)` 得到进位 `1`、当前位 `9`。

**为什么要检查最后的进位。** 两个 `n` 位数相加，结果可能有 `n + 1` 位。最高位相加产生进位时，没有下一位来消费它，循环就结束了。如果不追加，这一位的 `1` 就丢了。

**反例一：漏掉最后的进位。** `("999", "1")`：逐位得到 `0, 0, 0`，最后 `carry = 1`。漏掉收尾，返回 `"000"`；正确是 `"1000"`。更短的 `("5", "5")` 返回 `"0"`，正确是 `"10"`。

**反例二：用 `zip`。** `zip` 在较短的序列用完时停止。`("456", "77")`：只处理了两位，`6 + 7 = 13` 写 `3` 进 `1`，`5 + 7 + 1 = 13` 写 `3` 进 `1`，较长数的高位 `4` 被丢掉，最后补上进位得到 `"133"`；正确是 `"533"`。`("11", "123")` 得到 `"34"`，正确是 `"134"`。`zip_longest(…, fillvalue="0")` 把短数在高位补 `0`，高位照常参与运算。

**反例三：结果不反转。** `digits` 是低位在前。`("11", "123")` 的 `digits` 是 `["4", "3", "1"]`，不反转就得到 `"431"`。
