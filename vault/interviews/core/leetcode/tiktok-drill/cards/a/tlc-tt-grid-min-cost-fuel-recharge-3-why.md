## Q
**带油量限制和补给点的网格最小代价路径**｜正确性

带油量和补给点的最小代价路径，用 Dijkstra 在（位置，剩余油量）状态上搜索，并丢弃被支配的状态。为什么「每格只保留已弹出的最大剩余油量」不会丢掉最优解？为什么油量可以对 `m·n` 封顶？忽略油量、补给点处理错，各会错成什么样？

## A
**不变量。** Dijkstra 按总代价非递减弹出状态。若某格已经弹出过状态 `(c1, f1)`，之后弹出的 `(c2, f2)` 满足 `c2 >= c1`；当 `f2 <= f1` 时，任何从 `(c2, f2)` 出发的走法，都能从 `(c1, f1)` 出发原样走一遍（油量更多，限制更宽松），总代价不会更高，所以 `(c2, f2)` 对最优解没有贡献，可以丢弃。每个格子保留下来的状态，剩余油量严格递增。

**为什么能对 `m·n` 封顶。** 任何从起点到终点的走法，若重复经过同一个格子，把中间的环路删掉：代价不增加（代价非负），经过的补给点只会更靠前或不变，油量不会更少（删环路减少了消耗；若环路上有补给点，删掉后到下一个点的油量也不低于原来）。所以最优路径是简单路径，步数不超过 `m·n - 1`，油量超过这个数没有意义。

**反例一：忽略油量。** `[[0,1,1,1],[9,-1,9,1],[1,1,1,1]]`、`K = 4`：只按代价求最短路得到 `5`，但这条路要走 `5` 步，油量不够，正确是 `-1`。

**反例二：补给点处理错。** `[[0,1,1,1,1,1]]`（一行六格），补给点 `{(0, 2)}`、`K = 3`：走到 `(0, 2)` 用 `2` 步，油量恢复到 `3`，再走 `3` 步到终点，总代价 `5`。忽略补给点得到 `-1`（一共要走 `5` 步，只有 `3` 单位油）；把补给点当成“只加 `1` 单位油”，到达时剩余 `1 + 1 = 2`，还差一步，同样得到 `-1`。恢复为满才是 `5`。

**反例三：弹出终点前先检查油量。** 到达终点时油量恰好为 `0` 是合法的；如果先判断 `left == 0` 就丢弃，`K = 5` 的例子会错成 `-1`，正确是 `5`。
