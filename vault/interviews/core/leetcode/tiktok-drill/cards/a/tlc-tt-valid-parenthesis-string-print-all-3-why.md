## Q
**有效括号字符串：判断，并输出全部方案**｜正确性

判断带 `'*'` 的括号串是否有效时，贪心维护未匹配左括号数的范围 `[lo, hi]`。为什么这个范围里的每个整数都能取到，`hi < 0` 为什么直接失败，`lo` 为什么要和 `0` 取大？下界不取大、不检查 `hi`、输出方案不去重，各会错成什么样？

## A
**不变量。** 处理完前缀后，`hi` 是「所有 `'*'` 都当 `'('`」时的未匹配数，也是上界；`lo` 是「尽量把 `'*'` 当 `')'`」时的下界（不允许小于 `0`）。区间内每个整数都可达：从两端各改变一个 `'*'` 的取值，未匹配数每次变化 `1`，所以相邻整数都能取到。`hi < 0` 说明即使所有 `'*'` 都开括号，右括号仍然多出来，没有任何取法能救回来，失败。`lo` 小于 `0` 的取值对应前缀里右括号多于左括号，是非法状态，要裁剪到 `0`（多出的 `'*'` 当空串）。最终要求 `0` 在范围内，即 `lo == 0`。

**反例一：下界不与 `0` 取大。** `"()*("`：`(` 后 `lo = 1`，`)` 后 `0`，`*` 后 `lo = -1`，再 `(` 后回到 `0`，结尾 `lo == 0`，误判有效；实际末尾的 `(` 永远没有 `)` 配对，无效。裁剪后 `*` 之后 `lo = 0`，`(` 之后 `lo = 1`，结尾失败。

**反例二：不检查 `hi < 0`。** `")*"`：`)` 后 `lo = hi = -1`，裁剪 `lo` 到 `0` 后 `*` 使 `hi` 回到 `0`，结尾 `lo == 0`，误判有效；其实开头的 `)` 没有任何东西可以配对，无效。

**反例三：输出方案不去重。** `"***"` 共有 `27` 种取法，其中 `4` 种得到有效串，但只有 `""` 和 `"()"` 两个不同的字符串（`"()*"` 与 `"*()"` 两种取法都得到 `"()"`）；用列表收集会重复，应当用集合。

**反例四：只比较括号个数、不检查前缀。** `")("` 里左右括号个数相等，却是无效的；搜索里只有 `bal > 0` 时才允许选 `')'`，保证每个前缀合法。
