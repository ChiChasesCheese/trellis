## Q
**LC 306 累加数**｜正确性

为什么只枚举前两个数就够？前导零检查和 `j < n` 这两个边界各自防住什么错误？各给一个出错的输入。

## A
**不变量。** 前两个数 `a`、`b` 一旦确定，序列的第三个数必须等于 `a + b`，第四个必须等于 `b + (a + b)`……每个数的值都是唯一的，转成字符串后长度也唯一。所以对一组 `(i, j)`，序列要么存在要么不存在，不需要再选；枚举所有 `(i, j)` 就覆盖了所有可能的序列。

**边界 1：前导零。** 序列里的多位数不能以 `0` 开头，但 `int("02")` 会悄悄解析成 `2`。`num = "1023"`：
- 不检查前导零时，`(i, j) = (1, 3)` 把它读成 `1, 02, 3`：`1 + 2 = 3`，通过，返回 `True`；
- 正确答案 `False`：`02` 不是合法的数。其他切法也都失败。
- 注意单独的 `0` 是合法的：`"000"` 切成 `0, 0, 0`，`0 + 0 = 0`，正确答案 `True`。所以检查条件是「**多位**且以 `0` 开头」：`i > 1 and num[0] == "0"`，`j - i > 1 and num[i] == "0"`。

**边界 2：`j` 必须小于 `n`。** 序列至少要有三个数。如果 `j` 允许取到 `n`，第二个数一直到字符串末尾，`while k < n` 一次也不执行，直接返回 `True`。`num = "12"`：`(i, j) = (1, 2)` 切成 `1, 2`，只有两个数，被误判为累加数，返回 `True`；正确答案 `False`。

**剪枝为什么不会漏解。** 第三个数 `a + b` 的位数不少于 `max(len(a), len(b))`（加法不会让位数变少），所以剩下的字符数 `n - j` 必须至少是这个长度；不满足的 `(i, j)` 不可能成功，可以直接跳过。
