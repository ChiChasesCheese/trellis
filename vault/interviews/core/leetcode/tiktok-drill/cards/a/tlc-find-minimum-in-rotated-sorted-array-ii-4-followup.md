## Q
**LC 154 寻找旋转排序数组中的最小值 II**｜追问

面试官接着问：（1）允许重复为什么会让时间复杂度变差，能不能证明最坏情况下无法比 `O(n)` 更好；（2）去掉重复，代码怎么变；（3）要返回最小值的下标呢？

## A
1. **下界**：考虑数组 `[1,1,1,0,1,1]` 这一族：一个 `0` 加 `n - 1` 个 `1`，`0` 可以在任意位置，都是合法的旋转结果。任何算法在没有检查某个位置之前，对手都可以说那个位置是 `0`，除非已经检查完所有位置，否则无法确定最小值。所以最坏情形下界是 `Ω(n)`。上面的算法在 `[0] + [1] * 4999` 上要走 `4999` 次迭代，在 `[1] * 5000` 上也是。
2. **无重复（LC 153）**：去掉相等分支，`nums[mid] > nums[hi]` 时 `lo = mid + 1`，否则 `hi = mid`，每次折半，严格 `O(log n)`。

```python
def find_min_distinct(nums: list[int]) -> int:
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] > nums[hi]:
            lo = mid + 1
        else:
            hi = mid
    return nums[lo]
```

`[4,5,6,7,0,1,2]` → `0`，`[3,4,5,1,2]` → `1`，`[11,13,15,17]` → `11`。
3. **返回下标**：循环结束时 `lo` 是某个最小值所在的位置，但不一定是最小值第一次出现的位置。`[0,1,1,0]`（`[0,0,1,1]` 旋转 `3` 次）返回 `3`，而第一个 `0` 在下标 `0`。要得到「旋转点」或「第一个最小值」需要再约定清楚，并多做一次向左的扫描。

**Python 提醒**：`min(nums)` 在 C 层扫描，对 `n = 5000` 足够快；面试里它是正确性的基线，而不是对「步骤尽可能少」的回答。`(lo + hi) // 2` 对非负的 `lo`、`hi` 不会出问题，Python 整数也没有溢出。
