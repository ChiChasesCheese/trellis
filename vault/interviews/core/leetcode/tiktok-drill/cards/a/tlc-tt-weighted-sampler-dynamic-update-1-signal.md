## Q
**按权重采样器（支持动态修改权重）**｜Medium · TikTok 高频

类 `Sampler` 接收 `n` 个非负整数权重，`sample()` 按权重比例随机返回一个下标（权重为 `0` 的下标不会被选中）。追问：权重会被 `update(i, weight)` 动态修改，前缀和每次更新 `O(n)` 太慢，要让 `update` 和 `sample` 都是 `O(log n)`。`1 <= n <= 10^5`，`0 <= w[i] <= 10^6`，调用总数不超过 `10^5`。例：权重 `[1,3,0,6]`，随机整数 `0..9` 对应下标 `[0,1,1,1,3,3,3,3,3,3]`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「按权重随机」→ 前缀和切分 `[0, total)` 的区间，随机整数落在哪个区间就选哪个下标（逆变换采样），查找用二分。
- 「权重动态修改」→ 前缀和不能一次性算好，需要「单点更新 + 前缀和查询」的结构：Fenwick 树 / 线段树 / 平衡树。
- 「`update` 和 `sample` 都要 `O(log n)`」→ 采样要在树上直接找位置，而不是二分加每步求前缀和（那是 `O(log² n)`）。
- `n = 10^5`、调用 `10^5` 次：任何每次 `O(n)` 的做法总计 `10^10`，超时。

**推导链。**
1. 暴力：每次 `sample` 线性扫描累加，`O(n)`。
2. 静态版：`accumulate` 得前缀和，`bisect_right(prefix, randrange(total))` 采样 `O(log n)`；但每次 `update` 要重算前缀和 `O(n)`。
3. 浪费：一次单点修改只影响覆盖它的那几段前缀和，却重算了全部。
4. 洞察：Fenwick 树节点 `i` 管 `(i - lowbit(i), i]` 的权重和；单点更新只改 `O(log n)` 个节点，前缀和只合并 `O(log n)` 个节点。
5. 最优：采样用 Fenwick 的倍增下降，从高位到低位试着往右跨，找到最大的 `pos` 使前缀和 `<= r`，答案就是 `pos`，`O(log n)`。

**同模式的题**：LC 528 按权重随机选择、LC 497 非重叠矩形中的随机点、LC 398 随机数索引、LC 307 区域和检索 - 数组可修改。
