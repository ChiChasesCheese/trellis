## Q
**深度合并两个嵌套 JSON**｜正确性

用显式栈合并两个嵌套 JSON：栈里放 `(结果字典, 左字典, 右字典)`，弹出一个就遍历它们键的并集。为什么这样得到的结果和递归写法相同、且不会漏键或重复处理？递归、原地修改输入、只检查一边是字典，各会错成什么样？

## A
**不变量。** 栈里每个三元组都对应结果树中一个已经创建、位置确定的字典，它的内容尚待填充；每个三元组恰好被弹出一次，弹出时给结果字典填入键并集里的每个键，恰好一次。叶子情形（只在一边出现、列表拼接、标量覆盖、类型冲突）当场写入；需要继续合并的字典对先在结果里创建空字典再压栈。每对字典的处理彼此独立，所以弹出的先后顺序不影响结果，与递归的访问顺序可以不同，结果相同。

**反例一：递归。** 深度 `2 * 10^4` 的单链字典，`merge` 写成递归函数，运行到约 `1000` 层就抛 `RecursionError`；`copy.deepcopy` 对同样的输入也抛 `RecursionError`。

**反例二：原地修改。** `a = {"x": {"y": 1}}`，`b = {"x": {"z": 2}}`，写成「把 `b` 的内容并进 `a` 再返回 `a`」，返回值正确，但 `a` 已经被改成 `{'x': {'y': 1, 'z': 2}}`，违反不修改输入。

**反例三：只检查左边是字典。** 左边 `{"k": {"x": 1}}`、右边 `{"k": 5}`：只判断 `isinstance(left[key], dict)` 就递归，会对标量 `5` 调用字典方法而崩溃；两边都是字典才递归，其余走 `_combine`，`"later"` 策略下得到 `{'k': 5}`，`"error"` 策略抛 `TypeError`。

**反例四：列表拼接顺序反了。** `merge({"t": [1, 2]}, {"t": [3]})` 必须是 `{'t': [1, 2, 3]}`；写成 `y + x` 得到 `{'t': [3, 1, 2]}`。
