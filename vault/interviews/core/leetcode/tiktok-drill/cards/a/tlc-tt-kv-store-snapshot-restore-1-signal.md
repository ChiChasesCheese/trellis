## Q
**带快照与恢复的内存键值存储**｜Medium · 近一年被问：美国 2 次、国内 0 次 · 最近 2026-10-15（面试记录）

实现内存键值存储 `KVStore`：`put(key, value)`、`get(key)`、`delete(key)`，再加 `snapshot()`（把全部数据序列化成一个字符串返回）和 `restore(data)`（用快照字符串把存储恢复到快照时刻的状态）。序列化格式要自己设计，不能调用 `json` / `pickle`。key 和 value 是字符串，可以为空，可以含冒号、分号、换行等任意字符；快照之后的写入不能影响已取出的快照；数据损坏时 `restore` 抛 `ValueError` 且原存储不变。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「自己设计序列化」→ 核心是编码格式能否**无歧义地解回来**，不是存取本身。
- 「key 和 value 可以含任意字符」→ 分隔符拼接会冲突；要么转义，要么**长度前缀**（length-prefix）。
- 「快照之后的写入不能污染快照」→ 快照是不可变的值（字符串），不是内部字典的引用。
- 「数据损坏时原存储不变」→ `restore` 先解析到临时对象，成功再替换（先校验后提交）。

**推导链。**
1. 暴力：`"k=v;"` 拼接。`put("x=y", "z")` 得到 `x=y=z`，解码拆错。
2. 浪费 / 脆弱：给分隔符加转义，还要转义转义符本身，规则复杂、容易漏。
3. 洞察：每个字符串写成 `长度:内容`，解码时读完数字就按长度整段取，不需要判断内容里有没有分隔符；开头先写条目数，截断和多余数据都能发现。
4. 最优：编码、解码都是对总字符数的一次线性扫描；`restore` 解析到临时字典，全部成功才赋值。
