## Q
**补充题23 检测循环依赖**｜正确性

拓扑排序判环里，为什么「取走的模块数小于 `n`」恰好等价于「有环」？用并查集（把依赖当无向边）判环为什么不行？

## A
**不变量。** 每次取走的模块，其全部前置依赖都已经被取走。因此取走的集合始终是“依赖闭合”的：不会取走任何依赖了未取走模块的模块。

**无环 ⇒ 全部取走。** 无环的有向图里，任何非空的剩余子图都至少有一个入度为 `0` 的点（沿着入边一直往前走，不会重复，必然停在入度为 `0` 的点）。所以只要还有剩余，就能继续取，直到取完。

**有环 ⇒ 取不完。** 环上的每个点都依赖环上的另一个点，环上第一个被取走的点必须要求它的前置依赖（环上前一个点）已被取走，矛盾，所以环上的点一个也取不走，`done < n`。

**反例：并查集（无向）。** 并查集只能判断“两点是否已连通”，不记方向。`n = 3`，`deps = [[0,1],[0,2],[1,2]]`：
- 模块 `0` 依赖 `1` 和 `2`，`1` 依赖 `2`，没有环，可以按 `2, 1, 0` 构建，正确答案 `False`。
- 并查集依次合并 `(0,1)`、`(0,2)`，处理 `(1,2)` 时发现 `1`、`2` 已在同一集合，报告有环，结果 `True`，错了。

**另一个反例：只从 `0` 出发。** `n = 4`，`deps = [[2,3],[3,2]]`：模块 `2` 与 `3` 互相依赖，但从 `0` 出发的 DFS 只能访问到 `0`，返回 `False`，正确是 `True`。判环必须覆盖所有模块，Kahn 算法一开始就把所有入度为 `0` 的点入队，天然不依赖起点。
