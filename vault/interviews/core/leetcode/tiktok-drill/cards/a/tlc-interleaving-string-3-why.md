## Q
**LC 97 交错字符串**｜正确性

为什么状态只需要 `(i, j)` 两维，不用记录 `s3` 的位置？为什么不能用「能从 `s1` 取就从 `s1` 取」的贪心？给出反例。

## A
**不变量。** `dp[i][j]` 为真，当且仅当 `s1[:i]` 与 `s2[:j]` 能保序交错成 `s3[:i + j]`。`s3` 的前缀长度必然等于已用字符总数，所以 `s3` 的位置由 `(i, j)` 唯一确定，不是独立的状态。

**转移的两个来源。** `s3[i + j - 1]` 是交错结果的最后一个字符，只可能来自 `s1[i - 1]` 或 `s2[j - 1]`：
- 来自 `s1`：需要 `dp[i - 1][j]` 为真，且 `s1[i - 1] == s3[i + j - 1]`；
- 来自 `s2`：需要 `dp[i][j - 1]` 为真，且 `s2[j - 1] == s3[i + j - 1]`。
两种情况互斥又完备，所以取或。

**反例：贪心。** `s1 = "aa"`，`s2 = "ab"`，`s3 = "aaba"`。
- 贪心：`s3[0] = a` 取 `s1[0]`；`s3[1] = a` 取 `s1[1]`；`s3[2] = b`：`s1` 已用完，`s2[0] = a` 不是 `b`，失败，输出 `False`。
- 正确：`s3[0]` 取 `s1[0]`，`s3[1]` 取 `s2[0]`，`s3[2] = b` 取 `s2[1]`，`s3[3] = a` 取 `s1[1]`，输出 `True`。
两个字符串在同一位置上都可能匹配时，选哪个会影响后面，必须两条路都保留，这正是 DP 同时记录所有 `(i, j)` 的原因。

**长度检查的作用。** 它是 DP 的前提：转移公式默认 `i + j - 1 < len(s3)`。`("a", "b", "abc")` 不检查长度会被判成 `True`。

**边界。** `dp[0][0] = True`：都不取，交错出空串，所有格子都从它推出来；忘了它，`("a", "", "a")` 得到 `False`，正确是 `True`。
