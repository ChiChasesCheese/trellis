## Q
**连续内存分配器**｜正确性

空闲块列表按起始地址排序，释放时与左右邻居合并，分配时按对齐切分。为什么这能保证“空闲块互不相邻、互不重叠，空闲加已分配恰好是整个容量”？释放时漏合并左邻居、不检测 double free、对齐向下取整，各会错成什么样？

## A
**不变量。** 任意时刻：（1）`free_list` 按起始地址严格递增，且相邻两块之间至少隔着一个已分配单元（互不相邻）；（2）空闲块与已分配块互不重叠，总大小恰好等于 `capacity`。`alloc` 把一个空闲块拆成「对齐空隙、已分配、剩余」，三部分首尾相接，总和不变，空隙与剩余各自不与别的空闲块相邻（它们的另一侧是已分配块或原块边界）。`free` 插入一个新块，只可能与紧挨的左右邻居相邻，合并这两个就恢复（1）。

**反例一：漏掉左邻居的合并。** `capacity = 10`，`alloc(3)`、`alloc(4)`、`alloc(2)` 得到 `0, 3, 7`，依次 `free(0)`、`free(3)`。正确的空闲块是 `[(0, 7), (9, 1)]`，`alloc(7)` 返回 `0`；漏合并左邻居得到 `[(0, 3), (3, 4), (9, 1)]`，`alloc(7)` 返回 `-1`，碎片永远合不起来。

**反例二：不检测 double free。** 同一个地址释放两次，第二次往空闲列表里插入一个与已有空闲块重叠的区间，总空闲大小超过容量，之后同一段内存被分配给两个调用方。用 `used` 字典登记，第二次 `free` 时地址已不在其中，抛 `ValueError`。

**反例三：对齐向下取整。** `Allocator(32, 8)`：`alloc(3)` 得到 `0`，空闲块变成 `(3, 29)`；`alloc(1)` 若用 `start // align * align` 得到 `0`，与第一块重叠；向上取整得到 `8`，`(3, 5)` 这段空隙继续留作空闲块。

**反例四：丢掉对齐空隙。** 分配后只保存右边剩余，不保存 `pad` 部分：`Allocator(32, 8)` 里 `(3, 5)` 这 `5` 个单元永久丢失，空闲总量小于真实值。
