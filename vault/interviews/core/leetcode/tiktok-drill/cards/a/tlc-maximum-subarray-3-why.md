## Q
**LC 53 最大子数组和**｜正确性

Kadane 算法里，`cur = max(x, cur + x)` 保持什么不变量？为什么最大子数组一定在某个「以 `i` 结尾的最优子数组」里？如果把 `best` 和 `cur` 初始化为 `0`，会在什么输入上出错？

## A
**不变量。** 处理完下标 `i` 之后，`cur` 等于「所有以 `i` 结尾的非空子数组里的最大和」，`best` 等于「`0..i` 内所有子数组的最大和」。

**为什么 `max(x, cur + x)` 对。** 以 `i` 结尾的子数组只有两类：只含 `x` 自己，或者在以 `i - 1` 结尾的某个子数组后面接上 `x`。第二类里要让和最大，就该接上以 `i - 1` 结尾的**最大**的那个，即 `cur + x`。两类取较大者，就是新的 `cur`。全局最大子数组一定以某个下标结尾，所以 `best` 取所有 `cur` 的最大值就够了。

**反例：初始化为 `0`。**
- 输入 `[-3, -1, -2]`，每个元素都是负数，最大子数组是 `[-1]`，答案 `-1`。
- 若 `best = cur = 0` 起步，`best` 一开始就比任何非空子数组的和都大，之后每个 `cur` 都是负数，永远刷新不了 `best`，返回 `0`。这相当于选了一个空子数组，而题目要求至少含一个元素。
- 用 `nums[0]` 起步：`best = cur = -3`，读到 `-1`：`cur = max(-1, -4) = -1`，`best = -1`；读到 `-2`：`cur = max(-2, -3) = -2`，`best` 仍是 `-1`，正确。

**同一道理的前缀和写法**：`best = max(best, P[j] - min(P[0..j-1]))` 里，「最小前缀和」要从 `P[0] = 0` 起算，并且在更新 `best` **之后**再更新最小前缀和，否则会出现长度为零的子数组。
