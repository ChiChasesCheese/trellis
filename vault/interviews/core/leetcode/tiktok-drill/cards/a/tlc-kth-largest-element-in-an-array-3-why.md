## Q
**LC 215 数组中的第 K 个最大元素**｜正确性

快速选择里，为什么要把「等于 pivot」的元素单独分成一段？以及进入「小于」那一堆时，`k` 为什么要减去 `len(bigger) + equal`？各给一个具体输入。

## A
**不变量。** 每一轮开始时，当前列表 `nums` 的第 `k` 大元素，就是原数组的第 `k` 大元素。三段把列表按大小顺序切成「大于 / 等于 / 小于」，排名 `1..len(bigger)` 属于第一段，接着的 `equal` 个排名属于第二段，其余属于第三段；丢掉的段不含答案，并且丢掉前面各段后要把排名相应前移。

**不分出「等于」段会怎样。** 若只分 `>` 和 `<=` 两堆，所有元素相同的数组每轮只能排除 pivot 自己一个。
- 反例：`nums = [2] * 100000`，`k = 50000`。两路划分每轮只排除 pivot 自己一个，要做约 5×10^4 轮，每轮扫至少 5×10^4 个元素，总计达到 10^9 数量级，超时。
- 三路划分：第一轮 `bigger = []`，`equal = 100000`，`k <= 0 + 100000`，立即返回 `2`。

**不减去前两段会怎样。** 进入「小于」堆后排名是相对于新列表的。
- 反例：`nums = [3,2,1]`，`k = 3`（要最小的）。pivot 取 `2` 时，`bigger = [3]`，`equal = 1`，`k = 3 > 2`，进入 `[1]`。
- 新列表只有一个元素，正确的 `k` 是 `3 - 2 = 1`，返回 `1`。
- 若不减，`k` 仍是 `3`：在 `[1]` 上 `k <= 0` 与 `k <= 1` 都不成立，又掉进「小于」分支，列表变空，下一轮 `random.choice([])` 抛出 `IndexError`。
- 正确答案是 `1`。
