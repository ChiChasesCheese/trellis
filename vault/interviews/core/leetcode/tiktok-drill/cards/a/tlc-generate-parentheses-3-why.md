## Q
**LC 22 括号生成**｜正确性

为什么放右括号的条件是 `closed < opened`，而不是 `closed < n`？这两条放置规则为什么保证每个叶子都是有效括号、而且不遗漏任何一个有效串？

## A
**不变量。** 递归的任意时刻，`path` 都是某个有效括号串的前缀：满足 `closed <= opened <= n`。

**为什么有效。** 一个括号串有效，当且仅当任意前缀中右括号数不超过左括号数，并且总的左右括号数相等。规则 `closed < opened` 保证放入右括号后仍然 `closed <= opened`，规则 `opened < n` 保证左括号不超过 `n`。走到长度 `2n` 时，`opened + closed = 2n`，而 `opened <= n`、`closed <= opened`，所以 `opened = closed = n`，总数相等。

**为什么不遗漏。** 任何有效串都满足：它的每个前缀都满足 `closed <= opened <= n`。在搜索树里，沿着这个串的字符一步步走，每一步放置都是规则允许的，所以它一定会被生成，并且只有一条路径，不会重复。

**反例：用 `closed < n` 代替。** 这条规则只限制了右括号的总数，没有要求「先有左括号」。`n = 2` 时：
- 第一位可以放 `")"`（`closed = 0 < 2`），路径 `")(()"`、`"())("` 等都会被生成。
- 最终得到 `6` 个串：`["(())", "()()", "())(", ")(()", ")()(", "))(("]`，其中后四个无效。
- 正确的 `closed < opened` 规则只产生 `["(())", "()()"]`。

数量也能验证：`n = 1..8` 的结果个数是卡特兰数 `1, 2, 5, 14, 42, 132, 429, 1430`，而 `2^(2n)` 的无约束枚举是 `4, 16, 64, …`。
