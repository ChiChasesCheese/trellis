## Q
**LC 69 x 的平方根**｜正确性

二分找"最大的可行值"时，为什么 `mid` 要向上取整？可行条件为什么是 `mid * mid <= x` 而不是 `<`？各给一个错误写法的具体输入和输出。

## A
**不变量。** 答案 `m*`（最大的满足 `m * m <= x` 的整数）始终在 `[lo, hi]` 内。`mid * mid <= x` 时 `m* >= mid`，所以 `lo = mid` 保持不变量；否则 `m* < mid`，所以 `hi = mid - 1`。

**为什么向上取整。** 可行分支是 `lo = mid`，区间只有两个数时（`hi = lo + 1`），向下取整得到 `mid = lo`，`lo = mid` 没有改变任何东西，循环永远不会结束。向上取整让 `mid = hi`，可行则 `lo = hi`，不可行则 `hi = lo`，区间都会缩小。

**反例一：向下取整。** 输入 `x = 1`：`lo = 0`，`hi = 1`，`mid = 0`；`0 * 0 <= 1` 为真，`lo = mid = 0`，状态不变，永远循环，程序卡住。正确答案 `1`。

**反例二：可行条件用严格小于。** 把条件写成 `mid * mid < x`，等号取不到，平方数会被少算一位：`x = 4` 时 `lo = 0, hi = 4`，`mid = 2`，`4 < 4` 为假，`hi = 1`，之后收敛到 `1`，输出 `1`，正确答案 `2`；非平方数不受影响（`x = 8` 仍得 `2`），所以只用 `8` 测试发现不了。

**浮点开方的陷阱。** 如果绕过限制用 `int(math.sqrt(x))`，在 `x` 很大时会出错：`int(math.sqrt(2**60 - 1))` 得到 `1073741824`，正确的整数平方根是 `1073741823`（`math.isqrt` 给出的值）。`x < 2^31` 时浮点没有问题，但这是为什么大整数场景要用 `math.isqrt` 的原因。
