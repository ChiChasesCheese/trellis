## Q
**N 叉树路径和（前缀和加哈希）**｜正确性

在树上用「根到当前节点的前缀和」加哈希统计和为 `target` 的向下路径，为什么 `seen[cur - target]` 恰好是以当前节点结尾的合法路径数？哈希表为什么必须回溯？初值 `seen[0] = 1`、先查询后登记，各防什么错？

## A
**不变量。** 处理节点 `v` 时，`seen` 里恰好记录了「根到 `v` 的父亲」这条链上每个节点的前缀和（加上空前缀 `0`）的出现次数。以 `v` 结尾的向下路径，起点是链上某个祖先 `a`（或 `v` 自己），路径和 `= prefix[v] - prefix[parent(a)]`，等于 `target` 当且仅当 `prefix[parent(a)] = prefix[v] - target`；`parent(a)` 取遍链上的节点和空前缀，所以个数就是 `seen[cur - target]`。

**反例一：不回溯。** 树 `Node(3, [Node(-4, [Node(-1, [Node(4)]), Node(0)])])`，`target = 3`。正确答案是 `2`（节点 `3` 单独一条，`-1 -> 4` 一条）。不撤销时，先处理的兄弟分支 `0`（前缀和 `-1`）留在哈希表里，之后 `-1 -> 4` 这支查询前缀和 `-1` 时多匹配了一次，答案变成 `3`。

**反例二：缺少初值 `seen[0] = 1`。** 从根开始的路径需要用“空前缀”配对。`Node(5)`、`target = 5`：路径 `[5]` 的前缀和 `5`，`5 - 5 = 0`，哈希表里没有 `0`，答案是 `0`，正确是 `1`。

**反例三：先登记再查询。** 当前节点的前缀和先进了哈希表，查询时就会匹配到自己：`target = 0` 时 `cur - target = cur`，把一条长度为 `0` 的「空路径」数进去。`Node(5)`、`target = 0` 得到 `1`，正确是 `0`。

**反例四：用递归。** 退化成 `10^5` 层的链时，递归 DFS 在约 `1000` 层抛 `RecursionError`；显式栈加退出标记没有这个限制。
