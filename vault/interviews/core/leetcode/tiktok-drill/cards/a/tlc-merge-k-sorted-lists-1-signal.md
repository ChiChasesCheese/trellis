## Q
**LC 23 合并 K 个升序链表**｜Hard · LC TikTok 热度 63/100 · 近一年被问：美国 3 次、国内 2 次 · CodeTop 国内累计 114 次 · 最近 2026-10-19（CodeTop）

给一个链表数组 `lists`，每个链表都已按升序排列。把所有链表合并成一个升序链表，返回合并后的链表。`k == lists.length`，`0 <= k <= 10^4`，`0 <= lists[i].length <= 500`，`-10^4 <= lists[i][j] <= 10^4`，所有链表长度之和不超过 `10^4`。例：`lists = [[1,4,5],[1,3,4],[2,6]]` → `[1,1,2,3,4,4,5,6]`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「`k` 个**已升序**的序列合并成一个」→ **k 路归并**：每一步从 `k` 个队头里取最小的 → **最小堆**（priority queue）。
- 「链表」→ 不能随机访问，也不能就地排序数组；合并时拼接指针，节点可以原地复用，空间只需堆的 `O(k)`。
- 总长度 `N <= 10^4`，`k <= 10^4`：`O(N · k)` 约 `10^8`，太慢；`O(N log k)` 约 `1.4 × 10^5`，轻松。

**推导链。**
1. 暴力一：每次扫描 `k` 个队头找最小，`O(N · k)`。
2. 暴力二：收集所有值整体排序，`O(N log N)`，多花 `O(N)` 空间，并且浪费了「每条链表已有序」这个条件。
3. 洞察：全局最小一定在某条链表的队头，所以每步只需要在 `k` 个队头里选最小。用堆维护这 `k` 个队头，选最小 `O(log k)`。
4. 最优：弹出最小的接到结果后面，把它的后继换进堆（`heapreplace`）；`N` 次操作，`O(N log k)` 时间，`O(k)` 空间。堆元素带上唯一编号，避免值相同时去比较 `ListNode`。
