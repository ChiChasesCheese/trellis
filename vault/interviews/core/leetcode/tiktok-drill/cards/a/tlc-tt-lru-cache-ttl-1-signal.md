## Q
**带 TTL 的 LRU 缓存**｜Hard · 近一年被问：美国 14 次、国内 27 次 · 最近 2026-10（面试记录）

设计固定容量 `capacity` 的 LRU 缓存：`get(key)` 返回值或 `-1`，`put(key, value, ttl)` 写入并给这一条设存活时间 `ttl` 秒（不同条目可不同）。写入后过了 `ttl` 即过期，读到过期条目当作不存在并删除（懒删除）；`put` 已有 key 时覆盖值、重置 `ttl`、变成最近使用；容量已满要插入新 key 时，先清掉已过期的条目，仍满再淘汰最久未使用的。要求 `get`、`put` 均摊 `O(1)`，`1 <= capacity <= 10^5`，`ttl > 0`。例：容量 `2`，`put(1, 1, 5)`，`put(2, 2, 10)`，`get(1)` → `1`，`put(3, 3, 10)` 淘汰 key 2。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「固定容量 + 淘汰最久未使用 + `O(1)`」→ LRU：哈希表（查找）加双向链表（调序、淘汰）；Python 里 `OrderedDict` 就是这个组合。
- 「读到过期当作不存在、不要后台线程」→ 懒删除（lazy deletion）：读路径上只检查被碰到的那一个 key。
- 「满了先清过期」→ 需要一次找出**所有**过期条目；链表按使用顺序排，帮不上忙 → 要一个按到期时刻排序的结构，最小堆。
- 「覆盖写重置 `ttl`」→ 堆里会留下旧项，不能原地删除 → 版本号加懒丢弃。

**推导链。**
1. 暴力：满时遍历全部条目找过期的，每次 `put` 都 `O(n)`。
2. 浪费：过期的只会是到期时刻最小的那些，却整表扫描。
3. 洞察：按到期时刻建最小堆，只看堆顶，`<= now` 就弹出；每条数据至多进出堆各一次，均摊 `O(log n)`。覆盖写留下的旧堆项用写入版本号识别并丢弃。
4. 最优：`OrderedDict` 管使用顺序（`move_to_end`、`popitem` 的 `O(1)`），堆加版本号管到期；`get` 为 `O(1)`，`put` 均摊 `O(log n)`。

**同模式的题**：LC 146 LRU 缓存、LC 460 LFU 缓存、LC 432 全 `O(1)` 的数据结构、LC 981 基于时间的键值存储。
