## Q
**LC 721 账户合并**｜Medium · LC TikTok 热度 38/100 · 近一年被问：美国 2 次、国内 0 次 · CodeTop 国内累计 2 次 · 最近 2026-07-25（面试记录）

`accounts[i]` 的第一个元素是名称，其余是邮箱。两个账户只要有一个共同邮箱就属于同一个人（同名不一定是同一个人）。合并后每个账户是「名称 + 按 ASCII 排序的邮箱」，账户顺序任意。`1 <= accounts.length <= 1000`，`2 <= accounts[i].length <= 10`，`1 <= accounts[i][j].length <= 30`。例：两个 `John` 共享 `johnsmith@mail.com`，合并成一个；第三个 `John` 与他们无关，保持独立。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「共享某个元素就是同一组」，且关系**可传递**（A-B 共享、B-C 共享 ⇒ A、B、C 同组）→ **连通分量**：**并查集**（union-find）或图的 DFS / BFS。
- 「同名不一定同一人」→ 名字**不参与**合并判断，只有邮箱说了算；名字只在输出时取用。
- 「邮箱 → 属于谁」是一对一的身份信息 → 用字典记录邮箱的第一个拥有者，后来者与之合并。
- 规模小（`<= 1000` 个账户，约 `9000` 个邮箱）→ 不需要更复杂的结构；输出要求邮箱排序，排序代价 `O(E log E)`。

**推导链。**
1. 暴力：两两比较账户的邮箱交集，有交集就合并，合并后重新比较，直到不再变化，`O(N^2 · k)`。
2. 浪费：每轮都重新扫邮箱；传递性要靠多轮迭代。
3. 洞察：给每个邮箱记录它的第一个拥有者；任何账户遇到这个邮箱，就和拥有者所在的集合合并，传递性由并查集保证。
4. 最优：一遍扫描完成合并，再按根分组、排序输出。
