## Q
**LC 1099 小于 K 的两数之和**｜正确性

为什么和 `< k` 时可以排除 `lo`，和 `>= k` 时可以排除 `hi`？`best` 的初值和比较符号写错会错成什么样？

## A
**不变量。** 双指针每一步维护：最优数对（如果存在）的两个下标都在 `[lo, hi]` 内。若 `s = nums[lo] + nums[hi] < k`，对任何 `j' <= hi`（`j' > lo`），`nums[lo] + nums[j'] <= s`，所以 `lo` 能得到的最好成绩就是 `s`，已经记录，`lo` 可排除。若 `s >= k`，对任何 `i' >= lo`，`nums[i'] + nums[hi] >= s >= k`，`hi` 与它们都不合法，`hi` 可排除。每步排除一个端点而不丢掉最优解，直到指针相遇。

**反例（错误写法一）：用 `<=`。** `[10,20,30]`、`k = 30`：`10 + 20 = 30` 不满足严格小于，正确是 `-1`；写成 `s <= k` 会返回 `30`。

**反例（错误写法二）：`best` 初值为 `0`。** `[10,20,30]`、`k = 15`：没有合法数对，应返回 `-1`，初值 `0` 会原样返回 `0`。

**反例（错误写法三）：合法后两个指针同时移动。** `[1,2,3]`、`k = 11`：`1 + 3 = 4` 合法，若 `lo += 1; hi -= 1` 之后指针重合退出，返回 `4`；漏掉了 `2 + 3 = 5`，正确是 `5`。
