## Q
**剑指 Offer 51 数组中的逆序对**｜追问

面试官接着问：（1）要输出每个元素右侧有多少个比它小的数（LC 315）？（2）翻转对（LC 493，`nums[i] > 2 * nums[j]`）怎么改？（3）答案会不会溢出，`n` 增大到 `10^5` 呢？

## A
1. **逐元素计数（LC 315）**：归并时不只传值，还传原始下标；每次从左半取出一个元素，就给它的答案加上当前的 `j`。结果数组按原始下标存放，最后返回。思路与卡片相同，只是把"总数"拆成"每个元素的数"。
2. **翻转对**：条件变成 `a[i] > 2 * a[j]`，它不再与合并的比较一致，所以**合并之前**单独用双指针数一遍：左右两半各自有序，对每个左元素 `x`，移动右指针直到 `right[j] * 2 >= x`，已越过的右元素个数就是它的贡献；数完再按普通方式合并排序。
3. **数值范围**：最多的逆序对是严格降序数组，`n(n-1)/2`；`n = 50000` 时是 `1249975000`，仍在 32 位有符号整数内（`< 2147483647`）。`n = 10^5` 时约 `5 * 10^9`，超出，需要 64 位整数；Python 的整数没有这个问题，用 C++ / Java 要换成 `long`。
4. **工程上的小优化**：用一个全局辅助数组 + 下标区间做原地归并，避免每层 `a[:mid]` 的切片复制，时间不变，常数更小。

**Python 提醒**：`bisect.insort` 配合 `k - bisect_right(sorted_prefix, v)` 也能数逆序对，代码只有几行（`n = 50000` 约 `0.1` 秒），但最坏是 `O(n^2)`（列表插入要移动元素），面试里先写归并，说明这个写法的上限。
