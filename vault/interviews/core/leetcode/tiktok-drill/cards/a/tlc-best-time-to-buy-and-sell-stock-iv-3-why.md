## Q
**LC 188 买卖股票的最佳时机 IV**｜正确性

最多 `k` 笔交易的股票问题，用 `buy[j]`、`sell[j]` 两个数组滚动更新，`buy[j]` 由 `sell[j-1]` 转移。为什么这两个状态足够，为什么 `k >= n // 2` 可以直接累加价差？`buy` 初值写 `0`、`buy[j]` 由 `sell[j]` 转移，各会错成什么样？

## A
**不变量。** 处理完第 `i` 天后：`sell[j]` 是前 `i` 天内最多完成 `j` 笔交易、手上没货的最大收益；`buy[j]` 是前 `i` 天内恰好已完成 `j - 1` 笔、并持有第 `j` 笔买入的股票时的最大收益。第 `i` 天的价格 `p` 只能：保持不动，或者在持有时卖出（`sell[j] = buy[j] + p`），或者在没货时买入（`buy[j] = sell[j-1] - p`，上一笔已完成才能开始第 `j` 笔）。所以两个数组的更新完整覆盖了所有选择。

**为什么 `k >= n // 2` 可以直接累加。** 一笔交易至少占用两天，`n` 天最多完成 `n // 2` 笔；`k` 不小于它时限制不起作用。不限次数时最优策略是抓住每一段上涨，等价于累加所有正的相邻价差。

**反例一：`buy` 初值是 `0`。** 相当于第一笔交易免费拿到一只股票，`k = 2`、`prices = [3,2,6,5,0,3]` 得到 `9`，真实最大利润是 `7`（两笔：`2 → 6` 赚 `4`，`0 → 3` 赚 `3`）。

**反例二：`buy[j]` 由 `sell[j]` 转移。** `sell[j]` 已经包含了第 `j` 笔，再从它出发买入，不增加笔数，次数限制失效，等价于不限次数：`k = 1`、`prices = [3,2,6,5,0,3]` 得到 `7`，正确是 `4`。

**反例三：答案取 `buy[k]`。** `buy` 是持有股票的状态，还没有卖出，不算已实现的利润，并且值可能是负数；答案必须取 `sell[k]`。

**反例四：`k` 很大时仍分配 `k + 1` 个状态。** 若输入的 `k` 是 `10^9`，`[-inf] * (k + 1)` 直接耗尽内存；`k >= n // 2` 时必须走累加的快捷分支。
