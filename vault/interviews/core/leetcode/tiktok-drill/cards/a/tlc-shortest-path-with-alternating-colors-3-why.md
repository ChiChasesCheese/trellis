## Q
**LC 1129 颜色交替的最短路径**｜正确性

为什么状态必须是 `(结点, 颜色)`，只按结点标记访问为什么会错？起点为什么要把两种颜色都放进队列？给出各自的反例。

## A
**不变量。** BFS 队列里状态的步数单调不降，且每个状态 `(u, c)` 第一次入队时的步数，就是「到达 `u` 且下一条边必须是颜色 `c`」的最短交替路径长度。结点 `u` 的答案是它的两个状态中先出队的那个步数。

**为什么状态要带颜色。** 到达 `u` 的方式（红边或蓝边）决定了从 `u` 出去能走哪种颜色。两种到达方式的后续可达集合不同，不能合并成一个「已访问」。

**反例 1：只按结点标记。** `n = 3`，`red_edges = [[0,1],[1,2]]`，`blue_edges = [[0,1]]`。
- 先处理红边：`0 →(红) 1`，把结点 `1` 标记为已访问；之后蓝边 `0 →(蓝) 1` 被当作重复丢弃；
- 从 `1` 出发只有红边 `1→2`，要求上一条边是蓝色，但记录的到达方式是红边，无法继续，结点 `2` 得到 `-1`，输出 `[0, 1, -1]`；
- 正确：`0 →(蓝) 1 →(红) 2`，输出 `[0, 1, 2]`。

**反例 2：起点只放红色状态。** `n = 3`，`red_edges = []`，`blue_edges = [[0,1],[1,2]]`。第一条边可以任选颜色，路径 `0 →(蓝) 1` 合法。只放红色起点，永远走不出结点 `0`，输出 `[0, -1, -1]`；正确是 `[0, 1, -1]`（`1→2` 也是蓝边，紧接着不能再走蓝边，所以 `2` 不可达）。

**自环和平行边为什么不会死循环。** 状态去重保证每个 `(u, c)` 最多入队一次，状态总数 `2n` 有限，BFS 必然终止；自环 `(u, c) → (u, 1 - c)` 只是换一个状态。
