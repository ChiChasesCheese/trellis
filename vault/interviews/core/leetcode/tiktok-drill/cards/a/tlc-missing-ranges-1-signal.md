## Q
**LC 163 缺失的区间**｜Easy · TikTok 高频

给闭区间 `[lower, upper]` 和一个**升序**整数数组 `nums`（元素互不相同，都落在 `[lower, upper]` 内）。区间内不在 `nums` 里的整数叫「缺失数」，返回**恰好覆盖所有缺失数**的最小有序区间列表。`-10^9 <= lower <= upper <= 10^9`，`0 <= nums.length <= 100`。例：`nums = [0,1,3,50,75]`，`lower = 0`，`upper = 99` → `[[2,2],[4,49],[51,74],[76,99]]`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「**有序**数组」+「找缺口」→ 缺失数只会出现在**相邻两个已知数之间**，用相邻差值直接算出缺口，一趟扫描。
- `lower`、`upper` 高达 `10^9` 而 `n <= 100` → 复杂度只能跟 `n` 有关，不能遍历值域。
- 头、尾、空数组三种边界 → 用**哨兵**（sentinel）把边界并进同一条规则。

**推导链。**
1. 暴力：把 `nums` 放进集合，从 `lower` 扫到 `upper`，把连续的未命中数合成段 → `O(upper - lower)`，最坏 `2 * 10^9`，不可行。
2. 浪费：值域里绝大多数数字的状态由「两侧的已知数」决定，根本不用逐个看。
3. 关键：相邻已知数 `prev`、`x` 满足 `x - prev >= 2` 时，`[prev + 1, x - 1]` 恰好是一段缺失区间。
4. 头尾：在 `nums` 前补 `lower - 1`、后补 `upper + 1`，第一个和最后一个缺口也成了「两个已知数之间」→ 一趟 `O(n)`。

**同模式的题**：LC 228 汇总区间、LC 56 合并区间、LC 57 插入区间、LC 352 将数据流变为不相交区间。
