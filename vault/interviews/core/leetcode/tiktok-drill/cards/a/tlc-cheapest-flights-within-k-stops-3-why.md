## Q
**LC 787 K 站中转内最便宜的航班**｜正确性

为什么松弛 `k + 1` 轮就能得到「最多 `k` 站中转」的最小价格？为什么每轮要复制一份数组、读旧写新？普通 Dijkstra 为什么会给出错误答案？

## A
**不变量。** 第 `t` 轮结束后，`dist[v]` 等于从 `src` 出发，使用**至多 `t` 条边**到达 `v` 的最小价格。

**归纳。** `t = 0`：只有 `src` 为 `0`，其余无穷，成立。第 `t` 轮：至多 `t` 条边的最优路线，要么不用第 `t` 条边（保持 `dist[v]` 不变，因为 `nxt` 从 `dist` 复制而来），要么最后一条是 `u → v`，前面是至多 `t - 1` 条边到 `u` 的最优，也就是 `dist[u] + w`。两种情况取小，正是松弛的结果。`k` 站中转就是至多 `k + 1` 条边，所以 `k + 1` 轮后读答案。

**为什么读旧写新。** 若不复制、直接在 `dist` 上就地松弛，一轮里刚更新的值又会被后面的航班读到，一轮就可以连走多条边，第 `t` 轮的含义变成“至少 `t` 条边也可能”，限制被突破。
- `n = 3`，`flights = [[0,1,100],[1,2,100],[0,2,500]]`，`src = 0`，`dst = 2`，`k = 0`（只允许 1 条边）：航班按这个顺序处理，就地松弛先得 `dist[1] = 100`，再用它得到 `dist[2] = 200`，返回 `200`。
- 正确的答案是 `500`（只能直达）。

**为什么不能用普通 Dijkstra。** Dijkstra 的贪心是“弹出的第一个到达 `v` 的就是价格最小的”，没有记录边数。示例 1 中不限站数的最短路是 `0 → 1 → 2 → 3`，价格 `400`，但它中转了 `2` 站，超过 `k = 1`；而价格更高的 `0 → 1 → 3`（`700`）才合法。要用 Dijkstra，状态必须是 `(城市, 已用边数)`，不能只看城市。
