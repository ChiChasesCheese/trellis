## Q
**LC 95 不同的二叉搜索树 II**｜追问

面试官接着问：（1）只要求 BST 的**数量**，`n` 到 19（LC 96）？（2）你的结果里多棵树共享子树节点，调用方要修改其中一棵，怎么办，代价是多少？（3）`n` 再大一点（比如 15），还能全部生成吗？

## A
1. **只计数**：同一个分解给出卡特兰数递推，`g[0] = 1`，`g[i] = Σ_{j=1..i} g[j-1] · g[i-j]`，`O(n^2)`；或闭式 `math.comb(2 * n, n) // (n + 1)`。

```python
def num_trees(n: int) -> int:
    g = [1] + [0] * n                             # g[k]：k 个值能组成的 BST 数
    for i in range(1, n + 1):
        g[i] = sum(g[j - 1] * g[i - j] for j in range(1, i + 1))   # j 为根
    return g[n]
```

运行：`n = 3` → `5`，`n = 8` → `1430`，`n = 19` → `1767263190`。
2. **独立副本**：共享来自直接复用子树对象，`@cache` 让同一区间的子树在所有树之间复用。要独立，在组合时对两边各做 `copy.deepcopy(left)`、`copy.deepcopy(right)`。只去掉缓存不够：列表推导里同一个 `left` 对象仍会和多个 `right` 组合，照样共享。每棵树 `n` 个节点，总代价 `O(n · C_n)`，`n = 8` 时 `1430 × 8 = 11440` 个节点；共享版只新建 `2974` 个。
3. **规模**：输出就是 `C_n` 棵树，`C_15 = 9694845`，每棵 15 个节点，内存以 GB 计；生成全部不现实。应改为**惰性生成**（`yield` 一棵处理一棵），或只要计数、按序号取第 `k` 棵（用卡特兰数做「按根分组」的跳跃）。

**Python 提醒**：`@cache` 的返回值是同一个列表对象，调用方若对返回的列表做 `append` / `sort`，会污染缓存，同一次生成里后续的递归调用拿到被改过的结果。
