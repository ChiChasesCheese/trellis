## Q
**LC 75 颜色分类**｜正确性

为什么遇到 `0` 时 `i` 可以前进，遇到 `2` 时 `i` 却不能前进？给出遇到 `2` 也前进会答错的输入。

## A
**不变量。** 每次循环开始时：`nums[:lo]` 全是 `0`，`nums[lo:i]` 全是 `1`，`nums[hi+1:]` 全是 `2`，`nums[i:hi+1]` 是还没检查的部分。循环结束（`i > hi`）时未检查区为空，数组被分成三段，已经有序。

**遇到 `0`。** 和 `nums[lo]` 交换。如果 `lo < i`，`nums[lo]` 属于 `1` 区，被换到位置 `i` 的是一个确认的 `1`，放在 `[lo+1, i+1)` 这一段刚好符合不变量；如果 `lo == i`，换的是自己。两种情况换来的都是已检查过的值，所以 `lo`、`i` 一起前进是安全的。

**遇到 `2`。** 和 `nums[hi]` 交换。`nums[hi]` 来自**未检查区**，可能是 `0`、`1` 或 `2`，我们完全不知道它是什么。如果这时 `i` 前进，这个换来的数就从未被检查，会留在错误的区域里。所以只让 `hi` 收缩，下一轮继续处理位置 `i`。

**反例 `[1,2,0]`。** 正确结果 `[0, 1, 2]`。遇到 `2` 也让 `i += 1` 的错误写法：
- `i = 0`：值 `1`，`i = 1`。
- `i = 1`：值 `2`，与 `hi = 2` 交换，数组变成 `[1, 0, 2]`，`hi = 1`；错误写法此时 `i = 2`。
- `i = 2 > hi = 1`，循环结束，返回 `[1, 0, 2]`，错；换来的 `0` 没被检查。
正确写法让 `i` 停在 `1`，下一轮看到 `0`，与 `lo = 0` 交换，得到 `[0, 1, 2]`。
