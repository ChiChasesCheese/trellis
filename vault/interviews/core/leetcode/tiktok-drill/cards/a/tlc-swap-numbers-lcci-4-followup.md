## Q
**面试题 16.01 交换数字**｜追问

面试官接着问：（1）用加减法交换，在 Java 的 `int` 上会不会因为溢出出错？（2）实际工程里为什么几乎不用异或交换？（3）Python 的 `a, b = b, a` 是怎么执行的，有什么坑？

## A
1. **加减法与溢出**：`a = a + b` 可能溢出，但 Java 的 `int` 按 `2^32` 取模回绕，后面两次减法也回绕，模运算下等式成立，结果仍正确。`[2147483647, 1]`：`a = -2147483648`（回绕），`b = a - b = 2147483647`，`a = a - b = 1`，得到 `[1, 2147483647]`。C/C++ 的有符号溢出是未定义行为，编译器可能做出意外优化，要用无符号类型或直接用异或。
2. **工程里不用**：临时变量通常放在寄存器里，`mov` 比三次异或更快；三次异或前后依赖，CPU 不能并行执行；同一位置会清零；可读性差。编译器看到临时变量交换也能优化成寄存器重命名。
3. **Python 元组交换**：先把右边求值成一个元组，再**从左到右**依次赋给左边的目标。目标里的下标表达式在赋值时才求值，所以前一个赋值会影响后一个目标的位置。

**Python 提醒**：`nums[i], nums[nums[i] - 1] = nums[nums[i] - 1], nums[i]` 对 `nums = [3,1,2], i = 0` 得到 `[2,3,2]`（正确 `[2,1,3]`）：右边是 `(2, 3)`，先赋 `nums[0] = 2`，第二个目标变成 `nums[2 - 1] = nums[1]`，写错了位置。先存 `j = nums[i] - 1`，再写 `nums[i], nums[j] = nums[j], nums[i]`（LC 41 缺失的第一个正数常踩这个坑）。
