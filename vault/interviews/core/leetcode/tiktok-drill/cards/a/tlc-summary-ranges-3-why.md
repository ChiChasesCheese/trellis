## Q
**LC 228 汇总区间**｜正确性

双指针解法里，内层循环为什么必须拿 `nums[j + 1]` 和**前一个元素** `nums[j]` 比较，而且处理完一段后为什么要令 `i = j + 1`？给出写成 `i += 1` 或「拿段首比较」时的错误输出。

## A
**不变量。** 外层每轮开始时，`nums[:i]` 已经被若干极长段完整覆盖且没有重复输出；内层结束时，`[i, j]` 是以 `i` 开头的**极长**连续段（`j` 是最后一个满足条件的位置）。

**为什么跳到 `j + 1`。** `[i, j]` 已经输出，`i + 1 .. j` 作为段首只会得到它的子段，输出重复且不再是极长。直接跳到 `j + 1`，每个元素只属于一个段。

**反例一：`i += 1`。** `nums = [0,1,2,4,5,7]`：
- 输出 `['0->2', '1->2', '2', '4->5', '5', '7']`，每个元素都当了一次段首。
- 正确输出 `['0->2', '4->5', '7']`。

**反例二：内层拿段首比较**（`nums[j + 1] == nums[i] + 1`）。只能延伸一格，`[0,1,2,4,5,7]` 输出 `['0->1', '2', '4->5', '7']`，把 `0->2` 拆成了两段，违反「最小」。
