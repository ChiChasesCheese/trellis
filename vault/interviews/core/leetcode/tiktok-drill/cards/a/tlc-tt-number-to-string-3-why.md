## Q
**手写数字转字符串**｜正确性

`int_to_str` 为什么必须先取绝对值再 `divmod`？`decimal_to_str` 里“小数前导 `0`”和“负号”分别靠什么保证正确？给出写错之后输出出错的输入。

## A
**不变量。** 整数循环里，设原数的绝对值为 `N`，每一轮开始时 `n * 10^k + (已取出的低 k 位) == N`，`n` 始终非负；`n` 到 `0` 时低位全部取完。

**为什么取绝对值。** Python 的 `//` 和 `divmod` 向下取整，对负数 `divmod(-12, 10)` 是 `(-2, 8)`，下一轮 `divmod(-2, 10)` 是 `(-1, 8)`，再下一轮 `divmod(-1, 10)` 是 `(-1, 9)`：`n` 停在 `-1`，永远到不了 `0`，循环**不会结束**，而且每一位都是错的。先取绝对值让 `n` 非负，不变量才成立。（C、Java 的 `%` 对负数给负余数，`-2^63` 取绝对值又会溢出，所以那些语言里要在负数一侧累积；Python 没有溢出问题。）

**小数部分。** `frac_value` 当整数读时位数信息丢了，`frac_len` 是唯一记录位数的量：去掉末尾 `0` 时两者同步变化（值除以 `10`，位数减一），转成数字串后再用 `frac_len - len(串)` 补零，位数不变量就守住了。
- 反例 `(1, 0, 5, 3)`（即 `0.005`）：不补零得 `"0.5"`，补零得 `"0.005"`。
- 反例 `(1, 0, 500, 3)`（即 `0.500`）：去尾零后 `frac_value = 5`、`frac_len = 1`，输出 `"0.5"`；如果只补零不去尾零会输出 `"0.500"`，不是规范写法。

**负号。** 负号看的是整个数值是否非零，不是只看整数部分：`(-1, 0, 5, 2)` 的整数部分是 `0`，只看 `int_part` 会输出 `"0.05"`，正确是 `"-0.05"`；`(-1, 0, 0, 2)` 数值为零，去尾零后 `frac_len` 变成 `0`、`int_part` 也是 `0`，不加负号，输出 `"0"` 而不是 `"-0"`。
