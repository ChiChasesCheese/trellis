## Q
**LC 460 LFU 缓存**｜正确性

为什么 `min_freq` 只需要在"插入新键"和"最小桶被搬空"两种情况下更新？`put` 一个已存在的键为什么也要算一次使用？各给出一个遗漏时出错的具体操作序列。

## A
**不变量。** 缓存非空时，`min_freq` 等于所有键的最小使用次数，且 `buckets[min_freq]` 非空；每个桶里的键按"最近一次使用"从旧到新排列。

**`min_freq` 为什么只在两处变化。**
- 新键插入：它的次数是 `1`，不可能有比 `1` 更小的次数（次数从 `1` 起），所以 `min_freq = 1`。
- 某个键被使用，从 `f` 号桶搬到 `f+1` 号桶：只有当它是 `f = min_freq` 桶里的**最后一个**键时，最小次数才会变，新的最小次数恰好是 `f+1`（刚被搬进去的那个键就在那里）。其他情况最小次数不变。
- 淘汰只发生在插入新键之前，插入之后 `min_freq` 又被重置为 `1`，所以淘汰引起的变化不需要单独处理。

**反例 1：`put` 已存在的键不算使用。** 容量 `2`：`put(1,1)`、`put(2,2)`、`get(2)`、`put(1,10)`、`put(3,3)`：
- 正确：`get(2)` 让键 `2` 次数为 `2`；`put(1,10)` 让键 `1` 次数也为 `2`，且比键 `2` 更新近。`put(3,3)` 淘汰次数相同里更久没用的键 `2`。随后 `get(1)` → `10`，`get(2)` → `-1`，`get(3)` → `3`。
- 漏掉 `_touch`：键 `1` 次数仍是 `1`，被淘汰。`get(1)` → `-1`，`get(2)` → `2`，`get(3)` → `3`。

**反例 2：最小桶搬空后不更新 `min_freq`。** 容量 `2`：`put(1,1)`、`put(2,2)`、`get(1)`、`get(2)`、`put(3,3)`：
- 两次 `get` 之后所有键次数都是 `2`，`1` 号桶已经被删掉。
- `min_freq` 若仍是 `1`，淘汰时对一个空的 `OrderedDict` 调用 `popitem`，抛 `KeyError`。
- 正确的 `min_freq` 是 `2`，淘汰桶里最老的键 `1`。

**同次数的先后顺序。** 桶内按使用顺序追加到末尾，淘汰取最左边，对应"次数相同则最久未使用"。
