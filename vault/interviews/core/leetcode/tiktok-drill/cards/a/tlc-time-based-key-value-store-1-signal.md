## Q
**LC 981 基于时间的键值存储**｜Medium · 近一年被问：美国 1 次、国内 0 次 · 最近 2026-03-20（面试记录）

设计 `TimeMap`：`set(key, value, timestamp)` 存入键在某个时间戳的值；`get(key, timestamp)` 返回 `timestamp_prev <= timestamp` 中 `timestamp_prev` 最大的那次 `set` 的值，没有则返回 `""`。`set` 的时间戳**严格递增**，`1 <= timestamp <= 10^7`，`set` 与 `get` 合计最多 `2 * 10^5` 次。例：`set("foo","bar",1)` 后 `get("foo",3)` → `"bar"`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「不超过目标的最大时间戳」→ 有序序列里找**前驱**，用 **二分查找**（`bisect_right` 减一）。
- 「`set` 的时间戳严格递增」→ 追加就是有序，**不需要排序、不需要中间插入**。这是题目给的关键条件。
- 「设计类」+「一键多值」→ `dict[键, 列表]`，列表按时间有序。
- `2 * 10^5` 次调用 → `get` 不能 `O(m)` 线性扫描。

**推导链。**
1. 暴力：每个键存 `(时间戳, 值)` 列表，`get` 从后往前找第一个不超过目标的，最坏 `O(m)`，总 `O(n^2)`。
2. 浪费：列表本来就按时间有序，线性扫描没用上这个性质。
3. 关键：对时间戳列表 `bisect_right(times, timestamp)` 返回第一个大于目标的位置 `i`，`i - 1` 就是答案下标；`i == 0` 表示没有符合的版本，返回 `""`。
4. 为了让 `bisect` 直接作用在整数列表上，把时间戳和值存成两个并行列表；`set` 追加，`get` 二分，`O(1)` 和 `O(log m)`。

**同模式的题**：LC 1146 快照数组、LC 729 我的日程安排 I、LC 34 在排序数组中查找元素的第一个和最后一个位置、LC 2034 股票价格波动。
