## Q
**LC 912 排序数组**｜正确性

堆排序为什么每一步后结果都对？建堆为什么必须自底向上、下沉的堆大小为什么是 `end`？

## A
**不变量。** 建堆后，`nums[:size]` 是大根堆（每个节点不小于它的孩子）；每轮结束后，`nums[end:]` 已经是整个数组中最大的那些元素，并按升序排好，且都不小于堆里任何元素。把堆顶换到 `end - 1` 位置，等于把堆里的最大值放进有序后缀，再把大小缩到 `end`，只有新堆顶可能违反堆性质，而它的两棵子树仍是堆，所以一次下沉就能修复。

建堆自底向上：`sift_down(i)` 需要 `i` 的两棵子树已经是堆。倒着处理 `i` 时，比它编号大的节点都处理过了，前提成立；从 `0` 往后处理则前提不成立。

**反例 1：建堆顺序错。** 用 `for i in range(0, n // 2)` 建堆，输入 `[1, 2, 3, 4]` 得到 `[1, 2, 4, 3]`，正确是 `[1, 2, 3, 4]`：根被下沉时，子树还不是堆，较大的孩子不一定在子树顶端。

**反例 2：堆大小写成 `n`。** 每轮 `sift_down(0, n)` 会把已排好的后缀又当成堆的一部分，最大值被换回前面，结果不再有序。

**反例 3：快排固定首元素基准。** 在升序数组 `list(range(2000))` 上每次划分只切掉一个元素，递归深度 `2000`，默认递归上限 `1000` 下抛出 `RecursionError`；堆排序不依赖输入顺序，最坏也是 `O(n log n)`。
