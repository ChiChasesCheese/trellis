## Q
**PercentileFinder：实时维护数字并返回第 p 百分位**｜Medium · TikTok 高频

设计类 `PercentileFinder`，实时维护一组整数：`addNums(nums)` 加入一批数字；`findPercentile(p)` 返回当前全部数据的第 `p` 百分位值。`p` 是 `0` 到 `100` 的整数，用最近秩法：第 `max(1, ceil(p * N / 100))` 小，`N` 是当前数据个数；无数据时抛 `ValueError`。要求先用 `bisect` 实现。调用总数和加入的数字总数都不超过 `10^5`。例：`[15,20,35,40,50]` 的 `p = 40` → `20`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「实时维护 + 随时查第 `p` 百分位」→ 动态顺序统计：数据有序时第 `k` 小就是下标 `k - 1`。
- 「先用 `bisect`」→ 有序列表加二分插入（`insort`）。
- 「`addNums` 一次加一批」→ 批量大小不同，要在「逐个插入」和「整体重排」之间选。
- 「百分位」→ 先约定定义（最近秩 / 线性插值）和边界（`p = 0`、`p = 100`），整数运算避免浮点误差。
- 调用数 `10^5`：每次查询重新排序是 `10^5 * N log N`，不可接受。

**推导链。**
1. 暴力：每次查询对全部数据排序再取，`O(N log N)` 一次。
2. 浪费：每次查询重复排序，而两次查询之间只多了几个数。
3. 洞察一：保持列表有序，把排序分摊到加入时；`bisect.insort` 用二分找位置，`O(log N)` 次比较，插入的 `O(N)` 平移是 `memmove`，常数很小。
4. 洞察二：一批很大时逐个插入总平移量太大，直接 `extend` 再 `sort`，Timsort 对已有序的前缀近似线性。
5. 最优：查询按名次直接取下标，`O(1)`；名次用整数算 `max(1, -(-p * N // 100))`。

**同模式的题**：LC 295 数据流的中位数、LC 703 数据流中的第 K 大元素、LC 480 滑动窗口中位数、LC 315 计算右侧小于当前元素的个数。
