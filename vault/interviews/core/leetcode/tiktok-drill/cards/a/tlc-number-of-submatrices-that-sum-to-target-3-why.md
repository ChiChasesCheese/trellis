## Q
**LC 1074 元素和为目标值的子矩阵数量**｜正确性

为什么「哈希表里查 `s - target`」就数出了所有和为 `target` 的子数组？`{0: 1}` 的初值、「先查后更新」这两处各防住什么错误？为什么不能用双指针？

## A
**不变量。** 扫描到第 `j` 列时，`s` 是 `col[0..j]` 的前缀和，`seen[p]` 是此前所有前缀位置（含空前缀）里前缀和等于 `p` 的个数。以第 `j` 列结尾的子数组 `col[i+1..j]` 的和是 `s - s_i`；它等于 `target` 当且仅当 `s_i = s - target`，所以满足条件的起点个数恰好是 `seen[s - target]`。

**错误 1：忘了空前缀 `{0: 1}`。** 空前缀对应「从第 0 列开始」的子数组。`matrix = [[5]]`，`target = 5`：`s = 5`，要找 `s - target = 0`，表里没有，结果 `0`，而正确答案 `1`。`[[1,-1],[-1,1]]`、`target = 0` 同样漏掉所有从第 0 列开始的子数组，得到 `1`（正确 `5`）。

**错误 2：先更新后查询。** 写成 `seen[s] += 1` 再 `ans += seen[s - target]`，当 `target = 0` 时 `s - target = s`，刚更新的当前前缀被数到自己，等于数进了一个空子数组。`matrix = [[904]]`，`target = 0`：得到 `1`，正确是 `0`。

**错误 3：双指针（滑动窗口）。** 滑动窗口依赖「元素非负时，窗口和随右端单调增」。矩阵元素可以为负，窗口和不再单调，`s > target` 时缩左端可能错过之后又回到 `target` 的情形。`[[1,-1],[-1,1]]`、`target = 0`：双指针版本得到 `4`，正确答案 `5`。

**为什么边界枚举不重复不遗漏。** 每个子矩阵由唯一的 `(top, bottom, left, right)` 决定；外两层枚举 `(top, bottom)`，内层前缀和计数覆盖所有 `(left, right)`，每个子矩阵恰好被数一次。
