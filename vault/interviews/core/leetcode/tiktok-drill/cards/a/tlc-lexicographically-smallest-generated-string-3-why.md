## Q
**LC 3474 字典序最小的生成字符串**｜正确性

为什么「改最右的自由位、改成 `'b'`」既是字典序最优的修补，又不会让之前已经检查过的 `'F'` 窗口重新变成 `str2`？

## A
**不变量。** 填完 `'a'` 后，每个自由位已经是它能取的最小字母，任何合法答案在自由位上都不小于 `'a'`。`'F'` 窗口恰好等于 `str2` 时，必须有某个自由位变得不同，该位至少要大于 `'a'`，最小的选择是 `'b'`。在窗口的自由位里，被改动的位置越靠右，前面保持 `'a'` 的位越多，字典序越小。

**为什么不会连累更早的窗口。** 设改动的位置是 `j`，它是窗口 `i` 内最右的自由位，所以 `j+1` 到窗口末尾全被 `'T'` 窗口钉死，且 `j+1` 正是某个 `'T'` 窗口的起点。若更早的 `'F'` 窗口 `i' < i` 因这次改动才变回 `str2`，则 `str2` 同时具有周期 `j + 1 - i`，并且在同一个下标上既要是 `'a'`（来自窗口 `i`）又要是 `'b'`（来自窗口 `i'`），矛盾。所以单次从左到右扫描就够了。

**反例（错误写法一）：改最左的自由位。** `str1 = "F", str2 = "aa"`：改最左得 `"ba"`，最右得 `"ab"`，后者字典序更小。**反例（错误写法二）：铺 `'T'` 时不检查冲突。** `str1 = "TT", str2 = "ab"`：后一个窗口覆盖前一个，得到 `"aab"`，但它的第 `0` 个窗口是 `"aa"`，不等于 `"ab"`，不合法；正确答案是 `""`。
