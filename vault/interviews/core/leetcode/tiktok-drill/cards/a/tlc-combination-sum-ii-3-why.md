## Q
**LC 40 组合总和 II**｜正确性

去重条件为什么是 `i > start and nums[i] == nums[i - 1]`，而不是 `i > 0 and nums[i] == nums[i - 1]`？给出写成 `i > 0` 会漏解的输入。

## A
**不变量。** 在同一次 `dfs` 调用的 `for` 循环里，每个不同的值至多被作为「当前位置的选择」尝试一次；而在不同层，同一个值可以再次出现（它们是组合里不同位置的元素）。

**为什么是 `i > start`。** 重复组合来自「同一层选了值相同的两个不同下标」：比如 `[1,1,6]` 里，第一层选下标 0 的 `1` 或下标 1 的 `1`，两者后面能走出的组合完全一样，保留一个就够。`i == start` 表示这是本层的第一个候选，不是「同一层的第二次尝试」，不能跳过。而在下一层，`start = i + 1`，`nums[start]` 即使等于 `nums[start - 1]`（上一层刚选的那个 `1`），因为 `i == start`，也不会被跳过——它是组合里的第二个元素，必须允许。

**反例 `[1,1,6]`，`target = 8`。** 正确答案 `[[1,1,6]]`。
- 写成 `i > 0`：第一层选下标 0 的 `1`，进入第二层 `start = 1`，候选 `nums[1] = 1`，此时 `i = 1 > 0` 且 `nums[1] == nums[0]`，被跳过；后面只剩 `6`，`1 + 6 = 7 != 8`。结果 `[]`，错。
- 写成 `i > start`：第二层 `i == start == 1`，不跳过，选到第二个 `1`，再选 `6`，得到 `[1,1,6]`，对。

**反过来，漏掉去重。** 示例 `[10,1,2,7,6,1,5]`，`target = 8`：两个 `1` 在第一层各引出一次 `[1,2,5]`、`[1,7]`，结果出现 `[[1,1,6],[1,2,5],[1,7],[1,2,5],[1,7],[2,6]]`，共 `6` 个，正确是 `4` 个。
