## Q
**LC 88 合并两个有序数组**｜正确性

为什么原地合并要从后往前写，而不能从前往后？从后往前写时，什么不变量保证不会覆盖还没读的元素？给出从前往后写会丢数据的具体输入。

## A
**不变量。** 每一步开始时，写入位置 `k = i + j + 1`。`nums1[k+1:]` 里已经是最终结果中最大的那些元素，`nums1[:i+1]` 与 `nums2[:j+1]` 是还没处理的部分。因为 `j >= 0`，`k >= i + 1 > i`，所以 `k` 一定在 `nums1` 未读部分的右侧，写入 `k` 不会碰到 `nums1[:i+1]` 里任何元素。

**为什么能这样做。** 两个数组各自有序，剩下元素里最大的一定是 `nums1[i]` 与 `nums2[j]` 之一；它是最终结果里尚未确定的位置中最大的，应放在 `k`。这样每一步都确定了一个最终位置。

**反例：从前往后。** `nums1 = [1,2,3,0,0,0]`，`nums2 = [2,5,6]`，用 `i = j = k = 0` 往后写：
- `k = 0`：`1 <= 2`，取 `nums1[0] = 1`，写入位置 0（原来就是 1）。
- `k = 1`：`2 <= 2`，取 `nums1[1] = 2`，写入位置 1（原来就是 2）。
- `k = 2`：`nums1[2] = 3 > nums2[0] = 2`，取 `nums2[0] = 2`，写入位置 2，覆盖了原来的 `3`，而这个 `3` 还没被读到。
- 之后 `3` 再也找不回来，最终得到 `[1, 2, 2, 2, 5, 6]`，正确结果是 `[1, 2, 2, 3, 5, 6]`。

从前往后要想正确，就得先把 `nums1` 的有效部分整体后移 `n` 格，多一次 `O(m)` 的搬运；从后往前则天然避开这个问题。
