## Q
**LC 921 使括号有效的最少添加**｜正确性

为什么「遇到没有 `(` 可配的 `)` 时直接补一个 `(`」就是最优的？为什么不能只比较 `(` 与 `)` 的个数之差？

## A
**不变量。** 扫描到任意位置时，`add` 是「该位置之前，为了让每个 `)` 都有配对而必须补的 `(` 的最少个数」，`open_cnt` 是补完之后还没配上的 `(` 个数。两个量都已经是最小的。

**为什么这样补最优。** 一个 `)` 在它之前已经没有未配对的 `(`，那么无论在别处怎么插，只有在它的左边补一个 `(` 才能让它有对象，这一次插入无法避免。结尾剩下的 `(` 的右边也只能靠补 `)`，同样无法避免。每次插入最多消除一个未匹配的括号，所以下界就是未匹配括号的总数，贪心达到了它。

**为什么不能看个数之差。** 括号有**顺序**要求：`)` 必须出现在与它配对的 `(` 之后。个数相等并不代表有效。

**反例。** `s = ")("`：
- `(` 与 `)` 各一个，个数之差是 `0`，错误地认为不用插入。
- 实际要补两个：先在最前面补一个 `(`，再在最后补一个 `)`，得到 `"()()"`，答案是 `2`。
- 扫描过程：读到 `)` 时 `open_cnt` 为 `0`，`add = 1`；读到 `(` 时 `open_cnt = 1`；结束 `add + open_cnt = 2`。
