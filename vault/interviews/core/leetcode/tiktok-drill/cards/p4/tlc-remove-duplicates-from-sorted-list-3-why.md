## Q
**LC 83 删除排序链表中的重复元素**｜正确性

为什么摘掉重复节点后 `cur` 必须留在原地？写成"无论如何都前进一步"会错在哪里？给出具体输出。

## A
**不变量。** 每次循环开始时，从 `head` 到 `cur` 这一段已经没有重复值，并且 `cur.val` 不小于其中任何值（有序）。`cur.next` 之后的节点还没处理。

**为什么留在原地。** 摘掉 `cur.next` 之后，新的 `cur.next` 是原来的第二个后继，它可能仍然等于 `cur.val`（连续三个或更多个相同值）。`cur` 不动，下一轮继续比较，直到下一个值不同，再前进。只有当 `cur.next.val != cur.val` 时，才能确定 `cur` 这个值已经只剩一个。

**反例：删除后无条件前进。**
```text
if cur.val == cur.next.val:
    cur.next = cur.next.next
cur = cur.next                  # 无论如何都前进
```
- 输入 `[1,1,1]`：第一次摘掉第二个 `1`，链表变成 `1 -> 1`，`cur` 却已经前进到第三个 `1`（原来的），下一轮 `cur.next` 为空，循环结束。
- 输出 `[1,1]`，正确是 `[1]`。
- 输入 `[1,1,1,2,2,2]`：输出 `[1,1,2,2]`，正确是 `[1,2]`。

**有序的作用。** 无序链表中相同值可能不相邻，只比较相邻节点会漏掉它们（`[1,2,1]` 不会去重）；本解依赖「有序 → 相同值相邻」这个前提。
