## Q
**LC 547 省份数量**｜正确性

省份数量的 DFS 解法为什么「启动 DFS 的次数 = 省份数」？`seen` 必须在递归邻居之前标记，顺序反过来会怎样？把矩阵当成网格去数连通块又会错在哪里？

## A
**不变量。** 外层循环处理到城市 `i` 时，所有被前面 DFS 启动过的省份，其城市已全部标记。一次 `dfs(i)` 沿着 `isConnected` 的 `1` 走遍 `i` 的整个连通分量，并且只走这个分量：传递性保证分量内任何城市都能到达，无向（矩阵对称）保证不会漏掉反向的边，而不同分量之间没有 `1`，走不出去。所以每个分量恰好被启动一次（第一个被外层循环碰到的城市），启动次数等于分量数。

**反例一：先递归、后标记。** `[[1]]`（一个城市，正确答案 `1`）：`dfs(0)` 里 `isConnected[0][0] == 1` 且 `0` 还没标记，立刻再调 `dfs(0)`，无限递归，抛 `RecursionError`。`[[1,1],[1,1]]` 同理，`0` 和 `1` 来回调用。标记必须是 `dfs` 的第一句。

**反例二：把矩阵当网格数岛屿。** `[[1,0,1],[0,1,0],[1,0,1]]` 是三个城市：`0` 和 `2` 直接相连，`1` 单独一个，答案是 `2`；按网格四方向数 `1` 的连通块得到 `5`。邻居是同一行里所有 `isConnected[i][j] == 1` 的 `j`，不是上下左右的格子。

**反例三：并查集里每遇到一条边就让计数减一。** 三个城市两两相连 `[[1,1,1],[1,1,1],[1,1,1]]`，答案是 `1`；有 `3` 条边，`3 - 3 = 0`。第三条边 `0-2` 的两端在前两条边之后已经同属一个根，不该再减；只在两端的根不同时才合并、才减一，才得到 `3 - 2 = 1`。
