## Q
**LC 787 K 站中转内最便宜的航班**｜正确性

为什么填 `k + 1` 行就能得到「最多 `k` 站中转」的最小价格？为什么第 `t` 行要读第 `t - 1` 行、不能读自己？普通 Dijkstra 为什么会给出错误答案？

## A
**不变量。** 第 `t` 行填完后，`dp[t][v]` 等于从 `src` 出发，使用**至多 `t` 条边**到达 `v` 的最小价格。

**归纳。** `t = 0`：只有 `src` 为 `0`，其余无穷，成立。第 `t` 行：至多 `t` 条边的最优路线，要么不用第 `t` 条边（沿用 `dp[t-1][v]`，因为第 `t` 行从第 `t - 1` 行复制而来），要么最后一条是 `u → v`，前面是至多 `t - 1` 条边到 `u` 的最优，也就是 `dp[t-1][u] + w`。两种情况取小，正是这一行的结果。`k` 站中转就是至多 `k + 1` 条边，所以填到第 `k + 1` 行读答案。

**为什么读上一行。** 若转移写成 `dp[t][u] + w`（读本行），一行里刚更新的值又会被后面的航班读到，一行就可以连走多条边，第 `t` 行的含义变成“可能超过 `t` 条边”，限制被突破。
- `n = 3`，`flights = [[0,1,100],[1,2,100],[0,2,500]]`，`src = 0`，`dst = 2`，`k = 0`（只允许 1 条边）：航班按这个顺序处理，读本行先得 `dp[1][1] = 100`，再用它得到 `dp[1][2] = 200`，返回 `200`。
- 正确的答案是 `500`（只能直达）。

**行数与复制。** 表要开 `k + 2` 行：只开 `k + 1` 行时，`k = 0` 的表里只有第 0 行，同一组航班得到 `-1`；新的一行如果不从上一行复制，就成了「恰好 `t` 趟」，`flights = [[0,1,100],[1,2,100],[0,2,150]]`、`k = 1` 得到 `200`，正确是 `150`（直达）。

**为什么不能用普通 Dijkstra。** Dijkstra 的贪心是“弹出的第一个到达 `v` 的就是价格最小的”，没有记录边数。示例 1 中不限站数的最短路是 `0 → 1 → 2 → 3`，价格 `400`，但它中转了 `2` 站，超过 `k = 1`；而价格更高的 `0 → 1 → 3`（`700`）才合法。要用 Dijkstra，状态必须是 `(城市, 已用边数)`，不能只看城市。
