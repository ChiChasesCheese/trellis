## Q
**LC 540 有序数组中的单一元素**｜正确性

为什么单一元素左边的成对元素从偶数下标开始、右边的从奇数下标开始？二分时 `mid` 为什么必须对齐成偶数？不对齐会出什么错？

## A
**不变量。** 设单一元素的下标为 `p`（数组长度是奇数，`p` 必为偶数）。
- 对每个偶数下标 `m < p`：`nums[m] == nums[m+1]`（`p` 之前有偶数个元素，恰好配成整对，每对从偶数下标开始）。
- 对每个偶数下标 `m >= p`：`nums[m] != nums[m+1]`（`m = p` 时它是单一元素，与后一个不同；`m > p` 时，`p` 之后的元素被错位一格，整对从奇数下标开始，所以 `nums[m]` 是上一对的右端，与 `nums[m+1]` 不同）。

所以在偶数下标上，谓词「`nums[m] != nums[m+1]`」先假后真，分界点就是 `p`。

**为什么必须对齐成偶数。** 谓词只在偶数下标上有这个单调性。奇数下标 `m` 上，`nums[m] == nums[m+1]` 的含义恰好相反：`m < p` 时，`nums[m]` 是某一对的右端，与后一对的左端不同；`m > p` 时，反而是同一对。

**反例：不对齐。** `nums = [3,3,7,7,10,11,11]`（单一元素 `10`，下标 `4`）：
- `lo = 0`，`hi = 6`，`mid = 3`（奇数），`nums[3] = 7`，`nums[4] = 10`，不相等，错误地认为答案在左半，`hi = 3`；
- 此后区间 `[0, 3]` 里已经没有 `10`，最终返回 `7`，正确是 `10`。

对齐后：`mid = 3 → 2`，`nums[2] == nums[3]`（都是 `7`），`lo = 4`，区间收到 `[4, 6]`，再 `mid = 5 → 4`，`nums[4] != nums[5]`，`hi = 4`，返回 `nums[4] = 10`。
