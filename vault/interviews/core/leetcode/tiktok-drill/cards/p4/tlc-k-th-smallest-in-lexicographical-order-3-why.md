## Q
**LC 440 字典序的第 K 小数字**｜正确性

为什么跳到右邻兄弟 `cur + 1` 不会跳出这棵树？为什么 `count(prefix)` 里要用半开区间和 `n + 1`？

## A
**不变量。** 每次循环开始时，目标数（字典序第 `原k` 小）要么就是 `cur`，要么在 `cur` 的子树里的后面某处，或者在 `cur` 的右侧；`k` 是目标相对于 `cur` 在先序中的偏移。`size <= k` 说明偏移越过了整棵子树，目标在右侧；此时目标一定还在 `cur` 的父结点的子树内（我们是因为 `size(父结点) > 当时的偏移` 才下钻到父结点的孩子层的），所以 `cur` 一定有右邻兄弟，`cur + 1` 不会越出同一层（不会出现 `19 → 20` 这种跳到别的父结点的情况）。`size > k` 说明目标在 `cur` 的子树里，偏移减去 `cur` 自己，进入第一个孩子。

**为什么半开区间。** 每层的数是 `[lo, hi)`，而 `n` 本身要算进去，所以上界是 `min(n + 1, hi)`；用 `min(n, hi)` 会漏掉 `n` 所在的最后一个数。

**反例（错误写法一）：`min(n, hi)`。** `n = 13, k = 13`：`count(1)` 少算 1，最终返回 `10`，正确答案是 `9`（字典序最后一个数）。

**反例（错误写法二）：忘了 `k -= 1`。** `n = 13, k = 2`：`cur = 1` 已经是第 1 小，却仍按 `k = 2` 走，返回 `11`，正确答案是 `10`。
