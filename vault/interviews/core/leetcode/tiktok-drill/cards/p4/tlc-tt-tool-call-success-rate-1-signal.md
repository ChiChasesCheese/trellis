## Q
**工具调用成功率统计**｜Easy · 近一年被问：美国 0 次、国内 1 次 · 最近 2026-10（面试记录）

日志每行是 `"<timestamp> <tool_name> <status>"`（字段以空白分隔，`timestamp` 是非负整数秒，`status` 是 `SUCCESS` 或 `FAIL`），可能有空行或格式错误的行（字段数不是 3、`status` 不是这两个值、`timestamp` 不是整数），要跳过。返回每个工具的成功率（成功次数 / 总调用次数，保留 4 位小数）和失败次数最多的工具名（并列取字典序最小，没有失败返回空字符串）。日志行数 `n <= 10^6`，要求一次遍历、`O(n)`。例：`["100 search SUCCESS", "101 search FAIL", "102 calc FAIL", "103 calc FAIL"]` → 成功率 `{"search": 0.5, "calc": 0.0}`，失败最多的是 `"calc"`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「每个工具的成功率」「失败最多的工具」→ **按名字分组计数**（哈希计数，`Counter`）。
- 「`n <= 10^6`、一次遍历」→ 流式处理，每行 `O(1)`；不能先收集工具名再对每个工具重扫，也不需要排序。
- 「空行或格式错误的行要跳过」→ 解析是第一道关：字段数、取值、整数性都要校验，坏行**整行**丢弃，不能只计一部分。
- 「并列取字典序最小」→ 比较键用元组 `(-次数, 名字)`，一次 `min` 同时表达两条规则。

**推导链。**
1. 暴力：先扫一遍收集所有工具名，再对每个工具扫整份日志数成功和失败，`O(n · 工具数)`。
2. 浪费：一行日志只影响一个工具的两个计数，没必要重复扫描。
3. 读一行就更新 `total[tool]` 和 `fails[tool]`，一次遍历 `O(n)`。
4. 结束时对每个工具算 `(总数 - 失败) / 总数`；失败最多的工具用 `min(fails, key=lambda t: (-fails[t], t), default="")`，`default=""` 处理没有任何失败的情况。

**同模式的题**：LC 692 前 K 个高频单词、LC 811 子域名访问计数、LC 819 最常见的单词、LC 347 前 K 个高频元素。
