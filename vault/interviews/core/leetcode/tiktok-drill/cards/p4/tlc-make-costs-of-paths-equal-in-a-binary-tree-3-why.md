## Q
**LC 2673 使二叉树所有路径值相等的最小代价**｜正确性

满二叉树上每个节点可以加 `1`，要让根到所有叶子的路径值相等。自底向上时，为什么每个节点处的最少操作数就是两个孩子“路径值”之差，并且补在较小的孩子上？把增量补在叶子上、忘记把子树路径值累加给自己，各会错成什么样？

## A
**不变量。** 处理完节点 `i` 的两个孩子后，`i` 的每个孩子子树内部的所有叶子路径（从孩子到叶子）都已经相等，`c[2i]`、`c[2i+1]` 就是这个公共值。要让经过 `i` 的所有根到叶路径相等，两个孩子子树的公共值必须相等：较小的一侧至少要补 `|L - R|`，而补在该孩子的根上恰好一次抬高整个子树，且不破坏子树内部已经拉齐的状态，所以 `|L - R|` 既是下界也能达到。拉齐后 `i` 到叶子的路径值是 `c[i] + max(L, R)`，只和这个值有关，上一层的决策与子树内部无关，所以各节点的代价相加就是全局最小。

**反例一：补在叶子上。** `n = 7`，`cost = [1,5,2,2,3,3,1]`：根到四个叶子的路径值是 `8, 9, 6, 4`。都补到 `9`，叶子分别加 `1, 0, 3, 5`，共 `9` 次；补在兄弟子树的根上只要 `6` 次（节点 4 加 `1`、节点 3 加 `3`、节点 7 加 `2`），因为节点 3 上的一次加法同时抬高它下面的两个叶子。

**反例二：不累加子树路径。** 只比较孩子自己的值，写成 `c[i]` 不加 `max(left, right)`。`n = 7`，`cost = [1,2,3,4,5,6,7]`：节点 `1` 处比较的是 `2` 与 `3`，错误地得到总数 `1 + 1 + 1 = 3`；正确要比较「到叶子的路径值」`8` 与 `11`，总数 `1 + 1 + 3 = 5`。

**反例三：自顶向下。** 处理根时，两个子树内部还没拉齐，不知道各自的“公共路径值”是多少，无法计算差值；顺序必须是先孩子、后父亲。
