## Q
**LC 867 转置矩阵**｜正确性

转置矩阵满足 `res[j][i] = matrix[i][j]`。`zip(*matrix)` 为什么恰好给出转置？原地交换只遍历上三角（`j > i`）的理由是什么？新矩阵写成 `[[0] * m] * n`、原地版本让 `j` 从 `0` 开始、对非方阵原地操作，各会错成什么样？

## A
**不变量。** `zip(*matrix)` 产出的第 `j` 个元组由每一行的第 `j` 个元素按行序组成，即 `(matrix[0][j], matrix[1][j], ..., matrix[m-1][j])`，正是结果的第 `j` 行，`res[j][i] = matrix[i][j]`。原地交换时，位置 `(i, j)` 与 `(j, i)` 互为镜像，交换一次就完成；对角线上的元素 `(i, i)` 自己和自己对称，不用动。

**反例一：`[[0] * m] * n`。** `n` 个“行”其实是同一个列表对象。转置 `[[1,2,3],[4,5,6]]` 时，对 `res[j][i]` 的每次写入都写进共享的那一行，最后得到 `[[3, 6], [3, 6], [3, 6]]`，正确是 `[[1, 4], [2, 5], [3, 6]]`。

**反例二：内层 `j` 从 `0` 开始。** 对 `(i, j)` 和 `(j, i)` 各换一次，等于换了两次，元素回到原位；`[[1,2,3],[4,5,6],[7,8,9]]` 做完之后仍然是它自己。

**反例三：对非方阵原地。** `2 x 3` 的矩阵转置后是 `3 x 2`，形状变了，原来的二维数组装不下；按方阵的下标公式交换会触发 `IndexError`（访问 `matrix[2][0]`，而只有两行），必须新建矩阵。
