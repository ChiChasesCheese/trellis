## Q
**圆环上走 n 步回到原点的方案数**｜正确性

环上 `10` 个点，每步顺时针或逆时针走一格，用 `ways[p]` 记录当前步数下停在 `p` 的走法数。为什么 `ways_new[p] = ways[p-1] + ways[p+1]` 能算出所有走法？更新时覆盖旧数组、`p + 1` 不取模，各会错成什么样？

## A
**不变量。** 走完 `s` 步后，`ways[p]` 等于所有“恰好 `s` 步、结束在 `p`”的方向序列的数量。走第 `s + 1` 步，到达 `p` 的最后一步只可能来自 `p - 1`（顺时针一步）或 `p + 1`（逆时针一步），这两类走法互不重叠、没有遗漏，所以 `ways_new[p]` 是两项之和；环上的 `p - 1`、`p + 1` 对 `10` 取模。初始 `ways[0] = 1` 对应 `0` 步。

**反例一：原地覆盖。** 在同一个数组上依次写 `ways[p] = ways[p - 1] + ways[(p + 1) % size]`：处理 `p = 1` 时 `ways[0]` 已经是本步的新值，混用新旧两代数据。`n = 2` 得到 `0`，正确是 `2`（顺逆、逆顺各一种）。

**反例二：`p + 1` 不取模。** `p = 9` 时读 `ways[10]`，`IndexError`；环的最后一个点的“顺时针下一个”是点 `0`。

**反例三：只记能否到达。** 把 `ways[p]` 当成布尔值（能到达就是 `1`）会把不同的方向序列合并：`n = 4` 回到起点有 `6` 种方向序列（两次顺时针、两次逆时针的所有排列，`C(4,2) = 6`），布尔版只得到 `1`。题目按方向序列计数，所以每个位置上累加的是路径条数。
