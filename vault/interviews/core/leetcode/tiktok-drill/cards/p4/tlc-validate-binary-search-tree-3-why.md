## Q
**LC 98 验证二叉搜索树**｜正确性

为什么「中序遍历严格递增」就等价于「是 BST」？为什么只比较每个结点和它的左右孩子不够？给出这个错误写法答错的输入。

## A
**不变量。** 访问到每个结点时，已经访问过的结点恰好是中序序列的一个前缀，`prev` 是这个前缀的最后一个值。如果整棵树是 BST，中序序列严格递增，所以每个新访问的值都大于 `prev`；反过来，只要有一次 `node.val <= prev`，就找到了一对「中序靠前却不更小」的结点，它们不可能同时满足 BST 的定义（祖先与后代的大小关系被违反），树无效。

**等价性的来源。** BST 要求「左子树 < 根 < 右子树」。把这个规则递归展开，中序序列是「左子树的中序、根、右子树的中序」：左边全小于根、右边全大于根，且两边各自递增，拼起来就是严格递增。反方向：序列严格递增时，每个结点左边（左子树，加上祖先里更靠前的）都更小，右边都更大，规则成立。

**反例：只比较父子。** 写 `node.left.val < node.val < node.right.val` 的递归，输入 `[5,4,6,null,null,3,7]`：
- 结点 `5` 的孩子是 `4`、`6`，合法；结点 `6` 的孩子是 `3`、`7`，对 `6` 来说 `3 < 6 < 7`，也合法。
- 返回 `True`；但 `3` 在 `5` 的右子树里，必须大于 `5`，所以正确答案是 `False`。
- 中序得到的序列是 `4, 5, 3, 6, 7`，访问 `3` 时 `3 <= 5`，立刻返回 `False`。

祖先对整个子树的约束要么靠 `prev`（中序）、要么靠向下传递的 `(lo, hi)` 区间带下去，只看直接孩子等于丢掉了这些约束。
