## Q
**OrderValidator（规则 DAG）**｜Medium · 近一年被问：美国 1 次、国内 0 次 · 最近 2026-08-06（美国面试记录）

实现 `OrderValidator`：订单要通过一组有依赖关系的校验规则（构成 DAG），被依赖的规则先执行，任一规则失败则订单不通过。接口：`add_rule(name, check, depends_on=())`，依赖只能引用已存在的规则；`remove_rule(name)`，删除时把它的所有前驱直接连到它的所有后继上；`validate(order)` 返回 `(是否通过, 第一个失败的规则名或 None)`。规则数不超过 `10^4`。例：`ship` 依赖 `stock` 和 `price`，两者都依赖 `auth`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「规则之间有依赖、被依赖者先执行」→ 拓扑排序（Python 标准库 `graphlib.TopologicalSorter`）。
- 「依赖只能引用已存在的规则」→ 图在构造上无环，不需要每次加边都做环检测。
- 「删除时前驱连后继」→ 节点收缩：前驱 × 后继两两连边，保持传递关系；需要同时存正向和反向边。
- 「任一规则失败则不通过」→ 可短路，返回第一个失败的规则名。
- 「交付可运行的代码加完整的测试」→ 先列边界：空图、单规则、菱形依赖、删中间节点、重复名、未知依赖。

**推导链。**
1. 暴力：手写递归 DFS 带访问标记执行规则，自己处理环；删除时只把节点从字典里拿掉。
2. 浪费：拓扑排序和环检测标准库现成；只删节点会丢掉经由它传递的顺序约束。
3. 洞察一：`add_rule` 只允许依赖已有规则，所以永远是 DAG；用 `graphlib` 排序即可。
4. 洞察二：删除节点 `x` 时，前驱 `p` 到后继 `s` 的约束原本经过 `x` 传递；重连 `p -> s` 后约束保留，且不会成环，因为 `p` 在 `x` 之前、`x` 在 `s` 之前本来就成立。
5. 最优：维护 `deps` 与 `users` 两个字典，`remove_rule` 只触及该规则的邻居，`validate` 为 `O(V + E)`。
