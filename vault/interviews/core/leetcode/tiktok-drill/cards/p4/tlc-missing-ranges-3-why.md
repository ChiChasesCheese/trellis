## Q
**LC 163 缺失的区间**｜正确性

扫描解法里为什么要在 `nums` 后面补哨兵 `upper + 1`，而且缺口的判断是 `x - prev >= 2`？去掉尾哨兵会在哪个输入上出错？

## A
**不变量。** 每处理完一个 `x`，`prev == x`，并且 `[lower, prev]` 内的所有缺失数都已写进答案。循环结束时要保证 `[lower, upper]` 全部覆盖，所以最后一个已知数之后到 `upper` 的那一段必须也被处理。

**为什么要尾哨兵。** 缺口都是在「遇到下一个已知数」时才写出。最后一个元素之后没有「下一个已知数」，这一段永远不会触发。补上 `upper + 1` 后，`x - prev >= 2` 恰好等价于 `upper - prev >= 1`，即 `prev < upper`，缺口 `[prev + 1, upper]` 照常写出。头部同理，`prev = lower - 1` 让第一个缺口 `[lower, nums[0] - 1]` 不需要特判。

**为什么是 `>= 2`。** `x - prev == 1` 表示两数相邻，没有缺口；`x - prev == 2` 表示恰好缺一个数，得到单点区间 `[prev + 1, prev + 1]`，同样必须输出。

**反例。** `nums = [0,1,3,50,75]`，`lower = 0`，`upper = 99`：
- 去掉尾哨兵（只遍历 `nums`）：输出 `[[2, 2], [4, 49], [51, 74]]`，少了 `[76, 99]`。
- 带尾哨兵：`[[2, 2], [4, 49], [51, 74], [76, 99]]`，正确。
