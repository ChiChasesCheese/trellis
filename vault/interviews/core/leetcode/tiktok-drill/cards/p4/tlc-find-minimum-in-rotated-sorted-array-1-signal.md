## Q
**LC 153 寻找旋转排序数组中的最小值**｜Medium · LC TikTok 热度 50/100 · CodeTop 国内累计 17 次 · 最近 2026-04-16（CodeTop）

元素互不相同的升序数组旋转 `1` 到 `n` 次得到 `nums`（旋转一次 = 最后一个元素移到最前面）。找出最小元素，要求 `O(log n)`。`1 <= n <= 5000`，`-5000 <= nums[i] <= 5000`，元素互不相同。例：`[4,5,6,7,0,1,2]` → `0`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「有序数组被**旋转**」+ 明确要求 `O(log n)` → **二分查找**（binary search），但数组整体不单调。
- 旋转后是两段各自递增的数组，且左段每个元素都大于右段每个元素：「我在左段还是右段」是一个**单调的是非判断**（左段全是『是』、右段全是『否』），二分找的就是分界点。
- 「元素互不相同」是二分能严格成立的前提；有重复时 `nums[mid] == nums[hi]` 无法判断方向（LC 154）。

**推导链。**
1. 暴力：`min(nums)`，`O(n)`，不满足要求。
2. 要二分，就要找到「最小值在 `mid` 的哪一侧」的判据。
3. 与 `nums[lo]` 比较：数组恰好没旋转时（整体有序）会误判，`mid` 永远「在左段」。与 `nums[hi]` 比较没有这个漏洞：`nums[mid] > nums[hi]` 当且仅当断崖在 `(mid, hi]` 内。
4. 区间更新：断崖在右边 `lo = mid + 1`；否则最小值在 `[lo, mid]`，`mid` 自己可能就是答案，所以 `hi = mid`。`lo == hi` 时停。`O(log n)`。

**同模式的题**：LC 154 带重复的最小值、LC 33 搜索旋转排序数组、LC 162 寻找峰值、LC 852 山脉数组的峰顶。
