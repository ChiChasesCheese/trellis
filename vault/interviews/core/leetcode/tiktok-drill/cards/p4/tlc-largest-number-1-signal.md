## Q
**LC 179 最大数**｜Medium · 近一年被问：美国 0 次、国内 1 次 · CodeTop 国内累计 32 次 · 最近 2026-10-18（面试记录）

给一组非负整数 `nums`，重新排列每个数的顺序（每个数不可拆分）使之拼成一个最大的整数，返回字符串。`1 <= nums.length <= 100`，`0 <= nums[i] <= 10^9`。例：`[3,30,34,5,9]` → `"9534330"`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「重新排列，使拼出的结果最大」→ **排序 + 自定义比较器**（comparator）：不是按值排，而是按「谁放前面更大」排。
- 「返回字符串，因为结果可能非常大」→ 全程用字符串，不转 int。
- `n <= 100`：`n!` 不可能，但 `O(n log n)` 排序即可；比较器里做字符串拼接的常数无所谓。

**推导链。**
1. 暴力：枚举 `n!` 种排列取最大，不可行。
2. 按数值降序？`[3,30]` 得 `"303"`，而 `"330"` 更大。按字符串字典序降序？`"30"` 比 `"3"` 长但字典序小于它，结果也是 `"303"`。
3. 根本原因：两个数谁在前，取决于**两种拼法**哪个更大，而不是它们各自的大小。直接比较 `a + b` 与 `b + a`。
4. 为什么排序有效：交换论证——相邻两个数若 `b + a > a + b`，交换后整体更大，所以最优排列里每个相邻对都满足 `a + b >= b + a`；该关系可传递，排序一次就得到全局最优。
5. 收尾：排序后的第一个串若是 `"0"`，说明全是 `0`，返回 `"0"`，不要返回 `"000"`。
