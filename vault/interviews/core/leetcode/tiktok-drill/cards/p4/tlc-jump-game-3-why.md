## Q
**LC 55 跳跃游戏**｜正确性

为什么只维护「最远可达下标」就够了？为什么发现 `i > reach` 就可以直接返回 `False`？去掉这个检查会错成什么？

## A
**不变量。** 扫描到下标 `i` 之前，下标 `0..reach` 全部可达，`reach + 1` 及以后全部不可达（`reach` 等于所有已扫描可达下标 `j` 上 `j + nums[j]` 的最大值）。

**为什么可达集合是连续前缀。** 从可达的 `j` 出发可以跳 `1` 到 `nums[j]` 之间的任意步，所以 `j + 1` 到 `j + nums[j]` 全部可达，区间没有空洞。多个可达位置的覆盖区间都从各自的 `j` 起，且 `j` 本身可达，它们的并集仍是一段包含 `0` 的连续区间，右端点就是 `reach`。

**为什么 `i > reach` 即失败。** 所有可达位置的最远落点都不超过 `reach`；`i` 落在 `reach` 之外，没有任何可达位置能跳到 `i`；而终点下标不小于 `i`，要到达终点必须经过或越过 `i`，而越过 `i` 的起跳点也在 `i` 之前，且也不可达。所以直接返回 `False`。

**反例：去掉检查。** 只在最后比较 `reach >= len(nums) - 1`：`nums = [3,2,1,0,4]`。
- 扫描：`i = 0..3` 时 `reach` 一直是 `3`；到 `i = 4`，`4` 本身不可达，但代码照样执行 `reach = max(3, 4 + 4) = 8`。
- 最后 `8 >= 4`，返回 `True`；正确是 `False`，因为下标 `4` 不可达。

不可达的位置没有资格贡献跳跃距离，所以检查必须放在更新 `reach` 之前。
