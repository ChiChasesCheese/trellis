## Q
**LC 1740 找到二叉树中的距离**｜正确性

为什么「LCA 到 `p` 的边数 + LCA 到 `q` 的边数」就是 `p` 与 `q` 之间的距离？`lca` 命中 `p` 就立刻返回，会不会漏掉 `q`？只用从根起的深度相加会错在哪？

## A
**不变量。** 树中两点之间的简单路径唯一，它先从 `p` 上行到 LCA、再下行到 `q`；LCA 到 `p` 与 LCA 到 `q` 的两段没有公共边（否则公共部分的起点会是更深的公共祖先），所以距离恰好是两段边数之和。`lca(node)` 的约定是：返回 `node` 子树里 `p`、`q` 的汇合点（只含一个就返回那个，都不含返回 `None`）；两边各返回非空，说明 `p`、`q` 分居左右，当前结点就是汇合点；只有一边非空，汇合点在那边或就是那边返回的结点。

**命中就返回为什么安全。** 若 `lca` 在 `p` 处直接返回 `p`，而 `q` 在 `p` 的子树里，那么 `p` 自己就是 LCA，返回 `p` 正确；若 `q` 不在 `p` 的子树里，`q` 会在别处被找到，两边汇合时当前结点才是 LCA。题目保证 `p`、`q` 都在树中，所以不会因为提前返回而漏掉。

**反例：只用从根起的深度。** 示例树 `[3,5,1,6,2,0,8,null,null,7,4]` 中 `p=6, q=2`：二者都是 `5` 的孩子，都在第 2 层。
- 错误写法：`depth[p] + depth[q]` 直接返回 `4`。
- 正确写法：先找到 LCA `5`，`down(5, 6) = 1`，`down(5, 2) = 1`，返回 `2`。

**另一个常见错误：`down` 找不到时返回 `0`。** `down` 在一个孩子的子树里没找到，应该返回 `-1`，由 `>= 0` 的判断跳到另一个孩子；返回 `0` 会把「没找到」当成「命中」，加上 `1` 后得到错误的距离。
