## Q
**LC 207 课程表**｜正确性

为什么「取出的课程数小于 `numCourses`」就等价于「图里有环」？如果改用 DFS 判环，只用一个 `visited` 集合会错在哪里，给一个具体输入。

## A
**不变量。** 一门课进入队列时，它的所有先修课都已经被取出（入度减到 0 就是"先修课全部学完"的意思）。所以取出的课程构成一个合法的学习顺序的前缀。

**为什么有环就一定少取。** 设环 `v1 → v2 → … → vk → v1`。环上每个点 `vi` 至少有一条来自 `v(i-1)` 的入边。要让 `vi` 入度降到 0，就必须先取出 `v(i-1)`，沿环循环依赖，环上第一个被取出的点不存在。所以环上的点永远进不了队列，取出数小于 `numCourses`。反过来，无环图一定能把所有点取完：每一步剩余子图仍是无环图，必有入度为 0 的点（否则沿入边一路倒走会走出环）。

**反例：DFS 判环只用 `visited`。** 菱形图 `4, [[1,0],[2,0],[3,1],[3,2]]`：`0` 指向 `1` 和 `2`，`1` 和 `2` 都指向 `3`，没有环，正确答案 `True`。只用一个 `visited` 集合的 DFS 从 `0` 走到 `1` 再到 `3`，回溯后从 `2` 又走到 `3`，发现 `3` 已在 `visited` 里就报"有环"，输出 `False`。区分"当前递归路径上的点"（遇到才是环）和"已经完整探索完的点"（遇到是正常的）需要三种状态：未访问、在路径上、已完成。

**孤立课程。** 不在任何先修对里的课程入度也是 `0`，初始队列要扫描全部 `numCourses` 个点，否则 `taken` 少算，会把 `numCourses = 3, prerequisites = [[1,0]]` 误判成无法完成。
