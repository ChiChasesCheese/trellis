## Q
**带 TTL 的 LRU 缓存**｜追问

固定容量的 LRU 缓存，每条数据带自己的 `ttl`，满了先清过期再淘汰最久未用。面试官接着问：（1）改成 LFU（先淘汰访问次数最少的，次数相同按 LRU）；（2）每个条目带权重，按总权重限容量；（3）多线程使用；（4）命中率很低时怎么办；（5）所有条目用同一个 TTL，为什么有的条目「没有过期」，大量 key 同时过期怎么办？

## A
1. **LFU**：`freq -> OrderedDict` 加 `min_freq`；`get`/`put` 命中就把条目挪到 `freq + 1` 的桶，淘汰时从 `min_freq` 桶的队首弹出。过期清理还是靠堆加版本号。
2. **加权**：记 `used` 总权重，把「淘汰一个」改成循环：先清过期，再 `while used + weight > capacity: 淘汰队首并 used -= 其权重`；单个条目权重超过容量要直接拒绝。
3. **线程安全**：`get` 会改使用顺序，读也是写，读写锁没有收益；用一把 `threading.Lock` 包住所有公开方法，吞吐不够再按 `hash(key) % N` 分段，每段自己的锁和容量（代价：全局 LRU 变成近似）。
4. **命中率低**：先量再改。容量小于工作集就扩容；TTL 过短就调长；一次性的大扫描把热数据挤掉，就加准入策略（TinyLFU、2Q、分段 LRU）。
5. **统一 TTL**：到期顺序就是写入顺序，再用一个按写入顺序排的 `OrderedDict`，队首过期就弹，不需要堆。「没有过期」常见原因：单位混用（毫秒和秒）、用 `>` 而不是 `>=`、覆盖写没重置 TTL、懒删除下没人读就一直占位。大批 key 同时过期（缓存雪崩）：TTL 加随机抖动，清理分批限量，回源请求合并（singleflight）。

**Python 提醒**：`functools.lru_cache` 没有 TTL，也不能按 key 失效；线程安全要自己加锁：就算单个 `OrderedDict` 方法有 GIL 保护，「先读再 `move_to_end`」「先查容量再插入」这样的组合也不是原子的。
