## Q
**LC 347 前 K 个高频元素**｜正确性

桶排序解法里，桶的个数为什么必须是 `n + 1`？另外，用堆做这个问题时，`heapq.nlargest(k, count)` 少写一个参数会错在哪？各给一个具体输入。

## A
**不变量。** 桶 `buckets[c]` 里放的恰好是出现了 `c` 次的元素。倒序扫桶就是按频次从高到低枚举元素；先取到的 `k` 个就是频次最高的 `k` 个。

**为什么是 `n + 1` 个桶。** 频次的取值范围是 `1` 到 `n`，而下标从 `0` 开始，需要下标 `n` 存在。
- 反例：`nums = [1,1,1]`，`k = 1`。唯一元素频次为 `3 = n`。只开 `n = 3` 个桶（下标 `0..2`）时，`buckets[3].append(1)` 抛出 `IndexError`。
- 开 `n + 1` 个桶，下标 `0` 永远为空，扫描时直接跳过，无害。

**堆版本漏掉 `key`。** `heapq.nlargest(k, count)` 遍历的是字典的键，不给 `key` 就按**元素值**比较大小，而不是频次。
- 反例：`nums = [1,1,1,2,2,3]`，`k = 2`。`heapq.nlargest(2, count)` 比较的是键 `1, 2, 3`，返回 `[3, 2]`。
- 正确答案是 `[1, 2]`；写成 `heapq.nlargest(2, count, key=count.get)` 才对。

**补充。** 题目保证前 `k` 名的集合唯一，所以桶内同频次元素在边界处被 `ans[:k]` 截断时不会产生歧义；没有这个保证时，边界上的并列项取谁是需要和面试官确认的需求。
