## Q
**LC 146 LRU 缓存**｜Medium · LC TikTok 热度 100/100（近 30 天） · 近一年被问：美国 14 次、国内 27 次 · CodeTop 国内累计 367 次 · 最近 2026-10（美国面试记录）

设计 LRU（最近最少使用，Least Recently Used）缓存类 `LRUCache(capacity)`：`get(key)` 存在就返回值，否则返回 `-1`；`put(key, value)` 已存在则更新值，不存在则插入，插入后键的数量超过 `capacity` 就逐出**最久未使用**的键。`get`、`put` 都要平均 `O(1)`。`1 <= capacity <= 3000`，`0 <= key <= 10000`，`0 <= value <= 10^5`，最多调用 `2 * 10^5` 次。例：容量 2，`put(1,1)`、`put(2,2)`、`get(1)` 得 `1`、`put(3,3)` 逐出键 `2`、`get(2)` 得 `-1`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「`get`/`put` 都要 `O(1)`」+「按键查找」→ 哈希表（hash map）。
- 「逐出最久未使用」「每次访问都要把元素标成最新」→ 需要一个按使用顺序排列、能 `O(1)` 删除任意元素并放到一端的结构 → 双向链表（doubly linked list）。
- 两个要求一个结构满足不了 → 这是**组合数据结构**的设计题：字典指向链表节点。
- 调用 `2 * 10^5` 次、容量 3000：每次 `O(n)` 扫描总计约 `6 * 10^8`，不行。

**推导链。**
1. 暴力：用列表按使用顺序存键值对，查找 `O(n)`，挪到末尾也是 `O(n)`。
2. 浪费：查找本该靠字典；挪动元素在数组里要整体平移。
3. 洞察：链表摘节点只改相邻两个指针，前提是已经拿到节点，字典正好存「键 → 节点」；摘节点要改前驱，所以用双向；头尾各放一个哨兵（sentinel）省掉边界判断。
4. 结果：字典查找加常数次指针修改，`get`/`put` 都是 `O(1)`；逐出的尾节点自带 `key`，用它回头删字典。
