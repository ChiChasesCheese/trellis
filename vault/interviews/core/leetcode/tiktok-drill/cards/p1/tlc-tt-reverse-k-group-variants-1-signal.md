## Q
**K 个一组翻转链表的变体**｜Hard · 近一年被问：美国 7 次、国内 12 次 · 最近 2026-10-27（国内面试记录）

给链表头节点 `head` 和正整数 `k`，每 `k` 个节点为一组翻转，必须改指针而不是改值，额外空间 `O(1)`。基础版：从头分组，尾部不足 `k` 个的部分保持原样。变体：（1）尾部不足 `k` 个的部分也要翻转；（2）从链表尾部开始分组，头部不足 `k` 个的那一组保持原样。节点数 `1 <= n <= 10^5`，`k >= 1`，`k` 可以大于 `n`。例：`[1,2,3,4,5,6,7,8]`、`k = 3` → 基础 `[3,2,1,6,5,4,7,8]`，变体（2）`[1,2,5,4,3,8,7,6]`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「分段处理链表 + 段内翻转」→ 把链表翻转（LC 206）当子程序，外层负责分组与接线，用哑节点（dummy）统一第一组。
- 「必须改指针、`O(1)` 空间」→ 不能读进数组，也不能递归（递归深度 `n / k`）。
- 「尾部不足 `k` 个怎么办」「从尾部开始分组」→ 这些都是**分组边界**的规则：先量出长度 `n`，边界只取决于 `n` 和 `k`，与翻转本身无关。
- `n` 到 `10^5`：线性扫两遍即可，每个节点只能翻一次。

**推导链。**
1. 暴力：读进数组分组翻转再写回，违反「改指针」，额外空间 `O(n)`。
2. 浪费：LC 25 是「边走边数 `k` 个」，每个变体都要重写边界逻辑，从尾分组更是做不到。
3. 洞察：量出 `n`，算出组大小序列（`n // k` 个 `k`，加上余数组，余数组放前还是放后由「是否从尾分组」决定）；每组只做两件事：翻转，或整组跳过。
4. 最优：两个开关 `from_tail`、`reverse_partial` 覆盖全部变体，`O(n)` 时间、`O(1)` 空间。

**同模式的题**：LC 25 K 个一组翻转链表、LC 2074 反转偶数长度组的节点、LC 24 两两交换链表中的节点、LC 92 反转链表 II。
