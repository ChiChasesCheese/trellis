## Q
**LC 480 滑动窗口中位数**｜Hard · CodeTop 国内累计 2 次 · 最近 2026-03-26（国内 CodeTop）

数组 `nums` 上有一个长度为 `k` 的窗口从最左端滑到最右端，每次右移一位。返回每个窗口的**中位数**组成的数组：窗口排序后，`k` 为奇数取最中间的数，`k` 为偶数取中间两个数的平均值。`1 <= k <= nums.length <= 10^5`，`nums[i]` 是 32 位有符号整数；与真实值误差在 `10^-5` 以内即算正确。例：`nums = [1,3,-1,-3,5,3,6,7], k = 3` → `[1,-1,-1,3,5,6]`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「中位数 + 集合不断变化」→ **对顶堆**：大顶堆存较小一半、小顶堆存较大一半，中位数只看两个堆顶。
- 「滑动窗口」→ 每步不仅插入，还要**删除一个任意元素**；`heapq` 只能删堆顶 → 延迟删除（lazy deletion）。
- `n`、`k` 都到 `10^5` → 每个窗口排序 `O(nk log k)` 不行；每步 `O(k)` 的有序列表最坏约 `10^10` 次元素搬移，偏险；目标每步 `O(log n)`。

**推导链。**
1. 暴力：每个窗口复制、排序、取中间，`O(nk log k)`。
2. 浪费：相邻窗口只差一进一出，却每次整体重排。
3. 改进：维护有序窗口，`bisect` 找位置、插入删除各 `O(k)`，总 `O(nk)`。
4. 洞察：中位数只依赖两个堆顶；过期元素只要不在堆顶就无害。记下「欠删」次数，平衡时按**有效**个数计，元素浮到堆顶时再真正弹出。
5. 最优：对顶堆 + `Counter` 延迟删除，`O(n log n)` 时间、`O(n)` 空间。
