## Q
**LC 1352 最后 K 个数的乘积**｜正确性

为什么遇到 `0` 就可以把前缀积列表清空？查询里判断 `k >= len(prefix)` 为什么恰好表示“最后 `k` 个数里含 `0`”？不清空会出什么错？

## A
**不变量。** `prefix[i]` 是最近一个 `0` 之后（不含该 `0`）前 `i` 个数的乘积，`prefix[0] = 1`；`len(prefix) - 1` 就是最近一个 `0` 之后的数字个数 `m`。

**为什么可以清空。** 任何覆盖了该 `0` 的区间，乘积必为 `0`，答案与 `0` 之前的数无关；不覆盖它的区间，起点一定在 `0` 之后，只用到清空后新建的前缀。`0` 之前的前缀因此永远不会再被用到。

**`k >= len(prefix)` 为什么对。** 流的末尾有 `m` 个非零数，最近的 `0` 紧挨在它们之前。最后 `k` 个数里：`k <= m` 时全是非零数，`prefix[-1] // prefix[-1 - k]` 正好是这 `k` 个数的乘积；`k > m`（即 `k >= m + 1 = len(prefix)`）时，区间向左延伸到了那个 `0`，乘积为 `0`。

**反例：不清空。** 把 `0` 也乘进前缀：加入 `3, 0, 2, 5, 4` 得到前缀 `[1, 3, 0, 0, 0, 0]`。
- `getProduct(2)` 想算 `5 * 4`：`prefix[-1] // prefix[-3] = 0 // 0`，抛 `ZeroDivisionError`。
- 即使改成“除数为 `0` 就返回 `0`”，`getProduct(2)` 也会错成 `0`，正确是 `20`，因为这两个数并不跨过 `0`。

清空之后的前缀是 `[1, 2, 10, 40]`，`getProduct(2) = 40 // 2 = 20`，`getProduct(3) = 40 // 1 = 40`，`getProduct(4)` 满足 `4 >= len(prefix) = 4`，返回 `0`。
