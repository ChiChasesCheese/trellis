## Q
**LC 3086 拾起 K 个 1 需要的最少行动次数**｜追问

面试官接着问：（1）除了步数，还要输出 Alice 应该站在哪里？（2）同一个数组要回答很多个 `(k, maxChanges)` 查询怎么办？（3）如果「造 1」的规则改了，代价不再是 `2` 步，现有分支还成立吗？

## A
1. **站立位置。** 第一支（造 `1` 够用）里，站在最长连续 `1` 的中间那一格（长度 `>= 3` 时），否则站在那段 `1` 里；第二支里，记下取到最小值的窗口起点 `l`，站在 `pos[l + need // 2]`。只要把 `min(map(cost, …))` 换成 `min(range(…), key=cost)`，得到的 `l` 就能还原位置。
2. **多查询。** `pos` 和 `pre` 与 `(k, maxChanges)` 无关，只建一次；每个查询重算 `c` 的分支判断和窗口，窗口个数是 `m - need + 1`，`need` 越大越少。
3. **规则变了。** `0, 1, 1, 2` 这几档和「前三个相邻」的结论是针对「造 + 换 = 2 步」推出来的，代价一变就失效。稳妥做法是退回逐位置、取最便宜 `k` 个的写法（枚举站立位置，把各个 `1` 的距离和各次造 `1` 的新代价放在一起取最小的 `k` 个），把常数 `2` 换成新代价即可，只是时间变成平方级。

**Python 提醒**：`len(list(g))` 会把 `groupby` 的分组迭代器耗尽；同一个组不能再迭代第二次。而且 `groupby` 的分组必须在取下一个分组之前消费完，所以不要把 `g` 存进列表稍后再读。
