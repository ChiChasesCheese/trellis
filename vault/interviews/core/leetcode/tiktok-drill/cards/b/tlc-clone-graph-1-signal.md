## Q
**LC 133 克隆图**｜Medium · LC 字节 热度 50/100 · CodeTop 国内累计 2 次 · 最近 2021-08-08（CodeTop）

给无向连通图中一个节点的引用，返回整张图的深拷贝。节点有 `val` 和 `neighbors`（邻居节点列表）。节点数 `[0, 100]`，`1 <= Node.val <= 100` 且互不相同，无重复边、无自环。例：邻接表 `[[2,4],[1,3],[2,4],[1,3]]` 克隆后结构不变。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「**深拷贝**一个图」+ 节点之间互相引用 → 要**遍历**整张图（DFS / BFS），每个节点处理一次；最直觉的是递归 DFS：克隆自己，再克隆每个邻居。
- 无向图 = 每条边都是环（`A` 的邻居有 `B`，`B` 的邻居又有 `A`）→ 必须有 **visited 记录**，否则死循环。
- 新节点之间还要接上边 → 光有 visited 不够，要能从原节点**找到它的拷贝**：**哈希表 原节点 → 拷贝**，一表两用。
- 节点数只有 `100`：怎么写都过，考的是正确性和对环的处理，而不是性能。

**推导链。**
1. 朴素递归：克隆当前节点，再对每个邻居递归克隆。遇到环无限递归。
2. 加 `visited` 集合：不再死循环，但跳过已访问节点后，拿不到它的拷贝，没法给当前拷贝连边。
3. 洞察：visited 本来就想记「这个节点处理过」，不如记「它对应的拷贝是谁」，字典 `copies[node] = clone`。
4. 最优：`copies` 里有就直接复用拷贝，没有就先建拷贝并登记、再递归邻居；每个节点建一次，每条边处理一次，`O(V + E)`。递归深度等于最长路径，节点上千的链状图改用 BFS（见追问）。
