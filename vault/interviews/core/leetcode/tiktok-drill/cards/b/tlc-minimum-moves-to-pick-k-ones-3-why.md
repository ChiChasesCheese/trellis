## Q
**LC 3086 拾起 K 个 1 需要的最少行动次数**｜正确性

为什么拾起代价可以按「脚下 `0`、紧邻 `1`、造 `1` 是 `2`、距离 `d` 是 `d`」逐个独立相加？为什么 `maxChanges` 不够时，要选的 `need` 个已有 `1` 一定是位置数组上连续的一段，并且站在中位数？

## A
**不变量。** Alice 站在 `i`，各个 `1` 按距离由近到远依次拾起，近的先被拿走，不会挡住远的；于是每个已有 `1` 的代价恰好是距离 `|j - i|`，互不影响。造 `1` 加一次交换固定 `2` 步，且要求紧邻位置是 `0`；若紧邻位置已经是 `1`，直接拿更便宜。所以代价序列是 `0, 1, 1, 2, 2, 3, …`（已有的）与若干个 `2`（造的）的并集，取最便宜的 `k` 个。

**为什么连续。** 选了 `pos[a]` 和 `pos[c]` 而漏掉 `a < b < c` 的 `pos[b]`，把其中离站立点更远的那个换成 `pos[b]`，距离不会更大，所以最优选择可以取连续一段。**为什么中位数。** 窗口内各点到 `x` 的距离和是关于 `x` 的凸函数，在中位数处最小。

**反例（错误写法一）：`c` 取三格内 `1` 的个数。** `nums = [1,0,1], k = 2, maxChanges = 1`：把 `c` 算成 `2`，得到 `max(2 - 1, 0) = 1` 步；真实答案是 `2`（紧邻的位置是 `0`，要么造 `1` 加交换，要么从距离 `2` 处挪）。

**反例（错误写法二）：永远走窗口，忽略造 `1`。** `nums = [1,1,0,0,0,1,1,0,0,1], k = 3, maxChanges = 1`：窗口最小值是 `4`，正确答案是 `3`。
