## Q
**LC 1539 第 k 个缺失的正整数**｜正确性

为什么答案是 `lo + k`？为什么缺失个数要写 `arr[mid] - (mid + 1)`，比较要用 `>= k`？各给一个写错就出错的输入，写出错误输出和正确输出。

## A
**不变量。** `miss(i) = arr[i] - (i + 1)`：`1..arr[i]` 中共有 `arr[i]` 个正整数，其中 `i + 1` 个在数组里（严格升序，所以 `arr[0..i]` 恰好是其中 `i + 1` 个），其余都缺失。`miss` 随 `i` 单调不减。设 `lo` 是第一个 `miss(lo) >= k` 的下标，那么 `miss(lo - 1) < k`，第 `k` 个缺失数在 `arr[lo - 1]` 之后、`arr[lo]` 之前（或在末尾之后）。这一段里没有数组元素，所以它是 `arr[lo - 1] + (k - miss(lo - 1))`，把 `miss(lo - 1) = arr[lo - 1] - lo` 代入得 `k + lo`。

**反例 1：漏掉 `+ 1`。** 写成 `arr[mid] - mid`，`arr = [1]`、`k = 1`：`miss(0)` 被算成 `1`，认为 `arr[0]` 之前已缺 `1` 个，`lo = 0`，返回 `1`；`1` 其实在数组里，正确是 `2`。

**反例 2：`>` 代替 `>=`。** `arr = [2]`、`k = 1`：`miss(0) = 1`，刚好等于 `k`，说明第 `1` 个缺失数在 `arr[0] = 2` 之前，答案是 `1`。用 `> k` 会认为不够，`lo = 1`，返回 `2`，错了。

边界上 `lo = 0` 表示缺失数全在第一个元素之前，答案就是 `k`；`lo = n` 表示整个数组都不够，答案是 `k + n`，公式都成立。
