## Q
**LC 1860 增长的内存泄露**｜正确性

为什么循环条件只看 `max(memory1, memory2) >= second` 就够了？为什么平局时的比较必须是 `>=`？给出平局写错的输出，并说明模拟为什么不会超时。

## A
**不变量。** 每次进入循环时，`second` 是将要分配的位数，`memory1`、`memory2` 是此刻两个内存条的剩余量。规则要求把 `second` 位分给剩余较多的内存条；只要较多的那个放得下（`max >= second`），分配就成立；较多的那个都放不下，较少的更放不下，所以“两个都不足”等价于“较大的不足”。

**为什么平局要 `>=`。** 题目规定相等时分配给第一个。`memory1 >= memory2` 在相等时为真，走第一个分支，恰好是第一个内存条。写成 `memory1 > memory2`，相等时会走 `else` 分支，扣第二个内存条。

**反例：平局写成严格大于。** `memory1 = 2, memory2 = 2`：
- 第 `1` 秒：相等，应当扣第一个，变成 `(1, 2)`；错误写法扣第二个，变成 `(2, 1)`。
- 第 `2` 秒：正确写法下第二个更大（`2`），扣它 `2` 位，变成 `(1, 0)`；错误写法下第一个更大（`2`），扣它 `2` 位，变成 `(0, 1)`。
- 第 `3` 秒：两条都不足 `3` 位，退出。
正确结果是 `[3, 1, 0]`，错误写法得到 `[3, 0, 1]`。

**为什么不会超时。** 第 `t` 秒结束时已消耗 `t(t+1)/2` 位，这不会超过 `memory1 + memory2 <= 2^32 - 2`，所以 `t(t+1)/2 <= 2^32`，`t <= 92681` 左右。最大输入 `(2^31 - 1, 2^31 - 1)` 的崩溃时刻就是 `92681`，循环不到十万次。
