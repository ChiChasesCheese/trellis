## Q
**LC 767 重构字符串**｜正确性

为什么每步必须取“剩余次数最多”的字符，而且刚用过的字符要暂存一轮？给出这两处各自被换掉后会出错的输入，写出错误输出和正确输出。

## A
**不变量。** 每轮开始时，堆里不含上一轮放下的字符，所以堆顶一定与结果的最后一个字符不同；同时堆顶是“除上一个字符外剩余最多”的字符，这样最难安置的字符总是尽早放下，不会被拖到最后只剩它自己。

**反例 1：不暂存。** 取出后立刻放回堆，`"aab"`：第一轮取 `a`，放回后剩 `1` 个，仍是堆顶（次数并列时 `a` 排在 `b` 前），第二轮又取 `a`，得到 `"aab"`，相邻重复。正确结果是 `"aba"`。

**反例 2：不按次数，只取字母序最小且不同于上一个的字符。** `"aabbb"`：依次取 `a, b, a, b`，只剩一个 `b`，而上一个正好是 `b`，函数返回 `""`，宣布无解。正确结果是 `"babab"`（`b` 出现 `3` 次，等于 `(5 + 1) // 2`，可行）。

按次数取的理由：位置有限，次数最多的字符占用的“互不相邻位置”最多，必须最先安排；留到最后，剩下的位置里就放不下它。可行性判据同源：最多的字符数 `m <= (n + 1) // 2` 时按此贪心永远不会陷入“只剩上一个字符”的局面，`m` 超过时必然失败。
