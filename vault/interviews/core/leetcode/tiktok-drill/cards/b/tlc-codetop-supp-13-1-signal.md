## Q
**补充题 13 中文数字转阿拉伯数字**｜Medium · CodeTop 国内累计 4 次 · 最近 2026-02-27（国内 CodeTop）

给一个表示非负整数的中文数字字符串 `s`，把它转成对应的整数。`s` 只含 `零一二两三四五六七八九十百千万亿` 这些字符，规范书写、保证合法（`十二` 表示 `12`，开头的 `一十` 可省成 `十`；`两` 在百、千、万、亿前等同于 `二`；各单位按规范顺序出现）。`1 <= len(s) <= 30`，结果满足 `0 <= 结果 <= 10^12`。例：`"一亿两千三百万零五"` → `123000005`；`"十二"` → `12`；`"两千零二"` → `2002`；`"零"` → `0`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「数字 + 单位」的累加结构 → 一次**线性扫描**加几个累加器；不需要栈或递归。
- 单位分两层：`十百千` 在块内，`万亿` 在块间，`亿` 管的范围比 `万` 大 → 累加器也分层：`num`（个位数）、`section`（块内）、`total`（已结算的块）。
- 「规范书写」的细节：`十` 前可省略 `一`、`零` 只是占位、`两` 等同 `二` → 用 `num or 1` 补一，`零` 映射成 `0`。
- 长度只有 `30` → 线性扫描绰绰有余，重点是处理好层级。

**推导链。**
1. 暴力：按 `亿`、`万` 把字符串递归切开，各段按 `千百十` 解析再相加。
2. 浪费：切分和解析是两遍，其实一遍扫描能同时做。
3. 洞察：`万` 只结算上一次 `万` / `亿` 之后的这一块（`section`），`亿` 乘的是前面攒下的全部（`total`）。
4. 最优：一次扫描，`O(n)` 时间、`O(1)` 空间。

**同模式的题**：LC 8 字符串转换整数 (atoi)、LC 273 整数转换英文表示、LC 12 整数转罗马数字、LC 13 罗马数字转整数。
