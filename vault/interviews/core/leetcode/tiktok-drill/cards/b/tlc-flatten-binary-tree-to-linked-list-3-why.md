## Q
**LC 114 二叉树展开为链表**｜正确性

为什么「把右子树接到左子树的最右下节点后面」能保持先序顺序？漏掉「接右子树」这一步会出什么错？给出具体输出。

## A
**不变量。** `dfs(node)` 返回后，`node` 的子树已经是一条只有 `right` 的链，顺序是原来的先序，`node` 在链头，返回值是链的最后一个节点。整棵树的先序是「`node`、左子树的先序、右子树的先序」，两棵子树的先序各自已经是链，只要把右链接在左链的尾后面，再把左链挂到 `node.right`，整棵树的先序没有变，`node.left` 变空。

**为什么要返回尾节点。** 接右链需要知道左链的最后一个节点。靠递归返回，每个节点只做 `O(1)` 的指针操作；不返回就得沿 `right` 重新走一遍左链，链状树上会退化成 `O(n^2)`。尾节点的取值：有右子树时是右链的尾，没有右子树但有左子树时是左链的尾，两边都没有时是 `node` 自己。

**反例一：不先接右子树，直接搬左子树。**
```text
node.right = node.left     # 没有 left_tail.right = node.right
node.left = None
```
- 输入 `[1,2,5,3,4,null,6]`：节点 `2` 把 `right` 改成 `3`，原来的右孩子 `4` 丢了；根 `1` 把 `right` 改成 `2`，原来的右子树 `5`（带着 `6`）丢了。
- 输出 `[1,null,2,null,3]`，只剩 `3` 个节点。
- 正确输出是 `[1,null,2,null,3,null,4,null,5,null,6]`，共 `6` 个节点。

**反例二：始终返回 `node` 当尾。** 节点 `2` 拼好后链是 `2 -> 3 -> 4`，却返回了 `2`；根 `1` 于是把 `5` 接在 `2` 后面，`3`、`4` 被覆盖，输出 `[1,null,2,null,5,null,6]`，只剩 `4` 个节点。

另一个常见错误：忘记 `node.left = None`。展开后每个节点还挂着左指针，评测检查「`left` 始终为 `null`」时失败，遍历时还会重复走到旧子树。
