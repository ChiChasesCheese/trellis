## Q
**LC 114 二叉树展开为链表**｜正确性

为什么「把右子树接到左子树的最右下节点后面」能保持先序顺序？漏掉「接右子树」这一步会出什么错？给出具体输出。

## A
**不变量。** 每一步拼接都**不改变整棵树的先序序列**，并且让当前节点的左指针变空。处理完所有节点后，所有左指针都是空，树只剩一条 `right` 链，它的先序序列就是链本身，也就是原来的先序。

**为什么不改变先序。** `cur` 的先序是「`cur`、左子树、右子树」。`pred` 是左孩子沿右链走到头的节点：它没有右孩子，所以先序走完 `pred` 和它自己的左子树之后，整棵左子树就结束了，下一个就是原右子树。把原右子树挂到 `pred.right` 恰好把它放在这个位置（`pred` 的左子树之后），先序不变。再把左子树整体搬到 `cur.right`、`cur.left` 置空，`cur` 后面第一个仍是左子树的根。`pred` 不一定是左子树先序的最后一个节点（它可能还有左子树），所以不要把它理解成「先序最后一个」，而是「右子树应当接的位置」。

**反例：不先接右子树，直接搬左子树。**
```text
cur.right = cur.left     # 直接覆盖，原右子树再也没有引用
cur.left = None
```
- 输入 `[1,2,5,3,4,null,6]`：根 `1` 把 `right` 改成 `2`，原来的右子树 `5`（带着 `6`）丢了；`2` 再把 `right` 改成 `3`，`4` 也丢了。
- 输出 `[1,null,2,null,3]`，只剩 `3` 个节点。
- 正确输出是 `[1,null,2,null,3,null,4,null,5,null,6]`，共 `6` 个节点。

顺序要点：先把原右子树接到 `pred.right`，再覆盖 `cur.right`。

另一个常见错误：忘记 `cur.left = None`。展开后每个节点还挂着左指针，评测检查「`left` 始终为 `null`」时失败，遍历时还会重复走到旧子树。
