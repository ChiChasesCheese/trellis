## Q
**LC 164 最大间距**｜正确性

为什么只比较「相邻非空桶的边界」就够了？桶宽为什么取 `(hi - lo) // (n - 1)`，取得更大会出什么问题？

## A
**不变量。** 排序后有 `n - 1` 个相邻间隔，总和是 `hi - lo`，所以最大间隔 `G >= ceil((hi - lo) / (n - 1)) >= d`（`d` 是整除得到的桶宽）。同一个桶内的两个数最多相差 `d - 1 < G`，因此桶内的相邻差不可能是最大间隔。最大间隔因此一定出现在两个不同的桶之间，而且是某个桶的最大值与它后面第一个非空桶的最小值之间——这正是扫描时 `mn - prev_max` 计算的量。空桶不贡献元素，所以 `prev_max` 保持为最近一个非空桶的最大值。

**反例（错误写法一）：只比较编号相邻的两个桶。** `[1,2,100,101]`：`n = 4`，桶宽 `33`，数字落在桶 `0` 和桶 `3`，中间两个桶是空的；只看 `i - 1` 与 `i` 号桶会得到 `0`，正确是 `98`。

**反例（错误写法二）：桶宽没有保底 `1`。** `[1,1,1,2]`：`(2 - 1) // 3 = 0`，计算桶编号时除以 `0`，抛 `ZeroDivisionError`；正确答案是 `1`。

**反例（错误写法三）：桶宽取成两倍。** 桶内的差可以达到 `2d - 1`，不再保证小于最大间隔。`[21, 29]`：`n = 2`，正确桶宽 `8`，两数分属两个桶；翻倍成 `16` 后大于数值跨度 `8`，两数落进同一个桶，没有任何桶间比较，返回 `0`，正确是 `8`。
