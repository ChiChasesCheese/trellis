## Q
**LC 169 多数元素**｜正确性

为什么摩尔投票最后留下的一定是多数元素？如果题目不保证多数元素存在，会得到什么？给出具体输入和输出。

## A
**不变量。** 扫描到任意位置时，已经处理过的前缀可以拆成两部分：若干对"互不相同的两个数"，以及 `count` 个等于 `candidate` 的剩余元素（`count = 0` 时没有剩余）。

**为什么留下的是多数元素。** 设多数元素 `m` 出现 `c` 次，`2c > n`。删掉一对互不相同的数，最多带走一个 `m`：`c` 至多减 `1`，长度减 `2`，不等式 `2c > n` 依然成立；如果这一对里没有 `m`，`c` 不变、长度减 `2`，更强。删完所有的对之后，剩下的元素里 `m` 仍然严格过半。剩下的只有 `count` 个 `candidate`，而 `m` 在其中过半，所以 `m == candidate`。

**为什么 `count == 0` 才换人。** `count > 0` 表示手里还有未被抵消的候选人票；遇到不同的数，抵掉一票就是一对；`count == 0` 表示前缀已经被完全配成对，当前元素是新一轮的开始，它可以成为新的候选人。

**反例：没有多数元素时。**
- `[1,2,3]`：`1` 成为候选，被 `2` 抵消；`3` 成为新候选，最后返回 `3`。但每个数只出现一次，没有多数元素。
- `[1,1,2,2]`：`1` 的票被两个 `2` 抵消，最后候选人是 `1`，计数为 `0`；每个数恰好出现 `n/2` 次，仍没有多数元素。
- 所以投票阶段只负责"如果存在，就是它"；没有存在性保证时必须再扫一遍验证 `nums.count(candidate) > len(nums) // 2`。
