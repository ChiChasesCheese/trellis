## Q
**LC 154 寻找旋转排序数组中的最小值 II**｜Hard · TikTok 高频

升序数组经过 `1` 到 `n` 次旋转（每次把最后一个元素移到最前面）得到 `nums`，数组中可能有重复元素。找出并返回最小元素，步骤要尽可能少。`1 <= n <= 5000`，`-5000 <= nums[i] <= 5000`。进阶：允许重复对时间复杂度有什么影响？例：`[2,2,2,0,1]` → `0`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「旋转有序数组找最小值」→ 二分查找，目标是「断点」：最小值就是旋转点。
- 「旋转了若干次」→ 数组分成两段各自有序，右段所有元素不大于左段，比较对象选右端点 `nums[hi]`。
- 「可能有重复元素」→ `nums[mid] == nums[hi]` 时无法判断断点在哪一侧，二分在这一步失效。
- 「尽可能减少操作步骤」「允许重复会影响复杂度吗」→ 答案是最坏情形退化为 `O(n)`，并且要能说出为什么下界就是 `Ω(n)`。
- `n <= 5000`：线性扫描也不会超时，考点在于二分的细节。

**推导链。**
1. 暴力：`min(nums)`，`O(n)`。
2. 无重复：比较 `nums[mid]` 与 `nums[hi]`，大则 `lo = mid + 1`，否则 `hi = mid`，`O(log n)`。
3. 障碍：有重复时，`nums[mid] == nums[hi]` 两侧都可能有最小值：`[3,3,1,3]` 在右侧，`[1,3,3]` 在左侧。
4. 洞察：此时 `nums[hi]` 有一个值相同的「替身」`nums[mid]`，丢掉 `hi` 不会丢最小值，`hi -= 1`。
5. 最优：三路比较，大于折半向右、小于折半向左、相等收缩一格；平均 `O(log n)`，最坏（全部相同）`O(n)`。
