## Q
**LC 301 删除无效的括号**｜正确性

为什么扫描得到的 `left_rem`、`right_rem` 恰好是最少删除量？为什么结果必须用集合？没有删除额度限制时会错在哪？

## A
**不变量。** 扫描时 `left_rem` 表示「当前还没配对的 `(` 个数」，`right_rem` 表示「已经确定配不上的 `)` 个数」。

**为什么是最少。** 遇到 `)` 而 `left_rem == 0`：它前面没有任何可用的 `(`，无论删别的什么都救不了，这个 `)` 必须删，计入 `right_rem`。扫描结束后剩下的 `left_rem` 个 `(` 后面没有 `)` 可配，必须删。这两类括号互不重叠，且删掉它们之后恰好有效，所以总数是下界，也是上界。

**为什么要集合。** 删哪一个括号不同，但删完得到的串可能相同。`"()())()"` 要删一个 `)`：删下标 `3` 和删下标 `4` 都得到 `"()()()"`。用列表会得到 `['(())()', '()()()', '()()()']`，正确是两个。

**没有额度限制的反例。** 只检查最终是否有效、不限制删除数：`"()())()"` 还会收集 `"()"` 之类删得更多的有效串，不满足「最少」。额度 `left == right == 0` 的终止条件保证只收集恰好删了最少数量的结果。

**中途剪 `balance < 0` 的依据。** 前缀里 `)` 比 `(` 多，后面再怎么留也补不回来，这条路必然无效，直接放弃。
