## Q
**LC 862 和至少为 K 的最短子数组**｜正确性

单调队列解法里，为什么可以放心把队首弹出、把队尾弹出而不丢掉最优解？直接用「扩右端、满足就缩左端」的双指针为什么不行？给出反例。

## A
**不变量。** 处理完下标 `j` 后，队列里是 `0..j` 中所有「还可能成为最优起点」的下标，且前缀和严格递增。

**队首弹出为什么安全。** 起点 `i` 与当前 `j` 配对成功后，对任何更大的 `j'`，`j' - i > j - i`，即使它仍满足条件也只会更长，不会改进答案。

**队尾弹出为什么安全。** 设 `i1 < i2` 且 `pre[i1] >= pre[i2]`。对任意后续 `j`：只要 `i1` 满足 `pre[j] - pre[i1] >= k`，那么 `pre[j] - pre[i2]` 更大，`i2` 也满足，而且 `j - i2 < j - i1`。所以 `i1` 永远不会比 `i2` 更好。

**为什么双指针不行（反例）。** `nums = [84,-37,32,40,95]`，`k = 167`。正确答案是 `3`（`32 + 40 + 95 = 167`）。标准双指针「右端累加，和 `>= k` 就缩左端」：
- 右端走到末尾时窗口是 `[84,-37,32,40,95]`，和 `214 >= 167`，记下长度 `5`；左端移走 `84` 后和变成 `130 < 167`，循环停止；
- 但再移走负数 `-37`，和会变回 `167 >= 167`，窗口 `[32,40,95]` 长度 `3` 才是答案；双指针只在「和仍然够大」时才缩左端，错过了这一步，输出 `5`。
原因是负数让「缩小窗口和只会变小」不再成立。

**另一个反例（漏掉队尾弹出）。** `nums = [-4,6]`，`k = 6`：队列里留着前缀和更大的 `0`，挡在更好的起点 `-4` 前面，`pre[2] - pre[0] = 2 < 6` 不触发，输出 `-1`；正确答案 `1`（子数组 `[6]`）。
