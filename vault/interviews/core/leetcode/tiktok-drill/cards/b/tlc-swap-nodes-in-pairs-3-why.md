## Q
**LC 24 两两交换链表中的节点**｜正确性

每轮交换之后，为什么 `prev` 要移到 `a` 而不是 `b`？循环条件为什么要同时判断 `prev.next` 和 `prev.next.next`？各给一个写错就出错的输入，写出错误输出和正确输出。

## A
**不变量。** 每轮开始时，`prev` 之前的部分已经全部交换完成并且连成正确的前缀，`prev` 是这个前缀的最后一个节点，`prev.next` 是尚未处理的部分的第一个节点。一轮交换把 `prev` 之后的两个节点颠倒，接着 `prev` 必须是新的“已处理部分的最后一个节点”。

**为什么是 `a`。** 交换之后顺序是 `prev → b → a → rest`，已处理部分的末尾是 `a`，`rest` 才是下一轮的起点。如果把 `prev` 移到 `b`，`prev.next` 就是 `a`，下一轮会把 `a` 当作新一对的第一个节点，已经交换过的节点被重复处理。`[1,2,3,4]`：第一轮后链表是 `2 → 1 → 3 → 4`，`prev` 移到 `b = 2`，第二轮交换 `1` 和 `3`，得到 `2 → 3 → 1 → 4`，之后 `prev` 又移到 `3`，再交换 `1` 与 `4`，最终 `[2, 3, 4, 1]`；正确是 `[2, 1, 4, 3]`。

**为什么要两个条件。** 一对需要两个节点都存在。节点数为奇数时最后会剩一个节点，此时 `prev.next` 存在而 `prev.next.next` 是 `None`；只判断前者的话，`b = None`，随后 `b.next` 抛 `AttributeError`。`[1]` 和 `[1,2,3]` 都会触发。空链表时 `prev.next` 本身就是 `None`，也被第一个条件挡住。

`and` 的短路保证了先判断 `prev.next` 为真，才去取 `prev.next.next`，顺序不能反。
