## Q
**LC 165 比较版本号**｜正确性

为什么必须逐段按整数比较，并且缺失的修订号要补 `0`？直接比较字符串，或者用 `zip` 代替 `zip_longest`，各会在什么输入上给出错误结果？

## A
**规则。** 版本号是修订号的有序序列，比较规则是字典序，但每一段的比较是**数值**比较，缺失的段等价于 `0`。所以 `"1.0"` 和 `"1.0.0.0"` 表示同一个版本，`"1.0.1"` 大于 `"1"`，因为后者等价于 `"1.0.0"`。

**不变量。** 循环到第 `k` 段时，前 `k - 1` 段都已经相等。此时只有第 `k` 段能决定结果：不等就立刻返回，相等就进入下一段。若所有段（含补出来的）都相等，两个版本相等。

**反例一：直接比较字符串。** `"1.2"` 与 `"1.10"`：逐字符比较到第三个字符，`'2'` 大于 `'1'`，字符串比较认为 `"1.2"` 更大，返回 `1`。数值上 `2 < 10`，正确答案是 `-1`。

**反例二：`zip` 不补齐。** `"1.0.1"` 与 `"1"`：`zip` 在较短的列表用完时停止，只比较了第一段 `1` 和 `1`，相等，返回 `0`。多出来的 `0` 和 `1` 被丢掉了；`"1"` 等价于 `"1.0.0"`，第三段 `1 > 0`，正确答案是 `1`。

**反例三：把修订号当字符串比较。** `"1.01"` 与 `"1.001"`：字符串 `"01"` 和 `"001"` 不相等，会判成不同的版本；转成整数后都是 `1`，正确答案是 `0`。
