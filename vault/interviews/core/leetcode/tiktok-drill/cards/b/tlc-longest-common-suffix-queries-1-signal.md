## Q
**LC 3093 最长公共后缀查询**｜Hard · TikTok 高频

给字符串数组 `wordsContainer` 和 `wordsQuery`。对每个查询词，在 `wordsContainer` 中找与它有最长公共后缀的字符串；多个并列时取长度最短的，仍并列取下标最小的。返回每个查询对应的下标数组。`1 <= wordsContainer.length, wordsQuery.length <= 10^4`，每个字符串长度在 `1` 到 `5 * 10^3` 之间，只含小写字母，两个数组各自的长度总和至多 `5 * 10^5`。例：`wordsContainer = ["abcd","bcd","xbcd"]`，`wordsQuery = ["cd","bcd","xyz"]` → `[1,1,1]`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「最长公共后缀」→ 反转后是最长公共前缀，用字典树（Trie）。
- 总长度 `5 * 10^5`、查询很多 → 预处理一次，每个查询只花自己的长度；任何依赖「容器大小 × 查询数」的做法都会超时。
- 「并列时最短、再最早」→ 平局规则要预先存在节点上，查询时不要再收集候选再比较。
- 没有公共后缀时答案不是 `-1`，而是按同样规则选出的全局最优：根节点也要存代表。

**推导链。**
1. 暴力：每个查询对每个容器词逐字符比后缀，`O(Q * C * L)`。
2. 换哈希表存下所有后缀：成本是各词长度的平方和，一个长 `5000` 的词就有 `1250` 万个字符，不可行。
3. 浪费：反转后，不同词的后缀共享大量前缀，逐个存是重复劳动。
4. 洞察：反转后的字典树，根到节点的路径就是一个后缀，共享只存一份；节点上预存「经过它的最短最早单词」。
5. 最优：按下标顺序插入，只在严格更短时替换代表，平局自然留下更早的；查询时沿反向字符走到走不动为止，取停下节点的代表。总 `O(Σ|容器| + Σ|查询|)`。
