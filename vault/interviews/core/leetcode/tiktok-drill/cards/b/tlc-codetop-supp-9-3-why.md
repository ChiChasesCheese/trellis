## Q
**补充题 9 36进制加法**｜正确性

为什么进位只会是 `0` 或 `1`？循环条件里为什么必须带 `carry`？字符映射写错会出什么结果？给出具体输入和输出。

## A
**不变量。** 每轮开始时，`out` 里已经是低位若干位的正确结果，`carry` 是这些位向更高位的进位，`i`、`j` 指向尚未处理的最高位。

**进位的范围。** 每位的 `total ≤ 35 + 35 + carry`。若 `carry ≤ 1`，则 `total ≤ 71`，`divmod(71, 36) = (1, 35)`，新进位仍 `≤ 1`。初始进位为 `0`，由归纳法，进位始终是 `0` 或 `1`。

**为什么循环要带 `carry`。** 两个数都处理完后，最高位相加可能还有进位，要再产生一位。

**反例 1：漏掉最后的进位。** 循环条件写成 `while i >= 0 or j >= 0`：
- `"zz" + "1"`：`z + 1 = 36`，本位 `0`、进位 `1`；下一位 `z + 1 = 36`，本位 `0`、进位 `1`；循环结束，进位丢了，输出 `"00"`。
- 正确是 `"100"`（`35 * 36 + 35 + 1 = 1296 = 36^2`）。
- `"z" + "z"` 输出 `"y"`，正确是 `"1y"`。

**反例 2：用十进制思维。** 把进位基数写成 `10`，或者数值映射只认数字：
- `"19" + "1"` 在 36 进制里：`9 + 1 = 10`，对应字符 `a`，结果 `"1a"`。
- 十进制思维会得到 `"20"`。

**反例 3：整体转成整数。** `int("z" * 10000, 36)` 在 Python 3.11 及以上抛 `ValueError: Exceeds the limit (4300 digits)`；即使调高上限，转换也是平方级，逐位加法才是线性。
