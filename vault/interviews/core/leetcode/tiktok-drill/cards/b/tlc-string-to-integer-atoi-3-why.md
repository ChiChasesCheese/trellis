## Q
**LC 8 字符串转换整数 (atoi)**｜正确性

为什么正负要分别设 `limit`？符号读成循环会错在哪里？为什么 `num >= limit` 就可以提前返回？给出具体输入和输出。

## A
**不变量。** 状态只前进：空格阶段 → 符号阶段 → 数字阶段，每个阶段最多经过一次；任何时刻 `num` 是已经读入的数字前缀的值，且 `num < limit`（否则已经返回）。

**为什么 `limit` 不对称。** 32 位有符号整数范围是 `[-2^31, 2^31 - 1]`，负数一侧比正数一侧多一个值。负数的绝对值最大为 `2^31`，正数最大为 `2^31 - 1`。

**为什么能提前返回。** 数字只会越读越多，`num` 单调不减；一旦 `num >= limit`，不论后面还有多少位，结果都至少是 `limit`，截断后就是 `sign * limit`。

**反例 1：两边都用 `INT_MAX`。** 把正负的上限都设成 `2^31 - 1`：
- 输入 `"-2147483648"`，输出 `-2147483647`。
- 正确是 `-2147483648`。

**反例 2：符号写成循环。** `while s[i] in "+-"`：
- 输入 `"+-12"`，循环吃掉 `+` 和 `-`，结果 `-12`。
- 正确是 `0`：读到符号之后下一个字符必须是数字，`-` 不是数字，读数阶段什么也没读到。

**读数阶段的停止条件。** `"0-1"` 读完 `0` 之后遇到 `-` 就停止，返回 `0`；读数阶段不再接受符号。

**空格只在开头跳过。** `"  +0 123"`：读到 `0` 后遇到空格停止，结果是 `0`，不是 `123`；空格只在最开头被跳过。
