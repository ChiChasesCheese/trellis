## Q
**LC 378 有序矩阵中第 K 小的元素**｜正确性

二分的是「值」而不是下标，为什么最后得到的 `lo` 一定是矩阵里真实存在的元素？为什么收缩条件是 `count_le(mid) >= k` 而不是 `> k`？

## A
**不变量。** 答案 `ans`（排序后第 `k` 小）始终在 `[lo, hi]` 内。

**单调性。** 记 `f(v)` = 矩阵中 `<= v` 的元素个数。`f` 对 `v` 单调不减。第 `k` 小的值 `ans` 满足：`f(ans) >= k`，且对任何 `v < ans` 有 `f(v) < k`。也就是说 `ans` 是「最小的使 `f(v) >= k` 的整数」。

**为什么 `lo` 在矩阵里。** `f(v)` 只在 `v` 恰好等于某个矩阵元素时才增加。最小的使 `f(v) >= k` 的 `v`，如果不在矩阵里，那么 `v − 1` 的个数和 `v` 一样，`f(v − 1) >= k` 也成立，与「最小」矛盾。所以它必须是矩阵里的元素。

**为什么是 `>= k`。** `count_le(mid) >= k` 说明 `mid` 本身可能就是答案（有重复值时，`mid` 的个数可能一下子跨过 `k`），所以保留 `mid`：`hi = mid`。写成 `> k` 会漏掉恰好 `f(mid) == k` 的情形。

**反例：去重后的第 `k` 个。** `[[1,5,9],[10,11,13],[12,13,15]], k = 8`：
- 去重后元素是 `1,5,9,10,11,12,13,15`，第 `8` 个是 `15`，错误。
- 保留重复值，排序后是 `1,5,9,10,11,12,13,13,15`，第 `8` 个是 `13`，正确。`count_le(13) = 8 >= 8`，`count_le(12) = 6 < 8`，所以 `lo` 停在 `13`。
