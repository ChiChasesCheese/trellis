## Q
**由扁平记录构建嵌套评论树**｜Medium · TikTok 高频

给扁平的评论记录列表，每条记录 `{"id": int, "parent_id": int | None, "text": str, "time": int}`，根评论的 `parent_id` 为 `None`。构建嵌套结构：每条评论带一个 `children` 列表，返回所有根评论。记录无序（孩子可能在父亲之前）；同一父亲下的孩子按 `(time, id)` 升序；父亲不存在的孤儿当根；有环时抛 `ValueError`；不修改输入。记录数不超过 `10^5`，`id` 互不相同。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「扁平记录 + `parent_id`」→ 只记父亲的邻接表，转成树要用哈希表 `id -> 节点`。
- 「记录无序」→ 不能边读边挂，要两遍：先建全部节点，再连边。
- 「孤儿」→ `nodes.get(parent_id)` 为 `None` 就当根；「环」→ 从根出发遍历，访问数少于总数。
- `n = 10^5`：每个节点扫全表是 `10^10`，必须 `O(1)` 找父亲；深度可能到 `10^5`，不能递归。
- 「孩子的顺序」→ 先整体排序一次，之后 `append` 的顺序就是最终顺序。

**推导链。**
1. 暴力：对每个节点扫描整张表找孩子，`O(n^2)`。
2. 简化版：假设父亲先出现、一遍线性挂接，乱序输入时有父亲的评论被当成根。
3. 浪费：重复的线性查找，加上一个不成立的顺序假设。
4. 洞察：字典让「找父亲」`O(1)`；两遍扫描消除顺序依赖；孤儿与环是图的两种异常，用 `get` 和可达计数分别处理。
5. 最优：排序 `O(n log n)`，建树和检测 `O(n)`，用迭代栈遍历，深度不受限制。
