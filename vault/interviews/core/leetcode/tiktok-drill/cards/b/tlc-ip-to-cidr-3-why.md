## Q
**LC 751 IP 到 CIDR**｜正确性

为什么每个块的大小是 `min(x & -x, 不超过 n 的最大 2 的幂)`？为什么不能只看数量、忽略起点对齐？为什么贪心取最大块就是最少块？

## A
**不变量。** 每次循环开始时，`[x, x + n - 1]` 是还没覆盖的部分，已输出的块恰好覆盖 `[ip, x - 1]` 且互不重叠。

**两个上限。**
- 块是 `2^j` 个地址，合法要求 `x` 是 `2^j` 的倍数，`x & -x` 正是 `x` 的最大 2 的幂因子，所以 `size <= x & -x`。
- 块不能越过 `x + n - 1`，所以 `size <= n`，且是 2 的幂，最大取 `1 << (n.bit_length() - 1)`。

**贪心为什么最优。** 第一个块必须从 `x` 开始。在合法的前提下取最大的块，剩余区间更短，而且它的起点 `x + size` 的对齐能力不比任何更小的选择差（`x + size` 是 `size` 的倍数）。更小的第一块只会把更多地址留给后面。

**反例：忽略对齐。** `ip = "255.0.0.7"`，`n = 10`：
- 只取 `size = 8`，输出 `255.0.0.7/29`，但 `/29` 块覆盖 `255.0.0.0` 到 `255.0.0.7`，起点没对齐，包含了范围之外的 `255.0.0.0` 到 `255.0.0.6`。
- 正确做法：`x & -x = 1`，第一块只能是 `/32`；`x` 变成 `8` 后 `x & -x = 8`，才可以放 `/29`。

**反例：`x = 0` 不特判。** `ip = "0.0.0.0"`，`x & -x = 0`，`size = 0`，`x`、`n` 都不变，死循环。
