## Q
**补充题 1 排序奇升偶降链表**｜正确性

为什么偶数位必须先反转再合并，而且用头插法恰好完成反转？拆完以后为什么还要把 `odd_tail.next` 置空？给出漏掉任一步的错误输出。

## A
**不变量。** 扫描完成后，奇链按原顺序排列，所以升序；偶链是每个偶数位结点依次插到最前面得到的，顺序恰好与原顺序相反，原来降序，现在升序。合并两条升序链表，结果就是全局升序。

**为什么要反转。** 合并两个有序链表的前提是两条都按同一个方向有序。偶数位是降序，直接拿来合并，等于拿一个降序序列去和升序序列比大小，比较结果没有意义。

**反例 1：不反转，直接合并。** 输入 `1 -> 8 -> 3 -> 6 -> 5 -> 4 -> 7 -> 2`：奇链 `1,3,5,7`，偶链（原顺序）`8,6,4,2`。每次比较两个链头，奇链的 `1,3,5,7` 都比偶链头 `8` 小，全部先出；然后只剩偶链 `8,6,4,2`。输出 `1, 3, 5, 7, 8, 6, 4, 2`，不是有序的；正确输出 `1, 2, 3, 4, 5, 6, 7, 8`。

**为什么要 `odd_tail.next = None`。** 奇链的最后一个结点在原链表里后面可能还跟着偶数位结点，它的 `next` 仍指向那个结点，而那个结点已经挂在偶链里了。合并时，指针沿着这条旧边又走回偶链，形成环。

**反例 2：不切断。** 输入 `1 -> 8 -> 3 -> 6`，奇链 `1, 3`，偶链（反转后）`6, 8`；结点 `3` 的 `next` 仍指着原链表里的结点 `6`，而 `6` 同时挂在偶链里。合并时同一个结点从两条链各被处理一次，把链表接成了环：从头遍历得到 `1, 3, 6, 8, 8, 8, ...` 永不结束；切断 `3.next` 后得到 `1, 3, 6, 8`，正确。

奇偶按**位置**区分，与 `val` 的奇偶无关；用 `pos % 2` 而不是 `node.val % 2`。
