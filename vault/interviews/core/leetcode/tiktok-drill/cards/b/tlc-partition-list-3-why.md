## Q
**LC 86 分隔链表**｜正确性

双链划分的解法里，为什么必须在拼接前执行 `big.next = None`？给出一个不断开就出错的输入，并说明解法保持的不变量。

## A
**不变量。** 循环中的每一步，小链和大链都是各自已处理节点的稳定子序列；两条链的尾指针 `small`、`big` 分别指向各链最后一个节点；原链尚未处理的部分是从 `node` 开始的后缀。

**为什么要断开。** 节点是原地复用的，每个节点的 `next` 还是原链里的旧值。大链最后一个节点 `big` 在原链里后面可能还跟着小节点，它的 `next` 仍指向那个节点。拼接后，小链尾会接上大链头，如果 `big.next` 不置空，遍历会从大链尾巴跳回小链，形成环。小链尾巴不需要断，因为紧接着 `small.next = big_dummy.next` 会覆盖它。

**反例。** `head = [3, 1]`，`x = 3`：`3` 进大链，`1` 进小链。`3.next` 仍然是 `1`。不断开时：`small.next = big_dummy.next` 得 `1 → 3`，而 `3 → 1`，结果是环 `1 → 3 → 1 → …`，遍历永不停止。断开后得到 `[1, 3]`。

**另一个细节。** 条件必须是 `node.val < x` 进小链（严格小于）；`== x` 的节点属于大链。
