## Q
**LC 45 跳跃游戏 II**｜正确性

贪心解法里，`cur_end` 和 `farthest` 各自保证了什么？为什么循环只扫到 `n - 2`？给出一个把范围写错就会多算一跳的输入。

## A
**不变量。** 处理完下标 `i` 之后：`farthest` 是 `0..i` 中所有格子能到的最远位置；`cur_end` 是用 `jumps` 跳能到的最远位置，且 `0..cur_end` 里的每个格子都能用不超过 `jumps` 跳到达（可达格子的最少跳数沿下标不降，所以是一段连续区间）。

**为什么成立。** 当 `i == cur_end` 时，`0..cur_end` 全部扫过，`farthest` 恰好是「多跳一次」能到的最远点，也就是下一层的右边界。保证可达，所以每次换层 `farthest > cur_end`，最终必然覆盖 `n - 1`。

**为什么只扫到 `n - 2`。** 一旦 `cur_end >= n - 1`，终点已经在当前层里，不需要再跳。如果扫到 `n - 1`，且此时 `i == cur_end`，就会再计一跳。

**反例。** `nums = [2,3,1,1,4]`，正确答案 `2`。
- 把循环写成 `range(len(nums))`：`i = 0` 时换层，`cur_end = 2`、已计 `1` 跳；`i = 2` 时再换层，`cur_end = 4`、已计 `2` 跳；扫到 `i = 4 == cur_end` 又触发一次，答案错成 `3`。
- 范围写对后，`i` 走到 `3` 就结束，答案 `2`。

另一个常见错误是「跳到 `nums[j]` 最大的格子」：`[2,1,1,0]` 中两个候选的值并列都是 `1`，取靠前的会走 `0→1→2→3` 得 `3`，而按 `j + nums[j]` 比较能走 `0→2→3` 得 `2`。
