## Q
**LCP 13 寻宝**｜正确性

为什么可以把「搬石头」压缩成机关之间的一条边 `hop[i][j]`，并且各段之间互不影响？「每次去最近的下一个机关」的贪心错在哪？给出反例。

## A
**不变量。** `dp[mask][j]` 是「已触发集合恰为 `mask`，人站在机关 `j` 上，且手里没有石头」的最少步数。

**为什么可以压缩。** 一次完整的触发动作是：从当前位置走到某个石堆（拿起一块），再走到目标机关（放下）。这两段都是迷宫里的最短路，中间没有其他有用事件：搬石头不占步数，石堆无限，放下一块石头既不会改变其他机关的状态，也不会影响迷宫的通行（石头不挡路）。因此从机关 `i`（或起点）出发触发机关 `j` 的最优代价，只取决于选哪个石堆，等于 `min(石堆) 距离(i, 石堆) + 距离(石堆, j)`，与此前触发了哪些机关无关，可以独立预计算。全程的总步数就是各段代价之和，再加最后一个机关到宝藏的距离。

**为什么触发顺序要用 DP 而不是贪心。** 总代价 = `first[顺序[0]] + Σ hop[顺序[t]][顺序[t+1]] + end[顺序[-1]]`，其中 `end` 与「最后一个机关」绑定，所以不能只看前面的局部最短。

**反例：贪心选最近的下一个机关。** 迷宫 `["TSO","MOM"]`（`T` 在左上，`S` 在上中，上右是 `O`，下排依次 `M`、`O`、`M`）：
- 起点到左下机关与到右下机关的代价都是 `2`，贪心先选左下（下标靠前）；之后到右下机关 `2`，最后从右下机关走到 `T` 要 `3`，总计 `2 + 2 + 3 = 7`；
- 最优：先触发右下机关（`2`），再触发左下机关（`2`），最后左下机关紧挨 `T`，只需 `1`，总计 `5`。

**反例：忘了往返取石头。** 示例 `["S#O","M..","M.T"]` 里若把机关间距离直接当成步行距离，路径是 `S→M→M→T`，只要 `1 + 1 + 2 = 4` 步；而每个机关都要去石堆 `O` 取石头，实际是 `4 + 3 + 3 + 4 + 2 = 16` 步。
