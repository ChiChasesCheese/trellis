## Q
**LC 44 通配符匹配**｜正确性

DP 里 `*` 的转移为什么是「`new[j - 1]` 或 `dp[j]`」？第 0 行的初始化为什么必须单独写？漏掉初始化会给出什么错误输出？

## A
**不变量。** 处理完第 `i` 行后，`dp[j]` 恰好等于「`s[:i]` 能否被 `p[:j]` 完整匹配」。

**`*` 的转移。** 把 `*` 的所有可能匹配长度分成两类，互斥且完备：
- 匹配**空串**：`s[:i]` 要被 `p[:j - 1]` 匹配，即 `new[j - 1]`；
- 至少匹配一个字符：最后一个字符 `s[i - 1]` 被这个 `*` 吞掉，`*` 依然可以继续吞，所以只需要 `s[:i - 1]` 被 `p[:j]`（含这个 `*`）匹配，即上一行的 `dp[j]`。
两类的并集就是「`*` 匹配任意长度」，不需要枚举长度，所以转移是 `O(1)`。

**第 0 行为什么要单独写。** 「`s` 为空」不是边界情况而是真实状态：`p` 开头的连续 `*` 都能匹配空串，后面的每一行都从这一行转移而来。

**反例。** 漏掉初始化，只设 `dp[0] = True`、其余全 `False`：
- `s = "aa", p = "*"`：第 1 行里 `new[1] = new[0] or dp[1]`，`new[0]` 是 `False`，`dp[1]` 也是 `False`，结果 `False`；
- 正确答案是 `True`（一个 `*` 吞下 `"aa"`）。
同理 `s = ""`、`p = "*"` 也会错成 `False`。
