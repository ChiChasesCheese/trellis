## Q
**LC 3043 最长公共前缀的长度**｜正确性

为什么必须把 `arr1` 的**所有前缀**存进集合，而不是只存原来的数？插入时“已经在集合里就提前停止”为什么不会漏？为什么检查 `y` 是否为零很重要？给出具体输入和错误输出。

## A
**不变量。** 集合 `prefixes` 始终是“一些数的全部前缀的并集”，即对集合里的任意元素 `p`，`p // 10`（若非零）也在集合里。因为每次插入的是一整条链 `x, x // 10, x // 100, …`；提前停止只在 `x` 已经在集合里时发生，那时它的整条链此前已被插入，剩下的部分不用再加。

**为什么要存所有前缀。** 公共前缀 `c` 不一定是 `arr1` 里某个原数，只要它是某个数的前缀。只存原数，等于只能识别“`y` 的某个前缀恰好等于 `arr1` 的某个数”。
- `arr1 = [123]`，`arr2 = [129]`：公共前缀是 `12`，正确答案 `2`；只存 `123`，`129 → 12 → 1 → 0` 都不命中，得到 `0`。
- `arr1 = [5655359]`，`arr2 = [56554]`：公共前缀 `5655`，正确 `4`；只存原数得到 `0`。

**为什么要检查 `y` 非零。** `y` 逐位除到 `0` 说明没有任何前缀命中，此时 `len(str(0)) = 1`，如果不判断，会把“没有公共前缀”误算成长度 `1`。`arr1 = [1,2,3]`，`arr2 = [4,4,4]`：每个 `4` 除一次变成 `0`，没有判断的版本返回 `1`，正确是 `0`。
