## Q
**LC 974 和可被 K 整除的子数组**｜正确性

为什么「两个前缀和的余数相同」等价于「它们之间的子数组和可被 `k` 整除」？哈希表为什么要预先放入 `{0: 1}`？负数余数会带来什么错误？

## A
**不变量。** 处理完前 `j` 个元素后，`seen[r]` 等于前缀 `pre[0..j]`（含空前缀 `pre[0] = 0`）中余数为 `r` 的个数。

**等价性。** 子数组 `nums[i..j-1]` 的和是 `pre[j] - pre[i]`。若 `pre[j] ≡ pre[i] (mod k)`，则差是 `k` 的倍数；反之差是 `k` 的倍数，两者对 `k` 同余。所以以第 `j` 个前缀为右端的合法子数组数，等于更早的前缀里与它余数相同的个数。

**为什么放 `{0: 1}`。** 空前缀 `pre[0] = 0`，余数 `0`，它对应“从下标 `0` 开始”的子数组。不放它，从开头开始、和恰好整除的子数组不会被计数。`nums = [4,5,0,-2,-3,1]`，`k = 5`：整个数组的和是 `5`，前缀余数序列（含空前缀）是 `0, 4, 4, 4, 2, 4, 0`。
- 加了 `{0: 1}`：答案 `7`。
- 不加：最后一个余数 `0` 找不到之前的 `0`，少数一个，得到 `6`。

**负数余数。** 余数相等要求落在同一个余数类里。按零截断的余数（C++ / Java 的 `%`）对负和给出负余数：`-1 % 5` 得 `-1`，而数学上与它同余的 `4` 被当成不同的类。把 Python 写成 `int(math.fmod(prefix + x, k))` 模拟这种行为，同一输入 `[4,5,0,-2,-3,1]`、`k = 5` 得到 `4`，正确是 `7`。Python 内置 `%` 在 `k > 0` 时总返回 `[0, k)`，所以直接用它；其他语言要补成 `((s % k) + k) % k`。
