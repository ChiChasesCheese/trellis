## Q
**LC 329 矩阵中的最长递增路径**｜正确性

为什么 `dfs(i, j) = 1 + max(严格更大邻居的 dfs)` 并且缓存起来就对？为什么这个算法不需要 `visited`？给出把严格改成非严格后的错误输出。

## A
**不变量。** `memo[i][j]` 一旦写入，就是从 `(i, j)` 出发的最长递增路径的格子数。归纳：没有更大邻居的格子是 `1`；有更大邻居的格子，路径的第二个格子一定是某个更大的邻居，而这个邻居的最优后缀长度已经是它自己的 `dfs`，所以取最大再加 `1` 就是最优。邻居的值严格更大，归纳可以按值从大到小进行。

**为什么不需要 `visited`。** 边只从小值指向严格更大的值，沿边走值严格增加，不可能回到出发点，图无环；`dfs` 的递归一定在有限步内结束，缓存只是为了不重复计算。

**反例一：非严格。** 把「更大」改成「大于等于」：
- `[[1,1]]`：`dfs(0,0)` 调 `dfs(0,1)`，`dfs(0,1)` 又调 `dfs(0,0)`，结果还没写进 `memo`，无限递归，抛 `RecursionError`；正确答案 `1`（一个格子本身就是长度 `1` 的路径）。
- `[[5,5],[5,5]]`：同样抛 `RecursionError`；正确是 `1`。
相等的值在严格递增的要求下不连边；一旦连了，图里出现环，记忆化递归就停不下来。

**反例二：把对角线也算邻居。** `[[3,4,5],[3,2,6],[2,2,1]]` 加上对角线后答案变成 `6`，正确是 `4`。

**反例三：不缓存。** 每次都重新递归，同一个格子被很多条路径重复展开：`6 x 6` 的行优先递增矩阵（值 `0..35`）要调用 `dfs` `3382` 次，只有 `36` 个不同的格子；`200 x 200` 的矩阵会指数级变慢。
