## Q
**LC 329 矩阵中的最长递增路径**｜正确性

为什么「剥了几层」就等于最长路径的格子数？为什么这个算法不需要 `visited`？给出把严格改成非严格后的错误输出。

## A
**不变量。** 第 `k` 层的格子，恰好是「最长递增路径起点为它时长度为 `k`」的格子：从它出发，最长路径有 `k` 个格子。第 `1` 层是没有更大邻居的格子（路径只能停在自己，长度 `1`）；一个格子被放进第 `k + 1` 层，当且仅当它所有更大的邻居都在前 `k` 层，且至少有一个在第 `k` 层，所以它的最长路径是 `1 + max(更大邻居的最长路径)`，也就是 `k + 1`。

**为什么答案是层数。** 整个矩阵剥完后，最后一层的编号就是所有格子里最大的「最长路径长度」，它就是答案。

**为什么不需要 `visited`。** 边只从小值指向严格更大的值，沿边走值严格增加，不可能回到出发点，图无环；每个格子的出度减到 `0` 时恰好进入一次下一层，天然不会重复处理。

**反例：非严格。** 把「更大」改成「大于等于」（统计出度和减出度时都用 `>=` / `<=`）：
- `[[1,1]]`：两个格子互相是对方的「不小于」邻居，出度都是 `1`，没有出度为 `0` 的格子，第一层为空，返回 `0`；正确答案 `1`（一个格子本身就是长度 `1` 的路径）。
- `[[5,5],[5,5]]`：同样所有格子出度都不为 `0`，返回 `0`；正确是 `1`。
相等的值在严格递增的要求下不连边；一旦连了，图里出现环，拓扑排序永远剥不到这些格子。
