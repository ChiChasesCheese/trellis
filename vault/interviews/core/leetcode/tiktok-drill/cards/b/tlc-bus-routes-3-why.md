## Q
**LC 815 公交路线**｜正确性

为什么 BFS 的层数就是乘坐的车辆数？为什么线路只展开一次不会漏掉更短的方案？给出把“站数”当“车数”以及漏掉 `source == target` 的错误输出。

## A
**不变量。** 处理完第 `k` 层之后，`seen_stops` 恰好是“乘不超过 `k` 辆车能到达的所有车站”（包含起点）。第 `k` 层展开的每条线路，都是第一次被乘到，所以到它上面的车站需要的车数恰好是 `k`。

**为什么线路只展开一次。** 一条线路第一次被展开时，对应的层数是到达它所需的最小车数 `k`（BFS 保证层数递增）。它上面的所有车站在这一层都被加入了 `seen_stops`，得到的车数是 `k`，不可能更少。之后无论哪个站再碰到这条线路，展开它只会给出 `>= k` 的车数，不会产生更优的结果，可以安全跳过。

**为什么层数是车数。** 同一条线路上任意两站之间，乘一辆车就能到；换线路必须在换乘站下车再上另一辆车，这时才多一辆。BFS 每进入一层，对应“多上一辆车”。

**反例 1：站数当车数。** 如果只在线路上的相邻站之间连边、按边数计数：`routes = [[1,2,3,4,5]]`，`source = 1`，`target = 5`，需要走 `4` 条边，返回 `4`；正确答案是 `1`（乘同一辆车坐到底）。

**反例 2：漏掉 `source == target`。** `routes = [[1,2]]`，`source = 1`，`target = 1`：不用乘车，答案是 `0`。没有提前返回的实现会展开线路 `[1,2]`，在其中看到 `nxt == target`（就是起点自己），返回 `1`，错。

**不标记线路的代价。** 两条线路各含同样的 `5000` 个车站，从其中一站出发找一个不可达的目标：标记线路时内层循环共执行 `10000` 次；不标记时，每个已到达的车站都把两条线路各扫一遍，共 `50000000` 次。答案相同（`-1`），但后者在 `10^5` 规模下会超时。
