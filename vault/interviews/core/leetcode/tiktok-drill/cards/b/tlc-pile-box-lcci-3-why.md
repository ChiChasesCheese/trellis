## Q
**面试题 08.13 堆箱子**｜正确性

为什么先按宽度排序就能把「排列」问题变成「子序列」问题？既然排过序，内层循环能不能只比较深度和高度、省掉宽度的比较？给出出错的输入。

## A
**为什么排序后是子序列。** 一个合法箱堆从上到下宽度**严格**递增。按宽度升序排序后，堆里位置靠上的箱子宽度更小，一定排在靠下的箱子前面（宽度不同，排序顺序唯一）。所以任何合法箱堆都对应排序数组的一个子序列，DP 只需从前往后看。

**不变量。** 计算 `dp[i]` 时，所有能放在 `boxes[i]` 上面的箱子 `j` 都满足 `j < i`，`dp[j]` 已经是「以 `j` 为底」的最优值；`dp[i] = h_i + max(dp[j])` 枚举了紧挨在 `i` 上面的所有可能，取最好的那个。上面整个箱堆只通过「紧挨着的那个箱子」与 `i` 发生约束（严格支配是传递的：`j` 能放在 `i` 上，`j` 上面的箱子也一定比 `i` 小），所以最优子结构成立。

**只比较深度和高度的错误。** 排序只保证宽度**不减**，不保证严格递增：宽度相等的箱子也会排在前面，而它们不能叠放。
- `[[1,1,1],[1,2,2]]`：两个箱子宽度都是 `1`。省掉宽度比较后，`[1,1,1]` 被当成能放在 `[1,2,2]` 上面，得到 `1 + 2 = 3`；正确是 `2`（只能放一个，取高的）。

**修法。** 三个维度都显式比较 `wj < w and dj < d and hj < h`。另一种做法是按 `(宽度升序, 深度降序)` 排序：同宽的箱子里，排在前面的深度不小于后面的，`dj < d` 必然不成立，于是宽度比较可以省掉；但这依赖排序细节，改动排序键就会悄悄出错，直接比较三维最稳。
