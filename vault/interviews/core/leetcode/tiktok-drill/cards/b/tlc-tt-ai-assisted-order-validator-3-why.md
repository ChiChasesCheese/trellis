## Q
**OrderValidator（规则 DAG）**｜正确性

删除规则时，为什么要把前驱连到后继？这样连会不会产生环？`deps` 和 `users` 两个字典靠什么保持一致？给出漏掉重连或漏更新反向边时的具体输入。

## A
**为什么要重连。** 约束「`p` 必须先于 `s`」在删除前是通过 `p -> x -> s` 传递保证的。直接删掉 `x`，这条路径断了，`p` 与 `s` 之间不再有任何约束。重连 `p -> s` 后，所有「剩余规则两两之间谁先谁后」的可达关系与删除前完全相同。

**为什么不会成环。** 图原本无环，`p` 可达 `x`、`x` 可达 `s`，所以 `p` 可达 `s`；若新增的边 `p -> s` 成环，就需要 `s` 可达 `p`，那么原图里 `p -> x -> s -> ... -> p` 已经是环，矛盾。

**一致性不变量。** 对任意规则 `u`、`v`：`u in deps[v]` 当且仅当 `v in users[u]`。`add_rule` 一次写入 `deps[name]` 与每个依赖的 `users`；`remove_rule` 对称地清理邻居，并在新增边时同时写两边。

**反例一：不重连。** `a`、`b`（依赖 `a`）、`c`（依赖 `b`），删除 `b`：
- 不重连：`deps` 为 `{'a': set(), 'c': set()}`，`c` 不再依赖 `a`，任何合法的拓扑顺序都允许 `c` 排在 `a` 前面。
- 重连：`deps` 为 `{'a': set(), 'c': {'a'}}`，`a` 一定先于 `c`。

**反例二：只更新 `deps`，漏了 `users`。** 同样的三条规则，先删 `b`（重连时没写 `users['a']`），再删 `a`：
- `users['a']` 为空，找不到后继 `c`，`c` 的依赖里仍残留已不存在的 `a`。
- 之后 `validate` 排序得到 `a`，取 `self._rules['a']` 时抛 `KeyError: 'a'`。
