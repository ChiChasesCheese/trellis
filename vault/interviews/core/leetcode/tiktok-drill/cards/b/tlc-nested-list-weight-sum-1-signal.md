## Q
**LC 339 嵌套列表加权和**｜Medium · 近一年被问：美国 1 次、国内 0 次 · 最近 2026-02-27（面试记录）

给嵌套整数列表 `nestedList`，每个元素是整数或子列表，整数的深度是它所在的嵌套层数（最外层为 `1`）。通过接口 `isInteger()`、`getInteger()`、`getList()` 访问元素，返回所有整数「值 × 深度」之和。`1 <= nestedList.length <= 50`，整数值在 `[-100, 100]`，最大深度 `<= 50`。例：`[1,[4,[6]]]` → `27`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「嵌套结构」+「深度」→ 把列表当内部节点、整数当叶子的树，**深度就是层号**：层序遍历（BFS）或带 `depth` 参数的 DFS。
- 元素通过**接口**访问 → 必须先 `isInteger()` 分流，不能当 Python 原生列表直接迭代。
- 深度上限 `50` → 递归不会爆栈，但 BFS 也一样简单，并且能顺手推广到「反向加权」。

**推导链。**
1. 暴力：先把整个结构摊平、同时记下每个整数的深度，再求和，需要额外存一遍。
2. 浪费：深度只用来乘一次，不需要保存。
3. 关键：DFS 里 `dfs(list, depth)` 对整数直接累加 `值 × depth`，遇到子列表带着 `depth + 1` 递归。
4. 迭代等价写法：`level` 装着当前深度的全部元素，整数当场加权，子列表的内容并进 `nxt`，处理完一层 `depth += 1`。每个元素只被访问一次，`O(N)`。
