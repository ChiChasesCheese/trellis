## Q
**LC 739 每日温度**｜正确性

为什么弹栈的条件必须是严格的 `<`？为什么弹出的下标 `j` 的答案就是当前下标 `i - j`，不会漏掉更近的更高温度？给出写成 `<=` 的错误输出。

## A
**不变量。** 处理完下标 `i` 之后，栈里的下标按从底到顶递增，对应温度非严格递减（不增），并且栈里恰好是「到 `i` 为止还没遇到更高温度」的所有下标。

**为什么 `i - j` 就是答案。** 下标 `j` 是在某个 `i` 处被弹出的，说明 `temperatures[j] < temperatures[i]`。如果在 `j+1..i-1` 之间还有更高的温度 `k`，那么 `k` 到来时也会把 `j` 弹出（`j` 还在栈里就说明没被更早的任何温度解决，而弹栈是从栈顶往下，`j` 低于 `k` 的温度时一定会被弹）。所以 `j` 一定是被它右边第一个更高的温度弹出的。

**为什么要 `<`。** 题目要的是严格更高。写成 `<=`，相等的温度也会把栈顶弹掉，答案变成「下一个不低于它的」。

**反例 `[70,70,80]`。** 正确答案 `[2, 1, 0]`：第 0 天要等到第 2 天的 `80`，第 1 天等 `1` 天。
- 写成 `<=`：第 1 天的 `70` 到来时，栈顶（第 0 天的 `70`）满足 `70 <= 70` 被弹出，`answer[0] = 1 - 0 = 1`；第 2 天的 `80` 弹出第 1 天，`answer[1] = 1`；结果 `[1, 1, 0]`，错。
- 写成 `<`：第 1 天的 `70` 不弹栈，两个 `70` 都留在栈里，直到 `80` 到来一起弹出，`answer[0] = 2`、`answer[1] = 1`，结果 `[2, 1, 0]`，对。

注意这时栈里温度只是不增（两个 `70` 相邻），不影响正确性，因为弹栈只比较栈顶与新来的温度。
