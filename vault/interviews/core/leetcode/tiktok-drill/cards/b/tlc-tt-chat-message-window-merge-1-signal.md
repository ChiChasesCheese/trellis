## Q
**聊天消息窗口合并（get_chat_messages）**｜Medium · TikTok 高频

`get_chat_messages(chat_message_id)` 返回以该消息为中心、上下各 `5` 条（含自己，最多 `11` 条）、按顺序排列的消息。对多个 ID 各调用一次得到多个窗口，窗口可能重叠、相邻、不相交，同一个窗口也可能重复出现。写函数把这些窗口合并成一个按消息顺序排列、不重复的列表。消息是 `{"id": int, "text": str}`，`id` 严格递增，窗口内按 `id` 升序；窗口数不超过 `10^4`，消息总数不超过 `1.1 * 10^5`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「多段各自有序、合并成一个有序序列」→ `k` 路归并（`heapq.merge`，同 LC 23 / LC 88 的思路）。
- 「重叠、重复，同一个 ID 是同一条消息」→ 按唯一键 `id` 去重；归并之后重复项必然相邻。
- 「边界处不足 5 条、同一个 ID 重复调用」→ 窗口长度不固定、可能有完全相同的窗口，不能假设每段 `11` 条。
- 「顺序依据是消息 ID」→ 窗口之间没有先后之分，只能按 `id` 排。

**推导链。**
1. 暴力：全部放进 `dict[id -> 消息]` 去重，再按 `id` 排序，`O(N log N)`，正确且简单。
2. 浪费：输入本来就是 `k` 段有序序列，全部重排丢掉了这个信息。
3. 洞察一：`heapq.merge(*windows, key=itemgetter("id"))` 每次只比较各窗口的队头，`O(N log k)`，惰性产出。
4. 洞察二：归并输出按 `id` 有序，所以同一条消息的副本相邻，`groupby` 取每组第一条即可去重。
5. 最优：两个标准库调用组合，没有额外的集合，也不依赖窗口出现的顺序。
