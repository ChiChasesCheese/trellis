## Q
**LC 298 二叉树最长连续序列**｜正确性

为什么子节点不满足「值 = 父值 + 1」时要把长度重置为 `1`，而不是 `0`？为什么不用单独枚举起点？「差的绝对值为 `1`」的写法错在哪？

## A
**不变量。** 对每个被访问的节点 `v`，传入的 `length` 等于「以 `v` 结尾、向上追溯的最长连续递增链」的节点数。

**为什么重置为 `1`。** 不满足条件时，`v` 不能接在父节点后面，但 `v` 自己是一条长度为 `1` 的路径，也是一个新的合法起点。这样「可以从任意节点开始」被自动包含，不用单独枚举起点。重置为 `0` 会少算一个节点：链 `5 → 7 → 8` 中 `7` 被记成 `0`、`8` 记成 `1`，答案 `1`，而 `7 → 8` 的长度是 `2`。

**为什么不会漏。** 最长连续路径的最后一个节点 `u` 也会被访问，它的 `length` 正好等于这条路径的长度；取全局最大值就得到答案。

**反例：用绝对值。** 判断写成 `abs(child.val - node.val) == 1`。输入 `[2,null,3,2,null,1]`（`2` 的右孩子是 `3`，`3` 的左孩子是 `2`，该 `2` 的左孩子是 `1`）：
- 沿 `2 → 3 → 2 → 1` 每步差的绝对值都是 `1`，长度算成 `4`。
- 题目只要依次**递增** `1`：`2 → 3` 是递增，`3 → 2 → 1` 是递减，不能算。正确答案是 `2`。

**反例：忘记重置。** 子节点不满足条件时仍写 `length + 1`，则任何一棵节点数为 `n` 的链（如 `[1,3,5,7]` 靠右排列）会得到 `n`，而正确答案是 `1`。
