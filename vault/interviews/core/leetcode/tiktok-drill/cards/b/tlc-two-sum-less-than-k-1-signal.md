## Q
**LC 1099 小于 K 的两数之和**｜Easy · CodeTop 国内累计 2 次 · 最近 2026-05-14（国内 CodeTop）

整数数组 `nums`（长度 `1..100`，元素 `1..1000`）和整数 `k`（`1..2000`）。求满足 `nums[i] + nums[j] < k`（`i < j`）的最大和，不存在返回 `-1`。例：`[34,23,1,24,75,33,54,8]`，`k = 60` → `58`；`[10,20,30]`，`k = 15` → `-1`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「两个数的和」+「与阈值比较」→ 两数之和家族；因为是**不等式**（`< k`）不是相等，哈希表帮不上忙，要靠**排序 + 对撞双指针**（two pointers）。
- 「最大的、满足 `< k`」→ 在有序数组里逼近上界，和偏大就缩右端、偏小或合法就推进左端。
- `n <= 100` → `O(n^2)` 暴力只有约 `5000` 对，完全可行；优化是展示思路，不是必须。
- 返回的是和（不是下标）→ 排序不会破坏答案，可以放心 `sorted`。

**推导链。**
1. 暴力：枚举所有数对 `(i, j)`，取小于 `k` 的最大和，`O(n^2)`。
2. 浪费：数对的和关于下标有单调性，却在逐个比较。
3. 洞察：排序后，`nums[lo] + nums[hi] < k` 时，`lo` 与 `hi` 以内的任何右端搭配的和都不超过它，`lo` 已经没有价值，可以排除；`>= k` 时 `hi` 与任何左端搭配都不合法，排除 `hi`。
4. 最优：排序后双指针，一遍扫描，`O(n log n)`。

**同模式的题**：LC 167 两数之和 II、LC 15 三数之和、LC 16 最接近的三数之和、LC 259 较小的三数之和。
