## Q
**LC 74 搜索二维矩阵**｜正确性

为什么这个矩阵可以当作一维有序数组做二分？下标换算时用 `m` 还是 `n` 作除数，写错会怎样？只满足"每行每列各自有序"的矩阵为什么不行？

## A
**不变量。** 一维下标 `k` 对应 `matrix[k // n][k % n]`。设 `flat[k]` 是展开后的值：同一行内 `flat[k] <= flat[k + 1]`（行内非严格递增）；跨行时 `k` 是某行最后一个、`k + 1` 是下一行第一个，题目保证"下一行第一个大于上一行最后一个"，所以 `flat[k] < flat[k + 1]`。因此 `flat` 整体非严格递增，二分的前提成立。

**为什么除数是 `n`。** 每行有 `n` 个元素（列数），一维下标每过 `n` 步就换一行。

**反例 1：用 `m` 当除数。** `matrix = [[1,3,5,7],[10,11,16,20]]`（`m = 2`、`n = 4`）：
- 第一个 `mid = 4`：`row = 4 // 2 = 2`，超出 `m = 2` 行，抛 `IndexError: list index out of range`。
- 正确换算是 `row = 4 // 4 = 1`、`col = 4 % 4 = 0`，对应 `10`。

**反例 2：只满足"每行每列各自升序"的矩阵（LC 240）。** `matrix = [[1,4],[2,5]]`：
- 行内升序、列内升序，但第二行的首个数 `2` 并不大于第一行的末尾 `4`，展开后 `flat = [1,4,2,5]` 不再有序。
- 用上面的二分查 `target = 2`：结果是 `False`，而 `2` 明明在矩阵里（正确是 `True`）；查 `4` 同样得到 `False`。
- 这类矩阵要用阶梯搜索：从右上角出发，大了左移、小了下移，`O(m + n)`。

**边界检查。** `target` 比所有元素都大时 `lo == m * n`；此时 `lo // n` 等于 `m`，越界；必须先判断 `lo < m * n`，利用 `and` 的短路避免访问。
