## Q
**LC 1669 合并两个链表**｜正确性

为什么是「走 `a` 步到 `before`，再走 `b - a + 2` 步到 `after`」？这两个步数少算或多算一步，结果会错成什么样？

## A
**不变量。** 哑节点相当于下标 `-1`，所以从哑节点走 `a` 步正好落在下标 `a - 1`，它的下一个节点就是被删段的第一个（下标 `a`）。从 `before`（下标 `a - 1`）往后数到下标 `b + 1` 需要 `(b + 1) - (a - 1) = b - a + 2` 步。被删段 `a..b` 共 `b - a + 1` 个节点，它们被 `before.next = list2` 之后再也没有任何指针指向，实际上已被摘除。`list2` 的尾接上 `after`，链表保持连通且无环。

**反例（错误写法一）：第二段走 `b - a + 1` 步。** 示例 1（`[10,1,13,6,9,5]`，`a = 3, b = 4`）：停在下标 `b = 4`（值 `9`），接上之后得到 `[10,1,13,1000000,1000001,1000002,9,5]`；正确是 `[10,1,13,1000000,1000001,1000002,5]`。

**反例（错误写法二）：没有找 `list2` 的尾。** 直接写 `list2.next = after`，示例 1 得到 `[10,1,13,1000000,5]`，`list2` 的后两个节点被丢掉。

**反例（错误写法三）：第一段走 `a + 1` 步。** `before` 落在下标 `a`，被删段的第一个节点（`6`）留在链上，`after` 也整体后移一位，尾部的 `5` 丢失；示例 1 得到 `[10,1,13,6,1000000,1000001,1000002]`。
