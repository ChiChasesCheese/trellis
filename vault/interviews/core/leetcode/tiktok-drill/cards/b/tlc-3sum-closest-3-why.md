## Q
**LC 16 最接近的三数之和**｜正确性

为什么和偏小时排除 `lo`、和偏大时排除 `hi` 不会漏掉最接近的组合？为什么 `best` 的初值必须是真实的三数之和？

## A
**不变量。** 固定 `i` 后，所有还没被排除的候选对 `(a, b)` 都满足 `lo <= a < b <= hi`。若 `nums[i] + nums[lo] + nums[hi] = s < target`，对任何 `b' < hi`，有 `nums[i] + nums[lo] + nums[b'] <= s < target`，它们离 `target` 比 `s` 更远（或相等）；而 `s` 已经被记录。所以 `lo` 与任何更靠左的右端搭配都不可能更好，`lo` 可以排除。`s > target` 时对称地排除 `hi`。每步排除一个端点而不丢失候选，直到两指针相遇。

**初值。** `best` 是"迄今见过的最接近的真实和"。用不是任何三数之和的数（比如 `0`）当初值，它自己会参与比较，可能一直比真实和更近而被保留。

**反例（错误写法一）：比较时不取绝对值。** `[-1,2,1,-4], target = 1`：写成 `s - target < best - target` 会偏向更小的和，返回 `-4`，正确是 `2`。

**反例（错误写法二）：`best` 初值取 `0`。** `[1,1,1,0], target = -100`：所有真实的和都 `>= 2`，距离 `102`，而 `0` 的距离是 `100`，更近，于是错误地返回 `0`；正确答案是 `2`。
