## Q
**LC 115 不同的子序列**｜另一种解法

不压缩空间，直接写二维 DP 表怎么写？它有什么好处，什么时候选二维、什么时候选一维？

## A
**思路。** `f[i][j]` 是 `s[:i]` 中等于 `t[:j]` 的下标选法数。第 `0` 列恒为 `1`（空串，什么都不选）；第 `0` 行除 `f[0][0]` 外恒为 `0`（空的 `s` 凑不出非空的 `t`）。每个格子：不用 `s[i - 1]`（继承上一行同列），再加上「用它配 `t[j - 1]`」（字符相等时加上左上角）。

```python
def num_distinct_2d(s: str, t: str) -> int:
    m, n = len(s), len(t)
    f = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(m + 1):
        f[i][0] = 1                        # 空串是任何前缀的子序列，恰好 1 种
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            f[i][j] = f[i - 1][j]          # 不用 s[i-1]
            if s[i - 1] == t[j - 1]:
                f[i][j] += f[i - 1][j - 1] # 用 s[i-1] 去配 t[j-1]
    return f[m][n]
```

运行：`("rabbbit", "rabbit")` → `3`，`("babgbag", "bag")` → `5`，`("a", "aa")` → `0`，`("aaa", "a")` → `3`；与一维版在 `("ab" * 500, "ab" * 250)` 上结果相同。

**为什么对。** 与一维版是同一个递推，只是把每一行都保留了下来；一维版的「`j` 倒序」在这里不需要，因为读取的 `f[i-1][*]` 和写入的 `f[i][*]` 是两行，互不覆盖。

**取舍。** 二维版：思路直接、没有倒序的陷阱，能回溯出具体方案、方便打印表格调试；空间 `O(mn)`，`1000 × 1000` 约一百万个整数，仍可接受。一维版：空间 `O(n)`，面试里先写二维讲清楚状态和转移，再说「第 `i` 行只依赖上一行，可以压缩成一维，注意倒序」，这是一个标准的加分点。自顶向下的 `@cache` 写法最直观，但递归深度可达 `2000`，会超过 Python 默认递归上限，除非改成迭代。
