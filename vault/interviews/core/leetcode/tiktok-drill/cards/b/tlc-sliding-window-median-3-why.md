## Q
**LC 480 滑动窗口中位数**｜正确性

对顶堆 + 延迟删除这个解法要守住哪几条不变量？为什么每步结束时**两个**堆顶都必须清理？给出只清理一个堆会出错的输入。

## A
**不变量（每步结束时）。**
1. `small` 里每个有效元素 `<=` `large` 里每个有效元素。
2. 有效元素个数：`small` 等于 `large` 或多 1 个；所以 `k` 为奇数时中位数是 `small` 堆顶，偶数时是两堆顶的平均。
3. 两个堆顶都是有效元素（不在 `delayed` 里欠删）。

**为什么能维持。** 第 3 条保证 `-small[0]` 是 `small` 有效元素的最大值，于是 `out <= -small[0]` 准确判断 `out` 属于哪个堆（相等时属于 `small`，同值元素可互换）；`new` 按同样的比较入堆，维持第 1 条。一出一进让「`small` 有效数 − `large` 有效数」变化 `-2、0、+2`，挪一个有效堆顶即可恢复第 2 条。最后清理堆顶，恢复第 3 条。

**反例：只清理 `small`。** `nums = [2,1,3], k = 2`。
- 初始 `small = {1}`，`large = {2}`，中位数 `1.5`。
- 滑出 `2`（属于 `large`）、滑入 `3`（进 `large`），`balance = 0`。
- `large` 堆顶仍是过期的 `2`，不清理就算出 `(1 + 2) / 2 = 1.5`；正确窗口 `[1, 3]` 的中位数是 `2.0`。

判断归属若写成 `out < -small[0]`，`[1,3], k=1` 中滑出的 `1` 恰为 `small` 堆顶，被误判到 `large`，清理后 `small` 变空，取堆顶 `IndexError`。
