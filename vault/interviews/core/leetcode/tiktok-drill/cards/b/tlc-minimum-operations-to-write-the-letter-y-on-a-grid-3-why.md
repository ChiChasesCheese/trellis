## Q
**LC 3071 在矩阵上写出字母 Y 所需的最少操作次数**｜正确性

为什么操作数等于 `n * n - in_y[a] - out_y[b]`，并且必须限定 `a != b`？为什么 `Y` 的判定要把竖线限制在中心以下？各给一个写错就出错的输入，写出错误输出和正确输出。

## A
**不变量。** 目标状态由 `(a, b)` 完全确定：`Y` 内全是 `a`，`Y` 外全是 `b`。从当前矩阵到目标状态，每个不等于目标的格子恰好需要改一次，等于目标的格子不用动。所以操作数是 `n * n` 减去“已经等于目标”的格数，`Y` 内等于 `a` 的有 `in_y[a]` 个，`Y` 外等于 `b` 的有 `out_y[b]` 个，两部分互不重叠。

**为什么 `a != b`。** 题目要求 `Y` 的值与非 `Y` 的值不同。允许 `a == b`，相当于允许整个矩阵一个颜色。
- 全 `1` 的 `3 × 3`：`Y` 有 `4` 个格子，`Y` 外 `5` 个。允许 `a == b = 1` 得到 `0`；正确是 `4`（把 `Y` 外或 `Y` 内改成别的值，取 `Y` 的 `4` 个格子改成 `0`，用 `4` 次操作）。
- 示例 2：允许 `a == b` 得到 `11`，正确是 `12`。

**为什么竖线只从中心往下。** 中心上方的那一列格子不属于 `Y`。如果把整条中线都算作 `Y`（判定写成 `c == mid`，不限制行），示例 2 的 `Y` 多了中心上方的两个格子，统计变了，得到 `10`，正确是 `12`。

下半部分只有竖线，不再有对角线：行 `r > mid` 时只看 `c == mid`；上半部分与中心行用两条对角线，`r = mid` 时两条线汇合到中心。
