## Q
**LC 64 最小路径和**｜正确性

为什么第一行、第一列要单独初始化，而不能直接套 `min(上, 左)`？边界上的格子各只有一个来源，初始化错了会错成什么样？为什么贪心不行？

## A
**不变量。** `dp[i][j]` 恒等于从 `(0, 0)` 走到 `(i, j)` 的最小路径和。到 `(i, j)` 的最后一步只能来自上方 `(i-1, j)` 或左方 `(i, j-1)`，最优路径的前一段也必须是到那一格的最优路径（否则换成更优的一段，总和更小），所以 `dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])`。填表按行从上到下、每行从左到右，用到的上方、左方此刻都已算好。

**边界。** 第一行的格子没有上方，只能从左来：`dp[0][j] = dp[0][j-1] + grid[0][j]`；第一列没有左方，只能从上来：`dp[i][0] = dp[i-1][0] + grid[i][0]`。

**反例（错误写法一）：边界没有初始化。** 只设了 `dp[0][0]`，第一行、第一列留着 `0`：`grid = [[1,3,1],[1,5,1],[4,2,1]]` 里 `dp[1][1] = 5 + min(0, 0) = 5`，最后得到 `2`；单列 `[[1],[2],[3]]` 干脆返回 `0`。正确答案是 `7` 和 `6`。

**反例（错误写法二）：用一圈 `0` 做哨兵。** 表外加一行一列 `0`，统一用 `min(上, 左)`：第一行的格子会从哨兵的 `0` 里取最小，路径等于可以凭空从边外进来。`grid = [[1,3,1],[1,5,1],[4,2,1]]` 得到 `3`，正确答案是 `7`。哨兵要用 `inf`，只有起点上方那一个是 `0`。

**反例（错误写法三）：贪心地每步选较小的邻格。** `grid = [[1,3,1],[1,5,1],[4,2,1]]`：先走下（`1 < 3`），再走下（`4 < 5`），总和 `9`；正确答案是 `7`（先右、右、再下、下）。局部最小不等于全局最小。
