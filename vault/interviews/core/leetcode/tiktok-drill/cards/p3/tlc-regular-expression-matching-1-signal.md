## Q
**LC 10 正则表达式匹配**｜Hard · LC TikTok 热度 53/100 · 近一年被问：美国 3 次、国内 0 次 · CodeTop 国内累计 19 次 · 最近 2026-09-04（面试记录）

给字符串 `s` 和模式 `p`，实现支持 `'.'`（匹配任意单个字符）和 `'*'`（匹配零个或多个前面的那一个元素）的匹配，匹配要覆盖整个 `s`。`1 <= s.length <= 20`，`1 <= p.length <= 20`，`s` 只含小写字母，`p` 含小写字母、`'.'`、`'*'`，每个 `'*'` 前面都有有效字符。例：`s = "aa", p = "a*"` → `true`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「两个字符串逐步对齐，要求完整匹配」→ 状态是两个下标 `(i, j)`：**二维 DP / 记忆化搜索**（和编辑距离、最长公共子序列同类）。
- 「`'*'` 匹配零个或多个」→ 每遇到 `x*` 是一个**选择**，不能贪心（吃多了会错过后面的匹配），必须保留回头的可能。
- `m, n <= 20` → 指数级回溯在恶意输入下会超时，但 `O(mn) = 400` 个状态的 DP 没有压力；小数据范围提示「可以递归 + 缓存」。
- 「匹配整个字符串」→ 终点条件是 `j` 走完 `p` 时 `i` 恰好走完 `s`。

**推导链。**
1. 暴力回溯：遇到 `x*` 枚举匹配 `0..k` 次，最坏指数级（`a*a*a*...b` 对 `aaaa...a`）。
2. 浪费：不同的「每个星号吃几个」组合会到达同一个 `(i, j)`，后面的子问题一模一样。
3. 洞察：把「吃几个」拆成两条边——零次 `(i, j+2)`；吃一个后仍停在 `x*` 上 `(i+1, j)`。每个状态只有两条出边。
4. 最优：给 `match(i, j)` 加缓存，`O(mn)` 时间；也可以改成自底向上的表。

**同模式的题**：LC 44 通配符匹配、LC 72 编辑距离、LC 1143 最长公共子序列、LC 97 交错字符串、LC 115 不同的子序列。
