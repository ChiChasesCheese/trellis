## Q
**LC 297 二叉树的序列化与反序列化**｜追问

面试官接着问：（1）输出能压缩吗，比如树很稀疏时？（2）如果是**二叉搜索树**，还需要空位标记吗？（3）树大到不能一次放进内存，怎么办？（4）树是 `10^4` 深的链，递归爆栈怎么办？

## A
1. **压缩**：前序的 `#` 占了近一半标记，树稀疏时可改成只存「非空节点的位置编号 + 值」；值域小时用变长编码存整数，用位图记录「是否有左孩子 / 右孩子」。层序版本（见「另一种解法」）的尾部有一串多余的 `null`，序列化最后去掉即可，反序列化里 `next(tokens, "null")` 已经把缺失的标记当作空位。
2. **BST（LC 449）**：不需要空位标记。只存前序序列，还原时用值域区间 `(lo, hi)` 判断下一个值属于哪棵子树：`lo < 值 < hi` 才能作为当前节点，左子树的上界是当前值，右子树的下界是当前值。序列长度从 `2n + 1` 降到 `n`。
3. **超大树**：流式输出——序列化边遍历边写文件，不在内存拼整个字符串；前序只需要树高大小的栈，层序需要保留最宽一层的队列，按树的形状选择。还原时同样边读边建。
4. **树很深（`RecursionError`）**：`10^4` 的链会超过默认的递归上限约 1000。可以 `sys.setrecursionlimit(20000)`，或者改用层序版本，两边都是循环，不递归，代码见「另一种解法」。
5. **别犯的错**：不要依赖语言的内置序列化（如 `pickle`）作为答案——面试考的是设计编码。

**Python 提醒**：`next(iterator, default)` 在迭代器耗尽时返回 `default`，而不是抛 `StopIteration`；省略默认值时，数据被截断会直接抛 `StopIteration`；在生成器内部它还会被转成 `RuntimeError`，排查起来更绕。拼接结果用 `",".join(list)`，不要在循环里对字符串做 `+=`。
