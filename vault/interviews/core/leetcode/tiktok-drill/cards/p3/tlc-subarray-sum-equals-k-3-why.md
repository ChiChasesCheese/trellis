## Q
**LC 560 和为 K 的子数组**｜正确性

前缀和加哈希表的解法里，为什么初始要放 `{0: 1}`？为什么必须先查询、后把当前前缀和记入表中？另外，为什么不能用滑动窗口？各给一个具体输入。

## A
**不变量。** 处理到下标 `j` 时，`seen` 里恰好是 `pre[-1], pre[0], ..., pre[j-1]` 这些前缀和（`pre[-1] = 0` 代表空前缀）出现的次数。每个满足 `pre[i-1] = pre[j] - k` 的 `i <= j` 对应一个以 `j` 结尾、和为 `k` 的非空子数组。

**为什么要 `{0: 1}`。** 从下标 0 开始的子数组，其左边的前缀是空的，和为 `0`；表里没有它就数不到。
- 反例：`nums = [3]`，`k = 3`。没有初始 `0` 时，`pre = 3`，查 `seen[0]` 得 `0`，返回 `0`。
- 正确答案是 `1`（子数组 `[3]`）。

**为什么先查后存。** 先把 `pre` 记入表中再查，`pre - k` 可能命中刚刚记入的自己，等于把「长度为 0 的空子数组」当成了答案。
- 反例：`nums = [1]`，`k = 0`。先存后查：`seen[1]` 变 `1`，查 `seen[1 - 0] = 1`，返回 `1`。
- 正确答案是 `0`，因为子数组必须非空。

**为什么不能滑动窗口。** 窗口法依赖「窗口和过大就缩左端」，这要求元素非负。
- 反例：`nums = [1,-1,1]`，`k = 1`。和为 `1` 的子数组有 `[1]`（下标 0）、`[1,-1,1]`、`[1]`（下标 2）共 `3` 个。
- 窗口法在 `[1,-1]` 之后和为 `0`，不会回头把更长的窗口纳入，只得到 `2`。
