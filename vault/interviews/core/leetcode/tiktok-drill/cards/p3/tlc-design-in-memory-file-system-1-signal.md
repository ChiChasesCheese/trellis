## Q
**LC 588 设计内存文件系统**｜Hard · LC TikTok 热度 50/100 · 近一年被问：美国 3 次、国内 0 次 · 最近 2026-08-31（美国面试记录）

设计类 `FileSystem`，支持：`ls(path)`（文件路径返回只含该文件名的列表，目录路径返回其中所有文件名和子目录名，按字典序）、`mkdir(path)`（中间目录缺失也要创建）、`addContentToFile(filePath, content)`（文件不存在则创建，存在则追加）、`readContentFromFile(filePath)`。路径是以 `/` 开头、不以 `/` 结尾的绝对路径（根目录 `/` 除外），`1 <= path.length, filePath.length <= 100`，名字只含小写字母且同目录不重名，参数都有效，`1 <= content.length <= 50`，四个方法合计至多调用 `300` 次。例：`mkdir("/a/b/c")`，`addContentToFile("/a/b/c/d", "hello")` 之后，`ls("/")` → `["a"]`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「路径、层级、目录」→ 树；按名字一层层往下查 → 前缀树（trie），每个节点一个 `children` 字典。
- 「目录或文件」两种节点 → 节点上留一个字段区分，例如 `content is None` 表示目录。
- 「`ls` 按字典序」→ 取 `children` 的键后 `sorted`；没有“按序遍历”的需求，不必用有序结构。
- 调用次数只有 `300`、路径至多 `100` → 复杂度不是难点，考的是类设计和边界（根目录、文件上的 `ls`、追加）。

**推导链。**
1. 暴力：一个扁平字典 `路径 → 内容`，`ls` 扫描所有路径找直接子项，`O(路径数 × L)`。`300` 次调用够用，但每次重扫。
2. 浪费：路径天然是树，扁平化后“谁是谁的子项”要靠字符串前缀反推，还容易把 `/a` 和 `/ab` 混淆。
3. 洞察：按 `/` 拆路径，逐段下行；每个目录节点直接持有 `children`，`ls` 只读当前节点。
4. 操作统一为“走路径”这一个原语 `_walk(path, create)`，四个方法各自只写几行。
