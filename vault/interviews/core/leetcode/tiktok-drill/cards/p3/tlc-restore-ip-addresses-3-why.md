## Q
**LC 93 复原 IP 地址**｜正确性

为什么遇到前导零或超过 `255` 时可以直接 `break`，而不是 `continue`？为什么前导零的判断必须是「长度大于 `1` 且以 `0` 开头」？切满四段之后为什么还要检查 `start == n`？

## A
**为什么 `break`。** 对同一个起点，段的长度从 `1` 增加到 `3`。以 `0` 开头且长度已大于 `1` 的段有前导零，把它再延长一位仍以 `0` 开头，同样非法。超过 `255` 的数，在末尾再加一位数字只会更大。所以一旦某个长度非法，所有更长的长度都非法，后面的循环可以全部放弃。

**为什么单独的 `"0"` 合法。** 地址 `"0.0.0.0"` 是有效的，`"0"` 是合法的一段。只有当段长大于 `1` 并且以 `0` 开头（如 `"01"`、`"00"`）才算前导零。

**为什么要检查 `start == n`。** 题目要求把整个字符串都用上。只切 `4` 段不保证用完字符：`s = "11111"` 时，切 `1.1.1.1` 只用了前 `4` 位。

**反例。**
- 不判前导零：`"101023"` 会多出 `"1.0.1.023"`、`"1.01.0.23"`、`"1.01.02.3"` 等，共 `10` 个；正确是 `5` 个。
- 把任何以 `0` 开头的段都判非法：`"0000"` 得到 `[]`，正确是 `["0.0.0.0"]`；`"101023"` 只剩 `["10.10.2.3"]`。
- 不检查 `start == n`：`"11111"` 会多出 `"1.1.1.1"`（丢掉了最后一位），正确只有 `["1.1.1.11", "1.1.11.1", "1.11.1.1", "11.1.1.1"]` 四个。

**长度剪枝为什么对。** 还要切 `left` 段，每段 `1` 到 `3` 位，所以剩余字符数至少 `left`、至多 `3 * left`；不在区间内，无论怎么切都不可能刚好用完，提前返回只是少走无用的分支，不影响结果。
