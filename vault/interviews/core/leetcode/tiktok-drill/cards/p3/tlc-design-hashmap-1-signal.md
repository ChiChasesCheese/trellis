## Q
**LC 706 设计哈希映射**｜Easy · LC TikTok 热度 62/100（近 6 个月） · 近一年被问：美国 2 次、国内 1 次 · CodeTop 国内累计 3 次 · 最近 2026-08-13（国内面试记录）

不使用任何内建的哈希表库设计一个哈希映射（HashMap）。实现 `MyHashMap` 类：`MyHashMap()` 初始化空映射；`put(key, value)` 插入键值对，`key` 已存在则更新其值；`get(key)` 返回对应的值，不存在返回 `-1`；`remove(key)` 若存在则移除。`0 <= key, value <= 10^6`，最多调用 `10^4` 次 `put`、`get` 和 `remove`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「不使用内建哈希表」→ 这是**设计题**：考你对哈希表原理的理解——哈希函数、冲突处理、增删改查的边界情况。
- 键的取值范围只有 `0..10^6` → 有一个取巧解：长度 `10^6 + 1` 的数组直接寻址（每个键一个槽，值域 `>= 0` 所以可用 `-1` 表示空）；它占 `10^6` 空间且只对小整数键成立，面试要展示的是通用设计。
- 最多 `10^4` 次操作 → 桶数取一千左右、每桶平均个位数元素就足够。
- 「`key` 已存在则更新」→ `put` 必须先在桶里找，不能无脑追加。

**推导链。**
1. 暴力：一个 `[key, value]` 列表，每次线性扫描整个列表，`O(n)`。
2. 浪费：每次操作都要扫所有键值对。
3. 关键：用哈希函数 `hash(key) % B` 把键分配到 `B` 个桶之一，只扫自己所在桶里的少数元素。`B` 取质数，让有规律的键分布更均匀。
4. 冲突（两个键落到同一个桶）用**拉链法**：桶里放小列表，里面逐个比较键；删除时与桶尾交换再 `pop`，`O(1)`。键值对数增长时可以扩容重新散列，保持每桶平均长度小。

**同模式的题**：LC 705 设计哈希集合、LC 146 LRU 缓存、LC 380 O(1) 时间插入、删除和获取随机元素、LC 460 LFU 缓存。
