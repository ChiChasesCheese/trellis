## Q
**深度合并两个嵌套 JSON**｜正确性

递归合并两个嵌套 JSON：两边都是字典就遍历键的并集，两边都有的键对子值递归。为什么这样不会漏键或重复处理？递归深度、原地修改输入、只检查一边是字典，各会错成什么样？

## A
**不变量。** `walk(x, y)` 返回「`x` 与 `y` 合并后的新结构」，对键并集里的每个键恰好填一次：只在一边出现的直接取；两边都有的，子值的合并结果由同一个函数返回（对嵌套深度归纳：叶子情形直接正确，字典情形用更小的实例拼出）。不同键的子问题互相独立，所以键的处理顺序不影响结果。

**反例一：不留意递归深度。** 深度 `2 * 10^4` 的单链字典，在默认递归上限（约 `1000`）下运行到约 `1000` 层就抛 `RecursionError`，`copy.deepcopy` 对同样的输入也一样；需要 `sys.setrecursionlimit` 调大或改成显式栈。

**反例二：原地修改。** `a = {"x": {"y": 1}}`，`b = {"x": {"z": 2}}`，写成「把 `b` 的内容并进 `a` 再返回 `a`」，返回值正确，但 `a` 已经被改成 `{'x': {'y': 1, 'z': 2}}`，违反不修改输入。

**反例三：只检查左边是字典。** 左边 `{"k": {"x": 1}}`、右边 `{"k": 5}`：只判断 `isinstance(left[key], dict)` 就递归，会对标量 `5` 调用字典方法而崩溃；两边都是字典才递归，其余走 `_combine`，`"later"` 策略下得到 `{'k': 5}`，`"error"` 策略抛 `TypeError`。

**反例四：列表拼接顺序反了。** `merge({"t": [1, 2]}, {"t": [3]})` 必须是 `{'t': [1, 2, 3]}`；写成 `y + x` 得到 `{'t': [3, 1, 2]}`。
