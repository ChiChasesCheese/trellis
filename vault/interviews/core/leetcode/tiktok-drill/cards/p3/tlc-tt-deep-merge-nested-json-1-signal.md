## Q
**深度合并两个嵌套 JSON**｜Medium · 近一年被问：美国 0 次、国内 4 次 · 最近 2026-10（面试记录）

实现 `merge(a, b)`，合并两个嵌套 JSON 值（字典、列表、标量），返回新结构，不修改输入：两边都有的 key，两个值都是字典就递归合并；只在一边出现的 key 直接保留；两个值都是列表就拼接；类型不同按策略处理（以后者为准或抛 `TypeError`）。键是字符串，嵌套深度可达 `2 * 10^4`，总元素数不超过 `10^5`。例：`merge({"cfg": {"a": 1}, "t": [1]}, {"cfg": {"b": 2}, "t": [2]})` → `{"cfg": {"a": 1, "b": 2}, "t": [1, 2]}`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「两边都有的 key 且都是字典就递归合并」→ 两棵树按相同路径同步遍历。
- 「嵌套深度可能超过一万层」→ 递归会 `RecursionError`（默认上限 `1000`），必须用显式栈把递归改成迭代。
- 「不修改输入」→ 沿合并路径新建字典，没有被合并的子树可以共用，不能原地改 `a`。
- 「类型不同按策略处理」→ 叶子情形集中到一个函数里分派：列表拼接、同类标量取后者、冲突按策略。

**推导链。**
1. 暴力：`deepcopy(a)` 后递归地把 `b` 并进去；深拷贝本身也是递归的，深层直接崩溃，还会拷贝没有变化的部分。
2. 浪费：调用栈只是在记「接下来要合并哪一对字典」。
3. 洞察：把这些待合并的字典对放进自己的栈里；处理一对只会产生下一层的新任务，叶子情形当场解决。
4. 最优：栈里放 `(结果字典, 左, 右)`，遍历键的并集，只在一边出现的直接取，`O(总元素数)`，空间 `O(深度)`。

**同模式的题**：LC 617 合并二叉树、LC 21 合并两个有序链表、LC 1634 多项式链表相加、LC 138 随机链表的复制。
