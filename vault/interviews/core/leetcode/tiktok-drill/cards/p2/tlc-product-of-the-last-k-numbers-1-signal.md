## Q
**LC 1352 最后 K 个数的乘积**｜Medium · LC TikTok 近 6 个月热度 50/100（全时段 38）

设计类 `ProductOfNumbers`：`add(num)` 把整数加到流的末尾，`getProduct(k)` 返回最后 `k` 个数的乘积（保证至少有 `k` 个数）。任意连续序列的乘积都在 32 位整数内。`0 <= num <= 100`，`1 <= k <= 4 * 10^4`，调用合计至多 `4 * 10^4` 次。进阶：两个操作都 `O(1)`。例：加入 `3, 0, 2, 5, 4` 后，`getProduct(2)` 得 `20`，`getProduct(4)` 得 `0`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「数据流」+「最后 `k` 个」+「`O(1)` 查询」→ **前缀积**，与前缀和同一思想：区间和用减法，区间积用除法。
- 「`0 <= num`」→ 会出现 `0`，除法的唯一障碍：设计要围绕 `0` 做文章。
- 「32 位内、保证至少有 `k` 个数」→ 不用担心溢出和边界缺失。
- 调用 `4 * 10^4` 次、`k` 到 `4 * 10^4` → 每次现算 `O(k)` 总共约 `1.6 * 10^9`，超时。

**推导链。**
1. 暴力：存列表，查询时对最后 `k` 个现乘，`O(k)` 每次。
2. 前缀积：`prefix[i]` 是前 `i` 个数的乘积，最后 `k` 个数的乘积 = `prefix[-1] // prefix[-1 - k]`，查询 `O(1)`，添加也 `O(1)`。
3. 障碍：`0` 让后面的前缀都是 `0`，除法失效。
4. 观察：任何覆盖这个 `0` 的区间乘积都是 `0`，`0` 之前的前缀已经没用，直接清空为 `[1]`。
5. 查询时，若 `k >= len(prefix)`，说明最后 `k` 个数里含最近的 `0`，返回 `0`；否则相除。

**同模式的题**：LC 303 区域和检索、LC 238 除自身以外数组的乘积、LC 713 乘积小于 K 的子数组、LC 560 和为 K 的子数组。
