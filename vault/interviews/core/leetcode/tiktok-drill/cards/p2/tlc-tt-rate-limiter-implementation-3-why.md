## Q
**手写限流器**｜正确性

滑动窗口限流器保证「任意长度为 1 秒的窗口内最多放行 `r` 次」，令牌桶保证「任意区间 `T` 内最多放行 `b + r·T` 次」。各自靠什么不变量做到？固定窗口计数、滑动窗口里把被拒请求也入队、令牌桶不封顶，分别会错成什么样？

## A
**滑动窗口的不变量。** 处理完每个请求后，`deque` 恰好是 `(now - 1, now]` 内所有被放行请求的时间戳，所以 `len(deque)` 就是窗口内已放行的次数；`< r` 才放行，窗口内放行数永远不超过 `r`。

**令牌桶的不变量。** `0 <= tokens <= b`，且放行一次恰好扣 1。任意区间 `T` 内：开始时最多有 `b` 个令牌，期间最多补充 `r·T` 个，每次放行消耗 1 个，所以放行数不超过 `b + r·T`；长期平均速率不超过 `r`。

**反例一：固定窗口计数。** 把时间切成 `[0, 1)`、`[1, 2)` 整秒窗口各数一次，`r = 2`，请求在 `t = 0.9, 0.95, 1.0, 1.05`：每个窗口里都只有 2 个，全部放行，`0.15` 秒内通过了 4 个；滑动窗口的结果是 `[True, True, False, False]`。

**反例二：被拒请求也入队。** `r = 1`，请求在 `t = 0, 0.5, 1.0, 1.5`。把被拒的 `0.5` 也记进窗口，`t = 1.0` 时窗口里还剩 `0.5`，被拒；整串得到 `[True, False, False, False]`。正确的 `[True, False, True, False]`：`t = 1.0` 时窗口 `(0, 1.0]` 里没有被放行的请求。

**反例三：令牌桶不封顶。** `rate = 1`、`burst = 3`，`t = 0` 连发 3 个后空闲到 `t = 100`，再连发 5 个。不封顶时令牌累积到 `100`，5 个全放行，`[True, True, True, True, True, True, True, True]`；封顶后只有前 3 个放行，`[True, True, True, True, True, True, False, False]`。
