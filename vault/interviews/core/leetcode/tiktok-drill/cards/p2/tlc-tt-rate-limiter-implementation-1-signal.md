## Q
**手写限流器**｜Medium · 近一年被问：美国 0 次、国内 10 次 · 最近 2026-08（国内面试记录）

实现 `allow(key, now) -> bool`：每个 `key` 每秒最多放行 `r` 次请求，突发上限 `b`；`now` 是请求到达的秒数（浮点数，一般单调不减）。先用滑动窗口，再用令牌桶重写。`1 <= r <= 10^4`，`1 <= b <= 10^6`，key 数量可达 `10^6`。例：`r = 2` 的滑动窗口对 `t = 0.0, 0.5, 0.9, 1.0` 依次返回 `True, True, False, True`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「每个 key 每秒最多 r 次」→ 限流（rate limiting），状态按 key 分开存，用哈希表。
- 「滑动窗口」→ 精确计数：窗口 `(now - 1, now]` 内被放行的请求数；时间戳单调进入，用 `deque` 在队首弹出过期项。
- 「突发上限 b」「令牌按速率补充」→ 令牌桶：用两个数 `(tokens, last)` 惰性补充，不需要定时器。
- key 数量 `10^6`：每个 key 的内存要小，令牌桶 `O(1)`，滑动窗口 `O(r)`。

**推导链。**
1. 暴力：保存每个 key 的全部历史时间戳，每次请求扫一遍统计窗口内个数，`O(历史长度)`，内存无限增长。
2. 浪费：窗口之外的时间戳永远不会再被数到；被拒的请求也不占额度。
3. 洞察：只保留窗口内被放行的时间戳，队首过期即弹，均摊 `O(1)`、内存 `O(r)`；再进一步，额度只取决于「剩余令牌数和上次计算的时刻」，两个数就够。
4. 最优：令牌桶 `tokens = min(b, tokens + (now - last) * r)`，够 1 个放行并扣 1；`O(1)` 时间和内存，支持突发。
