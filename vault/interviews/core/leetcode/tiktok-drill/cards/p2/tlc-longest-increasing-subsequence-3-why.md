## Q
**LC 300 最长递增子序列**｜正确性

`tails` 数组每一步维护的不变量是什么？为什么替换第一个 `>= x` 的位置是安全的？`bisect_left` 写成 `bisect_right` 会错在哪，`tails` 本身是不是一条真实的子序列？

## A
**不变量。** 处理完前 `k` 个数后，`tails[j]`（从 0 数）等于这前 `k` 个数里所有长度为 `j+1` 的严格递增子序列的最小结尾，并且 `tails` 严格递增。

**为什么严格递增。** 若 `tails[j] >= tails[j+1]`，取长度 `j+2` 的序列去掉最后一个元素，得到长度 `j+1` 且结尾小于 `tails[j+1]` 的序列，与 `tails[j]` 是最小结尾矛盾。

**为什么替换第一个 `>= x` 的位置安全。** `x` 可以接在任何结尾 `< x` 的序列之后，形成长度为 `i+1` 的序列，其中 `i` 是第一个 `>= x` 的下标；它的结尾 `x` 不大于原来的 `tails[i]`，所以只会让 `tails[i]` 变小。更小的结尾对未来只有好处，没有坏处。

**反例：用 `bisect_right`。** 输入 `[7,7,7,7,7,7,7]`，严格递增意味着答案是 `1`。`bisect_right` 在遇到相等元素时返回其后的位置，每个 `7` 都被追加到 `tails`，得到 `7`。它实际计算的是最长非递减子序列的长度。

**`tails` 不是真实子序列。** 输入 `[4,5,1]`：处理完后 `tails = [1, 5]`。`1` 在原数组里位于 `5` 之后，`[1, 5]` 并不是一条合法子序列，但长度 `2` 是对的。所以只能用 `tails` 的长度；要还原序列，需要另外记录前驱。
