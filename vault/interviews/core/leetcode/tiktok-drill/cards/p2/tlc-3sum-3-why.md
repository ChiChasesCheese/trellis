## Q
**LC 15 三数之和**｜正确性

双指针为什么能在有序数组里不漏掉任何一对解？去重时为什么和**前一个**比较，而不是和后一个比较？给一个比较方向写反的具体输入。

## A
**不变量。** 固定 `i` 后，在 `[lo, hi]` 内，所有包含下标 `< lo` 或 `> hi` 的数对都已被排除（它们不可能是解）。

**为什么不会漏。** 若 `nums[lo] + nums[hi] < target`（这里 `target = -nums[i]`），则 `nums[lo]` 与 `[lo+1, hi]` 里任何数配对的和都不超过 `nums[lo] + nums[hi]`，仍小于 `target`，所以 `lo` 不可能出现在任何解里，可以安全右移；和过大时对 `hi` 同理。每次移动都排除了一个不可能的下标。

**为什么和前一个比较。** 排序后相同的数相邻。对第一个数，我们想让每个值只作为"第一个数"处理一次，而最先出现的那次能够使用右边所有的数（包括同值的数），信息最全；后出现的同值第一个数能用的集合更小，其解是前者的子集，跳过它不会丢解。

**反例：和后一个比较。** 把条件写成 `if i + 1 < n and nums[i] == nums[i + 1]: continue`。排序后 `[-4,-1,-1,0,1,2]`，`i = 1` 的 `-1` 因为后面还有一个 `-1` 被跳过，而 `i = 2` 的 `-1` 右边已经没有另一个 `-1`，只能找到 `[-1,0,1]`。结果是 `[[-1,0,1]]`，丢了 `[-1,-1,2]`，正确是 `[[-1,-1,2],[-1,0,1]]`。

**找到解后的处理。** 找到解后 `lo += 1; hi -= 1`，再让 `lo` 跳过重复值。不跳重复时 `[-2,0,0,2,2]` 会输出两个 `[-2,0,2]`。
