## Q
**LC 160 相交链表**｜正确性

双指针各自走完「自己的链表 + 对方的链表」为什么一定会在交点相遇？不相交时为什么会停？把换表头的条件写成 `a.next is None`，或者把 `a is not b` 换成按值比较，各会错成什么样？

## A
**不变量。** 设 A 独有 `x` 个节点，B 独有 `y` 个，共享尾部 `c` 个。指针 `a` 走过的路径是「A 的 `x + c` 个节点，再接 B 的 `y + c` 个节点」，指针 `b` 是「B 的 `y + c` 个，再接 A 的 `x + c` 个」。把越过末尾的那一步（走到 `None`）也算一步：`a` 到达交点共 `(x + c) + 1 + y` 步，`b` 共 `(y + c) + 1 + x` 步，两者相等，所以同时站在交点上。

**不相交为什么会停。** `c = 0`，`a` 走 `m + 1 + n` 步，`b` 走 `n + 1 + m` 步，两者同时取到 `None`，`None is None`，循环结束，返回 `None`。

**反例。** 示例一，`listA = [4,1,8,4,5]`，`listB = [5,6,1,8,4,5]`，交点值为 `8`：
- 按值比较（`a.val != b.val`）：A 的值为 `1` 的节点和 B 的值为 `1` 的节点值相同，但它们是两个不同的节点；循环在那里停下，返回值为 `1` 的节点，正确答案是值为 `8` 的节点。
- 换表头的条件写成 `a.next is None`：指针在最后一个节点就换表，永远不会变成 `None`。示例三 `[2,6,4]` 与 `[1,5]` 不相交，两个指针一直循环，不会退出。
- 走到 `None` 就结束、不换表头：两个指针从不对齐，示例一返回 `None`，正确答案是值为 `8` 的节点。
