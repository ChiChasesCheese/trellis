## Q
**LC 295 数据流的中位数**｜Hard · LC TikTok 近 3 个月热度 70/100（全时段 62） · 近一年被问：美国 3 次、国内 0 次 · CodeTop 国内累计 18 次 · 最近 2026-10-15（美国面试记录）

实现 `MedianFinder` 类：`addNum(int num)` 将数据流中的整数加入数据结构；`findMedian()` 返回到目前为止所有元素的中位数（元素个数为偶数时取两个中间值的平均，答案允许 `10^-5` 的误差）。`-10^5 <= num <= 10^5`，调用 `findMedian` 前至少有一个元素，最多 `5 * 10^4` 次调用。例：`addNum(1)`、`addNum(2)`、`findMedian()` → `1.5`，`addNum(3)`、`findMedian()` → `2.0`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「数据流」+「随时查询中位数」→ **在线**问题：每次插入后都要能快速回答，不能攒到最后再排序。
- 中位数只和「中间一两个」元素有关，不需要全体有序 → **只维护中间的边界**：左半的最大值与右半的最小值 → **双堆**（two heaps）：左半用大根堆，右半用小根堆。
- 调用至多 `5×10^4` 次 → 每次操作 `O(log n)` 轻松；`O(n)` 的插入（`bisect.insort`）也能过，但不能扩展到更大的流。
- 值域 `[-10^5, 10^5]` 固定且不大 → 还有计数数组的做法（追问会用到）。

**推导链。**
1. 暴力：每次 `findMedian` 前对所有元素排序，`O(n log n)`，调用 `5×10^4` 次不可接受。
2. 改进：用 `bisect.insort` 让列表始终有序，`findMedian` 是 `O(1)`，插入要搬元素是 `O(n)`。
3. 浪费：我们保持了全局顺序，但查询只看中间。只需把元素分成「较小的一半」和「较大的一半」，保证左半的每个数不大于右半的每个数。
4. 两个堆的堆顶就是中间的两个数。新数进来，先过左堆再把左堆最大值送到右堆（保持有序性），再平衡大小（左堆等于右堆或多 1），每次 `O(log n)`，查询 `O(1)`。
