## Q
**LC 432 全 O(1) 的数据结构**｜追问

面试官接着问：（1）这个结构怎样改成 LFU 缓存（LC 460）？（2）要求 `getMaxKey` 返回字典序最小的 key？（3）多线程并发调用怎么办？（4）还想要“计数恰好是 `c` 的所有 key”？

## A
1. **LFU 缓存。** 桶按**访问频率**分，桶内要能区分“谁最久没用”：用 `OrderedDict`（或双向链表）代替集合。`get` / `put` 命中时把 key 从频率 `f` 的桶挪到 `f + 1` 的桶；缓存满时从**最小频率的桶**里弹出最久未使用的 key。同样 `O(1)`，只是多了容量和桶内的次序。
2. **字典序最小。** 桶里的集合换成有序结构（如堆或排序容器）后，每次 `inc` / `dec` 的桶内增删变成 `O(log n)`；真要 `O(1)` 是做不到的，需要在面试里说清取舍。
3. **并发。** 每个操作要同时改 `where` 和链表指针，不是原子的；给整个类加一把 `threading.Lock`，读 `getMaxKey` 也要加锁（指针可能正在改）。吞吐不够时再考虑分片：按 key 的哈希分成多个子结构，`getMaxKey` 合并各片结果，代价是不再严格 `O(1)`。
4. **按计数查 key。** 链表节点本身已经按计数组织，再加一个字典 `cnt → 桶`，就能 `O(1)` 找到计数为 `c` 的桶（需要在建桶和摘桶时同步维护这个字典）。

**Python 提醒**：`next(iter(s))` 取集合的一个元素但不删除它；`set.pop()` 取一个并删除。两者平均 `O(1)`，不过集合经历大量删除后，迭代要先跳过空槽，常数会变大。这里每个桶里的 key 很少，影响可以忽略；要在大集合上反复取元素时需要换结构。
