## Q
**LC 1 两数之和**｜Easy · LC TikTok 热度 66/100（近 3 个月） · 近一年被问：美国 1 次、国内 2 次 · CodeTop 国内累计 127 次 · 最近 2026-09-07（CodeTop）

给整数数组 `nums` 和整数 `target`，找出和为 `target` 的**两个**元素，返回它们的**下标**。同一个元素不能用两次，答案可按任意顺序返回，只会存在一个有效答案。`2 <= nums.length <= 10^4`，`-10^9 <= nums[i] <= 10^9`，`-10^9 <= target <= 10^9`。例：`nums = [2,7,11,15], target = 9` → `[0,1]`。进阶：想出时间复杂度小于 `O(n^2)` 的算法。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「找一对满足 `a + b = target`」等价于：对每个元素 `x`，问「`target - x` 在不在」。这是**查找问题** → 用**哈希表**（hash table）把单次查找降到 `O(1)`。
- 要的是**下标**，不是值 → 不能直接排序（排序会打乱下标）；排序加双指针只适合「返回值」或「有序数组」的变体。
- `n` 到 `10^4`：`O(n^2)` 大约 5×10^7 对，能过，但进阶明确要更优 → 目标 `O(n)`。
- 值域到 ±10^9 → 不能拿数组下标直接当计数桶，只能用哈希表。

**推导链。**
1. 暴力：枚举所有下标对 `(i, j)`，`O(n^2)`。
2. 浪费：固定 `i` 之后，在剩下的元素里线性找 `target - nums[i]`——要找的是一个**确定的值**，却花了 `O(n)`。
3. 关键：「某个确定的值在不在」正是哈希表最擅长的。边扫边存：扫到 `x` 时，只需查**前面**已出现的元素里有没有 `target - x`；每一对都会在较晚的那个元素处被发现一次，所以不用回头。
4. 一遍扫描，哈希表存「值 → 下标」，时间 `O(n)`，空间 `O(n)`——用空间换时间。

**同模式的题**：LC 167 两数之和 II（有序数组，双指针）、LC 15 三数之和、LC 653 两数之和 IV（输入是 BST）、LC 560 和为 K 的子数组（前缀和 + 哈希表）。
