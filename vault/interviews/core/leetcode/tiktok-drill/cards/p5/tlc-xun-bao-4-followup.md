## Q
**LCP 13 寻宝**｜追问

面试官接着问：（1）要输出触发机关的顺序？（2）机关数量到 `20`、`25` 怎么办？（3）石堆非常多（上万个）？（4）石头可以一次搬两块，或者石堆的石头有限？

## A
1. **输出顺序**：DP 同时记录前驱，`parent[mask][j] = i`；终点处找到最优的最后一个机关 `j`，沿 `parent` 往回走，依次得到触发顺序，反转后输出。要还原每一段的具体路径，再对相应的两点各做一次 BFS 并保留前驱格子。
2. **机关更多**：`2^20 * 20` 约两千万个状态，纯 Python 的三重循环太慢。做法：把 `dp[mask]` 当作定长数组，用 NumPy 对 `i` 向量化（`np.min(dp[prev] + hop[:, j])`）；`25` 以上状态数过大，只能用近似算法（最近邻加 2-opt 局部改进）。
3. **石堆很多**：BFS 次数取 `min(机关数, 石堆数) + 2`——机关少就从机关出发 BFS，石堆少就从石堆出发；`hop` 的预计算是 `O(k^2 · |O|)`，`|O| = 10^4`、`k = 16` 时约 `2.5 * 10^6`，仍然轻松。
4. **变体**：一次搬两块，状态要记录手里的石头数，不能再压缩成「一次往返」；石堆石头有限，则每个石堆要记录剩余量，状态爆炸，通常只能小规模搜索。

**Python 提醒**：`dp = [[inf] * k for _ in range(full)]` 必须用推导式，写成 `[[inf] * k] * full` 会让所有 `mask` 共用同一行；在 Python 里，移位和按位与的优先级高于比较，低于算术，`not` 最低：`not mask >> j & 1` 解析为 `not ((mask >> j) & 1)`；拿不准时加括号。
