## Q
**剑指 Offer 26 树的子结构**｜Medium · CodeTop 国内累计 48 次 · 最近 2026-10-27（CodeTop）

给两棵二叉树 `tree1` 和 `tree2`，判断 `tree2` 是否是 `tree1` 的**子结构**：存在 `tree1` 的某个节点，以它为根向下，`tree2` 的每个节点都能在相同位置找到值相同的节点。空树不是任何树的子结构。节点个数 `0 <= n <= 10000`。例：`tree1 = [3,6,7,1,8]`，`tree2 = [6,1]` → `true`；`tree1 = [1,7,5]`，`tree2 = [6,1]` → `false`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「`tree2` 是否出现在 `tree1` 里」→ **树匹配**：外层枚举候选根，内层同步向下验证。
- 「相同的结构和节点值」但示例 2 里 `tree1` 的节点 `6` 还有右孩子 `8` 仍然成立 → 这是**包含**而不是**相等**：`tree2` 的一支走到空，就不再看 `tree1` 的对应位置。
- 「空树不是子结构」→ 入口先排除任一棵为空。
- 节点数到 `10000` → 链状树 `10000` 层，递归可能超出 Python 默认的递归上限，改用显式栈。

**推导链。**
1. 暴力就是正解的骨架：枚举 `tree1` 的每个节点作根，检查 `tree2` 能否从它向下对上。
2. 内层 `match(a, b)`：`b` 为空 → 这一支成功；`a` 为空或值不同 → 失败；否则左右两支都要成功。
3. 优化候选根：只有节点值等于 `tree2` 根的值才进入 `match`，提前过滤掉大部分候选。
4. 复杂度：`m` 个候选根，每个最多比较 `n` 个节点，`O(m * n)`；严格的“子树”版本（LC 572）才能靠序列化降到 `O(m + n)`。
5. 递归深度：用显式栈写外层遍历和 `match`，避免 `10000` 层递归。

**同模式的题**：LC 572 另一棵树的子树、LC 100 相同的树、LC 101 对称二叉树、LC 226 翻转二叉树。
