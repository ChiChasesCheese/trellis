## Q
**一个骰子掷出更大点数的概率**｜正确性

求骰子 `A` 严格大于骰子 `B` 的概率时，为什么对排好序的 `B` 用 `bisect_left` 而不是 `bisect_right`？为什么「赢的组合数 / `p·q`」就是概率？给一个用错二分函数时出错的例子。

## A
**为什么是计数。** 两个骰子独立且公平：`A` 的每面概率 `1/p`，`B` 的每面概率 `1/q`，每个（`A` 面，`B` 面）组合的概率都是 `1/(pq)`。所以 `P(A > B)` = 满足 `a > b` 的组合数 × `1/(pq)`。重复的数字按面分别计数，不去重。

**不变量。** 对有序列表 `s`，`bisect_left(s, x)` 返回最小的下标 `k` 使 `s[k] >= x`，所以 `s[0 : k]` 全部 `< x`，`k` 正好是「严格小于 `x`」的个数。`bisect_right(s, x)` 返回第一个 `> x` 的位置，数的是「`<= x`」，多出的部分就是与 `x` 相等的面，也就是平局。

**反例。** `A = [2,5]`，`B = [2,5]`，`sorted_b = [2,5]`。
- `bisect_right`：`x = 2` 得 1，`x = 5` 得 2，共 3，结果 `3/4`。平局 `2 = 2`、`5 = 5` 被算成了赢。
- `bisect_left`：`x = 2` 得 0，`x = 5` 得 1，共 1，结果 `1/4`（正确：4 种组合里只有 `5 > 2`）。

**浮点的问题。** `1/3` 这类概率用浮点表示有舍入误差，比较或累加后可能和期望值不相等；`Fraction` 用整数分子分母，结果精确。
