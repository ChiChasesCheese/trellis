## Q
**LC 44 通配符匹配**｜正确性

DP 里 `*` 的转移为什么是「`dp[i][j-1]` 或 `dp[i-1][j]`」？第 0 行的初始化为什么必须单独写，第 0 列为什么保持 `False`？写错会给出什么错误输出？

## A
**不变量。** `dp[i][j]` 恰好等于「`s[:i]` 能否被 `p[:j]` 完整匹配」。

**`*` 的转移。** 把 `*` 的所有可能匹配长度分成两类，互斥且完备：
- 匹配**空串**：`s[:i]` 要被 `p[:j - 1]` 匹配，即 `dp[i][j-1]`；
- 至少匹配一个字符：最后一个字符 `s[i - 1]` 被这个 `*` 吞掉，`*` 依然可以继续吞，所以只需要 `s[:i - 1]` 被 `p[:j]`（含这个 `*`）匹配，即上一行的 `dp[i-1][j]`。
两类的并集就是「`*` 匹配任意长度」，不需要枚举长度，所以转移是 `O(1)`。

**第 0 行为什么要单独写。** 「`s` 为空」不是边界情况而是真实状态：`p` 开头的连续 `*` 都能匹配空串，后面的每一行都从这一行转移而来。

**第 0 列。** 非空的 `s` 不可能被空模式匹配，`dp[i][0] = False`（`i > 0`）。

**反例一：漏掉第 0 行的初始化。** 只设 `dp[0][0] = True`、其余全 `False`：
- `s = "aa", p = "*"`：`dp[1][1] = dp[1][0] or dp[0][1]`，两个都是 `False`，结果 `False`；
- 正确答案是 `True`（一个 `*` 吞下 `"aa"`）。
同理 `s = ""`、`p = "*"` 也会错成 `False`。

**反例二：第 0 列设成 `True`。** 非空 `s` 被空模式"匹配"：`s = "a"`，`p = ""` 得到 `True`，正确是 `False`。
