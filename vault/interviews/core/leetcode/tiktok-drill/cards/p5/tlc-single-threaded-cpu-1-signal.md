## Q
**LC 1834 单线程 CPU**｜Medium · LC TikTok 热度 69/100（近 3 个月）

给二维数组 `tasks`，`tasks[i] = [enqueueTime_i, processingTime_i]`：任务 `i` 在 `enqueueTime_i` 进入队列，需要 `processingTime_i` 时长。单线程 CPU 一次只执行一项任务，空闲且队列非空时选**执行时间最短**的任务（并列选**下标最小**的），开始后必须执行完，完成后可立刻开始下一个。返回处理任务的顺序。`1 <= n <= 10^5`，`1 <= enqueueTime_i, processingTime_i <= 10^9`。例：`tasks = [[1,2],[2,4],[3,2],[4,1]]` → `[0,2,3,1]`。

题面里哪些信号指向哪个模式？从暴力解怎样一步步推到最优解？

## A
**信号 → 模式。**
- 「每次从当前可选的任务里选最短，并列选下标最小」→ **优先队列（最小堆）**，键是元组 `(执行时间, 下标)`，Python 的元组比较正好是先时间后下标。
- 「任务在某个时刻才进入队列」→ **按到达时间排序加指针**，到达的任务才进堆。
- 时间值到 `10^9` → 不能逐秒模拟，必须**事件驱动**：时间只在“任务完成”或“空闲时跳到下一个到达”两种情况下推进。
- `n = 10^5` → 每次扫描全部任务的 `O(n^2)` 不行，目标 `O(n log n)`。

**推导链。**
1. 暴力：每次空闲时扫描全部任务，找已到达、未执行、执行时间最短的，`O(n^2)`。
2. 浪费：每个任务被反复比较；已到达的候选池只会增加（到达）和减少（被选中）。
3. 先按到达时间排序，用指针 `p` 依次放进候选池；候选池用最小堆，取最短 `O(log n)`。
4. 空闲处理：堆为空且下一个任务还没到，把时间直接设成它的到达时刻，不空转。
5. 每个任务入堆一次、出堆一次，`O(n log n)`。

**同模式的题**：LC 253 会议室 II、LC 621 任务调度器、LC 295 数据流的中位数、LC 23 合并 K 个升序链表（堆取最小）。
