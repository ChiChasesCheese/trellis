## Q
**LC 154 寻找旋转排序数组中的最小值 II**｜正确性

三个分支各自为什么不会丢掉最小值？为什么相等时只能丢右端点，而不是 `hi = mid` 或 `lo += 1`？给出两种写错时的具体输入。

## A
**不变量。** 循环中，`[lo, hi]` 内始终含有整个数组的最小值（至少一个）。

**`nums[mid] > nums[hi]`。** `mid` 落在被旋转到前面的大数段，而 `hi` 在后面的小数段，断点（最小值）在 `(mid, hi]` 内，`mid` 本身不是最小值，`lo = mid + 1` 不丢。

**`nums[mid] < nums[hi]`。** `[mid, hi]` 是一段有序（无断点）的区间，最小值不会在 `mid` 右边，所以在 `[lo, mid]` 内，`hi = mid` 不丢。

**`nums[mid] == nums[hi]`。** 不知道断点在哪一侧。丢掉 `hi`：如果 `nums[hi]` 是最小值，则 `nums[mid]` 与它相等，也是最小值，且 `mid < hi` 仍在区间内，最小值还在；如果 `nums[hi]` 不是最小值，丢掉它更不影响。所以 `hi -= 1` 总是安全的。

**为什么不能丢左端点或 `hi = mid`。** 左端点没有这样的「替身」：`nums[lo]` 可能就是唯一的最小值。`hi = mid` 会丢掉 `(mid, hi]`，而最小值可能就在那里。

**反例一：相等时 `hi = mid`。** `[3,3,1,3]`：
- `lo = 0, hi = 3`，`mid = 1`，`nums[1] == nums[3] == 3`，`hi = 1`。
- 之后 `mid = 0`，`3 == 3`，`hi = 0`，返回 `3`。
- 正确是 `1`，最小值在被丢掉的 `(mid, hi]` 里。

**反例二：相等时 `lo += 1`。** `[1,3,3]`：
- `lo = 0, hi = 2`，`mid = 1`，`3 == 3`，`lo = 1`，区间 `[3,3]`，最终返回 `3`。
- 正确是 `1`，被丢掉的 `nums[0]` 正是最小值。
