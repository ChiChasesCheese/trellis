# q19 · Accept-Language 解析（精确 → 语言 → 通配 → q 值）

> `problems/q19_accept_language/` · 4 个 part · phone screen 常见
> **主题：优先级规则叠加时，"哪一条 entry 说了算"必须写死。**

## 一句话题意

给浏览器发来的 `Accept-Language` 头和服务端支持的语言列表，
返回**服务端支持的、满足请求的**标签，按偏好从高到低。

## 输入 / 输出

```
第 1 行：头的值（可能为空）
第 2 行：逗号分隔的支持列表，按服务端偏好排序
```
标签是 `language[-REGION]`，**大小写不敏感**比较；标签和 `;` 参数周围的空白忽略。
最多 10^4 个头条目 × 10^3 个支持标签。**没有 `PART` 行**，规则累积。

输出：匹配的标签，每行一个，**拼写用支持列表里的写法**，最偏好的在前；无匹配 → `NONE`。

## 核心考点

`S02` 解析 · **`S08` 确定性顺序（q 降序 + 头位置）** · **`S14` 归一化（大小写、空白）** ·
`S18` 校验（坏 q） · `S19` 增量 · `S20` 自测

## 解题思路

### Part 1 — 精确匹配

按**头的顺序**返回支持列表里出现过的标签。头里重复的只输出一次（**第一次的位置算数**）。

### Part 2 — 只有语言的标签

`en` 意思是"任何英语变体" → 展开成**支持列表里所有语言部分是 `en` 的标签，按支持列表顺序**
（`en-US`、`en-GB`，以及服务端如果列了裸 `en` 的话也算）。

**已经输出过的不再重复**：`"fr-FR, fr"` → `fr-FR, fr-CA`（不是 `fr-FR, fr-CA, fr-FR`）。
不支持的语言展开成空。

### Part 3 — 通配符

`*` = "所有其他语言" —— 支持列表里**没有被任何显式条目（精确或语言级）覆盖**的标签，
按支持列表顺序。第二个 `*` 什么都不加。

### Part 4 — q 值（本题的难点）

```
entry 可带 ;q=<0..1>（默认 1.0）；其他参数（;level=1）忽略；无法解析的 q 当 1.0
```

**对每个支持标签，由"最具体"的匹配条目决定它的 q**：

```
精确标签  >  只有语言的标签  >  *          平手按**头中的位置**
```

所以 `fr-CA;q=0, fr;q=0.5` 给 fr-CA 的 q 是 **0**，不是 0.5。

**输出顺序**：q **降序** → 决定它的那个条目在头中的**位置** → 支持列表顺序。

**`q=0` 表示"不可接受"**：该标签被丢弃，而且 `*` 或语言级条目**不能把它加回来**。

## 坑

1. 空头、只有空白/逗号的头、空支持列表 → `NONE`。
2. **大小写**：头里 `EN-us` 匹配支持的 `en-US`，**输出用支持列表的拼写**；
   支持列表本身也可能是混合大小写（`en-us`）。
3. 空白：`" en-US ,fr ; q=0.5 "` 要能解析。
4. 头里和支持列表里的重复都只输出一次。
5. `fr-FR, fr` **不重复** `fr-FR`；`fr, fr-FR` → `fr-CA, fr-FR`（`fr-FR` 已被 `fr` 输出）。
6. `*` 单独 → 整个支持列表按支持序；`en, *` → 英语在前，其余在后。
7. q 平手保持头的顺序；`0.80` 和 `0.8` 相等；`q=1.0` 是默认值。
8. **`q=0` 排除，且挡住 `*` 把它加回来。**
9. 语言级标签本身也在支持列表里时（`en` 在 `["en", "en-US"]`）→ **两个都要**。

## 变体

- **q=0 沉底**而不是排除（programhelp）：`parse_accept_language(header, supported, zero_q="last")`。
  主线按 RFC 7231 §5.3.5 的 "not acceptable" 语义**排除**。
- 返回 set 而不是有序列表（但排序仍然是 follow-up）。
