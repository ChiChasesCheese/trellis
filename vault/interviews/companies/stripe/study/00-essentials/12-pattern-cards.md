# 第一部分 · 共性 —— 无论哪一类，这 6 件事一定在考

这 6 条是 Stripe OA 的「地基」。**任何一题，先按这 6 条起手，再谈家族特有的算法。**
它们是你 90% 的翻车点，而不是算法本身。

1. **先读完整份 spec，为 Part N+1 设计。**
   题面几乎都是 `Part 1/2/3/4` 层层加需求。上来只实现 Part 1 → 到 Part 4 发现状态形状不对 → 重写。
   起手三问：*后面会不会要撤销一笔？会不会要按某维度重新聚合？会不会要历史查询？* 只要有一个「会」，
   就得**保留原始记录、聚合值从它派生**，而不是只存计数器。

2. **面向行解析永远是前 10 分钟。**
   stdin 纯文本、多种记录类型靠第一个 token 区分。纪律：`strip()` 再判空 → 每字段 `strip()` →
   `maxsplit` 保护含分隔符的字段 → **setup 行可能出现在任意位置但语义上先生效 → 两遍扫描**。

3. **按 id 建字典建模，小记录 + 索引。**
   `dict[id -> record]` 是默认形状。别一上来就 `Counter`——统计值是投影，原始记录才是真相。

4. **严格 vs 非严格阈值（`>` 还是 `>=`）是故意埋的雷。**
   比例阈值一律**整数交叉相乘**，绝不用 float 比大小（`fraud*den >= num*total`）。钱一律**整数分 + 手写 half-up**。

5. **输出必须字节级确定。**
   多关键字排序 → 把排序键做成**元组**、稳定排序一次到位；同值 tie-break 常要用**输入位置**兜底
   （相当于给 SQL 补一个隐藏 `ROW_NUMBER()`）。空结果往往要输出字面量 `NONE`，别输出空行。

6. **非法输入 = 静默跳过，不是异常。**
   未知 id / 状态不对 / 参数个数不对 / 数字解析失败 → **什么都不做，continue**，不崩溃、不输出。
   实现上就是「每个操作先问一句『我现在适用吗』，答否就跳过」。

> 记住这句总纲：**保留能撤销的最小单元，聚合是它的可增量投影；先校验、后落地；排序要确定、输出要精确。**

# 第二部分 · 八大题型家族

先扫这张表建立地图，再进第三部分看逐题卡。**很多题跨界**（比如 q21 既是图又是钱），
卡片里会标 `跨界:`。归到哪个家族看的是「解题的主脊椎」。

| 家族 | 一眼信号（题面里出现就往这想） | 统治直觉（一句话） | 成员 |
|---|---|---|---|
| **F1 事件流重放** | 「按行重放命令 / CHARGE+DISPUTE / 撤销 / 重复通知 / 状态转移 / 静默忽略非法」 | 保留每一笔原始记录（`dict[id]`），撤销 = 加操作的逐字镜像；先校验后落地 | q01 q07 q10 q11 q13 q25 q27 q30 q35 qA06 |
| **F2 规则引擎** | 「一堆规则按顺序 / 独立应用 / 默认值+覆盖表 / 第一条匹配说了算 / 收集所有理由码」 | 规则 = 数据（谓词列表 or 查表），不是 if/elif；分清「短路取首」还是「全评估收集」 | q02 q12 q15 q16 q19 q38 |
| **F3 钱与舍入** | 「计费 / 费率 / 税率 / proration / 阶梯价 / 对账」 | 整数分搬运 + 手写 half-up；阶梯(volume)=整批一档价，累进(graduated)=分段像水流过水管 | q03 q20 qA01 |
| **F4 区间与时间轴** | 「区间合并/补集/覆盖 / 生效时间段 / 时区 / 某时刻哪个版本生效」 | 排序后扫描线，只追踪一个「水位线(max end)」；时区先转 UTC 分钟数轴就退化成纯几何 | q04 q29 q36 q37 qA07 |
| **F5 滑动边界/前缀** | 「移动一个分割线 / 一小时内 ≥k 次 / 时间窗口计数 / 关门·摘除时刻」 | 分割线挪一格只改一个元素 → +1/-1 递推 O(n)；窗口用 deque 惰性弹队首 | q08 q23 q39 q40 qA04 qA05 qA13 |
| **F6 堆 + 惰性删除** | 「反复取最小/最闲 / 最小空闲号 / LRU / 10^5–10^6 规模」 | 频繁取最值 + 集合动态增减 = 堆的原生场景；堆存旧快照，取时判版本，过期就扔 | q09 q24 q26 q28 |
| **F7 图与结算** | 「关系可传递 / 多跳最优 / 先修依赖 / 共享标识符 / 把账结平最少转账」 | 先把它读成图（节点+带权边+逆边）；净额化后忘掉原图只剩数字 | q18 q21 q22 q31 q32 qA02 qA08 qA09 qA12 |
| **F8 解析·建模·字符串** | 「CSV join / 归一化 / 畸形输入校验 / 比较器 / 字符串压缩·编辑 / 网格计数」 | 把它翻译成一句 SQL 或一个纯函数；归一化 = 把「相似」降级成「相等」 | q05 q06 q14 q17 q33 q34 qA03 qA10 qA11 |

**跨界速查**（同一题两个脊椎，考场上先认主的、再想副的）：

- 钱 × 图：q21 汇率（乘积最短路 + 整数分）、q22 运费（Dijkstra + 阶梯价）。
- 结算 × 图：q32 资金调拨、qA08 最优账目（都是「净额化 → 组合拆分」）。
- 区间 × 事件流：q37 规则生效时间（版本查找但输入是事件流）。
- 堆 × 区间：q26 AccountScheduler（锁是半开区间，选人是堆）。

> 读法：一次读一个家族。家族内的题**共用同一条脊椎**，连着读能把「变体」看穿。

## 家族 F1 · 事件流重放（可撤销 / 幂等 / 状态机）

**这一族的母题**：一串命令/事件按时间到达，你重放它们、维护状态、最后吐一个快照。
**统治直觉**：*聚合值会骗你*。任何允许「事后撤销一笔 / 重复通知 / 部分退款」的题，都必须
**保留能撤销的最小单元**（`dict[id -> 原始记录]`），聚合数只是它的可增量投影。撤销操作永远是
新增操作的逐字镜像。非法命令一律「先问适用吗，答否就跳过」。看到 DISPUTE / REFUND / REVERSE /
CHANGE / RENEW / 重复 id，就往这条脊椎上靠。

### q01 · 按 MCC 判定欺诈商户
- **题意**：商户配置 + CHARGE/DISPUTE 事件流，按每个 MCC 的欺诈容忍度（计数 or 比例），输出当前被标欺诈的账户。
- **信号**：有 DISPUTE 能撤销一笔 charge；阈值有「计数」和「比例」两种。
- **方向**：账本模型——`charges: dict[id->Charge]` 必存，`apply_dispute` 是 `apply_charge` 的镜像；比例阈值整数交叉相乘。**这是全库第一题，把整套套路演示了一遍。**

### q07 · 订阅通知调度
- **题意**：每个订阅在 3 个时点发邮件；CHANGE 改套餐、RENEW 续期要**重算尚未发出的邮件**，按时间序输出。
- **信号**：「改套餐/续期后重新安排未来的邮件」「已发的不能动」。
- **方向**：每用户只有 3 个待发槽位；核心是一条**锁定线 `since`**——历史不可变，只重写未来。删除已算好的邮件是错的，改的只是边界。

### q10 · PaymentIntent 命令流
- **题意**：重放 API 命令维护每个 payment 的状态机 + 商户余额，输出最终余额；**任何不适用的命令静默忽略**。
- **信号**：「未知 id / 状态不对 / 参数错 → 不输出不崩溃」。
- **方向**：自动售货机——枚举合法 `(命令,状态)->新状态` 转移表，不在表里就 continue。幂等和状态机在这题是同一套代码。

### q11 · 订阅数据库（替换 vs 累加）
- **题意**：`start/end/check`，只有 check 有输出；Part 2 新 start **替换**旧，Part 3 新 start **在到期时间上累加**。
- **信号**：三个 part 只改「新事件怎么改到期日」这一条规则。
- **方向**：每用户一张「到期票」`exp[user]`（`None`=永久，缺=没票）；三个 part 只是 `start` 那步写新值的方式不同，`simulate(mode)` 一个 if 分支搞定。

### q13 · 账户台账（拒透支 + 平台放贷）
- **题意**：credit/debit/transfer 维护余额；Part 2 拒绝负余额，Part 3 platform 放贷/自动还款并报峰值放贷额。 `跨界: F3 钱`
- **信号**：「拒绝会导致负余额的操作」「峰值放贷额」。
- **方向**：单趟流水账，每行只碰几个数字。放贷 = 把 loan 也当成一个账户余额，规则和 credit/debit 同构；峰值就是「欠款总和」的历史 `max()`。**先校验后修改**。

### q25 · 发票对账
- **题意**：把付款匹配到发票；P1 memo 严格、P2 自由文本点名、P3 一笔覆盖多张、P4 审计流水。
- **信号**：「付款 → 匹配发票」「memo 决定能覆盖哪些」。
- **方向**：一根水管往一排水桶（按到期日排）倒水，规则恒为 `min(剩余付款, 桶欠款)`。四个 part 只改「水管能浇到哪些桶」（memo = 点名过滤器）。

### q27 · PaymentLedger（幂等 + 部分退款）
- **题意**：内存台账 add_payment/add_refund/查营收/按日查 + Stripe 风格 balance_transaction 流水。 `跨界: F3 钱`
- **信号**：「幂等键」「按日期分组查询」「滚动余额」。
- **方向**：银行流水打印机。幂等键三态：同 id 同内容=重试吐旧值、同 id 异内容=拒绝。时间戳用**定长零填充字符串**（字符串序=时间序，`ts[:10]`=日期键）。

### q30 · Stripe Capital 贷款记账
- **题意**：维护商户贷款余额，PAY/INCREASE/TRANSACTION_PROCESSED 三种改动，输出总欠款。 `跨界: F3 钱`
- **信号**：「多笔贷款」「超额还款封顶」「不带 loan id 时最老优先」。
- **方向**：两层 dict `merchant->{loan->balance}` 就是账本；三个命令全退化成 `balance = clamp(balance±delta, 0, ∞)`。最老优先靠 dict 插入顺序天然满足。

### q35 · 用户积分 FIFO
- **题意**：从多个 payer 积分；spend 按**时间戳最早优先**消费，返回每个 payer 被扣多少；Part 3 有负数交易修正。
- **信号**：「最早优先消费」「返回扣了谁的」。
- **方向**：每张积分是「盖了时间章的代金券」，状态必须是**一条条独立可变条目**（不能是 payer->余额聚合）。负数交易 = 先撕该 payer 自己最老的券，再统一 FIFO。

### qA06 · LC2043 简单银行系统
- **题意**：`transfer/deposit/withdraw` 返回布尔；Part 2 加流水+撤销，Part 3 加平台授信。 `跨界: F3 钱`
- **信号**：「操作返回成功/失败」「reverse 撤销」。
- **方向**：**先问能不能做、再做**（`_can_debit` / `_debit` 拆两阶段），失败零副作用。reverse = 用当时记录的方向做一次反向交易并重新校验。

## 家族 F2 · 规则引擎（阈值 / 查表 / 优先级匹配）

**母题**：一堆规则，对每条输入判定结果。
**统治直觉**：*把规则当数据，不当 if/elif*。规则做成「谓词列表」或「查找表」，加规则 = 往列表加一项。
上手先分清两种模式：**短路取首**（第一条匹配说了算，如 feature flag、Radar）vs **全评估收集**
（所有规则都跑、收集全部理由码，如 KYC）。看到「默认值 + 覆盖表」就想「按优先级 try 几次查找」。

### q02 · 商户风险评分（三趟规则）
- **题意**：每商户有初始分，按**三趟独立全表扫描**依次应用三条规则，输出最终分。
- **信号**：「某维度第 N 次出现才触发」「三条规则」。
- **方向**：三条流水线，分组维度不同（单笔 / (merchant,customer) / +hour）。看到「第 N 次触发」第一反应是 `Counter` 累加 + 阈值，不是排序切片。

### q12 · 平台余额 + Radar 规则引擎
- **题意**：P1 按 query string 更新余额账本；P2 加 `==`/`!=` 拦截规则；P3 换成真正 Radar 语法（引号、AND/OR、括号）。
- **信号**：「规则从一层 `field OP value` 长成带括号、带优先级的多层」。
- **方向**：语言的演化。P3 到了正则的极限 → 上编译器三段式 `tokenize → parse(AST) → eval`。规则求值 = 短路 + 默认分支。

### q15 · KYC 商户核验
- **题意**：每行商户资料，Part n 应用规则 1..n，**所有规则都评估**（一行可多个理由码），输出 VERIFIED/NOT。
- **信号**：「收集所有理由码」「逐年新增条款」。
- **方向**：合规检查表——不是查到第一条不合格就 return，而是全跑收集。规则 = `(最低part, 码, 谓词)` 三元组列表，加规则=加一项。**全评估模式的典型**。

### q16 · 拒付记录解析 + 撤回
- **题意**：解析拒付记录跳过坏行；`(network, tx_id)` 组里只要有一行是 `withdrawn`，整组不输出。
- **信号**：「整组消失」「撤回和原始行顺序无关」。
- **方向**：两次独立过滤——先丢语法坏行，再按「集合成员关系」判整组（先收集 withdrawn 的 key 集，再过滤）。想成流式匹配就会踩「取消先到」的坑。

### q19 · Accept-Language 解析
- **题意**：给 Accept-Language 头 + 服务端支持列表，返回支持且满足的标签，按偏好从高到低。
- **信号**：「精确标签 > 只有语言 > `*`」「q=0 表示拒绝」。
- **方向**：CSS 选择器优先级模型——越具体权重越高，和出现顺序无关。给每个支持标签算 `(q, 头位置, 列表位置)` 元组排序。q=0 是黑名单不是低权重。

### q38 · 功能开关（灰度 + 依赖）
- **题意**：判断用户对某 flag 是 ON/OFF；四层：kill switch/黑白名单 → 属性规则 → 百分比灰度 → 依赖。
- **信号**：「一层层关卡，某层拦下就出结果」。
- **方向**：海关安检——**顺序即语义**，换顺序就是另一道题。依赖检查最前（地基），allow/deny 中间（你是谁），灰度最后（兜底）。灰度用**稳定哈希桶**（纯函数，无需存状态）。**短路取首模式的典型**。

## 家族 F3 · 钱与舍入（计费 / 费率 / 税率）

**母题**：把钱按规则算出来，且累加 10^5 次分毫不差。
**统治直觉**：*钱是不可分割的整数分*。只要出现除法（proration、比例、费率）就有精度陷阱 → 全程整数分搬运 +
手写 half-up。第二个必考区分：**阶梯(volume/tiered)** = 看总量落哪档、整批按那一档单价；
**累进(graduated)** = 数量像水流过一节节水管，每节按自己单价。把舍入方式当**参数**，不要刻进函数体。
（钱几乎总跟别的家族跨界：见 q13/q21/q22/q27/q30/qA06。）

### q03 · Chat 计费（计量 + 套餐 + 分摊）
- **题意**：每会话按 payg（100 token 一块）或 fixed（$15 含 40k 额度）计费；中途换套餐费用和额度按**会话数占比**分摊。
- **信号**：「含额度」「中途换套餐按比例分摊」。
- **方向**：fixed 额度是个水桶，会话往里倒 token（先 input 后 output），溢出才按 payg 计费。换套餐 = 把桶按会话占比**线性缩小**，其余逻辑不变。整数分 + half-up。

### q20 · 手续费 + 应收 + 对账
- **题意**：P1 按状态算手续费；P2 用 `(provider,country)` 费率表覆盖默认；P3 按 `(merchant,card,date)` 汇总净额；P4 对账两套账本。
- **信号**：「默认费率 + 覆盖表 + 通配符」「同 key 多行合并」「两种舍入同时出现」。
- **方向**：费率查表 + 单遍聚合的管道。覆盖表=按优先级 try 查找；合并=`defaultdict(int)` 摊平；两种舍入=把 `rounding_bias` 当参数（half-up 时 =`scale//2`，floor 时 =0）。

### qA01 · LC2303 累进税
- **题意**：`brackets=[(upper, percent)]`，按累进计税，第 i 档应税 = `min(income, upper_i) - upper_{i-1}`。
- **信号**：「分档」「upper 严格递增」。
- **方向**：一排有容量上限的水杯，收入从下往上倒，每档能装的水量固定（与收入无关）。倒不到的档直接 break。**累进(graduated)的样板题**，对照 q22 的 volume 模式看。

## 家族 F4 · 区间与时间轴

**母题**：一堆区间铺在数轴上，问合并 / 补集 / 覆盖 / 某点落哪段。
**统治直觉**：*排序把二维「谁覆盖谁」压成一维「追踪一个水位线（目前见过的最大 end）」*。
两个杀手锏：① 遇到时区/跨午夜，**先把所有时间转成 UTC 分钟数**，「时区」这个概念就消失，退化成纯几何区间；
② 遇到「某时刻哪个版本生效」，那是**时间轴上的分段常量函数 + bisect 定位**，不是遍历。

### q04 · 卡号区间补空隙
- **题意**：给若干 `[start,end]->brand` 区间，把整个 BIN 范围补满、合并同品牌相邻区间，规范输出。
- **信号**：「补缝隙」「合并相邻」「嵌套区间」。
- **方向**：木板铺数轴——缝由「往左最近、够得着的板」（owner=当前最大 end）来补。四个 part 是同一次排序+单趟扫描的不同截断。

### q29 · 部署窗口（时区 + 区间补集）
- **题意**：各地区本地营业时间 + UTC 偏移，求所有地区都空闲的窗口，从「现在」找前 K 个长 ≥L 的、跳过封禁日。
- **信号**：「时区」「所有地区都不忙的空闲窗口」。
- **方向**：全转 UTC 分钟 → 退化成「区间求并 + 补集」纯几何题。看 D-1/D/D+1 是因为区间可能跨格边界，不是时区特殊。剩下全是背过的 merge-intervals。

### q36 · 时间键值映射（TTL）
- **题意**：`set(key,value,time)` / `get(key,time)` 返回写入时间 ≤ time 的最大那次的值；写入**可能乱序到达**；Part 3 加 TTL。
- **信号**：「返回 ≤ t 的最近一次」「乱序写入」。
- **方向**：每个 key 是一条时间轴上的**分段常量函数**，get 就是「t 落哪段」= `bisect`。TTL 只是给找到的段加个存活判断。

### q37 · 风控规则生效时间
- **题意**：规则有 `effective_from`（+Part3 的 `effective_to`）；请求在时刻 t 是否被拒取决于**当时生效的版本**。 `跨界: F1 事件流`
- **信号**：「当时生效的版本」「不是最新版本」「乱序输入」。
- **方向**：每个规则名是一部「法律」，判案看**案发时刻的现行版本**。同名版本按 effective_from 排序，对每个 t 做历史查询（≤t 的最大），再查是否已被更晚版本废止。

### qA07 · 区间合并 / 覆盖 / 补空隙
- **题意**：P1 合并重叠、P2 数被完全覆盖的、P3 品牌补空隙(=q04)、P4 整数闭区间合并。
- **信号**：「合并 / 覆盖 / 补隙」——区间家族的公式集。
- **方向**：水位线一把梭。合并=橡皮筋能接就拉长；数覆盖=谁 end 追不上水位线就被吃掉（同 start 时 end 降序排避免抢跑）。**这题是 F4 的教科书。**

## 家族 F5 · 滑动边界与前缀递推

**母题**：一根分割线在数轴上滑，或一个时间窗口在流上移。
**统治直觉**：*分割线挪一格，只有一个元素的归属变了* → 罚分/计数是能 +1/-1 递推的量，O(n) 一趟，暴力 O(n²) 是没看穿这一点的产物。时间窗口版则用 **deque 惰性弹队首**（时间只往前走，过期的永远在队头）。
关键区分：**定点邻近**（一小时内 ≥k 次、排序后看 `ts[i+k-1]-ts[i]`）vs **覆盖窗口**（含全部目标的最短区间 = LC76 计数+双指针）。

### q08 · 门店最佳关门时间
- **题意**：关门时刻 t，罚分 = 营业时段的 N 数 + 关门时段的 Y 数，求罚分最小 t（平手取小）；Part 3 从噪声里抠日志。
- **信号**：「选一个分割时刻使某代价最小」。
- **方向**：t 是滑动分割线，右移一格只改一个小时的归属 → +1/-1 递推。平手取小是「从小到大扫、严格更优才更新」的副产品。Part 3 的 BEGIN/END 是开关状态机。

### q23 · 限流器（滑窗 + 令牌桶）
- **题意**：请求按时间到达判 ALLOW/DENY；P1 全局滑窗、P2 按客户、P3 带权重、P4 令牌桶。
- **信号**：「时间窗口内计数超限」「10^6 请求」。
- **方向**：deque 只在头收缩、尾生长，累加和 O(1) 摊还。被拒的请求不入队（否则污染未来窗口）。令牌桶是同一个「惰性按需结算」换方向（补令牌 vs 弹过期）。

### q39 · 服务器运行日志（k 次摘除）
- **题意**：`1`=UP `0`=DOWN，摘除时刻 x；罚分 = 在网期 DOWN 数 + 摘除后 UP 数，求最小；Part 4 最多 k 段。
- **信号**：「选摘除时刻使代价最小」——q08 的镜像。
- **方向**：分界线滑动 +1/-1，O(n) 前缀。Part 4「最多 k 次翻转」→ 按小时展开、按已用次数分层的 DP。

### q40 · 邻近词查询（最小窗口）
- **题意**：P1 首词在 i、其余词都在 `(i, i+k]`；P2 换成含全部查询词的最短连续区间。
- **信号**：「词在某距离内」（定点）vs「含全部词的最短窗口」（覆盖）。
- **方向**：**分界线**——定点查询用倒排表 + bisect（LC243/244 词版）；覆盖查询用 LC76 计数+双指针。两个 part 用不同结构是必然。

### qA04 · LC1169 非法交易
- **题意**：非法 ⟺ 金额>1000，**或**同名交易时间差 ≤60 分且城市不同。
- **信号**：「同名 + 时间窗口 + 异地」= 异地盗刷。
- **方向**：先按 name 分组（必然），组内按时间滑窗 + 城市计数。金额超限和异地是两条独立「或」规则，分开判取并。

### qA05 · LC1604 刷卡告警
- **题意**：某人在任意一小时内刷 ≥3 次就告警，返回排序去重名字。
- **信号**：「任意一小时内 ≥k 次」。
- **方向**：排序后**定长窗口** `ts[i+2]-ts[i] ≤ 60`——把「任意一小时」转成相邻元素比较，O(n²)→O(n log n)。Part 3 实时限流只数「被放行」的。

### qA13 · LC2483 商店最小惩罚
- **题意**：关门时刻 j，惩罚 = 营业段 N 数 + 关门后 Y 数，求最小（平手取早）。
- **信号**：与 q08/q39 同母题。
- **方向**：跷跷板——j 右移一格把一个砝码换盘，一趟前缀扫描。Part 2/3 把 Y/N 记成 +1/-1 → 最大子数组 / k 段子数组；Part 4 权重把 ±1 换成 ±w，架子不变。

## 家族 F6 · 堆 / 优先队列 + 惰性删除

**母题**：反复取「最小/最闲/最久未用」，且集合动态增减，规模 10^5–10^6。
**统治直觉**：*频繁取最值 + 动态增减 = 堆的原生场景*，不用发明新结构。堆里存的是「曾经的快照」而非当前状态，
所以**惰性删除不是补丁，是自然用法**——过期条目留着不影响正确性，取的时候判一下版本/是否作数，作废就扔。
各种约束（粘性、容量、专才）都是叠加在「取最值」这个默认排序上的额外判断，不用单独设计选取逻辑。

### q09 · Jupyter 负载均衡
- **题意**：每个 CONNECT 去当前连接最少的服务器（平手取小下标），带 objectId 要粘同一台，有容量上限，SHUTDOWN 按原序重路由。
- **信号**：「去最闲的那台」「10^n 规模不让你线性扫一圈」。
- **方向**：「谁最闲」= 频繁查最小值 → 堆。堆存旧负载快照，惰性删除。粘性/容量叠在选取上。SHUTDOWN = 把该机连接当一批新 CONNECT 重放，复用 `pick`。

### q24 · 服务器编号分配
- **题意**：主机名=类型+序号，分配取该类型**最小空闲号**，释放后回池；10^6 命令、每操作 O(log n)。
- **信号**：「最小空闲号」「回收复用」「O(log n)」。
- **方向**：停车场——空位回收用最小堆吐最小号；`next`（high-water mark）管从未用过的新号，堆空了才动用它。两条独立水位线。

### q26 · AccountScheduler（锁 + LRU）
- **题意**：账户池 ADD/AVAILABLE/ACQUIRE(带时长锁)/ACQUIRE_ANY(挑最久未用)/RELEASE。 `跨界: F4 区间`
- **信号**：「锁有时长」「自动挑最久未用」。
- **方向**：图书馆借书——锁是半开区间 `[t0,t0+d)`，可用性 = 一次时间比较。ACQUIRE_ANY = 排序（没借过 vs 借过 → 最后借时间 → id）。Part 4 双堆 + 惰性失效。RELEASE 不动 last_used。

### q28 · 任务分派（技能 + 专才 + 容量）
- **题意**：任务逐个派给工人，P1 看负载、P2 加技能、P3 同负载优先技能少的（专才）、P4 加容量。
- **信号**：「每次挑最小负载」「加约束」。
- **方向**：每次弹最小值的优先队列。四个 part = 同一个「取最小」叠三件事：候选收窄（按技能开独立队列）、排序键加维度（元组）、取前多一次校验（容量）。堆 + 惰性失效 = 乐观锁/CAS。

## 家族 F7 · 图与结算（最短路 / 并查集 / 拓扑 / 净额拆分）

**母题**：实体之间有关系，问传递、连通、最优路径、或把账结平。
**统治直觉**：*先把它读成图*——节点、带权边、（除法/汇率类要补）逆边。读成图之后：
可传递关系 → 连通分量（并查集）；多跳最优 → 最短路（乘积最大对数一下、或种类少直接 DFS）；
跳数上限 → 别用原地松弛的 Dijkstra，用**按轮(Bellman)/按层(BFS)** 推进；先修依赖 → 拓扑序/CPM。
结算类（把账结平）有个反直觉关键跳：**净额化后忘掉原始转账图，只剩一组数字**，问题变成「拆成最多个零和子集」的组合搜索。

### q18 · 团伙识别（共享标识符）
- **题意**：两账户共享任一标识符就相连、可传递；P1 直接相连、P2 团伙规模+封禁、P3 风险分、P4 带权记录链接。
- **信号**：「共享设备/卡/邮箱 → 相连」「连接可传递」。
- **方向**：并查集，但**别两两连边(O(k²))**——把每个标识符值当「房间」，房间里的人根都指向房间(O(k))。标识符类型要编码进房间名。P2/3 = 连通分量。

### q21 · 货币转换（多跳最优）
- **题意**：汇率表求任意两货币汇率，先直接、再逆报价、再多跳取**乘积最大**，最后套金额四舍五入到分。 `跨界: F3 钱`
- **信号**：「多跳」「乘积最大」「汇率」。
- **方向**：货币=节点、报价=带权有向边、权重=乘数。求乘积最大路径（货币种类少直接 DFS）。P1→2→3 是同图逐步放松可用边。**选路用 float、算金额用 Decimal**（两件事分开）。

### q22 · 运费（路径 + 阶梯价目表）
- **题意**：A 版求 A→B 运费（限承运商零跳 → ≤1 跳 → 任意跳最便宜）；B 版逐件计价 + 数量阶梯。 `跨界: F3 钱`
- **信号**：「跳数上限从 0 到 1 到 ∞」「数量阶梯」。
- **方向**：同一张邻接表随约束放宽升级：查表 → 有界 BFS → Dijkstra。「直达永远优先」= 业务规则套在图搜索外。B 版 volume vs graduated = 整批一档价 vs 分段水管（对照 qA01）。

### q31 · 心愿单互选排名
- **题意**：判断「互为第一志愿」「同 rank 互选」；Part 2 问把某项提一位会改变哪些配对（**只算不做**）；Part 4 环检测。
- **信号**：「互选（双向都存在才算）」「环」。
- **方向**：一条边要双向都存在才闭合。预建 `pos[u]`（name->rank 反查表）→ 反方向查 O(1)。BUMP 用异或（只关心状态是否翻转）。Part 4 = 有向环 DFS。

### q32 · 资金调拨（最少转账）
- **题意**：一堆账户余额 + 最低额，设计转账让每个都 ≥ 最低；P2 转账次数最少、P3 审计一份清单、P4 加手续费。
- **信号**：「最少转账次数」——结算信号。
- **方向**：分「必须补的坑」和「能借的钱」。P1 可行解按序扫；P2 次数最少 = DFS+剪枝（账户 ≤12 可指数搜）。P3 是逆运算 = 重放+审计。对照 qA08。

### qA02 · LC787 ≤K 跳最便宜航线
- **题意**：有向带权图，最多 k 次中转求最便宜价格。
- **信号**：「最短路 + 跳数上限」。
- **方向**：Dijkstra 不行（它假设第一次到达即最终，无法表达「暂时不合法」）。用 **Bellman-Ford 按轮**（轮数=边数，卡死 k+1）或 **BFS 按层**。核心：**不能让更新跨跳数传播**。

### qA08 · LC465 最优账目结算
- **题意**：一堆借贷记录，求把所有人结平的**最少转账次数**。
- **信号**：「结平」「最少次数」。
- **方向**：净额化 → **忘掉原图只留一组数字**（全题最关键的反直觉跳）。变成「拆成最多个零和子集」的组合搜索（n≤12 → 状压/DFS）。DFS 里「每次必须完全结清一个人」是安全的搜索收缩。

### qA09 · LC2050 并行课程 III
- **题意**：n 任务、先修边、各有耗时，无依赖的可同时开始，求全部完成最短总时间。
- **信号**：「先修依赖（DAG）」「最短完成时间」。
- **方向**：CPM 关键路径——任务最早完成 = 最晚前置决定，DAG → 拓扑序剥洋葱（每节点只定值一次，不需 Bellman 反复迭代）。Part 3 的 tail = 反图上跑一遍。

### qA12 · LC399 除法求值
- **题意**：给 `a/b=v` 等式，回答 `c/d=?`；未知/不连通 → -1.0。
- **信号**：「等式传递」「a/b=v」。
- **方向**：`a/b=v` 是带权有向边（补逆边 `1/v`），查询 = 找路径乘积。少量查询 BFS-per-query；多次查询 → 带权并查集离线（`weight[x]=x/root`）。矛盾报价 = 图带环。

## 家族 F8 · 解析 · 建模 · 字符串

**母题**：把杂乱输入变成干净结构，或做字符串/网格上的变换。这一族没有统一算法，靠**翻译**：
把题面翻成一句 SQL、一个纯函数、一张倒排表、一个比较器。
两个高频套路：**归一化** = 把「字符串相似」降级成「字符串相等」（榨干噪音再 `==`）；
**反过来想** = 与其对每个窗口数里面有几个目标，不如对每个目标数它属于哪几个窗口（qA11）。

### q05 · 卡号校验（Luhn / `*` / `?`）
- **题意**：长度+前缀定卡组、Luhn 定校验；`*`=被涂掉一位（数合法补全数）、`?`=恰好一处错误（改一位或换相邻两位）。
- **信号**：「未知位 + 小搜索空间」「枚举合法原号」。
- **方向**：分类器（查表定卡组，与 Luhn 独立）+ 小规模搜索。`*`/`?` 都是「生成候选 → 复用 P1/2 判定函数过滤」，判定逻辑只写一次。

### q06 · 公司名可用性
- **题意**：按州规则归一化公司名判可用；Part 2 持久占用、Part 3 原注册人回收。
- **信号**：「归一化后判重复」「回收」。
- **方向**：归一化 = 把「相似度」降级成「相等」，做成纯函数、和 registry 状态机解耦。registry 存 `str|None`(注册人) → RECLAIM 三种非法用 `registry.get(c)==acct` 一行挡掉。

### q14 · 数据集 Join
- **题意**：两份 CSV + join 字段，做内/左/一对多连接，输出两表全列。
- **信号**：「join」「内/左连接」「多列排序」。
- **方向**：手写一句 SQL——ON 要先给一表建**哈希索引**（否则 O(n·m)）；LEFT=补空；ORDER BY 多列=元组稳定排序一次；同值用**输入位置**兜底（隐藏 ROW_NUMBER）。

### q17 · 数据中心路由（Haversine）
- **题意**：维护区域注册表（坐标/容量/健康），ROUTE 路由到**最近的、健康的、有容量的**区域并列候选。
- **信号**：「先校验一堆条件才生效」「距离既排序又展示」。
- **方向**：每条命令当**数据库事务**——全校验通过才 commit（先算 `ok` 再落地）。距离有两副面孔：精确 float 排序、`floor(d+0.5)` 整数展示，**别拿舍入值排序**。

### q33 · 分析型数据库（比较器）
- **题意**：记录是 `dict[str,int]`，求某 key 最小的记录 → 加方向 → 抽比较器 → 链式比较器 + 排序。
- **信号**：「min_by_key / 方向 / 抽比较器」。
- **方向**：`compare(a,b)` 是唯一真相，min/first/sort 都是它的消费者（min = 长度 1 的排序）。方向折进 compare 符号翻转。缺 key = 稀疏默认值 0（`.get(key,0)`），非「数据缺失」。

### q34 · URL 压缩（numeronym）
- **题意**：URL 按 `/` 切大段、`.` 切小段，每小段压成 `w[0]+len(middle)+w[-1]`（internationalization→i18n）；Part 2 每大段最多留 m 个小段、多的折成一个。
- **信号**：「首尾锚点 + 中间计数」。
- **方向**：每小段是「两端固定、中间可伸缩的绳子」，只留骨架。折叠 = 同一模型换粒度（把尾部整段当一根更长绳子）。Part 4 解压歧义 = 归并计数（压缩天然多对一）。

### qA03 · LC1087 花括号展开
- **题意**：`{a,b}c{d,e}` 展开成排序去重的全部结果。
- **信号**：「相邻段拼接 + `{}` 多选」。
- **方向**：点餐单——拼接=笛卡尔积(乘)、逗号=并。嵌套用栈（同括号匹配）。Part 4 第 k 个 = 把 k-1 做**混合进制展开**（每位进制不同的里程表），不用真展开。

### qA10 · LC161 一次编辑距离
- **题意**：s 和 t 是否**恰好相差一次编辑**（插/删/换）。
- **信号**：「恰好一次编辑」。
- **方向**：找**分歧点**——之前完全相同，信息压缩在「长度差 0 还是 1」+「分歧后尾巴能否对齐」。长度等→换尾巴、差一→删长的那边一个字符比尾巴。Part 4 带状 DP（`|i-j|≤k`）。

### qA11 · LC2768 黑格块计数
- **题意**：m×n 网格给一批黑格，统计每个 2×2 块含 0/1/2/3/4 个黑格的块各多少。
- **信号**：「网格 + 窗口计数」「坐标稀疏」。
- **方向**：**反过来想**——不是对每个窗口数黑格，而是对每个黑格数它属于哪几个窗口（≤k² 个，与 m,n 无关）。黑格是选民、窗口是候选人，统计每候选人几票。桶 0 用总数减。

# 附 · 30 秒速判流程图

读完题面，按这个顺序问自己：

1. **有「撤销 / 退款 / 重复通知 / 状态转移」吗？** → **F1 事件流**（保留原始记录 dict）。
2. **有「一堆规则 / 阈值 / 默认值+覆盖表」吗？** → **F2 规则引擎**（规则当数据，分清短路 vs 全评估）。
3. **算钱、有除法/proration/阶梯/税率吗？** → **F3 钱**（整数分 + half-up；阶梯 vs 累进）。
4. **有「区间 / 时区 / 生效时间段 / 某点落哪段」吗？** → **F4 区间**（排序+水位线；时区转 UTC 分钟；bisect）。
5. **要「选一个分割时刻 / 时间窗口内计数」吗？** → **F5 滑动边界**（+1/-1 递推；deque）。
6. **反复取「最小/最闲/最久未用」+ 大规模吗？** → **F6 堆**（+ 惰性删除）。
7. **实体间有「传递关系 / 多跳最优 / 依赖 / 结平账」吗？** → **F7 图**（建图；净额化）。
8. **都不是？** → **F8 解析/建模**（翻译成 SQL / 纯函数 / 倒排表 / 比较器）。

> 认错家族不致命——**共性那 6 条起手永远对**。家族只是帮你更快想到那条「统治直觉」。
