## Format facts (triangulated from candidate reports; see `raw/process_and_jd.md` §A)

- **HackerRank OA, 60 minutes hard limit** (2024-09 → 2026 university recruiting and most experienced-hire OAs; a 2024 variant was 75 min = 1 coding + 1 "how would you improve your code" essay; 2019–2021 NG/intern OA was 90 min).
- **ONE problem** per OA (not two, not a LeetCode set).
- **3–5 progressive parts** that unlock only after the previous part's tests pass; each part adds requirements to the same program, so bugs compound.
- **~17–25 test cases** total incl. hidden (reported 14/20, 18/20, 22/25, 16/19, 17/25, ~17). No numeric score shown; partial credit can advance.
- **Not LeetCode**: stdin/string parsing, hash maps, state machines, business rules, exact stdout formatting; code quality is graded. OA problems recycle into the 45–60 min phone screen (3–4 linked parts) and VO coding round.

## Counting rule

`#refs` = number of **independent** reports: distinct candidate posts (LeetCode Discuss, Blind, 1point3acres threads, Reddit, Glassdoor question pages, Medium), distinct GitHub repos/gists with the prompt, question-bank entries (1point3acres 题库, InterviewDB, PracHub) and **dated** aggregator write-ups (csoahelp, programhelp, oavoservice, linkjob, interviewfox…). Aggregator rewrites that obviously copy each other count once (linkjob 2025-09-16 ≡ extrabrain 2026-02-10 ≡ femisowems question5 → 1); one candidate cross-posting counts once; undated SEO lists (lodely, vervecopilot, sumansaurav mocks) are not counted. URLs are copied verbatim from the raw files; reports for which the raw files only give an id (e.g. "1point3acres thread-1163662", "Glassdoor QTN_8763050") are cited by that id — no URL is invented.

## Confidence key

**high** = verbatim/near-verbatim statement from a candidate post or repo, or ≥3 independent sources agreeing on rules · **medium** = paraphrase / consistent details from ≥2 sources / question-bank summary · **low** = single SEO/AI-farm rewrite or title only.

Stage abbreviations: **OA** = HackerRank online assessment · **PS** = technical phone/team screen · **VO** = virtual-onsite coding round · **INT** = integration round · **BUG** = bug-squash round.
