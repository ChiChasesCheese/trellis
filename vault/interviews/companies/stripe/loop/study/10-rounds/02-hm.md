# 02 · HM chat（30–45 min）

> 事实层在 `loop/LOOP_GUIDE.md` §2。题库在 `loop/rounds/02_hm/`。

## 先回答中文圈最常问的那个问题

**考不考技术？**

> **不写代码，但会深挖技术决策。**

所以准备方式跟 behavioral 不一样：你要能把一个技术决策讲给一个**不看你代码的人**听，并且讲清楚为什么当时那样选。

## 三种形态

| 形态 | 谁 | 什么时候 |
|---|---|---|
| 校招 | 独立 30 分钟 "Managerial" 轮 | onsite 之后 3–4 个工作日单独安排 |
| 社招 | onsite 内一轮 45 分钟 | behavioral + 项目深挖 |
| senior | HM 代替 recruiter 打首轮 | 最前面 |

## 会问什么

- **端到端项目**：ideated → pitched → broke down → risk → stakeholders（这五个动词就是提纲）
- deadline / 模糊需求 / 需求变化时你怎么协作
- ownership
- 你的沟通风格
- 出问题时你的反应
- **why Stripe（会再问一遍）**

## 怎么打分

对照 Operating Principles 写 **1–4 分书面反馈** → HC 周会 → **"all thumbs up or rejection"**。

有一手案例：L3 全 hire、**仅一轮 lean-no**，被 C-level 否掉。所以不存在"这轮混过去就行"。

## 端到端项目怎么讲（这是这轮的主菜）

按那五个动词组织，每段一到两句：

1. **Ideated** —— 问题是怎么被发现的？**是你发现的还是被指派的？**（前者分高得多）
2. **Pitched** —— 你怎么说服别人这件事值得做？对方一开始的反对意见是什么？
3. **Broke down** —— 你怎么拆的？为什么这样拆？
4. **Risk** —— 你当时最担心什么？做了什么来降低它？**这一段最容易被跳过，也最能区分人**
5. **Stakeholders** —— 谁受影响？你怎么跟他们对齐的？

然后准备好被追问：**"如果重来一次你会改什么？"**——这个问题几乎必问。

## 挂点 → 对策

| 挂点 | 对策 |
|---|---|
| 故事太长，被打断后接不上 | 准备 90 秒版作为重启点。有一手反馈说 HM "kept interrupting" |
| 只讲技术不讲用户结果 | 每个结果落到用户或业务数字 |
| 无 alternatives / trade-off | "我还考虑过 B，没选是因为……"必须有 |
| 把分歧对方说成傻子 | 先说清对方的理由为什么合理 |
| 术语堆砌 | 有 L4 因为**在 behavioral 里用技术术语**被拒 |

```bash
python3 loop/mock.py bq hm -n 3 -m 3
```

30 道题。练法同 behavioral：**抽题 → 计时开口 → 录音 → 用 `rubric.md` 自评**。

这一轮**必须至少完整讲一遍你的端到端项目并录音**。心里过一遍和嘴上说一遍差距极大，尤其在"risk"那一段——大多数人一到那里就开始含糊。
