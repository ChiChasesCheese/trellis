# 07 · 模板：常用模式

> 前六篇讲的是 Python 怎么写。这一篇讲的是**Stripe 的题反复长成什么样**。
> 配套可运行代码在 `templates/`，全部带自测：
> ```bash
> python3 loop/study/00-prereq/templates/patterns.py     # 九个模式自测
> ```

## 为什么需要模板

本仓库 **92 道题**，底下只有 **25 个业务技能 + 16 个算法靶子**（见 `skills_matrix.md`）。
也就是说你练到第 30 道题的时候，新增的知识量就已经很少了——剩下的全是**同样的骨架换一层皮**。

模板要解决的是这件事：**别每道题都从空白文件重新想一遍结构。**
骨架敲出来只要 3 分钟，但它决定了 part 2、part 3 加需求时你要不要重写。

## 两份模板

### `templates/skeleton.py` —— 多 part 题的骨架

92 道题里 90 道是这个形状：

```
parse  →  model  →  compute  →  render
原始行     记录       业务逻辑     输出字符串
```

**四段必须分开写。** 理由不是"代码整洁"，是 Stripe 的题**做完一个 part 才给下一个**，
而下一个 part 通常只动其中一段。揉在一起 = 每加一个 part 重写一次。

用法：

```bash
cp loop/study/00-prereq/templates/skeleton.py problems/qNN_xxx/starter.py
```

然后从上往下填。里面已经写好了：`PART n` 分发、脏行跳过、格式集中一处、调试走 stderr。

**一个自检信号**：如果你发现 part 2 要改 `parse_records` 才能做——停下来。
多半是 part 1 的模型建窄了（少存了一个字段）。**改模型，别在 compute 里打补丁。**

### `templates/patterns.py` —— 九个高频模式

每个都可直接跑、直接抄，注释里标了它在哪些题出现过、对应哪个 S/A 编号：

| # | 模式 | 出现在 | 编号 | 最容易错的地方 |
|---|---|---|---|---|
| 1 | 分组聚合 | q02 q20 ps06 ps13 | S04 | 写成"每行应用一次规则"→ 加法规则被重复计。**先分组再对组算** |
| 2 | 确定性排序 | 几乎全部 | S08 | tie-break 说不全 → 输出不稳定 → 隐藏测试随机挂 |
| 3 | 滑动窗口 | q23 ps01 ps13 q41 | S16 S12 | 闭区间还是开区间，差一个元素 |
| 4 | 阈值状态翻转 | ps13 q41 q01 | S05 S10 | TRIGGER 和 RESOLVE 的比较**方向相反** |
| 5 | 事件流状态机 | q10 q13 cd02 | S10 S03 | 写成一坨 if-elif；可变默认参数 |
| 6 | 并查集 | q18 ps09 | A16 | —— 20 行，背下来 |
| 7 | 有界 BFS | ps09 | A16 | 限跳数和不限跳数是两个实现，part 递进常考 |
| 8 | 金额 | q03 q13 q20 q21 q22 | S06 | float 累加漂移；`round()` 是**银行家舍入** |
| 9 | 区间合并 | q04 q29 | S13 A09 | 闭/开区间决定 `<=` 还是 `<` |

## 怎么用这两份模板

**第一阶段（现在）**：打开 `patterns.py`，**照着重敲一遍**。不要复制粘贴——手敲。
敲到第 3 个你就会发现 `defaultdict`、`sorted(key=)`、`deque` 这些不用想了。

**第二阶段**：做题时遇到卡壳，回来查表——"这题是分组聚合 + 确定性排序"，
直接抄那两段，把注意力留给业务规则。

**第三阶段（面试前一周）**：不看模板，默写骨架 + 任意三个模式。
默写不出来的那个，就是你还没内化的。

## 一个真实的例子

写这份模板时，我给滑动窗口那段的自测断言写成了：

```python
assert sliding_window_counts([(1, "u"), (2, "u"), (5, "u")], 3) == [..., (5, "u", 2)]
```

跑出来红了。window=3 时 ts=5 的窗口是闭区间 `[5-3+1, 5] = [3, 5]`，ts=1 和 ts=2 都在窗外，
**答案是 1 不是 2**。

代码是对的，我的预期是错的。这个断言现在留在文件里，旁边写着这段注释。

**off-by-one 就是这么发生的**——不是因为不会，是因为没有在纸上把边界代进去算一遍。
所以模板里每个涉及边界的地方，都逼你先回答"闭区间还是开区间"。
