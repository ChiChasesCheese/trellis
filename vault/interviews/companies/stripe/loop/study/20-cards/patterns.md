# 卡片 · 解题模式（Stripe 题库的可迁移套路）

> 53 道 OA 题 + 20 道 loop 题，底下只有 **25 个业务技能 + 16 个算法靶子**（`skills_matrix.md`）。
> 这份卡片记的是**跨题复用的模式**：下次遇到同族题，第一步做什么。
> 每条尽量给出"哪几道题在练它"，方便回去翻实现。
> 格式：`| Q | A | 哪些题 |`

## 建模：把一段业务白话变成数据结构

| Q | A | 哪些题 |
|---|---|---|
| 拿到一大段题面，前 5 分钟做什么？ | **读完全部 part 再动手**。后面的 part 会反噬前面的数据结构——先看到 part 3 才知道 part 1 该不该建类 | 全部；S01 |
| 一句话建模的模板长什么样？ | "这是一个 **按 X 分组** 的 **Y** 问题"（如"按用户分组的时间窗口计数"）。说不出这一句就别动手 | 全部；S03 |
| 电面和 VO coding 建模的差别？ | 电面像脚本题（函数 + dict 够了）；**VO coding 期望你先写类和接口签名再填实现** | cd 系列 |
| 什么时候该建类而不是用 dict？ | 同一个实体要在多个 part 之间携带状态、或要加方法时。纯查表用 dict | q10 q13 cd02 |
| 输入是"命令流"时的通用形状？ | `dispatch = {"CREATE": self._create, ...}`，每个 handler 只管一件事；主循环只负责分发 | q10 q13 q30 |
| 规则表（rate table / 优先级表）放哪？ | 抽成模块级常量或一个 dict，**不要 if-elif 堆在逻辑里**——part 2 加规则时就体现出差别 | q20 q02 q12 |

## 分组聚合

| Q | A | 哪些题 |
|---|---|---|
| 按 key 分组累加的标准写法？ | `from collections import defaultdict; agg[key] += value`。别先 `if key not in` | q02 q20 ps13 |
| 分组后"每组应用一次规则"最容易错在哪？ | 写成每行应用一次 → 加法规则被重复计。**先分组，再对组算** | q02（#1 失败原因） |
| 多字段分组的 key 怎么写？ | 元组：`(merchant_id, card_type, payout_date)`。元组可哈希、天然有序 | q20 ps06 |
| 要"分组后取每组最大的一个"？ | `max(group, key=...)`，或边扫边比。别先全排序 | q09 q28 |
| 计数 + 取 TopK？ | `collections.Counter` + `heapq.nlargest(k, ...)`，tie-break 写进 key | q09 ps01 |

## 阈值与状态翻转

| Q | A | 哪些题 |
|---|---|---|
| 看到"达到 N 次就……"，第一件事做什么？ | **确认 `>` 还是 `>=`**，并在代码里写死注释。这一个字符能翻掉一半隐藏测试 | q01 q02 ps13；S05 |
| "计数"和"比率"两种阈值的坑？ | 比率要处理分母为 0；而且题目常在 part 2 从计数切成比率，别把 part 1 的实现写死 | q01 |
| TRIGGER / RESOLVE 这类成对事件，最容易出的 bug？ | 两个方向的比较**严格性正好相反**（升破用 `>=`、回落用 `<`），照抄一个方向必错 | ps13 q41 |
| 怎么避免重复发同向事件？ | 记住"当前是否已处于告警态"，只在**状态翻转**的那一刻发 | ps13 q41；S10 |
| "最小成交量门槛"这类前置条件放哪？ | 放在规则判断最前面，且要想清楚"不满足门槛"是跳过还是算 0 | q02 |

## 时间与窗口

| Q | A | 哪些题 |
|---|---|---|
| 滑动窗口计数的标准结构？ | 每个 key 一个 `deque`，新事件进队后从左边弹出所有过期的 | q23 ps01 ps13；S16 |
| 窗口边界是闭区间还是开区间？ | **题面不说就问 / 自己定死并写在注释里**。`[t-w+1, t]` 和 `(t-w, t]` 差一个元素 | ps13 q23 |
| 滚动窗口（tumbling）和滑动窗口（sliding）的区别？ | 滚动不重叠（size == step）；滑动重叠（step < size） | q41 |
| 事件乱序到达怎么办？ | 要么先全排序，要么用 watermark 丢弃过迟的。**先问面试官允不允许乱序** | q41 ps13 |
| 月末锚定日期怎么处理？ | 1 月 31 日 + 1 月 = 2 月 28/29 日，要 clamp。别用 `day+30` | q07 cd01；S12 |
| 跨时区的窗口题第一步？ | 全部转成 UTC 再算，最后再转回展示时区 | q29 |

## 排序与输出格式

| Q | A | 哪些题 |
|---|---|---|
| 排序 tie-break 没写全会怎样？ | 输出不稳定，隐藏测试随机挂。**每个 sorted 都要能说出完整的 key** | 几乎全部；S08 |
| 多级排序的写法？ | `sorted(rows, key=lambda r: (r.a, r.b, r.c))`；要混升降序就用负号或分两次稳定排序 | q01 q20 |
| 字符串排序和数字排序的坑？ | `"10" < "9"` 是 True。日期做字符串排序只在 `YYYY-MM-DD` 格式下才等价于时间排序 | q20 q29 |
| 输出格式该放哪？ | **集中到一个 `_format()` 函数**。part 3 改格式时只改一处 | 全部；S09 |
| 为什么格式题比看起来难？ | Stripe 逐字节比对。多一个逗号、行尾多个空格、少一个换行都算错 | ps12 cd08–cd10 |
| 空结果要不要打表头？ | **题面明说的就照做，没说就问**。q20 的 part 3 明确要求"没有行也要打表头" | q20 |

## 金额

| Q | A | 哪些题 |
|---|---|---|
| 金额用什么类型？ | **整数最小单位（分）**，或 `Decimal` 且显式指定舍入模式。**永远不要 float 累加** | q03 q13 q20 q21 q22；S06 |
| 舍入规则要注意什么？ | half-up 还是银行家舍入要问清；Python 的 `round()` 是**银行家舍入**（`round(2.5) == 2`） | q03 q20 |
| 舍入该在哪一步做？ | 尽量**最后一步再舍**，中间保持精度；如果题面要求每步舍就必须每步舍——问清楚 | q20 q22 |
| 百分比费率怎么存？ | 用 basis points（万分之一）整数存，如 `290` = 2.9%，避免浮点 | q20 |
| 分档 / 阶梯计价的两种语义？ | graduated（每档各算）vs volume（按总量落到某一档全额算）——**两者结果不同，必须问清** | q03 q22；S07 |

## 图与连通性

| Q | A | 哪些题 |
|---|---|---|
| "谁和谁有关联"类题的标配数据结构？ | 并查集（union-find），或邻接表 + BFS | q18 ps09；A16 |
| 并查集最小实现？ | `parent` dict + `find` 带路径压缩 + `union`。20 行以内 | q18 |
| 求"完整关联群体"该用什么？ | 连通分量（并查集或 BFS 全遍历），不是一跳邻居 | ps09 part 3 |
| "≤2 跳"和"完整连通分量"的区别？ | 前者是**有界 BFS**（层数限制），后者是无界。part 递进常从 1 跳 → 2 跳 → 全量 | ps09 |
| 汇率 / 换算链路题的通用解法？ | 图上求路径乘积：BFS/DFS 记录累乘，或 Floyd 求全对 | q21 qA12；A02 |
| 带 ≤K 跳限制的最短路？ | Bellman-Ford 按轮松弛（每轮 = 多走一跳），不是 Dijkstra | q22 qA02；A03 |

## 解析

| Q | A | 哪些题 |
|---|---|---|
| 逐行解析的标准骨架？ | `parse_records(lines) -> list[Record]` 单独一个函数，**不要和业务逻辑揉一起**——part 2 就改不动了 | 全部；S02 S19 |
| 按列名取字段还是按位置？ | **按列名**（`csv.DictReader`）。题面常说"列顺序任意、可能有多余列" | q20 ps06 |
| 脏行怎么处理？ | 先问是丢弃、报错还是计入统计。**这三种做法结果完全不同** | q15 q16；S18 |
| 缩进敏感的格式（YAML 类）怎么解析？ | 先 tokenize 成 `(indent, kind, payload)` 记录，再按缩进递归下降。**不要边读边建树** | bs03 ps12 |
| 树形结构的输出怎么写？ | 递归渲染器 + 一个"前缀栈"传下去，最后一个孩子用 `└─` 其余 `├─` | ps12 |

## 分层设计（这是 Stripe 最看重的那一条）

| Q | A | 哪些题 |
|---|---|---|
| 一个 multi-part 题的标准分层？ | `parse → model → compute → render` 四段各自独立函数 | 全部；S19 |
| 为什么这样分？ | part N+1 通常只动其中一段。揉在一起 = 每加一个 part 就重写一次 | LOOP_GUIDE §3 |
| 先写什么才不会卡？ | **骨架先行**：`main()` 读入 → 解析 → 调 `part1`（空实现）→ 打印。先让整条链路跑通 | 全部 |
| 每个 part 写完立刻做什么？ | 写 2–3 个自测 `assert`，跑题面样例。**这轮没有自动测例** | LOOP_GUIDE §3；S20 |
| 时间不够时优先保什么？ | 保**代码质量和已完成 part 的正确性**，不是硬凑最后一个 part。"quality over speed"是官方 prep 材料原话 | LOOP_GUIDE §3 |
| 做不完怎么办？ | **口头说思路**——真实面经里"写完两个 part，第三个口头说思路"当天就过了 | 面经 2026 |
