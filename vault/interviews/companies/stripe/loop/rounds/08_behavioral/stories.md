# STAR-L 六故事表 + Operating Principles 覆盖矩阵（Behavioral 轮）

> 这是 Behavioral 轮的核心备考产出。**这 6 个故事和 recruiter / HM 轮共用同一套**——
> 差别只在讲多长、被打断后怎么接、要不要主动扣回 Operating Principles 的措辞。
> 三个轮次的 `stories.md` 内容一致，分别放在 `01_recruiter/`、`02_hm/`、`08_behavioral/`
> 是为了让你在演练对应轮次时（`mock.py bq <round>`）不用跳目录找模板。
>
> **这里不替你编故事**——下面每个槽位只给"这个故事必须包含什么"的清单和一个
> **空白骨架**，你自己填。不要用虚构经历，也不要用别人的故事。

---

## STAR-L 模板（来源：`loop/raw/hr_hm_behavioral.md` §题库总表）

```
S  Situation   1–2 句。背景、规模、利益相关方、为什么难。（≤15% 时长）
T  Task        1 句。你个人的职责/目标；用 "I" 不用 "we"。（≤10%）
A  Action      3–5 个动作，按时间或按"alternatives→决策→执行"展开。
               每个动作说清「为什么这样选、放弃了什么」。（≥50%，这是重点）
R  Result      量化：延迟/错误率/收入/用户数/时间；也说明副作用。（15%）
L  Learning    你今天会怎么做不同；这个教训之后在哪里用上了。（10%）
```

**Stripe 特化四条硬要求**（少一条都会被记成"故事单薄"）：
1. A 段必须含 trade-off 与 alternatives——被问"你还考虑过什么方案、为什么放弃"要能立刻接上。
2. R 段必须回到用户（users first）——商户/开发者/内部同事受到的可见影响，不能只讲"上线了"。
3. L 段必须含"寻求反馈"的证据——谁给你提了意见、你怎么改的。
4. 少术语、多决策——讲清"为什么"比讲清"技术细节"重要（Blind kt6bwgwv 的真实反例）。

## 六个故事槽位

> 每个槽位分两部分：①「这个故事必须包含什么」自检清单 ②「空白骨架」——只填框架提示，不代入任何具体经历。

### 槽位 1 · Ownership（端到端负责，从头扛到尾）

**必须包含**：
- [ ] 这件事在正式职责范围内还是超出了？如果是本职内，端到端的证据是什么（需求→上线→运维你都在）？
- [ ] 有没有一个环节你本可以甩给别人但没有甩？
- [ ] Result 里有没有"如果我没扛，会发生什么"的对比？

**骨架**：
```
S: 我在 ___（团队/项目）负责 ___，当时的情况是 ___（为什么难/为什么重要）。
T: 我的职责是 ___（用"I"）。
A1: 我先做的是 ___，因为 ___（排除了 ___ 方案，原因是 ___）。
A2: 接着遇到 ___ 问题，我 ___。
A3: 最后我还主动做了 ___（本不在职责范围内的部分）。
R: 结果是 ___（量化），对用户/团队的影响是 ___。
L: 如果重来，我会 ___；这个教训我后来在 ___ 用上了。
```
**自检问题**：这个故事里，如果把"我"换成"我们团队"，句子还成立吗？如果成立，说明 ownership 不够个人化，需要换故事或换角度重讲。

### 槽位 2 · 冲突 / 分歧

**必须包含**：
- [ ] 对方的立场你能不能公正地转述（不是"对方错了"，是"对方当时基于什么理由"）？
- [ ] 你做了什么具体动作去化解，而不是等它自己消失？
- [ ] 最后是你说服了对方、对方说服了你、还是找到了第三方案？三种都可以，但要讲清楚。

**骨架**：
```
S: 我和 ___（同事/经理/团队）在 ___ 问题上有分歧，对方的立场是 ___（公正转述），我的立场是 ___。
T: 我需要 ___。
A1: 我先 ___（比如：约了 1:1、拉了数据、写了文档）。
A2: 对方反馈 ___，我 ___。
A3: 最终我们 ___（谁改变了立场，或者达成了什么折中）。
R: 结果 ___；关系后续 ___。
L: 我学到 ___。
```
**自检问题**：讲完这个故事，一个没参与过的人会不会觉得"对方也有道理"？如果对方在你嘴里完全是反派，重讲。

### 槽位 3 · 失败

**必须包含**：
- [ ] 这是不是一个真正让你难受的失败（不是"我本可以做得更好"级别的小事）？
- [ ] 归因里有没有你自己的责任（不是 100% 甩锅给外部）？
- [ ] 后续有没有具体改变了什么（流程/习惯/检查清单）？

**骨架**：
```
S: 当时 ___，我负责 ___。
T: 目标是 ___。
A: 我做了 ___，但没有 ___（说明当时的判断失误在哪）。
R: 结果是 ___（真实的负面影响，别美化）。
L: 我后来意识到 ___，并且把这个教训用到了 ___（具体的后续场景，最好能引用到另一个故事的开头）。
```
**自检问题**：这个失败案例，招聘方听完会不会觉得"这人不敢讲真事"？如果太轻，换一个更真实但仍可控的案例。

### 槽位 4 · 模糊 / 紧迫

**必须包含**：
- [ ] 当时到底缺什么信息，或者为什么"一切都紧急"？
- [ ] 你用什么原则做的排序/决策（不是"感觉"）？
- [ ] 后续证明这个决策是否正确？如果错了，怎么发现并纠正的？

**骨架**：
```
S: 当时情况是 ___（信息不全/多头紧急的具体表现）。
T: 我需要在 ___ 时间内决定 ___。
A1: 我先排除了 ___ 方案，原因是 ___。
A2: 我用 ___（原则/数据/优先级框架）决定先做 ___。
A3: 执行中发现 ___，我调整为 ___。
R: 结果 ___。
L: ___。
```
**自检问题**：如果面试官打断问"那如果信息还是不全你怎么办"，你能不能立刻讲出你当时定的"止损线"？

### 槽位 5 · 质量 / Craft

**必须包含**：
- [ ] 具体的质量手段是什么（测试/code review/监控/文档/边界情况处理）？
- [ ] 有没有为了质量牺牲过速度（返工、推迟发布）？
- [ ] Result 里有没有"如果没做这些，会出什么问题"的反事实？

**骨架**：
```
S: 当时的交付压力是 ___，但我认为质量上需要 ___。
T: 我的目标是 ___。
A1: 我加入了 ___（具体质量手段）。
A2: 这导致 ___（比如推迟了多久，或者和谁产生了张力）。
A3: 我是怎么说服/权衡的：___。
R: 结果 ___（有没有线上事故被提前拦住的证据）。
L: ___。
```
**自检问题**：这个故事里"quality"是不是只停留在"我很仔细"，还是有可验证的具体动作？

### 槽位 6 · 学习 / 好奇

**必须包含**：
- [ ] 你主动学习的是什么陌生领域/技术（不是被指派的培训）？
- [ ] 学习过程中具体做了什么（读源码/RFC/请教人）？
- [ ] 学完之后用在了什么地方？

**骨架**：
```
S: 当时我对 ___ 领域完全不熟悉，但项目需要 ___。
T: 我需要在 ___ 时间内掌握到能 ___ 的程度。
A1: 我先 ___（读文档/找人请教/搭 demo）。
A2: 遇到的最大困难是 ___，我 ___。
R: 最终我能 ___，产出是 ___。
L: ___。
```
**自检问题**：这个故事是不是"舒适区内"的项目？如果技术栈/领域你早就熟，换一个真正陌生的经历。

## Operating Principles 覆盖矩阵

> 用官方 6 条对外原则（`stripe.com/jobs/culture`，2026-09-03 复核无变化）做行；6 个故事做列。
> 每讲完一个故事，回头打勾——这个故事有没有明显命中某条原则。**目标：每一行至少 1 个勾，
> 每一列至少 2–3 个勾**（一个故事命中多条原则是正常的，甚至是好事）。

| Operating Principle（官方原文节选） | ① Ownership | ② 冲突 | ③ 失败 | ④ 模糊/紧迫 | ⑤ 质量 | ⑥ 学习 |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| **Users first** — "Our users trust us to provide an essential service, and it's a heavy responsibility." | ☐ | ☐ | ☐ | ☐ | ☐ | ☐ |
| **Create with craft and beauty** — "With careful thought, anything can be made surprisingly great." | ☐ | ☐ | ☐ | ☐ | ☐ | ☐ |
| **Move with urgency and focus** — "We move with speed on what matters most." | ☐ | ☐ | ☐ | ☐ | ☐ | ☐ |
| **Collaborate egolessly** — "We work as one team: no fiefdoms, no hoarding information." | ☐ | ☐ | ☐ | ☐ | ☐ | ☐ |
| **Stay curious** — "We're energized by the unfamiliar, preferring the joy of discovery to the comfort of certainty." | ☐ | ☐ | ☐ | ☐ | ☐ | ☐ |
| **Obsess over talent** — "It's every Stripe's responsibility to help hire the best." | ☐ | ☐ | ☐ | ☐ | ☐ | ☐ |

**用法**：讲完一遍六个故事后，如果发现某一行全空（比如 "Obsess over talent" 没有任何故事命中），
说明你缺一个"mentoring/帮同伴/参与招聘"的故事——回去改写⑥学习槽位，加一段"我怎么帮别人学"。
如果某一列全空（某个故事命中不了任何原则），说明这个故事太泛，换一个更具体的。

### 扩展矩阵（内部完整版 15 条，可选，来源同上文件 §Operating Principles 版本 B）

如果 6 条对外版覆盖太容易全打勾，用内部版做更严格的自查：
**How we work**（Users first / Move with urgency and focus / Be meticulous in your craft / Seek feedback / Deliver outstanding results）
**Who we are**（Curious / Resilient / Humble / Macro-optimistic / Exothermic）
**Leaders at Stripe**（Obsess over talent / Elevate ambitions / Set the pace and energy / Make decisions and be accountable / Lead with clarity and context / Solve problems——校招/IC 可弱化这组）。
拿同一张表把行换成这 15 条，再打一遍勾，通常会暴露"Seek feedback"和"Resilient"两列最容易空。

## 90 秒版 vs 3 分钟版：结构差异

> 依据：Blind wexjj3xy——HM 会不断打断换问题，"kept interrupting to ask different things"；
> 每个故事必须能被打断后从任意一点续接。

| 部分 | 90 秒版（HM 常打断，recruiter 电话开场） | 3 分钟版（Behavioral 轮完整版） |
|---|---|---|
| Situation | 1 句，只给"是什么项目、为什么重要"，不铺垫 | 2 句，加规模/干系人 |
| Task | 1 句 | 1 句，同 90 秒版 |
| Action | **压缩成 1–2 个最关键动作**，跳过次要步骤；心里要清楚被追问哪个动作能展开 | 完整 3–5 个动作，每个都讲"为什么这样选、放弃了什么" |
| Result | 1 个最重要的量化数字 | 完整数字 + 副作用 + 用户影响 |
| Learning | 省略或一句带过 | 完整讲，且要连回"后来用在哪" |
| 应对打断 | 提前想好：如果被追问 Action 里的某一步，能不能单独展开成 30 秒 | 如果 3 分钟还没讲完被打断，说明这个故事本身该精简 |

**练习方法**：对每个故事，先写 3 分钟版全文，再删到 90 秒版，最后自己掐表读一遍——
90 秒版读出来控制在 100–110 秒（留出面试官插话的余地），3 分钟版控制在 165–180 秒。
