# 评分 rubric（Exponent 五维，1–4 分/维，满分 20）

> 依据 `loop/LOOP_GUIDE.md` §7、`loop/raw/system_design.md` §4.3、systemdesignhandbook 与 Stripe 官方 Ledger 博客（2024-02-16）。Exponent 称这是「Stripe 的招牌题」，因为它直接考察候选人是否真正理解"钱"这个领域和普通业务数据的本质区别。

## 1. Problem framing

- **1 分**：把这道题当成普通的"账户余额表 + 转账"设计，第一反应是"我用一张 accounts 表存 balance 字段，转账时 update 两行"，没有意识到题目在暗示不可变性和可审计性。
- **4 分**：从题面里准确识别出这是一个**双记账（double-entry）不可变账本**问题，两句话复述："每一笔资金移动都要留下不可篡改的记录，能随时证明所有钱的去向，并且自动发现任何对不上的地方"；显式说出不变量——**借贷恒等**（每笔交易内 Σdebit = Σcredit）、**历史不可变**（只能追加反冲，不能改写）、**完整性**（每一个产生资金变化的业务事件都必须有对应的账本记录）。

## 2. API & data model（权重最高）

- **1 分**：只设计了一张 `transactions(from, to, amount)` 表，没有区分"账户"和"分录"的概念；余额直接存一个可变字段并直接 UPDATE；没有考虑多币种下怎么平账。
- **4 分**：清楚区分 **accounts**（资金的"桶"，按类型/币种分类，如 clearing、merchant_pending、merchant_available、fee_revenue）、**transactions**（一次业务事件，带唯一的 `external_id` 用于幂等摄取）、**entries**（不可变的借贷分录，属于某个 transaction 且指向某个 account）；能写出一个真实的分录示例（如"客户付款 $100，手续费 $3"如何拆成三条分录）；金额用整数最小货币单位，每种货币独立平衡。

## 3. Failure modes & scale

- **1 分**：对"某个账户写入非常频繁"这种场景没有对策，默认所有写入都要更新同一行余额；没有考虑历史某一时刻余额怎么查询；多币种/汇率损益账户完全没提。
- **4 分**：讲清楚**只追加 entries、不在写路径上更新单行余额**是应对热点账户的核心手段，余额是异步物化/可重建的派生数据；讨论按账户所属主体分片；历史余额通过"最近快照 + 之后的增量 entries 求和"高效计算；多币种下每个币种独立平衡，跨币种交易通过 FX clearing 账户加汇率损益账户处理，保证任何单一币种都不会凭空增减。

## 4. Separation of concerns

- **1 分**：业务系统直接写 ledger 的表，读写路径和权限没有边界；对账逻辑和记账逻辑混在一起。
- **4 分**：业务系统通过 outbox 向账本"发布"事件，账本是被动摄取方而不是被随意直接改写的共享数据库；实时余额查询走物化表（快路径），历史报表/大范围对账走离线的 OLAP 副本（慢路径），两者不共享同一套读压力；写入幂等由 `external_id` 唯一约束保证，与账户余额计算逻辑解耦。

## 5. Delivery beyond the diagram

- **1 分**：没有谈到怎么持续验证系统的正确性，好像上线之后账目自动就是对的。
- **4 分**：讲到 Stripe 官方提出的三项持续校验——**及时性**（数据摄取延迟有硬阈值）、**完整性**（每个业务系统的每个 ID 都能在账本里找到对应记录）、**清账**（clearing 类账户理论上应该归零，非零即报警）；讲到监控指标（摄取延迟 p99、clearing 非零账户数、完整性缺失率）；讲到修正错误分录时用"反冲追加"而不是直接改写的操作规范。

## 一条相关引用（体现"钱"这个领域的特殊性）

> Stripe 官方 Ledger 博客（2024-02-16）称其账本系统追求 **">99.9999% 的资金流向可解释性"**；另一处引用（Better Engineers，2026-07-23）说得更直白："Money is the one domain where 'eventually consistent' is not a strategy — it's a liability"（钱是这样一个领域：'最终一致'不是一种策略，而是一种负债）。候选人如果全程都在用"一般分布式系统"的默认思路（比如轻描淡写地说"最终一致就行"）而不去讨论"如何证明账是平的"，通常拿不到这一维的高分。
