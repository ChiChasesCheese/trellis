# Ledger service

公司里有很多个不同的系统会产生跟钱有关的动作：有人给商户扣了一笔款、扣了手续费、发起了一笔退款、把钱结算到了商户的银行账户、两个货币之间做了兑换……这些系统各自维护自己的业务状态就够了，但公司整体需要有一个地方能够回答"到底每一分钱现在在哪里、经历过什么"这种问题，无论是给财务部门做报表、给审计提供依据，还是万一哪天银行那边说"我们收到的钱和你们说的对不上"，我们都要能拿出一份完整、可信、任何人（包括我们自己）都无法悄悄修改的记录来解释资金的流转过程。这个记录系统每天要承接海量的资金变动事件，很多商户的账户资金变动极其频繁，我们不希望因为要更新某一个账户的余额而把这个账户的所有写操作都串行化排队、变成整个系统的瓶颈。同时钱是分很多种货币的，一笔涉及汇率兑换的交易理论上不应该让任何一种货币"凭空多出来"或者"凭空消失"，即便某天某个上游系统的数据出了错，我们也希望能第一时间自动发现"哪里有钱对不上"，而不是等到季度审计的时候才发现问题；而且历史记录一旦生成，哪怕后来发现记错了，也不能直接改这条记录，而是要用一种大家都能理解和追溯的方式去"修正"它。请设计这样一个记账系统。

---

**面试环境说明**：Stripe onsite System Design 轮，45 分钟（含开场与结尾提问，真正设计时间约 30–35 分钟），Whimsical 白板，无代码环境。题面不会告诉你"这是双记账 ledger"这几个字，你需要自己从"任何人都不能悄悄修改历史记录""钱不能凭空出现或消失"这些描述里识别出这是一个需要不可变、借贷平衡设计的记账系统。面试官会在你画出基本结构后，用高吞吐热点账户、多币种、对账、历史某一时刻余额查询等场景来考察设计的健壮性。
