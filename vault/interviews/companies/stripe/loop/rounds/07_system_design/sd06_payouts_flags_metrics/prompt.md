# 短题三连：Connect 分账/payouts · Feature flag SDK · Metrics counter library

有些面试官不会用一整个 45 分钟只问一道大题，而是准备三道相对短小、彼此独立的问题，按顺序抛给你，每道题给大概十分钟左右深入讨论，重点考察你能不能快速抓住每道题的核心矛盾并给出一个说得通的设计，而不是每道题都要求你画出完整的生产级架构图。今天你会遇到的就是这样的一轮，一共三道题，按顺序来。

第一道：我们的平台允许第三方开发者接入之后，代表他们自己的商户收款，收款之后要把钱按约定比例分给一个或多个"连接账户"（也就是这些商户自己），连接账户再定期把钱提现到自己的银行卡上。这中间涉及到平台自己的账户余额和每个连接账户各自的余额都要准确反映"现在有多少钱、有多少钱还在结算中不能动"，也要处理提现失败、银行退回、账户余额意外变成负数这些情况，请说说你会怎么设计这一部分。

第二道：公司内部有几十个服务团队，他们都想要一种能够在不重新部署代码的情况下，随时给一部分用户打开或者关闭某个新功能的能力，有的团队希望按用户 ID 的百分比灰度，有的希望按账户所在地区开关，还有的希望能一键把出问题的新功能立刻全部关掉。这个开关判断会在每个服务的每一次请求里被调用很多次，判断本身的延迟必须非常低，请说说你会怎么设计这套功能开关（feature flag）系统，包括开发者怎么用它。

第三道：我们有大量的服务实例分布在很多台机器上，每个服务都想上报一些简单的数字指标——比如某个接口被调用了多少次、耗时分布是什么样、错误发生了多少次——这些指标最终要能被聚合起来，让工程师可以在一个统一的地方按时间看趋势、设置告警阈值。请说说你会怎么设计这个指标采集和聚合的系统。

---

**面试环境说明**：Stripe onsite System Design 轮，45 分钟（含开场与结尾提问），Whimsical 白板，无代码环境。这是该轮的一种真实变体——面试官不出一道大题，而是连续问三道相对独立的短题，每题给大约 10 分钟左右深入，剩下时间留给追问与收尾。三道题各自独立评分，但共用同一套 Exponent 五维 rubric；面试官通常期待你能在有限时间内快速切入每道题最核心的矛盾点，而不是每道题都尝试面面俱到。
