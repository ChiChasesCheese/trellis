# 03 · 面试流程（每一轮考什么、怎么准备）

Cerebras 的面试按团队定，形式不完全统一，但这个组织的软件岗大体是：招聘官电话 → 经理面 45 分钟 → 三轮左右的技术面（每轮约 45 分钟，偏 Python）→ 一两天内给反馈 → offer 由 CEO 签字。编码题偏简单，技术深挖问的是"这份工作每天要用的东西"，不考抽象难题。测试岗还会问机器学习基础和测试思路。这页按轮次讲：形式、考什么、常见题、怎么准备、复习哪部分卡片。

## 0. 流程一览

| 步骤 | 形式 | 谁 | 考什么 |
|---|---|---|---|
| 招聘官电话 | 15–30 分钟 | 招聘官 | 背景、兴趣、时间安排 |
| **经理面** | **45 分钟**，视频 | 招聘经理或技术负责人 | 过往项目和当时的技术决策、兴趣是否对得上团队、沟通 |
| 技术面 | 3 轮 × 约 45 分钟，HackerRank 上写代码 | 工程师 | 编码（语言自选）+ 和岗位相关的技术深挖；**Python 是重点** |
| 经理轮（有时） | 45 分钟，Microsoft Teams | 招聘经理 | 自由聊：沟通、团队合作、解决问题的风格 |
| 允许用 AI 的轮次（有时） | 提前通知 | 工程师 | 在真实的代码库、服务或数据集上完成任务，再讨论能不能上生产 |
| 反馈与 offer | 24–48 小时反馈 | — | 多数 offer 要 CEO 签字；全程 2 周到 2 个月 |

- **按团队定**：有的团队面 6 轮再加 4 轮现场，有的只有 4 轮（2 编码 + 2 背景问题）。经理面时直接问"后面几轮各考什么"。
- **形式可能没说清**：招聘官和经理有时对"这是聊天还是技术面"理解不一样。电话前问清：要不要写代码、用什么平台、谁来面。
- **平台**：编码在 HackerRank，视频在 Microsoft Teams。提前装好 Teams、试一次 HackerRank 的 Python 环境。

---

## 1. 招聘官电话

- **考什么**：你是否真的感兴趣、时间线、地点（Sunnyvale 或 Toronto，每周至少 3 天到办公室）、工作许可。
- **准备**：
  - 30 秒自我介绍（见 [04-hm-screen.md](04-hm-screen.md)）。
  - 一句"为什么 Cerebras"。
  - 要问的三件事：经理面的形式、经理是谁、后面几轮的安排。
  - 薪资：先说想先了解岗位和级别。
- **卡片**：`6 Cerebras` 的 hm.self-intro、hm.why、loop。

## 2. 经理面（45 分钟）

- **考什么**：
  - 你过去做过什么、**为什么那样决定**、取舍是什么。这是这家公司经理面最常问的内容。
  - 简历上的每个词都可能被追问三层。
  - 你的兴趣和职业方向是否对得上这个团队。
  - 沟通、团队合作、解决问题的方式。
  - 可能有一段技术讨论，比如"你会怎么测 X"。
- **准备**：整页都在 [04-hm-screen.md](04-hm-screen.md)：时间线、自我介绍、三个"为什么"、项目深挖、测试策略、AI 缺口的说法、常见问题。
- **卡片**：`6 Cerebras` 的 hm 和 behavioural 两部分全部。

## 3. 编码轮

- **考什么**：LeetCode 简单到中等，常常一轮两题；讲清思路、复杂度，自己补测试用例。测试岗的编码通常比软件工程师岗简单，但会更看重边界情况和对自己代码的测试。
- **常见题**：

| 题 | 类型 |
|---|---|
| Two Sum、3Sum（low priority） | 哈希表、双指针 |
| 括号是否平衡（low priority） | 栈 |
| 二维数组操作（low priority） | 矩阵遍历 |
| 从零写二分查找（low priority） | 二分 |
| 开放式的图搜索、Flood Fill（low priority） | BFS / DFS |
| 拓扑排序（low priority） | 依赖图 |
| 二维前缀和，再改成多线程（low priority） | 并行计算 |
| 向量点乘 → 并行 → 稀疏（low priority） | 并行与稀疏数据 |
| 多频道消息队列：加频道、需要几个频道、用并查集找共享频道（low priority） | 面试官自己出的系统题 |

- **测试岗最可能的变体**：解析一份日志或测试结果文件，按测试名、错误类型聚合，输出报告；一个带超时和重试的并行任务执行器；读一段陌生代码找 bug。
- **准备**：
  1. 全部用 **Python** 写；练到不用查 `collections.Counter`、`defaultdict`、`heapq`、`bisect`、`concurrent.futures`。
  2. 每题写完先说出 3 个边界用例再跑。
  3. 练两道"解析日志 → 聚合 → 排序输出"的题，限时 25 分钟。
- **卡片**：LeetCode 牌组（数组哈希、双指针、栈、图、拓扑排序）、Code Core 牌组的输入解析部分。

## 4. 技术深挖轮

和岗位相关的概念题，"日常要用的，不是抽象的"。对这个岗位，最可能是下面四块。

### 4.1 测试与发布

- 怎么给一个新功能写测试计划；怎么按风险分配测试。
- 回归测试怎么分层（每次提交跑什么、每晚跑什么、发布前跑什么）。
- 不稳定测试（flaky）怎么发现、隔离、修；重试的代价。
- 测试框架怎么设计；测试环境怎么做到可复现（hermetic，不依赖外部状态）。
- 一个失败怎么定位到哪次提交（`git bisect`）、哪一层。
- 发布门（go/no-go）看什么证据。
- 用日常物品打比方的测试题（例如"你会怎么测一部电梯"）：按功能、边界、异常、性能、安全、可用性分层答。
- **卡片**：`软件测试与发布工程` 牌组全部。

### 4.2 机器学习基础（测试岗也会问）

- 监督学习和无监督学习的区别；过拟合（overfitting，只记住训练数据、对新数据不准）和欠拟合。
- 正则化（regularization）是什么，L1 和 L2 有什么区别。
- 怎么评价一个分类模型：准确率、精确率（precision）、召回率（recall）、F1，各自什么时候用。
- Transformer（今天大语言模型的基本结构）大致怎么工作。
- **卡片**：`LLM 推理与 AI 加速器` 牌组的"从零开始"和"机器学习基础"两部分。

### 4.3 LLM 推理

- 预填充和解码的区别，各自卡在哪；KV 缓存是什么。
- 批处理（batching，把多个请求一起算）为什么能提高吞吐、为什么会拉高单个请求的延迟。
- 延迟指标：首个 token 时间（TTFT, time to first token）、每个输出 token 的间隔、每秒 token 数。
- 量化对准确率的影响怎么测；为什么同一个输入两次推理结果可能不完全一样（浮点加法的顺序会影响结果）。
- 为什么晶圆级芯片推理快（见 [01-company-brief.md](01-company-brief.md) 第 3 节）。
- **卡片**：`LLM 推理与 AI 加速器` 牌组。

### 4.4 操作系统与调试

- 进程和线程、调度、共享内存、锁和死锁。
- 一个进程卡住了怎么查：`top`、`strace -p`、`gdb -p` 看栈、`py-spy dump` 看 Python 栈。
- 日志里怎么找跨组件的失败：按请求 ID 串起来、看时间线。
- **卡片**：八股牌组的操作系统部分、`软件测试与发布工程` 的排查部分。

## 5. 系统设计（可能有）

- **考什么**：实用、题目常常很模糊，要你自己问清需求。
- **常见题**：设计一个类似 Bugsnag 的错误追踪系统（low priority）。
- **测试岗最可能的版本**：设计一个测试执行平台（排队、分片、资源分配、结果存储）；设计一个 flaky 测试检测器；设计一条发布验证流水线。
- **准备**：用"需求 → 规模 → 核心数据流 → 存储 → 失败处理 → 可观测性"的顺序答；先问清楚每天跑多少测试、有多少硬件。
- **卡片**：系统设计牌组；`软件测试与发布工程` 的测试基础设施部分。

## 6. 背景问题

- **常见题**：
  - 和上级的一次严重分歧。
  - 在资料很少、没有系统学习材料的情况下学会一个领域。
  - 你怎么学新东西。
  - 团队合作和沟通。
- **准备**：每题一个故事，60 秒讲完，等追问。故事对照表在 [04-hm-screen.md](04-hm-screen.md) 第 7 节。
- **卡片**：`6 Cerebras` 的 behavioural 部分。

## 7. 允许用 AI 的轮次（如果被告知）

- **形式**：提前告诉你可以用 AI，而且希望你用。任务是真实的：读一个小代码库、给已有服务加功能、调查一份运维数据、改进一个开发工具、把不完整的需求做成原型。做完讨论扩展性、安全、可观测性、可维护性。
- **评分**：把问题框清楚、**验证**（读生成的代码、测边界）、判断、沟通、负责。高级岗更看重取舍和长期行为。
- **准备**：
  - 开始前先读代码、讲清你的计划，再交给工具。
  - 每次生成后读 diff、跑测试、自己补一个边界用例。
  - 说出你**没有**让 AI 做的部分和原因。
  - 你的真实习惯可以直接讲：计划 → 每阶段先写测试 → 用 CI 和阈值把关；钱相关的代码每个 diff 都读。

## 8. 每轮之后

- 当天写下：被问了什么、哪里卡住、下一轮的面试官可能追什么。
- 反馈一般 24–48 小时；超过一周没消息就礼貌地问招聘官。
