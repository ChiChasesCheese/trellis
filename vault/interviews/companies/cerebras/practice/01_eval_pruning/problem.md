# 01 · 评测集剪枝：用最少的题给出同样的排名和放行结论（low priority）

限时 45 分钟，Python。

一个大模型（会写代码、会回答问题的 AI 程序）好不好，要靠"考试"来量：准备几百道题，让模型逐题作答，再逐题打分。这套题叫评测集（benchmark）。全量跑一遍要占用很多硬件时间，所以发布前常常只想跑一个子集。问题是：剪掉大部分题以后，结论还可信吗？这组练习让你写一个工具：给定几个模型在全集上的逐题得分，找出最小的子集，使得用子集算出来的**模型排名**和**能不能放行的结论**都和全集一样，并用"留一个模型不看"的办法检查这个方法对没见过的模型是否还成立。这和测试工程里"把回归套件分档，用最少的用例拿到可信信号"是同一件事。

## 背景：先把几个词说清楚

| 词 | 白话 |
|---|---|
| 模型（model） | 一个会答题的程序。这里有 4 个：`model_a` 到 `model_d`，能力从强到弱 |
| 评测集（benchmark） | 一套固定的考题，每道题叫一个样本（sample） |
| 逐题得分 | 每个模型在每道题上的分数。写代码的题只有过或不过（0 或 1）；长文档问答由另一个模型当评委打 0 到 1 的分 |
| 评委模型（LLM judge） | 用另一个大模型给答案打分。同一个答案重打一次分数可能不同，有噪声 |
| 难度标签（difficulty） | 评测集自带的 easy / medium / hard，是题目本身的属性，和哪个模型无关 |
| 及格线（threshold） | 客户定的分数线。模型平均分不低于它就"放行"（go），否则"不放行"（no-go） |
| Kendall τ | 两个排名有多一致。对每一对模型，看两个排名是否把它们排成同样的先后：一致 +1，相反 −1，只有一边算平手记 0；加起来除以对数。1 = 完全一样，−1 = 完全反过来 |

## 数据

`data/` 下两个 CSV，由 `make_data.py` 生成（固定随机种子，重跑得到同样的文件；`--models 5` 可以多生成一个模型）。

| 文件 | 题数 | 分数 | 及格线 |
|---|---:|---|---:|
| `code_bench.csv` | 300 | 0 或 1（写出的程序是否通过测试） | 0.50 |
| `longctx_bench.csv` | 100 | 0 到 1，步长 0.1（评委打分） | 0.55 |

```text
sample_id,difficulty,model_a,model_b,model_c,model_d
code-000,medium,1,1,1,1
code-001,hard,1,0,1,0
```

**列的约定**：`sample_id`、`difficulty` 是元数据列，其余每一列都是一个模型。多一个模型就是多一列，代码不改。

## 任务

### Part 1：读数据、算分、比排名（约 10 分钟）

- `load_bench(path) -> Bench`：读 CSV。缺元数据列、没有模型列、没有数据行、`sample_id` 重复、分数不是数字或不在 [0, 1] 内（包括 `nan`），都抛 `ValueError`，错误信息带行号和列名。
- `model_means(bench, idx=None, models=None) -> {模型: 平均分}`：`idx` 是题的下标列表，`None` 表示全集；空列表抛 `ValueError`。
- `kendall_tau(a, b) -> float`：按上表的规则；两边共同的模型少于 2 个抛 `ValueError`。差值的绝对值不超过 `1e-12` 算平手。
- `verdicts(means, threshold) -> {模型: bool}`：分数 `>=` 及格线为 `True`。

### Part 2：选题（约 15 分钟）

- `item_stats(bench, models) -> (difficulty, discrimination)`：每道题两个数。经验难度 = 这些模型在该题上的平均分（越低越难）；区分度 = 这些模型分数的总体标准差（`statistics.pstdev`，越大越能把模型分开）。
- `allocate(sizes, k) -> {层: 名额}`：把 `k` 个名额按各层大小成比例分配。先取整（向下），剩下的名额给小数部分最大的层，并列时给层名排序靠前的。`k` 大于总数时按总数算。
- `select_subset(bench, k, models=None) -> 下标列表（升序）`：
  1. 按难度标签分层，用 `allocate` 定每层名额。
  2. 每层内部把题按（经验难度升序，区分度降序，下标升序）排成一行，取等距的位置：第 `j` 个取 `line[int((j + 0.5) * n / q)]`（`n` 是层大小，`q` 是名额）。
  3. 只读 `models` 里模型的分数。`k <= 0` 抛 `ValueError`。

### Part 3：检验，并找最小的子集（约 10 分钟）

- `evaluate_subset(bench, idx, threshold, models=None, max_gap=0.05) -> Report`：字段 `size`、`tau`（子集排名对全集排名）、`verdict_agreement`（结论没变的模型占比）、`max_gap`（各模型"子集分 − 全集分"的最大绝对值）、`ok`（τ = 1、结论全部一致、`max_gap <= 0.05` 三条同时成立）、`indices`。
- `smallest_subset(bench, threshold, models=None, max_gap=0.05) -> Report`：最小的 `k`，使得 `k` 以及所有更大的预算都 `ok`。做法：从全集往下逐个减 `k`，第一次不 `ok` 就停，返回上一个。

### Part 4：留一个模型不看（约 10 分钟）

- `leave_one_model_out(bench, threshold, max_gap=0.05) -> [HoldOut]`：对每个模型 `m`，只用其余模型做 Part 3，再拿得到的子集检查 `m`：`verdict_kept`（`m` 的放行结论是否和全集一致）、`gap`（`m` 的分差）、`tau_all`（包括 `m` 在内所有模型的排名一致度）、`size`、`indices`。少于 3 个模型抛 `ValueError`。

`main()` 对两个数据文件打印报告。

## 例子

6 道题、3 个模型；s0–s2 是 easy，s3–s5 是 hard：

| 模型 | s0 | s1 | s2 | s3 | s4 | s5 | 全集 | 只用 s0–s2 |
|---|---|---|---|---|---|---|---:|---:|
| a | 1 | 1 | 1 | 1 | 1 | 0 | 0.83 | 1.00 |
| b | 1 | 1 | 0 | 1 | 0 | 0 | 0.50 | 0.67 |
| c | 1 | 0 | 0 | 0 | 0 | 0 | 0.17 | 0.33 |

- 只用 s0–s2，排名仍是 a > b > c，τ = 1。
- 及格线 0.6：b 在全集不放行、在子集放行，`verdict_agreement` = 2/3，`ok` = False。

参考实现在数据上的结果（运行 `solution.py`）：

| 评测集 | 全集 | 最小稳定子集 | 留一法 |
|---|---:|---:|---|
| code_bench | 300 | 107（36%） | 4 个模型的结论都保住 |
| longctx_bench | 100 | 37（37%） | 不看 `model_c` 时只选了 17 题，`model_c` 子集分 0.52、全集 0.57，结论翻了 |

## 边界情况

- 分数格子为空、是 `abc`、`nan`、`1.5`、`-0.1`。
- 只有一个难度层；所有模型在所有题上分数相同（任何一道题都保住排名和结论，最小子集是 1）。
- 两个模型全集分数相同（τ 的平手规则）。
- 模型数少于 2（τ 无意义）、少于 3（留一法无意义）。
- `k` 比题数还大。

## 面试官会追问

| 追问 | 答题要点 |
|---|---|
| 为什么不随机抽？ | 随机抽的方差大，小样本下排名和结论都会抖；分层保证每种难度都有代表，方差更小 |
| 为什么不直接挑区分度最高的题？ | 它们是"有的模型对、有的模型错"的题，会把强模型的分抬高、弱模型的分压低，绝对分数偏了，放行结论跟着错。实测：先按区分度挑，code_bench 要留 240/300、longctx 要留 70/100 才满足分差 0.05；按难度等距取样只要 107 和 37 |
| 为什么分层用难度标签，不用模型分数？ | 标签是题目自己的属性，换一个新模型也成立；用当前模型的对错分层，等于拿这几个模型的答案来定题，换模型就失效 |
| 4 个模型、τ = 1，证据强吗？ | 很弱。4 个模型只有 6 对，没有平手时 τ 只能取 7 个值（−1、−2/3、…、1）；子集很小时也可能碰巧排对。所以要看留一法，并且要求从 `k` 往上都稳定，而不是第一个通过的 `k` |
| 留一法里结论翻了说明什么？ | 子集对离及格线近的模型不可靠。办法：在及格线两侧留安全边际（比如差 0.03 以内判"需要全量复测"）；或用自助法给子集分数一个置信区间，区间跨过及格线就不下结论 |
| 自助法（bootstrap）怎么做？ | 从选中的题里有放回地抽同样多的题，算一次平均分，重复 1000 次，取第 2.5 和第 97.5 百分位作为 95% 区间 |
| 评委打分有噪声怎么办？ | 同一批答案让评委重打 3 到 5 次，量出评委自己的波动；子集和全集的差小于这个波动，就不能解读为真差异。把这个波动当作 `max_gap` 的下限 |
| 题量到上万怎么办？ | `item_stats` 是一次遍历；`smallest_subset` 从上往下扫是 O(N) 次评估，每次 O(N·M)。可以先二分找一个大致的 `k`，再在附近线性确认稳定；或者按 1%、2%、5% 这样的几档预算只评估几次 |
| 发布流程里怎么用？ | 每次发布先跑子集当快速门（几分钟）；子集结论落在安全边际内或模型变化大时再跑全量；每隔一段时间用全量结果重新选一次子集，防止题目老化 |

## 评分看什么

- 先说清楚两个目标会打架：排名要区分度，放行结论要绝对分数准；并说出你的取舍。
- 选题只依赖题目属性和被选中的模型，留一法里被留出的模型完全没有被读过（测试会改掉它的分数来检查）。
- 能解释 Kendall τ 的平手规则，知道 3 到 4 个模型时 τ 的证据很弱。
- 边界输入抛清楚的错误，不是静默算出一个数。
- 输出的报告给出子集大小、τ、结论一致率、分差，而不是只给一个"通过"。
