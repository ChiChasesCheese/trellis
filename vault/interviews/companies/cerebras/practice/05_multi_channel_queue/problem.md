# 05 · 多频道消息队列：位集合、并查集、最少频道数（low priority）

限时 30 分钟，Python。

一个消息队列里有若干频道（channel）。生产者（producer）发消息时给它打上一个或多个频道标签；消费者（consumer）订阅若干频道，只要消息的标签和自己的订阅有交集就能收到。面试官会先让你实现队列本身，再问"哪些生产者和消费者通过频道连在一起"（并查集），再问"给定谁要和谁通信，最少要几个频道"，最后问每个操作的复杂度。没有 AI 概念，考的是数据结构选择和把模糊的问题定义清楚。

## 任务

### Part 1：队列本身（约 12 分钟）

`MessageQueue(channels=())`，每个频道对应一个位（bit），参与者的频道集合用一个整数当位集合存。

| 方法 | 行为 |
|---|---|
| `add_channel(name) -> int` | 运行时加频道，返回它的位下标（0、1、2…，只增不改）；重名 `ValueError` |
| `channel_mask(names) -> int` | 频道名列表 → 位集合；未知频道 `KeyError` |
| `subscribe(consumer, channel)` / `unsubscribe(consumer, channel)` | 未知频道 `KeyError`；没订阅时退订什么也不做 |
| `subscriptions(consumer) -> set` | 当前订阅的频道名 |
| `enqueue(producer, channels, payload) -> int` | 返回消息 id（递增）。投递给所有订阅了其中任一频道的消费者，每人只收一次。标签为空 `ValueError`；含未知频道 `KeyError`，并且什么都不改 |
| `consume(consumer, max_n=None) -> [Message]` | 先进先出，取走并返回；未知消费者返回空列表 |
| `pending(consumer) -> int` | 收件箱里还有几条 |
| `shared_channels(a, b) -> set` | 两个参与者共有的频道；生产者的频道 = 它发过消息的频道 |

约定：消费者只收到订阅**之后**发出的消息；退订后不再收到新消息，已经在收件箱里的保留。`bits_to_names(mask, names)` 把位集合换回频道名，只遍历置位的位（`mask & -mask` 取最低位）。

### Part 2：谁和谁连在一起（约 8 分钟）

- `UnionFind`：`find`（路径减半）、`union`（按大小合并，已在同一集合返回 `False`），没见过的元素自成一组。
- `groups(memberships) -> [[名字, ...], ...]`：`memberships` 是"参与者 → 频道列表"。共享频道是传递的：A 和 B 共享一个频道、B 和 C 共享另一个，A、B、C 在同一组。把频道也当作节点放进并查集，每条"参与者–频道"关系做一次 `union`，不要两两比较参与者。没有任何频道的参与者不出现。组内按名字排序，组之间按第一个名字排序。
- `MessageQueue.share_groups()`：用当前的订阅和发布关系调用 `groups`。

### Part 3：最少几个频道（约 7 分钟）

输入一组 `(生产者, 消费者)` 通信关系，表示这两个必须能通信。规则：

1. 每一对至少共享一个频道；
2. 两个参与者之间如果没有任何一串通信关系把它们连起来，就不能共享频道（隔离）。

`plan_channels(pairs) -> {参与者: 频道名}`，`min_channels(pairs) -> int`。答案是连通分量的个数：每个分量里至少有一对，需要至少一个频道；隔离规则不允许一个频道跨两个分量；一个分量一个频道就够了。频道名按分量里最小的名字排序，依次叫 `ch0`、`ch1`…

### Part 4（加分）：精确投递下的最少频道

更严格的规则：消费者**只能**收到和它配对的生产者的消息。一个频道就是一组生产者 × 一组消费者，其中每个组合都必须是要求的通信对；所有频道合起来要覆盖每一对。`min_channels_exact(pairs) -> [(生产者集合, 消费者集合), ...]` 返回频道数最少的方案。这在一般情况下是 NP 难问题（最小二分团覆盖），只要求小输入的精确解：

1. 候选频道只需要"极大"的：对每个非空的生产者子集 S，T = 它们共同的消费者；若 T 非空，候选是（所有能到达 T 中全部消费者的生产者，T）。
2. 从 1 个频道开始逐步加大上限，深度优先搜索：每次挑候选最少的那个未覆盖对来分支。
3. 生产者和消费者重名、生产者超过 14 个：`ValueError`。

## 例子

通信关系：(p1, c1)、(p1, c2)、(p2, c2)、(p3, c3)。

- 隔离规则：{p1, p2, c1, c2} 和 {p3, c3} 两个分量，2 个频道。
- 精确投递：c1 不能收到 p2 的消息，所以 p1、p2、c1、c2 不能共用一个频道。p1 用 {c1, c2}，p2 用 {c2}，p3 用 {c3}，共 3 个。

`data/scenario.txt` 是一串操作（加频道、订阅、发消息、取消息），测试会照着执行并核对每次取到的内容；`data/patterns.json` 是 6 组通信关系，两种规则下的答案：

| 名字 | 隔离规则 | 精确投递 |
|---|---:|---:|
| one_team | 1 | 2 |
| two_teams | 2 | 2 |
| chain | 1 | 3 |
| matching | 4 | 4 |
| full_block | 1 | 1 |
| crown_3 | 1 | 3 |

## 边界情况

- 一条消息带两个标签，消费者两个都订阅了：只收一次。
- 先发消息后订阅：收不到。
- 退订后再退订一次；从没订阅过的消费者取消息。
- `enqueue` 的标签里混了一个未知频道：抛错，而且收件箱、发布记录都不变（先校验再改状态）。
- 频道名和参与者同名（并查集里要给节点加类型前缀）。
- 空的通信关系：0 个频道。

## 面试官会追问

| 追问 | 答题要点 |
|---|---|
| 频道为什么用位集合？ | 求交集、并集是一次按位与、或，C 个频道只要 C/64 个机器字；集合求交要逐个元素哈希。Python 的 int 位数不限，加频道就是多用一位，旧的位不动 |
| `enqueue` 的复杂度？ | O(k + R)：k 个标签各取订阅者集合，R 是收件人数（取并集去重后逐个放进收件箱） |
| 推模式和拉模式怎么选？ | 推（本实现）：发消息时放进每个收件箱，消费 O(1)，但每条消息存 R 份引用。拉：所有消息进一条日志，每个消费者记一个读位置，消费时跳过标签不相交的消息；发消息 O(1)，但订阅很稀疏时消费要扫很多无关消息。订阅者多、消息大用拉模式，Kafka 就是日志 + 读位置 |
| 并查集各操作多快？ | 路径压缩 + 按大小合并，单次约等于常数（反阿克曼函数 α(n)，实际不超过 4）。`groups` 总共 O(关系数 · α) |
| 退订以后并查集怎么办？ | 并查集不能拆开。查询时用当前关系重建（O(关系数)）；如果查询很频繁，就离线：把操作倒过来做，退订变成合并 |
| 为什么把频道也当节点？ | 否则要两两比较参与者的位集合，O(P² · C/64)；频道当节点后每条关系一次合并 |
| 运行时加频道要改什么？ | 新分配一位，订阅表加一个空集合，O(1)；已有的位集合不用改 |
| 最少频道数为什么有两个答案？ | 题目没说清"多收到消息"算不算错。先问清楚：允许多收就是连通分量数，并查集一遍出结果；要求精确投递就是最小二分团覆盖，NP 难，只能小规模精确或用贪心近似 |
| 多线程下怎么保证安全？ | 一把锁保护频道表、订阅表和收件箱；或者每个收件箱一把锁加一个只在加频道时持有的全局锁。消费者阻塞等待用 `threading.Condition` |
| 消息要持久化、要能重放怎么办？ | 改成拉模式的追加日志，消费者提交读位置；重启后从提交的位置继续读 |

## 评分看什么

- 先问清楚投递语义：重复标签去重吗、订阅前的消息要不要、退订后收件箱怎么办。
- 选对数据结构并能说出复杂度：位集合求交、订阅表做反向索引、收件箱用 `deque`。
- 并查集写对（路径压缩、按大小合并），并能解释为什么频道要当节点。
- "最少频道"先把规则定义清楚，再给出能证明的答案。
- 失败的操作不留下半改的状态。
