# pc04 · Big-Integer String Arithmetic — 手写高精度加减乘（不用 `int()`）

> 45 min 第一轮：约 15 min 背景 + 30 min 编码。一手报道是"两个十进制字符串相加"（large integer
> addition as strings），本题在此基础上按第一轮"由浅入深"的惯例延伸出 Part 2（带符号加减）与
> Part 3（乘法 + 任意进制，**reconstructed**）。

## 背景

一位候选人在 Millennium 的 C++ Developer 电面（45 分钟：15 分钟背景 + 30 分钟编码）里被要求实现
"两个字符串表示的大整数相加"——面试官全程没什么反馈，候选人事后只能确认题目本身与耗时结构。这类
题考的不是数学，是**手写进位/借位的笔算过程**：面试官明确不接受直接 `int(a) + int(b)`（尽管
Python 原生大整数能算对），因为考点就是候选人能不能把小学笔算搬进代码。

## API 契约（英文签名）

```python
def add_unsigned(a: str, b: str) -> str: ...
def add_signed(a: str, b: str) -> str: ...
def subtract_signed(a: str, b: str) -> str: ...
def multiply_signed(a: str, b: str, base: int = 10) -> str: ...
```
`add_unsigned` 只接受十进制数字字符（无符号）；`add_signed` / `subtract_signed` 额外接受可选
前导 `+`/`-`；`multiply_signed` 额外接受 `base`（2–36，数字用 `0-9` 后接小写 `a-z`，输入大小写
不敏感、输出统一小写）。输入 `''` 一律非法。核心逻辑不得调用 `int()`/`str()` 做数值转换——逐位
用 `carry`/`borrow` 累加。

## 规则

### Part 1 — 无符号十进制加法（一手原题）
`add_unsigned(a, b)`：两个非负十进制数字字符串相加，模拟竖式加法，逐位累加进位。
- 允许输入带前导零（`"007"`），输出不带前导零（`"0"` 本身除外）。
- 空串 `''` 是非法输入 → `ValueError`。
- 出现非数字字符（含空格、负号）→ `ValueError`。

### Part 2 — 带符号加减
`add_signed(a, b)` / `subtract_signed(a, b)`：操作数可带可选前导 `+`/`-`（无前缀视为正数）。
- 减法通过"加上被减数的相反数"实现（`subtract_signed(a, b) == add_signed(a, negate(b))`）。
- 两个操作数同号：直接对数量级相加，结果符号跟操作数。
- 两个操作数异号：比较数量级大小，用大的减小的，结果符号跟数量级更大的那个操作数。
- 结果为零时**永远不带符号**（`"-0"` 不是合法输出；输入 `"-0"` 也要能正确处理并归一化为 `"0"`）。
- 只有符号、没有数字（`"-"`、`"+"`）或空串 → `ValueError`。

### Part 3 — 乘法 + 任意进制 **(reconstructed)**
`multiply_signed(a, b, base=10)`：把 Part 1/2 的"逐位累加"推广到**乘法**这个真正比重复加法更难
的操作，并同时推广到**任意进制 2–36**（`base` 省略时按十进制处理，向下兼容 Part 1/2 的输入）。
- 竖式长乘法：`O(len(a) · len(b))`，两个 O(n) 长度的数字相乘一定不可能压到 O(n)（下界由乘出的
  结果位数决定），这也是本题追问要问"时间复杂度"的原因。
- 任一操作数数量级为 `"0"` → 直接返回 `"0"`（不需要跑满两层循环）。
- 符号规则同小学乘法：同号得正、异号得负、结果为零不带符号。
- `base < 2` 或 `base > 36` → `ValueError`；操作数里出现该进制下不存在的数字（如十六进制下的
  `'0'`–`'9'` `'a'`–`'f'` 之外的字符，或八进制下出现 `'8'`/`'9'`）→ `ValueError`。

## Worked examples（全部由 `solution.py` 实际运行得出）

**Part 1**
```python
add_unsigned("123", "456")  # → "579"
add_unsigned("007", "013")  # → "20"   （前导零被容忍，输出无前导零）
add_unsigned("999", "1")    # → "1000" （连续进位）
```

**Part 2**
```python
add_signed("-5", "3")        # → "-2"
add_signed("-0", "0")        # → "0"   （负零归一化）
subtract_signed("5", "8")    # → "-3"
subtract_signed("-5", "-8")  # → "3"   （- (-5) - (-8) = -5 + 8 = 3）
```

**Part 3**
```python
multiply_signed("123", "456")        # → "56088"
multiply_signed("-12", "11")         # → "-132"
multiply_signed("ff", "2", 16)       # → "1fe"   （255 * 2 = 510 = 0x1fe）
multiply_signed("0", "999")          # → "0"
```

## `main()` 命令流

```
PART 1            PART 2            PART 3
123 456           ADD -5 3          123 456 10
007 013           SUB 5 8           -12 11 10
999 1                                ff 2 16
→ 579             → -2              → 56088
  20                -3                -132
  1000                                1fe
```
Part 1 每行 `<a> <b>`；Part 2 每行 `<ADD|SUB> <a> <b>`；Part 3 每行 `<a> <b> <base>`。每行产出
一行输出，无空行；`RECORD` 式的"无输出"操作在本题不存在（每条输入都对应一行输出）。

## 边界清单

- 空串操作数（Part 1/2）、只有符号没有数字（Part 2 的 `"-"`/`"+"`）→ `ValueError`
- 前导零输入（`"007"`）、结果本身需要多一位（`"999"+"1"="1000"`，进位链一路传到最高位）
- 两数相加/相减结果恰为零 → 输出 `"0"`，不带符号（正负两个操作数数量级相等时最常触发）
- Part 3：任一操作数数量级为 `"0"` → 直接短路返回 `"0"`；`base` 越界（`<2` 或 `>36`）→
  `ValueError`；数字字符超出该进制范围（如八进制里的 `'9'`）→ `ValueError`
- 大数（千位十进制数相乘）：验证纯 Python 逐位实现不依赖 `int()` 也能在预算时间内跑完
- 同一行重复调用（比如同一对 `(a, b)` 出现两次）结果必须一致（函数无隐藏状态）

## 追问

1. **为什么不能直接 `int(a) + int(b)`？** 面试考的是手写进位/借位的过程，不是"能不能算对"——
   Python 原生大整数确实能算对，但面试官要看候选人能不能把逐位运算讲清楚（这也是为什么
   `solution.py` 全程不出现把整段数字字符串转成 `int` 的转换）。
2. **各操作的时间复杂度？** 加/减 `O(max(len(a), len(b)))`；乘法 `O(len(a) · len(b))`——两个
   O(n) 位的数相乘，结果本身就有 `Θ(n)` 位，逐位竖式乘法是 `Θ(n²)`（更快的 FFT/Karatsuba 乘法
   超出本题范围，可以口头提一句）。
3. **负数怎么处理？** 减法统一转换成"加上相反数"，只在 `add_signed` 里集中处理符号判断（同号
   直接加数量级、异号比较数量级再减），`subtract_signed`/`multiply_signed` 复用这套符号逻辑而不
   是各自重新实现一遍。
