# Kaiju Cats：模拟器 + 最优解搜索

Kaiju Cats 是 Roblox 官方给候选人的练习游戏（在 Roblox 里搜游戏 ID `13977123257`），和正式的游戏化测评是同一类玩法。
正式测评会换关卡，甚至换游戏，所以这个目录的价值在于**练判断**，不在于背答案。

```bash
cd vault/interviews/companies/roblox/games/kaiju_cats
python3 -m unittest test_sim -v   # 21 条测试：每条规则一个，外加两张地图的基线，以及"最佳方案能复现其分数"
python3 improve.py 3              # 从候选方案出发做逐猫优化（约 1 分钟）
python3 exact.py 3                # 单猫穷举 + 组合上界 + 验证（约 1 分钟）
```

## 规则

### 题面明写的（2026-09-28 从游戏说明和指令面板转录）

| 类别 | 规则 |
|---|---|
| 目标 | 15 回合后，三只猫的 power 总和最大 |
| 建筑 | 高价值楼 2 层，每层 +500；低价值楼 2 层，每层 +250；发电厂 1 层，摧毁时当前 power ×2 |
| 泥地 | 进入后下一回合卡住不动，再下一回合沿原方向继续走 |
| 尖刺 | 进入时 power 减半，下一回合沿原方向继续走 |
| 巨石 | 挡路，猫反弹，朝反方向走 |
| 猫窝 | 只能进自己的窝。第 1 个进窝 +2000，第 2 个 ×3，第 3 个 ×5。同一回合到达时，score 低的先进 |
| 打架 | 两只猫进同一格就打架，power 高的赢；平局时，窝位置靠上的赢（红 > 绿 > 蓝） |
| 指令 | 挂在楼层的挂载点上，从 $200 里扣钱。四个转向各 $10；**Stomp** $20（"拆掉这一层后原地等一回合，下一回合再拆一层"）；**Power Up** $30（效果尚未转录） |
| 计分 | 可以测试多次，最终成绩取最高的一次 |

### Chi 在游戏里确认的

- **楼是逐层拆的。**
- **两只猫相撞会死掉一只。** 迎面交换位置也算相撞。

### 朴素假设（`sim.py` 里的 `ASSUMPTIONS`，都可以在 `Rules` 里切换）

- **进楼只拆一层，下一回合就接着走**，楼剩下的部分留在原地。理由是 Stomp 的说明："that cat will wait and stomp again next turn"。
  如果猫本来就会停下来把楼拆完，Stomp 就没有意义了。
- 初始 power 为 0，猫一开始朝东。每回合所有猫同时走一格。挡路时原地不动，然后掉头。
- 打架输的猫出局，它的 power 作废。
- **Power Up 暂时不参与搜索**，因为还不知道它的效果。

## 我在这里犯过的错（都已修正）

1. **把地图上的指令当成了关卡自带的。** 其实那是 Chi 自己放的：指令面板显示 $110 可用，7 个转向加 1 个 Stomp 正好是 $90。
2. **认错了两个图标，也猜错了价格。** "↩"其实是 Stomp，爪印是 Power Up；转向只要 $10，不是我假设的 $50。
3. **理解错了拆楼规则。** 我先猜"整栋拆"，又改成"停在楼里一层一层拆完"，两次都错了。
   Stomp 的说明才揭示了真实规则：拆一层就走。**教训：规则不确定时，先找游戏里能印证的原文，不要从"游戏设计应该怎样"去推。**
4. **求解器的 bug。** 一是"已付费指令"只跳过了收费，没有真正执行转向和 Stomp；二是束搜索没收敛就被当成了结果。
   第一个是用"逐回合对照回放、找出分叉的那一回合"查出来的。第二个是看到"宽度每放大一倍，分数都还在涨"才发现的。

## 搜索方法，以及它能证明什么、不能证明什么

1. **`solve.py`：束搜索。** 每回合只保留估值最高的若干个状态。**没有收敛**：宽度从 1,000 放大到 100,000，结果一直在涨，所以不能用。
2. **`exact.py`：单猫穷举 + 组合上界 + 验证。**
   - 每只猫单独在地图上跑，穷举它所有可能的走法，大约 55 万个终局状态，每只约 15 秒。
   - 三只猫组合时，按进窝顺序算出的分数是**上界**，因为抢楼和相撞只会让分数变低。
   - 然后从上界最高的组合开始，逐个放进完整模拟器验证。
   - **局限**：每只猫只能保留部分走法。全局最高的上界是 177,500，但那些组合都因为抢楼或相撞兑现不了，所以它**证明不了**全局最优。
3. **`improve.py`：逐猫优化。** 固定两只猫的指令，在**完整的三猫模拟**里穷举第三只猫的全部走法，找它的最佳应对，三只猫轮流做，直到谁都改不出更高分。
   结果是一个"任何一只猫单独改自己的指令都无法提高分数"的局部最优。
   不同起点会收敛到不同的局部最优，所以用很多个起点各跑一遍，取最好的。

**当前最好的方案保存在 `best_plan.json` 里**，测试会验证它确实能跑出所记录的分数。
这是**已知最好**，不是证明过的全局最优。

## 心法（从搜索结果里看出来的）

1. **集中火力，把乘法留到最后。** 最好的方案里，一只猫先攒 power，再连过两个发电厂（×2 ×2），最后一个进窝拿 ×5。
   这只猫一只就贡献了总分的 90%。
2. **进窝顺序按排序不等式安排：** 最弱的先进，拿固定的 +2000；中等的第二个进，×3；最强的最后进，×5。
3. **先加后乘。** 先拆楼，再过发电厂。
4. **Stomp 用在高价值楼上。** 花 $20 让猫多停一回合，把楼的第二层也拆掉。
5. **多个起点比一个聪明的估值函数更可靠。** 束搜索在这张地图上被估值函数误导了。
   在测评里的对应做法：多测几种差别很大的方案，最终成绩只取最高的那一次。
