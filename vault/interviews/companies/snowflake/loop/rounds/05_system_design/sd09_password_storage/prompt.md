# User Password Storage（密码存储系统设计）

我们的平台上有大量用户账号需要支持"用户名 + 密码"这种最基础的登录方式（即便平台同时也支持 SSO/OAuth，密码登录这条路径仍然存在且必须做对）。请设计存储用户密码这部分的系统：用户注册时设置密码，系统要存下一些东西使得将来用户登录时能够验证"这个人输的密码对不对"，但同时要保证即便我们的数据库整个被拖库（被攻击者拿到了存储的全部内容），攻击者也不能轻易地从存储的内容反推出用户的明文密码。除此之外还要考虑几个现实问题：万一某天我们发现当前用的哈希算法或者参数强度不够了，需要给全平台的密码存储做一次算法/参数的升级迁移，但显然不可能要求所有用户同时修改密码来配合这次迁移；如果真的发生了数据泄露事件，我们对外披露和补救的流程应该建立在什么样的存储设计基础上；另外这个系统本身也要能防御针对登录接口的暴力破解，不能让攻击者无限制地尝试撞库。请设计这个密码存储与验证系统。
