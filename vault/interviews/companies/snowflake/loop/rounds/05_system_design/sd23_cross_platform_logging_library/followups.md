# 追问预案（8 条，全部（推断））

## 1. 为什么宁可丢日志也不阻塞？
**期望要点**：日志是观测手段，不能反过来制造故障；阻塞会把平台故障传染给所有业务；丢弃要可见（计数、上报）。
**反例**："日志不能丢，用同步写"。

## 2. 级别不够时参数构造的开销怎么避免？
**期望要点**：先判断级别再求值；API 接受模板 + 参数或 lambda；Java 的 `isDebugEnabled` 模式；C++ 宏短路。
**反例**：先拼好字符串再判断。

## 3. 缓冲区为什么要有界、为什么无锁？
**期望要点**：无界会在平台故障时 OOM；有锁会在高并发下让业务线程互相等待；环形缓冲 + CAS 或线程本地缓冲批量合并。
**反例**：`LinkedBlockingQueue` 无界。

## 4. 各语言怎么保证一致？
**期望要点**：先定 schema 与语义规范；一致性测试逐字段比对；版本化 schema，新增字段可选。
**反例**：各团队照着 README 各写各的。

## 5. 驱动跑在客户机上，脱敏怎么做才靠谱？
**期望要点**：默认不上传；脱敏在进入缓冲前；字段名黑名单 + 正则 + SQL 字面量掩码；金丝雀串测试进 CI；用户显式开启上传且可审计。
**反例**：在服务端脱敏。

## 6. 不重启调高某模块的日志级别？
**期望要点**：agent / 配置服务下发前缀 → 级别映射，带 TTL 自动恢复；库原子替换阈值表；防止被忘记开着导致成本飙升。
**反例**：改配置文件重启。

## 7. 为什么要本机 agent，而不是库直连平台？
**期望要点**：鉴权、压缩、重试、磁盘队列、路由只实现一次；库更轻、崩溃半径小；平台协议升级不需要所有应用发版。代价是多一个要运维的进程。
**反例**：每个语言库里各写一个 HTTP 上传器。

## 8. 同一行代码在循环里每秒打几万条怎么办？
**期望要点**：按模板 + 调用点令牌桶限速，超出折叠为"已抑制 N 条"；报警给代码所有者。
**反例**：全部上传，让平台扛。
