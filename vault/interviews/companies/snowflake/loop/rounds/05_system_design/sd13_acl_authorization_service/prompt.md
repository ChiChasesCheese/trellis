# ACL Authorization Checking Service（集中式权限校验服务）

我们要给公司内部的数据平台做一个集中式的权限校验服务：几十个内部系统（查询引擎、数据目录、
调度器、现在还有跑在用户身后的 AI agent）都要在做任何操作前问它一句"主体 P 能不能对资源 R
执行动作 A？"。资源是有层级的（组织 → 数据库 → schema → 表 → 列），权限可以在角色之间继承，
也可以在某一层显式撤销或拒绝（比如整体授予了某个角色读权限，但某一张含 PII 的表要单独拒绝）。
读写比极端不对称——每天几十亿次权限校验，写（授权变更、吊销）远少于读，读延迟要求个位数毫秒；
但吊销之后不能允许"过期的允许"继续生效太久，这是安全事故。现在还多了一类新主体：代表用户操作
的 AI agent——它不是人，权限应该是"用户当前权限的一个受限、有过期时间的子集"，而不是创建时快照
一份、之后用户权限收窄了 agent 却不知道。每一次校验结果都要能审计（谁、什么时候、查了什么、
结果是什么、依据哪个策略版本）。请设计这个服务。
