# DAG Cache for Query Views / Materialized Views（对照 Snowflake Dynamic Tables）

我们的分析平台上，用户经常会基于一张或几张基础表定义"视图"，然后又有别的用户基于这些视图再定义新的视图，层层叠加下来，整个平台里的视图之间会形成一个复杂的依赖关系图（DAG）——A 依赖 B 和 C，B 又依赖 D，等等。目前这些视图每次被查询的时候都是现算的，代价很高，我们想做一层缓存/物化：把这些视图算好的结果物化下来，当底层依赖的数据发生变化时，自动把受影响的下游视图重新计算并更新，而不需要用户自己手动触发。这里有几个难点：第一，当某个基础表更新之后，你怎么知道应该增量地更新受影响的视图（只算变化的那部分数据），还是应该干脆推倒重来做一次全量刷新——这个判断本身需要根据视图的定义（比如是不是包含了不支持增量计算的操作，像是某些窗口函数或者非确定性函数）来决定；第二，当用户查询某个视图的时候，应该保证读到的是一个**一致的快照**——不能出现"视图 A 已经根据最新数据刷新完了，但它依赖的视图 B 还没刷新完"，导致用户看到一个逻辑上不自洽的中间状态；第三，失效需要在整个依赖图上正确传播——一个基础表变了，所有直接或间接依赖它的下游视图都需要知道自己"过时了"，但不应该因为传播逻辑本身的低效导致级联的、不必要的重新计算。请设计这套 DAG 缓存/物化视图系统。
