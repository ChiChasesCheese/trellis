# Expertise / 项目深挖轮 —— 自评表

> 依据：`loop/LOOP_GUIDE.md` §7；一手追问方向（Blind xcavd10l / 3tbrdamq）："depth of knowledge in your domain"、"the why behind every design decision"、"availability / fault tolerance"。

## 用法

`python3 loop/mock.py bq expertise -n 3 -m 5`，每题 5 分钟；按 5 维打分，任一 ≤ 2 重讲。

## 评分维度

### 1. 决策的 why
| 分数 | 长什么样 |
|---|---|
| 1 | "当时就这么做了" |
| 2 | 有理由但只有一个 |
| 3 | 约束 → 方案 → 理由 |
| 4 | 3 + 说出当时不知道、现在知道的事 |

### 2. 备选方案
| 分数 | 长什么样 |
|---|---|
| 1 | 没有 |
| 2 | 提了但没说为什么弃 |
| 3 | 每个决策 ≥ 2 个被否方案 + 弃因 |
| 4 | 3 + 被否方案在什么条件下反而更优 |

### 3. 系统属性（可用性 / 容错 / 扩展 / 监控）
| 分数 | 长什么样 |
|---|---|
| 1 | 停在功能层 |
| 2 | 提到重试 |
| 3 | 幂等、急停、依赖失败行为、什么会 page |
| 4 | 3 + 100× 时先坏哪里、怎么提前知道 |

### 4. 我的贡献与数字
| 分数 | 长什么样 |
|---|---|
| 1 | "我们做了" |
| 2 | 有 "我" 但没数字 |
| 3 | I designed / wrote / owned + 已确认数字（138B / 22M / 13.7M / 0.224%） |
| 4 | 3 + 说明数字怎么来的（impact summary、对账 SQL） |

### 5. 反思与重做
| 分数 | 长什么样 |
|---|---|
| 1 | "没什么要改" |
| 2 | 泛泛"可以更好" |
| 3 | 两条具体重做项 |
| 4 | 3 + 其中一条已经在后来做了（[[S2]] ADR） |
