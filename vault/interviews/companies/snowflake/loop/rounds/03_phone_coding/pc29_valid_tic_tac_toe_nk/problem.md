# pc29 · Valid Tic-Tac-Toe (Extended) — LC 794 推广到 N×N/K 连、外加原因码与"双赢"的真正条件

> Part 1、Part 2 是一手报道的原题面；Part 3（原因码）**(reconstructed)**，但 Part 1/2 本身在
> 实现时就踩到了一个经典 LC 794 题解也容易讲错的坑——见下方"双赢条件"。

## 背景

TrueInterview 题单预览：`N×N` 棋盘，`K` 连子获胜（行/列/两条对角线），X 先手、交替落子、一旦有
人获胜游戏立刻停止；判断给定局面是否**可达**（是否存在一个合法的落子顺序能产生这个局面）。
`N=3, K=3` 就是 LC 794 原题。

这题真正的难点不是"判断有没有连成 K 个"，而是**"可达性"的完整必要条件**，尤其是"一个人能不能
同时有两条连线"这一点——很多网上题解（包括不少 LC 794 的高赞题解）只检查"两条连线共享一个格
子"就判定可达，这是**不完整**的：当一个人同时有 **三条或更多**连线时，"每两条连线两两相交"不
等于"所有连线共享同一个格子"，而后者才是真正的必要条件（见下方"双赢条件"的完整推导，本 kit 在
写 `solution.py` 时用暴力枚举把这个 bug 亲手抓出来过一次）。

## 输入

- Part 1：`board: list[str]`，`3×3`，每个字符 `'X'/'O'/' '`。
- Part 2：`board: list[str]`，`N×N`，`K` 连获胜。
- Part 3：与 Part 2 相同的输入，返回一个原因码而不是布尔值。

## API 契约（英文签名）

```python
def valid_tic_tac_toe(board: list[str]) -> bool
def valid_tic_tac_toe_nk(board: list[str], n: int, k: int) -> bool
def valid_tic_tac_toe_reason(board: list[str], n: int, k: int) -> str
```

## 规则

### Part 1 — LC 794 原题（3×3, K=3）

### Part 2 — 推广到任意 N、任意 K（一手原题）

### 可达性的完整判定条件（Part 1、Part 2 共用）

1. **落子数关系**：X 先手交替，所以 `#X - #O ∈ {0, 1}`，否则直接不可达（`COUNT`）。
2. **赢了就停**：
   - 如果 X 赢了（存在至少一条 X 的 K 连线），赢的那一步必然是全局最后一步棋，所以此时必须
     `#X - #O == 1`（`X_WIN_BAD_COUNT` 否则）。
   - 如果 O 赢了，同理必须 `#X == #O`（`O_WIN_BAD_COUNT` 否则）。
   - **两人都赢是不可能的**（先赢的那一刻游戏就结束了，另一人不可能再赢）（`BOTH_WIN`）。
3. **"双赢"（同一个人有多条连线）的真正条件**：一个人可以同时有多条 K 连线，**当且仅当这些连
   线存在一个共同的格子**——想象最后一步棋恰好落在这个格子上，之前这些连线都因为缺这一个格子
   而没有完成，最后一步一次性把它们全部补齐。

   **易错点（本题最重要的坑）**：如果一个人有 **两条**连线，"两条连线共享一个格子"就是充分必
   要条件。但如果有 **三条或更多**连线，光检查"每两条连线两两都有共享格子"**是不够的**——三条
   连线可能两两相交（各自共享不同的格子），却**没有一个格子同时在这三条线上**。这种情况下：
   不管选哪条线的交点作为"最后一步"，另外那条不经过该交点的线都已经在更早的时候独立完成，游
   戏会在那一刻就结束，不可能撑到"最后一步"。**正确条件是对这个人的所有连线求交集，交集非空
   才可达**（`DOUBLE_WIN_IMPOSSIBLE` 否则，命名沿用两连线场景但逻辑覆盖任意条数）。

   本题在实现阶段用"暴力枚举 3×3 全部合法对局 + 随机抽样 4×4"交叉验证时，最初写的"两两相交"版
   本在 5000 组随机 4×4 局面里跑出 5 个反例（例如一个人同时占了一行、一列、一条对角线，三条线
   两两相交但没有共同交点），因此改成了"全部连线求交集"。

### Part 3 — 返回原因码而不是布尔值 **(reconstructed)**

`valid_tic_tac_toe_reason` 返回：`OK`、`COUNT`、`BOTH_WIN`、`X_WIN_BAD_COUNT`、
`O_WIN_BAD_COUNT`、`DOUBLE_WIN_IMPOSSIBLE` 之一，检查顺序：先查落子数关系，再查双赢，再分别查
X/O 获胜时的落子数与"多连线共同交点"条件。

## Worked examples（全部由 `solution.py` 实际运行得出）

**例 1**：`valid_tic_tac_toe(["O  ", "   ", "   "]) -> False`（O 先手，违反交替规则）
**例 2**：`valid_tic_tac_toe(["XOX", " X ", "  O"]) -> True`
**例 3**：`valid_tic_tac_toe_reason(["O  ", "   ", "   "], 3, 3) -> "COUNT"`
**例 4**：`valid_tic_tac_toe_reason(["XXX", "   ", "OOO"], 3, 3) -> "BOTH_WIN"`
**例 5**（两条连线共享一个交点，可达）
```python
valid_tic_tac_toe_reason(["XXX", "XOO", "XOO"], 3, 3) -> "OK"
# 行 0（XXX）与列 0（X,X,X）共享格子 (0,0)：最后一步落在 (0,0) 同时补齐两条线
```
**例 6**（三条连线两两相交但没有共同交点，**不可达**——这就是上面讲的易错点）
```python
board = ["XO  ", "OXOO", " XXX", "OX  "]
valid_tic_tac_toe_nk(board, 4, 3) -> False
valid_tic_tac_toe_reason(board, 4, 3) -> "DOUBLE_WIN_IMPOSSIBLE"
# X 的三条连线：行2的 (2,1)(2,2)(2,3)、列1的 (1,1)(2,1)(3,1)、主对角线的 (0,0)(1,1)(2,2)
# 行×列共享 (2,1)；行×对角线共享 (2,2)；列×对角线共享 (1,1)——两两相交，但三者没有共同格子
```
**例 7**（用暴力枚举验证）：`n=3, k=3` 时，对全部 `3^9 = 19683` 种局面逐一比较
`valid_tic_tac_toe_nk` 与"BFS 枚举所有合法对局能到达的局面集合"，**零差异**；`n=4, k=3` 用
5000 组随机局面交叉验证同样零差异（见 `test_pc29.py`）。

## 边界清单

- 落子数违反交替规则（`COUNT`）
- 两人都赢（`BOTH_WIN`）
- X 赢但落子数关系不对、O 赢但落子数关系不对
- 一个人有两条连线且共享交点（可达）
- 一个人有两条连线但不共享任何格子（不可达）
- **一个人有三条及以上连线，两两相交但没有共同交点（不可达——最容易被想当然地判成可达的情形，
  见例 6）**
- 一个人有三条及以上连线且确实有一个共同交点（可达）
- 全空棋盘（`OK`，游戏还没开始也是一种合法局面）
- `N=3,K=3` 全部 19683 种局面、`N=4,K=3` 随机抽样，逐一对照 BFS 暴力枚举的对局树

## 追问

1. **为什么很多题解只查"两两相交"就够了？** 因为 LC 794 原题是 3×3、K=3，一个人最多同时凑出
   2 条连线（3×3 棋盘上 3 连线只有 8 条可能的线，同一个人的子集要凑出 3 条互不包含全部共同点的
   线在 3×3、9 个格子的约束下几何上很难发生，很多题解因此没有踩到这个坑；一旦推广到更大的 N，
   反例就容易构造出来，例 6 就是在 4×4 上找到的。）
2. **能不能不算交集，改成"任选一条线的每个格子当候选交点，检查是否所有线都包含至少一个候选"？**
   那正是"交集非空"的等价说法（交集非空 ⟺ 存在一个格子同时属于所有线）。
3. **K 连的方向要不要考虑"折线"（比如 L 形）？** 不考虑，只有标准的行/列/主对角线方向/副对角
   线方向的连续 K 个格子算获胜，这是 LC 794 和几乎所有五子棋类题目的标准定义。
4. **N、K 很大时暴力枚举获胜线的复杂度？** `O(N^2)` 条候选线（每个方向 `O(N^2)` 个起点），每条
   验证 `O(K)`，总共 `O(N^2 * K)`；棋盘本身只有 `O(N^2)` 个格子，这个复杂度对面试规模足够。
