# q06 · Patching Array：LC 484 原题 + 一个"返回具体值"的追问

> [!tldr]
> - 这题考的是：贪心维护"当前保证能凑出的区间上界"，用最少的补丁让 `[1,n]` 全部可被子集和覆盖——LC 484 原题
> - 三步套路：先吃透 `miss` 这个不变量的含义 → Part 1 照抄标准贪心 → Part 2 只改"记录什么"，循环结构完全不变
> - 最值得带走的一个模式：**同一个贪心循环，Part 2 只是把"计数"换成"收集打补丁前的值"**——两个 part 共享一份循环体，不要写两份贪心逻辑

## 1. 题目在说什么（人话版）
给一个已排序数组 `nums` 和整数 `n`，可以往数组里加数（打补丁），使得 `[1,n]` 里的每个整数都能表示成
数组某个子集的和。求最少打几个补丁（Part 1），以及具体补丁的值是多少（Part 2，追问）。

三行小例子：
```
nums=[1,3], n=6
miss=1: nums[0]=1<=1,消费,miss=2 -> miss=2: nums[1]=3>2,打补丁2,miss=4 -> miss=4<=6: nums[1]=3<=4,消费,miss=7
miss=7>6,停止 -> part1=1(打了1个补丁), part2=[2]
```

## 2. 读题：把文字变成模型
- **实体**：已排序数组 `nums`、目标覆盖上界 `n`、贪心游标 `miss`。
- **输入长什么样**：`PART <1|2>` + `n` + 一行 `nums`（可能是空行）。
- **输出要什么**：Part 1 是一个整数（补丁数），Part 2 是一行补丁值（空格分隔，可能是空行）。
- **状态**：`miss` = 当前保证能凑出的连续区间的上界+1；`i` = `nums` 里下一个还没消费的下标。
- **一句话建模**：这是一个 **贪心不变量维护** 问题——`miss` 每次要么被真实元素扩展，要么被补丁翻倍，
  循环到 `miss>n` 为止。

> [!note] 为什么选这个数据结构
> 不需要额外的数据结构，只需要两个标量 `miss`、`i` 顺序扫描。这是贪心题的典型特征：状态压缩到极致，
> 一旦想清楚不变量是什么，代码本身极短。

## 3. 下笔顺序（面试里就按这个顺序敲）
1. **骨架先行**：`main()` 解析 `PART`/`n`/`nums`，调 `part1`/`part2`，按格式打印。
2. **Part 1 最小可用**：`miss=1,i=0,patches=0`；循环 `while miss<=n`：`nums[i]<=miss` 就消费
   （`miss+=nums[i], i+=1`），否则打补丁（`miss*=2, patches+=1`）。用官方样例验证。
3. **Part 2 叠加**：完全相同的循环，唯一区别是打补丁那一分支改成"把当前 `miss`（翻倍前）追加进结果列表"。
4. **收尾**：`n=0`（循环一次都不进）、空数组、已完全覆盖（0 补丁）、`nums` 里有用不上的大值等边界过一遍；
   断言 `len(part2(nums,n)) == part1(nums,n)` 恒成立。

## 4. 代码怎么组织
```
part1(nums, n) -> int          # 标准贪心，只计数
part2(nums, n) -> list[int]    # 同一个贪心循环，收集打补丁前的 miss 值
main(stdin, stdout)             # 解析、按 part 分派、格式化输出
```
两个函数各自独立跑一遍同样的循环，而不是 `part2` 调用 `part1` 再反推——因为"补丁值"必须在循环内实时
记录（翻倍前的 `miss`），事后没法从补丁数量反推出具体值。保持两份循环体逐行一致，是防止两个 part
结果不一致的最简单办法。

## 5. 核心代码（骨架，≤ 40 行，带注释）
```python
def part1(nums, n):
    miss, i, patches = 1, 0, 0
    length = len(nums)
    while miss <= n:
        if i < length and nums[i] <= miss:   # 真实元素能扩展当前保证区间
            miss += nums[i]
            i += 1
        else:                                  # 没有元素能用，打一个补丁
            miss *= 2                          # 补丁值就是当前 miss，翻倍后区间扩大一倍
            patches += 1
    return patches

def part2(nums, n):
    miss, i = 1, 0
    length = len(nums)
    result = []
    while miss <= n:
        if i < length and nums[i] <= miss:
            miss += nums[i]
            i += 1
        else:
            result.append(miss)                # 记录翻倍前的值，即补丁本身
            miss *= 2
    return result
```

## 6. 面试里怎么说（边写边讲）
- 开始前：「这题的核心不变量是 `miss`——当前能保证凑出的连续区间是 `[1, miss)`。每一步要么消费一个
  真实元素扩展这个区间，要么打一个值为 `miss` 的补丁把区间直接翻倍。」
- 写 Part 1 时：「循环到 `miss>n` 为止，说明 `[1,n]` 全部覆盖了；补丁数就是翻倍发生的次数。」
- 写 Part 2 时：「和 Part 1 一模一样的循环，我只是在打补丁那一步多做一件事——把当前 `miss` 存下来，
  这样两个 part 天然保持一致，不用担心逻辑分叉。」
- 交付时：「三个官方样例都过了；`n=0`、空数组、已完全覆盖、包含大数值元素这几个边界也单独测了；
  贪心是 `O(len(nums)+log n)`，`n` 到 `2^31` 也能瞬间跑完。」

## 7. 常见跑偏（方法层面，3 条）
- **把 Part 2 写成"先跑 Part 1 拿到补丁数，再反推具体值"**：补丁值依赖于打补丁那一刻的 `miss`，
  跑两遍循环（一遍计数一遍收集）虽然也对，但容易在两份逻辑之间产生细微不一致，不如共享同一个循环体。
- **`n=0` 时忘记循环条件本身就不成立**：`miss<=n` 即 `1<=0` 一开始就是假，答案恒为 `0`/`[]`，
  不需要特判，但容易被误以为要单独处理。
- **忽略 `nums` 中比 `n` 还大的元素**：这些元素永远不会被消费（`miss` 追不上它们），贪心必须能正确
  "跳过"而不是提前终止或报错——用一条边界样例显式覆盖。
