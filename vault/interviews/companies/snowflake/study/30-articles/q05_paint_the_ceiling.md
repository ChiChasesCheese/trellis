# q05 · Paint the Ceiling：生成序列 + 计数有序对，练的是"排序之后阈值单调"这个技巧

> [!tldr]
> - 这题考的是：用递推公式生成 n 个"边长"，再数有多少个**有序对**（允许 i==j）乘积不超过阈值 a
> - 三步套路：先照抄递推公式生成序列（正确性第一）→ Part 1 暴力 O(n²) 计数验证 → Part 2 排序后对每个值二分数满足条件的另一半
> - 最值得带走的一个模式：**乘积不等式在正整数域可以转成除法阈值**——`x*y<=a` 等价于 `y<=a//x`，转成阈值之后就能排序+二分/双指针，是一类计数题的通用跳板

## 1. 题目在说什么（人话版）
给 6 个整数 `s0 n k b m a`，先用递推公式生成 `n` 条边长：`sides[1]=s0`，
`sides[i] = ((k*sides[i-1]+b) mod m) + 1 + sides[i-1]`（每一步都严格递增）。然后统计**所有有序对**
`(i,j)`（`i` 和 `j` 各自独立取遍 `1..n`，允许 `i==j`）里满足 `sides[i]*sides[j] <= a` 的对数。

三行小例子：
```
s0=2,n=3,k=3,b=3,m=2 -> sides=[2,4,6]
a=15: (2,2)=4✓ (2,4)=8✓ (2,6)=12✓ (4,2)=8✓ (4,4)=16✗ (4,6)=24✗ (6,2)=12✓ (6,4)=24✗ (6,6)=36✗
共 5 对合法，答案 5
```

## 2. 读题：把文字变成模型
- **实体**：一串按递推公式生成的边长；一个乘积阈值 `a`。
- **输入长什么样**：一行 6 个整数（或 `PART n` + 一行 6 个整数）。
- **输出要什么**：一个整数——满足条件的有序对个数。
- **状态**：生成阶段只需要"上一个边长"；计数阶段需要"排好序的边长数组"以支持二分。
- **一句话建模**：这是一个 **先按公式生成数组，再在数组上做『有序对计数、条件是乘积不超过阈值』**
  的问题——本质是把乘积不等式转成除法阈值后的排序+二分计数。

> [!note] 为什么选这个数据结构
> `s0>=1` 保证每条边长都严格为正且递增（不会出现 0，除法安全）。排完序后，对固定的 `x`，满足
> `x*y<=a` 的 `y` 就是 `y<=a//x`，这是排序数组上的一个前缀，`bisect_right` 直接定位，不需要为每个
> `x` 重新扫一遍全部 `y`。

## 3. 下笔顺序（面试里就按这个顺序敲）
1. **骨架先行**：写 `_generate(s0,n,k,b,m)`，先用官方样例手算验证生成是否正确（这一步错了后面全错）。
2. **Part 1 最小可用**：生成后暴力双重循环数满足 `x*y<=a` 的对数，O(n²)，正确优先。
3. **Part 2 叠加**：排序生成的数组，对每个 `x` 算 `threshold=a//x`，`bisect_right` 数有多少 `y<=threshold`，
   累加到总数。
4. **收尾**：`a=0`（答案恒为 0，因为所有边长>=1）、`n=1`（唯一的对是自己和自己）、`m=1`（mod 恒为0）等边界过一遍。

## 4. 代码怎么组织
```
_generate(s0, n, k, b, m) -> list[int]     # 递推生成 n 条边长，两版共用
part1(...) -> int                          # 暴力双重循环计数，O(n^2)
part2(...) -> int                          # 排序 + 逐元素 bisect_right，O(n log n)
main(stdin, stdout)                        # 解析、分发
```
生成逻辑只写一次（`_generate`），因为它是这题第一个、也是最容易出错的关卡——递推公式抄错一个符号，
后面计数逻辑再对也没用。计数逻辑 Part 1/2 分开写，因为复杂度台阶是题目明确要求的对比对象。

## 5. 核心代码（骨架，≤ 40 行，带注释）
```python
def _generate(s0, n, k, b, m):
    if n <= 0:
        return []
    sides = [s0]
    for _ in range(n - 1):
        prev = sides[-1]
        sides.append(((k * prev + b) % m) + 1 + prev)   # 严格递增，恒为正整数
    return sides

def part1(s0, n, k, b, m, a):                 # 暴力：所有有序对，允许 i==j
    sides = _generate(s0, n, k, b, m)
    return sum(1 for x in sides for y in sides if x * y <= a)

def part2(s0, n, k, b, m, a):                 # 排序 + 阈值二分
    sides = sorted(_generate(s0, n, k, b, m))
    total = 0
    for x in sides:                            # x>=1 恒成立，整除安全
        threshold = a // x                     # x*y<=a  <=>  y<=a//x（正整数域）
        total += bisect_right(sides, threshold)
    return total
```

## 6. 面试里怎么说（边写边讲）
- 开始前：「我先确认：`i` 和 `j` 是有序对，允许相同下标；边长严格递增所以永远不会是 0，除法安全。」
- 写生成函数时：「我先用题面给的官方样例手算一遍生成过程，确认递推公式没抄错，再往下写计数逻辑，
  不然计数再对也是错的。」
- 写 Part 1 时：「先写最直白的双重循环验证语义——每个 `x` 配每个 `y`，乘积不超过 `a` 就计数，正确性
  优先。」
- 写 Part 2 时：「排序之后，对每个 `x` 我要数有多少 `y` 满足 `x*y<=a`，等价于 `y<=a//x`——这是排序
  数组上的一个前缀，直接 `bisect_right` 定位，总体 O(n log n)。」
- 交付时：「官方样例过了；`a=0` 和 `n=1` 这两个边界也单独测了；Part 2 在 n=1e6 上做了性能测试，
  远低于预算。」

## 7. 常见跑偏（方法层面，3 条）
- **生成公式抄错**（比如漏掉 `+1` 或者把 `mod` 和 `+1+sides[i-1]` 的顺序搞反）：这是本题第一道关卡，
  一步错步步错，务必先用官方样例手算验证生成序列。
- **把"有序对、允许重复"当成"无序对、不重复"来数**：本题明确要求 `i==j` 合法且 `(i,j)`/`(j,i)`
  分别计数，如果直接套用"组合数"的去重逻辑会漏算一半以上。
- **忘记验证 `x>=1` 的假设就直接整除**：如果边长可能是 0，`a//x` 会除零；本题因为 `s0>=1` 保证了
  安全，但要在代码里说明这个假设，而不是当成理所当然。

## 8. 同族题 / 延伸
- "乘积不超过阈值的计数" 是一个通用模式，同族题包括"两数之积小于k的对数"（LC 1358 变体）、
  "满足某单调条件的二维计数"，核心都是排序后把不等式转成一维阈值再二分/双指针。
- 延伸思考：如果条件从 `<=` 改成 `<`，只需要把 `bisect_right` 换成 `bisect_left`（阈值同样是
  `a//x`，但要注意 `a` 恰好整除 `x` 时的边界）。
