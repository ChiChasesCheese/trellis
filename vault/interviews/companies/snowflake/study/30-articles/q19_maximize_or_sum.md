# q19 · Maximize OR-Sum：练的是"一眼贪心"和"证明过的贪心"的差别

> [!tldr]
> - 2026-05 Snowflake AIML 实习 OA 一手原题（= LC 2680）；**Part 2 k 到 10⁹、结果取模是 (reconstructed)**
> - 这题考的是：至多 k 次"某个元素翻倍"，让整个数组的按位或最大
> - 三步套路：证明"k 次全给同一个元素最优" → 前缀 OR + 后缀 OR → 枚举是哪个元素
> - 最值得带走的一个模式：**原帖作者"全给最大元素"的贪心是错的，也过了 HackerRank 测试**——测试没抓到不代表对，面试官会给反例

## 1. 题目在说什么（人话版）

数组里每次可以挑一个数乘 2，最多 k 次（同一个数可以反复挑）。做完后把所有数按位或起来，最大是多少？

```
[12, 9], k = 1
翻倍 12：24 | 9  = 11000 | 01001 = 11001 = 25
翻倍 9 ：12 | 18 = 01100 | 10010 = 11110 = 30   ← 答案
```

## 2. 读题：把文字变成模型

- **状态**：数组、k；预处理前缀 OR、后缀 OR。
- **关键事实**：翻倍 = 左移一位。把某个数左移 k 位，它的最高位到达 `msb + k`，任何"分给几个数"的方案都到不了这么高，而 OR 的大小由最高位决定；最高位相同时再比较低位，全给一个数也不亏——所以全给同一个数最优，只需要枚举给哪一个。
- **一句话建模**：**枚举被翻倍的元素 i，答案是 `(nums[i] << k) | (除 i 外所有元素的 OR)`**。

> [!note] 为什么不能只试最大的元素
> 例子里 12 > 9，但 9 左移后填上了 12 没有的位。最高位相同的元素之间，谁翻倍更好取决于其它元素的位分布，只能枚举。

## 3. 下笔顺序

1. **先举反例推翻"翻倍最大的"**，再说出"全给一个"并论证。
2. **Part 1**：`prefix[i+1] = prefix[i] | nums[i]`、`suffix[i] = suffix[i+1] | nums[i]`；`max((x << k) | prefix[i] | suffix[i+1])`。
3. **Part 2**：k 很大时结果有 10⁹ 位，不能真的算出来比。`k > 64`（保险取值，实际 > 31 就够）时被移位的数与其它数的位完全不重叠，候选值 = `nums[i]·2^k + others_i`：先比 `nums[i]`，再比 `others_i`，选出下标后 `pow(2, k, MOD)` 算模。
4. **收尾**：全 0、单元素、`k = 0`、相等最大值。

## 4. 代码怎么组织

```
_validate(nums, k)
_others_or(nums) -> list[int]        # 每个位置"除自己外的 OR"
max_or_sum(nums, k)                  # Part 1
max_or_sum_mod(nums, k)              # Part 2：小 k 精确后取模，大 k 先选下标再取模
part1 / part2
```

## 5. 核心代码骨架

```python
MOD = 1_000_000_007

def _others_or(nums):
    n = len(nums); pre = [0] * (n + 1); suf = [0] * (n + 1)
    for i, x in enumerate(nums):
        pre[i + 1] = pre[i] | x
    for i in range(n - 1, -1, -1):
        suf[i] = suf[i + 1] | nums[i]
    return [pre[i] | suf[i + 1] for i in range(n)]

def max_or_sum(nums, k):
    return max((x << k) | o for x, o in zip(nums, _others_or(nums)))

def max_or_sum_mod(nums, k):
    if k <= 64:
        return max_or_sum(nums, k) % MOD
    others = _others_or(nums)
    i = max(range(len(nums)), key=lambda i: (nums[i], others[i]))   # 先在真实大小上选
    return (nums[i] * pow(2, k, MOD) + others[i]) % MOD               # 再取模
```

## 6. 每个 part 叠加什么

| Part | 改动 |
|---|---|
| 1 | 前后缀 OR + 枚举 |
| 2 | 大 k 时位不重叠 → 按 `(nums[i], others_i)` 选下标 → 模幂 |

## 7. 常见坑

- "翻倍最大的元素"（反例 `[12, 9]`）。
- 把 k 次分给多个元素去搜索（指数级，而且不需要）。
- Part 2 先取模再比较大小——取模后的数没有大小意义。
- 相等最大值时没比较 `others_i`（`[6, 1, 6]`）。
- 忘了校验空数组、负 k。

## 8. 追问怎么接

1. **O(1) 额外空间？** 统计每一位被多少个元素占用（31 个计数器）；去掉元素 i 时，只清掉"计数为 1 且 i 占用"的位。
2. **操作换成"乘 3"？** 会进位、改变低位，"全给一个"不再成立，需要重新分析。
3. **操作换成"加 1"？** 同样破坏位结构；OR 的贪心只适用于纯移位。
4. **要求最大 AND？** AND 越移越小（低位补 0），通常 k 次不用最好，需逐位讨论。
