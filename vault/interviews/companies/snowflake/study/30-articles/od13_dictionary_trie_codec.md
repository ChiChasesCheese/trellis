# od13 · Dictionary Trie Codec：先划分字符集再证明无歧义，编码本身可被跳过

> [!tldr]
> - 这题考的是：自定义序列化格式设计（trie -> 字符串 -> trie），以及"不重建整棵树就能回答局部
>   查询"这一常见的流式/惰性解析模式
> - 三步套路：先固定一个字符集划分（控制字符 vs 数据字符）证明编码无歧义 → 用迭代（不是递归）
>   构建/序列化/解析这棵编码 → 让 `starts_with` 只扫描字符串本身、用括号匹配跳过不相关子树
> - 最值得带走的一个模式：**设计自定义序列化格式时，先证明"控制字符"和"数据字符"的字符集互不
>   相交，编码就天然无歧义、不需要任何转义**——这比事后打补丁式地处理"分隔符出现在数据里怎么
>   办"更根本

## 1. 题目在说什么（人话版）

把一组互不相同的小写单词建成一棵 trie，序列化成一个字符串（用于落盘/传输），再能从这个字符串
精确重建全部单词。额外要求：不反序列化整棵树，也要能回答"某个前缀是否存在"这种局部查询。

三行小例子：
```
serialize(["a","ab","b"])       -> "0a1b1##b1##"
deserialize("0a1b1##b1##")      -> ["a","ab","b"]
starts_with("0a1b1##b1##", "a") -> True
```

## 2. 读题：把文字变成模型

- **实体**：单词、trie 节点（是否是某个单词的结尾、孩子字母到子节点的映射）。
- **输入长什么样**：`words: list[str]`（只含小写字母）；`data: str`（编码后的字符串）；
  `prefix: str`（Part 3 查询用）。
- **输出要什么**：`serialize` 输出编码字符串；`deserialize` 输出字典序单词列表；`starts_with`
  输出布尔值。
- **状态**：构建/序列化阶段是一棵普通嵌套结构；反序列化阶段是一个"当前打开节点前缀"的显式栈；
  `starts_with` 阶段只有几个扫描下标。
- **一句话建模**：这是一道**自定义无歧义编码格式设计**题——语法是
  `node ::= flag (letter node)* '#'`，`flag` 是 `'0'/'1'`，本质和 od14 的长度前缀、od15 的
  JSON 语法同族。

> [!note] 为什么这个编码不需要任何转义
> 编码的字符集被划分成两类：控制字符（`'0'`、`'1'`、`'#'`）和数据字符（小写字母）。单词本身
> 只包含小写字母，永远不会产生一个看起来像控制字符的片段，所以解析方不需要处理"数据里出现了
> 分隔符怎么办"这个问题——先划分字符集、证明数据永远不会跟控制字符混淆，是设计自定义序列化格
> 式最容易被忽视也最重要的一步。

## 3. 下笔顺序（面试里就按这个顺序敲）

1. **骨架先行**：`_build_trie(words)` 建一棵普通嵌套 dict trie（逐词遍历，不需要递归）。
2. **Part 1 最小可用**：`serialize` 用显式栈做迭代先序遍历发射 `flag`/`letter`/`#`；
   `deserialize` 用一个"当前打开节点前缀"的显式栈做迭代递归下降，非法输入先不管，跑通样例。
3. **Part 2 叠加**：验证压缩率下界——`len(data) <= sum(len(w)) + 2*N`（`N` 直接数编码里的
   `'0'`/`'1'` 字符个数，不需要重建树）。
4. **Part 3 叠加**：给 `deserialize` 加齐非法输入分类（坏 flag、悬空边、未闭合、尾部多余数
   据）；写 `starts_with`——只扫描 `data`，命中就深入，不命中就用一个深度计数器跳过整棵子树。
5. **收尾**：跑一遍单词长度 `10**4` 的单链场景，确认 `sys.setrecursionlimit()` 调低后依然不报
   `RecursionError`。

## 4. 代码怎么组织

```
_build_trie(words) -> dict                        # 普通嵌套 dict，逐词遍历构建
serialize(words) -> str                            # 显式栈迭代先序遍历发射编码
_skip_node(data, i) -> int                          # O(1) 额外空间的括号匹配跳过
deserialize(data) -> list[str]                      # 显式栈迭代递归下降解析，非法输入抛 ValueError
starts_with(data, prefix) -> bool                   # 只扫描 data，不重建 trie，跳过不匹配子树
```

## 5. 核心代码（骨架，≤ 40 行，带注释）

```python
def _skip_node(data, i):
    # i 指向打开一个节点的 flag；返回它匹配的 '#' 之后的位置。
    # flag('0'/'1') 开一层、'#' 关一层，字母不改变嵌套深度——正是括号匹配，O(1) 额外空间。
    depth = 0
    while i < len(data):
        c = data[i]
        if c in "01":
            depth += 1
        elif c == "#":
            depth -= 1
            if depth == 0:
                return i + 1
        i += 1
    raise ValueError("unterminated node")

def starts_with(data, prefix):
    # 不重建任何 trie 对象：只沿 prefix 指定的路径扫描 data 本身。
    i = 1                                    # 跳过根节点的 flag
    for c in prefix:
        matched = False
        while i < len(data):
            ch = data[i]
            if ch == "#":
                break                        # 这个节点没有更多孩子了：prefix 走不下去
            letter, i = ch, i + 1
            i += 1                           # 跳过这个孩子的 flag 字符
            if letter == c:
                matched = True
                break                        # 命中：进入这个孩子的孩子列表，继续匹配下一个字符
            i = _skip_node(data, i)          # 不是要找的字母：跳过整棵不相关的子树
        if not matched:
            return False
    return True
```

## 6. 面试里怎么说（边写边讲）

- 开始前：「我先固定一下编码的字符集划分——`'0'/'1'/'#'` 是控制字符，小写字母是数据字符，两者
  不相交，所以不需要任何转义。」
- 写 `starts_with` 时：「不重建 trie，只扫描 `data` 本身；命中当前前缀字符就深入，不命中就用一
  个深度计数器跳过整棵子树，因为这个编码里字母不改变嵌套深度，flag 开一层、`#` 关一层，正好是
  括号匹配。」
- 交付时：「样例过了；单词长度 `10**4` 的单链场景我用显式栈而不是递归，验证过
  `sys.setrecursionlimit()` 调低也不报错。如果讨论并发，我会展开讲这个编码本身是不可变字符串
  带来的天然优势。」
- **如果被追问并发**：「`serialize`/`deserialize`/`starts_with` 都是对一段不可变字符串
  `data` 的纯函数，没有共享可变状态——多个线程同时对同一份 `data` 调用这三个函数完全安全，不
  需要任何锁。真正需要考虑并发的地方是如果加一层'反序列化结果缓存'（比如按 `data` 内容缓存已
  构建好的 trie 对象），那层缓存本身的读写才需要保护，编码/查询逻辑本身不需要。」

## 7. 常见跑偏（方法层面，含并发一条）

- 用 `del frame[key]`/字符串拼接式的转义方案处理"分隔符出现在数据里"，而不是从一开始就划分好
  互不相交的字符集——事后转义容易漏掉边界（比如转义字符本身又需要转义）。
- 用 Python 递归写 `serialize`/`deserialize`，在单词长度 `10**4` 的输入上直接撞上递归深度限
  制，而不是用显式栈。
- **并发相关**：给这类纯函数式的编解码逻辑加不必要的锁（比如以为每次调用都要保护
  `data`），没有意识到不可变输入 + 无共享状态天然就是线程安全的，白白牺牲了并发性能。
