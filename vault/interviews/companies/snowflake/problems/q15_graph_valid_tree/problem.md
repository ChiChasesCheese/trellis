# q15 · Graph Valid Tree — 判断无向图是否构成一棵树

> 2023 Snowflake OA 候选人索引直接复用的 LeetCode 原题。Part 1 为原题；Part 2 **(reconstructed)**：边一条一条到达，每条边加入后都要实时汇报"是否仍无环"和"还剩几个连通分量"。

## 背景

`catalog/raw/coding_oa.md` #17（对应 2023 Canada OA 索引 item #15）："Graph Valid Tree (LC-exact)"，直链 https://leetcode.com/problems/graph-valid-tree/ （LC 261），confidence MED，逐字复用无改编。

Part 2 的追问把一次性判定变成在线维护——这正是并查集（Union-Find）真正的用武之地：题面本身不需要"在线"，但面试官几乎必然会问"如果边是一条条加进来的，你怎么维护？"，答案就是标准的路径压缩 + 按秩合并并查集。

## 输入格式

- `n: int`（`n >= 1`），节点编号 `0..n-1`；
- `edges: list[list[int]]`，每条 `[u, v]`（无向边，`u != v`，`0 <= u, v < n`）。

非法输入（`n < 1`、边格式不对、端点越界、自环）抛 `ValueError`。

## API 契约

```python
def valid_tree(n: int, edges: list[list[int]]) -> bool
def valid_tree_online(n: int, edges: list[list[int]]) -> list[tuple[bool, int]]
```

## 规则

### Part 1 — LC 261 原题

给定 `n` 个节点和无向边列表，判断它们是否构成一棵**树**——即**连通且无环**。

**关键事实**：边数必须恰好是 `n - 1`（必要条件，但不充分——比如两个不相交的环各自节点数加起来也可能边数凑巧不对，因此还要真正跑一遍连通性/环检测）。用并查集：初始 `n` 个分量；每条边尝试合并两个端点所在的集合；如果两端点已经在同一集合，说明这条边会成环，直接判否；处理完所有边后，只要边数是 `n-1` 且没有一步成环，最终一定只剩 1 个分量，图就是一棵树。

### Part 2 — 在线维护 **(reconstructed)**

边按顺序一条条到达。每加入一条边后，报告 `(是否仍无环, 剩余连通分量数)`：
- 无环状态一旦被打破（某条边使两端点已经连通，形成环）就永远保持"有环"，后续边不会让它恢复——环只会累积，不会被"加边"消除。
- 连通分量数只在真正发生合并（两端点原本不连通）时才减少；成环的边不改变分量数。

## 边界清单

- 单节点、零边（`n=1, edges=[]`）是一棵树
- 边数不等于 `n-1`：太少必然不连通，太多必然有环（两种都判否，不必先分类讨论）
- 连通但含环、以及不连通（分裂成多个分量）
- Part 2：环一旦出现，后续所有边的 `still_acyclic` 都保持 `False`（不会"恢复"）
- Part 2：零条边时输出为空列表
- 非法输入：`n<1`、端点越界、自环、边格式不对、非整数 → `ValueError`
- 性能：`n = 10⁵`（一棵随机打乱的树，`n-1` 条边）两个 part 都 < 2 s

## 追问

1. **为什么"边数 == n-1"不能单独判定？** 两个不相交的环加起来节点数、边数都可能巧合等于 `n` 和 `n-1`（比如两个三角形共 6 节点 6 边，n-1=5 不等，实际上边数不匹配就会被直接过滤掉；真正的陷阱是"连通但边数对但其实内部有环、外部有孤立点"这种边数计算凑巧相等的构造，需要构造反例验证），所以边数只是必要条件，必须真正做连通性+环检测。
2. **路径压缩 + 按秩合并的复杂度？** 均摊 O(α(n))（阿克曼函数的反函数，实践中视为常数），`m` 条边总复杂度 O(m·α(n))。
3. **如果边可以被删除呢？** 并查集不支持高效删除；需要换成"离线转在线"的技巧（如按时间倒序处理删除转合并），或者用更重的动态连通性结构（如 Euler Tour Tree）。
4. **能否只用 DFS/BFS 代替并查集？** 可以（一次性判定完全等价），但在线场景每加一条边都要重新 DFS/BFS 是 O(n) 每次，总 O(mn)，远不如并查集的 O(m·α(n))。
