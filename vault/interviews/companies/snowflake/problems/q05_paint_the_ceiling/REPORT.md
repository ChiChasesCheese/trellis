# q05 Paint the Ceiling — report

## 摘要
线性递推生成序列 + 计数满足乘积阈值的有序对。表面是"生成器"题，实际考点在计数口径
（有序、允许重复）和排序后如何把 O(n^2) 降到 O(n log n)。官方样例的生成过程和计数过程都
逐位手算验证过，是本题正确性的锚点。

## 来源与置信度
中等 — 主源 https://www.fastprep.io/problems/snowflake-paint-the-ceiling（递推公式、计数
规则、样例）；2026 面经合集 linkjob.ai 佐证标题与"two-pointer"解法方向。`s0>=1` 的边界假设
是作者基于"边长是物理量"这一题目语境补全的，不是题面逐字给出。

## 逐 part 思路
- **Part 1**：直接生成 `sides` 数组（`O(n)`），再暴力双重循环枚举所有 `n^2` 个有序对
  计数，`O(n^2)`，用于交叉验证 part2 的正确性。
- **Part 2**：生成后排序 `O(n log n)`；对每个 `sides[i]`（排序后遍历），用
  `bisect_right(sorted_sides, a // sides[i])` 在 `O(log n)` 内统计满足条件的 `j` 的个数
  （因为所有值是正整数，`x*y<=a` 精确等价于 `y<=a//x`）；总复杂度 `O(n log n)`。

## 隐藏测试针对的坑
1. **有序对 + 允许重复**：`(i,j)` 与 `(j,i)` 是两个不同的对且都要计数，`i==j` 也算一对
   （同一条边同时当长和宽）——官方样例的 5 这个答案本身就依赖这个口径（如果按无序不重复
   算会得到不同的数字）。
2. **生成公式的下标语义**：`sides[1]=s0` 不经过递推变换，是很多人会看漏的一点；从
   `sides[2]` 起才套用 `((k*s+b) mod m)+1+s`。
3. **整除代替浮点比较**：`x*y<=a <=> y<=a//x` 只有在 `x,y` 都是正整数时才精确成立；如果
   写成 `y <= a/x`（浮点除法）再取整，边界值上可能因为浮点误差多算或少算一个。
4. **`m=1`、`k=0`、`b=0` 等退化参数**：mod 恒为 0，递推简化为固定步长递增，容易被写死的
   特判逻辑打破——测试专门覆盖这些组合。
5. **part1 与 part2 的一致性**：这是本题除官方样例外最主要的正确性防线，50 组随机参数
   （含 `m=1`、`k=0`、`b=0`、`a` 极小/极大）交叉验证两者输出完全一致。

## 复杂度与实测
- Part 1：`O(n^2)`，仅用于交叉验证，测试中 n 保持 <= 200。
- Part 2：`O(n log n)`（生成 `O(n)` + 排序 `O(n log n)` + 每元素一次 `bisect`）。perf 测试
  用 `random.Random(0)` 生成 `n=1,000,000`，实测远低于 2s 预算（本机 <1s）。

共 12 个测试：
- `part1`：5 个（含 3 个 `edge`：生成+边界值、`n=1` 自配对、`m=1` 退化参数的精确计数）
- `part2`：5 个（官方样例、`n=1` edge、`a=0`/`a` 巨大 edge、50 轮随机交叉验证）+ 1 个
