# q23 · Work Schedule — 一周 7 天的 `?` 填法，凑出总工时

> OA 题（TrueInterview 同步清单 #72，2025-07 报告；本 kit 缺口补建）。Part 1 为原题
> （列出所有填法）；Part 2 **(reconstructed)**：只计数，规模放大到 DP。

## 背景

TrueInterview 清单 #72 "Work Schedule（`?` 填充枚举）"（2025-07 报告）：一周 7 天的排
班用一个 7 字符的 `pattern` 表示，每个字符要么是已经定好的工时（数字 `'0'`–`'8'`），要
么是待定的 `'?'`；每个 `'?'` 可以填 `0` 到 `dayHours` 之间的任意整数（含端点），使得
一周总工时恰好等于 `workHours`。返回所有满足条件的排班，按**字典序**排列。预览未给出
具体样例，本 kit 按标准形状重建题面与样例。

## 输入

- `pattern`：恰好 7 个字符，每个字符是 `'?'` 或 `'0'`–`'8'`；
- `workHours ≥ 0`，`0 ≤ dayHours ≤ 8`；
- 非法输入（`pattern` 长度不是 7、出现非法字符、`workHours < 0`、`dayHours` 超出范围）
  抛 `ValueError`。

## API 契约（英文签名）

```python
def all_schedules(pattern: str, work_hours: int, day_hours: int) -> list[str]
def count_schedules_mod(pattern: str, work_hours: int, day_hours: int) -> int
```

## 规则

### Part 1 — 列出所有排班，字典序排列

对 `pattern` 里每个 `'?'` 位置按从左到右回溯，每个位置尝试 `0..dayHours`（升序尝试）；
用后缀的"固定工时之和"与"剩余 `'?'` 个数 `× dayHours`"算出**当前部分和继续下去能达到
的工时区间 `[lo, hi]`**，一旦 `workHours` 不在这个区间里就剪枝，不再往下递归。因为
`'?'` 按升序尝试、位置按从左到右递归，生成的结果天然就是字典序，不需要额外排序。

### Part 2 — 只计数，规模放大到 `pattern` 长度 ≤ 10³、`workHours` ≤ 10⁴，
### 结果对 `1_000_000_007` 取模 **(reconstructed)**

Part 1 的回溯在 `pattern` 变长后不再可行（分支数是 `dayHours` 的幂）。改用 DP：
`dp[i][s]` = 前 `i` 天工时总和恰为 `s` 的方案数。固定数字的天：`dp[i][s] = dp[i-1][s-d]`，
是一次整体平移。`'?'` 的天：`dp[i][s] = Σ_{v=0}^{dayHours} dp[i-1][s-v]`——这是一个宽度
`dayHours+1` 的滑动窗口和，如果对每个 `s` 都重新求和是 `O(dayHours)`，全部加起来是
`O(n · S · dayHours)`；用**前缀和**预处理 `dp[i-1]` 后，每个 `s` 的窗口和变成两次前缀
和相减，整层降到 `O(S)`，总复杂度 `O(n · S)`。

## 边界清单

- 无 `?`：直接判断固定总和是否等于 `workHours`
- `workHours = 0`：全部 `?` 填 0
- `workHours` 等于全部填满 `dayHours` 的理论最大值（唯一解）
- `workHours` 超出理论上下界（`Part 1` 空列表、`Part 2` 为 `0`）
- 字典序验证：`?` 靠左的位置数字越大排班字符串越靠后（`"??00000"` 例）
- 非法输入：长度不是 7、非法字符（含 `'9'`）、`workHours < 0`、`dayHours` 超出 `[0,8]`
  → `ValueError`
- Part 2 允许 `pattern` 长度超过 7（不受 Part 1 的"恰好一周"限制）
- 性能：Part 1 全 `?`（分支数最大）`pattern` 在 `workHours` 居中时 `< 2s`；Part 2
  `pattern` 长度 1000、`workHours` 8000（`= 1000×8` 的理论上限，DP 表最大规模）`< 2s`

## 追问

1. **为什么升序回溯天然给出字典序？** 因为排班字符串只在 `?` 位置变化，其余位置对所
   有解都相同；只要保证每个 `?` 位置的取值按数值升序被访问、且外层是从左到右的位置顺
   序，生成顺序和字符串比较的字典序完全对应，不需要事后 `sorted()`。
2. **前缀和加速滑动窗口和的技巧还能用在哪？** 任何"某一步的转移是对前一状态某个定长
   区间求和/求最值"的 DP 都能用（区别是求和用前缀和，求最值要用单调队列，因为最值不能
   像和一样用减法抵消）。
3. **如果 `dayHours` 每天不同呢？** DP 转移里的滑窗宽度按天变化即可，前缀和技巧照样
   成立，只是每层的窗口宽度参数不同。
4. **能不能只统计"至少用了 `k` 个不同工时值"这类带约束的计数？** 需要在状态里再加一
   维（比如"已用的不同数字集合"用位掩码），状态空间乘上 `2^9`，对本题的 `S ≤ 10⁴`、
   `n ≤ 10³` 规模已经不便宜，通常会问"能不能换一种更弱的约束"来控制状态维度。
