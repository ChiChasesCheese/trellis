# TikTok：每一轮考什么、怎么过

这一页按轮次讲：形式、评分看什么、过线标准、常见的失败、该怎么准备。目标是 Senior Backend Software Engineer（美国，San Jose 的 Innovative Growth 组）。按 senior 标准准备：讲得清范围和影响，比较两种方案的取舍，主动补测试、边界和失败处理。每一轮都是单轮淘汰，一轮失败，后面已经约好的轮次会被取消。

## 总览

| 轮 | 时长 | 主要内容 | 去哪练 |
|---|---|---|---|
| 招聘官电话 | 20–30 分钟 | 背景、地点、入职时间、签证、级别、薪资预期 | [[06-questions-to-ask]] |
| 技术面 1 | 45–60 分钟 | 简历拷问 + 1–2 道编码 | 编码 deck 24 / 25 |
| 技术面 2 | 45–60 分钟 | 再一轮编码，或后端基础八股，或系统设计 | [[tiktok-fundamentals]] · [[tiktok-sd-index]] |
| 系统设计 | 45–60 分钟 | 一个流程密集的 HLD（高层设计），面试官追问其中一条流程 | [[tiktok-sd-index]] |
| 项目深挖 / HM | 45–90 分钟 | 项目、行为题，常常加一道编码或一个设计 | [[behavioral/00_how_it_works]] |
| HR / 总监 | 20–30 分钟 | 物流、薪资、行为题；有的组加一场 20 分钟的总监面 | 本页末尾 |

不同组的排列不一样：有的组 2 轮编码 + 1 轮行为，没有单独的设计轮；有的组 1 轮编码 + 1 轮设计 + 1 轮项目 + HR。招聘官给每一轮贴的标签不可靠：标「设计」的可能是纯编码或八股，标「编码」的也可能是一道设计题。三类都要准备，写代码的工具里也要能用文字描述架构。

## 招聘官电话

- **形式**：20–30 分钟，对方常在亚洲，可能是 LinkedIn 找来的猎头。
- **评分看**：地点（San Jose 还是别处）、入职时间、签证、级别区间、薪资预期，不考技术。
- **过线标准**：一句话讲清你做什么（支付费用管线、Snowflake / PostgreSQL、Java / Python / SQL）；说得出工作许可状态；不抢先报薪资数字。
- **常见失败**：没问清 req 对应的级别就进入下一轮，结果走完三轮只剩低一级的名额。
- **准备**：
  - 背 30 秒版自我介绍（[[behavioral/question_bank]] Q1）。
  - 问四件事：这个 req 的级别区间和是否仍在招；属于 TikTok 本体还是 USDS 合资公司；每一轮的形式和语言，编码用什么平台、是否允许 AI 工具；通过的轮次在换组重面时是否保留。
  - 【待补：工作许可状态的一句话回答】

## 技术面：编码

- **形式**：
  - 前 10–45 分钟拷问简历和项目，然后 1–2 道题，在 HackerRank 或 Lark 代码板里写，没有起始类，没有默认输入。
  - 语言不限，主流语言都行；你用 Python 写。
  - 题以 medium 为主，常被改写成业务场景，面试官会在半场把题改难；一道题的节奏约 20 分钟。
- **评分看**：
  - 写完、能运行的代码，加上你自己写的测试。
  - 先说思路和复杂度再动手，写的时候解释。沉默地写出对的代码，证据比边讲边写弱。
  - 最终解要是最优复杂度，不要求第一版最优，要求在一小时内从暴力走到最优。
  - 对追问的处理：不改输入、O(1) 额外空间、流式输入、放不进内存、已排序输入上的亚线性、加 TTL / LFU / 线程安全、「命中率低怎么办」。
- **过线标准**：
  - 先澄清（输入范围、重复、空输入、是否允许改输入），再说暴力解和复杂度，再优化。
  - 写完后用一个小例子手动走一遍，再补 3 个边界用例跑通。
  - 追问来了，说出「这一步要改的是哪一行 / 哪个结构」，不重写。
- **常见失败**：
  - 简历拷问拖长，只剩 15 分钟写题；没有主动说「我先写题，项目细节下面再展开」。
  - 思路对但代码没写完；写完了没有测试；不解释关键判断（例如拓扑排序里为什么要检查入度）。
  - 暴力解被直接否决（树上路径和用 O(n²) 被要求用前缀和），没想到换结构。
  - 面试官让你不要把光标移出代码板，或用自己的 IDE 加 AI：不了解当次规则就开始写。
- **AI 辅助变体**：个别组会让你用自己的 IDE 和 AI 工具现场实现一个带规则的小系统（例如订单校验器，规则是 DAG，删除一条规则要把前驱接到后继）。评分是你交付的**能跑的代码和完整的测试**，不是 AI 写了多少。测试没写完，当场就会失败。进场前问清楚这一轮是否允许 AI。
- **要练的题型**（按优先级）：
  1. 带 TTL / LFU / 加权 / 线程安全的 LRU 缓存，时间戳 KV、快照 / 恢复 KV，轮转 + 堆的调度器，幂等的版本化更新，滑动窗口限流。
  2. 网格与图（岛屿及其变体：不改输入、不同形状、流式、动态加陆地）、拓扑排序家族（课程表、外星字典、并行课程、构建顺序）、并查集。
  3. 表达式计算器（有无括号、一元负号）、K 个一组翻转链表（尾部不足 K 个怎么办）、O(1) 空间螺旋矩阵、有序数组上的二分变体。
  4. 堆 / Top-K / 数据流中位数，区间（合并、会议室），滑动窗口。
  5. 树的最大路径和（要求把路径打印出来）、路径和（用前缀和）、单词搜索 II（Trie）。
  6. 难的 DP / 回溯，放到最后。
- **准备**（可以反复演练）：
  - 用光板编辑器限时 20 分钟写一道 medium，不能补全，不能运行外部文件；写完 3 分钟内造出 5 个用例并跑过。
  - 每道题做完，自己问一遍上面的追问清单，写出每个追问要改的位置。
  - 一道题讲出声：先说「Here is my plan」，再写，写的同时说判断。
  - 去哪练：Anki `LeetCode Tops::24 TikTok 字节高频 · 整题答案`，先 **模式识别** 和 **Python 工具箱** 两个分支，再 `::25 · 拆分背诵`。

## 技术面：后端基础（八股）

- **形式**：口头问答，问机制，不是背定义。可能占一整小时，也可能是 50 分钟八股 + 10 分钟写代码。
- **评分看**：能不能讲到机制那一层：为什么这样设计、坏的时候会怎样、你怎么验证。
- **常考**：
  - 索引：B+ 树、联合索引的最左前缀、覆盖索引、为什么不给每一列建索引。
  - 事务隔离、MVCC、死锁。
  - 缓存：穿透、击穿、雪崩、cache-aside 一致性、热点 key。
  - Redis：分布式锁、持久化、sorted set。
  - Kafka：分区、重平衡、有序性、持久性、日志和队列的区别。
  - 幂等与分布式事务。
  - 并发：Java 的 ConcurrentHashMap、线程池、GC；Python 的 GIL。
  - 网络：TCP 握手、TIME_WAIT、TLS。
  - 服务保护：限流、降级、熔断、退避重试。
- **过线标准**：每个名词后跟一个「因为……」；被追问到不会的一层，说最深已知层、边界、怎么查，不编。
- **常见失败**：只能背定义；对自己简历上写过的东西（Kafka、Snowflake、幂等）讲不出内部机制。
- **准备**：[[tiktok-fundamentals]] 按主题过一遍，每个主题口述 2 分钟。

## 系统设计

- **形式**：45–60 分钟，有时压缩成混合一小时里的 15 分钟，有时放在 HM 面里（前面还有项目和一道编码）。
  - 题目常是团队真实产品的一个模块，两句话，不一定有人帮你澄清。
  - 白板不一定有：编辑器可能只能打字，你要能用文字加编号步骤讲清架构。
  - 面试官挑**一条流程**反复追问，整场围绕它。
- **评分看**：
  1. **先估算**：QPS、每事件存储、带宽，再画。
  2. **精确还是近似**：先问这个数是否必须精确。不问就设计，会被拒。
  3. **分层**：采集 / 聚合 / 服务。
  4. **失败处理**：重连、exactly-once 的效果、迟到事件、热点 key、崩溃在两步之间、重复或丢失的回调。
  5. **机制层的知识**：窗口类型、count-min sketch 的误差界、Kafka 分区。
- **过线标准**：每一个组件都说得出「它坏了会怎样」；追问同一条流程时前后一致，不推翻自己刚说过的话。
- **最可能的题**：
  1. 支付系统：幂等键、状态机 + 追加式账本（整数最小货币单位）、与 PSP（支付服务商）的对账、异步结算和 webhook、部分 / 全额退款、PSP 切换和故障转移、卖家出款。
  2. LIVE 礼物 / 金币结算：全球分布、幂等、每场直播的创作者收入、每周结算。
  3. 排行榜 / 热榜：窗口聚合、近似算法、热点 key。
  4. 内容审核：ML 分数 + 规则 + 人工复核 + 申诉 + 审计日志。
  5. 抢票 / 秒杀、实时竞拍、任务调度器、监控 / 告警聚合、信息流推荐。
- **常见失败**：
  - 在 HM 面里只剩 30 分钟时，把时间花在 UI 或集成细节上，核心的幂等和对账没讲。
  - 估算站不住：数字讲不出推导。
  - 追问一条流程时反复修改自己的方案。
- **准备**：
  - 读 [[tiktok-sd-index]]，从支付系统开始；每题口述 25 分钟，计时。
  - 练一次「不画图」：只用编号步骤和表格，把数据流讲出来。
  - 每题准备一个「崩溃在第 N 步」的追问回答。

## 项目深挖 / HM 面

- **形式**：45–90 分钟。项目讲解 + 行为题；常常再加一道编码（区间、0-1 BFS 之类）或一个高层设计（支付系统）。面试官可能先问「你会说中文吗」，然后整场换成普通话。
- **评分看**：
  - **ownership**：范围、决策、指标是你的，不是团队的。HM 用它定级。
  - **深度**：选了这个架构，为什么，指标证明了什么，重来会改什么；架构、模式、索引、并发模型被逐项挑战。
  - **强度**：「能不能承受高强度的工作」会直接问，和中国团队的晚间会议是常态。
  - **fit**：为什么离开、为什么这个组、怎么用 AI。
- **过线标准**：
  - 两个项目各能讲 30 分钟：[[behavioral/deep_dive]]。
  - 三个事故 / 失败故事，带数字，带你个人的动作：[[behavioral/question_bank]]。
  - 一个故事 60–90 秒讲完，数字说得出口，说「我」做了什么。
- **常见失败**：
  - 追问同一条流程时先提出一个方案，再自相矛盾。
  - 把故事讲成团队总结，说不出自己那一份。
  - 浅薄的行为题回答，或基础不牢，或对 IDE / 平台操作生疏。
- **准备**：
  - 每天口述两个故事（用计时器）；每周一次把 [[behavioral/deep_dive]] 的 12 个问题连着问自己。
  - 中文版：S1、S5 各一个 90 秒口述。
  - 通读 [[behavioral/bytestyle]]，知道哪个故事对应哪条价值观。

## HR 与总监面

- **形式**：HR 电话 20–30 分钟，物流和薪资；个别组再加一场 20 分钟到一小时的总监或部门经理面。
- **评分看**：动机、团队协作、职业规划；总监面看你对业务方向的理解。
- **过线标准**：回答简短、真实；不先报数字；不提前一家一家比较 offer。
- **准备**：
  - 薪资：公开的 base 区间是 $218,400–$387,600（San Jose，这个 Senior 岗）；总包 = base + 年度奖金 + RSU。RSU 4 年归属，近年的比例约 20 / 25 / 25 / 30，有 12 个月 cliff（满一年才开始归属），公司股票没有公开市场，靠定期回购变现。让对方把每一项的数写下来，不要只看 base。
  - 反问见 [[06-questions-to-ask]]。

## 级别与组匹配

- **级别**：HM 看简历深挖和设计轮的表现，把你放在组里有名额的级别上。强的面试也可能因为名额只剩一级而得到低一级的 offer，或者被告知可以重面另一个组。
- **目标岗位的公开要求是 3 年以上经验，同系列里也有写 7 年以上的 Senior 岗**：先问 req 的级别，再决定怎么讲 scope。
- **你要怎么提高级别的证据**：
  - 事实：S1 从空壳到 18 个月生产、S5 费用侧负责人、S2 框架 8 个领域铺开，这些是范围。
  - 决策：S5 的 A / B 方案取舍、S2 ADR 的四个方案，这些是判断。
  - 指标：22M 笔交易、13.7M 行 / >99.9% 一致、约 50 / 35,000 个商户，这些是证据。
- **换组重面**：HM 面失败后被转到另一个组的面试是常见的；问招聘官已通过的轮次是否保留。
- **组里名额收紧**：req 中途关闭、招聘暂停都发生过；一轮通过后迟迟没有下一轮，礼貌地问进度。
