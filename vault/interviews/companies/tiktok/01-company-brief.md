# 01 · 公司简报（TikTok / ByteDance）

TikTok 是 ByteDance 做的短视频应用；ByteDance 是一家总部在北京创立、全球经营的私人公司，用同一套推荐算法和同一套工程平台撑起一打以上的产品。这份简报先讲产品和收入线，因为后端工程师做的系统就长在这些收入线上；再讲工程团队怎么运作、用什么技术、规模有多大；最后讲面试官可能提到的美国背景。你不需要在面试里复述这些，目的是让你听懂面试官在问哪一块业务，并把自己的支付 / 数据管线经验接到合适的位置。每个概念第一次出现都给一句白话解释，每个结论写出因果。

## 0. 一页结论

1. **ByteDance 是母公司**：产品包括 TikTok、CapCut（剪辑）、TikTok Shop（电商）、Lark（办公套件，国内叫飞书）、Pico（XR 设备）、Mobile Legends: Bang Bang（游戏）；中国有抖音、今日头条、番茄小说、西瓜视频。官方说法是 15 万以上员工、遍布近 120 个城市，使命是「Inspire Creativity, Enrich Life」。
2. **你面的组是 Innovative Growth（San Jose）**：做 TikTok 的增长和内容优化系统，涉及 Web、Lite 等平台，用 AIGC、搜索与发现。它比广告或支付离业务指标更近：实验平台、流量渠道、AI 工具。
3. **最可能的设计题仍是支付**：因为 LIVE 的虚拟礼物、TikTok Shop 的交易和广告结算，都需要钱的正确性。你的 PayPal 管线经验是对口的，增长组的题则更偏产品。
4. **后端主力语言是 Go**：内部有数以万计的 Go 微服务，开源了 CloudWeGo（Kitex、Hertz）。岗位写 Go / Python / Java / C++ 都可以，面试里任何主流语言都行，你用 Java / Python 没问题。
5. **美国有两条招聘线**：TikTok 本体和 USDS 合资公司（2026 年 1 月成立）。你的岗位在本体。
6. **公开的 base 区间 $218,400–$387,600**（San Jose，这个 Senior 岗），RSU 另算。
7. **不要报没把握的数字**：除了下面列出的公开数字，别在面试里报 ByteDance 的内部规模。

## 1. TikTok 与 ByteDance：一套引擎，多个应用

**先讲因果。** 短视频的价值来自「每个用户看到的下一条视频都合适」，这靠推荐系统：把用户的每个动作（看了多久、点赞、划走）变成特征，实时训练模型，再用模型给下一次请求排序。这种系统很贵，也很难复制，所以 ByteDance 把它做成一个共用的平台，再用它启动一个又一个应用。结果是：

- 不同产品（TikTok、抖音、CapCut）共用招聘、工程平台和很多基础组件，所以 TikTok 与 ByteDance 的职位、层级、面试流程基本一致，面试官也会在两边之间流动。
- 一个组的工作往往能搬到别的应用上，所以「平台能力」（RPC 框架、消息队列、数据仓库、实验平台）在公司里很重。

**规模的口径**（公开的）：

| 说法 | 含义 |
|---|---|
| ByteDance 15 万以上员工，近 120 个城市 | 官方数字 |
| TikTok「全球超过十亿人」使用 | 官方说法，没有分国家的数字 |
| 美国「超过 2 亿用户、750 万企业」 | 合资公司的公告口径 |
| TikTok 总部在 Los Angeles 和 Singapore | 另有 New York、London、Dublin、Paris、Berlin、Dubai、Jakarta、Seoul、Tokyo 等办公室 |

## 2. 收入线：后端工程师做的系统长在哪里

后端系统由收入线决定。每条线都告诉你面试会考什么：

| 收入线 | 是什么 | 对后端的要求 |
|---|---|---|
| **广告 / 变现**（Global Monetization） | 信息流里的广告：出价、投放、点击和转化的统计，向广告主计费 | 实时聚合、反作弊、预算控制、结算与对账 |
| **TikTok Shop**（全球电商） | 用短视频和直播带货：商品、订单、支付、物流、退款 | 交易状态机、库存扣减、支付幂等、秒杀流量 |
| **TikTok LIVE** | 直播间里观众购买虚拟礼物（先买金币，再用金币送礼），主播按规则分成，定期结算 | 金币账本、幂等、每场直播的收入统计、跨国结算 |
| **用户增长**（你的组） | 拉新、留存、内容的搜索和发现、实验 | 实验平台、数据管线、流量渠道、AIGC 内容生成 |
| **信任与安全** | 内容审核：ML 打分、规则引擎、人工复核、申诉 | 规则不发版即时生效、审计日志、数据驻留 |
| **推荐** | 大模型和大规模 ML 系统，排序和召回 | 特征管线、在线训练、低延迟服务 |

**因果**：因为 LIVE 和 Shop 都有钱的流动，所以这两块的后端要处理「同一笔钱不能被扣两次」「订单不能在没收到钱时标成已付」。这与你在 PayPal 做的结算和费用管线是同一类问题：幂等、状态机、追加式账本、对账。这解释了为什么支付系统是最常被问的设计题。

**你的组**：Innovative Growth 的岗位说明写的是「面向 TikTok 的增长和内容优化系统，用 AIGC 技术和创新的搜索与发现策略」，偏好技能包括 AIGC / LLM 应用、agent 框架、AI 编码工具、实验平台、SEO 与 GEO（面向生成式引擎的优化，也就是让内容被 AI 搜索引用）。这意味着：

- 设计题可能偏产品，例如实验平台、内容生成管线、流量归因，不只是支付。
- 行为题会问你怎么用 AI 工具工作，见 [[behavioral/question_bank]] Q28。
- 「怎么证明一个改动有效」是这个组的日常，你的 S10（公开撤回自己的数字）和 S5（用生产查询自己做验证）正好对口。

## 3. 工程团队怎么运作

### 3.1 组织：各组自己招人

- **各组自己招**：用人组有自己的 headcount（名额），面试官来自这个组，所以不同组的轮数、顺序、题型不同。
- **面试官分散在多个时区**：很多人在新加坡或中国，轮次可能排在晚上。
- **重组是常态**：req 会中途关闭，HM 面没过会被推荐去面别的组。因果：名额跟着业务优先级走，所以面试里「你合适」和「这个组此刻有位子」是两回事。
- **工作地点**：办公室每周至少 3 天，按组可到 5 天。

### 3.2 语言与框架

- **Go 是后端主力**。内部有数以万计的 Go 微服务。因为服务多、调用多，ByteDance 自己做了 RPC 和 HTTP 框架并开源：**CloudWeGo**。
  - **Kitex**：RPC 框架（Thrift / gRPC），公开数字 2022 年支撑 6 万以上内部服务，峰值 QPS 到亿级。
  - **Hertz**：HTTP 框架，2022 年 1 万以上在线服务，峰值 QPS 4000 万以上。
- 岗位说明写 **Go、Python、Java、C++**；电商岗位还列 Scala。面试里主流语言都接受，所以你用 Java / Python 答题没有问题；入职后上手 Go 会有帮助。

### 3.3 存储与数据

这些是公开论文里的系统，面试不会直接考，但提到它们说明团队的规模压力在哪里：

| 系统 | 做什么 | 因果 |
|---|---|---|
| **ByteGraph** | 分布式图数据库，存社交关系 | 关注 / 好友 / 互动是图，规模到数百亿节点、万亿条边，通用图库扛不住；两层结构（持久层 + 缓存层） |
| **ByteHTAP**（基于 ByteNDB + Flink） | 同时服务交易和分析（HTAP） | 业务数据要在 1 秒内进入分析，免得先导出再算 |
| **ByteHouse**（开源版 ByConity） | 云原生数据仓库，ClickHouse 血统 | 实时多模态分析要快 |
| **ByteMQ / BMQ** | 兼容 Kafka 协议的云原生消息队列 | 要保留 Kafka 生态，但存算分离以降本 |
| **Flink** | 流处理，运行数万个并发作业 | 实时特征、实时指标 |
| **Monolith** | 推荐的在线训练系统 | 用户动作进来，模型立即更新；用无冲突的 cuckoo 哈希表存 embedding，过期的 embedding 会被淘汰 |

面试中出现的却是**通用组件的机制**：MySQL 索引与事务、Redis 数据结构与持久化、Kafka 分区与重平衡、Elasticsearch 倒排索引、Hadoop。因果：自研系统外人看不到，面试官只能考大家都懂的底层。所以备考重点是通用机制，见 [[tiktok-fundamentals]]。

### 3.4 文化与价值观

- 官方有六条价值观，叫 **ByteStyle**，见 [[behavioral/bytestyle]]。它不是公布的评分表，是 HM 听你的故事时用的透镜。
- 招聘页写「我们以好奇、谦逊和产生影响的愿望来领导，保持 Always Day 1 的心态」。
- 内部用 Lark 开会和写文档，所以编码面试用 Lark 代码板也不奇怪。
- 工作强度：面试里会直接问「你能不能承受高强度的工作」，与中国团队的晚间会议是常态。如实回答，说你怎么保持可持续，见 [[behavioral/question_bank]] Q32。

## 4. 美国背景：面试官可能提到什么

**Project Texas**（2022–2024）：TikTok 把美国用户数据放到 Oracle 云上，由一个隔离的美国数据安全组织（USDS）管理。因果：美国政府担心数据流向中国，所以要「数据留在美国、由美国人管」。

**TikTok USDS Joint Venture LLC**（2026 年 1 月成立）：

- 目的：保护美国用户数据、应用和算法的安全。
- 股东：Oracle、Silver Lake、MGX 三个管理投资人各约 15%，ByteDance 约 19.9%，其余是其他投资人。多数美国人组成的 7 人董事会，包括 TikTok CEO。
- 分工：合资公司负责美国的数据安全、信任与安全、内容审核，并在 Oracle 云里用美国用户数据重训和更新推荐算法；TikTok 全球的美国实体管理全球产品的互通，以及电商、广告、营销等商业活动。

**对你的含义**：

- 两条招聘线：USDS（数据安全、内容审核、美国基础设施）和 TikTok 本体（广告、电商、增长、LIVE）。你的岗位在后者。招聘官电话里问清 req 属于哪个实体。
- 招聘在交易前后有过暂停，后来恢复。面试被取消或 req 关闭不一定说明你的表现。
- 面试官可能问的几个问题，和回答方向：

| 可能被问 | 回答方向 |
|---|---|
| 为什么现在想加入 TikTok？ | 讲产品和你想做的工程问题（增长、实验、数据管线），不碰政治。【待补：你真实的原因】 |
| 数据驻留怎么影响设计？ | 数据按区域存放，跨区域只传聚合结果或脱敏数据；审核的审计日志按区域保留。这是设计推理，不要说成你做过 |
| 怎么和中美两地的团队协作？ | 异步沟通、文档先行、明确的决策人、固定的重叠时段。【待补：你的真实例子】 |

## 5. 面试里被问到公司时

- **只讲公开的**：产品线、岗位说明里的方向、官方价值观、公开论文里的系统。不报没读过的内部规模。
- **为什么 TikTok**：先讲一个具体的工程问题（实验怎么可信、增长怎么衡量、数据管线怎么保证正确），再接你的经验。别用「大平台」「大规模」这种空话。
- **为什么是增长组而不是支付组**：你的强项是数据的正确性和可验证性，增长靠指标驱动，一个错误的数字比一个慢的系统更伤。【待补：你自己的动机，一句话】
