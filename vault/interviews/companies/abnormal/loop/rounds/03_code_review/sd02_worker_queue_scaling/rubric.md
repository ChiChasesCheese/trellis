# sd02 · Rubric

| 维度 | strong | ok | weak |
|---|---|---|---|
| 并发量化 | Little 定律：5,000/s × 0.2 s = **1,000 个在途请求**；每 worker 20 个在途 → ~50 个 worker（或改 async I/O 让每进程上千在途） | "加 worker" 带个数 | 不算 |
| 找真正的瓶颈 | 下游才是瓶颈：大租户 2,000/s 对 50/s 限流 → 积压每秒涨 1,950，10 分钟 ≈ 117 万条；加 worker **只会更快地撞限流**（更多 429） | 提到限流 | 只看 worker CPU |
| 队列设计 | 按租户（或租户 + 端点）隔离：分区/子队列 + 每租户令牌桶；慢/挂的端点不阻塞别人（head-of-line blocking）；按严重度分优先级队列 | 一个队列 + 重试 | 一个 FIFO |
| 失败场景 | 端点宕机几小时：指数退避 + 抖动、熔断（per endpoint）、DLQ + 重放、可见性超时 > 处理时间、毒消息隔离；重启/重复投递 → 幂等键（alert id + version），让客户去重 | DLQ | "retry" |
| 顺序 | 同一 alert 的更新按 alert id 分区串行；或带单调 version 让客户丢弃旧的 | 提到顺序 | 无 |
| 观测与背压 | 每租户积压深度、最老消息年龄、429 率、熔断状态；入口背压（降级为摘要通知/批量） | 有 lag 指标 | 无 |
| 沟通 | 先算再改，每个改动对应一个数 | | 罗列组件 |
