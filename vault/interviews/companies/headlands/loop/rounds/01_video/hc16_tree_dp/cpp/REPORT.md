# hc16 · 思路与追问（C++20 版）

这是一道树上 DP 的题，面试官一路追问：状态怎么定义、平局怎么定、输入怎么校验、10^5 层的链怎么不爆栈。每一问都在看你能不能把规则说清，并且把「递归改迭代」讲成有因果的故事。下面按 Part 写清怎么写、面试官在探什么、该说出口的那句话，C++ 特有的坑（栈溢出是信号、`llabs(LLONG_MIN)` 是 UB、`size_t` 与 `int` 混比）放在对应的 Part 里。详细推导和可运行的代码在讲义 [[hc16_tree_dp_cpp]]。

## 30 秒版本

- **状态**：每个台两个数，`in[v]` 选它、`out[v]` 不选它，只依赖它的子树。`in[v] = pnl[v] + Σ out[孩子]`，`out[v] = Σ max(in[孩子], out[孩子])`。
- **顺序**：建树时 BFS 出一个「父亲在孩子前面」的 `order_`，所有查询都倒着扫它；不能从 `n-1` 倒着扫 `parent[]`，因为 `parent[i]` 可以大于 `i`。
- **存树**：`parent` 数组加 CSR（两个连续的 `vector<int>`），不用 `vector<vector<int>>`。
- **平局**：选 `v` 当且仅当父亲没被选、并且 `in[v] > out[v]`（严格大于），自顶向下一遍还原，不用回溯。
- **路径**：`down[v] = pnl[v] + max(0, 最好的孩子 down)`，拐弯用最好的两条非负支路；初值是 `LLONG_MIN`，因为路径不能为空。
- **深链**：迭代版栈深 O(1)；递归版在 512 KiB 栈上 10^5 层必崩，而且是进程被信号杀死，不是异常。

## Part 1 · 建树 + 最大总 PnL

**写法**

```cpp
in = pnl_;  out.assign(n_, 0);
for (int i = n_ - 1; i >= 0; --i) {          // order_ 倒着扫：孩子先于父亲
    int v = order_[i], p = parent_[v];
    if (p >= 0) { in[p] += out[v]; out[p] += std::max(in[v], out[v]); }   // 把结果推给父亲
}
return n_ == 0 ? 0 : std::max(in[root_], out[root_]);
```

建树按固定顺序校验：长度 → 台数 → `pnl` 范围 → `parent` 越界或自指 → 根的个数 → 有环。有环不用单独检测：BFS 之后 `order_.size() != n_`，说明有台从根够不着。

**面试官在探什么**

1. **状态定义**。选了 `v`，它的直接孩子不能选，只能取孩子的 `out`；孙辈可以选，已经包含在孩子的 `out` 里。用 `max(in, out)` 就会允许父子同选。
2. **为什么 BFS 顺序倒扫**。BFS 里一个节点总是在父亲之后入队，所以 `order_` 里每个节点都排在它所有孩子前面，倒着扫就是先孩子后父亲。错误写法：`for (v = n-1; v >= 0; --v)` 直接扫 `parent[]` → 当 `parent = {1, 2, -1}` 时，处理 1 号时它的孩子 0 号还没把结果推上来 → 答案错 → 改成按 `order_` 倒扫。
3. **为什么答案不为负**。允许一个都不选，所以空树、全负的树答案是 0；单个台 `{-7}` 也是 0。
4. **为什么用 CSR**。`vector<vector<int>>` 要分配 n 个小 vector，10^6 个台时又慢又碎；CSR 是「数孩子 → 前缀和 → 填入」，O(n)，只有两块连续内存。
5. **校验的顺序**。`parent = {-1, -1, 9}` 先报 `invalid parent`，不是 `invalid root`；顺序是接口的一部分，测试逐条检查 `what()`。
6. **溢出怎么论证**。`|pnl| ≤ 10^12`、`n ≤ 10^6`，任何和的绝对值 ≤ 10^18，小于 `LLONG_MAX`，所以查询里不需要溢出检查。要支持任意 `long long` 就改用 `__int128`，或者用 `__builtin_add_overflow` 并规定「真实答案超出范围才报错」。
7. **范围检查**。写 `p > MAX_ABS_PNL || p < -MAX_ABS_PNL`。错误写法 `std::llabs(p) > MAX_ABS_PNL` → `llabs(LLONG_MIN)` 溢出是 UB，UBSan 直接终止 → 改成直接比较两端。
8. **`size_t` 与 `int`**。`pnl.size() != n` 里 `n` 是 `int`，`n < 0` 时会被转成巨大的无符号数；所以先判 `n < 0`，再 `static_cast<std::size_t>(n)` 比较。`size()` 和 `root()` 返回 `int`，因为 `-1` 要能表示「没有」。
9. **拷贝与移动**。`DeskTree` 的成员全是 `vector`，默认的拷贝和移动都对；构造函数是 `private`，只能经 `of_parents` / `of_edges` 创建，所以存在的对象一定是合法的树。初始化列表的顺序要和成员声明顺序一致，否则 `-Wreorder`。

**该说出口的话**：「每个台两个状态，选和不选，只依赖子树；我用 BFS 顺序倒着扫，孩子一定先于父亲，不用递归。」

## Part 2 · 还原方案 + 边列表

**写法**

```cpp
for (int v : order_) {                       // 正着扫：处理 v 时父亲已经定了
    int p = parent_[v];
    chosen[v] = (p < 0 || !chosen[p]) && in[v] > out[v];
}
// 然后按编号 0..n-1 收集，desks 天然升序
```

`chosen` 用 `vector<char>`，不用 `vector<bool>`（位压缩的代理类型）。边列表入口：无向边在邻接 CSR 里存两次；`parent` 初值 `-2` 表示还没访问，根设 `-1`；BFS 时 `parent[w] == -2` 才把 `w` 认作孩子；BFS 结束后访问数不是 `n` 就报 `not a tree`。

**面试官在探什么**

1. **平局规则为什么要定**。最优方案不唯一，没有规则时调用方没法比较输出。这条规则是局部可判定的（`in > out`），所以只靠 DP 值自顶向下一遍就能还原，不用回溯。
2. **平局的具体结果**。`pnl = {5, 5}` 的链：`in[0] = out[0] = 5`，根不选，台 1 选，`Plan{5, {1}}`。PnL 为 0 的台永远不会被选；全 1 的偶数长度链选奇数编号。
3. **边列表的校验顺序**。先看每条边本身（两个端点、范围、非自环）→ 再数边数 → 最后看 BFS 访问数。重复边会让 `n-1` 条边凑不出连通图，BFS 访问数不足，报 `not a tree`。`n = 0` 时 `root` 被忽略，不要检查它。
4. **换根**。同一棵无向树换根后，最大独立集和最大路径和不变；`plan()` 的平局和 `best_subtree()` 依赖根，会变。

**该说出口的话**：「平局只在 `in > out` 严格成立时才选，这样还原只需要一遍自顶向下，不用回溯。」

## Part 3 · 路径与子树

**写法**

```cpp
long long down = pnl_[v] + top1[v];                          // top1/top2 初值 0：负支路自然不要
best_down = std::max(best_down, down);
best_path = std::max(best_path, pnl_[v] + top1[v] + top2[v]); // 在 v 拐弯：左支 + v + 右支
if (p >= 0 && down > 0) { /* 更新父亲的 top1 / top2 */ }
```

`best_down` 和 `best_path` 的初值是 `LLONG_MIN`。`best_subtree` 用 `sum` 倒扫累加，再按编号升序、严格大于才更新。

**面试官在探什么**

1. **往上传几条支路**。拐弯路径在 `v` 处用两条支路，但传给父亲的只能是一条（`down`），否则路径就分叉了。
2. **负支路**。负的 `down` 不传给父亲（`down > 0` 才更新），相当于「不走这条支路」；但路径本身不能为空，所以初值是 `LLONG_MIN`，全负时答案是最不坏的单个台。错误写法：初值写 0 → 全负树返回 0，实际没有这样的路径 → 改成 `LLONG_MIN`。
3. **拐点本身为负**。`pnl = {-1, 6, 7}` 的根带两个孩子：`-1 + 7 + 6 = 12` 仍然比单走 7 好；`-10` 就不值得拐，答案回到 7。
4. **子树和平局**。取编号最小：循环从小到大、`sum[v] > sum[best]` 严格大于才更新。错误写法：用 `>=` 或倒着扫 → 平局取到大编号。
5. **空树**。三个方法抛 `std::out_of_range("empty tree")`，先于任何计算检查。

**该说出口的话**：「向上只传一条非负支路，拐弯用最好的两条；路径不能为空，所以初值是最小值，不是 0。」

## Part 4 · 10^5 层的链

**写法**：所有查询已经是对 `order_` 的循环，栈深度 O(1)。唯一的递归是留作对照的 `max_pnl_recursive`：

```cpp
auto [ct, cs] = solve_recursive(child);      // 每个孩子递归一次
take += cs;  skip += std::max(ct, cs);
```

**面试官在探什么**

1. **为什么递归会崩**。每次调用在调用栈上压一个栈帧（返回地址、参数、局部变量、保存的寄存器），10^5 层就是 10^5 个栈帧叠在一起。线程栈大小固定，自己创建的线程栈更小（macOS 上 512 KiB），装不下。
2. **崩的方式**。C++ 没有 `StackOverflowError`：栈尽头是保护页，碰到它操作系统发 `SIGSEGV`，进程终止，此时栈已经用完，连运行 `catch` 的空间都没有。所以测试要用子进程观察它，在 512 KiB 栈的线程里跑迭代版。
3. **把栈调大行不行**。`ulimit -s` 或 `pthread_attr_setstacksize` 只是把上限往后推，链再长一个数量级还是崩。根治是把调用栈换成自己的数组。
4. **三种办法的代价**。BFS 顺序倒扫：O(1) 栈、O(n) 数组，最简单；显式栈做迭代后序：栈放在堆上，要记「孩子处理完没有」，代码更长；依赖编译器的尾调用优化：标准不保证，而且这个递归本身不是尾递归。
5. **两个方向的链**。`parent[i] = i-1`（根是 0）和 `parent[i] = i+1`（根是 `n-1`）都要对；后者会让「从 `n-1` 倒着扫父数组」的偷懒做法出错。
6. **流式追加叶子**。只影响祖先链，重算 `in/out`，最坏 O(深度)，深链上累计 O(n²)；要更快用重链剖分加线段树维护 2×2 的 max-plus 矩阵。
7. **森林**。加一个 PnL 为 0 的虚拟总根，或每棵树分别算：打家劫舍相加，路径取最大。
8. **怎么测**。手算样例；用 `2^n` 枚举当裁判做随机小树对拍；构造性用例（两个方向的 10^5 链，已知答案 50000）；512 KiB 栈线程验证不爆栈；子进程验证递归版真的会崩；错误顺序逐条测；UBSan 抓 `llabs(LLONG_MIN)`。

**该说出口的话**：「栈是固定大小的资源，递归把树的深度变成栈深度。我用 BFS 顺序倒扫，把调用栈换成数组，深度就和栈无关了；把栈调大只是推迟问题。」

## 和 Java 版的区别

| 话题 | Java | C++ |
|---|---|---|
| 返回方案 | `record Plan(long total, List<Integer> desks)`，`List.copyOf` | `struct Plan`，`operator== = default`；成员是普通 `vector` |
| 入参拷贝 | `parent.clone()` | 按值接收 + `std::move`，或从 `const&` 拷贝 |
| 非法输入 | `IllegalArgumentException`；`null` 抛 NPE | `std::invalid_argument`；没有 `null` 引用，不需要 NPE |
| 空树的路径查询 | `NoSuchElementException` | `std::out_of_range` |
| 校验 `pnl` | `p > MAX \|\| p < -MAX`（`Math.abs(Long.MIN_VALUE)` 是负数） | 同样不用 `llabs`：`llabs(LLONG_MIN)` 是 UB |
| 栈溢出 | 抛 `StackOverflowError`，可以断言 | 进程被信号杀死，必须用子进程观察 |
| 选中标记 | `boolean[]` | `vector<char>`，避开 `vector<bool>` |
| 整数比较 | 没有无符号问题 | `vector::size()` 是无符号，和 `int` 比较要显式转换 |
