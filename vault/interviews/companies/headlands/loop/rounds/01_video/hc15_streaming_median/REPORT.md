# hc15 · 思路与追问

## 概要

「数据流中位数」是堆的经典题，面试官用它看三件事：能不能把「两个堆」的不变式说清楚；加窗口之后怎么处理「堆里删任意元素」；
再追问到任意百分位时，会不会按场景在两个堆、顺序统计树、直方图之间做取舍。价格全程是整数 tick（`long`），不涉及浮点。

## 逐 Part 思路

1. **StreamingMedian**：`lo`（最大堆，较小的一半）+ `hi`（最小堆，较大的一半），不变式：`lo` 里每个数 ≤ `hi` 里每个数，且 `|lo| = |hi|` 或 `|hi| + 1`。
   新数先放对边再平衡一次；`median()` = `lo.peek()`（**下中位数**）。选下中位数的理由：结果是真实出现过的价格、仍是整数 tick、与最近秩百分位 p = 50 一致。
   真正的平均数用 `doubledMedian()`（两个中间值之和，中位数的两倍），避免舍入约定；和可能溢出，用 `addExact`。
2. **WindowMedian**：环形缓冲记最近 k 个值。堆不能删任意元素，所以惰性删除：滑出窗口的旧值记进所属堆的 `delayed` 表，浮到堆顶才真正弹出；平衡按有效个数，不按 `heap.size()`；每次操作后两个堆顶都保持有效。
   旧值属于哪个堆：`old ≤ lo.peek()` ⇒ `lo`（因为 `lo` 里每个数 ≤ `hi` 里每个数；相等时 `lo` 顶一定有一份有效拷贝）。各堆一张 `delayed` 表，避免「相等的值记错堆」。
   代价：升序流里失效元素永远沉在 `lo` 底部，堆会长到 O(n)；失效元素超过 2k 就整体重建（排序窗口），堆里最多留 3k 个。
3. **百分位**：最近秩 `rank = ceil(p·n/100)`，写成 `n/100·p + ((n%100)·p + 99)/100`，`n` 很大也不溢出。
   `TwoHeapPercentile(p)`：`lo` 装最小的 `rank` 个数，每次 add 后最多挪一两个；`p = 50` 就是 Part 1；但 `p` 固定在构造时。
   `OrderStatistics`：树堆（BST + 随机优先级），结点存值、重复计数、子树总数，数组存结点；`kth` 一次下降，`countAtMost` 一次下降；任意 `p`，查询时才给。
4. **TickHistogram**：价格有界（0..T−1）时，计数放进树状数组（Fenwick tree）：`add` 单点加，`kth` 倍增下降；构造时一次分配，之后零分配。

## 隐藏测试会打的坑

* 偶数个数时取了上中位数或平均数（`(a + b) / 2` 在两个大数时溢出）。
* 平衡条件写反，导致 `lo` 比 `hi` 少一个；新数放错边（`price < lo.peek()` 与 `≤` 的差别，重复值）。
* 窗口：窗口还没满就开始删；惰性删除时用 `heap.size()` 做平衡；堆顶是失效元素时 `median()` 读到旧值；相等的值记错了堆；升序流里堆无限增长。
* 百分位：`ceil(p·n/100)` 写成 `p·n/100`（向下取整）；`p·n` 溢出；`p = 0` / 101 没拒绝；空时先检查 p 还是先检查空。
* 树堆：数组扩容后 `left[t] = insert(left[t], x)` 把结果写进旧数组（Java 先求值数组引用）；C++ 里 `auto& n = nodes[t]` 在递归插入后悬空；有序输入使未平衡的 BST 退化成链表（栈溢出或超时）；重复值要合并计数。
* 树状数组：下标从 0 开始（`i & -i` 在 0 上死循环）；`maxTick` 不是 2 的幂时倍增下降的上界；`price` 越界。

## 复杂度与实测

| 结构 | add | 查询 | 实测（Java，100 万次） |
|---|---|---|---|
| `StreamingMedian` | O(log n) | O(1) | add + median：约 55 ms |
| `WindowMedian`（k = 10^4） | 摊还 O(log k) | O(1) | add + median：约 100 ms，堆里 ≤ 4k |
| `TwoHeapPercentile`（p = 95） | O(log n) | O(1) | 约 25 ms |
| `OrderStatistics`（树堆） | 期望 O(log n) | O(log n) | add + percentile：约 400 ms |
| `TickHistogram`（T = 2^20） | O(log T) | O(log T) | add + percentile：约 70 ms，预热后分配 0 字节 |

C++（`-O2`）同量级或更快：树堆约 0.4 s，直方图约 70 ms，其余 < 60 ms。

选哪个：只要一个固定分位 ⇒ 两个堆（最简单、查询 O(1)）；任意分位、值域无界 ⇒ 顺序统计结构（树堆 / 跳表 / 分块有序数组）；值域有界（tick 范围小）⇒ 直方图（常数最小、零分配，精度就是 tick）。

## Java 21 特性

| 特性 | 用在哪 | 比旧写法好在哪 |
|---|---|---|
| `Math.addExact` | `doubledMedian` | 两个中间值之和溢出直接抛，而不是静默回绕 |
| `Math.ceilDiv`（18） | 测试里的百分位基准 | 向上取整除法一步到位，免去 `(a + b - 1) / b` 的溢出隐患 |
| `Random.nextLong(bound)`（17，`RandomGenerator`） | 测试数据生成 | 有界随机数不用手写取模 |
| `Collections.reverseOrder` / `HashMap.merge` | 最大堆、`delayed` 计数 | 一行完成「最大堆」和「计数加一」 |
| `Integer.highestOneBit` | `TickHistogram` 的倍增起点 | 不手写位运算循环 |
| `var` | 局部变量（类型显然时） | 少写重复的泛型类型 |

## 面试官可能的追问

1. **偶数个数时中位数怎么定？** 给出选择与理由：下中位数 ⇒ 仍是整数 tick、是真实价格、与 p = 50 的最近秩一致；要平均数就返回两倍值（整数）或带明确舍入规则的定点数；平均 `(a + b) / 2` 会溢出，写成 `a + (b − a) / 2`（`a ≤ b`）或返回两倍。
2. **滑动窗口为什么不直接用 `TreeMap` / `TreeSet`？** 可以：`TreeMap<价格, 个数>` 加删都是 O(log k)，但取第 k/2 小是 O(k)（要走迭代器）。两个堆 + 惰性删除让取中位数 O(1)；顺序统计树两者都 O(log k)。
3. **惰性删除的内存问题？** 失效元素要浮到堆顶才会被清；升序流里永远浮不上来，堆会长到 O(n)。解决：失效数超过 2k 时整体重建（摊还 O(log k)），或换成支持按值删除的结构（有序表）。
4. **两个堆能算任意 p 吗？** 能，让 `lo` 装 `ceil(p·n/100)` 个：每次 add 最多挪一两个。但 p 固定；要同时回答多个 p，或 p 在查询时才给，就需要顺序统计结构。
5. **值域有界时怎么做最快？** 直方图 + 树状数组（或每 64 个 tick 一块的两级计数，查询 O(T/64)）；预分配、零分配、缓存友好。tick 范围太大（比如 1e9）就退回树 / 分位数草图（t-digest / GK），近似换空间。
6. **要近似分位数怎么办？** t-digest / GK / 对数分桶直方图（HdrHistogram）：空间 O(1/ε)，误差有界；监控类场景（延迟 p99）常用。
7. **多线程？** 每个线程一份局部结构，定期合并（直方图直接逐桶相加，最容易合并；堆不好合并）；或单写者 + 无锁读快照。
