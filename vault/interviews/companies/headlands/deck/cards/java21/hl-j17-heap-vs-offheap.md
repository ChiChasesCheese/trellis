## Q
Java 堆（heap）上的对象有什么代价？堆外内存（off-heap / native memory）有什么好处和代价？

## A
**堆的代价**（对象由 GC 管理）：
- GC 工作时要**扫描**堆里的对象，对象越多越大工作量越大；
- 对象位置和布局由 JVM 决定：每个对象有 12–16 字节对象头；数组里放 `Long` 是**指针数组**，你无法控制「这 100 万条记录在内存里连续」；
- GC 回收/整理会暂停或拖慢应用（现代 GC 暂停可压到毫秒以下，吞吐与内存占用仍有代价）。

**堆外内存**是堆之外、由 OS 直接分配的内存，GC 完全看不见。好处：
1. 能放**很大**的数据，且不增加 GC 工作量；
2. 布局由你定：连续、按缓存行对齐、像 C 的 `struct` 数组；
3. 可与别的进程共享（共享内存、`mmap` 文件），可直接交给 C 库。

代价：**你**负责释放；无保护的越界/用后释放就是 C 里的段错误（崩进程）。
