## Q
句柄（handle）的三种经典错误是什么？「A 还了块 7，B 借到 7，A 又还一次」为什么 Part 1 防不住，版本号（generation）怎么解决？

## A
句柄是「指向某资源的凭证」，`int` 编号就是最简单的句柄。池收回块后，数字还在你手里。三种错误：
| 错误 | 怎么发生 | 后果 |
|---|---|---|
| 重复归还（double free） | 对同一编号 `free` 两次 | 块挂进空闲链表两次，同一块借给两个人 |
| 归还后继续用（use-after-free） | `free(7)` 后又读写块 7 | 读到 / 写坏别人的数据 |
| 陈旧句柄（stale handle，ABA 的变种） | A 还了 7；B 借到 7；A 又 `free(7)` | B 的块被 A 还掉，B 毫不知情 |

第三种 Part 1 **无法防**：下标 7 在两个时刻代表两个不同所有者，数字却一样。

**版本号**：每个槽位带计数器，handle 是 `(版本号, 下标)`，槽位归还时版本号 +1；handle 的版本号与槽位当前版本不一致 → 旧 handle。约定：**偶数 = 空闲，奇数 = 在用**，每次借、每次还各 +1。

例：槽位 7 初始 0；A 借到 → 1（奇，A 的 handle `(1,7)`）；A 还 → 2（偶）；B 借到 → 3（奇，B 的 handle `(3,7)`）；A 再 `free(1,7)`：槽位当前是 3 ≠ 1 → 拒绝（`DOUBLE_FREE`）。

好处：版本号本来就必须有，奇偶白送不增空间；并发时**一次 CAS** 同时完成「校验 handle 有效」和「标记空闲」，独立 `boolean` 要对两个变量做原子操作；全零 handle 版本号为 0（偶数）自动无效，漏初始化的 handle 立刻暴露。

版本号 `int` 会回绕（`0xFFFFFFFF + 1 = 0`），2³² 是偶数，回绕后奇偶性不变。风险：同一槽位被借还 2³¹ 次后极老的 handle 可能撞上当前版本；可忽略，不能忽略就退役该槽位，或 64 位版本号 + 128 位 handle。

C++ 里版本号必须用 `uint32_t`（回绕有定义，`int` 溢出是 UB）。
