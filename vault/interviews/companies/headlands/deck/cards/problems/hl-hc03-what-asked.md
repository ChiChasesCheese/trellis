## Q
「写个函数，递归求 1 到 n 的和」这道热身题，面试官的追问链依次在试探什么？

## A
题本身一分钟写完（`sum(n) = n + sum(n-1)`，`sum(0)=0` 是基线条件），评分在追问里，每一句试探一个层面：
- 「结果放 int 还是 long？溢出怎么办？」→ 整数表示（补码）、返回类型设计（Part 1）；
- 「n = 一百万会怎样？能不能不爆栈？尾递归呢？」→ 调用栈、JVM 没有 TCO、trampoline（Part 2）；
- 「n 很大时有没有更快的办法？区间 [a, b] 呢？」→ 闭式公式的数值陷阱（Part 3）；
- 「数组里一亿个数怎么并行求和？」→ 线程、结合律、ForkJoin、虚拟线程（Part 4）。

手算：`sum(4) = 4 + (3 + (2 + (1 + sum(0))))`，回头加得 1、3、6、10。

统一的溢出语义：**数学上的真实和放不进该位宽 ⇒ `Overflow(exact)`**，`exact` 是精确值，绝不返回回绕后的错误数。累加器位宽 `Width { INT, LONG }`，`INT` 让溢出在 n = 65536 就发生，不必递归 43 亿次。

考的不是算法，而是被追问时的反应链：定义结果类型而不是抛异常 / 回绕 → 知道 JVM 为什么没有 TCO 并能量出阈值 → 用 trampoline 把栈换成堆 → 知道闭式的数值陷阱 → CPU 密集并行用 ForkJoin，虚拟线程给阻塞 I/O。
