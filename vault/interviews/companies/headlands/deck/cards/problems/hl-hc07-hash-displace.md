## Q
hash-and-displace（CHD 简化）怎么构造最小完美哈希？查询时为什么要比较 `keys[slot] == key`？

## A
**构造**：
1. **分桶**：用哈希把 n 个 key 分到 `r ≈ n/4` 个桶（`Math.max(1, (n+3)/4)`，每桶平均 4 个）；用计数排序按桶分组到 `members[]`，无对象分配；
2. **从大桶到小桶**：桶大小和桶号打包成一个 `long` 排序（省比较器）。对一个桶找位移 `d`（0,1,2,…），使桶里**每个** key 的 `slot(h, d, n)` 都落在还没被占的格子且桶内互不相同；找到就占用，记 `disp[桶] = d`。大桶要同时找到多个空位，最难，趁表还空先放；
3. **"先占着再回滚"**：`used[s] = true` 先占，若失败回滚 `used[tmp[p]] = false` 换下一个 d，同一个 `used[]` 同时检查「被别的桶占用」和「桶内两 key 撞同一格」；
4. **单元素桶最后放**：直接给下一个空格子（`cursor` 单调向前），位移里存 `~slot`（取反成负数表示「直接指定的格子」）。剩下空格数 = 剩下 key 数，必有空位；
5. 极罕见构造失败：换 `seed` 重来，最多 64 次。

**为什么单元素桶最后处理**：它放哪都行；大桶需要多个位置同时为空，越晚越难（成功概率按 `(空闲比例)^桶大小` 下降）。先放单元素会吃掉空格，大桶可能永远找不到位移。

**查询**：`h = hash(key)`；`bucket = fastrange(h 高 32 位, r)`；`d = disp[bucket]`；`slot = d<0 ? ~d : slot(h, d, n)`；`return keys[slot] == key ? slot : -1`。

**必须比较 `keys[slot] == key`**：完美哈希只保证**集合内** key 互不冲突；集合外的 key 也会被映射到某个格子，不比较就会误认成那个格子里的 key。

**常见坑**：用 `h + d × c` 缩到 [0,n) 当哈希族，小表上桶内两 key 的格子差在所有 d 下几乎固定，永远放不进去。修正：把 d 搅进 h 再乘大奇数 `slot = high32((h ^ d·K1) · K2)` 缩放到 [0,m)。
