## Q
DP 用滚动数组原地更新时，最容易出什么错？Part 3 里 `j` 为什么要从大到小更新？

## A
滚动数组只留「今天」一行，每天原地更新。n = 400 万天、k = 100 时完整表 4 亿格装不下，滚动后只有 k+1 格。

**最易错是更新顺序**：新值可能覆盖后面还需要的旧值。例：想要 `b' = a`（旧 a）、`a' = a+1`，若先 `a = a+1` 再 `b = a`，`b` 得到的是新 a。正确做法：先算依赖旧值的，再算会覆盖旧值的，或用临时变量暂存旧值。

Part 3 中新 `hold[j]` 要读**昨天的** `free[j-1]`，所以：
```java
for (int j = k; j >= 1; j--) {
    free[j] = Math.max(free[j], hold[j] + p);
    hold[j] = Math.max(hold[j], free[j - 1] - p);  // free[j-1] 仍是昨天的
}
```
`j` 从小到大会让 `free[j-1]` 先被今天更新，等于同一天先卖再用卖的钱买，违反「一天一个动作」。纯 Part 3 里碰巧答案一样（同价卖了又买现金不变），但加冷却或手续费就错。习惯：**每个转移只用昨天的值**。
