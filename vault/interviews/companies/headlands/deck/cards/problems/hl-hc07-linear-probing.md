## Q
线性探测（linear probing）下插入、查找怎么做？聚集（clustering）是什么，期望探测次数随装载因子怎么变？

## A
- **插入**：从家（home slot）出发，往后找第一个空格放进去。
- **查找**：从家出发往后看；**碰到目标就找到，碰到空格就确定不存在**（若存在，插入时一定放在碰到空格之前）。这要求「表里永远有空格」，否则查不存在的 key 无限循环，所以装载因子要限制。
- 往后看一格叫一次探测（probe），key 离家多远就探测多少次。

例：8 格，`AAPL` 家 3，`AMZN` 家 3 被占 → 住 4；查 `AMZN`：家 3 是 AAPL → 看 4 → 找到；查不存在的 key 家 5 → 空 → 立刻不存在。

**聚集**：冲突 key 占连续格子，这片区域像滚雪球越长越大，后来的 key 落进来就要走到片尾。Knuth（α = 占用/总格子）：
| α | 成功查找平均探测 `(1+1/(1−α))/2` | 失败查找 `(1+1/(1−α)²)/2` |
|---|---|---|
| 0.25 | 1.17 | 1.39 |
| 0.50 | 1.50 | 2.50 |
| 0.75 | 2.50 | 8.50 |
| 0.90 | 5.50 | 50.50 |

所以线性探测的 α 要压得比链地址低：本实现占用（含墓碑）不超过 1/2，刚 resize 完只有 1/4，内存换速度。装载因子影响显著：同一份 `LongTickerMap` 仅因 resize 公式改动使 8000 条目的 α 从 0.24 变到 0.49，ns/op 从 2.3 变到 4.0。
