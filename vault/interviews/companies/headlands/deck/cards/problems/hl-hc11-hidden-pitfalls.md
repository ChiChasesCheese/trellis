## Q
订单区间重叠题的隐藏测试和常见误区有哪些？

## A
| 很多人会这样写 | 为什么错 | 正确 |
|---|---|---|
| 事件只按时间排序 | 同一时刻 +1/−1 先后不确定，`[1,3)`+`[3,5)` 可能得 2 | 排序键 `(time, delta)`，−1 在前；或 `ends[j] <= s` |
| 把 `end` 当包含的 | `[1,3)` 与 `[3,5)` 被算成重叠 | 先确认约定；半开用 `<=`，闭区间用 `<` |
| `all = buy + sell` | 买卖峰值时刻不同，虚高 | 单独扫描全部 |
| 在线版每次 `place` 后更新最大值 | 同时间戳内被撤的订单污染 | 时钟前进时封账 |
| 撤单只减计数，忘了删 `expiries` 里原结束时间 | 到期时再减一次，计数变负 | 同时撤掉未来的 −1 |
| `expiries` 计数减到 0 不删键 | `firstEntry` 反复折叠 0 | `compute` 返回 `null` |
| 撤单时间 ≥ 计划结束仍「生效」 | 订单已结束，应返回 `false` | `end > time` 才生效 |
| 先改状态后校验 | 失败调用留下半修改状态 | 先校验再改 |
| `(lo+hi)/2`、`end-start` | 极大值溢出 | `>>> 1`，坐标只比较 |
| `rangeMax` 不加 `add[node]` | 整体平移标记丢了 | 回溯 `best + add[node]` |
| `[s,e)` 映射成 `idx(s)..idx(e)` | 多算一个段 | `idx(e) - 1` |
| 压缩坐标不去重 | 出现长度 0 的基本段 | 排序后去重 |
| 对输入数组原地排序 | 调用者数据被改 | 拷贝后再排 |

**边界清单**：tie 规则（`[1,3)`+`[3,5)`、链式交接、全部相同的区间）；空输入、`start == end`；撤单发生在开始前 / 开始瞬间 / 结束时刻 / 结束后；重复撤单、撤单写在 Place 前面、未知 id、同一时刻 place 后 cancel；只有一个方向、买卖峰值时刻不同、`all` 的峰值比两者都高；时间倒退、`liveAt` 越界、很多单恰好同一时刻结束、撤单后原计划的结束要同步取消；`Long.MAX_VALUE` 附近的 start/end、`end - start` 溢出；线段树范围伸出所有端点之外、`to` 不含、单个端点、`remove` 之后回到原状。

复杂度量级：Part 1 1e6 个区间约 80 ms；Part 2 约 85–125 ms；Part 3 约 305–320 ms；Part 4 建索引约 100 ms。
