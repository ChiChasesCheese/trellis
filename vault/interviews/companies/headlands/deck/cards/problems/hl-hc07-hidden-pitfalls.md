## Q
股票代码哈希表题的隐藏测试和常见误区有哪些？

## A
| 误区 | 为什么错 | 正确 |
|---|---|---|
| 下标 = `hashCode() & mask` | 低位分布不均；打包 key 低位全 0（最长探测 17575） | 乘法哈希取高位，或 `h ^ (h >>> 16)` |
| 删除时 `keys[i] = null` | 断探测链 | 墓碑；查找跳过；rehash 清理 |
| 遇到墓碑就插入 | key 可能在墓碑后面，造成重复 | 走完整条探测路，记第一个墓碑，没找到才复用 |
| 装载因子不算墓碑 | 反复插入 / 删除后表里无空格，查不存在的 key 死循环 | `(活 + 墓碑 + 1) × 2 > 容量` 就 rehash |
| `(c - 'A' + 1) << 35` 没转 long | `int` 移位量取模 32 | `(long)(c - 'A' + 1) << 35` |
| 用 `0` 当「不存在」返回值 | 累计量本可是 0 | `OptionalLong` / `containsKey` / `get(k, ifAbsent)` |
| `indexOf` 不比较原始 key | 集合外的 key 被误认 | 比较 `keys[slot] == key` |
| 等差序列 `h + d·c` 当哈希族 | 小表上永远放不进去 | 把 d 搅进 h 再乘大奇数 |
| 微基准不预热、结果不用 | 测到的是解释执行 / 被删的代码 | 预热 + 多轮取最好 + 使用结果 |
| 「堆外一定更快」「交错一定更快」 | 测量没有稳定支持 | 先测量再宣称 |

边界清单：空表、`""` 作 key、value 为 0 / 负数 / `Long.MIN_VALUE`；`null` key；同一 `hashCode` 的一大批字符串；删除探测链**中间**和**头部**之后查后面的 key；删除后重插同一个 key（复用墓碑，容量不增长）；resize 后所有 key 仍在；`add` 溢出且不改值；`Long.MAX_VALUE` 作 key；打包：1 / 8 / 9 个字符、小写、数字、全角字母；报文：前导 / 中间空格、全空格、`\0`；完美哈希：0、1、2 个 key，全部 17576 个三字母代码，集合外的 key，重复 key。

`OffHeapTickerMap`：`close()` 之后没有抛异常，或第二次 `close()` 抛异常，都是错的。
