## Q
每个 job 入度 ≤ 1 且 `next` 都存在时，怎样用一次计数比较判断有环？为什么成立？

## A
做法：从每个**入度为 0 的头**沿 `next` 走到尾，把走过的编号放进 `visited`；全部走完后若 `visited.size() != 总 job 数`，就有环。O(n)，不用 DFS 染色，也不用并查集。

为什么成立：
1. 入度 ≤ 1，两条链不可能中途汇合（汇合点入度会是 2），所以每个元素**最多被走到一次**，而且从头出发永远不会进环。
2. 设 X 没被走到。顺着「谁指向 X」往回找，前驱唯一：X ← P1 ← P2 ← …。若找到入度 0 的元素，它是头，会走到 X，矛盾；所以找不到头。
3. 元素有限，往回找必然重复，而每个元素只有一个 `next`，所以第一次重复只能绕回 X 自己：**X 在环上**。

所以「没被走到的点只可能在环上」，包括「好链 + 独立环」这种只从链尾往回走查不出来的情形。
