## Q
为什么不能用 `double` 维护队列的 running sum？举出具体反例，并说明灾难性抵消（catastrophic cancellation）。

## A
`double` 64 位：1 位符号、11 位指数、**52 位尾数**，有效数字约 15–16 位十进制（53 个二进制位）。相邻两个可表示数之间有空隙，数越大空隙越大。`10^16` 附近相邻 `double` 相差 2，所以 `1e16 + 1` 的精确值 `10000000000000001` 表示不出来，舍入（到偶数）得 `1e16`，**加的 1 消失了**。

反例：push `1e16`、push 1、push 1，再 pop 掉 `1e16`，剩两个 1，和应为 2。`double` 总和：`0 → 1e16 → 1e16（1 被吃掉）→ 1e16 → 0.0`，得 0，均值错且**静默**。这叫**灾难性抵消**：先加进小数再减去大数。

解决不是「更好的 double」，而是**别用浮点数存总和，用整数**：整数加减精确，`1e16, 1, 1, -1e16` 得 2。

另一个舍入点：最后一步除法。分子分母都能被 `double` 精确表示（绝对值 ≤ 2⁵³）时，IEEE 754 规定除法是「精确商舍入到最近」，所以 `(double) sum / size` 就是正确舍入；超出时先用 `BigDecimal` 高精度除再 `doubleValue()`（有极小概率二次舍入偏差）。C++ 里 `(double)sum / n` 对大和会舍入两次；转分数到 `double` 要用「粘滞位」（sticky bit）：被丢弃的位全 0 才是平局（取偶），任何非零位都必须向上进位。
