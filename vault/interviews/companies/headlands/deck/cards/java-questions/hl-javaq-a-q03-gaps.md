## Q
Java 做低延迟时无法完全追上 C++ 的几个差距分别为什么存在？各自的缓解办法是什么？

## A
- **预热**：方法要先解释执行、再被 C1/C2 编译，第一批请求慢。缓解：启动时回放典型流量；固定热路径；CDS/AOT 缓存（21 不要依赖）。
- **去优化**：推测失败会回到解释器。缓解：避免热路径类型分布突变；上线前用真实多样的输入预热。
- **内存布局**：无值类型，每个对象 12 字节头加对齐，容器装引用。缓解：原始类型数组、并行数组、`ByteBuffer` / `MemorySegment` 打包。
- **GC**：即便 ZGC 也有屏障开销，并发线程抢核，分配速率过高仍会拖垮。缓解：热路径零分配（复用对象、避免装箱、避免 lambda 捕获）。
- **系统调用 / 网络**：JNI / FFM 调用有开销，没有一流的内核旁路支持。缓解：第三方库、线程绑核；这类场景 C++ 仍占优。
- **其他尾部来源**：safepoint、页错误、OS 调度。缓解：`-Xlog:safepoint`、`-XX:+AlwaysPreTouch`、绑核。
