## Q
低延迟交易系统设计开场必问哪些澄清问题？没答案时采用什么假设？

## A
- tick-to-trade 目标与分位数 → 软件部分 p99 ≤ 10 µs（假设，用于演示拆预算）；
- 品种数、行情峰值速率 → 5,000 个品种，聚合峰值 1M msg/s（假设）；
- 场所数、协议 → 3 个场所，行情组播二进制协议，订单入口 TCP 二进制 / FIX 类；
- 策略有多少、多复杂 → 20 个策略，计算轻（µs 级）；
- 资产类别 → 现货股票 / 期货（限价单、撤单、改单）；
- 错单与丢行情哪个更贵 → 错单贵得多，行情有缺口时对该品种停止交易；
- 恢复时间要求（RTO）→ 秒级恢复，期间不报价；
- 监管 / 内部风控要求 → 必须有独立于策略的交易前风控与熔断；
- 语言 → 热路径 Java（题目设定），承认其下限。
