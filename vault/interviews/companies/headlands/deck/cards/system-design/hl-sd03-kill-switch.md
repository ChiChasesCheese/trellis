## Q
熔断（kill switch）为什么要三层纵深防御？各层是什么？触发后做什么？

## A
- **层 1 进程内闸门**：`volatile` 标志 + 自动触发（仓位 / 亏损 / 拒单率 / 下单速率异常 / 行情陈旧 / 日志落后），延迟 ns，但与策略同进程；
- **层 2 独立风控进程 / 网络设备**：订单经过独立的 Risk Gateway（独立仓位视图），可强制断开会话，延迟 + 几 µs，与策略故障隔离；
- **层 3 交易所 / 清算行侧**：断线即撤（cancel-on-disconnect）、交易所整体撤单（mass cancel）、券商 / 清算行的信用额度与风控工具。

为什么三层：层 1 的 bug 可能与策略 bug 同源（同进程、同内存）；层 2 隔离故障，但自己的状态可能滞后；层 3 是最后一道，不依赖我们的任何代码。监管上要求券商 / 市场准入者对订单设置自己直接且排他控制的预交易风控（美国 SEC 15c3-5，通识），这也是层 2 存在的理由。

熔断后：**撤销所有未完成订单**、禁止新单、保持行情与状态接收（以便恢复），需要人工确认才能恢复。第一原则：熔断不能依赖被熔断的东西。
