## Q
无用代码分析在评分表上，澄清、核心模型、估算、精度难点、可解释性这五个维度的「strong」标准分别是什么？

## A
总原则：**strong = 有数字 + 有失败模式 + 有验证方法**。
- **澄清与定义**：开口先拆「没用」（静态不可达 / 动态未用 / 公共 API），问语言、构建系统、规模、误报与漏报哪个更贵；明确产出候选而非自动删除；
- **核心模型**：符号图 + 根 + 可达性标记（和 GC 类比），能解释为什么 `grep` 找不到死环，指出根的定义决定成败；
- **估算**：推出符号数、边数、CSR 大小（约 80 MB @ 2×10⁷ 行）、标记时间（亚秒）、索引核·秒，得出「分布式只用在索引，图是单机问题」；
- **精度难点**：反射 / DI / SPI / 序列化 / JNI / 配置类名 / 公共 API / 虚调用（CHA vs RTA），每个都有对策与 blocker 记录；
- **可解释性**：证据卡含见证、blockers、信号、可信度；活的符号有最短路径，死的符号有「所有入边来源均不可达」，死簇整体处理。
