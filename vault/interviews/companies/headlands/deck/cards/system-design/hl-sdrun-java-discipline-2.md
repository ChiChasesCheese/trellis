## Q
Java 热路径的纪律：JIT 预热与反优化、safepoint、字符串与装箱、时钟、线程亲和、虚拟线程分别怎么处理？

## A
- **JIT 预热与反优化**：开盘前用合成 / 回放流量跑到编译稳定；热路径**调用点保持单态**；热方法里避免抛异常。冷执行比稳态慢 10–100 倍，类型假设失败会 deopt 回解释器。
- **safepoint**：避免热路径里无 safepoint 的长计数循环、避免大数组拷贝；任何 safepoint 操作都会停住所有线程。
- **字符串与装箱**：品种用 `int` id，价格用 `long` 定点，禁止 `String`、`Long` 装箱、`stream`、捕获型 lambda，每一个都是分配或间接寻址。
- **时钟**：业务时间用单调、可注入的时钟（回放时用事件时间戳），测延迟用 `System.nanoTime()`；决定性 + 不受 NTP 回拨影响。
- **线程亲和**：OS 绑核（`taskset`）或库；一个热线程独占一个物理核（避开 SMT 兄弟）。
- **虚拟线程**：**不要**用在热路径，用在 I/O 密集的外围（对账、批处理、重连管理）；它解决「很多阻塞等待」，不是「最低延迟」。
