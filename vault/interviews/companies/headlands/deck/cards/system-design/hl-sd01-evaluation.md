## Q
怎么评估无用代码分析器是对的？回测、种子注入、抽样人审的置信区间怎么算？

## A
1. **回测历史删除**：在 git 历史里找所有被人工标注为「remove unused / dead code」的提交，在**它的父提交**上跑分析器；被人删掉的符号里被我们标为候选的比例 = 召回的下界估计，被标为「活」的是漏报，逐条分析原因（几乎都能找到一类缺失的模型）；
2. **种子注入**：在快照里注入一批已知死代码（形状逼真：有测试、有死环、有包内引用），看检出率；
3. **抽样人审**：随机抽 100 个 HIGH 候选让 owner 判断，精度估计 p̂ = 0.98 时标准误 ≈ √(0.98×0.02/100) ≈ **1.4%**；
4. **对照现有工具**：IDE inspection / ProGuard 的 `-printusage`，交集与差集都值得看；
5. **回归**：同一快照两次运行输出逐字节相同；改动分析器时对固定快照 diff，所有变化必须有解释。
