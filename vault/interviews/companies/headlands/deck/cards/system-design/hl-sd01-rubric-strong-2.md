## Q
无用代码分析在评分表上，动态证据、删除流程、评估、增量与多语言、Java 与交易公司语境、沟通的「strong」标准是什么？一票否决项有哪些？

## A
- **动态证据**：类加载日志 vs 方法级探针的成本 / 偏差对比，知道采样的假阴性，`@KeepAlive` + 演练，组合规则；
- **删除流程**：owner 拆分、小 PR、软删除、观察期、revert 路径、按风险分级（L0 / L1 直接，L2 / L3 慢）、熔断刹车；
- **评估**：回测 git 历史、种子注入、抽样人审（含置信区间）、对照现有工具、回归；
- **增量与多语言**：索引按内容哈希缓存、图全量重算，跨语言边，覆盖率不足 fail closed，构建配置取并集；
- **Java / 交易语境**：字节码分析理由，CSR + `int[]` + `BitSet`，冷路径特殊性，change surface 价值主张；
- **沟通**：先给 30 秒结论再展开，每 10 分钟确认方向，主动指出自己方案的弱点。

**一票否决**（任一条整体降一档）：提议静态分析出结果就自动删除；没说明如何处理反射 / 公共 API / 冷路径；把「覆盖率低」当「没用」的充分证据；对 10⁸ 行规模给不出任何数量级。
