## Q
低延迟交易系统评分表上，订单入口与对账、高可用、Java 纪律、度量与测试、沟通的「strong」标准是什么？一票否决项有哪些？

## A
- **订单入口与对账**：会话序号、心跳、cancel-on-disconnect、限速、重连；drop copy 独立对账；差异 ⟹ fail closed；
- **高可用**：主备不双发；发单权 + fencing + STONITH；RTO 的代价明确；
- **Java 纪律**：零分配证据（GC 次数 = 0）、预热与单态调用点、safepoint、堆外与数组、无锁、绑核；虚拟线程不进热路径；诚实说明 Java 的下限与分工；
- **度量与测试**：线缆上度量、分段直方图、协调遗漏、日回放回归、模拟交易所、故障注入、灰度；
- **沟通**：先结论后展开；主动指出弱点与取舍；每个组件说失败模式。

**一票否决**（任一条整体降一档）：把消息队列 / 数据库 / 带锁结构放在 tick-to-trade 路径上而无量化论证；没有任何 fail-closed 机制；主备方案会让两个实例同时发单；没有估算每条消息的预算，或认为「加机器」能解决延迟。
