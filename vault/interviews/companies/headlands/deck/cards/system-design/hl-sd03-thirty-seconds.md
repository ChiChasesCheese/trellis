## Q
低延迟交易系统的 30 秒版回答怎么说？

## A
一台 co-location 在交易所机房的机器，按**品种分片**，每个分片一个**绑定到独占核心的线程**，从行情摄取到发单 **run-to-completion**（一个线程做完 解码 → 簿更新 → 策略 → 风控 → 编码，没有线程交接）。状态全在内存，**输入事件（行情 + 回报 + 命令）带序号追加到日志**，状态机是它的纯函数，所以崩溃后能重放、事后能复盘、研究能回测。风控是 O(1) 的数组查表，内联在热路径上，同时有独立进程和交易所侧的兜底（熔断三层）。出问题一律 **fail closed**。

Java 的纪律：稳态零分配、预热 JIT、堆外 / 数组代替对象、单写者无锁、绑核忙等。5 分钟版再加：延迟预算表、行情 A/B 仲裁与缺口处理、日志与对账的 source of truth、主备不双发。
