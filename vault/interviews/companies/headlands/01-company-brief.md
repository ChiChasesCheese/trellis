# 01 · 公司简报（Headlands Technologies · Software Engineer / Java）

这份简报先讲交易这个行业怎么赚钱，再讲 Headlands 是一家什么样的公司，最后讲你申请的 Java 岗每天做什么。你不需要任何金融背景：每个概念第一次出现都给一句白话定义，每个结论都写出因果。标 **（通识）** 的是行业常识，不是公司的官方说法。

## 0. 一页结论

1. Headlands 是**自营量化交易公司**（成立于约 2010 年，总部芝加哥，另有纽约、阿姆斯特丹、伦敦、新加坡办公室）：只用自己的钱交易，没有客户，也不接受外部投资人。
2. 你的 Java 岗**不在交易热路径上**：做的是"研究平台 + 分布式存储 + 计算集群 + 监控 + 系统内部网络延迟"这类基础设施。毫秒以下的交易引擎是 C++ 岗。
3. Chicago 的 Java 岗基础薪资 **$175k–$300k**（只是 base）。
4. 公司看重的人：好奇、独立、低自我；需要懂很多层（数学 / 统计 / CS / 交易系统）；金融知识反而要得很少。
5. 公司规模、营收、技术栈细节没有可靠的公开数字，面试中不要报数字。

## 1. 先把三种机构分清（通识）

你不需要懂金融才能通过面试（公司自己说工程师需要的金融知识"very little"）。但分不清这三个词，你会听不懂面试官的玩笑。

| | 自营交易公司（prop firm） | 对冲基金（hedge fund） | 投资银行 / 券商 |
|---|---|---|---|
| **谁的钱** | 公司自己的钱 | **别人的钱**（养老金、捐赠基金、富人） | 客户的钱 + 银行自有资本 |
| **怎么赚钱** | 交易利润，扣掉成本全归公司 | 对客户收**管理费 + 业绩提成** | 手续费、撮合差价、借贷利差、承销费 |
| **有没有客户** | 没有 | 有（出资人） | 有（很多） |
| **技术的角色** | 技术**就是**产品：系统更快、更稳、研究更快，谁赚钱 | 技术支持策略与风控 | 技术支持业务线与合规 |

**因果**：因为 prop firm 用自己的钱，所以（1）没有"向出资人解释亏损"这类外部成本；（2）亏了是自己的钱，风险控制和系统可靠性是生存问题；（3）收入与公司业绩直接挂钩，不按团队分，所以内耗少。

## 2. 它怎么赚钱：做市与量化，从零讲

### 2.1 市场怎么运转（通识）

交易所维护一本**订单簿（order book）**：所有人挂的"我愿意以这个价买 / 卖多少股"。

```
卖单 (ask)   100.03  x 500
             100.02  x 300
             100.01  x 200      <- 最低卖价 = best ask
-------------------------------- 价差 (spread) = 100.01 - 99.99 = 0.02
买单 (bid)    99.99  x 400      <- 最高买价 = best bid
              99.98  x 600
              99.97  x 100
```

**做市商（market maker）**：同时在买一和卖一附近挂单。有人想马上卖，就买他的；有人想马上买，就卖给他。做市商赚**价差**，并因此给市场提供"随时能成交"的**流动性（liquidity）**。

例：在 99.99 买入 1000 股，在 100.01 卖出 1000 股，赚 1000 × 0.02 = **$20**。一次只赚 $20，所以要做**海量次数**，必须全自动。

### 2.2 为什么风险叫"延迟"

你在 99.99 买了 1000 股，市场马上跌到 99.90：亏 1000 × 0.09 = **$90**，要 4.5 笔成功的往返才赚得回来。更糟的是**逆向选择（adverse selection）**：对手比你**更早**知道价格要跌，专挑你来不及撤的旧报价成交。

→ **报价"过期"得越快被打，就越亏；撤单、改价越快，就越安全。** 这就是低延迟（low latency）的经济学根源：不是炫技，是"慢一点就被对手吃掉"。一种建模方式是把报价看成一个"卖出的短期期权"，延迟相当于期权的到期时间；期权价值大致与 √T 成正比，延迟减半，被"选择"的代价约降三成（√0.5 ≈ 0.71）。

### 2.3 量化（quantitative）是什么

"量化"= 用数学、统计和程序来**研究**和**执行**交易想法，不靠直觉盯盘。公司做套利（arbitrage）、主动吃单（market taking）和做市三类策略。一个策略的一生（**通识**）：

1. 研究员提出假设（例如"某指标升高后，价格在 5 秒内上涨的概率更高"）；
2. 用历史数据**回测（backtest）**：重放历史行情，看按这个规则交易会怎样；
3. 通过了才上线，上线后监控、对账、再调参。

第 2 步要读海量历史数据并重复成千上万次——这就是"research platform / distributed storage / computing farm"存在的原因（§4）。

## 3. 为什么延迟重要，量级感

1 秒 = 1,000 ms；1 ms = 1,000 µs。人眨一次眼约 100 ms；一次内存读取约 100 ns。

| 环节 | 量级 |
|---|---|
| 一套较慢的软件系统，从收到行情到发出订单 | 约 30 µs |
| 交易所行情包之间的间隔 | 约 10–1,000 µs |
| 交易所撮合响应 | 约 100 µs – 5 ms |
| 纽约到芝加哥：微波 vs 光纤 | 约 4 ms vs 约 7 ms |

最后一行可自验：纽约到芝加哥直线约 1,150 km；真空光速约 300,000 km/s，1,150 / 300,000 ≈ 3.8 ms，与微波的 4 ms 吻合；光在光纤里慢约三分之一（约 200,000 km/s），线路又不是直线，所以约 7 ms。为了省 3 ms，有公司专门建微波塔——"几毫秒"在这行是真金白银。

**工程手段**：生产系统用 C++（不用 Python / R / Matlab）、co-location（服务器放进交易所机房，缩短物理距离）、Linux 调优（processor affinity 绑核、NUMA）、时钟同步。另一个手段是 **CPU 缓存局部性**：把很少用到的"冷数据"从对象里挪走，让热数据挤进同一缓存行，在一个构造的基准里快约 11.8 倍；Java 里的对应是对象布局与堆外内存。

**对你的 Java 岗意味着什么**：岗位描述里与延迟直接相关的只有一条——改善**系统内部组件之间**的网络通信，以达到最优延迟和吞吐；"exchange connectivity""lock-free""profiling"这些热路径词出现在 C++ 岗。Java 岗更偏研究平台与基础设施。

## 4. Java 团队做什么：research platform、distributed storage、computing farm

岗位描述只给了词，没给内部结构。下面是用 §2–3 的因果**推出的合理图景**，面试时当作"我的理解，请你纠正"来说。

### 4.1 一笔交易背后的系统

```
 【实盘链路：必须极快】
 交易所 ──▶ market data parser ──▶ strategy ──▶ order gateway ──▶ 交易所
 【配套】monitoring GUI · drop copy(交易所回传的成交副本) · market data capture(行情落盘)

 【离线：不极快，但极大】
 参数优化 · production reconciliation(对账：实盘 vs 模拟是否一致) · backtesting simulator(回测) · 画图
 其中 tick 数据"可达每天数百 GB"
```

Java 岗大概率在**下面的"离线 + 配套"那一半**。

### 4.2 Research platform（研究平台）

研究员用来**提假设 → 取数据 → 回测 → 看结果**的内部自研软件，要你"improve performance and support new exchanges, products and functionality"。为什么自研：回测要和实盘用同一套"行情怎么解析、订单怎么模拟"的逻辑，否则回测不可信；每新增一个交易所、一种品种，数据格式和规则都不同，所以平台要持续支持新交易所、新产品。

### 4.3 Distributed storage（分布式存储）

tick 数据"每天数百 GB"。设每天 200 GB（示例值）：250 个交易日 × 200 GB = 50 TB / 年，历史越长越大。一块盘装不下，也读不快（单盘顺序读约 500 MB/s，读 50 TB 要 50,000,000 MB ÷ 500 MB/s = 100,000 s ≈ 28 小时）。所以数据要**切开放在很多台机器上**并行读。岗位要求"with various performance and reliability requirements"：有的数据要快（最近的 tick），有的要稳（不能丢的审计数据），取舍不同，设计也不同。

### 4.4 Distributed computing farm（分布式计算集群）

几百到几千台机器，研究员提交"跑一个回测 / 一批参数"的作业，调度器分到空闲机器（类似 Spark / Kubernetes job，但自建）。为什么需要：试 1,000 组参数、每组回测 1 小时，串行 = 1,000 小时 ≈ 42 天；100 台并行 ≈ 10 小时。研究员的迭代速度 = 公司研究产出的速度。

相关职责：调查新技术以提升集群的稳定性、可扩展性和性能；做基础数据分析（作业量、磁盘增长）以规划扩容；开发监控与主动检测——机器、作业、数据质量出问题要**先于研究员**发现。

### 4.5 24 小时、全自动

交易周从芝加哥时间周日 16:00 到周五下午；芝加哥 24 小时有人值守，阿姆斯特丹、新加坡做冗余。系统不眠 → 变更不能随便停机、监控必须自动、测试必须充分，这就是岗位描述强调 "fully automated … with extensive testing" 的原因。

## 5. 文化（一句话版）

自驱、好奇、低自我：要的是什么层都愿意往下挖的人（数学、统计、CS、交易系统都要碰），金融知识可以入职后学，问题解决能力才是基础；不适合只想朝九晚五、不愿提出独立想法的人。没有办公室政治，想法按内容而不是按资历被对待；奖金只看个人与公司业绩，团队不内耗；迭代快，改动几周内就能在生产里看到影响；上手需要一两年，他们接受你学得慢，但要证明学得快。面试官是将来的同事，会写评价，所以互动本身也在被评分；流程大约 2–3 周。

## 8. 术语速查

| 词 | 一句话 |
|---|---|
| prop firm | 用自己的钱交易的公司，无客户 |
| market making | 双边挂单赚价差并提供流动性 |
| spread | 最低卖价与最高买价之差 |
| adverse selection | 对手比你更早知道价格，专挑你的旧报价成交 |
| latency / throughput | 一件事要多久 / 单位时间能做多少件，二者常此消彼长（批量提高吞吐但增加延迟） |
| tick data | 逐笔行情，每笔报价 / 成交都记录 |
| backtest | 用历史行情重放策略，估计它过去会赚多少 |
| co-location | 服务器放在交易所机房里 |
| drop copy | 交易所给你的成交副本，用来对账 |
| reconciliation | 对账：两个系统的同一批数据是否一致 |
| compute farm | 一大批机器 + 作业调度，并行跑大量独立作业 |
| NUMA / affinity | 多路 CPU 的内存分区 / 把线程绑在某个核上，减少抖动 |
