## Q
A take-home has no clock and no hidden tests — only a reviewer reading the repository you send back. What becomes the score?

## A
**Your judgement, made visible.** With time pressure removed, the reviewer measures scope control and communication instead of speed.

- A README that states the assumptions you made, what is deliberately out of scope, and how to run it.
- Tests that would genuinely fail if the logic broke, covering the edge cases the spec implies rather than only the happy path.
- Honest scope: a clean, complete core beats a half-built extra feature.
- No dead code, no commented-out experiments, no dependency you cannot justify in one sentence.

## Q zh
带回家的作业没有计时，也没有隐藏测试 —— 只有一个 reviewer 在读你交回的仓库。这时分数由什么决定？

## A zh
**你的判断力，被看得见。** 去掉时间压力后，reviewer 衡量的是范围控制和沟通，而不是速度。

- 一个 README：写清你做了哪些假设、什么是有意排除在范围外的、怎么运行。
- 逻辑一旦坏掉就真的会失败的测试，覆盖 spec 隐含的边界情况，而不只是 happy path。
- 诚实的范围：干净完整的核心胜过做了一半的额外功能。
- 不留死代码、不留注释掉的试验、不引入一句话说不清理由的依赖。
