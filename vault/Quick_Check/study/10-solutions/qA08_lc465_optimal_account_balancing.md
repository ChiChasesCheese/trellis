# qA08 · LC 465 最优账目结算（最少转账次数）

> `problems/qA08_lc465_optimal_account_balancing/` · 3 个 part · LC Stripe tag 频率 52
> **主题：先净额化，再在 ≤12 个非零净额上做 DFS 剪枝。**

## 一句话题意

给一堆 `[from, to, amount]` 的借贷记录，求把所有人的账结平所需的**最少转账次数**。

## 直觉 / Intuition

把每个人的净额想象成一堆正负配重，要用最少的"连线"把它们全部清零 —— 这是一个组合拆分问题，不是图遍历也不是贪心问题。
- 一旦净额化，原始的转账图（谁给谁转过钱）就彻底作废了，剩下的只是一组数字；这一步"忘掉图、只留数字"是全题最反直觉但也最关键的一跳。
- 答案下界很好想：n 个非零净额如果没法互相拆成更小的封闭小组，最少要 n-1 次（想象一条链，每次结清一个人）；但如果这堆数字能拆成 k 个各自和为零的独立子集，子集内部互不依赖，答案直接降到 n-k —— "分组"就是压缩转账次数的唯一杠杆。
- 于是问题变成一个纯组合优化：怎么把 n 个数分成最多份零和子集。n ≤ 12 决定了这必然是指数级搜索（状压 DP 或 DFS），而不是什么线性扫描的技巧解。
- DFS 版本的"每次转账必须完全结清当前这个人"不是随便定的规则，而是一个安全的决策收缩：既然最优解里每次转账总能顺带结清至少一个人（不然这次转账就是浪费），那不如每次都主动选择去结清一个人，搜索空间从"任意金额组合"收缩成"选谁来配对"，复杂度立刻可控。

## 解题思路

### ① 净额化（不做这一步就没法谈最优）

```python
net = defaultdict(int)
for a, b, x in transactions:
    net[a] -= x; net[b] += x            # ★ [a,b,x] 表示 a 给了 b，所以 **b 欠 a**
debts = [v for v in net.values() if v != 0]     # 净额为 0 的人直接丢掉
```

净额化之后剩下的数**和为零**。

### ② 精确搜索（≤ 12 个）

取第一个未结清的 `i`，尝试用每个**异号**的 `j` 把它**完全结清**（`net[j] += net[i]`，
`net[i] = 0`，一次转账），递归。

**三个必须的剪枝**：
1. 跳过当前值与本层已试过的某个 `j` 相同的（重复值）；
2. 遇到**恰好抵消**的 `j`（`net[i] + net[j] == 0`）就**停止本层循环** —— 精确匹配不会更差；
3. 当前计数已经不可能打败最优解时**剪掉整支**。

**面试官想听到的理由**：存在一个最优解，其中**每次转账至少结清一个人**，
所以把每次转账限制成"完全结清当前这个人"不会丢掉最优解。

### ③ 状压 DP（另一种精确解）

`n` 个非零净额时，答案 = `n − (能把这些净额拆成的最多个不相交的零和子集数)`。
`dp[mask] = max_i dp[mask 去掉 i] + [sum(mask) == 0]`，O(2^n · n)。
两种解法必须在任何输入上一致。

### Part 2 — 输出转账清单

`Transfer(frm, to, amount)`（用 `frm` 因为 `from` 是关键字）。
确定性：人按 id 升序处理；每层的候选 `j` 按 id 升序试；**第一个**达到最小计数的清单被返回
（后来等长的不替换）。链式结算中接收方可能被**超付**，在后续转账里把多余的转出去。

### Part 3 — 尘埃核销

一次转账有固定手续费，所以小于 `threshold` 的余额不值得挪。
**`0 < |net| < threshold`（严格）的人被核销** —— 恰好等于阈值的**仍然结算**。

## 坑

1. **符号约定**：`[a,b,x]` 表示 a 给了 b，所以 **b 欠 a**。反了的话所有转账方向都反。
2. 全部净额为零 → 0 次转账、空清单。
3. 单条交易 → 1 次；**只当中转、净额为 0 的人必须被丢掉**。
4. **答案是 `n − 零和子集数`，不是 `n − 1`**（"大家都付给一个中心"是错的直觉）。
5. 一个欠债人对 k 个债主（或反过来）→ **恰好 k 次**，与金额无关。
6. **重复净额**：去重剪枝只能改变速度，**不能改变答案**。
7. LC 的最大输入：12 个非零净额、零和子集很少 ——
   无剪枝的 DFS 约 11! 个分支，加上三个剪枝是毫秒级。
8. Part 3：`|net| == threshold` 结算，`threshold − 1` 核销；
   被核销的净额恰好互相抵消时，**平台方不应出现在清单里**。
