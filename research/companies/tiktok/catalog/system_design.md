# System design prompts reported for TikTok / ByteDance backend (2025-10 to 2026-10-24)

Source ids as in `sources.md`. "Reports" = distinct source items that name the prompt in the window (an aggregator counts once per candidate report). Counts are small: 27 dated system-design sightings in TrueInterview [G1] over 12 months, 4 + 1 + 1 + 1 on Hello Interview [H1], 11 SD questions in the 79-question 1point3acres bank [A2].
Confidence: high = prompt text and pushes first-hand; medium = prompt named by an aggregator with a summary; low = title only.

## 1. How the design round is run (what the sources agree on)

- Length 45-60 min; "one or two design hours" for mid/senior; sometimes only 15 minutes inside a mixed hour; sometimes inside the HM round after 30 min of projects and a coding problem [G1][R3b][SU]. Singapore case: scheduled 1 h, ran 3 h (1 h experience, 2 h design deep dive) [R2].
- Prompts are often **a module of the team's real product** and may be **two sentences with no clarification help**; one candidate got a long internal spec and had to answer in plain text because the editor could not draw [G1]; another had a design question inside a coding platform with no drawing tool [B6]. Prepare to describe a diagram verbally and in text; for the whiteboard question a recruiter's answer was "same HackerRank link" [B-sd2].
- The interviewer **drills one flow**: "listed all requirements, explained the entities, wrote down the flow and drew the diagram ... he started asking questions about one specific flow that was the whole point of this design ... 4 questions" [R3]. "Standard prompt, nothing challenging" for an L6 (2-2 loop) [B2]; "a very famous system design question and he dug very deep" [R2]; "a consistency system design problem" in the third round of a USDS/ByteDance loop [B1].
- Graded on (G1 summaries): **estimates first** (QPS, storage per event, bandwidth), **exact vs approximate** ("not asking whether top-K had to be exact muddled the design" — a rejection), separating **ingestion / aggregation / serving**, **failure handling** (reconnects, exactly-once, late events, hot keys), mechanism-level knowledge of named tools (window types, count-min sketch error bounds, Kafka partitioning). For infra-flavored designs "graded on operating the system rather than drawing it" [G1].
- For senior: AI/ML serving, monitoring and drift for an AI feature appear ("senior candidates were asked for an AI feature's serving, monitoring and rollout infrastructure") [G1]; 1point3acres says "system design is mandatory for NG" and the hiring manager round may include HLD [A1].

## 3. Cross-cutting themes interviewers keep returning to

1. **Idempotency + exactly-once effects** (payments, coins, bids, moderation enforcement, job slots) — the most repeated word across prompts #1, #2, #5, #6, #7.
2. **Money correctness**: ledger/state machine, reconciliation, integer minor units, async settlement, webhooks, refunds, PSP failover.
3. **Windowed aggregation under skew**: top-K, exact vs approximate, hot keys, late events.
4. **Failure behavior over architecture drawing**: crash mid-step, duplicate/lost callbacks, backpressure, retries, dead letters, notification path availability.
5. **Operational shape**: SLAs, lag metrics, audit trails, safe rollout (rules without redeploy), model/rule versioning.
6. **AI/ML infra in senior loops**: serving and drift monitoring, retrieval K, agent tool-call tracing, moderation scoring (team-dependent).

## 4. Fundamentals questions that ride along (oral, mechanism-level)

CAP; composite/covering index and leftmost prefix; why not index every column; B+ tree vs hash; clustered vs secondary; transaction isolation (older Blind: MySQL isolation levels, why 3-way handshake, Python GC/WSGI [B-old3]); cache breakdown/penetration/avalanche; cache-aside consistency; Kafka partitions, rebalancing, retained log vs work queue, ordering and durability; Redis persistence and sorted sets; WebSocket vs SSE vs REST for streaming agent progress; Java LinkedHashMap vs ConcurrentHashMap; virtual memory beyond RAM; TCP handshake; TLS/HTTPS inspection; deadlock; monitoring/tracing/telemetry; MySQL→MongoDB migration; "what do you do when an LRU cache's miss rate is high" [G1][P1][G3].
