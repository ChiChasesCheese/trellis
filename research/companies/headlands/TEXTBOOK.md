# 教科书模式（本 kit 所有学习材料的写法）

> **核心要求（Chi，2026-10-20，优先于下面所有条目）**：必须简洁、教程级别；**不引用来源**，不放链接、证据标签、出处说明这类无关内容；**每篇文章自包含**，它用到的定义、代码、事实全部写在文中，不靠「见某某文件」代替讲解。

Chi 的原话：「出题和阅读学习的时候尽量教科书模式。因为我基础真的很差，最好前因后果都讲清楚。」

所以本 kit 的读者设定是：**会写基本的 Java（类、方法、循环、`ArrayList`/`HashMap` 的基本用法），但数据结构、复杂度、
并发、JVM 原理都需要从头讲**。写的时候想象在给一个聪明但没学过这些的同学上课。

## 每道题的讲义：`study/30-articles/<id>.md`

problem.md 是「考卷」，REPORT.md 是「给面试准备的速查」，讲义才是「课本」。讲义按下面的顺序写，标题照抄：

1. **这道题在问什么** — 用大白话复述，配一个最小的具体例子，手算一遍输入 → 输出。
2. **前置知识** — 本题用到的每个概念单独一小节，每节回答四个问题：
   *是什么*（一句话定义）→ *为什么需要它*（没有它会怎样，举反例）→ *它怎么工作*（画 ASCII 图或逐步演示）→ *Java 里怎么写*（最小代码片段）。
   每篇自包含：用到的概念都在本文讲清楚（可以简短），不靠链接到别的文件。
3. **从最笨的解法开始** — 先写出谁都想得到的暴力解，算它的复杂度，指出它**具体在哪个输入上**慢或错。
4. **一步一步改进** — 每一步都是「发现问题 → 想法 → 为什么这个想法能解决问题 → 代码变化 → 新复杂度」。不允许跳步：
   如果某一步需要一个新的数据结构，回到第 2 节讲它。
5. **逐段讲参考解** — 把 `reference/` 的代码分段贴出，每段后面解释「这几行在干什么、为什么这样写、换种写法会怎样」。
6. **Java 21 特性小课** — 本题用到的每个新特性：旧写法（Java 8 风格）和新写法并排，说明编译器/运行时多做了什么、
   什么时候**不该**用。链接 `study/10-java21/Jxx.md`。
7. **追问预演** — 面试官的每个追问写成一问一答：问题 → 思考过程（先想什么、排除什么） → 答案要点 → 可以说出口的一段话。
8. **常见误区** — 「很多人会这样写 → 为什么错 → 正确写法」，至少 3 条，来自测试里的边界用例。
9. **自测题** — 5 道左右，从概念题到小编程题，答案放在 `<details><summary>答案</summary>…</details>` 里。
10. （可选）**延伸** — 至多一行，告诉读者下一步学什么；不放链接和出处。

语言：中文，术语第一次出现写「中文（English）」，之后可以只写其一。复杂度用 `O(n log n)` 并说明 n 是什么。
长度不设上限：讲清楚优先于短。

## Java 21 特性课本：`study/10-java21/Jxx_<slug>.md`

CONVENTIONS.md 特性矩阵里的每个 id 一篇，同样教科书写法：它解决了什么老问题（先展示老写法的痛点）→ 语法逐条讲 →
编译器/JVM 做了什么 → 3 个由浅入深的例子 → 坑与限制 → 在本 kit 哪些题里用到（链接）→ 自测题。

## 基础概念课本：`study/00-foundations/<slug>.md`

被两篇以上讲义需要的基础概念（复杂度分析、哈希表原理、堆、平衡树/跳表、Java 内存模型与可见性、JIT 与逃逸分析、GC 基础、
线程 vs 虚拟线程、CPU 缓存与局部性）单独成篇，讲义链接过去。写法同第 2 节的四问，篇幅更长。
