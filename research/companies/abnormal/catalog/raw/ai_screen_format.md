## B. Abnormal 候选人对 AI 技术面的第一手报道（PracHub，均"Reported Jul 2026，Published Sep 4, 2026"，均 [中]：站方编辑过的摘要）

- **F-12** https://prachub.com/interview-experiences/abnormal-ai-software-engineer-interview-feature-implementation-in-an-existing-codebase-874b1387d9 —— Technical Screen · Medium · Bengaluru · feedback neutral · no offer：
  > "My technical interview focused on AI-assisted coding. I was placed in a fairly large existing codebase and first had to make sense of it with AI tools. Then I used that understanding and AI support to implement a feature and write tests for the changes."
  > "It felt less like a pure algorithm check and more like a test of whether I could turn a task into working code while using AI in a controlled way. The challenging part was how much depended on the AI interpreting both the codebase and my intent."
- **F-13** https://prachub.com/interview-experiences/abnormal-ai-software-engineer-interview-ai-agents-used-throughout-a-real-work-loop-6e26945209 —— HR Screen → Technical Screen → Other · New York · positive · no offer：
  > "The technical work centered on AI rather than classic LeetCode prompts. In a large codebase, I used AI to understand the structure, implemented a feature with AI assistance, and wrote tests. The later loop included a system-design and incident-management-style conversation plus a PR or code-review discussion where I could use AI agents throughout."
- **F-14** https://prachub.com/interview-experiences/abnormal-security-software-engineer-interview-ai-assisted-work-in-a-large-codebase-a2857641b5 —— HR Screen → Technical Screen → Other · New York · positive · no offer：
  > "They explained the company and likely day-to-day work, then asked about my background, why I was changing roles, and how I used AI in everyday work. About a week later, I had an AI-assisted technical screen. I received a large codebase and a feature requirement, and was expected to understand the existing structure with AI help, implement the feature with AI assistance, and add tests."
  > "They seemed interested in real work rather than abstract LeetCode patterns."
- 对 Chi 的含义（事实层）：三篇一致 = **(1) 读懂代码库 (2) 实现 feature (3) 写测试**；后续轮包括 **system design + incident-management 式对话** 与 **PR/code-review 讨论（可全程用 AI agent）**；HM 轮会问 **"how I used AI in everyday work"**。三篇可能是同一批 PracHub 编辑的短摘要，**独立性存疑**（三份都是同一天发布、同月、格式相同）。

## C. 同类面试的外部报道（迁移用，[中/低]）

**C1. Meta "AI-enabled coding"（2025-10 起）**
- **F-15 [中]** https://www.hellointerview.com/blog/meta-ai-enabled-coding （2026 年内更新）：
  - 形式："One classic LeetCode-style algorithm problem (no AI) and one AI-enabled interview."；"Every Meta AI-enabled coding interview follows the same structure. Three progressive phases, all built around a single extended problem. Your interviewer will spend the first five to six minutes orienting you ..."；"Not completing all phases is perfectly fine. Multiple candidates who didn't finish phase 3 still received offers."
  - 评分四项："Problem Solving. / Code Quality. / Verification. / Communication."；"The rhythm interviewers want to see is prompt, review, run, confirm, move on."；内部说法（转述）："Should use AI, but need to show you understand the code. Explain the output. Test before using. Don't prompt your way out of it."
  - 常见挂法："skipping the reading step" 是最大遗憾："Even if your interviewer doesn't tell you to read the code first, take the time anyway."；"A guaranteed way to fail this interview would be to prompt your way to success, never writing any code yourself or reviewing the AI's output. As one recruiter explicitly warned, 'you can be marked down if you use it as a crutch.'"；"Quickly pasting AI responses without checking is a red flag."；"Don't spend excessive time debugging AI output."；候选人 "appeared to rely heavily on AI, which impacted the quality of their solution" 得到负反馈；Prompt 粒度：先让 AI 做 "core logic ... a very basic single function so I can review it easily"。
  - 时间："The 60 minutes disappears faster than you think ... you're left with roughly 30 to 40 minutes for the actual implementation"。
- **F-16 [中]** https://prachub.com/resources/meta-ai-coding-interview ：Bug 通常 "not algorithmic: a type cast that breaks an assumption elsewhere, an off-by-one, a wrong conditional, a missing visited-set"；"Five minutes of reading saves fifteen of debugging."
- **F-17 [低]** https://alexcloudstar.com/blog/technical-interviews-ai-2026/ ：泛泛博客；"When the interviewer asks 'why did you use this approach?' the answer is 'because the AI suggested it.' That is a fail."；提到 Rippling 允许/鼓励面试用 AI（无细节，无日期之外的来源）。
- **与 Abnormal 的差异**：Meta 是 CoderPad 内的聊天助手、算法型分阶段题、AI 不能改文件；Abnormal 按任务书是 **浏览器 VS Code + 预装 Claude Code（agentic）+ 故意模糊的 feature**，因此"能否被 AI 带偏"的风险更大，"陈述假设与自测"权重更高。

**C2. Pocus 的 "AI-native technical screen"（非 Abnormal，非 Meta；一份详细的设计文）**
- **F-18 [中]** https://i0exception.substack.com/p/designing-an-ai-native-technical （Aniruddha，Jun 09, 2026）：1 小时、TypeScript 服务端 repo（"moderately-sized server that was more than a toy"）、3 个难度递增的 bug、可自由问模型但"The one thing they couldn't do was ask it to find the bug."；最后一关"file a support ticket for a bug in a service whose code they couldn't see"测沟通。
  - 候选人类型（原文）：**The Skeptic**（"their approach wouldn't bend when the problem outgrew it"）、**The Executor**（"asking it for a fix, pasting the fix in, running it, and asking again ... They became the model's hands without being its judgment"）、**The Deflector**（"Attacking the question instead of the problem is itself the signal"）、**The Leetcoder**、**The Collaborator**（"They got nerd-sniped ... They reasoned from first principles. They moved through strange code without needing permission to be there. ... used the model as a collaborator instead of being deferential or controlling."）。
  - 作者的原则："Reading matters more than writing"；"Engineers live in unfamiliar code now"；"Communication stopped being optional"。
  - 与 Abnormal 的关联：评分词 "不等指令推进 / Agency" 与 Collaborator 描述相近；**这是类比，不是 Abnormal 的做法**。
