# AI 应用工程（AI Engineering）：把大模型做成可靠的产品

读者：资深后端工程师，机器学习基础薄弱，目标是在 AI 团队里说得出生产系统怎么搭、怎么测、怎么省钱、怎么防出事。
和 ai-literacy 的分工：那边讲「是什么、为什么」（概念层），这里讲「怎么做、哪里会坏、怎么量」（工程层）。
记号：`*` = 帕累托核心；`(需先: …)` = 真依赖。

## 1. 起点：什么时候该做、怎么选
- * AI 工程栈与它和传统后端的差别（AI engineering stack）— 应用层、模型层、基础设施层；输出是概率性的，「正确」要靠评测定义而不是单元测试断言
- * 先用最简单的办法：单次调用 → 工作流 → 智能体（simplest thing first）— 每升一级换来什么、多付什么（延迟、成本、可调试性），用评测结果决定是否升级
- * 用例评估与期望设定：哪些功能值得上 LLM — 人工替代成本、容错度、可验证性；「演示 80% 容易，最后 20% 要几个月」
- * 模型选型流程：自建还是买接口（build vs buy）— 数据隐私、延迟、成本、可控性、供应商锁定五个维度；先用最强模型跑通再往下压
- 读公开基准选模型：它回答不了的问题 — 基准与自家任务的相关性、污染；怎么用自己的评测集重新排名
- 框架该不该用：LangChain、LlamaIndex 与直接调接口 — 框架隐藏提示和响应带来的调试代价；先写裸调用，读懂框架在做什么再引入 (需先: 先用最简单的办法)

## 2. 检索增强生成工程（RAG Engineering）
- * RAG 流水线全景：摄取、切块、索引、检索、重排、生成 — 每一段独立可测；先定位是检索错还是生成错
- * 文档解析与切块（chunking）：固定长度、按结构、语义切块 — 块太大稀释信号、太小丢上下文；表格、代码、PDF 的特殊处理
- * 嵌入模型选择与维度 — 领域适配、多语言、维度与存储成本的权衡；换模型要全量重建索引
- * 向量索引与近似最近邻（ANN）：HNSW、IVF、乘积量化 — 召回率、延迟、内存、更新代价四项权衡；什么时候用现有数据库的向量扩展就够
- * 混合检索：关键词（BM25）加向量，再做融合 — 为什么纯向量会漏掉专有名词和编号；倒数排名融合（RRF）怎么合并两路结果
- * 重排序（reranking）：交叉编码器二次打分 — 召回要广、精排要准的两段式；加一级的延迟和成本
- 查询改写与扩展：HyDE、多查询、分解子问题 — 用户问题和文档措辞不匹配时怎么补；每种改写多一次模型调用 (需先: RAG 流水线全景)
- 元数据过滤与多租户权限 — 检索阶段就按权限过滤，而不是生成后再遮蔽；先过滤还是后过滤对召回的影响
- * 检索评测：召回率@k、精确率、MRR、nDCG — 没有标注就先用 LLM 合成问答对；检索指标和最终答案质量分开看
- * RAG 生成端评测：忠实度（faithfulness）与答案相关性 — 答案是否只来自给定上下文；引用核对 (需先: 检索评测)
- RAG 的典型故障表：该检的没检到、检到了没用、过期数据、冲突文档 — 每类故障对应的排查入口与修法
- 长上下文还是 RAG：什么时候直接塞整库 — 成本、延迟、「中间丢失」；缓存前缀让长上下文变便宜
- 智能体式检索与知识图谱检索（GraphRAG）— 多跳问题单次检索不够；图索引的构建成本和适用面
- 索引的增量更新与数据新鲜度 — 变更捕获、软删除、嵌入版本；索引与源数据不一致怎么发现

## 3. 智能体工程（Agent Engineering）
- * 工作流模式五件套：提示链、路由、并行、编排者—执行者、评估者—优化者 — Anthropic 的分类；每种适用的任务形状 (需先: 先用最简单的办法)
- * 智能体循环的工程化：停止条件、最大步数、预算 — 没有终止条件的循环会烧钱；每步都要有环境反馈当地面真相
- * 工具设计（agent-computer interface）：命名、参数、描述、返回内容 — 工具描述就是给模型的 API 文档；让错误难以发生（poka-yoke）；返回精简而有信息量
- * 工具的幂等、权限与副作用分级 — 读、写、不可逆三类；写操作带幂等键，高风险操作要确认
- * 错误处理与重试：把错误当观察返回给模型 — 可重试与不可重试、退避、重复调用检测、熔断
- * 智能体状态与记忆：会话内状态、外部存储、压缩 — 什么放上下文、什么放数据库；摘要压缩的信息损失
- 上下文工程（context engineering）：窗口里放什么、怎么裁剪 — 工具结果清理、即时检索、笔记文件；上下文腐烂（context rot）
- * 人在回路（human-in-the-loop）：审批点与升级 — 按风险分级打断；审批疲劳的后果；默认拒绝与可撤销设计
- * 长任务的持久化执行（durable execution）— 检查点、可恢复、幂等；用工作流引擎（如 Temporal 类）承载智能体循环 (需先: 智能体循环的工程化)
- 多智能体：何时拆、怎么协作与汇总 — 并行研究类任务收益大、写代码类任务耦合高；token 成本放大数倍
- 子智能体与上下文隔离 — 用独立窗口做搜索，只回传摘要；避免主上下文被污染
- MCP 在生产里的用法与坑 — 工具数量膨胀、工具描述占上下文、远程服务器认证；代码执行方式降低 token (需先: 工具设计)
- 智能体沙箱与执行环境 — 容器、网络出口控制、资源限额；代码解释器与浏览器的隔离
- 智能体的典型失败：错误累积、循环、目标漂移、过度行动 — 每步 95% 成功，二十步后剩多少；从轨迹里定位首个出错步

## 4. 评测工程（Evals as Engineering）
- * 为什么评测是第一优先级：三个循环（评估、调试、改动）— 没评测就只能凭感觉改提示，改一处坏一处
- * 先看数据：错误分析与失败模式归类（error analysis）— 读一百条真实轨迹，开放式标注再归类；评测从失败里长出来，不是从通用指标来
- * 评测三层：断言单测、人工与模型评审、线上 A/B — 成本递增、频率递减；每层各自抓什么
- * 黄金集（golden set）的构建与维护 — 来源（线上采样、专家编写、合成）、覆盖、版本化、防污染；定期补入新失败样本
- * 代码断言与可验证评测 — 能用正则、解析器、执行结果判定的就不要用模型判；评测成本差两个数量级
- * 以大模型当评委（LLM-as-judge）与它的坑 — 位置偏好、冗长偏好、自我偏好；二元判定加理由比打 1–10 分稳 (需先: 黄金集)
- * 让评委对齐人类：人工标注、一致率、精确率与召回率 — 不平衡数据上总体一致率会骗人；评委也要有自己的测试集
- * 回归测试与 CI 门限 — 每次改提示、改模型、改检索都跑；通过率阈值是产品决定；噪声下怎么判「真退步」
- 评测的统计功效：样本量、置信区间与非确定性 — 多次采样、种子、温度；差 2 个点是不是噪声
- 智能体评测：轨迹、工具调用、终态检查 — 评结果还是评过程；多轮与有状态环境的评测；pass@k 与 pass^k（可靠性）
- * 线上评测与生产监控：抽样打分、护栏指标、用户信号 — 离线好不等于线上好；漂移时报警 (需先: 回归测试与 CI 门限)
- 基准的完整性：污染、饱和、刷分 — 为什么公开榜单不能代替自家评测

## 5. 护栏与安全（Guardrails & Prompt-Injection Defence）
- * 威胁模型：OWASP LLM Top 10（2025）— 提示注入、敏感信息泄露、供应链、输出处理不当、过度代理、无界消耗等十项
- * 直接与间接提示注入（prompt injection）— 间接注入来自网页、邮件、文档、工具返回；为什么模型分不清指令与数据
- * 「致命三要素」：私有数据、不可信内容、对外通信 — 三者同时具备就可被窃取数据；设计上拆开比检测更可靠
- * 过度代理与最小权限（excessive agency）— 工具范围、凭据范围、按用户身份下发权限；读与写分离
- * 输出处理：把模型输出当不可信输入 — 渲染链接与图片的外泄通道、拼接 SQL 与命令、XSS；模式校验后再执行
- * 输入输出护栏的分层 — 结构校验、内容安全分类、语义与事实性检查、PII 脱敏；各层的误杀与漏放
- 护栏产品与检测器的局限 — 「拦住 95%」在安全上不及格；检测只作为一层，不作为边界
- 架构级防御模式：双模型隔离、计划后执行、能力令牌 — 受信模型规划、不可信数据只经隔离模型处理 (需先: 「致命三要素」)
- 越狱、红队与对抗测试 — 自动化红队集合纳入回归；记录攻击成功率
- 系统提示泄露与数据外泄 — 不要把密钥放进提示；多租户下缓存与上下文串用
- 无界消耗与滥用控制：限流、配额、成本上限 — 拒绝服务与「钱包攻击」；按用户与按租户限额
- 结构化输出与受约束解码作为护栏 — 语法约束保证可解析，不保证内容正确

## 6. 成本与延迟工程（Cost & Latency）
- * 成本模型：输入、输出、缓存读写分别计价 — 每次请求成本公式；智能体里上下文每步重复付费
- * 延迟分解：首 token 时间、每 token 时间、端到端 — 流式输出、并行调用、减少输出长度往往最有效
- * 提示缓存（prompt caching）：稳定前缀放前面 — 命中条件、生存期、写入溢价；提示设计要把变量放后面
- * 精确缓存与语义缓存 — 语义缓存有误命中风险；用约束输入或条目 ID 作键更安全
- * 模型路由与级联：小模型先答、不确定再升级 — 分类器路由、置信度级联、成本节省与质量下降要用评测验证
- * 批量接口与异步处理 — 离线任务半价；批量用于评测、数据标注、回填
- 减 token：精简提示、压缩上下文、限制输出 — 先量出 token 花在哪一段，再砍
- 推理预算与思考模式的取舍 — 推理模型按需开启；思考 token 也计费
- 限流、重试与降级策略 — 429 退避与抖动、多供应商备份、流式中断的恢复
- 自托管还是接口：盈亏平衡点 — 利用率是关键变量；GPU 闲置成本 (需先: 成本模型)

## 7. 可观测性与排障（Observability）
- * 追踪（trace）与跨度（span）：一次请求里的每次模型与工具调用 — 记录输入、输出、延迟、token、成本；OpenTelemetry 的生成式语义约定
- * 日志里的隐私与留存 — 提示与回复含个人信息；脱敏、采样、保留期
- * 从线上轨迹到评测集：把失败变成测试 — 排障闭环的核心；标注界面要把所有上下文放一屏
- 提示与配置的版本管理 — 提示像代码一样入库、发布、回滚；变更与指标关联
- 质量指标与业务指标并看 — 拒答率、工具错误率、重试率、点赞率、任务完成率
- 供应商事故与模型静默变更的应对 — 固定模型快照、金丝雀、对照回放

## 8. 数据飞轮与反馈（Data Flywheel）
- * 显式与隐式用户反馈 — 点赞、重新生成、采纳与忽略、编辑距离；隐式信号更便宜但更噪
- * 反馈设计与它的偏差 — 反馈稀疏、极端用户占多数；怎么让用户顺手给出信号
- * 防御式用户体验（defensive UX）— 给出处、可撤销、易于忽略、设定预期；错误不可避免时的体面
- 把生产数据转成评测集与训练数据 — 去标识、去重、质量过滤；谁有权使用用户数据
- 合成数据与蒸馏的工程流程 — 强模型生成、过滤、训练小模型；许可条款的限制

## 9. 微调决策（Fine-tuning Decisions）
- * 先提示、再检索、最后微调 — 决策树：缺知识用 RAG，缺行为/风格/格式才考虑微调
- * 微调的理由与反对理由 — 延迟与成本、专用格式、小模型替代大模型；数据需求、维护负担、模型升级后要重做
- * LoRA 与参数高效微调的工程含义 — 只训小矩阵、可热插拔多适配器；显存账怎么算
- 偏好优化与强化微调的适用面 — DPO、基于可验证奖励的强化学习；什么任务值得
- 数据集工程：质量、覆盖、数量 — 质量压倒数量；去重与格式化；标注一致性
- 微调后的评测与回退 — 对比基线、灾难性遗忘检查、保留旧模型的路径

## 10. 网关与平台（LLM Gateway & Platform）
- * LLM 网关的职责：统一接口、路由、密钥、限流、审计 — 为什么应用不该直连供应商；多供应商回退
- * 多租户的配额、预算与成本归因 — 按团队与功能记账；超预算熔断
- * 编排与管道：队列、工作流引擎、异步任务 — 长耗时调用不放在请求线程里
- 发布与灰度：模型与提示的金丝雀与影子流量 — 双跑对比、自动回滚条件 (需先: 回归测试与 CI 门限)

## 卡片格式建议
- 每张卡先给一个具体故障或决策场景（「检索召回高但答案还是错」），再给机制与解法；不写「第几章说」。
- 带数字：延迟、成本、缓存命中后的价格比例、召回率改善量；没核实的数字不上卡（供应商价格会变，只写比例与公式）。
- 对比卡：混合检索 vs 纯向量、语义缓存 vs 精确缓存、工作流 vs 智能体、微调 vs RAG，各列适用条件与代价。
- 至少 30% 带图：RAG 流水线、智能体循环与重试、评测三层、网关架构、致命三要素三圈图（mermaid 或 svg）。
- 代码卡用短 Python 片段加行内注释：重试与幂等键、RRF 融合、LLM 评委的二元判定与一致率计算、缓存键设计。
